# Google Calendar Token Security Controls Checklist (GCAL-002)

## Storage & Encryption
- [x] OAuth token payloads are envelope-encrypted before persistence (`google_calendar_token_vault.encrypt_token_payload`).
- [x] Data keys are generated by KMS and ciphertext payload is AES-GCM protected.
- [x] Token ciphertext and encrypted data key are the only persisted secret artifacts.
- [x] Refresh/access/id tokens are never persisted in plaintext fields.

## Key Management & Rotation
- [x] Dedicated key setting supported: `GOOGLE_CALENDAR_TOKENS_KMS_KEY_ID`.
- [x] Fallback to global KMS key only when explicit Google key is absent.
- [x] Rotation path implemented via re-encryption helper (`rotate_encrypted_token_payload`).
- [x] Connection-level rotation workflow implemented (`rotate_google_calendar_connection_tokens`).

## Logging & Audit Redaction
- [x] Token payload redaction helper masks sensitive values before storage in log-safe metadata.
- [x] Connection upsert and token rotation audit events carry `token_redacted=True`.
- [x] Services avoid emitting raw `access_token`, `refresh_token`, or `id_token` in audit payloads.

## Operational Validation
- [x] Unit tests validate encrypted-at-rest behavior for connection records.
- [x] Unit tests validate non-breaking rotate/decrypt behavior.
- [x] Unit tests validate redaction behavior for sensitive token fields.
