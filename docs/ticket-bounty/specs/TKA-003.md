## 1. Summary & Goal

TKA-003 closes the ticket-attachment feature by:

1. Adding the frontend UI to `TicketsPage` — a drag-and-drop / file-picker upload zone, an attachment list with download links, and per-attachment delete actions.
2. Wiring the full round-trip in `frontend/src/api/endpoints/tickets.ts`: presign, S3 PUT, confirm, list, get-download-URL, and delete.
3. Delivering a hermetic offline pytest suite (`tests/test_ticket_attachments.py`) that covers every backend edge case, plus an end-to-end Playwright spec (`frontend/e2e/ticket-attachments.spec.ts`) that exercises the round-trip through the real browser UI.

The feature is entirely additive and remains gated behind `S.ticket_attachments_enabled` (default **off**). With the flag off, all new API endpoints return 404 and the upload UI is invisible. Nothing in the existing ticket system — the `_TICKET_STATUSES` tuple [`app/services/tickets.py:15`], `_STATUS_TRANSITIONS` map [`app/services/tickets.py:30`], `create_ticket`, `assign_ticket`, `update_status`, `get_ticket`, `TicketOut`, or any of the 42 tests in `tickets.spec.ts` — is modified.

## 4. API / Service Design

### New endpoint wrappers in `frontend/src/api/endpoints/tickets.ts`

These are **pure frontend additions** — they call the backend endpoints defined in TKA-001/TKA-002.

```typescript
// Step 1: obtain a presigned PUT URL and attachment_id
export const presignTicketAttachment = (
  ticketId: string,
  payload: { filename: string; content_type: string; filesize: number },
) =>
  api.post<TicketAttachmentPresignOut>(
    `/tickets/${ticketId}/attachments/presign`,
    payload,
  );

// Step 2: confirm after the S3 PUT completes
export const confirmTicketAttachment = (
  ticketId: string,
  payload: {
    attachment_id: string;
    bucket: string;
    key: string;
    filename: string;
    content_type: string;
    filesize: number;
    head_bytes_b64?: string;
  },
) =>
  api.post<TicketAttachment>(`/tickets/${ticketId}/attachments`, payload);

// Composed helper: presign → S3 PUT → confirm
export const uploadTicketAttachment = async (
  ticketId: string,
  file: File,
): Promise<TicketAttachment> => {
  // 1. Presign
  const presignResp = await presignTicketAttachment(ticketId, {
    filename: file.name,
    content_type: file.type || "application/octet-stream",
    filesize: file.size,
  });
  // 2. Upload to S3 via bare fetch (no CSRF, Content-Type must be the file's type)
  const putResp = await fetch(presignResp.upload_url, {
    method: "PUT",
    body: file,
    headers: { "Content-Type": presignResp.content_type },
  });
  if (!putResp.ok) throw new Error("Failed to upload attachment to S3");
  // 3. (Optional) read first 8 bytes for magic-byte validation
  const headBuf = await file.slice(0, 8).arrayBuffer();
  const headB64 = btoa(String.fromCharCode(...new Uint8Array(headBuf)));
  // 4. Confirm
  return confirmTicketAttachment(ticketId, {
    attachment_id: presignResp.attachment_id,
    bucket: presignResp.bucket,
    key: presignResp.key,
    filename: file.name,
    content_type: presignResp.content_type,
    filesize: file.size,
    head_bytes_b64: headB64,
  });
};

// List attachments (no cursor: TKA-002 list endpoint has no pagination)
export const listTicketAttachments = (ticketId: string) =>
  api.get<TicketAttachmentListOut>(`/tickets/${ticketId}/attachments`);

// Get a download URL for a specific attachment
export const getTicketAttachmentDownloadUrl = (
  ticketId: string,
  attachmentId: string,
) =>
  api.get<TicketAttachmentDownloadOut>(
    `/tickets/${ticketId}/attachments/${encodeURIComponent(attachmentId)}/download`,
  );

// Delete an attachment
export const deleteTicketAttachment = (
  ticketId: string,
  attachmentId: string,
) =>
  api.del<void>(
    `/tickets/${ticketId}/attachments/${encodeURIComponent(attachmentId)}`,
  );
```

### React Query integration in `TicketsPage.tsx`

```typescript
// Query: load attachments when a ticket is selected and flag is on
const attachmentsQuery = useQuery({
  queryKey: ["tickets", "attachments", selectedId],
  queryFn: () => listTicketAttachments(selectedId!),
  enabled: !!selectedId && attachmentsEnabled,

// Mutation: upload

  mutationFn: (file: File) => uploadTicketAttachment(selectedId!, file),
  onSuccess: () => {
    toast.success("Attachment uploaded");

  onError: (err: unknown) =>

});

// Mutation: delete

  mutationFn: (attachmentId: string) =>
    deleteTicketAttachment(selectedId!, attachmentId),
  onSuccess: () => {
    toast.success("Attachment deleted");

  onError: () => toast.error("Delete failed"),
});
```

`attachmentsEnabled` is derived from the ticket detail response: `const attachmentsEnabled = Array.isArray(selectedTicket?.attachments)`. When the flag is off, `selectedTicket.attachments` is absent and the panel is not rendered — no feature-flag endpoint needed.

## 5. Detailed Behavior & Edge Cases

### Upload flow — step by step

1. User selects or drops a file onto the `TicketAttachmentDropzone` element (or the hidden `<input type="file" />`).
2. The component calls `uploadMut.mutate(file)` which triggers `uploadTicketAttachment`.
3. `presignTicketAttachment` POSTs to `/tickets/{id}/attachments/presign` — receives `{attachment_id, upload_url, bucket, key, content_type}`.
4. A bare `fetch(upload_url, { method: "PUT", body: file })` uploads the file bytes. In dev, `upload_url` is `/mock/s3/{bucket}/{key}` (routed through the Vite proxy to the in-app mock S3 PUT handler). In prod, it is a full AWS presigned URL.
5. The first 8 bytes of the file are read via `file.slice(0, 8).arrayBuffer()` and base64-encoded for server-side magic-byte validation.
6. `confirmTicketAttachment` POSTs to `/tickets/{id}/attachments` with all metadata; server writes the DDB row and returns `TicketAttachment`.
7. React Query invalidates `["tickets", "attachments", selectedId]`; the list re-fetches and shows the new row.

### Download flow

1. User clicks the download icon next to an attachment row.
2. `getTicketAttachmentDownloadUrl(ticketId, attachmentId)` is called (fires a GET).
3. In dev, the backend returns `download_url = "/mock/s3/{bucket}/{key}"` (same proxy). In prod, it returns a 300-second presigned GET URL.
4. The UI opens the URL in a new tab via `window.open(download_url, "_blank")` — no client-side S3 SDK needed.

### Delete flow

1. User clicks the trash icon; a confirmation `window.confirm` (or an inline `AlertDialog` from shadcn/ui) is shown.
2. On confirmation, `deleteTicketAttachment(ticketId, attachmentId)` calls `DELETE /tickets/{id}/attachments/{aid}`.
3. Backend (TKA-002) soft-deletes the DDB row (`status="deleted"`) and best-effort deletes the S3 object.
4. React Query list invalidation removes the row from the UI.

### Drag-and-drop dropzone behavior

The `TicketAttachmentDropzone` component:
- Renders a bordered `<div>` with a `<Upload />` icon (lucide-react, same as `UploadZone.tsx`).
- Listens for `dragenter` / `dragleave` / `dragover` / `drop` on the container (counter-based to handle child `dragenter` events that would otherwise fire spurious `dragleave`).
- On drop, reads `event.dataTransfer.files[0]` (single file; if multiple files are dropped, only the first is processed — a toast warns the user).
- Falls back to a hidden `<input type="file" />` controlled by `accept` (the MIME type allowlist from the server: `application/pdf,image/png,image/jpeg,image/webp,text/plain,...`).
- While `uploadMut.isPending`, renders a loading spinner and disables the zone.

### Flag-off behavior

`attachmentsEnabled` is derived from `Array.isArray(selectedTicket?.attachments)`. When `S.ticket_attachments_enabled` is false, the `get_ticket` projection in TKA-002 does not include an `attachments` key — the field is simply absent from the JSON response. The TypeScript type marks it `attachments?: TicketAttachment[]` (optional), so `selectedTicket?.attachments` is `undefined`, `Array.isArray(undefined)` is `false`, and the attachment panel is not rendered. No API calls to the attachment endpoints are made.

### Per-ticket attachment cap

The backend enforces `ticket_attachments_max_per_ticket` (default 20). When the cap is reached, `confirmTicketAttachment` returns HTTP 409. The `uploadMut.onError` handler shows `toast.error("Attachment cap reached — delete an existing attachment first")`. The UI does not need to client-side count attachments; it relies entirely on the server error.

### Attachment MIME type acceptance

The `<input type="file" />` `accept` attribute mirrors the server allowlist:
```
accept="application/pdf,image/png,image/jpeg,image/webp,text/plain,
  application/msword,
  application/vnd.openxmlformats-officedocument.wordprocessingml.document,
  application/vnd.ms-excel,
  application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
```
This is a UI hint only — the browser's file picker will filter for these types, but users can bypass it. The server enforces the allowlist independently on the presign endpoint.

### Concurrent upload protection

`uploadMut.isPending` disables the dropzone and file input while an upload is in flight. This prevents a second upload from overwriting `uploadMut` state and producing race conditions. If the user needs to upload multiple attachments, they do so sequentially. (A queued multi-upload path is a follow-up enhancement.)

### Stale presigned URL

If the S3 PUT step fails with a non-OK response (e.g., the 900-second window has elapsed between presign and upload), `uploadToPresignedUrl`-equivalent code throws `"Failed to upload attachment to S3"`. The confirm step is never reached, so no orphaned DDB metadata row is created. The user sees a toast error and can retry, which will re-call presign (getting a fresh URL and a new `attachment_id`).

### Ticket not selected

The attachment panel renders only when `selectedId !== null`. React Query `enabled: !!selectedId && attachmentsEnabled` ensures no query fires when no ticket is open.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### Dev/prod parity

The only `S.dev_mode`-branch in the attachment code is in the presign handler (established by TKA-001, modelled on `messaging.py:8412-8422` [`app/routers/messaging.py:8412-8422` — VERIFIED]): dev returns `/mock/s3/{bucket}/{key}` (routes through Vite proxy `/mock` → `localhost:8000` per `frontend/vite.config.ts:117` — VERIFIED); prod returns a real presigned URL from `s3.generate_presigned_url("put_object", ...)`. Everything else — the confirm DDB write, the list query, the download presign, and the delete — runs the same code path in both environments. Moto intercepts boto3 calls in dev; real AWS S3/DDB in prod. No `dev_mode` branch exists outside the presign URL generation. Full SECOPS-007 compliance.

The Vite dev proxy (`frontend/vite.config.ts`) already routes `/mock/s3` to the backend's mock S3 handler — no config change needed.

### Idempotency

- **Presign:** Each call generates a fresh `attachment_id` and URL. Re-calling presign is safe; old URLs are abandoned.
- **Confirm (add_attachment):** `T.tickets.put_item(ConditionExpression="attribute_not_exists(sk)")` ensures exactly-once write per `attachment_id`. A retry with the same `attachment_id` after a network timeout re-reads and returns the existing row rather than erroring (TKA-001 §5).
- **Delete:** TKA-002 uses `update_item` with a `status=deleted` conditional; deleting an already-deleted attachment is a no-op (idempotent).
- **Frontend uploads:** Because each presign generates a new `attachment_id`, retrying the entire upload after a failure creates a new clean slot without risk of collision.

### Security

- **Auth on every endpoint:** All four backend endpoints (`presign`, `confirm`, `list`, `download`, `delete`) require `require_ui_session` + the owner/assignee/admin guard. The frontend inherits this via the shared `api` Axios instance which always attaches the `ui_session` cookie and `x-csrf-token` header (`api/client.ts`).
- **S3 PUT uses bare `fetch()` without cookies:** The presigned PUT URL is either a `/mock/s3/...` relative path (dev) or a full AWS URL (prod). Neither carries the session cookies or CSRF token — this is correct and mirrors the messaging precedent (`messaging.ts:419-427`). The presigned URL is the auth mechanism for the S3 PUT.
- **Key-ownership guard:** `add_attachment` in the service layer verifies `key.startswith(f"tickets/{ticket_id}/attachments/{attachment_id}/")` before writing. A malicious client cannot register metadata for a key they borrowed from another ticket.
- **Magic-byte validation:** The `head_bytes_b64` field (8 bytes, base64) is sent in the confirm body. The server checks it against `_MAGIC_BYTES` for known MIME types. For MIME types without a signature (`.docx`, `.xlsx`, `.txt`), the check is **skipped** (pass-through) — **NOTE: this is a divergence from `license_agreements.py`** [`app/services/license_agreements.py:85-90` — CORRECTED: that function returns `False` for unknown MIME types, which causes an error; ticket attachments must explicitly skip/allow unknown types, not inherit the license-agreements behaviour]. The `_MAGIC_BYTES` dict in `license_agreements.py` covers only `application/pdf`, `image/png`, `image/jpeg`, and `image/webp` [`license_agreements.py:47-52`]; the ticket attachment service must implement its own allowlist with an explicit skip path for unsupported MIME types.

### Money-safety

TKA-003 involves no money movement. No ledger entries, no wallet debits, no billing interactions. The cross-cutting money constraints (atomic escrow, no double-charge, `settle_or_reverse_ledger`, `_fraud_gate`) do not apply.

## 10. Open Questions / Assumptions

1. **Flag toggling in E2E:** Test 65.3 (flag-off → 404) requires either a backend admin endpoint to toggle `TICKET_ATTACHMENTS_ENABLED` at runtime, or a test-env restart. The simplest approach is to skip that specific case in E2E (`test.skip`) and cover it only in the hermetic pytest suite where `object.__setattr__(S, "ticket_attachments_enabled", False)` is trivial.

2. **Download: new tab vs inline preview:** The spec uses `window.open(download_url, "_blank")`. For image MIME types, some browsers render inline rather than downloading. If product requires a forced download, the `Content-Disposition: attachment` header should be set by the backend presigned-GET generator in TKA-002 — this is a TKA-002 concern, not TKA-003.

3. **Drag-and-drop E2E reliability:** Playwright drag-and-drop with `DataTransfer.files` is notoriously unreliable for the actual file-drop event. The recommended pattern (used in test 67.5) is to trigger the hidden file input via `setInputFiles` rather than a true drag. The dropzone component should expose the `<input type="file" />` with a `data-testid="attachment-file-input"` attribute for reliable test targeting.

4. **Duplicate filename handling:** Two attachments on the same ticket can have the same filename (they are distinguished by `attachment_id`). The list renders both with the same display name. This is consistent with the file manager (`FilesPage.tsx`) behavior and does not require a conflict check.

5. **`delete_attachment` permission check (TKA-002 concern):** TKA-002 should specify whether only the uploader may delete, or whether the ticket owner and admin may also delete. This affects test 21 in the pytest suite. The spec assumes: uploader OR ticket owner OR admin may delete; a regular user who is neither uploader, owner, nor admin receives 403.

6. **Magic-byte validation reliability:** `file.slice(0, 8).arrayBuffer()` in the browser reads 8 bytes from the local file synchronously. For very large files this is a trivial read. The assumption that `head_bytes_b64` always represents the true first 8 bytes holds in a browser context (no streaming API involved for a small slice).
