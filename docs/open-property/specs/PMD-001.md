# PMD-001 — Rent-policy settings entity — per-landlord configurable defaults + admin CRUD

**Ticket type:** Feature
**Priority:** P1
**Estimate:** 2 d
**Flag:** `PROPERTY_DASHBOARD_ENABLED` (default OFF; shared master flag for the entire PMD cluster)

---

## 1. Summary & Goal

Introduce the **rent-policy settings entity**: a per-owner (landlord) DynamoDB record
holding four configurable defaults — `rent_due_day`, `late_fee_cents`,
`grace_period_days`, and `currency` — that leases inherit at creation time.

Today the platform has only a **global** default currency (`S.default_currency = "usd"`,
`app/core/settings.py:325`; `S.default_currency_code = 840`, `:324`). There is no
per-owner policy, no rent due-day concept, and no late-fee or grace-period setting
anywhere in the codebase. This is the sole gap that makes the RNT (rent ledger) cluster
unusable out of the box: without per-owner policy, every lease must carry its own
overrides and there is no "platform default" for a landlord managing many units.

PMD-001 is **greenfield storage + service + router only**. It does not touch the billing
ledger, the rent-run timer, or any lease record — it exposes a `get_policy(owner_sub)`
function that downstream clusters (RNT, LSE) call at creation time. The entire feature is
a 404 no-op when `PROPERTY_DASHBOARD_ENABLED=false`.

## 3. Data Model

### 3.1 DynamoDB table — `rent_policy`

**Registration** in `scripts/local-ddb-init.py`, added to `_table_defs()`:

```python
TableDef(
    _resolve_table_name(S.rent_policy_table_name, "rent_policy"),
    "pk",   # partition key
    "sk",   # sort key
    # No GSI: per-owner reads are Key={pk,sk} or begins_with(sk, "AUDIT#").
    # No numeric GSI sort key, so no attr_types override needed.
)
```

No GSI is required. All access patterns are single-owner scans:
- Point read: `get_item(Key={"pk": "POLICY#{owner_sub}", "sk": "CURRENT"})` — O(1).
- Audit query: `query(KeyConditionExpression=pk.eq(...) & sk.begins_with("AUDIT#"), ScanIndexForward=False)` — per-owner, no cross-owner sweep.

Because neither GSI nor numeric sort key is introduced, the CLAUDE.md `attr_types` gotcha
does not apply here.

### 3.2 Item shapes

**CURRENT row** (`sk = "CURRENT"`):

| Attribute | DDB type | Notes |
|-----------|----------|-------|
| `pk` | S | `"POLICY#{owner_sub}"` |
| `sk` | S | `"CURRENT"` |
| `rent_due_day` | N | Integer 1–28 |
| `late_fee_cents` | N | Integer >= 0; `Decimal` in DDB |
| `grace_period_days` | N | Integer >= 0; `Decimal` in DDB |
| `currency` | S | Lower-cased 3-letter ISO code, e.g. `"usd"` |
| `updated_at` | N | `now_ts()` Unix seconds; `Decimal` in DDB |
| `updated_by` | S | `actor_sub` of the last writer |

**AUDIT row** (`sk = "AUDIT#{ts:010d}#{event_id}"`):

| Attribute | DDB type | Notes |
|-----------|----------|-------|
| `pk` | S | `"POLICY#{owner_sub}"` |
| `sk` | S | `"AUDIT#{ts:010d}#{event_id}"` — zero-padded ts, lexicographic newest-first when `ScanIndexForward=False` |
| `actor_sub` | S | Who made the change |
| `before` | M | Snapshot of all four fields before the write (or `None` if first write) |
| `after` | M | Snapshot of all four fields after the write |
| `created_at` | N | `now_ts()`; `Decimal` in DDB |

The CURRENT row is replaced wholesale on every `set_policy` call (a full `put_item` like
`billing_config.py:360-361`). The AUDIT row is always appended — even if the caller
submits identical values — to provide a timestamped record of every admin action.

## 4. API / Service Design

### 4.1 Service — `app/services/rent_policy.py` (new)

All public functions call `_require_enabled()` as their first statement.

```python
_POLICY_PK_PREFIX = "POLICY#"
_SK_CURRENT = "CURRENT"
_SK_AUDIT_PREFIX = "AUDIT#"

# Per-owner in-memory cache: {owner_sub: (policy_dict, cached_at_ts)}
_cache: Dict[str, Tuple[Dict[str, Any], int]] = {}


def _flag_on() -> bool:
    return bool(getattr(S, "property_dashboard_enabled", False))


def _require_enabled() -> None:
    if not _flag_on():
        raise HTTPException(status_code=404, detail="Property dashboard is not enabled")


def _cache_ttl() -> int:
    return int(getattr(S, "rent_policy_cache_ttl_seconds", 60) or 60)


def _owner_pk(owner_sub: str) -> str:
    return f"{_POLICY_PK_PREFIX}{owner_sub}"


def _effective_defaults() -> Dict[str, Any]:
    """Return platform-level defaults: matches billing_config 'override-or-env' contract."""
    return {
        "rent_due_day": 1,
        "late_fee_cents": 0,
        "grace_period_days": 0,
        "currency": str(getattr(S, "default_currency", "usd")).lower(),
    }


def invalidate_cache(owner_sub: str) -> None:
    _cache.pop(owner_sub, None)


def get_policy(owner_sub: str) -> Dict[str, Any]:
    """Return the effective rent policy for owner_sub.

    Returns the stored CURRENT row if present; otherwise the platform defaults
    with is_default=True. Cache TTL mirrors billing_config (app/services/billing_config.py:244-278).
    """
    _require_enabled()
    now = now_ts()
    cached = _cache.get(owner_sub)
    if cached is not None and (now - cached[1]) < _cache_ttl():
        return dict(cached[0])

    resp = T.rent_policy.get_item(Key={"pk": _owner_pk(owner_sub), "sk": _SK_CURRENT})
    item = resp.get("Item")

    defaults = _effective_defaults()
    if item is None:
        policy = {**defaults, "updated_at": None, "updated_by": None, "is_default": True}
    else:
        policy = {
            "rent_due_day":      int(item.get("rent_due_day", defaults["rent_due_day"])),
            "late_fee_cents":    int(item.get("late_fee_cents", defaults["late_fee_cents"])),
            "grace_period_days": int(item.get("grace_period_days", defaults["grace_period_days"])),
            "currency":          str(item.get("currency", defaults["currency"])).lower(),
            "updated_at":        int(item["updated_at"]) if item.get("updated_at") is not None else None,
            "updated_by":        item.get("updated_by"),
            "is_default":        False,
        }

    _cache[owner_sub] = (policy, now)
    return dict(policy)


def set_policy(
    owner_sub: str,
    *,
    rent_due_day: int,
    late_fee_cents: int,
    grace_period_days: int,
    currency: str,
    actor_sub: str,
) -> Dict[str, Any]:
    """Validate, persist, and cache-invalidate a new policy.

    Validation mirrors billing_config._validate_* helpers. Writes CURRENT row
    plus one AUDIT row. Returns the new effective policy dict.
    """
    _require_enabled()
    _validate_policy(rent_due_day, late_fee_cents, grace_period_days, currency)

    now = now_ts()
    event_id = f"evt_{uuid.uuid4().hex[:8]}"
    pk = _owner_pk(owner_sub)
    currency_norm = currency.strip().lower()

    # Snapshot before-state for audit (may be absent on first write)
    resp = T.rent_policy.get_item(Key={"pk": pk, "sk": _SK_CURRENT})
    before_item = resp.get("Item")
    before_snap = None
    if before_item is not None:
        before_snap = {
            "rent_due_day":      int(before_item.get("rent_due_day", 1)),
            "late_fee_cents":    int(before_item.get("late_fee_cents", 0)),
            "grace_period_days": int(before_item.get("grace_period_days", 0)),
            "currency":          str(before_item.get("currency", "usd")),
        }

    after_snap = {
        "rent_due_day": rent_due_day,
        "late_fee_cents": late_fee_cents,
        "grace_period_days": grace_period_days,
        "currency": currency_norm,
    }

    # Write CURRENT row (full replace, mirrors billing_config.py:354-361)
    T.rent_policy.put_item(Item={
        "pk": pk,
        "sk": _SK_CURRENT,
        "rent_due_day":      Decimal(str(rent_due_day)),
        "late_fee_cents":    Decimal(str(late_fee_cents)),
        "grace_period_days": Decimal(str(grace_period_days)),
        "currency":          currency_norm,
        "updated_at":        Decimal(str(now)),
        "updated_by":        str(actor_sub),
    })

    # Write AUDIT row (always append, even for identical values)
    T.rent_policy.put_item(Item={
        "pk": pk,
        "sk": f"{_SK_AUDIT_PREFIX}{now:010d}#{event_id}",
        "actor_sub":  str(actor_sub),
        "before":     before_snap,
        "after":      after_snap,
        "created_at": Decimal(str(now)),
    })

    invalidate_cache(owner_sub)
    _audit("rent_policy.updated", actor_sub, owner_sub=owner_sub, **after_snap)

    return get_policy(owner_sub)


def _validate_policy(
    rent_due_day: int,
    late_fee_cents: int,
    grace_period_days: int,
    currency: str,
) -> None:
    """Raise ValueError on invalid inputs (router converts to 422)."""
    if not (1 <= int(rent_due_day) <= 28):
        raise ValueError("rent_due_day must be between 1 and 28 inclusive")
    if int(late_fee_cents) < 0:
        raise ValueError("late_fee_cents must be >= 0")
    if int(grace_period_days) < 0:
        raise ValueError("grace_period_days must be >= 0")
    c = str(currency).strip()
    if len(c) != 3 or not c.isalpha():
        raise ValueError("currency must be a 3-letter ISO 4217 code")


def list_policy_audit(
    owner_sub: str,
    *,
    limit: int = 50,
    cursor: Optional[str] = None,
) -> Dict[str, Any]:
    """Return change history for owner_sub, newest-first.

    Mirrors billing_config.get_audit_log (app/services/billing_config.py:488-508).
    """
    _require_enabled()
    limit = max(1, min(int(limit), 200))
    kwargs: Dict[str, Any] = {
        "KeyConditionExpression": Key("pk").eq(_owner_pk(owner_sub))
            & Key("sk").begins_with(_SK_AUDIT_PREFIX),
        "ScanIndexForward": False,
        "Limit": limit,
    }
    if cursor:
        decoded = decode_cursor(cursor)
        if decoded:
            kwargs["ExclusiveStartKey"] = decoded

    resp = T.rent_policy.query(**kwargs)
    items = resp.get("Items", [])
    next_cursor = encode_cursor(resp.get("LastEvaluatedKey")) if resp.get("LastEvaluatedKey") else None

    entries = [
        {
            "actor_sub":  item.get("actor_sub", ""),
            "before":     item.get("before"),
            "after":      item.get("after"),
            "created_at": int(item.get("created_at", 0)),
        }
        for item in items
    ]
    return {"entries": entries, "count": len(entries), "cursor": next_cursor}


def _audit(event: str, user_sub: str, **fields: Any) -> None:
    try:
        from app.services.alerts import audit_event
        audit_event(event, user_sub or "system", None, **fields)
    except Exception:
        pass
```

## 5. Detailed Behavior & Edge Cases

### 5.1 Effective default (no stored policy)

`get_policy(owner_sub)` where no `CURRENT` row exists returns:
```json
{
  "rent_due_day": 1,
  "late_fee_cents": 0,
  "grace_period_days": 0,
  "currency": "<S.default_currency>",
  "updated_at": null,
  "updated_by": null,
  "is_default": true
}
```
This mirrors the `billing_config` "override-or-env" contract (`:3-7`). `is_default: true`
is a read-only signal — it cannot be set via `PUT`.

### 5.2 Validation rules

All validation is performed in `_validate_policy` before any DDB write. Failures raise
`ValueError`, which the router converts to HTTP 422:

| Field | Constraint | Error message |
|-------|-----------|---------------|
| `rent_due_day` | `1 <= x <= 28` | `"rent_due_day must be between 1 and 28 inclusive"` |
| `late_fee_cents` | `x >= 0` | `"late_fee_cents must be >= 0"` |
| `grace_period_days` | `x >= 0` | `"grace_period_days must be >= 0"` |
| `currency` | 3-letter alpha, case-insensitive | `"currency must be a 3-letter ISO 4217 code"` |

`rent_due_day` is capped at 28 (not 31) to avoid invalid dates in February for any year;
leases due on the 1st and unpaid through the 28th covers all months safely. Day 29, 30,
31 → 422.

Pydantic `RentPolicyUpdateIn` enforces `ge=1, le=28` and `ge=0` at the model level
(the first validation layer). `_validate_policy` is the second, service-layer defence.

### 5.3 Audit row semantics

An AUDIT row is written on **every** `set_policy` call, including calls where the new
values are identical to the previous ones. This contrasts with `billing_config`, which
skips audit rows on no-op updates (`:345-352`). The rationale: a landlord's policy audit
trail should be tamper-evident and capture every admin action, not just net changes.
PMD-005 E2E tests assert that two consecutive identical PUTs produce two audit rows.

The `before` field is `None` on the first-ever write (no previous row). Subsequent writes
capture the prior CURRENT snapshot. This is stored as a DynamoDB Map (`M`) attribute.

### 5.4 Cache semantics

The per-owner in-memory dict `_cache` uses a short TTL (`rent_policy_cache_ttl_seconds`,
default 60 s) identical to `billing_config._cache_ttl()` (`:51`). On `set_policy`, the
owner's cache entry is dropped immediately (`invalidate_cache(owner_sub)`) so the
subsequent `get_policy` at the end of `set_policy` reads fresh from DDB. The cache is
not shared across uvicorn workers — this is deliberate, matching the single-worker dev
constraint (CLAUDE.md "moto S3 workers: Run uvicorn with `--workers 1` in dev mode").

### 5.5 Lease inheritance hook

`app/services/rent_policy.py` exports `get_policy(owner_sub) -> dict`. LSE
`create_lease` (LEASES_TICKETS §LSE-001) should call this at lease creation time to
default unset `rent_due_day`, `late_fee_cents`, and `grace_period_days`:

```python
try:
    from app.services import rent_policy as _rp
    if _rp._flag_on():
        defaults = _rp.get_policy(owner_sub)
        rent_due_day     = rent_due_day     or defaults["rent_due_day"]
        late_fee_cents   = late_fee_cents   or defaults["late_fee_cents"]
        grace_period_days = grace_period_days or defaults["grace_period_days"]
        currency          = currency          or defaults["currency"]
except Exception:
    pass   # PMD-001 not yet deployed — silently skip
```

This is a one-liner addition in LSE; PMD-001 does not hard-depend on LSE and LSE does
not hard-depend on PMD-001. The call site is guarded by `_flag_on()` so it is inert when
`PROPERTY_DASHBOARD_ENABLED=false` even if LSE is deployed before PMD-001.

### 5.6 Flag-off behavior

When `PROPERTY_DASHBOARD_ENABLED=false`, every public function raises:
```
HTTPException(status_code=404, detail="Property dashboard is not enabled")
```
No DDB call is made. The `rent_policy` table may not even exist when the flag is off —
this is safe because `_require_enabled()` short-circuits before any table access.

### 5.7 Currency normalization

All input `currency` values are lower-cased before storage and returned lower-cased in
all read responses, matching `S.default_currency = "usd"`. The Pydantic validator
`_currency_alpha` strips whitespace and calls `.lower()`. Comparison in LSE and RNT
should always normalize before comparing.

### 5.8 Admin vs. owner access

`GET /ui/rent-policy` and `GET /ui/rent-policy/audit` are available to any authenticated
user via `require_ui_session` — a non-admin landlord can read their own policy and audit
log. `PUT /ui/rent-policy` requires `require_admin_or_root_csrf`, meaning only admins and
root can write policy values on behalf of (or as) the session owner. The admin endpoints

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### 7.1 SECOPS-007 — no `if S.dev_mode` branch

`app/services/rent_policy.py` contains zero `if S.dev_mode` or `if S.property_dashboard_enabled`
branches inside business logic. The single flag check is `_require_enabled()` at function
entry. The same DDB code path (`T.rent_policy.get_item`, `put_item`, `query`) runs in dev
(DynamoDB Local on port 8001 via `DDB_ENDPOINT_URL=http://localhost:8001`) and in prod
(real DynamoDB). `app/core/dev_s3.py` intercepts S3 calls only — it does not mock
DynamoDB. No mock return path exists. This matches `billing_config.py` and
`platform_financial_dashboard.py`, both cited as SECOPS-007 compliant in the
POLICY_DOCS_DASHBOARD_TICKETS.md §"Dev/prod parity".

### 7.2 Money-safety constraints

PMD-001 is **not a payment path**. It stores configuration, not money. No cents move
through `new_ledger_entry` (`app/services/billing_shared.py:224`), `settle_or_reverse_ledger`
(`:262`), `apply_balance_delta`, or any Stripe/PayPal/CCBill SDK call. The `late_fee_cents`
and `currency` values are read-only metadata that downstream rent-charge creation (RNT
cluster) reads via `get_policy` to stamp onto new ledger entries.

The money-safety guarantee is: `get_policy` is a pure read (never writes). `set_policy`
writes only to `T.rent_policy` (config table). No billing table (`T.billing`) row is
touched, no BALANCE row is updated, no LEDGER row is written. The `_validate_policy`
non-negative check on `late_fee_cents` ensures RNT can never inherit a negative fee that
would corrupt ledger arithmetic.

### 7.3 Idempotency

`PUT /ui/rent-policy` is not idempotent in the audit-log sense (two identical PUTs
produce two AUDIT rows — by design, §5.3). It is idempotent in the **state** sense:
two identical PUTs leave the CURRENT row in the same state. The CURRENT row is replaced
wholesale; there is no conditional write, so a retry cannot fail. The AUDIT rows are
keyed on `{ts}#{event_id}` where `event_id` is a random hex suffix — retries produce
separate audit rows, which is the intended behavior (full write history).

### 7.4 Cross-user isolation

Every DDB operation in `rent_policy.py` is scoped to `pk = "POLICY#{owner_sub}"`. There
is no cross-owner scan; no GSI query returns rows from other owners. An admin calling
`PUT /ui/rent-policy/{owner_sub}` writes to `POLICY#{owner_sub}`, not to their own
partition. Cache invalidation is keyed on `owner_sub`, so a write to owner A does not
evict owner B's cache entry.

## 8. Backward Compatibility & Migration

### 8.1 Additive only — no existing table or code is modified

PMD-001 introduces one new DDB table (`rent_policy`), two new settings fields
(`property_dashboard_enabled`, `rent_policy_table_name`), one new Tables field
(`rent_policy`), one new service module, one new router, and four new Pydantic models.
It does not modify any existing file except `app/core/settings.py` (additive field),
`app/core/tables.py` (additive field + T constructor entry), `app/models.py` (additive
models), `app/main.py` (additive router registration), and
`scripts/local-ddb-init.py` (additive `TableDef`).

No existing API endpoint, existing database table, or existing service function is
changed. With `PROPERTY_DASHBOARD_ENABLED=false` (the default), the platform is
byte-for-byte unchanged in behavior.

### 8.2 Table creation

`scripts/local-ddb-init.py` is re-run (`just restart`) to create the `rent_policy` table
in dev. In production, `create_table` is called once by the deployment pipeline before the
new code is deployed. The table creation is idempotent (the init script catches
`ResourceInUseException`). Existing `billing`, `billing_config`, and other tables are not
touched.

### 8.3 No data migration

There is no existing `rent_policy` data to migrate (the entity is greenfield). No backfill
is required. Owners with no stored policy receive effective defaults automatically from
`get_policy`.

### 8.4 LSE backward compatibility

The LSE inheritance hook (§5.5) is opt-in: LSE guards the import with `try/except` and
checks `_flag_on()`. If PMD-001 has not been deployed, the `try/except` catches the
`ImportError` and LSE continues with whatever defaults its caller provides. If PMD-001 is
deployed but the flag is off, `_flag_on()` returns `False` and the call is skipped.

## 10. Open Questions / Assumptions

1. **Should `GET /ui/rent-policy` be accessible to non-admin landlords?** The current
   design allows any authenticated user to read their own policy (USER role, via
   `require_ui_session`). This is intentional: a landlord should be able to see the
   policy that governs their leases. If the platform decides policy is admin-only
   metadata, both GET endpoints should be promoted to `require_admin_or_root_csrf`.
   *Assumption: landlords can read their own policy; only admins can write it.*

2. **`rent_due_day` range 1–28 vs. 1–31.** The spec caps at 28 for February safety.
   Alternative: allow 1–31 and have the rent-run timer clamp to the last day of the month
   when the month is shorter. *Assumption: cap at 28 (simpler, no clamp logic in RNT).*

3. **Multi-currency leases under one policy.** A landlord with properties in different
   countries may need per-property or per-unit currency overrides, not just a global owner
   default. PMD-001 provides only an owner-level default; the RNT cluster is free to
   override `currency` at lease creation. *Assumption: owner-level default is sufficient
   for PMD-001; per-property overrides are deferred to RNT.*

4. **Cache size bound.** The per-process `_cache` dict grows by one entry per distinct
   `owner_sub`. For a large multi-tenant platform with many landlords, this could grow
   unboundedly. *Assumption: acceptable for the property management vertical (typical
   deployment has O(100s) of landlords, not millions). An LRU bound can be added in a
   follow-up if needed.*

5. **Concurrent `set_policy` calls from two admins.** The current design uses
   `put_item` unconditionally (last writer wins). This is consistent with `billing_config`
   which also lacks optimistic locking. *Assumption: acceptable; the audit log provides
   a complete history of writes so no data is silently lost.*
