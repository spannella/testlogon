## 1. Summary & Goal

HTL-036 is the **final ticket** in the Tier-3 cancellation/no-show + reports + tax/currency
cluster. It is a thin wiring-and-presentation ticket that ships four things and re-implements
none of the heavy machinery underneath it:

1. **Tax + multi-currency wire-in** into the folio/invoice computation owned by HTL-029/031.
   The tax registry (`docs/suitecrm/specs/INV-005.md` named tax groups + INV-006 per-line tax)
   and the currency registry (`docs/suitecrm/specs/INV-002.md` registry + INV-003 transaction
   conversion + INV-004 invoice-currency display) are **unimplemented design specs** at the time
   of this cluster. HTL-036 therefore *consumes-or-implements-minimally*: it adds a narrow,
   double-flag-gated block that calls the INV accessors via a lazy `try/except` import and, when
   either flag is off OR the accessor raises (registry absent), falls back to the exact behaviour
   the codebase has today — flat `S.invoices_tax_bps` (`app/core/settings.py:2569`) and an opaque
   currency string (`app/services/invoices.py:334`). The wire-in is a no-op by default and lights
   up automatically when the INV tickets land.

2. **Cancellation-policy editor frontend** — a React Hook Form + Zod form
   (`CancellationPolicyEditor.tsx`) surfaced as a section/tab on the existing HotelDetailPage
   (HTL-004), admin-only edit, wired to the HTL-034 policy CRUD endpoints.

3. **KPI dashboard frontend** — `HotelReportsPage.tsx` under `/hotels/:hotelId/reports`: a
   date-range picker + occupancy/ADR/RevPAR/revenue summary **cards** and recharts charts
   (occupancy-over-time area chart + ADR/RevPAR bar chart), reusing the recharts dependency
   already present (`recharts ^3.8.1`, `frontend/package.json:67`; usage at
   `frontend/src/pages/earnings/EarningsPage.tsx:10-19`), wired to the HTL-035 `/reports/kpis`
   endpoint.

4. **Tests** — a hermetic offline pytest `tests/test_htl_cancellation_reports.py` covering the
   whole HTL-033/034/035 cluster (refund tiers, no-show fee, idempotency, inventory release, KPI
   math, tax/currency wiring, flag-off 404) and an E2E spec `frontend/e2e/hotel-reports.spec.ts`
   (admin upserts a policy, cancels a reservation, marks a no-show, loads the KPI dashboard).

With `HOTEL_PMS_ENABLED=false` (the default, introduced by HTL-001 next to the inventory block
at `app/core/settings.py:839-841`) the entire vertical is a 404 no-op: both frontend pages are
reachable (routes registered unconditionally) but every API call returns 404 and the pages render
a "Hotel PMS is not enabled" callout. With the INV sub-flags off (their default) the tax/currency
wire-in is also a no-op, so HTL-036 ships and passes its tests **with the INV registries entirely
absent**. The platform is byte-for-byte unchanged when all flags are off.

cancellation policy is the `CANCELPOLICY#{policy_id}` child row on the `hotels` partition (owned by

## 4. API / Service Design

### 4.1 Tax wire-in (folio/invoice computation, owned by HTL-029/031)

The wire-in is a narrow flag-gated block inside the folio total computation. Reference shape
(the actual edit lands in the HTL-029/031 folio/invoice service; HTL-036 owns the wiring):

```python
def _resolve_tax_cents(amount_cents: int, *, tax_rate_id: str | None,
                       tax_rate_name: str | None) -> int:
    """Resolve tax for a folio/invoice amount.

    Double-guarded (INV-005 §5.7): the registry accessor is consulted ONLY when both the
    INV-005 master flag and the INV-006 per-line sub-flag are on, AND the lazy import +
    accessor call succeed. Any miss → flat-bps fallback (today's behaviour).
    """
    if getattr(S, "crm_tax_rates_enabled", False) and getattr(S, "aos_per_line_tax_enabled", False):
        try:
            from app.services import crm_tax_rates  # lazy: registry may not exist
            rate = (crm_tax_rates.get_tax_rate_by_name(tax_rate_name)
                    if tax_rate_name else crm_tax_rates.get_tax_rate(tax_rate_id))
            bps = int(rate["rate_bps"])            # INV-005 stores integer bps
            return (amount_cents * max(0, bps)) // 10_000
        except Exception:
            pass  # registry absent / disabled / lookup miss → fall through
    # Fallback: exactly app/services/invoices.py:306
    return (amount_cents * max(0, S.invoices_tax_bps)) // 10_000
```

- `crm_tax_rates.get_tax_rate` / `get_tax_rate_by_name` are the INV-005 §4.1 accessors.
- Tax bps are integer basis points (cross-cutting "Money-as-cents", `:51-54`;
  `docs/suitecrm/specs/INV-005.md`). `// 10_000` matches `invoices.py:306`.
- With the INV flags off (default) this is **byte-for-byte** the flat-bps line that exists today.

### 4.2 Currency wire-in (folio/invoice computation)

```python
def _resolve_currency_amount(amount_cents: int, folio_currency: str,
                             platform_currency: str = "usd") -> tuple[int, str, int]:
    """Returns (display_amount_cents, original_currency, usd_amount_cents).

    Convert ONLY when CRM_CURRENCIES_ENABLED + the INV-003 conversion sub-flag are on and the
    folio currency differs from the platform default. Otherwise store the opaque currency string
    with no conversion (today's behaviour, app/services/invoices.py:334). Round to integer cents
    at the boundary (cross-cutting :51-54; FX rate_to_usd is Decimal, INV-002 :57).
    """
    iso = (folio_currency or platform_currency).lower()
    if (getattr(S, "crm_currencies_enabled", False)
            and getattr(S, "aos_invoice_currency_conversion_enabled", False)
            and iso != platform_currency):
        try:
            from app.services import crm_currencies  # lazy: registry may not exist
            usd = crm_currencies.convert_amount(amount_cents, iso, platform_currency)  # INV-003 :83
            return amount_cents, iso, int(usd)
        except Exception:
            pass
    # Fallback: opaque currency, no conversion (invoices.py:334)
    return amount_cents, "", amount_cents
```

- `convert_amount` is the INV-003 `:83` accessor (which itself wraps INV-002 `get_exchange_rate`).
- The returned `original_currency` / `usd_amount_cents` map onto the additive folio fields (§3),
  which default to `""` / the unconverted amount when the flag is off.

## 5. Detailed Behavior & Edge Cases

### 5.1 `CancellationPolicyEditor.tsx`

A section/tab on HotelDetailPage. `useQuery(["hotel", hotelId, "cancellation-policy"], …)` loads the
current policy; the form pre-populates from it (or from sensible defaults when none exists yet — a
404 from `getCancellationPolicy` is treated as "no policy set", not an error). React Hook Form + Zod:

```typescript
const policySchema = z.object({
  free_until_days_before: z.coerce.number().int().min(0).max(3650),
  penalty_mode: z.enum(["pct", "fixed"]),       // UI-only mutually-exclusive toggle
  penalty_pct: z.coerce.number().int().min(0).max(100),
  penalty_fixed_cents: z.coerce.number().int().min(0),
  no_show_fee_cents: z.coerce.number().int().min(0),
});
```

- **Mutually-exclusive penalty toggle**: a radio/segmented control picks `pct` or `fixed`. On
  submit the inactive field is zeroed so the backend sees a single source of truth
  (`penalty_fixed_cents > 0` takes precedence in HTL-033, `:124-127`). When `fixed` is selected,
  `penalty_pct` is sent as `0`; when `pct` is selected, `penalty_fixed_cents` is sent as `0`.
- **cents ↔ currency display**: `penalty_fixed_cents` and `no_show_fee_cents` render in a
  currency input (the user types dollars, the form stores cents) using the canonical `formatCents`
  helper (pattern `frontend/src/pages/Dashboard.tsx:30-35`) for the read-only display and a
  `* 100` round on input.
- **Admin-only edit**: the form is read-only for non-admin sessions. Role is decoded from the JWT
  via `getRoleFromAccessToken(useAuthStore(s => s.accessToken))` from `@/lib/adminCapabilities`
  (the established pattern, `frontend/src/pages/tickets/TicketsPage.tsx:43-44`; `useAuthStore` has
  NO `role` field — PROP-005 §7.3 correction). Non-admins see the values but the "Save" button is
  hidden; the backend `require_admin_or_root_csrf` (`app/auth/policy.py:100`) is the authoritative
  gate (403 for non-admins).
- **Save**: `useMutation(putCancellationPolicy)`, `onSuccess` → invalidate the policy query +
  `toast.success("Cancellation policy saved")`; `onError` → `toast.error(err.detail)`. The submit
  button is disabled while `isPending` (double-submit guard).
- **Flag-off**: a 404 on load OR save renders a "Hotel PMS is not enabled" inline callout.

### 5.2 `HotelReportsPage.tsx`

`useParams<{ hotelId: string }>()` extracts `hotelId`.

- **Date-range picker**: two date inputs (`from` / `to`) defaulting to the trailing 30 days
  (`to = today`, `from = today - 30d`). The values are converted to Unix-second timestamps
  (`now_ts` parity) and passed to `getHotelKpis(hotelId, from, to)` via
  `useQuery(["hotel", hotelId, "kpis", { from, to }], …)`. Changing either input changes the query
  key → React Query refetches.
- **Client-side range validation**: the page disables the query (or shows an inline message) when
  `to <= from` or the span exceeds 366 days, mirroring the backend 422 guard (HTL-035 `:373`); the
  backend remains the authoritative validator (422).
- **Summary cards** (shadcn/ui `<Card>` grid, `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`):
  - **Occupancy** — `kpis.occupancy_pct.toFixed(1) + "%"`.
  - **ADR** — `formatCents(kpis.adr_cents, kpis.currency)`.
  - **RevPAR** — `formatCents(kpis.revpar_cents, kpis.currency)`.
  - **Room Revenue** — `formatCents(kpis.room_revenue_cents, kpis.currency)`.
  - secondary line under the cards: `rooms_sold` / `rooms_available` room-nights, `arrivals`,
    `departures`.
- **Charts** (recharts, reusing `frontend/src/pages/earnings/EarningsPage.tsx:10-19` imports):
  - **Occupancy over time** — an `<AreaChart>` of daily occupancy. MVP: the `/reports/kpis`
    endpoint returns range totals, so the occupancy area chart plots a single-window value or a
    per-bucket series IF HTL-035 returns a daily breakdown (§10 Q3). When only the aggregate is
    available, the chart degrades gracefully to a one-bar/one-point summary; the cards remain the
    primary surface (acceptance criterion is "cards + charts render", `:507-509`).
  - **ADR / RevPAR bars** — a `<BarChart>` with two bars (ADR, RevPAR) for the selected window
    (`<Bar dataKey="adr">`, `<Bar dataKey="revpar">`), values in dollars (cents/100).
  - All charts wrapped in `<ResponsiveContainer>`.
- **Money formatting**: all cents fields render via a local `formatCents` (pattern
  `Dashboard.tsx:30-35`), using `kpis.currency` so a non-USD hotel shows its own symbol.
- **Loading**: `<Skeleton>` placeholders for cards + a chart placeholder while the query is
  pending.
- **Flag-off / 404**: a centered "Hotel PMS is not enabled, or hotel not found." callout with a
  "Back to Hotel" link.
- **Empty range**: a range with no reservations returns zero KPIs from HTL-035 (no division by
  zero — `occupancy_pct=0`, `adr_cents=0`, `revpar_cents=0`, `:340,342,343`); the cards render
  zeros and the charts render an empty/zero state, never an error.

### 5.3 Cancel / no-show actions (reservation list, HTL-034 wiring)

The cancel and no-show buttons live on the reservation row/detail (owned by the HTL reservation FE,
referenced here as the consumer of `cancelReservation`/`markNoShow`). On confirm:

- **Cancel** → `POST .../cancel` → shows the refund outcome (`penalty_cents` / `refundable_cents` /
  `released_nights`) in a toast/dialog and updates the row status. Idempotent: a second cancel on a
  terminal reservation returns the stored outcome (no second refund, HTL-033 `:143-144`,
  HTL-034 `:301-302`).
- **No-show** → `POST .../no-show` → shows `no_show_fee_cents` charged; idempotent on replay.
- Both invalidate `["hotel", hotelId, "kpis"]` so the dashboard reflects the cancelled room-nights.

### 5.4 Penalty edge cases surfaced in the UI

The editor's helper text spells out the HTL-033 semantics so admins understand the math:
`free_until_days_before` is "days before check-in for a full refund"; `penalty_fixed_cents` (when
set) "overrides the percentage"; the penalty is "clamped between zero and the room base"
(HTL-033 `:124-129`). The UI does not re-implement the math — it is computed server-side by
HTL-033 and only displayed.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### 7.1 SECOPS-007 — no dev-mode branches

Zero `if S.dev_mode` branches in the tax/currency wire-in or anywhere in this cluster
(`CANCELLATION_REPORTS_TICKETS.md:75-78`). The same `T.*` handles are used in both environments
(DynamoDB Local on port 8001 via `DDB_ENDPOINT_URL` in dev, real DynamoDB in prod). The
billing/refund path is identical dev↔prod (OFB-010 §7). The double-flag-gate is a *feature* flag,
not an environment branch — both flags read the same `S` in both envs.

### 7.2 ONE refund mechanism — never fork

All cancellation/no-show refunds and fees go through the existing billing-ledger primitives used by
both `refund_payment` (`app/routers/billing.py:1287`; ledger calls at `:1306-1324` —
`new_ledger_entry`+`apply_balance_delta`+`settle_or_reverse_ledger`, `reason="refund"`,
`provider="stripe"`) and RMA `refund_return`
(OFB-010 §4) — exactly one `type="adjustment", reason="refund"` ledger entry with a `provider`
field for FIN-013 attribution (`CANCELLATION_REPORTS_TICKETS.md:43-50`). The no-show fee is a normal
charge/debit ledger entry. HTL-036 does not touch this path directly — it is exercised by HTL-033 —
but the test suite (this ticket) asserts the single-entry invariant.

### 7.3 Idempotency

- **Cancel/no-show**: HTL-033 guards on the stored `cancellation_ledger_sk` / `no_show_ledger_sk`
  token (`:143-144`); a replay returns the stored outcome and posts no second ledger row
  (single-write token, OFB-010 §5). The pytest asserts a single billing entry after two calls.
- **Policy save**: `putCancellationPolicy` is a full-replace upsert of the `CANCELPOLICY#` child
  row; repeated saves with the same body are no-ops on the persisted shape. The FE disables the
  submit button while `isPending`.
- **Tax/currency wire-in**: the accessor consume is read-only and side-effect-free; it never writes
  to the INV registries and is safe to call repeatedly.

### 7.4 Security — admin-only mutations, CSRF

Reads (`getCancellationPolicy`, `getHotelKpis`) → `require_ui_session` (`app/services/sessions.py`).
Mutations (`putCancellationPolicy`, `cancelReservation`, `markNoShow`) →
`require_admin_or_root_csrf` (`app/auth/policy.py:100`) — the auth split from
`CANCELLATION_REPORTS_TICKETS.md:72-74`. The client injects `X-CSRF-Token` automatically
(`frontend/src/api/client.ts`); E2E `page.request` calls send `x-csrf-token` explicitly. The FE
hides mutation controls from non-admins (role decoded from JWT, §5.1) but the backend 403 is
authoritative.

### 7.5 Money-safety — integer cents, Decimal FX, rounding at the boundary

All amounts are integer cents (`penalty_cents`, `refundable_cents`, `no_show_fee_cents`,
`room_revenue_cents`, `adr_cents`, `revpar_cents`, `penalty_fixed_cents`). Tax bps are integer
basis points (`// 10_000`). FX uses `Decimal rate_to_usd` (INV-002 `:57`) and `convert_amount`
returns an `int` rounded to cents at the boundary (INV-003 `:83`); HTL-036 wraps it in `int(...)`
defensively. No float arithmetic on money. ADR/RevPAR use integer floor division
(`room_revenue // rooms_sold`, `room_revenue // rooms_available`, HTL-035 `:342-343`) with
`max(…, 1)` denominators (never divide by zero). The FE only divides cents by 100 for display
(`formatCents`).
