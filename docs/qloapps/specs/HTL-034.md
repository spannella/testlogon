# HTL-034 — Cancellation policy CRUD + reservation cancel/no-show router wiring

**Type**: Feature | **Priority**: P1 | **Estimate**: 1.5d
**Source**: `docs/qloapps/CANCELLATION_REPORTS_TICKETS.md` §HTL-034 + "Cross-cutting constraints" (`:32`) + `docs/qloapps/QLOAPPS_GAP_ANALYSIS.md` §"Cancellation policies + refunds"

---

## 1. Summary & Goal

HTL-034 makes the cancellation/no-show **policy** a first-class, persisted, admin-editable entity and connects it to
the live reservation lifecycle. It delivers exactly three things:

1. **A persisted cancellation policy** — a `CANCELPOLICY#{policy_id}` child row co-located on the existing `hotels`
   partition (HTL-001), with the four economic levers (`free_until_days_before`, `penalty_pct`,
   `penalty_fixed_cents`, `no_show_fee_cents`). No new DynamoDB table — the header+child idiom (FAC-001 §3,
   `docs/ofbiz/specs/FAC-001.md`; PROP-001 §3; HTL-001 §3.1) means the policy lives on the same partition as the hotel
   `META` row and the HTL-002 `AMEN#` amenity rows.
2. **Three service functions** in the existing `app/services/hotel_cancellation.py` (the HTL-033 file):
   `upsert_cancellation_policy`, `get_cancellation_policy`, and `resolve_policy_for_reservation` — the CRUD + the
   scope-resolution helper the transitions call.
3. **Router wiring** — two new policy endpoints (`GET`/`PUT /ui/hotels/{hotel_id}/cancellation-policy`) and the
   **enhancement** of the two already-shipped HTL-020 lifecycle handlers (`POST .../cancel`, `POST .../no-show`) so that
   after the HTL-019 FSM transition succeeds, they resolve the policy and call the matching HTL-033 engine function
   (`apply_cancellation` / `apply_no_show`), then back-write the returned ledger SK onto the reservation header.

The design splits cleanly along the cross-cutting "reuse primitives, never fork" rule. The **math and the refund/fee
orchestration** are entirely HTL-033's (`compute_cancellation_refund`, `apply_cancellation`, `apply_no_show` — the only
code that touches the billing ledger). HTL-019 owns the **status FSM** (the `version`-CAS transition that is the
idempotency token). HTL-034 owns only **persistence of the policy** and the **glue** that calls (FSM → engine →
back-write) in the right order with the right idempotency contract. No money path is re-implemented: every refund is the
one `type="adjustment", reason="refund"` ledger entry HTL-033 posts via `new_ledger_entry` /
`apply_balance_delta` / `settle_or_reverse_ledger` (`app/services/billing_shared.py:224,83,262`) — the exact sequence
`refund_payment` (`app/routers/billing.py:1287,1306-1324`) and RMA `refund_return` (`docs/ofbiz/specs/OFB-010.md` §4)
use.

The hard invariants: **one policy per scope** (deterministic `policy_id`, conditional upsert-in-place, no duplicates),
**the policy wins by scope precedence** (rate-plan-scoped → hotel default → implicit zero-penalty default), and **no
double refund** (the FSM `version`-CAS is the first idempotency gate; HTL-033's stored-`cancellation_ledger_sk` guard is
the second). With `HOTEL_PMS_ENABLED=false` (the default) every endpoint — the two new policy routes and the enhanced
cancel/no-show routes — raises HTTP 404 before any DynamoDB access; the router is still mounted and the platform is
byte-for-byte unchanged.

## 2. Context & Current State

### 2.1 Gap — policy is not persisted, refunds are not wired

The gap analysis records **"cancellation policies + refunds"** as a hospitality-spine gap
(`docs/qloapps/QLOAPPS_GAP_ANALYSIS.md` §Headline: "cancellation policies + refunds" listed among the net-new
hospitality features). HTL-033 lands the *engine* (the math + the side-effect orchestration) but it takes an
*already-resolved* policy dict and an *already-loaded* reservation dict as inputs — it persists nothing and reads
nothing about which policy applies (`docs/qloapps/CANCELLATION_REPORTS_TICKETS.md` §HTL-033: "reads an already-resolved
policy dict + an already-loaded reservation dict (both supplied by the HTL-034 caller)"). HTL-020 lands the
`POST .../cancel` and `POST .../no-show` lifecycle routes, but they currently **only** run the HTL-019 FSM transition
(which releases held inventory) and "write **no ledger entry / issue no refund** (HTL-033 owns refunds)"
(`docs/qloapps/specs/HTL-020.md:314,318`; HTL-019 §1: "cancel / no-show release held inventory and record the transition
but issue **no refund** … the cancellation/no-show **refund + penalty** engine is **HTL-033**",
`docs/qloapps/specs/HTL-019.md:44-47`).

So three things are missing today and are HTL-034's deliverables: (a) **where the policy lives** (a persisted row +
its CRUD), (b) **which policy applies to a given reservation** (scope resolution), and (c) **the glue** that calls the
engine after the FSM transition and persists the idempotency token. `grep -rn "upsert_cancellation_policy\|
resolve_policy_for_reservation\|CANCELPOLICY#\|cancellation-policy" app/` returns nothing today.

### 2.2 What HTL-033 provides (the engine HTL-034 calls)

HTL-033 (`docs/qloapps/CANCELLATION_REPORTS_TICKETS.md` §HTL-033) lands `app/services/hotel_cancellation.py` with:

- `compute_cancellation_refund(reservation, policy, now=None) -> dict` — pure/deterministic; returns
  `{base_cents, penalty_cents, refundable_cents, days_to_checkin}`.
- `apply_cancellation(reservation, policy, *, actor_sub, provider="stripe", now=None) -> dict` — `_require_enabled()`,
  the **stored-`cancellation_ledger_sk` idempotency guard**, `compute_cancellation_refund`, best-effort per-night
  HTL-011 `release_hold`, **exactly one** `type="adjustment", reason="refund"` ledger entry (only when
  `refundable_cents > 0`), `apply_balance_delta(... payments_settled_cents=-refundable)`, best-effort
  `settle_or_reverse_ledger` of the original charge, `_audit("hotel.reservation.cancelled", ...)`, and a return dict
  `{"reservation_id", "penalty_cents", "refundable_cents", "refund_ledger_sk", "released_nights"}`.
- `apply_no_show(reservation, policy, *, actor_sub, provider="stripe", now=None) -> dict` — `_require_enabled()`, the
  **stored-`no_show_ledger_sk` idempotency guard**, exactly one `reason="no_show_fee"` charge entry of
  `no_show_fee_cents` (none when the fee is 0), `apply_balance_delta(... payments_settled_cents=+fee)`,
  `_audit("hotel.reservation.no_show", ...)`, and a return dict `{"reservation_id", "no_show_fee_cents",
  "no_show_ledger_sk"}`.

Critically, HTL-033's engine **does NOT mutate reservation status** and **does NOT persist the ledger SK back onto the
reservation** — it returns the SK so HTL-034's router can do both (the FSM flip is HTL-019; the back-write is HTL-034 step
4). HTL-034 adds its three functions **to this same file** (`hotel_cancellation.py`) and reuses HTL-033's
`_flag_on()` / `_require_enabled()` / `_audit()` helpers (copied from `inventory.py:50,54,92`).

## 3. Data Model

HTL-034 introduces **no new DynamoDB table, no new GSI, and no new `attr_types`** (the cross-cutting constraint: "This
cluster adds no new tables, so no new `attr_types`", `CANCELLATION_REPORTS_TICKETS.md` §Cross-cutting). The policy is a
child row on the existing `hotels` partition (HTL-001 §3.1). The reservation back-write reuses existing
`hotel_reservations` header fields. This section documents the policy row, the resolution rule, and the I/O models.

### 3.1 Policy row: `CANCELPOLICY#{policy_id}` on the `hotels` partition

| Attribute | Type | Notes |
|---|---|---|
| `hotel_id` | S (PK) | Same partition as the hotel `META` row (HTL-001 §3.1) |
| `sk` | S (SK) | `CANCELPOLICY#{policy_id}` — `policy_id = "default"` (per-hotel) or `RATE#{rate_plan_id}` (per-rate-plan, HTL-014, forward dep) |
| `policy_id` | S | Convenience copy of the `policy_id` segment (`"default"` or `RATE#{id}`) |
| `free_until_days_before` | N | default `0` — cancel ≥ this many days before check-in → full refund, zero penalty |
| `penalty_pct` | N | `[0,100]`, default `0` — integer percent of the refundable base inside the penalty window |
| `penalty_fixed_cents` | N | default `0`; **precedence over `penalty_pct` when `> 0`** (HTL-033 engine contract) |
| `no_show_fee_cents` | N | default `0` — the charge applied on no-show |
| `created_at` / `updated_at` | N | `now_ts()` (`app/core/time.py:2`, verified `int(time.time())`) |

**One policy per scope, no GSI.** `policy_id` is deterministic (`"default"` or `RATE#{id}`), so the read is a point
`get_item(Key={hotel_id, sk})` and the write is a conditional `update_item` / `put_item` that upserts **in place** — a
second `PUT` to the same scope overwrites, never duplicates. The `META` header, the `AMEN#` rows (HTL-002), and the
`CANCELPOLICY#` rows all share the `hotel_id` partition; a single-partition `begins_with("CANCELPOLICY#")` query could
list all policies for a hotel, but HTL-034's read path is always a point read by the resolved scope key.

> Decision (per the ticket): **child-on-hotels-partition**, not a standalone `cancellation_policies` table. The
> economics are a tiny, single-row-per-scope annotation on a hotel; co-location keeps the FAC/PROP/HTL header+child
> idiom intact and avoids a table + GSI the cluster explicitly forbids.

### 3.2 The shape the HTL-033 engine consumes

HTL-033's `compute_cancellation_refund` / `apply_cancellation` / `apply_no_show` consume a plain **policy dict** with
`free_until_days_before`, `penalty_pct`, `penalty_fixed_cents`, `no_show_fee_cents` (all int cents / int)
(`CANCELLATION_REPORTS_TICKETS.md` §HTL-033 policy table). `get_cancellation_policy` / `resolve_policy_for_reservation`
return exactly this dict (DynamoDB `Decimal` values coerced to `int` at the boundary — §5.8), so the persisted row and
the engine input are the same shape. The **implicit zero-penalty default** (`{free_until_days_before: 0, penalty_pct: 0,
penalty_fixed_cents: 0, no_show_fee_cents: 0}`) is returned when no row exists, so the engine always receives a valid
dict and an absent policy degrades to "full refund, no fee" — never an error.

### 3.3 Scope resolution (`resolve_policy_for_reservation`)

```
resolve_policy_for_reservation(reservation):
    hotel_id = reservation["hotel_id"]
    rate_plan_id = reservation.get("rate_plan_id")               # HTL-014, forward/optional
    if rate_plan_id:
        scoped = get_cancellation_policy(hotel_id, scope=f"RATE#{rate_plan_id}")
        if scoped is not None: return scoped                     # 1. rate-plan-scoped wins
    default = get_cancellation_policy(hotel_id, scope="default")
    if default is not None: return default                       # 2. hotel default
    return _ZERO_PENALTY_DEFAULT                                 # 3. implicit zero-penalty
```

Precedence (acceptance criterion): **rate-plan-scoped → hotel default → implicit zero-penalty default**. A reservation
with no `rate_plan_id`, or one whose rate plan has no scoped policy, falls through to the hotel default; a hotel with no
default policy falls through to the implicit zero-penalty dict.

### 3.4 Reservation header fields touched (back-write)

The cancel/no-show handlers back-write **one** field each onto the existing `hotel_reservations` `META` header
(no new attribute is *defined* by HTL-034 — these are the idempotency tokens HTL-033's engine guards on, owned by
HTL-033/018 as the reservation dict shape):

| Field | Type | Written by | Notes |
|---|---|---|---|
| `cancellation_ledger_sk` | S | `POST .../cancel` (after `apply_cancellation`) | the refund ledger SK; HTL-033's idempotency guard reads it |
| `no_show_ledger_sk` | S | `POST .../no-show` (after `apply_no_show`) | the fee ledger SK; HTL-033's idempotency guard reads it |

Both are written via a **best-effort `update_item`** (`Key={reservation_id, sk:"META"}`, `SET cancellation_ledger_sk =
:v`) — a back-write failure must not crash the response (the engine has already posted the ledger row; the FSM is already
terminal). They are written **only on a fresh transition**, never on a replay (which short-circuits at the FSM layer with
a 409 — §5.3).

### 3.5 I/O models (`app/models.py`)

| Model | Fields | Used by |
|---|---|---|
| `CancellationPolicyIn` | `free_until_days_before: int = Field(ge=0, default=0)`, `penalty_pct: int = Field(ge=0, le=100, default=0)`, `penalty_fixed_cents: int = Field(ge=0, default=0)`, `no_show_fee_cents: int = Field(ge=0, default=0)` | `PUT .../cancellation-policy` body |
| `CancellationPolicyOut` | the four economic fields + `hotel_id`, `policy_id`, `scope`, `created_at`, `updated_at` | `GET`/`PUT .../cancellation-policy` response |

Pydantic constraints (`ge=0`, `le=100`) are the **router-edge** validation gate → FastAPI returns **422** for an
out-of-range `penalty_pct` or a negative cents value (the `inventory.py` "router validates, service trusts" convention,
HTL-001 §5 `:392`). The service `upsert_cancellation_policy` **re-validates** defensively (a direct service caller, e.g.
a test, must still be rejected) — see §5.2. `CancellationPolicyOut` coerces DynamoDB `Decimal` → `int` (§5.8).

## 4. API / Service Design

### 4.1 Service additions — `app/services/hotel_cancellation.py` (extends the HTL-033 file)

All three functions reuse HTL-033's `_flag_on()` / `_require_enabled()` (404 when `HOTEL_PMS_ENABLED` off) and
`_audit()` (lazy-import wrapper, `inventory.py:92`). Table handle is `T.hotels` (HTL-001). `now_ts()` from
`app/core/time.py:2`.

```python
_ZERO_PENALTY_DEFAULT = {
    "free_until_days_before": 0, "penalty_pct": 0,
    "penalty_fixed_cents": 0, "no_show_fee_cents": 0,
}

def _policy_sk(policy_id: str) -> str:           # policy_id ∈ {"default", "RATE#<rate_plan_id>"}
    return f"CANCELPOLICY#{policy_id}"

def _clamp(v: int, lo: int, hi: int) -> int:
    return max(lo, min(hi, int(v)))
```

#### `upsert_cancellation_policy(...)`

```python
def upsert_cancellation_policy(
    hotel_id: str, *, scope: str = "default",
    free_until_days_before: int = 0, penalty_pct: int = 0,
    penalty_fixed_cents: int = 0, no_show_fee_cents: int = 0,
    user_sub: str,
) -> dict:
```

Steps:
1. `_require_enabled()` — 404 when the flag is off (before any DDB access).
2. **Parent + ownership** — `hotel = get_hotel(hotel_id)` (HTL-001 `:336`); `None` → `HTTPException(404, "Hotel not
   found")`; `hotel.get("owner_sub") != user_sub` → `HTTPException(404, "Hotel not found")` (ownership failures are 404,
   not 403 — do not leak existence; mirrors HTL-020's reservation `hotel_id`-mismatch 404, `HTL-020.md:325-332`).
3. **Validate** — `0 <= penalty_pct <= 100` else `HTTPException(422, "penalty_pct out of range")`; each of
   `free_until_days_before`, `penalty_fixed_cents`, `no_show_fee_cents` `>= 0` else
   `HTTPException(422, "negative cents")`.
4. **Resolve `policy_id`** — `policy_id = "default" if scope == "default" else scope` (callers pass either `"default"`
   or `"RATE#{rate_plan_id}"`); `sk = _policy_sk(policy_id)`.
5. **Upsert in place** — `T.hotels.update_item(Key={"hotel_id": hotel_id, "sk": sk}, UpdateExpression="SET
   policy_id=:pid, free_until_days_before=:f, penalty_pct=:p, penalty_fixed_cents=:pf, no_show_fee_cents=:n,
   updated_at=:u, created_at=if_not_exists(created_at, :u)", ...)` with `now=now_ts()`. `if_not_exists(created_at)`
   preserves the original `created_at` on overwrite; no `ConditionExpression` (the deterministic key *is* the
   single-policy-per-scope guarantee — a second call overwrites, never duplicates).
6. `_audit("hotel.cancel_policy.upsert", user_sub, hotel_id=hotel_id, policy_id=policy_id, penalty_pct=..., ...)`.
7. Return the resolved policy dict (`{hotel_id, policy_id, scope, free_until_days_before, penalty_pct,
   penalty_fixed_cents, no_show_fee_cents, created_at, updated_at}`).

#### `get_cancellation_policy(hotel_id, scope="default") -> dict | None`

1. `_require_enabled()`.
2. `policy_id = "default" if scope == "default" else scope`.
3. `resp = T.hotels.get_item(Key={"hotel_id": hotel_id, "sk": _policy_sk(policy_id)})`; `item = resp.get("Item")`.
4. `None` if absent (the caller falls back to a zero-penalty default); else the coerced policy dict (§5.8).

#### `resolve_policy_for_reservation(reservation) -> dict`

The §3.3 logic — rate-plan-scoped → hotel default → `_ZERO_PENALTY_DEFAULT`. Never returns `None`; never raises (it
already ran `get_cancellation_policy`, which 404s only via `_require_enabled`). Used by the cancel/no-show handlers.

### 4.2 Router endpoints

| Method | Path | Auth | Handler does |
|---|---|---|---|
| GET | `/ui/hotels/{hotel_id}/cancellation-policy` | `require_ui_session` | `get_cancellation_policy(hotel_id, scope)`; `None` → return the zero-penalty default projected as `CancellationPolicyOut` (or 404 — see §10.3) |
| PUT | `/ui/hotels/{hotel_id}/cancellation-policy` | `require_admin_or_root_csrf` | `upsert_cancellation_policy(hotel_id, scope=..., **body, user_sub=user.sub)` |
| POST | `/ui/hotels/{hotel_id}/reservations/{reservation_id}/cancel` | `require_admin_or_root_csrf` | **(enhanced HTL-020 handler)** FSM `→ cancelled`, then `apply_cancellation`, then back-write `cancellation_ledger_sk` |
| POST | `/ui/hotels/{hotel_id}/reservations/{reservation_id}/no-show` | `require_admin_or_root_csrf` | **(enhanced HTL-020 handler)** FSM `→ no_show`, then `apply_no_show`, then back-write `no_show_ledger_sk` |

Both policy endpoints accept a `scope: str = "default"` query parameter (`"default"` or `RATE#{rate_plan_id}`). The
cancel/no-show handlers take no `scope` query — the policy is resolved from the reservation
(`resolve_policy_for_reservation`).

#### Policy GET/PUT (hotels-router family — HTL-003/HTL-008 own `/ui/hotels`)

```python
@hotels_router.get("/{hotel_id}/cancellation-policy", response_model=CancellationPolicyOut)
async def get_cancellation_policy_ep(
    hotel_id: str, scope: str = "default", session=Depends(require_ui_session),
) -> CancellationPolicyOut:
    _require_enabled()
    policy = hc.get_cancellation_policy(hotel_id, scope=scope)
    if policy is None:
        policy = {**hc._ZERO_PENALTY_DEFAULT, "hotel_id": hotel_id,
                  "policy_id": "default" if scope == "default" else scope,
                  "scope": scope, "created_at": 0, "updated_at": 0}
    return CancellationPolicyOut(**policy)

@hotels_router.put("/{hotel_id}/cancellation-policy", response_model=CancellationPolicyOut)
async def put_cancellation_policy_ep(
    hotel_id: str, body: CancellationPolicyIn, scope: str = "default",
    user: AuthenticatedUser = Depends(require_admin_or_root_csrf),
) -> CancellationPolicyOut:
    _require_enabled()
    policy = hc.upsert_cancellation_policy(
        hotel_id, scope=scope,
        free_until_days_before=body.free_until_days_before,
        penalty_pct=body.penalty_pct,
        penalty_fixed_cents=body.penalty_fixed_cents,
        no_show_fee_cents=body.no_show_fee_cents,
        user_sub=user.sub,
    )
    return CancellationPolicyOut(**policy)
```

`_require_enabled()` in the hotels router delegates to the hotel service's `_require_enabled` (the

```python
@hotel_reservations_router.post(
    "/hotels/{hotel_id}/reservations/{reservation_id}/cancel", response_model=ReservationOut)
async def cancel_reservation(
    hotel_id: str, reservation_id: str, body: ReservationTransitionIn | None = None,
    user: AuthenticatedUser = Depends(require_admin_or_root_csrf),
) -> ReservationOut:
    _require_enabled()
    existing = svc.get_reservation(reservation_id)
    if existing is None or existing.get("hotel_id") != hotel_id:
        raise HTTPException(status_code=404, detail="Reservation not found")
    # 1. FSM transition (idempotency token #1: version-CAS; replay of a terminal status → 409).
    item = svc.transition_reservation(
        reservation_id, "cancelled",
        actor=user.sub, reason=(body.reason if body else "") or "",
    )
    # 2. Fresh transition only (a replay already raised 409 above) → run the HTL-033 engine.
    policy = hc.resolve_policy_for_reservation(item)
    outcome = hc.apply_cancellation(
        item, policy, actor_sub=user.sub,
        provider=item.get("provider", "stripe"),          # OFB-010 Open-Q #2
    )
    # 3. Back-write the idempotency token #2 (best-effort; engine already posted the ledger).
    sk = outcome.get("refund_ledger_sk")
    if sk:
        try:
            svc.T.hotel_reservations.update_item(
                Key={"reservation_id": reservation_id, "sk": "META"},
                UpdateExpression="SET cancellation_ledger_sk = :v",
                ExpressionAttributeValues={":v": sk},
            )
            item["cancellation_ledger_sk"] = sk
        except Exception:
            pass
    return ReservationOut(**item)
```

## 5. Detailed Behavior & Edge Cases

### 5.1 Single-policy-per-scope upsert-in-place

`policy_id` is deterministic (`"default"` or `RATE#{id}`), so the `Key={hotel_id, sk="CANCELPOLICY#default"}` write
**overwrites** an existing row. A second `PUT .../cancellation-policy` with the same `scope` updates the four economic
fields + `updated_at` and **preserves `created_at`** via `if_not_exists(created_at, :u)`. There is exactly one row per
(hotel, scope) — never a duplicate. No GSI is needed because the read is always a point `get_item` by the resolved key.

### 5.2 Validation — 404 parent/ownership, 422 ranges

`upsert_cancellation_policy` 404s a non-existent or non-owned hotel (`get_hotel` `None` or `owner_sub` mismatch) and
422s an out-of-range `penalty_pct` (`<0` or `>100`) or any negative cents value, **before** the write. The router's
`CancellationPolicyIn` Pydantic constraints (`ge=0`, `le=100`) catch malformed input at the edge → 422; the service
re-checks so a direct caller (test) is also rejected (acceptance criterion: "rejects (404) … and (422) …").

### 5.3 Cancel/no-show idempotency — two gates, no double refund

The replay path is protected at **two** independent layers:

1. **FSM layer (HTL-019 `version`-CAS).** A `cancel` of an already-`cancelled` reservation hits the
   `target not in _RESERVATION_TRANSITIONS.get("cancelled", set())` check (`cancelled` is terminal → empty set) and
   raises **409 invalid_status_transition** (`HTL-019.md:271-272`) **before** the engine is ever called. So a naïve replay
   never reaches `apply_cancellation` — no second refund row is even attempted.
2. **Engine layer (HTL-033 stored-SK guard).** If, by some path, `apply_cancellation` is called on a reservation that
   already carries `cancellation_ledger_sk`, the engine returns the stored outcome **without posting a second ledger
   entry** (`CANCELLATION_REPORTS_TICKETS.md` §HTL-033 step 2). This is the belt-and-suspenders guarantee the acceptance
   criterion demands: "replay → terminal status → no second refund row."

Because the FSM 409 fires first, the back-write (step 3) only runs on a **fresh** transition — `cancellation_ledger_sk`
is written exactly once.

### 5.4 Reservation 404 / hotel mismatch

The cancel/no-show handlers keep HTL-020's guard: `get_reservation(reservation_id) is None` **or**
`existing.get("hotel_id") != hotel_id` → `HTTPException(404, "Reservation not found")` (`HTL-020.md:325-332`,
`inventory.py:118-120` 404-on-`None` idiom). This runs before the FSM transition, so a reservation filed under a
different hotel can never be cancelled through the wrong hotel's path.

### 5.5 Zero-refund / zero-fee → no ledger pollution

If `resolve_policy_for_reservation` returns the zero-penalty default (no policy set) and the cancellation is inside no
window, `compute_cancellation_refund` returns `refundable_cents = base` (full refund) — one ledger row. If the policy's
penalty equals the base (penalty 100% / `penalty_fixed_cents >= base`), `refundable_cents = 0` and HTL-033 posts **no**
ledger row (no zero-credit pollution, OFB-010 §5). Likewise `no_show_fee_cents = 0` posts no charge. HTL-034's
back-write skips when `outcome["refund_ledger_sk"]` / `outcome["no_show_ledger_sk"]` is empty (`if sk:`), so a zero-value
outcome writes no idempotency token (and a subsequent retry would re-run the FSM — but the FSM 409 already blocks that).

### 5.6 Route-ordering (literal-before-dynamic)

The new policy route `/{hotel_id}/cancellation-policy` is a literal sub-segment under a `{hotel_id}` param and does not
collide with any bare `/{hotel_id}` route in the hotels router as long as it is declared **before** a hypothetical bare
`GET /{hotel_id}/{something}` dynamic catch — by convention it is declared adjacent to the other literal hotel
sub-routes (the KYC `/templates`-before-`/{case_id}` and audit-export `/schedules`-before-`/{export_id}` discipline,
CLAUDE.md). The cancel/no-show sub-routes are already correctly ordered by HTL-020 (§2.4); HTL-034 only changes their
bodies, not their declaration position.

### 5.7 Flag-off behavior

With `HOTEL_PMS_ENABLED=false` (default), `_require_enabled()` in every handler (and in every
`hotel_cancellation.py` service function) raises `HTTPException(404, "Hotel PMS is not enabled")` before any DynamoDB
access (HTL-001 §5 `:404`). The two policy routes and the (enhanced) cancel/no-show routes 404; the routers remain
mounted; the platform is byte-for-byte unchanged.

### 5.8 Decimal coercion at the boundary

DynamoDB returns numeric attributes as `Decimal`. `get_cancellation_policy` and `resolve_policy_for_reservation` coerce
`free_until_days_before` / `penalty_pct` / `penalty_fixed_cents` / `no_show_fee_cents` / `created_at` / `updated_at` to
`int` before returning, so (a) the HTL-033 engine's integer arithmetic (`base * penalty_pct // 100`) never sees a
`Decimal`, and (b) `CancellationPolicyOut` validates cleanly. This mirrors the `MessageEncryptionEnvelope` Decimal-coerce
convention (CLAUDE.md memory) and the platform's "money-as-cents (int)" rule.

### 5.9 `provider` attribution

The cancel/no-show handlers pass `provider = item.get("provider", "stripe")` (OFB-010 Open-Q #2,
`CANCELLATION_REPORTS_TICKETS.md` §HTL-034). HTL-033 threads `provider` onto the ledger entry's `extra` (FIN-013
attribution, CLAUDE.md "Ledger `provider` attribution") so the platform financial dashboard buckets the refund/fee under
the correct provider rather than `"unknown"`.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### 7.1 SECOPS-007 — zero `dev_mode` branches

No HTL-034 code path contains `if S.dev_mode`. The same `T.hotels` and `T.hotel_reservations` handles back the policy
row and the back-write in both environments (DynamoDB Local on port 8001 via `DDB_ENDPOINT_URL` in dev, real DynamoDB in
prod). The refund/fee path is HTL-033's, which is "identical dev↔prod" (OFB-010 §7, cited by the cross-cutting
constraint) — the internal billing ledger, not a Stripe SDK call (`grep "if.*dev_mode" app/services/hotel_cancellation.py`
→ empty after HTL-033/034). Mirrors `inventory.py:27-28`.

### 7.2 Idempotency

- **Policy upsert** — deterministic `policy_id` + upsert-in-place; a repeated `PUT` to the same scope overwrites with
  the same row (no duplicate). `created_at` is preserved via `if_not_exists`.
- **Cancel/no-show** — two-gate idempotency (§5.3): the FSM `version`-CAS 409s a terminal-status replay before the
  engine runs; HTL-033's stored-SK guard is the second line. `cancellation_ledger_sk` / `no_show_ledger_sk` is written
  exactly once (on the fresh transition).

### 7.3 Security

- **Auth split** — read (`GET .../cancellation-policy`) → `require_ui_session` (`sessions.py:330`); all mutations
  (`PUT .../cancellation-policy`, `POST .../cancel`, `POST .../no-show`) → `require_admin_or_root_csrf`
  (`app/auth/policy.py:100`), role `∈ {ADMIN, ROOT}` + cookie CSRF. Identical split to `inventory.py:37,48,65,81`.
- **CSRF** — `require_admin_or_root_csrf` enforces `enforce_cookie_csrf(request)` for cookie-auth clients; a missing /
  mismatched `x-csrf-token` → 403 (`policy.py:95-97`). Bearer-auth requests skip CSRF (platform convention).
- **Ownership** — `upsert_cancellation_policy` 404s a hotel the caller does not own (`owner_sub != user_sub`), not 403,
  to avoid leaking hotel existence (§5.2). The cancel/no-show handlers 404 a reservation filed under a different
  `hotel_id` (§5.4).
- **No plaintext / PEM / secrets** flow through any HTL-034 path — the policy is four integers; the engine touches only
  the billing ledger.

### 7.4 Money-safety

- **One refund mechanism, never forked.** Every refund is HTL-033's single `type="adjustment", reason="refund"` ledger
  entry via `new_ledger_entry` + `apply_balance_delta` + `settle_or_reverse_ledger`
  (`app/services/billing_shared.py:224,83,262`) — the exact `refund_payment` (`app/routers/billing.py:1306-1324`) /
  RMA `refund_return` (OFB-010 §4) sequence. The no-show fee is one normal `reason="no_show_fee"` charge entry — not a
  new payment rail. HTL-034 itself **posts no ledger entry**; it only resolves the policy and calls the engine.
- **Money-as-cents.** `penalty_fixed_cents`, `no_show_fee_cents`, `refundable_cents`, `penalty_cents` are integer
  cents; `penalty_pct` is an integer percent clamped `[0,100]`; the engine's `base * penalty_pct // 100` is integer
  arithmetic with no float rounding. Decimal → int coercion at the read boundary (§5.8).
- **No double refund.** §5.3 — the FSM 409 + the engine's stored-SK guard.
- **No zero-credit pollution.** §5.5 — a zero-`refundable_cents` / zero-fee outcome posts no ledger row and no
  idempotency token.

### 7.5 Audit trail

`upsert_cancellation_policy` emits `_audit("hotel.cancel_policy.upsert", user_sub, hotel_id=..., policy_id=...,
penalty_pct=..., ...)`. The cancel/no-show **refund/fee** audit events
(`hotel.reservation.cancelled` / `hotel.reservation.no_show`) are emitted by **HTL-033's engine** (not duplicated by
HTL-034), and the **status-transition** HIST row + `_audit` are emitted by **HTL-019**. `_audit` is the lazy-import,
never-raising wrapper (`inventory.py:92`), so an audit failure never aborts a refund or a transition.

## 8. Backward Compatibility & Migration

### 8.1 Additive-only changes

HTL-034 adds: two service functions to an existing file (`hotel_cancellation.py`), two endpoints to an existing router
(`hotels_router`), and an enhancement to two existing handlers (`hotel_reservations.py` cancel/no-show). It adds the
`CancellationPolicyIn` / `CancellationPolicyOut` models to `app/models.py`. **No existing endpoint, table, GSI, model,
or behavioral contract is modified** — the cancel/no-show handlers gain a refund step that was previously a documented
forward-ref no-op (HTL-020 §"cancel": "writes no ledger entry / issues no refund (HTL-033 owns refunds)").

### 8.2 No DynamoDB migration

The policy row is a new SK on the **existing** `hotels` partition; no table create, no GSI add, no `attr_types`
change (the cross-cutting constraint: "This cluster adds no new tables"). Pre-existing hotels with no `CANCELPOLICY#`
row resolve to the implicit zero-penalty default (full refund, no fee) — the safest default and the same behavior the
FSM-only HTL-020 cancel had (release inventory, no charge). No backfill required.

### 8.3 Pre-existing reservations

Reservations created before HTL-034 carry no `cancellation_ledger_sk` / `no_show_ledger_sk`; the first cancel/no-show
writes it. A reservation with no `rate_plan_id` resolves to the hotel default (or zero-penalty) policy — `RATE#`-scoped
policies are an opt-in refinement (HTL-014 forward dep) and never required.

### 8.4 Production deployment sequence

1. Deploy code (flag `HOTEL_PMS_ENABLED` still off → every HTL-034 endpoint 404s; platform unchanged).
2. (When the vertical is launched) set `HOTEL_PMS_ENABLED=true`; admins `PUT` per-hotel policies as needed.
3. Until a policy is set, every hotel uses the zero-penalty default (full refund on cancel, no no-show fee) — a safe,
   guest-favourable default.

### 8.5 Rollback

Set `HOTEL_PMS_ENABLED=false` → all endpoints 404 again; the persisted `CANCELPOLICY#` rows remain but are inert
(never read while the flag is off, because `_require_enabled()` precedes any `get_item`). No data is lost; re-enabling
restores the policies exactly.

UI always renders an editable form pre-filled with the effective defaults. If the product wants a 404 to distinguish
"unset" from "explicitly zero", the handler returns 404 when `get_cancellation_policy` is `None`; a one-line change. The
default-projection choice matches the engine's "absent policy → zero-penalty" semantics (§3.2).

### 10.2 `RATE#`-scoped policies depend on HTL-014 (forward/optional)

`resolve_policy_for_reservation` prefers a `RATE#{rate_plan_id}`-scoped policy **only if** the reservation carries a
`rate_plan_id` and that scoped row exists. HTL-014 (rate plans) is a forward dependency; until it lands, reservations
carry no `rate_plan_id` and every resolution falls through to the hotel `default` (or zero-penalty). The `scope` query
param on the policy endpoints is already plumbed, so rate-plan policies become usable the moment HTL-014 supplies the
`rate_plan_id`. **Assumption**: shipping the `default`-only path first is correct; `RATE#` is additive.

### 10.3 Multi-tenant read isolation on `GET .../cancellation-policy`

The `GET` read uses `require_ui_session` and does **not** enforce `owner_sub == session.user_sub` (any authenticated
user can read any hotel's policy by ID). **Assumption**: single-platform deployment where admins operate one
landlord/hotelier entity (consistent with HTL-001/HTL-020 read posture). If per-hotelier isolation is required, add the
ownership check to the GET handler (fetch the hotel, compare `owner_sub`, 404 on mismatch) — a non-breaking additive
change. The `PUT` mutation already enforces ownership (§5.2).

### 10.4 No-show real off-session capture

`apply_no_show` posts an **internal ledger charge**, not a real off-session Stripe capture (HTL-033 / OFB-010 §7,
Open-Q #1: "A real off-session capture is a separate concern behind a future sub-flag"). **Assumption**: the internal
debit is the MVP; a true card capture is out of scope and would land behind its own sub-flag, not in HTL-034.

### 10.5 Back-write helper

The §4.2 cancel/no-show back-write is shown inline as `T.hotel_reservations.update_item(...)`. **Assumption**: if
HTL-018 ships a generic `update_reservation_field(reservation_id, field, value)` helper, HTL-034 uses it instead of the
inline call (cleaner, single owner for header writes). Either is acceptable; the contract is "best-effort single-field
SET on the `META` row."
