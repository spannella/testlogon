## 1. Summary & Goal

HTL-032 is the final ticket in the QloApps folios-and-payments cluster. It exposes
the folio services (HTL-029 `open_folio`/`add_line_item`/`get_folio`/`close_folio`;
HTL-030 `add_addon_to_folio`; HTL-031 `take_deposit`/`record_folio_payment`/
`render_folio_pdf`) over HTTP, and ships the React frontend that renders a folio
inside the reservation detail page. It ships exactly five deliverables:

1. **Router** — `app/routers/hotel_folios.py` (new), a `hotel_folios_router` with
   prefix `/ui/hotels`, modeled exactly on `app/routers/inventory.py` (auth split +
   `_require_enabled()` short-circuit) and the PROP-004 plan
   (`docs/open-property/specs/PROP-004.md`). Eight endpoints under
   `/ui/hotels/{hotel_id}/reservations/{rid}/folio`.
2. **`main.py` registration** — import + `app.include_router(hotel_folios_router)`
   adjacent to the existing HTL/inventory router mounts (`app/main.py:311,877`).
3. **Frontend types + endpoints** — `Folio`, `FolioLine`, `FolioPayment`,
   `DepositPolicy` and the in-shapes in `frontend/src/api/types.ts`; an
   `frontend/src/api/endpoints/hotelFolios.ts` axios wrapper
   (`frontend/src/api/client.ts`).
4. **Frontend component** — `FolioPanel.tsx` under `frontend/src/pages/hotels/`,
   rendered **inside the reservation detail page** (HTL-021, a forward dep): a
   line-item table, balance summary, add-addon dialog, record-payment dialog,
   deposit badge, and a download-PDF button.
5. **Tests** — hermetic pytest `tests/test_htl_folios_payments.py` (offline; moto +
   frozen `T`/`S`; route coroutines on a fresh event loop) and E2E
   `frontend/e2e/hotel-folios.spec.ts` (`HOTEL_PMS_ENABLED=1`).

The gap analysis (`docs/qloapps/QLOAPPS_GAP_ANALYSIS.md` §D) records the guest folio
/ booking invoice as **PARTIAL**: "`invoices.py` (FIN-001: invoice#, line items, tax,
S3 PDF, `deposit` type); **no folio/running-stay-balance entity**." HTL-029..031
landed the entity, add-ons, and money layer; HTL-032 makes them reachable over HTTP
and visible in the UI — closing the presentational half of the gap. With HTL-032
merged but `HOTEL_PMS_ENABLED=false` (the default), the router is mounted but every
handler 404s before touching DynamoDB; the platform is byte-for-byte unchanged and
**no folio/ledger/escrow row is ever written** (cluster cross-cutting constraint,
`docs/qloapps/FOLIOS_PAYMENTS_TICKETS.md:52-60`).

The design goal is a thin, policy-correct HTTP façade over an already-complete
service layer (the exact PROP-004 posture, `docs/open-property/specs/PROP-004.md`
§1). The router contributes four non-trivial concerns beyond simple delegation:
(1) the **auth split** (reads → `require_ui_session`; mutations →
`require_admin_or_root_csrf`); (2) **literal-before-dynamic** route declaration
order; (3) the **feature-flag 404 short-circuit**; and (4) a **binary-safe PDF
`Response`** (not `PlainTextResponse`) for the folio PDF download.

### 2.2 Canonical router idiom — `app/routers/inventory.py`

`app/routers/inventory.py` is the exact template (verified against the live file):

- **Router declaration** (`app/routers/inventory.py:29`):
  `inventory_router = APIRouter(prefix="/ui/inventory", tags=["inventory"])` — a

- **Local `_require_enabled()` wrapper** (`:32-33`): a module-level function that
  delegates to `inv._require_enabled()`. Every handler calls it as its first

- **Auth split** (`:37,48,65,81`): GET endpoints take `session=Depends(require_ui_session)`;

`hotel_folios_router` mirrors this pattern at every level.

### 2.3 Auth dependencies

- **`require_ui_session`** (`app/services/sessions.py:330`) — FastAPI `Depends`;
  validates cookie-based UI session or Bearer JWT; returns a dict carrying
  `user_sub`, `role`, etc. Used for read (GET) endpoints — including the folio PDF
  read (a guest may download their own folio).
- **`require_admin_or_root_csrf`** (`app/auth/policy.py:100-106`) — async FastAPI
  dependency; calls `enforce_cookie_csrf(request)` then `require_roles(user,
  {Role.ADMIN, Role.ROOT})`; raises HTTP 403 on CSRF failure, missing role, or role
  mismatch. Used for every mutation (POST). Hotel staff (admin/root) manage folios.
- **`AuthenticatedUser`** dataclass (`app/auth/deps.py:126`) — the type returned by
  `require_admin_or_root_csrf`; carries `.sub` (the `user_sub`), `.role`,
  `.admin_profile`.

### 2.4 The HTL-018 reservation (forward dep) — resolved by the router

The folio services are keyed on `reservation_id` only and never read the HTL-018
`hotel_reservations` table (cluster constraint; `docs/qloapps/specs/HTL-029.md`
§2.6). **The router** resolves the reservation dict via the Tier-2 reservation
service (a forward dep — the HTL-018 reservation-lifecycle cluster owns the table),
enforces that the reservation belongs to `{hotel_id}`, and passes the dict into
`open_folio(reservation, *, user_sub)`. Because the Tier-2 reservation service is
not yet defined, HTL-032 isolates the lookup behind a single thin local helper
`_resolve_reservation(hotel_id, rid)` (§4.3, §10 Q1) so the forward coupling lives
in one place and the test can patch it.

### 2.5 Route-ordering constraint (FastAPI path-param capture)

FastAPI matches routes in declaration order; a dynamic `/{rid}/folio/{action}`
catch-all would silently capture a literal suffix (`open`, `pdf`, …) as `action`.
CLAUDE.md documents this exact class of bug for two existing cases: KYC
(`/templates` before `/{case_id}`) and audit-export (`/schedules` before
`/{export_id}`). HTL-032's folio sub-routes are all **literal** suffixes
(`/open`, `/lines`, `/addons`, `/deposit`, `/payments`, `/close`, `/pdf`) under the
`/{rid}/folio` prefix — there is no dynamic-segment capture ambiguity *within* the
folio routes, but the router nonetheless declares each literal-suffix route
explicitly (no catch-all `/{action}` param) and declares the bare `GET .../folio`
read route first (§4.2, §5.1).

### 2.6 Binary-safe PDF `Response` — the audit-export lesson

The folio PDF (`render_folio_pdf`) returns raw `bytes` (a `%PDF` document). The
download endpoint MUST return a binary-safe `Response(content=..., media_type=
"application/pdf")` — **NOT** `PlainTextResponse`, which would UTF-8 re-encode and
corrupt the bytes. This is the same lesson the audit-export PDF download already
applies (CLAUDE.md "Audit export PDF format (GAP-0209)"; `app/routers/audit_export.py:299-305`):

```python
# app/routers/audit_export.py:301-305 (the pattern to copy)
return Response(
    content=base64.b64decode(content_b64),
    media_type="application/pdf",
    headers={"Content-Disposition": f'attachment; filename="audit-export-{export_id}.pdf"'},
)
```

`fastapi.responses.Response` is imported alongside `PlainTextResponse` at
`app/routers/audit_export.py:15`.

## 3. Data Model

HTL-032 introduces **no new DynamoDB tables, no new GSIs, and no new DynamoDB
attributes**. The `hotel_folios` table and the `T.hotel_folios` handle were declared
by HTL-029 (`docs/qloapps/specs/HTL-029.md` §3.1-3.3). The deposit-policy /
escrow / ledger rows live on the `hotel_folios` `META` row and the existing

## 4. API / Service Design

### 4.1 Router file: `app/routers/hotel_folios.py` (new file)

```python
"""Hotel folios + payments router (QloApps PMS vertical, HTL-032).

Additive + flag-gated (``HOTEL_PMS_ENABLED``, default OFF — reused from
HTL-001, no new master flag). Every handler calls ``_require_enabled()``
first; when the flag is off all endpoints return 404 and the platform is
byte-for-byte unchanged.

Auth split (mirrors app/routers/inventory.py:37,48,65,81):
  * Read endpoints  (GET folio / folio PDF) → ``require_ui_session``
  * Write endpoints (open/lines/addons/deposit/payments/close)
                                            → ``require_admin_or_root_csrf``
"""
from __future__ import annotations

from typing import Any, Dict, Optional

from fastapi import APIRouter, Depends, HTTPException
from fastapi.responses import Response

from app.auth.deps import AuthenticatedUser
from app.auth.policy import require_admin_or_root_csrf
from app.models import (
    FolioOut, FolioLineIn, FolioAddonIn, TakeDepositIn, FolioPaymentIn,
)
from app.services import hotel_folios as folios
from app.services.sessions import require_ui_session

hotel_folios_router = APIRouter(prefix="/ui/hotels", tags=["hotel-folios"])

_FOLIO = "/{hotel_id}/reservations/{rid}/folio"


def _require_enabled() -> None:
    folios._require_enabled()
```

### 4.2 Endpoint specifications (declaration order = literal-before-dynamic)

All folio sub-routes are literal suffixes under `_FOLIO` (`/open`, `/lines`,
`/addons`, `/deposit`, `/payments`, `/close`, `/pdf`); the bare `GET _FOLIO` read is
declared first. There is **no** catch-all `/{action}` param (§2.5, §5.1).

#### `GET /ui/hotels/{hotel_id}/reservations/{rid}/folio`
*(declared first; auto-opens on first read)*

```python
@hotel_folios_router.get(_FOLIO, response_model=FolioOut)
async def get_folio(hotel_id: str, rid: str, session=Depends(require_ui_session)) -> FolioOut:
    _require_enabled()
    folio = folios.get_folio(rid)
    if folio is None:
        reservation = _resolve_reservation(hotel_id, rid)   # 404 if reservation absent
        folio = folios.open_folio(reservation, user_sub=session["user_sub"])
    _assert_scope(folio, hotel_id, session)                 # §5.4 hotel + guest scoping
    return FolioOut(**folio)
```

- Auth: `require_ui_session` — a guest may read **their own** folio (`_assert_scope`
  enforces `folio["guest_sub"] == session["user_sub"]` for non-admin callers; §5.4).
- `get_folio` auto-`open_folio`s on first read (idempotent, HTL-029 §5.1), so the
  panel always has a folio to show. If the reservation does not exist → 404
  (`_resolve_reservation`).

#### `POST .../folio/open`

```python
@hotel_folios_router.post(_FOLIO + "/open", response_model=FolioOut)
async def open_folio(hotel_id: str, rid: str,
                     user: AuthenticatedUser = Depends(require_admin_or_root_csrf)) -> FolioOut:
    _require_enabled()
    reservation = _resolve_reservation(hotel_id, rid)
    folio = folios.open_folio(reservation, user_sub=user.sub)
    return FolioOut(**folio)
```

- Auth: `require_admin_or_root_csrf`. Idempotent (HTL-029 §5.1) — re-open returns the
  existing folio, never re-seeds lines.

#### `POST .../folio/lines`

```python
@hotel_folios_router.post(_FOLIO + "/lines", response_model=FolioOut)
async def add_line(hotel_id: str, rid: str, body: FolioLineIn,
                   user: AuthenticatedUser = Depends(require_admin_or_root_csrf)) -> FolioOut:
    _require_enabled()
    folios.add_line_item(rid, line_type=body.line_type, description=body.description,
                         quantity=body.quantity, unit_price_cents=body.unit_price_cents,
                         sku=body.sku, user_sub=user.sub)
    return FolioOut(**folios.get_folio(rid))
```

- `add_line_item` raises 404 (unknown folio) / 409 (closed folio) / 422 (bad
  `quantity`/`unit_price_cents`/`line_type`) — propagated naturally (HTL-029 §5.2-5.3).

#### `POST .../folio/addons`

```python
@hotel_folios_router.post(_FOLIO + "/addons", response_model=FolioOut)
async def add_addon(hotel_id: str, rid: str, body: FolioAddonIn,
                    user: AuthenticatedUser = Depends(require_admin_or_root_csrf)) -> FolioOut:
    _require_enabled()
    folios.add_addon_to_folio(rid, sku=body.sku, quantity=body.quantity, user_sub=user.sub)
    return FolioOut(**folios.get_folio(rid))
```

- `add_addon_to_folio` (HTL-030) resolves `unit_price_cents`/`description` from the
  catalog server-side (anti-tamper); unknown SKU → 404; `quantity < 1` → 422.

#### `POST .../folio/deposit`

```python
@hotel_folios_router.post(_FOLIO + "/deposit", response_model=FolioOut)
async def take_deposit(hotel_id: str, rid: str, body: TakeDepositIn,
                       user: AuthenticatedUser = Depends(require_admin_or_root_csrf)) -> FolioOut:
    _require_enabled()
    folios.take_deposit(rid, amount_cents=body.amount_cents, user_sub=user.sub)
    return FolioOut(**folios.get_folio(rid))
```

- `take_deposit` (HTL-031) performs the atomic escrow `transact_write_items`
  (wallet debit + escrow put + ledger put). Insufficient balance → nothing written;
  a second deposit for the same reservation → already-held (the
  `attribute_not_exists(pk)` guard). 422 for `<= 0` or `> balance_due_cents`.

#### `POST .../folio/payments`

```python
@hotel_folios_router.post(_FOLIO + "/payments", response_model=FolioOut)
async def record_payment(hotel_id: str, rid: str, body: FolioPaymentIn,
                         user: AuthenticatedUser = Depends(require_admin_or_root_csrf)) -> FolioOut:
    _require_enabled()
    folios.record_folio_payment(rid, amount_cents=body.amount_cents, method=body.method,
                                reference=body.reference, user_sub=user.sub)
    return FolioOut(**folios.get_folio(rid))
```

- `record_folio_payment` (HTL-031) writes exactly one `hotel_payment` ledger row,
  bumps `payments_total_cents` + the BALANCE counter, and (for `method="wallet"`)
  deducts exactly `amount_cents` once via `apply_wallet_delta` (no double-charge).

#### `POST .../folio/close`

```python
@hotel_folios_router.post(_FOLIO + "/close", response_model=FolioOut)
async def close_folio(hotel_id: str, rid: str,
                      user: AuthenticatedUser = Depends(require_admin_or_root_csrf)) -> FolioOut:
    _require_enabled()
    folio = folios.close_folio(rid, user_sub=user.sub)
    return FolioOut(**folio)
```

- `close_folio` (HTL-029 §4.5) flips `open → closed` once (idempotent under replay);
  missing folio → 404.

#### `GET .../folio/pdf`
*(binary-safe `Response`, NOT `PlainTextResponse` — §2.6)*

```python
@hotel_folios_router.get(_FOLIO + "/pdf")
async def folio_pdf(hotel_id: str, rid: str, session=Depends(require_ui_session)) -> Response:
    _require_enabled()
    folio = folios.get_folio(rid)
    if folio is None:
        raise HTTPException(status_code=404, detail="Folio not found")
    _assert_scope(folio, hotel_id, session)
    pdf = folios.render_folio_pdf(rid)            # bytes | None (HTL-031)
    if not pdf:
        raise HTTPException(status_code=404, detail="Folio PDF not available")
    return Response(
        content=pdf,
        media_type="application/pdf",
        headers={"Content-Disposition": f'attachment; filename="folio-{rid}.pdf"'},
    )
```

- Auth: `require_ui_session` (a guest may download their own folio; `_assert_scope`).
- The `Response(content=pdf, media_type="application/pdf")` is the binary-safe path
  (CLAUDE.md GAP-0209; mirrors `app/routers/audit_export.py:301-305`). Using
  `PlainTextResponse` here would UTF-8 re-encode and corrupt the `%PDF` bytes.

def _resolve_reservation(hotel_id: str, rid: str) -> Dict[str, Any]:
    """Resolve the HTL-018 reservation (forward dep, Tier-2). 404 if absent or
    not under {hotel_id}. Isolated so the forward coupling lives in one place and
    tests can patch it (§10 Q1)."""

        from app.services import hotel_reservations as resv  # forward dep (Tier-2)

        reservation = None

        raise HTTPException(status_code=404, detail="Reservation not found")

def _assert_scope(folio: Dict[str, Any], hotel_id: str, session: Dict[str, Any]) -> None:
    """Multi-tenant + guest scoping for reads (§5.4)."""
    if folio.get("hotel_id") != hotel_id:
        raise HTTPException(status_code=404, detail="Folio not found")
    role = str(session.get("role", "")).lower()
    if role not in ("admin", "root") and folio.get("guest_sub") != session.get("user_sub"):
        raise HTTPException(status_code=403, detail="Not authorized for this folio")

## 5. Detailed Behavior & Edge Cases

### 5.1 Route-ordering correctness — literal suffixes, no catch-all

The router declares `GET _FOLIO` first, then each literal-suffix route
(`/open`, `/lines`, `/addons`, `/deposit`, `/payments`, `/close`, `/pdf`). Because
every suffix is a static segment (not a `/{action}` param), FastAPI never captures
a literal as a path parameter — there is no KYC-`/templates`-style ambiguity *within*
the folio routes. The discipline (no catch-all, explicit literals, read route first)
is the same as the KYC `/templates`-before-`/{case_id}` and audit-export
`/schedules`-before-`/{export_id}` orderings (CLAUDE.md). A test asserts the literal
PDF route is reachable and routes to `folio_pdf`, not to a catch-all (§9.1 case 13).

### 5.2 `GET .../folio` auto-opens the folio on first read

The read endpoint calls `get_folio(rid)`; if it returns `None` it resolves the
reservation and `open_folio`s (idempotent, HTL-029 §5.1) so the panel always has a
folio. This matches the §HTL-032 endpoint table ("auto-`open_folio` on first read,
or 404 if reservation absent"). If the reservation does not exist, the auto-open
path raises 404 from `_resolve_reservation`.

### 5.3 Mutation handlers return the full refreshed folio

`add_line`/`add_addon`/`take_deposit`/`record_payment` re-read via `get_folio(rid)`
after the service mutation and return the assembled `FolioOut`. This lets the panel
re-render the whole table + balance summary from one response and keeps the response
contract uniform (`FolioOut` for every endpoint except the binary PDF). `get_folio`
is the source of truth for `charges_total_cents` (recomputed from line rows) and the
derived balances (HTL-029 §4.4, §5.4).

### 5.4 Read scoping — hotel isolation + guest ownership

`_assert_scope` enforces (a) `folio["hotel_id"] == hotel_id` (a folio under the
wrong hotel path → 404, prevents cross-hotel enumeration) and (b) for non-admin
sessions, `folio["guest_sub"] == session["user_sub"]` (a guest reads only their own
folio → 403 otherwise). Admin/root read any folio under the matching hotel (the
inventory/PROP read posture, `docs/open-property/specs/PROP-004.md` §10.1). The
mutation endpoints are already admin/root-gated by `require_admin_or_root_csrf`, so
they need no per-folio guest check.

### 5.5 CSRF enforcement on mutation endpoints

`require_admin_or_root_csrf` (`app/auth/policy.py:100-106`) calls
`enforce_cookie_csrf(request)` before the role check. For cookie-auth (browser)
requests it validates `x-csrf-token` header == `ui_csrf` cookie. Bearer-token API
clients (no `ui_session` cookie) skip CSRF (the platform-wide contract). The folio
GET reads (including the PDF) are CSRF-exempt (CSRF applies to non-GET only).

### 5.6 PDF download is binary-safe end-to-end

Server: `Response(content=pdf, media_type="application/pdf")` (§4.2) — not
`PlainTextResponse` (CLAUDE.md GAP-0209). Client: `downloadFolioPdf` uses `fetch`
→ `res.blob()` (not the JSON `api` client, which would parse the body as JSON and
corrupt it) → `URL.createObjectURL(blob)` → synthetic anchor click → revoke. The
`%PDF` bytes survive untouched in both directions. A test asserts the response body
starts with `%PDF` (§9.1 case 11).

### 5.7 Insufficient-balance / already-held deposit surfaces as a clean error

`take_deposit` (HTL-031) does the whole hold atomically via `transact_write_items`:
insufficient wallet balance → the transact fails and nothing is written → the
service raises (422/insufficient) → the handler propagates it → the panel shows a
`toast.error`. A second deposit for the same reservation fails the
`attribute_not_exists(pk)` escrow guard → already-held → propagated. No partial
state is ever written (the escrow's all-or-nothing property).

### 5.8 No double-charge on payment

Each `POST .../folio/payments` call is a distinct payment event (RNT-002 §7.5; not
dedup-keyed). The wallet deduction is exactly `amount_cents`, once, because
`record_folio_payment` does a single `apply_wallet_delta` per call with a conditional
balance guard (HTL-031). The panel disables the submit button while the mutation is
pending (`useMutation.isPending`) to prevent accidental double-submit; backend
single-deduct is the safety net.

### 5.9 Closed folio is read-only

When `folio.status === "closed"`, the panel disables add-addon / record-payment /
take-deposit / close controls (download + read remain). Server-side, `add_line_item`
/ `add_addon_to_folio` already 409 on a closed folio (HTL-029 §5.3); the disabled
controls are a UX courtesy, not the enforcement.

### 5.10 Flag-off behavior

When `HOTEL_PMS_ENABLED=false` (default), every handler's first statement
`_require_enabled()` → `folios._require_enabled()` raises
`HTTPException(404, "Hotel PMS is not enabled")` before any DynamoDB access. The
router is still mounted (`app.include_router(hotel_folios_router)`) — the gate is at
the handler level, not the mount level (the `inventory_router` posture). The panel
catches the 404 and renders the "not enabled" callout. No folio/ledger/escrow row is
written.

### 5.11 Decimal coercion

Every numeric field on `FolioOut`/`FolioLineOut` is `int` (HTL-029 §5.8 coerces with
`_to_int` before returning). The router returns the service dict unchanged into the
Pydantic model, which additionally coerces; no extra coercion in the router.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### 7.1 SECOPS-007 — zero `dev_mode` branches

`app/routers/hotel_folios.py` contains **no** `if S.dev_mode` branch — the same
handler code runs in dev (moto-intercepted DynamoDB/S3) and prod (real
DynamoDB/S3). This mirrors the cluster cross-cutting constraint
(`docs/qloapps/FOLIOS_PAYMENTS_TICKETS.md:90-94`) and the `app/routers/inventory.py`
precedent (no `dev_mode` branch in that file). The folio PDF reuses the
dependency-free `invoices._render_pdf` (HTL-031; `app/services/invoices.py:103`) —
identical bytes in dev and prod, no `reportlab`/system deps (mirrors `receipts.py`).
The frontend has no concept of dev mode.

### 7.2 Idempotency

- `GET .../folio` — auto-open is idempotent (HTL-029 §5.1); re-read never duplicates
  lines.
- `POST .../folio/open` — idempotent on `reservation_id` (HTL-029 §5.1).
- `POST .../folio/lines` / `.../addons` — intentionally NOT idempotent (each appends
  a fresh `LINE#{uuid}` row; a folio may hold many identical lines — HTL-029 §2.5).
- `POST .../folio/deposit` — idempotent via the escrow `attribute_not_exists(pk)`
  guard (second deposit → already-held, HTL-031).
- `POST .../folio/payments` — a distinct event per call; the wallet deduct is
  single + amount-exact (§5.8).
- `POST .../folio/close` — idempotent under replay (HTL-029 §5.7).
- `GET .../folio/pdf` — a pure read.

### 7.3 Security

- **Mutation auth**: all POST endpoints require `require_admin_or_root_csrf`
  (`app/auth/policy.py:100`) — role ∈ {ADMIN, ROOT} + CSRF for cookie-auth clients.
- **Read auth**: GET endpoints require `require_ui_session`
  (`app/services/sessions.py:330`), plus `_assert_scope` for hotel isolation + guest
  ownership (§5.4).
- **Anti-tamper pricing**: the router never trusts a client-supplied price it does
  not compute — `add_line_item`'s `amount_cents = quantity * unit_price_cents` is
  server-derived (HTL-029); `add_addon_to_folio` resolves the SKU price from the
  catalog server-side (HTL-030; the `unlock_post` PM-validation posture).
- **Path traversal**: `hotel_id`/`rid` are FastAPI path params, URL-encoded; no
  filesystem/shell paths — no traversal risk.

### 7.4 Money-safety

- The router never constructs a ledger row, never deletes one, and never forks
  billing — every money move flows through the HTL-031 service primitives
  (`new_ledger_entry` / `apply_wallet_delta` / `transact_write_items`), the cluster's
  absolute "ONE refund/ledger mechanism" rule
  (`docs/qloapps/FOLIOS_PAYMENTS_TICKETS.md:73-78`). The router imports only the
  folio service + models + auth deps — no `billing_shared`, no Stripe/PayPal/CCBill
  client.
- Every monetary value crossing the wire is integer cents (`FolioOut`/`FolioLineIn`/
  `TakeDepositIn`/`FolioPaymentIn`); the frontend formats with `formatCents` and
  never does float arithmetic on money.
- The atomic deposit hold (`transact_write_items`) is all-or-nothing (§5.7) — no
  partial wallet debit without the paired escrow + ledger rows.

### 7.5 Audit trail

The router emits no audit events directly — every service mutation already emits its
own best-effort `_audit()` event (`hotel.folio.opened`/`line_added`/`addon_added`/
`deposit_held`/`payment_recorded`/`closed`; HTL-029/030/031, via the
`app/services/inventory.py:92`-style lazy-import wrapper). Audit failure never
propagates to the HTTP caller.

   (`price_cents=1200`, `name="Breakfast"`); call `add_addon` with that SKU,
   `quantity=2`; assert a new `addon` line `amount_cents == 2400`,
   `charges_total_cents` increased by 2400. Unknown SKU → `HTTPException(404)`.
7. **`POST .../folio/deposit` atomic hold**: seed wallet balance 50000; call
   `take_deposit` with `amount_cents=10000`; assert wallet dropped by exactly 10000,
   an escrow row written, a paired ledger row written, `deposit_held_cents == 10000`.
8. **deposit insufficient balance → nothing written**: seed wallet 500; call
   `take_deposit(amount_cents=10000)`; assert it raises, wallet unchanged, no escrow
   row, no ledger row, `deposit_held_cents == 0` (the transact all-or-nothing, §5.7).
9. **second deposit → already-held**: after case 7, call `take_deposit` again; assert
   it raises (the `attribute_not_exists(pk)` guard); `deposit_held_cents` unchanged
   (no double-hold).
10. **`POST .../folio/payments` no double-charge**: seed wallet 50000; call
    `record_payment(amount_cents=5000, method="wallet")`; assert wallet dropped by
    exactly 5000, one `hotel_payment` ledger row, `payments_total_cents == 5000`,
    `balance_due_cents == charges - 5000`. A second call deducts another exact 5000
    (no double-deduct in a single call).
11. **`GET .../folio/pdf` binary-safe**: call `folio_pdf` handler; assert the result
    is a `Response` with `media_type == "application/pdf"` and `response.body`
    starts with `b"%PDF"` (the binary-safe `Response`, NOT `PlainTextResponse`, §5.6).
12. **`POST .../folio/close` idempotent**: call `close_folio` → `status="closed"`,
    `closed_at` set; second call returns the closed folio, no exception.
13. **route ordering / literal PDF reachable**: assert in `hotel_folios_router.routes`
    that the `.../folio/pdf` literal route exists and is bound to `folio_pdf` (not a
    catch-all `/{action}`); assert the bare `_FOLIO` GET route is declared before the
    literal-suffix POST routes (§5.1).
14. **read scoping — guest reads own folio**: call `get_folio` handler with
    `GUEST_SESSION` (matching `guest_sub`); assert success. With a different guest
    session → `HTTPException(403)`. With a mismatched `hotel_id` path → 404 (§5.4).
15. **mutation rejects non-admin**: drive `add_line` with a `USER`-role
    `AuthenticatedUser`; assert `HTTPException(403)` from `require_admin_or_root_csrf`.
16. **unknown reservation → 404**: patch `_resolve_reservation` to raise 404; call
    `open_folio`; assert `HTTPException(404)`.
17. **`main.py` registration**: import `create_app` from `app.main`; assert
    `hotel_folios_router` routes are present in the app and the
    `.../reservations/{rid}/folio/pdf` path is registered.
18. **Decimal coercion**: assert all numeric fields on the returned `FolioOut`/
    `FolioLineOut` are plain `int`, not `Decimal` (HTL-029 §5.8).

## 10. Open Questions / Assumptions

1. **Tier-2 reservation lookup (forward dep).** `_resolve_reservation` imports a
   not-yet-built `app.services.hotel_reservations.get_reservation` (the HTL-018/
   Tier-2 reservation-lifecycle cluster). **Assumption**: that service exposes a
   `get_reservation(rid) -> dict | None` returning at least `reservation_id`,
   `hotel_id`, `guest_sub`, `currency`, `nights`, `total_cents`, `room_type_id`,
   `checkin`, `checkout` (the fields `open_folio` seeds from, HTL-029 §2.6). Until it
   exists, `_resolve_reservation` is the single isolation point (patched in tests).
   If the reservation service is named/located differently, only this helper changes.

2. **Reservation detail page host (forward dep).** FolioPanel mounts inside the
   HTL-021 reservation-detail page (Tier-2). **Assumption**: HTL-021 ships
   `frontend/src/pages/hotels/ReservationDetailPage.tsx` (or equivalent) that renders
   `<FolioPanel hotelId={...} reservationId={...} />`. HTL-032 ships only the
   component + types + endpoints; it adds no new top-level route or sidebar entry
   (§2.7). If HTL-021 is not yet merged, FolioPanel is an unmounted, harmless
   addition.

3. **`guest_sub` for guest reads.** `_assert_scope` compares
   `folio["guest_sub"] == session["user_sub"]` for non-admin reads. **Assumption**:
   the folio's `guest_sub` is the billing `user_sub` (HTL-029 §2.6, §10 Q1) and a
   guest's session `user_sub` matches it. If the party→user mapping diverges,
   `_assert_scope` may over-restrict guest reads; admin/root are unaffected.

4. **Mutation auth for the guest deposit/payment.** All money mutations are
   admin/root-gated (`require_admin_or_root_csrf`) — front-desk staff record
   deposits/payments. **Assumption**: guests do not self-record folio payments in
   this MVP (a guest-initiated online folio payment is a later
   billing-integration ticket). The guest's role is read-only (folio view + PDF).

5. **`POST .../folio/open` returns 200, not 201.** The handler returns `FolioOut`
   with the default 200 (idempotent — a re-open returns the existing folio).
   **Assumption**: 200 on both first-create and replay is acceptable (the read
   endpoint also auto-opens, so an explicit `open` is rarely the first touch).

6. **PDF download via `fetch`, not the JSON client.** `downloadFolioPdf` uses raw
   `fetch` because `frontend/src/api/client.ts` parses bodies as JSON.
   **Assumption**: `credentials: "include"` carries the cookie session and GET needs
   no CSRF header (§5.5). If the deployment requires Bearer auth for the PDF, the
   helper must add the Authorization header from the auth store.

7. **Catalog table handle name in tests.** The hermetic test binds the catalog table
   to `T.catalog` (or whatever HTL-030's `add_addon_to_folio` reads via
   `catalog._find_item_by_id`). **Assumption**: HTL-030 patches the catalog lookup
   behind a thin `_resolve_addon(sku)` (HTL-030 reuse note), so the test patches that
   helper rather than constructing the exact catalog DDB shape.
