# HTL-003 — Router — /ui/hotels + amenities sub-routes + registration in app/main.py

**Type**: Feature | **Priority**: P1 | **Estimate**: 1d
**Source**: `docs/qloapps/HOTELS_AMENITIES_TICKETS.md` §HTL-003 (+ "Cross-cutting constraints") + `docs/qloapps/QLOAPPS_GAP_ANALYSIS.md` §A (rows 1 & 4)

---

## 1. Summary & Goal

HTL-003 exposes the entire hotel-PMS service layer over HTTP by introducing a new
`app/routers/hotels.py` — a single `hotels_router` (prefix `/ui/hotels`) — and registering
it in `app/main.py` immediately after `inventory_router` (`app/main.py:311` import,
`app/main.py:877` include). The ticket delivers exactly **10 endpoints** covering hotel CRUD
(`list_hotels` / `create_hotel` / `get_hotel` / `update_hotel` / `archive_hotel`), the
reusable amenity dictionary (`list_amenities` / `create_amenity`), the many-to-many
amenity attach/detach (`attach_amenity` / `detach_amenity`), and the per-hotel amenity
listing (`list_amenities_for`).

No new DynamoDB tables, no new GSIs, and no new Pydantic models are introduced by HTL-003.
The `hotels` table (HTL-001) and `hotel_amenities` table (HTL-002), their GSIs, and every
request/response model (`HotelIn` / `HotelOut` / `HotelUpdateIn` / `AmenityIn` /
`AmenityOut` / `AmenityAttachIn` / `AmenityAssociationOut`) already exist by the time
HTL-003 lands. Every endpoint is a thin, policy-correct HTTP façade that delegates directly
to a function in `app/services/hotel_pms.py`.

The router contributes exactly three non-trivial concerns beyond simple delegation, each
mirrored from the canonical `app/routers/inventory.py` template:

1. **Auth split** — reads use `require_ui_session` (`app/services/sessions.py:330`); mutations
   use `require_admin_or_root_csrf` (`app/auth/policy.py:100`), i.e. role `∈ {ADMIN, ROOT}`
   plus cookie CSRF. This is the identical split used at `app/routers/inventory.py:37,48,65,81`.
2. **Route-declaration order** — the static literal `/amenities` (and `/amenities/attach`,
   `/amenities/detach`) routes must be declared **before** the dynamic `/{hotel_id}` routes,
   so FastAPI does not capture the literal `amenities` segment as a `hotel_id` path
   parameter. This is the same gotcha CLAUDE.md documents for KYC `/templates`-before-`/{case_id}`
   and audit-export `/schedules`-before-`/{export_id}`.
3. **Feature-flag short-circuit** — every handler calls a module-level `_require_enabled()`
   first; when `HOTEL_PMS_ENABLED=false` (the default) the entire surface returns HTTP 404
   and the platform is byte-for-byte unchanged.

With the flag off the router is still mounted (just as `inventory_router` is always mounted —
`app/main.py:877`) but every handler is a silent 404 no-op via
`hotel_pms._require_enabled()` (the HTL-001 analogue of `app/services/inventory.py:54-56`).
No existing endpoint, table, model, setting, or behavioral contract is modified.

### 2.2 Canonical router idiom — `app/routers/inventory.py`

`app/routers/inventory.py` is the exact template HTL-003 follows at every level:

- **Router declaration** (`app/routers/inventory.py:29`):
  `inventory_router = APIRouter(prefix="/ui/inventory", tags=["inventory"])` — a single
  `APIRouter` with a `/ui/` prefix and a single tag.
- **Local `_require_enabled()` wrapper** (`app/routers/inventory.py:32-33`): a module-level
  function that delegates to `inv._require_enabled()`. Every handler calls this as its
  first statement (`:38`, `:50`, `:67`, `:83`).
- **Auth split** (`app/routers/inventory.py:37,48,65,81`): GET read endpoints use
  `session=Depends(require_ui_session)`; mutation endpoints use
  `user: AuthenticatedUser = Depends(require_admin_or_root_csrf)`. (Note: in inventory the
  `low-stock` GET is itself admin-gated at `:81`; for HTL all GETs are reads → `require_ui_session`.)
- **404-on-miss for single-record reads** (`app/routers/inventory.py:39-41`): `get_inventory`
  returns `None` → handler raises `HTTPException(404, ...)`. HTL's `get_hotel` mirrors this.
- **422 on invalid filter** (`app/routers/inventory.py:84-85`): the router validates the
  `status` query param and raises `HTTPException(422)` — the same shape used for HTL's
  `list_hotels` status filter.
- **`main.py` import + registration** (`app/main.py:311`, `app/main.py:877`): imported as
  `from app.routers.inventory import inventory_router`; included via
  `app.include_router(inventory_router)` inside `create_app()`.

The flag short-circuit it delegates to lives in `app/services/inventory.py:50-56`:
`_flag_on()` returns `bool(getattr(S, "inventory_reservations_enabled", False))` and
`_require_enabled()` raises `HTTPException(status_code=404, detail="...")` when off. HTL-001's
`hotel_pms._flag_on()` / `_require_enabled()` are byte-for-byte copies keyed on
`hotel_pms_enabled`.

### 2.3 Auth dependencies

- **`require_ui_session`** (`app/services/sessions.py:330`) — async FastAPI `Depends`;
  validates cookie-based UI session (`ui_session` + `ui_access_token`) or Bearer JWT;
  returns a `dict` carrying `user_sub`, `role`, etc. Used for every read (GET) endpoint.
  The caller's session `user_sub` flows into `list_hotels(owner_sub=...)` and
  `list_amenities_for(...)`.
- **`require_admin_or_root_csrf`** (`app/auth/policy.py:100-106`) — async FastAPI dependency;
  calls `enforce_cookie_csrf(request)` (`app/auth/policy.py:71-97`) then
  `require_roles(user, {Role.ADMIN, Role.ROOT})` (`:106`); raises HTTP 403 on CSRF failure,
  on missing role, or on role mismatch. Used for every mutation (POST/PUT/DELETE) endpoint.
- **`AuthenticatedUser`** dataclass (`app/auth/deps.py:126`) — the type returned by
  `require_admin_or_root_csrf`; carries `.sub` (the `user_sub`), `.role`, `.admin_profile`.
  `create_hotel` passes `owner_sub=user.sub`; every amenity mutation passes `user_sub=user.sub`.

### 2.4 Route-ordering constraint (FastAPI path-param capture)

FastAPI matches routes in declaration order. Under the `/ui/hotels` prefix, the literal
two-segment path `/amenities` and the dynamic one-segment capture `/{hotel_id}` are
length-distinct, but `/amenities` *as a single segment* WILL be captured by `/{hotel_id}`
if `get_hotel` (`GET /{hotel_id}`) is declared first — `GET /ui/hotels/amenities` would
route into `get_hotel(hotel_id="amenities")`, which then 404s (no hotel with id
`"amenities"`). The same hazard applies to the POSTs (`POST /ui/hotels/amenities` vs a
hypothetical dynamic POST) — but here the decisive collision is the GET. CLAUDE.md
documents this exact class of bug for two existing cases:

- KYC: `/templates` declared **before** `/{case_id}` (CLAUDE.md §"KYC template-signature endpoints").
- Audit export: `/schedules` declared **before** `/{export_id}` (CLAUDE.md §"Scheduled audit export reports").

**HTL-003's router file MUST declare the literal `/amenities`, `/amenities/attach`, and
`/amenities/detach` routes before any `/{hotel_id}` route.** This is the single most
important implementation detail of this ticket: a wrong declaration order works for every
other endpoint but silently breaks `GET /ui/hotels/amenities` with a misleading
"hotel not found" 404. This mirrors the `/portfolio/occupancy`-before-`/{property_id}`
requirement in `docs/open-property/specs/PROP-004.md` §2.4 / §5.1.

## 3. Data Model

HTL-003 introduces **no new DynamoDB tables, no new GSIs, no new DynamoDB attributes, and
no new Pydantic models.** The `hotels` table (HTL-001) and `hotel_amenities` table
(HTL-002) and all GSIs were declared in `scripts/local-ddb-init.py` by those tickets
(both with `attr_types={"created_at": "N"}` per the CLAUDE.md numeric-GSI gotcha). The
request/response models were defined in `app/models.py`. This section documents which models
flow through each endpoint and the query parameters.

### 3.1 Models flowing through the router

| Endpoint | Request body model | Response model |
|---|---|---|
| `GET /ui/hotels` | — | `{items: List[HotelOut], count: int, cursor: str \| None}` (HTL-001 `list_hotels` shape) |
| `POST /ui/hotels` | `HotelIn` | `HotelOut` |
| `GET /ui/hotels/amenities` | — | `List[AmenityOut]` |
| `POST /ui/hotels/amenities` | `AmenityIn` | `AmenityOut` |
| `POST /ui/hotels/amenities/attach` | `AmenityAttachIn` | `AmenityAssociationOut` |
| `POST /ui/hotels/amenities/detach` | `AmenityAttachIn` | `{"ok": bool}` |
| `GET /ui/hotels/{hotel_id}` | — | `HotelOut` |
| `PUT /ui/hotels/{hotel_id}` | `HotelUpdateIn` | `HotelOut` |
| `DELETE /ui/hotels/{hotel_id}` | — | `HotelOut` (soft-archive) |
| `GET /ui/hotels/{hotel_id}/amenities` | — | `List[AmenityAssociationOut]` |

The list response is the plain `{items, count, cursor}` dict returned by `list_hotels`
(mirroring `host_inventory.list_hosts`, CLAUDE.md), not a dedicated Pydantic envelope — the
handler returns the service dict directly (FastAPI serializes it). The detach response is a
simple `{"ok": bool}` dict (not a model), exactly as `delete_host_endpoint` returns
`{"ok": True}` (`app/routers/host_inventory.py:174`) — but HTL's detach uses the no-raise
`{"ok": False}` idempotent contract (§5.5), not the 404-on-miss the host endpoint uses at
`:172-173`.

### 3.2 Query parameters

`GET /ui/hotels` accepts:
- `status: Optional[str] = None` — `"active"` | `"archived"` filter; omitted ⇒ all of the
  owner's hotels. An unrecognized value is rejected with `HTTPException(422)` in the handler
  (same shape as `app/routers/inventory.py:84-85`).
- `cursor: Optional[str] = None` — opaque HMAC-signed pagination token produced by
  `encode_cursor` (`app/core/cursor.py:94`) and consumed by `decode_cursor`
  (`app/core/cursor.py:103`); a tampered token restarts from the beginning (per
  `decode_cursor`).
- `limit: int = 50` — page size; the service caps it server-side.

`GET /ui/hotels/amenities` accepts:
- `category: Optional[str] = None` — one of `connectivity` | `wellness` | `parking` |
  `dining` | `family` | `accessibility` | `general`; when supplied the service queries
  `GSI_CATEGORY` (HTL-002) instead of listing the whole dictionary. An unrecognized value
  is rejected by the service/model (422) — the router passes it through.

No query parameters for `GET /ui/hotels/{hotel_id}` or `GET /ui/hotels/{hotel_id}/amenities`.
Attach/detach take their target identity (`target_type`, `target_id`, `amenity_id`) from
the JSON body (`AmenityAttachIn`), never the URL.

## 4. API / Service Design

### 4.1 Router file: `app/routers/hotels.py` (new file)

```python
"""Hotel-PMS router (QloApps hospitality vertical, HTL-003).

Additive + flag-gated (``HOTEL_PMS_ENABLED``, default OFF). Every handler calls
``_require_enabled()`` first; when the flag is off all endpoints return 404 and
the platform is byte-for-byte unchanged (the router is still mounted, exactly
like ``inventory_router`` — app/main.py:877).

Auth split (mirrors app/routers/inventory.py:37,48,65,81):
  * Read endpoints  → ``require_ui_session``          (any authenticated user)
  * Write endpoints → ``require_admin_or_root_csrf``  (ADMIN | ROOT + CSRF)

Route order (CLAUDE.md path-param-capture gotcha): the literal ``/amenities``
routes are declared BEFORE the dynamic ``/{hotel_id}`` routes.
"""
from __future__ import annotations

from typing import Optional

from fastapi import APIRouter, Depends, HTTPException

from app.auth.deps import AuthenticatedUser
from app.auth.policy import require_admin_or_root_csrf
from app.models import (
    AmenityAssociationOut, AmenityAttachIn, AmenityIn, AmenityOut,
    HotelIn, HotelOut, HotelUpdateIn,
)
from app.services import hotel_pms as svc
from app.services.sessions import require_ui_session

hotels_router = APIRouter(prefix="/ui/hotels", tags=["hotels"])

_VALID_STATUS = {"active", "archived"}


def _require_enabled() -> None:
    svc._require_enabled()
```

This mirrors `app/routers/inventory.py:13-33` line-for-line in structure: `__future__`
import, FastAPI imports, `AuthenticatedUser` + `require_admin_or_root_csrf` from auth,
models, the service module aliased (`svc`, matching `inv`), `require_ui_session`, the
`APIRouter` declaration, and the local `_require_enabled()` delegating wrapper.

### 4.2 Full endpoint table

All 10 endpoints in **declaration order**. The literal `/amenities*` group is declared
before the `/{hotel_id}*` group (§2.4, §5.1).

| # | Method | Path | Auth | Service call |
|---|---|---|---|---|
| 1 | GET | `/ui/hotels` | `require_ui_session` | `list_hotels(owner_sub=session["user_sub"], status=, cursor=, limit=)` |
| 2 | POST | `/ui/hotels` | `require_admin_or_root_csrf` | `create_hotel(owner_sub=user.sub, **body)` |
| 3 | GET | `/ui/hotels/amenities` | `require_ui_session` | `list_amenities(category=)` — **literal, declared before `/{hotel_id}`** |
| 4 | POST | `/ui/hotels/amenities` | `require_admin_or_root_csrf` | `create_amenity(name=, category=, icon=, user_sub=user.sub)` |
| 5 | POST | `/ui/hotels/amenities/attach` | `require_admin_or_root_csrf` | `attach_amenity(target_type=, target_id=, amenity_id=, user_sub=user.sub)` |
| 6 | POST | `/ui/hotels/amenities/detach` | `require_admin_or_root_csrf` | `detach_amenity(target_type=, target_id=, amenity_id=, user_sub=user.sub)` |

### 4.3 Endpoint specifications

#### 1. `GET /ui/hotels` — list the caller's hotels

```python
@hotels_router.get("")
async def list_hotels(
    status: Optional[str] = None,
    cursor: Optional[str] = None,
    limit: int = 50,
    session=Depends(require_ui_session),
) -> dict:
    _require_enabled()
    if status is not None and status not in _VALID_STATUS:
        raise HTTPException(status_code=422, detail="invalid status filter")
    return svc.list_hotels(
        owner_sub=session["user_sub"],
        status=status,
        cursor=cursor,
        limit=limit,
    )
```

- Auth: `require_ui_session` — `owner_sub` is the caller's session `user_sub`, so a hotelier
  automatically sees only their own hotels (`GSI_OWNER` PK=`owner_sub`).
- Service: `list_hotels` (HTL-001 list path) queries `GSI_OWNER` newest-first, paginated via
  `encode_cursor`/`decode_cursor` (`app/core/cursor.py:94,103`).
- Response: `{items: [HotelOut...], count, cursor}` — returned as the service dict (the
  `host_inventory.list_hosts` shape, CLAUDE.md).
- The 422 status-filter guard mirrors `app/routers/inventory.py:84-85`.

#### 2. `POST /ui/hotels` — create a hotel (idempotent on owner+name)

```python
@hotels_router.post("", response_model=HotelOut, status_code=201)
async def create_hotel(
    body: HotelIn,
    user: AuthenticatedUser = Depends(require_admin_or_root_csrf),
) -> HotelOut:
    _require_enabled()
    item = svc.create_hotel(
        owner_sub=user.sub,
        name=body.name,
        description=body.description,
        star_rating=body.star_rating,
        address=body.address.model_dump() if hasattr(body.address, "model_dump") else body.address,
        check_in_time=body.check_in_time,
        check_out_time=body.check_out_time,
        policies=body.policies.model_dump() if hasattr(body.policies, "model_dump") else body.policies,
        contact=body.contact.model_dump() if hasattr(body.contact, "model_dump") else body.contact,
        photo_urls=body.photo_urls,
    )
    return HotelOut(**item)
```

- Auth: `require_admin_or_root_csrf` (`app/auth/policy.py:100`).
- Service: `create_hotel` derives `hotel_id = sha256(f"{owner_sub}|{name}")[:32]`, conditional
  put `attribute_not_exists(hotel_id)` ⇒ idempotent on (owner_sub, name) (returns the
  existing row on collision, HTL-001).
- HTTP status: `201` on first create; on idempotent replay the service returns the same item
  and the handler returns `201` again (§7.2 — callers treat 201 idempotently).
- Nested `address`/`policies`/`contact` are serialized to plain dicts before the service call
  (the service layer works with dicts, not Pydantic models — same `.model_dump()` pattern as
  `docs/open-property/specs/PROP-004.md` §4.2 `create_property`).

#### 3. `GET /ui/hotels/amenities` — list the amenity dictionary *(literal, declared before `/{hotel_id}`)*

```python
@hotels_router.get("/amenities", response_model=list[AmenityOut])
async def list_amenities(
    category: Optional[str] = None,
    session=Depends(require_ui_session),
) -> list[AmenityOut]:
    _require_enabled()
    return [AmenityOut(**a) for a in svc.list_amenities(category=category)]
```

- Auth: `require_ui_session` (the FE amenity picker needs read access for any user).
- Service: `list_amenities(category=)` queries `GSI_CATEGORY` when `category` is supplied,
  else lists the dictionary; sorted by `name` (HTL-002). An invalid `category` is rejected
  by the service/model (422).
- **Declaration position is decisive**: this route is declared before `GET /{hotel_id}` so
  `amenities` is never captured as a `hotel_id` (§2.4, §5.1).

#### 4. `POST /ui/hotels/amenities` — create a dictionary entry (idempotent on name)

```python
@hotels_router.post("/amenities", response_model=AmenityOut, status_code=201)
async def create_amenity(
    body: AmenityIn,
    user: AuthenticatedUser = Depends(require_admin_or_root_csrf),
) -> AmenityOut:
    _require_enabled()
    item = svc.create_amenity(
        name=body.name, category=body.category, icon=body.icon, user_sub=user.sub,
    )
    return AmenityOut(**item)
```

- Auth: `require_admin_or_root_csrf`.
- Service: `create_amenity` derives `amenity_id = sha256(f"amenity|{name}")[:32]`, conditional
  put ⇒ idempotent on `name` (returns existing on collision, dedupes "WiFi" across callers).

#### 5. `POST /ui/hotels/amenities/attach` — attach an amenity to a target

```python
@hotels_router.post("/amenities/attach", response_model=AmenityAssociationOut)
async def attach_amenity(
    body: AmenityAttachIn,
    user: AuthenticatedUser = Depends(require_admin_or_root_csrf),
) -> AmenityAssociationOut:
    _require_enabled()
    item = svc.attach_amenity(
        target_type=body.target_type,
        target_id=body.target_id,
        amenity_id=body.amenity_id,
        user_sub=user.sub,
    )
    return AmenityAssociationOut(**item)
```

- Auth: `require_admin_or_root_csrf`.
- Service: `attach_amenity` validates the amenity dictionary entry exists (404 if not) and
  the target exists (404 if not), then `put_item`s the `AMEN#{amenity_id}` child row on the

  even though no room-type entity ships; an unknown `target_type` raises 422 in
  `_target_partition` (HTL-002) — propagates naturally.
- Both 404s and the 422 originate in the service and propagate without any router try/except.

## 5. Detailed Behavior & Edge Cases

### 5.1 Route-ordering correctness — `/amenities*` before `/{hotel_id}*`

The router declares, in order: `GET ""`, `POST ""`, `GET /amenities`, `POST /amenities`,
`POST /amenities/attach`, `POST /amenities/detach`, then `GET /{hotel_id}`,
`PUT /{hotel_id}`, `DELETE /{hotel_id}`, `GET /{hotel_id}/amenities`. FastAPI matches in
declaration order; declaring `GET /{hotel_id}` before `GET /amenities` would route
`GET /ui/hotels/amenities` into `get_hotel(hotel_id="amenities")`, producing a misleading
"Hotel not found" 404. Declaring the literal `/amenities` group first guarantees the literal
segment wins. Test #6 (§9) asserts the literal route's index in `hotels_router.routes`
precedes the dynamic `/{hotel_id}` route's index. This mirrors PROP-004 §5.1.

The `/{hotel_id}/amenities` route is a two-segment dynamic+literal path; it does not conflict
with the one-segment `/amenities` literal (different lengths), so its relative position among
the `/{hotel_id}*` group is free — it is grouped last for readability.

### 5.2 `POST /ui/hotels` idempotency

`create_hotel` uses a conditional put (`attribute_not_exists(hotel_id)` over the deterministic
`sha256(owner|name)[:32]` id) and returns the existing item on collision (HTL-001). Two
identical POSTs by the same admin return `201` with the same `HotelOut` both times — no error,
no duplication. This is a service-layer property the router inherits.

### 5.3 `POST /ui/hotels/amenities` idempotency & dedup

`create_amenity` derives `amenity_id = sha256("amenity|"+name)[:32]`, so "WiFi" maps to one
canonical dictionary entry regardless of caller; a duplicate-name POST returns the existing
entry (HTL-002). The amenity dictionary is global (not owner-scoped) by design.

### 5.4 `DELETE /ui/hotels/{hotel_id}` is soft-archive

`DELETE` calls `archive_hotel`, which sets `status="archived"` via `update_item` (HTL-001).
The response is a `HotelOut` with `status="archived"`; the row stays in DynamoDB. A later
`GET /ui/hotels/{hotel_id}` still returns it (archived). `GET /ui/hotels?status=active`
excludes it; `?status=archived` includes it. No hard delete — this protects future
Room-Type / reservation FKs from dangling (the property vertical's no-hard-delete contract,
`docs/open-property/specs/PROP-004.md` §5.3).

### 5.5 `POST /ui/hotels/amenities/detach` idempotency (no-raise)

`detach_amenity` returns `False` (never raises) for a missing association — the
`host_inventory.delete_host` no-raise contract (HTL-002, CLAUDE.md). The HTTP response is
`{"ok": False}` with status 200, not 404. Callers detaching an already-detached (or never-
attached) amenity receive `{"ok": False}` and treat it as a no-op. Note this diverges from
`delete_host_endpoint`, whose router *raises* 404 on miss (`app/routers/host_inventory.py:172-173`)
and returns `{"ok": True}` on success (`:174`); HTL's detach uses the no-raise idempotent
contract deliberately (§10.3).

### 5.6 CSRF enforcement on mutation endpoints

`require_admin_or_root_csrf` (`app/auth/policy.py:100-106`) calls `enforce_cookie_csrf(request)`
(`app/auth/policy.py:71-97`) before the role check. For cookie-authenticated (browser)
requests it validates that both the CSRF header and the `ui_csrf` cookie are present and equal
(`:94-97`); a missing or mismatched token raises `HTTPException(403)`. For Bearer-token /
API-key clients with no session cookie, CSRF is not applicable and `enforce_cookie_csrf`
returns early (`app/auth/policy.py:87-89`) — so mutation endpoints are reachable by Bearer-auth
API clients without a CSRF header, consistent with every other admin endpoint.

### 5.7 Flag-off behavior

When `HOTEL_PMS_ENABLED=false` (the default) every handler's first statement
`_require_enabled()` → `svc._require_enabled()` raises `HTTPException(404, "...")` (the HTL-001
copy of `app/services/inventory.py:54-56`). The router is still mounted via
`app.include_router(hotels_router)` — the gate is at the handler level, not the mount level —
so the platform is byte-for-byte unchanged and no DynamoDB read/write occurs. This is the
identical contract `inventory_router` honors.

### 5.8 Decimal coercion in response models

`HotelOut` / `AmenityOut` / `AmenityAssociationOut` integer fields (`created_at`,
`updated_at`, `star_rating`) must be plain `int`, not `Decimal`. The HTL-001/HTL-002
service-layer item-builders coerce Decimal → int before returning dicts; the Pydantic models
additionally coerce on assignment. No extra coercion in the router (same as PROP-004 §5.8).

### 5.9 422 vs 404 vs 403 ordering

The handler runs `_require_enabled()` (404 when flagged off) *before* touching the body or
auth-derived state, but FastAPI resolves `Depends(...)` (auth → 403; body validation → 422)
*before* the handler body executes. Therefore, with the flag off, a malformed body or a
non-admin caller surfaces a 422/403 from the dependency layer *before* the 404 short-circuit —
identical to `inventory_router`'s ordering and acceptable (the platform reveals nothing about
the disabled feature beyond standard auth/validation errors). Tests that assert the flag-off
404 call the handler coroutine directly with already-validated args and a valid mock user, so
they observe the 404 deterministically (§9).

### 5.10 Ownership on reads

`GET /ui/hotels/{hotel_id}`, `GET /ui/hotels/{hotel_id}/amenities`, and the amenity
dictionary GETs do **not** enforce that the caller's `user.sub` equals the hotel's
`owner_sub`. Any authenticated session can read a hotel by id (single-platform-operator
assumption; §10.1). `list_hotels` IS owner-scoped (it queries `GSI_OWNER` keyed on
`session["user_sub"]`), so the list path leaks nothing cross-owner; only direct id reads are
unscoped. The amenity dictionary is intentionally global/shared (HTL-002).

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### 7.1 SECOPS-007 — zero `dev_mode` branches

`app/routers/hotels.py` must contain **no** `if S.dev_mode` branch and import no dev-mode
helper or mock path. The same handler code runs in dev (in-process moto-intercepted
DynamoDB, `app/core/dev_s3.py`) and prod (real DynamoDB) — moto interception is transparent
to the router. This mirrors the HTL "Cross-cutting constraints" SECOPS-007 clause
(`docs/qloapps/HOTELS_AMENITIES_TICKETS.md`) and the precedent in `app/routers/inventory.py`
(no `dev_mode` branch in that file) and `app/services/inventory.py:27-28`.

### 7.2 Idempotency

- `POST /ui/hotels` — idempotent on (owner_sub, name): second call returns the same
  `hotel_id` / `HotelOut`, HTTP 201, no error, no duplication (§5.2).
- `POST /ui/hotels/amenities` — idempotent on `name` (dedupes the dictionary entry, §5.3).
- `POST /ui/hotels/amenities/attach` — idempotent re-attach: the conditional
  `attribute_not_exists(sk)` makes a repeat attach a no-op, returning the existing
  association (§4.3 #5).
- `PUT /ui/hotels/{hotel_id}` — idempotent in final state; `updated_at` advances each call
  (timestamp not idempotent, acceptable).
- `DELETE /ui/hotels/{hotel_id}` — idempotent: archiving an already-archived hotel returns
  `status="archived"` again with no error (§5.4).
- `POST /ui/hotels/amenities/detach` — idempotent: detaching a missing association returns
  `{"ok": False}` with no error (§5.5).

### 7.3 Security

- **Mutation auth**: every POST/PUT/DELETE requires `require_admin_or_root_csrf` — role
  `ADMIN`/`ROOT` plus CSRF for cookie-auth clients (`app/auth/policy.py:100-106`). A
  `USER`-role caller is rejected with 403 by `require_roles` (`:106`).
- **Read auth**: every GET requires `require_ui_session` (`app/services/sessions.py:330`) —
  any authenticated user. `list_hotels` is owner-scoped via `GSI_OWNER`; direct id reads are
  not (§5.10, §10.1).
- **CSRF**: `enforce_cookie_csrf` validates header == cookie for non-GET cookie-auth
  requests; Bearer/API-key clients are exempt (`app/auth/policy.py:87-89`).
- **Path traversal**: `hotel_id` is a FastAPI path parameter (URL-encoded); no filesystem
  paths or shell commands are involved — no traversal risk. `target_id`/`amenity_id` arrive
  in the JSON body and are used only as DynamoDB key components.
- **Forward-compat `room_type`**: `target_type="room_type"` is accepted at the surface but
  resolves to a 422 in `_target_partition` until the Room-Type cluster lands (HTL-002) — no
  silent write to an unknown partition.

### 7.4 Money-safety

HTL-003 touches **no** billing table, billing service, or payment provider. The imports in
`app/routers/hotels.py` are only `hotel_pms`, the HTL Pydantic models, and the two auth
dependencies — no `billing_shared`, `new_ledger_entry`, `settle_or_reverse_ledger`,
`apply_balance_delta`, `compute_due`, or any Stripe/PayPal/CCBill client. The hospitality
vertical's monetary paths (folios, deposits, reservations) are separate downstream ticket
clusters (gap analysis §§ on folios/payments). HTL-003 has zero financial invariants to
enforce. This matches the money-safety posture of `docs/open-property/specs/PROP-004.md` §7.4.

### 7.5 Audit trail

The router does not call `_audit()` directly — audit events (`hotel.created`,
`hotel.updated`, `hotel.archived`, `hotel.amenity.created`, `hotel.amenity.attached`,
`hotel.amenity.detached`) are emitted by the HTL-001/HTL-002 service functions via the
best-effort `_audit()` lazy-import wrapper (the HTL copy of `app/services/inventory.py:92-98`,
which swallows exceptions). Audit failure never propagates to the HTTP caller.

## 10. Open Questions / Assumptions

### 10.1 Multi-tenant hotelier isolation on direct id reads

`GET /ui/hotels/{hotel_id}`, `GET /ui/hotels/{hotel_id}/amenities`, and the amenity
dictionary GETs do not enforce `caller.sub == hotel.owner_sub` (§5.10). Any authenticated
session can read a hotel by id.

**Assumption**: single-platform deployment where admins/root operate the same hotelier
entity. If cross-hotelier isolation is required, the read handlers can fetch the hotel,
compare `owner_sub` to the session `user_sub`, and 403/404 on mismatch — a non-breaking
additive change. `list_hotels` is already owner-scoped (`GSI_OWNER`), so the list path leaks
nothing.

### 10.2 Detach response — `{"ok": False}` vs 404

The current detach contract returns HTTP 200 `{"ok": False}` for a missing association, not
404 (§5.5), giving idempotent semantics. Some callers may want 404 to distinguish "already
detached" from "never attached".

**Assumption**: idempotent detach is preferred. If 404 is required, the handler can inspect
`detach_amenity`'s return and raise `HTTPException(404)` — a one-line change. Note this is a
deliberate divergence from `delete_host_endpoint`, which raises 404 on miss
(`app/routers/host_inventory.py:172-173`).

### 10.3 `POST` status on idempotent replay

`POST /ui/hotels` and `POST /ui/hotels/amenities` return 201 on idempotent replay (existing
item). 200 might be more semantically precise for "found existing", but 201-on-replay matches
the HTL-001/HTL-002 service contract and has no behavioral impact.

**Assumption**: 201-on-replay is acceptable; callers treat 201 idempotently (same posture as
PROP-004 §10.5).

### 10.4 `list_hotels` ownership of the list path

HTL-003 calls `list_hotels` but treats its implementation as part of the HTL-001 `GSI_OWNER`
list-path deliverable (§2.1). If sequencing puts the function on this ticket instead, it is a
single new function over the already-existing `hotels`/`GSI_OWNER` substrate (no table/GSI/model
change) and is delivered alongside the router.

**Assumption**: `list_hotels` exists by merge time; if not, it ships with HTL-003.

### 10.5 `list_hotels` / `list_amenities` pagination

`list_hotels` paginates via `encode_cursor`/`decode_cursor`. `list_amenities` and
`list_amenities_for` return flat lists (the dictionary and a single hotel's amenity set are
small).

**Assumption**: amenity sets per hotel and the global dictionary stay well under the 1MB DDB
read limit; pagination on those reads is an additive follow-up if ever needed.
