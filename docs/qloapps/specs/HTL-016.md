# HTL-016 — Router + price-quote endpoint + frontend rate-plan editor + price-preview + tests

**Type**: Feature | **Priority**: P2 | **Estimate**: 2.5d
**Source**: `docs/qloapps/RATE_PLANS_TICKETS.md` §HTL-016 + "Cross-cutting constraints" + `docs/qloapps/QLOAPPS_GAP_ANALYSIS.md` §B

---

## 1. Summary & Goal

HTL-016 is the third and final ticket in the Hotel-PMS nightly-rate-plan cluster (the **price half** of the Tier-1 spine, `docs/qloapps/RATE_PLANS_TICKETS.md:14-22`). It exposes the rate-plan service layer (HTL-014) and the multi-night price computation engine (HTL-015) over HTTP, builds the admin frontend rate-plan editor + a live price-preview widget, and ships the hermetic pytest + Playwright E2E suites.

The deliverable is intentionally a **thin, policy-correct HTTP façade** over an already-complete service layer plus the React surfacing of that façade. Nothing in this ticket re-implements pricing math, table CRUD, validation, or the flag gate — those all live in `app/services/hotel_rate_plans.py` (HTL-014/015). HTL-016 contributes exactly five non-trivial concerns beyond delegation:

1. **A new router** `app/routers/hotel_rate_plans.py` (prefix `/ui/hotels`) with **10 endpoints** — rate-plan + rule CRUD plus a price-**quote** endpoint that wraps `compute_stay_price`.
2. **Auth split** — reads + the quote endpoint use `require_ui_session`; mutations use `require_admin_or_root_csrf` — identical to `app/routers/inventory.py:38,48,65,81`.
3. **Route-declaration order** — the static `/{hotel_id}/rate-plans` collection routes are declared **before** the dynamic `/{hotel_id}/room-types/{rt}/...` routes, and the literal `/quote` is the **last** segment under `{rt}` so it is never captured as a sub-resource id (FastAPI matches in declaration order — same gotcha as KYC `/templates`-before-`/{case_id}` and audit-export `/schedules`-before-`/{export_id}`, CLAUDE.md).
4. **Feature-flag short-circuit** — every handler calls `_require_enabled()` first; when `HOTEL_PMS_ENABLED=false` (the default) the entire surface returns HTTP 404 and the platform is byte-for-byte unchanged. The router is still mounted, exactly as `inventory_router` is always mounted (`app/main.py:877`).
5. **Frontend** — TypeScript types, axios endpoint wrappers, a `RatePlanEditorPage` (rules list + per-kind add-rule forms) with an embedded `StayPricePreview` widget that calls the quote endpoint and renders the per-night breakdown + total (cents → formatted currency), a lazy route in `App.tsx`, and an optional Sidebar nav entry.

With the flag off, both the backend surface (every handler 404s) and the frontend (the page renders a "Hotel PMS is not enabled" callout on the 404) are no-ops. No existing endpoint, table, Pydantic model, or behavioral contract is modified.

### 2.3 Auth dependencies

- **`require_ui_session`** (`app/services/sessions.py:330`) — async FastAPI dependency; validates the cookie-based UI session or a Bearer JWT and returns a `dict` carrying `user_sub`, `role`, etc. Used for all read (GET) endpoints **and the `/quote` endpoint** (the quote computes but never persists — a price preview a storefront or admin can call).
- **`require_admin_or_root_csrf`** (`app/auth/policy.py:100-106`) — async FastAPI dependency; calls `enforce_cookie_csrf(request)` then `require_roles(user, {Role.ADMIN, Role.ROOT})` (verified at `:104-106`); raises HTTP 403 on a CSRF failure or a missing/insufficient role. Returns an `AuthenticatedUser`. Used for all mutation (POST/PUT/DELETE) endpoints.
- **`AuthenticatedUser`** dataclass (`app/auth/deps.py`) — the type returned by `require_admin_or_root_csrf`; carries `.sub` (the `user_sub`), `.role`, `.admin_profile`. Mutation handlers pass `user.sub` as `user_sub` to the service.

### 2.4 Route-ordering constraint (FastAPI path-param capture)

FastAPI matches routes in declaration order. If a dynamic route like `/{hotel_id}/room-types/{rt}/rate-plan` is declared before a literal-segment sibling, the literal can be silently captured as a path parameter. Two concrete risks for this router:

1. The collection routes `GET/POST /{hotel_id}/rate-plans` are two-segment paths under the prefix; the room-type routes are deeper (`/{hotel_id}/room-types/{rt}/...`). To keep the file readable and the precedent intact, the `/rate-plans` collection routes are declared **first**.
2. The `/quote` literal must be the **last** path segment under `{rt}` (`/{hotel_id}/room-types/{rt}/quote`) so it can never be captured as a `{rule_id}` value belonging to `/{hotel_id}/room-types/{rt}/rate-plan/rules/{rule_id}`. Because `/quote` sits directly under `{rt}` (not under `/rate-plan/rules/`), there is no structural overlap, but declaration order is the documented safe practice.

CLAUDE.md documents this class of bug for two existing cases: KYC `/templates` before `/{case_id}` (§"KYC template-signature endpoints"), and audit-export `/schedules` before `/{export_id}` (§"Scheduled audit export reports"). HTL-016 follows the same literal-before-dynamic discipline.

### 2.5 `main.py` registration adjacent to `inventory_router`

`app/main.py:311` imports `inventory_router`; `:877` includes it (verified). `hotel_rate_plans_router` is imported immediately after the inventory import and `include_router`'d immediately after `app.include_router(inventory_router)`, keeping the commerce/PMS vertical routers grouped. ## 3. Data Model

HTL-016 introduces **no new DynamoDB tables, no new GSIs, and no new DynamoDB attributes**. The `hotel_rate_plans` table (PK=`hotel_id#room_type_id`, SK=`META` / `RULE#{kind}#{rule_id}`) and its two GSIs (`GSI_HOTEL`, `GSI_ROOM_TYPE`) were declared by HTL-014 in `scripts/local-ddb-init.py` with `attr_types={"created_at": "N"}` (the numeric-GSI gotcha from `docs/qloapps/RATE_PLANS_TICKETS.md:152-171`). This section documents which Pydantic models flow through each endpoint and the **two net-new request/response models** HTL-016 adds for the quote endpoint.

### 3.1 Models flowing through the router (defined by HTL-014/015)

| Endpoint | Request body model | Response model |
|---|---|---|
| `GET /ui/hotels/{hotel_id}/rate-plans` | — | `{rate_plans: List[RatePlanOut], count, cursor?}` |
| `POST /ui/hotels/{hotel_id}/rate-plans` | `RatePlanIn` (+ `room_type_id`) | `RatePlanOut` |
| `GET /ui/hotels/{hotel_id}/room-types/{rt}/rate-plan` | — | `RatePlanOut` (404 if none) |
| `PUT /ui/hotels/{hotel_id}/room-types/{rt}/rate-plan` | `RatePlanUpdateIn` | `RatePlanOut` |
| `DELETE /ui/hotels/{hotel_id}/room-types/{rt}/rate-plan` | — | `RatePlanOut` (deactivated) |
| `GET /ui/hotels/{hotel_id}/room-types/{rt}/rate-plan/rules` | — | `List[RatePlanRuleOut]` |
| `POST /ui/hotels/{hotel_id}/room-types/{rt}/rate-plan/rules` | `RatePlanRuleIn` | `RatePlanRuleOut` |

`RatePlanIn`, `RatePlanOut`, `RatePlanUpdateIn`, `RatePlanRuleIn`, `RatePlanRuleOut` are HTL-014 deliverables (`docs/qloapps/RATE_PLANS_TICKETS.md:186-193`). ### 3.2 Net-new quote models (HTL-016, in `app/models.py`)

The quote endpoint needs an HTTP request body and a serializable response shape mirroring HTL-015's `StayPriceResult`. These are added to `app/models.py` adjacent to the HTL-014 rate-plan models:

```python
class StayQuoteIn(BaseModel):
    checkin: str          # "YYYY-MM-DD" inclusive (first night)
    checkout: str         # "YYYY-MM-DD" exclusive (departure day, not a night)
    adults: int = Field(ge=1)
    children: int = Field(default=0, ge=0)
    rooms: int = Field(default=1, ge=1)
    advance_days: Optional[int] = Field(default=None, ge=0)  # caller-pinnable for reproducible quotes

class NightLineOut(BaseModel):
    date: str
    base_cents: int
    season_delta_cents: int
    weekend_delta_cents: int
    occupancy_cents: int
    night_total_cents: int

class StayQuoteOut(BaseModel):     # serialization of HTL-015's StayPriceResult
    nights: int
    per_night: List[NightLineOut]
    stay_subtotal_cents: int
    los_discount_cents: int
    advance_modifier_cents: int    # signed: negative = discount
    rooms: int
    total_cents: int               # final, all rules applied, × rooms, floored ≥ 0
    currency: str
    applied_rule_ids: List[str]
```

If HTL-015 already defines `NightLineOut` / `StayPriceResult` as Pydantic models in `app/models.py` (the ticket leaves the dataclass-vs-model choice open, `docs/qloapps/RATE_PLANS_TICKETS.md:327`), the router reuses them and HTL-016 adds only `StayQuoteIn` + a thin `StayQuoteOut = StayPriceResult` alias. All money fields are integer cents; `adults ≥ 1`, `rooms ≥ 1`, `children ≥ 0`, `advance_days ≥ 0` are validated at the Pydantic layer (422 on violation, before any service call).

### 3.3 Query parameters

- `GET /ui/hotels/{hotel_id}/rate-plans` accepts `cursor: Optional[str] = None` (opaque HMAC-signed token from `encode_cursor`/`decode_cursor`, `app/core/cursor.py:94,103`; silently restarts if tampered) and `limit: int = 50` (capped server-side by the service). It queries `GSI_HOTEL` (PK=`hotel_id`, SK=`created_at` newest-first).
- `DELETE .../rules/{rule_id}` requires `kind: str` as a **query parameter** (the SK is `RULE#{kind}#{rule_id}`, so `kind` is needed to address the row) — `kind ∈ {season, occupancy, los, advance, weekend}`, 422 otherwise.
- No query parameters on the other endpoints.

## 4. API / Service Design

### 4.1 Router file: `app/routers/hotel_rate_plans.py` (new file)

```python
"""Hotel nightly rate-plan router (Hotel-PMS vertical, HTL-016).

Additive + flag-gated (``HOTEL_PMS_ENABLED``, default OFF). Every handler
calls ``_require_enabled()`` first; when the flag is off all endpoints return
404 and the platform is byte-for-byte unchanged (router still mounted).

Auth split (mirrors app/routers/inventory.py:38,48,65,81):
  * Read endpoints + /quote → ``require_ui_session``     (any authenticated user)
  * Write endpoints         → ``require_admin_or_root_csrf`` (ADMIN | ROOT + CSRF)
"""
from __future__ import annotations

from typing import List, Optional

from fastapi import APIRouter, Depends, HTTPException

from app.auth.deps import AuthenticatedUser
from app.auth.policy import require_admin_or_root_csrf
from app.models import (
    RatePlanIn, RatePlanOut, RatePlanUpdateIn,
    RatePlanRuleIn, RatePlanRuleOut,
    StayQuoteIn, StayQuoteOut,
)
from app.services import hotel_rate_plans as rp
from app.services.sessions import require_ui_session

hotel_rate_plans_router = APIRouter(prefix="/ui/hotels", tags=["hotel-rate-plans"])


def _require_enabled() -> None:
    rp._require_enabled()
```

### 4.2 Endpoint specifications (in declaration order)

All 10 handlers below are declared in this exact order. **Literal collection routes (`/rate-plans`) first; the `/quote` literal is the last segment under `{rt}`.**

```python
@hotel_rate_plans_router.delete("/{hotel_id}/room-types/{rt}/rate-plan/rules/{rule_id}")
```

```python
    hotel_id: str, rt: str, rule_id: str, kind: str,
```

#### `POST /ui/hotels/{hotel_id}/room-types/{rt}/quote` *(literal `/quote` — last segment under `{rt}`)*

```python
@hotel_rate_plans_router.post("/{hotel_id}/room-types/{rt}/quote", response_model=StayQuoteOut)
async def quote_stay(
    hotel_id: str, rt: str, body: StayQuoteIn,
    session=Depends(require_ui_session),
) -> StayQuoteOut:
    _require_enabled()
    result = rp.compute_stay_price(
        hotel_id, rt,
        checkin=body.checkin, checkout=body.checkout,
        adults=body.adults, children=body.children,
        rooms=body.rooms, advance_days=body.advance_days,
    )
    return StayQuoteOut(**(result.__dict__ if hasattr(result, "__dict__") else result))
```

## 5. Detailed Behavior & Edge Cases

### 5.1 Route-ordering correctness

The router declares `GET/POST /{hotel_id}/rate-plans` (collection) before the `/{hotel_id}/room-types/{rt}/...` routes, and `/{hotel_id}/room-types/{rt}/quote` is the **last** segment under `{rt}`. The `/quote` literal sits directly under the `{rt}` param (not under `/rate-plan/rules/`), so it cannot be captured as a `{rule_id}`. The `/rate-plans` literal collection cannot be captured as `room-types/{rt}` because the path shapes differ (`/rate-plans` is one segment after `{hotel_id}`; `/room-types/{rt}/...` is at least three). Declaration order (literal before dynamic) is the documented safe practice — same gotcha as KYC `/templates`-before-`/{case_id}` and audit-export `/schedules`-before-`/{export_id}` (CLAUDE.md, `docs/qloapps/RATE_PLANS_TICKETS.md:421-427`).

### 5.2 `POST .../rate-plans` idempotency

`create_rate_plan` uses a conditional `attribute_not_exists` put on the `META` SK (`docs/qloapps/RATE_PLANS_TICKETS.md:201-204`), so two HTTP POSTs with the same `(hotel_id, room_type_id)` return the same `rate_plan_id` and HTTP 201 both times. Idempotency is a service property; the router does nothing special. Callers should treat 201 idempotently.

### 5.3 `DELETE .../rate-plan` is soft-deactivate

`DELETE /ui/hotels/{hotel_id}/room-types/{rt}/rate-plan` calls `deactivate_rate_plan`, which flips `active=false` via an `update_item` and stamps `updated_at`. The META row and all `RULE#` children remain in DynamoDB; subsequent `get_rate_plan` returns the (deactivated) plan. This avoids cascading deletes of rule rows and keeps quote history reproducible. There is no hard-delete endpoint in HTL-016.

### 5.4 `DELETE .../rules/{rule_id}` idempotency

`delete_rule` returns `False` (never raises) for an unknown rule (`docs/qloapps/RATE_PLANS_TICKETS.md:217-219`). The HTTP response is `{"ok": False}` with status 200 — not 404. Re-deleting an already-deleted rule is a safe no-op. The `kind` query param is required (422 if missing/invalid) because the SK is `RULE#{kind}#{rule_id}`.

### 5.5 Quote endpoint — LOS rejection surfaces as 422

`compute_stay_price` raises `HTTPException(422, "stay too short")` when `nights < min_nights` and `HTTPException(422, "stay too long")` when `nights > max_nights` (`docs/qloapps/RATE_PLANS_TICKETS.md:314-318`). The router does not catch these — they propagate to the caller as 422. The frontend `StayPricePreview` shows the detail string as a toast and renders no breakdown.

### 5.6 Quote endpoint — determinism and `advance_days`

`compute_stay_price` is pure deterministic arithmetic; the only non-determinism is the `advance_days` default (derived from `now_ts()` to `checkin` when the caller omits it, `docs/qloapps/RATE_PLANS_TICKETS.md:342-345`). The `StayQuoteIn` body exposes `advance_days` so a caller (or a test) can pin it for a reproducible quote. With `advance_days` pinned, identical inputs always yield an identical breakdown.

### 5.7 CSRF enforcement on mutation endpoints

`require_admin_or_root_csrf` (`app/auth/policy.py:100-106`) runs `enforce_cookie_csrf(request)` before the role check. For cookie-auth (browser) requests it validates that `x-csrf-token` header and `ui_csrf` cookie match (403 on mismatch). Bearer-token API clients (no `ui_session` cookie) skip CSRF and are gated by role alone — consistent with every other admin endpoint in the platform. All four mutation verbs (POST/PUT/DELETE on plans and rules) require ADMIN/ROOT.

### 5.8 Quote + read endpoints accept any UI session

`GET .../rate-plans`, `GET .../rate-plan`, `GET .../rules`, and `POST .../quote` use `require_ui_session` — any authenticated user (USER/ADMIN/ROOT). The quote endpoint deliberately admits a non-admin session because a storefront price preview is a read-class operation that never mutates state. Multi-tenant isolation (a hotel's plans visible only to its operator) is out of scope here — single-platform deployment assumption (§10).

### 5.9 Flag-off behavior

When `HOTEL_PMS_ENABLED=false` (the default), every handler's first statement `_require_enabled()` delegates to `rp._require_enabled()`, which raises `HTTPException(404, ...)` per the inventory pattern (`app/services/inventory.py:54-56` analogue). The router is still mounted via `app.include_router(hotel_rate_plans_router)` — the flag check is at the handler level, not the mount level. With the flag off there are zero DynamoDB reads/writes and the platform is byte-for-byte unchanged.

### 5.10 Decimal coercion in response models

`RatePlanOut` / `RatePlanRuleOut` / `StayQuoteOut` integer fields (`*_cents`, `base_occupancy`, `created_at`, `updated_at`, `priority`, `nights`, `rooms`) must be plain `int`, not `Decimal`. HTL-014/015 service helpers coerce `Decimal → int` before returning dicts (the established pattern); the Pydantic models additionally coerce on assignment. No extra coercion in the router.

### 5.11 Frontend flag-off rendering

When the flag is off, the first `getRatePlan` / `listRules` query 404s. The editor page renders a centered callout ("Hotel rate plans are not enabled on this platform.") instead of a partial/broken UI. This matches the Inventory vertical's flag-off frontend behavior and avoids duplicating the backend's authoritative flag in the frontend.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### 7.1 SECOPS-007 — zero `dev_mode` branches

`app/routers/hotel_rate_plans.py` contains **no** `if S.dev_mode` branch. It imports no dev-mode helpers and calls no mock path. The same handler code runs in dev (moto-intercepted DynamoDB via the in-process moto layer, `app/core/dev_s3.py`) and prod (real DynamoDB). This mirrors `app/routers/inventory.py` (zero `dev_mode` branches) and the cross-cutting constraint at `docs/qloapps/RATE_PLANS_TICKETS.md:85-89`. The HTL-015 engine itself is pure deterministic arithmetic — no randomness, no time-of-day non-determinism beyond the caller-supplied / `now_ts()`-derived `advance_days`.

### 7.2 Idempotency

- `POST .../rate-plans` — idempotent on `(hotel_id, room_type_id)`: second call returns the same `rate_plan_id`, HTTP 201, no duplication (§5.2).
- `PUT .../rate-plan` and `PUT .../rules/{rule_id}` — idempotent in final state; `updated_at` advances each call (acceptable).
- `DELETE .../rate-plan` — idempotent: deactivating an already-inactive plan returns `active=false` again, no error.
- `DELETE .../rules/{rule_id}` — idempotent: deleting an already-deleted rule returns `{"ok": False}`, no error (§5.4).
- `POST .../quote` — a pure read computation: same inputs (with `advance_days` pinned) always return the same breakdown; no state change (§5.6).

### 7.3 Security

- **Mutation auth**: all POST/PUT/DELETE on plans and rules require `require_admin_or_root_csrf` (role ADMIN|ROOT + CSRF for cookie clients).
- **Read + quote auth**: `require_ui_session` — any authenticated user. The quote endpoint is read-class (computes, never persists). No ownership enforcement at the router layer (single-platform assumption, §10).
- **CSRF**: `enforce_cookie_csrf` (`app/auth/policy.py:71`) validates `x-csrf-token` header == `ui_csrf` cookie for non-GET cookie-auth requests; Bearer-auth clients are exempt.
- **Input validation**: occupancy/rooms/dates validated at the Pydantic layer (`StayQuoteIn`, 422 before any service call); rule configs validated per-kind in the service (422). `kind` allow-listed in `delete_rule` (422 otherwise).
- **Path traversal**: `hotel_id`, `rt`, `rule_id` are FastAPI path parameters (URL-encoded); no filesystem paths or shell commands — no traversal risk.

### 7.4 Money-safety

HTL-016 does **not** touch any billing table, billing service, or payment provider. The router imports only `hotel_rate_plans`, the Pydantic models, and the auth dependencies — no `billing_shared`, `new_ledger_entry`, `compute_due`, `settle_or_reverse_ledger`, `apply_balance_delta`, or any Stripe/PayPal/CCBill client. The `/quote` endpoint **computes a price; it never charges**. Money is integer cents end-to-end (the OFB-019/PRD-012 convention carried into HTL-014/015, `docs/qloapps/RATE_PLANS_TICKETS.md:48-53,79`); the engine floors every night and the stay total at ≥ 0 (`docs/qloapps/RATE_PLANS_TICKETS.md:307-308,323-325`), so no quote can ever return a negative total. Turning a quote into a charge is a future booking-cluster ticket (HTL-017 stay-search → reservation → folio), which will route every monetary row through `billing_shared.new_ledger_entry`. HTL-016 has zero financial invariants to enforce beyond surfacing the engine's floored, integer-cents total.

### 7.5 Audit trail

The router does not call `_audit()` directly — audit events (`hotel.rate_plan.created`, `hotel.rate_plan.rule.added`, etc.) are emitted by the HTL-014 service functions via the best-effort `_audit()` lazy-import wrapper (copied from `app/services/inventory.py:92-98`). Audit failure never propagates to the HTTP caller. The quote endpoint emits no audit event (it is a pure read).

9. `add_rule` against a non-existent plan → `HTTPException(404)`.
10. `add_rule` with a malformed config (bad date range / `dow` outside 1..7 / `max_nights < min_nights` / unknown mode) → `HTTPException(422)` (per-kind validator).
11. `update_rule` re-validates and stamps `updated_at`.
12. `delete_rule` handler with `kind` query → `{"ok": True}`; unknown rule → `{"ok": False}` (no exception); invalid `kind` → `HTTPException(422)`.

*Quote math (via the `quote_stay` handler, `advance_days` pinned for determinism)*
13. **season** — a night inside an `absolute` window uses the season rate; a `delta` window adds; an outside night uses `base_nightly_rate_cents`.
14. **occupancy** — `adults > base_occupancy` and/or `children > 0` add the correct per-night surcharge; `adults <= base_occupancy, children == 0` adds 0.
15. **weekend** — nights whose ISO weekday ∈ `dow` get the override/delta; weekday nights do not.
16. **los math + rejection** — in-range stay gets the discount applied to the subtotal; `nights < min_nights` → `HTTPException(422, "stay too short")`; `nights > max_nights` → `HTTPException(422, "stay too long")`.
17. **advance** — `gte`/`lte` comparator on `advance_days` toggles the modifier; `advance_modifier_cents` is signed.
18. **span summation** — `len(per_night) == nights` of `[checkin, checkout)` (checkout excluded); `stay_subtotal_cents == sum(night_total_cents)`.
19. **rooms + floor** — with no whole-stay mods, `total_cents == subtotal × rooms`; a discount larger than the subtotal yields `total_cents == 0`, never negative.
20. **determinism** — two `quote_stay` calls with identical inputs + pinned `advance_days` return byte-identical breakdowns.

*Auth / route ordering / registration*
21. Mutation handler with a `USER`-role `AuthenticatedUser` → `HTTPException(403)` from `require_admin_or_root_csrf` (role gate).
22. Route ordering: inspect `hotel_rate_plans_router.routes` and assert the `/{hotel_id}/rate-plans` route precedes the `/{hotel_id}/room-types/{rt}/rate-plan` route, and `/{hotel_id}/room-types/{rt}/quote` exists as its own route (last segment under `{rt}`, not captured by `{rule_id}`).
23. `main.py` registration: `from app.main import create_app; app = create_app()`; assert a route whose path contains `/ui/hotels/{hotel_id}/rate-plans` and one ending in `/quote` are present in `app.routes`.

## 10. Open Questions / Assumptions

### 10.1 Multi-tenant hotel isolation on read/quote endpoints

Read endpoints and `/quote` do not enforce that the caller's `user.sub` owns the hotel — any authenticated session can read any hotel's rate plans or request a quote.

**Assumption**: single-platform deployment where admins/root operate the same property entity, and a quote is a storefront-facing price preview that is intentionally readable by any logged-in user. If per-hotel isolation is later required, an ownership check (fetch the plan, compare a hotel-owner field to `session["user_sub"]`, 403/404 on mismatch) is a non-breaking additive change.

### 10.2 Quote verb — POST vs GET

`/quote` uses POST because the request carries a structured body (dates + occupancy + advance_days). A GET with query params is an alternative, but POST-with-body is the cleaner contract for a compute endpoint and matches search/compute POST endpoints elsewhere.

**Assumption**: POST with `require_ui_session` (a read-class auth) is acceptable; the endpoint never mutates state, so it is idempotent and cacheable at the application layer if needed.

### 10.3 `list_rate_plans` helper existence

The `GET .../rate-plans` handler assumes HTL-014 exposed a `GSI_HOTEL`-backed listing helper (`docs/qloapps/RATE_PLANS_TICKETS.md:154-156` describes the index purpose). If HTL-014 did not ship a `list_rate_plans` function, HTL-016 adds a thin service helper (a `GSI_HOTEL` query + cursor pagination via `encode_cursor`/`decode_cursor`) — additive, in `app/services/hotel_rate_plans.py`, no new table.

**Assumption**: the `GSI_HOTEL` listing helper is either present or trivially addable; the router shape is unaffected.

### 10.4 `NightLineOut` / `StayQuoteOut` ownership

HTL-015 leaves the dataclass-vs-Pydantic choice open (`docs/qloapps/RATE_PLANS_TICKETS.md:327`). If HTL-015 already defined Pydantic `NightLineOut` / `StayPriceResult`, HTL-016 reuses them and adds only `StayQuoteIn`. If HTL-015 used a dataclass, HTL-016 adds the Pydantic `NightLineOut` / `StayQuoteOut` mirror in `app/models.py` (§3.2) and serializes the dataclass into it.

**Assumption**: either path yields the same wire shape; the §3.2 models are the canonical wire contract.

### 10.5 Sidebar entry destination

The Sidebar "Hotels" entry points at `/hotels`, but HTL-016 only ships the rate-plan **editor** route (`/hotels/:hotelId/room-types/:rt/rate-plan`). A `/hotels` index/listing page is a sibling-cluster deliverable (the HTL room-type cluster).

**Assumption**: the Sidebar entry is optional in HTL-016 (`docs/qloapps/RATE_PLANS_TICKETS.md:474-477` says "optionally surface"); if added before the `/hotels` index exists, it can point at a placeholder or be deferred until the room-type cluster ships the index.
