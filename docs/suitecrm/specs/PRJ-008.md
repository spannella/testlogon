# PRJ-008 — Gantt chart frontend component

**Ticket type:** Feature  
**Priority:** P1  
**Estimate:** 3 days  
**Flag:** `CRM_PROJECTS_ENABLED` (existing, default `"0"`) / `VITE_CRM_PROJECTS_ENABLED` (frontend)

---

## 1. Summary & Goal

PRJ-008 delivers the interactive Gantt chart view for CRM projects. It is a pure-frontend feature: no new DynamoDB tables, no new API endpoints, and no new service logic. The component consumes the task API introduced by PRJ-003/PRJ-004 (endpoint `GET /v1/crm/projects/{project_id}/tasks`) and renders each task as a proportional bar using the `gantt-task-react` library. Milestone tasks render as diamond markers. Dependency arrows link tasks that carry `predecessor_task_ids`. A slide-over panel allows inline editing of a selected task without leaving the Gantt view.

The goal matches SuiteCRM's Gantt tab in its Projects module: visual timeline with Day/Week/Month zoom, milestone diamonds, dependency arrow rendering, and resource annotations — all gated by the `CRM_PROJECTS_ENABLED` flag so the existing platform is byte-for-byte unchanged when the flag is off.

## 3. Data Model

PRJ-008 introduces no new DynamoDB tables and no schema changes. It reads from tables scaffolded by PRJ-001:

**`crm_pm_projects` table** (PRJ-001/PRJ-002):
- `PK = OWNER#{user_sub}`, `SK = PROJECT#{project_id}`
- GSI1: `GSI1PK = PROJECT#{project_id}` for single-project lookup
- GSI2: `GSI2PK = STATUS#{status}`, `GSI2SK = created_at` (`attr_types={"GSI2SK": "N"}`)

**`crm_pm_tasks` table** (PRJ-001/PRJ-003):
- `PK = PROJECT#{project_id}`, `SK = TASK#{task_order:06d}#{task_id}`
- Relevant attributes consumed by the Gantt component:
  - `id` (str), `name` (str), `task_order` (int), `start_date` (int, Unix seconds), `end_date` (int, Unix seconds), `percent_complete` (int 0-100), `is_milestone` (bool), `assigned_user_sub` (Optional[str]), `predecessor_task_ids` (List[str])
- GSI2: `GSI2PK = ASSIGNEE#{user_sub}`, `GSI2SK = end_date` (`attr_types={"GSI2SK": "N"}`) — not queried directly by Gantt, but surfaced in the task list response

No `scripts/local-ddb-init.py` changes are required for PRJ-008. Both tables are created by PRJ-001.

## 4. API / Service Design

PRJ-008 is frontend-only. It calls two existing backend endpoints (provided by PRJ-002 and PRJ-003) and one PATCH endpoint (PRJ-003). No new backend endpoints are added.

**Endpoints consumed:**

```
GET  /v1/crm/projects/{project_id}
     Auth: require_ui_session (cookie + ui_access_token JWT)
     Response: CrmProjectOut { id, name, status, priority, start_date, end_date, ... }

GET  /v1/crm/projects/{project_id}/tasks
     Auth: require_ui_session
     Query params: limit (int, default 200), cursor (opaque pagination cursor from
                   app/core/cursor.encode_cursor, app/core/cursor.py:94)
     Response: { items: CrmProjectTaskOut[], cursor: str | null }
     Note: tasks returned in ascending task_order (ScanIndexForward=True per PRJ-003)

PATCH /v1/crm/projects/{project_id}/tasks/{task_id}
     Auth: require_ui_session + member-or-owner role check (PRJ-007)
     Body: CrmTaskUpdateIn (partial; any subset of name, start_date, end_date,
           percent_complete, assigned_user_sub, duration_days)
     Response: CrmProjectTaskOut
```

## 5. Detailed Behavior & Edge Cases

### 5.1 Library installation

Add `gantt-task-react` to `frontend/package.json` dependencies. The package publishes as `gantt-task-react` on npm (MIT license) and exports `{ Gantt, Task, ViewMode }`. No server-side rendering dependency. No extra Vite config is required.

### 5.2 Data fetching strategy

`CrmProjectGanttPage` (located at `frontend/src/pages/crmProjects/CrmProjectGanttPage.tsx`) fetches both the project header and all tasks in parallel:

```typescript
const projectQuery = useQuery({
  queryKey: ["crm-projects", projectId],
  queryFn: () => getCrmProject(projectId!),
  enabled: Boolean(projectId),
});

const tasksQuery = useQuery({
  queryKey: ["crm-project-tasks", projectId],
  queryFn: () => listCrmProjectTasks(projectId!, { limit: 200 }),
  enabled: Boolean(projectId),
});
```

The `limit: 200` cap is intentional: PRJ-003 implements cursor pagination (`encode_cursor` at `app/core/cursor.py:94`) but the Gantt library requires the full task array in memory at render time. If `cursor` is non-null in the response, the component loads additional pages sequentially before rendering and shows the `Loader2` spinner during accumulation. This avoids partial renders with missing dependency arrows.

### 5.3 Task-to-Gantt mapping

```typescript
function toGanttTask(task: CrmProjectTask): Task {
  const startMs = (task.start_date ?? 0) * 1000;
  const endMs   = (task.end_date   ?? startMs + 86_400_000) * 1000;
  return {
    id:           task.id,
    name:         task.name,
    type:         task.is_milestone ? "milestone" : "task",
    start:        new Date(startMs),
    end:          new Date(endMs),
    progress:     task.percent_complete,
    dependencies: task.predecessor_task_ids,
    styles:       task.is_milestone ? { backgroundColor: "#6366f1" } : undefined,
  };
}
```

Edge cases:
- **No `start_date`**: task was created without dates (valid per PRJ-003 model where `start_date` is Optional). The fallback `start` is `new Date(0)` (epoch). Such tasks render at the far left of the timeline with a one-day width. A warning badge "Undated tasks" appears in the toolbar when one or more tasks lack dates.
- **`end_date` equals `start_date`**: duration is zero. The library clamps to one day width visually; no crash.
- **No tasks**: when `items` is empty the library renders an empty grid. The page shows an `EmptyState` component ("No tasks yet — add tasks from the Tasks tab") instead of the Gantt wrapper.
- **Single task, no predecessors**: renders correctly; no dependency arrow drawn.
- **Tasks with missing predecessor IDs**: if a `predecessor_task_ids` entry references a task ID not present in the current page (deleted task), the `gantt-task-react` library silently ignores the missing dependency and renders without an arrow. No error is thrown.

### 5.4 View mode toolbar

A segmented control rendered above the chart offers three view modes matching the `ViewMode` enum exported by `gantt-task-react`: `ViewMode.Day`, `ViewMode.Week`, `ViewMode.Month`. Default is `ViewMode.Day`. The selected mode is stored in local `useState` (not React Query, not URL params) — it is a pure display preference and need not survive navigation.

```typescript
const [viewMode, setViewMode] = React.useState<ViewMode>(ViewMode.Day);
```

### 5.5 Task-click slide-over (inline edit)

Clicking a Gantt bar fires the library's `onSelect` callback with the `Task` object. The page maps the clicked `task.id` back to its `CrmProjectTask` and opens a shadcn/ui `Sheet` (right-side drawer, `frontend/src/components/ui/sheet.tsx`) containing a `CrmTaskEditForm` sub-component.

`CrmTaskEditForm` accepts: `task: CrmProjectTask`, `projectId: string`, `onClose: () => void`. It renders with React Hook Form + Zod:

```typescript
const schema = z.object({
  name:             z.string().min(1).max(200),
  start_date:       z.number().optional(),
  end_date:         z.number().optional(),
  percent_complete: z.number().int().min(0).max(100),
  assigned_user_sub:z.string().optional(),
});
```

On submit:
```typescript
const updateMutation = useMutation({
  mutationFn: (data: CrmTaskUpdateReq) =>
    updateCrmProjectTask(projectId, task.id, data),
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ["crm-project-tasks", projectId] });
    onClose();
  },
  onError: () => toast.error("Failed to save task"),
});
```

The `Sheet` closes and the Gantt re-fetches after a successful save, reflecting updated bar positions and progress fill.

### 5.6 Loading and error states

- **Loading**: while either `projectQuery.isLoading` or `tasksQuery.isLoading` is true, render a full-height centred `<Loader2 className="animate-spin" />` (same pattern as `frontend/src/pages/projects/ProjectDetailPage.tsx:46-48`).
- **Feature-flag error (404)**: if `getCrmProject` returns 404 (flag off), catch the error and render a neutral `<Alert>` with text "CRM Projects is not enabled for this environment." No redirect, no crash.
- **Other errors**: render `<Alert variant="destructive">` with the error message.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

**No backend changes**: PRJ-008 is frontend-only. All backend services (auth, DDB, cursor pagination) were delivered by PRJ-001 through PRJ-005 and already follow SECOPS-007 (same code path dev and prod, no `dev_mode` branches in service layer).

**Auth**: all three consumed endpoints use `Depends(require_ui_session)` (same dep as `app/routers/projects.py:169`). The `api` client in `frontend/src/api/client.ts` attaches the `x-csrf-token` header from the `ui_csrf` cookie on every non-GET request. The PATCH call for task edit goes through this path.

**No money-out path**: this feature involves no payments, refunds, or billing ledger writes. The refund/ledger primitives (`refund_payment`, `settle_or_reverse_ledger`) are not applicable.

**No S3 uploads**: the Gantt component renders SVG in-browser via `gantt-task-react`. No file uploads.

**No KMS calls**: the component reads only task metadata (dates, names, percent_complete). No encrypted fields.

**Idempotency**: the PATCH (`updateCrmProjectTask`) is idempotent by design — re-sending the same field values yields the same task state. React Query cache invalidation after success ensures the UI re-reads the authoritative backend state.

**XSS**: task `name` values are mapped to the `gantt-task-react` `Task.name` prop, which the library renders as SVG `<text>` elements. SVG text elements are not HTML and do not parse embedded HTML. React's reconciler never calls `dangerouslySetInnerHTML` for these values. Safe by construction.

**Authorization boundary**: the PATCH endpoint enforces `_assert_project_access(caller_sub, project_id, min_role="member")` (PRJ-007). The frontend's slide-over form omits the Save button when the current user is a viewer, but the backend enforces the role check independently as the authoritative guard.

## 10. Open Questions / Assumptions

1. **`gantt-task-react` exact version**: the spec targets the latest published MIT release. If the library API changes the `Task` shape between versions, the mapping in section 5.3 must be updated. A pinned version in `package.json` is recommended to avoid silent regressions.

2. **Viewer-role edit suppression**: PRJ-007 defines `_assert_project_access` but that ticket is listed as a dependency. Until PRJ-007 lands, the edit form is shown to all authenticated users. The backend enforces the role check, so a viewer who submits the form receives a `403` which the form displays as a toast error. The UI-only suppression of the Save button for viewers is deferred to PRJ-012 (which wires the member role into the detail page).

3. **Large projects**: `limit: 200` per page is an assumption about typical project size. Projects with more than 200 tasks will require multi-page accumulation (section 5.2). If a project exceeds 1000 tasks, the sequential accumulation loop may introduce perceptible loading delay. A future optimization (PRJ-013+) could implement windowed rendering; this is out of scope for PRJ-008.

4. **Date display timezone**: `gantt-task-react` uses the browser's local timezone for rendering `Date` objects. Unix-second timestamps from the backend are timezone-neutral. No server-side timezone conversion is needed; the browser's local timezone governs bar placement. If a future requirement demands UTC rendering, a `Date` wrapper function can be injected.

5. **`assigned_user_sub` display name**: `CrmProjectTask.assigned_user_sub` is a raw `user_sub` string. The Gantt library's resource row feature requires a display name. For PRJ-008, the resource label renders the raw `user_sub` truncated to 12 characters. PRJ-012 will resolve display names from the user profile API.

6. **PRJ-007 dependency**: PRJ-008 lists PRJ-007 (project team members) as a soft prerequisite. The Gantt component does not call the members API itself, but the inline edit form in `CrmTaskEditForm` assigns `assigned_user_sub`. Without PRJ-007, the assignment field accepts a free-text `user_sub` value rather than a member-picker dropdown. The picker enhancement is deferred to PRJ-012.
