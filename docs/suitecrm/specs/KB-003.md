# KB-003 — Article file attachments (S3 upload + download)

**Type:** Feature  **Priority:** P1  **Estimate:** 2 days  
**Ticket source:** `docs/suitecrm/CRM_KNOWLEDGE_BASE_TICKETS.md`, section "KB-003"

---

## 1. Summary & Goal

KB-003 allows admins to attach files (PDFs, images, Word documents, spreadsheets) to Knowledge Base articles. Attachment bytes are stored in S3 under a deterministic key path. Attachment metadata is recorded as `ATTACHMENT#{attachment_id}` sub-items on the existing `crm_kb_articles` DynamoDB table — the same table that holds article META rows. Authenticated users (or unauthenticated visitors for published articles) can list attachments and obtain download URLs. Admin-only endpoints handle upload and soft-delete.

The feature is entirely additive and default-OFF. With `KNOWLEDGE_BASE_ENABLED=0` (or absent) every new route returns 404 and no S3 or DynamoDB write is ever attempted. No existing file, route, or service is modified.

### 2.2 S3 upload pattern

The canonical S3 upload pattern is `app/routers/newsfeed.py:3117–3135` (`POST /uploads/image`):
1. `await file.read()` — reads multipart bytes into memory.
2. Size check against `_MAX_UPLOAD_BYTES` (raises `HTTPException(400, ...)` when exceeded; KB-003 raises 413).
3. Key construction: `f"uploads/{user_id}/{attachment_id}/{safe_name}"`.
4. `s3.put_object(Bucket=UPLOAD_BUCKET, Key=s3_key, Body=content, ContentType=...)`.
5. Return a URL path.

The S3 client is always obtained from the centralized factory `app.core.aws_clients.s3_client()` (`app/core/aws_clients.py:114–122`). In dev mode moto intercepts boto3 S3 calls in-process (no endpoint URL is set, `app/core/aws_clients.py:81–83`); in prod the real S3 service is used. No `S.dev_mode` branch is needed in the feature code — the same `s3_client()` call works both ways (SECOPS-007 parity).

### 2.3 Presigned URL pattern

The canonical presigned URL / dev-fallback pattern is `app/services/kyc_partner_api.py:583–649` (`get_document_download`):

## 3. Data Model

### 3.1 Attachment sub-item (new row type on existing table)

No new DynamoDB table is created. All attachment metadata lives in `crm_kb_articles` alongside the article META rows.

```
Table:  crm_kb_articles   (created by CAS-001, extended by KB-001)
  Hash key:  pk  (S)
  Sort key:  sk  (S)

New row type — Attachment metadata:
  pk:             "ARTICLE#{article_id}"        (same PK as article META)
  sk:             "ATTACHMENT#{attachment_id}"
  attachment_id:  str   — "att_" + uuid4().hex (see §4.1)
  article_id:     str
  filename:       str   — sanitized original filename (max 255 chars)
  content_type:   str   — MIME type as declared by uploader
  size_bytes:     int   — byte length of the stored object
  s3_key:         str   — full S3 object key
  uploaded_by:    str   — user_sub of uploading admin
  created_at:     int   — Unix timestamp integer (now_ts())
  deleted_at:     int | absent — Unix timestamp of soft-delete; absent = active
```

**No new GSI is required.** All attachment queries are `query(PK="ARTICLE#{article_id}", KeyConditionExpression=Key("pk").eq("ARTICLE#{id}") & Key("sk").begins_with("ATTACHMENT#"))`. This is a direct hot-partition query that does not touch the ByCategory, ByStatus, ByAuthor, or ByTag GSIs.

### 3.2 `scripts/local-ddb-init.py` change

No new `TableDef` row is needed because `crm_kb_articles` already exists. The attachment sub-items use only `pk` (S) and `sk` (S), which are the table's existing hash/sort keys — no numeric attribute requires an `attr_types` declaration for the attachment rows.

The KB-001 spec has already confirmed that `attr_types={"published_at": "N", "created_at": "N"}` is declared on the table. KB-003 does not change that declaration.

### 3.3 Attachment count limit

A hard limit of **50 attachments per article** is enforced at upload time. The service queries `ATTACHMENT#` sub-items and counts active (non-soft-deleted) rows before inserting a new one. This keeps the per-article partition size bounded. The limit is governed by `S.kb_attachment_max_per_article` (new setting, see §6).

## 4. API / Service Design

### 4.1 Service additions — `app/services/kb_articles.py`

All four methods are added to the existing `KbArticleService` class (introduced by CAS-015). They import `T` from `app/core/tables`, `now_ts` from `app/core/time`, and `audit_event` from `app/services/alerts`.

```python
def add_attachment(
    self,
    article_id: str,
    *,
    uploaded_by: str,
    filename: str,
    content_type: str,
    size_bytes: int,
    s3_key: str,
) -> dict[str, Any]:
    """Write an ATTACHMENT# sub-item. Returns the full item dict."""
    ...

def list_attachments(self, article_id: str) -> list[dict[str, Any]]:
    """Query PK=ARTICLE#{article_id}, SK begins_with ATTACHMENT#.
    Returns only items where deleted_at is absent (active attachments).
    """
    ...

def get_attachment(self, article_id: str, attachment_id: str) -> dict[str, Any]:
    """Fetch a single ATTACHMENT# sub-item. Raises HTTPException(404) if
    not found or soft-deleted.
    """
    ...

def delete_attachment(
    self, article_id: str, attachment_id: str, admin_sub: str
) -> dict[str, Any]:
    """Soft-delete: sets deleted_at=now_ts() on the sub-item.
    Does NOT delete the S3 object (S3 lifecycle policy handles cleanup).
    Calls audit_event("kb.attachment.deleted", admin_sub, ...).
    Returns the updated item.
    """
    ...
```

**`add_attachment` detail:**
1. Verify that `article_id` resolves to a live article META row (raises `HTTPException(404)`) by calling `self.get_article(article_id)` (CAS-015 method).
2. Count active attachments for the article: `query(PK, SK begins_with ATTACHMENT#)`, filter `deleted_at` absent, count. If count >= `S.kb_attachment_max_per_article`, raise `HTTPException(400, {"code": "kb_attachment_limit_reached", ...})`.
3. Generate `attachment_id = "att_" + uuid4().hex` (same pattern as `new_id("att")` at `app/routers/newsfeed.py:3128`).
4. Write item via `T.kb_articles.put_item(Item={...})`.
5. Call `audit_event("kb.attachment.uploaded", uploaded_by, article_id=article_id, attachment_id=attachment_id, filename=filename, size_bytes=size_bytes)`.
6. Return the item dict.

**`list_attachments` detail:**
1. `T.kb_articles.query(KeyConditionExpression=Key("pk").eq(f"ARTICLE#{article_id}") & Key("sk").begins_with("ATTACHMENT#"))`.
2. Filter client-side: return only items where `"deleted_at" not in item`.
3. Sort by `created_at` ascending.

**`get_attachment` detail:**
1. `T.kb_articles.get_item(Key={"pk": f"ARTICLE#{article_id}", "sk": f"ATTACHMENT#{attachment_id}"})`.
2. If item is absent or `deleted_at` is present, raise `HTTPException(404, {"code": "kb_attachment_not_found", ...})`.
3. Return item dict.

**`delete_attachment` detail:**
1. Call `get_attachment(article_id, attachment_id)` to verify existence.
2. `T.kb_articles.update_item(Key=..., UpdateExpression="SET deleted_at = :ts", ExpressionAttributeValues={":ts": now_ts()})`.
3. Call `audit_event("kb.attachment.deleted", admin_sub, article_id=article_id, attachment_id=attachment_id)`.
4. Return the updated item.

### 4.3 Router additions — `app/routers/kb_articles.py`

All four endpoints are gated with `if not S.knowledge_base_enabled: raise HTTPException(404)` at the top of each handler (consistent with the flag-gate pattern prescribed by the ticket source). All four are declared **before** any `/{article_id}` dynamic route to prevent the literal segment `attachments` being swallowed as an article ID (`docs/suitecrm/CRM_KNOWLEDGE_BASE_TICKETS.md:27`).

```
POST   /kb/articles/{article_id}/attachments
GET    /kb/articles/{article_id}/attachments
GET    /kb/articles/{article_id}/attachments/{attachment_id}
DELETE /kb/articles/{article_id}/attachments/{attachment_id}
```

**`POST /kb/articles/{article_id}/attachments`** — multipart upload; admin-only.

```python
@router.post("/kb/articles/{article_id}/attachments", response_model=KbAttachmentOut)
async def upload_kb_attachment(
    article_id: str,
    file: UploadFile = File(...),
    user: AuthenticatedUser = Depends(get_authenticated_user),
):
    if not S.knowledge_base_enabled:
        raise HTTPException(404)
    if not _is_admin(user):
        raise HTTPException(403, "Admin required")
    _validate_content_type(file.content_type)
    content = await file.read()
    if len(content) > S.kb_attachment_max_bytes:
        raise HTTPException(413, {"code": "kb_attachment_too_large",
                                  "max_bytes": S.kb_attachment_max_bytes,
                                  "size_bytes": len(content)})
    safe_name = re.sub(r"[^A-Za-z0-9._-]", "_", file.filename or "file")[:255]
    attachment_id = "att_" + uuid4().hex
    s3_key = (f"{S.kb_attachments_s3_prefix}"
              f"{article_id}/{attachment_id}/{safe_name}")
    try:
        s3_client().put_object(
            Bucket=S.kb_attachments_bucket,
            Key=s3_key,
            Body=content,
            ContentType=file.content_type or "application/octet-stream",
        )
    except ClientError as exc:
        raise HTTPException(500, f"S3 error: {exc.response['Error'].get('Message','unknown')}") from exc
    item = KbArticleService().add_attachment(
        article_id,
        uploaded_by=user.sub,
        filename=safe_name,
        content_type=file.content_type or "application/octet-stream",
        size_bytes=len(content),
        s3_key=s3_key,
    )
    return _attachment_item_to_out(item)
```

Note: `attachment_id` is generated in the router before the S3 `put_object` so the S3 key embeds it. The service `add_attachment` receives the already-computed `attachment_id` as a parameter (not shown above for brevity, but the signature includes it).

**`GET /kb/articles/{article_id}/attachments`** — public for published articles; no auth required.

```python
@router.get("/kb/articles/{article_id}/attachments", response_model=list[KbAttachmentOut])
```

**`GET /kb/articles/{article_id}/attachments/{attachment_id}`** — presigned URL; public for published articles.

```python
@router.get("/kb/articles/{article_id}/attachments/{attachment_id}",
```

### 4.4 Router helper functions

```python
def _is_admin(user: AuthenticatedUser) -> bool:
    """Mirror of app/routers/tickets.py:207."""
    return normalize_role(user.role) in {Role.ADMIN, Role.ROOT}


_ALLOWED_CONTENT_TYPES: frozenset[str] = frozenset({
    "application/pdf",
    "application/msword",
    "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
    "application/vnd.ms-excel",
    "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
    "application/vnd.ms-powerpoint",
    "application/vnd.openxmlformats-officedocument.presentationml.presentation",
    "text/plain",
    "text/csv",
    "image/jpeg",
    "image/png",
    "image/gif",
    "image/webp",
    "image/svg+xml",
})


def _validate_content_type(content_type: str | None) -> None:
    ct = (content_type or "").split(";")[0].strip().lower()
    if ct not in _ALLOWED_CONTENT_TYPES:
        raise HTTPException(400, {"code": "kb_attachment_unsupported_type",
                                  "content_type": ct,
                                  "allowed": sorted(_ALLOWED_CONTENT_TYPES)})


def _make_download_url(s3_key: str) -> str:
    """Return /mock/s3/... in dev, presigned S3 URL in prod.
    Pattern: app/services/kyc_partner_api.py:630–641.
    """
    bucket = S.kb_attachments_bucket
    if S.dev_mode:
        return f"/mock/s3/{bucket}/{s3_key}"
    try:
        return s3_client().generate_presigned_url(
            "get_object",
            Params={"Bucket": bucket, "Key": s3_key},
            ExpiresIn=300,
        )
    except Exception:
        logger.warning("kb.attachment.presign_failed key=%s", s3_key)
        raise HTTPException(503, {"code": "kb_attachment_unavailable",
                                  "message": "Download temporarily unavailable"})


def _attachment_item_to_out(item: dict[str, Any]) -> KbAttachmentOut:
    return KbAttachmentOut(
        attachment_id=item["attachment_id"],
        article_id=item["article_id"],
        filename=item["filename"],
        content_type=item["content_type"],
        size_bytes=int(item.get("size_bytes") or 0),
        url=item.get("url", ""),   # populated by caller when presigning
        created_at=int(item.get("created_at") or 0),
        uploaded_by=str(item.get("uploaded_by") or ""),
    )


def _require_published_or_admin(article_id: str, user: AuthenticatedUser | None) -> None:
    """For public list/get endpoints: ensure article is published, or caller is admin."""
    if user is not None and _is_admin(user):
        return
    article = KbArticleService().get_article(article_id)   # 404 if not found
    if article.get("status") != "published":
        raise HTTPException(404)
```

## 5. Detailed Behavior & Edge Cases

### 5.1 S3 key construction

```
s3_key = f"{S.kb_attachments_s3_prefix}{article_id}/{attachment_id}/{safe_name}"
```

Example: `kb-attachments/art_abc123/att_def456/my_document.pdf`

The `attachment_id` component makes the key unique even if the same filename is uploaded twice. The filename component preserves the original name for human readability when downloaded. `safe_name` is produced by `re.sub(r"[^A-Za-z0-9._-]", "_", filename)[:255]` (identical to `app/services/kyc_partner_api.py:489`), preventing path traversal via `../` sequences or shell-special characters.

### 5.2 Draft article visibility

- An admin uploading an attachment to a draft article succeeds unconditionally (the article need not be published).
- `GET /kb/articles/{id}/attachments` for a draft article: if the caller has admin role, return the list; if the caller has no role or USER role, return 404 (the article itself is not publicly visible).
- `GET /public/kb/articles/{id}` (KB-011) includes `attachments: list[KbAttachmentOut]` only when `status="published"`.

### 5.3 Soft-delete semantics

`DELETE` sets `deleted_at` on the DDB sub-item and returns 200. The S3 object is **not** deleted. Rationale: S3 object deletions are irreversible and audit trails require the key to remain traceable. An S3 lifecycle policy can purge objects with keys matching `kb-attachments/*` that are older than a configurable retention window. The `deleted_at` timestamp on the DDB item is the authoritative marker for filtering in `list_attachments`.

Soft-deleted items are never returned by `list_attachments` or `get_attachment`. A `GET .../attachments/{id}` for a soft-deleted attachment returns 404 (same as not found), preventing URL leakage.

### 5.4 Re-upload of the same filename

If the same filename is uploaded twice, both create distinct `ATTACHMENT#` sub-items with distinct `attachment_id` and distinct S3 keys. The older file is not overwritten. Admins must explicitly delete the unwanted attachment.

### 5.5 Size enforcement

`S.kb_attachment_max_bytes` (default 20 MB) is enforced after `await file.read()`. If the upload exceeds this size, the bytes are discarded and `HTTPException(413)` is returned before any `put_object` call. This avoids partial S3 writes. Note: `file.read()` loads the entire body into memory, which is acceptable for the 20 MB cap. If the cap is raised significantly in future, streaming via `s3_client().upload_fileobj(file.file, ...)` should replace the in-memory approach.

### 5.6 Attachment count limit

Default: 50 active attachments per article. Exceeded limit returns `HTTPException(400, code="kb_attachment_limit_reached")`. Soft-deleted items are not counted toward the limit, so deleting an attachment frees a slot.

### 5.7 Article not found

If `article_id` does not match any META row in `crm_kb_articles`, `add_attachment` raises `HTTPException(404)` before attempting the S3 write. This prevents orphaned S3 objects for non-existent articles.

### 5.8 Concurrent upload race

Two simultaneous uploads to the same article with identical filenames produce two distinct `ATTACHMENT#` rows (different `attachment_id`, different S3 keys). There is no unique-filename constraint. This is intentional — uniqueness is guaranteed by the `attachment_id` UUID component.

### 5.9 Content-type spoofing

The router validates `file.content_type` against `_ALLOWED_CONTENT_TYPES`. This list covers the primary document and image formats SuiteCRM supports. Magic-byte sniffing is not performed for MVP (it would require a `python-magic` dependency not currently in the project). Operators wishing to add stricter content inspection can do so by extending `_validate_content_type` without changing the DDB schema.

### 5.10 S3 `ClientError` handling

If `put_object` raises `ClientError`, the router returns `HTTPException(500)`. No DDB item is written (the `add_attachment` call is not reached). The upload is atomic in the sense that a partial S3 failure leaves no dangling DDB row.

### 5.11 Presigned URL expiry

Presigned URLs expire in 300 seconds (5 minutes), matching the pattern in `app/services/kyc_partner_api.py:639`. Clients that need longer-lived URLs must re-request the download endpoint. The `url` field in `KbAttachmentOut` is therefore ephemeral and must not be cached by API clients.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 Dev/prod parity

The single `if S.dev_mode` check is confined to `_make_download_url` (§4.4), which returns a `/mock/s3/...` path in dev and a presigned URL in prod. All other code — the DDB writes, the S3 `put_object`, the `list_attachments` query, the `delete_attachment` update — runs identically in both environments. In dev, moto intercepts `s3_client().put_object(...)` at the botocore layer (`app/core/aws_clients.py:81–83`); the application code is unaware of the difference. This matches the SECOPS-007 parity pattern established by `app/services/kyc_partner_api.py:480–508`.

### 7.2 Idempotency

There is no idempotency key on attachment upload. Each `POST` creates a new `ATTACHMENT#` sub-item. If a client retries after a network timeout, it may create a duplicate entry and a duplicate S3 object. Operators can detect duplicates via identical `filename` + `created_at` values and delete one. Future enhancement: accept an optional `idempotency_key` header and store it on the sub-item with a conditional write.

### 7.3 Access control

- Upload (`POST`) and delete (`DELETE`) require admin or root role. A USER-role caller receives 403.
- List (`GET .../attachments`) and single-attachment URL (`GET .../attachments/{id}`) are public for published articles. For draft or archived articles they return 404 to unauthenticated callers, preventing enumeration of unpublished content.
- Presigned URLs are time-limited (300 s) and tied to a specific S3 key. An attacker with a leaked URL can download the file within 5 minutes; there is no additional session check on the S3 presigned URL (standard S3 behavior).

### 7.4 Filename sanitization

`re.sub(r"[^A-Za-z0-9._-]", "_", filename)[:255]` (pattern from `app/services/kyc_partner_api.py:489`) prevents path traversal characters (`/`, `\`, `..`) and shell-special characters from reaching the S3 key. The length cap prevents excessively long filenames.

### 7.5 No money-out path

KB-003 involves no billing, refunds, or ledger entries. The additive constraint "any money-out reuses `refund_payment` / `settle_or_reverse_ledger`" is satisfied vacuously.

### 7.6 Audit trail

Every successful upload emits `audit_event("kb.attachment.uploaded", admin_sub, ...)` and every soft-delete emits `audit_event("kb.attachment.deleted", admin_sub, ...)`. This provides a full trail of who attached and who removed files, queryable via the existing audit export mechanism (`app/services/audit_export_worker.py`).

## 8. Backward Compatibility & Migration

### 8.1 No breaking changes

All changes are purely additive:
- New DDB sub-item type (`ATTACHMENT#`) on an existing table — existing queries use specific SK prefixes or `begins_with("META")` and are unaffected.
- New settings fields on `Settings` dataclass — frozen dataclass additions are backward-compatible because `os.environ.get` provides defaults.
- New fields on `Tables` dataclass — same reasoning.
- New routes on an existing router — FastAPI route matching is sequential; new routes do not shadow existing ones.
- New Pydantic model `KbAttachmentOut` — additive to `app/models.py`.

### 8.2 DDB migration

No `UpdateTable` call is required. The new `ATTACHMENT#` SK prefix is simply a new access pattern on the existing table; no GSI, no attribute type change, and no backfill is needed. The table capacity is PAY_PER_REQUEST (`BillingMode="PAY_PER_REQUEST"` throughout `scripts/local-ddb-init.py`) so no throughput planning is required.

### 8.3 S3 bucket

In dev, the `local-uploads` bucket is already created by the moto in-process mock at app startup (`app/core/dev_s3.py`). No bucket creation step is required for KB-003. In prod, `KB_ATTACHMENTS_BUCKET` should point to a pre-existing or newly-provisioned bucket with:
- Server-side encryption (AES-256 or AWS KMS).
- Lifecycle rules to expire (hard-delete) objects more than 90 days after their corresponding DDB row has a `deleted_at` set (manual or automated via a periodic sweep).
- No public-read ACL (all access via presigned URLs).

### 8.4 Rollback

Setting `KNOWLEDGE_BASE_ENABLED=0` returns all KB-003 routes to 404 with no database rollback. Existing `ATTACHMENT#` DDB rows are harmless (they are only read when the flag is on). S3 objects for uploaded attachments remain in the bucket until the lifecycle policy expires them.

## 10. Open Questions / Assumptions

1. **S3 bucket creation in prod**: The spec assumes `KB_ATTACHMENTS_BUCKET` points to a pre-existing bucket. If the platform manages bucket provisioning via CDK/Terraform, a new bucket definition for KB attachments will be needed. This is outside the scope of KB-003 but should be tracked as an infra ticket.

2. **Content-type vs. magic-byte validation**: The MVP validates `file.content_type` from the multipart headers. Browsers set this from the file extension, not the actual byte content. A malicious admin (already elevated privilege) could upload an executable disguised as a PDF. Magic-byte sniffing is not implemented to avoid adding a `python-magic` or `filetype` dependency. Accepted risk given that only admins can upload.

3. **S3 key format for very long article IDs**: If `article_id` is longer than expected (e.g., from a bug), the S3 key could exceed 1024 bytes (S3 limit). The spec assumes `article_id` follows the `art_{uuid4().hex}` convention (36 chars) — this is safe. A defensive check on combined key length is recommended but not required for MVP.

4. **Streaming vs. in-memory read**: The spec uses in-memory `await file.read()` (matching `app/routers/newsfeed.py:3125`). For a 20 MB cap this is acceptable. If the cap is raised to 100+ MB in future, streaming via `upload_fileobj` should replace it to avoid memory pressure.

5. **Attachment ordering in `KbArticleOut`**: The ticket source states `KbArticleOut.attachments: list[KbAttachmentOut]`. This spec sorts by `created_at` ascending. If display order should be admin-configurable (drag-and-drop reorder), a `sort_order` integer field can be added to the sub-item in a follow-up without changing the schema.

6. **Download redirect vs. inline URL**: The spec returns the presigned URL in the `url` field of `KbAttachmentOut`, letting the browser open it directly. An alternative is a redirect endpoint (`GET /kb/articles/{id}/attachments/{att_id}/download` → `302 Location: <presigned URL>`) that re-presigns on each call and avoids leaking the signed URL into API responses. Either approach is valid; this spec prefers the simpler inline URL approach to minimize round-trips.
