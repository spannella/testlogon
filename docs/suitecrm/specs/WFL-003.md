# WFL-003 — Condition evaluator engine

**Type:** Feature | **Priority:** P0 | **Estimate:** 1d | **Depends on:** WFL-001, WFL-002

---

## 1. Summary & Goal

Implement `app/services/workflow_condition_evaluator.py` — a pure, stateless module that accepts a list of `ConditionIn` dicts (from the WFL-002 data model) and a flat record dict, and returns `(matched: bool, details: list[dict])`. The module has **zero DynamoDB calls**, making it fully testable without moto and free of I/O latency on the evaluation hot path.

This is the shared primitive called by every subsequent WFL ticket (`WFL-004` on-save hook, `WFL-005` scheduler, `WFL-006` executor) to decide whether a rule fires. Isolating it here lets correctness be proven once without duplication. Supported operators mirror SuiteCRM AOW: `eq`, `neq`, `contains`, `gt`, `lt`, `is_empty`, `is_not_empty`. All conditions are ANDed with short-circuit on the first failure.

Gated by `S.crm_workflow_enabled` (`CRM_WORKFLOW_ENABLED`, default `"0"`). With the flag off the platform is byte-for-byte unchanged.

## 3. Data Model

WFL-003 is purely in-memory. It introduces no DynamoDB tables, no new settings, and no Pydantic models.

**Input — condition dict** (shape defined by WFL-002 `WorkflowConditionIn`):

```
{ "field": str, "operator": str, "value": str | None }
```

`field` supports one level of dot-notation (`"meta.priority"` → `record.get("meta", {}).get("priority", "")`). Missing keys resolve to `None`; the evaluator never raises `KeyError`.

**Input — record dict**: flat `dict[str, Any]` as returned by the relevant service layer (`TicketStore.get_ticket`, contacts service, etc.). Numeric fields may be `int`, `float`, or `Decimal`. Fields absent from the dict resolve to `None`; the evaluator never raises `KeyError`. The record dict is not mutated.

**Output — details list** (one entry per evaluated condition that was actually evaluated):

```
{
  "field": str,          # copied from the condition
  "operator": str,       # copied from the condition
  "value": str,          # copied from the condition ("" if absent)
  "record_value": str,   # str() of resolved value, or "" if None
  "passed": bool,        # True if this condition passed
  "error": str           # present only on "unknown_operator" or "type_error"
}
```

Short-circuit means the details list has fewer entries than the conditions list when a failure occurs mid-evaluation. The caller (WFL-006) can detect this by comparing `len(details)` to `len(rule["conditions"])`. Skipped conditions (never evaluated) produce no entry — they are not added with `passed=False`, which would misrepresent the reason for the rule not firing.

## 4. API / Service Design

### 4.1 Module: `app/services/workflow_condition_evaluator.py`

Sole deliverable of WFL-003. No class, no startup, no DynamoDB. Imports only from the standard library and `app/core/settings.S`.

```python
_SUPPORTED_OPERATORS = frozenset(
    {"eq", "neq", "contains", "gt", "lt", "is_empty", "is_not_empty"}
)
```

### 4.2 Public function: `evaluate_conditions`

```python
def evaluate_conditions(
    conditions: list[dict],
    record: dict,
) -> tuple[bool, list[dict]]:
```

**Guard**: `if not S.crm_workflow_enabled: return (False, [])` — mirrors `fraud_detection.py:271`.

**Empty-list fast path**: `if not conditions: return (True, [])` — enables "fire on all records" rules (matches SuiteCRM AOW with no conditions configured).

**Main loop** — AND semantics with short-circuit:

```python
    details: list[dict] = []
    for condition in conditions:
        passed, entry = _eval_one(condition, record)
        details.append(entry)
        if not passed:
            return (False, details)
    return (True, details)
```

### 4.3 Private function: `_eval_one`

```python
def _eval_one(condition: dict, record: dict) -> tuple[bool, dict]:
```

Resolves the field via `_resolve_field`, builds the base detail entry (`field`, `operator`, `value`, `record_value`, `passed=False`), validates the operator against `_SUPPORTED_OPERATORS`, then calls `_apply_operator` inside a broad `try/except Exception` that maps any error to `entry["error"] = "type_error"` and returns `(False, entry)`. Never raises — all exceptions are absorbed into the details entry.

### 4.4 Operator implementations (`_apply_operator`)

| Operator | Logic |
|---|---|
| `is_empty` | `_is_empty(record_value)` — `None`, `""`, empty collections |
| `is_not_empty` | `not _is_empty(record_value)` |
| `eq` | `str(rv).lower() == str(cv).lower()` |
| `neq` | inverse of `eq` |
| `contains` | `cv.lower() in str(rv).lower()` |
| `gt` | `_to_float(rv) > _to_float(cv)` |
| `lt` | `_to_float(rv) < _to_float(cv)` |

`_to_float` coercion chain: `int`/`float` → `float()` directly; `Decimal` (returned by boto3 for DynamoDB Number attributes, e.g. `Decimal("1717000000")`) → `float()` directly; numeric string `"42.5"` → `float(s)`; ISO-8601 datetime string `"2024-06-15T10:30:00Z"` → `datetime.fromisoformat(s.replace("Z", "+00:00")).timestamp()`; anything else → `ValueError` (caught by `_eval_one` → `type_error`). This allows comparing `created_at` Unix integers against a condition value like `"1717000000"`, and also date-field strings from external integrations. `_resolve_field` handles one-level dot-notation (`"meta.priority"` → `record["meta"]["priority"]`); deeper paths or non-dict parents return `None`.

## 5. Detailed Behavior & Edge Cases

**Flag off**: `evaluate_conditions` returns `(False, [])` unconditionally. Zero computation.

**Empty conditions**: `(True, [])` — "match all records" is a valid rule intent.

**Missing field + numeric operators** (`gt`/`lt`): `_to_float(None)` raises → entry gets `error="type_error"`, condition fails. Failing explicitly rather than silently zeroing prevents wrong fires.

**`eq` on Decimal**: `str(Decimal("42")) == "42"` matches `value="42"`. `str(Decimal("42.0")) == "42.0"` does NOT match `"42"`. Rule authors must use the same numeric representation as the stored field; `gt`/`lt` are preferred for numeric comparisons.

**`contains` with empty value**: `"" in "anything"` is always `True`. WFL-002 `create_rule` should warn on empty `contains` values but the evaluator does not reject them.

**Unknown operator**: sets `entry["error"] = "unknown_operator"`, returns `(False, entry)`. Rule does not fire rather than incorrectly firing — safe default.

**Short-circuit observability**: `len(details) < len(conditions)` when a failure occurs mid-list. WFL-006 run-log writer stores the details list; incomplete lists are expected and identifiable.

**Thread safety**: no module-level mutable state. `S` is frozen (`app/core/settings.py:6`). Safe for concurrent asyncio tasks.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

**Dev/prod parity**: zero `if S.dev_mode` branches. No AWS SDK calls. Identical byte-for-byte code in both environments. SECOPS-007 satisfied by construction.

**Idempotency**: pure function. Same inputs always produce the same output. No state to reset.

**PII in logs**: `logger.debug` logs `field` and `operator` only — never `record_value` or `condition_value`, which may contain PII. The `record_value` field in the details dict is persisted to `T.crm_workflow_runs` under admin access in WFL-006; that is acceptable.

**No arbitrary code execution**: `_SUPPORTED_OPERATORS` is a frozen set; unknown operators fail safe. `_resolve_field` only calls `dict.get` — no `eval`, `exec`, or `getattr`. A malicious `field` value like `"__class__.__bases__"` simply resolves `None`.

**Auth**: the module is server-internal only. It is never called from a router endpoint. Auth enforcement belongs to WFL-009's admin router (`Depends(require_admin_or_root_csrf)`, as used at `app/routers/admin_notifications.py:13`). The evaluator has no concept of the calling user's identity — it operates purely on pre-fetched record data and condition configs.

**`TestUnknownOperator`**: `error="unknown_operator"`; no exception raised; short-circuits at one detail entry.

**`TestShortCircuit`**: 3 conditions, failure at index 0 → 1 detail; failure at index 1 → 2 details; all pass → 3 details.

## 10. Open Questions / Assumptions

1. **`eq` Decimal representation**: `str(Decimal("42.0")) == "42.0"` does not match condition value `"42"`. Rule authors should prefer `gt`/`lt` for numeric fields or ensure values match DynamoDB's stored representation. The evaluator does not normalize; this is documented and accepted.

2. **Multi-value `in_list` operator**: SuiteCRM supports list-membership checks. Omitted from v1. If added, a `values` list field alongside `value` string would be added to the condition shape in WFL-002 and a new `in_list` branch in `_apply_operator`. No breaking change to existing conditions.

3. **Dot-notation depth**: One level only. Deeper nesting is pre-flattened by the record fetcher in WFL-005 before reaching the evaluator. Evaluator is unchanged if fetchers handle this.

4. **`record_value` truncation**: Details store `str(record_value)` which may be large for text fields. WFL-006's `_write_run` should truncate to 256 chars before persisting to `T.crm_workflow_runs`. This is a WFL-006 concern.
