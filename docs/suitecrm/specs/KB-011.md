# KB-011 — Public KB portal (unauthenticated article browsing & search)

**Type:** Feature | **Priority:** P1 | **Estimate:** 2d  
**Ticket source:** `docs/suitecrm/CRM_KNOWLEDGE_BASE_TICKETS.md` §KB-011

---

## 1. Summary & Goal

KB-011 closes the gap between the minimal public surface defined in CAS-015 and a complete, unauthenticated-browsable Knowledge Base portal.

CAS-015 (`docs/suitecrm/CRM_CASES_PORTAL_TICKETS.md:497`) defines `GET /public/kb/articles` and `GET /public/kb/articles/{id}` but leaves out category-scoped browse, tag-scoped browse, and a dedicated public search endpoint. It also does not register any of those paths in `API_KEY_ROUTE_EXEMPTIONS`, so they are gated by the API key middleware for clients using API keys.

This ticket delivers:

1. A consolidated public router surface — `GET /public/kb/articles`, `GET /public/kb/articles/{id}`, `GET /public/kb/search`, `GET /public/kb/categories`, `GET /public/kb/categories/{category_id}`, `GET /public/kb/tags`, `GET /public/kb/tags/{tag}/articles` — all fully unauthenticated and properly exempted from API key scope checks.
2. The two Pydantic response models that the public surface returns: `KbArticleSummaryOut` and `KbArticleOut`.
3. Documentation/confirmation of KB search integration into the global search aggregator at `app/routers/search.py` under the `kb` type key. NOTE: the actual `_search_kb` function, the `ALLOWED_TYPES |= {"kb"}` addition, and the `_search_aggregator` branch are **owned by KB-009** (a hard prerequisite); KB-011 does not re-implement them (see §4.3 ownership note).
4. Correct flag gating: every public endpoint returns HTTP 404 when `S.knowledge_base_enabled` is `False`.

Nothing in the existing codebase is modified. All changes are additive.

## 2. Context & Current State

### Existing public KB surface (CAS-015)

`docs/suitecrm/CRM_CASES_PORTAL_TICKETS.md:497` defines the following public endpoints as part of CAS-015:

- `GET /public/kb/articles` — list published articles.
- `GET /public/kb/articles/{id}` — single published article; increments view count.
- `GET /public/kb/search?q=` — article prefix search.

CAS-015 also creates the `crm_kb_articles` DynamoDB table (`docs/suitecrm/CRM_CASES_PORTAL_TICKETS.md:491`) with `PK=ARTICLE#{article_id}` / `SK=META` and two GSIs (`ByCategory`, `ByStatus`), and defines the `KbArticleService` class in `app/services/kb_articles.py` with method stubs for `list_articles`, `get_article`, `search_articles`, `increment_view_count`, and `rate_article`.

### What is missing

CAS-015's `GET /public/kb/articles` has no `category_id` or `tag` filter parameter and no `excerpt` field in the response. The public portal therefore cannot support a category-scoped browse or tag-scoped browse without this ticket.

The global search aggregator at `app/routers/search.py:645` does not include a `kb` branch. The `ALLOWED_TYPES` set at `app/routers/search.py:43` is `{"users", "posts", "catalog", "files"}` plus `{"messages", "tickets", "contacts", "videos", "calendar"}` when `_EXTENDED_SEARCH` is true — KB is absent. Adding KB here requires only a new `_search_kb` function and one `ALLOWED_TYPES` update; the `ThreadPoolExecutor` fan-out in `_search_aggregator` at `app/routers/search.py:676` will pick it up automatically.

`app/services/api_key_route_scope_registry.py:70` defines `API_KEY_ROUTE_EXEMPTIONS`. No `/public/kb/*` entries exist. Without exemptions the API key middleware will return 403 for unauthenticated callers that carry an API key without the correct scope.

### Sibling KB tickets that provide the capabilities KB-011 aggregates

KB-011 does not re-implement; it assembles. The following sibling tickets provide the underlying service methods and DDB rows that KB-011's public endpoints delegate to:

- **KB-001** — `S.knowledge_base_enabled` flag, `T.kb_articles`, `S.kb_articles_table`.
- **KB-002** — `status` lifecycle; `publish_article`; `expire_article`; only `status=published` articles appear on the public surface.
- **KB-003** — `KbAttachmentOut`, `list_attachments`; included in `KbArticleOut.attachments`.
- **KB-004** — `CATEGORY#` rows; `list_categories`; `get_category`; `GET /public/kb/categories` and `GET /public/kb/categories/{category_id}` formally land here.
- **KB-006** — `record_view` / `increment_view_count`; wired into `GET /public/kb/articles/{id}`.
- **KB-007** — `TAG#{tag}` index rows; `list_articles_by_tag`; `list_popular_tags`; `GET /public/kb/tags` and `GET /public/kb/tags/{tag}/articles` formally land here.
- **KB-009** — `SEARCH_TOKEN#` inverted index; `search_articles(q)`; `_search_kb` global aggregator integration.

### Auth dependencies (current code)

The pattern for public (unauthenticated) endpoints in this codebase is to declare the route with no `Depends(...)` auth parameter. Cookie-auth and Bearer-token auth apply only when the dependency is declared. Examples: `GET /calendar/public/event/{calId}/{eventId}` in `app/routers/calendar.py` carries no auth dependency.

`app/auth/policy.require_admin_or_root` at `app/auth/policy.py:67` is the standard dependency for admin-only write paths — it calls `get_authenticated_user` and asserts `role in {Role.ADMIN, Role.ROOT}`. All KB write/admin endpoints (defined in KB-002 through KB-010) use this dependency. The public read endpoints in KB-011 use no auth dependency.

### Cursor pagination (current code)

`app/core/cursor.encode_cursor` / `decode_cursor` at `app/core/cursor.py:94` provide HMAC-signed, versioned DynamoDB `LastEvaluatedKey` wrapping. All paginated public KB list endpoints must use this primitive; callers must not receive raw DynamoDB continuation keys.

### Search aggregator (current code)

`app/routers/search.py:645–686` implements `_search_aggregator`. Each domain contributes a zero-argument lambda keyed by type name. `_empty_section()` at `app/routers/search.py:60` is the canonical no-op return value when a flag is off or a search module fails. Every domain search function is wrapped in `try/except` with `return _empty_section()` in the except clause — KB must follow the same pattern.

### Tag index (current code)

`app/routers/newsfeed.py:440` — `_write_tag_index` writes `TAG#{tag}` / `{created_at}#POST#{post_id}` rows with a `TAG_STATS` counter row. KB-007 mirrors this pattern for articles. KB-011 calls KB-007's `list_articles_by_tag` and `list_popular_tags` — it does not interact with the tag index directly.

### View counter (current code)

`app/services/stories.py:160` uses `UpdateExpression="ADD view_count :one"` with `ExpressionAttributeValues={":one": 1}` on the article META row. KB-006 adapts this for KB articles. KB-011's `GET /public/kb/articles/{id}` fires `record_view` as a best-effort async call after the response is returned.

### S3 presigned URL (current code)

Attachment download URLs are generated by KB-003. For `KbArticleOut.attachments`, the dev environment returns `/mock/s3/...` redirect URLs and production returns 300-second presigned URLs generated by `app/core/aws_clients.s3_client()` at `app/core/aws_clients.py:114`. KB-011 simply includes the attachment list in `KbArticleOut`; the URL generation lives in KB-003's service method.

## 4. API / Service Design

### 4.1 Public endpoints (`app/routers/kb_articles.py`)

All endpoints are prefixed with `/public/kb` and carry **no auth dependency**. Every endpoint begins with:

```python
if not S.knowledge_base_enabled:
    raise HTTPException(status_code=404, detail="Not found")
```

This is the sole gating mechanism; no middleware change is needed.

**Route ordering constraint**: The router file must declare static path segments (`/search`, `/categories`, `/tags`) before dynamic segments (`/{article_id}`). FastAPI matches routes in declaration order; a dynamic `/{article_id}` declared first would capture the literal strings `search`, `categories`, and `tags` as article IDs (constraint from `CRM_KNOWLEDGE_BASE_TICKETS.md` header, line 27).

---

#### `GET /public/kb/articles`

```python
async def public_list_articles(
    category_id: Optional[str] = Query(None),
    tag: Optional[str] = Query(None),
    limit: int = Query(25, ge=1, le=100),
    cursor: Optional[str] = Query(None),
) -> KbArticleListOut:
```

**Behavior:**

1. If `tag` is provided: delegate to `KbArticleService().list_articles_by_tag(tag, limit, cursor)` (KB-007). Returns articles from the `TAG#{normalize(tag)}` index.
2. If `category_id` is provided (and no `tag`): query `ByCategory` GSI with `KeyConditionExpression: Key("category").eq(category_id)`, `FilterExpression: Attr("status").eq("published")`, `ScanIndexForward=False` (newest published first), `Limit=limit`. Pass `ExclusiveStartKey=decode_cursor(cursor)` when cursor is non-null.
3. If neither filter: query `ByStatus` GSI with `KeyConditionExpression: Key("status").eq("published")`, `ScanIndexForward=False`, `Limit=limit`.
4. Return `KbArticleListOut(items=[KbArticleSummaryOut(...)], cursor=encode_cursor(resp.get("LastEvaluatedKey")), total_estimate=None)`.

`total_estimate` is `None` (DynamoDB does not provide row counts on GSI queries without a full scan).

**Response model:** `KbArticleListOut`.

---

#### `GET /public/kb/articles/{article_id}`

```python
async def public_get_article(
    article_id: str,
    request: Request,
) -> KbArticleOut:
```

**Behavior:**

1. Call `KbArticleService().get_article(article_id)`. If the item's `status` is not `"published"`, raise `HTTPException(404)`.
2. Call `KbArticleService().list_attachments(article_id)` to populate `KbArticleOut.attachments`.
3. Fire-and-forget `record_view`: `asyncio.create_task(service.record_view(article_id, viewer_id=request.client.host or "anonymous"))`. Wraps in `try/except` — view count failure must not block the response.
4. Return `KbArticleOut`.

**Response model:** `KbArticleOut`.

**`excerpt` generation helper** (`app/services/kb_articles.py`):

```python
import re as _re

def _extract_excerpt(body_html: str, max_chars: int = 200) -> str:
    """Strip HTML tags and return the first max_chars characters of plain text."""
    text = _re.sub(r"<[^>]+>", " ", body_html or "")
    text = _re.sub(r"\s+", " ", text).strip()
    return text[:max_chars]
```

This is a private helper; it must not use external libraries (no `html.parser` subprocess, no BeautifulSoup). The regex approach matches the dependency-free constraint applied elsewhere in the codebase (e.g. `app/services/receipts.py`, `app/services/audit_export_pipeline.py`).

```python
def _search_kb(q: str, limit: int) -> Dict[str, Any]:
    """Search KB articles via the token index. Returns empty section when flag off."""
    try:
        if not S.knowledge_base_enabled:
            return _empty_section()
        from app.services.kb_articles import KbArticleService
        results = KbArticleService().search_articles(q, limit=limit)
        items = [
            _make_result_item(
                type="kb_article",
                id=a["article_id"],
                title=a["title"],
                snippet=a.get("excerpt", "")[:120],
                url=f"/knowledge/{a['article_id']}",
                meta={
                    "category_id": a.get("category_id"),
                    "tags": a.get("tags", []),
                    "published_at": a.get("published_at"),
                },
            )
            for a in results
        ]
        return {"items": items, "total_estimate": len(items), "has_more": len(items) >= limit}
    except Exception:
        logger.exception("KB search failed")
        return _empty_section()
```

## 5. Detailed Behavior & Edge Cases

### Flag-off behavior

When `S.knowledge_base_enabled` is `False`, all seven public KB endpoints return HTTP 404 with body `{"detail": "Not found"}`. The global search `_search_kb` function returns `_empty_section()` (empty items list, no error). The platform behaves as if the KB feature does not exist.

### Draft and expired articles

`GET /public/kb/articles/{article_id}` fetches the article item and checks `item["status"] == "published"` before returning. Any other status — `draft`, `expired`, or absent — returns HTTP 404. This applies even if the caller has admin credentials; the public endpoint does not reveal non-published articles to any caller. The admin endpoint `GET /kb/articles/{article_id}` (defined in CAS-015, gated by `require_admin_or_root`) returns articles of any status.

### Category filter on article list

`GET /public/kb/articles?category_id=xyz` queries the `ByCategory` GSI. If `category_id` refers to a category that has no published articles, the response is `{"items": [], "cursor": null, "total_estimate": null}` — not a 404. A 404 is only returned when the category ID itself is looked up via `GET /public/kb/categories/{category_id}` and the category row does not exist.

### Tag filter precedence

If both `tag` and `category_id` are provided in a single request, `tag` takes precedence (delegates to `list_articles_by_tag`). The `category_id` parameter is silently ignored. This keeps the implementation simple and avoids a multi-GSI join. (A future ticket may add combined filtering.)

### Pagination consistency

Cursors are HMAC-signed via `app/core/cursor.encode_cursor`. A tampered or expired cursor causes `decode_cursor` to return `None`, which means the query starts from the beginning (no error is raised). This matches the existing behavior for all other paginated endpoints in the codebase.

### View counter and anonymity

The `record_view` call uses `request.client.host` as a proxy for anonymous viewer identity. This is coarse (multiple users behind NAT share one IP), but it is sufficient for deduplication within a 24-hour window and avoids requiring authentication for a public read. The `VIEW#{ip}` TTL row expires after 86400 seconds (set by KB-006). The view counter increment itself is a best-effort `try/except` fire-and-forget — a DDB outage must never surface a 500 to the public browser.

### Excerpt field

`KbArticleSummaryOut.excerpt` is derived by `_extract_excerpt(body_html, max_chars=200)` at response serialization time (computed in the service's `_article_to_summary` helper, not stored in DDB). It is not indexed or filterable. Storing it in DDB would add ~200 bytes per article per write; for a feature that renders at read time with a simple regex, the runtime cost is negligible.

### Search query length

`GET /public/kb/search` requires `q` with `min_length=2`. A single-character query would generate a single-character prefix token that matches almost every article (token prefixes are generated from length 3 upward per KB-009). FastAPI's `min_length=2` Query constraint enforces this at the HTTP layer before the service is called.

### Global search — `kb` type gating

`_search_kb` short-circuits to `_empty_section()` when `S.knowledge_base_enabled` is `False`. This means callers can include `types=kb` in a global search even when the feature is off — they simply get zero KB results rather than an error. This matches the existing behavior for other conditionally-enabled features.

### Attachment URLs in `KbArticleOut`

The `attachments` list is populated by calling `KbArticleService().list_attachments(article_id)` and constructing `KbAttachmentOut` objects with `url` set to the attachment download URL. In dev mode the URL is `/mock/s3/{s3_key}` (following the pattern in `app/services/kyc_partner_api.py`); in production it is a presigned URL from `s3_client().generate_presigned_url(...)` with `ExpiresIn=300`. The URL generation lives in KB-003's service method; KB-011 simply passes through the `KbAttachmentOut` list.

### Related articles

The public portal article page may also call `GET /public/kb/articles/{article_id}/related` (defined by KB-008) to populate a "You may also find helpful" panel. ## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### Dev/prod parity

KB-011 contains no `if S.dev_mode:` branches. All logic is identical between the local dev stack (DynamoDB Local at port 8001, moto S3, `AWS_ACCESS_KEY_ID=test`) and production (real DynamoDB, real S3). The only observable difference is the attachment URL format returned by KB-003's `get_attachment_url` helper (`/mock/s3/...` vs presigned URL), which is determined by the S3 endpoint URL, not by `dev_mode`. This follows the SECOPS-007 principle that no code path diverges between environments.

### Idempotency

All public read endpoints are idempotent GET requests. The one state-mutation side-effect — `record_view` — is itself idempotent within a 24-hour window via the `VIEW#{viewer_id}` DDB TTL row and `ConditionalCheckFailedException` handling (KB-006).

### Security considerations

**No authentication bypass**: Public endpoints deliberately omit the `Depends(get_authenticated_user)` dependency. This is intentional. The public surface exposes only articles with `status=published`; drafts and expired articles are never returned.

**No PII exposure**: `KbArticleSummaryOut` and `KbArticleOut` expose `author_sub` in the full article view. This is acceptable for a public help center (it identifies which admin wrote the article). If this is a concern, `author_sub` can be removed from `KbArticleOut`; this is an open question for the product team (see section 10).

**Excerpt XSS**: `_extract_excerpt` strips all HTML tags via regex before returning plain text. The excerpt is not rendered as HTML anywhere in the public API response — it is a plain string used for preview cards.

**Rate limiting**: The existing platform-level rate limiter (`S.rate_limit_global_enabled`) at `app/core/settings.py:1900` applies to all endpoints including the public KB routes (it is IP-based at the global middleware layer). No per-endpoint KB-specific rate limit is introduced by this ticket. If abuse is detected post-launch, a per-endpoint cap can be added using the existing `rate_limit.py` `_bucket_limit` primitive without a schema change.

**Search token injection**: `search_articles` calls `_sanitize_query` to normalize the query string before tokenization. Token strings are used only as DDB partition key values (not in `FilterExpression` with user-controlled operator injection); DynamoDB PK lookups are not SQL-injectable.

**API key exemptions scope**: Exempting `/public/kb/*` routes means they bypass the API key scope check entirely. This is correct — these are unauthenticated public routes. The exemption does not grant additional privileges; it simply means API key callers are not required to hold a KB-scoped key to fetch public articles.

## 8. Backward Compatibility & Migration

### Existing routes

No existing routes are changed. The `/public/kb/articles` and `/public/kb/articles/{id}` stubs defined by CAS-015 are extended in place (same URL, superset of query parameters and response fields).

### Response model extension

`KbArticleSummaryOut` adds `excerpt`, `category_id`, and `tags` fields not present in CAS-015's minimal list response. These are additive — consumers that only read `title` and `article_id` are unaffected.

### `KbArticleOut` vs CAS-015 minimal article response

CAS-015 defines a minimal single-article response with `title`, `body_html`, `status`, `view_count`, `helpful_count`, `not_helpful_count`. `KbArticleOut` is a superset of those fields plus `author_sub`, `created_at`, `updated_at`, `attachments`. Existing consumers reading the minimal fields continue to work.

### DynamoDB

No new tables. No new GSIs. No `UpdateTable` operations needed. No backfill.

### Migration order

KB-011 has service-layer dependencies on KB-001 through KB-009. In a migration scenario the following order must be respected:

1. CAS-001 — creates `crm_kb_articles` table.
2. KB-001 — adds `KNOWLEDGE_BASE_ENABLED` flag, `ByAuthor`/`ByTag` GSIs, `T.kb_articles`.
3. KB-002 through KB-009 — status lifecycle, attachments, categories, ratings, view counter, tags, related, search index.
4. KB-011 — assembles the public portal surface from the above.

In development (`just restart`), `scripts/local-ddb-init.py` creates/updates all tables in a single pass; order is irrelevant there.

## 10. Open Questions / Assumptions

1. **`author_sub` in public response**: `KbArticleOut.author_sub` exposes an internal user identifier to unauthenticated callers. The current design includes it to allow the frontend to display "Written by [display name]" using a separate profile lookup. If this is a privacy concern, `author_sub` should be replaced with a `KbAuthorOut` sub-object with only `display_name` and `avatar_url`, fetched by the service. **Assumed acceptable for now; flagged for product review.**

2. **Attachment visibility on public articles**: KB-011 includes the full `attachments` list in `KbArticleOut`. Attachments uploaded by KB-003 are stored in S3 and exposed via `/mock/s3/...` (dev) or presigned URLs (prod). There is no separate access control on attachment download beyond the S3 URL itself. If some attachments should be restricted (e.g. internal-only PDFs on a public article), a per-attachment `visibility` field would be needed. **Assumed all attachments on published articles are public.**

3. **`total_estimate` field**: DynamoDB GSI queries do not return a total count without a separate `select=COUNT` query. `KbArticleListOut.total_estimate` is set to `None`. Some frontend pagination UIs require a count (e.g. "Page 2 of 7"). If this is needed, a `COUNT#` counter row pattern (similar to `KB_TAG_STATS`) could be added. **Deferred; `None` is acceptable for infinite scroll UIs.**

4. **`GET /public/kb/articles` with both `tag` and `category_id`**: Current design uses `tag` when both are provided and silently ignores `category_id`. A future ticket could add a combined DDB query (requires a composite GSI or client-side intersection). **Assumed acceptable for the initial portal.**

5. **Search on body text**: KB-009 indexes tokens from `title` only. A caller searching for a term that appears in the article body but not the title will get no results. Full-body indexing would require either a separate search service (OpenSearch/Elasticsearch) or a significant expansion of the token index. **Assumed title-only search is sufficient for MVP.**
