# INV-002 — Admin currency management — currency registry and exchange rates

---

## 1. Summary & Goal

Implement a DynamoDB-backed currency registry that lets admins configure supported currencies, their ISO 4217 codes, display symbols, decimal precision, and exchange rates relative to the platform default (USD). Expose admin CRUD endpoints under `/ui/admin/currencies` and a `get_exchange_rate(from_iso, to_iso)` service accessor that the transaction-time conversion ticket (INV-003) will call.

This ticket is the **foundation layer** for all multi-currency work in the INV series. It does not implement live-rate fetching from an external feed (that remains in the longer-range Admin currency management item in the Security Suite area). All behavior is gated behind a default-off feature flag (`CRM_CURRENCIES_ENABLED`); with the flag off the platform is byte-for-byte unchanged.

## 3. Data Model

### New DynamoDB table: `crm_currencies`

**Environment variable**: `CRM_CURRENCIES_TABLE_NAME` (default `"crm_currencies"`)

**Key schema**:

```
PK  = CURRENCY#{iso_code}   (String)  e.g. CURRENCY#eur
SK  = META                  (String)  always "META"
```

**Item attributes**:

| Attribute | Type | Notes |
|-----------|------|-------|
| `pk` | S | `CURRENCY#{iso_code}` |
| `sk` | S | `"META"` |
| `iso_code` | S | Normalized lowercase ISO 4217, e.g. `"eur"` |
| `name` | S | Display name, e.g. `"Euro"` |
| `symbol` | S | Display symbol, e.g. `"€"` |
| `rate_to_usd` | N | Decimal — units of USD per 1 unit of this currency. `1.0` for USD itself. |
| `is_default` | BOOL | Exactly one currency has `is_default=True` (USD). Enforced at service layer; not a DDB constraint. |
| `is_active` | BOOL | Inactive currencies are excluded from the GSI1 active-list index. |
| `decimal_places` | N | Integer, typically 2; 0 for JPY, 3 for KWD. |
| `created_at` | N | Unix timestamp integer (`now_ts()`). |
| `updated_at` | N | Unix timestamp integer. |
| `GSI1PK` | S | `"CURRENCIES#ACTIVE"` when `is_active=True`; attribute omitted when `is_active=False` (sparse GSI). |
| `GSI1SK` | S | `iso_code` — string sort, alphabetical. |

**GSI1** — active currencies list:

```
IndexName : "GSI1"
PK attr   : GSI1PK  (String)
SK attr   : GSI1SK  (String)
```

Because `GSI1SK` is a **string** (`iso_code`), **no numeric `attr_types` entry is needed**. This differs from the pattern used on the `invoices` table (where `GSI1SK` is a numeric timestamp). The `TableDef` entry in `scripts/local-ddb-init.py` must NOT declare `attr_types={"GSI1SK": "N"}` for this table — the sort key is `"S"` by default.

**`TableDef` entry** to add to `scripts/local-ddb-init.py` inside `_table_defs()`, after the `invoices` table entry at line 2278:

```python
TableDef(
    _resolve_table_name(S.crm_currencies_table_name, "crm_currencies"),
    "pk",
    "sk",
    gsi=[
        {"index_name": "GSI1", "partition_key": "GSI1PK", "sort_key": "GSI1SK"},
    ],
    # GSI1SK is iso_code (String) — no numeric attr_types needed here.
),
```

**Table handle** — add to `app/core/tables.py` (the `Tables` dataclass at line ~296 and the `_wire()` factory):

```python

# in _wire():

### 4.1 Service: `app/services/crm_currencies.py` (new file)

All functions are gated by `S.crm_currencies_enabled`; when the flag is off they raise `ValueError("currency management not enabled")` immediately.

def create_currency(

    """Validate + write a new currency entry to crm_currencies table.

    Raises ValueError on iso_code length != 3, rate_to_usd <= 0, or
    decimal_places outside [0, 4]. Normalizes iso_code to lowercase.
    Emits audit_event("currency.created", ...).
    Returns the serialized currency dict.
    """
```

```python
def update_currency(
    iso_code: str,
    *,
    name: Optional[str] = None,
    symbol: Optional[str] = None,
    rate_to_usd: Optional[Decimal] = None,
    is_active: Optional[bool] = None,
    decimal_places: Optional[int] = None,
    updated_by: Optional[str] = None,
) -> dict:
    """Patch mutable fields on an existing currency. Raises ValueError if not found.

    When is_active changes to False, removes GSI1PK/GSI1SK from the item
    (sparse GSI — DynamoDB omits items without the index key).
    When is_active changes to True, writes GSI1PK="CURRENCIES#ACTIVE" and
    GSI1SK=iso_code.
    Emits audit_event("currency.rate_updated", ...) when rate_to_usd changes;
    audit_event("currency.updated", ...) for other field changes.
    """
```

```python
def get_currency(iso_code: str) -> Optional[dict]:
    """Direct PK lookup. Returns None if not found."""
```

```python
def list_currencies(active_only: bool = True) -> list[dict]:
    """When active_only=True: queries GSI1 (GSI1PK="CURRENCIES#ACTIVE"),
    ScanIndexForward=True (alphabetical by iso_code).
    When active_only=False: performs a table scan (admin use only — no
    pagination, capped at 200 items). Returns list of serialized dicts.
    """
```

```python
def get_exchange_rate(from_iso: str, to_iso: str) -> Decimal:
    """Compute cross-rate: (from_currency.rate_to_usd) / (to_currency.rate_to_usd).

    Special case: when from_iso == "usd", rate_to_usd for from_currency is
    implicitly Decimal("1"), so result = 1 / to_currency.rate_to_usd.
    When to_iso == "usd", result = from_currency.rate_to_usd.

    Raises ValueError if either currency is not found or is_active=False.
    Always uses at least 10 decimal places of precision to avoid rounding
    compounding errors; callers should round the final cents result.
    """
```

```python
def convert_amount(amount_cents: int, from_iso: str, to_iso: str) -> int:
    """Apply get_exchange_rate and return rounded integer cents.

    round(amount_cents * get_exchange_rate(from_iso, to_iso))
    When from_iso == to_iso, returns amount_cents unchanged (no lookup needed).
    """
```

**Internal `_serialize(item: dict) -> dict`** — coerces DynamoDB `Decimal` types to Python `float` for `rate_to_usd`, and `int` for `created_at`, `updated_at`, `decimal_places`. Returns keys matching `CurrencyOut`.

## 5. Detailed Behavior & Edge Cases

### Currency creation
- `iso_code` is normalized to lowercase before storage and used as the PK segment. A `create_currency("EUR", ...)` call stores `CURRENCY#eur`.
- Duplicate `iso_code` is detected via a DynamoDB conditional `put_item` with `attribute_not_exists(pk)`. On conflict, the service raises `ValueError("currency already exists: eur")` and the router returns HTTP 409.
- `rate_to_usd` for USD itself is always `Decimal("1.0")`. The platform can optionally seed a USD entry with `is_default=True`; if it is absent, `get_exchange_rate("usd", X)` falls back to treating `from_rate_to_usd=1`.

### Exchange rate computation
- Cross-rate formula: `rate = from_currency.rate_to_usd / to_currency.rate_to_usd`. Example: if EUR has `rate_to_usd=1.08` and GBP has `rate_to_usd=1.27`, then `get_exchange_rate("eur", "gbp") = 1.08 / 1.27 ≈ 0.8504`.
- `get_exchange_rate("usd", "eur")` where `rate_to_usd(eur) = 1.08` → `1.0 / 1.08 ≈ 0.9259`.
- `convert_amount(10000, "usd", "eur")` → `round(10000 * 0.9259) = 9259`.
- If `from_iso == to_iso`, `convert_amount` returns `amount_cents` unchanged without any DDB lookup.
- Division-by-zero: if a currency has `rate_to_usd=0` (should be blocked at creation by `gt=Decimal("0")` validation but defensive coding applies), `get_exchange_rate` raises `ValueError` rather than `ZeroDivisionError`.

### Deactivation and sparse GSI
- When `update_currency(iso_code, is_active=False)` is called, the service uses `update_item` with a `REMOVE GSI1PK, GSI1SK` expression alongside the `SET is_active = :false` expression. This makes the item disappear from the `GSI1` active-currencies index (DynamoDB does not index items that lack the index key attributes — a sparse GSI).
- Re-activating (`is_active=True`) adds `GSI1PK` and `GSI1SK` back via `SET` expression.
- Callers of `get_exchange_rate` that pass an inactive currency code receive `ValueError("currency not active: eur")`, not a silent zero rate.

### Default currency
- `is_default=True` signals which currency is the platform base. Only one item should carry this flag. The service does **not** enforce a single-default constraint at the DDB level (no conditional check); it is an admin responsibility. INV-003 treats `"usd"` as the base by string comparison, not by the `is_default` flag, to avoid a dependency on a seeded USD row.

### Idempotency of rate updates
- `update_currency(iso_code, rate_to_usd=X)` is idempotent — writing the same rate twice produces the same DDB item. The audit event is emitted each time regardless (each rate update is a meaningful action for the audit trail).

### Active-only list pagination
- `list_currencies(active_only=True)` queries `GSI1PK = "CURRENCIES#ACTIVE"` with `ScanIndexForward=True` (alphabetical). The expected number of active currencies is small (< 50 in any real deployment), so a single `Limit=200` query without cursor pagination is sufficient. If a future deployment exceeds that, a cursor can be added to `CurrencyListOut` without breaking existing callers.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

**No `dev_mode` branches in service code.** The `crm_currencies.py` service reads and writes `T.crm_currencies` via the `_safe_table` proxy (which coerces floats to `Decimal` — important for `rate_to_usd`). In dev, moto intercepts all boto3 calls at the botocore layer exactly as in prod. There is no `if S.dev_mode` fork anywhere in the service.

**Decimal precision and float safety.** `rate_to_usd` is stored as DynamoDB Number type. The `_FloatSafeTable` proxy at `app/core/tables.py:29–62` (class definition; `put_item` at lines 41–44, `update_item` at lines 46–49) coerces Python `float` → `Decimal(str(v))` on every `put_item` and `update_item` via `_to_decimal` (line 11), so passing `rate_to_usd=1.08` as a Python float is safe. The service should use `Decimal` internally when computing rates to avoid IEEE 754 rounding propagation into the stored value.

**Auth and CSRF.** All mutating endpoints (`POST`, `PATCH`) use `require_admin_or_root_csrf` (`app/auth/policy.py:100`), which enforces both the role check and CSRF header validation for cookie-auth browser requests. Bearer-token callers (API clients) skip CSRF per the existing policy implementation.

**Audit trail.** `create_currency` emits `audit_event("currency.created", created_by, iso_code=iso_code, rate_to_usd=str(rate_to_usd))`. `update_currency` emits `audit_event("currency.rate_updated", updated_by, iso_code=iso_code, old_rate=..., new_rate=...)` when `rate_to_usd` changes, or `audit_event("currency.updated", updated_by, iso_code=iso_code, changes={...})` for other field changes. Both delegate to `app.services.alerts.audit_event` (line 644 of `app/services/alerts.py`).

**Input sanitization.** `iso_code` is lowercased and must be exactly 3 characters (Pydantic `min_length=3, max_length=3`). `rate_to_usd` must be `gt=0`. `decimal_places` bounded `[0, 4]`. `symbol` max 8 characters to prevent overlong injections into PDF rendering downstream.

**No money-out path.** This ticket stores reference data only. It does not initiate any payment, ledger entry, refund, or settlement. No `billing_shared.new_ledger_entry` or `refund_payment` calls.

## 8. Backward Compatibility & Migration

**Zero impact when flag is off.** With `CRM_CURRENCIES_ENABLED=0` (the default):
- All four endpoints return 404 via `_require_enabled()` — no route conflict with existing paths.
- `get_exchange_rate` and `convert_amount` raise `ValueError` immediately without touching DDB.
- `create_invoice` at `app/services/invoices.py:272` is unchanged; it continues to accept `currency="usd"` as an opaque string.
- `InvoiceOut.currency` remains a plain string. No new fields are added to `InvoiceOut` by this ticket (that is INV-003's responsibility).

**No changes to existing tables.** The `invoices` table (`scripts/local-ddb-init.py:2269`), `billing` table, and all other existing tables are untouched. The new `crm_currencies` table is additive.

**`just restart` required after adding `TableDef`.** In dev, `scripts/local-ddb-init.py` is run at stack start. Adding the `crm_currencies` `TableDef` entry requires running `just restart` once to create the table. Existing data in other tables is unaffected (DDB Local uses separate table-level storage).

**In production**, the `crm_currencies` DDB table must be created before deploying the code that references it. Because the feature flag defaults to off, the table creation can be done as a pre-deployment step with zero risk: the code ignores the table until `CRM_CURRENCIES_ENABLED=1` is set.

**No data migration needed.** The existing `currency: str = "usd"` field on invoice items is not altered. INV-003 will add conversion fields additively when it reads rates from the registry populated by this ticket.

## 10. Open Questions / Assumptions

1. **USD canonical entry**: Should the seeding step (`scripts/local-ddb-seed.py`) pre-create a USD entry with `is_default=True, rate_to_usd=1.0`? The spec assumes no — `get_exchange_rate("usd", X)` uses a hardcoded `Decimal("1")` for the USD rate, making the USD row optional. Confirm whether a seeded USD row is required for completeness.

2. **Rate precision**: The spec stores `rate_to_usd` as a DynamoDB Number (arbitrary precision). The `CurrencyOut` model returns it as `float` for JSON compatibility, which loses precision beyond ~15 significant digits. For typical FX rates this is not an issue; confirm whether the frontend or downstream consumers need more precision.

3. **Rate history**: This ticket stores only the current rate. When INV-003 snapshots the rate at transaction time (storing `exchange_rate_snapshot` on the invoice item), historical rates are captured there. No rate-history table is needed for INV-002. Confirm no audit report requires historical rate querying against this table.

4. **Concurrent rate updates**: If two admins update the same currency rate simultaneously, the last write wins (no optimistic locking). This is acceptable for a low-frequency admin configuration table. Confirm no stronger consistency requirement.

5. **`is_default` enforcement**: The spec does not enforce a single-default constraint at DDB level. If two currencies are accidentally marked `is_default=True`, INV-003 still uses string comparison to `"usd"`, not the flag. Confirm whether a service-level guard (e.g., clearing `is_default` on other items before setting it) is required.
