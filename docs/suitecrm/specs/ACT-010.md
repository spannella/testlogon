# ACT-010 — CRM Notes module — standalone note with free-text body and file attachment

**Type:** Feature  **Priority:** P1  **Estimate:** 3d  
**Source:** `docs/suitecrm/CRM_ACTIVITIES_TICKETS.md` §ACT-010

---

## 1. Summary & Goal

Deliver a standalone CRM Notes module that allows an authenticated user to create, edit, and delete free-text notes, optionally attach a single file per note (stored in S3), and optionally link the note to an opaque CRM entity (`contact | lead | account | opportunity`). On creation the module writes a timeline entry to the CRM Activity History (ACT-009) in a fire-and-forget manner and emits an audit event. The entire module is additive and default-off; with the flags unset the platform is byte-for-byte unchanged.

## 3. Data Model

### Table: `crm_notes` (introduced by ACT-001)

```
PK  = user_sub          (String)
SK  = NOTE#{inverted_ts:013d}#{note_id}    (String)

Attributes:
  note_id              String   uuid4 hex, prefixed "note_"
  user_sub             String   owner
  body                 String   free-text, max 20 000 chars (empty string allowed)
  attachment_s3_key    String?  S3 object key
  attachment_filename  String?  original filename, sanitised
  attachment_content_type String? MIME type
  linked_entity_type   String?  "contact" | "lead" | "account" | "opportunity"
  linked_entity_id     String?  opaque id (PTY will resolve this once shipped)
  created_at           Number   Unix epoch int — also stored as GSI1SK
  updated_at           Number   Unix epoch int
```

#### GSI: `ByEntity`

```
PK  (GSI1PK) = ENTITY#{linked_entity_type}#{linked_entity_id}   (String)
SK  (GSI1SK) = created_at                                        (Number)
```

`attr_types={"GSI1SK": "N"}` **must** be declared in `scripts/local-ddb-init.py` — omitting it causes `ValidationException` at query time (CLAUDE.md gotcha, canonical example: `users` table at `scripts/local-ddb-init.py:53`).

#### scripts/local-ddb-init.py addition (inside `_table_defs()`)

```python
TableDef(
    _resolve_table_name(S.crm_notes_table_name, "crm_notes"),
    "user_sub",
    "sk",
    gsi=[{
        "index_name": "ByEntity",
        "partition_key": "GSI1PK",
        "sort_key": "GSI1SK",
    }],
    attr_types={"GSI1SK": "N"},
),
```

#### SK construction (mirrors `call_history.py:31–32`)

```python
_INVERTED_MAX = 9_999_999_999_999  # 13 digits

def _make_note_sk(created_at: int, note_id: str) -> str:
    inverted = _INVERTED_MAX - created_at
    return f"NOTE#{inverted:013d}#{note_id}"
```

`ScanIndexForward=True` on the PK query then returns notes newest-first. The ByEntity GSI uses raw `created_at` ascending; callers must pass `ScanIndexForward=False` to get newest-first on the GSI.

#### S3 key layout

```
crm-notes/{user_sub}/{note_id}/{safe_filename}
```

Bucket = `S.crm_notes_s3_bucket` (new setting, default `"local-uploads"` in dev). Safe filename: `re.sub(r"[^A-Za-z0-9._-]", "_", filename)` — same regex as `kyc_partner_api._store_document_bytes:489` (that line uses variable `safe_name` with fallback `"document"`; this module uses `safe` with fallback `"attachment"`).

def _store_attachment(
    *,
    user_sub: str,
    note_id: str,
    filename: str,
    content_type: str,
    file_bytes: bytes,
) -> dict:
    """Returns {"s3_key": ..., "bucket": ..., "url": ...}."""
    from app.core.aws_clients import s3_client
    from app.core.settings import S
    import re

                           Body=file_bytes, ContentType=content_type)
    url = (f"/mock/s3/{bucket}/{s3_key}" if S.dev_mode
           else s3_client().generate_presigned_url(
               "get_object",
               Params={"Bucket": bucket, "Key": s3_key},
               ExpiresIn=300,
           ))
    return {"s3_key": s3_key, "bucket": bucket, "url": url}

## 5. Detailed Behavior & Edge Cases

### Note body

- `body` defaults to `""` — a note with no body and a file attachment is valid.
- Body must be ≤ 20 000 characters; validation via Pydantic `max_length`, returns 422 on violation.
- Body update (`PATCH`) replaces the entire `body` field; it does not affect the attachment.

### File attachment

- A note may have **at most one attachment**. Calling `POST /{note_id}/attachment` a second time replaces the previous attachment: the old S3 object is deleted before the new one is uploaded (delete is best-effort; log warning on failure, do not abort the upload).
- File size is enforced in the router at 25 MB (`MAX_ATTACHMENT_BYTES = 25 * 1024 * 1024`). The `await file.read()` pattern mirrors `app/routers/kyc_partner_api.py:203`. The 422 response uses `code=file_too_large`.
- `attachment_url` is **not stored** in DynamoDB; it is synthesised at read time in `get_note` (dev: `/mock/s3/{bucket}/{key}`, prod: presigned URL with 300 s expiry). This avoids stale signed URLs in the database.
- `attachment_s3_key` stores the raw key without the bucket name, consistent with `kyc_partner_api` storage pattern.
- `delete_note` deletes the S3 object when `attachment_s3_key` is set. The S3 delete is wrapped in `try/except`; failure logs a warning but does not prevent the DDB row deletion.

### Ownership

- All endpoints enforce single-owner access: DDB reads use `PK=user_sub` and the SK prefix `NOTE#`, so a user cannot read or mutate another user's notes. `get_note` returns `None` (→ 404) if the note exists under a different `user_sub`.
- `list_notes_for_entity` queries by GSI1PK (entity key) and **does not filter by `user_sub`** — all notes for that entity are visible regardless of author. This matches SuiteCRM's "CRM entity timeline shows all notes from any user". Full record-level ACL (scoped to org/team) is deferred to a Security Suite area ticket.
- The `by-entity` endpoint still requires `require_ui_session` (authenticated user) to prevent unauthenticated enumeration.

### Linked entity

- `linked_entity_type` + `linked_entity_id` are opaque string pairs at this boundary. PTY-001..PTY-015 (`docs/ofbiz/specs/PTY-*.md`) will provide the Party/Contact/Account tables; no FK constraint is applied in ACT-010.
- Both fields must be provided together or both omitted. Validation rule in `CrmNoteCreateIn`:

  ```python
  @model_validator(mode="after")
  def _entity_pair(self) -> "CrmNoteCreateIn":
      has_type = bool(self.linked_entity_type)
      has_id = bool(self.linked_entity_id)
      if has_type != has_id:
          raise ValueError("linked_entity_type and linked_entity_id must both be set or both omitted")
      return self
  ```

### Pagination

- `list_notes` (PK query): uses `ExclusiveStartKey` from `decode_cursor(cursor)`, returns `encode_cursor(resp.get("LastEvaluatedKey"))`. Default `limit=20`, max `100` (enforced via `min(limit, 100)`).
- `list_notes_for_entity` (GSI query): same cursor pattern. Because GSI1SK is a Number, the `decode_cursor` / `encode_cursor` functions already handle `Decimal` serialisation correctly (see `app/core/cursor.py:17–18`).

### Audit events

Every mutating operation emits an audit event via `alerts.audit_event`:

| Operation | Event string |
|-----------|-------------|
| Create note | `crm_note_created` |
| Attach file | `crm_note_attachment_uploaded` |
| Update body | `crm_note_updated` |
| Delete note | `crm_note_deleted` |

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### SECOPS-007 parity

There is **no `dev_mode` branch** in business logic. The only place `S.dev_mode` is consulted is in `_store_attachment` when constructing `attachment_url`:

- `S.dev_mode=True` → `/mock/s3/{bucket}/{key}` (same pattern as `kyc_partner_api._store_document_bytes:507–508`).
- `S.dev_mode=False` → `s3_client().generate_presigned_url(...)` (same as `kyc_partner_api.py:634–636`).

The `s3_client()` factory (`app/core/aws_clients.py`) resolves to moto in-process in dev and real AWS S3 in prod — the calling code is identical in both environments.

### Idempotency

- `create_note` is not idempotent by design: each call mints a new `note_id` (uuid4). Callers must de-duplicate at the frontend layer.
- `attach_file` is idempotent if called twice with the same bytes: the S3 key is deterministic (`crm-notes/{user_sub}/{note_id}/{safe_filename}`) so the second upload overwrites the same object. The DDB update_item is a straightforward attribute update — no conditional expression needed.
- `delete_note` is idempotent: if the note is already absent, `get_note` returns `None` and the router returns 404 (not 500).

### Security

- **Ownership enforcement**: PK access pattern (`PK=user_sub, SK begins_with NOTE#`) means one user cannot read or delete another user's notes. This is enforced in the service layer, not just the router.
- **S3 key predictability**: S3 keys include `user_sub` and `note_id` (uuid4) — not guessable by another user. Presigned URLs expire in 300 seconds, limiting the window for leaked URL reuse.
- **File content-type**: `content_type` is stored as supplied by the browser `UploadFile.content_type`; no server-side MIME sniffing. The download endpoint (presigned URL) passes this through as `ContentType` on the S3 object, so browsers receive the correct `Content-Type` header.
- **Body XSS**: body is stored as raw text; sanitisation is the frontend's responsibility. The API never renders body HTML server-side.
- **No KMS encryption on attachment**: file bytes are stored unencrypted in S3 for this initial ticket. A follow-up ticket should add SSE-KMS (`ServerSideEncryption="aws:kms"`) at the `put_object` call site to match the approach used for SSH key storage in `app/core/crypto.py`.
- **Audit trail**: every write is captured via `audit_event` into `T.alerts` (existing table, no new infra needed), providing an immutable log for compliance.

## 8. Backward Compatibility & Migration

### Existing tables and routes

No existing DDB table, router, or endpoint is modified. The `crm_notes` table is entirely new.

### `T` dataclass extension (ACT-001)

`app/core/tables.py` is a frozen `@dataclass`. Adding a new field requires adding it to both the `Tables` dataclass body and the `T = Tables(...)` instantiation at the bottom of the file. ACT-001 does this; ACT-010 must verify ACT-001 is merged before proceeding. The `T` dataclass is frozen so any test that patches `T.crm_notes` must use `object.__setattr__(T, "crm_notes", mock_table)` with a corresponding cleanup.

### `just restart` DDB recreation

`scripts/local-ddb-init.py` runs `CreateTable` for every `TableDef`. Because DynamoDB Local is wiped on `just restart` (ephemeral dev data), no schema migration is needed: the table is recreated fresh with the correct GSI and `attr_types={"GSI1SK": "N"}` every time.

### Frontend route addition

Adding `/crm/notes` to `App.tsx` is additive. No existing route is changed or renamed.

## 10. Open Questions / Assumptions

1. **Multiple attachments per note**: SuiteCRM's Notes module supports multiple file attachments. This spec implements a single-attachment model (max one S3 object per note) to keep the data model simple. If the product decision changes, the DDB model should be extended to store `attachments: List[dict]` and the upload endpoint should allow repeated calls to append rather than replace.

2. **Shared / collaborative notes**: this ticket implements per-user private notes. If notes need to be shared across a team or org, a separate ACL table (similar to `crm_event_rsvp`) should be added in a follow-up ticket. The current `list_notes_for_entity` intentionally shows all authors' notes on an entity, which is the read-only sharing model.

3. **Rich text body**: SuiteCRM supports HTML-rich notes. This ticket stores plain text only (`body: str`). Switching to rich text (HTML or Markdown) is a non-breaking additive change to the model and frontend — the `body` field stays a string, the frontend textarea is replaced with a rich-text editor.

4. **Search indexing**: body text is not indexed for full-text search in this ticket. Integration with `app/services/search.py` is deferred to a search-integration ticket.

5. **ACT-001 assumed merged**: if ACT-001 is not yet merged at implementation time, the developer must inline the settings additions (`crm_activities_enabled`, `crm_notes_enabled`, `crm_notes_table_name`), the `TableDef` addition, and the `T.crm_notes` handle as part of this ticket.

6. **`S.dev_mode` in `_store_attachment`**: the only `dev_mode` branch in the entire module is URL construction — not data storage logic. This satisfies SECOPS-007 (same bytes reach S3 in both environments; only the returned URL differs).

7. **Presigned URL expiry in tests**: E2E tests run in dev mode so `attachment_url` is always `/mock/s3/...`. Prod presigned URL expiry (300 s) is only exercised in the unit test with a patched `generate_presigned_url`.
