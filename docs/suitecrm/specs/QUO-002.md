# QUO-002 — AOS PDF Template engine — module-agnostic merge-field PDF for Quotes, Invoices, and Contracts

**Type:** Feature  **Priority:** P1  **Estimate:** 3d  
**Depends on:** QUO-001 (quote entity)  
**Enables:** QUO-003 (quote/contract conversion), QUO-004 (contract PDF templates), QUO-005 (standalone invoice lifecycle)

---

## 1. Summary & Goal

Build a module-agnostic admin PDF template engine for the AOS (Advanced OpenSales) suite. Admins upload PDF files with `{{merge_field}}` placeholders, associate them with a `module` (quote, invoice, or contract), and the platform substitutes record-specific values at PDF download time. The engine is a thin parameterization layer over the existing `KycDocumentTemplateService` (`app/services/kyc_document_templates.py:108`), sharing its structural patterns (S3 upload, VERSION# row versioning, placeholder extraction, status lifecycle) without forking any code.

The only user-visible changes when `AOS_PDF_TEMPLATES_ENABLED=0` are none — the platform is byte-for-byte identical to its current state. The existing `GET /ui/invoices/{number}/pdf` endpoint continues rendering via `_render_pdf` / `_render_invoice_lines` (`app/services/invoices.py:103,150`) exactly as today.

### New DynamoDB table: `aos_pdf_templates`

**Registration** in `scripts/local-ddb-init.py` (append after the `kyc_document_templates` `TableDef` at line 208):

```python
TableDef(
    _resolve_table_name(S.aos_pdf_templates_table_name, "aos_pdf_templates"),
    "template_id",     # hash key
    "sk",              # range key — "VERSION#{n}", n=0 is metadata row
    gsi=[
        {
            "index_name": "slug-module-index",
            "partition_key": "slug",
            "sort_key": "module",
        },
        {
            "index_name": "module-status-index",
            "partition_key": "module_status",   # composite: f"{module}#{status}"
            "sort_key": "updated_at",
        },
    ],
    attr_types={"updated_at": "N"},   # numeric GSI sort key — REQUIRED
),
```

`attr_types={"updated_at": "N"}` is mandatory; without it DynamoDB Local stores `updated_at` as String and the `module-status-index` sort-key query using integer comparators raises `ValidationException` at runtime (see CLAUDE.md "DynamoDB numeric GSI sort keys" gotcha).

**Item schema** (VERSION#0 metadata row):

| Attribute | Type | Notes |
|-----------|------|-------|
| `template_id` | S | `"apdt_" + uuid4().hex[:16]` |
| `sk` | S | `"VERSION#0"` (metadata); `"VERSION#{n}"` for uploaded versions |
| `module` | S | `"quote"` \| `"invoice"` \| `"contract"` |
| `slug` | S | Human-readable key; unique per `(module, slug)` pair |
| `module_status` | S | `f"{module}#{status}"` — GSI2 partition key |
| `display_name` | S | |
| `description` | S | Default `""` |
| `status` | S | `"active"` \| `"inactive"` \| `"archived"` |
| `placeholder_fields` | L | `["quote_number", "total_cents", ...]` |
| `s3_key` | S | S3 key of latest uploaded PDF; `""` until first upload |
| `latest_version` | N | Incremented on each `upload_template_version` |
| `created_by` | S | `user_sub` of creating admin |

**COUNTER/SEQ row**: not required for this ticket; QUO-001 owns the quote-number counter; QUO-005 extends the invoice counter. This table has no sequence counter.

## 5. Detailed Behavior & Edge Cases

### Merge variable catalogue

At render time the caller passes a `dict[str, str]` of merge vars. The engine does not enforce which fields are present — missing `{{field}}` markers are left verbatim in the rendered PDF (no silent deletion), making unfilled placeholders visible to the reviewer. This intentionally differs from `_FALLBACKS` in `kyc_document_templates.py:62` which substitutes `[Name]` etc.; the AOS engine wants admin-visible gaps rather than invisible fallback text.

**Invoice merge vars** (`_invoice_merge_vars(record: dict) -> dict[str, str]`):

| Variable | Source |
|----------|--------|
| `invoice_number` | `record["invoice_number"]` |
| `invoice_date` | `datetime.fromtimestamp(record["created_at"]).strftime("%B %d, %Y")` |
| `buyer_name` | `record.get("buyer_name", "")` |
| `buyer_email` | `record.get("buyer_email", "")` |
| `seller_name` | `record.get("seller_name", "Platform")` |
| `subtotal` | `_money(record.get("amount_cents", 0))` (reuses `invoices.py:146`) |

### Slug uniqueness

Uniqueness is scoped to `(module, slug)` — the same slug string may exist for both `module="quote"` and `module="invoice"`. The `slug-module-index` GSI enforces this: query with `Key("slug").eq(slug) & Key("module").eq(module)`, returning a hit indicates collision.

### Template activation rules

- A template with `s3_key=""` (never uploaded) cannot be activated — `set_status` raises `AosPdfTemplateValidationError("no_pdf_uploaded")` when `new_status="active"` and `s3_key=""`.
- Only one template per `(module, status="active")` is enforced at the application level: when `set_status(template_id, "active")` is called, the service first queries `get_active_template_for_module(module)` and deactivates any other active template in the same module before activating the target. This mirrors the sibling-deactivation pattern at `kyc_document_templates.py:295`.
- Archived templates: the `archived` status is terminal. `set_status(template_id, "active"|"inactive")` raises `AosPdfTemplateValidationError("already_archived")` if `status == "archived"` on the metadata row.

### S3 key format

`f"{S.aos_pdf_templates_s3_prefix}{module}/{template_id}/v{version}.pdf"`

Example: `aos-pdf-templates/quote/apdt_abc123/v2.pdf`. Distinct from KYC prefix (`kyc-document-templates/`).

### Render fallback chain

1. If `s3_key != ""`, attempt `_get_object(s3_key)`.
2. If S3 returns `None` (transient failure, moto miss), fall back to `_placeholder_pdf(placeholder_fields)` from `kyc_document_templates.py:494` — re-imported, not duplicated.
3. Apply `_merge_placeholders(pdf_bytes, merge_vars)` regardless.
4. Any unrecognised `{{field}}` in the PDF that is not in `merge_vars` is left verbatim (not removed, not substituted with fallback). This ensures template authors see exactly which fields are unmapped.

### File size limit

`len(pdf_bytes) > S.aos_pdf_templates_max_pdf_bytes` raises `AosPdfTemplateValidationError("file_too_large")`. Default cap is 10 MB (same as `kyc_document_templates_max_pdf_bytes` at `settings.py:2723`).

### Concurrent uploads

Concurrent `upload_template_version` calls for the same `template_id` could race on `latest_version`. Mitigate with a conditional `update_item`:

```python
T.aos_pdf_templates.update_item(
    Key={"template_id": template_id, "sk": "VERSION#0"},
    UpdateExpression="SET latest_version = :v, s3_key = :k, updated_at = :ts, module_status = :ms",
    ConditionExpression="latest_version = :expected",
    ExpressionAttributeValues={":v": next_version, ":k": s3_key, ":ts": ts,
                                ":ms": f"{module}#{status}", ":expected": current_version},
)
```

On `ConditionalCheckFailedException`, the caller receives HTTP 409 with `code="version_conflict"`.

### PDF bytes encoding

`_merge_placeholders` decodes PDF bytes with `latin-1` (same as `kyc_document_templates.py:413`). This is intentional: PDF byte streams contain binary sequences that round-trip through `latin-1` without corruption, whereas `utf-8` decode would fail on typical PDF binary. `{{placeholder}}` markers in PDF text streams are ASCII-safe and survive this round-trip correctly.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

**No `if S.dev_mode` branches in service code.** Moto intercepts boto3 S3 calls at the botocore layer in dev exactly as in prod (`app/core/dev_s3.py`). `_put_object` and `_get_object` are identical in both environments. The `_placeholder_pdf` fallback fires only when S3 returns `None` (transient error or test stub), not based on dev mode.

**Template upload is idempotent per version**: each `upload_template_version` call increments `latest_version` atomically and writes a new VERSION#n row. Re-uploading the same bytes produces a new version row; it does not overwrite the previous. Version history is immutable.

**Slug creation idempotency**: `create_template` raises `AosPdfTemplateSlugExists` on duplicate `(module, slug)`. Callers must use an `Idempotency-Key` header pattern (or simply retry with a different slug). The router returns HTTP 409 on `AosPdfTemplateSlugExists`.

**Rendered PDF is not cached on S3** for quote/invoice templates (unlike the KYC `render_and_store` path at `kyc_document_templates.py:463`). Each `GET /pdf` call re-renders from the latest active template. If performance becomes a concern, caching can be layered on top without schema change. The existing invoice S3 cache (`_fetch_pdf` / `_store_pdf`) is preserved for the text-PDF regeneration path.

**Access control**: All template management endpoints require `ADMIN` or `ROOT` role (`require_admin_or_root` at `app/auth/policy.py:67`). The `GET /ui/quotes/{id}/pdf` and `GET /ui/invoices/{number}/pdf` endpoints use `require_ui_session` — users can only download PDFs for records they own (ownership enforced by the quote/invoice service layer before render).

**Audit trail**: `audit_event(...)` at `alerts.py:644` is emitted for `create_template`, `upload_template_version`, `set_status`. The preview and render-for-download paths do not emit audit events (read-only, high-frequency).

**No money-out paths**: this ticket does not touch billing, refunds, or the ledger. No `refund_payment` or `settle_or_reverse_ledger` calls are needed.

**CSRF**: Non-GET admin endpoints require a valid CSRF token when the request arrives via a browser cookie session. `enforce_cookie_csrf(request)` at `app/auth/policy.py:71` is called explicitly in non-GET route handlers, following the pattern used by other admin routers. Bearer-token API clients skip CSRF.

## 10. Open Questions / Assumptions

1. **Multi-page line items**: The `_merge_placeholders` pattern replaces scalar `{{field}}` markers only. Multi-line-item blocks (e.g., a repeating table row per line item) require a more advanced template language (e.g., `{{#each line_items}}`) and a library like `pdfrw` or `reportlab`. This ticket assumes simple scalar substitution only, matching the existing KYC approach. A follow-on ticket should address tabular line-item rendering if required.

2. **Per-module active-template constraint**: The spec enforces at most one `status="active"` template per module at the application level (not a DDB conditional). This is correct for the current scale but could have a TOCTOU gap under high concurrency. If multiple admins race to activate templates simultaneously, a DDB conditional-write approach (checking `module_status` on the row being deactivated) would be needed.

3. **Template versioning and cache invalidation**: rendered PDFs are not S3-cached (see section 7). If a quote was sent to a buyer and the admin then uploads a new template version, re-downloading the quote PDF will render with the new template. This is a business decision — the alternative is to snapshot the rendered PDF at "send" time, which would require integration with QUO-001's `stage=sent` transition.

4. **`module="contract"` placeholder catalogue**: contract merge vars (contract_number, start_date, end_date, value, etc.) depend on QUO-004 delivering `app/services/aos_contracts.py`. The `AosPdfTemplateService` already accepts `module="contract"` templates; `_contract_merge_vars(record)` is left as a stub returning `{}` until QUO-004 lands.

5. **Frontend admin UI**: this spec covers only the backend. A frontend `PdfTemplatesPage` under `frontend/src/pages/admin/` is a separate ticket.

6. **`python-multipart` dependency**: the dev environment installs this via `requirements.txt`. The `_MULTIPART_AVAILABLE` guard at `catalog.py:44` is replicated here as a safety net, but in practice it is always available in testlogon's virtualenv.
