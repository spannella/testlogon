# EML-008 — Inbound group mailbox auto-ticket creation

**Type:** Feature | **Priority:** P1 | **Estimate:** 3d  
**Flag:** `INBOUND_MAILBOX_ENABLED` (default OFF)

---

## 1. Summary & Goal

EML-008 adds an inbound email-to-ticket pipeline so that a dedicated support
email address (e.g. `support@example.com`) can automatically generate and
thread support tickets in the existing ticket system. Incoming email arrives
via AWS SES → SNS → a new `POST /internal/ses/inbound` endpoint that parses
the raw MIME payload, resolves the recipient address to a configured mailbox,
and either creates a fresh ticket or appends a reply to an existing one. Admin
users manage mailbox configurations through new endpoints appended to the
existing `app/routers/admin_email.py` router. A dev-only test endpoint
(`POST /ui/admin/email/mailboxes/test-inbound`) allows E2E testing without
real SNS infrastructure.

The entire feature is additive and gated behind `S.inbound_mailbox_enabled`.
With the flag off the platform is byte-for-byte unchanged.

## 3. Data Model

### New DynamoDB table: `inbound_mailboxes`

Add to `scripts/local-ddb-init.py` (after the `AdminMessagingTemplates` entry
at line 1429) and to `app/core/tables.py` (`Tables` dataclass + `T` instance).

```
Table name:  inbound_mailboxes  (S.inbound_mailboxes_table_name, default "inbound_mailboxes")
PK (hash):   pk   (S)
SK (range):  sk   (S)
```

**Row types:**

| pk | sk | Purpose |
|---|---|---|
| `MAILBOX#{mailbox_id}` | `META` | Mailbox configuration |
| `ADDR#{address_lower}` | `META` | Address→mailbox_id lookup (duplicate row for fast resolution) |

**META item attributes (MAILBOX# partition):**

```
mailbox_id:      str      uuid4 hex, prefix "mbx_"
address:         str      monitored email address, lowercase-normalised
label:           str      human label, max 100 chars
auto_assign_sub: str|None default assignee user_sub (optional)
space_id:        str|None ticket space to file new tickets in (optional)
enabled:         bool
created_at:      N        now_ts()
updated_at:      N        now_ts()
created_by:      str      admin user_sub
```

**ADDR# row** (written atomically with the MAILBOX# META row):

```
pk: ADDR#{address_lower}   e.g. ADDR#support@example.com
sk: META
mailbox_id: str            points to the MAILBOX# partition
address:    str
```

**GSI `ByAddress`:**

```
Partition key: address   (S)   — the normalised email address
No sort key needed
```

No numeric sort key → no `attr_types` entry required.

Add `TableDef` in `scripts/local-ddb-init.py`:

```python
TableDef(
    _resolve_table_name(S.inbound_mailboxes_table_name, "inbound_mailboxes"),
    "pk",
    "sk",
    gsi=[{"index_name": "ByAddress", "partition_key": "address"}],
),
```

Add to `Tables` dataclass (`app/core/tables.py`) and to the `T` singleton
initialiser, using `_safe_table(S.inbound_mailboxes_table_name or "inbound_mailboxes")`.

### Reuse of existing `T.tickets`

No schema changes. `create_ticket` and `add_message` are called exactly as they
exist today. The inbound pipeline writes a `source_email` key into the
`metadata` dict of the ticket header row so that the UI can distinguish
email-originated tickets, but this is an unindexed pass-through field.

## 4. API / Service Design

### 4.1 New service: `app/services/inbound_email.py`

```python
# All public functions operate under S.inbound_mailbox_enabled guard at call site.

def create_mailbox(
    actor_sub: str,
    address: str,
    label: str,
    *,
    auto_assign_sub: str | None = None,
    space_id: str | None = None,
) -> dict:
    """Create a new mailbox config. Raises ValueError if address already registered."""

def get_mailbox(mailbox_id: str) -> dict | None:
    """Fetch by mailbox_id (MAILBOX#{id}/META)."""

def resolve_mailbox_by_address(address: str) -> dict | None:
    """Query ByAddress GSI on inbound_mailboxes table; returns the mailbox dict or None."""

def list_mailboxes(*, limit: int = 50, cursor: str | None = None) -> tuple[list[dict], str | None]:
    """Paginated scan of all MAILBOX# partition META rows (admin use only)."""

def update_mailbox(
    actor_sub: str,
    mailbox_id: str,
    *,
    label: str | None = None,
    auto_assign_sub: str | None = None,
    space_id: str | None = None,
    enabled: bool | None = None,
) -> dict:
    """Patch mailbox fields. Returns updated dict. Raises KeyError if not found."""

def delete_mailbox(actor_sub: str, mailbox_id: str) -> None:
    """Delete both the MAILBOX# META and ADDR# lookup rows."""

def process_inbound_message(raw_mime: bytes) -> dict:
    """
    Parse raw MIME bytes, resolve recipient to a mailbox, create-or-thread ticket.

    Returns:
        {"action": "created", "ticket_id": str, "mailbox_id": str}
        {"action": "threaded", "ticket_id": str, "mailbox_id": str}
        {"action": "ignored",  "reason": str}

    Never raises — all exceptions are caught and logged; returns
    {"action": "error", "reason": str} on parse failures.
    """
```

**Implementation notes for `process_inbound_message`:**

1. Parse with `email.parser.BytesParser().parsebytes(raw_mime)` (stdlib).
2. Extract `To` / `Delivered-To` / `X-Original-To` headers to find the
   recipient address. Try each header in that order; take the first address
   that resolves to a known mailbox via `resolve_mailbox_by_address`.
3. If no mailbox resolves, return `{"action": "ignored", "reason": "no_matching_mailbox"}`.
4. If `mailbox.enabled` is False, return `{"action": "ignored", "reason": "mailbox_disabled"}`.
5. **Thread detection:** check `References` and `In-Reply-To` headers for a
   token matching `<ticket-{ticket_id}@` (e.g.
   `<ticket-tkt_abc123@support.example.com>`). If found and
   `STORE.get_ticket(ticket_id)` returns a record, call `STORE.add_message`
   with `sender_role="user"` and `sender_sub=_resolve_sender_sub(from_addr)`.
6. **Create path** (no matching ticket reference): extract `Subject` (strip
   `Re:` / `Fwd:` prefixes), decode body text (prefer `text/plain` part,
   fall back to stripping `text/html` tags with `html.unescape` + regex).
   Call `STORE.create_ticket(owner_sub=..., subject=..., description=...,
   space_id=mailbox.space_id, metadata={"source_email": from_addr,
   "source_mailbox_id": mailbox_id})`. If `mailbox.auto_assign_sub` is set,
   immediately call `STORE.assign_ticket(ticket_id=..., actor_sub="system_inbound",
   assignee_sub=mailbox.auto_assign_sub)`.
7. Call `audit_event("inbound_email_processed", actor_sub="system_inbound",
   mailbox_id=..., ticket_id=..., action=..., from_addr=...)`.
8. Return the action dict.

**Sender resolution (`_resolve_sender_sub`):** query `T.users` for a user
whose `email` attribute matches `from_addr` (case-insensitive). This is a
`scan` with `FilterExpression` in dev (acceptable — inbound volume is low
and the scan is bounded to the users table). Return the `user_sub` if found;
return `S.inbound_mailbox_sentinel_sub` (default `"inbound@system"`) otherwise
and store the literal email address in ticket `metadata["sender_email"]`.

### 4.3 New inbound SNS endpoint (appended to `app/routers/ses_notifications.py`)

```python
@router.post("/internal/ses/inbound")
async def ses_inbound(request: Request) -> Response:
    ...
```

**Flow:**

1. Parse JSON body (return 400 on parse failure, identical to `ses_notification`
   line 44).
2. Run SNS signature verification if `S.ses_sns_signature_verification_enabled`
   (same `verify_sns_message` + `SnsSignatureError` block as lines 47–57 of the
   existing endpoint).
3. Handle `SubscriptionConfirmation` (auto-confirm via `confirm_subscription`,
   same as line 75) and `UnsubscribeConfirmation` (log + 200).
4. For `Notification` type: extract raw MIME. SES inbound rule can be configured
   two ways:
   - **S3 action:** SNS message body contains `{"notificationType":"Received",
     "mail":{...}, "receipt":{...}}` and the `action.bucketName` / `action.objectKey`
     fields. Fetch the raw email from S3 via `app.core.aws_clients.s3_client`
     (`get_object`).
   - **SNS action (raw MIME in body):** SNS `Message` field contains the full
     MIME string (base64 or plain). Use when the SES rule uses SNS action directly.
   Detect mode by checking for `action.type == "S3"` in the receipt. Fall back
   to treating `body["Message"]` as raw MIME.
5. Return 503 with `{"action": "disabled"}` if `not S.inbound_mailbox_enabled`.
6. Call `inbound_email.process_inbound_message(raw_mime)`. All exceptions are
   swallowed (log + return 200) so SNS never retries a permanently-broken message.
7. Return `Response(status_code=200)` unconditionally (SNS must receive 200 or
   will retry).

## 5. Detailed Behavior & Edge Cases

### 5.1 Create-vs-thread decision

The pipeline checks `References` header first (full header, multiple Message-IDs
space/comma-separated), then `In-Reply-To`. Each token is matched against the
pattern `ticket-([a-z0-9_]+)@` using a single compiled regex. The first match
whose extracted `ticket_id` resolves via `STORE.get_ticket` wins. If the ticket
is in status `done`, calling `STORE.add_message` with `sender_role="user"` will
auto-reopen it to `open` (see `_next_status_for_message`, line 235 of
`app/services/tickets.py`).

### 5.2 Reply address / Message-ID injection

When `STORE.create_ticket` succeeds, the inbound service does NOT modify the
outbound reply Message-ID — the existing alert notification path in
`app/services/alerts.py` already sends `send_alert_email` with subject
`[Ticket #{ticket_id}] Created: …` (line 248). For proper threading, the
outbound ticket notification emails must carry an RFC-2822 `Message-ID` header
of the form `<ticket-{ticket_id}@{S.inbound_mailbox_domain}>`. This requires
EML-001's `html_body` extension to also accept a `message_id_header: str |
None` override. **This cross-ticket wiring is an open question (see §10).**
In the initial implementation the `References` token approach works for replies
sent by users who quote the original notification body or add the token manually
— a practical constraint for the MVP.

### 5.3 Sentinel user

When the sender's `From` address does not match any `T.users` record, the
ticket is created under `S.inbound_mailbox_sentinel_sub` (default
`"inbound@system"`). The literal sender email is stored in
`metadata["sender_email"]`. Admin UI can display this in the ticket detail view
without any schema change.

### 5.4 Duplicate delivery / idempotency

SES guarantees at-least-once delivery. To prevent a duplicate ticket from the
same email, `process_inbound_message` extracts the `Message-ID` header (the
RFC-2822 unique message identifier) and writes a deduplication row:

```
PK: DEDUP#{sha256(message_id_header)[:32]}
SK: META
processed_at: N   now_ts()
ticket_id:    str
action:       str
```

Before creating or threading, the service does a `get_item` on this key. If the
row exists, it returns `{"action": "duplicate", "ticket_id": ..., "reason":
"already_processed"}` immediately and SNS receives 200. The dedup row has a
TTL of 30 days (`dedup_ttl = now_ts() + 30 * 86400`). This row lives in the
same `inbound_mailboxes` table (single-table design).

### 5.5 Oversized bodies

If the decoded plain-text body exceeds 32 000 characters (safe DynamoDB item
size margin given other ticket attributes), it is truncated to 32 000 chars
with a `"\n\n[truncated]"` suffix. The full MIME bytes are NOT stored — only
the extracted text.

### 5.6 Attachment handling

Multipart emails with attachments: attachment parts are ignored in the MVP.
The count of attachments is stored in `metadata["attachment_count"]` so that
the admin can see that the original email had attachments and follow up. A
future ticket (EML-007 or an EML-008 follow-up) can persist attachments to S3.

### 5.7 MIME parsing errors

If `email.parser.BytesParser` raises or the result contains no `To`/`Subject`
headers, `process_inbound_message` returns `{"action": "error", "reason":
"mime_parse_failure"}`. `ses_inbound` logs the failure at WARNING level and
returns 200 to SNS.

### 5.8 Mailbox address uniqueness

`create_mailbox` normalises the address with `app/core/normalize.normalize_email`
(already imported in `alerts.py:17`). Before writing, it does a
`get_item(Key={"pk": f"ADDR#{address_lower}", "sk": "META"})` check. If the
row already exists, it raises a `ValueError("address_already_registered")`
which the router maps to HTTP 400.

### 5.9 Space / auto-assign validation

EML-008 does **not** validate that `space_id` points to an existing ticket
space or that `auto_assign_sub` is a real user. These are advisory fields; if
they are stale (space deleted, user deactivated), `create_ticket` / `assign_ticket`
silently degrades — the ticket is still created without a space or assignment.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### SECOPS-007 — no `dev_mode` branch in service logic

`process_inbound_message` calls the **same code** in dev and prod:
`email.parser.BytesParser`, `STORE.create_ticket`, `STORE.add_message`,
`audit_event`. There is no `if S.dev_mode` branch inside the service. The
test-inbound endpoint (`/ui/admin/email/mailboxes/test-inbound`) is gated by
`S.dev_mode` at the **router** level (HTTP 404 in prod) so only its
*route handler* is environment-specific, not the underlying service call.

S3 MIME body retrieval in `ses_inbound` calls `app.core.aws_clients.s3_client`,
which already resolves to the moto in-process S3 in dev
(`app/core/dev_s3.py` intercepts botocore). No separate branch required.

### SNS signature verification

Exactly mirrored from the existing endpoint (`ses_notifications.py:47`).
`S.ses_sns_signature_verification_enabled` defaults to `True`. The flag
exists only for test environments. No new bypass mechanism is introduced.

### Idempotency

Covered by the `DEDUP#{hash}/META` row (§5.4). The `conditional_update_meta`
version-check in `TicketStore` also prevents concurrent processing from
double-appending a message: the second writer hits `ConditionalCheckFailedException`
and returns an error, but because `process_inbound_message` wraps everything
in `try/except` and returns 200 to SNS either way, this is safe.

### Security considerations

- **SNS SSRF guard:** `verify_sns_message` validates `SigningCertURL` must be
  an `https://sns.<region>.amazonaws.com/…` URL before fetching. This guard
  runs on the new endpoint identically to the existing one.
- **Sentinel user isolation:** tickets created under `inbound@system` are
  visible to admins but cannot be escalated to owned sessions unless an admin
  manually reassigns.
- **Address normalisation:** `normalize_email` is called on all `address` inputs
  at `create_mailbox` time to prevent homograph/case variations from bypassing
  the uniqueness check.
- **Body truncation at 32 000 chars:** prevents a malicious oversized email
  from causing a DynamoDB item-too-large error or inflating ticket storage.

## 8. Backward Compatibility & Migration

### Flag-off guarantee

With `INBOUND_MAILBOX_ENABLED=0` (the default):

- `POST /internal/ses/inbound` returns 503 immediately (before any MIME
  parsing or DDB access).
- All `/ui/admin/email/mailboxes` endpoints return 503.
- `T.inbound_mailboxes` is created at DDB-init time regardless of the flag
  (`scripts/local-ddb-init.py` always creates all tables), but no data is
  written to it while the flag is off.
- The existing `/internal/ses/notifications` endpoint, `admin_email_router`,
  `T.tickets`, and `send_alert_email` are entirely unchanged.

### DynamoDB table creation

The `inbound_mailboxes` table is added to `scripts/local-ddb-init.py`. Local
dev: table is created on the next `just restart`. Prod: an `UpdateTable` /
`CreateTable` migration step is needed before enabling the flag. No GSI sort key
is numeric, so no `attr_types` workaround is required.

### Existing `ses_notifications_router`

The new `@router.post("/internal/ses/inbound")` is appended to the existing
router object in `app/routers/ses_notifications.py`. Because the router is
already included in `app/main.py:780`, no `app.include_router` call is added
to `main.py`. The existing `POST /internal/ses/notifications` route is
unmodified.

### No model.py breakage

`MailboxCreateIn`, `MailboxUpdateIn`, `MailboxOut` are new classes with no
relation to existing models. `TicketOut` and `TicketMessage` in
`app/routers/tickets.py` are unchanged.

## 9. Test Plan

### 9.1 Hermetic pytest: `tests/test_eml_008_inbound_mailbox.py`

## 10. Open Questions / Assumptions

1. **Reply Message-ID injection (§5.2):** Proper email threading requires
   outbound ticket notification emails to carry `Message-ID:
   <ticket-{ticket_id}@{domain}>` and `In-Reply-To` / `References` headers.
   EML-001 only adds `html_body` to `send_alert_email`; it does not add SMTP
   header injection. This needs either a follow-up EML-001 extension or a
   separate micro-ticket. The current design works for users who reply to emails
   that include the ticket ID in the body (common with subject-line ID encoding),
   but strict header-based threading is deferred.

2. **S3 vs SNS-raw MIME delivery mode:** The spec supports both. Operators must
   choose one when configuring the SES inbound rule. The `INBOUND_MAILBOX_DOMAIN`
   setting should match the SES verified domain. If `S3` mode is used, the SES
   rule must grant the backend's IAM role `s3:GetObject` on the target bucket.
   This IAM setup is out of scope for this ticket.

3. **User lookup performance:** `_resolve_sender_sub` performs a DynamoDB Scan
   with a `FilterExpression` on the users table to match by email. This is
   acceptable for low-volume inbound email (tens per hour), but for
   high-volume mailboxes an email→user GSI on the users table would be required.
   This is deferred until volume justifies it.

4. **Sentinel user authentication:** Tickets owned by `"inbound@system"` cannot
   be accessed by any real user session (the owner_sub does not map to a
   Cognito identity). The ticket router's `require_ui_session` check will still
   allow admins to view all tickets by status/assignee. This is the intended
   MVP behaviour.

5. **Attachment persistence:** MVP ignores attachment bytes. A follow-up can
   store attachments to S3 at `inbound-attachments/{mailbox_id}/{ticket_id}/{filename}`
   via `app.core.aws_clients.s3_client` and link them in `metadata["attachments"]`.
