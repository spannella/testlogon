# STU-010 — Admin currency management

**Type:** Feature  **Priority:** P1  **Estimate:** 2 days  
**Ticket source:** `docs/suitecrm/CRM_SECURITY_STUDIO_TICKETS.md`, section "STU-010"  
**Feature flag:** `CRM_STUDIO_ENABLED` (env `CRM_STUDIO_ENABLED`, default `"0"`) — all routes under `/ui/admin/currencies/*` return 404 while the flag is off.

---

## 1. Summary & Goal

`app/core/settings.py:324–325` defines two static env-var fields `default_currency_code` and `default_currency`, but there is no DynamoDB-backed store for currency metadata, no exchange-rate registry, and no admin API to create, update, or remove currencies at runtime without a process restart.

STU-010 delivers:

1. **`app/services/currency_service.py`** — a DynamoDB-backed currency store with a 60-second in-memory TTL cache, modelled directly on `app/services/billing_config.py`. Persists per-currency rows and a single global config row in the `currencies` table introduced by STU-001. Exposes `list_currencies`, `get_currency`, `create_currency`, `update_currency`, `delete_currency`, `set_default_currency`, `get_default_currency`, `convert_amount`, and `get_exchange_rate`.
2. **`app/routers/admin_currencies.py`** — six admin endpoints (`GET /`, `POST /`, `GET /{code}`, `PATCH /{code}`, `DELETE /{code}`, `POST /default`) under `/ui/admin/currencies`, gated by `CRM_STUDIO_ENABLED`.
3. **Pydantic models** in `app/models.py`: `CurrencyCreateIn`, `CurrencyUpdateIn`, `CurrencyOut`.

The change is purely additive and default-OFF. With `CRM_STUDIO_ENABLED=0` all six routes return 404, no DynamoDB reads occur, and the existing `S.default_currency` / `S.stripe_default_currency` paths used throughout `app/routers/billing.py:815–2429` and `app/services/billing_ccbill.py:180–656` continue to function without modification.

## 3. Data Model

All rows live in the `currencies` table introduced by STU-001 (`pk` S, `sk` S, no GSI). Two row shapes are used:

### 3.1 Per-currency row

| Field | Type | Notes |
|---|---|---|
| `pk` | S | `"CURRENCY#{code}"` where `code` is upper-case 3-letter ISO 4217 (e.g. `"CURRENCY#EUR"`) |
| `sk` | S | `"META"` (always) |
| `code` | S | Canonical upper-case code, e.g. `"EUR"` |
| `name` | S | Human-readable name, e.g. `"Euro"` |
| `symbol` | S | Display symbol, e.g. `"€"` |
| `exchange_rate_to_usd` | N | Stored as `Decimal`, the number of US dollars one unit of this currency buys. `1.0` for USD, `1.09` for EUR (≈ EUR is stronger), `0.0127` for JPY. **Always expressed as USD per 1 unit of this currency.** Must be `> 0`. |
| `is_default` | BOOL | True for exactly one currency at a time |
| `is_active` | BOOL | Inactive currencies are excluded from `list_currencies(active_only=True)` and from `convert_amount` |
| `updated_by_sub` | S | `user_sub` of the last admin who wrote this row |
| `updated_at` | N | Unix timestamp int from `now_ts()` |

### 3.2 Global config row

| Field | Type | Notes |
|---|---|---|
| `pk` | S | `"CURRENCY_CONFIG"` |
| `sk` | S | `"CURRENT"` |
| `default_currency_code` | S | Upper-case 3-letter code of the current default currency |
| `updated_by_sub` | S | Admin sub who last changed the default |
| `updated_at` | N | Unix timestamp |

### 3.3 DynamoDB init entry

No new `TableDef` is needed — the `currencies` table is already declared by STU-001 as:

```python
TableDef("currencies", "pk", "sk")
```

The `exchange_rate_to_usd` attribute stored on per-currency rows is a `Decimal` (number type `N` in DynamoDB). No GSI sort key is numeric, so no `attr_types` override is required beyond what STU-001 already declares.

`_FloatSafeTable` at `app/core/tables.py:29–66` already coerces Python floats to `Decimal` on `put_item` / `update_item`, so no extra handling is needed at the service level.

## 4. API / Service Design

### 4.1 Service: `app/services/currency_service.py`

```python
# Module-level cache (mirrors billing_config.py:46–58)
_cache: Optional[List[Dict[str, Any]]] = None
_cache_ts: int = 0
_CACHE_TTL = 60  # seconds

def invalidate_cache() -> None: ...

# ── Read ────────────────────────────────────────────────────────────────────

def list_currencies(active_only: bool = True) -> list[dict]:
    """Scan all CURRENCY# rows; return sorted by code.
    Uses module-level cache; invalidated on every write."""

def get_currency(code: str) -> dict | None:
    """Point-read CURRENCY#{code.upper()} / META. Returns None if not found."""

def get_default_currency() -> str:
    """Read CURRENCY_CONFIG / CURRENT → default_currency_code.
    Falls back to S.default_currency (uppercased) if the config row is absent."""

def get_exchange_rate(from_code: str, to_code: str) -> Decimal:
    """Return exchange rate from_code → to_code via USD pivot.
    Raises ValueError if either currency is unknown or inactive."""

def convert_amount(amount_cents: int, from_code: str, to_code: str) -> int:
    """Convert amount_cents in from_code to to_code currency.
    Uses USD as pivot: result = amount_cents * rate_from / rate_to.
    Returns int (truncates sub-cent). Raises ValueError for unknown/inactive codes."""

# ── Write ───────────────────────────────────────────────────────────────────

def create_currency(
    actor_sub: str,
    code: str,
    name: str,
    symbol: str,
    exchange_rate_to_usd: float,
) -> dict:
    """Validate code is 3-letter alpha; raise 409 if currency already exists.
    Writes CURRENCY#{code}/META. Sets is_default=False, is_active=True.
    Emits audit_event("currency.created", actor_sub, currency_code=code).
    Invalidates cache. Returns the new currency dict."""

def update_currency(
    actor_sub: str,
    code: str,
    *,
    exchange_rate_to_usd: float | None = None,
    name: str | None = None,
    symbol: str | None = None,
    is_active: bool | None = None,
) -> dict:
    """At least one field required. exchange_rate_to_usd must be > 0 if provided.
    Raises 404 if currency does not exist. Updates only provided fields via update_item.
    Emits audit_event("currency.updated", actor_sub, currency_code=code, changed_fields=[...]).
    Invalidates cache. Returns the updated currency dict."""

def delete_currency(actor_sub: str, code: str) -> None:
    """Raise 409 (ConflictError) if code is the current default currency.
    Raises 404 if currency does not exist.
    Hard-deletes the CURRENCY#{code}/META row.
    Emits audit_event("currency.deleted", actor_sub, currency_code=code).
    Invalidates cache."""

def set_default_currency(actor_sub: str, code: str) -> None:
    """Raises 404 if currency does not exist; raises 400 if currency is inactive.
    Writes CURRENCY_CONFIG/CURRENT with new default_currency_code.
    Updates old default currency row: is_default=False.
    Updates new default currency row: is_default=True.
    Emits audit_event("currency.default_changed", actor_sub,
        old_code=prev_default, new_code=code).
    Invalidates cache."""
```

All functions are synchronous (no async). They are called from async FastAPI route handlers via direct call (not `asyncio.to_thread`) because DynamoDB boto3 calls are fast and blocking is acceptable at this scale, consistent with the billing_config pattern.

Custom exception classes (local to the module, not forked from existing ones):

```python
class CurrencyNotFound(Exception): ...
class CurrencyAlreadyExists(Exception): ...
class CurrencyIsDefault(Exception): ...  # raised by delete when code == default
class CurrencyIsInactive(Exception): ...  # raised by set_default when target inactive
```

### 4.2 Router: `app/routers/admin_currencies.py`

**Prefix:** `/ui/admin/currencies`  
**Feature gate:** `if not S.crm_studio_enabled: raise HTTPException(404)`  
**Route ordering:** The static segment `/default` is declared **before** the dynamic `/{code}` segment to prevent FastAPI capturing the literal string `default` as a currency code.

| Method | Path | Auth dep | Description |
|---|---|---|---|

| `POST` | `/` | `require_root` | Create currency; body `CurrencyCreateIn` |

| `PATCH` | `/{code}` | `require_root` | Update currency; body `CurrencyUpdateIn` |
| `DELETE` | `/{code}` | `require_root` | Delete currency |

Response status codes:
- `200` for GET / PATCH / POST (non-default-set)
- `201` for POST (create)
- `204` for DELETE

- `400` if `set_default` targets an inactive currency

## 5. Detailed Behavior & Edge Cases

### 5.1 Code normalization

All currency codes are uppercased by the service before any DDB key is constructed. `CurrencyCreateIn.code = "eur"` produces `pk = "CURRENCY#EUR"`. The Pydantic model accepts any case; validation (3-letter alpha only) is enforced inside `create_currency` before the DDB write:

```python
code = code.strip().upper()
if len(code) != 3 or not code.isalpha():
    raise ValueError(f"Invalid currency code: {code!r}")
```

### 5.2 Exchange rate conversion

`convert_amount(amount_cents, from_code, to_code)` uses USD as the pivot currency:

```
result = amount_cents * exchange_rate_to_usd(from_code) / exchange_rate_to_usd(to_code)
```

For same-currency conversions (`from_code == to_code`), `amount_cents` is returned unchanged without a DDB read. The function truncates (floors) to integer cents; callers that need rounding must do so themselves. Both `from_code` and `to_code` must be active currencies; inactive currencies raise `ValueError("currency <X> is inactive or unknown")` rather than silently returning zero.

USD itself must be seeded as a currency row (via `POST /`) with `exchange_rate_to_usd=1.0` before `convert_amount` can be used to convert from/to USD. The service does not auto-seed; the operator runs a seeding script or uses the admin API at deployment time.

### 5.3 Default currency lifecycle

`create_currency` always sets `is_default=False`. `set_default_currency(actor_sub, new_code)`: reads the config row; if present, sets `is_default=False` on the old default row (best-effort — skip silently if that row no longer exists); sets `is_default=True` on the new default row; writes `CURRENCY_CONFIG/CURRENT`. There is no DDB transaction. Two concurrent calls may briefly leave two rows with `is_default=True`, acceptable for this admin-only, low-frequency operation. `get_default_currency()` reads from the authoritative config row, not by scanning for `is_default=True`, so the `is_default` field on currency rows is cosmetic only.

### 5.4 Deletion guard

`delete_currency` checks `get_default_currency() == code` before proceeding. If true, it raises `CurrencyIsDefault`. The HTTP layer maps this to `409 Conflict` with `{"code": "currency_is_default", "detail": "Cannot delete the default currency. Set a different default first."}`. This guard also prevents the operator from accidentally leaving the system with no default.

### 5.5 Cache invalidation scope

The module-level cache stores the full list of currency dicts (result of a DDB scan). Every write operation calls `invalidate_cache()` before returning. The config row (`CURRENCY_CONFIG/CURRENT`) is not cached with the list — `get_default_currency()` uses a separate `_config_cache` dict with its own 60-second TTL.

### 5.6 Inactive currencies

Setting `is_active=False` on a currency (via `PATCH /{code}`) does not delete it. It is excluded from `list_currencies(active_only=True)` (the default). `GET /{code}` always returns the row regardless of active status. `convert_amount` raises `ValueError` if either currency is inactive, preventing silently wrong conversions. The default currency cannot be set to inactive while it remains the default; the service raises `400 Bad Request` if the caller attempts `PATCH` with `is_active=False` on the current default currency.

### 5.7 Code input via URL path

The `/{code}` path parameter in `GET /{code}`, `PATCH /{code}`, `DELETE /{code}` accepts any string from the URL. The service normalizes it to uppercase before DDB lookup. A path like `/ui/admin/currencies/eur` is equivalent to `/ui/admin/currencies/EUR`.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 SECOPS-007

There is no `if S.dev_mode` branch anywhere in `currency_service.py` or `admin_currencies.py`. The service writes to and reads from DynamoDB via `T.currencies` in both dev (moto in-process mock) and prod (real DynamoDB). The table handle `T.currencies` is a `_FloatSafeTable` proxy in both environments (`app/core/tables.py:65`).

### 7.2 Idempotency

- `create_currency`: Uses a `ConditionExpression: "attribute_not_exists(pk)"` on `put_item`. A duplicate POST returns `409` rather than silently overwriting.
- `set_default_currency`: The config row is written unconditionally. Repeating the same call with the same `code` is a no-op in effect (both currency rows already have the correct `is_default` value; the config row is overwritten with an identical value and a fresh `updated_at`). The audit event is still emitted on every call.
- `update_currency`: Only the provided fields are touched via `update_item` with a targeted `UpdateExpression`. Repeating the same PATCH with unchanged values writes an identical `updated_at` but otherwise is safe.

### 7.3 Security

- All write endpoints require `Role.ROOT`. Read endpoints require `Role.ADMIN` or `Role.ROOT`. This matches the risk level: exchange rates influence financial calculations.
- The `code` field in `CurrencyCreateIn` is validated to be 3-letter alphabetic before any DDB key is constructed, preventing injection of arbitrary characters into the `pk` string.
- Audit events are emitted for every mutation. The audit trail is queryable via the existing `audit_export` worker.
- `exchange_rate_to_usd` is validated `> 0` at the service layer to prevent division-by-zero in `convert_amount`.

## 8. Backward Compatibility & Migration

### 8.1 No existing code is changed

All charge paths in `app/routers/billing.py` and `app/services/billing_ccbill.py` continue to read `S.stripe_default_currency` / `S.default_currency` unchanged. The new `currency_service.get_default_currency()` is an additive helper — it is not wired into any existing payment flow by this ticket.

### 8.2 First-run seeding

The `currencies` table starts empty. No migration script is required for the flag-off state. When an operator first enables `CRM_STUDIO_ENABLED=true`, they must seed at least one currency via the admin API (or a one-time script) before `convert_amount` or `get_default_currency` can return meaningful results for CRM features that call them. A recommended seeding sequence:

1. `POST /ui/admin/currencies` with `{code:"USD", name:"US Dollar", symbol:"$", exchange_rate_to_usd:1.0}`
2. `POST /ui/admin/currencies/default` with `{code:"USD"}`

This does not affect the billing subsystem's `S.default_currency` / `S.stripe_default_currency` values.

### 8.3 Restart procedure

After enabling `CRM_STUDIO_ENABLED=true` in `.env.local` and restarting the backend (`just restart`), the `currencies` table is recreated by `scripts/local-ddb-init.py` (it is always in the `_table_defs()` list via STU-001) and starts empty. The seeding step above must be repeated.

## 10. Open Questions / Assumptions

1. **Decimal precision**: Exchange rates are stored and manipulated as Python `Decimal`. The `CurrencyOut` model exposes `exchange_rate_to_usd: float`. This introduces a small precision loss on serialization (Python `float` has ~15 significant digits). If CRM invoicing or quote generation requires exact Decimal arithmetic, the response model should use `str` for the rate field. Assumption: `float` is acceptable for display; all internal arithmetic in `currency_service` uses `Decimal`.

2. **Auto-seeding on first enable**: This spec requires a manual seeding step. An alternative is an `on_startup` hook that seeds USD with rate=1.0 if the table is empty. This would be more operator-friendly but adds startup latency (one DDB scan). Deferred to the implementation team.

3. **Stripe / PayPal integration**: This ticket does NOT wire `currency_service.get_default_currency()` into existing billing charge paths. A future ticket (likely an OFB or STU follow-on) would replace `S.stripe_default_currency` with a call to `get_default_currency()` in payment initiation. This spec explicitly preserves the existing paths unchanged.

4. **Numeric format for `exchange_rate_to_usd` in DDB**: Stored as `Decimal` (type `N`) via `_FloatSafeTable`. Queried back as `Decimal`; converted to `float` only in `CurrencyOut`. Arithmetic in `convert_amount` keeps full `Decimal` precision throughout.

5. **Concurrent default-change races**: Two ROOT admins setting different defaults concurrently can result in a brief inconsistency (two rows with `is_default=True`). A DDB `TransactWriteItems` could prevent this but adds complexity. Given the admin-only, low-frequency nature of this operation, a non-transactional approach is assumed acceptable.

- **STU-009** (`docs/suitecrm/specs/STU-009.md`) — admin search config; uses the same `billing_config`-style cache pattern as STU-010. No direct dependency, but the two services are architectural siblings and should be implemented together.

- **QUO-xxx** (Quote / invoice tickets, INV series) — `convert_amount` is the intended utility for multi-currency quote line items.
- **INV-xxx** (`docs/suitecrm/specs/INV-*.md`) — invoice totals in non-USD currencies will call `convert_amount` and display the symbol from `get_currency(code)["symbol"]`.
- **RPT-xxx** (Reports) — financial summary reports that aggregate across currencies will use `convert_amount` to normalise to the default currency.

### 11.3 Existing platform tickets extended (not duplicated)

- **FIN-018 / GAP-0202** (`app/services/billing_config.py`) — defines the `billing_config` cache pattern that STU-010 mirrors. The existing `default_currency` and `supported_currencies` keys in `billing_config` are NOT replaced; they remain as billing-layer configuration. The new `currencies` table is an additive CRM-layer registry.
- **FIN-013** (`app/services/billing_shared.py:224`) — `new_ledger_entry` / `settle_or_reverse_ledger` are the canonical money-movement primitives. STU-010 does not introduce any ledger entries (no money moves in currency management); these are cited to confirm that no new money-out path is created.
