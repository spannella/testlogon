# FAC-004 — Facility & location service (CRUD + location dimension)

## 1. Summary & Goal

FAC-004 delivers `app/services/facilities.py`, the first service layer of the OFBiz Facility application. It introduces:

1. **Facility CRUD** — create, read, list, update, and archive warehouse/store/dropship facility entities stored in `T.facilities`.
2. **Location CRUD** — create and list per-facility bin/aisle/shelf locations, each stored as a child row on the same DynamoDB partition as its parent facility.
3. **Inventory dimension mapping** — a facility location's `location_id` is the exact string that `inventory._location_sk(location_id)` wraps as `LOC#{location_id}` (`app/services/inventory.py:59`). No translation layer exists; the location string is the addressable unit that `inventory.set_on_hand(...)` and `inventory.adjust(...)` write against.
4. **Default-facility back-compat** — an auto-seeded `"Default Warehouse"` facility with a single location `location_id="warehouse"` is idempotently created on first enabled use so every pre-existing inventory row keyed `(sku, LOC#warehouse)` is attributable to a real facility record.
5. **Audit trail** — every mutation emits an `alerts.audit_event` via a best-effort `_audit()` wrapper, mirroring `app/services/inventory.py:92–98`.
6. **Flag gate** — the entire module is dormant when `S.facility_fulfillment_enabled` is `False`; every public function calls `_require_enabled()` first and raises HTTP 404 when the flag is off.

The existing shop, cart, orders, billing, inventory, reservations, and returns paths are byte-for-byte unchanged when the flag is off. This ticket creates exactly one new file — `app/services/facilities.py` — plus a test file. It does not register any router (that is FAC-005's scope).

## 3. Data Model

FAC-004 reads and writes to `T.facilities`, the single DynamoDB table defined by FAC-002. This section re-states the schema for implementation clarity; the authoritative `TableDef` lives in `scripts/local-ddb-init.py` (added by FAC-002 after the `returns` block at line 2492).

### 3.1 Table: `facilities`

**Primary key**: `facility_id` (S, hash) / `sk` (S, range)

**GSIs**:

| Index | Hash key | Range key | `attr_types` note |
|---|---|---|---|
| `GSI_OWNER` | `owner_sub` (S) | `created_at` (N) | must be `"N"` or queries with integer values raise `ValidationException` |
| `GSI_STATUS` | `status` (S) | `created_at` (N) | same |

All `created_at` values are integer Unix timestamps from `now_ts()` (`app/core/time.now_ts`).

### 3.2 Facility header row (SK = `"META"`)

| Attribute | DDB type | Notes |
|---|---|---|
| `facility_id` | S | PK. `sha256(owner_sub + "\|" + name)[:32]`. Deterministic — enables idempotent create. |
| `sk` | S | Literal `"META"` |
| `owner_sub` | S | GSI_OWNER hash key. `"system"` for auto-seeded default facility. |
| `name` | S | Human label; max 200 chars |
| `facility_type` | S | `warehouse` / `retail` / `virtual` / `drop_ship` |
| `description` | S | Optional; omitted if `None` |
| `address` | S | Optional string (serialised address or JSON blob); omitted if `None` |
| `status` | S | `active` / `archived` — GSI_STATUS hash key |
| `created_at` | N | Immutable after creation; integer Unix timestamp |
| `updated_at` | N | Updated on every mutation |

### 3.3 Location child row (SK = `"LOC#{location_id}"`)

| Attribute | DDB type | Notes |
|---|---|---|
| `facility_id` | S | PK — same as parent |
| `sk` | S | `"LOC#{location_id}"` |
| `location_id` | S | Bare opaque string (e.g. `"bin-a1"`, `"warehouse"`). This is the value passed directly to `inventory._location_sk(location_id)`. |
| `name` | S | Human label; max 200 chars |
| `location_type` | S | `bulk` / `bin` / `aisle` / `shelf` / `staging` / `receiving` / `shipping` |
| `description` | S | Optional |
| `parent_location_id` | S | Optional; for nested bin addresses (aisle → shelf → bin) |
| `status` | S | `active` / `archived` |
| `created_at` | N | Integer Unix timestamp |

**Key design invariant**: the `location_id` attribute on a child row is the exact string consumed by `inventory._location_sk(location_id)` at `app/services/inventory.py:59`. There is no `LOC#` prefix stored — the internal `sk = "LOC#{location_id}"` is only the DynamoDB sort key; `location_id` is a separate denormalised attribute. This matches the pattern in `app/services/inventory.py:135` where `location_id` is stored without the prefix (line 133 is `"sku"`, line 134 is `"location_sk"` with the `LOC#` prefix, line 135 is the bare `"location_id"`).

### 3.4 Access patterns

| Query | Mechanism |
|---|---|
| Get a specific facility | `T.facilities.get_item(Key={"facility_id": fid, "sk": "META"})` |
| Get a specific location | `T.facilities.get_item(Key={"facility_id": fid, "sk": f"LOC#{lid}"})` |
| All rows for a facility (header + locations) | `T.facilities.query(Key={"facility_id": fid})` with `ScanIndexForward=False` |
| Facilities for a user (newest-first) | `GSI_OWNER` query with `Key={"owner_sub": sub}`, `ScanIndexForward=False` |
| Admin facility queue by status | `GSI_STATUS` query with `Key={"status": "active"\|"archived"}`, `ScanIndexForward=False` |

### 4.2 Module-level helpers

```python
def _flag_on() -> bool:
    return bool(getattr(S, "facility_fulfillment_enabled", False))

def _require_enabled() -> None:
    if not _flag_on():
        raise HTTPException(status_code=404, detail="Facility fulfillment is not enabled")

def _audit(event: str, user_sub: str, **fields: Any) -> None:
    try:
        from app.services.alerts import audit_event
        audit_event(event, user_sub or "system", None, **fields)
    except Exception:
        pass

def _to_int(value: Any, default: int = 0) -> int:
    try:
        return default if value is None else int(value)
    except (TypeError, ValueError):
        return default

def _facility_out(item: Dict[str, Any]) -> Dict[str, Any]:
    return {
        "facility_id": item["facility_id"],
        "name": item.get("name", ""),
        "facility_type": item.get("facility_type", "warehouse"),
        "description": item.get("description"),
        "address": item.get("address"),
        "owner_sub": item.get("owner_sub"),
        "status": item.get("status", "active"),
        "created_at": _to_int(item.get("created_at")),
        "updated_at": _to_int(item.get("updated_at")),
    }

def _location_out(item: Dict[str, Any]) -> Dict[str, Any]:
    sk: str = item.get("sk", "")
    # location_id stored directly on item; fall back to stripping LOC# from sk
    loc_id = item.get("location_id") or (sk[4:] if sk.startswith("LOC#") else sk)
    return {
        "facility_id": item["facility_id"],
        "location_id": loc_id,
        "name": item.get("name", ""),
        "location_type": item.get("location_type", "bulk"),
        "description": item.get("description"),
        "parent_location_id": item.get("parent_location_id"),
        "status": item.get("status", "active"),
        "created_at": _to_int(item.get("created_at")),
    }
```

### 4.3 Facility CRUD functions

#### `create_facility`

```python
def create_facility(
    owner_sub: str,
    name: str,
    facility_type: str = "warehouse",
    *,
    description: Optional[str] = None,
    address: Optional[str] = None,
) -> Dict[str, Any]:
```

Behaviour:
1. `_require_enabled()`.
2. Compute `facility_id = hashlib.sha256(f"{owner_sub}|{name}".encode()).hexdigest()[:32]`.
3. Build item dict: `facility_id`, `sk="META"`, `owner_sub`, `name`, `facility_type`, optional `description`/`address` (omitted if `None` to avoid DDB null storage), `status="active"`, `created_at=now_ts()`, `updated_at=now_ts()`.
4. `T.facilities.put_item(Item=item, ConditionExpression="attribute_not_exists(facility_id)")`.
5. On `ConditionalCheckFailedException`: the facility already exists — fetch with `get_facility(facility_id)` and return it (idempotent).
6. `_audit("facility.created", owner_sub, facility_id=facility_id, name=name, facility_type=facility_type)`.
7. Return `_facility_out(item)`.

#### `get_facility`

```python
def get_facility(facility_id: str) -> Optional[Dict[str, Any]]:
```

1. `_require_enabled()`.
2. `resp = T.facilities.get_item(Key={"facility_id": facility_id, "sk": "META"})`.
3. Return `_facility_out(resp["Item"])` or `None` if absent.

#### `list_facilities`

```python
def list_facilities(
    owner_sub: str,
    *,
    status: str = "active",
    cursor: Optional[str] = None,
    limit: int = 50,
) -> Dict[str, Any]:
```

1. `_require_enabled()`.
2. Build `GSI_OWNER` query: `KeyConditionExpression=Key("owner_sub").eq(owner_sub)`, `IndexName="GSI_OWNER"`, `ScanIndexForward=False`, `Limit=limit`, optional `ExclusiveStartKey` decoded from cursor.
3. Optionally filter by `status` using `FilterExpression` (note: FilterExpression does not reduce page size — loop if paginating across a status filter; for this service a single page of `limit` items is sufficient for MVP).
4. Encode `LastEvaluatedKey` via `app.core.cursor.encode_cursor` (following `app/services/fraud_detection.py:373`).
5. Return `{"facilities": [_facility_out(i) for i in resp["Items"] if i.get("sk") == "META"], "cursor": next_cursor}`.

#### `update_facility`

```python
def update_facility(
    facility_id: str,
    *,
    user_sub: str,
    name: Optional[str] = None,
    facility_type: Optional[str] = None,
    description: Optional[str] = None,
    address: Optional[str] = None,
) -> Dict[str, Any]:
```

1. `_require_enabled()`.
2. `item = get_facility(facility_id)` — raises `HTTPException(404)` if not found.
3. If `item["status"] == "archived"`: raise `HTTPException(409, detail="Cannot update an archived facility")`.
4. Build `UpdateExpression` from non-`None` kwargs plus `updated_at=now_ts()`. Only mutate supplied fields.
5. `T.facilities.update_item(Key={"facility_id": facility_id, "sk": "META"}, UpdateExpression=..., ExpressionAttributeValues=...)`.
6. `_audit("facility.updated", user_sub, facility_id=facility_id, updated_fields=list_of_keys)`.
7. Return updated dict by re-fetching or merging in-memory.

#### `archive_facility`

```python
def archive_facility(facility_id: str, *, user_sub: str) -> Dict[str, Any]:
```

1. `_require_enabled()`.
2. `item = get_facility(facility_id)` — 404 if absent.
3. If already `archived`: return `_facility_out(item)` (idempotent no-op).
4. Check open stock: query all `LOC#*` rows for this facility (single partition query filtered on `sk begins_with "LOC#"`), then for each `location_id` call `inventory.get_inventory(sku, location_id)` — but since iterating all SKUs is impractical, the guard is simplified: scan `T.inventory` via `GSI_AVAILABLE` with a filter for any row whose `location_id` matches a location of this facility, or raise 409 if any location of the facility has `available > 0` on ANY SKU. Implementation note: for MVP it is acceptable to skip this guard and document it as an open question (see Section 10). The 409 guard can be added in a follow-up without breaking the API contract.
5. `T.facilities.update_item(Key={...}, UpdateExpression="SET #status = :s, updated_at = :t", ExpressionAttributeNames={"#status": "status"}, ExpressionAttributeValues={":s": "archived", ":t": now_ts()})`.
6. `_audit("facility.archived", user_sub, facility_id=facility_id)`.
7. Return updated `_facility_out(...)`.

### 4.5 Default-facility auto-provisioning

```python
DEFAULT_FACILITY_OWNER = "system"
DEFAULT_FACILITY_NAME = "Default Warehouse"
DEFAULT_LOCATION_ID = "warehouse"  # matches inventory.DEFAULT_LOCATION

def ensure_default_facility() -> Dict[str, Any]:
    """Idempotently create the default warehouse facility and its 'warehouse' location.

    Called once on first enabled request. The facility_id is deterministic:
    sha256("system|Default Warehouse")[:32]. The default location_id is "warehouse",
    matching inventory.DEFAULT_LOCATION so all pre-existing stock rows are attributable.
    """
    _require_enabled()
    facility = create_facility(
        DEFAULT_FACILITY_OWNER,
        DEFAULT_FACILITY_NAME,
        facility_type="warehouse",
        description="Auto-provisioned default facility for pre-existing inventory rows",
    )
    fid = facility["facility_id"]
    # Ensure the "warehouse" location exists under this facility.
    # create_location uses uuid4(), so we use a direct conditional put instead
    # to keep location_id="warehouse" deterministic.
    loc_item = {
        "facility_id": fid,
        "sk": f"LOC#{DEFAULT_LOCATION_ID}",
        "location_id": DEFAULT_LOCATION_ID,
        "name": "Default warehouse floor",
        "location_type": "bulk",
        "status": "active",
        "created_at": now_ts(),
    }
    try:
        T.facilities.put_item(
            Item=loc_item,
            ConditionExpression="attribute_not_exists(sk)",
        )
    except ClientError as exc:
        if exc.response["Error"].get("Code") != "ConditionalCheckFailedException":
            raise
        # Already exists — idempotent no-op
    return facility
```

`ensure_default_facility()` is **not** called automatically on every request. It is called once during the first `create_facility` or `list_facilities` call, or explicitly from an admin endpoint (FAC-005). Because both `create_facility` and `ensure_default_facility` use `attribute_not_exists` conditional puts, concurrent calls are safe.

## 5. Detailed Behavior & Edge Cases

### 5.1 Idempotent facility create

Two calls with the same `owner_sub` + `name` compute the same `facility_id` and both attempt `put_item` with `ConditionExpression="attribute_not_exists(facility_id)"`. The second call receives `ConditionalCheckFailedException`. The service catches this, calls `get_facility(facility_id)`, and returns the existing record. The HTTP status is 200 (not 201) on replay — this is consistent with the OFBiz idempotency contract and the `commerce_order_service.py:67` precedent.

### 5.2 Location ID and inventory key relationship

The `location_id` returned by `create_location` (a `uuid4().hex` string) is passed verbatim to `inventory.set_on_hand(sku, qty, location_id=location_id)` and `inventory.adjust(sku, delta, reason, location_id=location_id)`. The inventory service wraps it internally with `_location_sk(location_id)` → `LOC#{location_id}` as the DDB sort key (`app/services/inventory.py:59,134`). The facilities service does not call `_location_sk` — that is an internal inventory helper.

Verification path from acceptance criteria: after `create_location(fid, "bin-a1", ...)` returns `{"location_id": "3f9ab..."}`, calling `inventory.set_on_hand("SKU1", 100, location_id="3f9ab...")` followed by `inventory.get_inventory("SKU1", "3f9ab...")` returns `{"on_hand": 100, "location_id": "3f9ab..."}`.

### 5.3 Default location backward compatibility

Existing inventory rows were written with `location_sk = "LOC#warehouse"` by the `_persist` helper at `app/services/inventory.py:134` via `_location_sk(DEFAULT_LOCATION)`. The facilities service's auto-seeded default facility has a location row with `location_id = "warehouse"` and `sk = "LOC#warehouse"`. No existing inventory rows need to change. `DEFAULT_LOCATION` at `app/services/inventory.py:43` remains `"warehouse"` and all callers that omit `location_id` continue to work identically.

### 5.4 Archived facility guard on location create

If a caller attempts `create_location` against a facility that has `status == "archived"`, the service raises `HTTPException(status_code=409, detail="Cannot add a location to an archived facility")`. This prevents phantom locations being added after archival.

### 5.5 Archived location guard on inventory

The facilities service does not gate `inventory.adjust` calls based on location status. It is the caller's responsibility to check `get_location(fid, lid)["status"]` before writing stock. This keeps the inventory and facilities layers decoupled.

### 5.6 Name uniqueness

`facility_id` is deterministic on `(owner_sub, name)`, so two facilities with the same name under the same `owner_sub` resolve to the same ID. There is no separate uniqueness constraint enforced at the DDB level beyond the conditional put. If an operator wants two facilities with the same name (e.g. "Warehouse A" and "Warehouse A"), they must use different names or different owner subs. This is acceptable for MVP.

### 5.7 `list_facilities` pagination and FilterExpression caveat

DynamoDB applies `FilterExpression` **after** reading up to the page `Limit`. A `Limit=50` query on `GSI_OWNER` may return fewer than 50 `active` facilities if the partition also contains `archived` ones. For MVP, the caller receives whatever fits in the first page. A full paginating loop is deferred to a follow-up once the data volume justifies it (the CLAUDE.md "DDB FilterExpression" gotcha applies).

### 5.8 Concurrent archive + create_location race

If `archive_facility` and `create_location` race, the location create check reads `get_facility` (which returns the current `status`) before the archive write completes. The worst outcome is a location created on a facility that is being archived simultaneously. This is a low-frequency, low-severity race; the MVP does not add a distributed lock. A `ConditionExpression="attribute_not_exists(sk) AND #status = :active"` on the location put would eliminate it at the cost of complexity; deferred to a follow-up.

### 5.9 `_to_int` and DynamoDB `Decimal`

DynamoDB returns numeric attributes as `decimal.Decimal`. The `_to_int` helper at line 9 of the module (`int(value)`) handles this correctly; `int(Decimal("1697000000"))` is `1697000000`. This matches `app/services/inventory.py:67–73`.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### SECOPS-007 parity

`app/services/facilities.py` contains zero `if S.dev_mode` branches. All DDB access uses `T.facilities` regardless of environment. moto intercepts boto3 in dev; real DynamoDB in prod. The `_audit()` wrapper's lazy import of `app.services.alerts.audit_event` works identically in both.

### Idempotency contracts

| Operation | Idempotency mechanism |
|---|---|
| `create_facility` | `sha256(owner_sub\|name)[:32]` deterministic ID + `attribute_not_exists(facility_id)` conditional put. Second call returns existing record. |
| `create_location` | Non-deterministic `uuid4().hex`. Not idempotent by design — two calls create two distinct locations. Callers must not retry on network timeout without checking existence first. |
| `archive_facility` | Already-archived check is a read-before-write returning early; safe to replay. |
| `update_facility` | No idempotency key; `update_item` is last-write-wins on the updated fields. |
| `ensure_default_facility` | `create_facility` (idempotent) + `attribute_not_exists(sk)` conditional put for the warehouse location. |

### Security

- No public (unauthenticated) facility endpoint is defined in this ticket. The router (FAC-005) applies `require_admin_or_root_csrf` (from `app/auth/policy.py:100`) to all mutation operations and `require_ui_session` (imported from `app/services/sessions.py:330`, same import path used by `app/routers/inventory.py:27`) to reads, mirroring `app/routers/inventory.py:45–81`.
- `facility_id` is derived from `sha256(owner_sub|name)`. An attacker who can predict another user's `owner_sub` could compute their `facility_id` — this is not a vulnerability because facility IDs are not secrets; they are referenced in transfer and receipt records with their own auth guards.
- `location_id` is a `uuid4().hex` — not guessable, though not a security boundary.
- Archived facilities are not deleted from DDB; their data remains available for audit queries.

### Billing impact

FAC-004 writes no ledger entries. Inventory write-offs for damaged goods are out of scope for this ticket (they belong to the receiving workflow in FAC-007). When such write-offs are implemented, they will use `billing_shared.new_ledger_entry(entry_type="inventory_writeoff", ...)` at `app/services/billing_shared.py:224` — not a new billing path.

## 10. Open Questions / Assumptions

1. **Assumption: FAC-002 has shipped** — `S.facility_fulfillment_enabled`, `S.facilities_table_name`, `T.facilities`, and the `facilities` `TableDef` in `scripts/local-ddb-init.py` all exist before FAC-004 lands. If FAC-002 is blocked, FAC-004 cannot compile.

2. **Assumption: FAC-003 has shipped** — `FacilityIn`, `FacilityOut`, `FacilityLocationIn`, and `FacilityLocationOut` are importable from `app/models.py`. FAC-004's service layer returns plain `dict` objects, so the models are not strictly required at the service level — but the router (FAC-005) needs them, and the test file may optionally import them for validation.

3. **Open question: archive-with-stock guard** — Should `archive_facility` raise 409 if any location of the facility has `available > 0` across any SKU? The FAC-001 spec assumes it should (preventing orphaned inventory). However, scanning all inventory rows filtered by a set of `location_id` values is expensive without a dedicated GSI on the inventory table. For MVP, the guard is omitted and the 409 is documented as a follow-up. Reviewer should confirm whether the guard is required for the initial ship.

4. **Open question: `list_facilities` admin vs owner scope** — The current design filters by `owner_sub` (GSI_OWNER). An admin may need to list ALL facilities across all owners. A separate `list_all_facilities(status="active")` function using `GSI_STATUS` is implied by the FAC-002 table design. FAC-005's router should expose this as a separate admin-only endpoint; FAC-004 should include a `list_facilities_by_status(status)` function to support it.

5. **Assumption: `location_id` non-determinism is correct** — FAC-001 spec section 4.2 states `create_location` uses `uuid4().hex` because "a facility may have many locations with the same label." This is intentional and confirmed. Callers who need to avoid duplicate locations with the same name must call `list_locations` before creating.

6. **Open question: `ensure_default_facility` call site** — Who calls `ensure_default_facility()`? Three options: (a) explicit admin API call via FAC-005, (b) called lazily from `list_facilities` when `owner_sub == "system"`, (c) called from the `on_startup` hook in `app/main.py` when the flag is enabled. Option (a) is the safest for MVP (no implicit side-effects at startup). The spec assumes option (a); reviewer should confirm.

7. **Assumption: `describe` vs `address` field type** — FAC-003 defines `address: Optional[str]` (a plain string) on `FacilityOut`. FAC-002 defines it as type `M` (DDB Map). The service layer stores and retrieves it as a JSON string to avoid DDB Map serialisation complexity. This is an assumption that may need revision if the address is later queried by sub-field.
