# SHP-011 — Shipments + ship-groups router

## 1. Summary & Goal

SHP-011 creates `app/routers/shipments.py`, the HTTP interface over the shipment service
assembled by SHP-008 (create + read), SHP-009 (package management), and SHP-010 (lifecycle
state machine). Three distinct principals interact with this router:

1. **Admins/root** (`require_admin_or_root` / `require_admin_or_root_csrf`) — can create
   shipments for any order, add packages, assign items to packages, and drive lifecycle
   transitions.
2. **Authenticated buyers** (`require_ui_session`) — can read shipments only for orders
   they own; foreign-order requests return 404 (not 403) to prevent enumeration.
3. **Unauthenticated / flag-off callers** — every handler returns HTTP 503 when
   `S.shipping_enabled` is `False`.

The router is registered in `app/main.py` adjacent to the existing carrier routers
(`carrier_tracking_mock_router` at line 680, `carrier_tracking_poller_router` at line 681
— `app/main.py:679–681`). [VERIFIED: `main.py:679–681`] No existing route, service, billing path, or DDB table is
modified; with the flag off the new file is effectively dead code.

## 2. Context & Current State

### 2.1 Service layer provided by SHP-008 / SHP-009 / SHP-010

`app/services/shipments.py` (delivered by SHP-008, extended by SHP-009 and SHP-010)
exposes the following functions SHP-011 delegates to:

**SHP-008 (create + read):**
- `create_shipment(*, user_id, order_id, ship_group_seq, carrier_code, method_code, ship_to_address, line_items, ship_method_id=None, purchase_txn_id=None) -> dict` — deterministic `sha256("shipment:{order_id}:{ship_group_seq}")[:32]` id (`docs/ofbiz/specs/SHP-008.md:63–67`), over-ship guard, audit event.
- `get_shipment(shipment_id) -> Optional[dict]` — returns full `ShipmentOut` including items and packages.
- `list_shipments_for_order(order_id) -> List[dict]` — queries `GSI_ORDER` (`order_id` / `created_at`) on `T.shipments`.
- `list_shipments_by_status(status, limit=100) -> List[dict]` — queries `GSI_STATUS` (`status` / `created_at`), header-only rows.

**SHP-009 (package management):**
- `add_package(shipment_id, package_in: ShipmentPackageIn) -> dict`
- `assign_item_to_package(shipment_id, package_seq, content_in: AssignItemToPackageIn) -> dict`
- `get_packing_status(shipment_id) -> dict` — returns `PackingStatusOut` with `pack_complete` flag.

**SHP-010 (state machine):**
- `transition_shipment(shipment_id, target_status, *, tracking_number=None, carrier=None, exception_reason=None, cancel_reason=None, note=None, actor_user_id: str) -> dict` — version-guarded optimistic-concurrency transition (`docs/ofbiz/specs/SHP-010.md:242–253`), rejects illegal transitions with 409, auto-detects carrier via `app/services/carrier_tracking.detect_carrier` (`carrier_tracking.py:46`). Note: the `carrier` kwarg is a free-form string (e.g. `"ups"`), not `carrier_code`; `actor_user_id` is required (no default). Convenience wrappers `advance_to_packed`, `advance_to_shipped`, etc. are also defined (`docs/ofbiz/specs/SHP-010.md:333–358`).

All service functions call `_require_enabled()` as their first line, so the router's own
flag gate (below) is belt-and-suspenders, but the pattern mirrors SHP-005
(`docs/ofbiz/specs/SHP-005.md:57–64`).

Buyer endpoints are under a distinct prefix `/ui/shop/my/orders/{order_id}/shipments`

#### `GET /ui/shop/my/orders/{order_id}/shipments` — buyer order shipments

  (ownership-through-obscurity: mirrors `purchase_history.py:384–387` and the pattern
  documented in `docs/ofbiz/specs/SHP-008.md:629–635`).
- Calls `_svc.list_shipments_for_order(order_id)` and returns results.

#### `GET /ui/shop/my/orders/{order_id}/shipments/{shipment_id}` — buyer shipment detail

```python
@buyer_router.get("/orders/{order_id}/shipments/{shipment_id}",
                  response_model=ShipmentOut)
async def buyer_get_shipment(
    order_id: str,
    shipment_id: str,
    ctx=Depends(require_ui_session),

```

- Calls `_ensure_enabled()`.
- Performs the same order-ownership check (fetch order, compare `user_id`); if mismatch → 404.
- Calls `_svc.get_shipment(shipment_id)`. If `None` **or** `shipment["order_id"] != order_id` → 404 "Shipment not found".

  a buyer from reading a different order's shipment by guessing `shipment_id`.
- Returns full `ShipmentOut` including tracking URL (computed by service).

## 5. Detailed Behavior & Edge Cases

### 5.1 Admin create bypasses ownership check

`create_shipment` in SHP-008 checks `order["user_id"] == user_id` and returns 404 on
mismatch. The admin router bypasses this by passing `user_id=order["user_id"]` (fetched
from `T.orders`) rather than the admin's own sub. This requires the router to perform a
pre-fetch of the order before calling the service. The fetch is a `get_item` on `T.orders`
keyed by `order_id`; if the order does not exist the router returns 404 before calling
the service.

Concretely in `admin_create_shipment`:
```python
order = T.orders.get_item(Key={"order_id": body.order_id}).get("Item")
if not order:
    raise HTTPException(404, "Order not found")
order_user_id = order["user_id"]
result = _svc.create_shipment(user_id=order_user_id, ...)
```

### 5.2 409 from state machine propagates transparently

`transition_shipment` (SHP-010) raises `HTTPException(409, ...)` for illegal
transitions and version-guard failures (same pattern as `purchase_history.py:566–579`
[VERIFIED: `purchase_history.py:562–579`]).
The router does not catch this; FastAPI propagates it as a 409 to the client. The body
shape is preserved from the service (`{"code": "illegal_transition", "from": ..., "to": ...}`
or `{"code": "conflict_version"}`).

### 5.3 Buyer cannot call advance or package management

Admin endpoints (`/ui/shop/shipments/…`) are gated by `require_admin_or_root` and
`require_admin_or_root_csrf`. A buyer attempting POST to `/ui/shop/shipments/{id}/advance`
receives 403. There is no shared admin/buyer route for mutations.

### 5.4 Buyer double-guard: order ownership + shipment/order linkage

The buyer `GET .../shipments/{shipment_id}` checks:
1. Order exists and `order["user_id"] == ctx["user_sub"]` (→ 404 if not).
2. Shipment exists (→ 404 if `get_shipment` returns `None`).
3. `shipment["order_id"] == order_id` from path (→ 404 if mismatch).

Check 3 prevents a crafted URL from leaking a shipment belonging to a different order.

### 5.5 Flag-off returns 503 on every path

With `S.shipping_enabled = False`, every handler raises 503 before touching any DDB
table or calling any service. Pre-existing shop/cart/orders/billing/tracking paths are
byte-for-byte unchanged (they live in separate router files).

### 5.6 Tracking URL on buyer responses

`_svc.get_shipment` calls `_shipment_out` which computes `tracking_url` via
`build_tracking_url(carrier_code, tracking_number)` at read time. Buyers see the live
tracking URL without any additional storage on the server side. This is identical to the
pattern in `purchase_history.py:389–394`.

### 5.7 `list_shipments_by_status` returns header-only rows

`_svc.list_shipments_by_status` returns `ShipmentOut`s with empty `items` and `packages`
lists (per SHP-008 §4.9, `docs/ofbiz/specs/SHP-008.md:509–532`). The admin queue UX is
expected to call `GET /ui/shop/shipments/{shipment_id}` for full detail. This avoids
O(N×M) DDB reads on the status list endpoint.

### 5.8 CSRF for cookie-auth admin mutations

Browser-based admin clients (cookie `ui_session` + `ui_csrf` cookies) must send
`x-csrf-token: <csrf_token>` on all POST/PATCH/DELETE requests. Bearer-token API clients
(E2E tests using the global `request` fixture, not `page.request`) skip CSRF. The
`require_admin_or_root_csrf` dependency enforces this via `enforce_cookie_csrf(request)`
at `policy.py:71–97`.

### 5.9 `target_status == "shipped"` requires tracking number

`ShipmentStatusTransitionIn` accepts an optional `tracking_number`. The service's
`transition_shipment` (SHP-010) validates at the service layer that `tracking_number`
is non-empty when `target_status == "shipped"`, returning 422 if absent. The router
passes through `body.tracking_number` without duplicating this check (single
responsibility).

### 5.10 `package_seq` URL parameter format

Package sequence IDs are zero-padded 5-digit strings (`"00001"`, `"00002"`) as defined
in SHP-008 §3.4 and SHP-009 §2.2. The router accepts the raw path segment and passes it
to `assign_item_to_package` without re-formatting; the service validates the format.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 Zero `dev_mode` branches

The router contains no `if S.dev_mode:` branch. All DDB access is performed the same way
in dev (moto-backed `T.shipments`) and prod (real DynamoDB). The only environment
difference is the DDB endpoint URL (`S.ddb_endpoint_url`), which is transparent to the
application code.

### 7.2 Idempotency

- **Create shipment**: deterministic `shipment_id = sha256("shipment:{order_id}:{ship_group_seq}")[:32]` means retrying the same POST is idempotent (`docs/ofbiz/specs/SHP-008.md:540–550`). DDB `put_item` without a condition expression overwrites with identical content.
- **Add package**: intentionally non-idempotent (each call appends a new package). The caller controls how many packages exist.
- **Assign item**: idempotent when the same `(shipment_id, package_seq, item_id, quantity)` is submitted twice (no double-write, per SHP-009 §4.2 step 8).
- **Advance status**: the version guard (`ConditionExpression="version = :v"`) serializes concurrent transitions; the loser receives 409 and must re-fetch before retrying.

### 7.3 Security

- **Ownership enforcement**: buyer paths check `order["user_id"] == ctx["user_sub"]`; mismatches return 404, not 403 (enumeration protection).
- **Admin isolation**: admin paths use `require_admin_or_root[_csrf]`; a USER-role caller receives 403 before any service call.
- **CSRF**: all admin cookie-auth POST/PATCH/DELETE paths use `require_admin_or_root_csrf`. Bearer-token clients are unaffected.
- **Input validation**: `ShipmentStatusTransitionIn.target_status` is pattern-constrained at the Pydantic layer; unknown statuses are rejected with 422 before reaching the service.

## 10. Open Questions / Assumptions

**OQ-1 (SHP-010 function name — RESOLVED)**: The SHP-010 spec defines the function as
`transition_shipment` (not `advance_shipment_status`). The router calls
`_svc.transition_shipment(shipment_id, body.target_status, carrier=body.carrier_code,
tracking_number=body.tracking_number, note=body.note, actor_user_id=user.sub)`.
See `docs/ofbiz/specs/SHP-010.md:242–253` and §4.3 above.

**OQ-2 (Admin create pre-fetch of order)**: This spec describes the router pre-fetching
`T.orders` to obtain `order_user_id` before calling the service. If SHP-010 changes
`create_shipment` to accept an `admin=True` flag that skips the ownership check
internally, the router can drop the pre-fetch and pass `user_id=""` to a revised
signature. Either approach is correct; the pre-fetch is the safer bet given SHP-008's
current service signature.

**OQ-3 (Route prefix collision for admin order-shipments list)**: The proposed path
`/ui/shop/shipments/orders/{order_id}/shipments` uses the literal segment `orders`
inside the `shipments` router. This is safe as long as `orders` is declared before
`{shipment_id}` in the router. The implementation must verify declaration order and
add a comment documenting why (same guard as `kyc_cases.py`).

**OQ-4 (Buyer router prefix)**: `/ui/shop/my/orders/{order_id}/shipments` is chosen to
avoid collision with the admin `/{shipment_id}` route. If a separate `buyer_router` is
undesirable (e.g. test harness complication), an alternative is to add a query param
`?buyer=1` gated on role; however, the two-router approach is cleaner and mirrors the
pattern in `app/routers/calendar.py` (public_router / router split).

**OQ-5 (Packing status before `packed` transition)**: SHP-010 may or may not enforce
`pack_complete == True` before permitting the `created → packed` transition. This spec
assumes it does (per SHP-009's description of `PackingStatusOut.pack_complete` as "the
gate that SHP-010's state machine checks"). If SHP-010 does not enforce this the packing
guard becomes advisory.

**OQ-6 (Pagination on `list_shipments_for_order`)**: The SHP-008 service scans all
shipments for an order without pagination; a single order is unlikely to have more than
a handful of ship groups. If large-order support requires pagination later, a cursor
parameter (`app/core/cursor.py`) can be added without breaking existing callers.
