# POS-004 — Register & session service — open/close with cash float

## 1. Summary & Goal

POS-004 implements `app/services/pos_register.py`, the core register-session service
for Milestone 2 of the POS channel. It delivers four public functions —
`create_register`, `open_session`, `get_open_session`, `close_session` — along with
the DDB access layer for the `pos` table (introduced by POS-003) and the audit
events that bookend every till shift.

A "register session" (also called a *till*) represents one cashier's working shift at
a physical terminal. Opening a session records the opening cash float; closing
computes the expected cash balance from that float plus recorded cash tenders, compares
it to the physically counted amount, and records the over/short variance. No money
actually moves during these transitions — money only moves during POS-006 (cash
tender) and POS-007 (card/wallet tender); this ticket only models the till wrapper
that those tenders will attach to.

The entire module ships behind the default-off `S.pos_enabled` flag introduced by
POS-003 (env `POS_ENABLED`). Every endpoint returns 404 when the flag is off, and
zero existing bytes in the cart/order/billing stack are modified by this ticket.

## 3. Data Model

POS-004 reads and writes the `pos` single-table defined by POS-003. This section
records the rows this ticket touches; the GSI definitions are owned by POS-003 and
reproduced here for cross-reference.

### 3.1 Register row

```
PK  pos_pk  = "REGISTER#{register_id}"
SK  pos_sk  = "META"
```

| Attribute | DDB type | Notes |
|---|---|---|
| `register_id` | S | `"reg_" + uuid4().hex[:12]` |
| `label` | S | 1–128 chars |
| `location_id` | S | store/location ref |
| `default_currency` | S | ISO-4217, default `"USD"` |
| `created_at` | N | `now_ts()` |
| `updated_at` | N | `now_ts()` |
| `created_by` | S | `user_sub` of creator |

Written by `create_register`; read by `open_session` to validate the register exists.
No GSI on this row (registers are looked up by primary key).

### 3.2 Session row

```
PK  pos_pk  = "SESSION#{session_id}"
SK  pos_sk  = "META"
```

| Attribute | DDB type | Notes |
|---|---|---|
| `session_id` | S | `"sess_" + sha256(idempotency_key)[:12]` or `"sess_" + uuid4().hex[:12]` |
| `register_id` | S | FK to register row |
| `cashier_sub` | S | `user_sub` of authenticating cashier |
| `status` | S | `"open"` or `"closed"` |
| `opening_float_cents` | N | Cash in drawer at open |
| `closing_float_cents` | N | Float confirmed at close (written at close) |
| `expected_cash_cents` | N | Computed at close (float + cash-in — change-out) |
| `counted_cash_cents` | N | Physically counted at close |
| `over_short_cents` | N | `counted − expected` (signed; positive = over) |
| `opened_at` | N | `now_ts()` — **sort key for GSI_REGISTER_OPEN and GSI_CASHIER** |
| `closed_at` | N | `now_ts()` at close (null when open) |
| `cash_in_cents` | N | Running sum of cash tender amounts (updated by POS-006) |
| `change_out_cents` | N | Running sum of change given back (updated by POS-006) |
| `idempotency_key` | S | Caller-supplied; enables replay detection |
| `open_sentinel_pk` | S | `"OPEN_SENTINEL#REGISTER#{register_id}"` — written at open, deleted at close |
| `open_sentinel_sk` | S | `"OPEN"` |

**GSI_REGISTER_OPEN**: `index_name="GSI_REGISTER_OPEN"`, partition key `register_id`,
sort key `opened_at` (N). Written when status is `open`; the open-sentinel conditional
put (Section 5.2) prevents duplicates without requiring a GSI query for the constraint
check.

**GSI_CASHIER**: `index_name="GSI_CASHIER"`, partition key `cashier_sub`, sort key
`opened_at` (N). Allows `list_sessions_for_cashier(cashier_sub)`.

Both numeric sort keys must appear in `attr_types` in the `scripts/local-ddb-init.py`
`TableDef` for `pos` (per CLAUDE.md DynamoDB gotcha):
`attr_types={"opened_at": "N"}`.

### 3.3 Open-session sentinel row

```
PK  pos_pk  = "OPEN_SENTINEL#REGISTER#{register_id}"
SK  pos_sk  = "OPEN"
```

| Attribute | DDB type | Notes |
|---|---|---|
| `register_id` | S | Denormalised |
| `session_id` | S | FK to the open session |
| `opened_at` | N | `now_ts()` |

This single-item sentinel row is the atomicity primitive for the one-open-session-per-
register invariant. `open_session` writes it with
`ConditionExpression="attribute_not_exists(pos_pk)"`. `close_session` deletes it
(unconditional). On a double-open attempt, the `ConditionalCheckFailedException` is
caught and re-raised as `HTTPException(409)`.

Using a sentinel row rather than a GSI query avoids a non-atomic read-then-write race.

## 4. API / Service Design

### 4.1 Service layer — `app/services/pos_register.py`

```python
from __future__ import annotations

import hashlib
import uuid
from typing import Any, Dict, Optional

from botocore.exceptions import ClientError
from fastapi import HTTPException

from app.core.settings import S
from app.core.tables import T
from app.core.time import now_ts


# ── flag guard ────────────────────────────────────────────────────────────────

def _flag_on() -> bool:
    return bool(getattr(S, "pos_enabled", False))

def _require_enabled() -> None:
    if not _flag_on():
        raise HTTPException(status_code=404, detail="POS is not enabled")


# ── audit helper ──────────────────────────────────────────────────────────────

def _audit(event: str, user_sub: str, **fields: Any) -> None:
    """Fire-and-forget audit event; never raises."""
    try:
        from app.services.alerts import audit_event
        audit_event(event, user_sub or "system", None, **fields)
    except Exception:
        pass


# ── internal helpers ──────────────────────────────────────────────────────────

def _register_pk(register_id: str) -> Dict[str, str]:
    return {"pos_pk": f"REGISTER#{register_id}", "pos_sk": "META"}

def _session_pk(session_id: str) -> Dict[str, str]:
    return {"pos_pk": f"SESSION#{session_id}", "pos_sk": "META"}

def _sentinel_pk(register_id: str) -> Dict[str, str]:
    return {"pos_pk": f"OPEN_SENTINEL#REGISTER#{register_id}", "pos_sk": "OPEN"}

def _session_id_from_key(idempotency_key: Optional[str]) -> str:
    if idempotency_key:
        return "sess_" + hashlib.sha256(idempotency_key.encode()).hexdigest()[:12]
    return "sess_" + uuid.uuid4().hex[:12]

def _to_int(v: Any, default: int = 0) -> int:
    try:
        return int(v) if v is not None else default
    except (TypeError, ValueError):
        return default

def _session_out(item: Dict[str, Any]) -> Dict[str, Any]:
    """Projection to RegisterSessionOut-compatible dict."""
    return {
        "session_id":          item.get("session_id"),
        "register_id":         item.get("register_id"),
        "cashier_sub":         item.get("cashier_sub"),
        "status":              item.get("status"),
        "opening_float_cents": _to_int(item.get("opening_float_cents")),
        "closing_float_cents": item.get("closing_float_cents"),   # None until close
        "expected_cash_cents": item.get("expected_cash_cents"),   # None until close
        "counted_cash_cents":  item.get("counted_cash_cents"),    # None until close
        "over_short_cents":    item.get("over_short_cents"),      # None until close
        "opened_at":           _to_int(item.get("opened_at")),
        "closed_at":           item.get("closed_at"),             # None until close
    }


# ── public API ─────────────────────────────────────────────────────────────────

def create_register(
    *,
    user_sub: str,
    label: str,
    location_id: str,
    default_currency: str = "USD",
) -> Dict[str, Any]:
    """Create a new register (terminal) record.  Idempotency: registers are
    unique by label+location; duplicate label+location → 409."""
    _require_enabled()
    register_id = "reg_" + uuid.uuid4().hex[:12]
    now = now_ts()
    item = {
        "pos_pk": f"REGISTER#{register_id}",
        "pos_sk": "META",
        "register_id": register_id,
        "label": label,
        "location_id": location_id,
        "default_currency": default_currency.upper(),
        "created_at": now,
        "updated_at": now,
        "created_by": user_sub,
    }
    T.pos.put_item(Item=item)
    _audit("pos_register_created", user_sub,
           register_id=register_id, label=label, location_id=location_id)
    return {
        "register_id": register_id,
        "label": label,
        "location_id": location_id,
        "default_currency": default_currency.upper(),
        "created_at": now,
        "updated_at": now,
        "created_by": user_sub,
    }


def open_session(
    *,
    cashier_sub: str,
    register_id: str,
    opening_float_cents: int,
    idempotency_key: Optional[str] = None,
) -> Dict[str, Any]:
    """Open a register session (till) for cashier_sub.

    Invariant: at most one OPEN session per register.  Enforced by a
    conditional put on the sentinel row; concurrent second opener receives 409.
    """
    _require_enabled()
    # Validate register exists.
    reg_resp = T.pos.get_item(Key=_register_pk(register_id))
    if not reg_resp.get("Item"):
        raise HTTPException(status_code=404, detail="Register not found")

    session_id = _session_id_from_key(idempotency_key)
    now = now_ts()

    # Idempotency: if this session_id already exists (replay), return it.
    existing = T.pos.get_item(Key=_session_pk(session_id)).get("Item")
    if existing:
        return _session_out(existing)

    # Enforce one-open-per-register via sentinel conditional put.
    sentinel = {
        "pos_pk": f"OPEN_SENTINEL#REGISTER#{register_id}",
        "pos_sk": "OPEN",
        "register_id": register_id,
        "session_id": session_id,
        "opened_at": now,
    }
    try:
        T.pos.put_item(
            Item=sentinel,
            ConditionExpression="attribute_not_exists(pos_pk)",
        )
    except ClientError as exc:
        if exc.response["Error"].get("Code") == "ConditionalCheckFailedException":
            raise HTTPException(
                status_code=409,
                detail="Register already has an open session",
            ) from exc
        raise

    # Write session row.
    session_item = {
        "pos_pk": f"SESSION#{session_id}",
        "pos_sk": "META",
        "session_id": session_id,
        "register_id": register_id,
        "cashier_sub": cashier_sub,
        "status": "open",
        "opening_float_cents": opening_float_cents,
        "cash_in_cents": 0,       # incremented by POS-006 on each cash tender
        "change_out_cents": 0,    # incremented by POS-006 on each change disbursement
        "opened_at": now,
        "idempotency_key": idempotency_key or "",
    }
    if idempotency_key:
        session_item["idempotency_key"] = idempotency_key
    T.pos.put_item(Item=session_item)

    _audit(
        "pos_session_opened",
        cashier_sub,
        session_id=session_id,
        register_id=register_id,
        opening_float_cents=opening_float_cents,
    )
    return _session_out(session_item)


def get_open_session(register_id: str) -> Optional[Dict[str, Any]]:
    """Return the open session for register_id, or None if no session is open."""
    _require_enabled()
    sentinel = T.pos.get_item(Key=_sentinel_pk(register_id)).get("Item")
    if not sentinel:
        return None
    session_id = sentinel.get("session_id")
    if not session_id:
        return None
    item = T.pos.get_item(Key=_session_pk(session_id)).get("Item")
    if not item or item.get("status") != "open":
        return None
    return _session_out(item)


def get_session(session_id: str) -> Optional[Dict[str, Any]]:
    """Return any session by ID (open or closed)."""
    _require_enabled()
    item = T.pos.get_item(Key=_session_pk(session_id)).get("Item")
    return _session_out(item) if item else None


def close_session(
    *,
    session_id: str,
    counted_cash_cents: int,
    actor_sub: str,
) -> Dict[str, Any]:
    """Close a register session.  Computes expected_cash and over_short.

    expected_cash_cents = opening_float_cents + cash_in_cents − change_out_cents
    over_short_cents    = counted_cash_cents − expected_cash_cents   (signed)

    Double-close is rejected with 409 (status already 'closed').
    """
    _require_enabled()
    item = T.pos.get_item(Key=_session_pk(session_id)).get("Item")
    if not item:
        raise HTTPException(status_code=404, detail="Session not found")

    status = item.get("status")
    if status == "closed":
        raise HTTPException(status_code=409, detail="Session is already closed")
    if status != "open":
        raise HTTPException(status_code=409, detail=f"Session status is '{status}'; cannot close")

    # Ownership: only the cashier who opened the session (or an admin) may close it.
    # The router enforces this; the service exposes actor_sub for audit.
    register_id = item.get("register_id", "")
    opening_float = _to_int(item.get("opening_float_cents"))
    cash_in       = _to_int(item.get("cash_in_cents"))
    change_out    = _to_int(item.get("change_out_cents"))

    expected_cash = opening_float + cash_in - change_out
    over_short    = counted_cash_cents - expected_cash
    now           = now_ts()

    # Atomic close: conditional update guards against concurrent close racing.
    try:
        T.pos.update_item(
            Key=_session_pk(session_id),
            UpdateExpression=(
                "SET #status = :closed, "
                "closing_float_cents = :counted, "
                "expected_cash_cents = :expected, "
                "counted_cash_cents  = :counted, "
                "over_short_cents    = :os, "
                "closed_at           = :now"
            ),
            ExpressionAttributeNames={"#status": "status"},
            ExpressionAttributeValues={
                ":closed":   "closed",
                ":counted":  counted_cash_cents,
                ":expected": expected_cash,
                ":os":       over_short,
                ":now":      now,
                ":open":     "open",
            },
            ConditionExpression="#status = :open",
        )
    except ClientError as exc:
        if exc.response["Error"].get("Code") == "ConditionalCheckFailedException":
            raise HTTPException(status_code=409, detail="Session is already closed") from exc
        raise

    # Remove the open sentinel so the register can accept a new session.
    T.pos.delete_item(Key=_sentinel_pk(register_id))

    _audit(
        "pos_session_closed",
        actor_sub,
        session_id=session_id,
        register_id=register_id,
        opening_float_cents=opening_float,
        cash_in_cents=cash_in,
        change_out_cents=change_out,
        expected_cash_cents=expected_cash,
        counted_cash_cents=counted_cash_cents,
        over_short_cents=over_short,
    )

    updated = T.pos.get_item(Key=_session_pk(session_id)).get("Item", item)
    return _session_out(updated)
```

## 5. Detailed Behavior & Edge Cases

### 5.1 `create_register`

- Validates `label` non-empty and `location_id` non-empty (Pydantic model enforces
  `min_length=1`).
- `register_id` is generated server-side; not supplied by caller.
- No uniqueness constraint on `label+location_id` at the DDB layer (DynamoDB has no
  secondary unique index). Callers who need label uniqueness must query first.
  This is acceptable at this scale; the constraint is out of scope for POS-004.
- Returns `RegisterConfig`-shaped dict.

### 5.2 One-open-session-per-register invariant

The invariant is implemented by a conditional `put_item` on the sentinel row
(`pos_pk = "OPEN_SENTINEL#REGISTER#{register_id}"`, `pos_sk = "OPEN"`) with
`ConditionExpression="attribute_not_exists(pos_pk)"`. DynamoDB evaluates the
condition atomically; the first opener wins, the second receives
`ConditionalCheckFailedException` → 409.

The sentinel row is deleted atomically during `close_session` (unconditional
`delete_item`). Even if the delete fails (e.g. network timeout after the session
`update_item` succeeds), the session row's `status = "closed"` means
`get_open_session` returns `None` for this session while `get_open_session` will show
the stale sentinel pointing to a closed session. A reconciliation path can be added
in the future; for now the conditional on the sentinel write with `attribute_not_exists`
means the stale row does not block a new open (the new `put_item` would overwrite the
stale sentinel since its `pos_pk` already exists — this must be handled: the sentinel
delete must always be retried if the session close succeeded, see Section 10 for the
open question).

### 5.3 `open_session` — idempotency

When `idempotency_key` is provided, `session_id = "sess_" + sha256(idempotency_key)[:12]`.
If the session already exists (same `session_id` in DDB), the existing item is returned
immediately — no second sentinel put, no DDB overwrite. The sentinel put has already
succeeded (because the session exists), so replaying is a pure read.

When no `idempotency_key` is provided, `uuid4().hex[:12]` is used, which is always
unique, so no replay path is needed.

### 5.4 `close_session` — expected-cash math

```
expected_cash_cents = opening_float_cents + cash_in_cents − change_out_cents
over_short_cents    = counted_cash_cents  − expected_cash_cents
```

`cash_in_cents` and `change_out_cents` are running totals maintained on the session
row by POS-006 (via `update_item` increments). At the time POS-004 is implemented,
these fields default to `0`; a session closed before POS-006 is merged will always
have `expected_cash = opening_float` and `over_short = counted - float`. That is
correct for the unit-test contract (POS-004 unit tests will explicitly set
`cash_in_cents` and `change_out_cents` to test the math).

The update is conditional on `#status = :open` to guard against concurrent close
attempts; losing thread receives 409.

### 5.5 Double-close

`close_session` raises `HTTPException(409)` in two places:
1. Eagerly, if `get_item` returns status `"closed"`.
2. If the conditional `update_item` races and another closer wins first
   (`ConditionalCheckFailedException` → 409).

Both paths produce identical 409 responses.

### 5.6 Register-not-found on `open_session`

`open_session` reads the register row before writing the sentinel. If the register
does not exist, 404 is raised before any sentinel write.

### 5.7 `get_open_session` returns `None` / 404

`get_open_session` returns `None` from the service layer. The router converts this to
`HTTPException(404, "No open session for this register")`. The service layer must
never raise on a valid absent-session query.

### 5.8 Over/short sign convention

`over_short_cents` is signed:
- Positive → cashier has more cash than expected (over).
- Negative → cashier has less cash than expected (short).
- Zero → exact match.

This matches standard retail POS practice (over is positive, short is negative).

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

**Dev/prod parity**: The `pos` DynamoDB table is created by
`scripts/local-ddb-init.py` in dev (via `just restart`) and by a one-time
`CreateTable` call in prod before this code ships. There is no `dev_mode` branch in
`pos_register.py`; all paths run against DDB local in dev (moto for tests) and real
DDB in prod — identical code.

**Idempotency**: `open_session` with `idempotency_key` derives a deterministic
`session_id` via `sha256(idempotency_key)[:12]`. A client that crashes after the DDB
write but before receiving the response can replay with the same key and receive the
same session without opening a duplicate. `close_session` is idempotent via the
conditional update: a second identical close call returns the already-closed session
after catching `ConditionalCheckFailedException` with 409 (the caller has enough
information to detect success-of-previous-attempt from the 409 body detail
`"Session is already closed"`).

**Security**:
- Register creation requires `require_admin_or_root_csrf` — a cashier without
  admin role cannot create or delete registers.
- `open_session` and `close_session` use `require_ui_session` (any authenticated
  user can open a till, consistent with cashier role in a typical POS).
- Close ownership: a cashier may only close their own session unless they hold
  ADMIN or ROOT role. This is enforced in the router handler, not the service.
- `over_short_cents` is stored unredacted in DDB and surfaced in audit events.
  Access to audit logs should be restricted to admin/root (existing audit
  infrastructure already does this).
- No plaintext currency amounts are logged to stdout; they appear only in DDB
  audit records.

**CSRF**: `open_session` and `close_session` are POST endpoints using
`require_ui_session`, which enforces the CSRF token check for cookie-auth clients
(per `app/services/sessions.py:427–436`). Bearer-auth API clients skip CSRF automatically.

## 10. Open Questions / Assumptions

1. **Assumption: POS-003 is merged first.** `T.pos` and `S.pos_enabled` do not exist
   until POS-003 lands. This spec's service and router code will not import cleanly
   without POS-003.

2. **Assumption: `RegisterCreateIn` model added in POS-002 or early in POS-004.**
   POS-002 spec (docs/ofbiz/specs/POS-002.md) lists `OpenSessionIn` and
   `CloseSessionIn` but does not list a `RegisterCreateIn`. The router needs one
   (label, location_id, default_currency). Either POS-002 is extended to include it,
   or POS-004 adds it. Recommend extending POS-002.

3. **Open question: sentinel-delete failure on close.** If the session `update_item`
   succeeds but the sentinel `delete_item` fails (network partition), the sentinel row
   points to a `status="closed"` session. `get_open_session` will follow the sentinel
   and find a closed session — returning `None` is correct per Section 5.2. However,
   a subsequent `open_session` will write a new sentinel for a new session, silently
   overwriting the stale one (since the conditional `attribute_not_exists` would
   FAIL — the stale sentinel still exists with its `pos_pk`). The correct behavior in
   this case is to allow the overwrite. **Recommendation**: change the sentinel
   `put_item` condition from `attribute_not_exists(pos_pk)` to
   `attribute_not_exists(pos_pk) OR session_id = :prev_sid` where `:prev_sid` is the
   stale closed session_id, checked by reading the sentinel first. Or simpler:
   check the sentinel-pointed session status before rejecting as "already open" — if
   the pointed session is closed, delete the stale sentinel and retry. This is a
   subtle edge case; the conservative first implementation rejects and forces operator
   intervention via admin close-session endpoint.

4. **Assumption: cashier ownership check in router, not service.** The service is
   intentionally unaware of caller identity beyond `actor_sub` for auditing. The router
   enforces `session.cashier_sub == ctx["user_sub"] or user.role >= ADMIN`. This is
   consistent with the pattern in `app/routers/returns_rma.py:49–51` for return
   ownership.

5. **Assumption: `cash_in_cents` / `change_out_cents` are updated by POS-006 via
   `update_item` ADD expressions.** POS-004 initialises them to `0` and never writes
   them again after session creation. The expected-cash formula is correct as long as
   POS-006 uses atomic `update_item` increments (not read-then-write).

6. **Open question: should `close_session` require that at least one transaction exists
   before closing?** The current design allows a zero-transaction close (edge: cashier
   opens and immediately closes with no sales). This produces `expected_cash =
   opening_float`. No acceptance criterion mandates a transaction count guard; leaving
   this permissive for now.

7. **Assumption: `source_system` for POS orders is `"shopping_cart"`** (per POS-001
   spec and `app/services/commerce_order_service.py:58` allowlist — currently
   `{"shopping_cart", "commercial_direct", "subscription_cycle"}`; `"pos_terminal"`
   may need to be added here). POS-004 does not create orders; this assumption is
   inherited by POS-005 and POS-006.
