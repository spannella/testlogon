## 1. Summary & Goal

PTY-015 adds a comprehensive, fully offline pytest suite (`tests/test_party_crm.py`) and a Playwright E2E spec (`frontend/e2e/party-crm.spec.ts`) for the Party/CRM feature introduced across PTY-001 through PTY-014.

The pytest suite exercises every service path — CRUD, idempotency, roles, relationships, contact mechanisms, org accounts, legacy migration, and profile back-fill — without touching real AWS. It uses the project's standard test-isolation pattern: a moto-backed in-memory DynamoDB resource whose table handles are patched onto the frozen `T` singleton via `object.__setattr__`, and `S` flags toggled the same way.

A dedicated flag-off regression subset asserts that the legacy `app/routers/contacts.py` surface (`list_contacts`, `add_contact`, `update_contact`, `remove_contact`) and `app/services/addresses.py` functions (`create_address`, `set_primary_address`) are byte-for-byte unchanged when `S.party_crm_enabled` is `False` — proving the additive, flag-gated contract of the entire Party/CRM feature group.

The E2E spec covers the happy-path UI flows for a signed-in Alice session: create party, add role, add a contact mech, create a B2B org, add a member, and a flag-off assertion that `/party` is unreachable.

## 3. Data Model

PTY-015 creates **no new DynamoDB tables**. It creates in-memory replicas of the tables introduced by PTY-002 for offline testing.

### 3.1 In-test table schema (mirrors PTY-002 production definition)

The test setUp recreates the `party` table with moto using the same schema that `scripts/local-ddb-init.py` will declare (PTY-002):

```
Table name:  party_test   (only within the moto context; real name from S.party_table_name)
PK:          PK (S)
SK:          SK (S)

GSI1:        GSI1PK (S) / GSI1SK (S)   — role-type lookup: ROLE#{role_type} → PARTY#{party_id}
GSI2:        GSI2PK (S) / GSI2SK (S)   — contact-mech reverse lookup: EMAIL#{norm} → PARTY#{party_id}
GSI3:        GSI3PK (S) / GSI3SK (S)   — inbound relationships + owner index: OWNER#{user_sub}
GSI_CREATED: type (S)   / created_at (N)  — newest-first party listing by type

attr_types: {"created_at": "N"}   — required per CLAUDE.md numeric GSI sort key gotcha
```

For the migration tests, a separate in-memory `Contacts` table replicates `scripts/local-ddb-init.py:691`:

```
PK: owner_id (S)
SK: contact_id (S)
(no GSIs)
```

For flag-off regression tests, the real `T.contacts` and `T.addresses` handles are patched with moto-backed tables having the same key schema as production.

## 5. Detailed Behavior & Edge Cases

### 5.1 Pytest isolation pattern

Each test class wraps its setup in a `moto.mock_aws()` `ExitStack` context (same pattern as `tests/test_gap_0233_0234_ssh_session_recording.py:71-81`). Crucially:

- `T.party` is patched via `object.__setattr__(T, "party", self.party_table)` with `addCleanup` to restore the previous handle.
- `S.party_crm_enabled` is toggled via `object.__setattr__(S, "party_crm_enabled", True)` (default is `False`) in each test class `setUp`, restored on teardown.
- `app.services.alerts.audit_event` is patched to `lambda *a, **k: None` to prevent side-effects.
- `app.services.profile.get_profile_identity` is patched for migration tests (avoids `T.profile` dependency).

**TestClient is not used.** Route handlers that are async coroutines are invoked via `asyncio.new_event_loop().run_until_complete(handler(...))` with dependency-injected arguments stubbed inline — matching the pattern in `tests/test_gap_0220_0221_ssh_stored_key.py`.

### 5.2 PTY-004 idempotency (create_party)

- `party_id = sha256(correlation_id.encode()).hexdigest()[:32]` when `correlation_id` is supplied (mirrors `app/services/commerce_order_service.py:67`).
- A conditional `put_item` with `ConditionExpression="attribute_not_exists(PK)"` makes replays a no-op — the test asserts the second call returns the same `party_id` and DDB scan count stays at 1.
- Without `correlation_id`, `party_id = uuid4().hex` — each call creates a distinct party.

### 5.3 PTY-005 role deduplication

- `add_role` stores `PK=PARTY#{party_id}`, `SK=ROLE#{role_type}`, `GSI1PK=ROLE#{role_type}`, `GSI1SK=PARTY#{party_id}`.
- Calling `add_role` twice with the same `(party_id, role_type)` is a no-op: `put_item` is unconditional (idempotent by key collision), or a conditional put with `attribute_not_exists(SK)` ignored on duplicate.
- `remove_role` on a non-existent role must not raise (DynamoDB `delete_item` is already a no-op when the key is absent).
- `parties_with_role` queries `GSI1` with `GSI1PK=ROLE#{role_type}`. The test seeds three parties with `SUPPLIER` and one with `CUSTOMER`, asserts `parties_with_role("SUPPLIER")` returns exactly 3.

### 5.4 PTY-006 relationship mirror and self-relationship guard

- Creating a relationship writes the primary row (`PK=PARTY#{from}`, `SK=REL#{type}#{to}`) and a mirror row (`PK=PARTY#{to}`, `SK=REL_TO#{type}#{from}`) in a single transaction or two sequential `put_item` calls.
- `list_relationships(party_id, direction="from")` queries `PK=PARTY#{party_id}` with `SK` beginning with `REL#`; `direction="to"` queries `PK=PARTY#{party_id}` with `SK` beginning with `REL_TO#`; `direction="both"` merges both.
- `delete_relationship` removes both rows. Test asserts that after deletion neither direction returns the edge.
- Self-relationship (`from_party_id == to_party_id`) raises `HTTPException(400, ...)`. Test exercises this path.

### 5.5 PTY-007 contact-mech normalization

- `EMAIL` values pass through `normalize_email` from `app/core/normalize.py:60`; `PHONE` through `normalize_phone` at line 66; `POSTAL` through `normalize_address_payload` from `app/services/addresses.py:39` with `require_all=True` (enforcing `line1` presence).
- The GSI2 reverse key is computed from the normalized value: `GSI2PK=EMAIL#{normalize_email(value)}`.
- `find_party_by_contact("EMAIL", "Alice@X.com ")` must normalize to match the stored normalized value. Test asserts case/whitespace insensitivity.
- Unknown `purposes` string values raise `ValidationError`; valid values include `PRIMARY_EMAIL`, `BILLING`, `SHIPPING`, `PRIMARY_PHONE`.

### 5.6 PTY-008 org account ORG_ADMIN guard

- `add_member(org_party_id, member_party_id, role_type, *, actor_party_id)` checks that `actor_party_id` holds `ORG_ADMIN` on `org_party_id` (queries `PK=PARTY#{org}`, `SK=ROLE#ORG_ADMIN` linked to actor, or a dedicated `PARTY#{actor}`, `SK=REL#OWNER#{org}` check).
- A non-admin actor raises `HTTPException(403, ...)`. The test seeds an org, adds Alice as ORG_ADMIN, adds Bob as non-admin member, then asserts Bob's `add_member` attempt raises 403.
- `create_org_account` is atomic and idempotent under the same `correlation_id`: creates `PARTY_GROUP`, assigns `CUSTOMER`+`BILL_TO` roles, creates `OWNER` relationship from the PERSON party. Replay with same `correlation_id` returns same `org_party_id`.

### 5.7 PTY-009 migration no-op and idempotency

- `run_contacts_backfill` reads from `T.contacts` (never writes to it) and projects into `T.party`.
- A pre-seeded contact row `{owner_id: "alice", contact_id: "bob", display_name: "Bob", is_favorite: True, is_blocked: False}` must produce: a PERSON party for `bob` linked to `user_sub=bob`, a `CONTACT_REL` relationship `alice→bob`, a `CONTACT` role on `bob`'s party.
- Re-running the backfill: the `create_party` idempotency key is `sha256(f"migrate:{contact_id}").hexdigest()[:32]`; the `create_relationship` key is `sha256(f"migrate_rel:{owner_id}:{contact_id}").hexdigest()[:32]`. Second run produces no new DDB rows (scan count unchanged).
- **Flag-off:** with `S.party_crm_contacts_migration_enabled = False`, calling `add_contact` in `app/routers/contacts.py` must behave identically (the hook is guarded by the flag). The test monkeypatches `run_contacts_backfill` to a side-effect counter and asserts it is never called with the flag off.

### 5.8 PTY-010 ensure_person_party back-fill

- `ensure_person_party(user_sub)` queries `GSI3` for `GSI3PK=OWNER#{user_sub}` to check if a PERSON party already exists; if not, calls `create_party(PERSON, user_sub=user_sub, correlation_id=f"person:{user_sub}")`.
- After creation, it reads `get_profile_identity(user_sub)` and `list_addresses(user_sub)` to back-fill mechs.
- Idempotency: called twice for the same `user_sub` returns the same `party_id` and creates no duplicate mechs (because `add_contact_mech` is also conditional on the mech not existing for the same `mech_type`+normalized value).
- Flag-off (`S.party_crm_enabled = False`): `apply_profile_update` in `app/services/addresses.py:136` must NOT call any party service function. The test patches `ensure_person_party` and asserts zero calls when the flag is off.

### 5.9 Flag-off regression tests

The regression class uses `unittest.mock.patch` to wrap the real contacts/addresses function calls and asserts:
1. `list_contacts` returns a `{"contacts": [...]}` dict from `T.contacts` without consulting `T.party`.
2. `add_contact` writes exactly one row to `T.contacts` and does not write to `T.party`.
3. `update_contact` modifies exactly the one `T.contacts` row and does not touch `T.party`.
4. `remove_contact` deletes the row from `T.contacts` and does not touch `T.party`.
5. `create_address` writes one `T.addresses` row with all expected fields (`user_sub`, `address_id`, `is_primary_mailing: False`, `created_at`, `line1`, etc.) and does not write to `T.party`.
6. `set_primary_address` flips `is_primary_mailing` on two rows in `T.addresses` and calls `apply_profile_update`, but does not touch `T.party`.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

**SECOPS-007 parity:** The party service uses `T.party` for all reads and writes. `T.party` resolves to DynamoDB Local in dev and real DynamoDB in prod; no code branches on `S.dev_mode`. All normalization, hashing, and conditional-put logic is identical in both environments. Tests exercise the same service code paths that prod uses.

**Idempotency:** Every write path that accepts a `correlation_id` uses `sha256(correlation_id.encode()).hexdigest()[:32]` as the deterministic key (pattern from `app/services/commerce_order_service.py:67`) and a conditional `attribute_not_exists(PK)` put. Tests verify that replaying the same `correlation_id` returns the original item and produces no duplicate DDB rows.

**No mutation of legacy tables:** The contacts table (`T.contacts`) and addresses table (`T.addresses`) are never written by any party service function. The migration service reads `T.contacts` read-only. The `ensure_person_party` hook reads `T.addresses` via `list_addresses` read-only. Tests assert these tables are unchanged after party operations.

**Audit events:** Every `create_party`, `update_party_status`, and org mutation emits `audit_event(...)` via `app.services.alerts.audit_event`. The test patches this to a no-op (as `tests/test_gap_0233_0234_ssh_session_recording.py:85` does) to avoid writing to `T.alerts`. A dedicated audit-coverage test verifies `audit_event` is called with the expected `event` string for create and status-change.

**Flag enforcement in router:** The router (PTY-011) guards every handler with `if not S.party_crm_enabled: raise HTTPException(404, "feature disabled")` or equivalent before any service call. The E2E flag-off test confirms this without any service side-effects.

## 8. Backward Compatibility & Migration

PTY-015 is purely additive — it adds test files only. No existing files are modified.

The flag-off regression class in `tests/test_party_crm.py` is the authoritative proof of backward compatibility: it runs the exact same code paths that the existing `app/routers/contacts.py` and `app/services/addresses.py` tests cover (if any), but now explicitly under `party_crm_enabled=False`, and the assertions are byte-level: the DDB calls made and the return shapes must be identical to a system with no party code present at all.

**Setup pattern** (shared across all test classes):

```python

except Exception:
    mock_aws = None

    return ddb.create_table(
        TableName="party_test",
        KeySchema=[
            {"AttributeName": "PK", "KeyType": "HASH"},
            {"AttributeName": "SK", "KeyType": "RANGE"},
        ],
        AttributeDefinitions=[
            {"AttributeName": "PK",         "AttributeType": "S"},
            {"AttributeName": "SK",         "AttributeType": "S"},
            {"AttributeName": "GSI1PK",     "AttributeType": "S"},
            {"AttributeName": "GSI1SK",     "AttributeType": "S"},
            {"AttributeName": "GSI2PK",     "AttributeType": "S"},
            {"AttributeName": "GSI2SK",     "AttributeType": "S"},
            {"AttributeName": "GSI3PK",     "AttributeType": "S"},
            {"AttributeName": "GSI3SK",     "AttributeType": "S"},
            {"AttributeName": "type",       "AttributeType": "S"},
            {"AttributeName": "created_at", "AttributeType": "N"},
        ],
        GlobalSecondaryIndexes=[...],  # GSI1..GSI3 + GSI_CREATED
        BillingMode="PAY_PER_REQUEST",
    )

class _PartyTestBase(unittest.TestCase):
    def setUp(self):
        self.stack = ExitStack()
        self.addCleanup(self.stack.close)
        self.stack.enter_context(mock_aws())
        ddb = boto3.resource("dynamodb", region_name="us-east-1")

        from app.core.tables import T
        from app.core.settings import S

        object.__setattr__(T, "party", self.party_table)
        self.addCleanup(lambda: object.__setattr__(T, "party", self._prev_party))

        self._prev_flag = S.party_crm_enabled
        object.__setattr__(S, "party_crm_enabled", True)
        self.addCleanup(lambda: object.__setattr__(S, "party_crm_enabled", self._prev_flag))

        self.stack.enter_context(
            patch("app.services.alerts.audit_event", lambda *a, **k: None)

        import app.services.party as party_svc
        self.svc = party_svc
```

## 10. Open Questions / Assumptions

1. **Assumption: `T.party` attribute exists on the frozen T handle before PTY-015 runs.** PTY-002 must add `party: Any` to the `TableHandles` dataclass at `app/core/tables.py` and wire `party=_safe_table(S.party_table_name)`. If `T.party` does not exist, `object.__setattr__` will add it dynamically but the service module import-time reference may be a separate binding. The test should import `app.services.party` after patching `T`.

2. **Assumption: Service functions are synchronous.** Based on the existing contacts router pattern (`app/routers/contacts.py` uses sync `def`, not `async def`), the party service functions are assumed to be sync. If PTY-004 implements them as `async`, the test runner must use `asyncio.new_event_loop().run_until_complete(...)` for those calls (pattern in `tests/test_gap_0220_0221_ssh_stored_key.py`).

3. **Assumption: Router handlers are declared as `async def`.** FastAPI handlers are typically async. The flag-off regression tests for the contacts router call `list_contacts`, `add_contact`, etc. directly as sync functions (they are currently sync in `app/routers/contacts.py:63`). If PTY-011 converts them to async, the calling convention must change.

4. **Assumption: The E2E flag-off section (105) runs against the default dev stack with `PARTY_CRM_ENABLED` absent or `0`.** The positive sections (101–104) require the dev stack to be running with `PARTY_CRM_ENABLED=1`. If the CI environment does not support per-test flag toggling, sections 101–104 must be skipped or run against a separately launched stack. A `test.skip` guard can be added: `test.skip(process.env.PARTY_CRM_ENABLED !== "1", "requires PARTY_CRM_ENABLED=1")`.

5. **Assumption: `create_relationship` uses the mirror GSI3 pattern from PTY-006.** The relationship mirror row uses `GSI3PK=REL_TO#{to}`, `GSI3SK=REL#{type}#{from}`. The test asserts `list_relationships(bob_party_id, direction="to")` returns the edge written from Alice to Bob. If PTY-006 uses a different SK prefix, the test assertions must be updated.

6. **Assumption: ORG_ADMIN authorization in `add_member` is implemented in the service layer** (not purely in the router). The test exercises this via direct service calls. If authorization is only enforced at the router layer, a separate router-level test is needed.

7. **Assumption: `find_party_by_contact` queries GSI2 and returns `None` (not a 404 exception) when no match is found.** The test asserts `assertIsNone(result)` for an unknown email. If the service raises 404 instead, the test must use `assertRaises`.

8. **Assumption: The contacts/addresses legacy surface regression can be exercised by calling the handler function directly** with a synthetic `ctx={"user_sub": "test-user"}` dict. If `require_ui_session` is invoked inside the handler body (rather than as a FastAPI `Depends` injected arg), additional patching of the session dependency is needed.
