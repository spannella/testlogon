# SHP-007 — Rate-estimation router + cart/checkout estimate endpoint

## 1. Summary & Goal

SHP-007 creates `app/routers/shipping_rates.py` — the HTTP surface over the SHP-006
rate-estimation engine. It exposes two authenticated endpoints under the `/ui/shop/shipping`
prefix, both gated on the dual flags `S.shipping_enabled` AND
`S.shipping_rate_estimation_enabled`:

1. **`POST /ui/shop/shipping/estimate`** — accepts an explicit destination + line-item
   set and returns a `ShippingRateQuote` directly from the SHP-006 engine.
2. **`POST /ui/shop/shipping/estimate/cart/{cart_id}`** — resolves the caller's active
   cart items via the cart-read path already used by `purchase_cart` in
   `app/services/shoppingcart.py:474`, then passes them to the same rate engine. This
   is the storefront variant: the checkout page shows live shipping options before the
   buyer commits to a method, **without mutating cart or order state**.

Both endpoints require `require_ui_session` (cookie-based or Bearer-token auth + CSRF
on non-GET cookie requests). Neither endpoint emits billing ledger entries, creates
orders, or touches any table other than `T.shipping_carriers` (read-only through the
SHP-006 service) and `T.shopping_cart` (read-only through `list_items`). The router is
registered in `app/main.py` adjacent to the carrier-tracking routers at line 681.

With both flags off the new router is dead code; all existing shop/cart/orders/billing
paths are byte-for-byte unchanged.

## 2. Context & Current State

### 2.1 Cart read path (reused, not forked)

`app/services/shoppingcart.py:277` defines `list_items(user_sub, cart_id) ->
List[Dict[str, Any]]`. It queries `T.shopping_cart` with
`KeyConditionExpression=Key("PK").eq(pk) & Key("SK").begins_with(prefix)` where
`prefix = f"CART#{cart_id}#ITEM#"` (`shoppingcart.py:279`). The returned dicts carry
the fields (`shoppingcart.py:82–95`, `_item_from_item`):

- `sku`, `name`, `quantity`, `unit_price_cents`, `line_total_cents`
- `category_id`, `item_id` (when catalog-linked items are in the cart)

`purchase_cart` (`shoppingcart.py:474`) calls `get_cart(user_sub, cart_id)` (line 482)
followed by `list_items(user_sub, cart_id)` (line 495) as its first two substantive
operations (the PURCHASED early-return at lines 483–492 and `_require_open_cart` at
line 493 execute between the two calls).
SHP-007 follows the exact same pattern for the cart-bound variant: `get_cart` first
(to validate ownership and open status), then `list_items`. No new query is introduced
and the shopping-cart DDB access pattern is unchanged.

`get_cart` (`shoppingcart.py:237`) raises `HTTPException(404, "Cart not found")` when
the cart does not exist. `_require_open_cart` (`shoppingcart.py:306` — called at line
493 in `purchase_cart`) raises `HTTPException(409, "Cart is not open")` when the cart
status is anything other than `"OPEN"` (i.e. any of `PURCHASED`, `ABANDONED`,
`EXPIRED`). SHP-007 reuses both guards via the imported service functions rather than
re-implementing them.

### 2.2 Rate-estimation engine (SHP-006 dependency)

`app/services/shipping_rates.py` (SHP-006's deliverable) exposes:

```python
def estimate_rate(
    *,
    destination_zip: str,
    origin_zip: Optional[str] = None,
    line_items: List[Dict[str, Any]],
    carrier_code: Optional[str] = None,
    method_code: Optional[str] = None,
) -> ShippingRateQuote:
```

The function reads enabled carriers/methods from `list_enabled_methods_all_carriers()`
(SHP-004), computes billable weight from `line_items` quantities and per-SKU
`shipping_weight_oz` (from the catalog item via `T.catalog.get_item`, default `16` oz
when unset), applies dimensional-weight breakpoints and flat/zone modifiers per method,
and returns a `ShippingRateQuote` with one `ShippingRateOption` per enabled method.
An empty enabled-method set yields an empty-but-valid quote (not an error).

The `request_id` on the returned quote is
`sha256("|".join([carrier_code or "", method_code or "", str(weight_oz), destination_zip]))
[:16]`, making the quote deterministic for identical inputs (safe to cache by the
caller).

SHP-007 calls `estimate_rate` directly — the router is a thin shim that validates
input, resolves optional cart items, and delegates all pricing math to SHP-006.

## 3. Data Model

### 3.1 No new DynamoDB tables

SHP-007 is a pure router ticket. All DDB access goes through service functions that own
their tables:

- `T.shopping_cart` — read-only via `get_cart` and `list_items` (SHP-007 never calls
  `T.shopping_cart` directly).
- `T.shipping_carriers` — read-only via `list_enabled_methods_all_carriers()` inside
  the SHP-006 engine (SHP-007 never imports `T`).
- `T.catalog` — read-only via the weight-resolution inside SHP-006's `estimate_rate`
  (SHP-007 never imports `T`).

No entries are added to `scripts/local-ddb-init.py`, `app/core/settings.py`, or
`app/core/tables.py` in this ticket — those are SHP-002's deliverables.

### 3.2 Response shape: `ShippingRateQuote`

The `ShippingRateQuote` returned by both endpoints is ephemeral (not persisted):

| Field | Type | Notes |
|---|---|---|
| `request_id` | `str` | `sha256(inputs)[:16]`; stable for identical inputs |
| `options` | `List[ShippingRateOption]` | One per enabled method; empty list is valid |
| `currency` | `str` | `"usd"` (from `S.shipping_default_currency`) |
| `generated_at` | `int` | `now_ts()` at computation time |

Each `ShippingRateOption`:

| Field | Type | Notes |
|---|---|---|
| `carrier_code` | `str` | `ups` / `fedex` / `usps` / `dhl` / `manual` |
| `method_code` | `str` | `ground` / `express` / `overnight` / `economy` / `flat_rate` |
| `rate_cents` | `int` | Non-negative; `0` = free shipping |
| `currency` | `str` | ISO 4217 |
| `transit_days_min` | `Optional[int]` | From carrier method catalog |
| `transit_days_max` | `Optional[int]` | From carrier method catalog |
| `estimated_delivery` | `Optional[str]` | ISO date computed from transit days + `now_ts()` |

### 3.3 New request model: `CartShippingEstimateIn`

Added to `app/models.py` in this ticket (SHP-003 does not define a cart-specific
request model). Placed under the existing `ShippingRateQuote` block in the
`# ── Shipping / Logistics` section.

```python
class CartShippingEstimateIn(BaseModel):
    destination_zip: str = Field(min_length=1, max_length=20)
    origin_zip: Optional[str] = Field(default=None, max_length=20)
    carrier_code: Optional[str] = Field(
        default=None,
        pattern=r"^(ups|fedex|usps|dhl|manual)$",
    )
    method_code: Optional[str] = Field(
        default=None,
        pattern=r"^(ground|express|overnight|economy|flat_rate)$",
    )
```

`carrier_code` and `method_code` are optional filters: when provided the engine returns
only the matching method (useful when the buyer has already selected a method and the
storefront wants to confirm/refresh the price). When both are `None` the engine returns
all enabled methods, giving the storefront a full option list to display.

## 4. API / Service Design

### 4.1 Router declaration

```python
# app/routers/shipping_rates.py

from fastapi import APIRouter, Depends, HTTPException, Request
from typing import Optional

from app.core.settings import S
from app.models import (
    ShippingRateRequest,
    ShippingRateQuote,
    CartShippingEstimateIn,
)
from app.services.sessions import require_ui_session
from app.services.shoppingcart import get_cart, list_items
from app.services.shipping_rates import estimate_rate     # SHP-006

router = APIRouter(
    prefix="/ui/shop/shipping",
    tags=["shipping-rates"],
)


def _ensure_rate_estimation_enabled() -> None:
    if not S.shipping_enabled:
        raise HTTPException(
            status_code=503,
            detail={"code": "feature_disabled", "message": "Shipping is not enabled"},
        )
    if not S.shipping_rate_estimation_enabled:
        raise HTTPException(
            status_code=503,
            detail={"code": "feature_disabled", "message": "Shipping rate estimation is not enabled"},
        )
```

The prefix `/ui/shop/shipping` keeps the new endpoints inside the session-auth
perimeter (Vite proxies `/ui/*` to the backend — CLAUDE.md §Dev stack), namespaced
below the existing `/ui/shop/tracking` prefix on `carrier_tracking_poller_router`
(`app/routers/carrier_tracking_poller.py:28`).

### 4.2 Endpoint: `POST /ui/shop/shipping/estimate`

```python
@router.post("/estimate", response_model=ShippingRateQuote, status_code=200)
async def estimate_shipping_rate(
    body: ShippingRateRequest,
    ctx=Depends(require_ui_session),
) -> ShippingRateQuote:
    _ensure_rate_estimation_enabled()
    quote = estimate_rate(
        destination_zip=body.destination_zip,
        origin_zip=body.origin_zip,
        line_items=[{
            "sku": None,
            "quantity": 1,
            "weight_oz": body.weight_oz,
        }],
        carrier_code=body.carrier_code,
        method_code=body.method_code,
    )
    return quote
```

The `line_items` list is a single synthetic item carrying the caller-supplied
`weight_oz` directly, bypassing the catalog weight lookup inside SHP-006. This is the
correct behavior for the explicit-weight variant: the caller already knows the weight
(e.g. from a physical product weigh-in) and does not need the engine to look up
per-SKU weights.

### 4.3 Endpoint: `POST /ui/shop/shipping/estimate/cart/{cart_id}`

```python
@router.post(
    "/estimate/cart/{cart_id}",
    response_model=ShippingRateQuote,
    status_code=200,
)
async def estimate_shipping_rate_for_cart(
    cart_id: str,
    body: CartShippingEstimateIn,
    ctx=Depends(require_ui_session),
) -> ShippingRateQuote:
    _ensure_rate_estimation_enabled()
    # Re-use the cart ownership + status check from purchase_cart
    cart = get_cart(ctx["user_sub"], cart_id)
    _require_open_cart_for_estimate(cart)
    items = list_items(ctx["user_sub"], cart_id)
    if not items:
        raise HTTPException(
            status_code=400,
            detail={"code": "cart_empty", "message": "Cart has no items to estimate shipping for"},
        )
    quote = estimate_rate(
        destination_zip=body.destination_zip,
        origin_zip=body.origin_zip,
        line_items=items,           # passes sku + quantity + category_id/item_id to SHP-006
        carrier_code=body.carrier_code,
        method_code=body.method_code,
    )
    return quote
```

`_require_open_cart_for_estimate` is a private helper that checks
`cart.get("status") != "PURCHASED"` and raises
`HTTPException(400, {"code": "cart_already_purchased"})` if so. Unlike the
`_require_open_cart` used in `purchase_cart` (which checks the full cart validity),
this lighter guard only prevents estimating shipping for a completed cart (which would
be confusing UX). Abandoned carts (`status == "ABANDONED"`) are allowed through —
the buyer may be reviving an abandoned session.

**Read-only guarantee**: `estimate_shipping_rate_for_cart` calls only `get_cart`,
`list_items`, and `estimate_rate`. None of these writes to any DDB table. The cart
`last_activity_at` is **not** touched (contrast with `add_item`, which calls
`_touch_cart_activity` at `shoppingcart.py:366`). This preserves the abandonment-timer
semantics: calling the estimate endpoint repeatedly does not reset the abandonment
countdown.

### 4.4 HTTP summary table

| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| `POST` | `/ui/shop/shipping/estimate` | `require_ui_session` | Explicit weight + destination → rate quote |
| `POST` | `/ui/shop/shipping/estimate/cart/{cart_id}` | `require_ui_session` | Active cart → rate quote (read-only) |

Both return HTTP 503 when `S.shipping_enabled=False` OR `S.shipping_rate_estimation_enabled=False`.

## 5. Detailed Behavior & Edge Cases

### 5.1 Flag states and responses

| `shipping_enabled` | `shipping_rate_estimation_enabled` | Both endpoints |
|---|---|---|
| `False` | any | 503 `"Shipping is not enabled"` |
| `True` | `False` | 503 `"Shipping rate estimation is not enabled"` |
| `True` | `True` | Normal operation |

This two-level gate allows an operator to enable the carrier catalog (SHP-005's
admin CRUD + storefront method list) without yet exposing the price-estimation surface
to buyers — useful when carrier data is being populated but rates haven't been tuned.

### 5.2 Empty carrier/method set

When the `shipping_carriers` table has no enabled methods (e.g. immediately after the
flag is first enabled but before `seed_default_carriers()` has run, or if all carriers
have been disabled), `estimate_rate` returns a `ShippingRateQuote` with `options=[]`.
Both endpoints return this empty-but-valid quote with HTTP 200. The client must
handle the empty case (e.g. hide the shipping picker and show "Contact us for
shipping options").

### 5.3 Cart ownership enforcement

`get_cart(ctx["user_sub"], cart_id)` uses
`Key={"PK": _user_pk(user_sub), "SK": _cart_sk(cart_id)}` which resolves to
`{"PK": f"USER#{user_sub}", "SK": f"CART#{cart_id}"}` (`shoppingcart.py:30–35`).
If `cart_id` exists but belongs to a different user, `get_cart` returns a 404 (the DDB
key is PK-scoped to the user; the item simply won't be found). This provides the
ownership check without a separate lookup — the same pattern used throughout
`shoppingcart.py`.

### 5.4 Large cart (>500 items)

`list_items` (`shoppingcart.py:277`) calls `T.shopping_cart.query` with
`begins_with(SK, "CART#{cart_id}#ITEM#")`. There is no `Limit` on this query and no
`LastEvaluatedKey` loop (single-page response); boto3 returns up to 1MB of results. In practice cart items are
bounded by product catalog size (typical carts have < 50 items). The weight aggregation
inside SHP-006 is O(n) over items — acceptable for all realistic inputs.

### 5.5 Catalog weight lookup inside SHP-006

SHP-006's `estimate_rate` resolves per-SKU `shipping_weight_oz` from `T.catalog` using
the `category_id` + `item_id` present on each `list_items` dict. When `category_id` or
`item_id` is absent (e.g. items added via `add_item` without catalog linkage), the
engine falls back to a default weight (`16 oz` per SHP-006's spec). SHP-007 does not
change this behaviour; it is fully delegated to SHP-006.

### 5.6 `ShippingRateRequest.carrier_code` / `method_code` filter

When the explicit-weight endpoint caller provides `carrier_code` and/or `method_code`,
SHP-006 filters the enabled methods to only the matching one. If no enabled method
matches the filter, the quote returns with `options=[]` (not a 404 — the filter is a
hint, not a guarantee). The storefront should handle the empty case gracefully.

### 5.7 CSRF on POST endpoints

Both endpoints are `POST` — non-GET methods. Cookie-authenticated callers must supply
`x-csrf-token: <csrf_token>` matching the session's stored CSRF token and the `ui_csrf`
cookie (enforced by `require_ui_session` — see CLAUDE.md §Auth). Bearer-authenticated
callers (e.g. E2E `request` fixture using `Authorization: Bearer`) skip CSRF
automatically because `require_ui_session` only enforces CSRF when the `ui_session`
cookie is present.

### 5.8 Concurrent estimate + purchase race

The estimate endpoint is read-only and does not lock stock or cart items. A concurrent
`purchase_cart` call may succeed between the estimate and the actual checkout flow. The
estimate result may therefore be stale (e.g. a catalog item goes out of stock, or an
admin disables the chosen carrier). This is expected: the estimate is advisory. The
checkout flow (future ticket) will re-validate the chosen method before creating the
shipment.

### 5.9 `PURCHASED` cart

If `cart.get("status") == "PURCHASED"`, `_require_open_cart_for_estimate` raises
`HTTPException(400, {"code": "cart_already_purchased"})`. This prevents confusing the
user into thinking they need to choose shipping for a completed order.

### 5.10 `ABANDONED` cart

If `cart.get("status") == "ABANDONED"`, the cart-bound estimate proceeds normally.
This is intentional: estimating shipping for an abandoned cart is part of the recovery
flow (the buyer clicked a recovery link and is comparing options before re-activating
their cart).

### 5.11 Response idempotency

The `ShippingRateQuote.request_id` is deterministic for identical inputs (carrier
code, method code, weight, destination zip). Calling either endpoint twice with the
same inputs returns a quote with the same `request_id` (but a fresh `generated_at`
timestamp). Clients may use `request_id` for deduplication/caching.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 No `dev_mode` branch in this router

`app/routers/shipping_rates.py` contains zero `if S.dev_mode` conditionals. The
`_ensure_rate_estimation_enabled()` sentinel is identical in dev and prod: it checks
the same two `S.*` flags against the same `SHIPPING_ENABLED` / `SHIPPING_RATE_ESTIMATION_ENABLED`
env vars. The actual rate computation is fully delegated to SHP-006, which also has no
`dev_mode` branch (the built-in estimator returns the same deterministic values in both
environments when UPS credentials are absent — per SHP-006's spec).

### 7.2 Idempotency

- **`POST /estimate`**: Fully idempotent for identical inputs. The SHP-006 engine is
  a pure function of (destination, items, filter); calling it twice does not mutate any
  state.
- **`POST /estimate/cart/{cart_id}`**: Also idempotent. `list_items` is read-only;
  `get_cart` is read-only. The estimate does not touch `last_activity_at` (see §5.3).
  The cart state is not changed.

### 7.3 No billing ledger entries

Neither endpoint calls `billing_shared.new_ledger_entry`. No money moves as a result
of a rate estimate. The GL is untouched. The constraint "new write paths use
deterministic-id idempotency" does not apply here because there are no write paths.

### 7.4 Security

- **Ownership**: Cart ownership is enforced by the PK-scoped DDB key in `get_cart` —
  a caller cannot access another user's cart by supplying an arbitrary `cart_id`.
- **Role**: `require_ui_session` accepts any authenticated user (no admin-only
  restriction). This is correct: estimating shipping is a buyer action, not an admin
  action. Admin/root users can also call the estimate endpoints without special handling.
- **CSRF**: cookie-authenticated `POST` requests require the `x-csrf-token` header.
  Bearer-authenticated requests skip CSRF. This is the standard pattern for every
  non-GET endpoint under `/ui/` in this codebase.
- **No PII in logs**: `destination_zip` and `origin_zip` are logged at most as
  info-level in the SHP-006 engine; the router does not log them. `cart_id` in the
  path is a hex UUID and does not contain PII.

## 8. Backward Compatibility & Migration

### 8.1 Zero impact with flags off

With `SHIPPING_ENABLED=false` or `SHIPPING_RATE_ESTIMATION_ENABLED=false` (both
default to `false` per SHP-002):

- `app/services/shoppingcart.py` is byte-for-byte unchanged: `get_cart`,
  `list_items`, `purchase_cart`, `add_item`, `_touch_cart_activity` are all unaffected.
- `app/services/commerce_order_service.py` is byte-for-byte unchanged.
- `app/routers/shoppingcart.py` is byte-for-byte unchanged.
- All billing paths (`billing_shared.py`, `billing.py`, `paypal.py`, etc.) are
  byte-for-byte unchanged.
- `app/services/carrier_tracking.py` is byte-for-byte unchanged.

### 8.2 `GET /openapi.json` change

The two new paths (`POST /ui/shop/shipping/estimate`,
`POST /ui/shop/shipping/estimate/cart/{cart_id}`) appear in the OpenAPI schema
regardless of flag value (unconditional `include_router`). This matches the pattern
for all other routers in `main.py`. When flags are off, the paths return 503; clients

## 10. Open Questions / Assumptions

**OQ-1 (SHP-006 `estimate_rate` signature)**: This spec assumes SHP-006 exports a
module-level function `estimate_rate(*, destination_zip, origin_zip, line_items,
carrier_code, method_code) -> ShippingRateQuote` (or a dict compatible with that
model). If SHP-006 uses a class-based service (e.g. `ShippingRatesService().estimate(...)`)
the router imports must be adjusted. Verify against the SHP-006 spec before
implementation.

**OQ-2 (Weight encoding for explicit-weight endpoint)**: This spec wraps the caller's
`weight_oz` in a synthetic `line_items=[{"sku": None, "quantity": 1, "weight_oz": body.weight_oz}]`
list to avoid forking the SHP-006 engine. If SHP-006's `estimate_rate` accepts a
top-level `total_weight_oz` parameter instead (bypassing the per-item lookup loop),
the wrapper is simpler. Clarify the SHP-006 engine's preferred input shape.

**OQ-3 (Cart-bound endpoint read-only guarantee)**: This spec asserts that neither
`get_cart` nor `list_items` calls `_touch_cart_activity`. This is true today
(`list_items` at `shoppingcart.py:277` does not call `_touch_cart_activity`; only
`add_item` (lines 336, 366), `set_item_quantity` (lines 411, 420), and
`decrement_item` (lines 436, 445) do — `start_cart` sets `last_activity_at` inline
without calling `_touch_cart_activity`). If a future ticket modifies `list_items` to
update activity, the read-only guarantee breaks. A comment in the router noting this
assumption should accompany the implementation.

**OQ-4 (Abandoned cart allow-through)**: The spec allows estimating shipping for
`ABANDONED` carts (status check only blocks `PURCHASED`). If product intent is to
block estimates for abandoned carts (to prevent reviving them without going through the
recovery link flow), `_require_open_cart_for_estimate` must also reject `ABANDONED`.
This assumption should be verified with product before implementation.

**OQ-5 (`CartShippingEstimateIn` placement in `app/models.py`)**: The spec adds
`CartShippingEstimateIn` to `app/models.py` as part of this ticket. SHP-003 did not
include it because the cart-bound endpoint was scoped to SHP-007. The model is minimal
(4 fields) and can be added inline in `app/routers/shipping_rates.py` instead if the
team prefers to keep `app/models.py` as the single source for only SHP-003-defined
shapes. Either location is acceptable; `app/models.py` is preferred for OpenAPI
documentation.

**OQ-6 (Destination-zip format)**: `destination_zip` is accepted as any 1–20 character
string (same as `ShippingRateRequest` from SHP-003). No US-format validation (5 or
9 digits) is applied. International postal codes vary widely in format; restricting to
US-only zip codes would be premature. If a US-only product requirement emerges, a
`pattern=r"^\d{5}(-\d{4})?$"` validator can be added.
