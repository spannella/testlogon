### No S3 protocol support in standard FFmpeg builds
FFmpeg's `s3://` protocol requires the `aws` / `s3` demuxer compiled in (`--enable-protocol=s3`). The standard Ubuntu/Debian apt package (`ffmpeg` from `ppa:savoury1/ffmpeg4` or apt) does not include this protocol. Without it, ffmpeg exits immediately with:

```
s3://...: Protocol not found
```

This causes every rendition to raise `NonRetryableError("source_not_found", ...)` (matched by the `"No such file or directory"` pattern in `ffmpeg_executor.py:39`) and the job fails on the first rendition of every submission.

## Root cause

The SYND-004 / VOD-004 implementation added the ffmpeg execution layer but omitted the S3 download pre-step. The `source_uri` was designed to be an `s3://` locator for storage purposes; the worker was supposed to download the source to `scratch_dir/source.<ext>` and pass the local path to ffmpeg. This pre-step is referenced in a comment (line 146-147) but the actual `vod_s3_downloader.py` module and the download call were never written.

## Exact fix (code-level)

**1. Create `app/services/vod_s3_downloader.py`:**
```python
"""Download a video source from S3 to a local scratch path before FFmpeg."""
import re
from pathlib import Path
from app.core.aws import s3_client
from app.core.settings import S

def download_source_to_scratch(source_uri: str, scratch_dir: Path) -> Path:
    """Download s3://bucket/key to scratch_dir/source.<ext>. Returns local path."""
    m = re.match(r"^s3://([^/]+)/(.+)$", source_uri)
    if not m:
        # Not an s3:// URI (e.g. already a local path or HTTPS); return as-is.
        return Path(source_uri)
    bucket, key = m.group(1), m.group(2)
    ext = Path(key).suffix or ".mp4"
    dest = scratch_dir / f"source{ext}"
    dest.parent.mkdir(parents=True, exist_ok=True)
    s3_client().download_file(bucket, key, str(dest))
    return dest
```

**2. `app/services/transcode_worker.py` — add download step before rendition loop (after line 102):**
```python
from app.services.vod_s3_downloader import download_source_to_scratch

source_uri = job.get("source_uri", "")
watermark = job.get("watermark", {})

# Download source to local scratch before passing to FFmpeg
local_source = download_source_to_scratch(source_uri, scratch_dir)
source_uri = str(local_source)   # replace s3:// with local path for ffmpeg
```

No changes needed to `ffmpeg_abr_pipeline.py` — it will receive a local file path instead of an s3:// URI.

## Blast radius / exploit

Every transcode job in production fails immediately. No video is ever successfully transcoded. The failure mode is silent from the user's perspective (job transitions to `failed` status). This blocks the entire VOD pipeline: uploaded videos remain in `queued` status and never reach `published`.

No security exploit. The impact is functional (complete feature outage) not a security issue.

## Dev/prod parity

**Dev mode:** moto intercepts boto3 calls at the botocore layer, so `s3_client().download_file(...)` works in dev against the moto mock. The local DynamoDB setup and `DEV_S3_ENABLED` flag do not affect boto3 `download_file`.

**Prod (AWS):** `s3_client()` from `app/core/aws.py` uses IAM role credentials; `download_file` works as expected. The worker EC2/ECS task must have `s3:GetObject` permission on the source bucket.

The `vod_s3_downloader.py` module must handle the case where `source_uri` is already an HTTPS presigned URL (some paths in `video_listing.py:914` may set `source_uri` to a local key without the `s3://` prefix). The `re.match(r"^s3://")` guard handles this correctly.
