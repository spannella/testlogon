# GAP-0010 Investigation: agent loop not running as background task

## Verdict

**Confirmed** — `app/services/agent_orchestrator.py:705` (`start_agent_loop()`)

`start_agent_loop()` sets `_running_loops[worker_id] = True` and updates DDB state but does not
spawn any asyncio coroutine. There is no `run_agent_loop` coroutine defined anywhere in the
codebase. The function's own docstring defers to "AGENT-006" but AGENT-006 (`terminal_monitor.py`,
`agent_feedback.py`) implements feedback signal detection and response injection — it does not
contain an autonomous ticket-pickup loop.

Relevant code at `app/services/agent_orchestrator.py:705–736`:

```python
def start_agent_loop(user_id: str, worker_id: str) -> Dict[str, Any]:
    """Mark the agent loop as started.

    The actual background task loop (run_agent_loop) is managed by
    AGENT-006. This function initializes state and marks the loop running.
    """
    ...
    _running_loops[worker_id] = True       # flag set in memory
    logger.info("agent.loop.started ...")
    return {"ok": True, "message": "Agent loop started. Will begin picking up eligible tickets."}
    # ^^^ no asyncio.create_task(), no coroutine spawned
```

A global search confirms: no function or coroutine named `run_agent_loop` exists anywhere under
`app/`. All other background loops in the codebase use `asyncio.create_task()` (e.g.,
`broadcast_scheduler.py:109`, `bot_scheduler.py:317`, `billing_dunning.py:302`, etc.). No such
call exists for the agent orchestrator.

The helper functions `find_next_ticket()`, `claim_ticket()`, `release_ticket()`, and
`complete_ticket()` all exist and are fully implemented. The autonomous loop that would call them
in sequence is simply absent.

## Root Cause

`start_agent_loop()` was written as a state-initialisation scaffold (AGENT-003 first pass). The
plan was for AGENT-006 to add the actual background coroutine, but AGENT-006 was scoped to
feedback/monitoring rather than autonomous ticket dispatch. The coroutine was never written.

## Exact Fix

Add a `run_agent_loop` async coroutine to `app/services/agent_orchestrator.py` and call
`asyncio.create_task()` from `start_agent_loop()`:

```python
import asyncio

async def run_agent_loop(user_id: str, worker_id: str) -> None:
    """Autonomous agent loop: pick up eligible tickets and work them."""
    logger.info("agent.loop.running worker_id=%s", worker_id)
    try:
        while worker_id in _running_loops:
            # 1. Check worker state — skip if paused/error
            worker = _get_worker_item(user_id, worker_id)
            if not worker or worker.get("agent_state") in ("paused", "error"):
                await asyncio.sleep(S.agent_loop_poll_interval_seconds)
                continue

            # 2. Find next eligible ticket
            ticket = find_next_ticket(user_id, worker_id)
            if not ticket:
                await asyncio.sleep(S.agent_loop_poll_interval_seconds)
                continue

            # 3. Claim and work ticket
            try:
                claim_ticket(user_id, worker_id, ticket["ticket_id"])
                transition_agent_state(user_id, worker_id, "working")
                # Dispatch to agent execution layer (AGENT-004)
                await _dispatch_ticket(user_id, worker_id, ticket)
            except ValueError:
                # Claim lost (race) — another worker got it
                pass
            except Exception:
                logger.exception("agent.loop.error worker_id=%s", worker_id)
                transition_agent_state(user_id, worker_id, "error")

            await asyncio.sleep(S.agent_loop_poll_interval_seconds)
    finally:
        _running_loops.pop(worker_id, None)
        logger.info("agent.loop.exited worker_id=%s", worker_id)


def start_agent_loop(user_id: str, worker_id: str) -> Dict[str, Any]:
    ...
    _running_loops[worker_id] = True
    asyncio.create_task(run_agent_loop(user_id, worker_id))   # <-- ADD THIS
    ...
```

Also add `agent_loop_poll_interval_seconds: int = 30` to `app/core/settings.py`.

## Blast Radius / Exploit

This is a functional gap rather than a security vulnerability. The impact is that agents marked
as "running" never autonomously pick up or process tickets. The `_running_loops` in-process dict
is also not distributed — on a multi-process/multi-instance deployment each process has its own
map and `is_loop_running()` returns `False` for workers started on other instances. The
`asyncio.create_task()` approach works correctly only for single-process (uvicorn `--workers 1`)
deployments; a production deployment would need a persistent queue (e.g., SQS) or a background
process.

## Dev/Prod Parity (SECOPS-007)

`asyncio.create_task()` is a standard Python async primitive. No AWS services are introduced.
`_running_loops` is an in-process dict — this is acceptable for dev (single uvicorn worker) but
must be replaced by a distributed lock/queue for production multi-instance deployments. A
SECOPS-007 note should be added to the implementation: the loop should be guarded by
`if workers == 1` or migrated to a background worker process before production deployment.

## Effort

**L** — Writing a correct and safe `run_agent_loop` coroutine requires careful handling of:
state machine transitions, claim races, error recovery, graceful shutdown, and the distributed
deployment concern (in-process dict vs. distributed lock). Scaffolding is ~50 lines but thorough
testing and the distributed-deployment aspect make this a larger effort than S/M tickets.
