# GAP-0032 Investigation: Admin can disburse treasury funds to their own wallet

**Verdict**: Confirmed — `app/services/syndicate_treasury.py:240-339`

---

## Confirmation against live code

### `disburse()` function (lines 240-339)
```python
def disburse(
    *,
    syndicate_id: str,
    admin_sub: str,
    recipient_user_id: str,
    amount_cents: int,
    note: str = "",
) -> Dict[str, Any]:
    """Admin disburses/withdraws treasury funds to a member's personal wallet."""
    # Admin-only.
    syndicate_svc._require_admin(syndicate_id, admin_sub)          # line 250

    if amount_cents <= 0:
        raise HTTPException(status_code=400, detail="Disbursement amount must be positive")

    # Recipient must be a member of the syndicate.
    syndicate = syndicate_svc._get_meta(syndicate_id)
    syndicate_svc._require_is_member(syndicate_id, recipient_user_id)  # line 257
    ...
```

**There is no check `if admin_sub == recipient_user_id`.**

### Why `_require_is_member` always passes for the admin

`app/services/syndicates.py:560-571`:
```python
def _require_admin(syndicate_id: str, user_id: str) -> None:
    meta = _get_meta(syndicate_id)
    if meta["admin_user_id"] != user_id:
        raise HTTPException(status_code=403, detail="Only the syndicate admin can perform this action")

def _require_is_member(syndicate_id: str, user_id: str) -> None:
    resp = T.syndicates.get_item(Key={"pk": f"SYND#{syndicate_id}", "sk": f"MEMBER#{user_id}"})
    if not resp.get("Item"):
        raise HTTPException(status_code=404, detail="User is not a member of this syndicate")
```

`app/services/syndicates.py:61-62` (create_syndicate):
```python
# Add creator as admin member
_add_member(syndicate_id, creator_sub, role="admin", ts=ts)
```

The creator is always added as `MEMBER#{admin_sub}`, so `_require_is_member(syndicate_id, admin_sub)` always returns without raising. Both guards pass for `recipient_user_id == admin_sub`.

### Attack path

1. Admin creates a syndicate; becomes both `admin_user_id` and `MEMBER#<admin_sub>`.
2. Members contribute funds; treasury balance grows.
3. Admin calls `POST /ui/syndicates/{id}/treasury/disburse` with `recipient_user_id = <admin_sub>`.
4. Both `_require_admin` and `_require_is_member` pass.
5. Treasury balance is debited, admin's personal wallet credited.
6. Admin has now unilaterally withdrawn all contributed funds to themselves.

---

## Root cause

The SYND-004 no-withdrawal constraint (admin cannot receive treasury disbursements) was documented in the ticket design but the one-liner guard `if admin_sub == recipient_user_id` was never added to the `disburse()` function. The two existing guards (`_require_admin` + `_require_is_member`) are necessary but insufficient; neither blocks self-disbursement.

---

## Exact fix (code-level)

In `app/services/syndicate_treasury.py`, add the self-disbursement guard immediately after the `_require_admin` call at line 250:

```python
def disburse(
    *,
    syndicate_id: str,
    admin_sub: str,
    recipient_user_id: str,
    amount_cents: int,
    note: str = "",
) -> Dict[str, Any]:
    """Admin disburses/withdraws treasury funds to a member's personal wallet."""
    # Admin-only.
    syndicate_svc._require_admin(syndicate_id, admin_sub)

    # Prevent admin from disbursing to themselves (no-withdrawal constraint).
    if admin_sub == recipient_user_id:
        raise HTTPException(
            status_code=400,
            detail="Admin cannot disburse treasury funds to themselves",
        )

    if amount_cents <= 0:
        ...
```

This is a one-line guard (plus the exception). No schema changes, no new tables.

---

## Blast radius / exploit

**Financial / trust integrity.** Any syndicate admin with at least one contributing member can drain the entire treasury to their own personal wallet in a single API call. The check is a simple equality comparison that is trivially absent. No rate limiting or secondary approval exists.

Severity is CRIT because:
- It is a direct financial theft vector against user funds held in trust.
- It requires no special tooling — just an authenticated API call from the admin account.
- The admin account can be the attacker (rogue admin) or can be compromised (account takeover).

No other paths in `syndicate_treasury.py` (`spend_on_advertising`, `contribute`) have this issue.

## Regression test

**pytest (offline):**
```python
def test_admin_cannot_disburse_to_self(client, syndicate_with_balance):
    syndicate_id, admin_sub, _ = syndicate_with_balance
    r = client.post(
        f"/ui/syndicates/{syndicate_id}/treasury/disburse",
        json={"recipient_user_id": admin_sub, "amount_cents": 100},
        ...  # admin session headers
    )
    assert r.status_code == 400
    assert r.json()["detail"] == "Admin cannot disburse treasury funds to themselves"

def test_admin_can_disburse_to_member(client, syndicate_with_balance):
    syndicate_id, admin_sub, member_sub = syndicate_with_balance
    r = client.post(
        f"/ui/syndicates/{syndicate_id}/treasury/disburse",
        json={"recipient_user_id": member_sub, "amount_cents": 50},
        ...
    )
    assert r.status_code == 200
```

Fails before: admin→self disbursement returns 200, treasury drained.
Passes after: admin→self returns 400.
