# GAP-0003 Investigation: internal charge endpoints lack access control

**Verdict**: Confirmed

---

## Evidence

`app/routers/ads.py` lines 447–483 — three `POST /ui/ads/internal/charge-*` endpoints are protected only by `require_ui_session` (any authenticated user):

```python
@router.post("/internal/charge-impression")
async def internal_charge_impression(body: dict, ctx=Depends(require_ui_session)):
    from app.services.ad_billing import charge_impression
    return charge_impression(
        account_id=body["account_id"],
        campaign_id=body["campaign_id"],
        ...
    )

@router.post("/internal/charge-click")
async def internal_charge_click(body: dict, ctx=Depends(require_ui_session)):
    from app.services.ad_billing import charge_click
    return charge_click(
        account_id=body["account_id"],
        ...
    )

@router.post("/internal/charge-conversion")
async def internal_charge_conversion(body: dict, ctx=Depends(require_ui_session)):
    from app.services.ad_billing import charge_conversion
    return charge_conversion(
        account_id=body["account_id"],
        ...
    )
```

The caller supplies `account_id` and `campaign_id` in the request body. Neither the router nor the service validates that the calling user owns the account. Contrast with other account-scoped endpoints in the same file (e.g., `invoice_endpoint` at line 438) which call `_require_account_owner(account_id, ctx["user_sub"])` before proceeding.

The `_require_account_owner` helper exists at line 60:

```python
def _require_account_owner(account_id: str, user_sub: str) -> dict:
    acct = get_ad_account(account_id)
    if not acct or acct["owner_sub"] != user_sub:
        raise HTTPException(status_code=404, detail="Account not found")
    return acct
```

It is not called by any of the three charge endpoints.

---

## Root Cause

The three `/internal/charge-*` endpoints were written as internal-use helpers (intended to be called only by trusted server-side code) but were registered under the public `/ui/ads/` prefix with only session auth. Any authenticated user can POST arbitrary `account_id` values to trigger charges against any advertiser's balance.

---

## Exact Fix

**Option A (preferred for internal-only calls):** Move the endpoints to `admin_router` and add `require_admin_or_root`:

```python
@admin_router.post("/internal/charge-impression")
async def internal_charge_impression(
    body: dict,
    user: AuthenticatedUser = Depends(require_admin_or_root),
):
    ...
```

**Option B (if the endpoints must be user-accessible):** Add ownership verification before each call:

```python
@router.post("/internal/charge-impression")
async def internal_charge_impression(body: dict, ctx=Depends(require_ui_session)):
    _require_account_owner(body["account_id"], ctx["user_sub"])
    ...
```

Option A is stronger because it restricts to admin/root entirely, preventing any abuse. Option B still allows a legitimate account owner to trigger charges, which may be intentional (e.g., for manual testing flows).

---

## Blast Radius / Exploit

An authenticated user (any registered account) can POST:

```json
{"account_id": "<victim_account_id>", "campaign_id": "<any_campaign_id>", "bid_cpm_cents": 99999}
```

to `/ui/ads/internal/charge-impression` and debit the victim's ad account balance to zero. Repeated calls can drain any advertiser's balance. No rate limiting, no ownership check.

## Regression Test

**pytest (offline)**

```python
# tests/test_ads_charge_authz.py
def test_charge_impression_requires_ownership(client, alice_session, bob_account_id, bob_campaign_id):
    # Alice tries to charge Bob's account
    resp = client.post(
        "/ui/ads/internal/charge-impression",
        json={"account_id": bob_account_id, "campaign_id": bob_campaign_id},
        cookies=alice_session,
        headers={"x-csrf-token": alice_session["csrf_token"]},
    )
    assert resp.status_code in (403, 404)
```

Before fix: returns `200` and debits Bob's account.
After fix: returns `403` or `404` (depending on chosen option).

## Dev/Prod Parity (SECOPS-007)

Both `require_admin_or_root` and `_require_account_owner` use the same `require_ui_session` dependency that works identically in dev (cookie/JWT) and production (Cognito JWT). No parity gap.
