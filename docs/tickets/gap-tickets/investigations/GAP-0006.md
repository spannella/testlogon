# GAP-0006 Investigation: legacy record_ad_impression() has no fraud check

## Verdict

**Confirmed** — `app/services/ad_placement.py:233`

The `record_ad_impression()` function takes no `ip_address`, `user_agent`, or `view_time_ms`
parameters and makes no call to `app.services.ad_fraud_prevention.check_fraud()` before
crediting creator revenue. The fraud service and `check_fraud()` function both exist (see
`app/services/ad_fraud_prevention.py:115`) and are called from `app/services/ad_serving.py:198`
for VOD ad serving — but that path is not used for impression events submitted by the player
via `POST /ui/videos/{id}/ad-impression`.

Relevant code at `app/services/ad_placement.py:233–287`:

```python
def record_ad_impression(
    *,
    video_id: str,
    user_id: str,
    slot_type: str,
    slot_index: int,
    creative_id: str = "",
    event_type: str = "impression",  # "impression" | "complete" | "skip"
) -> Dict[str, Any]:
    ...
    # On complete: credit creator with ad revenue  ← no fraud gate before this
    if event_type == "complete":
        _credit_ad_revenue(video_id=video_id, event_id=event_id, ts=ts)
```

No `check_fraud()` call exists anywhere in this function. The signature also lacks
`ip_address`/`user_agent`/`view_time_ms` so the caller cannot forward those signals.

## Root Cause

`record_ad_impression()` was implemented as a lightweight tracking helper (CREATOR-003/ADS-014
first pass) before `ad_fraud_prevention.py` existed.  The fraud service was added later for the
`serve_ad()` path but was never retrofitted into the impression-recording path.

## Exact Fix

1. Add `ip_address: str = ""`, `user_agent: str = ""`, `view_time_ms: int = 0` parameters to
   `record_ad_impression()` in `app/services/ad_placement.py:233`.
2. At the top of the function body (before writing to `T.ad_impressions`), add:

```python
if getattr(S, "ad_fraud_detection_enabled", True):
    try:
        from app.services import ad_fraud_prevention as fraud
        result = fraud.check_fraud(
            account_id=user_id,
            event=event_type,
            creative_id=creative_id,
            ip_address=ip_address,
            user_agent=user_agent,
            view_time_ms=view_time_ms,
        )
        if result.get("action") == "block":
            return {"ok": False, "event_id": "", "blocked": True, "reason": result.get("reason")}
    except Exception:
        logger.warning("ad_fraud_check_failed video=%s user=%s", video_id, user_id)
```

3. Update the router/caller (`POST /ui/videos/{id}/ad-impression` handler) to forward
   `request.client.host`, `request.headers.get("user-agent")`, and a `view_time_ms` body field.

## Blast Radius / Exploit

Any authenticated user can fire unlimited `POST /ui/videos/{id}/ad-impression` requests with
`event_type="complete"` for any `video_id`. Each call credits `max(1, cpm//1000)` cents (default
at $5 CPM = 0 cents floored to 1 cent) to the video owner's ledger via `_credit_ad_revenue()`.
With the default CPM of 500 (`DEFAULT_CPM_CENTS`) that is `max(1, 500//1000) = 1 cent` per call.
An attacker can also set `video_id` to a video they own, generating unbounded ad revenue credits.
There is no rate limit on the impression endpoint either.

## Dev/Prod Parity (SECOPS-007)

`T.ad_impressions` and `T.ad_fraud_events` are both DynamoDB tables present in both dev
(DynamoDB Local) and production. No AWS-specific path is introduced by this fix.
The `check_fraud()` function already handles dev mode gracefully (no external calls).

## Effort

**S** — Adding three optional parameters + a guarded `check_fraud()` call at the top of one
function. The fraud service already exists. Router change is minimal.
