# GAP-0028 Investigation: POST /feed/record accepts arbitrary user_id (SEC-005 cross-ref)

## Verdict

**Confirmed** — `app/routers/activity_feed.py:148–170` exactly as described.

```python
# app/routers/activity_feed.py:148–166
@router.post("/feed/record")
def record_activity(
    body: RecordActivityIn,
    session=Depends(require_ui_session),
):
    item = activity_feed_service.record_activity(
        user_id=body.user_id,          # ← caller-controlled; session["user_sub"] never checked
        actor_id=body.actor_id,
        activity_type=body.activity_type,
        target_type=body.target_type,
        target_id=body.target_id,
        metadata=body.metadata,
    )
```

`require_ui_session` is present, so the caller must be authenticated, but the handler passes
`body.user_id` (fully caller-controlled) directly to `record_activity()` with no ownership check.
No admin-role gate is present.  The session's `user_sub` is extracted but never compared to
`body.user_id`.

## Root Cause

The endpoint was likely written as a testing/internal utility ("for testing/internal use" is
stated in the docstring) without the ownership guard that should gate any write on behalf of a
specific user.

## Exact Fix

Replace line 158–159 in `app/routers/activity_feed.py`:

```python
# Before:
    item = activity_feed_service.record_activity(
        user_id=body.user_id,

# After:
    item = activity_feed_service.record_activity(
        user_id=session["user_sub"],   # always use authenticated identity
```

If an admin injection path is required for test/debug purposes, add a separate admin endpoint:

```python
@router.post("/feed/record")  # existing endpoint — scoped to session user
def record_activity(body: RecordActivityIn, session=Depends(require_ui_session)):
    item = activity_feed_service.record_activity(
        user_id=session["user_sub"], ...
    )

@admin_router.post("/feed/record")  # new admin endpoint
def admin_record_activity(body: RecordActivityIn, session=Depends(require_admin_session)):
    item = activity_feed_service.record_activity(
        user_id=body.user_id, ...  # admin may specify arbitrary user_id
    )
```

## Blast Radius / Exploit

Any authenticated user can inject forged activity items into any other user's feed:

- Flood a target user's feed with noise to degrade UX.
- Impersonate actors: craft `actor_id` = user A, `user_id` = user B → appears as though user A
  followed/tipped/liked something on user B's feed.
- Manipulate social metrics, mislead aggregated analytics, or trigger notification spam.

No privilege escalation or data exfiltration, but the IDOR allows cross-user data corruption.
