## Root cause

The SIGN-001 ticket specified a two-step "add signer → send" flow (§2.1). The store and router for managing signer records were never implemented. The `add_packet_signer` service function and the `POST /{packet_id}/signers` / `DELETE /{packet_id}/signers/{signer_id}` route handlers are completely absent. The `send` endpoint assumes signers exist but provides no way to create them.

---

## Exact fix (code-level)

**1. `app/services/signature_packet_store.py` — add helper:**
```python
def add_packet_signer(
    *,
    packet_id: str,
    signer_id: str,
    email: str | None = None,
    required: bool = True,
) -> Dict[str, Any]:
    require_signature_pdf_enabled()
    _ensure_packet_draft(packet_id)
    now = datetime.now(timezone.utc).isoformat()
    item: Dict[str, Any] = {
        "packet_id": packet_id,
        "signer_id": signer_id,
        "status": SignatureSignerStatus.PENDING.value,
        "status_key": signer_status_sort_key(SignatureSignerStatus.PENDING, packet_id),
        "required": required,
        "added_at": now,
        "updated_at": now,
    }
    if email:
        item["email"] = email
    T.signature_packet_signers.put_item(Item=item)
    return item


def remove_packet_signer(*, packet_id: str, signer_id: str) -> None:
    require_signature_pdf_enabled()
    _ensure_packet_draft(packet_id)
    T.signature_packet_signers.delete_item(
        Key={"packet_id": packet_id, "signer_id": signer_id}
    )
```

**2. `app/routers/signature_packets.py` — add endpoint models and handlers:**
```python
class AddSignerIn(BaseModel):
    signer_id: str = Field(..., min_length=1, max_length=256)
    email: Optional[str] = Field(default=None, max_length=256)
    required: bool = True

class AddSignerOut(BaseModel):
    packet_id: str
    signer_id: str
    status: str
    required: bool
    added_at: str

@router.post("/{packet_id}/signers", response_model=AddSignerOut)
def add_signer(packet_id: str, inp: AddSignerIn, user_sub: str = Depends(_current_user)):
    _validate_packet_owner_and_draft(packet_id, user_sub)
    signer = add_packet_signer(packet_id=packet_id, signer_id=inp.signer_id,
                               email=inp.email, required=inp.required)
    append_packet_event(packet_id=packet_id, actor_user_id=user_sub,
                        event_type="signer_added",
                        event_payload={"signer_id": inp.signer_id, "required": inp.required})
    return {"packet_id": packet_id, "signer_id": inp.signer_id,
            "status": signer["status"], "required": inp.required,
            "added_at": signer["added_at"]}

@router.delete("/{packet_id}/signers/{signer_id}", status_code=204)
def remove_signer(packet_id: str, signer_id: str, user_sub: str = Depends(_current_user)):
    _validate_packet_owner_and_draft(packet_id, user_sub)
    remove_packet_signer(packet_id=packet_id, signer_id=signer_id)
    append_packet_event(packet_id=packet_id, actor_user_id=user_sub,
                        event_type="signer_removed",
                        event_payload={"signer_id": signer_id})
```

Also update imports in `signature_packets.py` to include `add_packet_signer`, `remove_packet_signer`.

---

## Blast radius / exploit

A valid user who creates a signature packet is completely blocked at the `POST /{packet_id}/send` step because `list_packet_signers(packet_id)` will always return `[]`. The entire e-signature send flow is dead for any normal user. The only workaround is direct DynamoDB injection (dev/E2E only). This is a **complete functional blocker** for SIGN-001 as a feature.

No security exploit — the missing endpoint is additive, not a bypass.
