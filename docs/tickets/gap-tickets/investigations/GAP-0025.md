# GAP-0025 Investigation: Webhook `secret` is stored in plaintext in DynamoDB

## Verdict

**Partially confirmed** — the plaintext storage is real and confirmed in
`app/services/kyc_partner_api.py:543`, but the ticket description is misleading
because the general-purpose `webhook_service.py` already uses KMS encryption.
The bug is scoped to the KYC partner API's separate webhook registration path.

### General webhook service: ALREADY FIXED (uses KMS)

`/home/ubuntu/testlogon/app/services/webhook_service.py:245-250` and `:494-496`:
```python
# create_endpoint():
try:
    encrypted_secret = kms_encrypt(plaintext_secret)
except Exception:
    encrypted_secret = f"PLAIN:{plaintext_secret}"   # dev-mode fallback only

# rotate_secret():
try:
    encrypted_secret = kms_encrypt(plaintext_secret)
except Exception:
    encrypted_secret = f"PLAIN:{plaintext_secret}"
```
The general webhook service encrypts secrets with KMS and only falls back to `PLAIN:`
prefix in dev mode when KMS is unavailable. `_decrypt_secret()` at line 506-510 handles
both formats. This service is NOT the bug.

### KYC partner API webhook registration: CONFIRMED PLAINTEXT

`/home/ubuntu/testlogon/app/services/kyc_partner_api.py:534-546`:
```python
T.kyc_cases.put_item(
    Item={
        "pk": _partner_pk(partner_id),
        "sk": _wh_sk(webhook_id),
        "entity_type": "kyc_partner_webhook",
        "webhook_id": webhook_id,
        "partner_id": partner_id,
        "url": str(url),
        "events": list(events),
        "secret": str(secret),          # <-- plaintext, no KMS encryption
        "created_at": ts,
    }
)
```

The `secret` is stored verbatim in the `kyc_cases` DynamoDB table. There is no
corresponding `_decrypt_secret()` helper in `kyc_partner_api.py`.

The `_emit_callback()` function at lines 615-625 does not directly read the secret from
DynamoDB — it delegates to `kyc_webhooks.emit_kyc_event`, which routes through
`webhook_service.dispatch_webhook_event`. The partner-stored secret is therefore not
currently used for HMAC signing of outbound calls (a separate gap). However, the
plaintext secret is readable by anyone with DynamoDB read access and is returned
implicitly if the item is ever fetched and serialised without redaction.

Also note: `list_webhooks()` at line 550-568 does NOT redact the secret from the
returned items — it filters only on `entity_type`. If the router exposes a list
endpoint, callers would receive the plaintext secret.

## Root Cause

The KYC partner API (`kyc_partner_api.py`) was implemented independently of
`webhook_service.py` and did not reuse its encryption utilities. The `secret` field was
treated as an opaque string passed through by the partner, rather than a sensitive
credential requiring encryption at rest.

## Exact Fix

In `/home/ubuntu/testlogon/app/services/kyc_partner_api.py`, update `register_webhook()`:

```python
def register_webhook(principal, *, url, events, secret):
    # ... validation unchanged ...

    # Encrypt secret before storage
    from app.core.crypto import kms_encrypt
    try:
        stored_secret = kms_encrypt(secret)
    except Exception:
        stored_secret = f"PLAIN:{secret}"   # dev-mode fallback (KMS mock unavailable)

    T.kyc_cases.put_item(
        Item={
            ...
            "secret": stored_secret,         # encrypted
            ...
        }
    )
    # Return WITHOUT exposing stored_secret; plaintext shown only at registration time
    return {"webhook_id": webhook_id, "url": str(url), "events": list(events),
            "created_at": ts, "secret": secret}   # one-time plaintext exposure OK here
```

Add a `_decrypt_kyc_partner_secret(stored)` helper mirroring `webhook_service._decrypt_secret()`:
```python
def _decrypt_kyc_partner_secret(stored: str) -> str:
    from app.core.crypto import kms_decrypt
    if stored.startswith("PLAIN:"):
        return stored[6:]
    return kms_decrypt(stored).decode("utf-8")
```

Also update `list_webhooks()` to strip the secret from the returned items (or redact it
to `has_secret: True`), and any read path that fetches webhook items.

## Blast Radius / Exploit

- Any IAM principal, internal service, or attacker with DynamoDB read access to the
  `kyc_cases` table can query `pk BEGINS_WITH "KYCPARTNER#"` and read all partner
  webhook secrets in plaintext.
- Secrets are used (or intended to be used) for HMAC-SHA256 signing of outbound
  webhook deliveries. An exfiltrated secret allows an attacker to forge webhook
  payloads to the partner's endpoint, spoofing KYC status changes (e.g., forging
  `kyc.case.approved` events to grant access without real KYC).
- The `kyc_cases` table also contains KYC case data, PII, and document metadata;
  a DynamoDB compromise simultaneously exposes secrets and sensitive user data.

## Cross-reference SEC-022

SEC-022 establishes the project-wide policy that secrets must be encrypted at rest
using KMS. This gap is a direct SEC-022 violation in the KYC partner API's webhook
registration path.

## Dev/Prod Parity

The `kms_encrypt` / `kms_decrypt` utilities in `app/core/crypto.py` already proxy to
the mock KMS server (port 7999) in dev mode. The `PLAIN:` fallback (already used in
`webhook_service.py`) handles the case where the KMS mock is not running. No new
infrastructure needed. In production, real AWS KMS is used.
