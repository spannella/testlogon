# GAP-0022 Investigation: SSRF via SEC-020 — SSH Bastion hop validation

## Verdict

**Confirmed** — `/home/ubuntu/testlogon/app/services/ssh_bastion.py:65-83`

`validate_host()` accepts and normalises RFC-1918 / loopback / link-local IP addresses.
The function uses `ipaddress.ip_address(host)` to normalise but never calls
`.is_private()`, `.is_loopback()`, or `.is_link_local()` on the result:

```python
# app/services/ssh_bastion.py:65-83
def validate_host(host: str) -> str:
    host = (host or "").strip()
    if not host:
        raise InvalidHop("hostname is required")
    if len(host) > 253:
        raise InvalidHop("hostname too long")
    # Try IP literal first.
    try:
        return str(ipaddress.ip_address(host))   # normalises but never checks is_private()
    except ValueError:
        pass
    if _HOSTNAME_RE.match(host):
        return host.lower()                      # hostname regex passes any RFC-1123 name
    raise InvalidHop(f"invalid hostname or IP: {host}")
```

A bastion path stored with `hop.hostname = "169.254.169.254"`, `"127.0.0.1"`, or
`"10.0.0.1"` will pass validation without error. `_normalize_hop()` calls
`validate_host()` and returns the hop unchanged.

**Note on scope vs SEC-020**: SEC-020 targets `browser_ssh_terminal.py`'s
`_enforce_destination_policy()` (which IS confirmed allow-all by default when
`BROWSER_SSH_ALLOWED_HOSTS` / `BROWSER_SSH_DENIED_HOSTS` are unset). This GAP-0022
targets the separate `ssh_bastion.py` service which manages *stored* multi-hop paths —
a distinct attack surface where an authenticated user can persist a path containing
private-IP hops and distribute or trigger it later. Both issues are real and
independent.

A companion SSRF guard (`webhook_ssrf.py`) was properly implemented for the webhook
service with a full `_BLOCKED_NETWORKS` list, but this pattern was never applied to
`ssh_bastion.py`.

## Root Cause

`ssh_bastion.py` was implemented before `webhook_ssrf.py` existed (or without referencing
it). The `validate_host()` function was scoped to input sanitisation (format/length) and
was never extended to include a private-IP denylist. No hardcoded denylist exists in the
bastion service or its router.

## Exact Fix

In `/home/ubuntu/testlogon/app/services/ssh_bastion.py`, extend `validate_host()`:

```python
import ipaddress  # already imported

_PRIVATE_NETWORKS = [
    ipaddress.ip_network("10.0.0.0/8"),
    ipaddress.ip_network("172.16.0.0/12"),
    ipaddress.ip_network("192.168.0.0/16"),
    ipaddress.ip_network("127.0.0.0/8"),
    ipaddress.ip_network("169.254.0.0/16"),   # link-local / AWS metadata
    ipaddress.ip_network("0.0.0.0/8"),
    ipaddress.ip_network("100.64.0.0/10"),
    ipaddress.ip_network("::1/128"),
    ipaddress.ip_network("fe80::/10"),
    ipaddress.ip_network("fc00::/7"),
]

def validate_host(host: str) -> str:
    host = (host or "").strip()
    if not host:
        raise InvalidHop("hostname is required")
    if len(host) > 253:
        raise InvalidHop("hostname too long")
    try:
        addr = ipaddress.ip_address(host)
        for net in _PRIVATE_NETWORKS:
            if addr in net:
                raise InvalidHop(f"hop targets a private/reserved address: {host}")
        return str(addr)
    except InvalidHop:
        raise
    except ValueError:
        pass
    # Hostname: DNS-rebinding guard — resolve and check
    import socket
    if _HOSTNAME_RE.match(host):
        try:
            for info in socket.getaddrinfo(host, None):
                ip = ipaddress.ip_address(info[4][0])
                for net in _PRIVATE_NETWORKS:
                    if ip in net:
                        raise InvalidHop(
                            f"hostname {host} resolves to private/reserved address {ip}"
                        )
        except InvalidHop:
            raise
        except OSError:
            pass  # DNS failure at storage time is acceptable; re-validate at connect time
        return host.lower()
    raise InvalidHop(f"invalid hostname or IP: {host}")
```

## Blast Radius / Exploit

An authenticated user can call `POST /ssh-bastion/paths` to persist a path with
`jump_hops[0].hostname = "169.254.169.254"` (AWS instance metadata endpoint) or
`"127.0.0.1"` (backend loopback services). When the SSH client later calls
`GET /ssh-bastion/paths/{id}/config` to build a `ProxyJump` ssh_config, the hop is
emitted verbatim. If a real SSH client or the `MultiHopSshBridge` follows that config,
it dials the metadata endpoint / internal network from the backend's network context.
On AWS this yields IAM role credentials (`/latest/meta-data/iam/security-credentials/`),
enabling full account takeover.

## Regression Test

**pytest (offline)**:
```python
# tests/test_ssh_bastion_ssrf.py
import pytest
from app.services.ssh_bastion import validate_host, InvalidHop

@pytest.mark.parametrize("host", [
    "169.254.169.254",
    "127.0.0.1",
    "10.0.0.1",
    "192.168.1.1",
    "172.16.0.1",
    "::1",
    "0.0.0.0",
])
def test_validate_host_rejects_private_ips(host):
    with pytest.raises(InvalidHop, match="private/reserved"):
        validate_host(host)

def test_validate_host_accepts_public_ip():
    assert validate_host("8.8.8.8") == "8.8.8.8"
```
All parametrize cases fail (no `InvalidHop` raised) before fix; all pass after.

## Dev/Prod Parity

SSH bastion paths are stored in DynamoDB (local or AWS) and the hop validation runs on
the backend server. On AWS the metadata endpoint `169.254.169.254` is reachable from
the EC2 instance running the backend. The fix is purely server-side Python; no new AWS
services are required.
