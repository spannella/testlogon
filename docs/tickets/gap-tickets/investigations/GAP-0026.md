# GAP-0026 Investigation: Revenue split hooks absent from qualifying billing flows

## Verdict

**Confirmed** — `process_revenue_split` exists in `app/services/license_revenue.py:82` but is
called from only one location: the admin/debug `POST /process-split` endpoint in
`app/routers/license_revenue.py:150`.  It is **never called automatically** from any of the
three primary billing flows that generate revenue for licensed content:

1. **Messaging tip** (`send_message_tip`, `app/routers/messaging.py:13461`) — writes
   `TipLedgerEntry` and an invoice but makes no call to `process_revenue_split`.
2. **Messaging unlock** (`unlock_message`, `app/routers/messaging.py:13592`) — writes raw DDB
   ledger debit/credit entries (lines 13647–13687) but makes no call to `process_revenue_split`.
3. **Newsfeed post tip/unlock** (`app/routers/newsfeed.py`) — confirmed no import or call to
   `process_revenue_split` anywhere in the file.

There is no VOD purchase router call either (searched across all `app/routers/*.py`).

## Root Cause

`process_revenue_split` was built as a standalone utility and exposed as a test endpoint, but the
integration hooks connecting it to live billing events were never added.  The `license_revenue`
service is self-contained and no other service imports it at transaction time.

## Exact Fix

In each billing handler, after the primary ledger write completes, add a best-effort call:

```python
# app/routers/messaging.py — send_message_tip (~line 13531, after write_tip_ledger)
try:
    from app.services import license_revenue as _lr_svc
    _lr_svc.process_revenue_split(
        content_id=message_id,
        licensee_id=user_id,
        source_type="tip",
        source_amount_cents=inp.amount_cents,
        source_txn_id=tip_payment_id,
        currency=str(inp.currency or "usd").lower(),
    )
except Exception:
    logger.warning("license revenue split failed for tip on message %s", message_id)

# app/routers/messaging.py — unlock_message (~line 13689, after ledger writes)
try:
    from app.services import license_revenue as _lr_svc
    _lr_svc.process_revenue_split(
        content_id=message_id,
        licensee_id=user_id,
        source_type="unlock",
        source_amount_cents=amount_cents,
        source_txn_id=unlock_payment_id,
        currency="usd",
    )
except Exception:
    logger.warning("license revenue split failed for unlock on message %s", message_id)
```

Equivalent hooks are needed in the newsfeed post tip handler and any VOD purchase path.

## Blast Radius / Exploit

**Financial**: Licensors who registered content license terms via `register_content_license` never
receive revenue-share credits on tips or unlocks.  Licensees are not debited their contractual
share.  The discrepancy is invisible to both parties and to platform audit reports.

No security exploit — this is a revenue leakage bug.

The `license_revenue` table exists in both environments (created by `scripts/local-ddb-init.py`).
The fix touches no AWS-specific paths — `process_revenue_split` uses only DynamoDB via `T`
handles, which already follow the dev/prod parity rules.
