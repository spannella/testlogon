## Root cause

The VOD-005 implementation wrote the output metadata to `transcode_jobs` (for job status tracking) but never wrote the same data back to `video_metadata` (for video playback). The `transition_video_status` helper only handles the status state machine; it was never extended to accept and store output URLs. The two tables were never linked in the completion path.

## Exact fix (code-level)

**Option A (preferred): extend `transition_video_status` to accept output data:**
```python
# app/services/video_metadata_store.py
def transition_video_status(
    *,
    video_id: str,
    to_status: str,
    reason: str = "",
    actor: str = "",
    hls_manifest_url: str | None = None,
    thumbnail_url: str | None = None,
    renditions: list[dict] | None = None,
) -> VideoMetadataModel:
    current = get_video(video_id)
    ...
    update_data: Dict[str, Any] = {"status": to_status, "updated_at": ts}
    if to_status == "published" and current.published_at is None:
        update_data["published_at"] = ts
    if hls_manifest_url is not None:
        update_data["hls_manifest_url"] = hls_manifest_url
    if thumbnail_url is not None:
        update_data["thumbnail_url"] = thumbnail_url
    if renditions is not None:
        update_data["renditions"] = renditions
    updated = current.model_copy(update=update_data)
    T.video_metadata.put_item(Item=video_to_item(updated))
    return updated
```

**Caller update in `transcode_worker.py:199-205`:**
```python
from app.services.video_metadata_store import transition_video_status
transition_video_status(
    video_id=job["video_id"],
    to_status="published",
    hls_manifest_url=upload_result.manifest_s3_uri,
    thumbnail_url=upload_result.thumbnail_s3_keys[0] if upload_result.thumbnail_s3_keys else None,
    renditions=[{"name": r} for r in completed_renditions],
)
```

Note: In production `hls_manifest_url` should be the CloudFront/CDN URL, not the raw `s3://` URI. The `playback_url.url` field from `mint_vod_playback_url` is the correct public-facing URL to store.

**Corrected caller:**
```python
transition_video_status(
    video_id=job["video_id"],
    to_status="published",
    hls_manifest_url=playback_url.url,          # signed CDN URL
    thumbnail_url=(upload_result.thumbnail_s3_keys or [None])[0],
    renditions=[{"name": r} for r in completed_renditions],
)
```

## Blast radius / exploit

Every transcoded video is permanently unplayable via the standard `GET /ui/videos/{video_id}` → `hls_manifest_url` field. The frontend HLS player receives `null` for the manifest URL and cannot load the video. The video appears as "published" in listings but always fails to play.

No security exploit. This is a complete functional outage for video playback.

Secondary effects:
- Thumbnail images are never linked; video cards show no preview.
- Rendition quality ladder is unavailable to the player for ABR switching.

## Dev/prod parity

`playback_url.url` from `mint_vod_playback_url` in dev mode returns a dev-mode URL (e.g., `http://localhost:8000/ui/videos/{video_id}/playback`). In prod it returns a CloudFront signed URL. Either way, it is the correct public-facing HLS manifest URL to store in `video_metadata`.

`upload_result.thumbnail_s3_keys` contains raw S3 keys; in dev mode the `_message_out_from_item` pattern of converting to `/mock/s3/...` URLs applies. For the thumbnail in `video_metadata`, store the S3 key and convert to a URL at read time (consistent with the file manager pattern), or use the `/mock/s3/` path in dev.
