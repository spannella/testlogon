# GAP-0001 Investigation: no daily spent_today_cents reset task

**Verdict**: Confirmed

---

## Evidence

`app/services/ad_serving.py` lines 310–320 — `_has_budget()` reads `spent_today_cents` from the campaign record and compares it against `daily_budget_cents`:

```python
def _has_budget(campaign: dict) -> bool:
    budget = int(campaign.get("budget_cents", 0))
    spent = int(campaign.get("lifetime_spent_cents", 0))
    if campaign.get("budget_type") == "lifetime" and spent >= budget:
        return False
    if campaign.get("budget_type") == "daily":
        daily_spent = int(campaign.get("spent_today_cents", 0))
        daily_budget = int(campaign.get("daily_budget_cents", budget))
        if daily_spent >= daily_budget:
            return False
    return True
```

`app/services/ad_billing.py` line 136 increments `spent_today_cents` on every impression/click/conversion charge — this field accumulates across calendar days and is never zeroed.

A search across `app/` for any reset logic confirms no background task, cron, or startup handler resets `spent_today_cents`:

- `grep -rn "spent_today_cents" app/` returns only lines in `ad_serving.py`, `ad_billing.py`, `ad_optimization.py` (read/write), and `ad_campaigns.py` (initial creation set to 0).
- `app/main.py` registers ~20 startup background tasks; none references `spent_today_cents` or any daily ad-budget reset.

---

## Root Cause

`spent_today_cents` is written on every charge (`ad_billing.py:136`) but never reset at day rollover. After the first day's daily budget is exhausted, `_has_budget()` permanently returns `False` for that campaign, halting all ad serving for it.

---

## Exact Fix

Add a new async background task (e.g., `app/services/ad_daily_reset.py`) that:

1. Scans `T.ad_campaigns` for all campaigns with `budget_type = "daily"` and `spent_today_cents > 0`.
2. Sets `spent_today_cents = 0` for each using `update_item`.
3. Loops with `asyncio.sleep` aligned to midnight UTC (compute seconds until next midnight on each iteration).

Wire it in `app/main.py`:

```python
app.add_event_handler("startup", start_ad_daily_reset_task)
```

The check/reset must happen once per UTC day, not once per process start, so the loop must calculate sleep duration to the next UTC midnight.

---

## Blast Radius / Exploit

Any campaign with `budget_type = "daily"` is permanently suppressed after exhausting its first day's budget. All subsequent calls to `serve_ad()` will skip the campaign via `_has_budget()` returning `False`. Revenue impact: platform and creators lose all ad revenue from daily-budget campaigns after day 1; advertisers are effectively blocked from spend without refund or notification.
