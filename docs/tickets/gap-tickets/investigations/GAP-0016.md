# GAP-0016 Investigation: `useCallBillingHeartbeat.ts` hook does not exist

**Date**: 2026-06-05
**Investigator**: Claude Code

---

## Verdict

**Confirmed** — `useCallBillingHeartbeat.ts` does not exist as a dedicated hook file. The backend heartbeat endpoint and the `sendCallHeartbeat` API wrapper both exist, but no component or hook calls them during an active paid call.

---

## Evidence

### What exists

- **Backend endpoint**: `PATCH /messaging/messages/calls/{call_id}/heartbeat` is fully implemented at `app/routers/call_billing.py:148`. It calls `app/services/call_billing_timer.py:process_heartbeat()` and can return `action="end_call"` when balance is depleted.
- **Frontend API wrapper**: `frontend/src/api/endpoints/callBilling.ts:70` exports `sendCallHeartbeat(callId)` which issues the correct PATCH request.
- **Backend response**: `HeartbeatOut` (defined at `app/routers/call_billing.py:47`) contains `next_bill_in_seconds`, `warn_low_balance`, `minutes_remaining`, `action`, `balance_remaining_cents` — all fields a heartbeat hook would need.
- **Display components**: `CallBillingOverlay.tsx` and `CallBillingSummary.tsx` exist and accept the right props, but neither mounts itself nor triggers heartbeats.

### What is missing

No file in `frontend/src/hooks/` matches `useCallBillingHeartbeat*`:

```
frontend/src/hooks/
  useAlertStream.ts
  useBroadcastStream.ts
  useCallRecording.ts
  useConnectionQuality.ts
  ...
  useViewerHeartbeat.ts   ← presence heartbeat, unrelated
  (no useCallBillingHeartbeat.ts)
```

Searching all `.ts`/`.tsx` files for `sendCallHeartbeat` or `heartbeat_interval` yields only the definition in `callBilling.ts` — no call site. `CallSessionOverlay.tsx` (the connected-call UI, lines 130-148) runs a timer via `setInterval` for elapsed seconds but never calls `sendCallHeartbeat`.

---

## Root Cause

The CALL-011 implementation delivered the backend billing engine and the API wrapper but did not implement the frontend heartbeat scheduling loop. Without periodic heartbeats:

1. `process_heartbeat` is never called during a call, so per-minute billing cycles never fire mid-call.
2. `finalize_call_billing` at call end must bill the entire duration in one shot, which can exceed the caller's wallet balance and fail silently.
3. The `action="end_call"` enforcement path in the heartbeat endpoint is never triggered — low-balance calls run until they are manually ended.

---

## Exact Fix

Create `frontend/src/hooks/useCallBillingHeartbeat.ts`:

```typescript
import * as React from "react";
import { sendCallHeartbeat } from "@/api/endpoints/callBilling";
import type { HeartbeatResponse } from "@/api/endpoints/callBilling";

interface UseCallBillingHeartbeatOptions {
  callId: string | null;
  enabled: boolean;            // only true when call state === "connected" && paid
  intervalSeconds?: number;    // default 30; use next_bill_in_seconds from response
  onEndCall?: (reason: string) => void;
  onLowBalance?: (minutesRemaining: number) => void;
}

export function useCallBillingHeartbeat({
  callId,
  enabled,
  intervalSeconds = 30,
  onEndCall,
  onLowBalance,
}: UseCallBillingHeartbeatOptions): HeartbeatResponse | null {
  const [lastResponse, setLastResponse] = React.useState<HeartbeatResponse | null>(null);
  const intervalRef = React.useRef<number | null>(null);
  const nextIntervalRef = React.useRef(intervalSeconds);

  const sendHeartbeat = React.useCallback(async () => {
    if (!callId) return;
    try {
      const resp = await sendCallHeartbeat(callId);
      setLastResponse(resp);
      // Adapt interval to server's next_bill_in_seconds
      nextIntervalRef.current = Math.max(10, resp.next_bill_in_seconds || intervalSeconds);
      if (resp.action === "end_call") {
        onEndCall?.(resp.action);
      } else if (resp.warn_low_balance) {
        onLowBalance?.(resp.minutes_remaining);
      }
    } catch {
      // Network error — do not stop the loop; backend heartbeat_timeout handles it
    }
  }, [callId, intervalSeconds, onEndCall, onLowBalance]);

  React.useEffect(() => {
    if (!enabled || !callId) return;

    sendHeartbeat(); // immediate first heartbeat on connect

    const schedule = () => {
      intervalRef.current = window.setTimeout(async () => {
        await sendHeartbeat();
        schedule();
      }, nextIntervalRef.current * 1000);
    };
    schedule();

    return () => {
      if (intervalRef.current !== null) window.clearTimeout(intervalRef.current);
    };
  }, [enabled, callId, sendHeartbeat]);

  return lastResponse;
}
```

Mount in `CallSessionOverlay.tsx` (or wherever `state === "connected"` and `session.paid === true` is known), passing `onEndCall` → `onEnd()` prop.

## Blast Radius / Exploit

- **Financial**: All paid calls incur zero mid-call billing. The platform never collects per-minute revenue during a call; only finalization (if it succeeds) charges the full duration.
- **User harm**: A caller with $1 balance can run a paid call for hours; `finalize_call_billing` will see a balance shortfall and either fail (creator goes unpaid) or charge a fraction.
- **Denial of service**: Callers can intentionally run very long paid calls knowing mid-call enforcement is absent.

No external attacker is required — any caller on the platform benefits.
