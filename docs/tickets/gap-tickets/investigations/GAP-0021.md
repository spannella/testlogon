# GAP-0021 Investigation: `dissolve_group()` never calls `dissolve_treasury()`

## Verdict

**Confirmed** — `/home/ubuntu/testlogon/app/services/user_groups.py:474-501`

`dissolve_group()` marks the group dissolved and deletes all member records but never
calls `dissolve_treasury()`. The function has no import of `group_treasury` at all
(confirmed by reading the full import block at lines 1-16: only `app.core.settings`,
`app.core.tables`, `app.core.time`, `boto3.dynamodb.conditions`, `fastapi`, and `uuid4`).

Relevant code (lines 474-501):
```python
def dissolve_group(*, group_id: str, admin_id: str) -> Dict[str, Any]:
    _require_role(group_id, admin_id, "admin")
    meta = get_group_or_404(group_id)
    if meta.get("status") == "dissolved":
        raise HTTPException(status_code=410, detail="This group has been dissolved")
    ts = now_ts()
    T.user_groups.update_item(
        Key={"pk": f"GROUP#{group_id}", "sk": "META"},
        UpdateExpression="SET #s = :s, updated_at = :t",
        ExpressionAttributeNames={"#s": "status"},
        ExpressionAttributeValues={":s": "dissolved", ":t": ts},
    )
    # Clean up all member records and user-group indexes
    all_members = list_all_members(group_id)
    for m in all_members:
        uid = m.get("user_id", "")
        T.user_groups.delete_item(Key={"pk": f"GROUP#{group_id}", "sk": f"MEMBER#{uid}"})
        _remove_user_group_index(group_id, uid)
    logger.info("group.dissolved", extra={"group_id": group_id, "admin": admin_id})
    return {"ok": True, "status": "dissolved"}
```

`dissolve_treasury()` exists and is fully implemented in
`/home/ubuntu/testlogon/app/services/group_treasury.py:487-600`. It does pro-rata
refunds to contributors and sweeps donation surplus to `PLATFORM#ESCROW`. It is simply
never called.

## Root Cause

The author of `user_groups.py` (GROUP-001) and the author of `group_treasury.py`
(GROUP-004) implemented their respective services in isolation. The dissolution hook in
`dissolve_group()` was not updated when `dissolve_treasury()` was added.

## Exact Fix

In `/home/ubuntu/testlogon/app/services/user_groups.py`:

1. Add import after existing imports:
   ```python
   from app.services import group_treasury as _treasury_svc
   ```
   (lazy import inside the function also acceptable to avoid circular dependency risk)

2. Call `dissolve_treasury` before deleting member records (so treasury balance and
   contributor totals are still readable):
   ```python
   def dissolve_group(*, group_id: str, admin_id: str) -> Dict[str, Any]:
       _require_role(group_id, admin_id, "admin")
       meta = get_group_or_404(group_id)
       if meta.get("status") == "dissolved":
           raise HTTPException(status_code=410, detail="This group has been dissolved")

       # Distribute treasury funds before marking dissolved
       from app.services import group_treasury as _treasury_svc
       treasury_result = _treasury_svc.dissolve_treasury(group_id)

       ts = now_ts()
       T.user_groups.update_item(...)   # unchanged
       # ... member cleanup unchanged ...
       logger.info("group.dissolved", extra={
           "group_id": group_id, "admin": admin_id,
           "treasury": treasury_result,
       })
       return {"ok": True, "status": "dissolved", "treasury": treasury_result}
   ```

## Blast Radius / Exploit

Any group that has ever had a contribution or donation retains the treasury balance
permanently in the `billing` table under `GROUP#{group_id}` after dissolution.
- Contributors receive no refund; their contributed funds are permanently lost.
- Donations never reach `PLATFORM#ESCROW`; they are stranded.
- An attacker (or insider) who retains the `GROUP#{group_id}` DynamoDB prefix key
  can see the orphaned balance but cannot move it (no endpoint allows crediting from a
  dissolved group's billing record unless they call the internal `apply_wallet_delta`
  directly — i.e., no outward exploit, but definite money-loss).

The existing `dissolve_treasury()` already handles the `balance <= 0` edge case
gracefully (returns immediately), so calling it on a zero-balance group is a no-op.

## Dev/Prod Parity

`dissolve_treasury()` uses `T.billing` which maps to DynamoDB (local or AWS). The fix
is a pure service-layer call with no new AWS surface. No dev/prod asymmetry introduced.
