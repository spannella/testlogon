# GAP-0012 Investigation: WebSocket hook not wired — SSH terminal output bypasses monitoring pipeline

**Verdict**: Confirmed — `app/routers/browser_ssh_terminal.py:774-778`

## Code Evidence

The WebSocket forwarding loop (`browser_ssh_terminal_ws`, starting at line 715) polls SSH output and forwards it directly to the client:

```python
if ssh_bridge:
    output = ssh_bridge.poll_output()
    if output:
        session_last_activity_at = now
        await websocket.send_json({"type": "output", "payload": {"data": output}})
```

No call is made to `terminal_monitor.get_or_create_buffer()`, `terminal_monitor.PatternMatcher.match()`, or any function that would feed output through the detection pipeline (buffer accumulation → pattern match → feedback request or state transition).

Additionally, `process_terminal_output` — the top-level dispatch function referenced in the ticket description — **does not exist** in `app/services/terminal_monitor.py`. The file (475 lines) defines:
- `get_or_create_buffer(worker_id)` — manages per-worker `TerminalOutputBuffer`
- `PatternMatcher` / `PatternMatcher.match(text)` — regex-based signal detection
- `create_feedback_request(...)` — persists a feedback request to DDB
- No composite function that calls all three in sequence

Confirmed by `grep -rn "process_terminal_output" /home/ubuntu/testlogon/app/` → zero matches.

## Root Cause

The monitoring service was built as a set of primitives but was never wired into the live data path. The SSH WebSocket handler was not updated to tap the output stream, and no integration layer (`process_terminal_output`) was written to connect `poll_output → buffer → match → dispatch`.

## Exact Fix

1. Add `process_terminal_output(worker_id, chunk)` to `terminal_monitor.py`:
```python
def process_terminal_output(worker_id: str, chunk: str) -> Optional[Dict[str, str]]:
    """Feed a chunk of terminal output through the buffer and pattern matcher.
    Returns a signal dict if a pattern fires, else None."""
    buf = get_or_create_buffer(worker_id)
    buf.append(chunk)
    recent = buf.get_recent(2000)
    matcher = PatternMatcher(get_pattern_config(worker_id))  # or per-worker config
    return matcher.match(recent)
```

2. In the SSH WebSocket loop (`browser_ssh_terminal.py:774-778`), after forwarding output:
```python
if output:
    session_last_activity_at = now
    await websocket.send_json({"type": "output", "payload": {"data": output}})
    # Tap output for monitoring (worker_id associated at connect time)
    if session_worker_id:
        signal = terminal_monitor.process_terminal_output(session_worker_id, output)
        if signal:
            await _dispatch_terminal_signal(signal, session_worker_id, session_user_sub)
```

3. Implement `_dispatch_terminal_signal` to create a feedback request or mark ticket complete/error based on `signal["signal"]`.

4. The `worker_id` must be passed by the client in the `connect` payload or looked up from an active-worker registry keyed by `user_sub`.

## Blast Radius / Exploit

The entire AGENT-006 pipeline (pattern detection, automatic feedback requests, auto-completion on `[AGENT_COMPLETE]`) is non-functional for SSH-based agents. An agent that emits `[AGENT_FEEDBACK_NEEDED]` or `[AGENT_COMPLETE]` in the terminal will have those signals silently dropped. Workers remain in `working` state indefinitely; no feedback requests are ever auto-created.

No security exploit — purely a functional gap.
