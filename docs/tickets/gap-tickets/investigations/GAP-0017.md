# GAP-0017 Investigation: `useGroupCall.ts` hook does not exist

**Date**: 2026-06-05
**Investigator**: Claude Code

---

## Verdict

**Partially confirmed** — `useGroupCall.ts` does not exist as a standalone hook. However, the group-call state management and call lifecycle are already implemented inline inside `GroupCallOverlay.tsx` using `useQuery`/`useMutation` directly. The gap is real in the sense that no extracted hook exists, but the described functionality (join, leave, end, media updates, poll for state, auto-close on ended) IS present in `frontend/src/pages/messages/GroupCallOverlay.tsx`. The mesh/SFU mode-selection driven by join response (per CALL-012 §4.1) is NOT implemented.

---

## Evidence

### Hook file search

```
find frontend/src -name "useGroupCall*"   → (empty — no such file)
grep -rn "useGroupCall" frontend/src/     → (no references)
```

### What IS implemented (inline in GroupCallOverlay.tsx)

`frontend/src/pages/messages/GroupCallOverlay.tsx` contains:

- `GroupCallButton` component (lines 63-179): polls `getActiveGroupCall` every 5 s, create/join mutations.
- `GroupCallOverlay` function (lines 184-431): polls `getGroupCall` every 3 s, leave/end/media mutations, auto-close on `callData?.state === "ended"`.
- `GroupCallParticipant` tile rendering with audio/video/screen indicators.
- All API calls route through `frontend/src/api/endpoints/groupCalls.ts` which maps every CALL-012 backend endpoint.

All standard group call UI lifecycle behaviors are present — they are just embedded in the component rather than extracted into a reusable hook.

### What is NOT implemented

1. **`useGroupCall.ts` hook file** — does not exist. The gap ticket is correct on the naming.
2. **Mesh/SFU mode selection**: The `GroupCallJoinOut` response from `POST /ui/calls/group/{callId}/join` presumably returns a `mode` field or ICE server list that should drive a "mesh (peer-to-peer) vs SFU (selective forwarding unit)" signaling path. `GroupCallOverlay.tsx` ignores the join response entirely beyond setting `inCall = true` (line 101). No WebRTC negotiation code exists — the component is a state-management UI only (explicitly noted in the file header: "No actual WebRTC peer connections").
3. **WebRTC signaling**: `sendGroupCallSignal` and `updateGroupCallMedia` API wrappers exist but the actual WebRTC `RTCPeerConnection` setup, ICE candidate exchange, and SDP offer/answer flow are absent.

---

## Root Cause

CALL-012 delivered backend group-call state machine and REST API endpoints. The frontend implemented a visually complete overlay that tracks call state via polling but deferred the actual WebRTC media/signaling layer. The extracted `useGroupCall` hook (intended to encapsulate mesh vs SFU branching based on the join response) was never written; instead, a simplified inline version was embedded in the overlay.

The "partially confirmed" verdict is because:
- The hook file is genuinely absent.
- The mesh/SFU mode-selection logic is absent.
- BUT the basic group call UI lifecycle (create/join/leave/end/media-toggle) IS present inline.

---

## Exact Fix

1. **Extract `frontend/src/hooks/useGroupCall.ts`** encapsulating:
   - `joinGroupCall` → read `mode` from response.
   - If `mode === "mesh"`: initiate `RTCPeerConnection` per remote participant using `sendGroupCallSignal` for SDP/ICE exchange.
   - If `mode === "sfu"`: initiate single `RTCPeerConnection` to SFU URL returned in join response.
   - Expose `{ participants, localStream, remoteStreams, leave, end, toggleAudio, toggleVideo, toggleScreen }`.

2. **Replace inline state in `GroupCallOverlay.tsx`** with `useGroupCall(callId, userId)`.

The fix for the mode-selection alone (even without real WebRTC) would be:

```typescript
// In useGroupCall.ts
const joinResp = await joinGroupCall(callId);
const rtcMode = joinResp.mode ?? "mesh";   // "mesh" | "sfu"
const iceServers = joinResp.ice_servers ?? [];
// ... setup RTCPeerConnection based on rtcMode
```

---

## Blast Radius / Exploit

- **No audio/video in group calls**: Without WebRTC setup, group calls show participant tiles but no media flows. Users on paid group calls (if call billing is wired) pay for silence.
- **No external security exploit** — this is a missing feature, not a vulnerability.
- The mesh mode (peer-to-peer) leaks participant IP addresses to each other; an SFU would prevent this. Without the mode-selection logic the platform cannot enforce SFU for calls requiring IP privacy.
