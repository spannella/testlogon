# GAP-0007 Investigation: serve_broadcast_ad not wired to real ad serving engine

## Verdict

**Confirmed** — `app/services/broadcast_ads.py:55–83`

`serve_broadcast_ad()` unconditionally returns a hardcoded "house" creative. The function's own
docstring acknowledges this and says it should eventually delegate to
`app.services.ad_serving.serve_ad`. The real `serve_ad()` function exists at
`app/services/ad_serving.py:45` and is fully implemented (targeting, frequency caps, budget
checks, fraud suspension). The broadcast path simply never calls it.

Relevant code at `app/services/broadcast_ads.py:55–83`:

```python
def serve_broadcast_ad(*, surface, creator_id, content_id, slot_type, user_id):
    """
    NOTE: ADS-004 (ad serving engine) and ADS-002 (video creatives) are not yet
    implemented. This returns a deterministic stub "house" creative so the rest of
    the flow (overlay, tracking, skip) is exercisable end-to-end. When ADS-004 lands
    this function should delegate to ``app.services.ad_serving.serve_ad``.
    """
    creative_id = f"bcast_house_{slot_type}"
    return {
        "filled": True,
        "creative_id": creative_id,
        ...
    }
```

## Root Cause

`broadcast_ads.py` was written as an end-to-end scaffolding stub before `ad_serving.py` (ADS-004)
was completed. The delegation TODO was never closed out.

## Exact Fix

Replace the body of `serve_broadcast_ad()` with a delegation to `serve_ad()`, falling back to
the house creative on error:

```python
def serve_broadcast_ad(*, surface, creator_id, content_id, slot_type, user_id):
    """Select an ad for a broadcast surface via the real ad serving engine."""
    try:
        from app.services.ad_serving import serve_ad
        result = serve_ad(
            surface=surface,
            content_type="broadcast",
            creator_id=creator_id,
            content_id=content_id,
            slot_type=slot_type,
            user_id=user_id,
        )
        if result.get("filled"):
            return result
    except Exception:
        logger.warning("broadcast_ad_serve_engine_error creator=%s", creator_id)

    # Fallback: house creative
    creative_id = f"bcast_house_{slot_type}"
    return {
        "filled": True,
        "creative_id": creative_id,
        "format": "video",
        "video_url": f"/mock/s3/ad-creatives/{creative_id}.mp4",
        "image_url": None,
        "cta_url": None,
        "impression_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=impression",
        "click_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=click",
        "skip_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=skip",
    }
```

## Blast Radius / Exploit

No advertiser revenue is generated from broadcast ads (no campaign spend, no targeting, no
frequency caps). Creators relying on ad revenue from their broadcast sessions receive zero
monetisation from real campaigns. Frequency cap bypass is a secondary concern: since the house
creative has no campaign_id, no frequency-cap records are written, so real campaign frequency
caps are never enforced when the engine eventually does serve.

## Dev/Prod Parity (SECOPS-007)

`serve_ad()` uses DynamoDB tables (`T.ad_campaigns`, `T.ad_creatives`, etc.) present in both
dev and production. No AWS-specific code path is introduced. In dev mode the tables will simply
be empty → engine returns `_house_ad_response("no_active_campaigns")` → same fallback behaviour
as today.

## Effort

**S** — One-function body replacement with a try/except delegation + existing fallback logic.
