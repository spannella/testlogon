# GAP-0020 Investigation: TIN/SSN collection and KMS-encrypted storage absent

**Date**: 2026-06-05
**Investigator**: Claude Code
**Cross-ref**: SEC-022

---

## Verdict

**Confirmed** — No W-9 form submission endpoint exists, no `submit_tax_info()` function exists, no `tin_encrypted` field is stored in DynamoDB, and the 1099 PDF uses a hardcoded placeholder TIN. The gap ticket's location (`app/services/tax_form_1099.py:55`) is correct. SEC-022 does not overlap (it covers OAuth refresh-token ciphertext leakage, S3 secret exposure, and SFTP in-memory secrets — unrelated to TIN storage).

## Evidence

### Hardcoded placeholder TIN in 1099 PDF

`app/services/tax_form_1099.py:54-55`:
```python
_PAYER_NAME = "Platform Payments, Inc."
_PAYER_TIN_LAST4 = "0000"
```

`app/services/tax_form_1099.py:173`:
```python
f"  TIN          : ***-**-{_PAYER_TIN_LAST4}",
```

This placeholder is written into every generated 1099-NEC PDF ("***-**-0000"). A real Form 1099-NEC is legally required to show:
- **Payer's TIN** (the platform's own EIN) — currently `"0000"`.
- **Recipient's TIN** (the creator's SSN or EIN) — completely absent from both the PDF and the DynamoDB record.

`app/core/crypto.py` has `kms_encrypt`/`kms_decrypt` (referenced in the FIN-008 spec) but they are not imported by `tax_form_1099.py`.

## Root Cause

The FIN-008 implementation delivered the 1099 PDF generation and batch admin flow but omitted the W-9 collection prerequisite entirely. The 1099 PDF rendering was implemented as a standalone document without the data collection step. As a result:

1. The platform cannot generate IRS-compliant 1099-NEC forms (no real TINs).
2. Creators have no way to submit their tax information.
3. The payer TIN field is a literal "0000" placeholder.

## Exact Fix

### 1. Add KMS-encrypted W-9 submission service

`app/services/tax_info_w9.py` (new file):

```python
from app.core.crypto import kms_encrypt, kms_decrypt
from app.core.tables import T
from app.core.time import now_ts

def submit_tax_info(
    *,
    user_sub: str,
    legal_name: str,
    tin: str,           # raw SSN (XXX-XX-XXXX) or EIN (XX-XXXXXXX)
    tin_type: str,      # "ssn" | "ein"
    address_line1: str,
    city: str,
    state: str,
    zip_code: str,
    certified: bool,
) -> dict:
    tin_encrypted = kms_encrypt(tin)  # KMS ciphertext; never log raw tin
    item = {
        "pk": f"USER#{user_sub}",
        "sk": "TAX_INFO",
        "legal_name": legal_name,
        "tin_encrypted": tin_encrypted,
        "tin_last4": tin[-4:],         # for display only
        "tin_type": tin_type,
        "address_line1": address_line1,
        "city": city,
        "state": state,
        "zip_code": zip_code,
        "certified": bool(certified),
        "certified_at": now_ts() if certified else None,
        "updated_at": now_ts(),
    }
    T.tax_info.put_item(Item=item)
    return {k: v for k, v in item.items() if k != "tin_encrypted"}
```

## Blast Radius / Exploit

- **IRS non-compliance**: Issuing 1099-NEC forms with placeholder TINs ("0000") violates IRS Publication 1179 and exposes the platform to penalties of $50–$580 per incorrect form.
- **Missing recipient TIN**: The IRS can reject all filed 1099s, triggering backup withholding obligations.
- **No W-9 = no 1099**: Without a W-9 on file, the platform has no legal basis for issuing the 1099 at all. Generating and issuing forms without a certified TIN is a regulatory violation.
- **No direct security exploit** (no attacker can read non-existent data), but the compliance risk is critical for a production system.

### SEC-022 clarification

SEC-022 is about *existing* KMS-encrypted data leaking back to clients. GAP-0020 is about *absent* KMS encryption. They are orthogonal — fixing GAP-0020 introduces new KMS-encrypted data that must be handled per SEC-022 principles (never return `tin_encrypted` ciphertext in API responses; return `tin_last4` only).

## Dev/Prod Parity

In dev mode (`S.dev_mode = True`), `kms_encrypt` uses the mock KMS server at port 7999 (`scripts/mock_kms_server.py`). In prod it uses real AWS KMS. The `PLATFORM_EIN` env var must be populated in `.env.local.example` (with a dev placeholder) and in prod secrets. SECOPS-007 applies: any new field containing PII (TIN) must use KMS encryption, and the ciphertext must never be returned in API responses — per the SEC-022 patterns.
