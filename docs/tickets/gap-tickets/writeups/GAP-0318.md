# GAP-0318: IP Spoofing via Untrusted X-Forwarded-For Header — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual codebase; no prior investigation doc exists.

## 1. Summary & Classification

**Bug statement**: `client_ip_from_request()` in `app/core/normalize.py:9` blindly trusts the
`X-Forwarded-For` (XFF) header from any TCP peer. Any client — including one connecting
directly without passing through a load balancer — can inject an arbitrary IP address by
setting `X-Forwarded-For: 1.2.3.4` and will have that IP treated as their real address for
rate-limiting, lockout, audit logging, anomaly detection, geoblocking, and the root login
network gate. A single attacker can thereby exhaust lockout quotas attributed to any victim IP,
or bypass their own rate limits, or forge audit log entries.

**Claim verdict**: CONFIRMED with one important nuance. The ticket cites
`app/core/normalize.py:9` as the vulnerable function. The code at that exact line is indeed the
untrusted-XFF path. However, the codebase also contains a *correctly-implemented* XFF handler
at `app/auth/root_network.py:25` (`_resolve_client_ip`) which already checks whether
`request.client.host` is in `S.trusted_proxy_cidrs` before honouring XFF. The gap is therefore
confined to `client_ip_from_request()` — the general-purpose helper used by 20+ call sites —
while the root network gate is already secure. The fix must bring `client_ip_from_request()` up
to the standard already established in `root_network.py`.

**Severity**: HIGH (security bypass of all rate-limit and lockout controls)  
**Source ticket**: PLATFORM-001  
**Owning area**: Core / Security  
**Related tickets**: SECOPS-007 (dev/prod parity), GAP-0030 (root break-glass), GAP-0039
(no max-5-accounts rate limit).

## 2. Current-State Investigation (root cause)

### Vulnerable function — `app/core/normalize.py:9`

```python
def client_ip_from_request(req) -> str:
    if req is None:
        return "0.0.0.0"
    xff = req.headers.get("x-forwarded-for")
    if xff:
        for part in xff.split(","):
            candidate = part.strip()
            if candidate:
                return candidate          # ← returns FIRST part unconditionally
    return req.client.host if req.client else "0.0.0.0"
```

There is no check on whether the TCP peer (`req.client.host`) is a trusted proxy. Any client
that sets the header gets the first entry honoured.

### Correctly-implemented counterpart — `app/auth/root_network.py:25`

```python
def _resolve_client_ip(req: Request) -> Tuple[ipaddress._BaseAddress, str]:
    direct_host = req.client.host if req and req.client else ""
    direct_ip = ipaddress.ip_address(direct_host)
    trusted_proxy_networks = _parse_cidrs(S.trusted_proxy_cidrs)
    xff = (req.headers.get("x-forwarded-for") or "").strip()
    if not xff:
        return direct_ip, "direct"
    if not _ip_in_networks(direct_ip, trusted_proxy_networks):
        return direct_ip, "direct_untrusted_proxy"   # ignore spoofed XFF
    first = xff.split(",", 1)[0].strip()
    return ipaddress.ip_address(first), "trusted_proxy"
```

This is the correct pattern. It was written for the root network gate specifically, but the
same logic must apply to the general helper.

### `TRUSTED_PROXY_CIDRS` setting — `app/core/settings.py:32`

```python
trusted_proxy_cidrs: str = os.environ.get("TRUSTED_PROXY_CIDRS", "")
```

The setting already exists. The default empty string means "no trusted proxies" which is
correct for dev (direct TCP connections). In production behind an ALB/NLB the operator sets
this to the ALB's IP range (e.g., `10.0.0.0/8` or the ALB's specific CIDR).

### Call sites using `client_ip_from_request`

The function is imported in at least 12 router files and used for:

- **Rate limiting**: `app/routers/ui_mfa.py`, `app/routers/passwordless.py`,
  `app/routers/register.py`, `app/routers/profile.py`, `app/routers/filemanager.py`
- **Lockout tracking**: `app/routers/ui_mfa.py` (TOTP, SMS), `app/routers/passwordless.py`
- **Audit/anomaly detection**: `app/routers/admin_roles.py`, `app/routers/moderation.py`,
  `app/routers/questionnaires.py`
- **CCBill remote-IP validation**: `app/routers/billing_ccbill.py`
- **WebAuthn ceremony IP recording**: `app/routers/webauthn.py`

Every one of these is affected by the spoofing bug.

### Why the XFF "first entry" convention matters

RFC 7239 specifies that a forwarding proxy appends the sender's IP to XFF. With a single
trusted proxy (an ALB), the value is `<real-client-ip>, <alb-ip>`. The correct real-client IP
is the leftmost entry. If no proxy is trusted, the leftmost entry is fully attacker-controlled.

## 3. Impact / Exploit / Blast Radius

**Exploit 1 — Rate-limit bypass**

```
POST /ui/auth/mfa/totp HTTP/1.1
X-Forwarded-For: 10.0.0.1      ← forged
...
```

Repeat with cycling values of XFF (10.0.0.1, 10.0.0.2, ...). Each request is counted against
a different IP in the lockout store. The per-IP rate limit is never hit. Attacker can attempt
unlimited TOTP codes against a victim account.

**Exploit 2 — Audit log poisoning**

All `audit_event()` calls that pass `client_ip_from_request(req)` as the `ip` field will
record the spoofed IP. A compromised insider can perform sensitive operations (e.g., view a
user's documents via `/ui/files/`) and cause audit entries to attribute the access to an
executive's IP address, manufacturing false evidence or obscuring a real breach.

**Exploit 3 — Lockout DoS**

The lockout mechanism at `app/services/rate_limit.py` keys by `(user_id, ip)` or `(ip, ...)`.
An attacker can forge XFF headers set to a victim's known IP (e.g., from a public whois lookup
on a corporate IP range) and trigger lockout on MFA/login endpoints attributed to that IP,
causing support load without any genuine authentication attempts.

**Exploit 4 — CCBill remote-IP validation bypass**

`app/routers/billing_ccbill.py:497` uses `client_ip_from_request(req)` as `remote_ip` for
CCBill callback validation. If CCBill validates that callbacks come from its own IP range, this
check can be bypassed by spoofing XFF to CCBill's IP.

**Blast radius**: All authenticated users, all rate-limit and lockout-protected endpoints (login,
MFA, registration, file mounts, profile lookups), and the billing callback endpoint.

## 4. Fix Design (code-level)

### 4.1 Update `client_ip_from_request` — `app/core/normalize.py`

Replace the existing function entirely:

```python
def client_ip_from_request(req) -> str:
    """Return the best-guess real client IP for rate-limiting and audit logging.

    Trusts X-Forwarded-For ONLY when the direct TCP peer (req.client.host) falls
    within TRUSTED_PROXY_CIDRS. When the list is empty (dev mode / no proxy) the
    direct host is always returned, preventing XFF injection.

    SECOPS-007: TRUSTED_PROXY_CIDRS defaults to "" (empty) in dev, so the dev
    environment uses direct IP just like the test client; production ops sets the
    ALB/NLB CIDR. The code path is identical — no dev-only bypass.
    """
    if req is None:
        return "0.0.0.0"
    direct_host = req.client.host if req.client else "0.0.0.0"
    xff = req.headers.get("x-forwarded-for", "").strip()
    if not xff:
        return direct_host
    # Only honour XFF if the direct TCP peer is a known trusted proxy.
    if not ip_in_any_cidr(direct_host, _trusted_proxy_list()):
        return direct_host
    # XFF is trusted: the real client IP is the leftmost entry.
    first = xff.split(",", 1)[0].strip()
    return first if first else direct_host


def _trusted_proxy_list() -> list:
    """Parse TRUSTED_PROXY_CIDRS into a list of CIDR strings (cached via module-level var)."""
    raw = (S.trusted_proxy_cidrs or "").strip()
    if not raw:
        return []
    return [c.strip() for c in raw.split(",") if c.strip()]
```

`ip_in_any_cidr()` is already defined in the same file at line 53 and handles malformed CIDRs
gracefully.

### 4.2 Deprecate / unify with `root_network.py`

After this change, `client_ip_from_request` and `root_network._resolve_client_ip` implement the
same logic. In a subsequent cleanup PR, `_resolve_client_ip` should delegate to
`client_ip_from_request` and drop its own CIDR parsing. That is a refactor out of scope for
this gap fix.

### 4.3 Dev/Prod parity (SECOPS-007)

| Environment | `TRUSTED_PROXY_CIDRS` | Behaviour |
|---|---|---|
| Dev (local stack) | `""` (empty) | XFF always ignored; direct host used. No bypass. |
| Staging / CI | `""` (empty) | Same as dev. |
| Production (behind ALB) | `"10.0.0.0/8"` or ALB-specific CIDR | XFF honoured only from ALB. |

No dev-mode special case is introduced in `client_ip_from_request` itself. The behaviour
difference is entirely controlled by the env var, which is the correct SECOPS-007 pattern.

### 4.4 `.env.local.example` documentation

Add a comment to `.env.local.example`:

```bash
# Set to your load-balancer CIDR in production so X-Forwarded-For is trusted.
# Leave empty in dev (direct connections, no proxy).
TRUSTED_PROXY_CIDRS=
```

### 4.5 Alternatives considered

- **Uvicorn `--proxy-headers` flag**: Uvicorn has a `--forwarded-allow-ips` flag that sets XFF
  trust at the ASGI layer. Rejected because (a) it would require changing the startup script,
  (b) it duplicates the logic rather than fixing it at the source, and (c) the `uvicorn --workers 1`
  dev constraint (from CLAUDE.md) makes server-flag changes fragile.
- **Remove XFF support entirely**: Overly restrictive; production deploys behind AWS ALB/NLB
  require XFF to correctly attribute client IPs in audit logs and compliance reports.

## 5. Testing, Verification & Rollout

### Regression tests (pytest offline)

```python
# tests/test_client_ip.py
from app.core.normalize import client_ip_from_request
from unittest.mock import MagicMock, patch

def _make_req(host: str, xff: str | None = None):
    req = MagicMock()
    req.client.host = host
    headers = {}
    if xff is not None:
        headers["x-forwarded-for"] = xff
    req.headers.get = lambda key, default="": headers.get(key, default)
    return req

def test_xff_ignored_when_no_trusted_proxy_configured():
    """BEFORE fix: returns 1.2.3.4 (spoofed). AFTER fix: returns 10.0.0.5 (direct)."""
    with patch("app.core.normalize.S.trusted_proxy_cidrs", ""):
        req = _make_req("10.0.0.5", xff="1.2.3.4")
        assert client_ip_from_request(req) == "10.0.0.5"

def test_xff_honoured_when_peer_is_trusted_proxy():
    """AFTER fix: when direct peer is within TRUSTED_PROXY_CIDRS, XFF first entry is used."""
    with patch("app.core.normalize.S.trusted_proxy_cidrs", "10.0.0.0/8"):
        req = _make_req("10.0.0.1", xff="203.0.113.42, 10.0.0.1")
        assert client_ip_from_request(req) == "203.0.113.42"

def test_xff_ignored_when_peer_not_in_trusted_cidrs():
    """Direct peer outside TRUSTED_PROXY_CIDRS: XFF header is discarded."""
    with patch("app.core.normalize.S.trusted_proxy_cidrs", "10.0.0.0/8"):
        req = _make_req("203.0.113.99", xff="1.2.3.4")
        assert client_ip_from_request(req) == "203.0.113.99"

def test_no_xff_always_returns_direct():
    """Without XFF header, direct host is returned regardless of proxy config."""
    with patch("app.core.normalize.S.trusted_proxy_cidrs", "10.0.0.0/8"):
        req = _make_req("192.168.1.10")
        assert client_ip_from_request(req) == "192.168.1.10"

def test_none_request_returns_sentinel():
    assert client_ip_from_request(None) == "0.0.0.0"
```

### Integration test (rate-limit bypass prevention)

```python
def test_mfa_lockout_cannot_be_bypassed_by_xff_spoofing(client, alice_session):
    """Cycling XFF values must not allow unlimited TOTP attempts."""
    # Send 10 bad TOTP codes with cycling XFF headers.
    for i in range(10):
        resp = client.post(
            "/ui/mfa/totp",
            json={"code": "000000"},
            headers={**alice_session.csrf_headers,
                     "X-Forwarded-For": f"192.0.2.{i}"},
        )
    # The lockout should trigger based on the direct test-client IP, not the forged XFF.
    # Exact assertion depends on lockout threshold; at minimum the last response is not 200.
    assert resp.status_code in (429, 403)
```

### Manual QA steps

1. `just up` to start dev stack.
2. Send a request to `POST /ui/auth/mfa/totp` with `X-Forwarded-For: 192.168.99.99` and
   inspect the audit log (DynamoDB `audit_events` table) — the stored IP must be the
   `req.client.host` (127.0.0.1 in the test client), not `192.168.99.99`.
3. Set `TRUSTED_PROXY_CIDRS=127.0.0.1/32` in `.env.local`, restart backend, repeat step 2 —
   now the stored IP should be `192.168.99.99` because the direct host is in the trusted list.

### Observability

No new metrics required; the existing audit log captures IP. Add a log line at WARN level when
XFF is present but ignored (direct host not in trusted proxies) to make misconfigured
production deployments visible:

```python
if xff and not ip_in_any_cidr(direct_host, _trusted_proxy_list()):
    logger.debug(
        "XFF header present but direct peer %s is not in TRUSTED_PROXY_CIDRS; ignoring",
        direct_host,
    )
```

### Rollout

1. Deploy with `TRUSTED_PROXY_CIDRS=""` (the current default) — no behavioural change in dev
   or any environment that does not already have XFF in play.
2. For production: set `TRUSTED_PROXY_CIDRS` to the ALB's IP range before deploying. Verify
   that audit log IPs after the deployment show real client IPs (not ALB IPs).
3. Run the full E2E suite — `client_ip_from_request(None)` returns `"0.0.0.0"` as before, so
   tests that pass `req=None` are unaffected.

**Rollback**: Revert only `app/core/normalize.py`. No DynamoDB schema changes; no migrations.

**Effort estimate**: S (Small) — 2–4 hours including tests.
