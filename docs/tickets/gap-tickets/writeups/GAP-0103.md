# GAP-0103: App Credentials Injection Not Implemented — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; `file:line` citations are live.

## 1. Summary & Classification

**Severity**: HIGH
**Source ticket**: AGENT-016
**Owning area**: UI Stylist Agent
**Status**: Open (no fix deployed as of this write-up)

The UI Stylist Agent (AGENT-016) is designed to run Playwright browser sessions against the live application to capture screenshots, check contrast ratios, and verify design-system compliance. Real Playwright browsing requires authenticated sessions — the agent must be able to log in to the application it is reviewing. The ticket requires an `app_auth_credentials_secret_name` field to be added to the stylist config so operators can specify a Secrets Manager ARN; the actual credentials are resolved at trigger time, never stored in DDB, and never exposed in API responses (expose only `has_app_credentials: bool`).

`update_stylist_config` at `app/services/agent_stylist.py:721` accepts only the fields enumerated in `_CONFIG_FIELDS` (lines 61–76). `app_auth_credentials_secret_name` is absent from `_CONFIG_FIELDS`, `_DEFAULT_CONFIG`, and `StylistConfigOut` in `app/models.py:8025`. There is no mechanism to inject live-app auth for real Playwright browsing.

**Claim accuracy**: The ticket cites `app/services/agent_stylist.py:721` as the location. Code inspection confirms `update_stylist_config` starts at line 721 and that `app_auth_credentials_secret_name` is indeed absent from both `_CONFIG_FIELDS` and `_DEFAULT_CONFIG`. **Claim is confirmed and accurate.**

**Related tickets**: GAP-0102 (GitHub token pattern), GAP-0025 (webhook secret in plaintext), GAP-0101 (repo_url validation).

### 2.5 `trigger_review` at `app/services/agent_stylist.py:777`

Code inspection shows that `trigger_review` drives the Playwright mock review lifecycle. When `S.stylist_agent_execute_commands = True` (settings.py line 2186), this function would need to launch a real Playwright session. It currently has no mechanism to obtain app credentials for authentication before navigating to pages.

### 2.6 Dev vs prod parity

`S.stylist_agent_execute_commands` defaults to `False` (env `STYLIST_AGENT_EXECUTE_COMMANDS=0`). With this gate closed, Playwright is never launched and the missing credentials are harmless. The vulnerability activates when the gate is opened in prod: `trigger_review` will attempt to browse `pages_to_review` unauthenticated, producing meaningless results on auth-gated pages, or the agent will error and crash.

## 3. Impact / Exploit / Blast Radius

### 3.1 Functional failure mode

Without app credentials, when `stylist_agent_execute_commands = True`:
- Playwright navigates to pages like `/messages` or `/billing` without a session cookie.
- These routes redirect to `/login`. Screenshots show only the login screen.
- Contrast ratios, design tokens, and layout checks all fail vacuously — the agent either reports false compliance or throws on missing DOM elements.
- Review tickets generated from these runs have meaningless findings, wasting operator time and eroding trust in the agent.

### 3.2 Security risk if credentials are injected ad hoc

Without a formal `app_auth_credentials_secret_name` field, an operator may work around the gap by embedding credentials directly in `pages_to_review` as query parameters (`/messages?token=xxx`) or adding a raw `app_password` field to the config. Either approach stores credentials in DDB plaintext — the exact scenario GAP-0102 prevents for the GitHub token.

### 3.3 Scope of affected data

The agent runs with `user_id` of the configuring user. If the agent logs into the application as a service account with broad access (e.g., admin), a compromised secret resolution path could allow the agent to screenshot private data from other users' pages.

## 4. Fix Design (code-level)

### 4.1 Add `app_auth_credentials_secret_name` to the config

**`app/services/agent_stylist.py` — extend `_DEFAULT_CONFIG` and `_CONFIG_FIELDS`:**

```python
_DEFAULT_CONFIG: Dict[str, Any] = {
    ...
    "app_auth_credentials_secret_name": "",  # ADD — empty = not configured
    ...
}

_CONFIG_FIELDS = (
    ...existing fields...
    "app_auth_credentials_secret_name",  # ADD
)
```

### 4.2 Mask the secret name in GET responses — expose `has_app_credentials`

The `app_auth_credentials_secret_name` field holds an ARN or secret name, not a raw credential. It is safe to return the name itself (it is not secret — it is a pointer). However, following the same pattern as GAP-0102, expose a derived boolean for simplicity:

**`app/models.py` — extend `StylistConfigOut` and `UpdateStylistConfigIn`:**

```python
class StylistConfigOut(BaseModel):
    ...
    app_auth_credentials_secret_name: Optional[str] = None   # ADD
    has_app_credentials: bool = False                         # ADD — derived
    ...

class UpdateStylistConfigIn(BaseModel):
    ...
    app_auth_credentials_secret_name: Optional[str] = None   # ADD
```

In the stylist router (GET config endpoint), populate `has_app_credentials` before building the response:

```python
config = svc.get_stylist_config(user_id=user_id) or {}
config["has_app_credentials"] = bool(config.get("app_auth_credentials_secret_name"))
return StylistConfigOut(**config)
```

### 4.3 Credential resolution helper

Add to `app/services/agent_stylist.py`:

```python
import boto3

def _resolve_app_credentials(user_id: str) -> Optional[Dict[str, str]]:
    """Resolve app auth credentials for Playwright sessions.

    Returns a dict with keys 'username' and 'password' (or 'token'),
    or None if not configured.

    In dev mode, returns mock credentials (no Secrets Manager call).
    In prod, resolves from Secrets Manager using the configured secret name.
    """
    if S.dev_mode:
        return {"username": "e2e_alice@test.local", "password": "devpassword"}
    config = get_stylist_config(user_id=user_id) or {}
    secret_name = config.get("app_auth_credentials_secret_name", "")
    if not secret_name:
        return None
    sm = boto3.client("secretsmanager")
    try:
        resp = sm.get_secret_value(SecretId=secret_name)
        import json as _json
        return _json.loads(resp["SecretString"])
    except Exception as exc:
        logger.error("Failed to resolve app credentials from Secrets Manager: %s", exc)
        return None
```

### 4.4 Inject credentials into `trigger_review`

```python
def trigger_review(*, user_id: str, ...):
    if S.stylist_agent_execute_commands:
        creds = _resolve_app_credentials(user_id)
        if creds is None:
            raise ValueError("app_auth_credentials_not_configured")
        # Launch Playwright with creds — inject cookie or perform login
        _run_playwright_with_auth(creds, ...)
    else:
        # Mock path — unchanged
        ...
```

Surface this as an HTTP 400 at the router level:

```python
try:
    result = svc.trigger_review(user_id=user_id, ...)
except ValueError as exc:
    if str(exc) == "app_auth_credentials_not_configured":
        raise HTTPException(
            status_code=400,
            detail={
                "code": "app_credentials_required",
                "message": "Configure app_auth_credentials_secret_name before triggering a live review.",
            },
        )
    raise
```

### 4.5 Secrets Manager secret format

Document the expected JSON structure for the Secrets Manager secret:

```json
{
    "username": "stylist-agent@example.com",
    "password": "s3cur3p@ss",
    "mfa_totp_seed": "BASE32SEED"   // optional, for TOTP-protected accounts
}
```

Alternatively, a session cookie format:

```json
{
    "ui_session": "sess_xxx",
    "ui_access_token": "eyJ...",
    "ui_csrf": "csrf_xxx"
}
```

The latter is safer in E2E tests: seed a long-lived session for the stylist service account, store the cookie values in Secrets Manager, and the agent injects them directly.

### 4.6 Dev/Prod parity (SECOPS-007)

| Path | Dev | Prod |
|------|-----|------|
| Credential source | Mock static creds from `_resolve_app_credentials` | AWS Secrets Manager via secret name |
| Config stored in DDB | `app_auth_credentials_secret_name: ""` | `app_auth_credentials_secret_name: "arn:aws:..."` |
| GET response | `has_app_credentials: false` | `has_app_credentials: true` |
| Raw password in DDB | Never | Never |
| Raw password in API | Never | Never |
| Playwright auth | Skipped (mock mode) | Cookie injection or UI login |

Both paths go through `_resolve_app_credentials`; dev returns a constant, prod calls Secrets Manager. The `trigger_review` guard (`if creds is None: raise`) runs in both modes.

### 4.7 Alternatives considered

- **Store session token directly in stylist config**: an env-var-based approach. Rejected — puts sensitive data in DDB and makes rotation hard.
- **Use a dedicated Playwright service account with a never-expiring API key**: simpler but requires the API key to be stored somewhere; Secrets Manager is still the right store.
- **Skip auth entirely — use public pages only**: defeats the purpose of reviewing auth-gated pages like `/billing` and `/messages`, which are the highest-value surfaces for the stylist agent.

## 5. Testing, Verification & Rollout

### 5.1 Pytest regression test (fails before / passes after)

Add to `tests/test_agent_stylist.py`:

```python
def test_update_stylist_config_accepts_secret_name(client, alice_session):
    """BEFORE fix: app_auth_credentials_secret_name is silently discarded.
    AFTER fix: the field is stored and reflected in has_app_credentials."""
    resp = client.put(
        "/ui/agents/stylist/config",
        json={"app_auth_credentials_secret_name": "arn:aws:secretsmanager:us-east-1:123:secret:stylist-creds"},
        headers=alice_session,

    assert resp.status_code == 200
    body = resp.json()
    assert body["has_app_credentials"] is True

    """GET /config must include has_app_credentials bool."""
    resp = client.get("/ui/agents/stylist/config", headers=alice_session)
    assert resp.status_code == 200
    body = resp.json()
    assert "has_app_credentials" in body
    assert isinstance(body["has_app_credentials"], bool)

def test_trigger_review_fails_when_execute_enabled_no_creds(client, alice_session, monkeypatch):
    """AFTER fix: trigger_review returns 400 when execute_commands=True but no creds."""

    monkeypatch.setattr("app.core.settings.S.dev_mode", False)

        "/ui/agents/stylist/reviews/trigger",

        headers=alice_session,

    assert resp.status_code == 400
    assert resp.json()["detail"]["code"] == "app_credentials_required"

def test_resolve_app_credentials_uses_mock_in_dev(monkeypatch):

    # No boto3 call was made (would raise in test env without SM mock)
```

### 5.4 Observability and rollout

- Emit a structured log line when credentials are resolved: `logger.info("Resolved app credentials for stylist review user=%s has_creds=%s", user_id, creds is not None)`.
- Add a Secrets Manager access CloudTrail alert for the stylist secret ARN to detect unexpected credential reads.
- **Effort**: M (medium) — two service files, one model file, Secrets Manager mock in tests, operator documentation for the secret format.
- **Rollout**: Ship the config-field and model changes first (backward-compatible). Populate the Secrets Manager secret for the service account. Update the config via API. Then enable `STYLIST_AGENT_EXECUTE_COMMANDS=1` in staging, verify screenshots are authenticated, then promote to prod.
- **Rollback**: Set `STYLIST_AGENT_EXECUTE_COMMANDS=0`. The config field in DDB is harmless when the execute gate is off.
- **Sequencing**: Depends on the Secrets Manager IAM role for the ECS task being granted `secretsmanager:GetSecretValue` on the stylist credentials secret. Should be done in the same Terraform/CDK PR as this code change.
