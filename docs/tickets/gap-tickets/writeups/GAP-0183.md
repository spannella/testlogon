# GAP-0183: `sticker_url` accepts arbitrary external URLs with no platform-only enforcement — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against real code before writing; cites `file:line`.

## 1. Summary & Classification

**Bug statement**: The `sticker_url` field in `CreateCommentRequest` (`app/routers/newsfeed.py:1592`) is declared as an unconstrained string. The FEED-004 ticket specification requires sticker URLs to reference only platform-hosted CDN assets. The current validator at lines 1617–1630 only checks that `sticker_url` is non-empty for `kind="sticker"` comments — it does not verify that the URL originates from the platform CDN or the dev mock prefix. Any HTTP, HTTPS, `data:`, or `javascript:` URI is accepted, stored, and returned verbatim.

- **Severity**: HIGH
- **Source ticket**: FEED-004
- **Owning area**: Newsfeed / Comments
- **Status**: Open (confirmed gap)
- **Verdict**: **Confirmed**. The cited location `app/routers/newsfeed.py:1591` is the `sticker_collection_id` field; `sticker_url` is at line 1592. Both lines are correct: no scheme check and no platform-origin check exist in the `validate_comment_kind` validator.
- **Note on cited line**: The ticket cites `:1591`. Code inspection shows `sticker_collection_id` is at 1591 and `sticker_url` is at 1592. The gap itself (missing validation) is confirmed; the line reference is off by one, but the impact analysis is accurate.
- **One-line impact**: Attackers can embed arbitrary off-platform URLs as sticker content, enabling hotlinking abuse, tracking pixel injection, off-platform illegal content references, and SSRF-adjacent server-side fetch abuse if sticker URLs are ever proxied.
- **Related tickets**: GAP-0182 (gif_url, same file and pattern), FEED-004

### Difference from gif_url gap

GAP-0182 (`gif_url`) requires HTTP/HTTPS access to known third-party GIF CDN providers (Giphy, Tenor) because GIF content is inherently sourced from those services. `sticker_url` is architecturally different: the platform hosts its own sticker library in its own S3 bucket (dev: `/mock/s3/stickers/...`, prod: `S.filemgr_media_preview_cdn_base_url` or equivalent CDN origin). The fix for `sticker_url` is therefore more restrictive — it should enforce a platform origin prefix, not just a domain allowlist.

### Settings context (file:line)

```python
    "FILEMGR_MEDIA_PREVIEW_CDN_BASE_URL", ""

```

This field holds the CDN base URL for platform-hosted media in production. In dev, the mock S3 prefix is `/mock/s3/`. The fix uses both.

## 3. Impact / Exploit / Blast Radius

### Hotlinking and off-platform content injection

A `sticker_url` pointing to `https://attacker.example.com/tracking.gif` causes every user who loads that comment to make a request to the attacker's server, leaking their IP address and User-Agent. Unlike GIFs (where third-party CDNs are explicitly expected), sticker content should be fully under platform control.

### Platform brand abuse

If sticker URLs can reference any HTTPS image, an attacker can embed adult, offensive, or rights-restricted imagery while having it appear as a "sticker" — visually indistinguishable from legitimate platform sticker content in the UI.

### SSRF-adjacent risk

If a future platform feature proxies sticker images (e.g., for thumbnail generation, content moderation scanning, or caching) through a server-side fetch, an accepted off-platform URL becomes an SSRF vector pointing at internal infrastructure, cloud metadata endpoints, or third-party services.

### Data: and javascript: schemes

As with `gif_url`, `data:text/html,...` and `javascript:` URIs are accepted and stored. Sticker images rendered as `<img src="...">` in the frontend create the same stored XSS vector described in GAP-0182.

### Blast radius

- All authenticated users who can post `kind="sticker"` comments are affected.
- All users who read posts with sticker comments are exposed to stored malicious content.
- No privilege escalation is required — a normal USER role can exploit this.
- Data already stored with invalid `sticker_url` values remains in DynamoDB regardless of the fix and requires a separate data-hygiene migration.

## 4. Fix Design (code-level)

### Change 1: Platform-origin validator for sticker_url

The validator must accept URLs that originate from the platform. Two valid forms exist:
1. **Relative path**: Starts with `/mock/s3/stickers/` in dev; starts with `/stickers/` in prod (served from the same origin as the API).
2. **Absolute CDN URL**: Starts with the platform's configured `CDN_BASE_URL` (`S.filemgr_media_preview_cdn_base_url`).

```python
from urllib.parse import urlparse
from app.core.settings import S

def _validate_sticker_url(url: str) -> str:
    """Validate sticker_url: must be a platform-hosted relative path or CDN URL."""
    url = url.strip()

    # Allow platform-relative paths (served by the same origin as the API)
    if url.startswith("/"):
        # Must begin with the platform sticker path prefix
        allowed_relative_prefixes = ("/mock/s3/stickers/", "/stickers/", "/media/stickers/")
        if any(url.startswith(p) for p in allowed_relative_prefixes):
            return url
        raise ValueError(
            "sticker_url relative path must start with a platform sticker prefix"
        )

    # Allow absolute CDN URLs when CDN_BASE_URL is configured
    cdn_base = (getattr(S, "filemgr_media_preview_cdn_base_url", "") or "").rstrip("/")
    if cdn_base and url.startswith(cdn_base + "/"):
        return url

    # Reject all other forms (data:, javascript:, arbitrary http/https, etc.)
    try:
        parsed = urlparse(url)
    except Exception:
        raise ValueError("sticker_url is not a valid URL")

    raise ValueError(
        f"sticker_url must be a platform-relative path or platform CDN URL; "
        f"got scheme='{parsed.scheme}', host='{parsed.hostname}'"
    )
```

Wire it into `validate_comment_kind`:

```python
elif self.kind == "sticker":
    if not (self.sticker_id or "").strip():
        raise ValueError("sticker_id is required for sticker comments")
    if not (self.sticker_url or "").strip():
        raise ValueError("sticker_url is required for sticker comments")
    self.sticker_url = _validate_sticker_url(self.sticker_url)   # <-- ADD
```

### Change 2: Settings field for additional allowed CDN origins

Add a settings field to allow multiple CDN origins without code changes:

```python
# app/core/settings.py
sticker_cdn_allowed_prefixes: str = os.environ.get(
    "STICKER_CDN_ALLOWED_PREFIXES", ""
)
```

The validator resolves this at runtime and prepends each prefix as an additional allowed origin.

### SECOPS-007 dev/prod parity

- In **dev**, `/mock/s3/stickers/` is the expected prefix (matching the model docstring example at line 1610). No special dev-mode bypass is needed; the relative-path check applies to both environments.
- In **prod**, `FILEMGR_MEDIA_PREVIEW_CDN_BASE_URL` provides the CDN base (e.g., `https://cdn.example.com`). The same `_validate_sticker_url` function runs in both environments using the settings-resolved prefix.
- No split code path. No `if S.dev_mode` conditional around the validation.

### Backward compatibility

The fix is applied at the write layer only. Existing stored `sticker_url` values are unaffected. New writes with off-platform URLs return `HTTP 422`. No API response schema changes.

### Migration note

Existing records in DynamoDB with non-platform `sticker_url` values are not cleaned up by this fix. A data-hygiene script should scan `CommentKind="sticker"` records, identify URLs that do not match the allowed prefixes, and either null them out or flag them for moderation review. This is a separate operational task.

### Alternatives considered

1. **Rewrite sticker_url at write time to a canonical platform path**: Safer long-term (ensures stored data is always platform-relative), but requires an `sticker_id → canonical URL` lookup at validation time, coupling the validator to the sticker catalog service.
2. **Domain allowlist (like gif_url)**: Looser than needed. Since the platform controls all sticker content, a full platform-origin check is achievable and preferable.
3. **Client-side-only enforcement**: Insufficient. API clients (including the E2E tests) call the endpoint directly; frontend validation is easily bypassed.

## 5. Testing, Verification & Rollout

### Regression test (fails before fix, passes after)

**File**: `tests/test_newsfeed_sticker_url_validation.py` (new file)

```python
"""GAP-0183: sticker_url must only accept platform-relative or platform CDN URLs."""
import pytest
from pydantic import ValidationError

from app.routers.newsfeed import CreateCommentRequest


VALID_DEV_URL = "/mock/s3/stickers/coll_love_pack/stk_love_heart_01.webp"
VALID_STICKER_PATH = "/stickers/pack1/stk001.webp"


def _make(sticker_url: str) -> dict:
    return {
        "kind": "sticker",
        "sticker_id": "stk001",
        "sticker_collection_id": "pack1",
        "sticker_url": sticker_url,
        "sticker_alt_text": "test sticker",
    }


# --- cases that must PASS ---

def test_valid_dev_path():
    req = CreateCommentRequest(**_make(VALID_DEV_URL))
    assert req.sticker_url == VALID_DEV_URL


def test_valid_stickers_path():
    req = CreateCommentRequest(**_make(VALID_STICKER_PATH))
    assert req.sticker_url == VALID_STICKER_PATH


# --- cases that must FAIL (these pass before the fix) ---

def test_arbitrary_https_rejected():
    with pytest.raises(ValidationError, match="platform"):
        CreateCommentRequest(**_make("https://attacker.example.com/evil.webp"))


def test_data_uri_rejected():
    with pytest.raises(ValidationError, match="platform|scheme"):
        CreateCommentRequest(**_make("data:image/webp;base64,AAAA"))


def test_javascript_uri_rejected():
    with pytest.raises(ValidationError, match="platform|scheme"):
        CreateCommentRequest(**_make("javascript:alert(1)"))


def test_arbitrary_relative_path_rejected():
    with pytest.raises(ValidationError, match="platform"):
        CreateCommentRequest(**_make("/uploads/attacker/malicious.webp"))


def test_empty_scheme_rejected():
    with pytest.raises(ValidationError, match="platform|scheme"):
        CreateCommentRequest(**_make("//evil.com/sticker.webp"))
```

**Before fix**: The four "must FAIL" cases all pass validation (no `ValidationError` raised), causing the tests to fail.

**After fix**: All tests pass.

### Metrics / observability

Add a structured log warning in `_validate_sticker_url` on rejection:

```python
import logging
logger = logging.getLogger(__name__)
logger.warning("sticker_url rejected", extra={"url_prefix": url[:64]})
```

This allows CloudWatch Insights to surface probing attempts without logging the full URL.

### Rollback

Remove the `self.sticker_url = _validate_sticker_url(self.sticker_url)` call from `validate_comment_kind`. No schema or data migration needed to roll back.

### Risks

- **Dev test breakage**: If any existing test posts a `sticker_url` with a path outside `/mock/s3/stickers/`, it will break. The existing model docstring example (`/mock/s3/stickers/coll_love_pack/stk_love_heart_01.webp`) is within the allowed prefix and will continue to pass.
- **Relative-path vs absolute-path client behavior**: Clients that currently POST fully-qualified `https://...` sticker URLs from the platform CDN will be rejected if `FILEMGR_MEDIA_PREVIEW_CDN_BASE_URL` is not configured. This setting must be present in prod before the fix is deployed there.

### Effort: S (Small)

One new helper function (~25 lines), one optional settings field, one call site in the existing validator. Tests are offline/pytest only.

### Sequencing

Apply together with GAP-0182 (`gif_url`) in a single PR. Both gaps are in `app/routers/newsfeed.py` and share the same validator method. Deploy after confirming `FILEMGR_MEDIA_PREVIEW_CDN_BASE_URL` is set in the prod environment.
