# GAP-0033: FFmpeg Receives `s3://` URI Directly; Most Builds Lack S3 Protocol Support — Remediation Write-up

> ~5 pages. Fix-oriented. Cites real code at file:line. Builds on investigation doc
> `docs/tickets/gap-tickets/investigations/GAP-0033.md`.

## 1. Summary & Classification

**GAP-0033** identifies a critical production outage in the VOD transcoding pipeline.
The transcode worker passes a raw `s3://bucket/key` URI directly as the FFmpeg `-i`
input argument. Standard FFmpeg builds do not include the S3 demuxer protocol and exit
immediately with "Protocol not found", causing every transcode job to fail on its first
rendition.

- **Severity**: CRIT (complete VOD feature outage in production)
- **Source ticket**: VOD-004
- **Owning area**: Transcode worker (`app/services/transcode_worker.py`,
  `app/services/ffmpeg_abr_pipeline.py`)
- **Status**: Open
- **Effort**: M (~3 hours)

**Verdict**: Confirmed. `app/services/transcode_worker.py:101` reads `source_uri`
verbatim from the job record and passes it unchanged at line 118 into
`_run_ffmpeg_for_rendition`. `app/services/ffmpeg_abr_pipeline.py:75` uses this value
directly as the `-i` flag value. No download step, no presign, no local-path conversion
exists anywhere in the repository (`vod_s3_downloader.py` is absent entirely). A comment
at `transcode_worker.py:146-147` references "a download step" but the implementation was
never written.

**One-line impact**: Every video uploaded to the platform is transcoded to `failed` status
immediately; no VOD content is ever playable in production.

**Related tickets**: VOD-004 (original spec), GAP-0034 (`hls_manifest_url` never written
— the downstream gap that would surface even if GAP-0033 were fixed), GAP-0033 and
GAP-0034 must be fixed together for end-to-end video playback to work.

## 2. Current-State Investigation (Root Cause)

### 2.1 How `source_uri` becomes an `s3://` string

**Job submission** — `app/routers/transcode_jobs.py:83-88`:

```python
source_uri = body.source_uri
if not source_uri:
    s3_key = video.source_s3_key or ""
    if s3_key:
        bucket = S.video_upload_bucket or "local-uploads"
        source_uri = f"s3://{bucket}/{s3_key}"
```

When no explicit `source_uri` is provided in the request body (the normal path for
platform-uploaded videos), the code constructs `s3://local-uploads/<key>`. This string
is stored in the `transcode_jobs` DynamoDB record under the `source_uri` attribute.

### 2.2 The worker passes it directly to FFmpeg

**Worker execution** — `app/services/transcode_worker.py:99-124`:

```python
renditions: List[Dict[str, Any]] = job.get("renditions", [])
source_uri = job.get("source_uri", "")       # line 101 — "s3://bucket/key"
watermark = job.get("watermark", {})

completed_renditions: List[str] = []
total = len(renditions)

for i, rendition in enumerate(renditions):
    ...
    await _run_ffmpeg_for_rendition(
        job_id=job_id,
        source_uri=source_uri,               # line 118 — unchanged
        rendition=rendition,
        ...
    )
```

There is no download pre-step between lines 101 and 116. The `source_uri` value at
line 118 is the same `s3://` string from the job record.

### 2.3 FFmpeg receives it as `-i`

**`app/services/ffmpeg_abr_pipeline.py:75`**:

```python
args = [ffmpeg_bin, "-hide_banner", "-loglevel", "warning", "-y",
        "-rw_timeout", "5000000",
        "-i", input_url]   # input_url == "s3://bucket/key"
```

The final command executed is: `ffmpeg ... -i s3://bucket/key ...`.

### 2.4 The dead-code comment and absent downloader

`app/services/transcode_worker.py:145-149`:

```python
source_path = scratch_dir / "source"
# Find source file in scratch dir (download step places it here)
source_candidates = list(scratch_dir.glob("source*"))
if source_candidates:
    source_path = source_candidates[0]
```

This glob looks for a file that a "download step" would have placed in `scratch_dir`.
No download step exists anywhere before this point; `source_candidates` is always an
empty list. The code was written in anticipation of a downloader that was never
implemented.

A file-system search confirms `vod_s3_downloader.py` is absent:
`find /home/ubuntu/testlogon/app -name "vod_s3_downloader.py"` returns no results.

### 2.5 Why standard FFmpeg builds fail

FFmpeg's native S3 protocol support (`libavformat`'s `s3` demuxer) requires the binary to
be compiled with `--enable-protocol=s3` and linked against the AWS SDK. The standard
Ubuntu/Debian apt package (`ppa:savoury1/ffmpeg4` or the default `apt install ffmpeg`)
does not include this protocol. When FFmpeg encounters `s3://...` as an input, it exits:

```
s3://bucket/key: Protocol not found
```

The FFmpeg executor's error-matching logic in `ffmpeg_executor.py:39` treats this as
equivalent to "No such file or directory" and raises `NonRetryableError("source_not_found",
...)`, causing the job to fail immediately on the first rendition without retrying.

### 2.6 Root cause

VOD-004's implementation built the FFmpeg execution layer and stored the S3 URI in the
job record for tracking purposes, but omitted the S3 download pre-step that was implicitly
required. The comment at line 146-147 shows the developer intended to add the downloader
but never wrote `vod_s3_downloader.py` or the call to it.

## 3. Impact / Exploit / Blast Radius

**Who is affected**: Every user who uploads a video and expects it to transcode to HLS.
The `transcode_jobs` record for every submitted job transitions to `failed` status on the
first rendition attempt.

**Failure mode from the user's perspective**:
1. Video is uploaded; status shows `queued` then `processing`.
2. After the first rendition attempt (~seconds), the job transitions to `failed`.
3. The video remains in `queued` or `failed` state; `hls_manifest_url` is never populated
   (covered by GAP-0034); the video is permanently unplayable.

**Severity**: CRIT — the entire VOD pipeline is a no-op in production. No transcoding,
no playback, no thumbnails.

**No security exploit**: The impact is functional availability, not confidentiality or
integrity. A malformed `source_uri` (e.g., attacker-controlled) cannot be supplied through
normal user paths because the router always constructs the URI from a server-controlled
S3 key and bucket name.

**Dev vs prod discrepancy**: In dev mode, if `S.vod_thumbnail_enabled` is false and the
`source_candidates` glob is used for thumbnails only, the crash manifests at the FFmpeg
call. Because the local dev stack may use a different transcoding path (or may not run
the transcode worker at all), this bug may not be visible in development but will be
fatal in any production deployment that runs the worker.

## 4. Fix Design (Code-Level)

### 4.1 New module — `app/services/vod_s3_downloader.py`

Create this file (does not exist yet):

```python
"""Download a video source from S3 to a local scratch path before FFmpeg.

Used by transcode_worker.py to convert an s3:// URI to a local file path
that standard FFmpeg builds (without the S3 protocol demuxer) can read.
"""
from __future__ import annotations

import re
from pathlib import Path

from app.core.aws import s3_client


def download_source_to_scratch(source_uri: str, scratch_dir: Path) -> Path:
    """Download s3://bucket/key to scratch_dir/source.<ext>. Returns local path.

    If source_uri is not an s3:// URI (e.g. already a local path or HTTPS
    presigned URL), it is returned as a Path without downloading.
    """
    m = re.match(r"^s3://([^/]+)/(.+)$", source_uri)
    if not m:
        # Not an s3:// URI — assume it is already a usable local path.
        return Path(source_uri)
    bucket, key = m.group(1), m.group(2)
    ext = Path(key).suffix or ".mp4"
    dest = scratch_dir / f"source{ext}"
    dest.parent.mkdir(parents=True, exist_ok=True)
    s3_client().download_file(bucket, key, str(dest))
    return dest
```

`s3_client()` from `app/core/aws.py` returns a `boto3.client("s3", ...)` instance. In dev
mode, moto intercepts all botocore calls at the botocore layer, so
`s3_client().download_file(...)` transparently reads from the moto in-process S3 mock.
In production, it reads from AWS S3 using IAM role credentials. The behaviour is identical
from the caller's perspective.

### 4.2 Patch `app/services/transcode_worker.py`

Insert the download step between lines 101 (source_uri assignment) and 107 (rendition loop
start):

```python
source_uri = job.get("source_uri", "")         # line 101 — "s3://bucket/key"
watermark = job.get("watermark", {})

# Download source to local scratch before passing to FFmpeg.
# Standard FFmpeg builds do not support the s3:// protocol natively.
from app.services.vod_s3_downloader import download_source_to_scratch
source_uri = str(download_source_to_scratch(source_uri, scratch_dir))
# source_uri is now a local file path, e.g. /tmp/transcode/<job_id>/source.mp4
```

No change to `_run_ffmpeg_for_rendition` or `ffmpeg_abr_pipeline.py` is required —
they will receive a local file path instead of an `s3://` URI.

The existing thumbnail extraction code at lines 145-149 also benefits: `scratch_dir.glob("source*")`
will now find the downloaded file because `download_source_to_scratch` writes to
`scratch_dir/source.<ext>`.

### 4.3 Move the import to the module top-level (optional cleanup)

To avoid a per-job import inside the hot path, add the import at the module top level
alongside the other `app.services.*` imports. The `from ... import ...` inside the
`try` block is an existing pattern in this file (lines 128, 138, 163, 180, 188, 201, 208)
and is acceptable for lazy dependency management, but a top-level import is preferable
for clarity and performance.

### 4.4 Dev/Prod parity (SECOPS-007)

| Aspect | Dev | Prod |
|---|---|---|
| `s3_client()` target | moto in-process mock | AWS S3 |
| `download_file` call | intercepted by moto botocore layer | AWS SDK call |
| IAM credentials | `AWS_ACCESS_KEY_ID=test` (mock) | IAM role attached to worker instance/task |
| Worker IAM policy needed | none (mock accepts any) | `s3:GetObject` on source bucket |
| `source_uri` format | `s3://local-uploads/<key>` | `s3://<real-bucket>/<key>` |
| Behaviour of fix | identical code path | identical code path |

The only prod-specific action item is ensuring the worker's IAM role has `s3:GetObject`
on the video upload bucket. This should already exist as part of the VOD-004 infra ticket.

### 4.5 Alternatives considered

- **Compile FFmpeg with S3 support**: Requires a custom build step, significantly
  increases the Docker image size, ties the application to a specific FFmpeg build,
  and introduces a new binary dependency chain. Rejected in favour of the standard
  `boto3.download_file` path.
- **Use presigned HTTPS URLs as the `-i` input**: FFmpeg's HTTPS demuxer is always
  available, and a presigned URL for the source would work. However, presigned URLs
  expire, and very large files could stall FFmpeg mid-transcode if the URL expires.
  The download-first approach is more robust for large files and does not require
  managing URL expiry during transcoding.
- **Mount S3 via S3FS/FUSE**: Operational complexity, not appropriate for a containerised
  or Lambda-style worker. Rejected.

## 5. Testing, Verification & Rollout

### 5.1 Regression tests (pytest offline, using moto)

```python
# tests/test_vod_s3_downloader.py
from pathlib import Path
from unittest.mock import patch, MagicMock
from app.services.vod_s3_downloader import download_source_to_scratch


def test_download_s3_uri_calls_boto3(tmp_path):
    """download_source_to_scratch issues boto3 download_file for s3:// URIs.
    Before fix: function does not exist → ImportError.
    After fix: passes and mock is called.
    """
    with patch("app.services.vod_s3_downloader.s3_client") as mock_s3:
        mock_client = MagicMock()
        mock_s3.return_value = mock_client
        result = download_source_to_scratch("s3://my-bucket/videos/clip.mp4", tmp_path)
        mock_client.download_file.assert_called_once_with(
            "my-bucket", "videos/clip.mp4", str(tmp_path / "source.mp4")
        )
        assert result == tmp_path / "source.mp4"


def test_download_preserves_extension(tmp_path):
    """Extension is derived from the S3 key."""
    with patch("app.services.vod_s3_downloader.s3_client") as mock_s3:
        mock_s3.return_value = MagicMock()
        result = download_source_to_scratch("s3://bucket/path/video.mov", tmp_path)
        assert result.name == "source.mov"


def test_download_defaults_to_mp4_on_no_extension(tmp_path):
    """If the S3 key has no extension, fallback is .mp4."""
    with patch("app.services.vod_s3_downloader.s3_client") as mock_s3:
        mock_s3.return_value = MagicMock()
        result = download_source_to_scratch("s3://bucket/noext", tmp_path)
        assert result.name == "source.mp4"


def test_passthrough_for_local_path(tmp_path):
    """Non-s3:// URIs are returned unchanged as a Path, no download issued."""
    result = download_source_to_scratch("/tmp/local/file.mp4", tmp_path)
    assert result == Path("/tmp/local/file.mp4")


def test_passthrough_for_https_url(tmp_path):
    """HTTPS presigned URLs are passed through without downloading."""
    url = "https://s3.amazonaws.com/bucket/key?AWSAccessKeyId=..."
    result = download_source_to_scratch(url, tmp_path)
    assert result == Path(url)


# tests/test_transcode_worker_download_integration.py
import pytest
from unittest.mock import patch, AsyncMock, MagicMock

@pytest.mark.asyncio
async def test_worker_calls_download_before_ffmpeg(tmp_path, mock_job):
    """execute_transcode_job must call download_source_to_scratch before
    _run_ffmpeg_for_rendition.
    Before fix: ffmpeg receives 's3://' URI and raises NonRetryableError.
    After fix: download is called; ffmpeg receives a local path.
    """
    from app.services.transcode_worker import execute_transcode_job

    with patch("app.services.vod_s3_downloader.download_source_to_scratch",
               return_value=tmp_path / "source.mp4") as mock_dl, \
         patch("app.services.transcode_worker._run_ffmpeg_for_rendition",
               new_callable=AsyncMock) as mock_ffmpeg:

        await execute_transcode_job(mock_job)

        mock_dl.assert_called_once()
        call_args = mock_ffmpeg.call_args
        # ffmpeg receives local path, not s3:// URI
        assert not str(call_args.kwargs.get("source_uri", "")).startswith("s3://")
```

**Fails before**: `test_download_s3_uri_calls_boto3` raises `ModuleNotFoundError`
(module does not exist). `test_worker_calls_download_before_ffmpeg` fails because
`mock_ffmpeg` receives an `s3://` URI.

**Passes after**: All six tests pass.

### 5.2 Manual QA steps

1. Start dev stack (`just up`).
2. Upload a test video via the file manager UI.
3. Submit a transcode job via `POST /ui/transcode/jobs`.
4. Check `GET /ui/transcode/jobs/{id}` — verify status transitions to `processing`.
5. Check that `scratch_dir/<job_id>/source.mp4` is created (moto intercepted the S3 get).
6. If FFmpeg is installed locally, verify the rendition completes and status reaches
   `completed`.

### 5.3 Production checklist

- Confirm the worker IAM role has `s3:GetObject` permission on `S.video_upload_bucket`.
- Confirm `scratch_dir` (from `S.transcode_scratch_dir`) has sufficient disk space for
  the largest expected source file before transcoding begins. The download adds a full
  copy of the source to scratch.
- After deploy, monitor `transcode_jobs` table for jobs transitioning to `failed` — a
  clean deploy should show this error disappearing.

### 5.4 Rollout and rollback

- No schema changes; no new DynamoDB tables.
- The new module is imported lazily inside the worker's hot path; other services are
  not affected.
- Rollback: revert `transcode_worker.py` and delete `vod_s3_downloader.py`. Jobs
  already in `failed` status remain failed; they must be re-submitted.

### 5.5 Risk and effort

- **Risk**: Low. The change adds a well-understood boto3 `download_file` call on a code
  path that was previously crashing every time. The only new failure mode is an S3
  access error (IAM permission missing), which would manifest as a clear error message
  rather than the opaque "Protocol not found" crash.
- **Effort**: M — ~3 hours: create `vod_s3_downloader.py` (~35 lines), patch
  `transcode_worker.py` (~5 lines), write unit and integration tests (~60 lines).
- **Sequencing**: Must be deployed before or alongside GAP-0034. The two fixes together
  complete the end-to-end VOD transcoding + playback pipeline.
