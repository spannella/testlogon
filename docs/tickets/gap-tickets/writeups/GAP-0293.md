# GAP-0293: `BroadcastPriceEditor.tsx` Component Does Not Exist — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; all file:line citations confirmed.

## 1. Summary & Classification

**Bug**: The broadcaster-facing `BroadcastPriceEditor.tsx` React component, specified in LCOM-004 §3.9, does not exist. `ProductShelfManager.tsx` — the broadcaster's tool for managing which catalog items appear on the shelf during a live session — has no UI for setting or clearing broadcast-exclusive prices on individual shelf items. The backend endpoints are fully implemented (`PATCH /broadcast/sessions/{id}/products/{item_id}/price` and `DELETE /broadcast/sessions/{id}/products/{item_id}/price` at `app/routers/broadcast.py:2223–2310`), but a broadcaster has no way to invoke them without making raw API calls.

**Severity**: HIGH (source ticket LCOM-004). Effort: M.

**Status**: Open. No investigation doc exists; claim confirmed by filesystem search.

**Claim verdict**: Confirmed. `find /home/ubuntu/testlogon/frontend/src -name "BroadcastPriceEditor*"` returns no results. `ProductShelfManager.tsx` renders each shelf item row with only move-up, move-down, and delete controls (lines 199–267); there is no price-setting control, no reference to `setBroadcastPrice` or `clearBroadcastPrice`, and no import of those API wrappers. The ticket's reference to `app/routers/broadcast.py:2227` is accurate — `set_broadcast_price_route` begins at that line.

**Related tickets**: GAP-0291 (extend `ShelfItem` type — prerequisite), GAP-0292 (`BroadcastPrice.tsx` viewer component — companion); SEC implication: the backend already validates broadcaster identity at `app/routers/broadcast.py:2241`.

**Owning area**: Frontend / Broadcast management UI.

## 2. Current-State Investigation (Root Cause)

### Backend — fully implemented

`app/routers/broadcast.py:2220–2310` provides two endpoints:

**Set price** (`PATCH /sessions/{session_id}/products/{item_id}/price`):
- Requires `ctx["user_sub"] == session.created_by` (broadcaster-only, line 2241).
- Validates that `broadcast_price_cents < catalog_price` (enforced in service layer, `app/services/broadcast_product_shelf.py:347–352`).
- Accepts optional `expires_in_seconds` (60–86400 seconds, per `app/models.py:2561`).
- Writes DynamoDB update atomically and, if the session is live, publishes an SSE `shelf:price_update` event.
- Returns `BroadcastPriceOut` with `original_price_cents`, `broadcast_price_cents`, `broadcast_price_expires_at`, `discount_pct`, `set_by`, `set_at`.

**Clear price** (`DELETE /sessions/{session_id}/products/{item_id}/price`):
- Same broadcaster-only guard.
- Removes `broadcast_price_cents`, `broadcast_price_expires_at`, `broadcast_price_set_at` from DynamoDB.
- Publishes SSE `shelf:price_update` with `is_broadcast_price: false`.

### Frontend — what `ProductShelfManager.tsx` renders per item

`frontend/src/pages/broadcast/ProductShelfManager.tsx:199–267` renders each shelf row as:
- Drag handle
- Thumbnail image
- `item.name` and `formatPrice(item.price_cents, item.currency)` (line 228 — always catalog price)
- Move-up, move-down, and delete buttons

There is no "Set Price" or "Clear Price" button, no inline form for entering a broadcast price, and no import of `setBroadcastPrice` or `clearBroadcastPrice`. The comment at line 53 (`void _sessionCreatedBy; // used for future ownership checks`) is the only acknowledgment that broadcaster-specific functionality was anticipated but not implemented.

The `broadcast-shelf.ts` API file also lacks `setBroadcastPrice` and `clearBroadcastPrice` exports (part of GAP-0291's fix), which are prerequisites for this component.

### Root cause

LCOM-004 specified `BroadcastPriceEditor.tsx` as a per-row inline editor to be embedded in `ProductShelfManager.tsx`. The service and router layers were implemented; the frontend component was not created. The comment at `ProductShelfManager.tsx:53` confirms this was deferred.

## 3. Impact / Exploit / Blast Radius

1. **Broadcast pricing feature is inaccessible in the UI**: Broadcasters cannot set or clear discounted prices from the management interface. The only workaround is raw API calls (e.g., Postman or curl), which is not viable for non-technical users.

2. **Lost commerce conversion opportunity**: Time-limited flash deals (the primary use case for broadcast pricing) require fast, in-stream UI interaction. Without `BroadcastPriceEditor.tsx`, a broadcaster cannot spontaneously drop the price during a live session, which is the exact scenario LCOM-004 was designed to enable.

3. **Partial backend writes may persist uncleaned**: If a broadcaster sets a price via a raw API call during a live session, there is no UI to clear it. If `expires_in_seconds` is not set, the broadcast price persists indefinitely on the shelf item record in DynamoDB. Subsequent sessions that re-add the same item will inherit the stale broadcast price until it is manually cleared.

4. **No security concern**: The backend enforces broadcaster-only access. This gap is purely a missing UI — it does not create an authorization hole.

**Blast radius**: All broadcasters who want to use live pricing. The feature is effectively dead from a UX perspective for non-API users.

## 4. Fix Design (Code-Level)

### 4a. Create `BroadcastPriceEditor.tsx`

Create `frontend/src/pages/broadcast/BroadcastPriceEditor.tsx`:

```tsx
// frontend/src/pages/broadcast/BroadcastPriceEditor.tsx

import { useState } from "react";
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { Tag, X, Loader2 } from "lucide-react";
import { toast } from "sonner";
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";
import { Badge } from "@/components/ui/badge";
import {
  Popover,
  PopoverContent,
  PopoverTrigger,
} from "@/components/ui/popover";
import {
  setBroadcastPrice,
  clearBroadcastPrice,
  type ShelfItem,
} from "@/api/endpoints/broadcast-shelf";

interface BroadcastPriceEditorProps {
  sessionId: string;
  item: ShelfItem;
}

export function BroadcastPriceEditor({ sessionId, item }: BroadcastPriceEditorProps) {
  const queryClient = useQueryClient();
  const [open, setOpen] = useState(false);
  const [priceInput, setPriceInput] = useState("");
  const [expiryInput, setExpiryInput] = useState("");

  const invalidate = () =>
    queryClient.invalidateQueries({ queryKey: ["broadcast-shelf", sessionId] });

  const setMut = useMutation({
    mutationFn: () => {
      const cents = Math.round(parseFloat(priceInput) * 100);
      const expiry = expiryInput ? parseInt(expiryInput, 10) * 60 : undefined;
      return setBroadcastPrice(sessionId, item.item_id, {
        broadcast_price_cents: cents,
        expires_in_seconds: expiry,
      });
    },
    onSuccess: (data) => {
      invalidate();
      toast.success(
        `Broadcast price set: ${(data.data.broadcast_price_cents / 100).toFixed(2)} (${data.data.discount_pct}% off)`
      );
      setOpen(false);
      setPriceInput("");
      setExpiryInput("");
    },
    onError: (err) =>
      toast.error(err instanceof Error ? err.message : "Failed to set price"),
  });

  const clearMut = useMutation({
    mutationFn: () => clearBroadcastPrice(sessionId, item.item_id),
    onSuccess: () => {
      invalidate();
      toast.success("Broadcast price cleared");
    },
    onError: (err) =>
      toast.error(err instanceof Error ? err.message : "Failed to clear price"),
  });

  const catalogDollars = (item.price_cents / 100).toFixed(2);
  const maxDollars = ((item.price_cents - 1) / 100).toFixed(2);

  return (
    <div className="flex items-center gap-1">
      {item.is_broadcast_price && (
        <Badge variant="destructive" className="text-[10px] px-1 h-4"
               data-testid={`broadcast-price-active-badge-${item.item_id}`}>
          {item.discount_pct}% OFF
        </Badge>
      )}
      <Popover open={open} onOpenChange={setOpen}>
        <PopoverTrigger asChild>
          <Button
            variant="ghost"
            size="icon"
            className="h-6 w-6"
            aria-label={`Set broadcast price for ${item.name}`}
            data-testid={`set-broadcast-price-btn-${item.item_id}`}
          >
            <Tag className="h-3 w-3" />
          </Button>
        </PopoverTrigger>
        <PopoverContent className="w-64 p-3" align="end">
          <div className="space-y-3">
            <p className="text-sm font-medium">Broadcast Price</p>
            <p className="text-xs text-muted-foreground">
              Catalog price: ${catalogDollars}. Must be less than ${maxDollars}.
            </p>
            <div className="space-y-1">
              <Label htmlFor={`bp-price-${item.item_id}`} className="text-xs">
                Price ($)
              </Label>
              <Input
                id={`bp-price-${item.item_id}`}
                type="number"
                min="0.01"
                max={maxDollars}
                step="0.01"
                placeholder={`e.g. ${(item.price_cents / 200).toFixed(2)}`}
                value={priceInput}
                onChange={(e) => setPriceInput(e.target.value)}
                data-testid={`broadcast-price-input-${item.item_id}`}
              />
            </div>
            <div className="space-y-1">
              <Label htmlFor={`bp-expiry-${item.item_id}`} className="text-xs">
                Expires in (minutes, optional)
              </Label>
              <Input
                id={`bp-expiry-${item.item_id}`}
                type="number"
                min="1"
                max="1440"
                placeholder="e.g. 10"
                value={expiryInput}
                onChange={(e) => setExpiryInput(e.target.value)}
                data-testid={`broadcast-price-expiry-input-${item.item_id}`}
              />
            </div>
            <div className="flex gap-2">
              <Button
                size="sm"
                className="flex-1"
                disabled={!priceInput || setMut.isPending}
                onClick={() => setMut.mutate()}
                data-testid={`broadcast-price-save-btn-${item.item_id}`}
              >
                {setMut.isPending ? <Loader2 className="h-3 w-3 animate-spin mr-1" /> : null}
                Set Price
              </Button>
              {item.is_broadcast_price && (
                <Button
                  size="sm"
                  variant="outline"
                  disabled={clearMut.isPending}
                  onClick={() => clearMut.mutate()}
                  data-testid={`broadcast-price-clear-btn-${item.item_id}`}
                >
                  {clearMut.isPending ? <Loader2 className="h-3 w-3 animate-spin" /> : <X className="h-3 w-3" />}
                </Button>
              )}
            </div>
          </div>
        </PopoverContent>
      </Popover>
    </div>
  );
}
```

### 4d. Dev/Prod parity (SECOPS-007)

No backend changes are required. The `setBroadcastPrice` and `clearBroadcastPrice` API wrappers added by GAP-0291's fix call the same backend endpoints in both dev and prod. The broadcaster-only guard at the backend (`ctx["user_sub"] != session.created_by`) applies identically in both environments. The local DynamoDB stack and the production DynamoDB path share the same code in `app/services/broadcast_product_shelf.py`. No feature flags gate these endpoints.

Input validation for `broadcast_price_cents < catalog_price` is enforced server-side at `app/services/broadcast_product_shelf.py:347–352`, so even if the frontend validation is bypassed, the backend rejects invalid inputs with HTTP 400.

### 4e. Alternatives considered

- **Inline price input directly in the shelf row without a popover**: Simpler but clutters the row UI in the management panel, especially when many items are present. Rejected in favour of a popover that opens on demand.
- **Dedicated modal dialog instead of popover**: Heavier UX, requires a separate dialog component and more state management. Popover is lighter and contextual. Rejected.
- **Restrict price editing to live sessions only**: The backend allows price editing for `draft`/`ready`/`live` sessions (it only blocks `stopping`/`stopped`/`error`). Restricting to `live` only would reduce the broadcaster's ability to pre-configure deals. Rejected.
