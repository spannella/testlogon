# GAP-0068: Global Ad Kill Switch Absent — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual codebase 2026-06-05; claim is **confirmed**.

## 1. Summary & Classification

- **Severity**: HIGH
- **Source ticket**: ADS-018 · **Status**: Open
- **Owning area**: Backend / Admin Ad Platform (`app/services/admin_ad_platform.py`,
  `app/services/ad_serving.py`, `app/routers/admin_ad_platform.py`)
- **Verdict**: CONFIRMED. There is no emergency mechanism to halt all ad serving platform-wide.
  `admin_ad_platform.py` has no `toggle_kill_switch` function, `ad_serving.py` has no kill-
  switch check, and the `admin_ad_platform_router` has no `/kill-switch` endpoint. In an
  incident requiring immediate ad stoppage (legal hold, CSAM adjacency, billing runaway, fraud
  spike), operators must manually reject every active campaign one at a time.
- **Impact**: Operational — time-to-mitigate for platform-wide ad incidents is hours/days
  instead of seconds. Financial exposure accumulates every second until the last campaign is
  manually paused.
- **Related tickets**: GAP-0069 (account suspension cascade — complementary operational gap),
  ADS-018 source ticket, SECOPS-007 (dev/prod parity).

## 2. Current-State Investigation (root cause)

### admin_ad_platform.py — no kill switch service function

A full read of `app/services/admin_ad_platform.py` (385 lines) reveals no function named
`toggle_kill_switch`, `set_kill_switch`, or any equivalent. The service provides:
- `list_all_advertiser_accounts`, `list_all_campaigns`, `list_all_creatives` (scan-based)
- `get_account_detail`, `moderate_account`, `moderate_creative`
- `get_platform_metrics`, `get_monthly_revenue_series`, `get_top_spenders`

None of these provide a platform-wide halting mechanism.

### admin_ad_platform_router — no /kill-switch endpoint

`app/routers/admin_ad_platform.py` (193 lines) exposes endpoints under `/ui/admin/ad-platform`:
- `GET /accounts`, `GET /accounts/{id}`, `GET /campaigns`, `GET /creatives`
- `GET /moderation/queue`, `GET /moderation/{type}/{id}/history`
- `POST /accounts/{id}/moderate`, `POST /creatives/{id}/moderate`
- `GET /metrics`, `GET /metrics/revenue-series`, `GET /metrics/top-spenders`

There is no `POST /kill-switch` or `GET /kill-switch` endpoint.

### ad_serving.py — no kill-switch check at startup or per-call

`app/services/ad_serving.py:serve_ad` (lines 45–168) performs these checks before selecting
an ad:
1. Creator allows ads (`get_creator_ad_settings`)
2. Active campaigns exist
3. Account fraud suspension (via `is_account_suspended` from `ad_fraud_prevention`)
4. Creator block list
5. Budget check
6. Dayparting / flight eligibility
7. Targeting match
8. Frequency cap

Step 3 only checks **fraud**-suspension, not admin suspension from `moderate_account`. There is
no step that checks a platform-level kill switch flag.

### Comparison: kill switch patterns elsewhere in the codebase

Other subsystems implement kill switches as env-var gates checked on each request:

```python
# app/routers/messaging.py:263-267
kill_switch = os.getenv(
    "MESSAGING_MASS_SEND_KILL_SWITCH",
    "true" if getattr(S, "messaging_mass_send_kill_switch", False) else "false",
)
return enabled and not kill_switch

# app/routers/messaging.py:1628-1629
kill_switch = os.getenv("MESSAGING_DRAFTS_KILL_SWITCH", "0").strip().lower() in {"1", "true", "on", "yes"}
if kill_switch:
    ...
```

This pattern works for static env-var toggles but requires a process restart to take effect —
it is not a live toggle. The ADS-018 spec calls for a **persistent, live toggle** stored in
DynamoDB that takes effect on the next `serve_ad` call without a restart.

## 3. Impact / Exploit / Blast Radius

### Incident scenarios requiring immediate kill

| Scenario | Without kill switch | With kill switch |
|---|---|---|
| Malicious creative discovered after approval | Manually reject creative across all campaigns; ~minutes per creative | One POST; all serving stops in <1 s |
| Legal hold (court order on ad content) | Must pause all active campaigns one by one (may be hundreds) | One POST with `reason` field |
| Billing runaway (bug causes double-charging) | Campaigns keep running while bug is diagnosed; financial damage accumulates | Kill switch stops all charges instantly |
| Regulatory enforcement (GDPR breach discovered) | Every campaign still delivers targeting data; breach widens | Instant halt |
| Fraud spike exceeds tolerable rate | Fraud engine may auto-suspend individual accounts; platform-wide serving continues | Platform-level stop in one call |

### Blast radius of the absence

- **Every ad impression served during an active incident** is potentially billable,
  potentially legally exposed, and potentially user-harming.
- **No single-operator action** can stop serving — the task falls to whoever is on-call with
  DynamoDB console access or the ability to kill the uvicorn process.
- **Process restart** would halt serving but also cause a full backend outage; the kill switch
  allows granular control.

## 4. Fix Design (code-level)

### Design overview

1. **DynamoDB storage**: a single `PLATFORM_CONFIG` item in `T.ad_accounts` (reuse existing
   table; no new table needed) stores the kill-switch state.
2. **Service layer**: `toggle_kill_switch` writes the flag; `is_kill_switch_active` reads it
   with a 5-second in-process TTL cache to avoid DDB overhead on every ad impression.
3. **Router**: `POST /ui/admin/ad-platform/kill-switch` (ROOT only) calls the service.
   `GET /ui/admin/ad-platform/kill-switch` reads current state.
4. **Serving engine**: `serve_ad` checks `is_kill_switch_active()` as the first gate (before
   any per-campaign logic) and returns `_empty_response("kill_switch_active")` if set.
5. **Audit**: every toggle writes a moderation-log entry (same `_log_moderation` pattern).

### Service layer — `app/services/admin_ad_platform.py`

Add after the existing imports:

```python
import time as _time

# ── Platform-level kill switch ───────────────────────────────────────────────

_KILL_SWITCH_PK = "PLATFORM_CONFIG"
_KILL_SWITCH_SK = "AD_KILL_SWITCH"
_KS_CACHE: dict[str, Any] = {}   # {"active": bool, "expires": float}
_KS_TTL_SECONDS = 5              # cache lifespan to cap DDB read latency impact


def is_kill_switch_active() -> bool:
    """Return True if the platform-wide ad kill switch is currently on.

    Result is cached for _KS_TTL_SECONDS to limit DynamoDB reads to at most
    once per 5 seconds per worker, while still reacting to toggle within that
    window. Failures fail open (returns False) so a DDB outage does not
    accidentally halt all ad serving.
    """
    now = _time.monotonic()
    if _KS_CACHE.get("expires", 0) > now:
        return bool(_KS_CACHE.get("active", False))
    try:
        resp = T.ad_accounts.get_item(
            Key={"pk": _KILL_SWITCH_PK, "sk": _KILL_SWITCH_SK}
        )
        item = resp.get("Item") or {}
        active = bool(item.get("active", False))
    except Exception:
        logger.warning("ad_kill_switch_read_failed — failing open")
        active = False
    _KS_CACHE.update({"active": active, "expires": now + _KS_TTL_SECONDS})
    return active


def toggle_kill_switch(
    *, enabled: bool, admin_sub: str, reason: str = "", request=None
) -> dict[str, Any]:
    """Enable or disable the platform-wide ad kill switch.

    Requires ROOT role (enforced at the router layer). Writes state to DynamoDB
    and an immutable audit/moderation log entry. Invalidates the in-process
    cache so the change takes effect within _KS_TTL_SECONDS on this worker.

    Args:
        enabled: True to halt all ad serving; False to resume.
        admin_sub: sub of the ROOT operator making the change.
        reason: required justification string (caller must validate non-empty).
        request: FastAPI Request object for audit logging (optional).

    Returns:
        {"ok": True, "active": bool, "toggled_by": str, "reason": str,
         "updated_at": int}
    """
    ts = now_ts()
    T.ad_accounts.put_item(
        Item={
            "pk": _KILL_SWITCH_PK,
            "sk": _KILL_SWITCH_SK,
            "active": enabled,
            "toggled_by": admin_sub,
            "reason": reason or "",
            "updated_at": ts,
        }
    )
    # Invalidate cache so this worker picks up the change immediately.
    _KS_CACHE.clear()
    _log_moderation(
        item_type="platform",
        item_id="ad_kill_switch",
        action="enable" if enabled else "disable",
        admin_sub=admin_sub,
        reason=reason,
        prev_status="inactive" if enabled else "active",
        new_status="active" if enabled else "inactive",
        request=request,
    )
    logger.warning(
        "ad_kill_switch_toggled enabled=%s admin_sub=%s reason=%s",
        enabled, admin_sub, reason,
    )
    return {"ok": True, "active": enabled, "toggled_by": admin_sub,
            "reason": reason, "updated_at": ts}


def get_kill_switch_state() -> dict[str, Any]:
    """Return the current kill switch state from DynamoDB (bypasses cache)."""
    try:
        resp = T.ad_accounts.get_item(
            Key={"pk": _KILL_SWITCH_PK, "sk": _KILL_SWITCH_SK}
        )
        item = resp.get("Item") or {}
        return {
            "active": bool(item.get("active", False)),
            "toggled_by": item.get("toggled_by", ""),
            "reason": item.get("reason", ""),
            "updated_at": int(item.get("updated_at", 0)),
        }
    except Exception:
        return {"active": False, "toggled_by": "", "reason": "", "updated_at": 0}
```

### Router — `app/routers/admin_ad_platform.py`

Add at the bottom (before the end of the file), after existing imports have
`require_root_session` in scope (already imported):

```python
# ── Platform kill switch (ROOT only) ────────────────────────────────────────

class KillSwitchToggleIn(BaseModel):
    enabled: bool
    reason: str = ""

class KillSwitchStateOut(BaseModel):
    active: bool
    toggled_by: str
    reason: str
    updated_at: int

@admin_ad_platform_router.post(
    "/kill-switch", response_model=KillSwitchStateOut,
    summary="Enable or disable the platform-wide ad kill switch (ROOT only)",
)
async def toggle_kill_switch(
    body: KillSwitchToggleIn,
    request: Request,
    user: AuthenticatedUser = Depends(require_root_session),
):
    if body.enabled and not body.reason:
        raise HTTPException(422, "reason is required when enabling the kill switch")
    result = svc.toggle_kill_switch(
        enabled=body.enabled, admin_sub=user.sub,
        reason=body.reason, request=request,
    )
    return result


@admin_ad_platform_router.get(
    "/kill-switch", response_model=KillSwitchStateOut,
    summary="Read the current platform-wide ad kill switch state",
)
async def get_kill_switch(
    _user: AuthenticatedUser = Depends(require_admin_or_root),
):
    return svc.get_kill_switch_state()
```

### Serving engine — `app/services/ad_serving.py`

Add as the **first gate** inside `serve_ad`, before the creator-settings check:

```python
def serve_ad(*, surface, content_type, creator_id, content_id, slot_type, user_id,
             user_context=None):
    """Select and return the best ad for the given context."""
    from app.services.admin_ad_platform import is_kill_switch_active  # noqa: F401 (lazy)

    # 0. Platform-wide kill switch (admin emergency halt).
    if is_kill_switch_active():
        return _empty_response("platform_kill_switch_active")

    # 1. Check creator allows ads (existing logic continues below…)
    ...
```

The lazy import avoids a circular import since `admin_ad_platform` imports from `ad_accounts`
but not from `ad_serving`.

### Dev/Prod parity (SECOPS-007)

| Concern | Dev | Prod |
|---|---|---|
| Storage | DynamoDB Local (port 8001) | AWS DynamoDB |
| Kill switch write | `T.ad_accounts.put_item` | Same |
| Kill switch read | `T.ad_accounts.get_item` (5s cache) | Same |
| Cache | In-process per-worker dict | Same (each pod caches independently) |
| Auth | `require_root_session` (cookie JWT) | Same |

No environment flags, no mock/real branching. The `PLATFORM_CONFIG / AD_KILL_SWITCH` item
simply does not exist until first toggled, which `is_kill_switch_active` handles by returning
`False` (fail-open). This is consistent in both environments.

### Alternatives considered

- **Env-var toggle**: requires process restart; unacceptable MTTR for an emergency stop.
- **Feature-flag service (LaunchDarkly etc.)**: overkill, adds an external dependency.
- **Separate `platform_config` DynamoDB table**: cleaner schema isolation but adds table-
  creation overhead and the `T.ad_accounts` table is structurally flexible (uses generic PK/SK).

### Manual QA steps

1. Start dev stack: `just up`.
2. Confirm ad serving works: `POST /ui/ads/serve` returns a filled response.
3. Enable kill switch (as ROOT):
   ```bash
   curl -X POST http://localhost:8000/ui/admin/ad-platform/kill-switch \
     -H "Content-Type: application/json" \
     -H "x-csrf-token: <token>" \
     -b "ui_session=<root_session>" \
     -d '{"enabled": true, "reason": "QA test"}'
   ```
4. Within 5 seconds (cache TTL), retry ad serving — confirm `filled=false,
   fill_reason="platform_kill_switch_active"`.
5. Disable kill switch: repeat with `"enabled": false`.
6. Confirm ad serving resumes.
7. Check audit log: `GET /ui/admin/ad-platform/moderation/platform/ad_kill_switch/history`
   returns two log entries.

### Observability

- `logger.warning("ad_kill_switch_toggled ...")` is emitted on every toggle — alerts on this
  log pattern in CloudWatch/Datadog should page the on-call engineer.
- Add a Prometheus/CloudWatch metric `ad_kill_switch_active` (gauge 0/1) in the `serve_ad`
  early-exit branch to drive a dashboard and alert.

### Rollback

Remove the three additions (service functions, router endpoints, serve_ad gate). The
`PLATFORM_CONFIG / AD_KILL_SWITCH` DynamoDB item can be left in place — if `is_kill_switch_active`
is removed from `serve_ad`, serving resumes regardless of the stored value.

### Risks

- **Multi-worker cache lag**: each uvicorn worker has an independent in-process cache. A toggle
  reaches all workers within `_KS_TTL_SECONDS` (5 s). During that window, some workers may
  still serve ads. This is acceptable for a non-safety-critical platform feature; reduce TTL to
  1 s if tighter SLA is required.
- **DynamoDB outage**: `is_kill_switch_active` fails open (returns False) — ad serving
  continues. If the requirement were to fail-closed during a DDB outage, the `False` default
  should be changed to `True`; however, that would cause all ad serving to stop whenever DDB is
  slow, which is a worse failure mode for availability.

### Effort

**S** (Small) — three files, no schema changes, straightforward DynamoDB read/write pattern.

### Sequencing

1. Add service functions to `admin_ad_platform.py`.
2. Add router endpoints to `admin_ad_platform_router`.
3. Add kill-switch gate to `serve_ad` (one `if` block).
4. Add DDB item to `scripts/local-ddb-init.py` comment (no table change needed — existing
   `ad_accounts` table is used).
5. Run `just test`; deploy to staging; run manual QA.
6. Close GAP-0068.
