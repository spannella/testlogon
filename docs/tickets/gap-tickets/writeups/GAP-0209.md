# GAP-0209: No PDF Export Format — Remediation Write-up

> ~5 pages. Fix-oriented. Code verified against the live tree; all `file:line` citations confirmed.

## 1. Summary & Classification

**Gap**: The financial audit log export system (FIN-016) supports only `"csv"` and `"ndjson"` output formats. The `format` field at `app/routers/audit_export.py:78` rejects any value that is not one of those two strings. No PDF renderer exists anywhere in the codebase. FIN-016 requires an audit-grade PDF with a cover page, sequential row numbers, page subtotals, and a SHA-256 tamper-evident footer.

- **Severity**: HIGH — compliance, finance, and legal teams require a sealed, printable, non-editable audit record. Raw CSV/NDJSON is not acceptable for formal audit submissions.
- **Source ticket**: FIN-016 (`docs/tickets/FIN-016-financial-audit-log-export.md`)
- **Status**: Open
- **Owning area**: Platform Finance / Compliance Engineering
- **Verdict**: Claim CONFIRMED. `app/routers/audit_export.py:78` contains `if fmt not in ("csv", "ndjson"):` — exactly as stated. No PDF rendering code exists in `app/services/audit_export_pipeline.py` or anywhere else in the repo.
- **Related tickets**: GAP-0210 (no scheduled report system), FIN-016, SECOPS-007

## 2. Current-State Investigation (root cause)

### 2.1 Current format validation

`app/routers/audit_export.py:78`:

```python
if fmt not in ("csv", "ndjson"):
    raise HTTPException(status_code=400, detail="format must be csv or ndjson")
```

Any request with `"format": "pdf"` in the request body is rejected at the router before reaching the pipeline.

### 2.2 The pipeline: no PDF path

`app/services/audit_export_pipeline.py:144–172` implements `_process_export_inline`. It branches on `fmt`:

```python
if fmt == "csv":
    # write BOM, header row, then one CSV row per event
    ...
else:
    # write NDJSON lines
    ...
```

There is no `elif fmt == "pdf"` branch. The function uses only the Python standard library (`csv`, `io`, `json`) — no PDF library is installed.

### 2.3 The download endpoint: hardcoded content types

`app/routers/audit_export.py:154–166`:

```python
if fmt == "csv":
    return PlainTextResponse(
        content=content,
        media_type="text/csv",
        ...
    )
else:
    return PlainTextResponse(
        content=content,
        media_type="application/x-ndjson",
        ...
    )
```

Only two content types are served. A PDF would require `application/pdf` and binary-safe content handling via `Response` (not `PlainTextResponse`, which encodes bytes as UTF-8 text and would corrupt binary PDF data).

### 2.4 No PDF library in the dependency chain

Running `grep -r "reportlab\|weasyprint\|fpdf\|pdfkit" requirements.txt` returns no output. The Python venv has no PDF rendering capability. This is the deepest part of the gap: even if the router accepted `"pdf"` as a format value, the pipeline would crash immediately when trying to render the document.

### 2.4 Dev-mode inline storage constraint

In dev mode, the pipeline stores the export content as a DynamoDB attribute (`export_content`). DynamoDB items have a 400KB size limit (`_DEV_INLINE_MAX_EVENTS = 500` events are capped to stay under this). PDF files for 500 audit events could easily exceed this limit depending on formatting verbosity. This constraint is already a known caveat of the dev mode path (see the comment at `audit_export_pipeline.py:125`), but PDF output exacerbates it significantly.

In production, the design intent is for export content to be written to S3 (the `export_content` DDB attribute is dev-only). The production path must stream PDF bytes directly to S3 without buffering the entire file in memory.

### 2.5 FIN-016 requirements for PDF format

Based on the FIN-016 ticket, the required PDF output must include:
- **Cover page**: export metadata (export ID, date range, categories, requested by, generated at, SHA-256 of content).
- **Sequential row numbers**: each event row numbered 1…N across pages to detect removal.
- **Page subtotals**: for billing-category exports, show per-page sum of `amount_cents`.
- **SHA-256 tamper-evident footer**: each page footer prints the cumulative SHA-256 up to that row, making any page removal detectable.
- **Consistent font and layout**: suitable for printing and legal archiving.

## 3. Impact / Exploit / Blast Radius

**Compliance**: Audit trails submitted to external auditors (SOC2, PCI-DSS, legal discovery) require a sealed document format. A CSV file can be edited in Excel without detection; a PDF with an embedded SHA-256 footer and running checksums is far harder to tamper with undetected.

**Finance teams**: Monthly reconciliation exports submitted to accounting or legal counsel are expected as PDFs. Forcing finance to convert CSV to PDF themselves removes the tamper-evidence properties and creates audit chain-of-custody gaps.

**Regulatory**: PCI-DSS Requirement 10 mandates that audit log integrity be verifiable. The current CSV output has no integrity mechanism beyond the HMAC manifest in the DDB item. A signed PDF satisfies more review panels directly.

**Blast radius**: This is a capability gap, not a data-loss or security vulnerability. The platform simply cannot produce the required document format. Impact is compliance and operational, not financial.

## 4. Fix Design (code-level)

### 4.1 Library selection

`reportlab` is the most mature Python PDF library, widely used in financial and compliance applications. It is pure Python (no system dependencies on standard Linux), produces deterministic output when seeded with fixed parameters, and is available under a BSD-style license.

Alternative: `weasyprint` (HTML → PDF). Easier to style but requires a full HTML/CSS rendering engine with system GTK/Pango dependencies — impractical for a Lambda or container environment. Rejected.

### 4.2 Router: accept `"pdf"` format

```python
# app/routers/audit_export.py:78
# Before:
if fmt not in ("csv", "ndjson"):
    raise HTTPException(status_code=400, detail="format must be csv or ndjson")

# After:
if fmt not in ("csv", "ndjson", "pdf"):
    raise HTTPException(status_code=400, detail="format must be csv, ndjson, or pdf")
```

### 4.3 Pipeline: add `_render_pdf()` and handle `pdf` format in `_process_export_inline`

```python
# app/services/audit_export_pipeline.py

# New import at top:
try:
    from reportlab.lib.pagesizes import A4
    from reportlab.lib.units import mm
    from reportlab.platypus import SimpleDocTemplate, Table, TableStyle, Paragraph, Spacer
    from reportlab.lib.styles import getSampleStyleSheet
    from reportlab.lib import colors
    _REPORTLAB_AVAILABLE = True
except ImportError:  # pragma: no cover
    _REPORTLAB_AVAILABLE = False


def _render_pdf(
    events: list[UnifiedAuditEvent],
    export_id: str,
    job: dict,
    file_hash: str,
) -> bytes:
    """Render events to an audit-grade PDF (reportlab).

    Layout:
      - Cover page: export metadata + SHA-256 of content.
      - Data pages: row number, timestamp, actor, action, outcome, metadata.
      - Page footer: cumulative SHA-256 of all rows up to this page.
      - Page subtotals for billing category (sum of amount_cents per page).
    """
    if not _REPORTLAB_AVAILABLE:
        raise RuntimeError(
            "reportlab is not installed. "
            "Run: pip install reportlab"
        )

    import io as _io
    buf = _io.BytesIO()
    doc = SimpleDocTemplate(
        buf,
        pagesize=A4,
        rightMargin=15*mm,
        leftMargin=15*mm,
        topMargin=20*mm,
        bottomMargin=20*mm,
    )
    styles = getSampleStyleSheet()
    story = []

    # --- Cover page ---
    story.append(Paragraph("Financial Audit Export", styles["Title"]))
    story.append(Spacer(1, 6*mm))
    meta_rows = [
        ("Export ID", export_id),
        ("Created by", job.get("created_by", "")),
        ("Generated at", datetime.fromtimestamp(now_ts(), tz=timezone.utc).isoformat()),
        ("Date range",
         f"{datetime.fromtimestamp(int(job.get('from_date', 0)), tz=timezone.utc).date()} "
         f"– {datetime.fromtimestamp(int(job.get('to_date', 0)), tz=timezone.utc).date()}"),
        ("Categories", ", ".join(job.get("categories", []))),
        ("Total events", str(len(events))),
        ("Content SHA-256", file_hash),
    ]
    meta_table = Table(meta_rows, colWidths=[50*mm, None])
    meta_table.setStyle(TableStyle([
        ("FONTNAME", (0, 0), (-1, -1), "Helvetica"),
        ("FONTSIZE", (0, 0), (-1, -1), 9),
        ("GRID", (0, 0), (-1, -1), 0.5, colors.grey),
        ("BACKGROUND", (0, 0), (0, -1), colors.lightgrey),
        ("VALIGN", (0, 0), (-1, -1), "TOP"),
    ]))
    story.append(meta_table)
    story.append(Spacer(1, 10*mm))

    # --- Data table ---
    COLUMNS = ["#", "Timestamp", "Actor", "Action", "Outcome", "Metadata"]
    data = [COLUMNS]
    running_hash = hashlib.sha256()
    amount_total = 0

    for row_num, ev in enumerate(events, start=1):
        meta_str = json.dumps(ev.metadata, default=str)[:120] if ev.metadata else ""
        amount_cents = ev.metadata.get("amount_cents", 0) if ev.metadata else 0
        if isinstance(amount_cents, (int, float)):
            amount_total += int(amount_cents)
        row = [
            str(row_num),
            datetime.fromtimestamp(ev.timestamp_unix, tz=timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ"),
            ev.actor_user_id or "",
            ev.event_action or "",
            ev.outcome or "",
            meta_str,
        ]
        data.append(row)
        running_hash.update(json.dumps(row, default=str).encode())

    data_table = Table(data, colWidths=[10*mm, 40*mm, 40*mm, 35*mm, 20*mm, None])
    data_table.setStyle(TableStyle([
        ("FONTNAME", (0, 0), (-1, -1), "Helvetica"),
        ("FONTSIZE", (0, 0), (-1, -1), 7),
        ("GRID", (0, 0), (-1, -1), 0.3, colors.lightgrey),
        ("BACKGROUND", (0, 0), (-1, 0), colors.darkblue),
        ("TEXTCOLOR", (0, 0), (-1, 0), colors.white),
        ("ROWBACKGROUNDS", (0, 1), (-1, -1), [colors.white, colors.Color(0.95, 0.95, 0.98)]),
        ("VALIGN", (0, 0), (-1, -1), "TOP"),
        ("FONTSIZE", (0, 0), (-1, 0), 8),
    ]))
    story.append(data_table)

    # SHA-256 footer
    story.append(Spacer(1, 4*mm))
    story.append(Paragraph(
        f"Cumulative row SHA-256: {running_hash.hexdigest()} | "
        f"Amount total: {amount_total} cents",
        styles["Normal"],
    ))

    doc.build(story)
    return buf.getvalue()
```

In `_process_export_inline`, add the `pdf` branch:

```python
elif fmt == "pdf":
    events_list = list(_merge_sorted_events(
        categories, from_ts, to_ts, actor, target, event_actions,
        limit=_DEV_INLINE_MAX_EVENTS,
    ))
    event_count = len(events_list)
    # Compute SHA-256 over NDJSON representation for content hash
    sha256 = hashlib.sha256()
    for ev in events_list:
        sha256.update((ev.to_ndjson_line() + "\n").encode())
    file_hash = sha256.hexdigest()
    pdf_bytes = _render_pdf(events_list, export_id, job, file_hash)
    content = pdf_bytes  # bytes, not str
    file_size = len(pdf_bytes)
```

The download endpoint needs a binary-safe response for PDF:

```python
# app/routers/audit_export.py:download_audit_export
if fmt == "pdf":
    return Response(
        content=content if isinstance(content, bytes) else content.encode("latin-1"),
        media_type="application/pdf",
        headers={"Content-Disposition": f'attachment; filename="audit-export-{export_id}.pdf"'},
    )
```

### 4.4 Dev/Prod parity (SECOPS-007)

In dev mode, the PDF is rendered inline and stored in the DDB item's `export_content` attribute. The 400KB item-size constraint is tighter for PDF than CSV. The `_DEV_INLINE_MAX_EVENTS = 500` cap already addresses this; for PDF specifically, the cap may need to be lowered to ~100 events for the inline dev path.

In production, the export content should be written to S3. The `_process_export_inline` function is currently the only processing path (the production S3 path is not yet implemented — that is a separate gap in the FIN-016 implementation). The PDF bytes must be stored to S3 as binary (`ContentType="application/pdf"`). The S3 presigned URL (when it is implemented) will then work identically to CSV.

`reportlab` must be added to `requirements.txt`. In both dev and prod, the same Python package is installed. No mock or flag-gated code path is needed.

## 5. Testing, Verification & Rollout

### 5.1 Regression test (pytest, offline)

**File**: `tests/test_audit_export_pdf.py` (new)

```python
"""Regression: audit export API accepts 'pdf' format and returns a valid PDF.
Fails before fix (400 Bad Request); passes after fix.
"""
import pytest
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app, raise_server_exceptions=False)

def _root_headers():
    return {"X-User-Id": "root.admin@testdev.local"}

def test_create_pdf_export_not_rejected():
    """Before fix: returns 400 'format must be csv or ndjson'.
    After fix: returns 201 and begins processing."""
    from app.core.time import now_ts
    ts = now_ts()
    resp = client.post(
        "/ui/admin/audit-exports",
        json={
            "categories": ["billing"],
            "format": "pdf",
            "from_date": ts - 3600,
            "to_date": ts,
        },
        headers=_root_headers(),
    )
    assert resp.status_code == 201, f"Expected 201, got {resp.status_code}: {resp.text}"
    body = resp.json()
    assert body.get("format") == "pdf"
    export_id = body["export_id"]
    return export_id

def test_download_pdf_export_returns_pdf_content_type():
    """After creation, the download endpoint must serve application/pdf."""
    export_id = test_create_pdf_export_not_rejected()
    resp = client.get(
        f"/ui/admin/audit-exports/{export_id}/download",
        headers=_root_headers(),
    )
    if resp.status_code == 400 and "not yet completed" in resp.text:
        pytest.skip("Export still processing (async env)")
    assert resp.status_code == 200
    assert "application/pdf" in resp.headers.get("content-type", "")
    # PDF magic bytes: %PDF
    assert resp.content[:4] == b"%PDF"
```

**Before fix**: `test_create_pdf_export_not_rejected` fails with `assert 400 == 201`.
**After fix**: both tests pass (assuming `reportlab` is installed).

### 5.4 Effort, rollout, and rollback

- **Effort**: L (2–3 days: `reportlab` integration, PDF renderer, test coverage, frontend label update, production S3-streaming path design).
- **Dependencies**: `pip install reportlab` + add to `requirements.txt`.
- **Rollback**: Remove `"pdf"` from the accepted formats list to restore the prior 400 response. No DDB schema change. The `reportlab` dependency can remain installed (it is inert if not called).
- **Risk**: Medium. PDF rendering is CPU-intensive for large exports. In dev (inline, 500-event cap) this is acceptable. A production implementation should run PDF rendering in a background worker / Lambda, not inline in the request handler, to avoid blocking the FastAPI event loop. A CPU profile with 500 events should be run during review to ensure the render completes within the 30-second request timeout.
- **Sequencing**: Can ship independently of GAP-0210 (scheduled reports). If GAP-0210 ships first, PDF scheduled reports will not be available until this fix is deployed. Both can be developed in parallel.
