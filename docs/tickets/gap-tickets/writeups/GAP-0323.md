# GAP-0323: Crawler-Detection Middleware Not Implemented — Remediation Write-up

> **Claim status**: CONFIRMED — no crawler UA detection or meta-tag injection layer exists
> at the Vite dev-server level or in any production proxy configuration.

---

## 1. Summary & Classification

**Source ticket**: PLATFORM-005 (SEO / Open Graph metadata)
**Severity as filed**: HIGH
**Status**: Open
**Owning area**: Frontend infrastructure / FastAPI middleware

Social bots (Facebook, Twitter/X, Discord, Slack, LinkedIn, WhatsApp, Telegram, Googlebot) do not execute JavaScript. When they crawl a URL such as `/u/alice` or `/posts/p_abc123`, they receive the React SPA skeleton (`index.html`), which contains only `<title>Control Panel</title>` and no `og:*` meta tags. The `react-helmet-async` tags that would populate OG metadata are injected post-hydration by React — which bots never trigger.

The backend has a fully capable `/seo/meta-tags` endpoint (`app/routers/seo_metadata.py`) that produces a server-rendered `<meta>` tag block for any public resource. The gap is entirely at the request-routing layer: nothing intercepts bot requests and proxies them to that endpoint.

**Verdict**: Confirmed. `frontend/vite.config.ts` has no UA-sniffing hook. `app/main.py` has no `CrawlerMetaMiddleware`. No Nginx/Caddy production config with bot-routing rules is present in the repository.

**Related tickets**: GAP-0322 (the backend service that this middleware must call is already implemented); GAP-0321 (locale field — already resolved).

## 2. Current-State Investigation (root cause)

### 2.1 What social bots see today

When `facebookexternalhit/1.1` GETs `/u/alice`, the Vite dev server proxy table (`frontend/vite.config.ts:24-119`) has no entry that matches `/u/`. The server falls through to its SPA catch-all and returns `index.html`. The bot receives:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Control Panel</title>
    ...
  </head>
  <body><div id="root"></div><script ...></script></body>
</html>
```

There are no `og:title`, `og:description`, `og:image`, `twitter:card`, or `canonical` tags. The Facebook scraper, Discord embed renderer, and Twitter card validator all display a blank/generic card.

### 2.2 Frontend Helmet tags exist but are invisible to bots

`frontend/src/App.tsx:264-271` and per-page components (`PublicUserProfilePage.tsx:175`, `PublicEventPage.tsx:106`, `PublicClipPage.tsx:78`) set OG tags via `react-helmet-async`. For example:

```tsx
// frontend/src/pages/profile/PublicUserProfilePage.tsx:175-184
<Helmet>
  <title>{displayName} | Control Panel</title>
  <meta property="og:title" content={displayName} />
  <meta property="og:description" content={...} />
  <meta property="og:type" content="profile" />
  {publicFields.profilePhotoUrl && (
    <meta property="og:image" content={publicFields.profilePhotoUrl} />
  )}
</Helmet>
```

These tags are injected into the DOM only after React hydrates and the API response for the profile resolves. Social bots abort long before that point.

### 2.3 The backend endpoint is fully ready

`app/routers/seo_metadata.py:65-81` exposes `GET /seo/meta-tags`:

```python
@seo_metadata_router.get("/meta-tags", response_class=Response)
async def get_seo_meta_tags(req, type, id, secondary_id, path):
    """Return an HTML <meta> tag block for crawler / preview injection."""
    ...
    return Response(content=render_meta_tags(meta), media_type="text/html; charset=utf-8")
```

`app/services/seo_metadata.py:644-686` — `render_meta_tags()` — produces fully HTML-escaped `<title>`, `<meta property="og:*">`, `<meta name="twitter:*">`, `<link rel="canonical">`, and `<script type="application/ld+json">` tags. All user-controlled values pass through `html.escape(..., quote=True)` before insertion, preventing injection attacks.

The Vite proxy already routes `/seo` to the backend (`frontend/vite.config.ts:65`):
```ts
"/seo": "http://localhost:8000",
```

### 2.4 No middleware exists in main.py

A search for `crawler`, `CrawlerMiddleware`, `user.agent`, or `bot` in `app/main.py` yields only entries for the chat-bot router (unrelated). No `BaseHTTPMiddleware` or Starlette middleware intercepts UA strings for meta injection.

### 2.5 No production proxy config present

The repository contains no Nginx, Caddy, or HAProxy configuration files. Bot-routing at the infrastructure level is therefore not implemented either. The deployment model implied by `scripts/run_local_mock_backend.sh` and `scripts/dev.sh` is a single-binary FastAPI + Vite setup; a reverse-proxy config would need to be added separately for production.

### 2.6 The `/seo` proxy entry in vite.config.ts confirms intent

`frontend/vite.config.ts:65` contains:
```ts
"/seo": "http://localhost:8000",
```

This line was added when the `seo_metadata_router` was implemented, demonstrating that the backend was purposefully wired for dev access. The missing step is the UA-sniffing layer that directs bot requests to the `/seo/meta-tags` path rather than the SPA catch-all. This is the sole gap between the PLATFORM-005 design and what is running today.

## 3. Impact / Exploit / Blast Radius

**SEO impact** (no security or financial dimension):

- Every share of a creator profile, post, event, video, or live-stream link on any major social platform produces a blank preview card. Users sharing their content on Facebook, Discord, Slack, or Twitter/X see no image, no title, and no description — only the bare URL.
- Google's rich-results crawler does not associate JSON-LD `Person`, `Article`, `Event`, or `VideoObject` schema with pages, suppressing rich snippets in search results.
- Creator monetization indirectly affected: blank share previews reduce click-through rates on shared posts and subscription plan links, lowering new-subscriber acquisition.

**Affected URL patterns** (all public-facing):
- `/u/<identifier>` — creator / user profiles
- `/posts/<post_id>` — public newsfeed posts
- `/event/<cal_id>/<event_id>` — calendar events
- `/videos/<video_id>` — VOD library
- `/live/<session_id>` — live streams

**No data-leak risk** from this gap. The `/seo/meta-tags` endpoint already enforces privacy guards (private profiles return `available: False`, locked posts never expose body text).

## 4. Fix Design (code-level)

The fix consists of two equally important changes: a FastAPI middleware for production and a Vite plugin hook for dev, both calling the same `/seo/meta-tags` backend path.

### 4.1 FastAPI `CrawlerMetaMiddleware` (production)

Create `app/middleware/crawler_meta.py`:

```python
"""Intercept social-crawler User-Agent requests and return server-rendered
OG meta tags instead of the React SPA shell.

Only GET requests matching known public URL patterns are intercepted.
All other requests pass through unchanged.
"""
from __future__ import annotations

import re
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import HTMLResponse, Response
from app.core.settings import S

_BOT_UA_RE = re.compile(
    r"(facebookexternalhit|Twitterbot|LinkedInBot|Slackbot|Discordbot"
    r"|WhatsApp|TelegramBot|Pinterest|Googlebot|bingbot|DuckDuckBot"
    r"|Applebot|vkShare|W3C_Validator|ia_archiver|SemrushBot"
    r"|AhrefsBot|MJ12bot)",
    re.IGNORECASE,
)

_PUBLIC_PATH_RE = re.compile(
    r"^/(u/[^/?#]+|posts/[^/?#]+|event/[^/?#]+/[^/?#]+"
    r"|videos/[^/?#]+|live/[^/?#]+)/?$"
)

_HTML_SHELL = (
    '<!DOCTYPE html>\n<html lang="en"><head>\n'
    "    {tags}\n"
    "</head><body></body></html>\n"
)


class CrawlerMetaMiddleware(BaseHTTPMiddleware):
    """Return a pre-rendered <meta> tag document for known social bots."""

    async def dispatch(self, request: Request, call_next) -> Response:
        if not getattr(S, "seo_crawler_middleware_enabled", True):
            return await call_next(request)

        ua = request.headers.get("user-agent", "")
        path = request.url.path

        if request.method == "GET" and _BOT_UA_RE.search(ua) and _PUBLIC_PATH_RE.match(path):
            try:
                from app.services.seo_metadata import metadata_for_path, render_meta_tags
                base = str(request.base_url).rstrip("/")
                meta = metadata_for_path(path, base_url=base)
                tags = render_meta_tags(meta)
                html = _HTML_SHELL.format(tags=tags)
                return HTMLResponse(html, status_code=200)
            except Exception:
                # On any error fall through to normal request handling.
                pass

        return await call_next(request)
```

Register in `app/main.py` immediately after existing middleware declarations:

```python
from app.middleware.crawler_meta import CrawlerMetaMiddleware
app.add_middleware(CrawlerMetaMiddleware)
```

Add to `app/core/settings.py`:

```python
seo_crawler_middleware_enabled: bool = (
    os.environ.get("SEO_CRAWLER_MIDDLEWARE_ENABLED", "1") == "1"
)
```

### 4.2 Vite dev-server plugin (dev parity — SECOPS-007)

Add to `frontend/vite.config.ts` inside the `plugins` array:

```typescript
{
  name: "crawler-meta-inject",
  configureServer(server) {
    const BOT_RE =
      /facebookexternalhit|Twitterbot|LinkedInBot|Slackbot|Discordbot|WhatsApp|TelegramBot|Pinterest|Googlebot/i;
    const PUBLIC_RE =
      /^\/(u\/[^/?#]+|posts\/[^/?#]+|event\/[^/?#]+\/[^/?#]+|videos\/[^/?#]+|live\/[^/?#]+)\/?$/;

    server.middlewares.use(async (req, res, next) => {
      const ua = req.headers["user-agent"] ?? "";
      const rawPath = (req.url ?? "/").split("?")[0];
      if (!BOT_RE.test(ua) || !PUBLIC_RE.test(rawPath)) return next();
      try {
        const backendResp = await fetch(
          `http://localhost:8000/seo/meta-tags?path=${encodeURIComponent(rawPath)}`
        );
        const tags = await backendResp.text();
        const html =
          `<!DOCTYPE html>\n<html lang="en"><head>\n    ${tags}\n</head><body></body></html>\n`;
        res.setHeader("Content-Type", "text/html; charset=utf-8");
        res.statusCode = 200;
        res.end(html);
      } catch {
        next();
      }
    });
  },
},
```

Both the production middleware and the dev plugin call the identical `metadata_for_path()` code. There is no mock path that bypasses privacy enforcement, satisfying SECOPS-007.

### 4.3 Backward compatibility

- The middleware short-circuits only GET requests from known bot UAs matching known public paths. Normal browser requests are untouched.
- `SEO_CRAWLER_MIDDLEWARE_ENABLED=0` disables the feature at runtime without code change.
- No DynamoDB schema changes are needed.
- Existing `react-helmet-async` tags continue to work for browsers — they are additive and complementary.

### 4.4 Alternatives considered

**Option A: Prerender.io / Rendertron (third-party headless renderer)**: Adds latency (100-500 ms per bot request), external dependency, and cost. Rejected in favour of the lightweight in-process approach.

**Option B: Full SSR with React Server Components**: Requires a significant architecture shift (Vite SSR mode, streaming, hydration changes). Disproportionate for the narrow use case of bot previews. Rejected.

**Option C: Nginx `map` directive in production**: Effective for pure-infrastructure deployments but not testable in the dev stack and not part of the current single-binary deployment model. Can be added in parallel with the middleware approach.

### 5.1 Regression test — fails before / passes after

    """FAILS before middleware; PASSES after."""

    assert resp.status_code == 200
    assert 'property="og:title"' in resp.text
    assert 'property="og:type"' in resp.text

    resp = test_client.get("/posts/p_testpost", headers={"user-agent": DISCORD_UA})
    assert resp.status_code == 200
    assert 'property="og:type"' in resp.text

def test_browser_ua_not_intercepted(test_client: TestClient):
    """Normal browser must NOT receive the meta-only shell."""
    resp = test_client.get("/u/alice", headers={"user-agent": BROWSER_UA})
    # In test mode the React SPA is not available; middleware must pass through.
    # Either a 404 (no SPA served) or a non-meta response is acceptable.

    """Private paths like /messages must never match the middleware."""
    resp = test_client.get("/messages", headers={"user-agent": FACEBOOK_UA})

def test_middleware_disabled_by_flag(test_client: TestClient, monkeypatch):
    """When SEO_CRAWLER_MIDDLEWARE_ENABLED=0 the middleware is a no-op."""
    from app.core import settings as _s
    monkeypatch.setattr(_s.S, "seo_crawler_middleware_enabled", False)
    resp = test_client.get("/u/alice", headers={"user-agent": FACEBOOK_UA})

### 5.5 Rollout, risks, and effort

- **Effort**: M (middleware + Vite plugin + tests — approximately 4-6 hours of engineering).
- **Risk**: The `_PUBLIC_PATH_RE` pattern is conservative. A false positive (bot UA on a path that is also a valid React SPA route) would serve an HTML shell with OG tags to a browser — visually incorrect but not harmful, and with `available: False` fallback no private data is leaked. Mitigated by the `SEO_CRAWLER_MIDDLEWARE_ENABLED` flag.
- **Rollback**: `SEO_CRAWLER_MIDDLEWARE_ENABLED=0` environment variable — instant, no restart needed if the settings object reads from `os.environ.get` per call.
- **Sequencing**: Implement after GAP-0322 is confirmed deployed (it already is). This is the sole outstanding piece of the PLATFORM-005 feature.

### 5.6 Production robots.txt placement

The backend's `GET /seo/robots.txt` returns a correct policy. For Google and other crawlers to discover it, the file must be available at `GET /robots.txt` (the conventional root path). Options:

1. Add a redirect in the production reverse proxy: `location = /robots.txt { return 301 /seo/robots.txt; }`.
2. Add a FastAPI route alias at `app/main.py` for `GET /robots.txt` that calls `build_robots_txt()` directly.

Option 2 is preferable for consistency with the existing test coverage and the dev-mode proxy setup. It can be added in the same PR as the crawler middleware.

### 5.7 Security considerations for the middleware

The `CrawlerMetaMiddleware` calls `metadata_for_path()`, which internally calls `get_profile()`, `get_discoverability_state()`, and DynamoDB reads. These calls happen synchronously in the Starlette middleware dispatch chain. Two considerations:

- **Latency**: DDB reads in middleware add ~10-50 ms per bot request. Acceptable given bots are a small fraction of traffic.
- **Amplification**: A bot that enumerates all valid user IDs could trigger many DDB reads. The existing resource-not-found path returns `default_metadata()` without hitting DDB for the profile; the privacy guard exits early on `discoverability_status = "deleted"` or `"hidden"`. This mitigates the amplification risk. A rate-limit check on the middleware path can be added if bot-probe activity is detected in production.
- **Injection protection**: `render_meta_tags()` applies `html.escape(..., quote=True)` to all user-controlled values before inserting them into tag attributes. The JSON-LD block uses `json.dumps` + `replace("</", "<\\/")` to prevent script breakout. No additional sanitization is needed.
