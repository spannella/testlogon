# GAP-0378: `concat -safe 0` Allows Arbitrary `file://` Entries in `filelist.txt` — Remediation Write-up

> Source ticket: VOD-016 · Severity: HIGH · Effort: S · Status: Open

## 1. Summary & Classification

**Bug statement.** `_run_concat_demuxer` in `app/services/video_concatenator.py` passes `-safe 0` to FFmpeg's concat demuxer and writes file paths to `filelist.txt` without validating that each path is contained within the job's scratch directory. The `-safe 0` flag disables FFmpeg's built-in path safety checks, allowing the concat demuxer to open any path — including absolute paths like `/etc/passwd` or `file:///etc/shadow` — if an attacker can influence the contents of `filelist.txt`. SEC-012 explicitly flags this pattern as a local-file-read vector.

**Verdict:** Confirmed. `app/services/video_concatenator.py:339` contains `-safe`, `0` in the FFmpeg command list, and lines 325–328 write paths to `filelist.txt` with only shell-escaping (apostrophe quoting), not path containment validation:

```python
# app/services/video_concatenator.py:324-340
filelist_path = output_path.parent / "filelist.txt"
with open(filelist_path, "w") as f:
    for p in input_paths:
        escaped = str(p).replace("'", "'\\''")
        f.write(f"file '{escaped}'\n")
...
cmd = [
    ffmpeg_bin, "-hide_banner", "-loglevel", "warning", "-y",
    "-f", "concat", "-safe", "0",    # ← unsafe flag
    "-i", str(filelist_path),
    ...
]
```

**Severity and area.** HIGH / Security — FFmpeg pipeline. Classified as HIGH because the attack requires either a path-traversal write to inject attacker-controlled data into `filelist.txt`, or exploitation of a separate vulnerability that controls the `input_paths` list. If either precondition is met, the impact is local file disclosure to any user who can trigger a concat job.

**Related tickets.** VOD-016 (source feature), SEC-012 (flags `-safe 0` pattern), SECOPS-007 (dev/prod parity), GAP-0379 (concat job exception handling). GAP-0378 and GAP-0379 must both be fixed before VOD-016 concat is considered production-ready.

## 2. Current-State Investigation (root cause)

### The demuxer path

`execute_concat` at `video_concatenator.py:218` routes to `_run_concat_demuxer` when `concat_method == "demuxer"` (line 259). The `method` field is set by `_check_codec_compatibility` in `create_concat_job` (line 136): if all input videos share the same codec, resolution, and frame rate, `method = "demuxer"` is chosen.

### How `input_paths` is constructed

`input_paths` is built inside `execute_concat` at lines 246–249:

```python
for i, key in enumerate(s3_keys):
    ext = Path(key).suffix or ".mp4"
    local_path = scratch_dir / f"input_{i}{ext}"
    s3.download_file(bucket, key, str(local_path))
    input_paths.append(local_path)
```

`s3_keys` comes from `job.get("concat_source_s3_keys", [])`, which was written into the job record by `create_concat_job:163`. At job-creation time those keys are the `source_s3_key` values fetched from `VideoMetadataModel` records owned by the requesting user — so under normal operation the paths are safe.

### The vulnerability precondition

The risk arises in two scenarios:

1. **Job record tampering.** If an attacker with DynamoDB write access (e.g., exploiting a separate DDB injection) modifies `concat_source_s3_keys` to contain a key like `../../etc/passwd`, the constructed `local_path` under `scratch_dir` could be traversed outside the scratch directory. The current code does not check `local_path.resolve().is_relative_to(scratch_dir)`.

2. **`-safe 0` + direct `filelist.txt` manipulation.** With `-safe 0`, FFmpeg accepts any path in `filelist.txt` — including absolute paths like `/etc/shadow` or `file:///proc/self/mem`. If an attacker gains write access to the scratch directory (e.g., via a symlink attack, container escape, or worker process exploit), they can add arbitrary lines to `filelist.txt` and FFmpeg will include them in the output.

Under the current code, scenario 2 is made directly available because `-safe 0` is unconditional. With `-safe 1` (the default), FFmpeg rejects all absolute paths and any path containing `..` components, entirely eliminating the second attack vector.

### Why `-safe 0` was used

The comment at line 324 has no explanation, but the reason is almost certainly that `input_paths` contains absolute paths (e.g., `/tmp/scratch/concat-<job_id>/input_0.mp4`). The concat demuxer with `-safe 1` rejects absolute paths and paths containing `..` components, issuing an error like `Unsafe file name '/tmp/scratch/...'`. The original developer used `-safe 0` as the shortest path to making FFmpeg accept the absolute `local_path` values. The correct fix is to write paths relative to the working directory of the FFmpeg process — then `-safe 1` accepts them without restriction.

### The `-safe` flag semantics

When the concat demuxer option `safe` is `1` (default), FFmpeg only accepts file entries that:
- Are relative paths (do not start with `/` or a drive letter).
- Do not contain `..` path components.
- Do not contain special protocol prefixes like `file://`, `http://`, or `pipe:`.

When `safe` is `0`, all of these restrictions are lifted. The demuxer will read any path, including `file:///etc/shadow`, `/proc/self/cmdline`, or network paths. This is the known-unsafe pattern explicitly called out in SEC-012.

## 3. Impact / Exploit / Blast Radius

### Exploit walkthrough

**Attack requires two steps:**

Step 1 — Trigger demuxer path: submit a concat job with two videos that share the same codec/resolution/framerate so `_check_codec_compatibility` returns `True` and `concat_method = "demuxer"`.

Step 2a (direct) — Modify `filelist.txt` before FFmpeg reads it: requires a write primitive to the scratch directory on the worker host. This is a secondary exploit; mitigating `-safe 0` alone reduces the attack to zero-impact even if Step 2a is achieved.

Step 2b (indirect) — Tamper with `concat_source_s3_keys` in the DynamoDB job record to contain path-traversal segments. When `s3.download_file` is called, the local download path would be `scratch_dir / f"input_0../../etc/passwd"` — and since there is no `resolve()` + `is_relative_to()` check, the file would be written outside scratch. The file contents would then be read by FFmpeg and embedded in the output MP4.

**Worst-case impact:** An attacker who can both trigger a concat job and write to the worker's scratch directory can cause FFmpeg to embed the contents of any readable local file into the output MP4. On an ECS/EC2 worker this includes `/etc/passwd`, EC2 instance metadata via `file:///proc/net/...`, and any secret files left on the instance. The output MP4 can then be downloaded by the attacker via the normal video-download endpoint.

**Probability:** LOW in isolation (requires a second exploit for write access), but the `-safe 0` flag multiplies the blast radius of any other vulnerability that touches the worker process. SEC-012 explicitly requires this flag to be removed regardless of precondition probability.

## 4. Fix Design (code-level)

### Fix 1: Write relative paths to `filelist.txt`, use `-safe 1`

Rewrite `_run_concat_demuxer` to change the working directory (via `cwd=` on the subprocess) to `output_path.parent` and write paths relative to that directory:

```python
async def _run_concat_demuxer(
    input_paths: List[Path],
    output_path: Path,
    timeout_seconds: int = 600,
) -> None:
    """Concatenate via the concat demuxer (stream copy, fast)."""
    work_dir = output_path.parent
    filelist_path = work_dir / "filelist.txt"

    # Validate all inputs are inside work_dir before writing the filelist
    for p in input_paths:
        resolved = p.resolve()
        if not resolved.is_relative_to(work_dir.resolve()):
            raise ConcatError(
                f"Input path escapes scratch directory: {p}"
            )

    with open(filelist_path, "w") as f:
        for p in input_paths:
            # Write relative paths so -safe 1 accepts them
            rel = p.relative_to(work_dir)
            f.write(f"file '{rel}'\n")

    ...

    cmd = [
        ffmpeg_bin, "-hide_banner", "-loglevel", "warning", "-y",
        "-f", "concat", "-safe", "1",    # ← was: "-safe", "0"
        "-i", str(filelist_path),
        "-c", "copy",
        "-movflags", "+faststart",
        str(output_path.name),           # ← relative output path
    ]

    proc = await asyncio.create_subprocess_exec(
        *cmd,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
        cwd=str(work_dir),               # ← run FFmpeg in the scratch dir
    )
    ...
```

The `cwd=str(work_dir)` argument makes FFmpeg's working directory the scratch dir, so the relative input paths and the relative output path resolve correctly.

### Fix 2: Validate input paths in `execute_concat` before download

Add a path containment check for the constructed `local_path` in `execute_concat`:

```python
for i, key in enumerate(s3_keys):
    ext = Path(key).suffix or ".mp4"
    local_path = scratch_dir / f"input_{i}{ext}"
    # Verify the path is still inside scratch_dir after suffix substitution
    if not local_path.resolve().is_relative_to(scratch_dir.resolve()):
        raise ConcatError(f"Computed download path escapes scratch dir: {local_path}")
    s3.download_file(bucket, key, str(local_path))
    input_paths.append(local_path)
```

This blocks the DynamoDB-tampering scenario by ensuring that even a maliciously crafted S3 key suffix cannot traverse outside the scratch directory.

### Dev/Prod parity (SECOPS-007)

The FFmpeg invocation is identical in dev (`transcode_scratch_dir` typically `/tmp/scratch`) and production (ECS worker with a mounted EBS volume). The `cwd` parameter and relative path approach work identically in both environments. No environment-specific branching is needed. The `S.s3_endpoint_url` branching for moto vs real S3 is already handled at the `boto3.client` level and is unaffected by this change.

### Backward compatibility

The output file content is unchanged (same concat demuxer, same stream copy). The only difference is the path format written to `filelist.txt` and the `-safe` flag value. No DynamoDB schema changes; no migration required.

### Alternatives considered

- **Keep `-safe 0` but validate `filelist.txt` contents at write time:** Rejected. This provides defense-in-depth but does not eliminate the underlying risk if `filelist.txt` is modified between write and FFmpeg read (TOCTOU). The correct fix is to remove the unsafe flag entirely.
- **Use `-allowed_extensions ALL` instead of `-safe 0`:** Rejected. This only controls file extension restrictions, not path safety; `-safe 1` is the correct control.
- **Re-encode all inputs via filter path, removing demuxer entirely:** Rejected. The demuxer path is correct for compatible-codec inputs and avoids quality loss from re-encoding. The fix is surgical.

## 5. Testing, Verification & Rollout

### Regression test (pytest, offline — fails before, passes after)

```python
# tests/test_concat_safe_flag.py
import pytest
import asyncio
from unittest.mock import patch, AsyncMock, MagicMock
from pathlib import Path
import tempfile

@pytest.mark.asyncio
async def test_run_concat_demuxer_rejects_path_outside_scratch():
    """Verify that input paths outside scratch_dir raise ConcatError."""
    from app.services.video_concatenator import _run_concat_demuxer, ConcatError

    with tempfile.TemporaryDirectory() as scratch:
        scratch_path = Path(scratch)
        # One valid input inside scratch, one outside
        valid_input = scratch_path / "input_0.mp4"
        valid_input.touch()
        outside_input = Path("/etc/passwd")

        with pytest.raises(ConcatError, match="escapes scratch directory"):
            await _run_concat_demuxer(
                input_paths=[valid_input, outside_input],
                output_path=scratch_path / "out.mp4",
            )

@pytest.mark.asyncio
async def test_run_concat_demuxer_uses_safe_1(tmp_path):
    """Verify FFmpeg is invoked with -safe 1, not -safe 0."""
    from app.services.video_concatenator import _run_concat_demuxer

    (tmp_path / "input_0.mp4").touch()
    (tmp_path / "input_1.mp4").touch()

    captured_cmd = []

    async def mock_subprocess(*args, **kwargs):
        captured_cmd.extend(args)
        mock = AsyncMock()
        mock.returncode = 0
        mock.communicate = AsyncMock(return_value=(b"", b""))
        return mock

    with patch("asyncio.create_subprocess_exec", side_effect=mock_subprocess):
        await _run_concat_demuxer(
            input_paths=[tmp_path / "input_0.mp4", tmp_path / "input_1.mp4"],
            output_path=tmp_path / "out.mp4",
        )

    flat = [str(a) for a in captured_cmd[0]]  # first positional = cmd list
    assert "-safe" in flat
    idx = flat.index("-safe")
    assert flat[idx + 1] == "1", f"Expected '-safe 1' but got '-safe {flat[idx+1]}'"
    assert "0" not in flat[flat.index("-safe"):flat.index("-safe")+2]
```

**Before fix:** `test_run_concat_demuxer_uses_safe_1` fails because the captured command contains `-safe 0`; `test_run_concat_demuxer_rejects_path_outside_scratch` fails with no exception raised.

**After fix:** both tests pass.

### Rollout

- **Effort:** S (small — ~15 lines changed in `_run_concat_demuxer`, ~5 lines in `execute_concat`; no schema changes).
- **Risk:** Low. The behavioral change is:
  - FFmpeg now uses `-safe 1` (stricter); relative paths in `filelist.txt` are accepted.
  - Invalid paths now raise `ConcatError` before FFmpeg is invoked (previously would have been silently passed to FFmpeg or caused FFmpeg to error).
  - All legitimate concat jobs use paths inside scratch, so `-safe 1` will accept them without issue.
- **Sequencing:** Fix alongside GAP-0379 (fail_job for concat) in the same PR. Both are in `video_concatenator.py`. No external dependencies.
- **Rollback:** Restore `-safe`, `0` and remove the path validation loop. Note that rollback restores the vulnerability. Because this is a security fix, rollback should only be performed if the fix introduces a functional regression; in that case, the correct response is to fix the regression, not revert the security hardening.

### Acceptance criteria

The fix is complete when:
1. The `filelist.txt` written during a concat job contains relative paths (e.g., `file 'input_0.mp4'`), not absolute paths.
2. The FFmpeg command invoked for a concat-demuxer job contains `-safe 1`.
3. Supplying an input path that resolves outside `scratch_dir` raises `ConcatError` before FFmpeg is invoked.
4. A concat job with two compatible-codec videos completes successfully end-to-end (FFmpeg accepts the relative paths with `-safe 1`).
5. Both new pytest tests (`test_run_concat_demuxer_rejects_path_outside_scratch` and `test_run_concat_demuxer_uses_safe_1`) pass green.
