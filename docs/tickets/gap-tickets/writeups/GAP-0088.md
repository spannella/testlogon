# GAP-0088: Live GitHub API Not Wired — Remediation Write-up

> Source ticket: AGENT-007 · Severity: HIGH · Effort: S · Status: Open

## 1. Summary & Classification

**Bug statement.** When the PR creation method is `"api"` and a real `GITHUB_TOKEN` is configured in the environment, `_create_pr_via_api` in `app/services/agent_pr_integration.py` falls through to `raise NotImplementedError("Live GitHub API integration not enabled.")`. Production deployments that configure a GitHub token and set `method="api"` on `create_pr_from_agent` calls receive a 500 Internal Server Error with no PR created.

**Verdict (confirmed).** The code at `app/services/agent_pr_integration.py:363–380` contains the stub exactly as described. Line 371 short-circuits to mock data when `S.dev_mode` is true or when `token` is empty; any other combination falls to line 380's `raise NotImplementedError`. The comment on line 379 ("Real implementation would POST to…") confirms the stub was intentionally left unimplemented.

**Severity and area.** HIGH / Agent PR Integration (AGENT-007). Blocks all production PR creation via the API method, which is the preferred method for environments where the agent doesn't have access to the `gh` CLI on the local machine. Dev mode is unaffected; the gap is a pure production blocker.

**Related tickets.** AGENT-007 (parent), AGENT-008 (coder workflow — builds the workflow steps that call `create_pr_from_agent`). GAP-0089 and GAP-0090 (injection bugs in the CLI path — the API path, once implemented, avoids those vectors entirely). No blocking dependencies; `S.github_token` and `S.github_api_base_url` are already declared in `app/core/settings.py:909–910`.

### Repo URL parsing

The function receives `repo_url` (e.g. `https://github.com/acme/backend`). To call the GitHub REST API, `owner` and `repo` must be extracted. No helper currently exists for this; it must be added as part of the fix.

### Missing dependency

`httpx` is already in the project's Python dependencies (used elsewhere in the codebase for async HTTP calls). No new package is needed.

### GitHub REST API contract for PR creation

`POST /repos/{owner}/{repo}/pulls` accepts:

| Field | Type | Notes |
|-------|------|-------|
| `title` | string | required — the PR title |
| `body` | string | optional — Markdown description |
| `head` | string | required — source branch name |
| `base` | string | required — target branch name |
| `draft` | bool | optional — default `false` |

Response 201 JSON includes `html_url` (string), `number` (int), `state` (`"open"` or `"closed"`). Error responses include 422 (validation failure, e.g. branch not found) and 401/403 (auth failures).

Authentication uses `Authorization: Bearer {token}` with `Accept: application/vnd.github+json` and optionally `X-GitHub-Api-Version: 2022-11-28` for API versioning stability.

## 3. Impact / Exploit / Blast Radius

**Operational blocker.** Any production deployment that:
- Sets `GITHUB_TOKEN` in the environment, AND
- Calls `create_pr_from_agent` with `method="api"` (or invokes the `/ui/agent-pr/{worker_id}/create` endpoint with `"method": "api"` in the request body)

will receive an unhandled `NotImplementedError` propagated as a 500 response. The agent run is marked `error` and the ticket stalls indefinitely.

**Security advantage of the API path.** The `"cli"` path (GAP-0089, GAP-0090) injects user-controlled strings into a shell command string (`gh pr create --title "..."`), creating injection vectors. The API path bypasses the shell entirely; implementing it also removes an incentive to use the unsafe CLI path.

**Blast radius.** Affects only deployments with `GITHUB_TOKEN` set and explicitly requesting `method="api"`. Dev mode is fully functional (mock data returned). There is no data corruption risk — the failure is loud and clean (500 error).

## 4. Fix Design (code-level)

### Implementation: `app/services/agent_pr_integration.py`

```python
# app/services/agent_pr_integration.py — replace _create_pr_via_api

import re
import httpx  # already available in project dependencies

_GITHUB_REPO_RE = re.compile(
    r"(?:https?://[^/]+/|git@[^:]+:)([^/]+)/([^/]+?)(?:\.git)?$"
)


def _parse_owner_repo(repo_url: str):
    """Extract (owner, repo) from a GitHub HTTPS or SSH URL.

    Returns (owner, repo) or raises ValueError if the URL is not parseable.
    """
    m = _GITHUB_REPO_RE.match(repo_url.strip())
    if not m:
        raise ValueError(
            f"Cannot parse owner/repo from repo_url: {repo_url!r}. "
            "Expected format: https://github.com/owner/repo or git@github.com:owner/repo"
        )
    return m.group(1), m.group(2)


def _create_pr_via_api(
    *, repo_url: str, branch: str, title: str, description: str, user_id: str,
) -> Dict[str, Any]:
    """Create a PR via the GitHub REST API.

    In dev mode (or when no token is configured) returns mock data.
    Raises ValueError for malformed repo URLs.
    Raises httpx.HTTPStatusError on non-2xx GitHub responses.
    """
    token = getattr(S, "github_token", "")
    if S.dev_mode or not token:
        pr_number = (abs(hash(branch or title)) % 9000) + 1
        base = repo_url or "https://github.com/example/repo"
        return {
            "html_url": f"{base}/pull/{pr_number}",
            "number": pr_number,
            "state": "open",
        }

    owner, repo = _parse_owner_repo(repo_url)
    api_url = f"{S.github_api_base_url}/repos/{owner}/{repo}/pulls"

    headers = {
        "Authorization": f"Bearer {token}",
        "Accept": "application/vnd.github+json",
        "X-GitHub-Api-Version": "2022-11-28",
    }
    payload = {
        "title": title,
        "body": description,
        "head": branch,
        "base": "main",   # TODO: make configurable via coder config base_branch
    }

    resp = httpx.post(api_url, json=payload, headers=headers, timeout=30)
    resp.raise_for_status()
    data = resp.json()

    return {
        "html_url": data["html_url"],
        "number": data["number"],
        "state": data["state"],
    }
```

### Base branch wiring

The `payload["base"]` field should use the configured `base_branch` from the coder config rather than the hardcoded `"main"`. The `create_pr_from_agent` signature already passes `repo_url` and `branch`; extend `_create_pr_via_api` to accept a `base_branch: str = "main"` keyword argument and wire it through the call site:

```python
# call site update (agent_pr_integration.py:440–448)
result = _create_pr_via_api(
    repo_url=repo_url,
    branch=actual_branch,
    title=pr_title,
    description=pr_description,
    user_id=user_id,
    base_branch=base_branch or "main",  # NEW
)
```

### Dev/Prod parity (SECOPS-007)

The `if S.dev_mode or not token:` guard is already the correct dev/prod parity pattern. In dev mode (`DEV_MODE=1`), even if `GITHUB_TOKEN` is accidentally set, the function returns mock data — no real API call is made. In production (`DEV_MODE=0`) with a token, the live HTTP call is made. No additional feature flag is needed; the existing settings surface (`GITHUB_TOKEN`, `GITHUB_API_BASE_URL`) is sufficient.

For GitHub Enterprise: setting `GITHUB_API_BASE_URL=https://github.mycompany.com/api/v3` routes API calls to the enterprise instance. The `_parse_owner_repo` regex handles both `https://` and `git@` URL forms regardless of domain.

### Error handling / backward compatibility

- `_parse_owner_repo` raises `ValueError` for unrecognized URLs — propagated as a 422 by the router's existing exception handlers.
- `httpx.HTTPStatusError` (non-2xx from GitHub) is logged and re-raised; the router returns 502/503.
- No DDB schema changes. No migration required.

### Rollout

- **Effort**: S (< 1 day). One function replacement and one regex helper.
- **Risk**: Low in dev (mock path unchanged). Medium in production: a misconfigured `GITHUB_TOKEN` or wrong `GITHUB_API_BASE_URL` causes 4xx responses from GitHub. Handle with clear error logging.
- **Sequencing**: Deploy after GAP-0089 and GAP-0090 fixes (which harden the CLI path). Once the API path is live, migrate coder configs from `method="cli"` to `method="api"` to remove injection risk.
- **Rollback**: Restore `raise NotImplementedError(...)` line; all `method="api"` calls revert to 500 in production (which is the current state — no regression for users).

### GitHub Enterprise support

For on-premises GitHub Enterprise Server deployments, set:
```
GITHUB_API_BASE_URL=https://github.internal.example.com/api/v3
```
The `_parse_owner_repo` regex handles any domain in HTTPS URLs. The `Authorization: Bearer` header and JSON payload structure are identical between github.com and GitHub Enterprise Server 3.x and later. No code changes are needed for GHES compatibility beyond the `GITHUB_API_BASE_URL` setting.

### Token scope requirements

The `GITHUB_TOKEN` must have:
- `repo` scope (for private repositories), OR
- `public_repo` scope (for public repositories only)

Using a GitHub App installation token (with `contents: write` and `pull_requests: write` permissions) is the recommended production approach over a personal access token, as it scopes the credential to specific repositories and has shorter expiry windows. The implementation is compatible with either token type since both use Bearer authentication.

### Rate limiting

GitHub API rate limits are 5,000 requests/hour per authenticated token. PR creation consumes 1 request. Add `Retry-After` header handling:

```python
if resp.status_code == 403 and "X-RateLimit-Remaining" in resp.headers:
    if resp.headers["X-RateLimit-Remaining"] == "0":
        reset_at = int(resp.headers.get("X-RateLimit-Reset", 0))
        raise ValueError(f"GitHub rate limit exceeded. Resets at {reset_at}.")
```
