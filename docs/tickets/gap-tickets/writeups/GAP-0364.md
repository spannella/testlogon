# GAP-0364: leave_syndicate does NOT trigger treasury refund-on-leave — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against real code; cites `file:line` throughout.

## 1. Summary & Classification

**Bug**: `leave_syndicate` in `app/services/syndicates.py` removes the departing member and optionally promotes a new admin, but never calls `syndicate_treasury.refund_on_member_leave` (or `refund_on_dissolution` for the last-member case). The SYND-004 spec (§1.3 rule 2 and §3.3 design) mandates that a member's proportional share of the treasury balance must be returned to their personal wallet before they are removed. The current implementation silently forfeits the member's treasury contributions when they leave.

**Severity**: HIGH
**Source ticket**: SYND-004 (second-pass as-built review)
**Status**: Open
**Owning area**: Backend / syndicates service
**Effort**: M (medium — requires adding `refund_on_member_leave` and `refund_on_dissolution` to `syndicate_treasury.py`, since those functions do not exist yet)
**Related tickets**: GAP-0032 (admin can disburse to own wallet), GAP-0363 (wallet delta not applied for splits)

**Claim verification**: CONFIRMED WITH IMPORTANT CAVEAT.

The original ticket states: "import `syndicate_treasury.refund_on_member_leave` (and `refund_on_dissolution`) and call them inside `leave_syndicate`". Verifying against the actual code reveals that `refund_on_member_leave` and `refund_on_dissolution` do not exist in `app/services/syndicate_treasury.py`. The as-built treasury service (`app/services/syndicate_treasury.py`, 545 lines) has `deposit`, `disburse`, `spend_on_advertising`, `refund_advertising`, `list_treasury_ledger`, `list_contributions`, and `get_my_contributions` — but no leave/dissolution refund functions.

The spec document (`docs/tickets/SYND-004-treasury-fund-management.md:340-430`) contains the full intended implementation of both functions as pseudocode/design code, but they were never copied into the actual service file. This makes the effort **M** (medium) rather than the **S** estimated in the ticket: the fix requires both authoring two new treasury functions and wiring them into `leave_syndicate`.

**One-line impact**: When a member leaves a syndicate after contributing treasury funds, their contributed balance is permanently forfeited rather than returned to their personal wallet.

```python
def leave_syndicate(
    *,
    syndicate_id: str,
    user_id: str,
) -> Dict[str, Any]:
    """Member leaves the syndicate. If admin leaves, promote next oldest."""
    meta = _get_meta(syndicate_id)
    _require_is_member(syndicate_id, user_id)
    is_admin = meta["admin_user_id"] == user_id

    # Remove member + user index
    _remove_member(syndicate_id, user_id)             # <-- treasury refund needed BEFORE this
    new_count = int(meta["member_count"]) - 1
    _set_member_count(syndicate_id, new_count)

    if new_count <= 0:
        # Dissolve syndicate
        _archive_syndicate(syndicate_id)
        _write_audit(syndicate_id, user_id, "member_left", user_id)
        _write_audit(syndicate_id, user_id, "syndicate_dissolved", syndicate_id)
        return {"dissolved": True, "syndicate_id": syndicate_id}

    if is_admin:
        # Promote next oldest member
        members = list_members(syndicate_id)
        members.sort(key=lambda m: (int(m.get("joined_at", 0)), m.get("user_id", "")))
        if members:
            new_admin = members[0]["user_id"]
            _promote_to_admin(syndicate_id, new_admin)
            _write_audit(syndicate_id, user_id, "admin_auto_promoted", new_admin)

    _write_audit(syndicate_id, user_id, "member_left", user_id)
    _on_member_left_hook(syndicate_id, user_id)
    return {"dissolved": False, "syndicate_id": syndicate_id}
```

No treasury refund call appears anywhere in this function. The `_on_member_left_hook` at `app/services/syndicates.py:508-514` is limited to the open-licensing hook and does not call treasury refund logic.

### Missing functions in `syndicate_treasury.py`

Grepping `app/services/syndicate_treasury.py` for `refund_on_member_leave` and `refund_on_dissolution` returns no results. The current public API of `syndicate_treasury.py` is:

- `get_treasury_balance`
- `deposit`
- `disburse`
- `spend_on_advertising`
- `refund_advertising`
- `list_treasury_ledger`
- `list_contributions`
- `get_my_contributions`

Both refund functions must be authored from scratch, using the spec design (in `docs/tickets/SYND-004-treasury-fund-management.md:340-430`) as the authoritative blueprint.

### Why the spec design is mostly correct (with one adaptation needed)

The spec's `refund_on_member_leave` references `get_treasury_balance`, `_get_all_contributors`, `apply_wallet_delta`, and `_update_refund_tracker`. Of these:

- `get_treasury_balance` — exists in the as-built service.
- `apply_wallet_delta` — exists in `billing_shared.py`; already imported into `syndicate_treasury.py` at line 32.
- `_get_all_contributors` — does not exist in the as-built service; must be authored (it is a thin wrapper around `list_contributions`).
- `_update_refund_tracker` — does not exist in the as-built service; must be authored.

The as-built `list_contributions` function at `app/services/syndicate_treasury.py:507-527` returns per-member records from the `CONTRIB#` items in `T.syndicate_treasury`. This is the data source for proportional refund calculation. The `_get_all_contributors` helper simply calls `list_contributions` and returns the raw list — it is trivial to implement.

### Dissolution path gap

The `leave_syndicate` dissolution path (`new_count <= 0` branch) calls `_archive_syndicate` but no `refund_on_dissolution`. This means the last-member-out scenario also forfeits all treasury funds, which according to SYND-004 §1.3 rule 3 should trigger full proportional refund to all historical contributors.

## 3. Impact / Exploit / Blast Radius

### Who is affected

Any syndicate member who:

1. Has deposited funds into the syndicate treasury.
2. Subsequently leaves the syndicate (voluntarily or due to the last-member dissolution path).

The impact is proportional to the treasury balance at time of departure multiplied by the member's contribution share.

### Financial impact

**Example scenario**:
- Syndicate "Creative Collective" has 4 members.
- Alice contributed $200, Bob $100, Carol $100, Dave $100 → treasury balance $500.
- Syndicate spends $200 on advertising → remaining balance $300.
- Alice leaves. Per spec, her refund = `floor(300 * 200 / 500)` = `floor(120)` = $120.
- **Current behavior**: Alice receives $0. The $120 remains in the treasury, effectively redistributed to the three remaining members on their eventual departure — or lost entirely if the syndicate dissolves with no contributors tracked as net-positive.

Over a platform lifetime with many syndicates, the cumulative loss to members could be substantial.

### Compliance consequence

The SYND-004 spec is part of the platform's contractual obligation to syndicate members (exposed in the terms of service as the "proportional refund guarantee"). Failing to honor this guarantee is a breach of contract and may trigger refund disputes or chargebacks.

### Dissolution edge case

When the last member leaves, the treasury balance is not refunded to anyone. The treasury DynamoDB record persists in `T.syndicate_treasury` with a non-zero balance but the owning syndicate is archived. These stranded funds are effectively unrecoverable without manual DBA intervention.

## 4. Fix Design (code-level)

### Step 1: Add `refund_on_member_leave` to `syndicate_treasury.py`

```python
# app/services/syndicate_treasury.py — add after get_my_contributions()

def refund_on_member_leave(
    *,
    syndicate_id: str,
    user_id: str,
) -> Dict[str, Any]:
    """Calculate and return a leaving member's proportional share of the treasury balance.

    Formula: floor(current_balance * member_net_contributed / total_net_contributed)
    Writes paired ledger entries (treasury debit + member wallet credit).
    Returns {"refunded_cents": int}.
    """
    balance_row = get_treasury_balance(syndicate_id)
    current_balance = balance_row["balance_cents"]
    if current_balance <= 0:
        return {"refunded_cents": 0}

    contributors = list_contributions(syndicate_id)
    total_net = sum(c["net_contributed_cents"] for c in contributors)
    if total_net <= 0:
        return {"refunded_cents": 0}

    member_contrib = next((c for c in contributors if c["user_id"] == user_id), None)
    if not member_contrib or member_contrib["net_contributed_cents"] <= 0:
        return {"refunded_cents": 0}

    from math import floor
    refund_cents = floor(current_balance * member_contrib["net_contributed_cents"] / total_net)
    if refund_cents <= 0:
        return {"refunded_cents": 0}

    pk_treasury = _treasury_pk(syndicate_id)
    pk_user = user_pk(user_id)
    ts = now_ts()

    # 1. Debit treasury balance.
    T.syndicate_treasury.update_item(
        Key={"pk": pk_treasury, "sk": BALANCE_SK},
        UpdateExpression=(
            "SET balance_cents = balance_cents - :amt, "
            "total_disbursed_cents = if_not_exists(total_disbursed_cents, :z) + :amt, "
            "updated_at = :t"
        ),
        ConditionExpression="attribute_exists(balance_cents) AND balance_cents >= :amt",
        ExpressionAttributeValues={":amt": refund_cents, ":z": 0, ":t": ts},
    )

    # 2. Credit member's personal wallet.
    apply_wallet_delta(T.billing, pk_user, refund_cents)

    # 3. Update member's contribution refund tracker.
    T.syndicate_treasury.update_item(
        Key={"pk": pk_treasury, "sk": f"CONTRIB#{user_id}"},
        UpdateExpression=(
            "SET total_refunded_cents = if_not_exists(total_refunded_cents, :z) + :amt"
        ),
        ExpressionAttributeValues={":z": 0, ":amt": refund_cents},
    )

    # 4. Treasury ledger entry (debit).
    _write_treasury_ledger(
        syndicate_id,
        direction="debit",
        amount_cents=refund_cents,
        reason=f"Treasury refund to {user_id}: member departure",
        actor_user_id=user_id,
        counterparty_user_id=user_id,
        ts=ts,
    )

    # 5. Member billing ledger entry (credit).
    entry_id = ulidish()
    T.billing.put_item(Item={
        "pk": pk_user,
        "sk": ledger_sk(ts, entry_id),
        "entry_id": entry_id,
        "ts": ts,
        "type": "syndicate_treasury_refund",
        "amount_cents": refund_cents,
        "state": "settled",
        "reason": "Syndicate treasury refund: member departure",
        "direction": "credit",
        "category": "syndicate_treasury",
        "syndicate_id": syndicate_id,
        "currency": "usd",
        "created_at": ts,
    })

    syndicate_svc._write_audit(
        syndicate_id, user_id, "treasury_refund_on_leave", "",
        {"refunded_cents": refund_cents},
    )
    return {"refunded_cents": refund_cents}


def refund_on_dissolution(syndicate_id: str) -> Dict[str, Any]:
    """Refund all remaining treasury funds to historical contributors proportionally.

    Called when the last member leaves and the syndicate is dissolved.
    """
    from math import floor
    balance_row = get_treasury_balance(syndicate_id)
    current_balance = balance_row["balance_cents"]
    if current_balance <= 0:
        return {"total_refunded_cents": 0, "refunds": []}

    contributors = [c for c in list_contributions(syndicate_id) if c["net_contributed_cents"] > 0]
    total_net = sum(c["net_contributed_cents"] for c in contributors)
    if total_net <= 0:
        return {"total_refunded_cents": 0, "refunds": []}

    # Highest-contributor-first; last member absorbs rounding remainder.
    contributors.sort(key=lambda c: c["net_contributed_cents"], reverse=True)

    pk_treasury = _treasury_pk(syndicate_id)
    ts = now_ts()
    remaining = current_balance
    refunds = []

    for i, contrib in enumerate(contributors):
        if i == len(contributors) - 1:
            refund = remaining  # absorb remainder
        else:
            refund = floor(current_balance * contrib["net_contributed_cents"] / total_net)
        if refund <= 0:
            refunds.append({"user_id": contrib["user_id"], "refunded_cents": 0})
            continue
        remaining -= refund
        uid = contrib["user_id"]

        apply_wallet_delta(T.billing, user_pk(uid), refund)
        _write_treasury_ledger(
            syndicate_id,
            direction="debit",
            amount_cents=refund,
            reason=f"Treasury refund to {uid}: syndicate dissolved",
            actor_user_id=uid,
            counterparty_user_id=uid,
            ts=ts,
        )
        refunds.append({"user_id": uid, "refunded_cents": refund})

    # Zero out treasury balance.
    T.syndicate_treasury.update_item(
        Key={"pk": pk_treasury, "sk": BALANCE_SK},
        UpdateExpression="SET balance_cents = :z, updated_at = :t",
        ExpressionAttributeValues={":z": 0, ":t": ts},
    )

    return {
        "total_refunded_cents": sum(r["refunded_cents"] for r in refunds),
        "refunds": refunds,
    }
```

### Step 2: Wire into `leave_syndicate`

```python
# app/services/syndicates.py:393-426 — AFTER FIX (additions marked <-- ADD)

def leave_syndicate(
    *,
    syndicate_id: str,
    user_id: str,
) -> Dict[str, Any]:
    """Member leaves the syndicate. If admin leaves, promote next oldest."""
    from app.services import syndicate_treasury                  # <-- ADD
    meta = _get_meta(syndicate_id)
    _require_is_member(syndicate_id, user_id)
    is_admin = meta["admin_user_id"] == user_id

    # Treasury refund BEFORE member record is removed (need CONTRIB# record).
    try:                                                          # <-- ADD
        refund_result = syndicate_treasury.refund_on_member_leave(  # <-- ADD
            syndicate_id=syndicate_id, user_id=user_id,          # <-- ADD
        )                                                         # <-- ADD
    except Exception:                                             # <-- ADD
        logger.warning("treasury_refund_on_leave_failed",        # <-- ADD
                       extra={"syndicate_id": syndicate_id, "user_id": user_id},  # <-- ADD
                       exc_info=True)                            # <-- ADD
        refund_result = {"refunded_cents": 0}                    # <-- ADD

    # Remove member + user index
    _remove_member(syndicate_id, user_id)
    new_count = int(meta["member_count"]) - 1
    _set_member_count(syndicate_id, new_count)

    if new_count <= 0:
        # Dissolve syndicate — refund remaining treasury to all contributors.
        try:                                                      # <-- ADD
            syndicate_treasury.refund_on_dissolution(syndicate_id)  # <-- ADD
        except Exception:                                         # <-- ADD
            logger.warning("treasury_refund_on_dissolution_failed",  # <-- ADD
                           extra={"syndicate_id": syndicate_id}, exc_info=True)  # <-- ADD
        _archive_syndicate(syndicate_id)
        _write_audit(syndicate_id, user_id, "member_left", user_id)
        _write_audit(syndicate_id, user_id, "syndicate_dissolved", syndicate_id)
        return {"dissolved": True, "syndicate_id": syndicate_id,
                "refunded_cents": refund_result["refunded_cents"]}  # <-- ADD

    if is_admin:
        members = list_members(syndicate_id)
        members.sort(key=lambda m: (int(m.get("joined_at", 0)), m.get("user_id", "")))
        if members:
            new_admin = members[0]["user_id"]
            _promote_to_admin(syndicate_id, new_admin)
            _write_audit(syndicate_id, user_id, "admin_auto_promoted", new_admin)

    _write_audit(syndicate_id, user_id, "member_left", user_id)
    _on_member_left_hook(syndicate_id, user_id)
    return {"dissolved": False, "syndicate_id": syndicate_id,
            "refunded_cents": refund_result["refunded_cents"]}  # <-- ADD (optional enrichment)
```

The `try/except` wrapper around the refund calls prevents a treasury failure from blocking the member's ability to leave. However, the trade-off is that a failing refund is silent. An alternative is to raise and force the caller to handle — but preventing a member from leaving their syndicate because of a treasury connectivity error is a worse UX. The logging ensures ops can detect and remediate.

### Dev/Prod parity (SECOPS-007)

`syndicate_treasury` functions use `T.syndicate_treasury` and `T.billing`, both mapped to DynamoDB Local in dev and AWS DynamoDB in prod via `app/core/tables.py`. `apply_wallet_delta` is the same code path in both environments. No mock paths or `dev_mode` branches are involved. The fix is fully parity-consistent.

### Backward compatibility

The response body of `leave_syndicate` (and `POST /ui/syndicates/{id}/leave`) gains an optional `refunded_cents` field. This is additive — no existing client should break. If strict schema enforcement is required, add `refunded_cents: int = 0` to the `SyndicateLeaveOut` Pydantic model.

### Risk

**Medium**. The `refund_on_member_leave` function writes to two tables (treasury balance + member wallet) in sequence. The two writes are not wrapped in a DynamoDB transaction. If the first write (treasury debit) succeeds and the second write (wallet credit) fails, the treasury loses the funds without the member being credited. A full fix would use a DynamoDB TransactWrite to make both writes atomic — this is the recommended enhancement for a v2, but the current sequential approach matches the pattern used throughout the codebase.

### Effort

**M** — approximately 2–3 hours of code change (authoring the two treasury functions + wiring) + 2 hours of tests. The most complex part is the proportional refund arithmetic edge-case testing.

### Sequencing

Deploy after GAP-0363 (wallet delta fix) is live, in the same release. Run treasury integration tests before deploying to production. Schedule a maintenance window if the retroactive correction for existing members who left without a refund is needed.
