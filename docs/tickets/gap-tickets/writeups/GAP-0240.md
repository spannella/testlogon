# GAP-0240: `GoogleDrivePickerDialog` not used anywhere in the frontend — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No prior
> investigation doc exists for this ticket.

## 1. Summary & Classification

**Bug**: `GoogleDrivePickerDialog` (`frontend/src/components/shared/GoogleDrivePickerDialog.tsx`)
is a fully implemented, 352-line React component that provides a Google Drive file browser and
import dialog. Despite the component being export-ready, no page or component in the
application imports it. It is orphaned dead code. The E2E test at
`frontend/e2e/drive-picker.spec.ts:201` already acknowledges this with a `if (visible)` guard
around the button click that silently skips the UI integration test when the button is absent.

**Severity**: HIGH. The Google Drive picker is the user-visible surface of the INTEG-001
feature. Without a rendering site the entire integration is invisible: users cannot select
files from their Google Drive to import into the platform file manager.

**Source ticket**: INTEG-001. No prior investigation document.

**Owning area**: `frontend/src/components/shared/GoogleDrivePickerDialog.tsx` (component),
`frontend/src/pages/files/FilesPage.tsx` (rendering site).

**Claim verdict**: Confirmed. Running:
```
grep -rn "GoogleDrivePickerDialog" frontend/src/ | grep -v "GoogleDrivePickerDialog.tsx"
```
returns no output. The component is defined and exported but never imported by any consuming
file.

**Related tickets**: GAP-0239 ("Connect Google Drive" UI section absent) — this ticket and
GAP-0239 are two sides of the same gap. GAP-0239 covers the toolbar button, connection status
badge, and Disconnect flow; this ticket specifically covers the picker dialog rendering.
Together they constitute the full INTEG-001 frontend closure.

## 2. Current-State Investigation (root cause)

### 2.1 Component definition

`frontend/src/components/shared/GoogleDrivePickerDialog.tsx:84`:
```typescript
export function GoogleDrivePickerDialog({
  open,
  onOpenChange,
  onImportComplete,
  currentPath = "/",
}: GoogleDrivePickerDialogProps) {
```

The component:
- Calls `browseGoogleDriveFiles` via React Query (`queryKey: ["drive-files", ...]`) when
  `open` is true (line 120).
- Renders a search input, breadcrumb navigation, folder drill-down, file checkboxes, and an
  Import button (lines 212-352).
- On import, calls `importDriveFile` for each selected file and calls `onImportComplete` on
  success (lines 171-208).
- Uses `data-testid` attributes throughout (`drive-picker-dialog`, `drive-search-input`,
  `drive-breadcrumbs`, `drive-file-list`, `drive-import-button`) for testability.

The component is fully production-ready. Its `onImportComplete` callback is designed to
trigger a file list refresh at the calling page level.

### 2.2 Why the component is never used

`frontend/src/pages/files/FilesPage.tsx` has **no import** of `GoogleDrivePickerDialog`.
A search of all non-worktree source files:
```

```
→ Only `frontend/src/components/shared/GoogleDrivePickerDialog.tsx` itself (definition only).

The companion page `FilesPage.tsx` (1571 lines) imports 30+ components and helpers but none
from `@/components/shared/GoogleDrivePickerDialog`.

## 3. Impact / Exploit / Blast Radius

**Functionality**: The entire Google Drive import flow is inaccessible. Users cannot browse or
import files from their connected Google Drive into the platform file manager.

**Test coverage erosion**: The `if (visible)` guard in `drive-picker.spec.ts` means that if
the component is wired incorrectly and the dialog renders broken, the test still passes. The
test suite provides a false sense of coverage for this feature.

**Bundle size**: An orphaned 352-line component still gets tree-shaken by Vite/Rollup since no
page imports it. There is no runtime cost — but it will accumulate maintenance debt as the
surrounding APIs evolve.

**Discoverability**: Users who have connected their Google Drive via `GET /integrations/
google-drive/connect` (e.g., through a third-party integration or a direct API call) have no
UI surface to act on that connection.

## 4. Fix Design (code-level)

This ticket's fix is a subset of the broader GAP-0239 remediation. The minimum change to
address this specific gap is to import and render `GoogleDrivePickerDialog` in `FilesPage.tsx`
with appropriate state control. The full UX (Connect button, status badge, Disconnect) is
covered in GAP-0239; this writeup documents the dialog-wiring portion only.

### 4.1 Add `drivePickerOpen` state variable

In `FilesPage.tsx`, in the state block (around line 230):

```typescript
const [drivePickerOpen, setDrivePickerOpen] = React.useState(false);
```

### 4.2 Import the component

Add to imports at the top of `FilesPage.tsx`:

```typescript
import { GoogleDrivePickerDialog } from "@/components/shared/GoogleDrivePickerDialog";
```

### 4.3 Add a "Browse Google Drive" button in the toolbar

After the "Connect iCloud" button at `FilesPage.tsx:1040`:

```tsx
<Button
  variant="outline"
  size="sm"
  onClick={() => setDrivePickerOpen(true)}
  data-testid="connect-google-drive-button"
>
  <HardDrive className="h-4 w-4" />
  <span className="hidden sm:inline ml-1">Google Drive</span>
</Button>
```

(The `HardDrive` import already exists at line 16 — this finally gives it a rendering site.)

### 4.4 Render the dialog

Add at the bottom of the page JSX, after the `ImageEditorDialog` at line 1538:

```tsx
<GoogleDrivePickerDialog
  open={drivePickerOpen}
  onOpenChange={setDrivePickerOpen}
  currentPath={currentPath}
  onImportComplete={() => {
    queryClient.invalidateQueries({ queryKey: ["files", currentPath] });
  }}
/>
```

This is the minimum viable wiring: the button opens the dialog; the dialog renders the Drive
browser; on successful import, the files list refreshes. The full OAuth connect/disconnect
flow (GAP-0239) can be layered on top independently.

### 4.5 Dev/Prod parity (SECOPS-007)

The `GoogleDrivePickerDialog` queries `GET /ui/integrations/google-drive/files` via
`browseGoogleDriveFiles`. In dev mode this endpoint checks `S.dev_mode` and serves stub
file data from an in-memory mock (controlled by `POST /mock/google-drive/reset`). In
production the endpoint uses the user's stored OAuth token to call the real Google Drive API.
The component receives the same response shape in both environments. No component-level
changes are needed to support either path.

### 4.6 Alternatives considered

- **Separate route `/drive`**: Creates a dedicated Drive page rather than embedding in
  FilesPage. Rejected — the intended UX (ticket section 4.6) is an in-page picker that
  imports files into the current folder. Keeping it embedded avoids navigation and preserves
  the `currentPath` context.

- **Lazy-load the dialog**: Since the dialog is only needed when the button is clicked, it
  could be `React.lazy`-loaded. Not strictly necessary (the component is ~8 KB minified)
  but can be done as a follow-up performance optimization.

## 5. Testing, Verification & Rollout

### 5.1 Regression test (Playwright) — fails before / passes after

**Before fix**: `driveButton.isVisible()` returns false; the `if (visible)` branch is never
entered; the test passes vacuously with zero assertions about the dialog.

**After fix**: Replace the conditional in `drive-picker.spec.ts` with a strict expectation:

```typescript
// AFTER FIX: remove the `if (visible)` guard; test must now assert unconditionally.
test("GoogleDrivePickerDialog is reachable from FilesPage", async ({ page }) => {
  await injectAuth(page, "alice");
  await page.goto("/files");
  await page.waitForLoadState("domcontentloaded");

  // Button must now be visible — fails before fix, passes after.
  const driveButton = page.getByRole("button", { name: /google drive/i });
  await expect(driveButton).toBeVisible({ timeout: 5000 });

  await driveButton.click();
  const dialog = page.locator('[data-testid="drive-picker-dialog"]');
  await expect(dialog).toBeVisible({ timeout: 5000 });
  await expect(page.locator('[data-testid="drive-search-input"]')).toBeVisible();
  await expect(page.locator('[data-testid="drive-breadcrumbs"]')).toContainText("My Drive");

  await page.getByRole("button", { name: "Cancel" }).click();
  await expect(dialog).not.toBeVisible();
});
```

Remove the now-redundant `if (visible)` guard and the associated comment from the original
test at line 201.

### 5.2 Unit test — component renders without crash

Add to `frontend/src/components/shared/__tests__/GoogleDrivePickerDialog.test.tsx`:

```typescript
import { render, screen } from "@testing-library/react";
import { GoogleDrivePickerDialog } from "../GoogleDrivePickerDialog";
import { QueryClientProvider, QueryClient } from "@tanstack/react-query";

const qc = new QueryClient({ defaultOptions: { queries: { retry: false } } });

test("renders dialog when open", () => {
  render(
    <QueryClientProvider client={qc}>
      <GoogleDrivePickerDialog
        open={true}
        onOpenChange={jest.fn()}
        currentPath="/"
      />
    </QueryClientProvider>,
  );
  expect(screen.getByTestId("drive-picker-dialog")).toBeInTheDocument();
  expect(screen.getByTestId("drive-search-input")).toBeInTheDocument();
  expect(screen.getByTestId("drive-breadcrumbs")).toHaveTextContent("My Drive");
});

test("does not render when closed", () => {
  render(
    <QueryClientProvider client={qc}>
      <GoogleDrivePickerDialog
        open={false}
        onOpenChange={jest.fn()}
        currentPath="/"
      />
    </QueryClientProvider>,
  );
  expect(screen.queryByTestId("drive-picker-dialog")).not.toBeVisible();
});
```

### 5.5 Rollout

- **Effort**: S (approximately 15 lines: 1 import, 1 state variable, 1 toolbar button, 1
  dialog render). Removing the `if (visible)` guard in the E2E test and adding the strict
  assertion is ~5 additional lines.
- **Risk**: Very low. Purely additive: a new button and a dialog mount. The dialog's internal
  `browseGoogleDriveFiles` query is `enabled: open`, so no network requests fire until the
  button is clicked.
- **Rollback**: Revert the `FilesPage.tsx` additions. The component and API client remain
  unchanged.
- **Sequencing**: This is a prerequisite for making the GAP-0239 Connect/Disconnect UX
  useful. Recommend landing GAP-0239 and GAP-0240 fixes together in a single PR so the
  Google Drive feature goes live as a coherent unit.
