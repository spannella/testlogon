# GAP-0335: `analytics_rollup_engine.py` not implemented — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code at `app/services/creator_analytics.py`, `app/core/settings.py`, `app/main.py`, and `app/routers/creator_analytics.py`.

## 1. Summary & Classification

**Gap**: `app/services/analytics_rollup_engine.py` does not exist. The settings file defines `S.analytics_rollup_enabled` (default `True`), `S.analytics_rollup_interval_seconds` (default 900), and `S.analytics_rollup_lookback_days` (default 3) at `app/core/settings.py:1751–1753` — all three settings anticipate a background rollup loop — but no service file, no `run_rollup_loop` function, and no startup registration exists. `app/main.py` does not register any analytics rollup background task; a grep across the entire `app/` directory finds zero calls to `run_rollup_loop` or `compute_daily_rollups`.

**Claim status**: Confirmed. The settings are a forward-declaration of intent. The rollup engine is entirely absent. The creator analytics dashboard at `app/routers/creator_analytics.py` reads from `T.analytics_rollups` (the pre-aggregated output table), which is only populated today via the manual `POST /refresh` endpoint that calls `upsert_daily_rollup` with placeholder zeros. Automated data collection has never run.

**Severity**: HIGH — without the rollup engine the entire automated analytics pipeline is non-functional. The creator dashboard shows zeros unless a creator manually triggers a refresh. Because the manual refresh (`POST /refresh`) calls `upsert_daily_rollup` with placeholder data derived from other tables rather than from real raw events, the metrics it produces are at best approximations and at worst fabricated. Revenue, audience, and subscriber data are never computed from actual event records.

**Source ticket**: PLATFORM-019. **Status**: Open. **Effort**: M. **Owning area**: Analytics / Creator Tools.

**Related tickets**: GAP-0333 (analytics_events table absent — prerequisite), GAP-0334 (recording service absent — prerequisite), GAP-0337 (zero router instrumentation — parallel dependency). All three must be resolved before the rollup engine produces useful output.

## 4. Fix Design (code-level)

### 4a. Create `app/services/analytics_rollup_engine.py`

The engine aggregates raw events from `T.analytics_events` (by creator, by date) and calls `upsert_daily_rollup` with computed values:

```python
"""Analytics rollup engine (ANALYTICS-001 / PLATFORM-019).

Background loop that aggregates raw events from analytics_events into daily
rollup rows in analytics_rollups. Runs every S.analytics_rollup_interval_seconds
and reprocesses the last S.analytics_rollup_lookback_days days to handle
late-arriving events.

Startup registration:
    from app.services.analytics_rollup_engine import start_rollup_loop_task
    app.add_event_handler("startup", start_rollup_loop_task)
"""
from __future__ import annotations

import asyncio
import logging
from collections import defaultdict
from datetime import datetime, timedelta, timezone
from decimal import Decimal
from typing import Any, Dict, List

from boto3.dynamodb.conditions import Key

from app.core.settings import S
from app.core.tables import T
from app.core.time import now_ts
from app.services.creator_analytics import upsert_daily_rollup, upsert_summary_sentinel

logger = logging.getLogger(__name__)


# ── Date helpers ────────────────────────────────────────────────────────────

def _utc_date(ts: int) -> str:
    return datetime.fromtimestamp(ts, tz=timezone.utc).strftime("%Y-%m-%d")


def _lookback_dates(lookback_days: int) -> List[str]:
    today = datetime.now(tz=timezone.utc).date()
    return [
        (today - timedelta(days=i)).strftime("%Y-%m-%d")
        for i in range(lookback_days + 1)
    ]


# ── Event fetching ──────────────────────────────────────────────────────────

def _fetch_events_for_creator_date(creator_id: str, date_str: str) -> List[Dict[str, Any]]:
    """Fetch all raw events for a creator on a given date using GSI1."""
    items: List[Dict[str, Any]] = []
    last_key = None
    while True:
        kwargs: Dict[str, Any] = {
            "IndexName": "GSI1",
            "KeyConditionExpression": (
                Key("GSI1PK").eq(f"CREATOR#{creator_id}")
                & Key("GSI1SK").eq(f"DATE#{date_str}")
            ),
        }
        if last_key:
            kwargs["ExclusiveStartKey"] = last_key
        try:
            resp = T.analytics_events.query(**kwargs)
        except Exception:
            logger.exception(
                "rollup.fetch_events failed creator=%s date=%s", creator_id, date_str
            )
            break
        items.extend(resp.get("Items", []))
        last_key = resp.get("LastEvaluatedKey")
        if not last_key:
            break
    return items


# ── Aggregation ─────────────────────────────────────────────────────────────

def _to_int(v: Any) -> int:
    if isinstance(v, Decimal):
        return int(v)
    try:
        return int(v)
    except (TypeError, ValueError):
        return 0


def _compute_creator_daily(creator_id: str, date_str: str) -> Dict[str, Any]:
    """Aggregate all raw events for creator on date_str into a rollup dict."""
    events = _fetch_events_for_creator_date(creator_id, date_str)

    data: Dict[str, Any] = {
        "total_views": 0,
        "unique_viewers": 0,
        "watch_time_seconds": 0,
        "revenue_cents": 0,
        "revenue_tips_cents": 0,
        "revenue_subscriptions_cents": 0,
        "revenue_unlocks_cents": 0,
        "revenue_vod_cents": 0,
        "revenue_ads_cents": 0,
        "revenue_calls_cents": 0,
        "new_subscribers": 0,
        "churned_subscribers": 0,
        "net_subscribers": 0,
        "post_reactions": 0,
        "post_comments": 0,
    }

    viewers: set[str] = set()
    countries: Dict[str, int] = defaultdict(int)
    devices: Dict[str, int] = defaultdict(int)

    for evt in events:
        etype = evt.get("event_type", "")

        if etype == "page_view":
            data["total_views"] += 1
            viewer = evt.get("viewer_id", "")
            if viewer and viewer != "anonymous":
                viewers.add(viewer)
            data["watch_time_seconds"] += _to_int(evt.get("watch_time_seconds", 0))
            country = evt.get("country_code")
            if country:
                countries[country] += 1
            device = evt.get("device_type")
            if device:
                devices[device] += 1

        elif etype == "revenue":
            cents = _to_int(evt.get("amount_cents", 0))
            data["revenue_cents"] += cents
            rtype = evt.get("revenue_type", "")
            if rtype == "tip":
                data["revenue_tips_cents"] += cents
            elif rtype == "subscription":
                data["revenue_subscriptions_cents"] += cents
            elif rtype == "unlock":
                data["revenue_unlocks_cents"] += cents
            elif rtype == "vod":
                data["revenue_vod_cents"] += cents
            elif rtype == "ad":
                data["revenue_ads_cents"] += cents
            elif rtype == "call":
                data["revenue_calls_cents"] += cents

        elif etype == "subscriber":
            kind = evt.get("event_kind", "")
            if kind == "new":
                data["new_subscribers"] += 1
            elif kind in ("cancelled", "churned"):
                data["churned_subscribers"] += 1

        elif etype == "engagement":
            action = evt.get("action", "")
            if action == "reaction":
                data["post_reactions"] += 1
            elif action == "comment":
                data["post_comments"] += 1

    data["unique_viewers"] = len(viewers)
    data["net_subscribers"] = data["new_subscribers"] - data["churned_subscribers"]
    if countries:
        data["audience_countries"] = dict(countries)
    if devices:
        data["audience_devices"] = dict(devices)

    return data


# ── Active creator discovery ─────────────────────────────────────────────────

def _get_active_creator_ids(date_str: str) -> List[str]:
    """Scan GSI1 for all distinct CREATOR# PKs active on a given date."""
    creator_ids: set[str] = set()
    last_key = None
    while True:
        kwargs: Dict[str, Any] = {
            "IndexName": "GSI1",
            "KeyConditionExpression": Key("GSI1SK").eq(f"DATE#{date_str}"),
        }
        if last_key:
            kwargs["ExclusiveStartKey"] = last_key
        try:
            resp = T.analytics_events.query(**kwargs)
        except Exception:
            logger.exception("rollup.get_active_creators failed date=%s", date_str)
            break
        for item in resp.get("Items", []):
            pk = item.get("GSI1PK", "")
            if pk.startswith("CREATOR#"):
                creator_ids.add(pk[8:])
        last_key = resp.get("LastEvaluatedKey")
        if not last_key:
            break
    return list(creator_ids)


# ── Rollup computation ───────────────────────────────────────────────────────

def compute_daily_rollups(lookback_days: int | None = None) -> int:
    """Compute daily rollups for all active creators over the lookback window.

    Returns count of (creator, date) pairs processed.
    """
    if lookback_days is None:
        lookback_days = S.analytics_rollup_lookback_days
    dates = _lookback_dates(lookback_days)
    processed = 0

    for date_str in dates:
        creator_ids = _get_active_creator_ids(date_str)
        for creator_id in creator_ids:
            try:
                data = _compute_creator_daily(creator_id, date_str)
                upsert_daily_rollup(creator_id, date_str, data)
                processed += 1
            except Exception:
                logger.exception(
                    "rollup.compute_creator_daily failed creator=%s date=%s",
                    creator_id, date_str,
                )

    logger.info(
        "rollup.compute_daily_rollups complete dates=%d processed=%d",
        len(dates), processed,
    )
    return processed


# ── Background loop ──────────────────────────────────────────────────────────

async def run_rollup_loop() -> None:
    """Background coroutine: compute daily rollups on a fixed interval."""
    interval = max(60, S.analytics_rollup_interval_seconds)
    logger.info("rollup_engine.start interval=%ds lookback=%dd", interval, S.analytics_rollup_lookback_days)
    while True:
        try:
            n = compute_daily_rollups()
            logger.info("rollup_engine.ran processed=%d", n)
        except Exception:
            logger.exception("rollup_engine.loop_error")
        await asyncio.sleep(interval)


def start_rollup_loop_task() -> None:
    """FastAPI startup handler: launch run_rollup_loop as an asyncio background task."""
    if not S.analytics_rollup_enabled:
        logger.info("rollup_engine.disabled (ANALYTICS_ROLLUP_ENABLED=0)")
        return
    asyncio.ensure_future(run_rollup_loop())
    logger.info("rollup_engine.task_created")
```

### 4d. Dev/Prod parity (SECOPS-007)

The rollup engine uses only:
- `T.analytics_events` (DynamoDB Local in dev, real DynamoDB in prod).
- `T.analytics_rollups` (same).
- `asyncio.ensure_future` — standard Python, no AWS dependency.

No `if S.dev_mode` branching required. The `analytics_rollup_enabled` flag allows disabling in test environments where deterministic fixture data is preferred over live event aggregation:

```bash
# .env.local.example — dev default: enabled
ANALYTICS_ROLLUP_ENABLED=1
ANALYTICS_ROLLUP_INTERVAL_SECONDS=900
ANALYTICS_ROLLUP_LOOKBACK_DAYS=3

# Test environment override: disable to avoid background noise
ANALYTICS_ROLLUP_ENABLED=0
```

E2E tests that assert analytics data should seed `T.analytics_rollups` directly (via `upsert_daily_rollup`) rather than relying on the background loop.

### 4e. Alternatives considered

- **Lambda / EventBridge trigger instead of in-process loop**: More scalable and decoupled, but introduces AWS Lambda dependency and complexity. The existing pattern for background tasks (deletion scheduler, KYC analytics) uses in-process `asyncio` loops. Consistent with that pattern, use in-process loop for dev/prod parity. Production can optionally migrate to Lambda later.
- **Single-pass on startup only (no loop)**: Would handle stale data on restart but miss new events after startup. The loop approach correctly handles continuously arriving events. Rejected.
- **Compute rollups synchronously on dashboard GET**: Would make every dashboard load query raw events — expensive for large creators. The pre-aggregation pattern is correct. Rejected.

### Rollback

Set `ANALYTICS_ROLLUP_ENABLED=0` to disable the background loop without redeploying. The rollup rows already computed are retained and served by the dashboard. Re-enable by restoring the flag and restarting the backend.

### Risks

- **High cardinality creator scans**: `_get_active_creator_ids` queries a GSI with `GSI1SK = DATE#{date}`. If many creators have events on the same day, this returns a large result set. Mitigation: cap at 1,000 creators per run and stagger processing.
- **Concurrent runs**: If the backend is restarted during a run, two instances may process the same date. `upsert_daily_rollup` is a `put_item` overwrite, so idempotent — double processing produces the same result as single processing.
- **GSI eventually consistent reads**: The `GSI1` on `analytics_events` uses eventually consistent reads by default. A freshly written event may not appear immediately. The `lookback_days = 3` window ensures late-arriving events are picked up in subsequent runs.

**Effort**: M (Medium) — the aggregation logic is straightforward given the event schema; the main work is the loop infrastructure and date-range query. Implementation: 3–4 hours. Unit tests: 2–3 hours. Integration and startup wiring: 1 hour. Total: ~1 day. Sequence after GAP-0333 and GAP-0334.
