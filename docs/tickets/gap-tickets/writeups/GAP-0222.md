# GAP-0222: Real EC2 Launch Path Raises `NotImplementedError` — Remediation Write-up

> Source ticket: INFRA-003 · Severity: HIGH · Effort: L · Status: Open

## 1. Summary & Classification

**Bug statement.** When the platform is deployed in production mode (environment variable `EC2_MOCK_ENABLED=0` or `DEV_MODE=0`), every attempt to launch an EC2 instance via `launch_instance()` in `app/services/ec2_launcher.py` raises `NotImplementedError("Real EC2 launch not implemented yet")` at line 185 and returns a 500 to the caller. The INFRA-003 feature that allows users to provision cloud instances is therefore completely non-functional in any environment that does not have `EC2_MOCK_ENABLED` set to a truthy value.

**Claim correction.** The ticket states that `stop_instance` (~273), `start_instance` (~302), `terminate_instance` (~332), and `reboot_instance` (~370) *also* raise `NotImplementedError`. **This is inaccurate.** Inspecting the actual code reveals that only `launch_instance` (line 185) raises. The other four functions (`stop_instance`, `start_instance`, `terminate_instance`, `reboot_instance`) follow the pattern:

```python
if S.ec2_mock_enabled:
    _mock_store.stop(ec2_id)   # (or .start / .terminate / .reboot)
# no else branch — silently proceeds to DDB update
```

In production mode those operations silently skip the real AWS EC2 API call and only update the DynamoDB record — a different bug (the instance status in DDB diverges from actual AWS state) but not a crash. The ticket's claim that they *raise* `NotImplementedError` is incorrect.

**Severity and area.** HIGH / Infrastructure / Cloud Compute. Without a real launch path, the EC2-backed compute feature is entirely non-functional in production. Any request to provision a cloud instance results in an unhandled 500 error.

**Related tickets.** INFRA-003 (EC2 launcher spec), GAP-0223 (auto-registration in host inventory never happens — depends on launch completing successfully), GAP-0224 (host inventory not cleaned up on termination), GAP-0237 (ByGlobalStatus GSI missing from ec2_instances table).

## 2. Current-State Investigation (root cause)

### The broken launch path

`app/services/ec2_launcher.py:174–185`:

```python
# 4. Launch (mock or real)
instance_id = uuid.uuid4().hex
if S.ec2_mock_enabled:
    result = _mock_store.launch(
        instance_id=instance_id,
        instance_type=instance_type,
        ami_id=ami_id,
        user_data=startup_script,
    )
else:
    # Real EC2 launch would go here
    raise NotImplementedError("Real EC2 launch not implemented yet")
```

`S.ec2_mock_enabled` is defined at `app/core/settings.py:2043`:

```python
ec2_mock_enabled: bool = os.environ.get(
    "EC2_MOCK_ENABLED",
    os.environ.get("DEV_MODE", "1")
) not in ("0", "false", "False")
```

This defaults to `True` (mock on) when `EC2_MOCK_ENABLED` is unset, falling back to `DEV_MODE`. In a production deployment where `DEV_MODE=0` and `EC2_MOCK_ENABLED` is not explicitly set to `1`, `ec2_mock_enabled` evaluates to `False`, triggering the `NotImplementedError` on every `launch_instance` call.

### The silent no-ops on stop/start/terminate/reboot

`stop_instance` lines 273–274, `start_instance` lines 302–303, `terminate_instance` lines 332–333, and `reboot_instance` lines 370–371 all follow the same incomplete branch pattern:

```python
ec2_id = item["ec2_instance_id"]
if S.ec2_mock_enabled:
    _mock_store.stop(ec2_id)   # only mock branch
# production path: falls through to DDB update only
```

In production, the real AWS EC2 API is never called. The DDB record is updated (status → "stopped", "running", "terminated", etc.) while the actual EC2 instance remains unchanged. This creates a split-brain state: the platform reports an instance as stopped when AWS reports it as still running. For `terminate_instance` this is especially dangerous — the DDB record is marked "terminated" but the actual EC2 instance (and its associated costs) continues running indefinitely.

### Missing boto3 EC2 client

`app/core/aws.py` provides `sns_client()` and `sqs_client()` helpers but has no `ec2_client()` function. The ec2_launcher imports only `from app.core.settings import S`, `from app.core.tables import T`, and `from app.core.time import now_ts`. No boto3 EC2 client is instantiated anywhere in the module.

### What a `run_instances` call requires

The minimum parameters for `boto3.client("ec2").run_instances(...)` are: `ImageId`, `InstanceType`, `MinCount`, `MaxCount`. The existing `AMIS` dict at line 35 maps platform AMI IDs (e.g., `"ami-ubuntu-2204"`) to human names — it does not contain real AWS AMI IDs. Production would need a per-region AMI mapping or a parameter-store lookup.

## 3. Impact / Exploit / Blast Radius

### Availability

Every user who attempts to launch an EC2 instance in a production deployment receives an HTTP 500. The router (`app/routers/ec2_launcher.py`) wraps the service call without catching `NotImplementedError`, so the exception propagates to FastAPI's default exception handler, returning a generic `{"detail": "Internal Server Error"}` response. The user has no indication that the feature is permanently broken rather than temporarily unavailable.

### Financial / resource leak

Because `terminate_instance`, `stop_instance`, and `start_instance` silently skip the real AWS API calls, any instances that were previously launched (e.g., via a different code path or a temporary fix) cannot be terminated through the platform. They continue running and accruing AWS costs until manually shut down via the AWS Console or CLI. The auto-terminate background task (`run_idle_instance_checker`) calls `terminate_instance` internally — in production, that function updates DDB to "terminated" but does not actually terminate the EC2 instance, so idle instances accumulate unchecked costs.

### Security surface

An instance that the platform considers "terminated" (DDB record status = "terminated") but that is still running on AWS retains its network interfaces, security group rules, and any services started at launch. If the startup script installed SSH keys or opened ports, those remain accessible even after the platform believes the instance is gone. This is a latent security surface invisible to the platform operator.

### Blast radius

All production EC2 feature traffic. In dev mode (the only currently functional mode), the bug is masked. Any attempt to use the feature in a staging or production environment that correctly sets `DEV_MODE=0` will fail immediately.

## 4. Fix Design (code-level)

### Approach

1. Add an `ec2_client()` factory to `app/core/aws.py` following the existing `sns_client()` pattern.
2. Implement `_real_ec2_launch()` in `ec2_launcher.py` using `boto3.client("ec2").run_instances(...)`.
3. Implement real stop/start/terminate/reboot stubs that call the corresponding boto3 EC2 API operations.
4. Add a per-region real AMI mapping (or settings-based override) so the curated AMI list resolves to actual AWS AMI IDs in production.

### `app/core/aws.py` — add `ec2_client()`

```python
def ec2_client(region: str | None = None):
    from boto3 import client as _boto3_client
    return _boto3_client(
        "ec2",
        region_name=region or S.aws_region or "us-east-1",
        endpoint_url=S.aws_endpoint_url or None,
    )
```

Add the helper function (above `launch_instance`):

```python
def _real_ec2_launch(
    *,
    instance_type: str,
    ami_id: str,
    startup_script: str = "",
    ssh_key_name: str | None = None,
    security_group_id: str | None = None,
) -> Dict[str, Any]:
    """Call the real AWS EC2 RunInstances API. Returns a dict compatible
    with _MockEc2Store.launch() so the rest of launch_instance is unchanged."""
    from app.core.aws import ec2_client
    real_ami_id = _resolve_real_ami(ami_id)

    kwargs: Dict[str, Any] = {
        "ImageId": real_ami_id,
        "InstanceType": instance_type,
        "MinCount": 1,
        "MaxCount": 1,
    }
    if startup_script:
        import base64
        kwargs["UserData"] = base64.b64encode(startup_script.encode()).decode()
    if ssh_key_name:
        kwargs["KeyName"] = ssh_key_name
    if security_group_id:
        kwargs["SecurityGroupIds"] = [security_group_id]

    ec2 = ec2_client()
    resp = ec2.run_instances(**kwargs)
    inst = resp["Instances"][0]
    return {
        "ec2_instance_id": inst["InstanceId"],
        "status": inst["State"]["Name"],
        "public_ip": inst.get("PublicIpAddress", ""),
        "private_ip": inst.get("PrivateIpAddress", ""),
    }
```

Add the AMI resolver that reads from settings (enables per-environment override without a code change):

```python
# Map from platform AMI alias → real AWS AMI ID, overridable via settings.
_REAL_AMI_MAP: Dict[str, str] = {
    "ami-ubuntu-2204":  S.ec2_real_ami_ubuntu_2204 if hasattr(S, "ec2_real_ami_ubuntu_2204") else "",
    "ami-ubuntu-2404":  S.ec2_real_ami_ubuntu_2404 if hasattr(S, "ec2_real_ami_ubuntu_2404") else "",
    "ami-amzn2":        S.ec2_real_ami_amzn2        if hasattr(S, "ec2_real_ami_amzn2") else "",
    "ami-windows-2022": S.ec2_real_ami_windows_2022 if hasattr(S, "ec2_real_ami_windows_2022") else "",
}

def _resolve_real_ami(platform_ami_id: str) -> str:
    real = _REAL_AMI_MAP.get(platform_ami_id, "")
    if not real:
        raise ValueError(
            f"No real AWS AMI ID configured for alias '{platform_ami_id}'. "
            "Set EC2_REAL_AMI_* environment variables."
        )
    return real
```

### Real stop/start/terminate/reboot

Add `else` branches to each function (shown for `stop_instance`; same pattern for others):

```python
if S.ec2_mock_enabled:
    _mock_store.stop(ec2_id)
else:
    from app.core.aws import ec2_client

`start_instance`:

```

`reboot_instance`:

### Dev/Prod parity (SECOPS-007)

`S.ec2_mock_enabled` already provides the flag-selected fork. The real path is gated on `not S.ec2_mock_enabled`. In dev mode (`DEV_MODE=1` or `EC2_MOCK_ENABLED=1`), the in-memory mock continues to be used — no AWS API calls are made. In production (`EC2_MOCK_ENABLED=0`), the real boto3 path runs. The `aws_endpoint_url` in `ec2_client()` allows pointing at a LocalStack or moto HTTP endpoint in integration testing without changing any other code, giving full dev/prod parity at the AWS-client level.

### Alternatives considered

**SSM parameter store for AMI IDs.** More operationally correct (AMI IDs change per region per release), but introduces an async lookup at launch time and a boto3 SSM dependency. Deferred to a follow-on ticket; the settings-based approach delivers a working production path immediately.

**Catching `NotImplementedError` in the router.** Rejected — this hides a broken feature rather than fixing it and gives the user no useful error message.
