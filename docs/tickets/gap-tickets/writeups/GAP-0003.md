# GAP-0003: Internal Charge Endpoints Lack Access Control — Remediation Write-up

> Source ticket: ADS-007 · Severity: CRIT · Effort: S · Status: Open

## 1. Summary & Classification

**Bug statement.** Three `POST /ui/ads/internal/charge-*` endpoints in `app/routers/ads.py` (lines 447, 460, 473) accept arbitrary `account_id` and `campaign_id` values from the request body and pass them directly to the billing service with no ownership verification. Any authenticated user can drain any advertiser's account balance to zero by supplying a victim's `account_id` in the JSON body.

**Verdict (from investigation):** Confirmed. The endpoints are protected only by `require_ui_session` (any registered user). The `_require_account_owner()` helper that exists at `ads.py:60` and is called by every other account-scoped endpoint in the file (lines 131, 139, 147, 161, 172, 441) is not called by any of the three charge endpoints. This is a straightforward access-control omission.

**Severity and area.** Critical / Advertising & Monetisation / Security. This is a horizontal privilege-escalation vulnerability: any authenticated user can perform a financial write against any other user's ad account. The fix is trivial (one line per endpoint) but the blast radius is severe.

**Related tickets.** ADS-007 (ad billing feature), SECOPS-007 (dev/prod parity), GAP-0004 (revenue-share endpoint access control — same file, different endpoint class). SEC-010 IDOR family tickets are structurally similar.

## 2. Current-State Investigation (root cause)

### The vulnerable endpoints: `ads.py:447–483`

```python
# app/routers/ads.py:447–483

@router.post("/internal/charge-impression")
async def internal_charge_impression(body: dict, ctx=Depends(require_ui_session)):
    from app.services.ad_billing import charge_impression
    return charge_impression(
        account_id=body["account_id"],
        campaign_id=body["campaign_id"],
        creative_id=body.get("creative_id", ""),
        creator_id=body.get("creator_id", ""),
        content_id=body.get("content_id", ""),
        bid_cpm_cents=body.get("bid_cpm_cents", 500),
    )


@router.post("/internal/charge-click")
async def internal_charge_click(body: dict, ctx=Depends(require_ui_session)):
    from app.services.ad_billing import charge_click
    return charge_click(
        account_id=body["account_id"],
        campaign_id=body["campaign_id"],
        creative_id=body.get("creative_id", ""),
        creator_id=body.get("creator_id", ""),
        content_id=body.get("content_id", ""),
        bid_cpc_cents=body.get("bid_cpc_cents", 50),
    )


@router.post("/internal/charge-conversion")
async def internal_charge_conversion(body: dict, ctx=Depends(require_ui_session)):
    from app.services.ad_billing import charge_conversion
    return charge_conversion(
        account_id=body["account_id"],
        campaign_id=body["campaign_id"],
        creative_id=body.get("creative_id", ""),
        creator_id=body.get("creator_id", ""),
        content_id=body.get("content_id", ""),

```

All three endpoints use the `router` (prefix `/ui/ads`) and `Depends(require_ui_session)` — the same dependency used by user-facing endpoints. `ctx` contains `{"user_sub": ..., "role": ..., ...}` but `ctx["user_sub"]` is never compared to the owner of the supplied `account_id`.

### The existing guard: `ads.py:60–64`

```python
# app/routers/ads.py:60–64
def _require_account_owner(account_id: str, user_sub: str) -> dict:
    acct = get_ad_account(account_id)
    if not acct or acct["owner_sub"] != user_sub:
        raise HTTPException(status_code=404, detail="Account not found")
    return acct
```

This helper is called at lines 131, 139, 147, 161, 172, and 441 for campaign CRUD and invoice endpoints. It raises `404` (not `403`) to avoid leaking whether the account exists, which is the correct UX choice. It is simply absent from the three charge endpoints.

### The admin router: `ads.py:55`

```python
# app/routers/ads.py:55
admin_router = APIRouter(prefix="/ui/admin/ads", tags=["ads-admin"])
```

The `admin_router` is already defined in the same file and is used for account review, campaign review, and admin-only operations with `require_admin_or_root` (lines 184, 189, 203, 208). Moving the charge endpoints here is a viable alternative.

### Naming and intent

The `/internal/` path segment in the URL is a naming convention suggesting these endpoints were intended for server-to-server calls only. However, they were registered under the user-facing `/ui/ads/` router without IP filtering, network isolation, or API-key scoping. In both dev and production, the routes are exposed to any HTTP client with a valid session cookie.

### Charge magnitude per call

The billing functions in `ad_billing.py` compute the per-call charge as follows:
- `charge_impression` (line 65): `charge_cents = max(1, bid_cpm_cents // 1000)`. At the default `bid_cpm_cents=500`, each call charges `0` (rounds to 0, then clamped to 1 cent). At `bid_cpm_cents=50000`, each call charges 50 cents.
- `charge_click` (line 76–81): charges `bid_cpc_cents` directly — no division. Default 50 cents per call.
- `charge_conversion` (line 88–94): charges `bid_cpa_cents` directly. Default 500 cents ($5) per call.

An attacker using `charge-conversion` with `bid_cpa_cents=50000` can drain $500 per request. With no rate limiting and no per-account balance floor check before the debit, a scripted loop can drain a $10,000 balance in approximately 20 requests. The DynamoDB `update_item` at `ad_billing.py:127–131` allows the balance to go negative (`balance_cents = balance_cents - :amt` has no `ConditionExpression`), so the damage can exceed the advertiser's current balance — it can create a negative balance liability.

### The `ctx` variable is unused

In all three vulnerable endpoints, `ctx=Depends(require_ui_session)` is present in the function signature but `ctx` is never referenced in the function body. The session context is fetched but discarded. This is the clearest marker of the copy-paste omission: the developer included the session dependency (which was correct) but forgot to use `ctx["user_sub"]` for ownership validation.

## 3. Impact / Exploit / Blast Radius

### Exploit walkthrough

1. Attacker Alice logs in (any registered account).
2. Attacker obtains a victim's `account_id` — these are not secret; they appear in campaign URLs, ad transparency pages, and can be guessed from patterns such as `ACCT#<uuid>`.
3. Alice sends:

```http
POST /ui/ads/internal/charge-impression HTTP/1.1
Cookie: ui_session=...; ui_access_token=...
x-csrf-token: <alice_csrf>
Content-Type: application/json

{
  "account_id": "victim_account_id",
  "campaign_id": "victim_campaign_id",
  "bid_cpm_cents": 50000
}
```

4. `charge_impression` in `ad_billing.py:125–131` debits `victim_account_id`'s balance by `50000 / 1000 * 1 = 50` cents per call. At the maximum `bid_cpm_cents` value, repeated calls can drain the balance to zero in seconds.
5. The victim's campaigns are suspended by the budget check (`_check_budget_and_alert`) after balance hits zero.

### Financial blast radius

- Any advertiser's balance can be drained to $0 by an authenticated attacker in O(balance / bid_cpm_cents) requests. With no rate limiting on this endpoint, a scripted attacker can drain a $10,000 balance in under a minute.
- `lifetime_spent_cents` is also incremented, permanently misrepresenting the campaign's historical spend even after the balance is refunded.
- The billing ledger (`T.ad_billing`) receives fraudulent entries that are attributed to valid creative/campaign/creator IDs, polluting analytics.

### Scope

All three billing endpoints are equally affected:
- `charge-impression`: CPM billing at `/1000 × bid_cpm_cents` cents per call.
- `charge-click`: `bid_cpc_cents` cents per call.
- `charge-conversion`: `bid_cpa_cents` cents per call — highest per-event charge, up to the `bid_cpa_cents` field (no validation present on that field either).

No rate limiting exists on these endpoints (no `slowapi` or similar decorator), so the attack is scalable.

## 4. Fix Design (code-level)

### Preferred fix: move to `admin_router` with `require_admin_or_root`

These endpoints are named "internal" and are intended to be invoked by trusted server-side code (e.g., the ad tracking pipeline after a verified impression event). They should never be callable by regular users. Moving them to `admin_router` restricts them to admin and root roles:

```python
# app/routers/ads.py — replace lines 447–483

@admin_router.post("/internal/charge-impression")
async def internal_charge_impression(
    body: dict,
    user: AuthenticatedUser = Depends(require_admin_or_root),
):
    from app.services.ad_billing import charge_impression
    return charge_impression(
        account_id=body["account_id"],
        campaign_id=body["campaign_id"],
        creative_id=body.get("creative_id", ""),
        creator_id=body.get("creator_id", ""),
        content_id=body.get("content_id", ""),
        bid_cpm_cents=body.get("bid_cpm_cents", 500),
    )


@admin_router.post("/internal/charge-click")
async def internal_charge_click(
    body: dict,
    user: AuthenticatedUser = Depends(require_admin_or_root),
):
    from app.services.ad_billing import charge_click
    return charge_click(
        account_id=body["account_id"],
        campaign_id=body["campaign_id"],
        creative_id=body.get("creative_id", ""),
        creator_id=body.get("creator_id", ""),
        content_id=body.get("content_id", ""),
        bid_cpc_cents=body.get("bid_cpc_cents", 50),
    )


@admin_router.post("/internal/charge-conversion")
async def internal_charge_conversion(
    body: dict,
    user: AuthenticatedUser = Depends(require_admin_or_root),
):
    from app.services.ad_billing import charge_conversion
    return charge_conversion(
        account_id=body["account_id"],
        campaign_id=body["campaign_id"],
        creative_id=body.get("creative_id", ""),
        creator_id=body.get("creator_id", ""),
        content_id=body.get("content_id", ""),
        bid_cpa_cents=body.get("bid_cpa_cents", 500),
    )
```

The `admin_router` is already registered in `app/main.py` with the `/ui/admin/ads` prefix. Moving these three endpoints changes their URLs from `/ui/ads/internal/charge-*` to `/ui/admin/ads/internal/charge-*`. Any internal callers (e.g., impression tracking pipeline) must update their URLs accordingly.

### Alternative fix: add `_require_account_owner` per endpoint

If these endpoints must remain accessible to regular users (e.g., for self-service advertiser workflows), add ownership verification:

```python
@router.post("/internal/charge-impression")
async def internal_charge_impression(body: dict, ctx=Depends(require_ui_session)):
    _require_account_owner(body["account_id"], ctx["user_sub"])
    from app.services.ad_billing import charge_impression
    return charge_impression(
        account_id=body["account_id"],
        ...
    )
```

This is inferior to Option A because legitimate advertisers should not be able to self-trigger arbitrary billing charges; billing should be driven by the ad serving engine, not user-initiated POST requests.

### Dev/Prod parity (SECOPS-007)

`require_admin_or_root` resolves roles from the `ui_access_token` JWT cookie (HS256, signed with `UI_ACCESS_TOKEN_SECRET`). In dev, admin and root sessions are seeded by `e2e_admin_session_setup.py`. In production, roles are set via the admin role management system. The dependency works identically in both environments — no parity gap is introduced.

The `_require_account_owner` path (Option B) similarly uses `require_ui_session` which is identical in dev and prod.

### Backward compatibility and migration

Moving the endpoints changes their URL path. Audit all callers of `/ui/ads/internal/charge-*` in the codebase and update them to `/ui/admin/ads/internal/charge-*`. A grep of the frontend and backend confirms no existing frontend components call these paths (they are intended as internal/server-side calls only).

## 5. Testing, Verification & Rollout

### Regression test (pytest, offline — `tests/test_ads_charge_authz.py`)

```python
import pytest
from fastapi.testclient import TestClient
from app.main import create_app
from tests.conftest import make_session_cookies  # project test helper


@pytest.fixture
def client():

@pytest.fixture
```

**Fails-before / passes-after contract:**
- The three `_rejected_for_non_owner` tests currently fail (return 200, allowing the charge). After moving to `admin_router`, the old `/ui/ads/internal/charge-*` path returns 404/405 (route not registered), making these tests pass.
- `test_charge_impression_allowed_for_admin` fails before the fix (route `/ui/admin/ads/internal/charge-impression` does not exist, returns 404) and passes after.

### Manual QA steps

1. Log in as a regular user (Alice). Attempt `POST /ui/ads/internal/charge-impression` with a known `account_id`. Confirm the response is `404` (old path no longer registered on `router`).
2. Log in as admin. Attempt `POST /ui/admin/ads/internal/charge-impression`. Confirm it routes correctly and charges the specified account.
3. Verify existing campaign CRUD endpoints (`/ui/ads/accounts`, `/ui/ads/campaigns`) continue to work for regular users.

### Observability

Add a structured log entry in each charge endpoint including `user_sub` (from the auth context) and `account_id`. This creates an audit trail for post-incident review. Alert on any `account_id != owner_account_id` pattern if Option B is chosen.

### Rollout & risks

- **Risk:** Internal callers hardcode the old `/ui/ads/internal/charge-*` URL. Grep confirms no frontend call sites; backend callers (e.g., `broadcast_ads.py`, impression tracking) must be updated to use the new admin path or the server-to-server equivalent.
- **Risk:** Moving to `admin_router` breaks any automated test that currently posts to the old URL. Update those tests as part of this PR.
- **Risk:** The balance can go negative in DynamoDB (no `ConditionExpression` on the debit). As a complementary hardening measure, add `ConditionExpression=Attr("balance_cents").gte(charge_cents)` to the `update_item` in `ad_billing.py:127`. This is a separate ticket but should be shipped in the same release.
- **Rollback:** Revert the decorator changes. No data migration needed.
- **Effort:** S — three decorator changes plus URL updates in internal callers, plus tests.
- **Priority:** Deploy immediately; this is an exploitable financial vulnerability in production.

### Audit of existing charges

After deploying the fix, run an audit query against `T.ad_billing` to identify ledger entries where `entry_type IN ("impression_charge", "click_charge", "conversion_charge")` and the associated `user_sub` (call initiator, if logged) does not match the account owner. Any such entries represent fraudulent charges that may require manual reversal. Add `called_by_user_sub` to the ledger entry schema in the same release to make future audits tractable.
