# GAP-0179: S3 Upload Path Dead in Current Audit Export Pipeline — Remediation Write-up

> Source ticket: ENTERPRISE-004 · Severity: HIGH · Effort: L · Status: Open

## 1. Summary & Classification

**Bug statement.** `app/services/audit_export_pipeline.py` implements export content generation
fully (event merging, CSV/NDJSON serialisation, HMAC-signed manifest) but never uploads the
result to S3 in the production code path. The only function that writes export content —
`_process_export_inline` — stores it as a string attribute on the DynamoDB item, which is a
dev-mode workaround explicitly noted in the code comment. There is no `_process_export_s3`
function, no `boto3` S3 import, and no `s3.put_object` call anywhere in the pipeline file.
In production, `create_export_job` returns a `pending` record and no S3 object is ever written.

**Verdict:** Confirmed. A full-text search of `app/services/audit_export_pipeline.py` (250 lines)
finds zero occurrences of `s3`, `boto3`, `put_object`, `upload_fileobj`, or `generate_presigned_url`.
The inline comment at line 125 states: "In production the content would be written to S3, not
stored in the DDB item." The production S3 path is described, not implemented.

This gap is the complementary storage-layer half of GAP-0178 (missing worker). GAP-0178 ensures
a worker picks up `pending` jobs; GAP-0179 ensures those jobs write to S3 and generate a
download URL. Both must be fixed together.

**Severity and area.** HIGH / Enterprise Compliance & Audit (ENTERPRISE-004). Without S3
upload, even if GAP-0178 were fixed (worker added), production exports would either overflow
the 400 KB DynamoDB item limit for large datasets or produce no downloadable artifact at all.

**Related tickets.** ENTERPRISE-004, GAP-0178 (missing worker — must ship together). The
settings `S.audit_export_s3_bucket` and `S.audit_export_url_ttl_seconds` confirm S3 upload
was intended from the original design.

## 2. Current-State Investigation (root cause)

### What exists: inline dev-mode processing at `audit_export_pipeline.py:120–232`

`_process_export_inline` is a fully working function for dev mode:
- It generates events via `_merge_sorted_events` (capped at `_DEV_INLINE_MAX_EVENTS = 500`).
- It serialises to CSV or NDJSON.
- It computes HMAC-SHA256 manifest signature via `_compute_manifest_signature`.
- It writes `export_content` (the raw text) and `export_manifest` (JSON string) as DynamoDB
  attributes on the export record.

This works for development but is fundamentally bounded by DynamoDB's 400 KB item size limit.
A CSV export of 500 audit events at ~500 bytes each is 250 KB — approaching the limit. Any
production export with thousands of events would require splitting across items or a different
storage backend, which is exactly what S3 is for.

### What is missing: the S3 upload path

`app/core/settings.py:1914` declares `audit_export_s3_bucket: str = os.environ.get("AUDIT_EXPORT_S3_BUCKET", "data-exports")`.
`app/core/settings.py:1915` declares `audit_export_url_ttl_seconds: int`.

These settings are never referenced in `audit_export_pipeline.py`. A grep of the entire `app/`
directory for `audit_export_s3_bucket` returns only `app/core/settings.py`. The bucket name
is declared but never used.

### Downstream: download endpoint has no URL to serve

`app/routers/audit_export.py` exposes `GET /ui/admin/audit-exports/{export_id}/download`.
In dev mode this works because `export_content` is stored inline in DynamoDB. In production,
`export_content` is never written and the download endpoint returns an empty string or 404.

There is also no pre-signed URL generation: the download endpoint returns raw content
(suitable for small dev exports) rather than redirecting to an S3 pre-signed URL
(required for large production exports).

### Dev vs prod divergence

| Concern              | Dev mode (`S.dev_mode=True`)               | Production (`S.dev_mode=False`) |
|----------------------|--------------------------------------------|---------------------------------|
| Content storage      | DDB attribute `export_content`             | Not implemented (S3 intended)   |
| Max events           | 500 (hard cap)                             | Unlimited (but path is dead)    |
| Download mechanism   | Inline text from DDB                       | Not implemented                 |
| Manifest signature   | Written to DDB `export_manifest`           | Never computed                  |
| Status transition    | `pending` → `completed` synchronously      | Stays `pending` forever         |

## 3. Impact / Exploit / Blast Radius

**Production exports are completely non-functional.** A root admin who creates an export
job in production receives a 201 with a `pending` status. The job never progresses. The
download endpoint either returns empty content or a stale dev-mode artefact if the row was
somehow written by a dev migration.

**DynamoDB item size overflow (dev risk).** In a long-running dev environment with large audit
tables, a dev-mode export exceeding 400 KB will cause `ItemSizeTooLarge` on the DynamoDB
`update_item` call, silently marking the export as `failed`. Root admins see a failed export
with no actionable error message.

**Audit integrity.** The HMAC-signed manifest is designed to provide a tamper-evident chain
of custody for exported data. In production, no manifest is ever written, so the integrity
guarantee does not exist.

**Compliance.** Same as GAP-0178: GDPR data subject access requests, eDiscovery, and SOC 2
audit trail requirements depend on functional exports.

**No data leakage risk from the missing implementation.** The bug is a missing write, not a
missing read control.

## 4. Fix Design (code-level)

### Add `_process_export_s3` to `app/services/audit_export_pipeline.py`

```python
# app/services/audit_export_pipeline.py  (new function, add after _process_export_inline)

import boto3
from app.core.aws import get_s3_client   # or boto3.client("s3") directly


def _process_export_s3(export_id: str, job: dict) -> None:
    """Process an export job for production: generate content and upload to S3."""
    try:
        categories = list(job.get("categories", []))
        fmt = job.get("format", "ndjson")
        from_ts = int(job.get("from_date", 0))
        to_ts = int(job.get("to_date", 0))
        actor = job.get("actor_filter") or None
        target = job.get("target_filter") or None
        event_actions = job.get("event_actions_filter") or None
        if isinstance(event_actions, list) and len(event_actions) == 0:
            event_actions = None

        # Stream content into an in-memory buffer to avoid materialising
        # the entire export in RAM before upload.
        buf = io.BytesIO()
        event_count = 0
        sha256 = hashlib.sha256()

        if fmt == "csv":
            bom = "﻿".encode("utf-8")
            buf.write(bom)
            sha256.update(bom)
            header_buf = io.StringIO()
            csv.writer(header_buf).writerow(CSV_COLUMNS)
            header_bytes = header_buf.getvalue().encode("utf-8")
            buf.write(header_bytes)
            sha256.update(header_bytes)
            for event in _merge_sorted_events(
                categories, from_ts, to_ts, actor, target, event_actions
            ):
                row_buf = io.StringIO()
                csv.writer(row_buf).writerow(event.to_csv_row(CSV_COLUMNS))
                line_bytes = row_buf.getvalue().encode("utf-8")
                buf.write(line_bytes)
                sha256.update(line_bytes)
                event_count += 1
        else:
            for event in _merge_sorted_events(
                categories, from_ts, to_ts, actor, target, event_actions
            ):
                line_bytes = (event.to_ndjson_line() + "\n").encode("utf-8")
                buf.write(line_bytes)
                sha256.update(line_bytes)
                event_count += 1

        file_size = buf.tell()
        file_hash = sha256.hexdigest()
        file_extension = "csv" if fmt == "csv" else "ndjson"
        s3_key = f"audit-exports/{export_id}/{export_id}.{file_extension}"

        # Upload to S3
        buf.seek(0)
        s3 = get_s3_client()
        s3.upload_fileobj(
            buf,
            S.audit_export_s3_bucket,
            s3_key,
            ExtraArgs={
                "ContentType": "text/csv" if fmt == "csv" else "application/x-ndjson",
                "ServerSideEncryption": "AES256",
            },
        )

        # Build and sign manifest
        manifest = {
            "export_id": export_id,
            "schema_version": "1.0",
            "format": fmt,
            "event_count": event_count,
            "date_range": {
                "from": datetime.fromtimestamp(from_ts, tz=timezone.utc).isoformat(),
                "to": datetime.fromtimestamp(to_ts, tz=timezone.utc).isoformat(),
            },
            "categories": categories,
            "filters": {
                "actor_user_id": actor,
                "target_user_id": target,
                "event_actions": event_actions,
            },
            "s3_bucket": S.audit_export_s3_bucket,
            "s3_key": s3_key,
            "file_sha256": file_hash,
            "file_size_bytes": file_size,
            "created_at": datetime.fromtimestamp(now_ts(), tz=timezone.utc).isoformat(),
            "created_by": job.get("created_by", ""),
            "signing_key_id": S.audit_export_signing_key_id,
            "contains_pii": True,
        }
        manifest["signature"] = _compute_manifest_signature(manifest)

        T.audit_exports.update_item(
            Key={"export_id": export_id, "sk": "META"},
            UpdateExpression=(
                "SET #st = :st, completed_at = :ca, event_count = :ec, "
                "file_size_bytes = :fs, manifest_sha256 = :ms, events_written = :ew, "
                "s3_key = :s3k, s3_bucket = :s3b, export_manifest = :manifest"
            ),
            ExpressionAttributeNames={"#st": "status"},
            ExpressionAttributeValues={
                ":st": "completed",
                ":ca": now_ts(),
                ":ec": event_count,
                ":fs": file_size,
                ":ms": file_hash,
                ":ew": event_count,
                ":s3k": s3_key,
                ":s3b": S.audit_export_s3_bucket,
                ":manifest": json.dumps(manifest),
            },
        )
    except Exception as exc:
        logger.exception("S3 export job %s failed", export_id)
        T.audit_exports.update_item(
            Key={"export_id": export_id, "sk": "META"},
            UpdateExpression="SET #st = :st, error_message = :em",
            ExpressionAttributeNames={"#st": "status"},
            ExpressionAttributeValues={
                ":st": "failed",
                ":em": str(exc)[:500],
            },
        )
```

### Add `process_export_job` public entry point

```python
# app/services/audit_export_pipeline.py  (new public function)

def process_export_job(export_id: str, job: dict[str, Any]) -> None:
    """Dispatch to the correct processing path based on deployment mode."""
    if S.dev_mode:
        _process_export_inline(export_id, job)
    else:
        _process_export_s3(export_id, job)
```

### Update download endpoint for S3 pre-signed URLs

```python
# app/routers/audit_export.py  (update the download endpoint)

@router.get("/{export_id}/download")
async def download_export(export_id: str, ctx=Depends(require_ui_session)):
    _require_root(ctx)
    resp = T.audit_exports.get_item(Key={"export_id": export_id, "sk": "META"})
    item = resp.get("Item")
    if not item:
        raise HTTPException(404, "Export not found")
    if item.get("status") != "completed":
        raise HTTPException(409, f"Export not ready (status: {item.get('status')})")

    if S.dev_mode:
        # Dev: return inline content directly
        content = item.get("export_content", "")
        return PlainTextResponse(content)

    # Production: generate a pre-signed S3 URL
    s3_key = item.get("s3_key")
    s3_bucket = item.get("s3_bucket", S.audit_export_s3_bucket)
    if not s3_key:
        raise HTTPException(500, "Export completed but S3 key is missing")

    s3 = get_s3_client()
    url = s3.generate_presigned_url(
        "get_object",
        Params={"Bucket": s3_bucket, "Key": s3_key},
        ExpiresIn=S.audit_export_url_ttl_seconds,
    )
    return {"download_url": url, "expires_in": S.audit_export_url_ttl_seconds}
```

### Dev/prod parity (SECOPS-007)

The `process_export_job` function forks on `S.dev_mode`. In dev, the existing inline path is
preserved for backward compatibility (dev test assertions continue to work). In production,
`_process_export_s3` runs. Moto (the mock S3 in dev) intercepts `boto3` S3 calls at the
botocore layer when `S.dev_mode=True` — to exercise `_process_export_s3` in a dev environment,
set `DEV_MODE=0` and ensure `AUDIT_EXPORT_S3_BUCKET=data-exports` is present; the moto mock
will serve the S3 calls without a real AWS bucket.

### Bucket configuration

Create the `data-exports` S3 bucket (or the value of `AUDIT_EXPORT_S3_BUCKET`) in production
with:
- Server-side encryption (SSE-S3 or SSE-KMS).
- No public access.
- Lifecycle policy: `INTELLIGENT_TIERING` or 90-day transition to Glacier.
- Bucket policy allowing only the FastAPI task role to `s3:PutObject` and `s3:GetObject`.
