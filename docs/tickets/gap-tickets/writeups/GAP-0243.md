## 3. Impact / Exploit / Blast Radius

### 3.1 Current state (page present)

There is no functional impact from this gap ticket. Admins can navigate to `/admin/kyc`,
see the queue, filter by status and risk tier, paginate, and click through to case detail.

### 3.2 Regression risk

Without a dedicated E2E test for this page, future refactors of the API shape or routing
could silently break the queue. The test gap is the actionable finding.

### 3.3 One functional gap: "Assigned to Me" quick-filter absent

The KYC-001 acceptance criteria mention a "Claim" or "Assigned to me" quick-filter shortcut.
`KycQueuePage.tsx` provides a free-text `assignee_admin_sub` input but no "My Cases" button
that auto-fills the current admin's sub. This is a minor UX shortcut gap, not a blocking one.

## 4. Fix Design (code-level)

### 4.1 No structural fix required

The page is fully implemented. The following improvements are recommended to close the
residual gaps and harden the implementation:

### 4.2 Add "My Cases" quick-filter button

In `KycQueuePage.tsx`, import the auth store to get the current user's sub:

```typescript
import { useAuthStore } from "@/stores/authStore";
```

In the component body:
```typescript
const { user } = useAuthStore();
```

In the filter card, after the Assignee input:
```tsx
<div className="flex items-end">
  <Button
    variant="outline"
    size="sm"
    onClick={() => {
      setAssigneeFilter(user?.sub ?? "");
      setCursor(undefined);
      setPrevCursors([]);
    }}
    data-testid="my-cases-filter"
  >
    My Cases
  </Button>
</div>
```

### 4.3 Add "approved"/"rejected" status filter options

For supervisors who need to audit completed cases, add:
```tsx
<SelectItem value="approved">Approved</SelectItem>
<SelectItem value="rejected">Rejected</SelectItem>
```

This is a minor scope addition but aligns with KYC-001 audit trail requirements.

### 4.4 Persist filter state in URL search params

Current implementation uses React state. On page reload filters are lost. Use
`useSearchParams` from `react-router-dom`:

```typescript
const [searchParams, setSearchParams] = useSearchParams();
const [statusFilter, setStatusFilter] = useState(
  searchParams.get("status") ?? "all"
);
```

This also makes filter state shareable via URL (useful for supervisors sharing specific queue
views).

### 4.5 Dev/Prod parity (SECOPS-007)

The `fetchKycQueue` function calls `GET /ui/admin/kyc/queue` (or equivalent). The backend
endpoint should serve real DynamoDB data in both dev and prod; there is no mock/real split at
the API level for read-only admin views. Dev mode adds no special behavior here. SECOPS-007
is satisfied: no env-conditional logic in the frontend component.

### 5.3 Backend API contract verification

`KycQueuePage.tsx:91-98` calls `fetchKycQueue` with `limit: 20`. The backend must honor the
`limit` parameter and return `{ items: KycQueueItem[], next_cursor: string | null }`. Verify
the backend endpoint (`GET /ui/admin/kyc/queue` or equivalent) returns this exact shape.
Confirm that:

1. When the total queue size is ≤ 20, `next_cursor` is `null` and both pagination buttons
   are hidden (the `(prevCursors.length > 0 || nextCursor)` guard at line 283 handles this).
2. When the total queue size is > 20, `next_cursor` is a non-null string and the "Next"
   button becomes enabled.
3. Each `KycQueueItem` contains `waiting_seconds: number | null` — if the backend returns
   `null` for new cases (e.g., `waiting_seconds = None` in Python), `formatWaitTime(null)`
   at line 68 correctly returns `"--"`.
4. `risk_tier` may be `null` (the backend risk-scoring may not have run yet) — `riskBadgeVariant`
   at line 53 defaults to `"secondary"` for `null`, and the cell renders `"unknown"` via
   `item.risk_tier ?? "unknown"` at line 255.

These shape validations prevent silent table column blanking that could mislead reviewers
into believing a case has no risk score or no wait time.

### 5.4 TypeScript type safety

The `KycQueueItem` type used by the table cells must include the fields rendered in the table
(`kyc_case_id`, `user_sub`, `status`, `risk_tier`, `waiting_seconds`, `assigned_admin_sub`).
Verify `frontend/src/api/endpoints/kyc-admin.ts` exports this type with all required fields.
A missing field causes TypeScript to infer `undefined` silently in JSX, producing empty cells
rather than a compile error — add `strict: true` to `tsconfig.json` for the `api/` directory
if it is not already set.

### 5.5 Accessibility

The table uses `onClick` on `<TableRow>` to navigate to the detail page (line 239). This is
not keyboard-accessible without a `tabIndex="0"` and `onKeyDown` handler. Add:

```tsx
<TableRow
  key={item.kyc_case_id}
  tabIndex={0}
  role="button"
  aria-label={`Open KYC case ${item.kyc_case_id}`}
  onClick={() => handleRowClick(item)}
  onKeyDown={(e) => e.key === "Enter" && handleRowClick(item)}
  ...
>
```

This ensures keyboard-only compliance leads can navigate the queue without using the "View"
button on every row.
