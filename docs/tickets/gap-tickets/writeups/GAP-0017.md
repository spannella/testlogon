# GAP-0017: `useGroupCall.ts` Hook Does Not Exist — Remediation Write-up

> ~5 pages. Fix-oriented. Cites real file:line. Built on the verified investigation at
> `docs/tickets/gap-tickets/investigations/GAP-0017.md`.

## 1. Summary & Classification

**Plain-English statement**: The `useGroupCall.ts` hook specified in the CALL-012 design does
not exist as a standalone file. Group-call lifecycle logic is implemented inline inside
`GroupCallOverlay.tsx`, but it omits the critical mesh/SFU mode-selection step specified in
CALL-012 §4.1. The join response's `mode` field is read and immediately discarded; no
`RTCPeerConnection` is ever created in either path. Group calls show participant tiles but
transmit no audio or video.

- **Severity**: CRIT
- **Source ticket**: CALL-012
- **Status**: Open
- **Owning area**: Frontend (React hooks / WebRTC)
- **Verdict**: **Partially confirmed** — the hook file is absent; basic lifecycle (create/
  join/leave/end/media-toggle) IS present inline, but mesh/SFU mode selection and all WebRTC
  signaling are absent.
- **One-line impact**: Group calls are a state-management UI shell with no media flow; users
  on paid group calls pay for silence.
- **Related tickets**: GAP-0016 (call billing heartbeat missing), CALL-012 (source feature),
  GAP-0150 (no pytest unit tests for group call service).

## 2. Current-State Investigation (Root Cause)

### What is implemented (inline in `GroupCallOverlay.tsx`)

`frontend/src/pages/messages/GroupCallOverlay.tsx` is a 431-line file that contains all
group-call lifecycle management embedded directly in two React components:

**`GroupCallButton` (lines 63-179)**:
- Polls `getActiveGroupCall(conversationId)` every 5 s via `useQuery`.
- `createMut` mutation calls `createGroupCall(...)` and sets `inCall = true` on success
  (line 87-96).
- `joinMut` mutation calls `joinGroupCall(callId)` but in the `onSuccess` handler at line
  100-106 only sets `setInCall(true)` — the join response data is completely discarded:

```typescript
// GroupCallOverlay.tsx:98-107
const joinMut = useMutation({
  mutationFn: (callId: string) => joinGroupCall(callId),
  onSuccess: () => {
    setInCall(true);          // ← response payload never read
    toast.success("Joined group call");
  },
  // ...
});
```

The `joinGroupCall` API call returns a `GroupCallJoinOut` that per the CALL-012 spec includes
a `mode` field (`"mesh"` or `"sfu"`) and an `ice_servers` array. Neither is consumed.

**`GroupCallOverlay` (lines 184-431)**:
- Polls `getGroupCall(callId)` every 3 s.
- Handles leave/end/media-toggle mutations correctly at the REST level.
- Auto-closes when `callData?.state === "ended"`.
- Renders participant tiles with audio/video/screen indicators.

Critically, the file header comment (around line 1-15) explicitly states:
> "No actual WebRTC peer connections — media layer is out of scope for this ticket."

This confirms the media layer was intentionally deferred but was never subsequently
implemented.

### What is absent

A search of `frontend/src/hooks/` yields 28 hook files; none is named `useGroupCall*`. A
full-source `grep -rn "useGroupCall"` returns zero results — the hook is not referenced
anywhere.

`useRtcPeerConnection.ts` exists in `frontend/src/hooks/` and implements a generic WebRTC
peer connection hook, but it is not imported by `GroupCallOverlay.tsx`.

`frontend/src/api/endpoints/groupCalls.ts` exports `sendGroupCallSignal` (for SDP/ICE
exchange) and `updateGroupCallMedia` — both are dead code because no caller exists.

### How the gap manifests at runtime

Group calls currently show:
- A "Group call started/joined" toast.
- A participant panel with avatars, mute/video indicators.
- A working leave/end flow that updates DynamoDB state correctly.

Group calls do NOT transmit:
- Any audio stream.
- Any video stream.
- Any screen-share stream.

The `RTCPeerConnection` is never created, so no ICE candidates are exchanged and no SDP
offer/answer is performed. The STUN/TURN servers returned by the backend are never used.

## 3. Impact / Exploit / Blast Radius

### User-facing impact

Every group call in production is currently a silent, video-free experience. Participants
can see each other's names but cannot hear or see each other. This is a complete feature
failure for the core group-call use case.

### Privacy risk (mesh mode)

In WebRTC mesh topology (peer-to-peer), each participant's ICE candidates reveal their public
IP address to every other participant. The SFU topology routes media through a server,
preventing IP leakage. Because mode selection is absent, the platform cannot enforce SFU for
calls where IP privacy is required (e.g., enterprise tenants with a privacy policy). When the
WebRTC layer is eventually added without mode-selection, the platform may default to mesh and
inadvertently expose participant IPs.

### Financial impact

If call billing is wired (GAP-0016 fix deployed) before this gap is fixed, users on paid
group calls would be billed for time spent in a silent call with no media. The billing
enforcement would work while the product would be non-functional.

### No external security exploit

This is a missing feature, not a vulnerability. No data is exposed and no privilege is
escalated by the current state.

## 4. Fix Design (Code-Level)

The fix has two separable parts: (A) extract the hook and add mode-selection; (B) implement
WebRTC negotiation inside the hook. Part B is the larger effort; Part A can be delivered
independently as a meaningful step that unblocks the WebRTC work.

### 4.1 Create `frontend/src/hooks/useGroupCall.ts`

```typescript
import * as React from "react";
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import {
  getGroupCall,
  joinGroupCall,
  leaveGroupCall,
  endGroupCall,
  updateGroupCallMedia,
  sendGroupCallSignal,
} from "@/api/endpoints/groupCalls";
import { useRtcPeerConnection } from "@/hooks/useRtcPeerConnection";

export type GroupCallMode = "mesh" | "sfu";

interface UseGroupCallOptions {
  callId: string;
  userId: string;
  onEnded?: () => void;
}

export function useGroupCall({ callId, userId, onEnded }: UseGroupCallOptions) {
  const queryClient = useQueryClient();
  const [mode, setMode] = React.useState<GroupCallMode | null>(null);
  const [iceServers, setIceServers] = React.useState<RTCIceServer[]>([]);
  const [inCall, setInCall] = React.useState(false);

  // Poll call state
  const { data: callData } = useQuery({
    queryKey: ["group-call", callId],
    queryFn: () => getGroupCall(callId),
    refetchInterval: 3000,
    enabled: inCall,
  });

  // Auto-close on ended
  React.useEffect(() => {
    if (callData?.state === "ended") onEnded?.();
  }, [callData?.state, onEnded]);

  // Join and read mode from response
  const joinMut = useMutation({
    mutationFn: () => joinGroupCall(callId),
    onSuccess: (resp) => {
      setInCall(true);
      const resolvedMode: GroupCallMode =
        resp.mode === "sfu" ? "sfu" : "mesh";
      setMode(resolvedMode);
      setIceServers(resp.ice_servers ?? []);
      queryClient.invalidateQueries({ queryKey: ["group-call", callId] });
    },
  });

  const leaveMut = useMutation({
    mutationFn: () => leaveGroupCall(callId),
    onSuccess: () => {
      setInCall(false);
      onEnded?.();
    },
  });

  const endMut = useMutation({
    mutationFn: () => endGroupCall(callId),
    onSuccess: () => onEnded?.(),
  });

  const mediaMut = useMutation({
    mutationFn: (update: { audio?: boolean; video?: boolean; screen?: boolean }) =>
      updateGroupCallMedia(callId, update),
  });

  // WebRTC — wired only when mode is resolved
  // (useRtcPeerConnection already exists at frontend/src/hooks/useRtcPeerConnection.ts)
  const rtc = useRtcPeerConnection({
    enabled: inCall && mode !== null,
    mode: mode ?? "mesh",
    iceServers,
    callId,
    userId,
    participants: callData?.participants ?? [],
    onSignal: (signal) => sendGroupCallSignal(callId, signal),
  });

  return {
    callData,
    inCall,
    mode,
    join: joinMut.mutate,
    leave: leaveMut.mutate,
    end: endMut.mutate,
    updateMedia: mediaMut.mutate,
    localStream: rtc.localStream,
    remoteStreams: rtc.remoteStreams,
    toggleAudio: rtc.toggleAudio,
    toggleVideo: rtc.toggleVideo,
    toggleScreen: rtc.toggleScreen,
    isJoining: joinMut.isPending,
    isLeaving: leaveMut.isPending,
  };
}
```

### 4.2 Update `GroupCallOverlay.tsx` to use the hook

Replace the inline `useQuery`/`useMutation` blocks in both `GroupCallButton` and
`GroupCallOverlay` with calls to `useGroupCall(callId, userId)`. The component becomes a
pure presentation layer; all state management and WebRTC wiring live in the hook.

The key change in `GroupCallButton` (line 98-106) is:

```typescript
// Before (discards join response):
const joinMut = useMutation({
  mutationFn: (callId: string) => joinGroupCall(callId),
  onSuccess: () => { setInCall(true); },
});

// After (routes through hook — mode and iceServers are preserved):
const { join, isJoining } = useGroupCall({ callId: activeCallId!, userId, onEnded: ... });
// call join() where joinMut.mutate() was called
```

### 4.3 `useRtcPeerConnection.ts` integration contract

`frontend/src/hooks/useRtcPeerConnection.ts` already exists. It needs to accept a `mode`
prop to select mesh vs SFU topology:

- `mode === "mesh"`: create one `RTCPeerConnection` per remote participant; use
  `sendGroupCallSignal` to exchange SDP and ICE candidates.
- `mode === "sfu"`: create a single `RTCPeerConnection` to the SFU URL returned in
  `ice_servers`; one upstream track, multiple downstream tracks via simulcast.

This wiring into `useRtcPeerConnection.ts` is a separate, larger effort estimated at 3-5
days and outside the scope of the hook extraction task.

### 4.4 Dev/Prod parity (SECOPS-007)

The group-call backend is identical in dev and prod. `useRtcPeerConnection.ts` uses the
browser's native WebRTC API — no AWS dependency. ICE servers returned by the backend may be
TURN servers hosted on AWS; in dev, the backend returns stub ICE servers (STUN only). No
SECOPS-007 changes are needed for the hook extraction. When the TURN server wiring is added,
the TURN credentials must follow the KMS-encrypt-at-rest pattern specified in SECOPS-007 for
any secret stored in DynamoDB.

### 4.5 Alternatives considered

- **Leave inline logic in place and only add WebRTC**: Risks duplicating the mode-selection
  state that the hook needs to hold. Rejected in favor of a clean extraction first.
- **Single `useGroupCallMedia` hook separate from state management**: Over-engineering;
  `useGroupCall` can export both sets of concerns cleanly.

### Privacy implication of deferring the SFU path

The mode-selection logic is not just an architectural detail — it has a direct user-privacy
consequence. In mesh (peer-to-peer) WebRTC, the ICE candidate exchange reveals each
participant's public IP address to every other participant. Enterprise tenants or users in
sensitive roles (e.g., domestic-violence support, confidential counseling) may require the
SFU path precisely to avoid this IP leakage. Until mode-selection is implemented, the
platform cannot honour any such privacy contract.

The recommended interim mitigation is to force `mode = "sfu"` in the backend
`POST /ui/calls/group/{callId}` create endpoint and ensure the join endpoint always returns
`mode: "sfu"` until the mesh path is confirmed safe for all tenant types. This is a
conservative default that can be relaxed per-tenant once the mode-selection logic exists
on the client.

### Backend schema note

The investigation confirmed that `GroupCallJoinOut` in `frontend/src/api/endpoints/
groupCalls.ts` (TypeScript type definition) includes a `mode` field. However, the actual
backend endpoint for `POST /ui/calls/group/{callId}/join` must be verified to return this
field in its response. If the backend `GroupCallJoinOut` Pydantic model does not include
`mode`, both backend and frontend changes are needed.

A quick grep of `app/routers/` and `app/services/` for `GroupCallJoinOut` or the join
endpoint handler should be performed before implementing the frontend hook to confirm the
`mode` field is already in the response schema. If absent, add it with a default of
`"mesh"` so existing clients continue to work while new clients use the explicit mode.

### Relationship to group call billing

Once `useGroupCall.ts` is extracted and media flows (via GAP-0016-style billing integration),
the group call billing path must be verified separately. A group call may charge per-minute
based on the number of connected participants (different rate model from 1-to-1 calls). The
heartbeat hook for group calls may need to receive a `participant_count` parameter so the
backend can compute the correct billing amount. This is an additional design decision not
captured in CALL-012.

**Effort**: M for hook extraction and mode selection (~1-2 days). L for full WebRTC
signaling (3-5 days additional).
