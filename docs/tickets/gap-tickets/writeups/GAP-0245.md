## 2. Current-State Investigation (root cause)

### 2.1 File present, fully implemented

`frontend/src/pages/admin/KycMetricsDashboard.tsx` confirmed at 215 lines.

**Data fetching** (lines 58-62):
```typescript
const metricsQuery = useQuery({
  queryKey: ["kyc-metrics"],
  queryFn: () => fetchKycMetrics(),
  staleTime: 60_000,
});
```

`staleTime: 60_000` means the metrics are cached for 60 seconds; the dashboard does not
auto-refresh more frequently than once per minute. This is appropriate for a compliance
dashboard.

**Funnel bar chart** (lines 120-143): Iterates over `STATUS_LABELS` record and renders a
labeled progress bar per status. The bar width is `(count / maxFunnelCount) * 100%` — a
relative scale where the highest-count status fills 100%. `data-testid={`funnel-${status}`}`
on the count span enables targeted Playwright assertions.

**Approval rate card** (lines 145-159):
```typescript
const totalDecided =
  (metrics?.funnel_counts?.approved ?? 0) + (metrics?.funnel_counts?.rejected ?? 0);
const approvalRate =
  totalDecided > 0
    ? ((metrics?.funnel_counts?.approved ?? 0) / totalDecided * 100).toFixed(1)
    : "--";
```

Edge case when no cases have been decided: shows `"--"` rather than `NaN%` or `"0%"`.

**Latency cards** (lines 163-187): Iterates over `["p50", "p90", "p99"]`. The `latencyColor`
function at line 26 uses 24h (86400s) and 48h (172800s) thresholds for green/yellow/red.
`data-testid={`latency-${pLabel}`}` on each value.

**StaleQueueAlert** (lines 98-112): Orange card with `AlertTriangle` icon.
`data-testid="stale-alert"` on the text for Playwright targeting.

**Ticket sync counters section** (lines 190-210): Conditionally rendered only when
`Object.keys(metrics.ticket_sync_counters ?? {}).length > 0`. This section would show a
dead-letter count badge if the KYC→ticket sync has failures. In a clean dev environment this
section is never visible.

## 3. Impact / Exploit / Blast Radius

### 3.1 Current state (page fully present)

Compliance leads and root admins can navigate to `/admin/kyc/metrics` to see:
- Funnel counts by status (draft, submitted, under_review, needs_more_info, approved,
  rejected, expired).
- Approval rate as a percentage of decided cases.
- Review latency at p50/p90/p99 with SLA coloring.
- Stale queue count alert when cases are overdue.

There is no functional impact from this gap ticket.

### 3.2 Residual gap: no auto-refresh / live updates

`staleTime: 60_000` means the page shows data up to 60 seconds stale. There is no WebSocket
or SSE feed for real-time metric updates. For a high-volume compliance operation this is
acceptable, but a manual "Refresh" button or a shorter `staleTime` (e.g., 30s) would improve
the SLA monitoring experience.

### 3.3 Residual gap: no date-range filter for historical funnel

The metrics API presumably returns aggregate all-time counts. Compliance reports typically
need date-windowed funnel data (e.g., "approval rate this week"). A date-range picker is
absent. This is a feature gap, not a blocking one for the current implementation.

### 3.4 No alerting integration

The stale-queue alert is informational only — it shows a count but does not trigger a
notification to on-call staff. This means a reviewer must actively visit the dashboard to
notice SLA breaches.

## 4. Fix Design (code-level)

### 4.1 No structural fix required

The dashboard is implemented. The following improvements are recommended:

### 4.2 Add a manual refresh button and `refetchInterval`

```typescript
const metricsQuery = useQuery({
  queryKey: ["kyc-metrics"],
  queryFn: () => fetchKycMetrics(),
  staleTime: 60_000,
  refetchInterval: 120_000,   // auto-refresh every 2 minutes
});
```

Add a "Refresh" button to the header:
```tsx
<Button
  variant="outline"
  size="sm"
  onClick={() => metricsQuery.refetch()}
  disabled={metricsQuery.isFetching}
>
  {metricsQuery.isFetching ? "Refreshing..." : "Refresh"}
</Button>
```

### 4.3 Add date-range filtering

Add two `<Input type="date">` controls for `from_date` and `to_date`. Pass these as query
parameters to `fetchKycMetrics`:

```typescript
export function fetchKycMetrics(
  params?: { from_ts?: number; to_ts?: number }
): Promise<{ metrics: KycMetrics }> {
  return apiClient.get("/ui/admin/kyc/metrics", { params }).then((r) => r.data);
}
```

The backend `GET /ui/admin/kyc/metrics` endpoint must accept and apply these optional
timestamp filters.

### 4.4 Add SLA breach notification

When `metrics.stale_queue_count > 0` on mount, fire a browser notification (if permission
granted) and/or log to the admin alert system:

```typescript
useEffect(() => {
  if (metrics && metrics.stale_queue_count > 0) {
    // Optional: browser notification
    if (Notification.permission === "granted") {
      new Notification(`KYC SLA breach: ${metrics.stale_queue_count} stale cases`);
    }
  }
}, [metrics?.stale_queue_count]);
```

### 4.5 Dev/Prod parity (SECOPS-007)

`fetchKycMetrics` calls `GET /ui/admin/kyc/metrics` which is protected by
`Depends(require_admin_session)`. In dev mode the backend aggregates from local DynamoDB. In
production it aggregates from AWS DynamoDB. The frontend component is environment-agnostic —
it renders whatever the API returns. No client-side mock logic is needed. SECOPS-007 is
satisfied.
