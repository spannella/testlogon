# GAP-0262: Five Template/Witness Router Endpoints Missing — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No investigation
> doc exists for this gap; code verification was performed as part of this write-up.

## 1. Summary & Classification

**Gap**: `app/routers/kyc_cases.py` is missing five HTTP endpoints that expose the
KYC signature template workflow to clients. The endpoints were specified in KYC-007 but
were never added. The underlying service (`app/services/kyc_signature_templates.py`) is
also absent (GAP-0261); this gap is the router-layer half of the same omission.

**Verdict**: Confirmed. The router file (`app/routers/kyc_cases.py`, 1711 lines) was read
in full. A search for the five planned route paths — `/templates`, `/signature-templates/create-packets`,
`/signature-templates/status`, `/admin/cases/{case_id}/add-witness`,
`/signature-templates/version-check` — returns no matches. A grep for
`list_kyc_signature_templates`, `create_signature_packets_from_templates`,
`get_signature_templates_status`, `admin_add_witness_to_packet`, and
`check_template_version_migration` across the entire `app/` directory returns no results.

- **Severity**: HIGH
- **Source ticket**: KYC-007 / GAP-0262
- **Status**: Open
- **Owning area**: KYC / Document Signing (router layer)
- **Impact**: Clients have no way to initiate, inspect, or manage the template-based
  signature workflow. The feature is entirely inaccessible via HTTP.
- **Dependencies**: GAP-0261 (service), GAP-0263 (notary_stamp field type), GAP-0264
  (case data model). This ticket is the final integration point once all service-layer
  gaps are resolved. Also depends on `KycAddWitnessRequest` and `KycTemplateStatusOut`
  models being added to `app/contracts/kyc_cases_contract.py`.

## 2. Current-State Investigation (root cause)

### 2.1 Existing router structure

`app/routers/kyc_cases.py` currently exposes the following signature-related endpoints:

| Method | Path | Line |
|--------|------|------|
| POST | `/{case_id}/signature-packet` | 1285 |
| GET  | `/{case_id}/signature-status` | 1347 |

Both endpoints operate on a single `packet_id` stored in `case["signature"]["packet_id"]`.

### 2.2 What is absent

The KYC-007 spec (`docs/tickets/KYC-007-enhanced-document-signing.md`, section 3.5)
specifies five additional endpoints:

| Method | Path | Purpose |
|--------|------|---------|
| GET    | `/templates` | List available KYC templates, filter by `intake_profile` |
| POST   | `/{case_id}/signature-templates/create-packets` | Create one packet per required template |
| GET    | `/{case_id}/signature-templates/status` | Completion status for each template packet |
| POST   | `/admin/cases/{case_id}/add-witness` | Add admin as witness co-signer (high-risk only) |
| GET    | `/{case_id}/signature-templates/version-check` | Check for stale template versions |

None of these paths exist. The `router` object in `kyc_cases.py` does not register them.

### 2.3 Missing request/response models

`app/contracts/kyc_cases_contract.py` does not define `KycAddWitnessRequest` or
`KycTemplateStatusOut`. These are needed by the witness endpoint and the status endpoint
respectively. Their absence means the router endpoints cannot be added in isolation without
first adding the contracts.

### 2.4 Runtime behaviour

A client calling any of the five missing paths receives a `404 Not Found` from FastAPI
because the routes are simply not registered. There is no error in application logs —
the absence is entirely transparent to the server.

## 3. Impact / Exploit / Blast Radius

### 3.1 Functional gap

The entire template-based KYC consent workflow is inaccessible to frontend clients. No user
can initiate the creation of AML, PEP, or tax compliance packets from the UI. No admin can
add a witness co-signer. No client can query whether template versions need migration.

### 3.2 Compliance exposure

Because the five template packets are never created, the KYC submission flow proceeds with
only the legacy single-packet path. As described in GAP-0261, this means that enhanced and
high-risk cases are approved without the required five declarations being signed. The
reviewer queue shows `signature_completed: true` (single-packet gate passes) while the
regulatory requirement for multiple separate declarations is silently unmet.

### 3.3 Admin / witness gap

The `add-witness` endpoint specifically enables a second admin to co-sign critical-risk
cases. Without it, the witness workflow specified in KYC-007 is entirely impossible to
invoke. High-risk cases that require dual-reviewer sign-off have no mechanism to record
the second reviewer's attestation in the signed PDF.

### 3.4 Version migration gap

The `version-check` endpoint is the only way for a client to know that terms have been
updated and re-signing is required. Without it, the frontend cannot show the "Terms
updated — re-signing required" banner. Cases submitted before a terms update remain in
the queue with stale declarations indefinitely.

## 4. Fix Design (code-level)

### 4.1 New Pydantic models in `app/contracts/kyc_cases_contract.py`

```python
class KycAddWitnessRequest(BaseModel):
    expected_version: int = Field(..., ge=1)
    packet_id: str = Field(..., min_length=1)
    witness_sub: str | None = Field(
        default=None,
        description="Admin sub to add as witness. If None, uses calling user.",
    )

class KycTemplateStatusItem(BaseModel):
    template_type: str
    display_name: str
    version: str
    packet_id: str | None = None
    packet_status: str | None = None  # draft | completed
    signed_by_applicant: bool = False
    signed_by_witness: bool | None = None  # None if no witness required
    needs_version_migration: bool = False

class KycTemplateStatusEnvelope(BaseModel):
    templates: list[KycTemplateStatusItem]
    version_migration_required: bool = False
```

### 4.2 Five new endpoints in `app/routers/kyc_cases.py`

All five are added after the existing `signature-status` endpoint (currently at line 1347).
Auth patterns follow the existing conventions in the file.

```python
# ---- Import (add alongside existing signature_packet_store imports) ----
from app.services.kyc_signature_templates import KycSignatureTemplateService
_TEMPLATE_SVC = KycSignatureTemplateService()


@router.get("/templates")
def list_kyc_signature_templates(
    intake_profile: str | None = Query(default=None),
    _ctx: dict = Depends(require_ui_session),
    user: AuthenticatedUser = Depends(get_authenticated_user),
):
    """List available KYC signature templates, filtered by intake_profile."""
    if intake_profile:
        templates = _TEMPLATE_SVC.get_required_templates(
            intake_profile=intake_profile
        )
    else:
        templates = [
            {"template_type": k, **v}
            for k, v in _TEMPLATE_SVC.KYC_TEMPLATE_TYPES.items()  # noqa: SLF001
        ]
    return {"templates": templates}


@router.post("/{case_id}/signature-templates/create-packets",
             response_model=KycCaseEnvelope)
def create_signature_packets_from_templates(
    case_id: str,
    body: KycLinkSignaturePacketRequest,
    request: Request,
    _ctx: dict = Depends(require_ui_session),
    user: AuthenticatedUser = Depends(get_authenticated_user),
):
    """Create signature packets for all required templates; auto-populates fields."""
    case = STORE.get_case(case_id)
    if not case:
        _raise_kyc_error("kyc_case_not_found", details={"kyc_case_id": case_id})
    if case.get("user_sub") != user.sub:
        _raise_kyc_error("kyc_access_forbidden", details={"kyc_case_id": case_id})

    intake_profile = str(
        (case.get("intake_profile") or "standard")
    ).lower()
    packets = _TEMPLATE_SVC.create_packets_for_case(
        case_id=case_id,
        user_sub=user.sub,
        intake_profile=intake_profile,
        source_pdf_path=body.source_path,
    )
    # Merge into case["signature"]["template_packets"] via list_append pattern
    signature = dict(case.get("signature") or {})
    existing = list(signature.get("template_packets") or [])
    existing_types = {p["template_type"] for p in existing}
    to_add = [p for p in packets if p["template_type"] not in existing_types]
    signature["template_packets"] = existing + to_add

    try:
        updated = STORE.update_case_links(
            case_id=case_id,
            owner_sub=user.sub,
            expected_version=body.expected_version,
            signature=signature,
        )
    except KycCaseConflictError:
        _raise_kyc_error("kyc_case_update_conflict",
                         details={"kyc_case_id": case_id})
    if not updated:
        _raise_kyc_error("kyc_case_not_found", details={"kyc_case_id": case_id})
    audit_event("kyc_template_packets_created", user.sub, request,
                outcome="success", kyc_case_id=case_id, count=len(to_add))
    return _wrap_case(updated)


@router.get("/{case_id}/signature-templates/status")
def get_signature_templates_status(
    case_id: str,
    request: Request,
    _ctx: dict = Depends(require_ui_session),
    user: AuthenticatedUser = Depends(get_authenticated_user),
):
    """Return completion status for each required template packet."""
    case = STORE.get_case(case_id)
    if not case:
        _raise_kyc_error("kyc_case_not_found", details={"kyc_case_id": case_id})
    if case.get("user_sub") != user.sub:
        _raise_kyc_error("kyc_access_forbidden", details={"kyc_case_id": case_id})

    intake_profile = str(
        (case.get("intake_profile") or "standard")
    ).lower()
    required = _TEMPLATE_SVC.get_required_templates(
        intake_profile=intake_profile
    )
    tp_map = {
        p["template_type"]: p
        for p in list((case.get("signature") or {}).get("template_packets") or [])
    }
    stale = {s["template_type"]
             for s in _TEMPLATE_SVC.check_version_migration(case=case)}
    items = []
    for tmpl in required:
        tt = tmpl["template_type"]
        linked = tp_map.get(tt) or {}
        packet_id = linked.get("packet_id")
        packet = get_packet(packet_id) if packet_id else None
        items.append({
            "template_type": tt,
            "display_name": tmpl["display_name"],
            "version": tmpl["version"],
            "packet_id": packet_id,
            "packet_status": (packet or {}).get("status"),
            "signed_by_applicant": bool(
                packet and str(packet.get("status")) == "completed"
            ),
            "needs_version_migration": tt in stale,
        })
    return {
        "templates": items,
        "version_migration_required": bool(stale),
    }


@router.post("/admin/cases/{case_id}/add-witness",
             response_model=KycCaseEnvelope)
def admin_add_witness_to_packet(
    case_id: str,
    body: KycAddWitnessRequest,
    request: Request,
    _ctx: dict = Depends(require_ui_session),
    user: AuthenticatedUser = Depends(get_authenticated_user),
):
    """Add admin as witness co-signer. High-risk cases only."""
    if normalize_role(user.role) not in {Role.ADMIN, Role.ROOT}:
        _raise_kyc_error("kyc_admin_role_required")
    case = STORE.get_case(case_id)
    if not case:
        _raise_kyc_error("kyc_case_not_found", details={"kyc_case_id": case_id})
    if str((case.get("intake_profile") or "")).lower() != "high_risk":
        _raise_kyc_error("kyc_invalid_request",
                         details={"reason": "witness_only_for_high_risk"})
    witness_sub = body.witness_sub or user.sub
    _TEMPLATE_SVC.add_witness_signer(
        packet_id=body.packet_id,
        witness_sub=witness_sub,
    )
    audit_event("kyc_witness_added", user.sub, request, outcome="success",
                kyc_case_id=case_id, witness_sub=witness_sub,
                packet_id=body.packet_id)
    return _wrap_case(STORE.get_case(case_id))


@router.get("/{case_id}/signature-templates/version-check")
def check_template_version_migration(
    case_id: str,
    request: Request,
    _ctx: dict = Depends(require_ui_session),
    user: AuthenticatedUser = Depends(get_authenticated_user),
):
    """Return templates needing re-signing due to version update."""
    case = STORE.get_case(case_id)
    if not case:
        _raise_kyc_error("kyc_case_not_found", details={"kyc_case_id": case_id})
    if case.get("user_sub") != user.sub:
        _raise_kyc_error("kyc_access_forbidden", details={"kyc_case_id": case_id})
    stale = _TEMPLATE_SVC.check_version_migration(case=case)
    audit_event("kyc_template_version_check", user.sub, request,
                outcome="success", kyc_case_id=case_id, stale_count=len(stale))
    return {"stale_templates": stale, "migration_required": bool(stale)}
```

### 4.3 Ordering of route declarations

FastAPI matches routes in registration order. The new `/templates` path must be declared
**before** `/{case_id}` to avoid the literal string `"templates"` being captured as a
`case_id` path parameter. The same rule applies to `/admin/cases/{case_id}/add-witness`
which sits inside the `/admin/cases/...` prefix already used by existing admin endpoints —
the existing ordering for admin sub-routes already handles this correctly.

### 4.4 Dev/Prod parity (SECOPS-007)

All five endpoints rely on `require_ui_session` (cookie + CSRF or Bearer), consistent
with every other endpoint in the file. The underlying `_TEMPLATE_SVC` methods are
DynamoDB-backed via `T.users` and `T.signature_packet_fields`, both moto-backed in dev.
No AWS-specific divergence.
