# GAP-0020: TIN/SSN Collection and KMS-Encrypted Storage Absent — Remediation Write-up

> ~5 pages. Fix-oriented. Cites real file:line. Built on the verified investigation at
> `docs/tickets/gap-tickets/investigations/GAP-0020.md`.

## 1. Summary & Classification

**Plain-English statement**: The platform's 1099-NEC PDF generator (`app/services/
tax_form_1099.py`) uses a hardcoded placeholder payer TIN (`"0000"`) and does not collect
or store recipient TINs (SSNs / EINs) at all. No W-9 form submission endpoint or service
function exists. Every generated 1099-NEC form is IRS non-compliant because both the payer
and recipient TIN fields contain fabricated values.

- **Severity**: CRIT
- **Source ticket**: FIN-008
- **Status**: Open
- **Owning area**: Backend / Tax / Compliance / Security
- **Verdict**: **Confirmed** — `app/services/tax_form_1099.py:54-55` hardcodes payer TIN;
  no `submit_tax_info()` function, no `tin_encrypted` field, no W-9 endpoint exist anywhere
  in the codebase.
- **One-line impact**: All issued 1099-NEC forms are IRS non-compliant; the platform has no
  legal basis for issuing them without a certified TIN on file.
- **Related tickets**: GAP-0019 (consumer tax documents use wrong ledger direction),
  SEC-022 (credential exposure — cross-referenced in ticket, but confirmed non-overlapping),
  FIN-008 (source feature ticket).

## 2. Current-State Investigation (Root Cause)

### Hardcoded placeholder TIN

`app/services/tax_form_1099.py:54-55`:

```python
_PAYER_NAME = "Platform Payments, Inc."
_PAYER_TIN_LAST4 = "0000"
```

This string is embedded in every generated 1099 PDF at line 173:

```python
f"  TIN          : ***-**-{_PAYER_TIN_LAST4}",
```

The rendered output in every PDF is:

```
  TIN          : ***-**-0000
```

IRS Form 1099-NEC requires:
1. **Box 3**: Payer's TIN — the platform's own EIN (e.g., `12-3456789`). Currently `0000`.
2. **Box 4**: Recipient's TIN — the creator's SSN or EIN. Currently completely absent.

### No W-9 collection path

A comprehensive code search confirms the absence:

- `grep -rn "submit_tax_info" app/` → zero results
- `grep -rn "tin_encrypted" app/` → zero results
- `grep -rn "POST.*w9\|w9.*POST" app/routers/` → zero results
- `grep -rn "kms_encrypt" app/services/tax_form_1099.py` → zero results
- `find app/routers/ -name "*w9*"` → empty

`app/routers/tax_form_1099.py` exposes five endpoints:
1. `GET /ui/tax-forms/` — list forms
2. `GET /ui/tax-forms/{form_id}` — get single form
3. `POST /ui/tax-forms/generate` — trigger generation
4. `GET /ui/tax-forms/{form_id}/download` — download PDF
5. `POST /ui/tax-forms/admin/batch` — admin batch generation

None of these accept W-9 data. The `POST /ui/tax/w9` endpoint specified in FIN-008 §3.2
does not exist.

### KMS infrastructure exists but is not used here

`app/core/crypto.py:16,22` exports `kms_encrypt(plaintext: str) -> str` and
`kms_decrypt(ct_b64: str) -> bytes`. These are used in other services (e.g., API key
storage) but not imported by `tax_form_1099.py`. In dev mode, the mock KMS server at
`scripts/mock_kms_server.py` (port 7999) handles these calls transparently.

### How the gap manifests

When `generate_tax_document` is called for a creator who has earned over the $600 threshold:

1. A 1099-NEC PDF is generated with `TIN: ***-**-0000` in the payer field.
2. No recipient TIN line exists in the PDF at all.
3. The PDF is stored in S3 and the form record is written to DynamoDB.
4. If an admin triggers a batch generation (`POST /ui/tax-forms/admin/batch`), thousands of
   non-compliant PDFs are generated and stored.

The platform has no way to know any creator's SSN or EIN because the collection step was
never built.

## 3. Impact / Exploit / Blast Radius

### IRS regulatory penalties

IRS Publication 1179 and the penalty schedule under IRC §6721 impose the following for
incorrect or missing TIN on information returns:

| Violation | Penalty (2025) |
|---|---|
| Incorrect TIN filed | $60–$310 per form (tier based on correction timing) |
| Intentional disregard | $630 per form (no cap) |
| Failure to furnish to recipient | $60–$310 per form |

With even 100 creators above the $600 threshold, the platform faces $6,000–$31,000 in
penalties for a single tax year. At scale (10,000 creators), exposure exceeds $3 million.

### Missing recipient TIN triggers backup withholding

Under IRC §3406, when a payer cannot obtain a correct TIN from a payee, the payer is
required to withhold 24% of payments ("backup withholding") and remit to the IRS. The
current state — generating 1099s with no TIN instead of enforcing withholding — violates
both the TIN collection requirement and the backup withholding obligation.

### No direct security exploit from the current state

There is no existing `tin_encrypted` field that could be leaked. The risk is exclusively
regulatory and financial. However, when TIN storage is implemented, it must follow KMS
encryption principles to avoid a future SEC-022-class leak (returning ciphertext in API
responses).

### SEC-022 orthogonality

SEC-022 concerns *existing* encrypted data leaking back to clients (OAuth tokens, S3 keys).
GAP-0020 concerns *absent* encryption. They are orthogonal: fixing GAP-0020 introduces new
KMS-encrypted data that must comply with SEC-022's principle of never returning ciphertext
in API responses.

## 4. Fix Design (Code-Level)

### 4.1 Add `tax_info` DynamoDB table

`scripts/local-ddb-init.py` — add a new `TableDef`:

```python
TableDef("tax_info", "pk", "sk"),
```

Storage schema:
- `pk = USER#{user_sub}`
- `sk = "TAX_INFO"`
- Fields: `legal_name`, `tin_encrypted` (KMS ciphertext), `tin_last4` (4-char suffix for
  display), `tin_type` (`"ssn"` | `"ein"`), `address_line1`, `city`, `state`, `zip_code`,
  `certified` (bool), `certified_at` (Unix timestamp), `updated_at`.

The table does not need GSIs for the initial implementation (lookups are always by
`USER#{user_sub}`).

### 4.2 Add Pydantic model `W9SubmitIn` to `app/models.py`

```python
class W9SubmitIn(BaseModel):
    legal_name: str = Field(..., min_length=1, max_length=200)
    tin: str = Field(
        ...,
        description="Raw SSN (XXX-XX-XXXX) or EIN (XX-XXXXXXX). Never stored in plaintext.",
        min_length=9, max_length=11,
    )
    tin_type: Literal["ssn", "ein"]
    address_line1: str = Field(..., min_length=1, max_length=200)
    city: str = Field(..., min_length=1, max_length=100)
    state: str = Field(..., min_length=2, max_length=2)
    zip_code: str = Field(..., min_length=5, max_length=10)
    certified: bool  # user certifies accuracy under penalty of perjury
```

The `tin` field must be validated by format (digits + optional hyphens) before KMS encryption.

### 4.3 Create `app/services/tax_info_w9.py`

```python
"""W-9 / Tax-info collection service (FIN-008).

TINs (SSNs and EINs) are KMS-encrypted before storage. The raw TIN is NEVER
logged, returned in API responses, or stored in plaintext.
"""
import logging
from app.core.crypto import kms_encrypt, kms_decrypt
from app.core.tables import T
from app.core.time import now_ts

logger = logging.getLogger(__name__)

def submit_tax_info(
    *,
    user_sub: str,
    legal_name: str,
    tin: str,
    tin_type: str,
    address_line1: str,
    city: str,
    state: str,
    zip_code: str,
    certified: bool,
) -> dict:
    """Store KMS-encrypted TIN and W-9 data for a user.

    Returns a safe dict with tin_last4 only — never tin_encrypted.
    """
    tin_digits = tin.replace("-", "").replace(" ", "")
    if not tin_digits.isdigit() or len(tin_digits) not in (9,):
        raise ValueError("invalid_tin: TIN must be 9 digits (SSN or EIN).")

    tin_encrypted = kms_encrypt(tin_digits)

    item = {
        "pk": f"USER#{user_sub}",
        "sk": "TAX_INFO",
        "legal_name": legal_name,
        "tin_encrypted": tin_encrypted,      # ciphertext only
        "tin_last4": tin_digits[-4:],        # display suffix
        "tin_type": tin_type,
        "address_line1": address_line1,
        "city": city,
        "state": state,
        "zip_code": zip_code,
        "certified": bool(certified),
        "certified_at": now_ts() if certified else None,
        "updated_at": now_ts(),
    }
    T.tax_info.put_item(Item=item)

    logger.info(
        "tax_info_submitted",
        extra={"user_sub": user_sub, "tin_type": tin_type, "certified": certified},
        # NOTE: raw TIN is never logged
    )
    # Return dict without tin_encrypted
    return {k: v for k, v in item.items() if k != "tin_encrypted"}


def get_tax_info(user_sub: str) -> dict | None:
    """Retrieve stored tax info (without decrypting TIN — use get_decrypted_tin for that)."""
    resp = T.tax_info.get_item(Key={"pk": f"USER#{user_sub}", "sk": "TAX_INFO"})
    item = resp.get("Item")
    if not item:
        return None
    # Never expose tin_encrypted to callers
    return {k: v for k, v in item.items() if k != "tin_encrypted"}


def get_decrypted_tin(user_sub: str) -> str | None:
    """Decrypt and return the raw TIN for PDF generation. Audit log required at call site."""
    resp = T.tax_info.get_item(Key={"pk": f"USER#{user_sub}", "sk": "TAX_INFO"})
    item = resp.get("Item")
    if not item or not item.get("tin_encrypted"):
        return None
    return kms_decrypt(item["tin_encrypted"]).decode()
```

### 4.4 Add `POST /ui/tax-forms/w9` endpoint in `app/routers/tax_form_1099.py`

```python
from app.services import tax_info_w9
from app.models import W9SubmitIn

@tax_form_1099_router.post("/w9", summary="Submit W-9 tax information")
def submit_w9(
    body: W9SubmitIn,
    session=Depends(require_ui_session),
):
    """Collect and KMS-encrypt the creator's TIN. Required before 1099 generation."""
    try:
        result = tax_info_w9.submit_tax_info(
            user_sub=session["user_sub"],
            **body.model_dump(),
        )
    except ValueError as exc:
        raise HTTPException(422, detail={"code": str(exc)})
    return result
```

### 4.5 Update `_render_1099_pdf` to use real TINs

In `app/services/tax_form_1099.py`, replace the hardcoded payer TIN and add the recipient
TIN:

```python
# Before (line 55):
_PAYER_TIN_LAST4 = "0000"

# After — read from settings:
def _payer_tin_last4() -> str:
    ein = getattr(S, "platform_ein", "") or ""
    digits = ein.replace("-", "")
    return digits[-4:] if len(digits) >= 4 else "0000"
```

In the PDF render function:

```python
from app.services.tax_info_w9 import get_decrypted_tin, get_tax_info

def _render_1099_pdf(*, user_sub: str, form: dict, ...) -> bytes:
    # Recipient TIN
    tax_info = get_tax_info(user_sub)
    if tax_info:
        recipient_tin_display = f"***-**-{tax_info['tin_last4']}"
        legal_name = tax_info.get("legal_name", form.get("legal_name", user_sub))
    else:
        recipient_tin_display = "TIN NOT COLLECTED — FORM INVALID"
        legal_name = form.get("legal_name", user_sub)

    lines = [
        "FORM 1099-NEC",
        "-" * 60,
        f"Payer: {_PAYER_NAME}",
        f"Payer TIN: ***-**-{_payer_tin_last4()}",
        f"Recipient: {legal_name}",
        f"Recipient TIN: {recipient_tin_display}",
        ...
    ]
    # Audit event
    logger.info("tin_viewed", extra={"user_sub": user_sub, "context": "1099_generation"})
    ...
```

### 4.7 Dev/Prod parity (SECOPS-007)

In dev mode (`S.dev_mode = True`), `kms_encrypt` uses the mock KMS server at port 7999
(`scripts/mock_kms_server.py`). In prod, it uses real AWS KMS via `AWS_KMS_KEY_ID`. The code
path is identical; the only difference is the KMS endpoint resolved by the boto3 client.
This satisfies SECOPS-007's requirement that the same code path is used in both environments.

Per SECOPS-007 and the SEC-022 principles:
- `tin_encrypted` must never appear in any API response (enforced by the `{k:v ... if k !=
  "tin_encrypted"}` filter in `get_tax_info`).
- `tin_last4` is safe to return and display.
- `get_decrypted_tin` must only be called from PDF generation paths, never from HTTP
  response handlers.
- `PLATFORM_EIN` must not be logged.

### Security hardening (SECOPS-007 checklist for this change)

- `tin_encrypted` ciphertext: never returned in any API response (enforced at service layer).
- `tin` plaintext: never logged (logging uses `tin_type` and `certified` only).
- `PLATFORM_EIN`: present in `.env.local.example` as a dev placeholder; populated via
  prod secrets manager (not checked into source control).
- Mock KMS in dev: `scripts/mock_kms_server.py` runs at port 7999; `kms_encrypt` routes
  to it when `S.dev_mode = True`. Same code path as prod.
- Real AWS KMS in prod: `AWS_KMS_KEY_ID` env var; boto3 client resolves to real KMS.
