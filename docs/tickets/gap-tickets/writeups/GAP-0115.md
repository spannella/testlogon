# GAP-0115: SSE event stream lacks viewer access check (BCAST-004) — Remediation Write-up

## 1. Summary & Classification

**Bug statement**: The broadcast SSE endpoint `GET /ui/broadcast/sessions/{session_id}/stream`
at `app/routers/broadcast.py:717` subscribes any authenticated user to the real-time event queue
of a broadcast session — viewer-count changes, health snapshots, ad-break signals — without
checking whether the caller is authorised to view that session. This is the same handler affected
by GAP-0112 (raised from BCAST-002), now identified independently from the BCAST-004 (viewer
count / health) feature angle.

- **Severity**: HIGH (SEC-010 IDOR)
- **Source ticket**: BCAST-004 (second-pass as-built review)
- **GAP ID**: GAP-0115
- **Owning area**: Broadcast router — SSE event stream (viewer count and health data)
- **Status**: Open
- **Effort**: S

**Claim verdict**: Confirmed. The code at `app/routers/broadcast.py:717-737` (`broadcast_event_stream_route`)
discards `ctx` with `_ = ctx` and calls `broadcast_sse_subscribe(session_id)` unconditionally.
No `check_viewer_access` call is present between the 404-guard and the queue subscription.

**Relationship to GAP-0112**: GAP-0112 and GAP-0115 describe the **same vulnerable handler** from
two different source ticket perspectives (BCAST-002: viewer/player feature vs BCAST-004:
viewer-count/health feature). The root cause is identical — the single `_ = ctx` line at 720.
Both tickets require the same code change. This write-up preserves the BCAST-004 perspective and
analysis to document the health-data and ad-break leakage angle that was not emphasised in
GAP-0112.

**Related tickets**: BCAST-004, GAP-0112 (duplicate gap, BCAST-002 angle), GAP-0113, GAP-0114,
GAP-0111, SECOPS-007.

## 2. Current-State Investigation (root cause)

### The handler

`app/routers/broadcast.py`, lines 714–737:

```python
# ─── SSE Stream Endpoint ────────────────────────────────────────────

@router.get("/sessions/{session_id}/stream")
async def broadcast_event_stream_route(session_id: str, ctx: dict = Depends(_ctx)):
    """SSE stream for real-time broadcast events (viewer count, health updates)."""
    _ = ctx                           # line 720 — caller identity discarded
    _ = get_session(session_id)       # line 721 — 404 only, no access check
    q = broadcast_sse_subscribe(session_id)

    async def gen():
        try:
            yield "event: hello\ndata: {}\n\n"
            while True:
                try:
                    item = await asyncio.wait_for(q.get(), timeout=15.0)
                    event_type = item.pop("_type", "update")
                    yield f"event: {event_type}\ndata: {json.dumps(item, ...)}\n\n"
                except asyncio.TimeoutError:
                    yield ": ping\n\n"
        finally:
            broadcast_sse_unsubscribe(session_id, q)

    return StreamingResponse(gen(), media_type="text/event-stream")
```

The pattern is identical to the chat stream gap (GAP-0113): `ctx` is captured by FastAPI's
dependency injection (ensuring the caller is authenticated), but the resulting identity dict
is silently discarded. There is no call to `check_viewer_access` before
`broadcast_sse_subscribe`.

### What the SSE queue carries in the BCAST-004 context

The SSE queue (`app/services/broadcast_sse.py`) is populated by multiple producers:

- **Viewer join/leave events** (`register_viewer`, `unregister_viewer`): emit `viewer_count`
  update events. These carry the real-time audience size of the session.
- **Health snapshots** (`store_health_snapshot`): emit `health` events with `bitrate_kbps`,
  `dropped_frames_pct`, `rtt_ms`, `resolution`, `fps`, `connection_quality`, `source`. These
  are populated by the broadcaster's client reporting endpoint
  (`POST /sessions/{session_id}/health`, line 658). In production, a CloudWatch-backed health
  collector would push them automatically.
- **Ad-break events**: `ad_break_start` / `ad_break_end` signals carrying `duration_seconds`,
  `break_type`, `slot_count`, `ad_unit_ids`. These reveal the advertising schedule of the
  broadcast.
- **Session lifecycle events**: `session_end`, `session_start`, `broadcast_error`.

### Why the gap is distinct from GAP-0112

GAP-0112 was raised from the BCAST-002 (viewer player) angle, focusing on the privacy implication
of subscribing to a private broadcast's event stream. GAP-0115 is raised from the BCAST-004
(viewer count and health) angle and highlights the health metric and ad-break leakage. The
operational and business-intelligence value of health + ad data is different from the viewer count
data and justifies the separate analysis.

### The health report endpoint (additional BCAST-004 gap noted)

The BCAST-004 gap list also notes that `POST /sessions/{session_id}/health` at line 658 has no
broadcaster ownership check. Any authenticated user can POST fabricated health metrics to any
session. This is a separate medium-severity gap (not covered in this ticket's fix scope) but
interacts with GAP-0115: an attacker can both pollute the health data stream and observe the
effects in real time via the unprotected SSE endpoint.

## 3. Impact / Exploit / Blast Radius

### Concrete exploit: operational intelligence gathering

**Scenario A — Competitive intelligence via viewer counts**:
A competing streaming platform scrapes `?status=live` (GAP-0111) to enumerate live session IDs,
then connects to each session's SSE stream. They receive continuous viewer-count updates that
quantify the real-time audience of each creator — data normally visible only to the creator and
the platform operator.

**Scenario B — Ad intelligence**:
A DSP (demand-side platform) or ad-tech competitor connects to the SSE stream and collects
`ad_break_start` events. These carry `duration_seconds`, `slot_count`, and `ad_unit_ids`,
revealing the session's advertising inventory, break frequency, and campaign identifiers. This
data has direct commercial value and is confidential between the platform and its ad partners.

**Scenario C — Health data poisoning with real-time observation**:
An attacker sends fabricated health metrics via the unprotected health-report endpoint
(POST /health, BCAST-004 medium gap) and then subscribes to the SSE stream to confirm the
poisoned data is being delivered to the creator's dashboard. This creates a feedback loop for
targeted interference with the creator's broadcast quality indicators.

**Scenario D — Session monitoring for private creators**:
A stalker or bad actor monitors the SSE stream of a private creator's session to know exactly
when the creator goes live, how many people are watching, and when the session ends — without
being invited to the session.

### Affected scope

- All sessions regardless of `visibility` setting, though private sessions are the highest
  concern.
- Viewer-count, health, and ad data for every session that has active SSE subscribers.

## 4. Fix Design (code-level)

### The fix is identical to GAP-0112

Both GAP-0112 and GAP-0115 require the same code change to `broadcast_event_stream_route`.
The fix is documented in full in the GAP-0112 write-up and is reproduced here for completeness.

**Change to `app/routers/broadcast.py`, `broadcast_event_stream_route` (line 717)**:

```python
@router.get("/sessions/{session_id}/stream")
async def broadcast_event_stream_route(
    session_id: str,
    invite_token: Optional[str] = Query(default=None),
    ctx: dict = Depends(_ctx),
):
    """SSE stream for real-time broadcast events (viewer count, health updates)."""
    session = get_session(session_id)           # store result (not discard)
    from app.services.broadcast_privacy import check_viewer_access
    check_viewer_access(
        session_id,
        ctx["user_sub"],
        creator_id=session.created_by,
        visibility=session.broadcast_privacy_visibility,
        invite_token=invite_token,
    )
    q = broadcast_sse_subscribe(session_id)

    async def gen():
        try:
            yield "event: hello\ndata: {}\n\n"
            while True:
                try:
                    item = await asyncio.wait_for(q.get(), timeout=15.0)
                    event_type = item.pop("_type", "update")
                    yield f"event: {event_type}\ndata: {json.dumps(item, separators=(',', ':'), default=str)}\n\n"
                except asyncio.TimeoutError:
                    yield ": ping\n\n"
        finally:
            broadcast_sse_unsubscribe(session_id, q)

    return StreamingResponse(gen(), media_type="text/event-stream")
```

Key changes:
1. Remove `_ = ctx`. Replace `_ = get_session(session_id)` with `session = get_session(session_id)`.
2. Add `check_viewer_access(...)` call using the stored `session` object's `created_by` and
   `broadcast_privacy_visibility` fields.
3. Add `invite_token` query parameter so private-session invite holders can connect.

### Scope of the health-report endpoint (out of scope for this ticket)

The BCAST-004 gap list includes a medium-severity gap: `POST /sessions/{session_id}/health` at
line 658 has no broadcaster ownership check. The fix for that endpoint would add:

```python
if ctx["user_sub"] != session.created_by:
    _require_operator_role(ctx)
```

This is not in scope for GAP-0115 but is recommended as a companion change.

### Dev/Prod parity (SECOPS-007)

The `check_viewer_access` implementation reads from the `broadcast_sessions` DynamoDB table
(allowlist sub-items) via `app/services/broadcast_privacy.py`. Both DynamoDB Local (port 8001
in dev) and AWS DynamoDB (production) use the same schema and boto3 API. The SSE in-memory
pub/sub (`broadcast_sse.py`) is process-local in both environments (documented constraint:
`--workers 1`). No environment-specific code branch is introduced.

In dev mode, sessions created by E2E test users have `broadcast_privacy_visibility` set from the
test input. The `check_viewer_access` function correctly handles the `"public"` default by
returning immediately, so E2E tests for public sessions are unaffected.

### Feature flag

None required. The fix is a pure access-control addition. Behaviour for public/unlisted sessions
(short-circuit return in `check_viewer_access`) is unchanged.

## 5. Testing, Verification & Rollout

### Regression tests (pytest, offline)

Since this is the same handler as GAP-0112, the test suite from GAP-0112 already covers the
primary regression case. The following tests are added to emphasise the BCAST-004 specific
scenarios (health and ad-break data leakage):

```python
# tests/test_broadcast_sse_health_access.py

import pytest
from unittest.mock import patch, MagicMock
from fastapi.testclient import TestClient
from app.main import app

def _private_live_session(session_id="sess_health", creator="alice"):
    m = MagicMock()
    m.id = session_id
    m.created_by = creator
    m.broadcast_privacy_visibility = "private"
    m.status = "live"
    return m


# ── GAP-0115: health data + viewer count behind private session ──────

def test_sse_stream_rejects_non_allowlisted_user_for_health_data():
    """Non-allowlisted user must receive 403 before any health or viewer events are sent.

    Fails before fix (200 received + SSE events), passes after fix (403).
    """
    with (
        patch("app.routers.broadcast.get_session",
              return_value=_private_live_session()),
        patch("app.routers.broadcast._ctx",
              return_value={"user_sub": "eve", "role": "user", "admin_profile": None}),
        patch("app.services.broadcast_privacy.is_allowlisted", return_value=False),
        patch("app.services.broadcast_privacy.redeem_invite_token", return_value=False),
    ):
        client = TestClient(app, raise_server_exceptions=False)
        resp = client.get("/ui/broadcast/sessions/sess_health/stream")

    assert resp.status_code == 403, (
        f"Expected 403; got {resp.status_code}. "
        "Health/viewer-count data must be gated by check_viewer_access."
    )
    detail = resp.json()["detail"]
    assert detail["code"] == "BROADCAST_PRIVATE_ACCESS_DENIED"


def test_sse_stream_allows_allowlisted_user():
    """Allowlisted user must be able to subscribe to the SSE stream."""
    import asyncio
    session = _private_live_session()

    with (
        patch("app.routers.broadcast.get_session", return_value=session),
        patch("app.routers.broadcast._ctx",
              return_value={"user_sub": "bob", "role": "user", "admin_profile": None}),
        patch("app.services.broadcast_privacy.is_allowlisted", return_value=True),
        patch("app.routers.broadcast.broadcast_sse_subscribe",
              return_value=MagicMock()),
        patch("app.routers.broadcast.broadcast_sse_unsubscribe"),
    ):
        client = TestClient(app)
        with client.stream("GET", "/ui/broadcast/sessions/sess_health/stream") as resp:
            assert resp.status_code == 200


def test_sse_stream_allows_invite_token_holder():
    """User with a valid invite_token must be allowed to subscribe."""
    session = _private_live_session()

    with (
        patch("app.routers.broadcast.get_session", return_value=session),
        patch("app.routers.broadcast._ctx",
              return_value={"user_sub": "frank", "role": "user", "admin_profile": None}),
        patch("app.services.broadcast_privacy.is_allowlisted", return_value=False),
        patch("app.services.broadcast_privacy.redeem_invite_token", return_value=True),
        patch("app.routers.broadcast.broadcast_sse_subscribe",
              return_value=MagicMock()),
        patch("app.routers.broadcast.broadcast_sse_unsubscribe"),

        client = TestClient(app)
        with client.stream(
            "GET",
            "/ui/broadcast/sessions/sess_health/stream?invite_token=tok_valid",
        ) as resp:
            assert resp.status_code == 200


def test_sse_stream_creator_always_allowed():
    """Creator of the session must always be allowed, even for private sessions."""
    session = _private_live_session(creator="alice")

    with (
        patch("app.routers.broadcast.get_session", return_value=session),
        patch("app.routers.broadcast._ctx",

        patch("app.routers.broadcast.broadcast_sse_subscribe",
              return_value=MagicMock()),
        patch("app.routers.broadcast.broadcast_sse_unsubscribe"),

        client = TestClient(app)
        with client.stream("GET", "/ui/broadcast/sessions/sess_health/stream") as resp:
```

**Fails-before** test: `test_sse_stream_rejects_non_allowlisted_user_for_health_data` returns
200 before the fix (handler discards ctx and subscribes unconditionally).
**Passes-after** test: All four tests pass after the fix.

### Manual QA steps

1. Alice creates a private broadcast session and starts it.
2. As Eve (not on allowlist), `GET /ui/broadcast/sessions/{alice_session}/stream`:
   - Before fix: 200 + SSE events including viewer counts and health data.
   - After fix: 403.
3. Alice sends a health report (`POST /sessions/{id}/health`). As Eve (still not allowlisted),
   verify the SSE stream remains 403. As Alice (creator), verify health events are received.
4. Alice adds Bob to the allowlist. Bob connects to the SSE stream — should receive 200.
5. Bob uses an `invite_token` on a fresh private session — should be auto-enrolled and
   receive 200.
6. A public session SSE stream must remain accessible to any authenticated user.
7. Confirm ad-break events (`event: ad_break_start`) are only delivered to authorised subscribers.

### Observability / alerting

Add a counter `broadcast.sse.access_denied{reason="private_session"}` on each 403 from
`check_viewer_access`. Alert when this counter spikes — indicates active probing of private
sessions via the SSE endpoint.

### Rollback

Revert the router change to `broadcast_event_stream_route`. No data migration. The rollback
restores the current open-access behaviour.

### Risks & effort

- **Risk**: Identical to GAP-0112. Embed widgets or monitoring tools that subscribed to the SSE
  stream without performing a formal viewer join will receive a 403 for private sessions until
  they are allowlisted or hold an invite token. For public sessions there is no impact.
- **Effort**: S — the fix is the same code change needed for GAP-0112. If both tickets are
  resolved together (which they should be, since they target the same function), the combined
  effort is a single PR with one code change and a unified test suite.
- **Deduplication note**: GAP-0112 and GAP-0115 can be closed together by a single commit to
  `broadcast_event_stream_route`. The issue tracker should link both tickets to the same PR.
  The BCAST-004 medium-severity companion gap (health-report endpoint ownership check) should
  be tracked separately and fixed in the same release.
- **Sequencing**: Fix GAP-0112 / GAP-0115 first (same commit). Then fix GAP-0113 / GAP-0114
  (same commit for the chat stream). Then address the medium-severity BCAST-004 health-report
  ownership check and the BCAST-002 playback-entitlement secret validation. All four GAPs in
  this batch are S-effort and can ship together in one release.
- **Health endpoint companion fix** (`POST /sessions/{session_id}/health`, line 658): After the
  SSE access check gates observation of health events, the data-poisoning vector via the
  unprotected health-report endpoint remains. The companion fix adds a broadcaster ownership check:
  `if ctx["user_sub"] != session.created_by: _require_operator_role(ctx)`. This one-line addition
  at the top of the health-report handler mirrors the pattern used throughout the router (e.g.
  `configure_chat_tiers_route` at line 2723). It should be committed alongside this fix to close
  the full BCAST-004 HIGH + MED gap set in a single PR.
