# GAP-0096: Absolute Path Not Rejected in scan_paths — Remediation Write-up

> Claim accuracy note: The ticket states the gap is at `app/services/agent_architect.py:204`.
> Investigation confirms this is PARTIALLY CORRECT. The `validate_architect_config` function
> at line 207–212 checks `".."` in `scan_paths` entries but does NOT check for absolute paths.
> However, `app/services/agent_docs.py` (a separate module) has its own `validate_path` helper
> at line 174–185 that correctly rejects `path.startswith("/")`. The architect config validator
> is a distinct code path that was not updated with the same protection. The cited line number
> (204) is slightly off — the `scan_paths` loop begins at line 210 — but the file and function
> are correct.

## 1. Summary & Classification

**Bug**: `validate_architect_config` in `app/services/agent_architect.py` rejects path traversal sequences (`..`) in both `scan_paths` and `reference_docs` entries, but accepts fully absolute paths such as `/etc/passwd`, `/proc/self/environ`, `/root/.ssh/id_rsa`, or `/home/ubuntu/.env.local`. A user with access to the AGENT-011 architect-config save or validate endpoint can supply absolute paths. The backend embeds those paths verbatim into generated shell commands that are later dispatched to an agent worker terminal, granting the attacker arbitrary file-system read access on the machine running the agent.

- **Severity**: HIGH
- **Source ticket**: AGENT-011
- **Owning area**: Agent Architect service / security input validation
- **Status**: Open
- **Verdict**: Confirmed (partial claim — `agent_docs.py:validate_path` has the fix; `agent_architect.py:validate_architect_config` does not)
- **One-line impact**: Absolute paths pass the architect-config validator and are spliced verbatim into `find ... -type f | head -500` shell commands dispatched to worker terminals, enabling arbitrary file read on the agent host.
- **Related tickets**: GAP-0095 (analysis-prompt command injection latent), GAP-0089 (build-coder workflow command injection), GAP-0094 (repo-branch shell injection), SECOPS-007 (dev/prod parity)

## 2. Current-State Investigation (root cause)

### The vulnerable validator

`app/services/agent_architect.py:188–232` (`validate_architect_config`) is called from two router endpoints: `POST /ui/agent/architect/validate` (read-only validation) and implicitly from `PUT /ui/agent/architect/config` (saves the config to DynamoDB). The relevant sections are:

```python
# lines 200–205  (reference_docs)
reference_docs = config.get("reference_docs")
if reference_docs is not None and len(reference_docs) == 0:
    errors.append("At least one reference document path is required")
for path in reference_docs or []:
    if ".." in str(path):
        errors.append(f"Reference doc path must not traverse outside repo: {path}")

# lines 207–212  (scan_paths)
scan_paths = config.get("scan_paths")
if scan_paths is not None and len(scan_paths) == 0:
    errors.append("At least one scan path is required")
for path in scan_paths or []:
    if ".." in str(path):
        errors.append(f"Scan path must not traverse outside repo: {path}")
```

Neither loop tests for absolute paths, tilde-expanded paths, Windows drive letters, or backslashes. The `".."` check uses `str(path)` substring containment, which means `"..foo"` or `"foo.."` would also be blocked (false positives) but `"/etc"` passes cleanly.

### Contrast: the already-hardened sibling module

`app/services/agent_docs.py:174–185` (`validate_path`) was written with a complete set of guards:

```python
def validate_path(path: str) -> bool:
    """Return True if ``path`` is a safe relative repository path."""
    if not path or not isinstance(path, str):
        return False
    if path.startswith("/") or path.startswith("~"):
        return False
    if ".." in path.split("/"):
        return False
    if "\\" in path or ":" in path:
        return False
    return True
```

This function rejects Unix absolute paths (`/`), tilde-home paths (`~`), traversal tokens (`..` as a full path component, not substring), Windows-style backslash paths, and drive-letter colons. `agent_architect.py` was written or modified independently and never received the same treatment.

### How the path reaches a shell command

`app/services/agent_architect.py:1125–1159` (`generate_workflow_steps`):

```python
scan_paths = cfg.get("scan_paths", [])
...
{"step_id": 3, "type": "scan_codebase",
 "command": "find " + " ".join(scan_paths) + " -type f | head -500" if scan_paths else None,
 "timeout_seconds": 120, "on_failure": "next"},
```

If `scan_paths = ["/etc", "/proc/self"]`, the generated command is:

```
find /etc /proc/self -type f | head -500
```

This command is returned as part of the `workflow_steps` payload and is subsequently executed by the agent worker in its terminal session. The worker runs under the backend service account and has file-system access to all paths the process can read.

Similarly, `reference_docs` entries appear in step 2:

```python
{"step_id": 2, "type": "read_reference_docs",
 "command": "cat " + " ".join(reference_docs) if reference_docs else None,
```

With `reference_docs=["/etc/passwd"]`, the generated command is `cat /etc/passwd`, which outputs the contents of the password file to the agent's terminal stream.

### The default scan paths confirm relative-only intent

`app/services/agent_architect.py:52`:
```python
_DEFAULT_SCAN_PATHS = ["app/services/", "app/routers/", "app/models.py", "frontend/src/"]
```

Every default is a relative path. The configuration schema comment at line 325 also specifies `"default": _DEFAULT_SCAN_PATHS`. The intent is clearly relative-only; the validator simply failed to enforce it.

### Dev vs prod behaviour

The dev stack runs with `--workers 1` by default, but the validation gap is present in all environments. Any user who can reach the validate endpoint (session auth, no admin required per `app/routers/agent_architect.py:86`) can inject absolute paths. The shell commands are executed in the agent terminal session, not directly by the backend, but in dev the agent terminal and backend often share the same host.

## 3. Impact / Exploit / Blast Radius

**Exploit walkthrough**:

1. Attacker authenticates as any user (no ADMIN role required — the validate endpoint is session-auth only).
2. POST `/ui/agent/architect/validate` with `{"repo_url":"https://github.com/x/y","scan_paths":["/etc/passwd","/proc/self/environ"]}`. Response: `{"valid":true,"errors":[]}`.
3. POST `/ui/agent/architect/config` (or trigger ticket analysis) to save and use the config.
4. Call the workflow-steps generation endpoint. Step 3 (`scan_codebase`) contains `find /etc/passwd /proc/self/environ -type f | head -500`.
5. The agent worker executes the step and returns the file listing and optionally streams file contents back.
6. `reference_docs=["/proc/self/environ"]` is even more direct: the generated command is `cat /proc/self/environ`, which outputs all environment variables of the backend process — including `UI_ACCESS_TOKEN_SECRET`, `API_KEY_PEPPER`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and any Stripe/PayPal keys.

**Blast radius**:

- **Credential exfiltration**: Leaked `UI_ACCESS_TOKEN_SECRET` allows forging session JWTs for any user, including root. Leaked `API_KEY_PEPPER` allows brute-forcing all stored API key hashes. Leaked AWS credentials allow full DynamoDB and S3 access.
- **Lateral movement**: With IAM credentials the attacker can enumerate all DynamoDB tables, download all user records, and exfiltrate files from all S3 buckets.
- **PII breach**: Direct file reads on the agent host may expose private key files, configuration files containing database passwords, or application secrets managed via environment variables.
- **Compliance**: Arbitrary file read of user data stored on-disk violates GDPR and SOC 2 data minimisation and access control requirements.

**Who is affected**: All authenticated users who can reach the architect-config endpoints. The validate endpoint (`POST /ui/agent/architect/validate`) itself is a read-only reconnaissance oracle — an attacker can probe it to confirm that absolute paths are accepted before committing to an exploit.

## 4. Fix Design (code-level)

### Primary fix: centralise path validation using `_is_safe_path`

Introduce a module-level helper in `app/services/agent_architect.py` that mirrors `agent_docs.validate_path`, and call it from `validate_architect_config`. This eliminates the divergence and provides a single reviewed function.

**Add to `app/services/agent_architect.py`** (near the top, after imports and constants):

```python
def _is_safe_path(path: str) -> bool:
    """Return True only for safe relative repository paths.

    Rejects: absolute paths (/...), tilde-expansion (~...), path traversal
    components (.. as a segment), Windows backslash paths, and drive-letter
    paths (C:). Mirrors agent_docs.validate_path — keep in sync.
    """
    if not path or not isinstance(path, str):
        return False
    if path.startswith("/") or path.startswith("~"):
        return False
    if ".." in str(path).split("/"):
        return False
    if "\\" in str(path) or ":" in str(path):
        return False
    return True
```

**Update `validate_architect_config`** (replace the `reference_docs` and `scan_paths` loops):

```python
# reference_docs loop (replaces lines 203–205):
for path in reference_docs or []:
    if not _is_safe_path(str(path)):
        errors.append(f"Reference doc path must be a safe relative path: {path}")

# scan_paths loop (replaces lines 210–212):
for path in scan_paths or []:
    if not _is_safe_path(str(path)):
        errors.append(f"Scan path must be a safe relative path: {path}")
```

Note: `_is_safe_path` uses `path.split("/")` for the `..` check, which is more precise than the old `".." in str(path)` substring test. The old check would reject `"foo..bar"` (a legitimate filename containing dots) as a false positive; the new check only rejects `..` as a complete path segment.

### Secondary fix: defence-in-depth filter in command generation

At `app/services/agent_architect.py:1158–1160`, filter out any unsafe paths before building the shell command even if upstream validation was somehow bypassed:

```python
safe_scan_paths = [p for p in scan_paths if _is_safe_path(str(p))]
safe_reference_docs = [p for p in reference_docs if _is_safe_path(str(p))]

# step 2:
"command": "cat " + " ".join(safe_reference_docs) if safe_reference_docs else None,
# step 3:
"command": "find " + " ".join(safe_scan_paths) + " -type f | head -500" if safe_scan_paths else None,
```

This ensures that even if a config with absolute paths was stored before the fix was deployed, the command generation step does not include them.

### Dev/Prod parity (SECOPS-007)

`_is_safe_path` is pure string logic with no I/O and no environment dependency. It behaves identically in dev (`DEV_MODE=1`) and in production. No feature flag is required. The existing `agent_docs.validate_path` function follows the same design, confirming this is the correct approach for this codebase.

No data migration is required. Configs already stored in DynamoDB are not re-validated at read time. Any config stored before the fix that contains absolute paths would be rejected on the next `PUT /ui/agent/architect/config` call with the fixed validator. The secondary command-generation filter provides protection even for stale configs.

**Alternatives rejected**:
- **Allowlist of permitted path prefixes**: Overly restrictive for a general-purpose code analyst that needs to scan arbitrary repository structures. Different repositories have different directory layouts.
- **Sandbox execution with restricted filesystem**: Defence in depth, valuable long-term, but not a substitute for input validation. The generated `command` text is returned to API clients and can be forwarded to any executor outside the sandbox.
- **Import `validate_path` from `agent_docs`**: Creates a cross-module dependency between two services that should be independent. A local `_is_safe_path` helper is cleaner; a shared `app/core/path_security.py` utility is the right long-term home.

## 5. Testing, Verification & Rollout

### Regression test (pytest, offline)

Add to `tests/services/test_agent_architect_validation.py` (new file or appended to existing):

```python
import pytest
from app.services.agent_architect import validate_architect_config, _is_safe_path

BASE_CONFIG = {
    "repo_url": "https://github.com/example/repo",
    "reference_docs": ["docs/README.md"],
    "scan_paths": ["app/"],
}


class TestIsSafePath:
    def test_relative_path_accepted(self):
        assert _is_safe_path("app/services/foo.py") is True

    def test_nested_relative_accepted(self):
        assert _is_safe_path("frontend/src/pages/") is True

    def test_absolute_path_rejected(self):
        assert _is_safe_path("/etc/passwd") is False

    def test_tilde_path_rejected(self):
        assert _is_safe_path("~/secrets") is False

    def test_dotdot_component_rejected(self):
        assert _is_safe_path("app/../../../etc") is False

    def test_dotdot_as_filename_fragment_allowed(self):
        # "foo..bar" is a valid filename; only ".." as a segment should be blocked
        assert _is_safe_path("docs/CHANGELOG..md") is True

    def test_windows_backslash_rejected(self):
        assert _is_safe_path("app\\services") is False

    def test_windows_drive_rejected(self):
        assert _is_safe_path("C:\\Users\\x") is False

    def test_colon_rejected(self):
        assert _is_safe_path("app:services") is False


class TestValidateArchitectConfigPaths:
    def test_absolute_scan_path_rejected(self):
        """FAILS before fix: validate_architect_config returns [] for /etc/passwd."""
        cfg = {**BASE_CONFIG, "scan_paths": ["/etc/passwd"]}
        errors = validate_architect_config(cfg)
        assert any("/etc/passwd" in e for e in errors), \
            f"Expected error for absolute scan path, got: {errors}"

    def test_tilde_scan_path_rejected(self):
        cfg = {**BASE_CONFIG, "scan_paths": ["~/secrets"]}
        errors = validate_architect_config(cfg)
        assert any("~/secrets" in e for e in errors)

    def test_absolute_reference_doc_rejected(self):
        cfg = {**BASE_CONFIG, "reference_docs": ["/proc/self/environ"]}
        errors = validate_architect_config(cfg)
        assert any("/proc" in e for e in errors)

    def test_windows_drive_scan_path_rejected(self):
        cfg = {**BASE_CONFIG, "scan_paths": ["C:\\Users\\x"]}
        errors = validate_architect_config(cfg)
        assert errors  # any error is acceptable

    def test_dotdot_still_rejected(self):
        cfg = {**BASE_CONFIG, "scan_paths": ["../../../etc"]}
        errors = validate_architect_config(cfg)
        assert any("../../../etc" in e for e in errors)

    def test_valid_relative_paths_accepted(self):
        cfg = {**BASE_CONFIG, "scan_paths": ["app/services/", "frontend/src/"]}
        errors = validate_architect_config(cfg)
        # No path-related errors
        path_errors = [e for e in errors if "path" in e.lower()]
        assert path_errors == []
```

**Tests that FAIL before the fix**: `test_absolute_scan_path_rejected`, `test_tilde_scan_path_rejected`, `test_absolute_reference_doc_rejected`, `test_windows_drive_scan_path_rejected`. These all pass empty error lists today because the validator only checks `".."`.

**Tests that PASS after the fix**: All nine `TestIsSafePath` tests and all six `TestValidateArchitectConfigPaths` tests.

### Observability

Add a structured log entry in the validator when a path is rejected with `reason="unsafe_path"` and the offending value. This allows the security team to monitor abuse attempts via CloudWatch Logs Insights query: `filter reason="unsafe_path" | stats count(*) by user_id`.

### Rollout

- **Effort**: S (small — approximately 25 lines of logic change; no schema changes; no migration)
- **Risk**: Low — the change tightens input validation. The one behavioural difference vs the old check is that `"foo..bar"` (legitimate filename) is no longer a false-positive rejection. No stored data is mutated.
- **Sequencing**: Can be merged independently; no dependency on other AGENT-0xx gaps. Recommend bundling with GAP-0095 (analysis-prompt command injection) and GAP-0094 (repo-branch injection) in a single "input validation hardening" PR.
- **Rollback**: Revert the `_is_safe_path` helper and restore the `".."` substring check. Absolute paths are exploitable again but the `..` traversal protection remains.
