## 2. Current-State Investigation (Root Cause)

### 2.1 `CallBillingOverlay.tsx` — Built but Unused

`frontend/src/components/calls/CallBillingOverlay.tsx:1–62` exports `CallBillingOverlay` and `CallBillingOverlayProps`.  The component renders a translucent cost ticker in the top-left of the call UI and an animated low-balance warning banner.  Its props are:

```typescript

  totalCostCents: number;
  rateCentsPerMinute: number;
  elapsedSeconds: number;
  balanceRemainingCents: number;
  warnLowBalance?: boolean;
  minutesRemaining?: number;
}
```

A codebase-wide search for `CallBillingOverlay` returns only the file itself — no import sites.

### 2.2 `useCallBillingHeartbeat.ts` Does Not Exist

`frontend/src/hooks/` contains `useCallRecording.ts`, `useConnectionQuality.ts`, `useMediaCapture.ts`, `useRtcPeerConnection.ts`, and `useMessagingStream.ts`, among others — but no `useCallBillingHeartbeat.ts`.  Without this hook there is no periodic `PATCH /messaging/messages/calls/{call_id}/heartbeat` emitted from the browser during a connected paid call.

The consequence: `call_billing_timer.py`'s heartbeat handler never fires mid-call.  `finalize_call_billing()` is called at call end by `messaging_call_lifecycle.py:384–391`, but it attempts to charge the full accumulated duration in a single shot.  If the wallet balance has drifted below that amount between call-start balance check and call end, finalization may fail or partially fail.

### 2.3 `CallSessionOverlay.tsx` — No Billing Props

`CallSessionOverlay.tsx` `Props` interface (lines 42–70) contains only call-lifecycle and recording props.  There is no `totalCostCents`, `rateCentsPerMinute`, `warnLowBalance`, or any billing-related prop.  The overlay body has no import of `CallBillingOverlay` and no render site for it.

### 2.4 `ConversationView.tsx` — No Billing Wiring

`ConversationView.tsx` imports `useCallRecording` (`:53`) but not `useCallBillingHeartbeat` (which doesn't exist) and not `CallBillingOverlay`.  The `<CallSessionOverlay>` render block (`:1342–1447`) passes recording, mute, camera, and screen-share props, but passes no billing data.  The `callBillingHeartbeat` state that should drive the overlay's cost ticker does not exist anywhere in the component.

### 2.5 Backend Heartbeat Endpoint

`app/routers/call_billing.py:143–199` handles `PATCH /messaging/messages/calls/{call_id}/heartbeat`.  It:
1. Reads the `CallSessionRecord` for the call.
2. Calls `process_heartbeat(call_id, caller_user_id)` from `call_billing_timer.py`.
3. Returns `HeartbeatOut` with `elapsed_seconds`, `total_cost_cents`, `balance_remaining_cents`, `warn_low_balance`, `minutes_remaining`, and `action`.

When `action == "end_call"` the backend has determined the caller's balance is depleted and the call should be terminated.  Without the frontend hook, this signal is never received during the call.

## 3. Impact / Exploit / Blast Radius

**Financial — caller**: A caller in a paid call has zero in-product visibility of:
- How much they have spent so far.
- Their remaining wallet balance.
- A low-balance warning with estimated minutes remaining.
- The `action=end_call` signal that tells the client to tear down the call before the balance is fully depleted.

Without heartbeats, the server-side billing timer still accumulates cost on every heartbeat it *would* receive, but because no heartbeats arrive, `total_billed_cents` stays at 0 until `finalize_call_billing` runs at call end.  The final bill then attempts one large debit.  If the wallet balance is insufficient at that moment, the billing status is recorded as `failed` — the creator effectively provided the service for free.

**Financial — creator**: Loss of payment when final billing fails due to single-shot finalization.

**Trust**: Callers who discover post-hoc that they were charged for a long call with no in-call cost display may dispute the charge.  The absence of a displayed rate and running tally is a consumer-protection concern.

**Rate of occurrence**: Affects every paid call where `body.paid=true` was passed to `create_call_invite`.  Free calls (the majority in current dev usage) are unaffected.

## 4. Fix Design (Code-Level)

### 4.1 Create `frontend/src/hooks/useCallBillingHeartbeat.ts`

```typescript
// frontend/src/hooks/useCallBillingHeartbeat.ts
import * as React from "react";
import { sendCallHeartbeat, type HeartbeatResponse } from "@/api/endpoints/callBilling";

interface Options {
  callId: string | null;
  isPaidCall: boolean;
  isConnected: boolean;
  heartbeatIntervalMs?: number;
  onEndCall?: () => void;
}

export interface BillingState {
  totalCostCents: number;
  rateCentsPerMinute: number;
  elapsedSeconds: number;
  balanceRemainingCents: number;
  warnLowBalance: boolean;
  minutesRemaining: number;
}

const INITIAL_STATE: BillingState = {
  totalCostCents: 0,
  rateCentsPerMinute: 0,
  elapsedSeconds: 0,
  balanceRemainingCents: 0,
  warnLowBalance: false,
  minutesRemaining: 0,
};

export function useCallBillingHeartbeat({
  callId,
  isPaidCall,
  isConnected,
  heartbeatIntervalMs = 30_000,
  onEndCall,
}: Options): BillingState {
  const [state, setState] = React.useState<BillingState>(INITIAL_STATE);
  const onEndCallRef = React.useRef(onEndCall);
  onEndCallRef.current = onEndCall;

  React.useEffect(() => {
    // Reset billing state when call changes
    setState(INITIAL_STATE);
  }, [callId]);

  React.useEffect(() => {
    if (!callId || !isPaidCall || !isConnected) return;

    let active = true;
    const fire = async () => {
      try {
        const resp: HeartbeatResponse = await sendCallHeartbeat(callId);
        if (!active) return;
        setState({
          totalCostCents: resp.total_cost_cents,
          rateCentsPerMinute: resp.rate_cents_per_minute,
          elapsedSeconds: resp.elapsed_seconds,
          balanceRemainingCents: resp.balance_remaining_cents,
          warnLowBalance: resp.warn_low_balance,
          minutesRemaining: resp.minutes_remaining,
        });
        if (resp.action === "end_call") {
          onEndCallRef.current?.();
        }
      } catch {
        // Heartbeat failure is non-fatal; backend reconciles at call end
      }
    };

    fire(); // immediate first heartbeat on connect
    const id = window.setInterval(fire, heartbeatIntervalMs);
    return () => {
      active = false;
      window.clearInterval(id);
    };
  }, [callId, isPaidCall, isConnected, heartbeatIntervalMs]);

  return state;
}
```

Key design decisions:
- `isPaidCall` guard — heartbeats only sent for paid calls; free calls are unaffected.
- `active` flag — prevents stale state updates if the component unmounts between async calls.
- `onEndCall` ref pattern — avoids stale closure on the callback without adding it to the dependency array.
- Heartbeat failure is silently swallowed — same pattern as `call_billing_timer.py:67`'s best-effort finalization.

### 4.4 Dev/Prod Parity (SECOPS-007)

The `heartbeatIntervalMs` defaults to 30 000 ms (backend heartbeat interval default is also 30 s via `S.call_heartbeat_interval_seconds`).  In dev mode, `sendCallHeartbeat` hits the local backend at `localhost:8000` through the Vite proxy; in production it hits the real API.  The `call_billing_enabled` backend flag (`app/core/settings.py`) gates whether heartbeat processing applies.  The hook itself is always registered when `isPaidCall` is true — no `DEV_MODE`-only branches.  The `CallBillingOverlay` renders identically in both environments.

### 5.3 Rollback

The heartbeat hook is only activated when `isPaidCall=true`, which is only set when the call was created with `paid: true`.  Rolling back means removing the three wiring changes to `ConversationView.tsx` and the billing props from `<CallSessionOverlay>`.  Free calls are entirely unaffected throughout.
