# GAP-0290: `ShelfProductPicker.tsx` dialog does not exist — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code at
> `frontend/src/pages/broadcast/BroadcastChat.tsx`,
> `app/routers/broadcast.py` (lines 1693–1760, 2103–2167), and
> `frontend/src/api/endpoints/broadcast-chat.ts`.

## 1. Summary & Classification

**Plain-English statement**: The backend endpoint `POST /broadcast/sessions/{id}/chat/product`
is fully built and gated to the session creator (broadcaster). The broadcaster toolbar in
`BroadcastChat.tsx` already has toggle buttons for expiry, lock, and lottery, but has no
"Share Product" button and no product-picker dialog. `ShelfProductPicker.tsx` — the dialog
that should list the broadcaster's shelf items and allow one to be chosen for sharing —
does not exist in the codebase. The broadcaster has no UI mechanism to trigger a product
link share; only a direct API call would work.

- **Severity**: HIGH — the broadcaster's primary live-commerce action is absent from the UI
- **Source ticket**: LCOM-002
- **Owning area**: Broadcast Frontend / Live Commerce
- **Status**: Open
- **Claim accuracy**: Confirmed. `find frontend/src -name "ShelfProductPicker*"` returns
  empty. There is no "Share Product" button in `BroadcastChat.tsx`. The broadcaster
  toggles panel (lines 412–463) has `Clock`, `Lock`, and `Ticket` (lottery) buttons but
  no product-share button.

**Impact in one line**: Broadcasters cannot share products from the live chat UI — the
entire live-commerce product-sharing workflow is UI-inaccessible.

**Related tickets**: GAP-0289 (`ProductLinkCard.tsx` also absent — the viewer-side
rendering of the product link message), LCOM-002 write-up,
`app/routers/broadcast.py` lines 2103–2167 (shelf management endpoints already live).

## 2. Current-State Investigation (root cause)

### Backend shelf and product-share endpoints — fully implemented

`app/routers/broadcast.py` exposes:

| Endpoint | Line | Purpose |
|---|---|---|
| `GET /sessions/{id}/products` | 2103 | List all products on the broadcaster's shelf |
| `POST /sessions/{id}/products` | 2107 | Add a catalog item to the shelf |
| `DELETE /sessions/{id}/products/{item_id}` | 2151 | Remove a product from the shelf |
| `POST /sessions/{id}/chat/product` | 1694 | Share a shelf product into chat |

The `POST .../chat/product` handler (lines 1698–1760) validates the item is on the shelf,
resolves the effective broadcast price, stores a `kind="product_link"` chat message, and
returns the full `BroadcastChatMessageOut`. It is fully functional.

### BroadcastChat.tsx broadcaster toolbar — three buttons, none for product

Lines 412–463 of `BroadcastChat.tsx` show the broadcaster-only toggles:

```tsx
{isBroadcaster && (
  <div … data-testid="broadcaster-toggles">
    {/* Clock toggle — expiry */}
    <button … data-testid="toggle-expiry"><Clock … /></button>
    {/* Lock toggle */}
    <button … data-testid="toggle-lock"><Lock … /></button>
    {/* Lottery button (BCAST-014) */}
    <button … data-testid="toggle-lottery"><Ticket … /></button>
    {/* ← no product-share button */}
  </div>
)}
```

No state variable for a product picker, no dialog, no import of any product-related
component. The `ShoppingBag` or `Package` icon from Lucide (available in the project) is
not used anywhere in this file.

### Shelf API wrappers — not yet exported from `broadcast-chat.ts`

`frontend/src/api/endpoints/broadcast-chat.ts` exports `sendChatMessage`,
`getChatHistory`, `deleteChatMessage`, `muteChatUser`, `reactToChatMessage`,
`unlockChatMessage`, and lottery functions. It has no `getShelfProducts` or
`sendChatProductLink` functions.

### Shelf list API exists but has no frontend wrapper

`GET /broadcast/sessions/{id}/products` (line 2103 of `broadcast.py`) returns a list of
shelf products with full pricing data including `effective_price_cents`, `is_broadcast_price`,
and `discount_pct`. The response is typed as a list of `BroadcastShelfProductOut` objects.
However, `broadcast-chat.ts` has no `getShelfProducts()` function — it would need to be
added alongside the picker component. The products endpoint is accessible with session-cookie
auth and does not require broadcaster scope to read, which means the picker can query the
shelf for display purposes and then pass the chosen `item_id` to `POST .../chat/product`
(which does enforce broadcaster identity).

### Why the gap exists

The shelf management UI (adding/removing products from the shelf before a session, done
from the broadcast session setup page) may have been implemented separately. The in-session
chat share step — which requires a picker dialog that queries the live shelf — was simply
not built. The lottery feature (`BroadcastLotteryCreator`) serves as the architectural
template: it renders inline below the message list when `showLotteryCreator` is true and
uses a mutation to call the backend, then closes itself. The product picker should follow
the same pattern but uses a `Dialog` overlay instead since the shelf list requires more
vertical space than the lottery creator form.

### `BroadcastChatProductLinkOut` backend model

The backend response for `POST .../chat/product` (line 1695) returns a full
`BroadcastChatMessageOut` which includes the nested `product_link: BroadcastChatProductLinkOut`
object (line 1506). The `BroadcastChatProductLinkOut` model contains all fields needed
for `ProductLinkCard.tsx` rendering: `item_id`, `name`, `description`, `price_cents`,
`currency`, `image_url`, `effective_price_cents`, `is_broadcast_price`, and `discount_pct`.
The SSE stream broadcasts this to all viewers immediately, so there is no polling delay.

## 3. Impact / Exploit / Blast Radius

### Functional

A broadcaster who has added products to their shelf before going live has no way to share
them in the chat during the session without using a REST API client directly. The intended
UX ("click Share Product → select from shelf → card appears in chat for viewers to buy")
is completely inaccessible.

### Revenue

Live-commerce product sharing is a time-sensitive action — sending a product link during
a high-energy moment in a broadcast drives impulse purchases. The absence of the UI
means this revenue opportunity is entirely blocked.

### No security impact

The backend correctly restricts `POST .../chat/product` to the session creator. There is
no unauthorized access risk. The gap is purely functional.

### Blast radius

Limited to `BroadcastChat.tsx` and the broadcaster's in-session workflow. Viewer
experience (once GAP-0289 is also fixed) is unaffected for messages sent via API.

## 4. Fix Design (code-level)

### Step 1 — Create `ShelfProductPicker.tsx`

Create `frontend/src/pages/broadcast/ShelfProductPicker.tsx`:

```typescript
import { useState } from "react";
import { useQuery, useMutation } from "@tanstack/react-query";
import { ShoppingBag, Loader2, Zap } from "lucide-react";
import {
  Dialog,
  DialogContent,
  DialogHeader,
  DialogTitle,
  DialogDescription,
} from "@/components/ui/dialog";
import { Button } from "@/components/ui/button";
import { Badge } from "@/components/ui/badge";
import { getShelfProducts, sendChatProductLink } from "@/api/endpoints/broadcast-chat";
import type { ShelfProduct } from "@/api/endpoints/broadcast-chat";

interface ShelfProductPickerProps {
  sessionId: string;
  open: boolean;
  onClose: () => void;
  onSent: () => void;
}

export function ShelfProductPicker({
  sessionId,
  open,
  onClose,
  onSent,
}: ShelfProductPickerProps) {
  const [selectedItemId, setSelectedItemId] = useState<string | null>(null);

  const shelfQuery = useQuery({
    queryKey: ["broadcast", "shelf", sessionId],
    queryFn: () => getShelfProducts(sessionId),
    enabled: open,
    staleTime: 30_000,
  });

  const shareMut = useMutation({
    mutationFn: (itemId: string) => sendChatProductLink(sessionId, itemId),
    onSuccess: () => {
      setSelectedItemId(null);
      onSent();
      onClose();
    },
  });

  const products: ShelfProduct[] = shelfQuery.data?.products ?? [];

  return (
    <Dialog open={open} onOpenChange={(v) => !v && onClose()}>
      <DialogContent className="max-w-sm" data-testid="shelf-product-picker">
        <DialogHeader>
          <DialogTitle>Share a Product</DialogTitle>
          <DialogDescription>
            Choose a product from your shelf to share in the chat.
          </DialogDescription>
        </DialogHeader>

        {shelfQuery.isLoading ? (
          <div className="flex justify-center py-6">
            <Loader2 className="h-5 w-5 animate-spin text-muted-foreground" />
          </div>
        ) : products.length === 0 ? (
          <p
            className="py-6 text-center text-sm text-muted-foreground"
            data-testid="shelf-empty"
          >
            Your shelf is empty. Add products from the session settings.
          </p>
        ) : (
          <ul className="space-y-2 max-h-72 overflow-y-auto pr-1" data-testid="shelf-product-list">
            {products.map((p) => {
              const effectivePrice = (
                (p.effective_price_cents ?? p.price_cents) / 100
              ).toFixed(2);
              const regularPrice = (p.price_cents / 100).toFixed(2);
              const hasDiscount =
                p.is_broadcast_price && p.discount_pct != null && p.discount_pct > 0;

              return (
                <li key={p.item_id}>
                  <button
                    className={`w-full flex items-center gap-3 rounded-md border px-3 py-2 text-left transition-colors
                      ${selectedItemId === p.item_id
                        ? "border-primary bg-primary/10"
                        : "border-border hover:bg-muted/50"
                      }`}
                    onClick={() => setSelectedItemId(p.item_id)}
                    data-testid={`shelf-product-${p.item_id}`}
                  >
                    {p.image_url && (
                      <img
                        src={p.image_url}
                        alt={p.name}
                        className="h-10 w-10 rounded object-cover shrink-0"
                      />
                    )}
                    <div className="flex-1 min-w-0">
                      <p className="text-sm font-medium truncate">{p.name}</p>
                      <div className="flex items-center gap-1 mt-0.5">
                        <span className="text-xs font-bold text-primary">
                          ${effectivePrice}
                        </span>
                        {hasDiscount && (
                          <>
                            <span className="text-[10px] line-through text-muted-foreground">
                              ${regularPrice}
                            </span>
                            <Badge
                              variant="destructive"
                              className="text-[9px] px-1 py-0 h-4"
                            >
                              <Zap className="h-2 w-2 mr-0.5" />
                              {p.discount_pct}% off
                            </Badge>
                          </>
                        )}
                      </div>
                    </div>
                  </button>
                </li>
              );
            })}
          </ul>
        )}

        <div className="flex justify-end gap-2 pt-2">
          <Button variant="outline" size="sm" onClick={onClose}>
            Cancel
          </Button>
          <Button
            size="sm"
            disabled={!selectedItemId || shareMut.isPending}
            onClick={() => selectedItemId && shareMut.mutate(selectedItemId)}
            data-testid="shelf-share-btn"
          >
            {shareMut.isPending ? (
              <Loader2 className="mr-1 h-3.5 w-3.5 animate-spin" />
            ) : (
              <ShoppingBag className="mr-1 h-3.5 w-3.5" />
            )}
            Share in Chat
          </Button>
        </div>
      </DialogContent>
    </Dialog>
  );
}
```

### Step 2 — Add `getShelfProducts` and `sendChatProductLink` to `broadcast-chat.ts`

```typescript
export interface ShelfProduct {
  item_id: string;
  name: string;
  description?: string;
  price_cents: number;
  currency: string;
  image_url?: string;
  effective_price_cents?: number;
  is_broadcast_price?: boolean;
  discount_pct?: number | null;
}

export interface ShelfProductsResponse {
  products: ShelfProduct[];
}

export const getShelfProducts = (sessionId: string) =>
  api.get<ShelfProductsResponse>(`/broadcast/sessions/${sessionId}/products`);

export const sendChatProductLink = (sessionId: string, itemId: string) =>
  api.post<ChatMessage>(`/broadcast/sessions/${sessionId}/chat/product`, {
    item_id: itemId,
  });
```

```tsx

  open={showProductPicker}
  onClose={() => setShowProductPicker(false)}
  onSent={() => {
    // The SSE stream (chat:product_link event, wired in GAP-0289) will deliver
    // the new message automatically. No manual state update needed.
  }}

```

### Dev/Prod parity (SECOPS-007)

`getShelfProducts` and `sendChatProductLink` use the same Axios `api` client that proxies
through Vite to the backend in development and hits the production FastAPI server directly
in production. No mock path or feature flag is required. The backend shelf endpoints
(`GET /sessions/{id}/products`) are already protected by `_ctx` (session auth) and scoped
to the session creator for write operations.

The `ShelfProductPicker` opens as a `Dialog` (shadcn/ui `Dialog` primitive, already used
widely in the project). No new UI library dependencies are introduced.

### Backward compatibility

`showProductPicker` state starts as `false`. Existing broadcasters see no change until
they click the new button. No data migration or backward-incompatible API changes are
needed.
