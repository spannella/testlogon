# GAP-0254: ResidencyVerificationTab Missing from Admin Case Detail — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual codebase; no prior investigation doc exists.

## 1. Summary & Classification

**Claim from ticket**: The admin KYC case detail page (`frontend/src/pages/admin/KycCaseDetailPage.tsx`)
is missing a "Residency" tab. Without it, reviewers cannot see the address comparison or
per-field match status for the residency document attached to a case.

**Verdict: Claim CONFIRMED.** Reading `KycCaseDetailPage.tsx` in full confirms there is no
Residency tab. The page uses a two-column layout with a `DocumentViewer` (identity files)
and `KycFacialComparisonReview` on the left, and case info + action dialogs on the right.
The `Tabs`/`TabsList`/`TabsTrigger` components from shadcn/ui are imported and used only
within `DocumentViewer` (lines 150–226) to switch between document types. There is no top-
level page tab for "Residency", "Documents", "Face Comparison", etc.

The frontend API module (`frontend/src/api/endpoints/kycResidency.ts`) provides
`listKycResidencyByStatus` and `adminGetKycResidencyDocument` but no function that lists
residency documents scoped to a specific case for admin review. A backend endpoint and a
frontend API helper for case-scoped residency are also missing.

- **Severity**: HIGH (compliance/regulatory) — reviewers processing enhanced/high_risk cases
  cannot assess residency document quality or see address comparison results without leaving
  the case detail page and navigating to a separate admin queue.
- **Source ticket**: KYC-004
- **Owning area**: Frontend `KycCaseDetailPage.tsx`, `frontend/src/api/endpoints/kycResidency.ts`,
  backend `app/routers/kyc_residency.py`
- **Related tickets**: GAP-0252 (readiness gate), GAP-0253 (`get_verified_docs_for_case`
  helper), SECOPS-007
- **Dependencies**: GAP-0253 must be implemented first (provides the backend data source for
  this tab's address comparison panel).

## 2. Current-State Investigation (root cause)

### Page layout and existing tabs

`frontend/src/pages/admin/KycCaseDetailPage.tsx` lines 412–end render the case detail in a
two-column `grid-cols-1 lg:grid-cols-5` layout:

- **Left column (lg:col-span-3)**: `DocumentViewer` (identity files with document type
  sub-tabs: selfie, id_front, id_back, proof_of_address) and `KycFacialComparisonReview`.
- **Right column (lg:col-span-2)**: Case Information card, Decision card (if decided),
  Timeline, and action dialogs (Approve / Reject / Request Info).

There is no page-level tabbed navigation wrapping the left column. The `KycFacialComparisonReview`
component (line 435) is embedded directly — residency verification deserves the same first-
class treatment.

### Backend: no case-scoped admin residency endpoint

`app/routers/kyc_residency.py` exposes:

```
POST /ui/kyc/residency                        -> upload a document (owner)
GET  /ui/kyc/residency                        -> list own documents (owner)
GET  /ui/kyc/residency/admin/by-status        -> list all docs by status (admin)
GET  /ui/kyc/residency/admin/{document_id}    -> get one doc (admin)
POST /ui/kyc/residency/admin/{document_id}/review -> approve/reject (admin)
GET  /ui/kyc/residency/{document_id}          -> get own doc (owner)
POST /ui/kyc/residency/{document_id}/extract  -> run extraction (owner)
```

There is no `GET /ui/kyc/residency/admin/case/{case_id}` route. An admin opening the case
detail page has no way to fetch residency documents for that specific case without iterating
all status buckets (pending, verified, rejected, expired) and filtering by `case_id` in the
browser — an O(total docs) operation.

### Frontend: no case-scoped residency API helper

`frontend/src/api/endpoints/kycResidency.ts` does not export any function accepting a
`case_id` parameter. All existing functions target either the owner's own documents or a
document ID directly.

### Address match data structure (backend)

`app/services/kyc_residency.py` stores `address_match` and `extracted_address` on each
document record. `public_document_view` (line 666) exposes them when `include_match=True`:

```python
out["extracted_address"] = item.get("extracted_address") or {}
am = item.get("address_match") or {}
out["address_match"] = am if am else None
```

`address_match` is shaped as:
```json
{
  "status": "match|partial|mismatch|not_available",
  "profile_address": { "line1": "...", "city": "...", ... },
  "field_matches": {
    "line1": "match|mismatch",
    "city": "match|mismatch",
    "state": "match|mismatch",
    "postal_code": "match|mismatch",
    "country": "match|mismatch"
  }
}
```

This is the exact shape needed for the two-column address comparison UI and per-field match
badges the ticket specifies.

## 3. Impact / Exploit / Blast Radius

**Reviewer cannot assess EDD**: For enhanced and high_risk cases, the residency document
and its address comparison are EDD evidence. A reviewer who approves such a case without
seeing the residency check is making a decision without full information. The missing tab
makes sound EDD review structurally impossible in the current UI.

**Reviewer workflow disruption**: To view residency documents today, a reviewer must open a
separate browser tab, navigate to `GET /admin/by-status?status=verified`, and manually
match the case ID. This is a multi-minute interruption per case review and is prone to error.

**GAP-0252 dependency**: The readiness gate fix (GAP-0252) ensures residency documents are
uploaded before submission. The admin tab is the complementary control ensuring reviewers
can evaluate those documents once the case is in the queue. Without the tab, the gate
improvement has reduced audit value.

**No security risk**: This is a missing UI feature, not an authorization gap.

## 4. Fix Design (code-level)

### 4a. Add `GET /ui/kyc/residency/admin/case/{case_id}` backend endpoint

Insert in `app/routers/kyc_residency.py` after line 127 (after `admin_get_residency_document`):

```python
# Must be declared before admin/{document_id} to prevent FastAPI routing /{document_id}
# to match "case" as a literal document_id.
# The existing /admin/by-status and /admin/{document_id} ordering sets the precedent.

@kyc_residency_router.get(
    "/admin/case/{case_id}",
    response_model=KycResidencyListResponse,
)
async def admin_list_residency_for_case(
    case_id: str,
    _user: AuthenticatedUser = Depends(require_admin_or_root),
) -> KycResidencyListResponse:
    """List all residency documents for a specific case (admin/root)."""
    items = STORE.list_documents_for_case(case_id)
    return KycResidencyListResponse(
        documents=[_out(item, include_match=True) for item in items]
    )
```

This uses the existing `list_documents_for_case` method (queries ByCase GSI, O(docs per
case)) and `_out(item, include_match=True)` to include the full address comparison data.

### 4b. Add frontend API helper

Add to `frontend/src/api/endpoints/kycResidency.ts`:

```typescript
export const adminListKycResidencyForCase = (caseId: string) =>
  api.get<KycResidencyListResponse>(`/ui/kyc/residency/admin/case/${caseId}`);
```

### 4c. Add `ResidencyVerificationTab` component

Create `frontend/src/pages/admin/ResidencyVerificationTab.tsx`:

```tsx
import { useQuery } from "@tanstack/react-query";
import { adminListKycResidencyForCase } from "@/api/endpoints/kycResidency";
import { Badge } from "@/components/ui/badge";
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card";
import type { KycResidencyDocumentOut } from "@/api/types";

const ADDRESS_FIELDS = ["line1", "city", "state", "postal_code", "country"] as const;

function MatchBadge({ status }: { status: string | undefined }) {
  if (!status) return null;
  const variant =
    status === "match" ? "default" : status === "partial" ? "secondary" : "destructive";
  return <Badge variant={variant}>{status}</Badge>;
}

function AddressComparisonTable({ doc }: { doc: KycResidencyDocumentOut }) {
  const extracted = (doc.extracted_address as Record<string, string>) ?? {};
  const profileAddress =
    (doc.address_match as { profile_address?: Record<string, string> })?.profile_address ?? {};
  const fieldMatches =
    (doc.address_match as { field_matches?: Record<string, string> })?.field_matches ?? {};
  const overallStatus =
    (doc.address_match as { status?: string } | null)?.status ?? "not_available";

  return (
    <div className="space-y-3">
      <div className="flex items-center gap-2">
        <span className="text-sm font-medium">Overall address match:</span>
        <MatchBadge status={overallStatus} />
      </div>
      <div className="overflow-x-auto">
        <table className="w-full text-sm border-collapse">
          <thead>
            <tr className="border-b">
              <th className="text-left py-1 pr-4 text-muted-foreground font-medium">Field</th>
              <th className="text-left py-1 pr-4 text-muted-foreground font-medium">Extracted</th>
              <th className="text-left py-1 pr-4 text-muted-foreground font-medium">Profile</th>
              <th className="text-left py-1 text-muted-foreground font-medium">Match</th>
            </tr>
          </thead>
          <tbody>
            {ADDRESS_FIELDS.map((field) => (
              <tr key={field} className="border-b last:border-0">
                <td className="py-1.5 pr-4 capitalize text-muted-foreground">{field.replace("_", " ")}</td>
                <td className="py-1.5 pr-4" data-testid={`extracted-${field}`}>
                  {extracted[field] ?? <span className="text-muted-foreground">—</span>}
                </td>
                <td className="py-1.5 pr-4" data-testid={`profile-${field}`}>
                  {profileAddress[field] ?? <span className="text-muted-foreground">—</span>}
                </td>
                <td className="py-1.5" data-testid={`match-${field}`}>
                  <MatchBadge status={fieldMatches[field]} />
                </td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </div>
  );
}

interface ResidencyVerificationTabProps {
  caseId: string;
}

export function ResidencyVerificationTab({ caseId }: ResidencyVerificationTabProps) {
  const { data, isLoading, isError } = useQuery({
    queryKey: ["kyc-residency-case", caseId],
    queryFn: () => adminListKycResidencyForCase(caseId),
    enabled: !!caseId,
  });

  if (isLoading) {
    return <p className="text-sm text-muted-foreground py-4">Loading residency documents...</p>;
  }
  if (isError) {
    return <p className="text-sm text-destructive py-4">Failed to load residency documents.</p>;
  }

  const docs: KycResidencyDocumentOut[] = data?.documents ?? [];

  if (docs.length === 0) {
    return (
      <Card>
        <CardContent className="py-8 text-center text-sm text-muted-foreground">
          No residency documents attached to this case.
        </CardContent>
      </Card>
    );
  }

  return (
    <div className="space-y-4" data-testid="residency-verification-tab">
      {docs.map((doc) => (
        <Card key={doc.document_id}>
          <CardHeader className="pb-2">
            <div className="flex items-center justify-between">
              <CardTitle className="text-sm font-medium capitalize">
                {doc.document_type.replace("_", " ")} — {doc.issuing_entity}
              </CardTitle>
              <div className="flex items-center gap-2">
                <span className="text-xs text-muted-foreground">{doc.document_date}</span>
                <Badge
                  variant={
                    doc.status === "verified"
                      ? "default"
                      : doc.status === "rejected" || doc.status === "expired"
                      ? "destructive"
                      : "outline"
                  }
                  data-testid="residency-doc-status"
                >
                  {doc.status}
                </Badge>
              </div>
            </div>
          </CardHeader>
          <CardContent>
            {doc.address_match ? (
              <AddressComparisonTable doc={doc} />
            ) : (
              <p className="text-sm text-muted-foreground">
                Address extraction not yet run for this document.
              </p>
            )}
          </CardContent>
        </Card>
      ))}
    </div>
  );
}
```

### 4e. Dev/Prod parity (SECOPS-007)

The backend endpoint (`GET /ui/kyc/residency/admin/case/{case_id}`) calls
`STORE.list_documents_for_case` which queries `T.kyc_residency_documents` via the ByCase

and production. No environment-specific branches are introduced.
