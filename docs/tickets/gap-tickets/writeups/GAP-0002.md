# GAP-0002: `serve_broadcast_ad` Stub Not Wired to ADS-004 Engine — Remediation Write-up

> Source ticket: ADS-006 · Severity: CRIT · Effort: S · Status: Open

## 1. Summary & Classification

**Bug statement.** `app/services/broadcast_ads.py:serve_broadcast_ad()` is a stub that returns a hardcoded "house" creative for every broadcast ad slot. The real ad serving engine—`app/services/ad_serving.py:serve_ad()`—was fully implemented as part of ADS-004 and supports targeting, frequency caps, budget enforcement, and revenue attribution. The delegation from the broadcast surface to the engine was never completed. Every viewer of every broadcast stream sees the same placeholder creative regardless of targeting criteria, active campaigns, or budget state.

**Verdict (from investigation):** Confirmed. The stub comment inside `broadcast_ads.py:63–68` explicitly states "When ADS-004 lands this function should delegate to `app.services.ad_serving.serve_ad`", and `ad_serving.serve_ad()` exists at line 45 of the same module hierarchy. Zero call sites for `serve_ad` exist within `broadcast_ads.py`.

**Severity and area.** Critical / Advertising & Monetisation. The broadcast ad serving path — pre-roll, mid-roll, and post-roll slots — is entirely disconnected from the auction engine. No revenue is generated from broadcast ad breaks; advertisers with broadcast-targeted campaigns receive zero delivery on that surface.

**Related tickets.** ADS-006 (broadcast ads feature), ADS-004 (the serving engine now confirmed live), GAP-0007 (a parallel ticket describing the same missing wiring from the serve-broadcast-ad endpoint perspective), GAP-0046 (role-type comparison bug in ad-break authorisation — would need fixing before broadcast ads deliver correctly end-to-end).

## 2. Current-State Investigation (root cause)

### The stub: `broadcast_ads.py:55–83`

```python
# app/services/broadcast_ads.py:55–83
def serve_broadcast_ad(
    *,
    surface: str,
    creator_id: str,
    content_id: str,
    slot_type: str,
    user_id: str,
) -> Dict[str, Any]:
    """Select an ad for a broadcast surface.

    NOTE: ADS-004 (ad serving engine) and ADS-002 (video creatives) are not yet
    implemented. This returns a deterministic stub "house" creative so the rest of
    the flow (overlay, tracking, skip) is exercisable end-to-end. When ADS-004 lands
    this function should delegate to ``app.services.ad_serving.serve_ad``.

    Returns a dict with ``filled`` plus creative metadata + tracking URLs.
    """
    creative_id = f"bcast_house_{slot_type}"
    return {
        "filled": True,
        "creative_id": creative_id,
        "format": "video",
        "video_url": f"/mock/s3/ad-creatives/{creative_id}.mp4",
        "image_url": None,
        "cta_url": None,
        "impression_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=impression",
        "click_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=click",
        "skip_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=skip",
    }
```

The stub was intentional scaffolding: it allowed the broadcast overlay, skip-button, and tracking endpoints to be built and tested before the ad engine existed. The comment is clear about the intended migration path. ADS-004 was subsequently implemented, but `broadcast_ads.py` was never revisited.

### The real engine: `ad_serving.py:45+`

`app/services/ad_serving.py` begins at line 45 with `def serve_ad(...)`. From the investigation, the function accepts `surface`, `content_type`, `creator_id`, `content_id`, `slot_type`, and `user_id` — matching the parameters already present in `serve_broadcast_ad`'s signature. It performs targeting, frequency cap lookup in `T.ad_frequency_caps`, budget enforcement via `_has_budget()`, and creative selection before returning the same dict shape that the broadcast overlay consumes.

### How `serve_broadcast_ad` is called

`broadcast_ads.py:98–103` calls `serve_broadcast_ad` from `build_pre_roll()`:

```python
# broadcast_ads.py:98–103
ad = serve_broadcast_ad(
    surface="broadcast",
    creator_id=session.created_by,
    content_id=session.id,
    slot_type="broadcast_preroll",
    user_id=viewer_id,
)
```

`build_pre_roll()` is invoked by the broadcast router when a viewer joins a session, gated by `is_ad_free()` and `session.pre_roll_enabled` checks (lines 92–96). The same delegation pattern is used for mid-roll ad breaks via `start_ad_break()` (line 127) and any post-roll slots. All of these call sites pass through `serve_broadcast_ad`; the fix to that single function propagates to all broadcast ad surfaces simultaneously.

The real engine at `ad_serving.py:45` accepts exactly this parameter signature and adds `user_context: Optional[Dict[str, Any]] = None` as an optional extension point. The broadcast parameters map cleanly.

### Ad-free and no-fill paths

`build_pre_roll()` already handles the no-fill case at line 105–108: if `ad.get("filled")` is falsy, the pre-roll is set to `None` and the viewer is allowed directly into the stream. The engine's `serve_ad()` returns `{"filled": False, ...}` when no eligible campaign exists (see `_house_ad_response()` in `ad_serving.py`). The graceful-degradation fallback in the proposed fix preserves this contract: a house creative with `"filled": True` is returned when the engine raises, rather than returning `{"filled": False}`, maintaining the pre-roll display in error scenarios. This is the conservative choice — the alternative of failing open (returning `filled: False` on error) can be discussed separately.

### Dev vs prod behaviour

In dev mode the `/mock/s3/ad-creatives/bcast_house_*.mp4` path resolves via the S3 mock (`app/routers/s3_mock.py`). In production the same path would 404 because no real S3 object exists at that key and the S3 mock is not active. The stub is therefore not only wrong about ad targeting — in production, every broadcast viewer also gets a broken video URL in the pre-roll payload. The engine's `serve_ad()` returns real creative URLs from S3/CDN, which would resolve correctly in both environments.

## 3. Impact / Exploit / Blast Radius

**Revenue.** All broadcast ad impressions, clicks, and conversions generate zero platform revenue. The billing path (`charge_impression`, `charge_click`, `charge_conversion`) in `ad_billing.py` is never reached from the broadcast surface because the stub never creates a real campaign-attributed ad selection. Advertisers who specifically targeted the broadcast surface in their campaigns receive zero delivery.

**Targeting.** All broadcast viewers — regardless of age, location, interest, or frequency cap state — receive the same house creative. Users who have exceeded frequency caps continue to be shown the ad. Users who are not in the campaign's target geo/interest segment receive it anyway.

**Creative quality.** In production the `video_url` points to `/mock/s3/ad-creatives/bcast_house_*.mp4`, which is a path served by the dev-only S3 mock router. In a production deployment without `DEV_MODE=1`, this URL 404s, resulting in a blank ad slot for every broadcast viewer.

**No exploit required.** This is a logic gap, not a vulnerability. Any broadcast viewer can confirm the issue by inspecting the `creative_id` field in the pre-roll payload, which always starts with `bcast_house_`.

## 4. Fix Design (code-level)

### Replace the stub body in `broadcast_ads.py:55–83`

```python
# app/services/broadcast_ads.py — replace lines 55–83

def serve_broadcast_ad(
    *,
    surface: str,
    creator_id: str,
    content_id: str,
    slot_type: str,
    user_id: str,
) -> Dict[str, Any]:
    """Select an ad for a broadcast surface via the ADS-004 serving engine.

    Delegates to app.services.ad_serving.serve_ad for targeting, frequency caps,
    and budget enforcement. Falls back to the house creative when the engine raises
    (e.g. no eligible campaigns, engine error) to preserve broadcast continuity.
    """
    try:
        from app.services.ad_serving import serve_ad
        return serve_ad(
            surface=surface,
            content_type="broadcast",
            creator_id=creator_id,
            content_id=content_id,
            slot_type=slot_type,
            user_id=user_id,
        )
    except Exception:
        import logging
        logging.getLogger(__name__).warning(
            "serve_broadcast_ad: engine failed, falling back to house creative",
            exc_info=True,
        )
        # Graceful degradation: house creative when engine is unavailable
        creative_id = f"bcast_house_{slot_type}"
        return {
            "filled": True,
            "creative_id": creative_id,
            "format": "video",
            "video_url": f"/mock/s3/ad-creatives/{creative_id}.mp4",
            "image_url": None,
            "cta_url": None,
            "impression_url": (
                f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=impression"
            ),
            "click_url": (
                f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=click"
            ),
            "skip_url": (
                f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=skip"
            ),
        }
```

**Graceful degradation rationale.** The broadcast flow must not crash if the ad engine is temporarily unavailable (e.g., DynamoDB connection loss, no eligible campaigns). The `try/except Exception` fallback preserves the existing house-creative behaviour as a safety net. A warning log is emitted so that operations can distinguish intentional no-fill (no eligible campaigns) from engine errors. A future improvement would return `{"filled": False}` on no-fill rather than serving a house creative, but that is a separate product decision and out of scope for this remediation.

### Dev/Prod parity (SECOPS-007)

`serve_ad()` in `ad_serving.py` reads from `T.ad_campaigns`, `T.ad_frequency_caps`, and `T.ad_accounts` — all DynamoDB tables. In dev these are served by DynamoDB Local (port 8001). In production they are AWS DynamoDB. The code path is identical; no `DEV_MODE` branch exists in `serve_ad()`. No mock bypass is introduced by this change.

The fallback house-creative path retains the `/mock/s3/` URL. In production this should be replaced with a real CDN URL for the house creative (a separate cleanup ticket), but it is not a regression introduced by this fix — it was always the behaviour before.

### Backward compatibility

The function signature is unchanged. All callers (`build_pre_roll`, `build_mid_roll`, `build_post_roll`) continue to call `serve_broadcast_ad` with the same keyword arguments. The return dict shape is unchanged (both the engine and the fallback return the same keys). No database schema changes needed.

### Alternatives considered

- **Remove the fallback entirely:** Cleaner, but risks broadcast sessions breaking if the engine raises for an innocuous reason (e.g., empty campaign table during dev). Rejected in favour of graceful degradation.
- **Add a feature flag `BROADCAST_ADS_ENGINE_ENABLED`:** Adds operational overhead with no real benefit since the engine is already live. Rejected.
- **Inline `serve_ad` logic in `broadcast_ads.py`:** Duplicates the targeting and budget logic. Rejected; delegation is the correct abstraction.

### Manual QA steps

2. Start a broadcast session as a creator.
3. Join the session as a viewer. Observe the pre-roll ad payload in the network tab.
4. Confirm `creative_id` does not start with `bcast_house_` and matches the seeded campaign's creative.

### Observability

Add a counter `broadcast_ad_engine_delegations_total{result="success|fallback|error"}` to `serve_broadcast_ad`. Alert if `result="error"` rate exceeds 1% of all broadcast ad requests.

### Rollout & risks

- **Risk:** The engine may raise `KeyError` or `TypeError` if the broadcast surface's `slot_type` values do not match the set that `serve_ad()` expects. Mitigated by the `except Exception` fallback; validate accepted slot types in a follow-up.
- **Risk:** Broadcast sessions that currently show a house creative will begin showing real ads, potentially impacting viewers unexpectedly. This is the intended product behaviour.
- **Risk:** If `ad_serving.serve_ad()` introduces latency (e.g., DynamoDB targeting lookups), `build_pre_roll()` becomes slower. Profile the engine response time and add a per-request timeout in the try block if p99 latency is unacceptable for the live broadcast pre-roll path.
- **Rollback:** Revert the function body to the original stub. No data changes to roll back.
- **Effort:** S — one function body replacement (~30 lines) plus tests.
- **Sequence:** Fix GAP-0046 (role-type comparison bug in ad-break authorisation) in the same release to avoid authorisation failures on ad-break creation.

### Summary of the delegation contract

| Concern | Stub (current) | Engine-delegated (after fix) |
|---|---|---|
| Targeting | None — same ad for all viewers | Audience targeting via `ad_targeting.py` |
| Frequency caps | None | Enforced via `T.ad_frequency_caps` |
| Budget enforcement | None | Enforced via `_has_budget()` |
| Revenue attribution | None (no billing entry) | `charge_impression` called on impression event |
| Creative URL in production | 404 (`/mock/s3/` path) | Real CDN URL from approved creative record |
| No-fill handling | Always `filled: True` | Engine returns `filled: False` when no campaigns match |
| Error handling | N/A (pure function) | Falls back to house ad on exception |
