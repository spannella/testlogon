# GAP-0175: `relay_state` carries attacker-controlled form field not sanitised — Remediation Write-up

> ~5 pages. Fix-oriented. Cites real file:line. No prior investigation doc; claim verified
> against live code as part of this write-up.

## 1. Summary & Classification

**Plain-English statement**: The `POST /saml/acs` endpoint reads `RelayState` from the POST
form body without any sanitisation. The value is accepted at arbitrary length, may contain
arbitrary bytes (including null bytes, control characters, and non-ASCII sequences), and is
used verbatim in log messages, an in-memory data structure, and — most critically — as the
redirect target after a successful SAML authentication. While the related open-redirect risk
is catalogued separately in GAP-0018, this ticket focuses on the input-validation layer that
should exist regardless of what the value is used for: size limits, character-set
restrictions, and URL structural validation.

- **Severity**: HIGH
- **Source ticket**: ENTERPRISE-002
- **Status**: Open
- **Owning area**: Backend / SSO / Input Validation
- **Verdict**: **Confirmed** — `app/routers/sso_saml.py` line 78 reads `relay_state` from
  the form with no size cap, no character-set check, and no URL validation. Lines 212 and
  568 redirect to `str(relay_state or "/")` verbatim. This ticket's scope (sanitisation)
  is distinct from but overlaps with GAP-0018 (same-origin validation).
- **Related tickets**: GAP-0018 (open-redirect via RelayState, CRIT), ENTERPRISE-002,
  SECOPS-007.
- **Claim accuracy**: **Confirmed and extended.** The ticket describes the absence of a
  ≤2 KB limit, printable-ASCII restriction, and URL validation. All three are confirmed
  absent. Additionally, `relay_state` is passed to `_dev_bypass_acs` (line 92) and used
  in the redirect at line 568, making it a two-site issue.

## 2. Current-State Investigation (root cause)

### Form field extraction (no size cap)

`app/routers/sso_saml.py` lines 76–79:

```python
form = await request.form()
saml_response_b64 = form.get("SAMLResponse")
relay_state = form.get("RelayState", "/")
tenant_id = str(form.get("tenant_id", "default"))
```

`request.form()` is backed by Starlette's `FormData`, which reads the entire form body into
memory. No size limit is applied to `RelayState` before this assignment. The SAML 2.0
specification recommends a maximum of 80 characters for RelayState and defines it as an
opaque handle that should be URL-safe; neither constraint is enforced here.

### Redirect targets (unvalidated)

Two redirect call sites:

1. **Production ACS path** — `app/routers/sso_saml.py` line 212:
   ```python
   redirect = RedirectResponse(url=str(relay_state or "/"), status_code=303)
   ```

2. **Dev bypass path** — line 568 (inside `_dev_bypass_acs`):
   ```python
   redirect = RedirectResponse(url=relay_state or "/", status_code=303)
   ```

In both cases `relay_state` is cast to `str` and used directly. `starlette.responses.RedirectResponse`
does not validate that the URL is well-formed or same-origin.

### Downstream use in data structures

Line 103: `req_data["post_data"]["RelayState"] = relay_state` — the raw value enters the
`req_data` dict that is then passed into `MockSamlAuth` / (after GAP-0174 fix)
`OneLogin_Saml2_Auth`. A large or malformed value here can produce unexpectedly large log
entries or cause issues in the SAML library's internal XML building.

### What is missing

1. **Size cap**: No check that `len(relay_state) <= 2048`.
2. **Character-set restriction**: No check that the value is printable ASCII. Binary data,
   null bytes, and Unicode sequences are accepted.
3. **URL structural validation**: No check that the value, when non-empty, is a relative
   URL or a same-origin absolute URL (the open-redirect of GAP-0018, but also a
   prerequisite for safe use in any context).
4. **Encoding normalisation**: No percent-decode + re-encode cycle to canonicalise the
   value before use.

## 3. Impact / Exploit / Blast Radius

### Log injection / log poisoning

An attacker who controls `RelayState` can inject newline characters (`\r\n`) or ANSI escape
sequences into the audit log entry written by `audit_event` at line 63 and line 219. This
can produce fake log lines that appear to record legitimate activity, obscuring the audit
trail during incident response.

Example payload: `RelayState = /dashboard\r\n2026-01-01 00:00:00 INFO sso_login alice@acme.com`

### Memory amplification

The form body is parsed entirely into memory. An attacker who sends a 10 MB `RelayState`
value causes the backend to allocate 10 MB per request. With concurrent requests, this can
exhaust available heap. The SAML flow is unauthenticated at this point (the
`SAMLResponse` has not yet been verified when `relay_state` is read), making this a
pre-auth memory exhaustion vector.

### Open redirect (intersection with GAP-0018)

Without structural validation a value of `javascript:alert(1)` or
`https://attacker.com/steal` is accepted. The open-redirect is the primary exploitation
path; this ticket's fixes are the necessary prerequisite. Both tickets must be fixed
together for the defence-in-depth posture to be complete.

### Response-splitting

If the `relay_state` value contains bare `\r\n` sequences and the web server does not
sanitise redirect headers (many do not), the redirect response header can be split,
injecting arbitrary HTTP headers or a second response body into the browser (CWE-113).
`starlette.responses.RedirectResponse` quotes the `Location` value but does not strip `\r\n`
in all versions.

### Scope

The `/saml/acs` endpoint is public (no auth required). It is the most exposed SAML endpoint
since it is the callback target posted to by the IdP (or by an attacker). Both the
production path and the dev bypass path are affected.

## 4. Fix Design (code-level)

### Introduce a `_sanitise_relay_state` helper

Add the helper to `app/routers/sso_saml.py` (or to a new `app/core/saml_utils.py`):

```python
import re
from urllib.parse import urlparse

_RELAY_STATE_MAX_BYTES = 2048
_RELAY_STATE_RE = re.compile(r'^[\x20-\x7E]*$')  # printable ASCII only


def _sanitise_relay_state(raw: str) -> str:
    """
    Validate and sanitise a SAML RelayState value.

    Rules:
    - Truncate / reject values longer than 2048 bytes.
    - Accept only printable ASCII (0x20–0x7E); reject anything else.
    - If non-empty, must be either:
        (a) a relative URL (starts with '/'), or
        (b) an absolute URL whose scheme is 'http' or 'https' (open-redirect
            prevention is done separately in _safe_redirect_url, but we
            refuse blatantly dangerous schemes here).
    - Default to '/' on rejection to avoid 500 errors.

    This function is the FIRST line of defence; same-origin enforcement
    (GAP-0018 fix) is the SECOND line.
    """
    if not isinstance(raw, str):
        return "/"

    # 1. Size limit
    if len(raw.encode("utf-8", errors="replace")) > _RELAY_STATE_MAX_BYTES:
        logger.warning("RelayState too large (%d bytes), discarding", len(raw))
        return "/"

    # 2. Printable ASCII only
    if not _RELAY_STATE_RE.match(raw):
        logger.warning("RelayState contains non-printable characters, discarding")
        return "/"

    # 3. Must be relative or http(s) absolute
    if raw.startswith("/"):
        return raw  # relative URL -- accept (same-origin enforced downstream)

    try:
        parsed = urlparse(raw)
    except ValueError:
        return "/"

    if parsed.scheme not in ("http", "https"):
        logger.warning("RelayState has disallowed scheme '%s', discarding", parsed.scheme)
        return "/"

    return raw  # absolute URL -- same-origin check applied downstream (GAP-0018)
```

### Apply sanitisation immediately on form read

`app/routers/sso_saml.py` lines 76–79 become:

```python
form = await request.form()
saml_response_b64 = form.get("SAMLResponse")
relay_state = _sanitise_relay_state(str(form.get("RelayState", "/")))
tenant_id = str(form.get("tenant_id", "default"))
```

This ensures every downstream use of `relay_state` — including the `req_data` dict, the
audit event, and both redirect call sites — operates on a safe, bounded value.

### Apply to `saml_login` as well

The `saml_login` endpoint (line 49) accepts `return_to` as a query parameter and passes it
to `auth.login(return_to="/")`. The same sanitisation should be applied:

```python
@router.get("/saml/login")
async def saml_login(request: Request, tenant: str = "default", return_to: str = "/"):
    return_to = _sanitise_relay_state(return_to)
    ...
    redirect_url = auth.login(return_to=return_to)
```

### Global Starlette body-size limit (defence in depth)

Add a body size limit to the ASGI middleware stack in `app/main.py` to cap POST bodies at
a reasonable size (e.g., 1 MB). This prevents memory amplification even before the endpoint
reads the form:

```python
from starlette.middleware.trustedhost import TrustedHostMiddleware
# Already present in many setups; add ContentSizeLimitMiddleware:
from starlette.middleware import Middleware

# In create_app() or app factory:
app.add_middleware(
    ContentSizeLimitMiddleware,
    max_content_size=1 * 1024 * 1024,  # 1 MB
)
```

### Dev/prod parity (SECOPS-007)

`_sanitise_relay_state` is a pure function with no environment-specific branches. It runs
identically in dev and prod. The character-set and size checks are unconditional. In dev
the logging backend may format differently, but the validation logic is the same code path.

### Relationship to GAP-0018

GAP-0018 adds same-origin enforcement after sanitisation. The layering is:
1. `_sanitise_relay_state` — size, character set, scheme (this ticket).
2. `_safe_redirect_url` (GAP-0018 fix) — same-origin check, default to `/` for
   cross-origin values.

These are complementary: sanitisation prevents injection/memory attacks; same-origin
enforcement prevents the redirect being weaponised. Both should be deployed together.

## 5. Testing, Verification & Rollout

### Unit tests for `_sanitise_relay_state` (pytest, offline)

`tests/test_relay_state_sanitisation.py`:

```python
import pytest
from app.routers.sso_saml import _sanitise_relay_state

@pytest.mark.parametrize("raw,expected", [
    # Valid relative URLs
    ("/", "/"),
    ("/dashboard", "/dashboard"),
    ("/messages?tab=inbox", "/messages?tab=inbox"),
    # Valid absolute URLs
    ("https://app.example.com/post-login", "https://app.example.com/post-login"),
    # Over-length: rejected
    ("/" + "a" * 2048, "/"),
    # Non-printable: rejected
    ("/dashboard\x00evil", "/"),
    ("/dashboard\rnewline", "/"),
    ("/dashboard\nnewline", "/"),
    # Log injection attempts: rejected
    ("/ok\r\nINFO fake log", "/"),
    # Dangerous scheme: rejected
    ("javascript:alert(1)", "/"),
    ("data:text/html,<script>evil</script>", "/"),
    ("ftp://attacker.com/", "/"),
    # Cross-origin: accepted by sanitiser (same-origin check is GAP-0018)
    ("https://attacker.com/steal", "https://attacker.com/steal"),
    # Empty string
    ("", ""),
    # Non-string input
    (None, "/"),
])
def test_sanitise_relay_state(raw, expected):
    assert _sanitise_relay_state(raw) == expected  # type: ignore[arg-type]


def test_relay_state_2kb_exactly_accepted():
    """Exactly 2048 bytes must pass."""
    raw = "/" + "a" * 2046  # 2047 chars = 2047 bytes
    assert _sanitise_relay_state(raw) == raw

def test_relay_state_2kb_plus_one_rejected():
    """2049 bytes must be rejected."""
    raw = "/" + "a" * 2048
    assert _sanitise_relay_state(raw) == "/"
```

### Integration test (ACS endpoint)

```python
def test_acs_rejects_oversized_relay_state(client):
    """
    BEFORE fix: no 400; relay_state stored/used as-is (memory amplification risk).
    AFTER fix:  relay_state is silently clamped to '/'; no error is returned to the
                client (transparent sanitisation).
    """
    import base64
    # Build a minimal (forged) SAMLResponse that will fail validation -- we only
    # care that relay_state is sanitised, not that the login succeeds.
    resp = client.post("/saml/acs", data={
        "SAMLResponse": base64.b64encode(b"<fake/>").decode(),
        "RelayState": "A" * 3000,  # 3 KB
        "tenant_id": "default",
    })
    # The request should NOT have stored 3KB; sanitised to '/'.
    # The response may be 400 (bad SAMLResponse) but must not be 5xx.
    assert resp.status_code < 500

def test_acs_rejects_newline_in_relay_state(client):
    import base64
    resp = client.post("/saml/acs", data={
        "SAMLResponse": base64.b64encode(b"<fake/>").decode(),
        "RelayState": "/ok\r\nevil log line",
        "tenant_id": "default",
    })
    assert resp.status_code < 500
    # Verify the sanitised relay_state in the redirect (if any redirect occurs)
    if 300 <= resp.status_code < 400:
        location = resp.headers.get("location", "")
        assert "evil log line" not in location
        assert "\r" not in location
        assert "\n" not in location
```

### Manual QA steps

1. Use `curl` to POST to `/saml/acs` with a 5 MB `RelayState` value (generated with
   `python3 -c "print('A'*5000000)"`) and confirm the backend does not OOM and the relay
   state is discarded.
2. POST with `RelayState=/ok%0d%0aX-Injected: evil` (URL-encoded CRLF) and inspect the
   response headers for the injected header.
3. POST with `RelayState=javascript:alert(1)` and verify the Location header in any 3xx
   response does not contain `javascript:`.
4. POST with `RelayState=https://attacker.com/` and confirm (after GAP-0018 fix) that the
   redirect goes to `/` instead.

### Metrics / observability

Add `relay_state_sanitised_total{reason="too_large|non_ascii|bad_scheme"}` counter so
operators can detect probing activity. A spike in `too_large` or `non_ascii` events
indicates an active attack or a misconfigured IdP.

### Rollout

1. **Dark-launch phase**: Deploy `_sanitise_relay_state` with logging only (do not yet
   redirect to `/` on rejection; instead log `WARNING` and pass the sanitised-but-original
   value through). Run for 24–48 hours and inspect logs for any IdP-generated RelayState
   values that would have been rejected. This identifies misconfigured IdPs before the fix
   blocks their values silently.
2. **Enable enforcement**: Switch to the full implementation where rejected values default
   to `/`. This is the actual security fix.
3. **Monitor**: Watch `relay_state_sanitised_total` for one week. Alert if `too_large`
   or `non_ascii` events occur more than 10 times in any 5-minute window.
4. **Coordinate with GAP-0018 fix**: Deploy this ticket's sanitisation fix at the same
   time as the GAP-0018 same-origin enforcement fix. The two fixes are layered: sanitisation
   rejects malformed values; same-origin enforcement rejects cross-origin values that pass
   sanitisation. Together they form a complete defence. Deploying only this fix without
   GAP-0018 leaves the open-redirect risk partially open for well-formed cross-origin URLs.
5. **IdP compatibility note**: If monitoring shows an active IdP sending `RelayState` values
   with non-printable characters (a spec violation but technically possible from some older
   IdP implementations), add a percent-decode → re-encode normalisation step before the
   character-set check, and expand the allowed set to include percent-encoded sequences.
   This is unlikely given modern IdPs but should be handled if observed.

**Effort**: S (1 day: helper function ~30 lines, 3 call-site changes including `saml_login`,
parametric unit tests, one integration test, metrics counter wiring).

**Risk**: Very low. The validation is transparent to well-behaved IdPs (all compliant
RelayState values are printable ASCII and < 2 KB per SAML 2.0 section 3.6.3). The
default-to-`/` on rejection changes behaviour only for malformed values that should never
appear from a spec-compliant IdP. User-visible impact: an attacker's injected RelayState
value silently redirects to the dashboard (`/`) instead of the injected URL — a safe
degradation. No DDB changes, no migration, no infrastructure coordination required.
