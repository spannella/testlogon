# GAP-0376: Frontend UI for VOD Bridge Entirely Absent — Remediation Write-up

> Source ticket: VOD-014 · Severity: HIGH · Effort: L · Status: Open

## 1. Summary & Classification

**Bug statement.** The backend VOD-file-bridge API (`POST /ui/vod-bridge/import`, `GET /ui/vod-bridge/status/{video_id}`, `DELETE /ui/vod-bridge/{video_id}/link`) is fully implemented and registered, but the entire frontend surface for exercising it is missing. The `FileEntry` TypeScript interface carries no `vod_*` fields, no `importFileToVod` or `getVodBridgeStatus` wrapper functions exist in the frontend API layer, the `FileTable` context-menu has no "Watch" or "Send to VOD" items, `FilesPage` has no import dialog wiring, and `VideosPage` shows no "In Files" badge on video cards that were bridged from the file manager.

**Verdict:** Confirmed. Code search across `frontend/src/api/types.ts`, `frontend/src/api/endpoints/vod.ts`, `frontend/src/api/endpoints/files.ts`, `frontend/src/pages/files/FileTable.tsx`, and `frontend/src/pages/videos/VideosPage.tsx` finds zero VOD-bridge symbols. The backend router at `app/routers/vod_bridge.py` is wired and live; the frontend simply has no path to reach it.

**Severity and area.** HIGH / Frontend — File Manager and Videos. The gap is entirely a missing frontend layer; no data is lost or corrupted, but the VOD import workflow specified in VOD-014 §4.1–4.3 and Phase 2 is completely inaccessible through the UI.

**Related tickets.** VOD-014 (source feature), SECOPS-007 (dev/prod parity). No hard dependencies on other open GAPs, but GAP-0377 (clip job error handling) and GAP-0379 (concat error handling) affect the transcode pipeline that the imported files enter.

## 2. Current-State Investigation (root cause)

### Backend is complete

`app/routers/vod_bridge.py` registers three endpoints on prefix `/ui/vod-bridge`:

- `POST /import` (line 40–44): calls `import_file_to_vod()`, returns `ImportToVodOut` with `video_id`, `status`, `file_path`.
- `GET /status/{video_id}` (line 47–62): returns `BridgeStatusOut` including `vod_status`, `hls_manifest_url`, `duration_seconds`, dimensions.
- `DELETE /{video_id}/link` (line 65–69): calls `unlink_video_from_filemanager()`.

The router is included in `app/main.py:612`:

```python
# app/main.py:612
app.include_router(vod_bridge_router)
```

`app/services/vod_file_bridge.py` is fully implemented: `import_file_to_vod` (line 67) writes `vod_video_id`, `vod_linked`, and `vod_status` back onto the file-manager node; `unlink_video_from_filemanager` (line 151) removes those fields.

## 3. Impact / Exploit / Blast Radius

This is a feature completeness gap rather than a security or data-integrity issue.

**User impact:** No user can import a file from the file manager into the VOD pipeline through the UI. The workflow documented in VOD-014 — navigate to Files, right-click a video file, choose "Send to VOD", confirm title and visibility, then track the import progress — does not exist. Users who know the API can call `POST /ui/vod-bridge/import` via curl or Playwright, but the product interface is absent.

**Cross-feature impact:** The reciprocal "In Files" badge on video cards (showing that a VOD title originated from the file manager) is also absent, so even the discovery path from Videos → Files is broken.

**Risk of the current state:** Because the backend is live and correctly access-controlled (owner check at `vod_bridge.py:51`), there is no privilege escalation risk. The only consequence is that the feature is unreachable through the product UI.

**Blast radius:** Limited to users of the Files page and Videos page. No data is corrupted; existing file nodes and video records are unaffected.

## 4. Fix Design (code-level)

### 4.1 Extend `FileEntry` type

Add VOD bridge fields to `frontend/src/api/types.ts` after the existing `preview_reason` line:

```typescript
// frontend/src/api/types.ts — FileEntry additions
vod_linked?: boolean;
vod_video_id?: string | null;
vod_status?: string | null;          // "pending_encoding" | "published" | ...
vod_hls_manifest_url?: string | null;
vod_thumbnail_url?: string | null;
vod_duration_seconds?: number | null;
vod_linked_at?: number | null;
```

Add a `BridgeStatusOut` response type and `ImportToVodIn` request type to `types.ts`:

```typescript
export interface VodBridgeStatusOut {
  video_id: string;
  vod_status: string;
  file_path?: string | null;
  hls_manifest_url?: string | null;
  thumbnail_url?: string | null;
  duration_seconds?: number | null;
  width?: number | null;
  height?: number | null;
}

export interface VodImportToVodIn {
  file_path: string;
  title?: string;
  visibility?: "private" | "unlisted" | "public";
}

export interface VodImportToVodOut {
  video_id: string;
  status: string;
  file_path: string;
}
```

### 4.2 Add API endpoint wrappers

Create or extend `frontend/src/api/endpoints/vod.ts`:

```typescript
// frontend/src/api/endpoints/vod.ts — additions
import type { VodBridgeStatusOut, VodImportToVodIn, VodImportToVodOut } from "@/api/types";

export const importFileToVod = (body: VodImportToVodIn) =>
  api.post<VodImportToVodOut>("/ui/vod-bridge/import", body);

export const getVodBridgeStatus = (videoId: string) =>
  api.get<VodBridgeStatusOut>(`/ui/vod-bridge/status/${videoId}`);

export const unlinkVodBridge = (videoId: string) =>
  api.delete(`/ui/vod-bridge/${videoId}/link`);
```

### 4.3 Add "Send to VOD" context-menu item in `FileTable.tsx`

Extend `FileTableProps` with an optional `onSendToVod?: (file: FileEntry) => void` callback. In the `DropdownMenuContent`, add before the separator:

```tsx
{row.type === "file" && onSendToVod &&
  (row.content_type?.startsWith("video/") || row.preview_kind === "video") && (
  <>
    <DropdownMenuSeparator />
    <DropdownMenuItem onClick={() => onSendToVod(row)}>
      <Video className="h-4 w-4" />
      Send to VOD
    </DropdownMenuItem>
    {row.vod_linked && row.vod_video_id && (
      <DropdownMenuItem onClick={() => onWatchVod?.(row)}>
        <Play className="h-4 w-4" />
        Watch
      </DropdownMenuItem>
    )}
  </>
)}
```

The `onWatchVod` callback navigates to `/videos/{row.vod_video_id}`.

### 4.4 Add import dialog in `FilesPage.tsx`

Add a controlled `VodImportDialog` component (new file `frontend/src/pages/files/VodImportDialog.tsx`):

```tsx
// Minimal shape — fills in title/visibility fields, calls importFileToVod mutation
interface VodImportDialogProps {
  file: FileEntry | null;
  open: boolean;
  onClose: () => void;
}
```

Wire into `FilesPage.tsx`:

```tsx
const [vodImportTarget, setVodImportTarget] = useState<FileEntry | null>(null);
// ...
<FileTable
  ...
  onSendToVod={(f) => setVodImportTarget(f)}
/>
<VodImportDialog
  file={vodImportTarget}
  open={!!vodImportTarget}
  onClose={() => setVodImportTarget(null)}
/>
```

After a successful import, invalidate `["vod", "videos"]` and show a toast with the new `video_id`.

### 4.5 "In Files" badge on `VideosPage.tsx`

In the video card render, check `video.source_file_node_id` (already returned by the backend `VideoMetadataOut` model):

```tsx
{video.source_file_node_id && (
  <Badge variant="secondary" className="absolute top-2 left-2 gap-1 text-[10px]">
    <FolderOpen className="h-3 w-3" />
    In Files
  </Badge>
)}
```

### 4.6 Dev/Prod parity (SECOPS-007)

The backend bridge service (`app/services/vod_file_bridge.py`) already branches on `S.s3_endpoint_url` for local vs AWS S3 and uses `T.file_manager` (DynamoDB Local in dev, real DDB in prod). The frontend changes are pure HTTP wrappers through the Vite proxy and are environment-agnostic. No feature flag is required because `vod_bridge.py:14–16` already gate the endpoints on `S.vod_file_bridge_enabled`; the frontend should disable the "Send to VOD" menu item when the status endpoint returns 404, which is the correct degraded-mode behavior.

### 4.7 Backward compatibility

No migrations needed; the backend already writes `vod_video_id` fields to file-manager nodes on import. Adding optional `vod_*` fields to `FileEntry` is purely additive. Existing file entries that were never imported will have `vod_linked: undefined`, so all conditional renders must use `!!row.vod_linked`.

### Rollout

- **Effort:** L (large — multiple new components and API wrappers, plus E2E coverage). Estimated 3–5 engineering days: 1 day for `types.ts` + `vod.ts` additions, 1–2 days for `VodImportDialog` component + `FileTable` context-menu wiring, 1 day for `VideosPage` badge + navigation, 1 day for E2E test authoring.
- **Risk:** Low backend risk (no backend changes needed); moderate frontend risk due to new dialog state and the need for React Query cache invalidation across two page contexts (`["files", ...]` and `["vod", "videos"]`).
- **Sequencing:** Can ship independently. Recommend shipping the `types.ts` + `vod.ts` changes behind a feature flag evaluated client-side off the `S.vod_file_bridge_enabled` backend setting. If the bridge status endpoint returns 404, the "Send to VOD" menu item is hidden automatically (no extra flag needed in production). The "In Files" badge on VideosPage can ship in the same PR or a follow-on.
- **Rollback:** Remove the two new menu items and the import dialog; the backend remains unchanged. Any VOD videos imported during the rollout window remain valid video records; they simply lose the "Send to VOD" UI surface until the feature is re-enabled. Because the backend is stateless for this feature (all state is in DynamoDB file nodes and video records), rollback carries no data-loss risk.

### Acceptance criteria

The feature is complete when:
1. A video file in the file manager shows "Send to VOD" in its context menu.
2. Clicking it opens a dialog with a title field (pre-filled from the filename) and a visibility selector.
3. Submitting the dialog calls `POST /ui/vod-bridge/import` and on success shows a toast with the new video ID.
4. The bridged video appears in the Videos page with an "In Files" badge.
5. Clicking "Watch" from the file row navigates to the video player page for that video.
6. All five new Playwright tests (122.10–122.14) pass green in CI.
