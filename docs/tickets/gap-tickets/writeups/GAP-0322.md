> **Claim status**: PARTIALLY INCORRECT — the endpoint exists but under a different prefix

## 1. Summary & Classification

**Source ticket**: PLATFORM-005 (SEO / Open Graph metadata)
**Severity as filed**: HIGH
**Status**: Partially resolved — backend service fully implemented; crawler middleware absent
**Owning area**: SEO / metadata subsystem

The gap ticket claims that `app/routers/meta.py` does not exist, that no `meta_router` is registered in `app/main.py`, and that `_profile_meta`, `_event_meta`, `_post_meta`, `_video_meta` helpers are absent. All three claims are wrong about the core facts: a substantially richer router exists as `app/routers/seo_metadata.py`, is registered in `app/main.py:473`, and includes all four resource-type helpers plus a `_live_metadata` builder for live streams.

The genuine gap — shared with GAP-0323 — is that no mechanism routes social-media crawler User-Agent strings to the `/seo/meta-tags` endpoint so that bots receive server-injected OG tags instead of the empty React shell. The backend is ready; the front-door wiring is not.

**Related tickets**: GAP-0321 (locale field), GAP-0323 (crawler middleware — the actual missing piece).

### 2.3 Service implementation quality

`app/services/seo_metadata.py` (731 lines) fully implements all four resource-type helpers:

- **`_profile_metadata()`** (line 177): resolves `user_sub` via `_resolve_profile_identifier_to_user_sub()`, checks discoverability state before leaking any data, reads only public profile fields (`display_name`, `description`, `title`, `profile_photo_url`), builds JSON-LD `Person` schema.
- **`_event_metadata()`** (line 254): reads from `T.calendar`, enforces `_event_is_public()`, builds JSON-LD `Event` with `startDate`/`endDate`.
- **`_post_metadata()`** (line 371): enforces `status == "published"` and `visibility == "public"`, guards locked posts (never exposes body text or images of paywalled content), builds JSON-LD `Article`.
- **`_video_metadata()`** (line 495): checks video status and visibility, builds JSON-LD `VideoObject`.

Privacy protection is thorough: all four builders return `default_metadata()` (generic site fallback, `available: False`) for private, deleted, unlisted, or locked resources. HTML escaping is applied via `html.escape()` at render time (`render_meta_tags()`, line 644).

### 2.4 What is genuinely absent: crawler middleware

When Facebook, Twitter/X, Discord, or Slack fetch a URL like `/u/alice` or `/posts/p_abc123`, they send a HEAD or GET with a social-bot User-Agent string (e.g. `facebookexternalhit/1.1`, `Twitterbot/1.0`). The current architecture serves them the Vite-built React SPA (`index.html`), which contains only a bare `<title>Control Panel</title>` skeleton. The `react-helmet-async` tags that would populate `og:title` etc. are injected by JavaScript — which bots do not execute.

The backend has `GET /seo/meta-tags?path=/u/alice` ready to serve a fully-populated meta-tag block. Nothing intercepts the bot request and calls it.

### 2.5 React Helmet is present but bot-invisible

`frontend/src/pages/profile/PublicUserProfilePage.tsx:175-184` shows the client-side Helmet usage:

```tsx
<Helmet>
  <title>{displayName} | Control Panel</title>
  <meta property="og:title" content={displayName} />
  <meta property="og:description" content={bioText.slice(0, 200)} />
  <meta property="og:type" content="profile" />
  {publicFields.profilePhotoUrl && (
    <meta property="og:image" content={publicFields.profilePhotoUrl} />

</Helmet>
```

This injects the right tags into the DOM, but only after React hydrates and the profile API call resolves. Social crawlers (which abort after ~5 seconds and do not execute JS) see none of these. The `frontend/src/App.tsx:264-271` base Helmet block sets only generic site-level tags (`og:type = "website"`, `og:site_name`, `og:locale = "en_US"`) and no resource-specific content.

## 3. Impact / Exploit / Blast Radius

**Business impact** (no security/financial dimension):

- Every share of a profile, post, event, or video link on Facebook, Twitter, LinkedIn, Discord, or Slack produces a blank or generic preview card (`og:title = "Control Panel"`, no image, no description).
- Creator profiles are not indexable with structured data. Google's rich-results crawler will not associate JSON-LD `Person` or `Article` schema with the pages.
- The platform loses organic discovery traffic that would come from social sharing and search-result rich snippets.
- No user data is leaked — the service already enforces privacy guards — but SEO quality is degraded.

**Availability**: none. The missing middleware does not cause errors; it simply means bots receive the React shell.

**Blast radius**: all public-facing content types (profiles, posts, events, videos, live streams). Affects all production traffic from social crawlers immediately on launch.

## 4. Fix Design (code-level)

The backend service is complete. The fix is entirely at the request-routing layer: intercept requests from known social-crawler UAs and serve the pre-rendered `<meta>` tag block.

### 4.1 FastAPI middleware (production path)

Add a `CrawlerMetaMiddleware` to `app/main.py` that intercepts GET requests for public URL patterns when the User-Agent matches a social-bot fingerprint:

```python
# app/middleware/crawler_meta.py
import re
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import HTMLResponse

_BOT_UAS = re.compile(
    r"(facebookexternalhit|Twitterbot|LinkedInBot|Slackbot|Discordbot"
    r"|WhatsApp|TelegramBot|Pinterest|Googlebot|bingbot|DuckDuckBot"
    r"|Applebot|vkShare|W3C_Validator|ia_archiver)",
    re.IGNORECASE,
)
_PUBLIC_PATTERNS = re.compile(
    r"^/(u/[^/?#]+|posts/[^/?#]+|event/[^/?#]+/[^/?#]+"
    r"|videos/[^/?#]+|live/[^/?#]+)/?(\?.*)?$"
)

class CrawlerMetaMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        ua = request.headers.get("user-agent", "")
        path = request.url.path
        if (
            request.method == "GET"
            and _BOT_UAS.search(ua)
            and _PUBLIC_PATTERNS.match(path)
        ):
            from app.services.seo_metadata import metadata_for_path, render_meta_tags
            base = str(request.base_url).rstrip("/")
            meta = metadata_for_path(path, base_url=base)
            tags = render_meta_tags(meta)
            html = (
                "<!DOCTYPE html><html><head>\n"
                f"    {tags}\n"
                "</head><body></body></html>"
            )
            return HTMLResponse(html, status_code=200)
        return await call_next(request)
```

Register in `app/main.py` before the router includes:
```python
from app.middleware.crawler_meta import CrawlerMetaMiddleware
app.add_middleware(CrawlerMetaMiddleware)
```

### 4.2 Vite dev-mode equivalent (SECOPS-007 dev/prod parity)

In dev mode the Vite proxy intercepts requests. Add a `configureServer` plugin hook to `frontend/vite.config.ts` that performs UA detection and calls the backend `/seo/meta-tags` endpoint:

```ts
// In vite.config.ts plugins array:
{
  name: "crawler-meta-inject",
  configureServer(server) {
    const BOT_RE =
      /facebookexternalhit|Twitterbot|LinkedInBot|Slackbot|Discordbot|WhatsApp/i;
    const PUBLIC_RE =
      /^\/(u\/|posts\/|event\/|videos\/|live\/).+/;
    server.middlewares.use(async (req, res, next) => {
      const ua = req.headers["user-agent"] ?? "";
      const path = req.url?.split("?")[0] ?? "/";
      if (BOT_RE.test(ua) && PUBLIC_RE.test(path)) {
        const metaResp = await fetch(
          `http://localhost:8000/seo/meta-tags?path=${encodeURIComponent(path)}`
        );
        const tags = await metaResp.text();
        res.setHeader("Content-Type", "text/html; charset=utf-8");
        res.end(
          `<!DOCTYPE html><html><head>\n    ${tags}\n</head><body></body></html>`
        );
        return;
      }
      next();
    });
  },
},
```

Both paths call the identical `metadata_for_path()` logic. The dev plugin exercises the same code path as production, satisfying SECOPS-007.

### 4.3 Production reverse-proxy alternative

For NGINX/Caddy production deployments, the UA-sniffing can alternatively be done at the reverse proxy layer, forwarding bot requests to the FastAPI `/seo/meta-tags` endpoint. The FastAPI middleware approach is preferred for correctness during development and simpler integration testing.

### 4.4 Backward compatibility and feature flag

Introduce `SEO_CRAWLER_MIDDLEWARE_ENABLED` (`default: True`) in `app/core/settings.py`. When `False`, the middleware short-circuits to `call_next(request)`. This allows hot-disabling the feature if a bot-UA false positive interferes with a legitimate integration test.

## 5. Testing, Verification & Rollout

### 5.1 Regression test — fails before / passes after

```python
# tests/test_crawler_meta_middleware.py
import pytest
from httpx import AsyncClient

FACEBOOK_UA = "facebookexternalhit/1.1 (+http://www.facebook.com/externalhit_uatext.php)"
BROWSER_UA  = "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36"

@pytest.mark.anyio
async def test_bot_ua_profile_path_gets_meta_html(app_client):
    """A social bot UA on a public profile path must receive OG meta tags."""
    resp = await app_client.get(
        "/u/alice",
        headers={"user-agent": FACEBOOK_UA},
        follow_redirects=False,
    )
    assert resp.status_code == 200
    body = resp.text
    assert "<title>" in body
    assert 'property="og:title"' in body
    assert 'property="og:type"' in body

@pytest.mark.anyio
async def test_browser_ua_profile_path_gets_spa(app_client):
    """A normal browser UA must receive the React SPA shell, not meta HTML."""
    resp = await app_client.get(
        "/u/alice",
        headers={"user-agent": BROWSER_UA},
        follow_redirects=False,
    )
    # In test mode the SPA is not built; we check the response is NOT the meta page.
    # The middleware should pass through without short-circuiting.
    body = resp.text
    assert 'property="og:title"' not in body or resp.status_code != 200

@pytest.mark.anyio
async def test_bot_ua_private_path_does_not_leak(app_client):
    """/messages is a private path; even a bot UA must not receive user data."""
    resp = await app_client.get(
        "/messages",
        headers={"user-agent": FACEBOOK_UA},
    )
    # Middleware does not match /messages — bot passes through to normal handler.
    body = resp.text
    assert "og:title" not in body or "Control Panel" in body
```

Before the middleware is added, the first test fails (the response is either the SPA shell or a 404 with no OG tags). After adding `CrawlerMetaMiddleware`, all three pass.

### 5.5 Rollout, risks, and effort

- **Effort**: M (middleware implementation + Vite plugin + tests — estimated 4-6 hours of engineering).
- **Risk**: Low. The `_PUBLIC_PATTERNS` regex is conservative (only known public URL shapes). Misconfigured regex could serve the meta page to legitimate browser navigations, but `available: False` fallback means no data leak. Disable via `SEO_CRAWLER_MIDDLEWARE_ENABLED=0` if needed.
- **Rollback**: Set `SEO_CRAWLER_MIDDLEWARE_ENABLED=0` — no restart required if the settings object is re-read on each middleware dispatch call.
- **Sequencing**: This ticket (GAP-0322) confirms the backend is already done. GAP-0323 is the actionable work item. Both should be implemented in the same PR. GAP-0321 is already resolved and does not block this work.

### 5.6 Additional integration check: `/seo/robots.txt` and `/seo/sitemap.xml`

Beyond the core meta-tags capability, the backend also provides:

- `GET /seo/robots.txt` (`app/routers/seo_metadata.py:84`): returns a policy that allows `/u/`, `/posts/`, `/event/`, `/videos/`, `/live/` and disallows `/messages`, `/settings`, `/billing`, `/security`, `/admin`, `/files`. This should be exposed at the root `/robots.txt` by configuring a redirect or a separate route alias in the production reverse proxy.
- `GET /seo/sitemap.xml` (`app/routers/seo_metadata.py:89`): currently returns a minimal three-entry sitemap (`/`, `/login`, `/register`). The router can be extended with a paginated profile/post walker to generate a richer sitemap for Google Search Console indexing.

Both are purely additive improvements that do not require schema changes and are already guarded by the same privacy rules as the metadata endpoint. Including the robots.txt route alias in the same PR as the crawler middleware (GAP-0323) will give search engines a complete and correct policy in one deployment rather than two.

### 5.7 Verifying the service implementation is production-ready

Before shipping the crawler middleware, run the following checks against the existing SEO service:

1. `GET /seo/metadata?type=profile&id=alice` → assert `available: true`, `og.og:title` is populated, `json_ld["@type"] == "Person"`.
2. `GET /seo/metadata?type=post&id=p_locked_post` → assert `available: true`, `description` contains `"This post is locked"` and `json_ld["headline"]` does NOT contain the actual post body.
3. `GET /seo/metadata?type=profile&id=hidden_user` (a user with `discoverability_status = "hidden"`) → assert `available: false`, `title == "Control Panel"`.
4. `GET /seo/meta-tags?path=/u/alice` → assert HTML response contains `<meta property="og:title"`, `<link rel="canonical"`, and `<script type="application/ld+json">`.
5. `GET /seo/robots.txt` → assert `Allow: /u/` and `Disallow: /messages` are present.

All five can be run as pytest integration tests using the existing `moto`-backed DDB fixture without network access to AWS.
