# GAP-0235: `MultiHopSshBridge` Class Not Implemented — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; file:line citations are from
> the live codebase at `/home/ubuntu/testlogon`.

## 1. Summary & Classification

**Gap**: The INFRA-011 ticket design requires a `MultiHopSshBridge` class that
implements multi-hop SSH via Paramiko's `direct-tcpip` channel forwarding. No such
class exists anywhere in the repository. The `SshBastionPage.tsx` frontend
(registered at `/remote/bastion`) allows users to configure and store multi-hop
bastion paths, and `app/services/ssh_bastion.py` stores and resolves those paths
into ProxyJump representations — but the WebSocket `connect` handler in
`app/routers/browser_ssh_terminal.py` never reads a `bastion_path_id` field and
always instantiates only the single-hop `ParamikoSshBridge`. The resolve endpoint
produces an ssh_config block for use with a local ssh binary, but the browser-based
terminal cannot use that.

**Severity**: HIGH. Owning area: Infrastructure / SSH Terminal (INFRA-011).
**Status**: Open. **Source ticket**: INFRA-011. **Effort**: L.

**Claim accuracy**: Confirmed. The string `MultiHopSshBridge`, `multi_hop`,
`direct-tcpip`, and `resolve_connection_chain` do not appear in any Python file
under `app/`. `browser_ssh_terminal.py` line 895 always calls `_create_ssh_bridge`,
which unconditionally constructs a `ParamikoSshBridge`. The `path_id` /
`bastion_path_id` payload field is never validated or read in the connect handler.

**Impact**: Users who define multi-hop bastion chains in `SshBastionPage` cannot
actually connect through them in the browser terminal. The UI presents a working
management interface that is silently unconnected to the connection layer.

**Related tickets**: INFRA-011 (parent), GAP-0236 (missing `resolve_connection_chain`
function — a closely related gap in the same area), GAP-0233 / GAP-0234 (session
recording, same WebSocket handler), SECOPS-007 (dev/prod parity).


## 2. Current-State Investigation (root cause)

### `_create_ssh_bridge` — single-hop only, no path_id parameter

`app/routers/browser_ssh_terminal.py` lines 202–213:

```python
def _create_ssh_bridge(
    connect_info: dict[str, Any], cols: int, rows: int
) -> ParamikoSshBridge:
    return ParamikoSshBridge(
        host=connect_info["host"],
        port=connect_info["port"],
        username=connect_info["username"],
        auth_type=connect_info["authType"],
        password=connect_info.get("password"),
        private_key=connect_info.get("privateKey"),
        passphrase=connect_info.get("passphrase"),
        cols=max(cols, 80),
        rows=max(rows, 24),
    )
```

There is no `bastion_path_id` field, no call to `ssh_bastion.resolve_path`, and
no conditional to select a multi-hop bridge.

### Connect handler — path_id never read

The `msg_type == "connect"` validation path calls `_validate_connect_payload`
(line 635) and then `_create_ssh_bridge` (line 895). `_validate_connect_payload`
validates only `host`, `port`, `username`, `authType`, and credential fields.
A `bastion_path_id` field in the connect payload would be silently ignored.

### `ParamikoSshBridge` — direct connection only

`ParamikoSshBridge.connect()` (line 111) calls `client.connect(...)` directly:

```python
client.connect(
    hostname=self._host,
    port=self._port,
    username=self._username,
    ...
)
```

Paramiko's `direct-tcpip` channel forwarding (which enables multi-hop tunnelling)
is not used. For a multi-hop connection, the correct flow is:
1. Connect Paramiko client to hop N.
2. Open a `direct-tcpip` channel through hop N to hop N+1's address.
3. Wrap that channel in a new Paramiko `Transport`.
4. Repeat for each subsequent hop.
5. Invoke a shell on the final transport.

### ssh_bastion service — stores and resolves chains but cannot execute them

`app/services/ssh_bastion.py` lines 349–415 implement `resolve_path`, which
produces a `proxy_jump`, `ssh_command`, and `ssh_config` for a stored chain. This
output is useful for copy-pasting into a local terminal but is not usable by the
in-process Paramiko bridge. The service makes no call to Paramiko and has no
`connect` or `open_channel` logic.

### Frontend — SshBastionPage cannot initiate a WebSocket SSH session

`SshBastionPage.tsx` (registered at `App.tsx` line 374 as `/remote/bastion`)
allows creating and resolving bastion paths. The `resolveMut` mutation calls
`resolveBastionPath(pathId)` and shows the ssh_config in a dialog. There is no
"Connect" button that would open a WebSocket SSH terminal session using the path.
Users must manually copy the ssh_command and run it in a local terminal.

### Dev vs prod parity (SECOPS-007)

`ParamikoSshBridge` uses the `paramiko` library directly; there is no mock/real
branch for the SSH connection itself. The `MultiHopSshBridge` implementation must
follow the same pattern: pure Paramiko, no infrastructure-level branching. The
destination-policy enforcement (`_enforce_destination_policy`, line 452) must be
applied to all hops in the chain, not just the final target.


## 3. Impact / Exploit / Blast Radius

**Functional impact**: The "SSH Bastion Paths" feature is entirely non-functional at
the connection layer. Users who spend time configuring multi-hop routes in the UI
discover they cannot use them to connect. The only output (ssh_config) requires
a local ssh binary, defeating the purpose of a browser-based terminal.

**Security note**: If `MultiHopSshBridge` is implemented without applying
`_enforce_destination_policy` to intermediate hops, a user could craft a chain
where the final target bypasses the host/port policy via a trusted bastion. Each hop
in the chain must be individually checked.

**No active vulnerability**: The absence of the feature means no multi-hop
connections are made at all — users cannot exploit an unimplemented bridge.

**Blast radius**: All users of the browser SSH terminal feature who have bastion
paths configured. The management UI and storage layer work correctly; only the
actual connection is non-functional.


## 4. Fix Design (code-level)

### 4.1 `MultiHopSshBridge` class

Add to `app/routers/browser_ssh_terminal.py` after `ParamikoSshBridge` (line 200):

```python
class MultiHopSshBridge:
    """SSH bridge that tunnels through one or more bastion hosts using
    Paramiko direct-tcpip channels.

    ``hops`` is a list of dicts, each with:
      hostname, port, username, auth_type, password, private_key, passphrase.
    The last element is the target; all preceding elements are jump hosts.
    """

    def __init__(
        self,
        *,
        hops: list[dict[str, Any]],
        cols: int,
        rows: int,
    ) -> None:
        assert len(hops) >= 2, "MultiHopSshBridge requires at least 2 hops"
        self._hops = hops
        self._cols = cols
        self._rows = rows
        self._clients: list[Any] = []      # paramiko.SSHClient per hop
        self._channel: Any | None = None
        self._closed = False
        self._output_chunks: list[str] = []
        self._lock = threading.Lock()
        self._reader_thread: threading.Thread | None = None

    def _auth(self, client: Any, hop: dict[str, Any], paramiko: Any) -> None:
        """Attach credentials to a paramiko client."""
        kw: dict[str, Any] = {
            "hostname":     hop["host"],
            "port":         hop["port"],
            "username":     hop["username"],
            "look_for_keys": False,
            "allow_agent":  False,
            "timeout":      10,
        }
        if hop.get("auth_type") == "private_key":
            # Reuse the key-loading logic from ParamikoSshBridge
            kw["pkey"] = ParamikoSshBridge._load_private_key_static(
                hop.get("private_key", ""),
                hop.get("passphrase"),
                paramiko,
            )
        else:
            kw["password"] = hop.get("password")
        client.connect(**kw)

    def connect(self) -> None:
        try:
            import paramiko
        except ImportError as exc:
            raise BrowserSshError(
                "ssh_unavailable",
                "SSH support is unavailable on this server.",
            ) from exc

        try:
            # Connect to the first hop directly
            first = self._hops[0]
            client0 = paramiko.SSHClient()
            client0.set_missing_host_key_policy(paramiko.AutoAddPolicy())
            self._auth(client0, first, paramiko)
            self._clients.append(client0)

            # Tunnel through each subsequent hop via direct-tcpip
            for i in range(1, len(self._hops)):
                prev_client = self._clients[-1]
                current_hop = self._hops[i]
                transport = prev_client.get_transport()
                dest_addr = (current_hop["host"], current_hop["port"])
                local_addr = ("127.0.0.1", 0)
                channel = transport.open_channel(
                    "direct-tcpip", dest_addr, local_addr, timeout=10
                )
                new_client = paramiko.SSHClient()
                new_client.set_missing_host_key_policy(paramiko.AutoAddPolicy())
                new_transport = paramiko.Transport(channel)
                new_transport.start_client(timeout=10)
                # Authenticate on the new transport
                new_client._transport = new_transport
                hop_info = current_hop
                if hop_info.get("auth_type") == "private_key":
                    key = ParamikoSshBridge._load_private_key_static(
                        hop_info.get("private_key", ""),
                        hop_info.get("passphrase"),
                        paramiko,
                    )
                    new_transport.auth_publickey(hop_info["username"], key)
                else:
                    new_transport.auth_password(
                        hop_info["username"], hop_info.get("password", "")
                    )
                self._clients.append(new_client)

            # Open shell on the final transport
            final_transport = self._clients[-1].get_transport() \
                if hasattr(self._clients[-1], "get_transport") \
                else self._clients[-1]._transport
            shell_channel = final_transport.open_session()
            shell_channel.get_pty(
                term="xterm-256color",
                width=self._cols,
                height=self._rows,
            )
            shell_channel.invoke_shell()
            shell_channel.settimeout(0.0)
            self._channel = shell_channel
            self._reader_thread = threading.Thread(
                target=self._reader_loop, daemon=True
            )
            self._reader_thread.start()

        except (Exception,) as exc:
            self.close()
            if isinstance(exc, BrowserSshError):
                raise
            raise BrowserSshError(
                "connect_failed",
                f"Multi-hop SSH connection failed: {exc}",
            ) from exc

    # _reader_loop, poll_output, send_input, resize, close —
    # identical to ParamikoSshBridge; extract to a shared mixin or copy.
    ...
```

A `_load_private_key_static` class method should be extracted from
`ParamikoSshBridge._load_private_key` to avoid duplication.

### 4.2 `_create_multihop_bridge` factory

```python
def _create_multihop_bridge(
    hops: list[dict[str, Any]], cols: int, rows: int

    """Build a MultiHopSshBridge from a resolved bastion chain.

    Each element of ``hops`` must have the same shape as the validated
```

### 4.3 `_validate_connect_payload` — add `bastion_path_id`

In `_validate_connect_payload` (line 635), add optional field handling:

```python
# Allow callers to specify a stored bastion path instead of a direct host.
bastion_path_id = payload.get("bastionPathId") or payload.get("bastion_path_id")
normalized["bastion_path_id"] = str(bastion_path_id).strip() if bastion_path_id else ""
```

When `bastion_path_id` is provided, `host`, `port`, and `username` may be omitted
(they will be taken from the resolved chain's target hop).

### 4.4 Wire into the WebSocket `connect` handler

In the connect handler success path (line 895), replace:

```python
ssh_bridge = _create_ssh_bridge(normalized, session_size["cols"], session_size["rows"])
```

with:

```python
bastion_path_id = normalized.get("bastion_path_id", "")
if bastion_path_id:
    from app.services.ssh_bastion import resolve_path, BastionPathNotFound, ChainValidationError
    try:
        resolved = resolve_path(session_user_sub, bastion_path_id)
    except (BastionPathNotFound, ChainValidationError) as exc:
        raise BrowserSshError("bastion_not_found", str(exc)) from exc

    # Apply destination policy to EVERY hop in the chain
    for hop in resolved["chain"]:
        policy_err = _enforce_destination_policy(
            {"host": hop["hostname"], "port": hop["port"]}
        )
        if policy_err:
            raise BrowserSshError(
                str(policy_err.get("code") or "policy_denied"),
                str(policy_err.get("message") or "Bastion hop denied by policy"),
            )

    # Map chain entries to the bridge hop format
    hop_dicts = [
        {
            "host":       h["hostname"],
            "port":       h["port"],
            "username":   h["username"] or normalized.get("username", ""),
            "auth_type":  normalized.get("authType", "password"),
            "password":   normalized.get("password"),
            "private_key": normalized.get("privateKey"),
            "passphrase": normalized.get("passphrase"),
        }
        for h in resolved["chain"]
    ]
    ssh_bridge = _create_multihop_bridge(hop_dicts, session_size["cols"], session_size["rows"])
    session_host = f"chain:{bastion_path_id}:{resolved['target']['hostname']}"
else:
    ssh_bridge = _create_ssh_bridge(normalized, session_size["cols"], session_size["rows"])
```

### 4.5 Frontend — add "Connect" button to SshBastionPage

In `SshBastionPage.tsx`, add a "Connect" button per path that opens the browser
SSH terminal with the `bastion_path_id` pre-filled in the connect payload:

```tsx
<Button
  size="sm"
  onClick={() => navigate(`/browser-ssh?bastionPathId=${p.path_id}`)}
  data-testid="bastion-connect"
>
  Connect
</Button>
```

The browser SSH terminal page reads the query parameter and auto-populates the
connect form with `bastion_path_id`.

### 4.6 Dev/Prod parity (SECOPS-007)

`MultiHopSshBridge` uses Paramiko exclusively — no AWS SDK calls, no mock/real
branch. Destination-policy enforcement is applied to each hop using the existing
`_enforce_destination_policy` helper, which already applies to both mock and real
paths. No special dev-mode handling is required.

### Alternatives considered

- **ProxyJump via subprocess `ssh`**: Simpler to implement but requires `ssh` binary
  in the server container, creates a shell injection risk on hop hostnames, and
  bypasses the existing Python destination-policy checks. Rejected.
- **Single-hop only with user-provided ProxyJump**: The frontend already exposes the
  ssh_config for local use. This would not deliver an in-browser multi-hop terminal.
  Rejected as it does not fulfil INFRA-011.
- **Async transport instead of threading**: The current `ParamikoSshBridge` uses a
  background reader thread for non-blocking output. The `MultiHopSshBridge` follows
  the same threading pattern for consistency. A full asyncio Paramiko port is a
  longer-term refactor outside this ticket's scope.

### Rollout

- **Effort**: L (new class, handler changes, frontend button, E2E tests).
- **Risk**: Medium. Paramiko multi-hop via `direct-tcpip` works reliably but is more
  complex than direct SSH. Initial rollout should be behind a feature flag
  `SSH_MULTIHOP_ENABLED=false` (off by default) to allow staged enablement.
- **Sequencing**: Depends on GAP-0236 (a `resolve_connection_chain` helper may be
  needed to handle credential-per-hop scenarios). Can be developed in parallel;
  GAP-0236's helper is consumed inside `MultiHopSshBridge.connect()`.
- **Rollback**: Disable `SSH_MULTIHOP_ENABLED`. The single-hop `ParamikoSshBridge`
  path is unchanged.
- **Security**: Per-hop policy enforcement (section 4.4) is mandatory before
  enabling in production to prevent bastion-assisted policy bypass.
