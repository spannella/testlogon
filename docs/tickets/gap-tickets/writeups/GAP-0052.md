# GAP-0052: Min-CPM Floor Never Checked in Ad Serving Engine — Remediation Write-up

## 1. Summary & Classification

**Gap**: The `serve_ad` function in `app/services/ad_serving.py` ranks and selects ad
campaigns based on their `bid_cpm_cents` field but never checks whether that bid meets the
creator's configured minimum CPM (`min_cpm_cents`). A campaign that bids below the
creator's floor still wins an auction, overriding the creator's explicit monetization
threshold.

**Severity**: HIGH  
**Source ticket**: ADS-010  
**Owning area**: Ad Serving Engine  
**Status**: Open — claim confirmed against live code.

**One-line impact**: Every creator's `min_cpm_cents` setting is completely ineffective;
low-value ads serve regardless of what minimum rate a creator has configured.

**Related tickets**: GAP-0054 (per-creator revenue share also ignored), GAP-0046 (role
comparison bug in ad break authorization), ADS-003 (creator ad preferences feature).

---

## 2. Current-State Investigation (root cause)

### serve_ad fetches creator settings but reads only allow_ads

`app/services/ad_serving.py`, `serve_ad` function, lines 45–168.

Line 68:
```python
creator_settings = get_creator_ad_settings(creator_id)
```

Line 69:
```python
if not creator_settings.get("allow_ads", True):
    return _empty_response("creator_ads_disabled")
```

`get_creator_ad_settings` (`app/services/creator_ad_prefs.py`, lines 21–38) returns a
dict containing three fields: `allow_ads`, `allowed_ad_categories`, and `min_cpm_cents`.
The `serve_ad` function reads only `allow_ads` (line 69). The `min_cpm_cents` value is
silently discarded.

### Campaign loop uses bid_cpm but never compares to min_cpm_cents

Lines 78–126 iterate over active campaigns. The bid CPM is read at lines 119–120:

```python
bid_cpm = int(campaign.get("bid_cpm_cents", 500))
score = bid_cpm * 1.0
```

This value is used purely for scoring. There is no comparison against
`creator_settings["min_cpm_cents"]` before adding the campaign to `candidates`. A campaign
with `bid_cpm_cents=1` will be selected over a house ad even if the creator has set
`min_cpm_cents=200`.

### min_cpm_cents is correctly stored and returned

`creator_ad_prefs.py`, line 36:
```python
"min_cpm_cents": int(item.get("min_cpm_cents", 0)),
```

The default is 0 (no floor) if the setting has never been written. The PATCH endpoint
correctly persists updates (lines 41–62). The data layer is not broken; only the serving
engine ignores it.

### The creator_settings dict is populated correctly — the check simply never runs

The return dict from `get_creator_ad_settings` always includes `min_cpm_cents`:

```python
# creator_ad_prefs.py lines 31–37
return {
    "allow_ads": item.get("allow_ads", True),
    "allowed_ad_categories": item.get("allowed_ad_categories", []),
    "min_cpm_cents": int(item.get("min_cpm_cents", 0)),
    "updated_at": item.get("updated_at"),
}
```

So `creator_settings["min_cpm_cents"]` is populated and available. The bug is not that
the field is missing from the settings response, but that `serve_ad` never reads it after
line 69. This makes the fix surgical: one comparison added in the campaign scoring block.

### The UPDATE endpoint for min_cpm_cents is fully functional

`update_creator_ad_settings` (`creator_ad_prefs.py`, lines 41–62) correctly persists
`min_cpm_cents` to DynamoDB when a creator calls `PATCH /ui/ads/creator/settings`. The
storage layer is working; only the enforcement at serve time is missing.

### How the mis-ranking manifests for creators

Consider a creator who sets `min_cpm_cents=500` ($5 CPM floor). An active campaign with
`bid_cpm_cents=50` ($0.50 CPM) passes all existing checks (budget, targeting, frequency).
Since no floor check exists, this campaign gets `score=50.0` and can win the auction over
a house ad. The creator then sees a $0.50 CPM ad on their content that earns them about
$0.035 per impression — 93% below their stated floor.

### Allowed ad categories also not enforced (related, not this ticket)

Line 69 checks `allow_ads` but the `allowed_ad_categories` list from the same settings
dict is also never consulted in the serving loop (covered by GAP-0042). That is a
companion gap but distinct from this one.

## 3. Impact / Exploit / Blast Radius

**Creators** who have set a minimum CPM to ensure they only show premium ads receive no
protection. A `$0.01 CPM` remnant ad network campaign will serve on their content with the
same priority as a `$10 CPM` premium campaign if both pass the budget, targeting, and
frequency checks. The creator's explicit monetization setting is betrayed.

**Financial consequence**: A creator expecting a minimum `$2.00 CPM` revenue floor may
actually be paid at `$0.01 CPM` rates for a significant fraction of their impressions.
If `min_cpm_cents` was the contractual basis for a partnership agreement, the platform has
a breach-of-contract exposure.

**Exploit path**:
1. Advertiser creates a campaign with `bid_cpm_cents=1` (below any reasonable floor).
2. Creator has `min_cpm_cents=500` (requires $5 CPM floor).
3. Campaign passes all existing checks (budget, targeting, frequency cap).
4. Ad serves on creator's content.
5. Creator is credited `(1 * 0.70) // 1000 = 0` cents per impression (effectively zero),
   while their settings claimed they would receive at least $5 CPM.

**Blast radius**: Every creator with a non-zero `min_cpm_cents` setting. Because the
default is 0, creators who have never configured this are unaffected. But any creator who
deliberately set a floor to protect their brand or revenue is running with a silently broken
guarantee.

## 4. Fix Design (code-level)

### Minimal targeted fix

The minimum change is to add a `min_cpm_cents` check inside the campaign iteration loop,
immediately after the bid CPM is extracted and before the campaign is added to candidates.
This requires no schema change, no new service call (the creator settings are already
loaded at the top of `serve_ad`), and no database round-trip.

```python
# app/services/ad_serving.py, serve_ad, inside the campaign loop

# Score: bid_cpm * relevance (mock relevance = 1.0)
bid_cpm = int(campaign.get("bid_cpm_cents", 500))

# Enforce creator's minimum CPM floor (ADS-010 / GAP-0052)
min_cpm = int(creator_settings.get("min_cpm_cents", 0))
if min_cpm > 0 and bid_cpm < min_cpm:
    continue  # Campaign bid is below creator's minimum; skip

score = bid_cpm * 1.0
```

The `creator_settings` variable is in scope from line 68. No additional imports or
service calls are needed. The guard only activates when `min_cpm > 0` so that creators
with the default (zero) floor are not affected.

### Full ad settings path (recommended)

The ticket description calls for using `get_full_ad_settings(creator_id)` from
`app/services/content_ad_controls.py` instead of the base `get_creator_ad_settings`. The
full settings path also returns `revenue_share_bps` which will be needed by GAP-0054. Since
both gaps touch the same function, change the call at line 68 once:

```python
# Import at top of serve_ad (within the function body, as the existing imports are)
from app.services.content_ad_controls import get_full_ad_settings

creator_settings = get_full_ad_settings(creator_id)  # includes min_cpm_cents + revenue_share_bps
```

`get_full_ad_settings` calls `get_creator_ad_settings` internally and adds `revenue_share_bps`
(lines 61–75 of `content_ad_controls.py`). The return dict includes all three fields.
Changing to this call enables both GAP-0052 (min CPM) and GAP-0054 (revenue share) with
a single import change, and the min-CPM filter guard above then reads from the same dict.

### Fail-open behavior

If `get_full_ad_settings` raises (e.g., DynamoDB unavailable), the exception bubbles to
the existing `try/except` at the top of `serve_ad`'s creator block. The recommendation is
to catch and default to `min_cpm_cents=0` (fail open for serving, conservative for
filtering) by wrapping the call:

```python
try:
    creator_settings = get_full_ad_settings(creator_id)
except Exception:
    creator_settings = {"allow_ads": True, "min_cpm_cents": 0}
```

This preserves current behavior if the settings read fails.

### Dev / Prod parity (SECOPS-007)

The fix introduces no new AWS services or external calls. It reads an existing DynamoDB
record through `T.billing` (already wired via `app/core/tables.py`). In dev the table is
DynamoDB Local; in prod it is real DynamoDB. The same code path executes in both
environments. No `if dev_mode:` branches are needed. SECOPS-007 is satisfied.

### Alternatives considered

**Option A — Enforce at billing time, not serving time**: Reject the charge if the bid is
below `min_cpm_cents`. This would allow the ad to serve but refund/void the charge.
Rejected: creators expect that subfloor ads *not serve at all*, not that they serve and get
billed incorrectly. Serving-time enforcement is semantically correct.

**Option B — Store min_cpm_cents on the campaign record and filter at campaign load time**:
Requires a schema change and a data migration. Rejected as disproportionate to the fix.

## 5. Testing, Verification & Rollout

### Regression test (pytest — offline, fails before / passes after)

```python
# tests/services/test_serve_ad_min_cpm.py
import pytest
from unittest.mock import patch, MagicMock


def _make_campaign(bid_cpm: int) -> dict:
    return {
        "campaign_id": "c1",
        "account_id": "acct1",
        "bid_cpm_cents": bid_cpm,
        "budget_type": "lifetime",
        "budget_cents": 100_000,
        "lifetime_spent_cents": 0,
    }


def _creator_settings(min_cpm: int) -> dict:
    return {"allow_ads": True, "allowed_ad_categories": [], "min_cpm_cents": min_cpm}


def _mock_serve_infrastructure(campaign, creator_settings):
    """Patch all external calls in serve_ad so only CPM logic runs."""
    patches = [
        patch("app.services.ad_campaigns.list_campaigns_by_status", return_value=[campaign]),
        patch("app.services.ad_creatives.list_approved_creatives",
              return_value=[{"creative_id": "cr1", "format": "native_post"}]),
        patch("app.services.ad_targeting.list_targeting_sets", return_value=[]),
        patch("app.services.creator_ad_prefs.is_advertiser_blocked", return_value=False),
        patch("app.services.content_ad_controls.get_full_ad_settings",
              return_value=creator_settings),
    ]
    # Patch frequency cap to always return False (not capped)
    patches.append(
        patch("app.services.ad_serving._is_frequency_capped", return_value=False)
    )
    return patches


@pytest.mark.parametrize("bid,floor,expect_filled", [
    (500, 0,   True),   # no floor — any bid passes
    (500, 200, True),   # bid above floor — passes
    (100, 200, False),  # bid below floor — must be filtered out
    (200, 200, True),   # bid exactly at floor — passes (inclusive)
    (1,   500, False),  # very low bid against high floor
])
def test_min_cpm_floor_enforced(bid, floor, expect_filled):
    from app.services.ad_serving import serve_ad

    campaign = _make_campaign(bid)
    settings = _creator_settings(floor)

    ctx_patches = _mock_serve_infrastructure(campaign, settings)
    for p in ctx_patches:
        p.start()
    try:
        result = serve_ad(
            surface="feed",
            content_type="post",
            creator_id="creator1",
            content_id="video1",
            slot_type="native_post",
            user_id="user1",
        )
        if expect_filled:
            assert result["filled"] is True
            assert result.get("is_house_ad") is not True, \
                f"bid={bid} floor={floor}: expected paid ad, got house ad"
        else:
            # When all campaigns are filtered out, serve_ad returns house ad or unfilled
            assert result.get("is_house_ad") is True or result["filled"] is False, \
                f"bid={bid} floor={floor}: sub-floor campaign must not serve"
    finally:
        for p in ctx_patches:
            p.stop()
```

**Before fix**: `test_min_cpm_floor_enforced[100-200-False]` fails because the subfloor
campaign is selected and `result["filled"]` is `True` with `is_house_ad=False`.

**After fix**: All five parametrized cases pass.

### Manual QA

1. Create an ad account and campaign with `bid_cpm_cents=50`.
2. Set creator `min_cpm_cents=200` via `PATCH /ui/ads/creator/settings`.
3. Call `GET /ui/ads/serve?surface=feed&creator_id=...`.
4. Expect `is_house_ad: true` (no eligible campaigns above floor).
5. Update campaign to `bid_cpm_cents=300`, repeat step 3.
6. Expect a real ad response with `is_house_ad: false`.
7. Check that the response for step 6 uses the correct `creative_id` from the campaign.
8. Set `min_cpm_cents=0` (reset floor) and confirm the sub-floor campaign now serves.

### Edge cases to validate

- **min_cpm_cents=0 (default)**: All campaigns pass the floor check regardless of bid; behavior is unchanged from current.
- **Multiple campaigns, some above and some below floor**: Only the above-floor campaigns enter the scoring pool. The highest-scoring above-floor campaign wins.
- **All campaigns below floor**: `candidates` ends up empty → `_house_ad_response("no_eligible_campaigns")` is returned. This is the correct behavior.
- **min_cpm_cents read fails (DDB unavailable)**: With the `get_full_ad_settings` wrapper's `try/except`, `min_cpm_cents` defaults to 0 (fail open). This allows all campaigns to serve rather than silently blocking all ads on DDB degradation. Document this fail-open behavior in a code comment.
- **Exact match (`bid_cpm == min_cpm`)**: The comparison `bid_cpm < min_cpm` means exact equality passes. A creator setting a floor of $5 CPM and a campaign bidding exactly $5 CPM should serve. Verify the `>=` semantics with a test case.

### Observability

Add a `logger.debug` line when a campaign is skipped for subfloor bid:
```python
logger.debug("campaign_below_min_cpm campaign=%s bid=%d min=%d",
             campaign["campaign_id"], bid_cpm, min_cpm)
```

Monitor the rate of floor-filtered campaigns to detect misconfigured floors.

### Rollout

- **Effort**: S (half a day of code + 1 day of tests)
- **Risk**: Low but non-zero — creators who set a high floor may suddenly see more house
  ads served on their content if many active campaigns fall below the floor. Audit
  `min_cpm_cents` values against active campaign bids before deploying.
- **Sequencing**: Coordinate with GAP-0054 (revenue share fix) since both benefit from
  changing `get_creator_ad_settings` to `get_full_ad_settings`.
- **Rollback**: Revert `serve_ad` change; no DynamoDB schema change, no migration needed.
