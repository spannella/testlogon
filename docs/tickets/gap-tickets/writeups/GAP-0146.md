# GAP-0146: `RecordingsPanel.tsx` Frontend Component Not Implemented — Remediation Write-up

> ~5 pages. Source ticket: CALL-010. No investigation doc exists; code verified directly.

## 1. Summary & Classification

**Claim verification: CONFIRMED.**  The gap ticket states `frontend/src/pages/messages/RecordingsPanel.tsx` does not exist and that post-call recording discovery relies entirely on an ephemeral upload toast.  Both assertions are correct: a filesystem search of `frontend/src/pages/messages/` confirms no file named `RecordingsPanel.tsx` is present, and `ConversationView.tsx:730-736` confirms that `toast.loading` / `toast.success` / `toast.error` are the only user-visible signals when a recording completes.

**Bug / Gap**: After a WebRTC call with recording enabled, the upload-complete toast is the sole in-product path for a user to learn a recording exists.  If the user misses the toast (phone call, tab in background, notification fatigue), there is no UI they can navigate to in order to find past recordings for that conversation.  The backend endpoint `GET /ui/messaging/messages/recordings?conversation_id={id}` is fully implemented and returns pageable metadata including pre-signed download URLs, but no frontend component ever calls it.

**Severity**: HIGH — the recording feature (CALL-009 / CALL-010) is otherwise complete; this gap leaves the user-facing half of the feature unusable without direct API access.

## 2. Current-State Investigation (Root Cause)

### 2.1 Backend Endpoint Is Present

`app/routers/call_recording.py:439–465` registers:

```
GET /ui/messaging/messages/recordings
  ?conversation_id=<id>    (optional)
  → RecordingListOut { items: RecordingMetadataOut[] }
```

When `conversation_id` is supplied, it queries the `ByConversationCreatedAt` GSI on the `CallRecordings` DynamoDB table (via `get_recordings_for_conversation()` at `app/services/call_recording_store.py:172`), filters to recordings where the requesting user appears in `participants`, sorts descending by `created_at`, and returns up to 50 items.  Each item carries:

- `recording_id`, `call_id`, `conversation_id`, `status`
- `duration_seconds`, `file_size_bytes`
- `download_url` (pre-signed S3 / mock URL, populated only when `status == "ready"`)
- `download_expires_at`
- `created_at`

The frontend API wrapper in `frontend/src/api/endpoints/messaging.ts:1081–1091` mirrors this structure exactly:

```typescript
// messaging.ts:1081
return api.get<{ items: Array<{
  recording_id: string;
  call_id: string;
  conversation_id: string;
  status: string;
  duration_seconds: number | null;
  file_size_bytes: number | null;
  created_at: number;
  download_url: string | null;
}> }>(`/ui/messaging/messages/recordings`, { conversation_id: conversationId });
```

A `getRecordingDownloadUrl(recordingId)` helper also exists at `messaging.ts:1093–1097` for refreshing expired download URLs.

### 2.2 Frontend Toast Is the Only UI Hook

`ConversationView.tsx:53` imports `useCallRecording`.  `ConversationView.tsx:697–704` instantiates it.  The only user-visible result of a completed upload is the `useEffect` at `ConversationView.tsx:729–737`:

```typescript
// ConversationView.tsx:729
React.useEffect(() => {
  if (callRecording.recordingState === "uploading") {
    toast.loading("Uploading call recording...", { id: "recording-upload" });
  } else if (callRecording.recordingState === "complete") {
    toast.success("Call recording saved.", { id: "recording-upload" });
  } else if (callRecording.recordingState === "error") {
    toast.error(`Recording failed: ${callRecording.error ?? "Unknown error"}`, { id: "recording-upload" });
  }
}, [callRecording.recordingState, callRecording.error]);
```

Sonner toasts auto-dismiss after ~4 seconds.  Once dismissed, the recording is irrecoverable through the UI.

### 2.3 Existing Panel Pattern

Every other "extra content" panel in `ConversationView.tsx` follows the same slot pattern: a `boolean` state variable (`scheduledOpen`, `hiddenOpen`, `pinsOpen`, `threadPanelOpen`, `participantsOpen`) toggled by a toolbar button or dropdown menu item, and a corresponding `<XxxPanel open={...} onOpenChange={...} conversationId={convoId} ... />` rendered near the end of the JSX tree (`ConversationView.tsx:1295–1340`).  A `RecordingsPanel` can slot in identically.

### 2.4 Feature Flag

`frontend/src/lib/featureFlags.ts` already exposes `isCallRecordingEnabled()`.  The panel should be conditionally rendered only when this flag is truthy — matching the same guard used for the recording toolbar button inside `<CallSessionOverlay>`.

### 2.5 Why It Breaks at Runtime

Without `RecordingsPanel`, there is no "Recordings" entry in the conversation toolbar/dropdown.  Opening `GET /ui/messaging/messages/recordings?conversation_id=X` manually in the browser returns a valid JSON payload, but the feature is invisible in the UI.  There is no runtime error — just a missing surface.

## 3. Impact / Blast Radius

**Functional**: Every user who successfully records a call and then dismisses (or never sees) the upload toast loses access to their recording permanently within the product UI.  The recording file still exists on S3 and the metadata is in DynamoDB, but there is no frontend path to retrieve it.

**Financial / Retention**: Recording is an explicitly advertised call feature.  Loss of discoverability directly reduces perceived value of the feature and may trigger support tickets or chargebacks from users who expected download access.

**Compounding factors**:
- No `call_recording_available` system message is written to the conversation timeline (CALL-009 gap 3.1), so there is also no in-message anchor that would let a user jump to a download link.
- The 50-item hard cap (`call_recording.py:467 recordings[:50]`) means even a future `RecordingsPanel` would silently truncate heavy users' history.

**Security**: No direct security exposure; the backend correctly enforces participant membership before returning recordings.  The missing UI is purely a discoverability failure.

## 4. Fix Design (Code-Level)

### 4.1 Create `frontend/src/pages/messages/RecordingsPanel.tsx`

The component is a Sheet (slide-in panel) following the exact pattern of `PinnedMessagesPanel.tsx` and `ScheduledMessages.tsx`.

```typescript
// frontend/src/pages/messages/RecordingsPanel.tsx
import * as React from "react";
import { useQuery } from "@tanstack/react-query";
import { Download, Video } from "lucide-react";
import {
  Sheet, SheetContent, SheetHeader, SheetTitle,
} from "@/components/ui/sheet";
import { Button } from "@/components/ui/button";
import { getConversationRecordings } from "@/api/endpoints/messaging";
import { isCallRecordingEnabled } from "@/lib/featureFlags";

interface Props {
  open: boolean;
  onOpenChange: (open: boolean) => void;
  conversationId: string;
}

export function RecordingsPanel({ open, onOpenChange, conversationId }: Props) {
  const { data, isLoading } = useQuery({
    queryKey: ["recordings", conversationId],
    queryFn: () => getConversationRecordings(conversationId),
    enabled: open && isCallRecordingEnabled(),
  });

  const items = data?.items ?? [];

  return (
    <Sheet open={open} onOpenChange={onOpenChange}>
      <SheetContent side="right" className="w-80 sm:w-96">
        <SheetHeader>
          <SheetTitle className="flex items-center gap-2">
            <Video className="h-4 w-4" /> Call Recordings
          </SheetTitle>
        </SheetHeader>
        <div className="mt-4 space-y-2 overflow-y-auto">
          {isLoading && (
            <p className="text-sm text-muted-foreground">Loading…</p>
          )}
          {!isLoading && items.length === 0 && (
            <p className="text-sm text-muted-foreground" data-testid="recordings-empty">
              No recordings for this conversation.
            </p>
          )}
          {items.map((rec) => (
            <div
              key={rec.recording_id}
              data-testid="recording-item"
              className="flex items-center justify-between rounded border p-3"
            >
              <div className="min-w-0">
                <p className="truncate text-sm font-medium">
                  {new Date(rec.created_at * 1000).toLocaleString()}
                </p>
                <p className="text-xs text-muted-foreground">
                  {rec.duration_seconds != null
                    ? `${Math.floor(rec.duration_seconds / 60)}m ${rec.duration_seconds % 60}s`
                    : "—"}
                  {rec.file_size_bytes != null
                    ? ` · ${(rec.file_size_bytes / 1_048_576).toFixed(1)} MB`
                    : ""}
                </p>
                <p className="text-xs capitalize text-muted-foreground">{rec.status}</p>
              </div>
              {rec.download_url && rec.status === "ready" && (
                <Button size="sm" variant="outline" asChild>
                  <a href={rec.download_url} download aria-label="Download recording">
                    <Download className="h-3 w-3" />
                  </a>
                </Button>
              )}
            </div>
          ))}
        </div>
      </SheetContent>
    </Sheet>
  );
}
```

### 4.2 Add `getConversationRecordings` Wrapper

The existing inline fetch in `messaging.ts:1081` is typed as an anonymous helper.  Promote it to a named export used by the panel:

```typescript
// frontend/src/api/endpoints/messaging.ts — add named export
export interface RecordingMetadataOut {
  recording_id: string;
  call_id: string;
  conversation_id: string;
  status: string;
  duration_seconds: number | null;
  file_size_bytes: number | null;
  created_at: number;
  download_url: string | null;
  download_expires_at?: number | null;
}

export async function getConversationRecordings(
  conversationId: string,
): Promise<{ items: RecordingMetadataOut[] }> {
  return api.get(`/ui/messaging/messages/recordings`, {
    conversation_id: conversationId,
  });
}
```

Also add `RecordingMetadataOut` to `frontend/src/api/types.ts` for cross-feature reuse.

### 4.4 Toast Enhancement

On `callRecording.recordingState === "complete"`, invalidate the recordings query to force a refresh, and make the toast actionable:

```typescript
// ConversationView.tsx:732 — enhanced
} else if (callRecording.recordingState === "complete") {
  queryClient.invalidateQueries({ queryKey: ["recordings", convoId] });
  toast.success("Call recording saved.", {
    id: "recording-upload",
    action: {
      label: "View",
      onClick: () => setRecordingsOpen(true),
    },
  });
}
```

This ensures (a) the panel is already populated when the user opens it after the toast appears and (b) they have a second chance to reach the panel if they missed the toast later.

### 4.5 Dev/Prod Parity (SECOPS-007)

No new environment branches are introduced.  The feature is gated entirely by the existing `VITE_CALL_RECORDING_ENABLED` frontend env var and the backend `CALL_RECORDING_ENABLED` flag.  Both flags are `1` in `.env.local.example`.  In production, S3 pre-signed URLs are generated from real AWS credentials; in dev, the mock `/mock/s3/` URL path is used.  The panel code is identical in both environments — no `dev_mode` branching.
