# GAP-0149: No Creator Rate Settings UI — Remediation Write-up

> ~5 pages. Source ticket: CALL-011. No investigation doc exists; code verified directly.

## 1. Summary & Classification

**Claim verification: CONFIRMED.**  The gap ticket states that `frontend/src/pages/settings/CallRateSettings.tsx` does not exist and that creators cannot configure their call rate through the platform UI.  Both assertions are correct: the file is absent from `frontend/src/pages/settings/` (verified by `ls`), no route for `settings/call-rate` exists in `frontend/src/App.tsx` (verified by `grep`), and no link to a call-rate settings page exists in `frontend/src/pages/settings/SettingsPage.tsx` (verified by `grep`).

The backend rate management endpoints are fully implemented: `POST /ui/calls/rates`, `PUT /ui/calls/rates`, `DELETE /ui/calls/rates`, and `GET /ui/calls/rates/{creator_id}` in `app/routers/call_billing.py:78–165`.  The frontend API wrappers `setCallRate`, `updateCallRate`, `deleteCallRate`, and `getCallRate` exist in `frontend/src/api/endpoints/callBilling.ts:57–67`.  The entire gap is a missing settings page and route.

**Severity**: HIGH — without this UI, creators cannot opt in to (or modify) paid calls via the platform.  They would need to hit the raw API directly, which is not a supported user flow.  The pay-per-minute feature is non-functional for creators.

**Owning area**: Settings / Calls / Billing / Frontend  
**Status**: Open — backend and API wrappers complete; settings page and route absent

**Related gaps**: GAP-0148 (rate badge for callers — display side of the same data), GAP-0147 (billing overlay — in-call display), CALL-011 §4.4

## 2. Current-State Investigation (Root Cause)

### 2.1 Backend Rate Endpoints

`app/routers/call_billing.py`:

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/ui/calls/rates/{creator_id}` | session | Get a creator's rate (public) |
| `POST` | `/ui/calls/rates` | session | Create own rate (first-time enable) |
| `PUT` | `/ui/calls/rates` | session | Update own rate |
| `DELETE` | `/ui/calls/rates` | session | Delete rate (disable paid calls) |

`CallRateIn` model (`:28–32`) validates:
- `rate_cents_per_minute`: int, ge=100 (min $1.00/min), le=10000 (max $100.00/min)
- `enabled`: bool, default `True`
- `min_balance_minutes`: int, ge=1, le=60, default 5
- `max_duration_minutes`: int, ge=1, le=480, default 120

`CallRateOut` (`:35–40`) adds `currency: str = "USD"`.

### 2.2 Frontend API Wrappers

`frontend/src/api/endpoints/callBilling.ts:15–67`:

```typescript
export interface CallRateIn {
  rate_cents_per_minute: number;
  enabled?: boolean;
  min_balance_minutes?: number;
  max_duration_minutes?: number;
}

export const setCallRate = (data: CallRateIn) =>
  api.post<CallRate>("/ui/calls/rates", data);

export const updateCallRate = (data: CallRateIn) =>
  api.put<CallRate>("/ui/calls/rates", data);

export const deleteCallRate = () =>
  api.del("/ui/calls/rates");
```

All three mutation wrappers exist and are typed.  None are currently called by any component.

### 2.3 Existing Settings Page Structure

`frontend/src/pages/settings/SettingsPage.tsx` renders language, appearance, and Jira integration cards.  There is no "Calls" or "Call Rate" section.  `frontend/src/App.tsx:383–390` lists all `/settings/*` routes — none reference `call-rate`.  The sidebar at `frontend/src/components/layout/Sidebar.tsx` has no call-rate link.

### 2.4 Pattern to Follow

All other settings sub-pages follow the same structure:
- A standalone `lazy`-imported page component under `frontend/src/pages/settings/`.
- A `<Route path="settings/xxx" element={<XxxPage />} />` in `App.tsx`.
- A link card or list item in `SettingsPage.tsx` or in the Sidebar settings section.

`frontend/src/pages/settings/WebhooksPage.tsx` is a good reference: it uses React Query for a GET, React Hook Form + Zod for validation, and separate `useMutation` hooks for create/update/delete.

## 3. Impact / Blast Radius

**Functional**: Creators who want to offer paid consultations via the platform have no UI path to enable the feature.  The backend stores rate data in the `billing` DynamoDB table under `sk=CALL_RATE`, but no tool exists in the product to write that row except the raw API.

**Revenue**: The pay-per-minute feature generates platform revenue (configurable platform fee bps, `call_billing_timer.py`).  Blocked creator adoption directly reduces platform revenue from this feature.

**Creator UX**: A creator who discovers the call rate feature via documentation but cannot find a settings page will assume the feature is broken or unavailable.

**Blast radius**: Contained to creators who would configure paid calls.  Callers are unaffected (they simply cannot initiate paid calls if no rates exist).

## 4. Fix Design (Code-Level)

### 4.1 Create `frontend/src/pages/settings/CallRateSettings.tsx`

The page handles three states: (a) no rate configured yet — show an "Enable paid calls" form; (b) rate configured and enabled — show current rate with edit and disable actions; (c) rate configured but disabled — show "Re-enable" option.

```typescript
// frontend/src/pages/settings/CallRateSettings.tsx
import * as React from "react";
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";
import { toast } from "sonner";
import { PageHeader } from "@/components/shared/PageHeader";
import { Card, CardContent, CardHeader, CardTitle, CardDescription } from "@/components/ui/card";
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";
import { Separator } from "@/components/ui/separator";
import { Switch } from "@/components/ui/switch";
import {
  getCallRate, setCallRate, updateCallRate, deleteCallRate,
  type CallRateIn,
} from "@/api/endpoints/callBilling";
import { useAuthStore } from "@/stores/authStore";

const QUERY_KEY = ["call-rate", "own"] as const;

const rateSchema = z.object({
  rateDollarsPerMinute: z.number().min(1).max(100),
  minBalanceMinutes: z.number().int().min(1).max(60),
  maxDurationMinutes: z.number().int().min(1).max(480),
  enabled: z.boolean(),
});

type RateFormValues = z.infer<typeof rateSchema>;

export default function CallRateSettings() {
  const userId = useAuthStore((s) => s.userId);
  const queryClient = useQueryClient();

  const { data: existing, isLoading } = useQuery({
    queryKey: QUERY_KEY,
    queryFn: () => getCallRate(userId ?? ""),
    enabled: !!userId,
    retry: false,
  });

  const hasRate = !!(existing?.rate_cents_per_minute);

  const form = useForm<RateFormValues>({
    resolver: zodResolver(rateSchema),
    values: existing
      ? {
          rateDollarsPerMinute: existing.rate_cents_per_minute / 100,
          minBalanceMinutes: existing.min_balance_minutes,
          maxDurationMinutes: existing.max_duration_minutes,
          enabled: existing.enabled,
        }
      : { rateDollarsPerMinute: 1.00, minBalanceMinutes: 5, maxDurationMinutes: 120, enabled: true },
  });

  const saveMutation = useMutation({
    mutationFn: (values: RateFormValues) => {
      const body: CallRateIn = {
        rate_cents_per_minute: Math.round(values.rateDollarsPerMinute * 100),
        enabled: values.enabled,
        min_balance_minutes: values.minBalanceMinutes,
        max_duration_minutes: values.maxDurationMinutes,
      };
      return hasRate ? updateCallRate(body) : setCallRate(body);
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: QUERY_KEY });
      // Also invalidate the per-partner badge query so callers see the new rate immediately
      queryClient.invalidateQueries({ queryKey: ["call-rate"] });
      toast.success("Call rate saved.");
    },
    onError: () => toast.error("Failed to save call rate."),
  });

  const deleteMutation = useMutation({
    mutationFn: deleteCallRate,
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: QUERY_KEY });
      queryClient.invalidateQueries({ queryKey: ["call-rate"] });
      toast.success("Paid calls disabled.");
    },
    onError: () => toast.error("Failed to disable paid calls."),
  });

  if (isLoading) {
    return <div className="p-6 text-sm text-muted-foreground">Loading…</div>;
  }

  return (
    <div className="mx-auto w-full max-w-2xl space-y-6 p-4 sm:p-6">
      <PageHeader
        title="Call Rate Settings"
        description="Configure your per-minute rate for paid calls."
      />

      <Card>
        <CardHeader>
          <CardTitle className="text-base">Pay-Per-Minute Rate</CardTitle>
          <CardDescription>
            Callers will see this rate before initiating a call and will be charged per minute.
            The platform retains a fee; the remainder is credited to your wallet.
          </CardDescription>
        </CardHeader>
        <Separator />
        <CardContent className="pt-4 space-y-4">
          <form
            onSubmit={form.handleSubmit((v) => saveMutation.mutate(v))}
            className="space-y-4"
          >
            <div className="grid grid-cols-2 gap-4">
              <div className="space-y-1">
                <Label htmlFor="rate">Rate ($/min)</Label>
                <Input
                  id="rate"
                  type="number"
                  step="0.01"
                  min="1"
                  max="100"
                  data-testid="rate-input"
                  {...form.register("rateDollarsPerMinute", { valueAsNumber: true })}
                />
                {form.formState.errors.rateDollarsPerMinute && (
                  <p className="text-xs text-destructive">
                    {form.formState.errors.rateDollarsPerMinute.message}
                  </p>
                )}
              </div>

              <div className="space-y-1">
                <Label htmlFor="minBalance">Min balance (minutes)</Label>
                <Input
                  id="minBalance"
                  type="number"
                  min="1"
                  max="60"
                  data-testid="min-balance-input"
                  {...form.register("minBalanceMinutes", { valueAsNumber: true })}
                />
              </div>

              <div className="space-y-1">
                <Label htmlFor="maxDuration">Max duration (minutes)</Label>
                <Input
                  id="maxDuration"
                  type="number"
                  min="1"
                  max="480"
                  data-testid="max-duration-input"
                  {...form.register("maxDurationMinutes", { valueAsNumber: true })}
                />
              </div>

              <div className="flex items-center gap-3 pt-5">
                <Switch
                  id="enabled"
                  checked={form.watch("enabled")}
                  onCheckedChange={(v) => form.setValue("enabled", v)}
                  data-testid="enabled-switch"
                />
                <Label htmlFor="enabled">Enabled</Label>
              </div>
            </div>

            <div className="flex gap-3 pt-2">
              <Button
                type="submit"
                disabled={saveMutation.isPending}
                data-testid="save-rate-button"
              >
                {hasRate ? "Save Changes" : "Enable Paid Calls"}
              </Button>

              {hasRate && (
                <Button
                  type="button"
                  variant="destructive"
                  disabled={deleteMutation.isPending}
                  data-testid="delete-rate-button"
                  onClick={() => {
                    if (confirm("Disable paid calls and remove your rate?")) {
                      deleteMutation.mutate();
                    }
                  }}
                >
                  Disable Paid Calls
                </Button>
              )}
            </div>
          </form>
        </CardContent>
      </Card>
    </div>
  );
}
```

### 4.4 Dev/Prod Parity (SECOPS-007)

`POST/PUT/DELETE /ui/calls/rates` write to the `billing` DynamoDB table — moto in dev, AWS DynamoDB in production. No mock paths or dev-only code are needed in the settings component.

### 5.3 Metrics / Observability

Standard backend request counters cover the `POST/PUT/DELETE /ui/calls/rates` endpoints.  After deploy, watch for `POST /ui/calls/rates` requests as a signal of creator adoption.  Zero requests after a week of availability suggests the settings page navigation path is not discoverable — consider adding a call-to-action in the calls UI.

### 5.4 Rollback

Remove the `<Route path="settings/call-rate" ...>` from `App.tsx` and the card from `SettingsPage.tsx`.  The lazy-imported `CallRateSettings.tsx` is never loaded.  Backend endpoints are unaffected and can remain registered.

### 5.5 Effort / Sequencing

**Effort**: M — one new page component (~130 lines), one lazy import + one route in `App.tsx`, one card in `SettingsPage.tsx`.  
Independent of GAP-0147 and GAP-0148 but provides the data that GAP-0148's badge displays.  Recommend landing GAP-0149 and GAP-0148 together so creators can set a rate and callers immediately see the badge.
