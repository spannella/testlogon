# GAP-0237: `ByGlobalStatus` GSI never added to `ec2_instances` or `k8s_pods` — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No prior
> investigation doc exists for this ticket.

## 1. Summary & Classification

**Bug**: The admin compute dashboard (INFRA-012) needs to query all EC2 instances or all K8s
pods across every user by status (e.g., retrieve all `running` instances platform-wide). The
intended access pattern uses a `ByGlobalStatus` GSI on both tables. That GSI was never added to
either table in `scripts/local-ddb-init.py`. As a result, `list_all_instances` and
`list_all_pods` in `app/services/admin_compute.py` fall back to full-table `scan` calls, which
are unbounded, unordered, and will time-out or exhaust provisioned read capacity as the
platform grows.

**Severity**: HIGH. The full-table scan path is a latency and cost bomb in production: at scale
a single admin dashboard page load triggers an unconstrained table scan over millions of items.
DynamoDB charges per read unit and scan reads every item, hitting the 1 MB read limit before
FilterExpression is applied — so a "running only" filter still pays for every terminated
instance.

**Source ticket**: INFRA-012. No prior investigation document.

**Owning area**: `scripts/local-ddb-init.py` (table creation), `app/services/admin_compute.py`
(query logic), `app/core/tables.py` (table handle bindings).

**Claim verdict**: Confirmed. The `ec2_instances` table definition at line 1772 of
`scripts/local-ddb-init.py` has `ByStatus` (per-user) and `ByCreatedAt` GSIs but no
`ByGlobalStatus`. The `k8s_pods` table at line 1849 likewise has `ByNamespace`, `ByStatus`
(per-user), and `ByCreatedAt` but no `ByGlobalStatus`. Both `list_all_instances` (line 99) and
`list_all_pods` (line 135) call `_scan_all`, a full-table `scan` loop, with no GSI query.

**Related tickets**: GAP-0238 (quota not enforced in k8s_launcher — same INFRA-012 scope),
GAP-0039 (per-account rate limit), SECOPS-007 (dev/prod parity).

## 2. Current-State Investigation (root cause)

### 2.1 Table definitions today

`scripts/local-ddb-init.py:1772`:
```python

    _resolve_table_name(S.ec2_instances_table_name, "ec2_instances"),
    "user_sub",
    "sk",
    gsi=[
        {"index_name": "ByStatus",    "partition_key": "user_sub", "sort_key": "status"},
        {"index_name": "ByCreatedAt", "partition_key": "user_sub", "sort_key": "created_at"},
    ],
    attr_types={"created_at": "N"},
)
```

`scripts/local-ddb-init.py:1849`:
```python
TableDef(
    _resolve_table_name(S.k8s_pods_table_name, "k8s_pods"),
    "user_sub",
    "sk",
    gsi=[
        {"index_name": "ByNamespace", "partition_key": "namespace", "sort_key": "created_at"},
        {"index_name": "ByStatus",    "partition_key": "user_sub",  "sort_key": "status"},
        {"index_name": "ByCreatedAt", "partition_key": "user_sub",  "sort_key": "created_at"},
    ],
    attr_types={"created_at": "N"},
)
```

Neither table has a GSI with `status` as the partition key across all users (i.e., with no
`user_sub` qualifier in the PK).

### 2.2 Admin compute query path

`app/services/admin_compute.py:62` — `_scan_all`:
```python
def _scan_all(
    table,
    *,
    item_filter: Callable[[Dict[str, Any]], bool] | None = None,
) -> List[Dict[str, Any]]:
    out = []
    kwargs: Dict[str, Any] = {}
    while True:
        resp = table.scan(**kwargs)
        for item in resp.get("Items", []):
            if item_filter is None or item_filter(item):
                out.append(item)
        lek = resp.get("LastEvaluatedKey")
        if not lek:
            break
        kwargs["ExclusiveStartKey"] = lek
    return out
```

`list_all_instances` (line 78) calls `_scan_all(T.ec2_instances, item_filter=_keep)` where
`_keep` filters by status, user_sub, and instance_type in Python after every DynamoDB read
page. For a table with 100k items, this reads every item — paid in full — even if only 20
match `status="running"`.

`list_all_pods` (line 117) does the same for `T.k8s_pods`.

### 2.3 Why no GSI was created

The `ByGlobalStatus` GSI requires `status` as the PK (not prefixed by `user_sub`). DynamoDB
allows a GSI PK to be any attribute, but the attribute must be declared in `attr_types` as `S`
(String) if it isn't the table key. The existing `attr_types` only declares numeric keys
(`created_at: N`). Adding the GSI also needs `status` declared as `"S"` (its default type, but
must be in `attr_types` when referenced in any GSI or LSI).

## 3. Impact / Exploit / Blast Radius

**Cost**: DynamoDB scan costs scale with total stored bytes, not result set size. A platform
with 1 million instance records (~500 bytes each) produces roughly 500 MB of scan data per
admin dashboard page load — approximately $0.125 per request in `us-east-1`. At 100 admin page
loads per day that is ~$12.50/day in wasted read capacity.

**Latency**: A 500 MB scan at DynamoDB speeds (~25 MB/s in burst) takes ~20 seconds. Admin
dashboards become unusable.

**Availability**: Full-table scans consume provisioned read capacity units. Under heavy scan
load, concurrent user-facing operations (e.g., launching instances, fetching pod lists) are
throttled with `ProvisionedThroughputExceededException`.

**Security**: The admin dashboard exists precisely to identify anomalous `running` compute
(rogue instances). A broken or slow query means admins cannot detect abuse in a timely manner.

**Blast radius**: Every call to `GET /admin/compute/instances` and
`GET /admin/compute/pods` (admin-only) triggers the full scan. No end-user-facing endpoints
are affected but every admin session taxes the production table.

## 4. Fix Design (code-level)

### 4.1 Add `ByGlobalStatus` GSI to both tables in `scripts/local-ddb-init.py`

**EC2 instances** (replace the current definition at line 1772):
```python
TableDef(
    _resolve_table_name(S.ec2_instances_table_name, "ec2_instances"),
    "user_sub",
    "sk",
    gsi=[
        {"index_name": "ByStatus",        "partition_key": "user_sub",  "sort_key": "status"},
        {"index_name": "ByCreatedAt",      "partition_key": "user_sub",  "sort_key": "created_at"},
        {"index_name": "ByGlobalStatus",   "partition_key": "status",    "sort_key": "created_at"},
    ],
    attr_types={"created_at": "N", "status": "S"},
)
```

**K8s pods** (replace the current definition at line 1849):
```python
TableDef(
    _resolve_table_name(S.k8s_pods_table_name, "k8s_pods"),
    "user_sub",
    "sk",
    gsi=[
        {"index_name": "ByNamespace",    "partition_key": "namespace", "sort_key": "created_at"},
        {"index_name": "ByStatus",       "partition_key": "user_sub",  "sort_key": "status"},
        {"index_name": "ByCreatedAt",    "partition_key": "user_sub",  "sort_key": "created_at"},
        {"index_name": "ByGlobalStatus", "partition_key": "status",    "sort_key": "created_at"},
    ],
    attr_types={"created_at": "N", "status": "S"},
)
```

Note: `status` must be added to `attr_types` as `"S"`. The sort key `created_at` is already
declared `"N"`.

### 4.2 Update `list_all_instances` and `list_all_pods` in `app/services/admin_compute.py`

```python
def list_all_instances(
    *,
    status: str | None = None,
    user_sub: str | None = None,
    instance_type: str | None = None,
    limit: int = 100,
    cursor: str | None = None,
) -> Dict[str, Any]:
    if status:
        # Fast path: query the ByGlobalStatus GSI directly.
        # Only need Python-side filter for user_sub / instance_type if provided.
        items: List[Dict[str, Any]] = []
        kwargs: Dict[str, Any] = {
            "IndexName": "ByGlobalStatus",
            "KeyConditionExpression": Key("status").eq(status),
            "ScanIndexForward": False,  # newest first via created_at sort key
        }
        lek = None
        while True:
            if lek:
                kwargs["ExclusiveStartKey"] = lek
            resp = T.ec2_instances.query(**kwargs)
            for item in resp.get("Items", []):
                if "instance_id" not in item:
                    continue
                if user_sub and item.get("user_sub") != user_sub:
                    continue
                if instance_type and item.get("instance_type") != instance_type:
                    continue
                items.append(item)
            lek = resp.get("LastEvaluatedKey")
            if not lek:
                break
    else:
        # No status filter: fall back to scan (acceptable — admins rarely list all statuses).
        def _keep(item: Dict[str, Any]) -> bool:
            if "instance_id" not in item:
                return False
            if user_sub and item.get("user_sub") != user_sub:
                return False
            if instance_type and item.get("instance_type") != instance_type:
                return False
            return True
        items = _scan_all(T.ec2_instances, item_filter=_keep)
        items.sort(key=lambda x: int(x.get("created_at", 0)), reverse=True)

    start = 0
    decoded = _decode_cursor(cursor)
    if decoded and isinstance(decoded.get("offset"), int):
        start = decoded["offset"]
    page = items[start:start + limit]
    next_cursor = _encode_cursor({"offset": start + limit}) if start + limit < len(items) else None
    return {"instances": [_instance_out(i) for i in page], "count": len(items), "cursor": next_cursor}
```

Apply the same pattern to `list_all_pods` (using `ByGlobalStatus` on `T.k8s_pods`).

### 4.3 Dev/Prod parity (SECOPS-007)

The GSI exists in both dev (DynamoDB Local, created by `local-ddb-init.py`) and production
(created by the same `TableDef` fed into the AWS Terraform/CDK provisioner). There is no
dev-only code path; the query uses the standard `boto3` `query` API that DynamoDB Local
implements identically to AWS DynamoDB. No feature flag needed.

The `attr_types` addition (`status: S`) is additive and does not affect existing items — all
items already store `status` as a string, so DynamoDB Local will index them immediately after
table re-creation (or after `UpdateTable` in production).

### 4.4 Migration in production

A GSI can be added to an existing DynamoDB table via `UpdateTable` with zero downtime. The GSI
backfill happens asynchronously; while `CREATING` the index is not yet queryable. Add a
readiness check: `list_all_instances` / `list_all_pods` should check `S.admin_compute_dashboard_enabled`
(already gating the feature) and fall back to scan until the GSI is in `ACTIVE` state.
DynamoDB Local does not support `UpdateTable`; the dev stack requires a `just restart`.

   Passes after fix: query hits ByGlobalStatus GSI and returns only matching items."""

    """list_all_instances(status='running') must call query on ByGlobalStatus, not scan."""

    result = list_all_instances(status="running")
