# GAP-0256: Admin Reviewer Queue Page Missing — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`.

## 1. Summary & Classification

**Gap**: No dedicated admin reviewer queue page exists for KYC proof-of-funds submissions. The file `frontend/src/pages/kyc/KycProofOfFundsReviewQueue.tsx` does not exist, and there is no route registered under `admin/kyc/proof-of-funds` in `frontend/src/App.tsx`.

- **Severity**: HIGH
- **Source ticket**: KYC-005
- **Area**: Frontend (admin compliance tooling) + minor backend (missing per-user admin fetch endpoint)
- **Status**: Confirmed — the gap exists exactly as described in the ticket.
- **Impact**: KYC compliance reviewers cannot access a proper reviewer queue UI. They cannot filter submissions by status, page through the queue, or adjudicate from a purpose-built admin view. The only review capability that exists lives on the user-facing page (`/kyc/proof-of-funds`) as a primitive inline section (no DataTable, no pagination, no dedicated admin route guard, not linked from the admin navigation).
- **Related tickets**: KYC-005 (parent feature), GAP-0257 (Financial Verification tab missing from case detail), KYC-008 (risk score consumer), SECOPS-007 (dev/prod parity).

**Claim verdict**: Confirmed exactly. `KycProofOfFundsReviewQueue.tsx` does not exist. The route `admin/kyc/proof-of-funds` is absent from `frontend/src/App.tsx`. The existing `KycProofOfFunds.tsx` at line 172 has an inline "Reviewer queue" section but it lacks DataTable, pagination, adjudication dialog pattern, and admin-role guard.

## 2. Current-State Investigation (root cause)

### 2.1 What exists

`frontend/src/pages/kyc/KycProofOfFunds.tsx` is a **user-facing** page registered at the route `kyc/proof-of-funds` (`frontend/src/App.tsx:464`). It contains two sections: a submission form (lines 98–145) and a "Reviewer queue" (lines 172–226). The reviewer queue section:

- Uses a plain `<select>` and button to load submissions — no React Query, no caching, no error handling.
- Renders a flat list of `<div>` rows with three inline `<button>` elements (Verify / More info / Reject).
- Uses raw HTML elements instead of the project's shadcn/ui `DataTable`, `Dialog`, `Badge` components.
- Has no admin-role guard — any authenticated user who navigates to the page can see and interact with the reviewer controls (the adjudication endpoint is protected server-side by `require_admin_or_root`, but the UI is entirely exposed).

### 2.2 What is missing

**Dedicated admin page file** (`frontend/src/pages/kyc/KycProofOfFundsReviewQueue.tsx`) does not exist. Every other KYC document type has a dedicated admin queue page:

- `KycDocumentReviewQueuePage.tsx` — registered at `admin/kyc/documents`
- `KycResidencyReviewQueuePage.tsx` — registered at `admin/kyc/residency`
- `KycIdScannerReviewQueuePage.tsx` — registered at `admin/kyc/id-scanner`
- `KycScreeningReviewQueuePage.tsx` — registered at `admin/kyc/screening`

The `admin/kyc/proof-of-funds` route is absent from `frontend/src/App.tsx` (lines 429–469 cover all other admin KYC routes).

**Missing backend endpoint**: The GAP-0257 companion ticket references `GET /ui/kyc/proof-of-funds/admin/submissions?user_sub=` for per-user admin lookups from the case detail page. This endpoint does not exist in `app/routers/kyc_proof_of_funds.py` (102 lines total). The router has `GET /review/by-status/{status}` (line 78) for status-based listing but nothing for per-user admin fetch.

### 2.3 Adjudication endpoint type annotation bug

`app/routers/kyc_proof_of_funds.py:90` declares the `adjudicate` endpoint parameter as `session: dict = Depends(require_admin_or_root)`, but `require_admin_or_root` (defined in `app/auth/policy.py:67`) returns `AuthenticatedUser`, not `dict`. The code at line 97 then calls `session.sub`, which works at runtime because FastAPI injects the actual `AuthenticatedUser` object, but the misleading `dict` annotation violates project conventions and would break any static analysis or typed test fixtures.

### 2.4 Dev vs prod parity

The backend service (`app/services/kyc_proof_of_funds.py`) and DynamoDB table both follow SECOPS-007 patterns: DynamoDB Local is used in dev, real DynamoDB in prod, and all queries go through `app/core/tables.py`. No new AWS paths are needed for the review queue page. The fix is entirely frontend plus a backend endpoint addition that uses the existing `list_submissions_for_user` service function.

## 3. Impact / Exploit / Blast Radius

### 3.1 Compliance impact (primary)

The absence of a dedicated admin queue page means compliance reviewers have no operational UI to:

- List pending proof-of-funds submissions and triage them in priority order.
- Filter by status (`pending`, `verified`, `rejected`, `needs_more_info`, `expired`).
- View the declared amount, source category, risk score, and risk contribution for each submission before adjudicating.
- Adjudicate (approve/reject/request-more-info) from a safe, role-gated interface.

The inline reviewer section buried in the user-facing page `KycProofOfFunds.tsx` is non-discoverable for admin users, has no link from the admin navigation (`KycQueuePage.tsx` at `admin/kyc` does not link to it), and is functionally incomplete.

### 3.2 AML regulatory exposure

Proof-of-funds verification is a regulatory requirement for enhanced-due-diligence profiles. Without a functional reviewer queue, pending submissions stay in `pending` status indefinitely, causing:

- Affected users to remain blocked from tier upgrades or high-value transactions.
- Compliance audit failures if submissions cannot be reviewed within required timeframes (typically 5–10 business days under AML frameworks).
- Risk scores from `kyc_proof_of_funds` (consumed by KYC-008) remaining at the default `pending` contribution value (0) rather than progressing to `verified` (−10 risk reduction) or `rejected` (+15 risk increase).

### 3.3 Security surface (secondary)

The reviewer UI controls (Verify/Reject buttons) are exposed in the user-facing `KycProofOfFunds.tsx` page without a client-side role check. A regular user who discovers these buttons will receive a 403 from the backend, but the exposure is a UX violation and may confuse users who see adjudication controls in their own submission form.

## 4. Fix Design (code-level)

### 4.1 Backend: add `GET /admin/submissions?user_sub=` endpoint

Add one endpoint to `app/routers/kyc_proof_of_funds.py` to support per-user admin lookups (needed by GAP-0257's case detail tab):

```python
@kyc_proof_of_funds_router.get("/admin/submissions")
def admin_list_submissions_for_user(
    user_sub: str,
    _user: AuthenticatedUser = Depends(require_admin_or_root),
):
    return {"submissions": kyc_proof_of_funds.list_submissions_for_user(user_sub)}
```

Also fix the type annotation on `adjudicate` (line 90): change `session: dict` to `_user: AuthenticatedUser` and update line 97 from `session.sub` to `_user.sub`.

### 4.2 Frontend: new `KycProofOfFundsReviewQueue.tsx`

Create `frontend/src/pages/kyc/KycProofOfFundsReviewQueue.tsx` following the pattern of `KycResidencyReviewQueuePage.tsx`. The page should:

1. Use React Query `useQuery` to fetch submissions by status: `kycProofOfFundsApi.listByStatus(activeStatus)`.
2. Render a shadcn/ui `Tabs` bar with tabs: `pending | needs_more_info | verified | rejected | expired`.
3. Use the project's `DataTable` component (or a simple `Card`-wrapped table) to render rows showing: `submission_id` (truncated), `user_sub`, `source_category`, formatted `declared_amount_cents`, `score`, `risk_contribution` badge, `created_at` date.
4. Include an **Adjudicate Dialog** (shadcn `Dialog`) that opens on row click with decision radio buttons (verified / rejected / needs_more_info) and a `reviewer_note` textarea; calls `kycProofOfFundsApi.adjudicate()` on confirm and invalidates the query.
5. Guard with an `isAdmin` check from `useAuthStore` (following `KycQueuePage.tsx` pattern) so regular users navigating to the route see a 403 page rather than the queue.

### 4.3 Frontend: register route in App.tsx

In `frontend/src/App.tsx`, add after the existing `admin/kyc/screening` route (line 467):

```tsx
const KycProofOfFundsReviewQueue = lazy(
  () => import("@/pages/kyc/KycProofOfFundsReviewQueue")
);
// ...
<Route
  path="admin/kyc/proof-of-funds"
  element={<KycProofOfFundsReviewQueue />}
/>
```

### 4.4 Remove reviewer controls from user-facing page

Remove lines 172–226 from `frontend/src/pages/kyc/KycProofOfFunds.tsx` (the inline "Reviewer queue" section). This content belongs exclusively on the admin page. The user-facing page should show only the submission form and the user's own submission history.

### 4.5 Add navigation link

In the admin KYC navigation (e.g., `KycQueuePage.tsx` or the admin sidebar), add a link to `/admin/kyc/proof-of-funds` alongside the existing links to `/admin/kyc/documents`, `/admin/kyc/residency`, etc.

### 4.6 Dev/Prod parity (SECOPS-007)

No new AWS services are required. The backend uses DynamoDB Local in dev and DynamoDB in prod via `app/core/tables.py`. The deterministic scoring mock (`_deterministic_score`) is already gated behind `S.kyc_proof_of_funds_real_analysis_enabled` (default `False`). No environment-specific branching is needed in the new endpoint or page.

### 4.7 Backward compatibility

The new backend endpoint is purely additive (new URL, no changes to existing endpoints). The `adjudicate` type annotation fix does not change runtime behavior. The removal of reviewer UI from the user page is a UX-only change; users cannot call the adjudication endpoint regardless (server enforces `require_admin_or_root`).

### 5.1 Regression test (pytest, fails before / passes after)

Add `tests/test_kyc_proof_of_funds_admin_queue.py`:

```python
"""
Regression test for GAP-0256: admin submissions endpoint + adjudicate type fix.

Fails before the fix: GET /ui/kyc/proof-of-funds/admin/submissions returns 404 (no route).
Passes after the fix: endpoint exists and returns a submissions list.
"""
import pytest
from fastapi.testclient import TestClient
from fastapi import FastAPI
from app.routers.kyc_proof_of_funds import kyc_proof_of_funds_router
from app.auth.policy import require_admin_or_root
from app.auth.deps import AuthenticatedUser
from app.auth.roles import Role


def _admin_user():
    return AuthenticatedUser(sub="admin_sub", role=Role.ADMIN)


@pytest.fixture()
def client(monkeypatch):
    app = FastAPI()
    app.include_router(kyc_proof_of_funds_router)
    app.dependency_overrides[require_admin_or_root] = _admin_user
    # Monkeypatch service to avoid DynamoDB
    monkeypatch.setattr(
        "app.services.kyc_proof_of_funds.list_submissions_for_user",
        lambda user_sub: [{"submission_id": "pof_abc", "user_sub": user_sub, "status": "pending"}],
    )
    return TestClient(app)


def test_admin_list_submissions_for_user_exists(client):
    """Fails before fix (404), passes after endpoint is added."""
    resp = client.get("/ui/kyc/proof-of-funds/admin/submissions?user_sub=user_123")
    assert resp.status_code == 200
    assert resp.json()["submissions"][0]["user_sub"] == "user_123"


def test_adjudicate_type_annotation_uses_authenticated_user(client, monkeypatch):
    """Confirms session.sub → _user.sub fix: adjudicate sets reviewer_sub correctly."""
    captured = {}
    def fake_adjudicate(submission_id, *, decision, reviewer_sub, reviewer_note):
        captured["reviewer_sub"] = reviewer_sub
        return {"submission_id": submission_id, "status": decision}
    monkeypatch.setattr("app.services.kyc_proof_of_funds.adjudicate", fake_adjudicate)
    resp = client.post(
        "/ui/kyc/proof-of-funds/review/sub_001/adjudicate",
        json={"decision": "verified"},
    )
    assert resp.status_code == 200
    assert captured["reviewer_sub"] == "admin_sub"
```
