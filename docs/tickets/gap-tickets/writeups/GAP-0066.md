## 2. Current-State Investigation (root cause of the false-positive)

### What the gap audit expected

The ADS-017 ticket spec (sections 3.8–3.9) described a standalone page called
`OptimizationPanel.tsx` plus sub-components `RecommendationCards.tsx` and `ABTestResults.tsx`
living directly in `frontend/src/pages/ads/`, and an API wrapper named `adOptimization.ts` in
`frontend/src/api/endpoints/`.

### What was actually built

The implementation followed the spec but used slightly different naming conventions and
component decomposition:

**`frontend/src/pages/ads/AdOptimizationPanel.tsx`** (lines 1–227)
The main page component. It fetches recommendations, suggested bid, budget recommendation, and
A/B test results via React Query, and composes the sub-components:

```tsx
// AdOptimizationPanel.tsx:9-10
import AdOptimizationRecommendationCards from "@/components/ads/AdOptimizationRecommendationCards";
import AdOptimizationABTestResults from "@/components/ads/AdOptimizationABTestResults";
```

The sub-components were placed in `frontend/src/components/ads/` rather than in-page, which is
consistent with how `DaypartingGrid` and `FlightScheduler` are also housed in that directory.
The audit script apparently looked only inside `frontend/src/pages/ads/` and did not recurse
into `frontend/src/components/ads/`.

**`frontend/src/api/endpoints/adOptimization.ts`** (lines 1–97)
All seven API functions are present:
- `generateRecommendations` → `POST /ui/ads/optimization/campaigns/{id}/generate`
- `listRecommendations` → `GET /ui/ads/optimization/campaigns/{id}/recommendations`
- `applyRecommendation` → `POST …/recommendations/{recId}/apply`
- `dismissRecommendation` → `POST …/recommendations/{recId}/dismiss`
- `getABTestResults` → `GET …/ab-test`
- `getSuggestedBid` → `GET …/suggested-bid`
- `getBudgetRecommendation` → `GET …/budget-recommendation`
- `updateOptimizationConfig` → `PATCH …/optimization-config`

**Router wiring** (`frontend/src/App.tsx:205, 317`):
```tsx
const AdOptimizationPanel = lazy(() => import("@/pages/ads/AdOptimizationPanel"));
// …
<Route path="ads/optimization" element={<AdOptimizationPanel />} />
```

### Sub-component architecture

The gap ticket used the names `RecommendationCards.tsx` and `ABTestResults.tsx` — short names
without the `AdOptimization` prefix. Every ads-related sub-component in the codebase follows
the `Ad<Feature><SubComponent>` naming pattern:

| Pattern | Example |
|---|---|
| `Ad<Feature><SubComponent>` | `AdOptimizationRecommendationCards`, `AdOptimizationABTestResults` |
| `Ad<Feature><SubComponent>` | `DaypartingGrid` (in `components/ads/`) |

Both sub-components are fully functional:

- **`AdOptimizationRecommendationCards`** (80 lines): renders a list of recommendation cards
  with "Apply" and "Dismiss" buttons, action-label mapping (`pause_creative`,
  `reallocate_budget`, `adjust_bid`), severity badges (warning → destructive, else secondary),
  and per-recommendation status display. Passes `data-testid` attributes for Playwright testing.

- **`AdOptimizationABTestResults`** (59 lines): renders a two-variant CTR comparison card with
  lift percentage, p-value, statistical significance badge ("Significant — winner: variant X"
  vs "Not significant" vs "Needs more data"), and confidence level display.

Both are correctly imported into `AdOptimizationPanel.tsx` at lines 9–10 and rendered
conditionally based on query data.

### Residual risk surfaced during investigation

Although GAP-0066 itself is a false-positive, the investigation confirmed GAP-0067: when
`applyRecommendation` fires the `reallocate_budget` action, it writes a `creative_weights` map
onto the campaign DynamoDB record, but `ad_serving.py:_weighted_random_creative` (line 395)
ignores that map entirely and reads only per-creative `rotation_weight` fields. This means
the Apply button in `AdOptimizationPanel` silently has no observable effect on ad delivery for
the most common recommendation type. The UI correctly shows the recommendation status as
"applied" because the write to DynamoDB succeeds — only the serving engine's failure to read
the field makes the operation a no-op at runtime. That defect is documented and fixed in
**GAP-0067**.

### How the audit tooling produced a false-positive

The most likely explanation is that the gap-audit script used a simple `find` command looking
for exact filename matches in `frontend/src/pages/ads/`:

```bash
find frontend/src/pages/ads -name "RecommendationCards.tsx"  # returns nothing
find frontend/src/pages/ads -name "ABTestResults.tsx"        # returns nothing
find frontend/src/api/endpoints -name "adOptimization.ts"   # would have returned a hit
```

The sub-components in `frontend/src/components/ads/` were outside the search path, and the
`AdOptimization` prefix was not anticipated. A robust audit should search the entire
`frontend/src/` tree and match on export names (via `grep -r "export default"`) rather than
filenames.

## 3. Impact / Exploit / Blast Radius

### Current user-facing impact

Because the components exist and are routed, there is **no current user-facing outage** for
the optimization UI. Advertisers navigating to `/ads/optimization?campaign=<id>` will see the
panel, can generate recommendations, apply or dismiss them, view A/B test results, and update
optimization config.

### Indirect blast radius

1. **Wasted engineering review time** — the filed gap caused an audit cycle that consumed time
   for a non-issue. Every sprint that carries a false-positive HIGH gap displaces real defect
   triage time.
2. **Masking of GAP-0067** — the incorrect "entirely absent" classification may have led
   reviewers to deprioritise the related `creative_weights` bug, which is the real HIGH-severity
   defect. Applying a `reallocate_budget` recommendation currently has no observable effect on
   ad delivery (see GAP-0067 for full blast-radius analysis). The false-positive framing could
   cause engineers to mentally batch GAP-0066 and GAP-0067 as "ADS-017 frontend stuff to
   implement" rather than recognising GAP-0067 as an already-deployed backend bug.
3. **No financial, security, or data integrity impact** from GAP-0066 itself.

### Feature coverage assessment

Despite the false-positive, a full audit of the optimization UI's feature coverage reveals two
minor gaps worth noting for completeness (neither is HIGH severity):

| Feature | Status |
|---|---|
| Generate recommendations | Present — `POST .../generate`, "Run Optimization" button |
| List / display recommendations | Present — React Query, `AdOptimizationRecommendationCards` |
| Apply recommendation | Present — mutation + cache invalidation |
| Dismiss recommendation | Present — mutation + cache invalidation |
| A/B test results | Present — `AdOptimizationABTestResults`, two-variant CTR display |
| Suggested bid | Present — card with min/suggested/max + competition level |
| Budget recommendation | Present — card with desired-reach input |
| Optimization config | Present — CTR threshold input + "Enable Auto-Optimize" button |
| `reallocate_budget` effect on serving | **MISSING** — GAP-0067 (serving engine bug) |
| Auto-optimization background loop status | Not exposed in UI (informational gap, not HIGH) |

The only truly broken feature is GAP-0067 (the serving engine not consuming `creative_weights`).
Everything else the UI presents to the advertiser is functional end-to-end.
