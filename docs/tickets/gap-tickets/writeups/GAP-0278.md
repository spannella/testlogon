# GAP-0278: `list_templates` Uses a Full-Table Scan Instead of the `status-updated-index` GSI — Remediation Write-up

> Source ticket: KYC-017 · Severity: HIGH · Effort: S · Status: Open

## 1. Summary & Classification

**Gap**: `KycDocumentTemplateService.list_templates` in `app/services/kyc_document_templates.py` (line 324) uses a full `scan()` loop against the `kyc_document_templates` DynamoDB table. The `status-updated-index` GSI (`PK=status`, `SK=updated_at` numeric) was designed for exactly this query but is never used by `list_templates`. The sibling method `get_required_templates_for_tier` (line 360) queries the same GSI correctly, demonstrating the pattern is understood — it was simply not applied to `list_templates`.

**Claim verdict**: CONFIRMED. Lines 333–346 of `app/services/kyc_document_templates.py` use `self._table.scan()` with a `FilterExpression` on `sk`. The `status-updated-index` GSI is defined in `scripts/local-ddb-init.py` (line 170) and referenced in `S.kyc_document_templates_status_index` (settings line 2390), but `list_templates` does not use it.

**Severity**: HIGH. At scale, DynamoDB `Scan` operations read every item in the table (or every item in the page — 1 MB at a time), consuming read capacity units proportional to table size, not result set size. With thousands of template versions across dozens of slugs, each admin list request becomes a full table scan. This is both expensive and slow, and the current pagination cap (`len(items) < limit * 4`) is heuristic and not bounded by actual data volume.

**Owning area**: KYC/Document Templates — `app/services/kyc_document_templates.py`.

**Related tickets**: KYC-017.

## 2. Current-State Investigation (root cause)

### Current implementation

```python
# app/services/kyc_document_templates.py lines 324–346
def list_templates(
    self, *, status: str | None = None, limit: int = 100
) -> list[dict[str, Any]]:
    """List template metadata rows (VERSION#0), newest-updated first.

    Returns one row per template (the metadata placeholder), optionally
    filtered by status.
    """
    items: list[dict[str, Any]] = []
    scan_kwargs: dict[str, Any] = {
        "FilterExpression": Key("sk").eq(_sk(0)),
    }
    resp = self._table.scan(**scan_kwargs)
    items.extend(resp.get("Items", []))
    while "LastEvaluatedKey" in resp and len(items) < limit * 4:
        resp = self._table.scan(
            ExclusiveStartKey=resp["LastEvaluatedKey"], **scan_kwargs
        )
        items.extend(resp.get("Items", []))
    if status:
        items = [i for i in items if str(i.get("status")) == status]
    items.sort(key=lambda i: _coerce_int(i.get("updated_at")), reverse=True)
    return items[:limit]
```

**Problems**:
1. `self._table.scan()` reads the entire table regardless of how many results are needed.
2. `FilterExpression` on `sk` does not reduce consumed RCUs — DynamoDB fetches full pages before filtering.
3. The `while "LastEvaluatedKey" in resp and len(items) < limit * 4` guard is a heuristic: `limit * 4` items collected is not the same as all matching items fetched; some matching items may be beyond the 4× page boundary.
4. The `status` filter is applied in Python after the scan, not in DynamoDB — meaning a request for `status="active"` reads every archived and inactive template to discard them.
5. Post-scan `sort()` is correct but unnecessary if the GSI returns items sorted by `updated_at`.

### Correct pattern: `get_required_templates_for_tier`

```python
# app/services/kyc_document_templates.py lines 360–388
def get_required_templates_for_tier(self, tier: str) -> list[dict[str, Any]]:
    ...
    resp = self._table.query(
        IndexName=S.kyc_document_templates_status_index,  # "status-updated-index"
        KeyConditionExpression=Key("status").eq("active"),
    )
    ...
```

This uses `IndexName=S.kyc_document_templates_status_index` (value `"status-updated-index"`) with a `query()` — precisely the pattern that `list_templates` should follow.

### DynamoDB table schema confirmation

`scripts/local-ddb-init.py` lines 164–173:
```python
TableDef(
    _resolve_table_name(S.kyc_document_templates_table_name, "kyc_document_templates"),
    "template_id",   # PK
    "sk",            # SK
    gsi=[
        {"index_name": "slug-status-index", "partition_key": "slug",   "sort_key": "status"},
        {"index_name": "status-updated-index", "partition_key": "status", "sort_key": "updated_at"},
    ],
    attr_types={"updated_at": "N"},
)
```

The GSI sort key `updated_at` is numeric (`"N"`), enabling range queries and `ScanIndexForward=False` ordering by recency.

### Why the metadata-row filter (`sk == VERSION#0`) matters

The table stores both metadata rows (`sk = "VERSION#0"`) and version rows (`sk = "VERSION#1"`, `"VERSION#2"`, etc.). A status GSI query returns ALL rows with a given status, including version rows. `list_templates` must filter to metadata-only rows. Two approaches:

1. **Query GSI + filter on version==0 in Python** — viable; version rows include a `version` field.
2. **Store metadata rows with a distinct status prefix** — too invasive.

The correct fix is option 1: query the GSI by status, then filter `item["version"] == 0` in Python (a much smaller set than the full table scan).

### Edge case: listing all statuses

When `status=None` the caller wants templates of any status. The `status-updated-index` GSI uses `status` as its PK, so a single query cannot return all-status results. The fix requires parallel queries over the known status values: `"active"`, `"inactive"`, `"archived"`.

## 3. Impact / Exploit / Blast Radius

### Cost

DynamoDB pricing charges per RCU consumed. A Scan reads up to 1 MB per page regardless of matches. With 10 000 template rows (realistic for a platform with many historical versions), each admin call to `list_templates` may consume 10–50 RCU instead of the 1–2 RCU that a GSI query would consume. At scale this is a direct cost problem.

### Latency

The scan loop can take multiple round-trips (each up to 1 MB). Admin UIs calling this endpoint will experience increasing latency as the table grows. The `limit * 4` heuristic means the loop terminates inconsistently — some calls may return fewer than `limit` results even when more exist.

### Correctness

The current code applies status filtering in Python after the scan. This means:

- If a status transition is written to DDB after the scan started but before the Python filter, the result set may include stale-status items.
- The `len(items) < limit * 4` cap means that if there are many archived templates interspersed throughout the table, a request for `status="active"` with `limit=10` may stop scanning early and miss active templates that happen to live in later pages.

### No security impact

This is a performance and correctness issue, not a security vulnerability. The endpoint is admin-only (`require_admin_or_root`).

## 4. Fix Design (code-level)

### 4.1 Replace `list_templates` in `app/services/kyc_document_templates.py`

Replace lines 324–346 with a GSI-backed query implementation:

```python
# app/services/kyc_document_templates.py — replace list_templates
_ALL_TEMPLATE_STATUSES = ("active", "inactive", "archived")


def list_templates(
    self, *, status: str | None = None, limit: int = 100
) -> list[dict[str, Any]]:
    """List template metadata rows (VERSION#0), newest-updated first.

    Queries the ``status-updated-index`` GSI (PK=status, SK=updated_at N)
    instead of scanning the full table.  When ``status`` is supplied only
    that GSI partition is read; otherwise all three status partitions are
    read in parallel (three separate queries, each cheap).
    """
    statuses_to_query = [status] if status else list(_ALL_TEMPLATE_STATUSES)
    items: list[dict[str, Any]] = []

    for s in statuses_to_query:
        start_key: dict[str, Any] | None = None
        while True:
            kwargs: dict[str, Any] = {
                "IndexName": S.kyc_document_templates_status_index,
                "KeyConditionExpression": Key("status").eq(s),
                "ScanIndexForward": False,  # newest updated_at first
            }
            if start_key:
                kwargs["ExclusiveStartKey"] = start_key
            resp = self._table.query(**kwargs)
            for item in resp.get("Items", []):
                # Only metadata placeholder rows (version == 0)
                if _coerce_int(item.get("version")) == 0:
                    items.append(item)
            start_key = resp.get("LastEvaluatedKey")
            if not start_key:
                break

    # Sort by updated_at descending across all status partitions
    items.sort(key=lambda i: _coerce_int(i.get("updated_at")), reverse=True)
    return items[:limit]
```

**Key changes**:
- `self._table.scan()` → `self._table.query(IndexName=S.kyc_document_templates_status_index, ...)`
- Status filter moved from Python post-processing into the GSI PK equality condition.
- `len(items) < limit * 4` heuristic removed; now loops `LastEvaluatedKey` until exhausted (correct pagination).
- `ScanIndexForward=False` returns newest-updated items first within each status partition, reducing the items that need cross-partition sorting.
- Version-0 filter applied during iteration, not after full collection.

### 4.2 Dev/Prod parity (SECOPS-007)

- The DynamoDB Local instance on port 8001 supports GSI queries identically to the real DynamoDB service. The fix is fully testable in dev mode.
- No feature-flag gate is needed; the query path is correct in both environments. If the `status-updated-index` GSI does not exist in a table (migration scenario), the query raises `ResourceNotFoundException` — surfaced to the caller rather than silently scanning, which is safer.
- `S.kyc_document_templates_status_index` (default `"status-updated-index"`) is already used by `get_required_templates_for_tier`; the same setting name is reused.

### 4.3 Alternatives considered

| Approach | Verdict |
|---|---|
| Keep scan, add a GSI projection | Scan still reads the full table first |
| Use a parallel `asyncio.gather` for multi-status query | Adds complexity; loop is fast enough given three known statuses |
| Enforce `status` as required parameter | Breaks existing callers that list all templates |

### 4.4 Backward compatibility

The output contract (`list[dict]`, sorted by `updated_at` descending, capped by `limit`) is unchanged. Callers that pass `status=None` receive a superset of what the scan previously returned (the scan could miss items beyond the `limit * 4` heuristic; the new implementation is correct and complete). No migration required.

### Regression test (pytest offline, fails before / passes after)

Create `tests/test_gap_0278_list_templates_gsi.py`:

```python
"""GAP-0278: list_templates must use GSI query, not Scan."""
import pytest
from unittest.mock import MagicMock, patch, call


def _make_service():
    from app.services.kyc_document_templates import KycDocumentTemplateService
    table = MagicMock()
    # Default query response — empty
    table.query.return_value = {"Items": []}
    table.scan.return_value = {"Items": []}
    svc = object.__new__(KycDocumentTemplateService)
    svc._table = table
    return svc, table


def test_list_templates_uses_query_not_scan():
    """list_templates must call table.query(), never table.scan()."""
    svc, table = _make_service()
    svc.list_templates(status="active")
    table.query.assert_called()
    table.scan.assert_not_called()


def test_list_templates_queries_status_gsi():
    """Query must target the status-updated-index GSI."""
    svc, table = _make_service()
    svc.list_templates(status="active")
    kwargs = table.query.call_args[1]
    assert "IndexName" in kwargs, "IndexName must be supplied to query()"
    assert "status" in kwargs.get("IndexName", ""), \
        f"Expected status GSI index name, got: {kwargs.get('IndexName')}"


def test_list_templates_all_statuses_no_scan():
    """When status=None, list_templates must query all status partitions, not scan."""
    svc, table = _make_service()
    svc.list_templates()  # no status filter
    table.scan.assert_not_called()
    # Should have been called at least 3 times (once per status)
    assert table.query.call_count >= 3, (
        f"Expected >= 3 GSI queries for all statuses, got {table.query.call_count}"
    )


def test_list_templates_returns_only_metadata_rows():
    """Only version==0 rows (metadata placeholders) should be returned."""
    svc, table = _make_service()
    table.query.return_value = {
        "Items": [
            {"template_id": "t1", "sk": "VERSION#0", "version": 0,
             "status": "active", "updated_at": 1000},
            {"template_id": "t1", "sk": "VERSION#1", "version": 1,
             "status": "active", "updated_at": 900},   # non-metadata
        ]
    }
    results = svc.list_templates(status="active")
    assert len(results) == 1
    assert results[0]["version"] == 0
```

**Before fix**: `test_list_templates_uses_query_not_scan` fails because `table.scan.assert_not_called()` raises `AssertionError`.
**After fix**: All four tests pass.
