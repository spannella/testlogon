# GAP-0343: Promo Codes Not Integrated into Shop Checkout — Remediation Write-up

## 1. Summary & Classification

**Gap**: The source ticket claims promo codes are not integrated into shop checkout and
that the `applies_to: ["shop"]` checkout type is "orphaned" in `app/routers/catalog.py`.

**Claim accuracy**: **Corrected.** The original gap ticket is inaccurate in both its
location and its central claim. Code inspection shows:

1. The shop purchase path is not in `app/routers/catalog.py`. `catalog.py` has no
   checkout or purchase endpoint. All shop purchases flow through
   `app/routers/shoppingcart.py` → `app/services/shoppingcart.py`.
2. Promo codes ARE already integrated into the shop checkout. `purchase_cart` in
   `app/services/shoppingcart.py:545–661` accepts `promo_code` / `promo_code_id`,
   calls `promo_codes.validate_promo_code(checkout_type="shop")`, and calls
   `promo_codes.redeem_promo_code(checkout_type="shop")` after a successful purchase.
3. The frontend `frontend/src/pages/shop/Checkout.tsx:54–135` implements a promo code
   input, validation call to `validatePromoCode`, and passes `promo_code` to
   `purchaseCart`.
4. The `CartPurchaseIn` model in `app/models.py:882` already declares
   `promo_code: Optional[str]` and `promo_code_id: Optional[str]`.

**What remains genuinely incomplete**: There is no direct "buy-now" single-item
purchase endpoint in `catalog.py` that bypasses the cart. All shop purchases must go
through the multi-step cart flow. If a future single-item express checkout is added to
`catalog.py` without including promo code logic, the gap would re-open. Additionally,
the `applies_to: ["shop"]` promo code type has no corresponding direct-purchase entrypoint
that a creator can advertise without the buyer first creating a cart.

- **Severity**: LOW (the originally-described gap is resolved; residual risk is minimal)
- **Source ticket**: PROMO-001
- **Owning area**: Shop / Catalog / Backend + Frontend
- **Status**: Substantially resolved; original claim is inaccurate

**Related tickets**: PROMO-001, GAP-0342 (subscription promo codes — genuinely open)

## 2. Current-State Investigation (Root Cause)

### 2.1 What catalog.py actually provides

`app/routers/catalog.py` (935 lines) exposes endpoints for:
- Category CRUD (`POST /ui/catalog/categories`, `GET`, `DELETE`)
- Item CRUD (`POST /ui/catalog/categories/{id}/items`, `GET`, `PATCH`, `DELETE`)
- Reviews (`GET /ui/catalog/items/{id}/reviews`, `POST`)
- Stock management (`PATCH /ui/catalog/items/{item_id}/stock`)
- Bulk operations (`POST /ui/catalog/items/bulk-delete`, `bulk-update`)

There is no `POST /ui/catalog/items/{id}/buy` or any checkout endpoint. The `catalog.py`
router has zero references to `promo`, `cart`, `checkout`, or `purchase`.

### 2.2 The actual shop purchase path

Both validation and redemption (with TOCTOU guard) are wired. The `checkout_type="shop"`

### 2.3 Frontend state

`frontend/src/pages/shop/Checkout.tsx:27` imports `validatePromoCode` from the API
client. Lines 54–135 show a full promo code flow: input state, validation mutation,
display of `discount_cents`, and passing `promo_code` to the `purchaseCart` call.
The feature is implemented and visible to end users.

### 2.4 What is genuinely missing

The only real gap is that the **`applies_to: ["shop"]` type in a promo code is coupled
exclusively to the cart checkout flow**. There is no express single-item checkout
endpoint in `catalog.py`. Should a developer add one in the future, they must include
the same `validate_promo_code` / `redeem_promo_code` calls. A defensive test to guard
against this regression is the most valuable deliverable from this ticket.

Additionally, the `redeem_promo_code` call in `purchase_cart` is wrapped in
`try/except: pass` (best-effort). If the redemption fails silently, the promo code's
`current_uses` count is not incremented, potentially allowing a user to redeem the same
limited-use code multiple times across cart purchases. This is a minor integrity gap.

## 3. Impact / Exploit / Blast Radius

### 3.1 Current state (low impact — gap is resolved)

The shop promo code path is functional end-to-end. Customers can apply promo codes
to cart purchases. The `applies_to: ["shop"]` field is not orphaned.

### 3.2 Residual risk: silent redeem failure

The `try/except: pass` around `redeem_promo_code` at
`app/services/shoppingcart.py:650–661` means a transient DynamoDB error silently
swallows the usage increment. If `max_uses=10` and the redeem write fails for 2 of
10 purchases, those 2 users each effectively get a free redemption that does not count
toward the limit, allowing up to 2 extra uses. This is a low-probability but real
integrity issue.

### 3.3 Future regression risk

Any new direct-purchase endpoint in `catalog.py` written without promo code awareness
would silently skip discounts. This risk is mitigated by adding a contract test.

## 4. Fix Design (Code-Level)

### 4.1 Harden the redeem step (silent failure fix)

Change the `try/except: pass` in `app/services/shoppingcart.py:650` to log the failure
and store a record for manual reconciliation:

```python
    if resolved_promo and resolved_promo.get("code_id"):
        try:
            from app.services.promo_codes import redeem_promo_code
            redeem_promo_code(
                code_id=resolved_promo["code_id"],
                user_id=user_sub,
                original_price_cents=original_total_cents,
                final_price_cents=final_total,
                checkout_type="shop",
                checkout_item_id=cart_id,
            )
        except Exception as e:
            logger.warning(
                "promo_redeem_failed cart=%s code_id=%s error=%s",
                cart_id, resolved_promo["code_id"], e,
            )
            # Store the failed redemption in the cart record for manual reconciliation
            try:
                T.shopping_cart.update_item(
                    Key={"PK": cart["PK"], "SK": cart["SK"]},
                    UpdateExpression="SET promo_redeem_failed = :f",
                    ExpressionAttributeValues={":f": True},
                )
            except Exception:
                pass
```

### 4.2 Guard against future direct-purchase endpoints in catalog.py

Add a module-level comment and docstring to `app/routers/catalog.py` at the top,
after the imports:

```python
# PROMO-001 NOTE: Any new endpoint that processes a payment for a catalog item
# MUST call app.services.promo_codes.validate_promo_code(checkout_type="shop")
# and app.services.promo_codes.redeem_promo_code() following the pattern in
# app/services/shoppingcart.py:540-661. The applies_to=["shop"] promo type
# is wired to the cart checkout path; do not bypass it.
```

### 4.3 Dev / Prod Parity (SECOPS-007)

No AWS-backed paths are involved. Both `validate_promo_code` and `redeem_promo_code`
are pure DynamoDB. The fix (log + DDB annotation for failed redeems) is identical in
dev and prod. No feature flag is needed beyond the existing `S.promo_codes_enabled`
guard already checked by the promo code router.

### 4.4 Alternatives Considered

- **Add a direct "buy-now" endpoint to catalog.py**: This is a larger feature (Effort L)
  and goes beyond the scope of this bug fix. It should be a separate ticket and must
  include promo code wiring.
- **Remove `"shop"` from `VALID_CHECKOUT_TYPES`**: Would break existing promo codes that
  already specify `applies_to: ["shop"]` and the cart checkout that already handles them.
  Rejected.

## 5. Testing, Verification & Rollout

### 5.1 Pytest Regression Tests (fails-before / passes-after)

**Test A — shop checkout with valid promo code**

Create `tests/test_shop_promo_code.py`:

```python
"""Regression: shop cart checkout must validate and redeem promo codes."""
from unittest.mock import patch, MagicMock
import pytest


def _promo_valid(discount_cents=200):
    return {
        "valid": True, "code_id": "pc_1", "discount_type": "fixed_amount",
        "discount_cents": discount_cents, "final_price_cents": 800,
        "free_trial_days": 0, "message": None,
    }


def test_cart_purchase_applies_promo_discount(client, alice_session, seed_cart_with_item):
    """purchase_cart must reduce total by promo discount_cents."""
    cart_id = seed_cart_with_item["cart_id"]  # total_cents = 1000

    with patch("app.services.promo_codes.validate_promo_code",
               return_value=_promo_valid(200)) as mv, \
         patch("app.services.promo_codes.redeem_promo_code",
               return_value=({"code_id": "pc_1"}, None)) as mr:
        resp = client.post(
            f"/ui/shoppingcart/carts/{cart_id}/purchase",
            json={"promo_code": "SAVE20"},
            headers={
                **alice_session["headers"],
                "X-Idempotency-Key": "idem-001",
            },
        )

    assert resp.status_code == 200
    assert resp.json()["purchased_total_cents"] == 800
    mv.assert_called_once()
    mr.assert_called_once()


def test_cart_purchase_rejects_invalid_promo(client, alice_session, seed_cart_with_item):
    """purchase_cart must return 422 for an invalid promo code."""
    cart_id = seed_cart_with_item["cart_id"]

    with patch("app.services.promo_codes.validate_promo_code",
               return_value={"valid": False, "code_id": None,
                             "message": "Code not found", "discount_cents": 0,
                             "final_price_cents": 1000, "free_trial_days": 0,
                             "discount_type": None}):
        resp = client.post(
            f"/ui/shoppingcart/carts/{cart_id}/purchase",
            json={"promo_code": "BADCODE"},
            headers={
                **alice_session["headers"],
                "X-Idempotency-Key": "idem-002",
            },
        )
    assert resp.status_code == 422


def test_catalog_router_has_no_purchase_endpoint():
    """Guard: catalog.py must not introduce a purchase endpoint without promo wiring."""
    from app.routers.catalog import router
    paths = [r.path for r in router.routes]
    purchase_paths = [p for p in paths if "purchase" in p or "buy" in p or "checkout" in p]
    assert purchase_paths == [], (
        f"catalog.py added a purchase endpoint ({purchase_paths}) without "
        "promo code wiring — add validate_promo_code/redeem_promo_code following "
        "the shoppingcart.py pattern."
    )
```

The third test (`test_catalog_router_has_no_purchase_endpoint`) is a **contract test**
that fails immediately if a future developer adds a bare purchase endpoint to
`catalog.py` without this comment being updated to explicitly allow it.

**Before the redeem-log fix**: The first two tests already pass (integration is present).
The contract test also passes. This confirms the main claim of GAP-0343 was already
resolved at the time of the gap audit.
