# GAP-0080: Idle-Worker Auto-Shutdown Stub Not Implemented — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual codebase 2026-06-05; claim is **confirmed**
> — `check_idle_workers()` is a stub that always returns 0.

## 1. Summary & Classification

- **Severity**: HIGH (financial / availability) — provisioned compute instances (EC2 or k8s
  pods) are never stopped automatically. Each idle worker accrues per-minute compute charges
  indefinitely, burning the user's and/or platform's compute budget.
- **Source ticket**: AGENT-002 · **Status**: Open
- **Owning area**: `app/services/agent_worker_provisioner.py:462`, `app/main.py`
- **Related tickets**: AGENT-002 (worker provisioning), GAP-0076 (budget race),
  GAP-0077 (usage reset), SECOPS-007 (dev/prod parity)

**Verdict: CLAIM CONFIRMED.** The function `check_idle_workers` at line 462:

```python
def check_idle_workers() -> int:
    """Background task: find and stop workers where
    now() - last_activity_at > idle_timeout_seconds.
    Returns count of workers stopped."""
    # Simplified implementation — in production this would scan all users
    return 0
```

The comment acknowledges the stub. The function is also **never called** — a search of
`app/main.py` finds no `start_idle_worker_checker_task` or equivalent startup hook for
`check_idle_workers`. Workers created with `idle_timeout_seconds = 7200` (the default)
are never auto-stopped regardless of how long they have been idle.

**One-line impact**: Every provisioned agent worker runs forever, accumulating compute
cost at rates of $0.50–$3.20 per minute (per `COMPUTE_OPTIONS` in the provisioner).

## 2. Current-State Investigation (root cause)

### The stub

`app/services/agent_worker_provisioner.py`, line 462:

```python
def check_idle_workers() -> int:
    """Background task: find and stop workers where
    now() - last_activity_at > idle_timeout_seconds.
    Returns count of workers stopped."""
    # Simplified implementation — in production this would scan all users
    return 0
```

This is the complete implementation. No DynamoDB query, no iteration, no call to
`stop_worker`.

### No startup wiring

`app/main.py` registers ~30 startup tasks including `start_ec2_idle_checker_task` (line 696)
and `start_k8s_ttl_checker_task` (line 708) for the lower-level EC2/k8s launchers. However,
these check the raw compute instances, **not** the agent workers layer. The agent workers
table has its own `idle_timeout_seconds` and `last_activity_at` fields that are never
consulted.

`check_idle_workers` is not referenced anywhere in `app/main.py` or any other file.

### DynamoDB schema for idle detection

`scripts/local-ddb-init.py` (line 1890):

```python
TableDef(
    _resolve_table_name(S.agent_workers_table_name, "agent_workers"),
    "pk", "sk",
    gsi=[
        {"index_name": "ByStatus",    "partition_key": "pk", "sort_key": "worker_status"},
        {"index_name": "ByCreatedAt", "partition_key": "pk", "sort_key": "created_at"},
        {"index_name": "ByAgentType", "partition_key": "pk", "sort_key": "agent_type"},
    ],
    attr_types={"created_at": "N"},
)
```

Critical observation: **all three GSIs use `pk` (= `USER#{user_id}`) as the partition key.**
This means querying any GSI requires knowing the specific `user_id` in advance. There is no
GSI with a stable cross-user partition key (such as a status shard) that would allow the
background task to query "all ready/running workers across all users" efficiently.

The `ByStatus` GSI with `pk = USER#{user_id}` and `sort_key = worker_status` only works for
per-user queries (e.g., "show me Alice's ready workers"). It cannot answer "show me all ready
workers across all users" without a full table scan.

This is the core infrastructure gap that must be addressed alongside the stub implementation.

### The `last_activity_at` field

Created at `0` in `create_worker` (line 230: `"last_activity_at": 0`). It is set when a
worker transitions to `running` state (by the orchestrator, in AGENT-003 flows) but never
updated in the provisioner itself. An idle worker that has `last_activity_at = 0` (never
ran a job) and `started_at = T` would be correctly identified as idle after
`now - started_at > idle_timeout_seconds`.

The fix must handle two cases:
1. Worker that has run jobs: use `last_activity_at`.
2. Worker that has never run a job: use `started_at` as a proxy for activity.

## 3. Impact / Exploit / Blast Radius

### Financial impact

Each idle worker accrues:

| Compute type | Instance type | Cost per minute | Cost per day (idle) |
|---|---|---|---|
| k8s | standard-2cpu-4gb | $0.50 | $720 |
| ec2 | t3.medium | $0.70 | $1,008 |
| ec2 | t3.large | $1.40 | $2,016 |
| ec2 | m5.xlarge | $3.20 | $4,608 |

A user with 5 workers that have been idle for a week accumulates ~$35,000 in compute
charges (at the listed mock rates; real AWS rates will differ, but the principle is
identical).

### Platform risk

If the platform absorbs compute costs (subscription or free-tier model), unbounded idle
workers represent an unbounded operating expense. A single account could intentionally
provision the maximum number of workers (`S.agent_max_workers_per_user`) and abandon them.

### Availability risk

EC2 and k8s resources are finite. A build-up of idle workers can exhaust the per-user
or platform-wide instance limits, preventing new workers from being provisioned for other
users.

### Blast radius

All users with active workers that have surpassed their `idle_timeout_seconds` threshold.
The issue is not a security vulnerability in the traditional sense — no data is exposed.
It is a financial and operational gap that compounds over time and worsens as the user
base grows.

## 4. Fix Design (code-level)

### Part A — Cross-user GSI for idle detection

To query idle workers across all users without a full scan, add a sparse GSI with a
synthetic shard key that places all "active" workers in one queryable index partition.

**Update `scripts/local-ddb-init.py`:**

```python
TableDef(
    _resolve_table_name(S.agent_workers_table_name, "agent_workers"),
    "pk", "sk",
    gsi=[
        {"index_name": "ByStatus",          "partition_key": "pk",           "sort_key": "worker_status"},
        {"index_name": "ByCreatedAt",        "partition_key": "pk",           "sort_key": "created_at"},
        {"index_name": "ByAgentType",        "partition_key": "pk",           "sort_key": "agent_type"},
        # NEW: sparse GSI for cross-user idle detection
        # Partition key = worker_shard (set to "ACTIVE" for ready/running workers,
        # removed for stopped/terminated). Sort key = last_activity_at (numeric).
        {"index_name": "ActiveByActivity",   "partition_key": "worker_shard", "sort_key": "last_activity_at"},
    ],
    attr_types={"created_at": "N", "last_activity_at": "N"},
)
```

Set `worker_shard = "ACTIVE"` when a worker is created or started, and remove it
(or set to a non-indexed value) when stopped or terminated. This makes the GSI sparse —
only active workers appear in it.

### Part B — Implement `check_idle_workers`

Replace the stub in `app/services/agent_worker_provisioner.py`:

```python
def check_idle_workers() -> int:
    """Background task: find and stop workers where the effective activity time
    exceeds idle_timeout_seconds. Returns count of workers stopped.
    
    Uses the ActiveByActivity GSI to query across all users without a full
    table scan. Workers are queried in ascending last_activity_at order so the
    oldest-idle workers are processed first.
    """
    now = now_ts()
    stopped_count = 0

    # Query all shards with a low last_activity_at.
    # In the shard-key design there is only one shard ("ACTIVE"), so one query suffices.
    # For prod scale-out, shard into multiple buckets and fan out.
    try:
        resp = T.agent_workers.query(
            IndexName="ActiveByActivity",
            KeyConditionExpression="worker_shard = :shard AND last_activity_at <= :cutoff",
            ExpressionAttributeValues={
                ":shard":  "ACTIVE",
                ":cutoff": now,  # initial conservative cutoff; real cutoff per-item below
            },
        )
    except Exception:
        logger.exception("check_idle_workers GSI query failed")
        return 0

    while True:
        for item in resp.get("Items", []):
            try:
                _maybe_stop_idle_worker(item, now)
                stopped_count += 1
            except Exception:
                logger.exception(
                    "check_idle_workers error processing worker_id=%s",
                    item.get("worker_id"),
                )

        last_key = resp.get("LastEvaluatedKey")
        if not last_key:
            break
        resp = T.agent_workers.query(
            IndexName="ActiveByActivity",
            KeyConditionExpression="worker_shard = :shard AND last_activity_at <= :cutoff",
            ExpressionAttributeValues={":shard": "ACTIVE", ":cutoff": now},
            ExclusiveStartKey=last_key,
        )

    if stopped_count:
        logger.info("idle_workers_stopped count=%d", stopped_count)
    return stopped_count


def _maybe_stop_idle_worker(item: Dict[str, Any], now: int) -> None:
    """Stop a worker if it has been idle longer than its idle_timeout_seconds."""
    worker_id  = item.get("worker_id", "")
    user_id    = item.get("user_id", "")
    status     = item.get("worker_status", "")
    timeout    = int(item.get("idle_timeout_seconds", 7200))
    # Use last_activity_at; fall back to started_at for workers that never ran
    activity   = int(item.get("last_activity_at") or item.get("started_at", 0) or 0)

    if status not in ("ready", "running"):
        return  # already stopped, terminated, or in error
    if activity == 0:
        return  # not yet started — let the provisioning timeout handle this
    if (now - activity) < timeout:
        return  # not yet idle

    logger.info(
        "idle_worker_detected worker_id=%s user_id=%s idle_seconds=%d timeout=%d",
        worker_id, user_id, now - activity, timeout,
    )
    try:
        stop_worker(user_id, worker_id)
    except ValueError as e:
        logger.warning("idle_worker stop_failed worker_id=%s error=%s", worker_id, e)
```

### Part C — Background task and startup wiring

Add an async loop module (or add to the existing provisioner file):

```python
async def _idle_checker_loop() -> None:
    interval = int(os.environ.get("IDLE_WORKER_CHECK_INTERVAL_SECONDS", "300"))  # 5 min
    while True:
        try:
            check_idle_workers()
        except Exception:
            logger.exception("idle_checker_loop error")
        await asyncio.sleep(interval)


def start_idle_worker_checker_task() -> None:
    import asyncio
    loop = asyncio.get_event_loop()
    loop.create_task(_idle_checker_loop())
    logger.info("idle_worker_checker_task started interval=%ds",
                int(os.environ.get("IDLE_WORKER_CHECK_INTERVAL_SECONDS", "300")))
```

**`app/main.py`:**

```python
from app.services.agent_worker_provisioner import start_idle_worker_checker_task
...
app.add_event_handler("startup", start_idle_worker_checker_task)
```

### Part D — Maintain `worker_shard` attribute through the lifecycle

Update `create_worker`, `start_worker`, `stop_worker`, and `terminate_worker` in
`agent_worker_provisioner.py` to set/remove `worker_shard`:

- `create_worker` / `start_worker`: add `worker_shard = "ACTIVE"` to the `update_item`.
- `stop_worker` / `terminate_worker`: add `REMOVE worker_shard` to the `update_item`.

### Dev/Prod parity (SECOPS-007)

All changes are DynamoDB operations through `T.agent_workers`, which resolves to
DynamoDB Local in dev (port 8001) and real DynamoDB in prod. The `asyncio` task pattern
is identical to `start_ec2_idle_checker_task` already present in the codebase.

The `IDLE_WORKER_CHECK_INTERVAL_SECONDS` env var defaults to 300 (5 minutes) in both
environments. Dev and E2E tests use moto for DDB, so the task runs correctly in pytest
when the moto fixture is active.

### Manual QA steps

1. `just restart` to wipe state.
2. Provision a worker via the Worker Fleet UI; note the `worker_id`.
3. In DynamoDB Local, set `last_activity_at = 1` (epoch) on the worker item and
   `worker_shard = "ACTIVE"`.
4. Wait up to 5 minutes (or reduce `IDLE_WORKER_CHECK_INTERVAL_SECONDS=10` in `.env.local`).
5. Refresh the Worker Fleet UI; the worker should show `status = stopped`.
6. Confirm `stopped_at` timestamp is set and `compute_instance_id` is still present
   (stop, not terminate — worker can be restarted).

### Observability

The `logger.info("idle_workers_stopped count=N")` line fires each check cycle with a
non-zero count. Add a Prometheus counter:

```python
counter("agent_worker_idle_stop_total").inc(stopped_count)
```

A continuous non-zero value indicates workers are accumulating without being used —
useful for cost-monitoring dashboards.

Alert: if `idle_workers_stopped_total` rate is unusually high (e.g., >10/hour), it may
indicate a bug in worker pool sizing or users over-provisioning.

### Rollout

- **Effort**: M. DDB schema change (Part A — new GSI, requires table re-creation in dev
  or an `UpdateTable` in prod), implementation (Part B — ~80 lines), wiring
  (Part C — 4 lines), and lifecycle updates (Part D — 4 update expressions).
- **Risk**: MEDIUM. The DDB schema change for the new GSI requires coordination:
  - **Dev**: `just restart` re-creates tables; GSI added automatically.
  - **Prod**: Requires `UpdateTable` to add the GSI. This is non-destructive but takes
    time (minutes to hours for large tables). Schedule as a low-traffic-window change.
- **Interim approach (scan-based)**: If the GSI change cannot be deployed immediately,
  replace the stub with a full-table scan approach (DynamoDB `scan` with
  `FilterExpression`) as a safe interim. This is less efficient but functional and does
  not require a schema change.
- **Sequencing**: The schema change (Part A) must precede the `ActiveByActivity` GSI
  query (Part B). The scan-based interim can ship immediately. The startup wiring
  (Part C) should ship alongside Part B.
- **Rollback**: Remove the `add_event_handler` line; the task stops running. Workers
  already stopped by the task remain stopped (users can restart them via the UI). The GSI
  can be left in place — it adds a small write overhead but causes no harm.
