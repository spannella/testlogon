# GAP-0050: compute_hourly_rollup Never Called by Anything — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`.

## 1. Summary & Classification

**Claim (from ticket):** `app/services/ad_analytics.py:compute_hourly_rollup` is fully implemented but never called by any background task or scheduler; the `AdAnalyticsRollups` DynamoDB table therefore remains empty, causing all analytics dashboard endpoints to return zeros.

**Verdict: Claim confirmed.** A full text search of the codebase finds exactly one definition of `compute_hourly_rollup` at `ad_analytics.py:168` and zero call sites. `app/main.py` has no startup handler importing `ad_analytics`. All dashboard endpoints (`get_summary`, `get_timeseries`, `get_breakdown`) call `_fetch_daily_rollups` or `_fetch_rollups`, which query `T.ad_analytics_rollups`; that table is always empty in any environment where the background task has not been manually invoked.

- **Severity:** HIGH (all analytics dashboard data is permanently unavailable; advertiser trust and product completeness are both affected)
- **Source ticket:** ADS-008
- **Owning area:** Ad Analytics
- **Status:** Open
- **Effort:** M
- **Related tickets:** GAP-0048 (related background task gap, same startup registration pattern), GAP-0049 (upstream data dependency — platform revenue charges feed into rollup)

## 2. Current-State Investigation (root cause)

### The orphaned function

`app/services/ad_analytics.py:168-211`, function `compute_hourly_rollup`:

```python
def compute_hourly_rollup(
    campaign_id: str, account_id: str, hour: str
) -> dict:
    """Compute rollup for a specific campaign and hour.

    hour format: "2026-05-29T14"
    Called by background rollup job.
    """
    from app.services.ad_billing import get_campaign_spending

    entries = get_campaign_spending(campaign_id, limit=1000)

    impressions = sum(1 for e in entries if e.get("entry_type") == "impression_charge")
    clicks = sum(1 for e in entries if e.get("entry_type") == "click_charge")
    spend = sum(int(e.get("amount_cents", 0)) for e in entries)

    rollup = {
        "pk": f"CAMP#{campaign_id}",
        "sk": f"ROLLUP#hourly#{hour}",
        ...
        "computed_at": now_ts(),
    }

    T.ad_analytics_rollups.put_item(
        Item={k: v for k, v in rollup.items() if v is not None}
    )
    return rollup
```

The docstring explicitly says "Called by background rollup job." but no such job exists.

### How dashboard queries depend on rollup data

`app/services/ad_analytics.py:217-245`, `_fetch_daily_rollups`:

```python
if campaign_id:
    resp = T.ad_analytics_rollups.query(
        KeyConditionExpression=Key("pk").eq(f"CAMP#{campaign_id}")
        & Key("sk").between(
            f"ROLLUP#daily#{start_date}",
            f"ROLLUP#daily#{end_date}z",
        ),

```

Note that `_fetch_daily_rollups` queries for `ROLLUP#daily#` SK prefix, while `compute_hourly_rollup` writes `ROLLUP#hourly#` SK entries. There is no `compute_daily_rollup` function. The daily rollup writes are also absent — not just the hourly ones. The dashboard's time-series and summary data is doubly broken: no hourly rollups exist, and no daily rollups exist.

### Root cause classification

Two missing pieces:
1. **Hourly rollup task:** `compute_hourly_rollup` is defined but never called. Writing hourly rollup rows is a prerequisite for any other aggregation.
2. **Daily rollup aggregation:** No function rolls up hourly rows into daily rows with `ROLLUP#daily#` SK prefix, which is what the dashboard queries expect. `_fetch_daily_rollups` and `_fetch_rollups` with `granularity="daily"` are permanently empty.

The gap ticket focuses on the missing background task for `compute_hourly_rollup`, but complete remediation also requires a `compute_daily_rollup` step (or a query change to use hourly rollups directly).

## 3. Impact / Exploit / Blast Radius

**Advertiser-facing impact:**
Every analytics endpoint returns zeros or empty arrays:
- `GET /ads/analytics/summary` → all KPI counts are 0
- `GET /ads/analytics/timeseries` → empty `[]`
- `GET /ads/analytics/breakdown` → empty `[]`

Advertisers cannot evaluate campaign performance. They pay for impressions and clicks (via `_process_charge`) but cannot see any reporting data. This is a complete product gap, not a partial degradation.

**Financial reporting impact:**
The analytics data feeds into spend optimisation (`ad_optimization.py:353` reads `spent_today_cents` but also reads rollup-derived pacing signals). With no rollup data, any pacing logic that uses analytics is operating blind.

**No security exploit.** Analytics data is read-only; this is a data-availability issue.

**Blast radius:**
- All advertisers with active campaigns.
- All campaign managers relying on the dashboard.
- Any A/B testing or targeting optimisation that uses CTR, CPM, or completion rate from the analytics API.

**Second-order risk:** Advertisers interpret zero analytics as zero delivery and may dispute charges, demand refunds, or churn.

## 4. Fix Design (code-level)

### Approach: hourly background task + daily aggregation rollup

The cleanest design consistent with the existing codebase structure:

1. A background task runs every hour, calling `compute_hourly_rollup` for all active campaigns.
2. Once per day (at, say, 00:05 UTC, after the daily spend reset), aggregate the previous day's hourly rows into a single `ROLLUP#daily#` row per campaign.

This two-pass approach keeps hourly granularity for real-time dashboard queries and provides daily rollups for longer-range charts.

### Change 1 — Fix `compute_hourly_rollup` to filter by hour

The current implementation at `ad_analytics.py:178` calls `get_campaign_spending(campaign_id, limit=1000)` which returns all time billing entries for the campaign — not just the specified hour. The rollup computation is therefore always lifetime totals, not hourly totals. The `hour` parameter is used only as the SK but not as a filter.

Fix by filtering entries to the relevant hour window:

```python
def compute_hourly_rollup(
    campaign_id: str, account_id: str, hour: str
) -> dict:
    """Compute rollup for a specific campaign and hour.

    hour format: "2026-05-29T14"
    Writes a ROLLUP#hourly# row to T.ad_analytics_rollups.
    """
    from app.services.ad_billing import get_campaign_spending
    from datetime import datetime, timezone

    # Parse hour to Unix timestamp window
    hour_dt = datetime.strptime(hour, "%Y-%m-%dT%H").replace(tzinfo=timezone.utc)
    hour_start_ts = int(hour_dt.timestamp())
    hour_end_ts = hour_start_ts + 3600

    entries = get_campaign_spending(campaign_id, limit=5000)
    # Filter to only entries created within this hour
    hour_entries = [
        e for e in entries
        if hour_start_ts <= int(e.get("created_at", 0)) < hour_end_ts
    ]

    impressions = sum(1 for e in hour_entries if e.get("entry_type") == "impression_charge")
    clicks = sum(1 for e in hour_entries if e.get("entry_type") == "click_charge")
    spend = sum(int(e.get("amount_cents", 0)) for e in hour_entries)

    rollup = {
        "pk": f"CAMP#{campaign_id}",
        "sk": f"ROLLUP#hourly#{hour}",
        "campaign_id": campaign_id,
        "account_id": account_id,
        "period": "hourly",
        "date": hour,
        "impressions": impressions,
        "clicks": clicks,
        "skips": 0,
        "completes": 0,
        "spend_cents": spend,
        "revenue_cents": int(spend * 0.7),
        "unique_users": 0,
        "by_creative": {},
        "by_surface": {},
        "by_targeting": {},
        "computed_at": now_ts(),
    }
    T.ad_analytics_rollups.put_item(
        Item={k: v for k, v in rollup.items() if v is not None}
    )
    return rollup
```

### Change 2 — Add `compute_daily_rollup`

```python
def compute_daily_rollup(campaign_id: str, account_id: str, date: str) -> dict:
    """Aggregate hourly rollup rows into a single daily row.

    date format: "2026-05-29"
    Must be called after all 24 hourly rows for that date are computed.
    """
    resp = T.ad_analytics_rollups.query(
        KeyConditionExpression=(
            Key("pk").eq(f"CAMP#{campaign_id}") &
            Key("sk").between(
                f"ROLLUP#hourly#{date}T00",
                f"ROLLUP#hourly#{date}T23z",
            )
        )
    )
    hourly_rows = resp.get("Items", [])

    impressions = sum(int(r.get("impressions", 0)) for r in hourly_rows)
    clicks = sum(int(r.get("clicks", 0)) for r in hourly_rows)
    spend = sum(int(r.get("spend_cents", 0)) for r in hourly_rows)
    completes = sum(int(r.get("completes", 0)) for r in hourly_rows)
    skips = sum(int(r.get("skips", 0)) for r in hourly_rows)

    rollup = {
        "pk": f"CAMP#{campaign_id}",
        "sk": f"ROLLUP#daily#{date}",
        "campaign_id": campaign_id,
        "account_id": account_id,
        "period": "daily",
        "date": date,
        "impressions": impressions,
        "clicks": clicks,
        "completes": completes,
        "skips": skips,
        "spend_cents": spend,
        "revenue_cents": int(spend * 0.7),
        "unique_users": 0,
        "by_creative": {},
        "by_surface": {},
        "by_targeting": {},
        "computed_at": now_ts(),
    }
    T.ad_analytics_rollups.put_item(
        Item={k: v for k, v in rollup.items() if v is not None}
    )
    return rollup
```

### Change 3 — Background task: hourly loop + daily aggregation

Add to `app/services/ad_analytics.py`:

```python
import asyncio
from datetime import datetime, timezone, timedelta


async def _ad_analytics_rollup_loop():
    """Runs compute_hourly_rollup for all active campaigns once per hour,
    and compute_daily_rollup for the previous day at 00:05 UTC.
    """
    while True:
        try:
            now = datetime.now(timezone.utc)
            next_hour = (now + timedelta(hours=1)).replace(
                minute=2, second=0, microsecond=0
            )
            sleep_seconds = (next_hour - now).total_seconds()
            await asyncio.sleep(max(1.0, sleep_seconds))

            current_hour = now.strftime("%Y-%m-%dT%H")
            _run_rollup_for_all_campaigns(current_hour, "hourly")

            # At 00:05 UTC, also compute yesterday's daily rollup
            if now.hour == 23:  # run at 23:02 to cover the final hour of the day
                yesterday = (now - timedelta(days=1)).strftime("%Y-%m-%d")
                _run_rollup_for_all_campaigns(yesterday, "daily")

        except asyncio.CancelledError:
            break
        except Exception:
            logger.exception("ad_analytics_rollup_loop_error")
            await asyncio.sleep(60)


def _run_rollup_for_all_campaigns(period_key: str, rollup_type: str) -> None:
    """Fetch all active campaigns and compute rollup for the given period."""
    from boto3.dynamodb.conditions import Attr
    try:
        resp = T.ad_campaigns.scan(
            FilterExpression=Attr("status").eq("active")
        )
        for item in resp.get("Items", []):
            campaign_id = item.get("campaign_id") or item.get("sk", "").replace("CAMPAIGN#", "")
            account_id = item.get("account_id") or item.get("pk", "").replace("ACCT#", "")
            if not campaign_id or not account_id:
                continue
            try:
                if rollup_type == "hourly":
                    compute_hourly_rollup(campaign_id, account_id, period_key)
                else:
                    compute_daily_rollup(campaign_id, account_id, period_key)
            except Exception:
                logger.warning(
                    "ad_analytics_campaign_rollup_failed",
                    extra={"campaign_id": campaign_id, "period": period_key},
                )
    except Exception:
        logger.exception("ad_analytics_scan_failed")


def start_ad_analytics_rollup_task():
    """Register the hourly analytics rollup background task at startup."""
    loop = asyncio.get_event_loop()
    loop.create_task(_ad_analytics_rollup_loop())
```

### Change 4 — Register in `app/main.py`

```python
from app.services.ad_analytics import start_ad_analytics_rollup_task

app.add_event_handler("startup", start_ad_analytics_rollup_task)
```

### Dev/Prod parity (SECOPS-007)

All table operations (`T.ad_campaigns.scan`, `T.ad_analytics_rollups.put_item`, `T.ad_analytics_rollups.query`) use the shared `T` table handle, which resolves to DynamoDB Local in dev and AWS DynamoDB in prod. The same code path is taken in both environments. There is no mock or dev-specific bypass needed.

For dev convenience, an env var `AD_ANALYTICS_ROLLUP_INTERVAL_MINUTES` (default `60`) can be added to `settings.py` so developers can set it to `1` or `5` to see rollup data populate quickly without waiting an hour. The task loop sleeps to the next `interval` boundary rather than to the next clock hour when this override is set.

### Rollout

- **Effort:** M (approximately 6-8 hours: fix `compute_hourly_rollup` window filter, add `compute_daily_rollup`, add background loop, add `main.py` registration, add tests, add optional interval env var)
- **Risk:** Medium. The background task runs a campaign `scan` once per hour. For large ad catalogs (thousands of active campaigns), this scan could be slow or expensive. Mitigate with DDB `Limit` + pagination in `_run_rollup_for_all_campaigns`, and add a Capacity Unit budget alarm.
- **Migration:** Historical hourly and daily rollups do not exist. A one-time backfill script can replay billing entries from `T.ad_billing` to populate historical rollups. This should be a follow-on ticket.
- **Rollback:** Remove `start_ad_analytics_rollup_task` from `main.py`. The `T.ad_analytics_rollups` table will simply stop being populated (as it is today).
- **Sequencing:** Depends on GAP-0048 for daily spend data integrity, but can be implemented independently. Register the task in `main.py` in the same PR as GAP-0048's reset task to reduce merge friction on `main.py`.
