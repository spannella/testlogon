# GAP-0148: No Caller Rate Display Before Initiating Call — Remediation Write-up

> ~5 pages. Source ticket: CALL-011. No investigation doc exists; code verified directly.

## 1. Summary & Classification

**Claim verification: CONFIRMED.**  The gap ticket states that `frontend/src/pages/messages/PaidCallRateBadge.tsx` does not exist and that callers have no visual indication of the per-minute cost before pressing the call button.  Both assertions are correct: the file is absent, and no other component in the codebase calls `GET /ui/calls/rates/{partner_user_id}` or displays rate information near the call button.

The backend endpoint `GET /ui/calls/rates/{creator_id}` (`app/routers/call_billing.py:78`) returns the creator's configured `rate_cents_per_minute`, `enabled`, and other rate metadata.  The frontend API wrapper `getCallRate(creatorId)` exists in `frontend/src/api/endpoints/callBilling.ts:54–55`.  The gap is entirely in the UI layer.

**Severity**: HIGH — callers initiating paid calls have no pre-call disclosure of the per-minute cost.  This is both a trust/UX problem and a potential consumer-protection concern: a user presses the call button without knowing a charge will begin, and the first indication of cost appears only after connection (GAP-0147's billing overlay, once fixed).

## 2. Current-State Investigation (Root Cause)

### 2.1 Call Button Location

In `ConversationView.tsx`, the call initiation buttons are rendered as part of the conversation toolbar.  Around line 3 the imports include `Phone` and `Video` icons from `lucide-react`.  The toolbar (rendered in the header area of the conversation view) contains direct-call buttons that dispatch `createCallInvite`.  No rate information is fetched or displayed alongside these buttons.

### 2.2 `getCallRate` API Wrapper Exists

`frontend/src/api/endpoints/callBilling.ts:53–55`:

```typescript
/** Get a creator's per-minute call rate. */
export const getCallRate = (creatorId: string) =>
  api.get<CallRate>(`/ui/calls/rates/${creatorId}`);
```

`CallRate` interface at `callBilling.ts:7–13`:

```typescript
export interface CallRate {
  rate_cents_per_minute: number;
  enabled: boolean;
  currency: string;
  min_balance_minutes: number;
  max_duration_minutes: number;
}
```

The data contract is complete.  Nothing calls `getCallRate` in the messaging UI.

### 2.3 Backend Endpoint

`app/routers/call_billing.py:78–97` implements `GET /ui/calls/rates/{creator_id}`:

```python
@router.get("/ui/calls/rates/{creator_id}", response_model=CallRateOut)
async def get_creator_rate(creator_id: str, ...):
    ...
```

The endpoint reads the `CALL_RATE` row from the `billing` DynamoDB table for `creator_id`.  It returns a 404 if no rate is configured (creator has not enabled paid calls).  This means `useQuery` on this endpoint will return `null`/`undefined` for users who have not configured a rate — the badge must handle this gracefully by rendering nothing.

### 2.4 What the Spec Requires

CALL-011 §4.4 describes a `PaidCallRateBadge` component that:
- Uses `useQuery` on `GET /ui/calls/rates/{partner_user_id}`.
- Renders nothing (returns `null`) when no rate exists or the rate is disabled.
- Renders a visible badge (e.g., `"$1.00/min"`) when a rate is configured and enabled.
- Is placed adjacent to the call button so the caller sees the cost before clicking.

### 2.5 Call Invite Pre-check

When `createCallInvite` is called with `paid: true`, the backend at `app/routers/messaging.py:12978–12985` verifies:
1. The callee has a valid enabled call rate.
2. The caller's wallet balance is sufficient for `min_balance_minutes`.

If the caller has insufficient balance, a 402 is returned.  The badge prevents the user from being surprised by this error by surfacing the rate before they click — but neither the badge nor any pre-call balance check currently exists on the frontend.

## 3. Impact / Exploit / Blast Radius

**User trust**: A caller pressing the call button without any cost indication discovers they are being charged only after the call connects (assuming GAP-0147 is also fixed) or, worse, only when they receive a billing statement.  This pattern fails basic e-commerce disclosure requirements in many jurisdictions.

**Support cost**: Without pre-call disclosure, users who did not realize a call was paid are likely to dispute charges or request refunds.

**Frequency**: Affects every conversation where the other party has configured a paid-call rate.  Volume scales with creator adoption of the pay-per-minute feature.

**Error experience**: A caller who clicks "Call" without sufficient balance receives a 402 API error with no contextual explanation.  The badge pre-warns that a minimum balance is required, reducing confusing error states.

## 4. Fix Design (Code-Level)

### 4.1 Create `frontend/src/pages/messages/PaidCallRateBadge.tsx`

```typescript
// frontend/src/pages/messages/PaidCallRateBadge.tsx
import * as React from "react";
import { useQuery } from "@tanstack/react-query";
import { getCallRate } from "@/api/endpoints/callBilling";
import { DollarSign } from "lucide-react";
import { Badge } from "@/components/ui/badge";
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip";

interface Props {
  /** The user ID of the person being called (i.e., the creator / callee). */
  partnerUserId: string;
}

/**
 * Displays the per-minute rate for a paid call with the given partner.
 * Renders nothing if the partner has not configured a paid-call rate or
 * if calls are not enabled.
 */
export function PaidCallRateBadge({ partnerUserId }: Props) {
  const { data } = useQuery({
    queryKey: ["call-rate", partnerUserId],
    queryFn: () => getCallRate(partnerUserId),
    // Backend returns 404 if no rate is set; React Query treats this as an error.
    // We catch and treat it as "no rate configured".
    retry: false,
    staleTime: 60_000,   // rates change infrequently
  });

  if (!data?.enabled || !data?.rate_cents_per_minute) {
    return null;
  }

  const dollars = (data.rate_cents_per_minute / 100).toFixed(2);
  const currency = data.currency ?? "USD";

  return (
    <Tooltip>
      <TooltipTrigger asChild>
        <Badge
          variant="secondary"
          className="gap-1 text-xs font-normal"
          data-testid="paid-call-rate-badge"
        >
          <DollarSign className="h-3 w-3" />
          {dollars}/{currency === "USD" ? "min" : `min (${currency})`}
        </Badge>
      </TooltipTrigger>
      <TooltipContent>
        <p>This is a paid call.</p>
        <p>Rate: ${dollars} per minute.</p>
        <p>Minimum balance required: {data.min_balance_minutes} min.</p>
      </TooltipContent>
    </Tooltip>
  );
}
```

Design decisions:
- `retry: false` — a 404 (no rate configured) should not be retried; the badge silently returns `null`.
- `staleTime: 60_000` — rate data is cached for one minute to avoid hammering the API on every conversation view.
- `data?.enabled` guard — if a creator disables their rate, the badge immediately disappears on next cache refresh.
- Tooltip provides the full detail (rate, min balance) without cluttering the call button row.

### 4.2 Wire into `ConversationView.tsx`

The call buttons are rendered in the conversation header toolbar.  The rate badge should appear directly adjacent to the call button and only for DM conversations (group calls have a separate billing model, not yet implemented).

1. **Import**:
   ```typescript
   import { PaidCallRateBadge } from "./PaidCallRateBadge";
   ```

2. **Determine partner user ID** — for a DM, the partner is the other participant.  This is already computable from `conversation.participants` filtered to exclude `userId`.

3. **Render** — alongside the call button (around the toolbar `Phone`/`Video` button area):
   ```typescript
   {!isGroup && partnerUserId && callsEnabled && (
     <PaidCallRateBadge partnerUserId={partnerUserId} />
   )}
   ```

The badge renders `null` silently when the partner has no rate; free calls are completely unaffected.

### 4.3 Handle 404 in `getCallRate`

The existing `api.get` wrapper in `callBilling.ts` will throw on 404 (non-2xx).  The `useQuery` `onError` / `throwOnError` behavior means the error surfaces in the `error` state but does not crash the page.  The badge already handles this by returning `null` when `data` is `undefined`.  However, to be explicit, add an `onError` handler or use `throwOnError: false` to prevent React Query from logging a console error:

```typescript
// In the useQuery options inside PaidCallRateBadge:
meta: { suppressErrors: true },
```

Or configure a `QueryCache` default error handler that ignores 404 for this query key pattern.

Alternatively, the `getCallRate` wrapper can be made to return `null` on 404:

```typescript
export async function getCallRate(creatorId: string): Promise<CallRate | null> {
  try {
    return await api.get<CallRate>(`/ui/calls/rates/${creatorId}`);
  } catch (err) {
    if (err instanceof ApiError && err.status === 404) return null;
    throw err;
  }
}
```

This is the recommended approach — it converts the "no rate configured" case from an error to a clean `null` return, eliminating the need for error-state handling in the badge itself.

### 4.4 Dev/Prod Parity (SECOPS-007)

`GET /ui/calls/rates/{creator_id}` uses the same DynamoDB `billing` table in dev (moto, port 4566) and production (AWS DynamoDB).  The `call_billing_enabled` backend flag (`app/core/settings.py`) gates rate lookups.  The badge's `useQuery` is unconditional — if the backend returns 404 or an error, the badge renders nothing.  No `DEV_MODE` branching is needed in the frontend component.

For local testing, a call rate can be seeded directly via DynamoDB:

```python
# scripts/local-ddb-seed.py or test setup
billing_table.put_item(Item={
    "pk": f"USER#{creator_sub}",
    "sk": "CALL_RATE",
    "rate_cents_per_minute": 100,
    "enabled": True,
    "currency": "USD",
    "min_balance_minutes": 5,
    "max_duration_minutes": 120,
})
```

6. Reload Alice's conversation — badge is gone.
7. Verify free calls (conversations where the partner has no rate) never show the badge.

### 5.3 Metrics / Observability

The `GET /ui/calls/rates/{creator_id}` backend endpoint will receive one request per conversation view where the partner has a rate configured.  Monitor `call_rate_lookups_total` (or standard request counters by path) for unexpected spikes.  The `staleTime: 60_000` in the hook limits re-fetches to at most once per minute per conversation.

### 5.4 Rollback

The badge renders `null` when data is absent.  Removing the `<PaidCallRateBadge>` render site from `ConversationView.tsx` returns to the prior state with zero functional change to call initiation.
