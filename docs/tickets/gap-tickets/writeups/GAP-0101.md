# GAP-0101: SEC-021 Latent — No repo_url Validation Before Real Execution — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; `file:line` citations are live.

## 1. Summary & Classification

**Severity**: HIGH
**Source ticket**: AGENT-015
**Owning area**: Compliance & Security Agent / Agent PR Integration
**Status**: Open (no fix deployed as of this write-up)

The gap audit identified that `review_pr_mock` at `app/services/agent_compliance.py:1041` accepts an arbitrary `pr_ref` string without validating that the corresponding repository URL belongs to an allowlist of permitted hosts. When `S.compliance_agent_execute_commands` is flipped to `True` for real scanning, any attacker with a valid user session could supply a `pr_ref` that resolves to an arbitrary remote — triggering git clones, secret scans, or GitHub API calls against attacker-controlled infrastructure.

**Claim accuracy**: The ticket nominates line 1041 as the vulnerability site. Code inspection confirms `review_pr_mock` begins at line 1041. However, the broader vulnerability also spans `app/services/agent_pr_integration.py:387` (`create_pr_from_agent`) and `app/services/agent_pr_integration.py:363` (`_create_pr_via_api`), which accept a caller-supplied `repo_url` that is passed unvalidated to GitHub API calls. The gap claim is **partially accurate** — the site is real, but the full attack surface is wider than the single function named.

**Related tickets**: GAP-0079 (repo_url shell injection latent), GAP-0089 (command injection in build-coder workflow), GAP-0090 (build-pr command double-quote injection), GAP-0091 (pr-review command injection), GAP-0094 (repo/branch shell injection latent), GAP-0102 (GitHub token must not be stored in DDB — sibling credential-handling gap).

## 2. Current-State Investigation (root cause)

### 2.1 `review_pr_mock` at `app/services/agent_compliance.py:1041`

```python
def review_pr_mock(
    *, user_id: str, agent_id: str, pr_ref: str,
    diff_findings: Optional[List[Dict[str, Any]]] = None
) -> Dict[str, Any]:
    config = get_effective_config(user_id=user_id)
    created: List[Dict[str, Any]] = []
    for df in diff_findings or []:
        ...
        f = create_finding(
            ...
            source_ref=pr_ref,
            ...
        )
```

`pr_ref` is stored verbatim as `source_ref` on every finding and returned in API responses. In the mock path this is benign: no network call is made. The risk materialises the moment a real-execution path exists. The docstring says the function is "gated by `S.compliance_agent_execute_commands`" but the gate is not enforced inside the function — there is no guard that checks `S.compliance_agent_execute_commands` before proceeding. The gate is assumed to live at the call site; investigation shows no call site enforces it:

```
grep -rn "review_pr_mock" app/
  app/services/agent_compliance.py:1041:def review_pr_mock(
  app/services/agent_qa.py:1008: "review_pr"
```

There is no actual call site in production routers that calls `review_pr_mock` with an `execute_commands` guard. The function is currently dead-wired; when wired up it will receive the raw user input.

### 2.2 `_create_pr_via_api` at `app/services/agent_pr_integration.py:363`

```python
def _create_pr_via_api(
    *, repo_url: str, branch: str, title: str, description: str, user_id: str,
) -> Dict[str, Any]:
    token = getattr(S, "github_token", "")
    if S.dev_mode or not token:
        ...  # mock: no network call
    # Real implementation would POST to {github_api_base_url}/repos/.../pulls.
    raise NotImplementedError("Live GitHub API integration not enabled.")
```

`repo_url` arrives from `AgentPrCreateIn.repo_url` via the router (`app/routers/agent_pr_integration.py:61`). There is no validation that `repo_url` matches a known host before the token is used. Once the `NotImplementedError` branch is removed and real HTTP calls are inserted, an attacker can supply `repo_url = "https://attacker.example.com/evil"` and the platform's `GITHUB_TOKEN` would be sent to that host in the `Authorization` header.

### 2.3 Settings: `S.github_token`

`app/core/settings.py:910`:
```python
github_token: str = os.environ.get("GITHUB_TOKEN", "")
```

The token is stored as a plain environment-sourced string, not a KMS-resolved reference. In dev it is empty; in production it would be populated. There is no `github_token_secret_name` indirection pattern.

### 2.4 `_DEFAULT_SECURITY_CONFIG` does not contain `allowed_repo_hosts`

`app/services/agent_compliance.py:113–137` shows the full default config. There is no `allowed_repo_hosts`, `allowed_repo_patterns`, or equivalent field. Similarly `_CONFIG_FIELDS` (line 139) does not include any such field.

### 2.5 `AgentPrCreateIn.repo_url` model — no constraint

In `app/models.py`, the input model for PR creation accepts `repo_url` without a validator:

```python
class AgentPrCreateIn(BaseModel):
    repo_url: Optional[str] = None
    branch: Optional[str] = None
    title: Optional[str] = None
    description: Optional[str] = None
    ticket_id: str
    files_changed: Optional[List[str]] = None
    method: str = "cli"
```

No `AnyUrl`, no `field_validator`, no pattern restriction. Pydantic accepts any string, including `javascript:` URIs, `file://` paths, and `https://` URLs pointing at internal VPC endpoints (IMDS, metadata services, internal load balancers).

### 2.6 Dev vs prod parity

In dev mode (`S.dev_mode = True`) `_create_pr_via_api` short-circuits before any outbound HTTP call, so the vulnerability is latent in dev. The gap is a classic dormant vulnerability: safe today, dangerous the moment the execute gate is removed or the `NotImplementedError` in `_create_pr_via_api` is replaced with a real GitHub API call.

## 3. Impact / Exploit / Blast Radius

### 3.1 SSRF via `repo_url`

With `compliance_agent_execute_commands = True` and a real GitHub integration wired:

1. Attacker authenticates and calls `POST /ui/agent/pr/{worker_id}/create` with `body.repo_url = "https://169.254.169.254/latest/meta-data/"` (AWS IMDS).
2. `create_pr_from_agent` passes the URL to `_create_pr_via_api`.
3. The platform's GitHub token is sent as `Authorization: Bearer <github_token>` in a `POST` to the attacker-controlled URL.
4. Attacker harvests the token from their server logs; alternatively, if IMDS is hit, harvests EC2 instance credentials.

Worst case: exfiltration of `GITHUB_TOKEN` (repo read/write/delete) and AWS instance profile credentials.

### 3.2 Stored `pr_ref` in findings

Arbitrary `pr_ref` strings are stored in the `compliance_security_findings` DynamoDB table as `source_ref`. While this doesn't directly execute code, it poisons the audit trail and can be surfaced to admin dashboards or third-party integrations, constituting a stored injection point.

### 3.3 Scope

All authenticated users (role=USER and above) can call the PR create endpoint and set `repo_url`. The compliance audit trigger requires admin/root (`require_admin_or_root` on `/audits/trigger`), but the PR creation path at `/ui/agent/pr/{worker_id}/create` requires only `require_ui_session` — meaning any registered user with a valid session can exploit this.

### 3.4 Internal network pivoting

In an AWS VPC deployment, `repo_url` can be set to internal service URLs (e.g., `http://internal-rds-proxy.vpc.local/`, `http://10.0.1.5:5432/`). Even if the response is discarded, the GitHub API client makes a TCP connection and sends an HTTP request with an `Authorization` header, potentially triggering unintended side effects on internal services that have no authentication themselves.

## 4. Fix Design (code-level)

### 4.1 Add `allowed_repo_hosts` to the security config

**`app/services/agent_compliance.py` — extend `_DEFAULT_SECURITY_CONFIG`:**

```python
_DEFAULT_SECURITY_CONFIG: Dict[str, Any] = {
    ...
    "allowed_repo_hosts": ["github.com", "gitlab.com"],  # ADD
    ...
}
_CONFIG_FIELDS = tuple(_DEFAULT_SECURITY_CONFIG.keys())
```

**`app/models.py` — extend `SecurityAgentConfigOut` and `UpdateSecurityConfigIn`:**

```python
class SecurityAgentConfigOut(BaseModel):
    ...
    allowed_repo_hosts: List[str] = Field(default_factory=lambda: ["github.com", "gitlab.com"])
    ...

class UpdateSecurityConfigIn(BaseModel):
    ...
    allowed_repo_hosts: Optional[List[str]] = None
```

### 4.2 Add a validation helper

In `app/services/agent_compliance.py`, add before `review_pr_mock`:

```python
from urllib.parse import urlparse

def _validate_repo_url(repo_url: str, allowed_hosts: List[str]) -> None:
    """Raise ValueError if repo_url hostname is not in the allowlist."""
    if not repo_url:
        return  # empty means CLI mode; no outbound call
    try:
        parsed = urlparse(repo_url)
    except Exception:
        raise ValueError(f"invalid_repo_url: could not parse {repo_url!r}")
    host = (parsed.hostname or "").lower()
    if not any(
        host == allowed or host.endswith("." + allowed)
        for allowed in [h.lower() for h in allowed_hosts]
    ):
        raise ValueError(
            f"repo_url host {host!r} is not in allowed_repo_hosts"
        )
```

### 4.3 Apply the validation in `review_pr_mock`

```python
def review_pr_mock(
    *, user_id: str, agent_id: str, pr_ref: str,
    diff_findings: Optional[List[Dict[str, Any]]] = None
) -> Dict[str, Any]:
    config = get_effective_config(user_id=user_id)
    # Validate pr_ref as a URL when execute_commands is enabled
    if S.compliance_agent_execute_commands:
        _validate_repo_url(pr_ref, config.get("allowed_repo_hosts", ["github.com"]))
    ...
```

### 4.4 Apply the validation in `_create_pr_via_api`

In `app/services/agent_pr_integration.py`, import and apply:

```python
from app.services.agent_compliance import _validate_repo_url, get_effective_config

def _create_pr_via_api(
    *, repo_url: str, branch: str, title: str, description: str, user_id: str,
) -> Dict[str, Any]:
    if not S.dev_mode:
        config = get_effective_config(user_id=user_id)
        _validate_repo_url(repo_url, config.get("allowed_repo_hosts", ["github.com"]))
    token = getattr(S, "github_token", "")
    ...
```

### 4.5 HTTP 400 on validation failure in the router

`app/routers/agent_pr_integration.py:48`:

```python
@router.post("/{worker_id}/create", status_code=201)
async def create_pr(...):
    ...
    try:
        pr = svc.create_pr_from_agent(...)
    except ValueError as exc:
        raise HTTPException(
            status_code=400,
            detail={"code": "invalid_repo_url", "message": str(exc)},
        )
    return pr
```

### 4.6 Dev/Prod parity (SECOPS-007)

- In `dev_mode = True`, `_create_pr_via_api` short-circuits before any outbound call; the validation can be skipped for test ergonomics (no allowlist needed for mock data), but it is still applied so local integration tests cover the same code path.
- The `allowed_repo_hosts` field is stored in DynamoDB (agent_types table, per-user config). In dev, the table is on DynamoDB Local; in prod it is on AWS DynamoDB — same code path, same validation.
- The `GITHUB_TOKEN` in production should be moved to AWS Secrets Manager (see GAP-0102), but this fix is independent of that migration.

### 4.7 Alternatives considered

- **Environment-level allowlist only** (e.g., `ALLOWED_REPO_HOSTS` env var): rejected because it cannot be scoped per user and requires a redeploy to add a new host.
- **Reject any URL not matching `github.com`**: overly restrictive for self-hosted GitLab/GitHub Enterprise users; the per-user config list is more ergonomic.

## 5. Testing, Verification & Rollout

### 5.1 Pytest regression test (fails before / passes after)

Add to `tests/test_agent_compliance.py`:

```python
import pytest
from unittest.mock import patch

def test_review_pr_mock_rejects_non_allowlist_repo_when_execute_enabled(client, alice_session):
    """BEFORE fix: review_pr_mock stores any pr_ref without validation.
    AFTER fix: ValueError raised when execute_commands=True and host not in allowlist."""
    with patch("app.core.settings.S.compliance_agent_execute_commands", True):
        from app.services.agent_compliance import review_pr_mock, _validate_repo_url
        # Should raise on attacker-controlled host
        with pytest.raises(ValueError, match="not in allowed_repo_hosts"):
            _validate_repo_url(
                "https://attacker.example.com/evil/repo",
                ["github.com", "gitlab.com"],
            )
        # Should pass for allowed host
        _validate_repo_url("https://github.com/owner/repo", ["github.com"])
        # Empty string should pass (CLI mode — no outbound call)
        _validate_repo_url("", ["github.com"])

def test_create_pr_rejects_disallowed_repo_url(client, alice_session):
    """POST /ui/agent/pr/{worker_id}/create returns 400 for non-allowlist repo_url."""
    # Create a worker first
    ...
    resp = client.post(
        f"/ui/agent/pr/{worker_id}/create",
        json={"repo_url": "https://evil.example.com/pwn", "ticket_id": "t1"},
        headers=alice_session,
    )
    assert resp.status_code == 400
    assert resp.json()["detail"]["code"] == "invalid_repo_url"
```

### 5.2 Manual QA steps

1. Start dev stack (`just up`).
2. Log in as Alice. Create a worker via the Agent Fleet UI.
3. Call `POST /ui/agent/pr/{id}/create` with `repo_url = "https://github.com/legit/repo"` — expect 201.
4. Call the same endpoint with `repo_url = "https://attacker.example.com/evil"` — expect 400 with `code: invalid_repo_url`.
5. Confirm that the compliance config endpoint `GET /ui/agents/compliance/config` returns `allowed_repo_hosts` in the response.
6. Update the config via `PUT /ui/agents/compliance/config` with `allowed_repo_hosts: ["github.com", "mycompany.gitlab.com"]` and confirm the new list is respected.

### 5.3 Observability

Log a WARNING whenever `_validate_repo_url` rejects a host:

```python
logger.warning("repo_url validation rejected host=%r user=%s", host, user_id)
```

This surfaces reconnaissance attempts in application logs and can trigger a CloudWatch metric filter alarm.

### 5.4 Rollout and risks

- **Effort**: S (small) — two service files, one model file, one router change, a handful of test cases.
- **Rollout**: Deploy with default allowlist `["github.com", "gitlab.com"]`. Users with self-hosted Git servers or GitHub Enterprise domains (e.g., `github.mycompany.com`) will need to add their host via `PUT /ui/agents/compliance/config` before the execute flag is turned on; document this in the feature-flag runbook and surface a warning in the UI config panel if `allowed_repo_hosts` is empty and the flag is enabled.
- **Backward compatibility**: Existing `pr_ref` values stored as `source_ref` in the `compliance_security_findings` table are unaffected (historical data is not re-validated). No DynamoDB migration required.
- **Rollback**: Revert the validation call in `review_pr_mock` and `_create_pr_via_api`. The `allowed_repo_hosts` field in DDB is ignored if the validation code is absent, so no data migration is needed on rollback.
- **Sequencing**: This fix is a hard prerequisite for enabling `COMPLIANCE_AGENT_EXECUTE_COMMANDS=1` in any environment. GAP-0079 (repo_url shell injection), GAP-0089–0091 (command injection), and GAP-0094 (branch shell injection) must be resolved in the same sprint to close the full shell injection surface. GAP-0102 (GitHub token credential storage) should be resolved concurrently so the token being protected is never sent to an attacker-controlled host even if validation is momentarily bypassed.
