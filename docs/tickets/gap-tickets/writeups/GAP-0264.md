# GAP-0264: `case["signature"]` Stores Single Packet; Template Packets Require a List — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No investigation
> doc exists for this gap; code verification was performed as part of this write-up.

## 1. Summary & Classification

**Gap**: The `case["signature"]` map in DynamoDB stores a single `packet_id`. The KYC-007
template workflow requires one signature packet per consent template (up to five). The
current data model cannot represent a list of template packets without colliding with
the existing single-packet check in `_signature_status_for_case()`.

**Verdict**: Confirmed. `_signature_status_for_case()` at
`app/routers/kyc_cases.py:205` reads `case["signature"]["packet_id"]` as a scalar string.
The DDB update expressions in `update_case_links`
(`app/services/kyc_cases.py:291`) write a single `signature` map with one `packet_id` key.
Neither the router nor the service has any concept of a `template_packets` list.

- **Severity**: HIGH
- **Source ticket**: KYC-007 / GAP-0264
- **Status**: Open
- **Owning area**: KYC / Document Signing (data model)
- **Impact**: Deploying the template service (GAP-0261) without this fix would result in
  only the last-written template packet being stored (each call to `update_case_links`
  overwrites the entire `signature` map), silently discarding previously created template
  packets.
- **Related tickets**: GAP-0261 (service, calls `update_case_links` to persist
  `template_packets`), GAP-0262 (router, reads `template_packets`). Must be fixed before
  those tickets can function correctly.

## 2. Current-State Investigation (root cause)

### 2.1 Current `case["signature"]` shape

Written by `create_or_link_signature_packet` at `app/routers/kyc_cases.py:1326`:

```python
signature = {
    "packet_id": str(packet.get("packet_id") or ""),
    "status": str(packet.get("status") or ""),
    "final_pdf_ref": None,
    "legal_notice_version": S.signature_packet_legal_notice_version,
    "legal_notice_accepted": False,
}
```

This map is stored wholesale via `STORE.update_case_links(..., signature=signature)`.

### 2.2 `_signature_status_for_case` reads only `packet_id`

`app/routers/kyc_cases.py:205`:

```python
def _signature_status_for_case(case: dict) -> dict:
    sref = case.get("signature") or {}
    packet_id = str(sref.get("packet_id") or "").strip() or None
    ...
    if not packet_id:
        return { ... "ready_for_submit_gate": False }
    ...
    return { ... "ready_for_submit_gate": bool(completed and final_ready) }
```

The function only interrogates `sref["packet_id"]`. If `signature` has a `template_packets`
list but no `packet_id`, the gate returns `ready_for_submit_gate: False` — blocking case
submission even when all template packets are signed.

### 2.3 `update_case_links` overwrites the entire `signature` map

`app/services/kyc_cases.py:291` — the DDB update expression:

```python
UpdateExpression=(
    "SET questionnaire=:questionnaire, files=:files, signature=:signature, ..."
),
ExpressionAttributeValues={
    ...
    ":signature": signature or dict(existing.get("signature") or _empty_signature_ref()),
    ...
},
```

The entire `signature` attribute is replaced atomically. There is no `list_append` or
partial-update path. Every call to `update_case_links` with a `signature` argument clobbers
the previous value. If `create_packets_for_case` (GAP-0261) calls this helper once per
template, only the last call's packet would survive.

### 2.4 The `_readiness_for_case` cascade

`app/routers/kyc_cases.py:244` calls `_signature_status_for_case` and surfaces its
`ready_for_submit_gate` flag as one of the three pre-submission checks. The submit endpoint
(`app/routers/kyc_cases.py:895`) blocks submission when any check fails. Adding a
`template_packets` list without updating `_signature_status_for_case` would break
submission for all cases that use the new template flow.

## 3. Impact / Exploit / Blast Radius

### 3.1 Silent data loss

If GAP-0261 were deployed without this fix, each call to `create_packets_for_case` would
overwrite `case["signature"]`, retaining only the most recently created template packet.
The previous template packets would be lost from the case record. The packets themselves
would still exist in DDB (in `T.signature_packet_fields`), but the case would have no
reference to them.

### 3.2 Submit gate regression

If the template flow replaces the legacy single-packet flow without updating
`_signature_status_for_case`, the signature readiness gate evaluates `packet_id` which
is now absent (only `template_packets` is populated). All cases using the new template
flow would be blocked from submission with `signature_completed: false` regardless of
actual signing status.

### 3.3 Blast radius

The blast radius is fully contained within the future template workflow. The existing
single-packet path (`case["signature"]["packet_id"]`) is untouched. The risk only
materialises when GAP-0261 is deployed without this fix.

## 4. Fix Design (code-level)

The fix uses an additive approach: the existing `packet_id` key in `case["signature"]` is
preserved for backward compatibility; the new `template_packets` list is added as a
sibling key. `_signature_status_for_case` is extended to consider both paths.

### 4.1 Extended `case["signature"]` shape

```json
{
    "packet_id": "pkt_legacy_abc",          // existing — single ad-hoc packet
    "status": "completed",
    "final_pdf_ref": "packet:pkt_legacy_abc:final-pdf",
    "legal_notice_version": "v1.2",
    "legal_notice_accepted": true,
    "template_packets": [                    // NEW — list of template packets
        {
            "template_type": "terms_of_service",
            "packet_id": "pkt_tos_001",
            "version": "2026-05-v1"
        },
        {
            "template_type": "aml_declaration",
            "packet_id": "pkt_aml_002",
            "version": "2026-05-v1"
        },
        ...
    ]
}
```

A case may have `packet_id` set (legacy flow), `template_packets` set (template flow), or
both. `_signature_status_for_case` must handle all three variants.

### 4.2 Update `_signature_status_for_case` — `app/routers/kyc_cases.py:205`

```python
def _signature_status_for_case(case: dict) -> dict:
    sref = case.get("signature") or {}
    packet_id = str(sref.get("packet_id") or "").strip() or None
    template_packets = list(sref.get("template_packets") or [])
    legal_notice_version = str(
        sref.get("legal_notice_version") or S.signature_packet_legal_notice_version
    ).strip() or None

    # ---- Legacy single-packet path (unchanged) ----
    if packet_id and not template_packets:
        if not packet_id:
            return {
                "kyc_case_id": case.get("kyc_case_id"),
                "packet_id": None,
                "packet_status": None,
                "completed": False,
                "final_pdf_ready": False,
                "final_pdf_ref": None,
                "legal_notice_version": legal_notice_version,
                "legal_notice_accepted": False,
                "ready_for_submit_gate": False,
                "template_packets": [],
            }
        packet = get_packet(packet_id) or {}
        packet_status = str(packet.get("status") or "")
        completed = packet_status == "completed"
        artifact = get_packet_artifact(packet_id) or {}
        final_ready = bool(
            artifact and str(artifact.get("status") or "") == "ready"
        )
        final_ref = f"packet:{packet_id}:final-pdf" if final_ready else None
        signers = list_packet_signers(packet_id)
        accepted = False
        if signers:
            accepted = all(
                str(s.get("legal_notice_accepted_version") or "")
                == str(legal_notice_version or "")
                for s in signers
            )
        return {
            "kyc_case_id": case.get("kyc_case_id"),
            "packet_id": packet_id,
            "packet_status": packet_status or None,
            "completed": completed,
            "final_pdf_ready": final_ready,
            "final_pdf_ref": final_ref,
            "legal_notice_version": legal_notice_version,
            "legal_notice_accepted": accepted,
            "ready_for_submit_gate": bool(completed and final_ready),
            "template_packets": [],
        }

    # ---- New template-packets path ----
    if template_packets:
        statuses = []
        all_completed = True
        all_final_ready = True
        for tp in template_packets:
            pid = str(tp.get("packet_id") or "").strip()
            pkt = get_packet(pid) if pid else None
            ps = str((pkt or {}).get("status") or "")
            art = get_packet_artifact(pid) if pid else None
            fr = bool(art and str(art.get("status") or "") == "ready")
            statuses.append({
                "template_type": tp.get("template_type"),
                "packet_id": pid,
                "packet_status": ps or None,
                "completed": ps == "completed",
                "final_pdf_ready": fr,
            })
            if ps != "completed":
                all_completed = False
            if not fr:
                all_final_ready = False

        return {
            "kyc_case_id": case.get("kyc_case_id"),
            "packet_id": packet_id,              # may be None
            "packet_status": None,
            "completed": all_completed,
            "final_pdf_ready": all_final_ready,
            "final_pdf_ref": None,
            "legal_notice_version": legal_notice_version,
            "legal_notice_accepted": False,
            "ready_for_submit_gate": bool(all_completed and all_final_ready),
            "template_packets": statuses,
        }

    # ---- No packet linked at all ----
    return {
        "kyc_case_id": case.get("kyc_case_id"),
        "packet_id": None,
        "packet_status": None,
        "completed": False,
        "final_pdf_ready": False,
        "final_pdf_ref": None,
        "legal_notice_version": legal_notice_version,
        "legal_notice_accepted": False,
        "ready_for_submit_gate": False,
        "template_packets": [],
    }
```

### 4.3 `update_case_links` — idempotent merge for `template_packets`

The `update_case_links` helper in `app/services/kyc_cases.py:291` already replaces the
entire `signature` map. The caller in `create_packets_for_case` (GAP-0261) must read the
current `signature` map, merge the new `template_packets` entries into it, and pass the
merged map as the `signature` argument. The merge logic is:

```python
# In the router endpoint (GAP-0262) or service (GAP-0261):
signature = dict(case.get("signature") or {})
existing_tp = list(signature.get("template_packets") or [])
existing_types = {p["template_type"] for p in existing_tp}
new_tp = [p for p in new_packets if p["template_type"] not in existing_types]
signature["template_packets"] = existing_tp + new_tp
```

No changes to `update_case_links` itself are required — the caller assembles the correct
merged map before passing it. The existing conditional-check on `version` prevents races.

### 4.4 Backward compatibility

- Cases with no `template_packets` key continue to use the legacy single-packet path
  in `_signature_status_for_case`. No migration needed.
- The `KycSignatureStatusEnvelope` response model in
  `app/contracts/kyc_cases_contract.py` must be extended to include an optional
  `template_packets: list` field (defaults to `[]`).
- `evidence_snapshot["signature"]` in `submit_case` currently stores only `packet_id`
  and `final_pdf_ref`. For the template path, the snapshot should store
  `template_packet_refs` as a list of `{template_type, packet_id}` entries. This is a
  new optional key; the existing snapshot structure is unchanged.

### 4.5 Dev/Prod parity (SECOPS-007)

All changes are to DynamoDB read/write logic using the existing DDB table
(`T.kyc_cases`, `S.kyc_cases_table_name`). The `signature` attribute is a DynamoDB map
type (M), which supports arbitrary nested attributes. No schema migration is required in
`scripts/local-ddb-init.py`. The `template_packets` list is stored inside the `signature`
map, not as a top-level attribute. Both moto and DynamoDB Local handle nested maps
identically.

def test_template_packets_merge_is_idempotent(kyc_store, draft_case):
    """Calling update_case_links twice with overlapping template types preserves dedup."""
    initial_sig = {"template_packets": [
        {"template_type": "terms_of_service", "packet_id": "p1", "version": "v1"}
    ]}
    kyc_store.update_case_links(
        case_id=draft_case["kyc_case_id"],
        owner_sub=draft_case["user_sub"],
        expected_version=draft_case["version"],
        signature=initial_sig,
    )
    case2 = kyc_store.get_case(draft_case["kyc_case_id"])
    # Simulate second call with same type — caller deduplicates before passing
    existing = list((case2.get("signature") or {}).get("template_packets") or [])
    existing_types = {p["template_type"] for p in existing}
    new_entries = [
        {"template_type": "aml_declaration", "packet_id": "p2", "version": "v1"},
        {"template_type": "terms_of_service", "packet_id": "p1", "version": "v1"},  # dup
    ]
    to_add = [e for e in new_entries if e["template_type"] not in existing_types]
    merged = existing + to_add
    sig = dict(case2.get("signature") or {})
    sig["template_packets"] = merged
    kyc_store.update_case_links(
        case_id=case2["kyc_case_id"],
        owner_sub=case2["user_sub"],
        expected_version=int(case2["version"]),
        signature=sig,
    )
    final = kyc_store.get_case(draft_case["kyc_case_id"])
    tp = list((final.get("signature") or {}).get("template_packets") or [])
    types = [p["template_type"] for p in tp]
    assert types.count("terms_of_service") == 1  # not duplicated
    assert "aml_declaration" in types

**Passes after**: new branch handles the template path correctly.

### 5.4 Rollout

- **Effort**: S (~1–2 days; most code is in the updated `_signature_status_for_case`)
- **Sequence**: Must land before or alongside GAP-0261 and GAP-0262 in the same PR.
- **Rollback**: If `_signature_status_for_case` is reverted, template-path cases lose
  their submit gate. Since no template-path cases exist before GAP-0261 is deployed,
  rollback is safe.
- **Migration**: No DDB migration required. `template_packets` is an optional nested
  attribute. Existing case items without it simply evaluate through the legacy code path.
- **Risk**: LOW — the only change to existing paths is the addition of `template_packets: []`
  to the return dict of `_signature_status_for_case`, which is a backward-compatible
  response extension.
