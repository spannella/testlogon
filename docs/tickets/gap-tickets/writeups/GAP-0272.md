# GAP-0272: `kyc.case.approved` and `kyc.case.rejected` Events Never Dispatched — Remediation Write-up

> Claim status: **CLAIM OK** — confirmed by code inspection. `apply_admin_decision()` in
> `app/services/kyc_cases.py` performs a DynamoDB update and returns the updated case without
> ever calling `_emit_kyc_event_safe`. Both `kyc.case.approved` and `kyc.case.rejected` are
> registered in the webhook event registry and have in-app alert titles, email subjects, and
> SSE handlers configured, but the dispatch call is absent from all KYC case approval/rejection
> code paths.

---

## 1. Summary & Classification

**Bug/Gap**: When an admin approves or rejects a KYC case via `POST /v1/kyc/cases/admin/cases/
{case_id}/approve` or `.../reject`, the corresponding `kyc.case.approved` / `kyc.case.rejected`
webhook events are never emitted. Users receive no in-app notification, no email, and no
webhook delivery when their KYC application is decided. The `kyc.case.submitted` event is
correctly dispatched (line 412 of `app/services/kyc_cases.py`), but there is no equivalent
call for final decisions.

**Severity**: HIGH — KYC-011. A user whose application is approved or rejected has no
programmatic notification channel. Compliance integrations (webhook subscribers), mobile
push pipelines, and downstream automations (e.g., KYC-tier upgrades triggered by the event)
all fail silently.

**Verdict**: Confirmed. The gap is in `STORE.apply_admin_decision()` in
`app/services/kyc_cases.py:586–657`. The function concludes with `return self.get_case(case_id)`
at line 657 without any `_emit_kyc_event_safe` call. The router (`_admin_decide_case` in
`app/routers/kyc_cases.py:1165–1260`) also has no call to the event helper.

**Related tickets**: GAP-0273 (`kyc.case.needs_info`), GAP-0274 (`kyc.case.created`), KYC-011,
SECOPS-007.

## 2. Current-State Investigation (Root Cause)

### Where the DDB write happens

`app/services/kyc_cases.py:633–656` (inside `apply_admin_decision`):

```python
try:
    self._table.update_item(
        Key={"pk": _case_pk(case_id), "sk": "META"},
        UpdateExpression=(...),
        ExpressionAttributeValues={
            ":status": target_status,   # "approved" or "rejected"
            ...
        },
        ConditionExpression="version = :expected_version",
    )
except ClientError as exc:
    ...
    raise
return self.get_case(case_id)  # line 657 — returns without emitting any event
```

`target_status` is `"approved"` if `decision == "approve"` and `"rejected"` if
`decision == "reject"` (line 604).

### What the submitted path does (correct pattern to copy)

`app/services/kyc_cases.py:412–417` (inside `submit_case`):

```python
_emit_kyc_event_safe(
    event="kyc.case.submitted",
    user_sub=owner_sub,
    case_id=case_id,
    submitted_at=ts,
)
return self.get_case(case_id)
```

The approved/rejected path is structurally identical but missing the `_emit_kyc_event_safe` call.

### Why the helper exists but is not called

`app/services/kyc_cases.py:17–27` defines `_emit_kyc_event_safe` as a module-level helper
precisely to be called after successful DDB writes. It wraps `emit_kyc_event` from
`app/services/kyc_webhooks.py:191` in a try/except so a notification failure never breaks the
state machine. The helper is only called once in this module (line 412, `submit_case`).

### Event infrastructure is fully wired for these events

`app/services/kyc_webhooks.py:38–63` registers both events:

```python
"kyc.case.approved": "Identity verification approved",
"kyc.case.rejected": "Identity verification not approved",
```

Both appear in `_EMAIL_SUBJECTS` (lines 60–61) and `_ALERT_TITLES` (lines 40–41). The
`emit_kyc_event` dispatcher handles them explicitly at lines 323–333:

```python
if event == "kyc.case.approved":
    ...   # writes LEDGER/tier-upgrade helpers
if event == "kyc.case.rejected":
    ...   # writes rejection-specific details
```

The dispatch infrastructure is complete; the only missing piece is the call site.

### Router also silent

`app/routers/kyc_cases.py:1207–1260` (`_admin_decide_case`) calls `STORE.apply_admin_decision`,
then `_ensure_decision_ticket_updates`, then `_audit_state_transition`, then
`_emit_kyc_metric` — but no `_emit_kyc_event_safe` call.

## 3. Impact / Exploit / Blast Radius

**Users**: A user whose KYC case is approved or rejected receives no in-app alert, no email
notification, and no webhook delivery. They can only discover the outcome by polling the case
status endpoint.

**Webhook subscribers**: Any external compliance system, partner integration, or automation
that subscribes to `kyc.case.approved` / `kyc.case.rejected` webhook topics receives zero
deliveries for every decision.

**Downstream automations**: The KYC-tier upgrade logic (GAP-0269) that is supposed to trigger
on `kyc.case.approved` cannot fire because the event is never emitted. The monitoring periodic
review schedule (`create_review_schedule` at router line 1248–1259) is still called from the
router directly, but any webhook-driven integrations that depend on the approval event will fail.

**Worst case**: At scale, a compliance team's external dashboard (subscribed to the webhook)
never learns about approved identities. Approved users are never granted tier-gated features
(e.g., higher withdrawal limits, subscription tiers) if those features are gated on the event
rather than on polling case status.

**Data integrity**: The DDB update itself is correct; no case data is lost. The bug is
notification-only, but in a regulated KYC context missing notifications can constitute a
compliance violation (timely notification of a decision is often required by AML/KYC rules).

## 4. Fix Design (Code-Level)

### Minimal targeted fix

Add two `_emit_kyc_event_safe` calls in `apply_admin_decision()`, immediately after the
successful `update_item` and before `return self.get_case(case_id)`:

**File**: `app/services/kyc_cases.py`

```python
# After the try/except block that calls self._table.update_item(...):
# (existing code, line ~654)
        except ClientError as exc:
            if _is_conditional_conflict(exc):
                raise KycCaseConflictError("kyc_case_update_conflict") from exc
            raise

# ADD these lines before the return:
        event_name = "kyc.case.approved" if target_status == "approved" else "kyc.case.rejected"
        _emit_kyc_event_safe(
            event=event_name,
            user_sub=str(existing.get("user_sub") or ""),
            case_id=case_id,
            decision=normalized,
            reason_codes=reason_codes,
            note=note,
            decided_at=ts,
            admin_sub=admin_sub,
        )
        return self.get_case(case_id)
```

`existing` is already bound at line 598 (the pre-update case fetch), and `target_status`,
`normalized`, `ts`, `admin_sub`, `reason_codes`, and `note` are all local variables in scope.

### Where to place in the function

The emit must occur **after** a confirmed successful DDB write (the try/except block exiting
without raising) and **before** returning to the caller. This matches the pattern established
by `submit_case` (lines 412–418).

### Dev/Prod parity (SECOPS-007)

`emit_kyc_event` (`app/services/kyc_webhooks.py:191`) is parity-correct by design:

- In **dev mode** with no registered webhook endpoints, `dispatch_webhook_event` succeeds as a
  no-op delivery (no external HTTP call is made).
- In **production** the same code path dispatches signed, retried webhook deliveries via
  `app/services/webhook_service`.
- In-app alerts (`write_alert`) write to DynamoDB regardless of dev/prod — the DDB local instance
  in dev handles it transparently.

No feature flag is needed. The `_emit_kyc_event_safe` wrapper's broad `except Exception` clause
ensures the notification failure (e.g., DDB table not yet present in a fresh dev environment)
never propagates to the HTTP response.

### Backward compatibility

The change adds a side effect to `apply_admin_decision`. Callers that previously succeeded
silently will now fire events. No API contract changes. No model changes. No new tables.

## 5. Testing, Verification & Rollout

### Regression test (fails-before / passes-after)

Add to `tests/test_kyc_cases_store.py`:

```python
import pytest
from unittest.mock import patch, call

class TestApplyAdminDecisionEmitsEvents:
    """GAP-0272: apply_admin_decision must emit kyc.case.approved/rejected events."""

    def _make_store(self):
        from app.services.kyc_cases import KycCaseStore
        store = KycCaseStore(_table=_FakeTable())
        # Seed a case in under_review status
        case = store.create_case(user_sub="usr_alice")
        # Advance status manually so apply_admin_decision precondition passes
        _table = store._table
        item = _table.items[("KYC#" + case["kyc_case_id"], "META")]
        item["status"] = "under_review"
        return store, case["kyc_case_id"], case["user_sub"]

    @pytest.mark.parametrize("decision,expected_event", [
        ("approve", "kyc.case.approved"),
        ("reject", "kyc.case.rejected"),
    ])
    def test_event_emitted_on_decision(self, decision, expected_event):
        store, case_id, user_sub = self._make_store()
        case = store.get_case(case_id)
        version = int(case["version"])

        emitted = []
        def _fake_emit(*, event, user_sub, **kw):
            emitted.append({"event": event, "user_sub": user_sub, **kw})

        import app.services.kyc_cases as svc
        with patch.object(svc, "_emit_kyc_event_safe", side_effect=_fake_emit):
            store.apply_admin_decision(
                case_id=case_id,
                expected_version=version,
                admin_sub="admin_charlie",
                decision=decision,
                reason_codes=["identity_confirmed"],
                note="looks good",
                decision_hash="hash_abc",
            )

        assert len(emitted) == 1, f"Expected 1 event, got {len(emitted)}"
        ev = emitted[0]
        assert ev["event"] == expected_event, (
            f"Expected '{expected_event}', got '{ev['event']}' "
            f"(GAP-0272: event was never dispatched before fix)"
        )
        assert ev["user_sub"] == user_sub
        assert ev["case_id"] == case_id

    def test_no_event_emitted_on_idempotent_re_decision(self):
        """Idempotent re-submit of same decision hash returns early — no duplicate event."""
        store, case_id, user_sub = self._make_store()
        case = store.get_case(case_id)
        version = int(case["version"])

        emitted = []
        import app.services.kyc_cases as svc
        with patch.object(svc, "_emit_kyc_event_safe", side_effect=lambda **kw: emitted.append(kw)):
            store.apply_admin_decision(
                case_id=case_id, expected_version=version,
                admin_sub="admin_charlie", decision="approve",
                reason_codes=["r"], note="ok ok ok", decision_hash="h1",
            )
            # Second call with same hash returns early (idempotent path)
            store.apply_admin_decision(
                case_id=case_id, expected_version=version + 1,
                admin_sub="admin_charlie", decision="approve",
                reason_codes=["r"], note="ok ok ok", decision_hash="h1",
            )

        assert len(emitted) == 1, "Idempotent re-decision must not emit a second event"
```

**Before the fix**: `assert len(emitted) == 1` fails with `len(emitted) == 0`.
**After the fix**: all assertions pass.
