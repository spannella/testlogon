# GAP-0193: No W-9/TIN collection endpoints or frontend form — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code in
> `app/routers/tax_form_1099.py`, `app/services/tax_form_1099.py`,
> `app/models.py`, `app/core/crypto.py`, and the FIN-008 writeup at
> `docs/tickets/writeups/FIN-008.md`.

## 1. Summary & Classification

**Bug / Gap**: Creators cannot submit tax information (W-9 equivalent: legal name, TIN,
tax classification, address, certified signature). No service function, no API endpoints,
no frontend page, and no Pydantic models exist for W-9 collection. The existing 1099-NEC
generation service uses a hardcoded placeholder `_PAYER_TIN_LAST4 = "0000"` instead of a
real recipient TIN, producing non-compliant forms.

**Claim verdict**: Confirmed. The gap ticket's stated location
(`app/routers/tax_form_1099.py`) is accurate: that router handles 1099 generation but
contains no W-9 submission endpoints. A full search of the `app/` directory finds zero
occurrences of `W9`, `w9`, `TaxInfoOut`, `W9Submission`, `submit_tax_info`, or
`get_tax_info`. `app/services/tax_form_1099.py:55` confirms
`_PAYER_TIN_LAST4 = "0000"` is a hardcoded stub.

**Severity**: HIGH (compliance) — FIN-008 source ticket.
**Status**: Open.
**Owning area**: Tax / Creator Compliance.
**Impact**: Without TIN collection, all 1099-NEC PDFs generated by the platform use
placeholder TIN `"0000"`. Forms submitted to the IRS with incorrect TINs incur a
$290 penalty per form under IRC §6721 (2024 rates). IRS-flagged mismatches trigger
B-Notices to payers and payees. Creators also cannot certify backup withholding
exemption, potentially triggering mandatory 24 % withholding on all payments.

**Related tickets**: GAP-0194 (admin TIN reveal), SECOPS-007 (dev/prod parity),
cross-ref SEC-004 (TIN decryption audit trail).

## 2. Current-State Investigation (root cause)

### 1099 side (what exists)

`app/routers/tax_form_1099.py` (218 lines) implements 1099-NEC generation:
`GET /ui/tax-forms/1099s`, `GET /ui/tax-forms/1099s/{year}`, `POST /ui/tax-forms/1099s/{year}/generate`,
`GET /ui/tax-forms/1099s/{year}/download`, plus admin batch/correct/list endpoints.
All these work correctly but produce forms with a stub TIN.

`app/services/tax_form_1099.py:55`:


`app/services/tax_form_1099.py:173`:
```python

```

`app/services/tax_form_1099.py:233`:
```python

```

These three lines are all that the 1099 PDF renderer knows about the payee's TIN.
There is no call to any W-9 service, no read from a `TIN#<user_sub>` DDB row, and no
call to `kms_decrypt`.

### W-9 side (what is missing)

A search of the entire `app/` tree returns no occurrences of:
- `W9`, `w_9`, `tin_submit`, `submit_tax_info`, `get_tax_info`
- `TaxInfoOut`, `TaxInfoAdminOut`, `W9SubmissionIn`
- Any DDB key pattern that would store a TIN (e.g., `TIN#`, `W9#`, `TAX_INFO#`)

`app/core/crypto.py:16–25` provides `kms_encrypt`/`kms_decrypt` via the mock KMS
server (`KMS_ENDPOINT_URL`, defaulting to `http://localhost:7999` in dev). These
functions are used by the webhook service, provider credentials, and LLM API key
storage — but **not** by the tax service.

### Frontend

`docs/tickets/writeups/FIN-008.md` confirms `frontend/src/pages/billing/TaxForm1099Page.tsx`
exists (167 lines) for 1099 list/generate/download UI, and
`frontend/src/pages/billing/TaxDocumentsPage.tsx` (242 lines) exists for the overview.
Neither contains a W-9 form. No `TaxInfoPage.tsx` exists.

### Root cause

FIN-008 was partially implemented; the developer built the 1099 generation workflow
and stopped before implementing the prerequisite W-9/TIN collection workflow. The
two are interdependent: valid 1099 PDFs require a stored, KMS-encrypted TIN.

## 3. Impact / Exploit / Blast Radius

**Compliance**:
- Every generated 1099-NEC contains `***-**-0000` as the recipient TIN. If these forms
  are e-filed, the IRS's TIN Matching program will flag every one as a mismatch.
  Penalty: $290 per incorrect information return (IRC §6721) for intentional disregard.
- Backup withholding requirement: if TIN is missing/incorrect, the platform must
  withhold 24 % of all payments to the creator and remit to IRS — a major financial
  liability.
- GDPR / data minimisation: once TINs are collected they become sensitive personal data
  (Regulation (EU) 2016/679 Art. 9 in some interpretations for EU nationals). Storage
  must be encrypted at rest; `kms_encrypt` satisfies this.

**Financial impact**: If the platform pays 1,000 creators and all 1099s have bad TINs,
potential penalties reach $290,000 per filing year.

**Security**: No direct exploit, but if a TIN storage endpoint were built insecurely
(e.g., plaintext in DDB), it would create a PII breach vector. The fix must use
`kms_encrypt` from the first commit.

## 4. Fix Design (code-level)

### 4.1 New service file: `app/services/tax_w9.py`

```python
"""W-9 / TIN collection and retrieval service (FIN-008 GAP-0193)."""
from __future__ import annotations

import logging
from typing import Any, Dict, Optional

from app.core.crypto import kms_encrypt, kms_decrypt
from app.core.tables import T
from app.core.time import now_ts

logger = logging.getLogger(__name__)

_W9_SK_PREFIX = "W9#"


def _w9_key(user_sub: str) -> Dict[str, str]:
    return {"pk": f"USER#{user_sub}", "sk": _W9_SK_PREFIX}


def submit_tax_info(
    *,
    user_sub: str,
    legal_name: str,
    tin: str,                   # raw SSN/EIN — never stored plaintext
    tax_classification: str,    # "individual", "sole_prop", "llc_s", "llc_c", "corp", "other"
    address_line1: str,
    address_city: str,
    address_state: str,
    address_zip: str,
    certified: bool,            # must be True; caller validates
    ip_address: str,
) -> Dict[str, Any]:
    """Encrypt and persist W-9 tax information for a creator.

    TIN is encrypted via KMS before storage.  Only the last 4 digits are stored
    in plaintext for masked display.  Any pre-existing W-9 row is replaced
    (creators can re-submit to update their TIN).
    """
    if not certified:
        raise ValueError("certification_required:User must certify accuracy")
    if len(tin.replace("-", "").replace(" ", "")) not in (9,):
        raise ValueError("invalid_tin:TIN must be 9 digits (SSN: XXX-XX-XXXX or EIN: XX-XXXXXXX)")

    tin_clean = tin.replace("-", "").replace(" ", "")
    tin_encrypted = kms_encrypt(tin_clean)   # kms_encrypt → base64 ciphertext
    tin_last4 = tin_clean[-4:]

    ts = now_ts()
    item = {
        "pk": f"USER#{user_sub}",
        "sk": _W9_SK_PREFIX,
        "legal_name": legal_name,
        "tin_encrypted": tin_encrypted,
        "tin_last4": tin_last4,
        "tax_classification": tax_classification,
        "address_line1": address_line1,
        "address_city": address_city,
        "address_state": address_state,
        "address_zip": address_zip,
        "certified": True,
        "certified_at": ts,
        "certified_ip": ip_address,
        "updated_at": ts,
    }
    T.billing.put_item(Item=item)
    _write_tax_audit(
        action="w9_submitted",
        actor=user_sub,
        target=user_sub,
        ip=ip_address,
    )
    return _to_tax_info_out(item)


def get_tax_info(user_sub: str) -> Optional[Dict[str, Any]]:
    """Return masked tax info for a creator (tin_last4 only, no full TIN)."""
    resp = T.billing.get_item(Key=_w9_key(user_sub))
    item = resp.get("Item")
    if not item:
        return None
    return _to_tax_info_out(item)


def _to_tax_info_out(item: Dict[str, Any]) -> Dict[str, Any]:
    return {
        "legal_name": item.get("legal_name", ""),
        "tin_last4": item.get("tin_last4", ""),
        "tax_classification": item.get("tax_classification", ""),
        "address_line1": item.get("address_line1", ""),
        "address_city": item.get("address_city", ""),
        "address_state": item.get("address_state", ""),
        "address_zip": item.get("address_zip", ""),
        "certified": bool(item.get("certified", False)),
        "certified_at": int(item.get("certified_at", 0)) or None,
        "updated_at": int(item.get("updated_at", 0)) or None,
    }


def get_tax_info_admin(
    *,
    user_sub: str,
    actor_sub: str,
    ip_address: str,
) -> Dict[str, Any]:
    """Return full (decrypted) TIN for admin compliance review.

    Logs a TAX_AUDIT entry for every call (required by SEC-004 / GAP-0194).
    """
    resp = T.billing.get_item(Key=_w9_key(user_sub))
    item = resp.get("Item")
    if not item:
        raise LookupError("no_tax_info:No W-9 submitted for this user")
    tin_ct = item.get("tin_encrypted", "")
    tin_full = kms_decrypt(tin_ct).decode("utf-8") if tin_ct else ""
    _write_tax_audit(
        action="tin_viewed",
        actor=actor_sub,
        target=user_sub,
        ip=ip_address,
    )
    out = _to_tax_info_out(item)
    out["tin_full"] = tin_full   # only in admin response
    return out


def _write_tax_audit(
    *,
    action: str,
    actor: str,
    target: str,
    ip: str,
) -> None:
    """Append an audit entry to the billing table for TIN-related operations."""
    ts = now_ts()
    from app.services.billing_shared import ulidish
    entry_id = ulidish()
    T.billing.put_item(Item={
        "pk": f"TAX_AUDIT#{target}",
        "sk": f"AUDIT#{ts}#{entry_id}",
        "action": action,
        "actor": actor,
        "target": target,
        "ip": ip,
        "ts": ts,
    })
```

### 4.2 Router additions (`app/routers/tax_form_1099.py`)

Add new endpoints to the existing `tax_form_1099_router`:

```python
from app.services import tax_w9 as w9_svc
from app.models import TaxInfoOut, TaxInfoAdminOut, W9SubmissionIn

# --- Creator endpoints ---

@tax_form_1099_router.post("/w9", response_model=TaxInfoOut, status_code=201)
def submit_w9(
    body: W9SubmissionIn,
    request: Request,
    session: Dict[str, str] = Depends(require_ui_session),
) -> TaxInfoOut:
    """Submit W-9 tax information (TIN encrypted via KMS)."""
    _ensure_enabled()
    ip = request.client.host if request.client else "unknown"
    try:
        result = w9_svc.submit_tax_info(
            user_sub=session["user_sub"],
            legal_name=body.legal_name,
            tin=body.tin,
            tax_classification=body.tax_classification,
            address_line1=body.address_line1,
            address_city=body.address_city,
            address_state=body.address_state,
            address_zip=body.address_zip,
            certified=body.certified,
            ip_address=ip,
        )
    except ValueError as exc:
        code, _, message = str(exc).partition(":")
        raise HTTPException(status_code=422, detail={"code": code, "message": message or code})
    return TaxInfoOut(**result)


@tax_form_1099_router.get("/info", response_model=TaxInfoOut)
def get_tax_info(
    session: Dict[str, str] = Depends(require_ui_session),
) -> TaxInfoOut:
    """Get masked W-9 info for the authenticated creator."""
    _ensure_enabled()
    result = w9_svc.get_tax_info(session["user_sub"])
    if result is None:
        raise HTTPException(status_code=404, detail={"code": "not_found", "message": "No W-9 submitted"})
    return TaxInfoOut(**result)


# --- Admin endpoint (see also GAP-0194) ---

@tax_form_1099_router.get("/admin/info/{target_user_sub}", response_model=TaxInfoAdminOut)
def admin_get_tax_info(
    target_user_sub: str,
    request: Request,
    admin: Any = Depends(require_admin_or_root),
) -> TaxInfoAdminOut:
    """Admin: retrieve full (decrypted) TIN with IP-logged audit trail."""
    _ensure_enabled()
    ip = request.client.host if request.client else "unknown"
    try:
        result = w9_svc.get_tax_info_admin(
            user_sub=target_user_sub,
            actor_sub=admin.sub,
            ip_address=ip,
        )
    except LookupError as exc:
        code, _, message = str(exc).partition(":")
        raise HTTPException(status_code=404, detail={"code": code, "message": message or code})
    return TaxInfoAdminOut(**result)
```

### 4.5 Dev/prod parity (SECOPS-007)

KMS in dev uses `scripts/mock_kms_server.py` (port 7999). `app/core/aws_clients.py`
reads `S.kms_endpoint_url` (set via `KMS_ENDPOINT_URL` in `.env.local`) and points the
boto3 KMS client there. The same `kms_encrypt`/`kms_decrypt` calls work identically
in dev and prod; no branching is required. TIN ciphertext stored in dev DynamoDB Local
is decryptable only via the mock KMS; in prod it requires the real KMS key, enforcing
separation of environments by construction.

### 4.6 DDB table considerations

The W-9 row is stored in the existing `billing` table using
`pk="USER#<sub>", sk="W9#"`. This avoids creating a new table; the `billing` table
already stores mixed record types per user (`LEDGER#`, `PAY#`, `BILLING` rows).
If the project prefers a dedicated `tax_w9` table, add a `TableDef` to
`scripts/local-ddb-init.py` with `pk` as hash key only.
