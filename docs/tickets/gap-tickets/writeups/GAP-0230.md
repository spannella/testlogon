# GAP-0230: Auto-restart Policy Not Implemented — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code at `app/services/instance_monitoring.py`, `app/routers/instance_monitoring.py`, and related launcher files.

## 1. Summary & Classification

**Plain-English statement**: The INFRA-008 (Instance Monitoring & Health) design specifies a `_check_restart_policy` function that evaluates whether a crashed or failed EC2 instance or K8s pod should be automatically restarted based on a per-instance policy (`auto_restart_enabled`, `max_restarts`, `restart_count`). It also specifies a `PATCH /ui/compute/monitoring/instances/{id}/restart-policy` endpoint to configure this policy, and `record_timeline_event` to audit restart actions. None of these exist in the codebase. The monitoring service (`app/services/instance_monitoring.py`) and its router (`app/routers/instance_monitoring.py`) were implemented for metric ingestion, health derivation, and time-series queries — but the auto-restart policy subsystem was entirely omitted.

- **Severity**: HIGH
- **Source ticket**: INFRA-008
- **Status**: Open
- **Owning area**: Remote Compute / Instance Monitoring
- **Verdict**: Claim **confirmed**. A comprehensive search for `restart_policy`, `auto_restart`, `_check_restart`, `restart_count`, `max_restarts`, and `record_timeline_event` across all Python files under `app/` returns zero results. The monitoring router at `app/routers/instance_monitoring.py` has five endpoints (ingest, seed, latest, timeseries, health) and no restart-policy endpoint. The `app/services/instance_monitoring.py` file is 415 lines and contains no restart logic.
- **One-line impact**: Instances and pods that crash are never automatically restarted regardless of user preference, causing silent downtime for compute workloads without user notification.
- **Related tickets**: INFRA-008 (full design), INFRA-004 (K8s launcher — `terminate_pod`/relaunch), EC2 launcher (terminate/start instance cycle), GAP-0228 (billing timer — interacts with restart events for re-billing).

## 2. Current-State Investigation (root cause)

### What the INFRA-008 design specifies

The ticket design calls for:
1. `auto_restart_enabled: bool` — per-instance flag controlling whether the policy applies.
2. `max_restarts: int` — ceiling on consecutive automatic restarts.
3. `restart_count: int` — counter of how many times the instance has been automatically restarted.
4. `_check_restart_policy(user_sub, instance_id, health)` — evaluates the policy when a `critical` health status is detected and triggers a restart if conditions are met.
5. `record_timeline_event(instance_id, event_type, details)` — writes an audit timeline entry to DynamoDB.
6. `PATCH /ui/compute/monitoring/instances/{id}/restart-policy` — allows users to enable/disable auto-restart and set `max_restarts`.

### What exists in the codebase

`app/services/instance_monitoring.py` (415 lines) implements:
- `ingest_datapoint` — stores a metric point, derives health, optionally fires a health alert via `write_alert`.
- `derive_health` — evaluates CPU/mem/disk thresholds against configured levels and returns `health_status: "healthy" | "warning" | "critical" | "unknown"`.
- `get_health`, `get_latest`, `get_timeseries` — query functions.
- `seed_metrics` — deterministic test seeder.

When `ingest_datapoint` derives `HEALTH_CRITICAL`, it fires an alert (via `_maybe_alert`) but has no mechanism to check or invoke a restart policy. The alert is a fire-and-forget `write_alert` call.

`app/routers/instance_monitoring.py` (175 lines) has five endpoints, none of which is a `PATCH /restart-policy`.

The `ec2_instances` and `k8s_pods` DynamoDB tables have no `auto_restart_enabled`, `max_restarts`, or `restart_count` fields. The `instance_metrics` table has no `timeline_events` sort-key pattern.

### Root cause

The monitoring feature was shipped in two tiers: the observability tier (metric ingestion + health derivation + alerting) was implemented, and the remediation-action tier (`_check_restart_policy` + `record_timeline_event` + policy PATCH endpoint) was never started. The existing `ingest_datapoint` function has the correct structural hook point (after `_maybe_alert`) but the restart call was never added.

## 3. Impact / Exploit / Blast Radius

**Availability**:
- An EC2 instance or K8s pod that reports `status: "crashed"` or `status: "unreachable"` in an ingested metric datapoint will continue to show `health_status: "critical"` indefinitely. Without auto-restart, the user's workload is down until they manually intervene.
- Users who configured "auto-restart if crashed" in the UI (if such a UI exists) have a silently broken feature.

**Operational confusion**:
- Health alerts fire correctly (SEC-022 surface — `_maybe_alert` calls `write_alert`), but no remediation follows. Users receive a critical alert email/notification but the system takes no corrective action, implying it should but doesn't.

**Financial**:
- When GAP-0228 is fixed (billing timer), crashed resources that are not auto-restarted will stop incurring charges — which is correct behavior. However, without `record_timeline_event`, there is no audit trail showing why a resource stopped.
- Without `restart_count` tracking, the `max_restarts` safety limit (to prevent restart loops) is unenforceable.

**Blast radius**: Any user who relies on INFRA-008 auto-restart for production workloads has zero protection against instance crashes. The gap is functional rather than a data corruption or security issue.

## 4. Fix Design (code-level)

### Overview of the three-part implementation

1. **Data model extension**: Add `auto_restart_enabled`, `max_restarts`, `restart_count` to the `ec2_instances` and `k8s_pods` DDB records.
2. **Service functions**: `_check_restart_policy`, `record_timeline_event`, `update_restart_policy` in `app/services/instance_monitoring.py`.
3. **Router endpoint**: `PATCH /ui/compute/monitoring/instances/{id}/restart-policy` in `app/routers/instance_monitoring.py`.

### Part 1: DynamoDB schema extension

No new tables are needed. The `instance_metrics` table gains a new sort-key pattern for timeline events: `TIMELINE#{ts:010d}#{event_id}`. The `ec2_instances` and `k8s_pods` tables gain three new optional attributes (DynamoDB schema-on-write, no migration needed):

```
auto_restart_enabled: bool  (default: false)
max_restarts: int           (default: 3)
restart_count: int          (default: 0)
last_restart_at: int        (unix seconds, 0 if never)
```

### Part 2: `app/services/instance_monitoring.py`

#### `record_timeline_event`

```python
def record_timeline_event(
    instance_id: str,
    *,
    event_type: str,
    details: Optional[Dict[str, Any]] = None,
    ts: Optional[int] = None,
) -> Dict[str, Any]:
    """Write an audit timeline entry for an instance lifecycle event."""
    event_ts = ts if ts is not None else now_ts()
    event_id = f"ev_{uuid.uuid4().hex[:8]}"
    item = {
        "instance_id": instance_id,
        "sk": f"TIMELINE#{event_ts:010d}#{event_id}",
        "event_id": event_id,
        "event_type": event_type,
        "ts": event_ts,
        "details": details or {},
    }
    T.instance_metrics.put_item(Item=item)
    logger.info(
        "instance_timeline_event instance_id=%s event_type=%s event_id=%s",
        instance_id, event_type, event_id,
    )
    return item
```

#### `_check_restart_policy`

```python
def _check_restart_policy(
    user_sub: str,
    instance: Dict[str, Any],
    health: Dict[str, Any],
) -> bool:
    """Evaluate the auto-restart policy for an instance in a critical health state.

    Returns True if a restart was initiated, False otherwise.
    """
    if health.get("health_status") != HEALTH_CRITICAL:
        return False
    if not instance.get("auto_restart_enabled", False):
        return False

    max_restarts = int(instance.get("max_restarts", 3))
    restart_count = int(instance.get("restart_count", 0))

    if restart_count >= max_restarts:
        logger.warning(
            "instance_restart_limit_reached instance_id=%s restart_count=%d max=%d",
            instance.get("instance_id", ""), restart_count, max_restarts,
        )
        record_timeline_event(
            instance.get("instance_id", ""),
            event_type="restart_limit_reached",
            details={"restart_count": restart_count, "max_restarts": max_restarts},
        )
        return False

    instance_id = instance.get("instance_id", "")
    resource_type = instance.get("resource_type", "ec2")  # "ec2" or "k8s"

    record_timeline_event(
        instance_id,
        event_type="auto_restart_initiated",
        details={
            "restart_count": restart_count + 1,
            "max_restarts": max_restarts,
            "health_reasons": health.get("reasons", []),
        },
    )

    try:
        _perform_restart(user_sub, instance, resource_type)
        _increment_restart_count(user_sub, instance, resource_type, instance_id)
        record_timeline_event(
            instance_id,
            event_type="auto_restart_completed",
            details={"restart_count": restart_count + 1},
        )
        logger.info(
            "instance_auto_restarted user_sub=%s instance_id=%s restart_count=%d",
            user_sub, instance_id, restart_count + 1,
        )
        return True
    except Exception:
        logger.exception(
            "instance_auto_restart_failed user_sub=%s instance_id=%s",
            user_sub, instance_id,
        )
        record_timeline_event(
            instance_id,
            event_type="auto_restart_failed",
            details={"error": "restart exception (see logs)"},
        )
        return False


def _perform_restart(user_sub: str, instance: Dict[str, Any], resource_type: str) -> None:
    """Trigger the appropriate restart action for the resource type."""
    instance_id = instance.get("instance_id") or instance.get("pod_id", "")
    if resource_type == "k8s":
        from app.services.k8s_launcher import terminate_pod, launch_pod
        terminate_pod(user_sub, instance_id)
        launch_pod(
            user_sub,
            label=instance.get("label", "Restarted Pod"),
            image=instance.get("image", "ubuntu-ssh"),
            preset=instance.get("preset", "small"),
            ttl_seconds=int(instance.get("ttl_seconds", 14400)),
        )
    else:
        from app.services.ec2_launcher import stop_instance, start_instance
        stop_instance(user_sub, instance_id)
        start_instance(user_sub, instance_id)


def _increment_restart_count(
    user_sub: str, instance: Dict[str, Any], resource_type: str, instance_id: str
) -> None:
    table = T.k8s_pods if resource_type == "k8s" else T.ec2_instances
    sk_prefix = "POD#" if resource_type == "k8s" else "INST#"
    table.update_item(
        Key={"user_sub": user_sub, "sk": f"{sk_prefix}{instance_id}"},
        UpdateExpression=(
            "SET restart_count = if_not_exists(restart_count, :z) + :one, "
            "last_restart_at = :ts"
        ),
        ExpressionAttributeValues={":z": 0, ":one": 1, ":ts": now_ts()},
    )
```

#### `update_restart_policy`

```python
def update_restart_policy(
    user_sub: str,
    instance_id: str,
    *,
    auto_restart_enabled: Optional[bool] = None,
    max_restarts: Optional[int] = None,
) -> Dict[str, Any]:
    """Set the auto-restart policy for an owned EC2 instance."""
    instance = require_owned_instance(user_sub, instance_id)

    sets = []
    values: Dict[str, Any] = {}
    if auto_restart_enabled is not None:
        sets.append("auto_restart_enabled = :are")
        values[":are"] = bool(auto_restart_enabled)
    if max_restarts is not None:
        if max_restarts < 0 or max_restarts > 10:
            raise ValueError("max_restarts must be 0-10")
        sets.append("max_restarts = :mr")
        values[":mr"] = max_restarts

    if not sets:
        return instance

    T.ec2_instances.update_item(
        Key={"user_sub": user_sub, "sk": f"INST#{instance_id}"},
        UpdateExpression="SET " + ", ".join(sets),
        ExpressionAttributeValues=values,
    )

    logger.info(
        "instance_restart_policy_updated user_sub=%s instance_id=%s",
        user_sub, instance_id,
    )
    return get_instance_with_policy(user_sub, instance_id)
```

### Part 3: Router endpoint `app/routers/instance_monitoring.py`

```python
from app.models import RestartPolicyIn, RestartPolicyOut

@instance_monitoring_router.patch(
    "/instances/{instance_id}/restart-policy",
    response_model=RestartPolicyOut,
)
async def update_restart_policy_endpoint(
    instance_id: str,
    body: RestartPolicyIn,
    session: Dict = Depends(require_ui_session),
):
    _enabled_guard()
    user_sub = session["user_sub"]
    try:
        result = svc.update_restart_policy(
            user_sub,
            instance_id,
            auto_restart_enabled=body.auto_restart_enabled,
            max_restarts=body.max_restarts,
        )
    except svc.InstanceNotOwned:
        raise HTTPException(status_code=404, detail="Instance not found")
    except ValueError as exc:
        raise HTTPException(status_code=400, detail=str(exc))
    return RestartPolicyOut(**result)
```

class RestartPolicyOut(BaseModel):

### Dev/Prod parity (SECOPS-007)

- **Dev mode**: `S.k8s_mock_enabled = True` means `launch_pod` uses `_MockK8sStore`. The restart sequence (terminate + launch) works in dev with mock pods. EC2 `stop_instance` / `start_instance` use the EC2 mock similarly.
- **Prod mode**: Real K8s and EC2 API calls. Same code path; no environment-specific branches needed.
- **Feature flag**: `INSTANCE_MONITORING_AUTO_RESTART_ENABLED=false` by default ensures the feature is off in dev/test and must be explicitly enabled in prod. This protects against accidental restart loops in test environments.
- **KMS**: Not involved in restart policy (no credentials stored).

### Manual QA steps

1. `just restart`.
2. Set `INSTANCE_MONITORING_AUTO_RESTART_ENABLED=true` in `.env.local`.
3. Launch a K8s pod and note its `pod_id`.
4. Set the restart policy: `PATCH /ui/compute/monitoring/instances/{pod_id}/restart-policy` with `{"auto_restart_enabled": true, "max_restarts": 2}`.
5. Ingest a critical metric: `POST /ui/compute/monitoring/instances/{pod_id}/metrics` with `{"cpu_pct": 95, "mem_pct": 30, "disk_pct": 20, "status": "crashed"}`.
6. Verify: the pod transitions to `terminated` and a new pod is launched (check Containers page).
7. Check the timeline: `GET /ui/compute/monitoring/instances/{pod_id}/timeline` (add the endpoint) — should show `auto_restart_initiated` and `auto_restart_completed` events.
8. Repeat step 5 twice more — after the 2nd restart, `restart_limit_reached` should appear and no further restart is attempted.

### Rollout

- **Effort**: L (3-5 days: service layer, models, router, EC2/K8s launcher integration, tests)
- **Risk**: Medium-High. Auto-restarting instances has operational consequences (cost, disruption, restart loops). The `max_restarts` cap and the default-`false` flag mitigate the risk but must be validated in staging.
- **Sequencing**: Deploy after GAP-0228 (billing timer) so that restarted resources are properly billed from the first minute of their new lifecycle. Deploy after GAP-0226/GAP-0227 so that K8s pods created by restart also register/deregister in host inventory.
- **Rollback**: Set `INSTANCE_MONITORING_AUTO_RESTART_ENABLED=false`. No data is corrupted; `restart_count` fields remain and serve as an audit record.
