# GAP-0238: quota not enforced in `k8s_launcher.py` — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No prior
> investigation doc exists for this ticket.

## 1. Summary & Classification

**Bug**: The Kubernetes pod launcher is supposed to enforce per-user admin-assigned quotas
(max pods, allowed presets, monthly spend cap) through the same `enforce_k8s_quota` mechanism
that EC2 uses. A second-pass code review of INFRA-012 flagged that the quota call was missing
from `k8s_launcher.py`. However, reading the actual source code reveals that the call **is
already present** in the file. The claim in the gap ticket is therefore inaccurate.

**Claim verdict**: Claim INACCURATE — the quota enforcement is already implemented.

`app/services/k8s_launcher.py:144-154`:
```python
# 3b. Enforce per-user admin quota (INFRA-012)
if S.admin_compute_dashboard_enabled:
    from app.services.admin_compute import (
        enforce_k8s_quota,
        QuotaExceeded,
        SpendingLimitReached,
    )
    try:
        enforce_k8s_quota(user_sub, preset)
    except (QuotaExceeded, SpendingLimitReached) as e:
        raise PodLimitReached(str(e))
```

The pattern is structurally identical to the EC2 enforcement at
`app/services/ec2_launcher.py:162-172`. Both are gated on `S.admin_compute_dashboard_enabled`
and call the shared `enforce_k8s_quota` / `enforce_ec2_quota` helpers in
`app/services/admin_compute.py:526,551`.

**Severity (revised)**: Informational. The gap does not exist in the current codebase.

**Source ticket**: INFRA-012. **Owning area**: `app/services/k8s_launcher.py`.

**Related tickets**: GAP-0237 (ByGlobalStatus GSI — genuine gap in same INFRA-012 scope).

## 2. Current-State Investigation (root cause)

### 2.1 What the gap ticket claims

> quota not enforced in `k8s_launcher.py`

The ticket was generated as part of the INFRA-012 second-pass as-built review. The review
produced two gap tickets for INFRA-012: this one (GAP-0238, quota enforcement) and GAP-0237
(ByGlobalStatus GSI absent). GAP-0237 is a genuine gap. This ticket is not.

The likely origin of the false positive: the gap audit compared the INFRA-012 ticket spec
description — which listed quota enforcement as a required feature — against a snapshot of
the codebase taken before the step 3b block was merged, or against an intermediate branch
that lacked it. The `# 3b. Enforce per-user admin quota (INFRA-012)` comment in the current
source is a clear in-line cross-reference that the feature was deliberately added.

### 2.2 What the code actually does

`app/services/k8s_launcher.py:112` — `launch_pod` function:

Step 3 (lines 133-142) enforces the hard per-user pod count limit using the launcher's own
`S.k8s_max_pods_per_user` setting:

```python
# 3. Check pod limit (running or pending only)
active = [
    p for p in list_pods(user_sub)
    if p.get("status") in ("running", "pending")
]
max_pods = S.k8s_max_pods_per_user
if len(active) >= max_pods:
    raise PodLimitReached(
        f"Maximum {max_pods} running pods. Terminate one first."
    )
```

Step 3b (lines 144-154) adds the admin-assigned quota layer on top:

```python
# 3b. Enforce per-user admin quota (INFRA-012)
if S.admin_compute_dashboard_enabled:
    from app.services.admin_compute import (
        enforce_k8s_quota,
        QuotaExceeded,
        SpendingLimitReached,
    )
    try:
        enforce_k8s_quota(user_sub, preset)
    except (QuotaExceeded, SpendingLimitReached) as e:
        raise PodLimitReached(str(e))
```

`app/services/admin_compute.py:551` — `enforce_k8s_quota`:

```python
def enforce_k8s_quota(user_sub: str, preset: str) -> None:
    """Raise if launching a K8s pod would violate the user's quota."""
    quota = get_quota(user_sub)

    from app.services.k8s_launcher import list_pods
    active = [p for p in list_pods(user_sub) if p.get("status") in ("running", "pending")]
    if len(active) >= quota["max_k8s_pods"]:
        raise QuotaExceeded(f"Maximum {quota['max_k8s_pods']} pods allowed")

    if quota["allowed_k8s_presets"] and preset not in quota["allowed_k8s_presets"]:
        raise QuotaExceeded(f"Preset {preset} not allowed by your quota")

    _check_spend(user_sub, quota)
```

This is a complete, correct implementation of the enforcement:
- It enforces max pod count relative to the admin-assigned quota.
- It enforces allowed presets allowlist.
- It checks the monthly spending cap via `_check_spend` (line 566).

### 2.3 Possible origin of the false gap

The gap audit may have been generated from an intermediate version of the file before the
quota block was merged, or from a branch where the step 3b comment was absent. The current
`main` branch contains the fix.

### 2.4 Minor residual concern — `is_custom` guard asymmetry

The `enforce_k8s_quota` function always checks `len(active) >= quota["max_k8s_pods"]`
regardless of whether the quota is custom-set (`is_custom` flag). This means a user on the
default quota (`max_k8s_pods=5` by default) is also subject to the quota count check, which
double-counts with the hard limit already applied in step 3 (`S.k8s_max_pods_per_user`).

Compare with `enforce_ec2_quota` at `app/services/admin_compute.py:526`, which guards on
`quota.get("is_custom")` before applying the instance count check:

```python
# enforce_ec2_quota — only applies count cap when admin has set a custom quota:
if quota.get("is_custom"):
    if len(active) >= quota["max_ec2_instances"]:
        raise QuotaExceeded(f"Maximum {quota['max_ec2_instances']} instances allowed")
```

The K8s version at line 557 lacks this `is_custom` guard:
```python
def enforce_k8s_quota(user_sub: str, preset: str) -> None:
    quota = get_quota(user_sub)
    ...
    active = [p for p in list_pods(user_sub) if p.get("status") in ("running", "pending")]
    if len(active) >= quota["max_k8s_pods"]:   # unconditional — applies for default quotas too
        raise QuotaExceeded(f"Maximum {quota['max_k8s_pods']} pods allowed")
```

This is a minor inconsistency rather than a security or correctness bug. The practical
impact: if an operator sets the default quota `max_k8s_pods=3` but `k8s_max_pods_per_user=5`,
all users on the default quota are silently capped at 3 pods by the quota enforcement even
without an admin-set custom quota — contrary to the intent documented in the EC2 equivalent
(which explicitly separates platform defaults from admin-assigned ceilings).

The inconsistency does NOT cause under-enforcement (quota cap is more restrictive, not less),
but it may produce unexpected `QuotaExceeded` rejections for users who have not been
individually quota-limited by an admin.

### 2.5 Admin compute dashboard feature flag scope

Both enforcement blocks (EC2 and K8s) are gated by `S.admin_compute_dashboard_enabled`.
When this flag is `False` (the default in many deployments), neither quota call fires and
only the hard per-user launcher limits apply. This is intentional: the admin quota system
is an opt-in operator feature. The flag is documented in `app/core/settings.py` and in
`ADMIN_COMPUTE_DASHBOARD_ENABLED` in `.env.local.example`.

## 3. Impact / Exploit / Blast Radius

Since the primary enforcement is present and correct, there is no quota bypass vulnerability.
The only runtime risk is the minor inconsistency described in section 2.4:

- A user on the default quota with `max_k8s_pods=5` (same as `k8s_max_pods_per_user=5`) sees
  no difference.
- If an operator sets the default quota `max_k8s_pods=3` but leaves `k8s_max_pods_per_user=5`,
  all users are silently capped at 3 pods by the quota check even without a custom quota.

This is low-severity and consistent with a conservative default-deny posture.

## 4. Fix Design (code-level)

### 4.1 Primary recommendation — close as No-Action

The gap as stated (quota not enforced) does not exist. No product code changes are required
for the primary claim.

### 4.2 Optional consistency fix — mirror the `is_custom` guard from EC2

To make K8s quota enforcement consistent with EC2 (`enforce_ec2_quota` line 541), add the
`is_custom` guard to `enforce_k8s_quota` in `app/services/admin_compute.py:551`:

```python
def enforce_k8s_quota(user_sub: str, preset: str) -> None:
    quota = get_quota(user_sub)

    from app.services.k8s_launcher import list_pods
    active = [p for p in list_pods(user_sub) if p.get("status") in ("running", "pending")]

    # Only enforce the pod-count cap when an admin has explicitly set a custom quota.
    # Default-quota enforcement is handled by the hard limit in k8s_launcher.launch_pod.
    if quota.get("is_custom"):
        if len(active) >= quota["max_k8s_pods"]:
            raise QuotaExceeded(f"Maximum {quota['max_k8s_pods']} pods allowed")

    if quota["allowed_k8s_presets"] and preset not in quota["allowed_k8s_presets"]:
        raise QuotaExceeded(f"Preset {preset} not allowed by your quota")

    _check_spend(user_sub, quota)
```

This is a behaviour-preserving change for users with `is_custom=True` and removes the
double-counting for users on the default quota.

### 4.3 Dev/Prod parity (SECOPS-007)

No path difference exists between dev and production. The quota function calls DynamoDB for
the quota record, which is available in both DynamoDB Local (dev) and AWS DynamoDB (prod).
The `S.admin_compute_dashboard_enabled` flag gates the entire block uniformly in both
environments.
