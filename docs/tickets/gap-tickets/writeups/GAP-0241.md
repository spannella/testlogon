# GAP-0241: OAuth state parameter not HMAC-signed — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No prior
> investigation doc exists for this ticket.

## 1. Summary & Classification

**Bug**: The `initiate_google_drive_connect` endpoint (`app/routers/google_drive_integration.py:116`)
returns a stub `auth_url` of `"https://accounts.google.com/o/oauth2/v2/auth"` without
appending any query parameters — in particular without generating or attaching a `state`
parameter. The `complete_google_drive_connect` callback endpoint at line 134 accepts an
optional `state` field in its request body (`DriveCallbackReq.state: Optional[str] = None`,
line 47) but never reads, validates, or verifies it. In non-mock mode both endpoints fall
through to raise `HTTPException(501, "Real OAuth not implemented in this environment")` (line
156), meaning no real production path exists at all.

**Claim verdict**: Confirmed. The cited lines (122–131 for initiate; 155 for the 501) are
accurate. The ticket description of the line range is slightly off by four lines (the initiate
function body spans lines 117–131 and the 501 is on line 156 in the file as read), but the
substance is exact.

**Severity**: HIGH. CSRF via OAuth state forgery is a well-documented attack (OAuth 2.0 RFC
6749 §10.12). Without a signed, time-limited state token an attacker can forge the callback
and link a victim's account to the attacker's Google Drive credential.

**Source ticket**: INTEG-001. **Owning area**: `app/routers/google_drive_integration.py`,
`app/core/settings.py` (signing secret already present at line 919), `app/core/crypto.py`.

**Related tickets**: GAP-0242 (real token exchange absent — both gaps must be resolved
together before the production OAuth flow is viable); GAP-0239 (frontend Connect button
absent); GAP-0240 (picker dialog not wired into FilesPage). SECOPS-007 applies: the mock and
real paths must share the same validation logic.

## 2. Current-State Investigation (root cause)

### 2.1 The `initiate_google_drive_connect` endpoint

`app/routers/google_drive_integration.py:116-131`:

```python
@router.get("/connect")
async def initiate_google_drive_connect(ctx=Depends(require_ui_session)) -> Dict[str, Any]:
    """Generate OAuth authorization URL (or mock connect URL in dev mode)."""
    user_sub = ctx["user_sub"]

    if S.dev_mode and S.google_drive_mock_enabled:
        return {
            "auth_url": f"/files?drive-callback=1&code=mock_auth_code_{user_sub}&state=mock",
            "mock": True,
        }

    # Real OAuth flow would go here
    return {
        "auth_url": "https://accounts.google.com/o/oauth2/v2/auth",
        "mock": False,
    }
```

Two problems are visible here:

1. **Mock path**: the `state=mock` literal is returned, which is predictable and cannot be
   verified as belonging to any particular session.
2. **Real path**: the `auth_url` is the bare Google authorization base URL with no query
   parameters whatsoever. No `client_id`, no `redirect_uri`, no `scope`, and — critically —
   no `state`. A browser following this URL would reach Google's "Bad Request" page because
   `client_id` is required.

### 2.2 The `complete_google_drive_connect` callback endpoint

`app/routers/google_drive_integration.py:134-156`:

```python
@router.post("/callback")
async def complete_google_drive_connect(body: DriveCallbackReq, ctx=Depends(require_ui_session)):
    user_sub = ctx["user_sub"]

    if S.dev_mode and S.google_drive_mock_enabled:
        mock_token = f"mock-drive-token-{user_sub}"
        upsert_provider_credential(
            user_sub,
            "google_drive",
            mock_token,
            scopes_override=["https://www.googleapis.com/auth/drive.file"],
            metadata_override={"email": f"{user_sub}@drive.mock"},
        )
        return {"ok": True, "connected": True}

    # Real OAuth exchange would go here
    raise HTTPException(501, "Real OAuth not implemented in this environment")
```

The `body.state` field is accepted in the request model (`DriveCallbackReq.state:
Optional[str] = None`, line 47) but is silently ignored in both branches. In the mock path,
any unauthenticated caller who knows any `user_sub` could forge a callback and link
credentials to that user's account (the endpoint does check the session for `user_sub`, which
provides partial mitigation, but still permits session fixation-style attacks where a victim
is induced to hit a crafted callback URL).

### 2.4 Comparison with the working Google Calendar OAuth pattern

The codebase already has a working, security-correct OAuth state implementation in
`app/services/google_calendar_oauth.py`. The `create_connect_start_state` function (line 121)
generates a `secrets.token_urlsafe(32)` nonce, stores it in DynamoDB with a TTL, and returns
it. The `consume_connect_state` function (line 150) fetches the DDB row, checks
`user_sub` ownership, checks the TTL, and marks it consumed — a classic single-use,
time-limited state token.

The Jira OAuth service (`app/services/jira_oauth.py:95-115`) uses a similar pattern with an
in-memory `_state_store` dict and TTL pruning.

The Google Drive router has neither: it has the settings fields but no service layer backing
them.

## 3. Impact / Exploit / Blast Radius

### 3.1 CSRF via forged callback (production risk)

OAuth CSRF works as follows:

1. Attacker initiates a Google Drive Connect flow in *their* browser; Google redirects back
   with `?code=ATTACKER_CODE`.
2. Attacker does **not** follow the redirect. Instead, they craft a URL to the victim:
   `POST /ui/integrations/google-drive/callback` with `{ "code": "ATTACKER_CODE" }`.
3. The victim, already authenticated (their session cookie is sent), hits the callback. The
   server exchanges ATTACKER_CODE for tokens and stores them under the victim's `user_sub`.
4. The victim's Drive integration is now linked to the attacker's Google account. The attacker
   can browse or exfiltrate any files the victim subsequently imports.

Without a per-session signed state parameter that the callback verifier checks, step 3 cannot
be prevented.

### 3.2 Blast radius

- Any authenticated user's Google Drive credential store can be silently hijacked.
- If the victim later imports sensitive files, those files are accessible to the attacker via
  their own Google Drive.
- The attack requires the attacker to briefly initiate their own OAuth flow (to obtain a
  valid `code`), then deliver a CSRF payload to the victim — feasible via email, QR code, or
  a cross-site request in the same browser session.

### 3.3 Current severity qualifier

Because `complete_google_drive_connect` raises `HTTPException(501)` in production (non-dev,
non-mock), the CSRF attack is only exploitable in **dev/mock mode** today. However the gap
**must** be closed before the production path is wired (GAP-0242), or the production feature
will ship vulnerable.

## 4. Fix Design (code-level)

### 4.1 Add `_sign_oauth_state` and `_verify_oauth_state` helpers

Add to `app/routers/google_drive_integration.py` (before the endpoint definitions):

```python
import hashlib
import hmac
import secrets
import time
from base64 import urlsafe_b64encode, urlsafe_b64decode

def _sign_oauth_state(user_sub: str) -> str:
    """Generate a signed, time-limited OAuth state token.

    Format: base64url(<user_sub_b64>.<ts>.<nonce>.<hmac-sha256>)
    """
    secret = S.google_oauth_state_signing_secret
    if not secret:
        raise HTTPException(500, "OAuth state signing secret not configured")
    ts = str(int(time.time()))
    nonce = secrets.token_hex(16)
    payload = f"{user_sub}|{ts}|{nonce}"
    sig = hmac.new(
        secret.encode("utf-8"),
        payload.encode("utf-8"),
        hashlib.sha256,
    ).hexdigest()
    raw = f"{payload}|{sig}"
    return urlsafe_b64encode(raw.encode("utf-8")).decode("ascii")


def _verify_oauth_state(state: str, expected_user_sub: str) -> None:
    """Verify a signed state token; raise HTTP 400 on any failure."""
    secret = S.google_oauth_state_signing_secret
    if not secret:
        raise HTTPException(500, "OAuth state signing secret not configured")
    try:
        raw = urlsafe_b64decode(state.encode("ascii") + b"==").decode("utf-8")
        sub, ts, nonce, sig = raw.split("|", 3)
    except Exception:
        raise HTTPException(400, "Invalid OAuth state")

    payload = f"{sub}|{ts}|{nonce}"
    expected_sig = hmac.new(
        secret.encode("utf-8"),
        payload.encode("utf-8"),
        hashlib.sha256,
    ).hexdigest()
    if not hmac.compare_digest(sig, expected_sig):
        raise HTTPException(400, "Invalid OAuth state signature")
    if sub != expected_user_sub:
        raise HTTPException(400, "OAuth state user mismatch")
    age = int(time.time()) - int(ts)
    if age < 0 or age > S.google_oauth_state_ttl_seconds:
        raise HTTPException(400, "OAuth state expired")
```

### 4.2 Update `initiate_google_drive_connect` to embed signed state

```python
@router.get("/connect")
async def initiate_google_drive_connect(ctx=Depends(require_ui_session)) -> Dict[str, Any]:
    user_sub = ctx["user_sub"]
    state = _sign_oauth_state(user_sub)       # NEW

    if S.dev_mode and S.google_drive_mock_enabled:
        return {
            "auth_url": (
                f"/files?drive-callback=1"
                f"&code=mock_auth_code_{user_sub}"
                f"&state={state}"             # signed, not "mock"
            ),
            "mock": True,
        }

    # Real path: build full authorization URL
    from urllib.parse import urlencode
    params = {
        "client_id": S.google_oauth_client_id,
        "redirect_uri": S.google_oauth_redirect_uri,
        "response_type": "code",
        "scope": S.google_oauth_scopes,
        "access_type": "offline",
        "prompt": "consent",
        "state": state,
    }
    auth_url = f"https://accounts.google.com/o/oauth2/v2/auth?{urlencode(params)}"
    return {"auth_url": auth_url, "mock": False}
```

### 4.3 Update `complete_google_drive_connect` to verify state before accepting code

```python
@router.post("/callback")
async def complete_google_drive_connect(
    body: DriveCallbackReq, ctx=Depends(require_ui_session)
) -> Dict[str, Any]:
    user_sub = ctx["user_sub"]

    # Verify state before touching any credential store
    if not body.state:
        raise HTTPException(400, "Missing OAuth state")
    _verify_oauth_state(body.state, user_sub)  # NEW — raises 400 on failure

    if S.dev_mode and S.google_drive_mock_enabled:
        mock_token = f"mock-drive-token-{user_sub}"
        upsert_provider_credential(
            user_sub, "google_drive", mock_token,
            scopes_override=["https://www.googleapis.com/auth/drive.file"],
            metadata_override={"email": f"{user_sub}@drive.mock"},
        )
        return {"ok": True, "connected": True}

    # Real path: see GAP-0242
    raise HTTPException(501, "Real OAuth not implemented in this environment")
```

### 4.4 Dev/Prod parity (SECOPS-007)

Both the mock and real paths execute `_verify_oauth_state` with the same signing logic and the
same `S.google_oauth_state_signing_secret`. The only difference is what happens after
verification. In dev/mock mode a synthetic credential is stored; in prod the code is exchanged
for real tokens (GAP-0242). This satisfies SECOPS-007: the security check runs identically
regardless of environment, controlled by the same settings singleton.

The `GOOGLE_OAUTH_STATE_SIGNING_SECRET` env var must be set in `.env.local` (dev) and via AWS
Secrets Manager (prod). A missing secret causes a 500 response at connect time rather than
silently weakening security.

### 4.5 Alternatives considered

- **DynamoDB-backed state store** (same pattern as `google_calendar_oauth.py`): More robust —
  supports single-use consumption and survives backend restarts. Preferred for production
  hardening. Rejected for this ticket to keep the fix self-contained within the router file;
  DDB-backed state can be layered in the same PR as GAP-0242.
- **Stateless HMAC-only token** (chosen above): Simpler, no DDB dependency, still provides
  cryptographic binding of `user_sub` + timestamp. Adequate for the threat model — the main
  attack (CSRF code injection) is mitigated.
- **Storing state in DDB session**: Would bind state to the session row. Requires a DDB write
  on every `/connect` call. Not chosen because it conflates OAuth state with session state.

1. Set `GOOGLE_OAUTH_STATE_SIGNING_SECRET=dev-secret-not-for-prod` in `.env.local`.
2. Call `GET /ui/integrations/google-drive/connect` — confirm `auth_url` contains

### 5.4 Observability

Add a `record_google_oauth_state_rejection(reason=...)` metrics call (mirroring the calendar
OAuth pattern in `app/metrics.py`) to log `missing_state`, `bad_signature`, `user_mismatch`,
`expired` rejection reasons. Wire an alert on sustained rejection rates as a signal for CSRF

### 5.5 Rollout

- **Effort**: M. ~60 lines of new code in the router. Settings field already present.
- **Risk**: Low. The 501 non-mock path already rejects real callbacks; adding state
  verification to the mock path does not break existing mock E2E tests if the test helper is
  updated concurrently (see §5.2).
- **Rollback**: Revert the router changes. No DDB migration needed (stateless HMAC).
- **Sequencing**: Land this ticket before or alongside GAP-0242 (real token exchange). The
  fix is a blocker for any production OAuth flow.
- **Secret rotation**: `GOOGLE_OAUTH_STATE_SIGNING_SECRET` rotation invalidates all
  in-flight `state` tokens (users whose OAuth popup is open will see a 400 and must
  reconnect). TTL of 600s means exposure window is short.
