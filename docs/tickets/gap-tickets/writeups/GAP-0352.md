# GAP-0352: No Signature Drawing Canvas — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code before writing; all cites are `file:line`.

## 1. Summary & Classification

**Bug statement**: The "drawn" signature capture mode in `SignaturePacketComposer` accepts raw JSON coordinate arrays typed into a plain `<Input>` text field rather than letting the user draw freehand with a mouse or finger. There is no HTML5 `<canvas>` element with touch/pointer event handling. Users who select "drawn" mode are expected to type something like `[[0.1,0.2],[0.2,0.3]]` by hand — an unusable UX that blocks the drawn-signature workflow for all non-developer users.

- **Severity**: HIGH
- **Source ticket**: SIGN-001, §1c ("HTML5 canvas component for freehand signature drawing")
- **Status**: Open — no canvas element, no pointer/touch events, no stroke serialiser.
- **Owning area**: Frontend / Document Signing
- **Investigation verdict**: Confirmed exactly as stated. The ticket cites `SignaturePacketComposer.tsx:565`; that line is the `<Input placeholder="Drawn JSON points…">` fallback widget described below.
- **Related tickets**: GAP-0351 (no PDF viewer — same component). No new AWS-backed paths; SECOPS-007 not triggered.

## 2. Current-State Investigation (Root Cause)

### The text-box fallback at line 565

When a signature or initials field has its per-field capture mode set to `"drawn"`, `SignaturePacketComposer.tsx:540–568` renders:

```tsx
{(field.field_type !== "signature" && field.field_type !== "initials") ||
 (captureModes[field.field_id] ?? defaultCaptureMode) === "typed" ? (
  <Input
    type={field.field_type === "date" ? "date" : "text"}
    value={currentValue}
    ...
    placeholder={`Enter ${field.field_type}`}
    data-testid={`field-input-${field.field_id}`}
  />
) : (
  <Input                                           {/* ← line 556 */}
    value={drawnValues[field.field_id] ?? ""}
    onChange={(e) => {
      const value = e.target.value;
      setDrawnValues((prev) => ({ ...prev, [field.field_id]: value }));
      ...
    }}
    placeholder="Drawn JSON points, e.g. [[0.1,0.2],[0.2,0.3]]"   {/* ← line 565 */}
    data-testid={`field-drawn-${field.field_id}`}
  />
)}
```

The entire drawn-mode experience is a single `<Input>` box that accepts raw JSON strings. There is no `<canvas>`, no `useRef<HTMLCanvasElement>`, no `pointerdown`/`pointermove`/`pointerup` event handlers, and no stroke serialisation logic anywhere in the file.

### Validation logic expects JSON points — confirming the bypass

`SignaturePacketComposer.tsx:62–71` (`validateFieldInput` for drawn mode):

```ts
const strokes = parseDrawnStrokes(drawnRaw);
if (strokes.length < 2) return "Drawn mode needs JSON points, e.g. [[0.1,0.2],[0.2,0.3]]";
if (strokes.length > 20) return "Max points is 20";
for (const point of strokes) {
  if (!Array.isArray(point) || point.length !== 2) return "Each point must be [x,y]";
  const x = Number(point[0]); const y = Number(point[1]);
  if (Number.isNaN(x) || Number.isNaN(y) || x < 0 || x > 1 || y < 0 || y > 1)
    return "Drawn points must be within 0..1";
}
```

The backend `fillSignaturePacketField` call for drawn mode passes `drawn_strokes: parseDrawnStrokes(drawnRaw)` (`SignaturePacketComposer.tsx:291`). The API accepts `drawn_strokes` as an array of `[x, y]` pairs in the 0–1 normalized coordinate space. The underlying data model is sound; only the capture UI is missing.

### Runtime behaviour

In both dev and prod: selecting "drawn" on a signature field shows a plain text box. Users who type valid JSON can complete the workflow, but real freehand signatures cannot be produced. The `mark-done` button becomes available only if the text box contains valid JSON with ≥ 2 points. Non-technical users are stuck.

## 3. Impact / Exploit / Blast Radius

**UX impact**: Any user choosing drawn mode (or having "drawn" set as the default) cannot produce a real signature. The only workaround is typing a JSON array directly — not discoverable, not accessible, not legally meaningful as a "signature".

**Legal / compliance**: Drawn signatures carry legal weight partly because they capture the motor act of signing. A JSON-array typed in a text box does not satisfy the intent of e-signature law even if the backend renders it as strokes.

**Feature completeness**: The SIGN-001 ticket was closed as implemented, but §1c (drawn canvas) was never built. Any feature flag or marketing copy describing "hand-drawn signatures" is currently misleading.

**Blast radius**: Affects all users in signer role who select "drawn" capture mode. No backend data corruption risk; the API correctly stores and renders whatever strokes are submitted. A proper canvas only improves the input quality.

## 4. Fix Design (Code-Level)

### 4.1 No new library needed for a basic canvas

HTML5 Canvas with React refs is sufficient for a simple freehand input. For a polished production widget, `signature_pad` (npm: `signature_pad`) is a well-maintained MIT library with touch support, pressure sensitivity, and built-in bezier smoothing, and it outputs a simple array of points. Either approach works; this write-up uses the lightweight custom approach to avoid a new dependency, with `signature_pad` noted as an upgrade path.

### 4.2 New `SignatureDrawCanvas` component

Create `frontend/src/components/shared/SignatureDrawCanvas.tsx`:

```tsx
import * as React from "react";
import { Button } from "@/components/ui/button";

interface Point { x: number; y: number; }
type Stroke = Point[];

interface Props {
  onStrokesChange: (strokes: number[][]) => void;
  width?: number;
  height?: number;
  "data-testid"?: string;
}

export function SignatureDrawCanvas({ onStrokesChange, width = 320, height = 120, "data-testid": testId }: Props) {
  const canvasRef = React.useRef<HTMLCanvasElement>(null);
  const strokesRef = React.useRef<Stroke[]>([]);
  const activeStroke = React.useRef<Stroke | null>(null);

  const normalize = (e: React.PointerEvent<HTMLCanvasElement>): Point => {
    const rect = canvasRef.current!.getBoundingClientRect();
    return {
      x: Math.max(0, Math.min(1, (e.clientX - rect.left) / rect.width)),
      y: Math.max(0, Math.min(1, (e.clientY - rect.top) / rect.height)),
    };
  };

  const redraw = () => {
    const canvas = canvasRef.current;
    if (!canvas) return;
    const ctx = canvas.getContext("2d")!;
    ctx.clearRect(0, 0, canvas.width, canvas.height);
    ctx.strokeStyle = "#1e293b";
    ctx.lineWidth = 2;
    ctx.lineCap = "round";
    ctx.lineJoin = "round";
    for (const stroke of strokesRef.current) {
      if (stroke.length < 2) continue;
      ctx.beginPath();
      ctx.moveTo(stroke[0].x * canvas.width, stroke[0].y * canvas.height);
      for (const pt of stroke.slice(1)) ctx.lineTo(pt.x * canvas.width, pt.y * canvas.height);
      ctx.stroke();
    }
  };

  const emitChange = () => {
    const flat = strokesRef.current.flatMap((s) => s.map((p) => [p.x, p.y]));
    onStrokesChange(flat);
  };

  const handlePointerDown = (e: React.PointerEvent<HTMLCanvasElement>) => {
    canvasRef.current?.setPointerCapture(e.pointerId);
    activeStroke.current = [normalize(e)];
  };
  const handlePointerMove = (e: React.PointerEvent<HTMLCanvasElement>) => {
    if (!activeStroke.current) return;
    activeStroke.current.push(normalize(e));
    redraw();
    // Draw the active stroke segment on top
    const canvas = canvasRef.current!;
    const ctx = canvas.getContext("2d")!;
    const stroke = activeStroke.current;
    if (stroke.length < 2) return;
    ctx.beginPath();
    ctx.strokeStyle = "#1e293b";
    ctx.lineWidth = 2;
    ctx.lineCap = "round";
    ctx.moveTo(stroke[stroke.length - 2].x * canvas.width, stroke[stroke.length - 2].y * canvas.height);
    ctx.lineTo(stroke[stroke.length - 1].x * canvas.width, stroke[stroke.length - 1].y * canvas.height);
    ctx.stroke();
  };
  const handlePointerUp = () => {
    if (!activeStroke.current) return;
    if (activeStroke.current.length >= 2) {
      strokesRef.current = [...strokesRef.current, activeStroke.current];
      emitChange();
    }
    activeStroke.current = null;
  };

  const clear = () => {
    strokesRef.current = [];
    activeStroke.current = null;
    redraw();
    onStrokesChange([]);
  };

  return (
    <div className="space-y-1">
      <canvas
        ref={canvasRef}
        width={width}
        height={height}
        onPointerDown={handlePointerDown}
        onPointerMove={handlePointerMove}
        onPointerUp={handlePointerUp}
        onPointerLeave={handlePointerUp}
        className="rounded border border-slate-300 bg-white cursor-crosshair touch-none"
        data-testid={testId}
        style={{ width, height }}
      />
      <Button size="sm" variant="outline" onClick={clear} type="button">Clear</Button>
    </div>
  );
}
```

### 4.3 Wire into `SignaturePacketComposer`

Replace the plain `<Input>` for drawn mode (`SignaturePacketComposer.tsx:556–567`) with:

```tsx
import { SignatureDrawCanvas } from "@/components/shared/SignatureDrawCanvas";

// …inside the "drawn" branch:
) : (
  <SignatureDrawCanvas
    data-testid={`field-drawn-canvas-${field.field_id}`}
    onStrokesChange={(points) => {
      const raw = JSON.stringify(points);
      setDrawnValues((prev) => ({ ...prev, [field.field_id]: raw }));
      const mode = captureModes[field.field_id] ?? defaultCaptureMode;
      const err = validateFieldInput(field, fillValues[field.field_id] ?? "", mode, raw);
      setFillErrors((prev) => ({ ...prev, [field.field_id]: err ?? "" }));
    }}
  />
)}
```

`validateFieldInput` already accepts the JSON array form produced by `onStrokesChange`; no backend changes are required.

### 4.4 Preserve typed mode preference

The `defaultCaptureMode` preference (stored in `localStorage`) is unchanged. Users who prefer "typed" continue to see the `<Input>` text field. The canvas is only rendered when mode is `"drawn"`.

### 4.5 Dev/prod parity (SECOPS-007)

This is entirely frontend state management and HTML5 Canvas — no AWS paths, no flags. The component behaves identically in dev and prod.

### 4.6 Stroke decimation

Raw pointer events at 60fps produce hundreds of points per second. The backend validates that strokes contain at most 20 points total (`SignaturePacketComposer.tsx:64: if (strokes.length > 20) return "Max points is 20"`). Add a decimation pass before calling `onStrokesChange`:

```ts
function decimatePoints(points: number[][], maxPoints: number): number[][] {
  if (points.length <= maxPoints) return points;
  const step = points.length / maxPoints;
  return Array.from({ length: maxPoints }, (_, i) => points[Math.floor(i * step)]);
}
```

Call `decimatePoints(flat, 20)` before passing to `onStrokesChange`. This ensures the canvas can capture detailed strokes without violating the backend validation limit.

### 4.7 Alternatives considered

- **`signature_pad` npm package**: polished bezier smoothing, better pressure handling, built-in touch event support. Adds ~12 KB gzip. Recommended for v2 if freehand signature quality is a product priority; the custom canvas above is sufficient for MVP and avoids an additional dependency.
- **SVG path approach**: achievable without `<canvas>` using `<svg>` and `<polyline>` elements. More complex state management for multi-stroke drawings; no clear benefit over canvas here.
- **Typed mode only**: remove drawn mode entirely. Rejected — the API explicitly supports `drawn_strokes`, SIGN-001 §1c requires it, and a typed name in a text box has weaker legal standing as a "signature" compared to a handwritten stroke.
- **Image capture (upload a PNG)**: users could upload a photograph of their handwritten signature. Requires a separate upload endpoint and introduces storage costs; out of scope for SIGN-001.

### Effort and risk

**Effort**: M (as stated in the gap ticket). The `SignatureDrawCanvas` component is ~80 lines. The integration change in `SignaturePacketComposer.tsx` is ~10 lines.

**Rollout**: Low risk. The canvas replaces a text box that was essentially unusable. No backend migration; existing signed packets are unaffected.

**Risks**: Touch-device pointer events should be tested on iOS Safari (requires `touch-action: none` CSS, included as `touch-none` Tailwind class). Very thin or accidental single-point "strokes" are filtered by the `stroke.length >= 2` guard before submission.

**Accessibility**: Freehand drawing is inaccessible to users with motor impairments who rely on keyboard navigation. The default capture mode preference (`localStorage: signature_packet_capture_mode_default`) is already set to `"typed"`, so keyboard users are unaffected as long as they do not switch to drawn mode. Consider adding a note in the drawn-mode UI explaining that typed mode is available as an alternative for accessibility needs.

**Legal standing of typed vs drawn signatures**: Both modes produce a valid `filled_at` timestamp and a stored representation in DynamoDB, so both are legally equivalent within the system. The distinction between typed and drawn is a UI preference, not a backend policy. Operators with stricter requirements (requiring wet-signature image capture) should implement the image-upload variant described in §4.7.
