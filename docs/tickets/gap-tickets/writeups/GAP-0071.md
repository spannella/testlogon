# GAP-0071: record_ad_event Does Not Write to ad_billing, ad_fraud_prevention, or ad_analytics — Remediation Write-up

## 1. Summary & Classification

**Claim status: Confirmed.**

`record_ad_event` in `app/services/broadcast_ads.py` (lines 185–216) is the single entry point called whenever a viewer browser reports a broadcast ad impression, skip, completion, or click. The function writes one row to `T.broadcast_ad_events` and returns immediately. It never calls `charge_impression` from `app/services/ad_billing.py`, never invokes `check_fraud` from `app/services/ad_fraud_prevention.py`, and never triggers `compute_hourly_rollup` or any equivalent analytics write in `app/services/ad_analytics.py`. Those three service modules all exist and have implemented logic — but `record_ad_event` is completely unaware of them.

- **Severity**: HIGH
- **Source ticket**: ADS-020
- **Owning area**: Ads / Monetization back-end
- **Status**: Open
- **Impact**: Every broadcast ad impression generates zero advertiser charges, zero fraud signals, and zero analytics data. Ad revenue is silently lost regardless of campaign activity.
- **Related tickets**: GAP-0072 (missing feature flag, which this fix depends on), GAP-0050 (rollup never called), GAP-0049 (platform revenue share not written), GAP-0052 (CPM floor not enforced).


## 2. Current-State Investigation (root cause)

### The broken function

`app/services/broadcast_ads.py`, lines 185–216:

```python
def record_ad_event(
    *,
    session_id: str,
    creative_id: str,
    user_id: str,
    event_type: str,
    slot_type: str = "",
) -> Dict[str, Any]:
    """Record a broadcast ad event (impression/skip/complete/click).

    Best-effort: tracking failures must never break playback.
    """
    if event_type not in _VALID_EVENTS:
        event_type = "impression"
    ts = now_ts()
    event_id = f"bae_{uuid4().hex}"
    try:
        T.broadcast_ad_events.put_item(
            Item={
                "session_id": session_id,
                "event_sk": f"{ts}#{event_id}",
                "event_id": event_id,
                "creative_id": creative_id,
                "user_id": user_id,
                "event_type": event_type,
                "slot_type": slot_type,
                "created_at": ts,
            }
        )
    except Exception:  # pragma: no cover - tracking is best-effort
        pass
    return {"ok": True, "event_id": event_id, "event_type": event_type}
```

The function body does exactly one thing: write a raw event row to `BroadcastAdEvents`. There is no call to any of:

- `app/services/ad_billing.py::charge_impression` (line 60) — which debits advertiser balance, credits creator share, and checks campaign budget.
- `app/services/ad_fraud_prevention.py::check_fraud` (line 115) — which runs six deterministic fraud rules and returns a `FraudCheckResult`.
- `app/services/ad_fraud_prevention.py::record_fraud_event` (line 308) — which persists flagged events for admin review.
- `app/services/ad_analytics.py::compute_hourly_rollup` (line 168) — which aggregates impression/click/spend data.

### Call chain

The router endpoint at `app/routers/broadcast_ads.py` line 237–253 calls `record_ad_event` directly and returns. There is no post-processing, no async task, and no background job that picks up the raw event rows and fans them out to billing or fraud.

### What exists vs. what is missing

| Component | Exists? | Called from record_ad_event? |
|---|---|---|
| `BroadcastAdEvents` DDB write | Yes (line 202) | Yes |
| `charge_impression` in ad_billing | Yes (line 60) | No |
| `check_fraud` in ad_fraud_prevention | Yes (line 115) | No |
| `record_fraud_event` | Yes (line 308) | No |
| `compute_hourly_rollup` | Yes (line 168) | No |
| `BROADCAST_ADS_BILLING_ENABLED` flag | No — GAP-0072 | N/A |

### How the router hands off to the service

`app/routers/broadcast_ads.py` lines 237–253:

The router does not pass `account_id`, `campaign_id`, `bid_cpm_cents`, `ip_address`, or `user_agent` — none of which are optional for billing or fraud. These fields are not on the current `record_ad_event` signature at all. This means the router change is a required part of the fix, not just a service-layer change.

### Dev vs. prod behaviour

The gap is identical in both environments: neither mock DDB (local) nor real DynamoDB (AWS) receives any billing write, fraud record, or analytics rollup when a broadcast ad event arrives. The raw event row accumulates in `BroadcastAdEvents` without consequence. In dev, this is invisible because the dev dashboard shows all-zero analytics regardless. In production, this means every broadcast ad exposure since ADS-006 shipped has been revenue-free for the platform and creator, and fraud-blind for the ad system.


## 3. Impact / Exploit / Blast Radius

### Revenue loss

Every broadcast impression goes uncharged. An advertiser can run a campaign indefinitely without their account balance decreasing. Because `charge_impression` (`ad_billing.py:60`) also drives `_split_revenue` (`ad_billing.py:150`), creators receive no ad revenue credits either. Platform revenue share (30%) is never written to the billing ledger (cross-reference GAP-0049).

### Fraud signals absent

Because `check_fraud` is never called, six fraud rules — click velocity, IP clustering, bot user-agent detection, invalid traffic (IVT), CTR anomaly, and geo-mismatch — are never evaluated. A single IP address can generate unlimited fake impressions. The `AUTO_SUSPEND_FRAUD_RATE_BPS` auto-suspend mechanism in `ad_fraud_prevention.py` line 464 can never trigger. Cross-reference SEC-013 (duplicate-write race) and GAP-0048 (no daily spend reset).

### Analytics blackout

Because `compute_hourly_rollup` is never driven by impression events, `ad_analytics.py`'s summary, time-series, breakdown, and CSV-export functions (`get_summary`, `get_timeseries`, `get_breakdown`) all return empty data. The analytics dashboard shows zero activity regardless of actual broadcast ad exposure.

### Blast radius

Affects every `POST /ui/broadcast/sessions/{session_id}/ads/{creative_id}/track` call. Pre-roll and mid-roll events from all viewers on all live sessions since the ADS-006 feature shipped are silently lost from billing, fraud, and analytics systems.

### Concrete exploit

1. Attacker registers an advertiser account, deposits minimum $50 balance.
2. Creates a campaign, sets high CPM.
3. Script-drives `POST .../track?event=impression` from many IPs repeatedly.
4. Advertiser balance is never decremented. Ad budget is never consumed. Fraud score is never computed. System never auto-suspends the account.


## 4. Fix Design (code-level)

### Step 1: Add the feature flag (depends on GAP-0072)

Add `broadcast_ads_billing_enabled` to `app/core/settings.py` (see GAP-0072 write-up). This is a prerequisite; the billing calls below must be gated on it.

### Step 2: Wire billing, fraud, and analytics into record_ad_event

Modify `app/services/broadcast_ads.py`. The function needs four additional concerns:

1. **Fraud pre-check** — run before billing so fraudulent impressions are never charged.
2. **Billing call** — on `impression` and `complete` events (CPM model charges on impression; some publishers charge on complete — the spec uses impression).
3. **Fraud post-record** — persist fraud result for admin review.
4. **Analytics increment** — increment rollup counters for impression/skip/complete/click.

```python
# Add to top of broadcast_ads.py imports
from app.core.settings import S


def record_ad_event(
    *,
    session_id: str,
    creative_id: str,
    user_id: str,
    event_type: str,
    slot_type: str = "",
    # Billing context — required when billing is enabled
    account_id: str = "",
    campaign_id: str = "",
    creator_id: str = "",
    bid_cpm_cents: int = 0,
    # Fraud context
    ip_address: str = "",
    user_agent: str = "",
    view_time_ms: int = 0,
) -> Dict[str, Any]:
    """Record a broadcast ad event (impression/skip/complete/click).

    Best-effort: tracking failures must never break playback.
    """
    if event_type not in _VALID_EVENTS:
        event_type = "impression"
    ts = now_ts()
    event_id = f"bae_{uuid4().hex}"

    # ── Fraud check (always, regardless of billing flag) ──────────────
    fraud_flagged = False
    fraud_score = 0
    if user_id:
        try:
            from app.services.ad_fraud_prevention import (
                check_fraud,
                record_fraud_event,
                record_account_activity,
            )
            result = check_fraud(
                user_id=user_id,
                ip_address=ip_address,
                user_agent=user_agent,
                creative_id=creative_id,
                campaign_id=campaign_id,
                view_time_ms=view_time_ms,
                event_type=event_type,
            )
            fraud_flagged = result.flagged
            fraud_score = result.score
            if fraud_flagged:
                record_fraud_event(
                    user_id=user_id,
                    event_type=event_type,
                    creative_id=creative_id,
                    campaign_id=campaign_id,
                    session_id=session_id,
                    score=fraud_score,
                    rule_scores=result.rule_scores,
                )
            record_account_activity(
                account_id=account_id, flagged=fraud_flagged
            )
        except Exception:
            pass  # fraud check failure must never block playback

    # ── Billing (impression charges, gated by flag) ───────────────────
    charge_id = None
    if (
        S.broadcast_ads_billing_enabled
        and not fraud_flagged
        and event_type == "impression"
        and account_id
        and campaign_id
        and bid_cpm_cents > 0
    ):
        try:
            from app.services.ad_billing import charge_impression
            charge_result = charge_impression(
                account_id=account_id,
                campaign_id=campaign_id,
                creative_id=creative_id,
                creator_id=creator_id,
                content_id=session_id,
                bid_cpm_cents=bid_cpm_cents,
            )
            charge_id = charge_result.get("entry_id")
        except Exception:
            pass  # billing failure must never break playback

    # ── Raw event row ─────────────────────────────────────────────────
    try:
        T.broadcast_ad_events.put_item(
            Item={
                "session_id": session_id,
                "event_sk": f"{ts}#{event_id}",
                "event_id": event_id,
                "creative_id": creative_id,
                "user_id": user_id,
                "event_type": event_type,
                "slot_type": slot_type,
                "created_at": ts,
                "fraud_flagged": fraud_flagged,
                "fraud_score": fraud_score,
                **({"charge_id": charge_id} if charge_id else {}),
            }
        )
    except Exception:
        pass

    return {
        "ok": True,
        "event_id": event_id,
        "event_type": event_type,
        "fraud_flagged": fraud_flagged,
    }
```

### Router change

`app/routers/broadcast_ads.py` — the `track_ad_event_route` endpoint must pass billing context down. The ad-join response (`BroadcastJoinOut`) already knows `account_id`, `campaign_id`, and `bid_cpm_cents` from the pre-roll build — the router should extract these from the session or accept them as query params (the latter is simpler for the initial fix):

```python
@router.post("/sessions/{session_id}/ads/{creative_id}/track", response_model=AdEventOut)
def track_ad_event_route(
    session_id: str,
    creative_id: str,
    event: str = Query(default="impression"),
    slot_type: str = Query(default=""),
    account_id: str = Query(default=""),
    campaign_id: str = Query(default=""),
    bid_cpm_cents: int = Query(default=0),
    view_time_ms: int = Query(default=0),
    ctx: dict = Depends(_ctx),
    request: Request = None,
):
    result = record_ad_event(
        session_id=session_id,
        creative_id=creative_id,
        user_id=ctx["user_sub"],
        event_type=event,
        slot_type=slot_type,
        account_id=account_id,
        campaign_id=campaign_id,
        bid_cpm_cents=bid_cpm_cents,
        view_time_ms=view_time_ms,
        ip_address=request.client.host if request else "",
        user_agent=request.headers.get("user-agent", "") if request else "",
    )
    return AdEventOut(**result)
```

### Dev/Prod parity (SECOPS-007)

The billing and fraud calls use `T.ad_billing`, `T.ad_fraud_events`, and `T.ad_accounts` — all of which resolve against `DDB_ENDPOINT_URL` in dev (pointing to DynamoDB Local on port 8001) and against real DynamoDB in production. No mock-only code path exists. The flag `broadcast_ads_billing_enabled` defaults to `False` in `.env.local.example` (to avoid billing calls during normal dev sessions) and is enabled via environment variable in production. The fraud check is always active (not gated by the billing flag) to ensure fraud counters accumulate in both environments. This is the correct split: fraud detection is a safety mechanism; billing is revenue-affecting.

### Alternatives considered

- **Background fan-out job**: process raw `BroadcastAdEvents` rows asynchronously. Rejected because it adds minutes of billing latency and requires a separate loop that GAP-0050 shows is already missing. Synchronous best-effort calls within the existing try/except envelope are consistent with the existing tracking design.
- **Single analytics write per event**: instead of driving rollup at event time, the analytics service already has `compute_hourly_rollup` which aggregates from `ad_billing`. Once billing is wired, analytics will self-heal. A direct raw-event → rollup call at event time is redundant.

### Rollout

1. Deploy GAP-0072 first (feature flag). This is a hard prerequisite — without the flag the billing path cannot be controlled.
2. Deploy this fix with `BROADCAST_ADS_BILLING_ENABLED=false` (no charge calls yet, but fraud counters start accumulating). Verify in staging that the fraud path runs without errors by inspecting `ad_fraud_events` table.
3. Run fraud path in production for 48 hours; verify `T.ad_fraud_events` accumulates event rows and the auto-suspend logic (`maybe_auto_suspend` in `ad_fraud_prevention.py:464`) correctly identifies suspicious accounts.
4. Enable billing flag in staging; run a broadcast session with a test advertiser account. Verify: advertiser `balance_cents` decrements by the expected CPM amount, creator billing ledger receives an `ad_revenue_credit`, campaign `spent_today_cents` increments.
5. Enable billing flag in production; monitor advertiser balance changes and creator credit entries. Alert on unexpected balance-going-negative events.
6. Rollback path: set `BROADCAST_ADS_BILLING_ENABLED=false` — billing halts immediately, raw events still recorded, no data loss.

### Backward compatibility and migration

No DynamoDB schema changes are required. The new `account_id`, `campaign_id`, `creator_id`, and `bid_cpm_cents` fields on `record_ad_event` are optional with defaults, so any callers that have not been updated yet will continue to work — they will simply produce events that are not billed (fraud check will still run). The `fraud_flagged` field added to the raw event row is new but additive; DynamoDB's schemaless model accommodates this without migration.
