# GAP-0007: serve_broadcast_ad Not Wired to Real Ad Serving Engine — Remediation Write-up

> ~5 pages. Fix-oriented. Grounded in the investigation doc
> (docs/tickets/gap-tickets/investigations/GAP-0007.md) and real code at
> app/services/broadcast_ads.py:55–83.

---

## 1. Summary & Classification

**Bug statement.** `serve_broadcast_ad()` in `app/services/broadcast_ads.py`
unconditionally returns a hardcoded "house" creative for every broadcast ad
request. The function contains a TODO comment acknowledging it should delegate
to `app.services.ad_serving.serve_ad`, but that delegation was never
implemented. As a result, all broadcast ad slots serve the same stub creative
regardless of which campaigns are active, what targeting criteria are set, or
what frequency caps apply to the viewer.

| Field | Value |
|-------|-------|
| Severity | **CRITICAL** |
| Source ticket | ADS-020 |
| Status | Open |
| Owning area | Ads / Broadcast Monetisation |
| Investigation verdict | **Confirmed** |

**One-line impact.** Zero advertiser revenue is generated from broadcast ads;
creator ad revenue from live streams is always $0 regardless of active
campaigns.

**Related tickets.** ADS-004 (ad serving engine — `serve_ad()` already
implemented), ADS-002 (video creatives), GAP-0006 (VOD impression fraud gate),
GAP-0047 (broadcast ad feature flags), GAP-0072 (broadcast ads billing flag).

## 2. Current-State Investigation (root cause)

### Function under investigation

`app/services/broadcast_ads.py:55–83`:

```python
def serve_broadcast_ad(
    *,
    surface: str,
    creator_id: str,
    content_id: str,
    slot_type: str,
    user_id: str,
) -> Dict[str, Any]:
    """Select an ad for a broadcast surface.

    NOTE: ADS-004 (ad serving engine) and ADS-002 (video creatives) are not yet
    implemented. This returns a deterministic stub "house" creative so the rest of
    the flow (overlay, tracking, skip) is exercisable end-to-end. When ADS-004 lands
    this function should delegate to ``app.services.ad_serving.serve_ad``.
    """
    creative_id = f"bcast_house_{slot_type}"
    return {
        "filled": True,
        "creative_id": creative_id,
        "format": "video",
        "video_url": f"/mock/s3/ad-creatives/{creative_id}.mp4",
        "image_url": None,
        "cta_url": None,
        "impression_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=impression",
        "click_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=click",
        "skip_url": f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=skip",
    }
```

The entire function body is a single hard-coded return. No table lookup, no
campaign selection, no targeting logic, no frequency-cap check, no fraud check.

### Call site: `build_pre_roll()` at `app/services/broadcast_ads.py:98`

```python
    ad = serve_broadcast_ad(
        surface="broadcast",
        creator_id=session.created_by,
        content_id=session.id,
        slot_type="broadcast_preroll",
        user_id=viewer_id,
    )
```

`build_pre_roll()` is called whenever a viewer joins a broadcast session that
has `pre_roll_enabled=True`. The result is embedded in the session join payload
delivered to the player.

### The real engine that exists but is never called

`app/services/ad_serving.py:45` — `serve_ad()` — is fully implemented. It
performs targeting (geo, device, category), budget checks, frequency-cap
enforcement, fraud suspension checks, and returns a properly formed creative
payload. Its DynamoDB tables (`T.ad_campaigns`, `T.ad_creatives`,
`T.ad_targeting`, `T.ad_frequency_caps`) are created and wired. The only
missing link is the call from `broadcast_ads.py`.

### Why the gap exists

`broadcast_ads.py` was written as an end-to-end scaffolding stub for the
broadcast flow before `ad_serving.py` (ADS-004) was completed. The docstring
records this explicitly. The ADS-020 ticket was supposed to close the delegation
but was merged in stub state — the TODO comment was accepted as if it were an
implementation placeholder rather than a remaining work item.

### Mid-roll path is also affected

`build_mid_roll()` (defined immediately below `build_pre_roll()` at
approximately line 120) contains an equivalent `serve_broadcast_ad()` call
with `slot_type="broadcast_midroll"`. Both pre-roll and mid-roll paths are
broken. The fix to `serve_broadcast_ad()` automatically repairs both call
sites since they share the same function.

### Tracking URLs are broken in production

The house creative's `impression_url`, `click_url`, and `skip_url` all point
to `/mock/s3/ad-creatives/{creative_id}.mp4` — a dev-only path that returns
404 in production. Even if a house ad is desired as a fallback, its tracking
URLs should point to a real tracking endpoint. The fix preserves the house
creative as a fallback but the tracking URLs must be updated to point to the
real broadcast ad tracking handler (e.g., `/broadcast/sessions/{id}/ads/track`).

### Dev vs prod behaviour

In dev, `T.ad_campaigns` is populated by `scripts/local-ddb-seed.py` with
sample campaigns. The stub returns a `bcast_house_*` creative regardless,
even when real campaigns are present in DDB. In production, no real campaign
ever serves from a broadcast session. Both dev and production are equally
broken — the stub runs in all environments unconditionally.

## 3. Impact / Exploit / Blast Radius

This is primarily a **revenue / correctness** gap rather than a security
vulnerability.

**Advertiser impact.** Campaigns configured for `surface=broadcast` are never
selected, never served, and never spend. Budgets remain frozen at 0. Advertisers
receive no reach from live broadcast inventory, potentially in violation of
campaign contracts.

**Creator impact.** Creators who have enabled broadcast ads (`pre_roll_enabled`,
`mid_roll_enabled`) receive zero ad revenue from those streams. The platform's
revenue-share commitment (e.g., 70% of CPM to creator) is never fulfilled for
any broadcast session.

**Frequency-cap / targeting bypass.** Because the house creative has no
`campaign_id`, `record_ad_impression()` cannot write frequency-cap entries.
When the fix is applied and real campaigns start serving, viewers who were
previously exposed to the house creative will have zero frequency cap history,
which may result in over-serving the first real campaign until their cap records
accumulate.

**Cascading stub tracking URLs.** The house creative's `impression_url`,
`click_url`, and `skip_url` point to `/mock/s3/ad-creatives/...` paths that
do not exist in production. Any player that fires those tracking URLs will
receive 404s. Impression and click counts are therefore completely absent for
all broadcast ad events today, meaning even the "how many viewers saw pre-roll"
metric is unavailable.

**Frequency-cap records are never written.** Because the house creative has
`creative_id = f"bcast_house_{slot_type}"` with no real `campaign_id`, the
frequency-cap table (`T.ad_frequency_caps`) is never incremented for any
broadcast viewer. When the fix is applied and real campaigns start serving,
all viewers have zero cap history. The first real campaign will immediately
over-serve (no cap to enforce) until viewer frequency records accumulate to
normal levels. A one-time cap-history backfill or a grace period with
reduced frequency-cap enforcement is advisable at launch.

**No fraud detection.** `serve_broadcast_ad()` does not call `check_fraud()`
before returning the house creative. In the current stub state this is
irrelevant (no advertiser money is spent). After the fix, the delegation to
`serve_ad()` inherits whatever fraud-check logic `serve_ad()` applies at
serve time. Verify that `serve_ad()` calls `check_fraud()` (it does — see
`app/services/ad_serving.py:198`) before going live with real campaigns.

## 4. Fix Design (code-level)

### Core change: delegate to `serve_ad()` with house fallback

Replace the entire body of `serve_broadcast_ad()` in
`app/services/broadcast_ads.py:55–83`:

```python
def serve_broadcast_ad(
    *,
    surface: str,
    creator_id: str,
    content_id: str,
    slot_type: str,
    user_id: str,
) -> Dict[str, Any]:
    """Select an ad for a broadcast surface via the real ad serving engine.

    Delegates to app.services.ad_serving.serve_ad with surface="broadcast".
    Falls back to the house creative if the engine errors or returns unfilled.
    """
    try:
        from app.services.ad_serving import serve_ad
        result = serve_ad(
            surface=surface,
            content_type="broadcast",
            creator_id=creator_id,
            content_id=content_id,
            slot_type=slot_type,
            user_id=user_id,
        )
        if result.get("filled"):
            return result
    except Exception:
        logger.warning(
            "broadcast_ad_serve_engine_error creator=%s content=%s",
            creator_id, content_id,
        )

    # Fallback: house creative (same as current stub behaviour)
    creative_id = f"bcast_house_{slot_type}"
    return {
        "filled": True,
        "creative_id": creative_id,
        "format": "video",
        "video_url": f"/mock/s3/ad-creatives/{creative_id}.mp4",
        "image_url": None,
        "cta_url": None,
        "impression_url": (
            f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=impression"
        ),
        "click_url": (
            f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=click"
        ),
        "skip_url": (
            f"/broadcast/sessions/{content_id}/ads/{creative_id}/track?event=skip"
        ),
    }
```

The `try/except` with fallback means:
- If `serve_ad()` returns a filled creative → use it (real campaign serves).
- If `serve_ad()` returns `filled=False` (no matching campaign) → fall through
  to house creative (unchanged user experience).
- If `serve_ad()` raises (engine bug, DDB timeout) → fall through to house
  creative with a warning log (no service degradation to the viewer).

### Surface parameter alignment

`serve_ad()` receives `surface="broadcast"`. Confirm that
`app/services/ad_targeting.py` (the targeting evaluator inside `serve_ad`)
accepts `"broadcast"` as a valid surface value and that test campaigns can be
seeded with `allowed_surfaces=["broadcast"]`.

### Frequency-cap migration

After the fix, new frequency-cap records will accumulate for real campaign
creatives. Existing viewers have no history. This is benign — frequency caps
enforce a ceiling, and starting from zero is safe.

### Feature flag

Wrap the delegation behind the existing `S.broadcast_ads_billing_enabled` flag
(see GAP-0072). If the flag is `False`, skip the engine call and return the
house creative immediately, preserving the current safe-to-deploy state:

```python
    if not getattr(S, "broadcast_ads_billing_enabled", False):
        # Billing not live yet — serve house creative as before
        creative_id = f"bcast_house_{slot_type}"
        return { ... }

    try:
        from app.services.ad_serving import serve_ad
        ...
```

This allows the code change to be deployed and tested without enabling real
billing, then the flag can be flipped independently.

### Dev/Prod parity (SECOPS-007)

`serve_ad()` uses only DynamoDB (`T.ad_campaigns`, `T.ad_creatives`) — tables
present in both DynamoDB Local and production. No AWS-specific code path is
introduced. In dev with an empty campaigns table, `serve_ad()` returns
`filled=False` → the house creative fallback is triggered automatically, so
dev behaviour is unchanged until campaigns are seeded. No migration required.

## 5. Testing, Verification & Rollout

```python
import pytest
from unittest.mock import patch

from app.services.broadcast_ads import serve_broadcast_ad


def test_serve_broadcast_ad_delegates_to_engine(mocker):
    """FAILS before fix (engine never called), PASSES after."""
    mock_serve = mocker.patch(
        "app.services.ad_serving.serve_ad",
        return_value={
            "filled": True,
            "creative_id": "cmp_creative_123",
            "format": "video",
            "video_url": "https://cdn.example.com/ad.mp4",
            "impression_url": "/track?event=impression",
            "click_url": "/track?event=click",
            "skip_url": "/track?event=skip",
        },
    )
    result = serve_broadcast_ad(
        surface="broadcast",
        creator_id="creator_1",
        content_id="session_1",
        slot_type="broadcast_preroll",
        user_id="viewer_1",
    )
    mock_serve.assert_called_once_with(
        surface="broadcast",
        content_type="broadcast",
        creator_id="creator_1",
        content_id="session_1",
        slot_type="broadcast_preroll",
        user_id="viewer_1",
    )
    assert result["creative_id"] == "cmp_creative_123"
    assert result["filled"] is True


def test_serve_broadcast_ad_falls_back_on_engine_error(mocker):
    """Engine exception must not surface to caller — falls back to house."""
    mocker.patch(
        "app.services.ad_serving.serve_ad",
        side_effect=Exception("DDB timeout"),
    )
    result = serve_broadcast_ad(
        surface="broadcast",
        creator_id="c1",
        content_id="s1",
        slot_type="broadcast_preroll",
        user_id="u1",
    )
    assert result["filled"] is True
    assert "bcast_house" in result["creative_id"]


def test_serve_broadcast_ad_falls_back_when_unfilled(mocker):
    """filled=False from engine also triggers house fallback."""
    mocker.patch(
        "app.services.ad_serving.serve_ad",
        return_value={"filled": False},
    )
    result = serve_broadcast_ad(
        surface="broadcast",
        creator_id="c1",
        content_id="s1",
        slot_type="broadcast_preroll",
        user_id="u1",
    )
    assert result["filled"] is True
    assert "bcast_house" in result["creative_id"]


def test_serve_broadcast_ad_flag_off_skips_engine(mocker, monkeypatch):
    """When broadcast_ads_billing_enabled=False, engine is never called."""
    monkeypatch.setattr("app.core.settings.S.broadcast_ads_billing_enabled", False)
    mock_serve = mocker.patch("app.services.ad_serving.serve_ad")
    result = serve_broadcast_ad(
        surface="broadcast", creator_id="c1",
        content_id="s1", slot_type="preroll", user_id="u1",
    )
    mock_serve.assert_not_called()
    assert result["filled"] is True
```

### Manual QA steps

1. `just up` — confirm dev stack running.
2. Start a broadcast session as Alice; join as Bob (viewer).
3. Before fix: observe pre-roll creative_id is always `bcast_house_broadcast_preroll`.
4. Seed a campaign in `T.ad_campaigns` with `allowed_surfaces=["broadcast"]`.
5. Apply fix and set `BROADCAST_ADS_BILLING_ENABLED=true` in `.env.local`.
6. Restart backend; join the broadcast as Bob again.
7. Confirm pre-roll creative_id is the campaign creative, not the house stub.
8. Confirm fallback: delete all campaigns from DDB; rejoin — should fall back
   to house creative without error.

### Metrics / observability

Add `logger.info("broadcast_ad_engine_served creative=%s ...", ...)` in the
success path and `logger.info("broadcast_ad_house_fallback reason=unfilled",
...)` in the fallback. Track `broadcast_ad_engine_served_total` vs
`broadcast_ad_house_fallback_total` in Prometheus/CloudWatch. Alert if
fallback rate exceeds 20% (indicates campaign inventory issue).

### Rollback

Set `BROADCAST_ADS_BILLING_ENABLED=false` to revert to house creative with
no code change. Code revert removes the delegation entirely.

### Risks

- **Targeting data quality:** If `T.ad_campaigns` has malformed targeting data,
  `serve_ad()` may raise unexpectedly. Covered by the `except Exception`
  fallback.
- **Latency:** `serve_ad()` performs 3–5 DynamoDB reads. Adds ~10–20 ms to
  the join payload. Acceptable for a pre-roll (player already buffering).
- **Frequency cap cold start:** First campaign deployment will see no cap
  history; watch for over-serving alerts.

### Effort

**S** — One-function body replacement. The engine (`serve_ad`) is fully
implemented. Total estimated effort: 2–3 hours development, 1 hour testing.
