# GAP-0044: bid_cpm_cents Not a Campaign Field — Remediation Write-up

## 1. Summary & Classification

**Plain-English statement**: The ad-serving engine at `app/services/ad_serving.py:119` reads `campaign.get("bid_cpm_cents", 500)` to rank candidates by CPM bid. For this to work, each campaign's DynamoDB item must store a `bid_cpm_cents` attribute. However, `CampaignCreateIn` (the input model for campaign creation) at `app/models.py:4296–4303` has no `bid_cpm_cents` field, and `create_campaign` in `app/services/ad_campaigns.py:35–61` never writes `bid_cpm_cents` to the DynamoDB item. Every campaign is therefore silently stored without this attribute, and the serving engine falls back to the hardcoded default of 500 for all campaigns. The auction cannot differentiate between a $50 CPM advertiser and a $1 CPM advertiser — all bids are treated equally.

- **Severity**: HIGH
- **Source ticket**: ADS-004
- **Status**: Open
- **Owning area**: Ads Platform / Campaign Management & Serving Engine
- **Effort**: S
- **Claim verdict**: CLAIM OK — confirmed. `app/models.py:4296–4303` — `CampaignCreateIn` — contains no `bid_cpm_cents` field. `app/models.py:4305–4319` — `CampaignOut` — also has no `bid_cpm_cents` field. `app/services/ad_campaigns.py:40–55` — `create_campaign` — builds the item dict with `budget_cents`, `budget_type`, `daily_budget_cents`, etc., but no `bid_cpm_cents`. The serving engine at `ad_serving.py:119` reads the attribute with a hardcoded default of 500, confirming the fallback path is always taken. Notably, `CampaignUpdateIn` at `app/models.py:4617–4623` *does* include `bid_cpm_cents: Optional[int] = None`, and `update_campaign` passes it through `UpdateExpression SET`, so an advertiser who creates a campaign and then immediately updates it can set a bid. But the creation path never captures the initial bid.

**One-line impact**: All campaigns are auctioned at an identical effective CPM of 500 cents ($5.00), making the auction purely a random selection among eligible campaigns; advertisers who are willing to pay more receive no preference, destroying monetisation revenue and auction fairness.

**Related tickets**: ADS-004 (source), GAP-0042 (serve_ad category filter interacts with CPM ranking), GAP-0043 (pagination fix must precede scale at which CPM differentiation matters), SECOPS-007 (dev/prod parity).

### create_campaign — missing attribute write

The item dict written to DynamoDB has no `bid_cpm_cents` key. When `serve_ad` later reads this item from DynamoDB (via `list_campaigns_by_status`), `campaign.get("bid_cpm_cents", 500)` always returns 500.

### Serving engine — hardcoded default

`app/services/ad_serving.py:118–120`:

```python
# Score: bid_cpm * relevance (mock relevance = 1.0)
bid_cpm = int(campaign.get("bid_cpm_cents", 500))
score = bid_cpm * 1.0
```

The comment "mock relevance = 1.0" signals this was left as a placeholder. The default of 500 is used for every campaign that lacks the attribute, making every campaign's score identically 500.0. The `candidates.sort(key=lambda c: c["score"], reverse=True)` at line 132 therefore produces a deterministic sort order based on creation order (the stable sort preserves the input order from `list_campaigns_by_status("active")`, which itself is `ScanIndexForward=False` on `created_at` — so the most recently created campaign always wins, regardless of bid).

## 3. Impact / Exploit / Blast Radius

**Auction unfairness**: A campaign bidding $50 CPM is treated identically to one bidding $0.01 CPM. The platform cannot monetise by running a real-time auction — it is effectively running a random lottery among eligible campaigns. High-budget advertisers receive no benefit from their higher bids.

**Revenue loss**: If the platform's business model depends on a CPM auction (higher bids win more impressions), the current code means the platform earns the floor rate on all impressions rather than the market rate. For 1M daily impressions at an average market CPM of $8.00 vs the default $5.00, the revenue gap is $3,000/day.

**Advertiser trust**: An advertiser who submits a $20 CPM bid via the update path (`PATCH /campaigns/{id}` — which does accept `bid_cpm_cents`) then creates a second campaign at $5 CPM will see both campaigns win the same share of auctions, even though the first is paying 4x more. If discovered, this is a platform integrity violation.

**Data integrity**: `CampaignOut` omits `bid_cpm_cents`, so advertisers cannot verify their bid via the API read path. This makes debugging and audit impossible.

**Blast radius**: Every advertiser who has created a campaign via the standard creation flow is affected. Only advertisers who have subsequently called `PATCH /campaigns/{id}` with `bid_cpm_cents` have a real bid stored. The creation form in the frontend (if it exists) never collects or submits a bid.

## 4. Fix Design (code-level)

### Step 1 — Add bid_cpm_cents to CampaignCreateIn and CampaignOut

In `app/models.py`, extend the campaign models:

```python
# Reasonable bid bounds (in cents):
# Floor: $0.50 CPM = 50 cents
# Ceiling: $200 CPM = 20000 cents
_BID_CPM_MIN = 50
_BID_CPM_MAX = 20_000
_BID_CPM_DEFAULT = 500  # $5.00 CPM default

class CampaignCreateIn(BaseModel):
    name: str = Field(..., min_length=1, max_length=200)
    objective: str = Field(..., pattern=r"^(awareness|traffic|conversions)$")
    budget_cents: int = Field(..., ge=100)
    budget_type: str = Field(..., pattern=r"^(daily|lifetime)$")
    start_date: Optional[int] = None
    end_date: Optional[int] = None
    bid_cpm_cents: int = Field(default=_BID_CPM_DEFAULT, ge=_BID_CPM_MIN, le=_BID_CPM_MAX)  # NEW

class CampaignOut(BaseModel):
    campaign_id: str
    account_id: str
    name: str
    objective: str
    budget_cents: int
    budget_type: str
    daily_budget_cents: int = 0
    spent_today_cents: int = 0
    lifetime_spent_cents: int = 0
    status: str
    start_date: Optional[int] = None
    end_date: Optional[int] = None
    created_at: int
    updated_at: int
    bid_cpm_cents: int = _BID_CPM_DEFAULT  # NEW — default for legacy items without the attribute
```

Also update `CampaignUpdateIn` to add bounds validation (it currently has none):

```python
class CampaignUpdateIn(BaseModel):
    name: Optional[str] = None
    objective: Optional[str] = None
    budget_cents: Optional[int] = None
    budget_type: Optional[str] = None
    status: Optional[str] = None
    bid_cpm_cents: Optional[int] = Field(default=None, ge=_BID_CPM_MIN, le=_BID_CPM_MAX)  # bounds added
```

### Step 2 — Write bid_cpm_cents in create_campaign

In `app/services/ad_campaigns.py`, add to the item dict in `create_campaign`:

```python
item = {
    ...
    "bid_cpm_cents": data.bid_cpm_cents,
    ...
}
```

The `data.bid_cpm_cents` field will carry the value from the request or the model default of 500 if not supplied. This preserves backward compatibility with API clients that do not supply a bid.

### Step 3 — Remove the hardcoded default from serve_ad

In `app/services/ad_serving.py:119`, the fallback default of 500 should remain as a last-resort guard for legacy items, but it is now an error path rather than the normal path:

```python
bid_cpm = int(campaign.get("bid_cpm_cents", 500))
if campaign.get("bid_cpm_cents") is None:
    logger.warning(
        "ad_serve_missing_bid_cpm campaign_id=%s; using default 500",
        campaign.get("campaign_id"),
    )
score = bid_cpm * 1.0
```

### Step 4 — Add bid estimation endpoint (optional, recommended)

Add `GET /ui/ads/accounts/{account_id}/campaigns/bid-estimate` that returns:

```json
{"min_bid_cpm_cents": 50, "suggested_bid_cpm_cents": 750, "max_bid_cpm_cents": 20000}
```

The suggested bid is the 75th percentile of active campaign `bid_cpm_cents` values. This helps advertisers set a competitive bid at creation time.

### Dev/Prod parity (SECOPS-007)

All changes are to model validation and DynamoDB item construction — no AWS-specific code path. DynamoDB Local handles the new attribute identically to production DynamoDB. No feature flag is needed; the default value of 500 ensures no regression for existing campaign items.

### Data migration

Existing campaigns in DynamoDB have no `bid_cpm_cents` attribute. Options:

1. **Lazy default**: `CampaignOut.bid_cpm_cents` defaults to 500; `serve_ad` already defaults to 500. No migration needed for correctness.
2. **Proactive back-fill**: A one-time DynamoDB scan + `update_item` script sets `bid_cpm_cents = 500` on all existing items. This makes the data clean for future analytics but is not required for correctness.

Recommended: deploy the code fix first (lazy default is safe), then run the back-fill script during the next maintenance window.

## 5. Testing, Verification & Rollout

### Regression test (pytest, offline — fails before fix, passes after)

Add to `tests/test_ad_campaigns.py`:

```python
def test_create_campaign_stores_bid_cpm_cents(ddb_mock):
    """create_campaign must persist bid_cpm_cents; default must be 500."""
    from app.services.ad_campaigns import create_campaign
    from app.models import CampaignCreateIn
    from app.core.tables import T

    data = CampaignCreateIn(
        name="Test Campaign",
        objective="awareness",
        budget_cents=5000,
        budget_type="lifetime",
    )
    item = create_campaign("acct_001", data)
    assert item.get("bid_cpm_cents") == 500  # default

    stored = T.ad_campaigns.get_item(
        Key={"pk": "ACCT#acct_001", "sk": f"CAMPAIGN#{item['campaign_id']}"}
    )["Item"]
    assert int(stored["bid_cpm_cents"]) == 500


def test_create_campaign_stores_custom_bid_cpm_cents(ddb_mock):
    """create_campaign must persist a non-default bid_cpm_cents."""
    from app.services.ad_campaigns import create_campaign
    from app.models import CampaignCreateIn
    from app.core.tables import T

    data = CampaignCreateIn(
        name="High Bid Campaign",
        objective="traffic",
        budget_cents=10000,
        budget_type="daily",
        bid_cpm_cents=1500,
    )
    item = create_campaign("acct_002", data)
    assert item.get("bid_cpm_cents") == 1500

    stored = T.ad_campaigns.get_item(
        Key={"pk": "ACCT#acct_002", "sk": f"CAMPAIGN#{item['campaign_id']}"}
    )["Item"]
    assert int(stored["bid_cpm_cents"]) == 1500


def test_serve_ad_ranks_by_bid_cpm(ddb_mock, seed_active_campaign):
    """serve_ad must select the highest-bid campaign from the eligible set."""
    seed_active_campaign(campaign_id="camp_low_01", bid_cpm_cents=200)
    seed_active_campaign(campaign_id="camp_high_01", bid_cpm_cents=1500)
    seed_active_campaign(campaign_id="camp_mid_01", bid_cpm_cents=800)

    from app.services.ad_serving import serve_ad
    # Run 10 serves; the highest-bid campaign must win all of them
    # (mock relevance = 1.0, so score = bid_cpm * 1.0, deterministic winner)
    winners = set()
    for _ in range(10):
        result = serve_ad(
            surface="feed",
            content_type="post",
            creator_id="creator_rank_test",
            content_id="post_rank_test",
            slot_type="in_feed",
            user_id="user_rank_test",
        )
        winners.add(result.get("campaign_id"))

    assert winners == {"camp_high_01"}, f"Expected high-bid campaign to win all auctions, got {winners}"
```

**Fails before fix**: `test_create_campaign_stores_bid_cpm_cents` passes (the default fallback happens to be 500) but `test_create_campaign_stores_custom_bid_cpm_cents` fails because `CampaignCreateIn` rejects `bid_cpm_cents` as an unexpected field. `test_serve_ad_ranks_by_bid_cpm` fails because all three seeded campaigns have `bid_cpm_cents=500` (the fallback) and the winner is the first campaign in the GSI result, not the highest-bid one.

**Passes after fix**: `CampaignCreateIn` accepts `bid_cpm_cents`, `create_campaign` persists it, and `serve_ad` reads the real value from DynamoDB. The highest-bid campaign wins every auction.

### Rollout

- **Effort**: S (< 1 day including tests).
- **Risk**: Low. The model default of 500 ensures no regression for existing campaigns or API clients that omit `bid_cpm_cents`. The `CampaignOut` default of 500 means read responses for legacy items are indistinguishable from newly-created campaigns with the default bid.
- **Sequencing**: Deploy before enabling any advertiser-facing bid transparency or auction analytics. Must be deployed before GAP-0042's `min_cpm_cents` floor check, since the floor check reads `campaign["bid_cpm_cents"]`.
- **Rollback**: Remove `bid_cpm_cents` from `CampaignCreateIn`, `CampaignOut`, and `create_campaign`. Existing items with the attribute are harmless — DynamoDB ignores extra attributes when Pydantic models omit them.
