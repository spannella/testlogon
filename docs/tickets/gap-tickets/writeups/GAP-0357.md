# GAP-0357: Overlap with FEED-009 (Post Bookmarks): Same Feature, Separate Tickets — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code. Source ticket: SOCIAL-001.

## 1. Summary & Classification

**Plain-English statement**: SOCIAL-001 ("User Collections / Saved Posts") and FEED-009 ("Post
Bookmarks") describe the same backend subsystem and the same frontend page. The bookmark and
collections feature is implemented in `app/routers/newsfeed.py:6277–6560` and
`frontend/src/pages/saved/SavedPage.tsx`. Both tickets catalogue overlapping gaps against the
same code. GAP-0357 is a **meta-gap**: it flags that the SOCIAL-001 gap report itself
duplicates FEED-009, and that all implementation deficiencies catalogued in
`docs/tickets/gaps/FEED-009.md` apply equally to SOCIAL-001. This write-up treats GAP-0357 as
a unified remediation ticket covering all bookmark/collections gaps under one plan, rather
than tracking them in two separate queues.

**Claim verdict**: CONFIRMED. Code search shows that:
- All bookmark endpoints (`/ui/bookmarks`, `/ui/bookmark-collections`) live in
  `newsfeed.py:6277–6560`.
- The only frontend consumer is `frontend/src/pages/saved/SavedPage.tsx` (imported via
  `BookmarkButton` in PostCard).
- `docs/tickets/gaps/FEED-009.md` and `docs/tickets/gaps/SOCIAL-001.md` list overlapping
  deficiencies against this identical code surface.

- **Severity**: HIGH (composite — aggregated from the sub-gaps, the highest of which are
  user-facing data integrity issues)
- **Source ticket**: SOCIAL-001 / FEED-009
- **Status**: Open (both tickets)
- **Owning area**: Newsfeed / Saved Posts
- **Related tickets**: FEED-009 (primary), GAP-0356, GAP-0358
- **Dependencies**: None blocking; all sub-gaps are independent.

## 2. Current-State Investigation (root cause)

### 2.1 Bookmark/collections code surface

The entire server-side bookmark feature lives in `app/routers/newsfeed.py`. Key endpoints:

| Endpoint | Line | Notes |
|---|---|---|
| `POST /ui/bookmarks` | 6299 | Create bookmark; validates content exists |
| `DELETE /ui/bookmarks/{ct}/{id}` | 6354 | Delete bookmark; does NOT decrement collection counter |
| `GET /ui/bookmarks` | 6370 | List bookmarks with enriched previews |
| `GET /ui/bookmarks/status` | 6440 | Bulk is-bookmarked check (up to 25 IDs) |
| `POST /ui/bookmark-collections` | 6474 | Create collection |
| `GET /ui/bookmark-collections` | — | List collections |
| `PATCH /ui/bookmark-collections/{id}` | — | Rename collection |
| `DELETE /ui/bookmark-collections/{id}` | 6540 | Dissolve collection (moves bookmarks to default) |

Frontend: `frontend/src/pages/saved/SavedPage.tsx` renders saved posts and videos.
`frontend/src/components/shared/BookmarkButton.tsx` provides the toggle UI for posts.

### 2.2 Sub-gap 1: `is_bookmarked` missing from feed/post responses

`_post_to_dict` (`newsfeed.py:~2180`) does not include an `is_bookmarked` field.
`GET /feed` never queries `BOOKMARK_LOOKUP#{user_id}` to annotate posts. The frontend
`PostCard.tsx` derives bookmark state from optimistic local state only — this means a hard
refresh loses the visual indicator for already-bookmarked posts.

The DDB lookup item is stored as:
```
pk=BOOKMARK_LOOKUP#{user_id}  sk={content_type}#{content_id}
```
A `begins_with(sk, "post#")` query before the post list is assembled would produce a set
of bookmarked post IDs that can be passed into `_post_to_dict` as an optional parameter.

### 2.3 Sub-gap 2: Move-bookmark-between-collections endpoint absent

`app/routers/newsfeed.py` has no `PATCH /ui/bookmarks/{ct}/{id}` endpoint. Once a bookmark
is created in collection A, there is no API call that reassigns it to collection B without
deleting and re-creating it. The ticket design (SOCIAL-001 US-6) required this.

The DDB bookmark item stores `collection_id` as a top-level attribute (written at
`newsfeed.py:6321`). Moving requires updating the bookmark item, the lookup item, and
adjusting `bookmark_count` on both old and new collection items.

### 2.4 Sub-gap 3: Video bookmark enrichment returns empty object

`list_bookmarks` (`newsfeed.py:6403–6434`) has enrichment logic inside a `if ct == "post"`
block with no `elif ct == "video"` branch. Bookmarked videos produce
`content_preview: {}` in the API response. `SavedPage.tsx` shows "[No content]" for such
items.

Verified: `newsfeed.py:6416`: `"author_display_name": post_dict.get("author_id", "")` also
incorrectly copies the UUID instead of a human-readable display name for post previews.

### 2.5 Sub-gap 4: `bookmark_count` not decremented on bookmark delete

`delete_bookmark` (`newsfeed.py:6354–6368`) calls `ddb_delete_item` for the bookmark and
lookup items but never issues an `ADD bookmark_count :-1` on the collection item. Over time,
collection badge counts become stale and show inflated totals.

### 2.6 Sub-gap 5: Collection sidebar missing from SavedPage

`SavedPage.tsx` renders a content-type tab (`post` / `video`) but no collection selector.
`GET /ui/bookmark-collections` is never called from the page. The `collection_id` query
parameter on `GET /ui/bookmarks` is therefore never used from the UI. The SOCIAL-001
ticket US-3 required a browsable collection sidebar.

### 2.7 Sub-gap 6: Video bookmark button missing from video cards

`BookmarkButton` is integrated into `PostCard.tsx` but not into any video card component.
Users viewing the video gallery or the video detail page have no way to bookmark a video,
even though the backend accepts `content_type="video"` bookmark creates.

## 3. Impact / Exploit / Blast Radius

None of these gaps are security issues. All are user-experience and data-integrity defects.

**Sub-gap 1 (is_bookmarked)**: Users who refresh their feed see all bookmark icons reset to
unfilled, creating a confusing UX on every page load.

**Sub-gap 2 (move bookmark)**: Users cannot reorganize bookmarks without delete-and-recreate.
The API design is internally consistent (data is not corrupted) but the UX requirement from
the ticket is unmet.

**Sub-gap 3 (video enrichment)**: Every bookmarked video produces an empty content preview.
The SavedPage is visually broken for video bookmarks.

**Sub-gap 4 (bookmark_count)**: Collection badge counts are monotonically increasing and
never go down. A collection that once had 50 bookmarks all of which were deleted still shows
"50 bookmarks".

**Sub-gap 5 (collection sidebar)**: Collections are createable via API but invisible and
non-navigable in the UI. The feature is delivered at ~50% of its specified functionality.

**Sub-gap 6 (video bookmark button)**: Video content cannot be bookmarked from any current
UI surface (only via direct API call).

Collectively, the Saved/Collections feature is shipped but not user-complete, breaking two
of SOCIAL-001's primary user stories (US-2, US-3, US-6).

## 4. Fix Design (code-level)

### 4.1 Sub-gap 1 — inject `is_bookmarked` into feed responses

In the `GET /feed` aggregation path, add a bookmark set query before looping over posts:

```python
# Fetch bookmarked post IDs for the viewer (up to 500)
_bookmarked_ids: set[str] = set()
try:
    bk_resp = T.newsfeed.query(
        KeyConditionExpression=Key("pk").eq(f"BOOKMARK_LOOKUP#{user_id}")
            & Key("sk").begins_with("post#"),
        ProjectionExpression="sk",
        Limit=500,
    )
    for bk_item in bk_resp.get("Items", []):
        cid = bk_item["sk"].removeprefix("post#")
        _bookmarked_ids.add(cid)
except Exception:
    pass
```

Then in `_post_to_dict`, accept an optional `bookmarked_ids: set[str] | None = None`
parameter and emit `"is_bookmarked": post_id in (bookmarked_ids or set())`.

### 4.2 Sub-gap 2 — move-bookmark endpoint

```python
@router.patch("/ui/bookmarks/{content_type}/{content_id}")
def move_bookmark(content_type: str, content_id: str,
                  req: MoveBookmarkRequest, user_id: UserIdDep):
    # 1. Fetch existing bookmark to get old collection_id
    # 2. Update bookmark item SET collection_id = :new_coll
    # 3. Update lookup item SET collection_id = :new_coll
    # 4. ADD bookmark_count :-1 on old collection item
    # 5. ADD bookmark_count :1 on new collection item
    ...
```

`MoveBookmarkRequest` needs only `collection_id: str`.

### 4.3 Sub-gap 3 — video enrichment in `list_bookmarks`

Add an `elif ct == "video"` branch in `list_bookmarks` that fetches the video record from
`T.video_metadata` and returns `title`, `thumbnail_url`, `creator_id`, `view_count`.
Fix the display-name bug at line 6416: replace
`"author_display_name": post_dict.get("author_id", "")`
with `"author_display_name": _post_fadt_display_name(post_dict.get("author_id", ""))`.

### 4.4 Sub-gap 4 — decrement `bookmark_count` on delete

In `delete_bookmark` (`newsfeed.py:6354`), after the two `ddb_delete_item` calls, add:

```python
if old_collection_id:
    try:
        ddb_update_item(
            key={"pk": pk_bmcol(user_id), "sk": f"COL#{old_collection_id}"},
            update_expr="ADD bookmark_count :neg",
            expr_vals={":neg": -1},
        )
    except Exception:
        logger.warning("Failed to decrement bookmark_count for collection %s", old_collection_id)
```

`old_collection_id` is available from the existing bookmark item fetched at the top of
`delete_bookmark`.

### 4.5 Sub-gap 5 — collection sidebar in SavedPage

```ts
// SavedPage.tsx
const collectionsQ = useQuery({
  queryKey: ["bookmark-collections"],
  queryFn: () => getBookmarkCollections(),
});
```

Render a left-side `<aside>` listing each collection with its `bookmark_count`. Pass the
selected `collection_id` as a state variable to the `getBookmarks` query call.

### 4.6 Sub-gap 6 — video bookmark button

Import `BookmarkButton` in `VideoCard.tsx` and the video detail page, passing
`contentType="video"` and `contentId={video.video_id}`.

### 4.7 Dev/Prod parity (SECOPS-007)

All bookmark endpoints use DynamoDB Local in dev. No S3 or Cognito involvement. The fix
touches no AWS-backed paths that differ between dev and prod. No feature flags needed
beyond the existing `bookmarks_max_collections` setting already in `S`.

## 5. Testing, Verification & Rollout

### 5.1 Pytest regression tests (offline)

```python
# tests/test_bookmark_gaps.py

def test_is_bookmarked_in_feed_response(client, alice_session, alice_post_id):
    """GAP-0357 sub-gap 1: is_bookmarked must be True for a bookmarked post in the feed."""
    client.post("/ui/bookmarks", json={"content_type": "post", "content_id": alice_post_id},
                headers=alice_session)
    resp = client.get("/ui/feed", headers=alice_session)
    posts = resp.json()["posts"]
    target = next((p for p in posts if p["post_id"] == alice_post_id), None)
    assert target is not None
    assert target.get("is_bookmarked") is True  # fails before fix

def test_bookmark_count_decremented_on_delete(client, alice_session, alice_post_id):
    """GAP-0357 sub-gap 4: bookmark_count must go down when a bookmark is deleted."""
    client.post("/ui/bookmarks", json={"content_type": "post", "content_id": alice_post_id},
                headers=alice_session)
    colls_before = client.get("/ui/bookmark-collections", headers=alice_session).json()
    count_before = colls_before["collections"][0]["bookmark_count"]

    client.delete(f"/ui/bookmarks/post/{alice_post_id}", headers=alice_session)
    colls_after = client.get("/ui/bookmark-collections", headers=alice_session).json()
    count_after = colls_after["collections"][0]["bookmark_count"]

    assert count_after == count_before - 1  # fails before fix

def test_move_bookmark_changes_collection(client, alice_session, alice_post_id, coll_a, coll_b):
    """GAP-0357 sub-gap 2: PATCH /ui/bookmarks must change the bookmark's collection."""
    client.post("/ui/bookmarks",
                json={"content_type": "post", "content_id": alice_post_id, "collection_id": coll_a},
                headers=alice_session)
    resp = client.patch(f"/ui/bookmarks/post/{alice_post_id}",
                        json={"collection_id": coll_b}, headers=alice_session)
    assert resp.status_code == 200  # 404 before fix
    saved = client.get("/ui/bookmarks", params={"collection_id": coll_b}, headers=alice_session).json()
    assert any(b["content_id"] == alice_post_id for b in saved["bookmarks"])

def test_video_bookmark_preview_not_empty(client, alice_session, alice_video_id):
    """GAP-0357 sub-gap 3: bookmarked video must return non-empty content_preview."""
    client.post("/ui/bookmarks",
                json={"content_type": "video", "content_id": alice_video_id},
                headers=alice_session)
    resp = client.get("/ui/bookmarks", headers=alice_session)
    vid_bk = next((b for b in resp.json()["bookmarks"] if b["content_type"] == "video"), None)
    assert vid_bk is not None
    assert vid_bk["content_preview"].get("title")  # empty dict before fix
```
