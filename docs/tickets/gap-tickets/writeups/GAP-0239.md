# GAP-0239: "Connect Google Drive" UI section absent from `FilesPage.tsx` — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No prior
> investigation doc exists for this ticket.

## 1. Summary & Classification

**Bug**: The Files page (`frontend/src/pages/files/FilesPage.tsx`) implements a full iCloud
Connect wizard and mount management panel but has no equivalent section for Google Drive. The
backend exposes a complete Google Drive OAuth + browse + import API at
`/ui/integrations/google-drive/*` (`app/routers/filemanager.py`). The frontend Google Drive
API client exists at `frontend/src/api/endpoints/googleDrive.ts`. The picker dialog component
`GoogleDrivePickerDialog` exists at
`frontend/src/components/shared/GoogleDrivePickerDialog.tsx`. None of these are imported by
`FilesPage.tsx`. No "Connect Google Drive" button, connection status badge, or Disconnect
button exists in the page.

**Severity**: HIGH. The Google Drive integration (INTEG-001) is entirely unreachable for end
users. All backend work and the picker dialog component are dead code from a UI perspective.

**Source ticket**: INTEG-001. No prior investigation document.

**Owning area**: `frontend/src/pages/files/FilesPage.tsx`, `frontend/src/api/endpoints/googleDrive.ts`.

**Claim verdict**: Confirmed. A search of `FilesPage.tsx` for `GoogleDrive`, `google-drive`,
`drivePickerOpen`, or `HardDrive` (the icon used in the dialog title) finds only the bare
`HardDrive` import from `lucide-react` — imported but not rendered anywhere in the file. No
Google Drive state variables, queries, or JSX blocks exist.

**Related tickets**: GAP-0240 (`GoogleDrivePickerDialog` unused — this and that ticket are
two facets of the same root gap; GAP-0240 is the component-wiring half).

## 2. Current-State Investigation (root cause)

### 2.1 What exists in the backend

`app/routers/filemanager.py` registers Google Drive integration endpoints under
`/ui/integrations/google-drive/*`:
- `GET /status` — OAuth connection status, email, scopes
- `GET /connect` — initiates OAuth flow, returns `auth_url`
- `POST /callback` — completes OAuth, stores tokens
- `POST /disconnect` — revokes and removes tokens
- `GET /files` — browses Google Drive folder contents
- `POST /import` — imports a Drive file into the user's file store

The backend is gated by `S.filemgr_google_drive_mounts_enabled` (checked at lines 257-264)
and has a dev-mode mock path that returns realistic stub data.

### 2.2 What exists in the frontend

**API client** — `frontend/src/api/endpoints/googleDrive.ts` exports:
- `getGoogleDriveStatus()` → `DriveStatusResp { connected, email, scopes, connected_at }`
- `initiateGoogleDriveConnect()` → `{ auth_url, mock? }`
- `completeGoogleDriveConnect(code, redirectUri, state)` → `{ ok, connected }`
- `disconnectGoogleDrive()` → `{ ok }`
- `browseGoogleDriveFiles(params)` → `DriveFilesResp`
- `importDriveFile(fileId, destinationPath)` → `DriveImportResp`

**Picker dialog** — `frontend/src/components/shared/GoogleDrivePickerDialog.tsx` (352 lines):
A fully functional dialog with breadcrumb navigation, search, multi-select file checkboxes,
and an Import button. Props: `open`, `onOpenChange`, `onImportComplete`, `currentPath`.

**FilesPage imports** — `frontend/src/pages/files/FilesPage.tsx:15` imports `HardDrive` from
`lucide-react`. This icon is referenced nowhere in the JSX (confirmed by searching the entire
1571-line file). The import was presumably added in anticipation of the Google Drive section.

### 2.3 What is missing

`FilesPage.tsx` lacks:
1. Imports for `getGoogleDriveStatus`, `initiateGoogleDriveConnect`, `disconnectGoogleDrive`
   from `@/api/endpoints/googleDrive`.
2. Import for `GoogleDrivePickerDialog` from `@/components/shared/GoogleDrivePickerDialog`.
3. State variables: `drivePickerOpen`, `driveConnectBusy`, `driveConnectError`.
4. A `useQuery` call for `getGoogleDriveStatus()` to show connection badge.
5. A `useMutation` for `disconnectGoogleDrive()`.
6. A "Connect Google Drive" button in the toolbar (parallel to the existing "Connect iCloud"
   button at line 1040).
7. A connection status section in the mount management panel or a dedicated Google Drive
   panel beneath it.
8. The `<GoogleDrivePickerDialog>` rendered at the bottom of the page with `drivePickerOpen`
   controlled by a Browse button.
9. An OAuth callback handler (redirect from Google after authorization — can be a separate
   lightweight route `/files?drive_callback=1` or handled via a shared `OAuthCallbackPage`).

## 3. Impact / Exploit / Blast Radius

**User impact**: The Google Drive integration is completely inaccessible via the UI. Users who
were told about the feature (via docs, marketing, or changelog) see no Connect button.

**Dead code risk**: Over time the `GoogleDrivePickerDialog` component, the API client, and
the backend endpoints will drift out of sync with the actual product because there are no
real consumers exercising the integration path. E2E test `drive-picker.spec.ts:201` already
works around the missing wiring with a conditional `if (visible)` guard that silently skips
the UI test if the button does not exist.

**Security surface**: The backend OAuth endpoints exist and are callable. There is no security
exposure from the missing UI — the endpoint requires valid session auth — but an unadvertised
connected endpoint is harder to audit.

**Financial**: Any operator-facing pricing that includes Google Drive integration is broken
for end-to-end demos and trials.

## 4. Fix Design (code-level)

### 4.1 Add Google Drive connection state and query to `FilesPage.tsx`

At the top of the state block (after line 231, alongside existing dialog state):

```typescript
// Google Drive integration state
const [drivePickerOpen, setDrivePickerOpen] = React.useState(false);
const [driveConnectBusy, setDriveConnectBusy] = React.useState(false);
const [driveConnectError, setDriveConnectError] = React.useState<string | null>(null);
```

Add a `useQuery` for drive connection status (alongside `mountsQuery` at line 258):

```typescript
const driveStatusQuery = useQuery({
  queryKey: ["google-drive-status"],
  queryFn: () => getGoogleDriveStatus().then((r) => r.data),
  staleTime: 60_000,
});
const driveConnected = driveStatusQuery.data?.connected ?? false;
const driveEmail = driveStatusQuery.data?.email;
```

Add a `useMutation` for disconnect:

```typescript
const driveDisconnectMut = useMutation({
  mutationFn: () => disconnectGoogleDrive().then((r) => r.data),
  onSuccess: () => {
    toast.success("Google Drive disconnected.");
    queryClient.invalidateQueries({ queryKey: ["google-drive-status"] });
  },
  onError: () => toast.error("Failed to disconnect Google Drive."),
});
```

### 4.3 Google Drive connect handler

```typescript
const handleGoogleDriveConnect = async () => {
  if (driveConnected) {
    setDrivePickerOpen(true);
    return;
  }
  setDriveConnectBusy(true);
  setDriveConnectError(null);
  try {
    const res = await initiateGoogleDriveConnect().then((r) => r.data);
    if (res.mock) {
      // Dev mode: backend completes OAuth automatically; just refetch status.
      await queryClient.invalidateQueries({ queryKey: ["google-drive-status"] });
      setDrivePickerOpen(true);
    } else {
      // Production: redirect to Google OAuth.
      window.location.href = res.auth_url;
    }
  } catch {
    setDriveConnectError("Failed to start Google Drive connection. Try again.");
    toast.error("Failed to initiate Google Drive connection.");
  } finally {
    setDriveConnectBusy(false);
  }
};
```

### 4.4 Connection status in the mount management panel

Add a Google Drive section inside the "Connected mounts" panel (after line 1173, below iCloud
mounts):

```tsx
<div className="mt-3 rounded-md border p-2 text-xs" data-testid="google-drive-status-panel">
  <div className="flex flex-wrap items-center gap-2">
    <HardDrive className="h-3.5 w-3.5" />
    <span className="font-medium">Google Drive</span>
    {driveConnected ? (
      <>
        <Badge variant="default" data-testid="google-drive-connected-badge">connected</Badge>
        {driveEmail && <span className="text-muted-foreground">{driveEmail}</span>}
        <Button
          size="sm"
          variant="outline"
          onClick={() => setDrivePickerOpen(true)}
          data-testid="google-drive-browse-button"
        >
          Browse
        </Button>
        <Button
          size="sm"
          variant="destructive"
          onClick={() => driveDisconnectMut.mutate()}
          disabled={driveDisconnectMut.isPending}
          data-testid="google-drive-disconnect-button"
        >
          Disconnect
        </Button>
      </>
    ) : (
      <Badge variant="outline" data-testid="google-drive-disconnected-badge">not connected</Badge>
    )}
    {driveConnectError && (
      <p className="w-full text-red-600">{driveConnectError}</p>
    )}
  </div>
</div>
```

### 4.7 OAuth callback handling (production path)

In production, Google redirects to a callback URL (e.g., `/files?code=...&state=...`). Add a
`useEffect` in `FilesPage.tsx` that detects these query params, calls
`completeGoogleDriveConnect`, and redirects back to `/files`:

```typescript
React.useEffect(() => {
  const params = new URLSearchParams(window.location.search);
  const code = params.get("code");
  const state = params.get("state");
  if (code) {
    completeGoogleDriveConnect(code, window.location.origin + "/files", state || undefined)
      .then(() => {
        queryClient.invalidateQueries({ queryKey: ["google-drive-status"] });
        window.history.replaceState({}, "", "/files");
        setDrivePickerOpen(true);
      })
      .catch(() => toast.error("Google Drive authorization failed."));
  }
}, []);  // eslint-disable-line react-hooks/exhaustive-deps
```

### 4.8 Dev/Prod parity (SECOPS-007)

The backend mock path (`S.dev_mode=True`) for `GET /ui/integrations/google-drive/connect`
returns `{ auth_url: "...", mock: true }` and auto-completes the connection when the frontend
calls `initiateGoogleDriveConnect`. The `handleGoogleDriveConnect` handler above checks
`res.mock` and skips the `window.location.href` redirect in dev mode — same code path, flag-
selected behaviour. No separate dev-only code block is required.
