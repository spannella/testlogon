# GAP-0198: AffiliateDashboard.tsx Is Still the 204-Line Stub — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; claim partially corrected: the file is 204 lines (confirmed), but "stub" requires clarification — it IS a functional link manager, not a skeleton placeholder.

## 1. Summary & Classification

**Plain-English statement**: `frontend/src/pages/affiliates/AffiliateDashboard.tsx` is a 204-line component that renders only the affiliate links CRUD list (create, copy, revoke). The FIN-010 specification called for a full analytics dashboard with a tabbed layout: an "Analytics" tab showing summary stats cards and a click time-series chart, an "Earnings" tab showing a per-product commission breakdown, and a "Top Products" tab. None of these tabs or their data-fetching hooks exist. Correspondingly, `frontend/src/api/endpoints/affiliates.ts` contains no wrappers for the four analytics endpoints described in GAP-0197.

**Claim correction**: The ticket calls the component a "204-line stub." This is slightly inaccurate: the 204-line component is a fully working link manager (create/list/revoke/copy), not an empty skeleton. The gap is that the analytics tabs are absent, not that the component is a stub that does nothing.

- **Severity**: HIGH
- **Source ticket**: FIN-010
- **Status**: Open — link management present; analytics absent
- **Owning area**: Affiliate / Creator monetisation frontend
- **Verdict**: Confirmed (with correction above). The component at line 35–204 renders a single `<Card>` with a link list and a create dialog. No `<Tabs>` import, no chart component, no summary cards, no calls to non-existent analytics endpoints.
- **Impact**: Creators visiting the Affiliates page see only a link list with click/conversion counter badges per row. There is no time-series view, no earnings breakdown, and no cross-link aggregate — the analytics promise of the feature is invisible.
- **Related tickets**: FIN-010 (parent), GAP-0197 (backend dependency — must be resolved first), SECOPS-007

- No export for `getAffiliateSummary`, `getLinkClickTimeSeries`, `getAffiliateEarnings`, or `getTopProducts`.
- No TypeScript interfaces for `AffiliateSummaryOut`, `AffiliateClickTimeSeriesOut`, `AffiliateEarningsBreakdownOut`, `AffiliateTopProductsOut`.

`frontend/src/api/types.ts`:
- No affiliate analytics types (confirmed by searching for `AffiliateSummary`, `AffiliateEarnings`, `AffiliateTimeSeries`, `AffiliateTopProduct` — zero matches).

### Root cause

GAP-0197 documents that the backend analytics endpoints were never built. The frontend gap is a direct consequence: there were no API endpoints to call, so the frontend was never extended beyond the basic CRUD. The component name `AffiliateDashboard` implies the full analytics experience but the implementation stopped at the link manager phase.

The component is not broken — it renders correctly for its implemented scope. The gap is purely one of missing tabs and missing API wrappers.

## 3. Impact / Exploit / Blast Radius

- **Creator experience**: Creators have no programmatic way to see aggregate performance data through the UI. They must call the backend stats endpoint per-link manually, or wait for GAP-0197 to be fixed and a UI layer added.
- **Revenue / engagement**: Affiliate marketing programs live or die on analytics visibility. Without trends, creators cannot optimise their promotional content. Expected result: low affiliate link creation rates and high churn from the feature.
- **Dependency risk**: This gap cannot be closed independently — GAP-0197 must ship the four backend analytics endpoints first. The frontend work is blocked.
- **Security**: None. The fix is purely additive and only queries the authenticated user's own data.
- **Blast radius**: Contained to the `/affiliates` page.

## 4. Fix Design (code-level)

### 4a. Frontend API wrappers and types (`frontend/src/api/endpoints/affiliates.ts`)

Add four new wrappers corresponding to the four GAP-0197 endpoints:

```ts
// New analytics types
export interface AffiliateSummaryOut {
  total_links: number;
  active_links: number;
  total_clicks: number;
  unique_clicks: number;
  total_conversions: number;
  total_revenue_cents: number;
  total_commission_cents: number;
  overall_conversion_rate_pct: number;
}

export interface AffiliateClickBucket {
  bucket: string;   // epoch-seconds string (day) or "YYYY-WWW" (week)
  clicks: number;
}

export interface AffiliateClickTimeSeriesOut {
  items: AffiliateClickBucket[];
  interval: string;
}

export interface AffiliateEarningsItem {
  link_id: string;
  target_name: string;
  target_type: string;
  commission_earned_cents: number;
  revenue_cents: number;
  conversions: number;
}

export interface AffiliateEarningsBreakdownOut {
  items: AffiliateEarningsItem[];
  total_commission_cents: number;
}

export interface AffiliateTopProductItem {
  link_id: string;
  target_name: string;
  target_id: string;
  click_count: number;
  conversion_count: number;
  commission_earned_cents: number;
}

export interface AffiliateTopProductsOut {
  items: AffiliateTopProductItem[];
}

// New API wrappers
export const getAffiliateSummary = () =>
  api.get<AffiliateSummaryOut>("/ui/affiliates/summary");

export const getLinkClickTimeSeries = (params?: {
  interval?: "day" | "week";
  from_ts?: number;
  to_ts?: number;
}) => {
  const p: Record<string, string> = {};
  if (params?.interval) p.interval = params.interval;
  if (params?.from_ts) p.from_ts = String(params.from_ts);
  if (params?.to_ts) p.to_ts = String(params.to_ts);
  return api.get<AffiliateClickTimeSeriesOut>("/ui/affiliates/timeseries", p);
};

export const getAffiliateEarnings = (params?: {
  from_ts?: number;
  to_ts?: number;
}) => {
  const p: Record<string, string> = {};
  if (params?.from_ts) p.from_ts = String(params.from_ts);
  if (params?.to_ts) p.to_ts = String(params.to_ts);
  return api.get<AffiliateEarningsBreakdownOut>("/ui/affiliates/earnings", p);
};

export const getTopProducts = (limit = 10) =>
  api.get<AffiliateTopProductsOut>(`/ui/affiliates/top-products`, { limit: String(limit) });
```

### 4b. AffiliateDashboard rewrite (full tabbed layout)

The component needs to be rewritten to introduce four tabs. The existing link-list code moves verbatim into the "Links" tab to preserve the working functionality:

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@/components/ui/tabs";
import {
  getAffiliateSummary, getLinkClickTimeSeries,
  getAffiliateEarnings, getTopProducts,
} from "@/api/endpoints/affiliates";

export default function AffiliateDashboard() {
  const qc = useQueryClient();
  // ... existing create/delete state ...
  const [interval, setInterval] = useState<"day" | "week">("day");

  // Existing query
  const linksQ = useQuery({ queryKey: ["affiliate-links"], queryFn: listAffiliateLinks });

  // New analytics queries
  const summaryQ = useQuery({
    queryKey: ["affiliate-summary"],
    queryFn: getAffiliateSummary,
    staleTime: 60_000,
  });
  const timeseriesQ = useQuery({
    queryKey: ["affiliate-timeseries", interval],
    queryFn: () => getLinkClickTimeSeries({ interval }),
    staleTime: 60_000,
  });
  const earningsQ = useQuery({
    queryKey: ["affiliate-earnings"],
    queryFn: () => getAffiliateEarnings(),
    staleTime: 60_000,
  });
  const topProductsQ = useQuery({
    queryKey: ["affiliate-top-products"],
    queryFn: () => getTopProducts(10),
    staleTime: 60_000,
  });

  return (
    <div className="space-y-6">
      <Tabs defaultValue="links">
        <TabsList>
          <TabsTrigger value="links">Links</TabsTrigger>
          <TabsTrigger value="analytics">Analytics</TabsTrigger>
          <TabsTrigger value="earnings">Earnings</TabsTrigger>
          <TabsTrigger value="top-products">Top Products</TabsTrigger>
        </TabsList>

        {/* "Links" tab — existing component code, unchanged */}
        <TabsContent value="links">
          <AffiliateLinkList ... />
        </TabsContent>

        {/* "Analytics" tab — summary cards + time-series bar chart */}
        <TabsContent value="analytics">
          <SummaryCards data={summaryQ.data} loading={summaryQ.isLoading} />
          <ClickTimeSeriesChart
            data={timeseriesQ.data?.items ?? []}
            loading={timeseriesQ.isLoading}
            interval={interval}
            onIntervalChange={setInterval}
          />
        </TabsContent>

        {/* "Earnings" tab — per-link earnings table */}
        <TabsContent value="earnings">
          <EarningsBreakdownTable
            data={earningsQ.data}
            loading={earningsQ.isLoading}
          />
        </TabsContent>

        {/* "Top Products" tab — ranked product table */}
        <TabsContent value="top-products">
          <TopProductsTable
            data={topProductsQ.data?.items ?? []}
            loading={topProductsQ.isLoading}
          />
        </TabsContent>
      </Tabs>
    </div>
  );
}
```

**Sub-component notes**:
- `SummaryCards`: six stat cards (total links, total clicks, unique clicks, conversions, revenue, commission) using the existing `formatCents` helper pattern from `PayoutDashboard.tsx`.
- `ClickTimeSeriesChart`: bar chart using shadcn's `recharts`-based chart primitive (or a simple CSS-bar fallback with `div` bars width-proportioned to `max(clicks)` if recharts is not yet in the bundle). Includes a Day/Week toggle.
- `EarningsBreakdownTable`: sortable table with columns: Product, Type, Conversions, Revenue, Commission, Commission%. Highlights the top earner row.
- `TopProductsTable`: rank, product name, clicks, conversions, earned — sorted by clicks descending server-side.

### 4c. Dev/Prod parity (SECOPS-007)

All four new API calls go to `/ui/affiliates/...` which requires `require_ui_session` on the backend — the same cookie-based auth path used by all other `/ui/` endpoints. The Vite dev proxy forwards these to `localhost:8000` without any additional configuration. No environment-specific code paths, no feature flags.

### 4d. Alternatives considered

- **Separate `/affiliates/analytics` route**: cleaner code splitting but breaks the single-page mental model of the dashboard.
- **Recharts vs CSS bars for time-series**: recharts is already in the `package.json` (used by other chart components) so it is available at no bundle cost.

### Sequencing / Rollout

**Effort**: M (3 days for the frontend rewrite after GAP-0197 backend ships).

**Hard dependency**: GAP-0197 must be deployed first. Until the backend analytics endpoints exist, stub the four analytics queries with `enabled: !!import.meta.env.VITE_AFFILIATE_ANALYTICS` (a build-time flag) or simply `enabled: false` in the `useQuery` options. This prevents 404 noise in the browser console and ensures the Links tab continues to work during the rollout window.

**Progressive disclosure**: The tab headers ("Analytics", "Earnings", "Top Products") can be rendered immediately on deploy. If the backend returns an error, each tab shows a skeleton loader with an inline "Analytics coming soon" message. This avoids a broken experience during the rollout window and communicates forward intent to creators.

**Rollback**: Revert `AffiliateDashboard.tsx` and `affiliates.ts` to the previous versions; no DynamoDB changes needed for this frontend-only work.

**Risk**: Low — the Links tab content is preserved verbatim; only additive tabs are new. The recharts bundle-size impact should be verified with `vite build --report` before deployment. If the chart bundle adds more than 30 KB gzip, use the CSS-bar fallback described in section 4b for the initial release.

### Observability and loading states

Each new tab should implement React Query's `isLoading` and `isError` states explicitly:
- **`isLoading`**: show a `<Skeleton>` placeholder for each card or table row.
- **`isError`**: show an inline `<Alert variant="destructive">` with a Retry button that calls `queryClient.invalidateQueries`.
- **Empty state** (no links yet): show a prompt in each analytics tab directing the creator to the "Links" tab to create their first link, since all analytics derive from existing links.

The `staleTime: 60_000` on all four queries prevents redundant refetches when switching between tabs. Setting `refetchOnWindowFocus: false` on the time-series query is recommended to avoid unnecessary API calls when the user switches windows.
