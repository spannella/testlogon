# GAP-0263: `notary_stamp` Field Type Not Valid — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No investigation
> doc exists for this gap; code verification was performed as part of this write-up.

## 1. Summary & Classification

**Gap**: The `notary_stamp` signature field type, together with its associated metadata
fields (`stamp_image_ref`, `stamp_number`, `stamp_expiry`, `stamped_at`), is not
supported by the signature packet store. KYC-007 requires this field type to allow
official notary or compliance stamps to be embedded in signed KYC documents for
high-risk cases.

**Verdict**: Partially confirmed — and the code state is actually better than the GAP
ticket implies. The `SignatureFieldType` enum in
`app/services/signature_packet_domain.py` (lines 20–27) **already includes**
`NOTARY_STAMP = "notary_stamp"`. The enum omission claim in the GAP ticket is therefore
**inaccurate**. However, the field store (`app/services/signature_packet_store.py`) does
not persist or validate the notary-specific metadata subfields (`stamp_image_ref`,
`stamp_number`, `stamp_expiry`, `stamped_at`), and there is no S3-backed stamp image
path handling. The storage layer and the fill-field endpoint ignore those attributes
entirely. The gap is real but narrower than stated.

- **Severity**: HIGH (for compliance workflows that require notarised documents)
- **Source ticket**: KYC-007 / GAP-0263
- **Status**: Open (partial)
- **Claim accuracy**: **Claim corrected** — `notary_stamp` is already in the enum; the
  gap lies in the persistence and metadata handling layer, not the type definition.
- **Owning area**: KYC / Document Signing (field storage)
- **Related tickets**: GAP-0261, GAP-0262. The notary stamp field type is consumed by
  the template service (GAP-0261), so both must be fixed together.

## 2. Current-State Investigation (root cause)

### 2.1 The enum — already present

`app/services/signature_packet_domain.py`:

```python
class SignatureFieldType(str, Enum):
    SIGNATURE = "signature"
    INITIALS  = "initials"
    DATE      = "date"
    TEXT      = "text"
    NOTARY_STAMP = "notary_stamp"   # line 26 — already exists
```

The `SignatureFieldType.NOTARY_STAMP` value (`"notary_stamp"`) is accepted by
`upsert_packet_field` at `app/services/signature_packet_store.py:142` because that
function takes a `field_type: SignatureFieldType` parameter and stores `field_type.value`
in DDB without further validation. A field of type `notary_stamp` can already be stored.

### 2.2 What is missing — metadata persistence

The `upsert_packet_field` function signature (lines 133–165):

```python
def upsert_packet_field(
    *,
    packet_id: str,
    field_id: str,
    page: int,
    x: float, y: float, width: float, height: float,
    field_type: SignatureFieldType,
    assigned_signer_id: Optional[str],
    required: bool,
) -> Dict[str, Any]:
```

There are no parameters for `stamp_image_ref`, `stamp_number`, `stamp_expiry`, or
`stamp_metadata`. The DDB item written at lines 148–165 contains only geometry, type,
and assignment. For a `notary_stamp` field, the stamp image (stored in S3), the official
registration number, and the commission expiry must be recorded when the stamp is applied.

The field-fill endpoint in `app/services/signature_packet_store.py` (starting around
line 259) also does not handle notary-specific attributes:

```python
expression = "SET #value = :value, filled_at = :filled_at, ..."
```

There is no branch for `field_type == "notary_stamp"` that would also write
`stamp_image_ref`, `stamp_number`, `stamp_expiry`, `stamped_at`.

### 2.3 S3 stamp image path

When a notary applies their stamp, the stamp image must be uploaded to S3 (or moto in dev)
and the key stored as `stamp_image_ref`. The current fill-field code path has no S3 upload
step and no `stamp_image_ref` column in the field item schema.

### 2.4 Why `notary_stamp` fields pass silently

Because the enum already includes `NOTARY_STAMP`, a caller can create a `notary_stamp`
field via `upsert_packet_field` with no error. The field is stored in DDB without
notary metadata. When the PDF rendering pipeline reads back the field (via
`list_packet_fields` at line 180), it sees a `field_type: "notary_stamp"` entry with no
stamp data. The rendering outcome is undefined — the PDF generator either renders nothing
or renders a blank overlay box, silently omitting the notary certification.

## 3. Impact / Exploit / Blast Radius

### 3.1 Compliance / legal

Documents requiring a notary stamp for high-risk KYC cases will be generated without
the stamp, or with an empty placeholder. The final signed PDF is structurally deficient:
it claims the notarisation requirement is met (the field type exists in the packet) but
contains no stamp image or notary credentials. This constitutes fraudulent or erroneous
certification.

### 3.2 Data integrity

- `stamp_image_ref` is absent from the DDB item, so downstream systems that query the
  field to verify notary credentials have no data to read.
- `stamp_expiry` is never checked, so an expired notary commission could be used without
  any validation error.

### 3.3 Security

A malicious or careless admin could add a `notary_stamp` field to a packet and mark it
as filled without providing any stamp credentials, bypassing the notarisation requirement
entirely. Because the field is typed `notary_stamp` in DDB, audit logs would show the
field as "stamped" even though no stamp data was ever stored.

### 3.4 Blast radius

Limited to KYC cases that explicitly use the `notary_stamp` field type. No existing
endpoint in the router currently creates such fields (since the template service is
absent — GAP-0261), so the blast radius is currently zero at runtime. The risk is latent
until the template service is implemented.

## 4. Fix Design (code-level)

### 4.1 Extend `upsert_packet_field` — `app/services/signature_packet_store.py:133`

Add optional notary metadata parameters and persist them when the field type is
`notary_stamp`:

```python
def upsert_packet_field(
    *,
    packet_id: str,
    field_id: str,
    page: int,
    x: float,
    y: float,
    width: float,
    height: float,
    field_type: SignatureFieldType,
    assigned_signer_id: Optional[str],
    required: bool,
    default_value: Optional[str] = None,           # NEW — for auto-population
    stamp_image_ref: Optional[str] = None,          # NEW — S3 key of stamp image
    stamp_number: Optional[str] = None,             # NEW — notary registration number
    stamp_expiry: Optional[str] = None,             # NEW — ISO date string
) -> Dict[str, Any]:
    require_signature_pdf_enabled()
    _ensure_packet_draft(packet_id)
    now = datetime.now(timezone.utc).isoformat()
    item: Dict[str, Any] = {
        "packet_id": packet_id,
        "field_id": field_id,
        "page": int(page),
        "x": Decimal(str(x)),
        "y": Decimal(str(y)),
        "width": Decimal(str(width)),
        "height": Decimal(str(height)),
        "field_type": field_type.value,
        "required": bool(required),
        "updated_at": now,
    }
    existing = T.signature_packet_fields.get_item(
        Key={"packet_id": packet_id, "field_id": field_id}
    ).get("Item")
    item["created_at"] = (existing or {}).get("created_at", now)
    if assigned_signer_id:
        item["assigned_signer_id"] = assigned_signer_id
    if default_value is not None:
        item["default_value"] = default_value
    # Notary stamp metadata — only persisted for notary_stamp fields
    if field_type == SignatureFieldType.NOTARY_STAMP:
        if stamp_number:
            item["stamp_number"] = stamp_number
        if stamp_expiry:
            item["stamp_expiry"] = stamp_expiry
            # Validate expiry is a future date
            from datetime import date
            try:
                expiry_date = date.fromisoformat(stamp_expiry)
                if expiry_date < date.today():
                    raise ValueError("stamp_expiry is in the past")
            except ValueError as exc:
                raise ValueError(f"Invalid stamp_expiry: {exc}") from exc
        if stamp_image_ref:
            item["stamp_image_ref"] = stamp_image_ref
    T.signature_packet_fields.put_item(Item=item)
    return item
```

### 4.2 Extend fill-field path to accept notary stamp attributes

The `fill_packet_field` function (approximately line 259) should write notary metadata
when filling a `notary_stamp` field:

```python
def fill_packet_field(
    *,
    packet_id: str,
    field_id: str,
    signer_id: str,
    value: str | None,
    stamp_image_ref: str | None = None,     # NEW
    stamp_number: str | None = None,         # NEW
    stamp_expiry: str | None = None,         # NEW
) -> Dict[str, Any]:
    require_signature_pdf_enabled()
    field = T.signature_packet_fields.get_item(
        Key={"packet_id": packet_id, "field_id": field_id}
    ).get("Item")
    if not field:
        raise ValueError("field_not_found")

    now = datetime.now(timezone.utc).isoformat()
    expression = (
        "SET #value = :value, filled_at = :filled_at, "
        "filled_by_signer_id = :filled_by_signer_id, updated_at = :updated_at"
    )
    attr_values = {
        ":value": value or "",
        ":filled_at": now,
        ":filled_by_signer_id": signer_id,
        ":updated_at": now,
    }
    if str(field.get("field_type")) == SignatureFieldType.NOTARY_STAMP.value:
        expression += (
            ", stamp_image_ref = :stamp_image_ref"
            ", stamp_number = :stamp_number"
            ", stamp_expiry = :stamp_expiry"
            ", stamped_at = :stamped_at"
        )
        attr_values[":stamp_image_ref"] = stamp_image_ref or ""
        attr_values[":stamp_number"] = stamp_number or ""
        attr_values[":stamp_expiry"] = stamp_expiry or ""
        attr_values[":stamped_at"] = now
    # ... remainder of update_item call unchanged
```

### 4.3 S3 stamp image upload helper

For the router that handles the "apply stamp" action, a small helper should upload the
stamp image to S3 (moto-backed in dev):

```python
def upload_stamp_image(
    *,
    packet_id: str,
    field_id: str,
    image_bytes: bytes,
    content_type: str = "image/png",
) -> str:
    """Upload stamp image to S3; return the S3 key."""
    import boto3
    from app.core.settings import S
    key = f"kyc/stamps/{packet_id}/{field_id}/stamp.png"
    s3 = boto3.client("s3", endpoint_url=S.s3_endpoint_url or None)
    s3.put_object(
        Bucket=S.s3_bucket,
        Key=key,
        Body=image_bytes,
        ContentType=content_type,
    )
    return key
```

In dev, `S.s3_endpoint_url` points to moto. In prod, it is `None` and boto3 routes to
real AWS S3. The same code path — SECOPS-007 parity maintained.

### 4.4 Backward compatibility

- No existing DDB items are modified. The new fields are optional and absent from
  existing `field_type != "notary_stamp"` items.
- The `upsert_packet_field` signature is extended with keyword-only optional parameters
  — all callers that omit the new params continue to work without change.
- The existing `fill_packet_field` callers are unaffected since the new parameters
  default to `None`.

## 5. Testing, Verification & Rollout

### 5.1 Offline regression test (pytest)

```python
# tests/services/test_signature_packet_store_notary.py
import pytest
from app.services.signature_packet_domain import SignatureFieldType
from app.services.signature_packet_store import upsert_packet_field, fill_packet_field
from tests.conftest import make_packet  # test helper that creates a draft packet

def test_notary_stamp_field_persists_metadata(make_packet):
    packet_id = make_packet()
    item = upsert_packet_field(
        packet_id=packet_id,
        field_id="notary_1",
        page=1, x=0.0, y=0.0, width=100.0, height=100.0,
        field_type=SignatureFieldType.NOTARY_STAMP,
        assigned_signer_id="admin_sub",
        required=True,
        stamp_number="NP-12345",
        stamp_expiry="2027-12-31",
    )
    assert item["stamp_number"] == "NP-12345"
    assert item["stamp_expiry"] == "2027-12-31"
    assert item["field_type"] == "notary_stamp"

def test_notary_stamp_field_rejects_past_expiry(make_packet):
    packet_id = make_packet()
    with pytest.raises(ValueError, match="stamp_expiry is in the past"):
        upsert_packet_field(
            packet_id=packet_id,
            field_id="notary_exp",
            page=1, x=0.0, y=0.0, width=100.0, height=100.0,
            field_type=SignatureFieldType.NOTARY_STAMP,
            assigned_signer_id="admin_sub",
            required=True,
            stamp_number="NP-00001",
            stamp_expiry="2020-01-01",
        )

def test_fill_notary_stamp_writes_stamped_at(make_packet_with_notary_field):
    packet_id, field_id = make_packet_with_notary_field()
    result = fill_packet_field(
        packet_id=packet_id,
        field_id=field_id,
        signer_id="admin_sub",
        value=None,
        stamp_image_ref="kyc/stamps/p1/notary_1/stamp.png",
        stamp_number="NP-12345",
        stamp_expiry="2027-12-31",
    )
    assert result.get("stamped_at") is not None
    assert result.get("stamp_image_ref") == "kyc/stamps/p1/notary_1/stamp.png"
```

**Fails before**: `upsert_packet_field` returns items without `stamp_number` / `stamp_expiry`
regardless of input; `fill_packet_field` raises `TypeError` on unexpected kwargs.
**Passes after**: metadata is stored and filled correctly.
