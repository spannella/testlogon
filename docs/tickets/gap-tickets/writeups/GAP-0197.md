# GAP-0197: Affiliate Summary, Time-Series, Earnings, and Top-Products Backend Endpoints Absent — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; claim confirmed.

## 1. Summary & Classification

**Plain-English statement**: The FIN-010 ticket specified five backend analytics endpoints for the affiliate dashboard. Only one of the five — `GET /ui/affiliates/links/{link_id}/stats` — was implemented. The remaining four aggregate/reporting endpoints are entirely absent: a creator-level summary, a click time-series, an earnings breakdown, and a top-products leaderboard. Because there are no backend routes, there can be no frontend data, and creators see only per-link totals with no cross-link or trend view.

- **Severity**: HIGH
- **Source ticket**: FIN-010
- **Status**: Open — partial implementation (one of five endpoints exists)
- **Owning area**: Affiliate / Creator monetisation analytics
- **Verdict**: Confirmed. Scanning `app/services/affiliate_links.py` (383 lines) and `app/routers/affiliate_links.py` (217 lines) shows zero functions or routes matching `summary`, `timeseries`, `earnings_breakdown`, or `top_products`. The service layer exposes `get_link_stats` (per-link) and the router exposes `GET /ui/affiliates/links/{link_id}/stats`, but nothing cross-link.
- **Impact**: Creators cannot view aggregate affiliate income, cannot spot time-based click trends, cannot identify which products drive the most commission. The analytics value proposition of the affiliate feature is effectively zero.
- **Related tickets**: FIN-010 (parent), GAP-0198 (companion frontend gap), SECOPS-007

## 2. Current-State Investigation (root cause)

### What is present

`app/services/affiliate_links.py` provides:
- `create_affiliate_link` (line 63) — CRUD
- `get_link` / `get_link_by_code` / `list_creator_links` / `delete_link` (lines 135–176)
- `record_click` (line 190) — writes to `T.affiliate_clicks`
- `record_conversion` (line 272) — updates `T.affiliate_links` counters
- `get_link_stats` (line 336) — reads counters from a single link item

The DynamoDB schema stores aggregates as denormalised counters on the `affiliate_links` table item (`click_count`, `unique_click_count`, `conversion_count`, `revenue_cents`, `commission_earned_cents`). The `affiliate_clicks` table stores individual click events with a `clicked_at` timestamp and a `GSI1PK = VISITOR#{visitor_hash}` key, and conversion records under `GSI1PK = CONV#{link_id}`.

`app/routers/affiliate_links.py` exposes:
- `POST /ui/affiliates/links` — create (line 66)
- `GET  /ui/affiliates/links` — list (line 96)
- `GET  /ui/affiliates/links/{link_id}` — detail (line 106)
- `DELETE /ui/affiliates/links/{link_id}` — revoke (line 120)
- `GET  /ui/affiliates/links/{link_id}/stats` — per-link stats (line 133)
- `POST /ui/affiliates/links/{link_id}/conversions` — manual conversion (line 148)
- `GET  /r/{tracking_code}` — public redirect (line 174)

### What is missing

The four endpoints specified in FIN-010 are:

| Endpoint | Service function needed | Model needed |
|---|---|---|
| `GET /ui/affiliates/summary` | `get_creator_summary(creator_id)` | `AffiliateSummaryOut` |
| `GET /ui/affiliates/timeseries` | `get_click_timeseries(creator_id, interval, from_ts, to_ts)` | `AffiliateClickTimeSeriesOut` |
| `GET /ui/affiliates/earnings` | `get_earnings_breakdown(creator_id, from_ts, to_ts)` | `AffiliateEarningsBreakdownOut` |
| `GET /ui/affiliates/top-products` | `get_top_products(creator_id, limit)` | `AffiliateTopProductsOut` |

None of these functions exist in `affiliate_links.py`, and none of these routes exist in the router. The `app/models.py` file has no `AffiliateSummaryOut` class (confirmed by grepping for `AffiliateSummary`, `AffiliateClickTimeSeries`, `AffiliateEarningsBreakdown`, `AffiliateTopProducts` — no results).

### Why it is hard to add retroactively without schema changes

The click time-series endpoint requires scanning the `affiliate_clicks` table by `creator_id` and bucketing clicks by day/week. The table's current GSI (`GSI1PK = VISITOR#{hash}`) does not support creator-scoped time-range queries. A new GSI — `ByCreator` (GSI1PK = `CREATOR#{creator_id}`, GSI1SK = `clicked_at`) — is needed on the `affiliate_clicks` table, or the click records need a `creator_id` attribute added by the `record_click` function.

The `top_products` and `summary` endpoints can be derived by iterating the creator's links (already available via `list_creator_links`) and aggregating their counter fields in Python — no GSI change required.

## 3. Impact / Exploit / Blast Radius

- **Creator experience**: Without aggregate analytics, creators cannot make data-driven decisions about which products to promote. This is the primary UX promise of the affiliate links feature.
- **Revenue / retention risk**: Creators may disengage from the affiliate feature entirely if the only visible metric is a per-link click count shown in the link list table.
- **Data integrity**: The underlying click records are being stored correctly. The gap is purely in the read/aggregation layer, so no historical data is lost.
- **Security**: None — these are read-only, auth-gated endpoints on the authenticated user's own data.
- **Blast radius**: Medium. The feature is additive (affiliate analytics is not a compliance requirement), but it is the primary differentiator of the FIN-010 milestone.

## 4. Fix Design (code-level)

### 4a. DynamoDB schema change for click time-series

Add `creator_id` to each click record in `record_click` (line 190 of `affiliate_links.py`). The link item already has `affiliate_user_id`; pass it through:

```python
def record_click(
    *,
    link_id: str,
    tracking_code: str,
    ip_address: str,
    user_agent: str,
    referrer: Optional[str] = None,
    creator_id: str = "",   # NEW
) -> Dict[str, Any]:
    ...
    click: Dict[str, Any] = {
        ...
        "creator_id": creator_id,                    # NEW
        "GSI2PK": f"CREATOR#{creator_id}",           # NEW — for ByCreator GSI
        "GSI2SK": now,
    }
```

Add the `ByCreator` GSI to `affiliate_clicks` in `scripts/local-ddb-init.py`:
```python
TableDef(
    name=S.affiliate_clicks_table_name,
    pk="link_id", sk="click_id",
    gsis=[
        GsiDef("ByVisitor", pk="GSI1PK", sk="GSI1SK"),
        GsiDef("ByCreator", pk="GSI2PK", sk="GSI2SK"),   # NEW
    ],
    attr_types={"GSI1SK": "N", "GSI2SK": "N"},
)
```

The `affiliate_redirect` endpoint (line 188 of the router) already has the link object; pass `link["affiliate_user_id"]` as `creator_id` to `record_click`.

### 4b. New service functions (`app/services/affiliate_links.py`)

```python
def get_creator_summary(creator_id: str) -> Dict[str, Any]:
    """Aggregate totals across all links for a creator."""
    links = list_creator_links(creator_id)
    total_clicks = sum(int(l.get("click_count", 0)) for l in links)
    total_unique = sum(int(l.get("unique_click_count", 0)) for l in links)
    total_conversions = sum(int(l.get("conversion_count", 0)) for l in links)
    total_revenue = sum(int(l.get("revenue_cents", 0)) for l in links)
    total_commission = sum(int(l.get("commission_earned_cents", 0)) for l in links)
    active_links = sum(1 for l in links if l.get("status") == "active")
    return {
        "total_links": len(links),
        "active_links": active_links,
        "total_clicks": total_clicks,
        "unique_clicks": total_unique,
        "total_conversions": total_conversions,
        "total_revenue_cents": total_revenue,
        "total_commission_cents": total_commission,
        "overall_conversion_rate_pct": round(
            total_conversions / total_unique * 100, 2
        ) if total_unique > 0 else 0.0,
    }


def get_click_timeseries(
    creator_id: str,
    interval: str = "day",   # "day" | "week"
    from_ts: int = 0,
    to_ts: int = 0,
) -> List[Dict[str, Any]]:
    """Aggregate click counts by time bucket using the ByCreator GSI."""
    from boto3.dynamodb.conditions import Key as K, Attr
    kce = K("GSI2PK").eq(f"CREATOR#{creator_id}")
    kwargs: Dict[str, Any] = {
        "IndexName": "ByCreator",
        "KeyConditionExpression": kce,
        "ScanIndexForward": True,
    }
    if from_ts:
        kwargs["KeyConditionExpression"] = kce & K("GSI2SK").between(
            int(from_ts), int(to_ts) if to_ts else int(now_ts())
        )
    buckets: Dict[str, int] = {}
    resp = T.affiliate_clicks.query(**kwargs)
    for item in resp.get("Items", []):
        ts = int(item.get("clicked_at", 0))
        if interval == "week":
            import datetime
            dt = datetime.datetime.utcfromtimestamp(ts)
            bucket = dt.strftime("%Y-W%W")
        else:
            bucket = str(ts // 86400 * 86400)  # floor to day epoch
        buckets[bucket] = buckets.get(bucket, 0) + 1
    return [{"bucket": k, "clicks": v} for k, v in sorted(buckets.items())]


def get_earnings_breakdown(
    creator_id: str,
    from_ts: int = 0,
    to_ts: int = 0,
) -> Dict[str, Any]:
    """Earnings breakdown by product for all links."""
    links = list_creator_links(creator_id)
    by_product = []
    for link in links:
        if from_ts or to_ts:
            pass  # counter-based; full date-range filtering requires per-conversion scan
        by_product.append({
            "link_id": link["link_id"],
            "target_name": link.get("target_name", ""),
            "target_type": link.get("target_type", ""),
            "commission_earned_cents": int(link.get("commission_earned_cents", 0)),
            "revenue_cents": int(link.get("revenue_cents", 0)),
            "conversions": int(link.get("conversion_count", 0)),
        })
    by_product.sort(key=lambda x: x["commission_earned_cents"], reverse=True)
    total = sum(x["commission_earned_cents"] for x in by_product)
    return {"items": by_product, "total_commission_cents": total}


def get_top_products(creator_id: str, limit: int = 10) -> List[Dict[str, Any]]:
    """Top N products by click count for a creator."""
    links = list_creator_links(creator_id)
    ranked = sorted(links, key=lambda l: int(l.get("click_count", 0)), reverse=True)
    return [
        {
            "link_id": l["link_id"],
            "target_name": l.get("target_name", ""),
            "target_id": l.get("target_id", ""),
            "click_count": int(l.get("click_count", 0)),
            "conversion_count": int(l.get("conversion_count", 0)),
            "commission_earned_cents": int(l.get("commission_earned_cents", 0)),
        }
        for l in ranked[:limit]
    ]
```

### 4d. New router endpoints (`app/routers/affiliate_links.py`)

```python
from app.models import (
    AffiliateSummaryOut, AffiliateClickTimeSeriesOut,
    AffiliateEarningsBreakdownOut, AffiliateTopProductsOut,
)
from app.services.affiliate_links import (
    get_creator_summary, get_click_timeseries,
    get_earnings_breakdown, get_top_products,
)

@router.get("/ui/affiliates/summary", response_model=AffiliateSummaryOut)
async def creator_summary(ctx: Dict = Depends(require_ui_session)):
    _require_enabled()
    return get_creator_summary(ctx["user_sub"])

@router.get("/ui/affiliates/timeseries")
async def click_timeseries(
    interval: str = Query("day", regex="^(day|week)$"),
    from_ts: Optional[int] = Query(None),
    to_ts: Optional[int] = Query(None),
    ctx: Dict = Depends(require_ui_session),
):
    _require_enabled()
    buckets = get_click_timeseries(
        ctx["user_sub"],
        interval=interval,
        from_ts=from_ts or 0,
        to_ts=to_ts or 0,
    )
    return {"items": buckets, "interval": interval}

@router.get("/ui/affiliates/earnings", response_model=AffiliateEarningsBreakdownOut)
async def earnings_breakdown(
    from_ts: Optional[int] = Query(None),
    to_ts: Optional[int] = Query(None),
    ctx: Dict = Depends(require_ui_session),
):
    _require_enabled()
    return get_earnings_breakdown(ctx["user_sub"], from_ts or 0, to_ts or 0)

@router.get("/ui/affiliates/top-products", response_model=AffiliateTopProductsOut)
async def top_products(
    limit: int = Query(10, ge=1, le=50),
    ctx: Dict = Depends(require_ui_session),
):
    _require_enabled()
    items = get_top_products(ctx["user_sub"], limit=limit)
    return {"items": items}
```

### 4e. Dev/Prod parity (SECOPS-007)

All four endpoints use `require_ui_session` (the same cookie-based session path as every other `/ui/` endpoint). No separate AWS path exists. The `T.affiliate_clicks` table is DynamoDB Local in dev and DynamoDB in prod — same code path, no flag gating. The new ByCreator GSI must be added to `scripts/local-ddb-init.py` with `attr_types={"GSI2SK": "N"}` (numeric sort key) to avoid a `ValidationException` when queried with integer timestamps.

### Rollout

**Effort**: M (3–4 days). GSI addition is the highest-risk item and must be done in a DynamoDB migration run before backend deployment.

**Sequencing**:
1. Add `creator_id` and `GSI2PK/GSI2SK` fields to `record_click` → deploy. Historical clicks already in the table will not have these fields; time-series queries for pre-deploy clicks will return zero, which is acceptable — all data going forward will be captured.
2. Add the ByCreator GSI to the `affiliate_clicks` table definition in `scripts/local-ddb-init.py` with `attr_types={"GSI2SK": "N"}` and run the GSI creation migration in production. DynamoDB creates GSIs online, populating only rows that have the new `GSI2PK` attribute. Pre-deploy rows are not indexed.
3. Add service functions (`get_creator_summary`, `get_click_timeseries`, `get_earnings_breakdown`, `get_top_products`) to `affiliate_links.py`.
4. Add Pydantic models to `app/models.py`.
5. Add the four router endpoints to `affiliate_links.py`.
6. Deploy. GAP-0198 frontend work can then proceed.

**Rollback**: Removing the four endpoints is a zero-downtime router change. The GSI can be deleted independently via the DynamoDB console or a migration script without affecting the base table.

**Risk**: Medium. The GSI creation on a populated table takes time proportional to the number of rows with `GSI2PK` set (only new rows after step 1). Pre-existing rows without the attribute are simply not indexed — no data loss. The `get_creator_summary` and `get_top_products` functions perform an in-memory aggregation over all creator links; for creators with >500 links this is an O(N) DynamoDB query per request. If the number of links per creator exceeds that threshold, a server-side aggregation table (materialised summary) should be introduced, but that is not needed for launch.

### Backward compatibility

The four new endpoints are additive. No existing endpoint is modified. The `record_click` signature change adds an optional `creator_id=""` parameter with a default, so existing callers (the redirect endpoint at line 188) compile without change once the router is updated to pass `creator_id=link["affiliate_user_id"]`.

The `affiliate_clicks` table items for existing click records will simply lack `creator_id` and `GSI2PK`. The `get_click_timeseries` function handles this silently because only GSI-indexed items are returned by the query; older click events are not surfaced in time-series charts, and a data-backfill script can be run during a maintenance window if historical accuracy is required.
