# GAP-0242: Real OAuth token exchange not implemented — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No prior
> investigation doc exists for this ticket.

## 1. Summary & Classification

**Bug**: The `complete_google_drive_connect` endpoint at
`app/routers/google_drive_integration.py:134` raises `HTTPException(501, "Real OAuth not
implemented in this environment")` in every non-mock code path (line 156). When a real
Google Drive OAuth flow completes and Google redirects the user back with an authorization
`code`, the backend throws 501 instead of exchanging the code for access/refresh tokens and
storing the credential.

**Claim verdict**: Confirmed. The cited line (155 in the ticket; 156 in the actual file — one
line off due to a blank line) is accurate. The comment `# Real OAuth exchange would go here`
at line 155 and the raise at line 156 are unmistakable.

**Severity**: HIGH. Without the token exchange the Google Drive integration is entirely
non-functional in production. The INTEG-001 acceptance criteria require a working
`/callback` endpoint that stores `access_token`, `refresh_token`, and `expires_at`.

**Source ticket**: INTEG-001. **Owning area**: `app/routers/google_drive_integration.py`,
`app/services/provider_credentials.py`, `app/services/provider_oauth.py`,
`app/core/settings.py`.

**Related tickets**: GAP-0241 (OAuth state not signed — must be resolved first, so that the
token exchange is only reached after a valid state is verified); GAP-0239 (frontend Connect
button absent); GAP-0240 (picker dialog orphaned). SECOPS-007 applies.

## 3. Impact / Exploit / Blast Radius

### 3.1 Feature completely broken in production

Any user who attempts to connect their Google Drive in a non-dev environment receives
`HTTP 501 Not Implemented`. The frontend shows an error toast and the connection does not
complete. The Google Drive file picker, file import, and any future Drive-backed features are
inaccessible.

### 3.2 Latent security risk if partially deployed

If GAP-0241 (state signing) is fixed first but GAP-0242 is not, the state verification adds
overhead that delays the 501 response by a fraction of a millisecond. There is no practical
security risk from GAP-0242 alone — the 501 itself is a "safe" non-action — but shipping
the Connect UI button (GAP-0239) while the callback returns 501 creates a confusing user
experience and exposes the endpoint structure to probing.

### 3.3 Token storage gaps if implemented naively

If `access_token`, `refresh_token`, and `expires_at` are not stored correctly:
- `get_provider_auth_context` will attempt a refresh on every request (expensive).
- If `refresh_token` is missing, the credential becomes permanently invalid after the
  access token expires (~1 hour for Google).
- If `expires_at` is stored as a string instead of an integer the refresh-trigger comparison
  at `provider_credentials.py:495` (`cred.expires_at < now_ts()`) will silently skip refresh.

## 4. Fix Design (code-level)

### 4.1 Implement `_exchange_oauth_code` helper

Add to `app/routers/google_drive_integration.py`:

```python
async def _exchange_oauth_code(code: str, redirect_uri: str) -> dict:
    """POST authorization code to Google token endpoint.

    Returns the raw token response dict. Raises HTTPException on failure.
    """
    if not S.google_oauth_client_id:
        raise HTTPException(500, "Google OAuth client ID not configured")
    if not S.google_oauth_client_secret:
        raise HTTPException(500, "Google OAuth client secret not configured")

    payload = {
        "code": code,
        "client_id": S.google_oauth_client_id,
        "client_secret": S.google_oauth_client_secret,
        "redirect_uri": redirect_uri or S.google_oauth_redirect_uri,
        "grant_type": "authorization_code",
    }
    resp = await asyncio.to_thread(
        requests.post,
        S.google_oauth_token_url,
        data=payload,
        timeout=10,
    )
    if resp.status_code != 200:
        logger.warning(
            "Google token exchange failed: status=%s body=%s",
            resp.status_code,
            resp.text[:500],
        )
        raise HTTPException(502, "Google token exchange failed")

    data = resp.json()
    if "access_token" not in data:
        raise HTTPException(502, "Google token exchange returned no access_token")
    return data
```

### 4.2 Update `complete_google_drive_connect` to call the exchange

```python
@router.post("/callback")
async def complete_google_drive_connect(
    body: DriveCallbackReq, ctx=Depends(require_ui_session)
) -> Dict[str, Any]:
    user_sub = ctx["user_sub"]

    # --- State verification (GAP-0241 fix must precede this) ---
    if not body.state:
        raise HTTPException(400, "Missing OAuth state")
    _verify_oauth_state(body.state, user_sub)

    if S.dev_mode and S.google_drive_mock_enabled:
        mock_token = f"mock-drive-token-{user_sub}"
        upsert_provider_credential(
            user_sub, "google_drive", mock_token,
            scopes_override=["https://www.googleapis.com/auth/drive.file"],
            metadata_override={"email": f"{user_sub}@drive.mock"},
        )
        return {"ok": True, "connected": True}

    # Real OAuth exchange
    token_data = await _exchange_oauth_code(body.code, body.redirect_uri)

    access_token: str = token_data["access_token"]
    refresh_token: Optional[str] = token_data.get("refresh_token")
    expires_in: int = int(token_data.get("expires_in", 3600))
    expires_at: int = now_ts() + expires_in - 30   # 30s grace

    granted_scope: str = token_data.get("scope", "")
    scopes = [s.strip() for s in granted_scope.split() if s.strip()]

    # Fetch the user's Google email from userinfo
    email: Optional[str] = None
    try:
        userinfo_resp = await asyncio.to_thread(
            requests.get,
            "https://www.googleapis.com/oauth2/v3/userinfo",
            headers={"Authorization": f"Bearer {access_token}"},
            timeout=5,
        )
        if userinfo_resp.status_code == 200:
            email = userinfo_resp.json().get("email")
    except Exception:
        pass  # email is optional metadata

    upsert_provider_credential(
        user_sub,
        "google_drive",
        access_token,
        refresh_token=refresh_token,
        expires_at=expires_at,
        scopes_override=scopes or [S.google_oauth_scopes],
        metadata_override={"email": email} if email else {},
    )

    logger.info("Google Drive connected for user=%s scopes=%s", user_sub, scopes)
    return {"ok": True, "connected": True}
```

### 4.3 Ensure `upsert_provider_credential` accepts `refresh_token` and `expires_at`

Verify `app/services/provider_credentials.py:363` signature. If `refresh_token` and
`expires_at` kwargs are not present, add them:

```python
def upsert_provider_credential(
    owner: str,
    provider: str,
    token: str,
    *,
    refresh_token: Optional[str] = None,
    expires_at: Optional[int] = None,
    org: Optional[str] = None,
    scopes_override: Optional[list] = None,
    metadata_override: Optional[dict] = None,
) -> ProviderCredential:
```

The DDB item already stores `refresh_token` and `expires_at` as part of the credential
model (used by `refresh_google_oauth_access_token`). The kwarg just needs to be threaded
through from the upsert call site.

### 4.4 Dev/Prod parity (SECOPS-007)

The mock path (`S.dev_mode and S.google_drive_mock_enabled`) stores a synthetic credential,
skipping the network call. The real path calls `S.google_oauth_token_url` (defaulting to
`https://oauth2.googleapis.com/token`). In integration tests `S.google_oauth_token_url` can
be pointed at a local mock server (e.g., `http://localhost:12222/token`), keeping tests
hermetic. The `_exchange_oauth_code` helper uses `asyncio.to_thread` (same pattern as
`_drive_api_get`) so it is non-blocking in production.

Both paths write to the same `upsert_provider_credential` function, satisfying the SECOPS-007
requirement that dev and production paths share code below the environment gate.

### 4.5 Alternatives considered

- **Use `httpx` instead of `requests`**: Avoids `asyncio.to_thread` wrapping. Acceptable
  alternative but introduces a new dependency; `requests` is already used throughout the
  router. Use httpx as a follow-up.
- **Store token in Cognito user attributes**: Possible but couples OAuth storage to the auth
  provider. Rejected — `provider_credentials` DDB table is the established pattern.
- **Skip userinfo call**: The `email` metadata is optional (`DriveStatusResp.email`) and only
  used for display. The userinfo call can be made fire-and-forget, but its failure must be
  swallowed (shown above with `except Exception: pass`).

### 5.4 Security considerations for the token exchange path

Two additional hardening steps should accompany this fix:

**Validate `redirect_uri` against an allowlist** before including it in the token exchange
POST. `S.google_oauth_redirect_uri_allowlist` (settings.py:916) is already declared as a
comma-separated list of allowed URIs. Add a check:

```python
allowed = [u.strip() for u in (S.google_oauth_redirect_uri_allowlist or "").split(",") if u.strip()]
effective_redirect = body.redirect_uri or S.google_oauth_redirect_uri
if allowed and effective_redirect not in allowed:
    raise HTTPException(400, "Redirect URI not allowed")
```

This prevents an attacker who bypasses state verification from substituting a malicious
`redirect_uri` to capture the authorization code at their endpoint.

**Log the token exchange outcome** with structured fields (user_sub, granted scopes, but
NOT the token values) at INFO level. This creates an audit trail for compliance and makes
it easy to detect bulk connect/disconnect cycles that could indicate credential-farming
behavior.
