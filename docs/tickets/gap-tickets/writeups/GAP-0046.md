# GAP-0046: Role-Type Comparison Bug in Ad-Break Authorization — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`.

## 1. Summary & Classification

**Claim (from ticket):** `ctx["role"]` is a `Role` enum but is compared against the plain-string set `{"admin", "root"}` at three places in `app/routers/broadcast_ads.py`; admins and roots therefore fail the admin-bypass check and are incorrectly blocked from updating ad config or triggering ad breaks.

**Verdict: Claim partially correct — the comparison lines exist as stated, but the bug does not cause a runtime failure today.** Because `Role` inherits from `str` (`class Role(str, Enum)`), `Role.ADMIN in {"admin", "root"}` evaluates to `True` in Python 3.12. However the `require_ui_session` dependency (in `app/services/sessions.py`) returns `role` as `role.value` (a plain `str`) anyway, so the comparison works regardless.

The defect is real in a different sense: (a) the comparison is semantically wrong and dangerous — it works only by accident of `Role`'s `str` inheritance and the specific `.value` serialisation in `sessions.py`; (b) any future refactor that changes `Role` storage, or any code path that passes a `Role` enum instance directly into `ctx`, would silently break authorisation without a test failure. The correct idiom throughout this codebase (see `app/auth/roles.py:60`) is `role in {Role.ADMIN, Role.ROOT}`.

- **Severity:** HIGH (access-control bypass, latent)
- **Source ticket:** ADS-006
- **Owning area:** Broadcast / Advertising
- **Status:** Open
- **Effort:** S (< 1 hour)
- **Related tickets:** GAP-0047 (same router file, independent fix)

### Background: Why `Role` is a `str, Enum`

`app/auth/roles.py:8` defines `class Role(str, Enum)`. Python's `str, Enum` pattern makes every member a true `str` subclass: `Role.ADMIN == "admin"` evaluates to `True`, and `Role.ADMIN in {"admin", "root"}` evaluates to `True`. This is intentional design — it allows serialising roles to JSON and DynamoDB without an explicit `.value` call, and permits convenient comparisons in both directions. The implication for this gap is nuanced: the guards at lines 127, 188, and 225 work correctly *today*, but only because of two coincident implementation details that are not contractually guaranteed to remain stable.

## 2. Current-State Investigation (root cause)

The three affected guards are in `app/routers/broadcast_ads.py`:

```
line 127:  if session.created_by != ctx["user_sub"] and ctx.get("role") not in {"admin", "root"}:
line 188:  if session.created_by != ctx["user_sub"] and ctx.get("role") not in {"admin", "root"}:
line 225:  if session.created_by != ctx["user_sub"] and ctx.get("role") not in {"admin", "root"}:
```

These guard three endpoints:
- `PATCH /broadcast/sessions/{session_id}/ad-config` (line 124)
- `POST /broadcast/sessions/{session_id}/ad-break` (line 185)
- `POST /broadcast/sessions/{session_id}/ad-break/end` (line 222)

The `_ctx` dependency (line 37) calls `require_ui_session` from `app/services/sessions.py`. That function returns `ctx["role"] = role.value` at line 398 of `sessions.py`, where `role` is a `Role` enum instance. `role.value` is a plain Python `str` (`"admin"`, `"root"`, or `"user"`). So at runtime the value inserted into `ctx["role"]` is a bare string, and `"admin" in {"admin", "root"}` is `True`.

Why does the latent risk still matter:

1. **Fragile path to correctness.** The guard works only because two implementation details must both remain true: `Role` inherits `str`, and `sessions.py` serialises `role.value`. If either changes — e.g. Role becomes a plain `Enum`, or a future refactor returns the enum object instead of `.value` — the guards silently flip to "deny everyone who is not the broadcaster", locking out admin operators.

2. **No import of Role.** `broadcast_ads.py` does not import `Role` at all (confirmed: no `from app.auth.roles import Role` line). This means the intent to compare against enum members was never expressed; the string literals are load-bearing magic values.

3. **The canonical pattern is already established.** `app/auth/roles.py:60` shows the right idiom: `return role in {Role.ADMIN, Role.ROOT}`. Using the same pattern here makes the guard correct by construction, immune to future `str`-inheritance removal.

4. **Consistent divergence across three endpoint guards.** All three endpoints are copy-pasted versions of the same guard. Once the import is added and the fix is applied to one, it must be applied to all three — a missed guard on any one endpoint is an exploitable bypass.

**How the bug would manifest if the latent risk materialised:**
An admin or root user trying to configure ad-breaks on a broadcast they do not own (the broadcaster is someone else) would receive HTTP 403 NOT_BROADCASTER. The only workaround would be to use the broadcaster's own session, which is not possible for break-glass or emergency intervention scenarios. In a live broadcast with problematic advertising content (e.g. a mis-targeted ad running during an emergency), an on-call admin would be unable to terminate the ad break without interrupting the entire broadcast session.

### Why `sessions.py` serialises `role.value`

At `app/services/sessions.py:398`, the auth dependency returns `ctx["role"] = role.value`. This is the `.value` string (`"admin"`, `"root"`, `"user"`), not the `Role` enum object. This means the `ctx` dict throughout the application carries a bare string for the role. Any future change that returns the `Role` enum object instead (for richer typing, for mypy compliance, or as part of a dependency refactor) would not change any existing tests — because the `Role(str, Enum)` design means `Role.ADMIN == "admin"` — but would silently break if someone simultaneously changed `Role` to a non-str base class. The defensive fix costs zero effort and removes the dependency on these two coincident facts.

## 3. Impact / Exploit / Blast Radius

**Current runtime impact:** None — admin and root users can currently manage ad-breaks on other users' broadcasts because the `str`-equality happens to be True.

**Latent/future risk walkthrough:**
1. Developer changes `Role` to a non-`str` Enum (reasonable refactor, or upgrade to Python `StrEnum` with different identity semantics).
2. `sessions.py` returns the `Role` enum object in `ctx["role"]` rather than `.value`.
3. `ctx.get("role") not in {"admin", "root"}` evaluates to `True` for `Role.ADMIN` because `Role.ADMIN != "admin"` once str-inheritance is removed.
4. Admin and root users are blocked from `PATCH ad-config`, `POST ad-break`, and `POST ad-break/end` on any session they do not own.
5. Emergency ad-break termination during a broadcast incident requires escalation to the session owner.

**Secondary risk — code-review false assurance:** Reviewers inspecting these guards may assume string sets are authoritative (no IDE warning, no type error) and approve subsequent changes that depend on the guards working correctly.

**Blast radius:** Confined to the three broadcast ad-break management endpoints. Users are not at risk of privilege escalation; the direction of the flaw is denial-of-access (too restrictive) once materialised, not privilege escalation.

**Why HIGH severity despite current non-impact:**
The HIGH rating is correct because: (a) the affected endpoints gate emergency operational controls (ending a live ad break); (b) the defect is directly contrary to the stated access model (admins should be able to override broadcaster-owned resources); and (c) the fix is trivial — any latent defect that is trivially fixable but still open is a severity indicator in itself, signalling that a code review for correctness was skipped.

## 4. Fix Design (code-level)

### Change 1 — import Role

At the top of `app/routers/broadcast_ads.py`, add:

```python
from app.auth.roles import Role
```

No other import changes are needed; `require_ui_session` is already imported from `app.services.sessions`.

### Change 2 — replace all three guards

Replace every occurrence of `ctx.get("role") not in {"admin", "root"}` with `ctx.get("role") not in {Role.ADMIN, Role.ROOT}`.

**Line 127** (update_ad_config_route):
```python
# Before
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {"admin", "root"}:

# After
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {Role.ADMIN, Role.ROOT}:
```

**Line 188** (trigger_ad_break_route):
```python
# Before
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {"admin", "root"}:

# After
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {Role.ADMIN, Role.ROOT}:
```

**Line 225** (end_ad_break_route):
```python
# Before
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {"admin", "root"}:

# After
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {Role.ADMIN, Role.ROOT}:
```

### Dev/Prod parity (SECOPS-007)

This change is purely within the FastAPI router layer. There is no AWS-specific code path, no feature flag gating, and no mock/dev bypass. The same three lines execute identically in dev and production. No additional parity work is required.

Since `Role(str, Enum)` means `Role.ADMIN == "admin"` is `True`, this fix is **backward-compatible at runtime**: the check result does not change for any currently valid `ctx["role"]` value (whether it is the string `"admin"` or the enum `Role.ADMIN`). The fix simply removes the latent fragility.

### Alternatives considered

- **Use `role_allows_admin_features(role)` helper** (`app/auth/roles.py:60`): This is the most elegant option, but it requires converting `ctx.get("role")` back to a `Role` enum first (via `normalize_role`). That adds a line and is overkill for this narrow fix. Inline set membership against `{Role.ADMIN, Role.ROOT}` is already the pattern used in `deps.py`.
- **Add a `require_broadcaster_or_admin` dependency:** Cleaner long-term, but larger scope change that should be tracked separately.

## 5. Testing, Verification & Rollout

### Regression test (pytest, fails-before / passes-after)

Add to `tests/routers/test_broadcast_ads.py` (or create it):

```python
import pytest
from unittest.mock import patch, MagicMock
from fastapi.testclient import TestClient
from app.main import create_app

app = create_app()
client = TestClient(app)

MOCK_SESSION = MagicMock(
    id="sess_001",
    created_by="broadcaster_user",
    pre_roll_enabled=True,
    mid_roll_ad_break_duration_seconds=30,
    mid_roll_skip_after_seconds=15,
    ad_break_active=False,
    ad_break_started_at=None,
    total_ad_breaks=0,
    status="live",
)

def _admin_ctx():
    return {
        "user_sub": "admin_user",
        "session_id": "sess_admin",
        "role": "admin",   # string form (current sessions.py output)
        "ip": "127.0.0.1",
    }

def test_admin_can_update_ad_config_on_other_broadcaster():
    """Admin should be able to PATCH ad-config on a session they don't own."""
    with patch("app.routers.broadcast_ads._ctx", return_value=_admin_ctx()), \
         patch("app.routers.broadcast_ads.get_session", return_value=MOCK_SESSION), \
         patch("app.routers.broadcast_ads.update_session_fields", return_value=MOCK_SESSION):
        resp = client.patch(
            "/broadcast/sessions/sess_001/ad-config",
            json={"pre_roll_enabled": False},
        )
    # Should be 200, not 403
    assert resp.status_code == 200, f"Expected 200, got {resp.status_code}: {resp.text}"


def test_admin_role_enum_does_not_break_guard():
    """Guard must hold whether role is a Role enum or a plain string."""
    from app.auth.roles import Role
    # Role is str+Enum, so Role.ADMIN == "admin". Both forms must grant access.
    for role_val in ("admin", Role.ADMIN, "root", Role.ROOT):
        ctx = {"user_sub": "other_user", "session_id": "s", "role": role_val, "ip": ""}
        with patch("app.routers.broadcast_ads._ctx", return_value=ctx), \
             patch("app.routers.broadcast_ads.get_session", return_value=MOCK_SESSION), \
             patch("app.routers.broadcast_ads.update_session_fields", return_value=MOCK_SESSION):
            resp = client.patch(
                "/broadcast/sessions/sess_001/ad-config",
                json={"pre_roll_enabled": True},
            )
        assert resp.status_code == 200, \
            f"role_val={role_val!r}: expected 200, got {resp.status_code}"
```

**Fails before:** The second test would fail if `Role` were changed to a non-`str` base and the string-set guard were left in place (Role.ADMIN would not be `in {"admin", "root"}`).
**Passes after:** The import + set substitution means both string and enum forms of the role are accepted.

### Type annotations (optional, same PR)

With `Role` now imported, the three route functions can be annotated to document that `ctx["role"]` is expected to be either a `Role` enum or a role string:

```python
from app.auth.roles import Role
from typing import Union

def _check_broadcaster_or_admin(session, ctx: dict) -> None:
    """Shared guard: raise 403 if caller is not broadcaster or admin/root."""
    role_val = ctx.get("role")
    if session.created_by != ctx.get("user_sub") and role_val not in {Role.ADMIN, Role.ROOT}:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail={"code": "NOT_BROADCASTER", "detail": "Only the broadcaster or admin can perform this action"},
        )
```

This helper replaces the three identical guards and ensures a single point of change if the access policy is ever updated (e.g. adding a new `BROADCAST_MANAGER` role). This refactor is optional but recommended as part of the same small PR.
