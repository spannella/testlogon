# GAP-0279: `_readiness_for_case` Does Not Include Template-Signing Completeness Check — Remediation Write-up

> Source ticket: KYC-017 · Severity: HIGH · Effort: M · Status: Open

## 1. Summary & Classification

**Gap**: `_readiness_for_case` in `app/routers/kyc_cases.py` (line 244) is the single authoritative function that determines whether a KYC case has satisfied all preconditions before it can be submitted for review. The KYC-017 spec (§3.6) requires this function to verify that all tier-required document templates have been signed by the applicant. The current implementation checks only three conditions — questionnaire submission, required identity files, and the KYC-007 consent signature packet — without ever consulting `KycDocumentTemplateService.get_required_templates_for_tier()`. A case that is missing a required template signature will incorrectly appear `ready_to_submit: true`.

**Claim verdict**: CONFIRMED. Lines 244–307 of `app/routers/kyc_cases.py` contain no reference to `KycDocumentTemplateService`, `get_required_templates_for_tier`, `kyc_document_templates`, or `unsigned_templates`. The `KYC_TEMPLATE_READINESS_GATE` feature flag mentioned in the ticket does not exist in `app/core/settings.py`.

**Severity**: HIGH. Cases missing a required template signature can be submitted and reviewed without the template being signed. This represents a compliance gap: if tier-2 KYC requires signing an AML disclosure template, a user can skip it entirely and still appear ready for submission.

**Owning area**: KYC/Cases — `app/routers/kyc_cases.py`, `app/services/kyc_document_templates.py`.

**Related tickets**: KYC-017, GAP-0252 (readiness gate extension for enhanced high-risk), GAP-0279 sister ticket GAP-0281 (which addresses a different line in the same function).

## 2. Current-State Investigation (root cause)

### Current `_readiness_for_case` implementation

```python
# app/routers/kyc_cases.py lines 244–307
def _readiness_for_case(case: dict) -> dict:
    questionnaire = _questionnaire_status_for_case(case, include_submit_gate=False)
    files = _validate_file_requirements(case)
    signature = _signature_status_for_case(case)

    checks = {
        "questionnaire_submitted": bool(questionnaire.get("submitted")),
        "required_files": bool(files.get("ready_for_submit_gate")),
        "signature_completed": bool(signature.get("ready_for_submit_gate")),
    }
    hint_map = {
        "questionnaire_submitted": "Submit the linked questionnaire to continue.",
        "required_files": "Attach all required identity files: selfie, id_front, id_back.",
        "signature_completed": "Complete the consent signature packet and wait for final PDF generation.",
    }

    requirements: list[dict] = [
        { "key": "questionnaire_submitted", ... },
        { "key": "required_files",          ... },
        { "key": "signature_completed",     ... },
    ]
    missing_requirements = [item["key"] for item in requirements if not item["ready"]]
    missing_hints = [hint_map[key] for key in missing_requirements]

    return {
        "kyc_case_id": case.get("kyc_case_id"),
        "status": case.get("status"),
        "ready_to_submit": all(checks.values()),
        "missing_requirements": missing_requirements,
        "missing_hints": missing_hints,
        "checks": checks,
        "requirements": requirements,
    }
```

**What's missing**: There is no check #4 — template-signing completeness. The `checks` dict has exactly three keys; `all(checks.values())` will return `True` even when template signatures are absent.

### The available service method

`KycDocumentTemplateService.get_required_templates_for_tier` (line 360 of `app/services/kyc_document_templates.py`) returns a list of active, uploaded templates whose `required_tier` rank is ≤ the requested tier:

```python
def get_required_templates_for_tier(self, tier: str) -> list[dict[str, Any]]:
    # Queries status-updated-index GSI for status="active",
    # filters to version > 0, deduplicates by slug (latest version wins),
    # returns list sorted by (tier_rank, slug).
```

Each returned item has at minimum: `template_id`, `slug`, `display_name`, `required_tier`.

### Where template signatures are stored

Template document signing uses the existing signature packet system. Each template signing produces a signature packet. The case stores signed-template packet references, but this relationship needs to be cross-checked: for each slug returned by `get_required_templates_for_tier(target_tier)`, is there a `completed` packet in the case?

Looking at `_signature_status_for_case` (referenced at line 246), it checks only the primary KYC consent packet (`case["signature"]`). Template packets are separate; they are linked via a different case sub-object. The exact storage key must be confirmed from the broader KYC-017 implementation.

### Feature flag (absent)

The ticket mentions a `KYC_TEMPLATE_READINESS_GATE` feature flag. This setting does not exist in `app/core/settings.py`. It should be added to allow the gate to be disabled during initial rollout (when templates may not yet be configured in production).

### Call sites for `_readiness_for_case`

The function is called in two places:
- `app/routers/kyc_cases.py` line 890 (in `get_case_readiness` endpoint)
- `app/routers/kyc_cases.py` line 911 (in `submit_case` to gate submission)

Both call sites are affected: if the gate is missing from `_readiness_for_case`, both the readiness check endpoint and the submission gate are bypassed.

## 3. Impact / Exploit / Blast Radius

### Compliance bypass

KYC-017 templates are explicitly for legally-required disclosures, consent forms, and AML-acknowledgment documents. If `_readiness_for_case` does not verify template signatures, the following scenario is possible:

1. Admin configures an `AML_Disclosure_v2` template as required for Tier 2.
2. Alice begins a Tier 2 KYC case, completes the questionnaire, uploads her ID documents, and signs the consent packet.
3. The readiness endpoint returns `ready_to_submit: true` and Alice's case is submitted.
4. The admin reviewer sees a case missing the AML disclosure signature but the case appears fully ready.
5. If reviewed and approved: Alice holds Tier 2 without having signed a legally-required document.

### No financial impact

This gap does not directly affect billing or financial operations. The impact is compliance and legal.

### Blast radius

Every active KYC case at any tier could be submitted without required templates. The severity scales with the number of configured required templates — if none are configured yet (new deployment), the immediate impact is zero. But as templates are added, the gap becomes retroactively dangerous.

### 4.2 Extend `_readiness_for_case` in `app/routers/kyc_cases.py`

```python
# app/routers/kyc_cases.py — replace _readiness_for_case (line 244)

from app.services.kyc_document_templates import SERVICE as TEMPLATE_SERVICE

def _readiness_for_case(case: dict) -> dict:

    files = _validate_file_requirements(case)
    signature = _signature_status_for_case(case)

    # ── KYC-017 template-signing gate (GAP-0279) ─────────────────────────
    unsigned_template_slugs: list[str] = []
    if S.kyc_template_readiness_gate_enabled and S.kyc_document_templates_enabled:

                "kyc.readiness.template_check_error case_id=%s",
                case.get("kyc_case_id"),

            # On error: gate open (do not block submission due to service error)
    # ─────────────────────────────────────────────────────────────────────

    templates_signed = len(unsigned_template_slugs) == 0

    checks = {
        "questionnaire_submitted": bool(questionnaire.get("submitted")),
        "required_files": bool(files.get("ready_for_submit_gate")),
        "signature_completed": bool(signature.get("ready_for_submit_gate")),
        "templates_signed": templates_signed,                    # NEW
    }
    hint_map = {
        "questionnaire_submitted": "Submit the linked questionnaire to continue.",
        "required_files": "Attach all required identity files: selfie, id_front, id_back.",
        "signature_completed": "Complete the consent signature packet and wait for final PDF generation.",
        "templates_signed": (                                     # NEW
            "Sign all required document templates: "
            + (", ".join(unsigned_template_slugs) or "see admin for details")
        ),
    }

    requirements: list[dict] = [
        {
            "key": "questionnaire_submitted",
            "ready": checks["questionnaire_submitted"],
            "missing": [] if checks["questionnaire_submitted"] else ["questionnaire_submission"],
            "hint": hint_map["questionnaire_submitted"],
            "refs": {
                "questionnaire_id": questionnaire.get("questionnaire_id"),
                "response_session_id": questionnaire.get("response_session_id"),
                "response_pdf_ref": questionnaire.get("response_pdf_ref"),
            },
        },
        {
            "key": "required_files",
            "ready": checks["required_files"],
            "missing": list(files.get("missing_types") or []),
            "hint": hint_map["required_files"],
            "refs": {"present_types": ",".join(files.get("present_types") or [])},
        },
        {
            "key": "signature_completed",
            "ready": checks["signature_completed"],
            "missing": (
                [] if checks["signature_completed"]
                else ["signature_completion", "signature_final_pdf"]
            ),
            "hint": hint_map["signature_completed"],
            "refs": {
                "packet_id": signature.get("packet_id"),
                "final_pdf_ref": signature.get("final_pdf_ref"),
            },
        },
        {
            "key": "templates_signed",                           # NEW
            "ready": templates_signed,
            "missing": [f"unsigned_templates:{s}" for s in unsigned_template_slugs],
            "hint": hint_map["templates_signed"],
            "refs": {"unsigned_slugs": ",".join(unsigned_template_slugs)},
        },
    ]

    missing_requirements = [item["key"] for item in requirements if not item["ready"]]
    missing_hints = [hint_map[key] for key in missing_requirements]

    return {
        "kyc_case_id": case.get("kyc_case_id"),
        "status": case.get("status"),
        "ready_to_submit": all(checks.values()),
        "missing_requirements": missing_requirements,
        "missing_hints": missing_hints,
```

### 4.3 `_get_signed_template_slugs` helper

```python
def _get_signed_template_slugs(case: dict) -> set[str]:
    """Return the set of template slugs that have a completed signed packet for this case.

    Template packets are stored in ``case["template_packets"]`` as a dict
    of ``{slug: {"packet_id": ..., "status": "completed"|"draft"|...}}``.
    Only "completed" packets count as signed.
    """
    template_packets = case.get("template_packets") or {}
    if isinstance(template_packets, dict):
        return {
            slug
            for slug, packet in template_packets.items()
            if isinstance(packet, dict) and str(packet.get("status")) == "completed"
        }
    return set()
```

The exact field name (`case["template_packets"]`) should be confirmed from the KYC-017 case schema. If the field name differs, only the helper function needs updating.

### 4.4 Dev/Prod parity (SECOPS-007)

- `TEMPLATE_SERVICE.get_required_templates_for_tier(target_tier)` queries the `status-updated-index` GSI (see GAP-0278). In dev it queries DynamoDB Local; in prod it queries real DynamoDB. The same code path is used.
- The `KYC_TEMPLATE_READINESS_GATE` flag defaults to `true`. In dev, set `KYC_TEMPLATE_READINESS_GATE=false` to disable the gate if no templates are configured, avoiding false-positive failures in unrelated tests.
- The `except Exception: gate open` pattern ensures that a DynamoDB outage or a misconfigured template table does not block case submissions. This is the safer failure mode — an outage does not lock out applicants.

### 4.5 Alternatives considered

- **Hard fail on template service error**: Would block all submissions during DDB issues. Rejected — availability over strictness for the service-error case.
- **Store signed template slugs on a separate DDB item**: Too complex; the case dict already holds related packet data.
- **Enforce at submit time only, not readiness check**: The readiness endpoint exists to give early feedback to applicants. Missing the gate there degrades UX. Both call sites must be gated.

```python
import pytest
from unittest.mock import patch, MagicMock


def _build_case(target_tier="tier_2", template_packets=None):

        "kyc_case_id": "case_001",
        "status": "in_progress",
        "target_tier": target_tier,
        "template_packets": template_packets or {},
        "questionnaire": {"submitted": True, "questionnaire_id": "q1"},

def _mock_template_service(required_slugs):
    svc = MagicMock()
    svc.get_required_templates_for_tier.return_value = [
        {"slug": s, "template_id": f"kdt_{s}", "required_tier": "tier_2", "version": 1}
        for s in required_slugs
    ]
    return svc


def _call_readiness(case, template_svc):
    """Import and call _readiness_for_case with mocked dependencies."""
    import importlib
    import app.routers.kyc_cases as kyc_cases_mod

    with patch.object(kyc_cases_mod, "TEMPLATE_SERVICE", template_svc), \
         patch.object(kyc_cases_mod.S, "kyc_template_readiness_gate_enabled", True), \
         patch.object(kyc_cases_mod.S, "kyc_document_templates_enabled", True), \
         patch.object(kyc_cases_mod, "_questionnaire_status_for_case",
                      return_value={"submitted": True}), \
         patch.object(kyc_cases_mod, "_validate_file_requirements",
                      return_value={"ready_for_submit_gate": True, "missing_types": []}), \
         patch.object(kyc_cases_mod, "_signature_status_for_case",

def test_not_ready_when_template_unsigned():

    assert "templates_signed" not in result["missing_requirements"]

    """Case with no required templates (tier_1) must still be ready."""
    svc = _mock_template_service([])  # no required templates

    assert result["ready_to_submit"] is True
```

### Rollout / risk

- **Risk**: MEDIUM. Enabling the gate retroactively blocks cases that were previously ready-but-unsigned. For a smooth rollout: (1) deploy with `KYC_TEMPLATE_READINESS_GATE=false`; (2) identify any in-progress cases that would now fail the gate; (3) notify applicants; (4) re-enable the flag.
- **Effort**: M (the service logic is available; the integration is straightforward, but the `target_tier` field on cases must be verified against the actual schema, and `_get_signed_template_slugs` may need adjustment based on the true storage layout of `template_packets`).
- **Sequencing**: Depends on KYC-017 template library being operational (templates must exist and be active). Coordinate with GAP-0278 fix (GSI query) to ensure template queries are performant at readiness-check time.
