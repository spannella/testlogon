# GAP-0295: `/ui/licenses/revenue/register-license` Allows Spoofing `licensor_id` — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; all file:line citations confirmed.

## 1. Summary & Classification

**Bug**: The `POST /ui/licenses/revenue/register-license` endpoint at `app/routers/license_revenue.py:107–124` accepts an optional `licensor_id` field from the request body and passes it verbatim to `svc.register_content_license`. The default fallback is `user_id` (the authenticated sub), but any authenticated user can override this by supplying an arbitrary `licensor_id` in the JSON body, causing revenue credits to be attributed to a third party of their choosing.

**Severity**: HIGH (source ticket LICENSE-003). Effort: S.

**Status**: Open. No investigation doc exists; claim confirmed by direct code inspection.

**Claim verdict**: Confirmed. `app/routers/license_revenue.py:117`:

```python
licensor_id=body.get("licensor_id", user_id),
```

The `body.get("licensor_id", user_id)` expression returns any client-supplied `licensor_id` string before falling back to `user_id`. No validation compares the supplied value against the authenticated user's sub.

**Related tickets**: GAP-0294 (no content ownership enforcement on `issue_license` — a companion vulnerability in a separate endpoint). Together, these two gaps allow a malicious user to create fully fabricated license revenue relationships targeting any user account.

**Owning area**: Backend / License Revenue router.

## 2. Current-State Investigation (Root Cause)

### The vulnerable endpoint

`app/routers/license_revenue.py:107–124`:

```python
@router.post("/register-license")
async def register_license(
    body: dict,
    ctx: dict = Depends(require_ui_session),
):
    """Register a content license mapping (used for testing and integration)."""
    user_id = ctx["user_sub"]
    result = svc.register_content_license(
        issued_license_id=body.get("issued_license_id", ""),
        content_id=body.get("content_id", ""),
        licensor_id=body.get("licensor_id", user_id),   # ← VULNERABILITY
        licensee_id=body.get("licensee_id", ""),
        revenue_share_pct=int(body.get("revenue_share_pct", 0)),
        profit_share_pct=int(body.get("profit_share_pct", 0)),
        fixed_cost_cents=int(body.get("fixed_cost_cents", 0)),
        status=body.get("status", "active"),
    )
    return {"ok": True, "license": result}
```

`user_id` is correctly extracted from the session cookie at line 113. However, because the body is typed as `dict` and `body.get("licensor_id", user_id)` evaluates to the caller's value when present, the authenticated identity is not enforced as the licensor.

### The service function that writes the record

`app/services/license_revenue.py:357–390` (`register_content_license`):

```python
def register_content_license(
    *,
    issued_license_id: str,
    content_id: str,
    licensor_id: str,       # ← whatever was passed in
    licensee_id: str,
    ...
) -> Dict[str, Any]:
    item: Dict[str, Any] = {
        "pk": f"CONTENT_LIC#{content_id}",
        "sk": f"LIC#{issued_license_id}",
        "licensor_id": licensor_id,     # written to DDB verbatim
        ...
    }
    T.license_revenue.put_item(Item=item)
    return item
```

The `licensor_id` value is written directly to DynamoDB with no secondary validation. There is no check against the users table, the content tables, or any ACL.

### How `licensor_id` flows to revenue payouts

When revenue-split processing occurs (via `POST /ui/licenses/revenue/process-split` or triggered by a tip/unlock event), `list_licenses_for_content` at `app/services/license_revenue.py:393–398` queries `CONTENT_LIC#{content_id}` and returns all active license records. The `licensor_id` from each record is used to route revenue credits. A spoofed `licensor_id` causes revenue to flow to the attacker-specified account.

### Endpoint comments acknowledge non-production intent

The docstring at line 112 states "used for testing and integration," but the endpoint is registered under the `/ui/licenses/revenue` prefix behind standard `require_ui_session` auth (line 19 of the file: `router = APIRouter(prefix="/ui/licenses/revenue", ...)`). It is reachable by any authenticated user in both dev and production. There is no `dev_mode` guard, no admin restriction, and no rate limit.

### Note on GAP-0295 vs the parallel endpoint in `app/routers/issued_licenses.py`

`app/routers/issued_licenses.py` also has a `POST /register-license` endpoint (not `POST /revoke-license`) that similarly accepts `licensor_id` from the body. That endpoint is part of the same test/integration surface but is subject to GAP-0294's fix. GAP-0295 is specifically about `app/routers/license_revenue.py:107` which targets the `license_revenue` table, not the `issued_licenses` table.

## 3. Impact / Exploit / Blast Radius

### Exploit walkthrough

1. Attacker (authenticated as `user_A`) knows `user_B`'s user sub (e.g., obtained from a public profile API).
2. Attacker calls:
   ```
   POST /ui/licenses/revenue/register-license
   {
     "issued_license_id": "il_fake001",
     "content_id": "vid_popular_XYZ",
     "licensor_id": "user_B_sub",   ← spoofed
     "licensee_id": "user_A_sub",
     "revenue_share_pct": 0,
     "profit_share_pct": 0,
     "fixed_cost_cents": 0
   }
   ```
3. A record is written: `CONTENT_LIC#vid_popular_XYZ / LIC#il_fake001` with `licensor_id: user_B_sub`.
4. The attacker then calls `POST /ui/licenses/revenue/process-split` with `content_id: vid_popular_XYZ, source_amount_cents: 10000`:
   - `list_licenses_for_content` returns the fake record.
   - Revenue logic routes a split to `user_B_sub`.
5. If the attacker instead sets `licensor_id` to their own sub (`user_A`) but sets an inflated `licensee_id` pointing to a mule account, they can also manufacture revenue credits for themselves on content they don't own.

### Alternative: DoS via revenue sink

An attacker can register hundreds of `"status": "active"` license records pointing to a popular content_id, each with a different `licensor_id`. `process_revenue_split` iterates all active licenses and distributes revenue across all licensors. By flooding the content_id with fake licenses, the attacker can dilute all legitimate licensors' revenue shares to near-zero.

### Worst-case financial impact

- Direct: Any revenue-split event on the targeted content_id credits the spoofed account. For a high-revenue content_id this could be significant ongoing fraud.
- Indirect: Platform compliance reports (1099 forms, VAT) generated from `license_revenue` table data will contain fraudulent `licensor_id` entries, creating legal and tax exposure.
- Availability: The `process-split` endpoint at line 140–158 has no per-content-id cap on the number of licenses processed; a flooded license table can cause timeouts.

**Blast radius**: Any authenticated user can exploit this against any other user. All revenue splits for any content_id are at risk.

## 4. Fix Design (Code-Level)

### 4a. Primary fix — ignore `licensor_id` from body; always use authenticated sub

The correct and minimal fix is one line in `app/routers/license_revenue.py:117`. Replace:

```python
# BEFORE (vulnerable)
licensor_id=body.get("licensor_id", user_id),
```

with:

```python
# AFTER (fixed)
licensor_id=user_id,
```

This removes the body parameter entirely from the `licensor_id` resolution path. Any client-supplied `licensor_id` is silently ignored.

### 4b. Secondary fix — restrict endpoint to admin/internal use only

The docstring calls this an "internal / testing" endpoint. It should be gated behind admin auth, since legitimate production use cases (e.g., platform-level license registration by an ops team) require elevated privileges:

```python
from app.auth.policy import require_admin_or_root
from app.auth.deps import AuthenticatedUser

@router.post("/register-license")
async def register_license(
    body: dict,
    admin: AuthenticatedUser = Depends(require_admin_or_root),  # replace require_ui_session
):
    """Register a content license mapping (admin/internal use only)."""
    result = svc.register_content_license(
        issued_license_id=body.get("issued_license_id", ""),
        content_id=body.get("content_id", ""),
        licensor_id=admin.user_sub,    # always authenticated admin's sub
        licensee_id=body.get("licensee_id", ""),
        revenue_share_pct=int(body.get("revenue_share_pct", 0)),
        profit_share_pct=int(body.get("profit_share_pct", 0)),
        fixed_cost_cents=int(body.get("fixed_cost_cents", 0)),
        status=body.get("status", "active"),
    )
    return {"ok": True, "license": result}
```

If the platform requires an admin to register a license on behalf of a user, `licensor_id` can be re-introduced as an admin-only body field with an explicit guard:

```python
# If admin explicitly specifies a licensor on behalf of a user:
licensor_id = body.get("licensor_id") or admin.user_sub
# Note: admin is required; this does not re-open the vector for regular users
```

### 4c. Also fix the parallel `register-license` in `issued_licenses.py` router

`app/routers/issued_licenses.py` contains an analogous `POST /register-license` endpoint (the router for `app/routers/license_revenue.py` is prefixed `/ui/licenses/revenue` and registered separately). While the ticket specifically cites the `license_revenue.py` endpoint, the same pattern in `issued_licenses.py` should be fixed simultaneously to prevent an auditor finding it as a secondary gap:

`app/routers/issued_licenses.py` does not have an explicit `register-license` endpoint — confirm by reading the file: lines 90–113 show `POST /issued` which already uses `licensor_sub=user_sub` correctly. The `register-license` endpoint only lives in `license_revenue.py`. No change needed to `issued_licenses.py` for this GAP.

### 4d. Add `revoke-license` owner check

`app/routers/license_revenue.py:127–137` (`POST /revoke-license`) accepts a body with `content_id` and `issued_license_id` and calls `svc.revoke_content_license` with no ownership validation. This is a closely related issue (but not the primary subject of GAP-0295). The same admin-only guard from step 4b should be applied.

### 4e. Dev/Prod parity (SECOPS-007)

The fix is a one-line router change. Both the dev stack (which uses DynamoDB Local and `require_ui_session` with the cookie-based JWT) and the production stack use the same router code. There is no `dev_mode` branch in this endpoint. The `require_admin_or_root` dependency from `app/auth/policy` works identically in both environments — in dev, admin sessions are seeded by `e2e_admin_session_setup.py`. No feature flag is needed.

### 4f. Alternatives considered

- **Keep `licensor_id` as a regular-user field but validate it matches `user_sub`**: `if body.get("licensor_id") and body["licensor_id"] != user_id: raise HTTPException(403, ...)`. This is equivalent to ignoring the field (fix 4a) but is noisier. Rejected in favour of silent ignore + body parameter removal.
- **Rate-limit the endpoint**: Limits exploit throughput but doesn't close the hole. Rejected as primary fix (may be added as a defence-in-depth measure alongside the auth change).
- **Delete the endpoint entirely**: The docstring indicates it is needed for testing. Moving it to a dev-only route gated by `S.dev_mode` would eliminate the production surface. This is an option if the admin-gating approach is considered insufficient.

## 5. Testing, Verification & Rollout

### Regression test — pytest (fails before, passes after)

Add to `tests/test_license_revenue.py`:

```python
import pytest
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def _session_headers(user_sub: str, csrf: str, cookie: str) -> dict:
    return {
        "Cookie": cookie,
        "x-csrf-token": csrf,
    }

def test_register_license_ignores_body_licensor_id(alice_session_headers):
    """licensor_id in body must be ignored; authenticated sub always used."""
    resp = client.post(
        "/ui/licenses/revenue/register-license",
        json={
            "issued_license_id": "il_test001",
            "content_id": "vid_001",
            "licensor_id": "evil_user_sub",    # attacker-supplied
            "licensee_id": "licensee_sub",
            "revenue_share_pct": 10,
        },
        headers=alice_session_headers,
    )
    # Before fix: 200, license.licensor_id == "evil_user_sub"
    # After fix with admin-only guard: 403 for non-admin Alice
    assert resp.status_code == 403

def test_register_license_admin_uses_own_sub(root_session_headers, root_sub):
    """Admin register-license always records admin's own sub as licensor."""
    resp = client.post(
        "/ui/licenses/revenue/register-license",
        json={
            "issued_license_id": "il_test002",
            "content_id": "vid_002",
            "licensee_id": "licensee_sub",
        },
        headers=root_session_headers,
    )
    assert resp.status_code == 200
    data = resp.json()
    assert data["license"]["licensor_id"] == root_sub  # not from body
```

### Playwright E2E test

Add to `frontend/e2e/license-revenue.spec.ts`:

```typescript
test("register-license returns 403 for non-admin user", async () => {
  const resp = await alicePage.request.post("/ui/licenses/revenue/register-license", {
    headers: { "x-csrf-token": sessions["alice"].csrf_token },
    data: {
      issued_license_id: "il_spoof_001",
      content_id: "vid_any",
      licensor_id: "bob_sub",   // spoofing Bob
      licensee_id: "alice_sub",
    },
  });
  // Before fix: 200 with licensor_id=bob_sub
  // After fix: 403
  expect(resp.status()).toBe(403);
});

test("register-license as root: licensor_id taken from session, not body", async () => {
  const resp = await rootPage.request.post("/ui/licenses/revenue/register-license", {
    headers: { "x-csrf-token": sessions["root"].csrf_token },
    data: {
      issued_license_id: "il_root_001",
      content_id: "vid_root_content",
      licensor_id: "alice_sub",  // attempt to override; should be ignored
      licensee_id: "bob_sub",
    },
  });
  expect(resp.status()).toBe(200);
  const body = await resp.json();
  expect(body.license.licensor_id).toBe(sessions["root"].user_sub); // not alice
});
```

### Manual QA steps

1. `just up`.
2. As Alice (non-admin), call `POST /ui/licenses/revenue/register-license` with `licensor_id: bob_sub`. Confirm HTTP 403.
3. As root (admin), call the same endpoint without a `licensor_id` field. Confirm HTTP 200 and `license.licensor_id == root_sub`.
4. As root, call with `licensor_id: alice_sub`. Confirm HTTP 200 and `license.licensor_id == root_sub` (body value ignored).
5. Confirm the DynamoDB `license_revenue` table has no records with `licensor_id: alice_sub` from Alice's 403 attempt.

### Observability

Add a structured log line `"licensor_id_spoofing_blocked"` to the 403 case (or before the exception is raised) so that a CloudWatch / Elasticsearch query can surface attempted spoofing events for incident response. Also add a Prometheus counter `license_register_unauthorized_total` to `app/metrics.py`.

Consider adding a background integrity check (e.g., daily Lambda or cron job) that scans the `license_revenue` table for records where `licensor_id` differs from the content owner in the content table, to identify any records written before this fix is deployed.

### Rollback

The change is a one-line auth upgrade (`require_ui_session` → `require_admin_or_root`) plus removal of `body.get("licensor_id")`. Rolling back restores the vulnerable but functional endpoint. Any E2E tests that currently use this endpoint as a non-admin user must be updated to use admin/root credentials before the fix is deployed.

### Effort and sequencing

**Effort: S** (as noted in the ticket). The core fix is two lines in `license_revenue.py`. Auth dependency swap is one line. Tests add ~60 lines. Estimated 1–2 hours.

**Sequencing**: This fix is independent and can be deployed ahead of GAP-0294. However, both should be deployed together in a single security-hardening release to close the combined exploitation surface. Any existing E2E tests that call `register-license` as a non-admin user must be updated simultaneously (change to root session or `Bearer` admin token).
