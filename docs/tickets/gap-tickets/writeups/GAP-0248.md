# GAP-0248: No `case_id` Filter on Admin By-Status Endpoint — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual codebase; no prior investigation doc exists.

## 1. Summary & Classification

**Claim from ticket**: The `GET /ui/kyc/documents/admin/by-status` endpoint accepts no
`case_id` query parameter. Listing all documents for a specific case across all statuses
requires either multiple round-trips (one per status) or a full scan. The fix is to add an
optional `case_id: str | None = Query(default=None)` parameter and apply a client-side
`FilterExpression` on the GSI result.

**Verdict: Claim CONFIRMED.** `app/routers/kyc_documents.py` line 90–99 shows the
endpoint accepts only `status` and `limit`. The service-layer method `list_by_status`
(line 289, `app/services/kyc_document_verification.py`) performs a DynamoDB query on the
`ByStatus` GSI with no `FilterExpression`. No `case_id` parameter exists anywhere in that
call chain.

However, the proposed fix of a **client-side `FilterExpression`** requires clarification:
DynamoDB `FilterExpression` is applied server-side by DynamoDB after fetching up to 1 MB
of results; it does not reduce the number of items scanned or the cost. The CLAUDE.md
project guide specifically warns about this: "DDB FilterExpression doesn't reduce page
size." The correct approach is either (a) a `FilterExpression` in the DynamoDB query that
filters by `case_id` (acceptable when the `ByStatus` partition is small) or (b) using the
existing `ByCase` GSI via `list_documents_for_case` (as described in GAP-0247). The
write-up below provides both and recommends (b) as the primary fix.

- **Severity**: HIGH — the `by-status` endpoint is the only admin-accessible listing
  endpoint for documents. Without `case_id` filtering, admins wishing to review all
  documents for a case must load the entire status partition (up to 500 items per status ×
  5 statuses = up to 2500 documents), either in the browser or via scripted API calls.
- **Source ticket**: KYC-002
- **Owning area**: Backend / KYC document service
- **Related tickets**: GAP-0247 (ExtractionResultsPanel — uses this endpoint), SECOPS-007

## 2. Current-State Investigation (root cause)

### Router (current state)

`app/routers/kyc_documents.py` lines 90–99:

```python
@kyc_documents_router.get("/admin/by-status", response_model=KycDocumentListResponse)
async def admin_list_by_status(
    status: str = Query(..., description="pending | extracted | failed | approved | rejected"),
    limit: int = Query(100, ge=1, le=500),
    _user: AuthenticatedUser = Depends(require_admin_or_root),
) -> KycDocumentListResponse:
    if status not in LISTABLE_STATUSES:
        raise HTTPException(status_code=422, ...)
    items = STORE.list_by_status(status, limit=limit)
    return KycDocumentListResponse(documents=[_out(i, include_match=True) for i in items])
```

There is no `case_id` parameter. The `STORE.list_by_status` call does not pass any
filtering beyond the `status` value.

### Service method (current state)

`app/services/kyc_document_verification.py` lines 289–310:

```python
def list_by_status(self, status: str, *, limit: int = 100) -> list[dict[str, Any]]:
    ...
    kwargs: dict[str, Any] = {
        "IndexName": S.kyc_documents_status_index_name,
        "KeyConditionExpression": Key("status").eq(st),
        "ScanIndexForward": False,
        "Limit": min(limit, 500),
    }
    ...
    resp = self._table.query(**kwargs)
    ...
```

No `FilterExpression`. The method paginates until `limit` items are collected.

### Existing alternative path

`list_documents_for_case(case_id)` (line 275) queries the `ByCase` GSI
(`KeyConditionExpression=Key("case_id").eq(case_id)`) and returns all documents for a
case, without a status filter. It is not exposed on any HTTP endpoint accessible to admins
— only used internally. This is the preferred building block for a clean fix.

### DynamoDB table design (relevant GSIs)

From `scripts/local-ddb-init.py` (as documented), the `kyc_documents` table has at
minimum:

- **`ByStatus` GSI**: PK = `status`, SK = `created_at` (numeric)
- **`ByCase` GSI**: PK = `case_id`, SK = `created_at` (numeric)

A `FilterExpression` on `ByStatus` GSI for `case_id` will scan the entire status partition
and throw away non-matching rows — expensive when a status partition is large. The
`ByCase` GSI is the correct access pattern.

### `_none` sentinel and `case_id` encoding

`app/services/kyc_document_verification.py` line 236 stores `case_id or "_none"` when a
document is uploaded without a case. `public_document_view` (line 564) normalizes this
back: `None if item.get("case_id") == "_none" else item.get("case_id")`. A
`FilterExpression` for a specific case ID will never match the `_none` sentinel, so
documents without a case are naturally excluded — this is the correct behaviour, but it
must be verified in tests to avoid regression if the sentinel string changes.

## 3. Impact / Exploit / Blast Radius

This is a performance and operational correctness gap, not a security vulnerability.

| Area | Impact |
|------|--------|
| **Reviewer workflow** | To see all documents for case `KYC#abc123`, an admin must make five separate API calls (one per status), collect 0–500 items each, and merge client-side. In practice no reviewer does this; they use the queue page, losing case context as described in GAP-0247. |
| **ExtractionResultsPanel (GAP-0247)** | The panel was specified to call `by-status?case_id=`. Without this parameter the panel would load the entire status partition, rendering hundreds of unrelated documents. This makes the integration effectively unusable without the fix here. |
| **Cost (production)** | If `FilterExpression` is naively added without using a separate GSI, every admin document lookup scans a full status partition. At 10k documents per status and five statuses, a single case-detail page load triggers 50k DynamoDB read units. At standard DynamoDB pricing (~$0.00025 per 1k RCU) this is $12.50 per 1000 page loads. |
| **Correctness** | Without a dedicated case filter, documents with `case_id="_none"` (documents uploaded without a case) pollute the result when filtering is applied in-memory. The service normalizes `_none` → `None` in `public_document_view` (line 564), but any in-memory filter must account for this sentinel. |
| **Pagination correctness** | The CLAUDE.md guide warns explicitly: "DDB FilterExpression doesn't reduce page size." A `FilterExpression` on `ByStatus` with a sparse `case_id` filter may return fewer than `Limit` items per page while still having a `LastEvaluatedKey`. The pagination loop in `list_by_status` handles this correctly (it loops until `limit` items are collected or no `LastEvaluatedKey` remains), but this adds latency: O(N/match_rate) DynamoDB pages for a case with few documents in a large status partition. |

## 4. Fix Design (code-level)

### Recommended fix: new `by-case` admin endpoint (supersedes naive `FilterExpression` approach)

This is identical to the backend endpoint described in GAP-0247 § 4a. It is repeated here
because GAP-0248 is the authoritative ticket for this backend change.

Add to `app/routers/kyc_documents.py` (before the existing `admin_list_by_status`):

```python
@kyc_documents_router.get(
    "/admin/by-case/{case_id}",
    response_model=KycDocumentListResponse,
)
async def admin_list_documents_for_case(
    case_id: str,
    _user: AuthenticatedUser = Depends(require_admin_or_root),
) -> KycDocumentListResponse:
    """Return all documents for a specific case with full match results (admin view).

    Uses the ByCase GSI — O(docs_per_case) DynamoDB reads, not O(docs_per_status).
    """
    items = STORE.list_documents_for_case(case_id)
    return KycDocumentListResponse(
        documents=[_out(i, include_match=True) for i in items]
    )
```

**Dev/Prod parity (SECOPS-007)**: `STORE.list_documents_for_case` queries DynamoDB via the
`ByCase` GSI in both environments. In dev, DynamoDB Local (`localhost:8001`) is used; in
production, the real DynamoDB service. No environment-specific branching is introduced.

### Secondary fix: add `case_id` to `by-status` (for backward-compat / other consumers)

If existing callers depend on the `by-status` endpoint and filtering by both status and
case is needed, add the optional parameter with a `FilterExpression`:

```python
@kyc_documents_router.get("/admin/by-status", response_model=KycDocumentListResponse)
async def admin_list_by_status(
    status: str = Query(...),
    limit: int = Query(100, ge=1, le=500),
    case_id: str | None = Query(default=None),
    _user: AuthenticatedUser = Depends(require_admin_or_root),
) -> KycDocumentListResponse:
    if status not in LISTABLE_STATUSES:
        raise HTTPException(status_code=422, detail={"code": "invalid_status", ...})
    items = STORE.list_by_status(status, limit=limit, case_id=case_id)
    return KycDocumentListResponse(documents=[_out(i, include_match=True) for i in items])
```

And update `list_by_status` in the service:

```python
def list_by_status(
    self,
    status: str,
    *,
    limit: int = 100,
    case_id: str | None = None,
) -> list[dict[str, Any]]:
    st = str(status or "").strip()
    if st not in LISTABLE_STATUSES:
        raise KycDocumentValidationError("invalid_status")
    items: list[dict[str, Any]] = []
    last_key: dict | None = None
    kwargs_base: dict[str, Any] = {
        "IndexName": S.kyc_documents_status_index_name,
        "KeyConditionExpression": Key("status").eq(st),
        "ScanIndexForward": False,
        "Limit": min(limit, 500),
    }
    # FilterExpression: applied server-side by DynamoDB, does NOT reduce reads,
    # but does reduce response payload and in-memory processing.
    # Normalize sentinel value so stored "_none" is handled correctly.
    if case_id:
        from boto3.dynamodb.conditions import Attr
        kwargs_base["FilterExpression"] = Attr("case_id").eq(case_id)
    while True:
        kwargs = dict(kwargs_base)
        if last_key:
            kwargs["ExclusiveStartKey"] = last_key
        resp = self._table.query(**kwargs)
        items.extend(resp.get("Items", []))
        last_key = resp.get("LastEvaluatedKey")
        if not last_key or len(items) >= limit:
            break
    return items[:limit]
```

**Important caveat**: This filter is safe for small-to-medium status partitions but will
degrade at scale. For the `ExtractionResultsPanel` use case, the `by-case` endpoint
(recommended fix above) is strongly preferred.

### Frontend API wrapper

The frontend `kycDocuments.ts` already has `listKycDocumentsByStatus`. If the `case_id`
parameter is added to `by-status`, update the wrapper:

```ts
export const listKycDocumentsByStatus = (
  status: KycDocumentStatus,
  limit = 100,
  caseId?: string,
) =>
  api.get<KycDocumentListResponse>("/ui/kyc/documents/admin/by-status", {
    status,
    limit: String(limit),
    ...(caseId ? { case_id: caseId } : {}),
  });
```

## 5. Testing, Verification & Rollout

### Regression test — fails before / passes after

**pytest offline** (`tests/test_kyc_documents_by_status_case_filter.py`):

```python
def test_by_status_with_case_id_filter(client, admin_headers, seeded_docs_multi_case):
    """list_by_status with case_id only returns docs for that case."""
    target_case, other_case = seeded_docs_multi_case
    resp = client.get(
        "/ui/kyc/documents/admin/by-status",
        params={"status": "extracted", "case_id": target_case},
        headers=admin_headers,
    )
    assert resp.status_code == 200
    docs = resp.json()["documents"]
    # All returned documents must belong to the target case
    assert all(d["case_id"] == target_case for d in docs)
    # Documents from other_case must NOT appear
    assert not any(d["case_id"] == other_case for d in docs)

def test_by_status_without_case_id_unchanged(client, admin_headers, seeded_docs_multi_case):
    """Existing behaviour: by-status without case_id still returns all docs."""
    resp = client.get(
        "/ui/kyc/documents/admin/by-status",
        params={"status": "extracted"},
        headers=admin_headers,
    )
    assert resp.status_code == 200
    # No regression: returns docs from both cases
    case_ids = {d["case_id"] for d in resp.json()["documents"]}
    assert len(case_ids) > 1

def test_by_case_endpoint_uses_gsi(client, admin_headers, seeded_kyc_case_with_docs):
    """The by-case endpoint returns all statuses for the case via ByCase GSI."""
    case_id = seeded_kyc_case_with_docs["case_id"]
    resp = client.get(
        f"/ui/kyc/documents/admin/by-case/{case_id}",
        headers=admin_headers,
    )
    assert resp.status_code == 200
    docs = resp.json()["documents"]
    assert len(docs) >= 1
    assert all(d["case_id"] == case_id for d in docs)
```

**Before fix**: `GET /ui/kyc/documents/admin/by-status?status=extracted&case_id=X`
ignores the `case_id` parameter and returns all extracted documents. The dedicated
`by-case` endpoint returns 404.

**After fix**: All three tests pass.

### Additional edge cases

**Empty status partition**: When `list_by_status` is called with a `case_id` filter and
no documents match, the endpoint must return `{"documents": []}` with HTTP 200 (not 404).
The current `list_by_status` already returns an empty list in this scenario; the new
`FilterExpression` variant preserves this behaviour.

**Case ID with special characters**: KYC case IDs are generated as
`f"kyc_{uuid4().hex[:16]}"` (service code), so they contain only lowercase hex and
underscore. No URL-encoding issues arise. However the `case_id` path parameter in the
`by-case/{case_id}` endpoint should be validated to prevent injection — this is handled
implicitly by DynamoDB (it treats `case_id` as a string literal in the key condition).
