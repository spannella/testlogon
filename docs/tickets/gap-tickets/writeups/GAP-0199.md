# GAP-0199: No Admin-Global Dispute Arbitration Endpoint — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; claim confirmed with one important nuance.

## 1. Summary & Classification

**Plain-English statement**: The FIN-011 spec requires two admin-global endpoints — `GET /ui/admin/collaboration-disputes` (list all open disputes across all collaborations) and `POST /ui/admin/collaboration-disputes/{dispute_id}/arbitrate` (admin-force-resolve any dispute without needing its `collab_id` in the URL). Neither endpoint exists. Admins can only reach disputes through `GET /ui/collaborations/{collab_id}/disputes`, which requires knowing the collaboration ID in advance. Because there is no cross-collaboration scan at the route level, disputes can go unnoticed and unresolved indefinitely.

**One nuance the ticket does not mention**: The `app/services/collaboration_revenue.py:553` `list_disputes` function already supports `collaboration_id=None` (the global query path via the `ByDisputeStatus` GSI). The service layer is therefore complete. The gap is purely a missing router layer.

- **Severity**: HIGH
- **Source ticket**: FIN-011
- **Status**: Open — service complete, router endpoints absent
- **Owning area**: Collaboration Revenue / Admin Arbitration
- **Verdict**: Confirmed. `grep -rn "/ui/admin/collaboration-disputes"` across `app/routers/` returns zero results. The existing route `GET /{collab_id}/disputes` (line 495 of `collaborations.py`) and `POST /{collab_id}/disputes/{dispute_id}/resolve` (line 511) are scoped to participants of a specific collaboration.
- **Impact**: Admins have no first-class UI or API path to discover all open disputes. A creator or collaborator who disputes a revenue split and gets no response from their partner is left with no escalation path. Disputes age in the queue silently.
- **Related tickets**: FIN-011 (parent), GAP-0200 (sibling), SECOPS-007

## 2. Current-State Investigation (root cause)

### Service layer — already supports global queries

`app/services/collaboration_revenue.py` line 553–585:

```python
def list_disputes(
    collaboration_id: Optional[str] = None,
    status: Optional[str] = "open",
    limit: int = 50,
) -> List[Dict[str, Any]]:
    if collaboration_id:
        # scoped query: SK begins_with DISPUTE#
    else:
        # GLOBAL query via ByDisputeStatus GSI
        target_status = status or "open"
        resp = T.collaboration_agreements.query(
            IndexName="ByDisputeStatus",
            KeyConditionExpression=Key("gsi_dispute_pk").eq(
                f"DISPUTE_STATUS#{target_status}"
            ),
            ScanIndexForward=False,
            Limit=int(limit),
        )
```

The `ByDisputeStatus` GSI is populated in `file_dispute` (line 472):
```python
"gsi_dispute_pk": "DISPUTE_STATUS#open",
"gsi_dispute_sk": now,
```
and updated in `resolve_dispute` (line 533) to `DISPUTE_STATUS#{new_status}`.

The `resolve_dispute` service function also already accepts `is_admin=True` which bypasses the participant check (line 509):
```python
if not is_admin:
    _require_participant(collab, resolved_by)
```

### Router layer — two gaps

`app/routers/collaborations.py` (prefix `/ui/collaborations`):

- **Line 495**: `GET /{collab_id}/disputes` → calls `cr.list_disputes(collaboration_id=collab_id, ...)`. Allows admin or participant, but requires `collab_id` in the URL path.
- **Line 511**: `POST /{collab_id}/disputes/{dispute_id}/resolve` → calls `cr.resolve_dispute(...)` with `is_admin=_is_admin(ctx)`. Also requires `collab_id`.

The spec asks for:
1. `GET /ui/admin/collaboration-disputes` — scoped to `require_admin_or_root`, calls `cr.list_disputes(collaboration_id=None, status=...)`.
2. `POST /ui/admin/collaboration-disputes/{dispute_id}/arbitrate` — scoped to `require_admin_or_root`, resolves a dispute without requiring `collab_id` (must look up the dispute's own `collaboration_id` from the dispute record).

The second endpoint requires the arbitrate path to resolve the dispute given only a `dispute_id`. The current `resolve_dispute` service function signature is:
```python
def resolve_dispute(dispute_id, collaboration_id, resolved_by, resolution, accept, *, is_admin)
```
It still requires `collaboration_id` to look up the dispute. A helper is needed to resolve a dispute by its ID alone (scanning the dispute record for its embedded `collaboration_id`).

### Why is there no `dispute_id` lookup function?

Disputes are stored under `PK=collaboration_id, SK=DISPUTE#{ts}#{dispute_id}`. Because the table PK is `collaboration_id`, there is no single-table lookup by `dispute_id` alone without a GSI or a scan. The `ByDisputeStatus` GSI does return full dispute records including the `collaboration_id` attribute, so the arbitrate endpoint can:
1. Query `ByDisputeStatus` (all statuses) or use a dedicated `ByDisputeId` GSI approach.
2. Alternatively, the `list_disputes(None)` global call already returns full records with `collaboration_id` embedded; the arbitrate endpoint can call `list_disputes(None, status=None)` with a filter, but this is O(all disputes).

The practical solution is to add a `get_dispute_global` helper that queries the `ByDisputeStatus` GSI without a status filter, looking for the specific `dispute_id`:

```python
def get_dispute_global(dispute_id: str) -> Optional[Dict[str, Any]]:
    """Look up a dispute by ID across all collaborations (admin use only)."""
    for status in ("open", "counter", "resolved", "admin_review"):
        resp = T.collaboration_agreements.query(
            IndexName="ByDisputeStatus",
            KeyConditionExpression=Key("gsi_dispute_pk").eq(
                f"DISPUTE_STATUS#{status}"
            ),
        )
        for item in resp.get("Items", []):
            if item.get("dispute_id") == dispute_id:
                return item
    return None
```

For production scale, a dedicated `ByDisputeId` GSI would be preferable, but the status-enumerate approach works correctly for the current data volume and is zero-migration.

## 3. Impact / Exploit / Blast Radius

### Security analysis

Both new endpoints are gated by `require_admin_or_root`. There is no privilege-escalation risk in adding them. However, there is a subtle concern: the arbitrate endpoint force-resolves a dispute with `accept=True` (which always sets `new_status = "resolved"`, line 518 of `resolve_dispute`), and this triggers an update to the split record's `dispute_status`. An admin could arbitrarily mark any dispute resolved. This is by design (admin arbitration), but the action must be logged.

### Operational impact

Without the global endpoints, the only way to discover disputes is:
1. An admin must know the `collab_id` in advance (perhaps from a user support ticket).
2. Then call `GET /ui/collaborations/{collab_id}/disputes` as an authenticated admin (the `_is_admin` check on line 505 allows this).

This is cumbersome. Every support ticket involving a collaboration dispute requires the admin to discover the `collab_id` through user lookups before they can view or resolve the dispute.

**Financial impact**: Disputes block revenue resolution for participants. A split stuck in `dispute_status = "disputed"` means the revenue ledger is in limbo; neither participant can accurately report earnings until the dispute is resolved.

## 4. Fix Design (code-level)

### 4a. Service helper (`app/services/collaboration_revenue.py`)

Add after `list_disputes`:

```python
def get_dispute_global(dispute_id: str) -> Optional[Dict[str, Any]]:
    """Look up a dispute by dispute_id across all collaborations.
    Iterates ByDisputeStatus partitions. For admin use only.
    """
    for status_val in ("open", "counter", "admin_review", "resolved"):
        resp = T.collaboration_agreements.query(
            IndexName="ByDisputeStatus",
            KeyConditionExpression=Key("gsi_dispute_pk").eq(
                f"DISPUTE_STATUS#{status_val}"
            ),
        )
        for item in resp.get("Items", []):
            if item.get("dispute_id") == dispute_id:
                return item
    return None
```

### 4b. New router file (`app/routers/admin_collaborations.py`)

Create a dedicated admin router rather than adding to the existing `collaborations.py`, to keep admin and user routes clearly separated:

```python
"""Admin global dispute arbitration endpoints (FIN-011 / GAP-0199)."""
from __future__ import annotations

from typing import Optional
from fastapi import APIRouter, Depends, HTTPException, Query
from app.auth.policy import require_admin_or_root
from app.auth.deps import AuthenticatedUser
import app.services.collaboration_revenue as cr
from app.routers.collaborations import _dispute_out  # reuse existing serialiser

router = APIRouter(prefix="/ui/admin/collaboration-disputes", tags=["admin-collaborations"])


@router.get("")
def list_all_disputes(
    status: Optional[str] = Query("open"),
    limit: int = Query(50, ge=1, le=200),
    admin: AuthenticatedUser = Depends(require_admin_or_root),
):
    """List all disputes across every collaboration (admin queue)."""
    items = cr.list_disputes(collaboration_id=None, status=status, limit=limit)
    return {"items": [_dispute_out(i).model_dump() for i in items], "count": len(items)}


@router.post("/{dispute_id}/arbitrate")
def arbitrate_dispute(
    dispute_id: str,
    body: dict,
    admin: AuthenticatedUser = Depends(require_admin_or_root),
):
    """Admin force-resolve any dispute by dispute_id without needing collab_id."""
    resolution = body.get("resolution", "")
    accept = body.get("accept", True)  # True = resolve, False = escalate to admin_review

    dispute = cr.get_dispute_global(dispute_id)
    if not dispute:
        raise HTTPException(404, "Dispute not found")

    collab_id = dispute.get("collaboration_id")
    if not collab_id:
        raise HTTPException(500, "Dispute record missing collaboration_id")

    try:
        result = cr.resolve_dispute(
            dispute_id=dispute_id,
            collaboration_id=collab_id,
            resolved_by=admin.sub,
            resolution=resolution,
            accept=accept,
            is_admin=True,
        )
    except KeyError as exc:
        raise HTTPException(404, f"Not found: {exc}")

    return {"ok": True, "dispute": _dispute_out(result).model_dump()}
```

### 4c. Register in `app/main.py`

```python
from app.routers.admin_collaborations import router as admin_collabs_router
# ...
app.include_router(admin_collabs_router)
```

### 4d. Dev/Prod parity (SECOPS-007)

The new router uses `require_admin_or_root` from `app/auth/policy.py` which resolves role from the same JWT (cookie or Bearer token) used throughout the app. No dev-mode bypass needed. The `ByDisputeStatus` GSI is on `T.collaboration_agreements` which maps to DynamoDB Local in dev and live DynamoDB in prod — same code path, no flag gating. No new tables or GSIs are required.

### 4e. Alternatives considered

- **Add global endpoints to existing `collaborations.py`**: avoids a new file, but `collaborations.py` is already 534 lines and the prefix is `/ui/collaborations` which would force an awkward path like `/ui/collaborations/admin/global-disputes`.
- **Dedicated `ByDisputeId` GSI on `collaboration_agreements`**: cleaner O(1) lookup, but requires a DynamoDB migration. The multi-partition scan approach works correctly for <10K disputes (the expected order of magnitude at launch).

### Rollout

**Effort**: S (1–2 days). Service helper is minimal; router is ~50 lines.

**Sequencing**: Can be shipped independently of GAP-0200 and the other FIN-011 gaps. There are no schema changes and no DynamoDB migrations. The `ByDisputeStatus` GSI already exists (populated by `file_dispute` at line 472 of `collaboration_revenue.py`).

**Rollback**: Remove `admin_collabs_router` registration from `main.py` and delete the `admin_collaborations.py` router file; no DynamoDB changes. The existing scoped dispute endpoints (`GET /{collab_id}/disputes`, `POST /{collab_id}/disputes/{dispute_id}/resolve`) are unaffected.

**Risk**: Low — additive. The service layer's `is_admin=True` path (`resolve_dispute(..., is_admin=True)`) was already exercised by the existing `POST /{collab_id}/disputes/{dispute_id}/resolve` router endpoint (line 511 of `collaborations.py`), which passes `is_admin=_is_admin(ctx)`. The new arbitrate endpoint uses the same service call; the only novelty is the `get_dispute_global` helper.

### CSRF note

The new router uses `require_admin_or_root` from `app/auth/policy.py` rather than `require_ui_session` directly. The `require_admin_or_root` dependency calls `get_authenticated_user` which supports both cookie-based and Bearer-token auth. For cookie-auth admin calls from the browser, the frontend must include the `x-csrf-token` header — the same pattern already used by all other `/ui/` mutation endpoints. The Playwright E2E test `page.request.post(...)` call should include `"x-csrf-token": sessions["charlie_admin"].csrf_token` to match this requirement.

### Future improvement: `ByDisputeId` GSI

The `get_dispute_global` helper currently iterates up to four DynamoDB query operations (one per status partition). This is acceptable for the current dispute volume but should be replaced by a `ByDisputeId` GSI on `collaboration_agreements` before the dispute count exceeds a few thousand. The GSI would use `dispute_id` as the GSI PK and allow O(1) lookup. Adding the GSI and backfilling `dispute_id` for existing records can be done as a follow-up task with no change to the API contract.
