# GAP-0217: Platform-level country block list is env-var only — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code before writing.

## 1. Summary & Classification

**Plain-English statement**: The platform-wide "always block these countries, regardless of per-content settings" list (`geo_platform_block_countries`) lives exclusively in the `GEO_PLATFORM_BLOCK_COUNTRIES` environment variable. There is no admin UI, no database-backed store, and no runtime mutation path. Changing the platform block list requires a full redeployment of the backend, which introduces operational risk, creates a multi-minute gap during rollout, and makes it impossible for a ROOT/ADMIN operator to respond to a geo-compliance incident in real time without an infrastructure engineer.

**Severity**: HIGH — Compliance and legal incidents may require immediate country-level blocks (sanctions lists, OFAC updates, emergency injunctions). An env-var-only path cannot satisfy the "block within minutes" SLA that most compliance programmes require.

**Status**: Open. Source ticket: GEO-001. Owning area: Geo-blocking / Platform admin. Related: GAP-0216 (catalog geo enforcement missing), SECOPS-007 (dev/prod parity).

**Claim verdict**: Confirmed. `app/core/settings.py:1762` contains:
```python
geo_platform_block_countries: str = os.environ.get("GEO_PLATFORM_BLOCK_COUNTRIES", "")
```
`app/services/geo_check.py:53` reads only this setting:
```python
platform_blocked = _parse_csv(getattr(S, "geo_platform_block_countries", ""))
```
There is no DynamoDB table, no admin endpoint, and no hot-reload path. The original claim is accurate.

**Related tickets**: GAP-0216 (catalog enforcement gap), SECOPS-007 (parity).

## 2. Current-State Investigation (root cause)

### Where the platform block is consumed

`app/services/geo_check.py` applies the platform block before any per-content geo check:

```python
# geo_check.py:52-65
platform_blocked = _parse_csv(getattr(S, "geo_platform_block_countries", ""))
if platform_blocked:
    if country is None:
        country = lookup_country(ip)
    if country and country in platform_blocked:
        raise HTTPException(
            status_code=403,
            detail={
                "code": "geo_blocked",
                "message": "This content is not available in your region.",
                "country": country,
            },
        )
```

This is correct logic — the platform block is enforced first, regardless of the per-content `geo_mode`/`geo_countries`. However, `platform_blocked` is derived from:

```python
# settings.py:1762
geo_platform_block_countries: str = os.environ.get("GEO_PLATFORM_BLOCK_COUNTRIES", "")
```

`S` (the settings singleton) is loaded once at process startup from environment variables. `getattr(S, "geo_platform_block_countries", "")` returns a frozen string for the lifetime of the process. There is no mechanism to refresh it without restarting uvicorn.

### What is missing

1. **DynamoDB store**: No table row that holds the current platform block list.
2. **Admin endpoint**: No `PATCH /ui/admin/geo/platform-block` or equivalent.
3. **In-process cache with TTL**: No periodic reload or watch path.
4. **Audit trail**: No log of who changed the list or when.

### Dev vs prod comparison

In dev, `GEO_PLATFORM_BLOCK_COUNTRIES` is typically empty (not set in `.env.local.example`), so the block is effectively disabled. In prod, operators set it at deploy time. The gap is present in both environments: there is no runtime mutability in either.

This is a SECOPS-007 concern: the dev stack should mirror the prod capability so operators can validate incident-response procedures without a prod deployment.

## 3. Impact / Exploit / Blast Radius

**Who is affected**: All content accessed through any endpoint that calls `check_geo_access` (video, broadcast, and — after GAP-0216 is fixed — catalog). The platform block is the outermost guard.

**Compliance scenario** (worst case): OFAC adds a new country to its SDN list at 11 PM. The compliance team needs to block all content delivery to that country within 30 minutes. Under the current design, the process is:
1. Update `GEO_PLATFORM_BLOCK_COUNTRIES` in the production environment secrets store.
2. Trigger a full backend redeployment (ECS task replacement, Lambda redeploy, etc.).
3. Wait for rolling deployment to complete (typically 3–15 minutes for a medium-sized fleet).
4. Verify enforcement.

During the deployment window, the new country is unblocked. In an OFAC context this is a potential regulatory violation.

**Operational blast radius**: Any mistake in the env-var value (e.g., typo like `"US,CN,"` with a trailing comma — note that `_parse_csv` handles trailing commas correctly, but `"US,CN;RU"` would not split correctly) silently misconfigures global blocking. There is no validation layer and no history of changes.

**Secondary blast radius**: If `GEO_PLATFORM_BLOCK_COUNTRIES` is ever added to an encrypted secrets manager (AWS Secrets Manager, SSM Parameter Store), a rotation or emergency update still requires a restart because the value is bound at startup.

## 4. Fix Design (code-level)

### Overview

Introduce a DynamoDB-backed platform geo block list with:
- A single DDB record as the store (fits in the existing `geo_rules` table or the `settings` table, whichever exists).
- A ROOT-only admin endpoint to read/write the list.
- An in-process TTL cache (60–120 seconds) in `geo_check.py` so lookups remain fast.
- The env-var retained as a bootstrap override (for cold-start scenarios where DDB is unavailable).

### Step 1 — DynamoDB record

Store the list in an existing config table. If none exists, use the `geo_rules` table that already exists for per-content rules. Key: `pk = "PLATFORM"`, `sk = "GEO_BLOCK"`. Schema:

```python
{
    "pk": "PLATFORM",
    "sk": "GEO_BLOCK",
    "countries": ["CN", "RU", "KP"],   # list of ISO codes
    "updated_at": 1717200000,
    "updated_by": "root.admin@testdev.local",
}
```

No new table is required.

### Step 2 — Root admin endpoints

Add to a new or existing admin router (e.g., `app/routers/admin_geo.py`):

```python
@router.get("/ui/root/geo/platform-block")
async def get_platform_block(ctx=Depends(require_root_session)):
    """Return current platform-level blocked countries."""
    item = _load_platform_block_from_ddb()
    env_countries = _parse_csv(getattr(S, "geo_platform_block_countries", ""))
    return {
        "countries": item.get("countries", []),
        "env_override": sorted(env_countries),
        "updated_at": item.get("updated_at"),
        "updated_by": item.get("updated_by"),
    }

@router.put("/ui/root/geo/platform-block")
async def set_platform_block(body: PlatformGeoBlockIn, ctx=Depends(require_root_session)):
    """Set the platform-level blocked country list. ROOT only."""
    validated = _validate_country_codes(body.countries)
    T.geo_rules.put_item(Item={
        "pk": "PLATFORM",
        "sk": "GEO_BLOCK",
        "countries": validated,
        "updated_at": now_ts(),
        "updated_by": ctx["user_sub"],
    })
    _platform_block_cache.invalidate()
    audit_event("platform_geo_block_updated", ctx["user_sub"], request,
                outcome="success", countries=validated)
    return {"ok": True, "countries": validated}
```

Where `PlatformGeoBlockIn` is a Pydantic model requiring a `countries: List[str]` field with ISO-code validation (reuse `GeoRestrictionRequest`-style validators from `app/models.py:3207–3223`).

### Step 3 — In-process TTL cache in geo_check.py

Replace the direct `getattr(S, ...)` read with a cached loader:

```python
# geo_check.py additions

import time
from threading import Lock

_PLATFORM_BLOCK_CACHE_TTL = 60  # seconds
_platform_block_cache: set[str] = set()
_platform_block_cache_ts: float = 0.0
_platform_block_lock = Lock()


def _get_platform_blocked_countries() -> set[str]:
    """Return the union of env-var block list and DDB block list, cached for 60s."""
    global _platform_block_cache, _platform_block_cache_ts
    now = time.monotonic()
    with _platform_block_lock:
        if now - _platform_block_cache_ts < _PLATFORM_BLOCK_CACHE_TTL:
            return _platform_block_cache
        # Refresh from DDB
        try:
            from app.core.tables import T
            item = T.geo_rules.get_item(Key={"pk": "PLATFORM", "sk": "GEO_BLOCK"}).get("Item") or {}
            ddb_countries = set(item.get("countries") or [])
        except Exception:
            ddb_countries = set()
        env_countries = _parse_csv(getattr(S, "geo_platform_block_countries", ""))
        _platform_block_cache = ddb_countries | env_countries
        _platform_block_cache_ts = now
        return _platform_block_cache
```

Replace `check_geo_access`'s direct reference (line 53) with:

```python
# Before fix:
platform_blocked = _parse_csv(getattr(S, "geo_platform_block_countries", ""))

# After fix:
platform_blocked = _get_platform_blocked_countries()
```

### Dev/Prod parity (SECOPS-007)

The same DDB read path runs in dev (against DynamoDB Local on port 8001) and prod (against AWS DynamoDB). No `if S.dev_mode` branch is needed — the infrastructure mock is transparent. In dev, operators can call the `PUT /ui/root/geo/platform-block` endpoint to seed the block list and test incident-response procedures without touching env vars or restarting processes. The 60-second TTL means changes are visible within 1 minute in both environments.

### Backward compatibility

The env-var `GEO_PLATFORM_BLOCK_COUNTRIES` remains honoured (unioned with the DDB list). An empty DDB record is equivalent to the current state — env-var-only behaviour is preserved for any deployment that has not yet used the new admin endpoint.

### Alternatives considered

- **Redis/ElastiCache for the cache**: Adds an operational dependency. The 60-second TTL on the DDB path is acceptable for a block-list that does not need sub-second propagation.
- **Server-Sent Events or WebSocket push to invalidate cache instantly**: Overkill for a compliance block list; 60-second propagation is within any reasonable SLA.
- **Feature flag in S**: The env-var already serves this role for initial config; the DDB-backed path is the runtime update mechanism.

### Metrics / observability

- Existing `geo_blocked` 403 detail field distinguishes blocks. Add counter `platform_geo_block_cache_refresh_total` and `platform_geo_block_ddb_error_total` to catch DDB failures during refresh.
- Alert if `platform_geo_block_ddb_error_total` increases while `GEO_PLATFORM_BLOCK_COUNTRIES` is empty — this means the platform block is silently unavailable.

### Rollout

- **Effort**: M (medium) — ~60 lines of new code: admin router, cache logic, Pydantic model, audit call.
- **Backward compat**: Additive. Env-var fallback ensures zero regression for existing deployments.
- **Migration**: No DDB table migration required (uses existing `geo_rules` table).
- **Rollback**: Remove the new admin router and revert `check_geo_access` to the direct `getattr(S,...)` call. The env-var mechanism is unchanged.
- **Risk**: The only new failure mode is a DDB read error in the TTL refresh. The cache falls back to the env-var value in that case (fail-safe). Low risk overall.
- **Sequencing**: Can ship independently. Should be deployed before or alongside GAP-0216 fix so the unified `check_geo_access` call covers all content types.

### Edge case: env-var and DDB list both empty

When both sources are empty, `_get_platform_blocked_countries()` returns an empty set, and `check_geo_access` skips the platform block (line 54: `if platform_blocked:` is `False`). This is identical to the current behaviour and requires no special handling.

### Edge case: DDB unavailable at startup (cold start)

If DynamoDB is temporarily unreachable when `_get_platform_blocked_countries()` is first called, the `except Exception: ddb_countries = set()` handler falls back to the env-var value only. The cache TTL timestamp is not updated in the error path (it stays at `0.0`), so the next call will retry immediately. This ensures DDB is retried without requiring a process restart. However, if DDB is down for an extended period, the platform block list may be stale (env-var only). An alert on `platform_geo_block_ddb_error_total` handles this scenario.

### Note on `_parse_csv` handling

`geo_check.py:117–119`:
```python
def _parse_csv(value: str) -> set:
    return {v.strip().upper() for v in (value or "").split(",") if v.strip()}
```
This correctly handles empty strings, trailing commas, and mixed-case codes. The DDB `countries` list (already a Python list of uppercase strings) does not need `_parse_csv` — it is converted directly to a `set`. The union operation `ddb_countries | env_countries` is type-safe since both are `set[str]`.
