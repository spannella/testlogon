# GAP-0297: `syndicate_content` table renamed `syndicate_open_licensing`; `CREATOR_SYND#` index missing from listing queries — Remediation Write-up

> ~5 pages. Fix-oriented. No investigation doc exists; the claim is verified directly against the codebase.

## 1. Summary & Classification

**Bug statement:** The original LICENSE-005 ticket specified a `syndicate_content` DynamoDB table with a `CREATOR_SYND#{user_id}/CONTENT#{content_id}` access pattern and a single GSI. The implementation uses a table named `syndicate_open_licensing` with a compatible schema, and the `CREATOR_SYND#` access pattern is stored as a GSI attribute on each item but the `list_syndicate_content` query function never uses that GSI — it performs a full partition scan (fetching all `CONTENT#` records for a syndicate) and filters in Python, making creator-scoped listing O(N-content) rather than O(N-creator-content).

- **Severity:** HIGH
- **Source ticket:** LICENSE-005
- **Status:** Open — naming divergence is already deployed; the GSI-scan gap is the actionable deficiency
- **Owning area:** Syndicate Open Licensing / DynamoDB performance
- **Claim verdict:** PARTIALLY CONFIRMED (with correction). The ticket's claim that "no `CREATOR_SYND#` index pattern exists in the implementation" is **incorrect** — the GSI attribute _is_ written to DynamoDB items. What is missing is that `list_syndicate_content` never _queries_ that GSI; it always does a full-partition scan and Python-side filters. The naming difference (`syndicate_open_licensing` vs `syndicate_content`) is a cosmetic divergence that is acceptable once documented.

**Related tickets:** LICENSE-005 (parent); GAP-0024 (GSI fallback scan pattern); SECOPS-007 (dev/prod parity).


## 2. Current-State Investigation (root cause)

### 2.1 Table naming

The table is named `syndicate_open_licensing` (configured via `S.syndicate_open_licensing_table_name`, `app/core/settings.py`). The DynamoDB table definition in `scripts/local-ddb-init.py:1699-1706` creates the table with GSI1 (`GSI1PK` / `GSI1SK`).

The ticket's `CREATOR_SYND#{user_id}/CONTENT#{content_id}` pattern corresponds to the item written in `app/services/syndicate_open_licensing.py:277-278`:

```python
# Line 276-278
"GSI1PK": f"SYND_CREATOR#{syndicate_id}#{creator_sub}",
"GSI1SK": registered_at,
```

The partition key used is `SYND_CREATOR#{syndicate_id}#{creator_id}` (not `CREATOR_SYND#{user_id}` as the ticket stated). The key name difference is cosmetic; the combination of syndicate + creator is correct.

### 2.2 The actual gap: `list_syndicate_content` ignores GSI1

**File:** `app/services/syndicate_open_licensing.py:511-533`

```python
def list_syndicate_content(
    *,
    syndicate_id: str,
    creator_id: Optional[str] = None,
    include_exempt: bool = True,
) -> List[Dict[str, Any]]:
    """List content registered under syndicate open licensing."""
    items = _list_registered_content(syndicate_id)   # <-- always full scan
    out: List[Dict[str, Any]] = []
    for item in items:
        if creator_id and item.get("creator_id") != creator_id:  # <-- Python filter
            continue
        ...
```

`_list_registered_content` (line 347-353) queries only on the partition key `SYND#{syndicate_id}` with a `sk begins_with CONTENT#`:

```python
def _list_registered_content(syndicate_id: str) -> List[Dict[str, Any]]:
    resp = T.syndicate_open_licensing.query(
        KeyConditionExpression=Key("pk").eq(f"SYND#{syndicate_id}")
        & Key("sk").begins_with("CONTENT#"),
    )
    return resp.get("Items", [])
```

This always fetches every content record in the syndicate, regardless of `creator_id`. For a large syndicate with thousands of registered content items, most of the items fetched will be discarded by the Python-side filter. There is also a silent pagination issue: DynamoDB's `query()` call here has no `ExclusiveStartKey` loop, so it fetches only the first 1 MB of results. Items beyond the first page are silently dropped (noted in CLAUDE.md as a known pattern under "DDB FilterExpression doesn't reduce page size").

The correct approach is to use GSI1 when `creator_id` is provided, so DynamoDB only returns the relevant items.

### 2.3 Router exposure

The router (`app/routers/syndicate_open_licensing.py:100-103`) calls `list_syndicate_content` without passing `creator_id`:

```python
@syndicate_open_licensing_router.get("/{syndicate_id}/content")
def list_content(syndicate_id: str, session: Dict[str, Any] = Depends(require_ui_session)):
    items = svc.list_syndicate_content(syndicate_id=syndicate_id)
    return {"items": [SyndicateOpenLicensingContentOut(**i) for i in items]}
```

There is no query parameter to filter by creator; all callers always receive the full list, then do any filtering client-side.

### 2.4 Dev vs prod

Both dev (DynamoDB Local) and production (AWS DynamoDB) are affected equally because `list_syndicate_content` never issues a GSI query. The table definition in `local-ddb-init.py` correctly creates GSI1 with `attr_types={"GSI1SK": "N"}`, so the GSI is available — it simply goes unused.


## 3. Impact / Exploit / Blast Radius

**Performance regression:** For a syndicate with N content items from M creators, a creator-filtered listing currently fetches all N items from DynamoDB and discards (N − creator_items) in Python. For a busy syndicate (e.g., 10,000 registered items), this generates 10,000 DynamoDB read units per request instead of the expected O(creator_items). This can cause throttling under moderate load.

**Correctness/data loss:** Because there is no pagination loop, `_list_registered_content` silently returns only the first DynamoDB page (≤1 MB ≈ ~2,000-5,000 items depending on record size). Syndicates with more registered content than fits on one page will have items silently omitted from all listing results — including `enable_open_licensing`'s `_reconcile_all_content` call. This means auto-licensing will be **skipped** for content beyond the first DynamoDB page when open licensing is first enabled. Existing licensees are not affected; only newly-eligible content/members after the pagination boundary are missed.

**Financial impact:** Missed auto-licenses mean licensors do not receive revenue splits for content that should have been licensed. This is a silent correctness failure with potential financial consequences.

**Blast radius:** Any syndicate with a large content registry (thousands of items per syndicate). Small syndicates (< ~2,000 content items) are unaffected by the pagination issue but still incur unnecessary read costs.


## 4. Fix Design (code-level)

### 4.1 Use GSI1 when creator_id is provided

```python
# app/services/syndicate_open_licensing.py

from boto3.dynamodb.conditions import Key

def list_syndicate_content(
    *,
    syndicate_id: str,
    creator_id: Optional[str] = None,
    include_exempt: bool = True,
) -> List[Dict[str, Any]]:
    """List content registered under syndicate open licensing.

    When creator_id is provided, queries GSI1 for efficient creator-scoped
    retrieval. Otherwise performs a full partition scan with pagination.
    """
    if creator_id:
        items = _list_content_by_creator(syndicate_id, creator_id)
    else:
        items = _list_registered_content_paginated(syndicate_id)

    out: List[Dict[str, Any]] = []
    for item in items:
        if not include_exempt and item.get("exempt"):
            continue
        out.append({
            "content_id": item.get("content_id", ""),
            "content_type": item.get("content_type", ""),
            "creator_id": item.get("creator_id", ""),
            "registered_at": int(item.get("registered_at", 0) or 0),
            "exempt": bool(item.get("exempt", False)),
        })
    out.sort(key=lambda c: c["registered_at"], reverse=True)
    return out


def _list_content_by_creator(syndicate_id: str, creator_id: str) -> List[Dict[str, Any]]:
    """Query GSI1 for content registered by a specific creator in a syndicate."""
    gsi_pk = f"SYND_CREATOR#{syndicate_id}#{creator_id}"
    items: List[Dict[str, Any]] = []
    kwargs: Dict[str, Any] = {
        "IndexName": "GSI1",
        "KeyConditionExpression": Key("GSI1PK").eq(gsi_pk),
    }
    while True:
        resp = T.syndicate_open_licensing.query(**kwargs)
        items.extend(resp.get("Items", []))
        lek = resp.get("LastEvaluatedKey")
        if not lek:
            break
        kwargs["ExclusiveStartKey"] = lek
    return items


def _list_registered_content_paginated(syndicate_id: str) -> List[Dict[str, Any]]:
    """Paginated full-partition scan for all CONTENT# items in a syndicate."""
    items: List[Dict[str, Any]] = []
    kwargs: Dict[str, Any] = {
        "KeyConditionExpression": Key("pk").eq(f"SYND#{syndicate_id}")
        & Key("sk").begins_with("CONTENT#"),
    }
    while True:
        resp = T.syndicate_open_licensing.query(**kwargs)
        items.extend(resp.get("Items", []))
        lek = resp.get("LastEvaluatedKey")
        if not lek:
            break
        kwargs["ExclusiveStartKey"] = lek
    return items
```

`_reconcile_all_content` and `on_member_joined` both call `_list_registered_content` internally. They should be updated to call `_list_registered_content_paginated` instead, so that open-licensing reconciliation does not silently miss items.

### 4.2 Add creator_id query param to the router

```python
# app/routers/syndicate_open_licensing.py

from typing import Optional

```

### 4.3 Dev/prod parity (SECOPS-007)

No AWS-specific code paths are introduced. DynamoDB Local (port 8001) supports GSI queries identically to AWS DynamoDB. The `attr_types={"GSI1SK": "N"}` declaration in `local-ddb-init.py` already ensures the sort key is numeric on both environments. The GSI1 query path is identical in dev and prod.

### 4.4 Table naming

No rename is required. `syndicate_open_licensing` is a valid, descriptive name. The ticket's `syndicate_content` was a design artefact. Document the actual name in `docs/dynamodb.md`.

The key pattern difference (`SYND_CREATOR#{syndicate_id}#{creator_id}` vs the ticket's `CREATOR_SYND#{user_id}`) is also acceptable. The implementation's pattern encodes the syndicate first, enabling a single GSI to serve per-syndicate-per-creator queries, which is exactly the access pattern needed. The ticket's pattern (`CREATOR_SYND#{user_id}`) would only serve per-creator cross-syndicate queries, which is less useful. The implementation pattern is therefore _better_ than the spec.

### 4.5 `_reconcile_all_content` and `on_member_joined` pagination fix

Both of these functions call `_list_registered_content` without pagination:

```python
# app/services/syndicate_open_licensing.py:356-369 (_reconcile_all_content)
def _reconcile_all_content(syndicate_id: str, *, terms: Dict[str, Any]) -> int:
    total = 0
    for item in _list_registered_content(syndicate_id):  # <-- no pagination
        ...

# Line 387-400 (on_member_joined)
for item in _list_registered_content(syndicate_id):  # <-- no pagination
    ...
```

Both must be updated to call `_list_registered_content_paginated` (defined in the fix above) to ensure that when open licensing is enabled on a large syndicate, all registered content receives auto-licenses — not just the first DynamoDB page.

### 4.5 Backward compatibility

The change to `list_syndicate_content` is backward compatible: callers that do not pass `creator_id` continue to get the full list (now correctly paginated). The router change adds an optional query parameter — no existing callers are broken.

### Additional validation: confirm GSI1 covers all existing items

After deploying, run a reconciliation scan to confirm all existing `CONTENT#` records have `GSI1PK` and `GSI1SK` populated:

```python

import boto3
from boto3.dynamodb.conditions import Key

missing = []
resp = table.scan()
for item in resp.get("Items", []):
    if item.get("sk", "").startswith("CONTENT#"):
        if not item.get("GSI1PK") or item.get("GSI1SK") is None:
```

Items written before the GSI attributes were added to `register_content` (line 277-278 in the service) would lack `GSI1PK`/`GSI1SK` and would never be returned by the GSI query.
