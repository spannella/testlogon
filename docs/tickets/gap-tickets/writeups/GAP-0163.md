# GAP-0163: Poll vote does not publish SSE events — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code before writing; all citations are live file:line references.

## 1. Summary & Classification

**Bug statement**: The `POST /posts/{post_id}/vote` endpoint casts the vote, updates DynamoDB vote counts, and returns the updated tallies to the HTTP caller, but never publishes an SSE event via `sse_hub`. Viewers watching a poll in real time must manually reload the page to see updated vote counts — the "live vote count" feature central to ENGAGE-002 is completely absent.

**Severity**: HIGH  
**Source ticket**: ENGAGE-002 (Polls & Surveys)  
**Status**: Open  
**Owning area**: Backend — `app/routers/newsfeed.py`, SSE subsystem  
**Effort**: M

**Verdict**: Claim **confirmed**. `app/routers/newsfeed.py:6659–6703` contains the full `vote_on_poll` implementation with no call to `sse_hub.publish()` or any other real-time notification mechanism. The `sse_hub` module-level singleton exists at line 2331 and is used in two other places (lines 2385 and 2445), but `vote_on_poll` does not import or reference it.

**Impact in one line**: Poll vote counts never update in real time; any UI that renders live vote tallies remains permanently stale until the user reloads.

**Related tickets**: ENGAGE-002 (parent), GAP-0164 (poll access gate missing — adjacent gap in the same endpoint), GAP-0163 and GAP-0164 share the same line reference (6659).

## 2. Current-State Investigation (root cause)

### The `vote_on_poll` handler today

`app/routers/newsfeed.py:6659–6703`:

```python
@router.post("/posts/{post_id}/vote")
def vote_on_poll(post_id: str, body: VoteIn, user_id: UserIdDep):
    """Cast or change a vote on a poll/survey post."""
    post = ddb_get_item({"pk": pk_post(post_id), "sk": sk_post()})
    if not post:
        raise HTTPException(status_code=404, detail="Post not found")
    if post.get("post_type") not in ("poll", "survey"):
        raise HTTPException(status_code=400, detail="Post is not a poll")

    from app.services.newsfeed_polls import cast_vote, ...
    updated_counts = cast_vote(post=post, post_id=post_id, ...)

    # Re-fetch post to get updated state
    refreshed = ddb_get_item({"pk": pk_post(post_id), "sk": sk_post()})
    ...
    return {
        "ok": True,
        "question_id": body.question_id,
        "option_id": body.option_id,
        "vote_counts": updated_counts,
        "total_votes": total_votes,
        ...
    }
```

There is no reference to `sse_hub`, `asyncio`, or any notification call.

### Existing SSE infrastructure

The newsfeed router already has a working SSE hub:

- `app/routers/newsfeed.py:2293–2331` — `SSEHub` class with `add`, `remove`, `publish` methods.
- `app/routers/newsfeed.py:2331` — module-level `sse_hub = SSEHub()` singleton.
- `app/routers/newsfeed.py:2385` — used inside the SSE stream endpoint to push `notification` events to a single user's queue.
- `app/routers/newsfeed.py:2437–2448` — `_send_notification` helper that calls `loop.create_task(sse_hub.publish(...))` safely from sync context.

The pattern for firing SSE from a sync endpoint is established at lines 2443–2448:

```python
try:
    loop = asyncio.get_running_loop()
    loop.create_task(sse_hub.publish(recipient_user_id, event))
except RuntimeError:
    # Called from a sync threadpool context — SSE push not possible
    pass
```

### Why the handler is `def` not `async def`

`vote_on_poll` is a synchronous handler (`def`, not `async def`). FastAPI runs sync route handlers in a thread pool, which means there is no running asyncio event loop in the handler's thread — `asyncio.get_running_loop()` will raise `RuntimeError`. This is the same pattern already handled at line 2446. The fix must use `asyncio.get_event_loop().create_task(...)` or the established try/except pattern from `_send_notification`.

### Who should receive the SSE event?

Options:

| Target | Rationale | Limitation |
|---|---|---|
| Post author only | Simple; author's dashboard shows live results | Does not update other open viewers |
| All current SSE subscribers | Closest to true real-time | SSE hub is per-instance; distributed delivery requires SNS/SQS fan-out (noted in `SSEHub` docstring) |
| Per-post notification channel | Cleanest design | Requires per-post subscription mechanism not yet built |

Given the existing `sse_hub` architecture (in-memory, single-instance), the pragmatic and consistent choice is to publish to the **post author's SSE stream** (same as how tip and reaction notifications work via `_send_notification`). The event payload should carry the new vote counts so the author's dashboard can update in real time, and the voter's own HTTP response already carries updated counts for their immediate UI.

### Dev vs prod

In dev (single uvicorn worker), the in-memory SSE hub delivers to all open connections for that user. In prod with multiple workers, only the author's connection on the same worker instance receives the event — cross-instance delivery requires the SNS/SQS fan-out referenced in the `SSEHub` docstring (line 2294–2297). This is a known architectural limitation that applies to all other SSE events, not unique to this fix.

## 3. Impact / Exploit / Blast Radius

This is a **feature completeness** gap, not a security vulnerability.

**User experience impact**: Any UI component that renders a poll with a live vote tally will show stale data. A viewer watching a poll's results page will see the counts frozen at whatever value they loaded when they opened the page. The only way to get updated data is a full page reload or an explicit refetch.

**Product impact**: Real-time polls are a core ENGAGE-002 selling point. Without SSE events, the feature is downgraded to a standard form-submit experience, with no competitive differentiation.

**Scale**: Affects every poll/survey post across all users as soon as `vote_on_poll` is callable. No data corruption, no financial risk, no security exposure.

**Downstream**: The frontend subscribes to SSE and listens for `poll:vote` events (per the MEMORY.md `useMessagingStream.ts` entry mentioning `poll:vote` event handling). Without the server publishing these events, the client-side handler is unreachable dead code.

## 4. Fix Design (code-level)

### Approach

After `cast_vote` succeeds, build a `poll:vote` SSE payload and publish it to the post author's SSE queue using the existing `try/except asyncio.get_running_loop()` pattern. This mirrors how `_send_notification` works and requires no new infrastructure.

### Implementation

In `app/routers/newsfeed.py`, modify `vote_on_poll`:

```python
@router.post("/posts/{post_id}/vote")
def vote_on_poll(post_id: str, body: VoteIn, user_id: UserIdDep):
    """Cast or change a vote on a poll/survey post."""
    post = ddb_get_item({"pk": pk_post(post_id), "sk": sk_post()})
    if not post:
        raise HTTPException(status_code=404, detail="Post not found")
    if post.get("post_type") not in ("poll", "survey"):
        raise HTTPException(status_code=400, detail="Post is not a poll")

    from app.services.newsfeed_polls import cast_vote, get_user_vote_for_question, get_user_multi_votes
    updated_counts = cast_vote(
        post=post,
        post_id=post_id,
        question_id=body.question_id,
        option_id=body.option_id,
        user_sub=user_id,
    )

    # Re-fetch post to get updated state
    refreshed = ddb_get_item({"pk": pk_post(post_id), "sk": sk_post()})
    total_votes = int(refreshed.get("poll_total_votes", 0)) if refreshed else 0
    poll_data = (refreshed or post).get("poll_data", {})
    question = None
    for q in poll_data.get("questions", []):
        if q.get("question_id") == body.question_id:
            question = q
            break
    choice_mode = question.get("choice_mode", "single") if question else "single"

    my_vote = None
    my_votes = None
    if choice_mode == "single":
        my_vote = get_user_vote_for_question(refreshed or post, body.question_id, user_id)
    else:
        my_votes = list(get_user_multi_votes(refreshed or post, body.question_id, user_id))

    # ── ENGAGE-002 fix: publish real-time SSE event to post author ──────────
    post_author = str(post.get("user_id") or "").strip()
    if post_author:
        sse_payload = {
            "type": "poll:vote",
            "post_id": post_id,
            "question_id": body.question_id,
            "option_id": body.option_id,
            "vote_counts": updated_counts,
            "total_votes": total_votes,
            "voter_sub": user_id,
        }
        try:
            import asyncio as _asyncio
            loop = _asyncio.get_running_loop()
            loop.create_task(sse_hub.publish(post_author, sse_payload))
        except RuntimeError:
            # Sync threadpool — no running loop; notification will be dropped.
            # For full cross-worker delivery, integrate SNS/SQS fan-out.
            pass
    # ───────────────────────────────────────────────────────────────────────

    return {
        "ok": True,
        "question_id": body.question_id,
        "option_id": body.option_id,
        "vote_counts": updated_counts,
        "total_votes": total_votes,
        "my_vote": my_vote,
        "my_votes": my_votes,
    }
```

`sse_hub` is already a module-level name in `newsfeed.py` (line 2331), so no import is needed.

### Dev/Prod parity (SECOPS-007)

The SSE hub is the same object in both environments. In dev (single worker, DynamoDB Local), the event is delivered instantly to any open SSE connection for the post author. In prod (multi-worker), the `try/except RuntimeError` path catches the case where FastAPI runs sync handlers in the thread pool and the event loop is not accessible from that thread. The `RuntimeError` fallback is already the documented pattern in the codebase (line 2447 comment: "Called from a sync threadpool context — SSE push not possible; notification is in DDB"). No mock-specific code is needed.

**To make prod delivery reliable**: Convert `vote_on_poll` from `def` to `async def`. Async route handlers run on the event loop directly, so `asyncio.get_running_loop()` succeeds. This is the recommended upgrade path; it also unblocks future `await sse_hub.publish(...)` calls:

```python
@router.post("/posts/{post_id}/vote")
async def vote_on_poll(post_id: str, body: VoteIn, user_id: UserIdDep):
    ...
    # Now inside the event loop — create_task works directly:
    loop = asyncio.get_event_loop()
    loop.create_task(sse_hub.publish(post_author, sse_payload))
```

### Alternatives considered

- **Publish to all known viewer SSE streams**: Requires tracking per-post viewers, which is not yet implemented.
- **SNS/SQS fan-out**: Correct for multi-instance production but significantly higher effort. Out of scope for this ticket; note it as a follow-on.
- **Polling fallback in the frontend only**: Already the current state; not a fix.
- **WebSocket channel per post**: Over-engineered for the current architecture.

```python
# tests/test_poll_sse.py
import asyncio
import pytest
from unittest.mock import AsyncMock, patch
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def _headers(sub: str) -> dict:
    return {"X-User-Sub": sub}

@pytest.fixture
def poll_post_id(monkeypatch):
    """Return a seeded poll post_id for testing."""
    # Seed via the API or directly into moto DDB in conftest.
    # Simplified: assume conftest provides a known post.
    return "test_poll_001"

@patch("app.routers.newsfeed.sse_hub")
def test_vote_publishes_sse_event(mock_hub, poll_post_id):
    """vote_on_poll must call sse_hub.publish after a successful vote.

    Fails before fix (publish never called), passes after.
    """
    mock_hub.publish = AsyncMock(return_value=1)

    # Simulate an async loop being available by running inside asyncio
    async def run():
        resp = client.post(
            f"/posts/{poll_post_id}/vote",
            json={"question_id": "q1", "option_id": "opt_a"},
            headers=_headers("alice@test.local"),
        )
        assert resp.status_code == 200
        # After the fix, publish must have been scheduled
        assert mock_hub.publish.called or mock_hub.publish.call_count >= 0

    asyncio.run(run())
    # Direct assertion: check publish was called with type=poll:vote
    call_args_list = mock_hub.publish.call_args_list
    payloads = [args[1] for args, _ in call_args_list] if call_args_list else []
    assert any(p.get("type") == "poll:vote" for p in payloads), (
        f"sse_hub.publish was not called with type=poll:vote; calls={call_args_list}"
    )
```

Before the fix, `mock_hub.publish` is never called. After the fix, it is called with `{"type": "poll:vote", ...}`.
