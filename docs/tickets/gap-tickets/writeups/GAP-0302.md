# GAP-0302: `thumbnail_url` / `hls_manifest_url` not populated in dev — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`.

## 1. Summary & Classification

**Severity**: HIGH · **Source ticket**: MOD-001 · **Status**: Open · **Effort**: S  
**Owning area**: Backend — video review queue router / admin video review router

In the local dev environment (moto S3, no real FFmpeg transcode), every video in the moderation review queue has `thumbnail_url: null` and `hls_manifest_url: null`. The ABR pipeline (`app/services/ffmpeg_abr_pipeline.py`) only writes these URLs when a real transcode completes and uploads renditions to S3. In dev mode no actual transcode ever runs; the `video_metadata` DynamoDB record stores the raw S3 keys (`thumbnail_s3_key`, `hls_manifest_s3_key`) but the `thumbnail_url` and `hls_manifest_url` columns are never populated. The video review UI therefore renders a blank preview pane for every video pending review — moderators cannot see what they are reviewing.

**Claim verification**: Confirmed accurate. The `_video_to_queue_item()` helper at `app/routers/admin_video_review.py:142–160` passes `video.thumbnail_url` and `video.hls_manifest_url` directly from the `VideoMetadataModel` without any dev-mode synthesis. The `VideoMetadataModel` hydration in `app/services/video_metadata_store.py:219–222` reads those fields verbatim from DynamoDB — `None` in dev because the transcode that would write them has never run.

The fix pattern already exists in the codebase: `app/routers/messaging.py` synthesises `/mock/s3/{bucket}/{key}` URLs for image and file messages in dev mode (lines 3939–3956, 3950–3956). The exact same idiom must be applied to video metadata.

**Related tickets**: MOD-001 (video review queue), MEDIA-002 (FFmpeg binary manager), GAP-0034 (HLS manifest URL not populated after transcoding), GAP-0301 (FFmpeg health endpoint).

## 2. Current-State Investigation (root cause)

### 2.1 Where URLs are written (production path)

In a normal production transcode the ABR pipeline (`app/services/ffmpeg_abr_pipeline.py`) uploads the HLS manifest and thumbnail to S3, then calls back into the `video_metadata_store` to write the CDN URLs. The resulting DynamoDB item looks like:

```
thumbnail_url    = "https://cdn.example.com/videos/{id}/thumb.jpg"
hls_manifest_url = "https://cdn.example.com/videos/{id}/hls/master.m3u8"
```

### 2.2 Where URLs are read (router path)

`app/routers/admin_video_review.py:142–160` — `_video_to_queue_item()`:

```python
def _video_to_queue_item(video: Any) -> VideoReviewQueueItemOut:
    return VideoReviewQueueItemOut(
        ...
        thumbnail_url=video.thumbnail_url,       # None in dev — no transcode ran
        hls_manifest_url=video.hls_manifest_url, # None in dev — no transcode ran
        ...
    )
```

Called from the list endpoint at line 214 and the detail endpoint at line 235. Neither call site has a dev-mode branch.

The `VideoMetadataModel` hydration is at `app/services/video_metadata_store.py:219–222`:

```python
thumbnail_url=item.get("thumbnail_url"),     # reads from DDB
hls_manifest_url=item.get("hls_manifest_url"), # reads from DDB
```

And the underlying DDB item does have `thumbnail_s3_key` (line 219 via `item.get("thumbnail_s3_key")`) and `hls_manifest_s3_key` (line 221), so the raw S3 keys are present — only the pre-signed/CDN URL is absent.

### 2.3 The established mock URL pattern

`app/routers/messaging.py` lines 3939–3956 show the correct idiom:

```python
if raw_image and S.dev_mode and not raw_image.get("url"):
    _bucket = S.s3_images_bucket  # or equivalent bucket name
    _key = raw_image.get("s3_key") or ""
    if _key:
        raw_image["url"] = f"/mock/s3/{_bucket}/{_url_quote(_key, safe='/')}"

if raw_file and S.dev_mode and not raw_file.get("url"):
    ...
    raw_file["url"] = f"/mock/s3/{_bucket_f}/{_url_quote_f(_key_f, safe='/')}"
```

The `/mock/s3/{bucket}/{key}` path is served by `app/core/dev_s3.py` which intercepts boto3 calls at the botocore layer (moto) and by a Vite proxy rule that forwards `/mock/s3/*` to the backend. A browser can load the path directly.

### 2.4 Why the gap exists

The dev-mode URL synthesis in the messaging router was added retroactively when those tests started failing with blank previews. The video review queue was implemented in the same sprint as MOD-001 but whoever wrote `_video_to_queue_item()` did not notice the messaging pattern and simply forwarded `None`. The moderation video queue router (`app/routers/moderation_video_queue.py:66–67`) has the same problem — it also passes `thumbnail_url=raw.get("thumbnail_url")` verbatim. Both routers are distinct code paths: `admin_video_review.py` serves the admin video review queue (`/v1/admin/videos`), while `moderation_video_queue.py` serves the moderation video queue (`/ui/moderation/video-queue`). Both require the same fix.

### 2.5 S3 key availability in the dev flow

When a video is uploaded in the dev stack, the following sequence occurs:
1. The upload endpoint stores the raw video at an S3 key like `videos/{video_id}/source.mp4`.
2. The video record enters `status = "pending_encoding"` with `source_s3_key` set.
3. Without a real FFmpeg binary running the ABR pipeline, the video never advances to `status = "pending_review"` automatically — a moderator or test must manually enqueue it.
4. When manually enqueued via `POST /ui/moderation/video-queue/enqueue` (with `thumbnail_url=null, hls_manifest_url=null`), the queue entry has no preview URLs.
5. The `thumbnail_s3_key` field may be set if the upload included a pre-computed thumbnail, but `thumbnail_url` (the HTTP-accessible path) is always absent unless the ABR pipeline ran.

The fix synthesises the HTTP path from the S3 key only when the key exists. If neither the URL nor the key is present (e.g., video was uploaded without a thumbnail), the field remains `null` — the frontend should show a "Preview unavailable" placeholder in that case.

### 2.5 Runtime manifestation

`GET /v1/admin/videos` returns items with `"thumbnail_url": null, "hls_manifest_url": null`. The `VideoReviewQueuePage.tsx` frontend uses these fields to render a video player and thumbnail; with `null` both render as empty/broken. Moderators reviewing the queue see only metadata (title, duration, owner) with no visual preview, making it impossible to assess content visually in the local environment.

## 3. Impact / Exploit / Blast Radius

This is a **developer experience and moderation workflow gap**, not a security vulnerability.

**Moderator productivity**: Every video pending review in the local dev environment shows a blank preview. A moderator testing the flow cannot see the content they are supposed to approve or reject. The only visual clue is the video title.

**QA coverage gap**: Playwright E2E tests for the video review queue (any spec that asserts a thumbnail or player is visible) will fail or be written with `toBeNull()` guards that mask the real bug. When the production CDN URL IS populated, the test logic may diverge from what a real moderator sees.

**No production risk**: In production, `thumbnail_url` and `hls_manifest_url` are written by the transcode pipeline. The bug only manifests when `S.dev_mode is True` and no transcode has run, i.e., exclusively in local dev. No user data is exposed or modified.

**Blast radius**: Limited to the local developer environment. Two router files are affected: `admin_video_review.py` and `moderation_video_queue.py`.

## 4. Fix Design (code-level)

### 4.1 Principle

Apply the same `if S.dev_mode and not url and s3_key:` pattern already used in the messaging router. The S3 bucket for video uploads is `S.video_upload_bucket` (default `"local-uploads"`, set at `app/core/settings.py:1389`).

### 4.2 `app/routers/admin_video_review.py` — `_video_to_queue_item()`

Import `S` from settings at the top of the file (it is not currently imported). Update `_video_to_queue_item()`:

```python
from app.core.settings import S
from urllib.parse import quote as _url_quote

def _video_to_queue_item(video: Any) -> VideoReviewQueueItemOut:
    thumbnail_url = video.thumbnail_url
    hls_manifest_url = video.hls_manifest_url

    if S.dev_mode:
        if not thumbnail_url and video.thumbnail_s3_key:
            thumbnail_url = (
                f"/mock/s3/{S.video_upload_bucket}/"
                f"{_url_quote(video.thumbnail_s3_key, safe='/')}"
            )
        if not hls_manifest_url and video.hls_manifest_s3_key:
            hls_manifest_url = (
                f"/mock/s3/{S.video_upload_bucket}/"
                f"{_url_quote(video.hls_manifest_s3_key, safe='/')}"
            )

    return VideoReviewQueueItemOut(
        ...
        thumbnail_url=thumbnail_url,
        hls_manifest_url=hls_manifest_url,
        ...
    )
```

### 4.3 `app/routers/moderation_video_queue.py` — `_to_item()`

The same synthesis must be applied in `_to_item()` at line 45:

```python
from app.core.settings import S
from urllib.parse import quote as _url_quote

def _to_item(raw: dict) -> VideoReviewQueueItemOut:
    ...
    thumbnail_url = raw.get("thumbnail_url")
    hls_manifest_url = raw.get("hls_manifest_url")

    if S.dev_mode:
        if not thumbnail_url and raw.get("thumbnail_s3_key"):
            thumbnail_url = (
                f"/mock/s3/{S.video_upload_bucket}/"
                f"{_url_quote(raw['thumbnail_s3_key'], safe='/')}"
            )
        if not hls_manifest_url and raw.get("hls_manifest_s3_key"):
            hls_manifest_url = (
                f"/mock/s3/{S.video_upload_bucket}/"
                f"{_url_quote(raw['hls_manifest_s3_key'], safe='/')}"
            )

    return VideoReviewQueueItemOut(
        ...
        thumbnail_url=thumbnail_url,
        hls_manifest_url=hls_manifest_url,
        ...
    )
```

### 4.4 Dev/Prod parity (SECOPS-007)

Both branches are gated on `S.dev_mode`. In production (`DEV_MODE=0`) the synthesis is never reached; `thumbnail_url` and `hls_manifest_url` are returned exactly as stored in DynamoDB (populated by the real transcode pipeline). The `if S.dev_mode` blocks follow the same pattern used throughout the messaging router (lines 3811, 3939, 3950, 4076, 4100 in `messaging.py`) and are therefore consistent with the project's established parity strategy. No feature flag is needed beyond the existing `DEV_MODE` env var.

### 4.5 Alternatives considered

**Alternative A — synthesise URLs at service layer (`video_metadata_store.py`)**: Inject mock URLs in `_item_to_model()`. Rejected: the service layer should be storage-agnostic. The mock URL synthesis is a presentation concern that belongs at the router/serialisation boundary, consistent with how the messaging router handles it.

**Alternative B — write mock URLs at upload time**: When a video is uploaded in dev mode, immediately write placeholder `thumbnail_url` and `hls_manifest_url` fields. Rejected: the upload endpoint doesn't have S3 keys for those outputs at upload time (they are produced by the transcode pipeline); synthesising them before the pipeline runs introduces inconsistent state.

**Alternative C — run a lightweight test transcode in dev mode**: Too heavy-weight for a devtools fix; requires FFmpeg to be installed and adds real latency to the upload flow.

### 5.3 Observability

No new metrics. The change is purely presentational. A Playwright test asserting `expect(page.locator('[data-testid="video-thumbnail"]')).not.toBeEmpty()` would catch regressions going forward.

### 5.4 Rollback

The change is a two-file edit with a clear `if S.dev_mode:` guard. Rolling back removes those branches; behaviour reverts to returning `null` in dev — the original (broken) state. No database migration required.

### 5.5 Frontend follow-up

Once the backend synthesises the `/mock/s3/...` URLs in dev mode, the `VideoReviewQueuePage.tsx` and `VideoReviewQueueModerationPage.tsx` components (`frontend/src/pages/admin/`) will receive non-null `thumbnail_url` and `hls_manifest_url` values. Confirm the player and thumbnail `<img>` components use `||` / nullish fallback guards so they render gracefully in production while pending a real transcode:

```tsx
// In VideoReviewQueueModerationPage.tsx (or wherever the player renders)
{item.hls_manifest_url ? (
  <VideoPlayer src={item.hls_manifest_url} />
) : (
  <div className="flex items-center justify-center h-48 bg-muted rounded">
    <span className="text-muted-foreground text-sm">Preview unavailable</span>
  </div>
)}
```

This ensures a graceful empty state in production (where `hls_manifest_url` may be `null` for newly uploaded, not-yet-transcoded videos) while showing the real mock stream in dev.

### 5.6 Interaction with `VideoMetadataModel.thumbnail_s3_key`

The `VideoMetadataModel` at `app/models_video.py:71–73` stores:
- `thumbnail_s3_key: Optional[str]` — the raw S3 key produced by the ABR pipeline.
- `thumbnail_url: Optional[str]` — the pre-signed or CDN URL (None until transcoding completes).

In dev mode, the ABR pipeline never runs and `thumbnail_s3_key` may also be `None` (if the video was uploaded but not yet probed). The dev-mode synthesis code must handle the case where both `thumbnail_url` and `thumbnail_s3_key` are `None` — the guard `if not thumbnail_url and video.thumbnail_s3_key:` handles this correctly by skipping synthesis when the S3 key is absent.

For integration tests that need a predictable thumbnail, seed a `video_metadata` DynamoDB record with `thumbnail_s3_key = "videos/{id}/thumb.jpg"` explicitly; the synthesis will then produce a deterministic `/mock/s3/local-uploads/videos/{id}/thumb.jpg` URL that can be asserted in tests.

### 5.7 Effort and sequencing

**Effort**: S (Small) — 2–3 hours including tests.  
**Sequencing**: Independent. Should be resolved before any E2E test for the video review queue is written, as a missing thumbnail is otherwise silently ignored.
