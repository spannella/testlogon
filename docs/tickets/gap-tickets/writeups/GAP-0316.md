# GAP-0316: GIF `gif_url` Is Accepted Without Domain Allowlist Validation — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual codebase; no prior investigation doc exists.

## 1. Summary & Classification

**Bug statement**: The `POST /ui/messaging/conversations/{conversation_id}/messages/gif` endpoint
accepts any URL in the `gif_url` field without checking whether the domain belongs to an approved
list of GIF providers. Any authenticated user can send a message that renders a GIF loaded from
a server they control, enabling cross-site content injection, image-proxied tracking pixels, and
— depending on browser Content-Security-Policy configuration — potential SSRF if the back-end
ever pre-fetches or thumbnails the URL.

**Severity**: HIGH  
**Source ticket**: MSG-008  
**Owning area**: Messaging  
**Status**: Open — no domain allowlist exists in the current code  
**Claim verdict**: CONFIRMED. `send_gif_message()` at
`app/routers/messaging.py:9626` stores `inp.gif_url` directly into DynamoDB without any
netloc/allowlist check. The `SendGifMessageIn` model at `app/routers/messaging.py:2105` enforces
only a max-length of 2048 characters.

**Related tickets**: MSG-008 (feature origin), SECOPS-007 (dev/prod parity rules),
GAP-0022 (SSRF via SEC-020 for comparison pattern).

## 2. Current-State Investigation (root cause)

### Input model — `app/routers/messaging.py:2105`

```python
class SendGifMessageIn(BaseModel):
    gif_url: str = Field(..., max_length=2048)
    gif_alt_text: str = Field(default="", max_length=256)
    gif_width: int = Field(default=0, ge=0, le=4096)
    gif_height: int = Field(default=0, ge=0, le=4096)
    reply_to_message_id: Optional[str] = None
```

No URL scheme check, no domain check. Any well-formed string up to 2048 characters passes
Pydantic validation.

### Handler — `app/routers/messaging.py:9625`

```python
@router.post("/conversations/{conversation_id}/messages/gif", response_model=MessageOut, status_code=201)
def send_gif_message(conversation_id: str, inp: SendGifMessageIn, ...):
    if not S.gif_messages_enabled:
        raise HTTPException(403, "GIF messages are not enabled")
    require_participant_active(user_id, conversation_id)
    ...
    item: Dict[str, Any] = {
        ...
        "gif_url": inp.gif_url,   # ← stored verbatim, no domain check
        ...
    }
    tbl_msgs.put_item(Item=item)
```

The URL is then returned in `MessageOut.gif_url` and rendered by the frontend
(`MessageBubble` renders `<img src={msg.gif_url} />`). There is no server-side re-write
or proxy layer between the client-supplied URL and the `<img>` tag.

### Settings — `app/core/settings.py:1107`

```python
gif_messages_enabled: bool = ...
gif_provider: str = os.environ.get("GIF_PROVIDER", "mock")
```

`gif_provider` is read-only metadata stored on each message (`S.gif_provider or "mock"`) but
is never used to validate the incoming URL. There is no `gif_allowed_domains` setting.

### Mock GIF service — `app/services/gif_provider.py`

The dev mock returns URLs of the form `/mock/gifs/placeholder_N.gif` (relative, no host).
In production the real Tenor/Giphy CDN domains would be used, but the API never enforces this.

### Why `urllib.parse.urlparse` is already imported

`app/routers/messaging.py:19` already imports `from urllib.parse import urljoin, urlparse` and
uses `urlparse` at line 4836 for a different URL validation path (inside the video-share SSRF
guard). The fix therefore requires only a few additional lines in the same file — no new
imports and no new dependencies.

### Mock GIF provider context — `app/services/gif_provider.py`

The mock service at `app/services/gif_provider.py:16` returns URLs of the form
`/mock/gifs/placeholder_N.gif` (relative paths, no scheme, no host). In production the
application is expected to proxy GIF search queries to a real CDN (Tenor or Giphy) and surface
CDN-absolute URLs like `https://media.tenor.com/abc123/cat.gif`. The absence of domain
validation means both the mock and a production-mode deployment with a malicious URL pass
through identically — there is no server-side distinction. The fix must handle the relative
mock path specifically in dev mode while enforcing the CDN allowlist in all other environments.

## 3. Impact / Exploit / Blast Radius

**Scenario 1 — Tracking pixel / privacy leak**  
An attacker who is a conversation participant sends:

```json
{"gif_url": "https://attacker.example.com/pixel.gif", "gif_alt_text": "funny cat"}
```

Every recipient who opens the conversation makes a browser GET to `attacker.example.com`,
leaking their IP address, User-Agent, and timing information. This cannot be blocked by the
application's own CSP because the `<img>` src is set to the attacker domain at response time.

**Scenario 2 — Phishing / malicious content rendering**  
The `<img>` tag will follow HTTP redirects. An attacker can point `gif_url` at
`https://attacker.example.com/redirect?to=malicious-page` and serve MIME-switching payloads
or credential-harvesting pages depending on request headers.

**Scenario 3 — SSRF precursor (future risk)**  
If a thumbnail-generation or pre-fetch feature is added later (common for messaging apps), the
stored arbitrary URL immediately becomes a full SSRF vector into the VPC, private S3 endpoints,
or the IMDSv1 metadata service (`http://169.254.169.254/`). Fixing the allowlist now eliminates
this attack surface before it is widened.

**Affected users**: All users in conversations where a malicious GIF message exists. Because GIF
messages fanout to all conversation participants (line 9675), every participant's browser loads
the URL on conversation open. The URL is also persisted in the `gif_url` field in DynamoDB and
returned in perpetuity by `_message_out_from_item()` — unlike ephemeral messages, GIF messages
have no expiry by default. A tracking pixel embedded via `gif_url` will fire every time any
participant opens or scrolls past the conversation thread, including weeks or months after the
message was sent.

**Blast radius**: Medium — requires a valid session and conversation membership, but the
attacker only needs to be in one conversation with the target. Group conversations amplify the
impact: a single malicious GIF message in a 50-person group chat leaks the IP address of every
member who opens the thread.

## 4. Fix Design (code-level)

### 4.1 Add `gif_allowed_domains` setting

**File**: `app/core/settings.py`

Add after the existing `gif_provider` line (currently line 1110):

```python
# Comma-separated list of allowed GIF hostnames (empty string = any, for testing only).
# Default includes Tenor and Giphy CDN domains for production use.
# Dev mode: also allows relative paths (no host) served by the mock GIF provider.
gif_allowed_domains: str = os.environ.get(
    "GIF_ALLOWED_DOMAINS",
    "media.tenor.com,media1.tenor.com,media.giphy.com,i.giphy.com,c.tenor.com"
)
```

The empty-string default is intentionally NOT used for prod; the non-empty default enforces the
two primary GIF CDNs. Dev mode adds a special case for `/mock/...` paths (see 4.2).

### 4.2 Add validation helper and integrate into `send_gif_message`

**File**: `app/routers/messaging.py`

Add a private validator near the top of the file (after existing imports, before the first
`@router` decorator):

```python
def _validate_gif_url(url: str) -> None:
    """Reject gif_url values whose host is not on the configured allowlist.

    In dev mode (/mock/* relative URLs are accepted unconditionally so that
    the built-in mock GIF provider works without needing a real CDN domain).
    """
    parsed = urlparse(url)  # urlparse already imported at line 19
    # Relative paths (no scheme, no netloc) are only allowed in dev mode for mocks.
    if not parsed.netloc:
        if S.dev_mode and url.startswith("/mock/"):
            return
        raise HTTPException(400, "gif_url_not_allowed")
    # Scheme must be https (block http: and data: URIs)
    if parsed.scheme not in ("https",):
        raise HTTPException(400, "gif_url_not_allowed")
    # Empty allowlist means any domain — only acceptable in dev with mocks.
    allowed_raw = (S.gif_allowed_domains or "").strip()
    if not allowed_raw:
        if S.dev_mode:
            return
        raise HTTPException(400, "gif_url_not_allowed")
    allowed = {d.strip().lower() for d in allowed_raw.split(",") if d.strip()}
    if parsed.netloc.lower() not in allowed:
        raise HTTPException(400, "gif_url_not_allowed")
```

Then call it inside `send_gif_message`, directly after the `_validate_reply_target` call
(currently line 9637):

```python
    _validate_reply_target(conversation_id, inp.reply_to_message_id)
    _validate_gif_url(inp.gif_url)  # ← ADD THIS LINE
```

### 4.3 Dev/Prod parity (SECOPS-007)

| Environment | `GIF_ALLOWED_DOMAINS` | Behaviour |
|---|---|---|
| Dev (local stack) | Not set → defaults to Tenor+Giphy CDNs, BUT relative `/mock/*` paths also accepted when `S.dev_mode=True` | Mock GIF provider works; real CDN URLs also pass |
| CI / tests | Set to empty string + `DEV_MODE=1` → all relative `/mock/*` paths pass | Tests can use `/mock/gifs/placeholder_1.gif` |
| Production | Set explicitly to `media.tenor.com,...` | Only whitelisted CDN hosts pass |

The `S.dev_mode` branch in `_validate_gif_url` is the only difference between dev and prod code
paths, and it is gated on the same flag already used throughout the codebase. No separate
`_mock_enabled()` path is introduced.

### 4.4 Alternatives considered

- **Pydantic `validator` on `SendGifMessageIn`**: Rejected because the validator would need
  access to `S` (a global) and `HTTPException`, coupling the model to the application layer.
  A service-layer helper is the established pattern in this codebase.
- **URL re-write to CDN proxy**: Stronger security but high effort and out of scope for a gap
  ticket. Document as a follow-on hardening item.
- **CSP `img-src` restriction**: Already desirable but outside the backend; cannot be the only
  control because CSP is set per-response and can be bypassed in API clients.

## 5. Testing, Verification & Rollout

### Regression tests (pytest offline)

Add to `tests/test_gif_url_validation.py`:

```python
import pytest
from fastapi.testclient import TestClient
from unittest.mock import patch

# --- fails BEFORE fix (returns 201), passes AFTER fix (returns 400) ---
def test_gif_url_arbitrary_domain_rejected(auth_client):
    """An arbitrary external domain must be blocked (400 gif_url_not_allowed)."""
    resp = auth_client.post(
        f"/ui/messaging/conversations/{CONVO_ID}/messages/gif",
        json={"gif_url": "https://evil.example.com/track.gif"},
        headers=CSRF_HEADERS,
    )
    assert resp.status_code == 400
    assert resp.json()["detail"] == "gif_url_not_allowed"

def test_gif_url_http_scheme_rejected(auth_client):
    """http:// scheme must be blocked even for allowlisted domains."""
    resp = auth_client.post(
        f"/ui/messaging/conversations/{CONVO_ID}/messages/gif",
        json={"gif_url": "http://media.tenor.com/safe.gif"},
        headers=CSRF_HEADERS,
    )
    assert resp.status_code == 400

def test_gif_url_data_uri_rejected(auth_client):
    """data: URI must be blocked."""
    resp = auth_client.post(
        f"/ui/messaging/conversations/{CONVO_ID}/messages/gif",
        json={"gif_url": "data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7"},
        headers=CSRF_HEADERS,
    )
    assert resp.status_code == 400

# --- passes both BEFORE and AFTER fix ---
def test_gif_url_allowlisted_domain_accepted(auth_client):
    """An allowlisted CDN domain must succeed (201)."""
    with patch("app.core.settings.S.gif_allowed_domains", "media.tenor.com"):
        resp = auth_client.post(
            f"/ui/messaging/conversations/{CONVO_ID}/messages/gif",
            json={"gif_url": "https://media.tenor.com/abc123/cat.gif"},
            headers=CSRF_HEADERS,
        )
        assert resp.status_code == 201

def test_gif_url_mock_path_accepted_in_dev_mode(auth_client):
    """Relative /mock/* paths must be accepted when dev_mode=True."""
    with patch("app.core.settings.S.dev_mode", True), \
         patch("app.core.settings.S.gif_allowed_domains", ""):
        resp = auth_client.post(
            f"/ui/messaging/conversations/{CONVO_ID}/messages/gif",
            json={"gif_url": "/mock/gifs/placeholder_1.gif"},
            headers=CSRF_HEADERS,
        )
        assert resp.status_code == 201
```
