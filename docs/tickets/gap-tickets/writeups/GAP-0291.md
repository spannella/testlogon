# GAP-0291: `ShelfItem` TypeScript Interface Missing Broadcast Pricing Fields — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; all file:line citations confirmed.

## 1. Summary & Classification

**Bug**: The `ShelfItem` TypeScript interface exported from `frontend/src/api/endpoints/broadcast-shelf.ts` (lines 5–17) contains only base catalog fields and is missing all seven broadcast-exclusive pricing fields that the backend already returns from `GET /broadcast/sessions/{session_id}/products`. As a result, every component that consumes `ShelfItem` — primarily `ProductShelf.tsx` and `ProductShelfManager.tsx` — cannot access `broadcast_price_cents`, `effective_price_cents`, `is_broadcast_price`, `discount_pct`, `broadcast_price_expires_at`, `broadcast_price_set_at`, or `original_price_cents`.

**Severity**: HIGH (source ticket LCOM-004). Effort: S.

**Status**: Open. No investigation doc exists for this gap; the claim is based on a second-pass as-built review of LCOM-004.

**Claim verdict**: Confirmed. The interface at `frontend/src/api/endpoints/broadcast-shelf.ts:5–17` lacks all seven pricing fields that the backend `BroadcastShelfItemOut` Pydantic model (`app/routers/broadcast.py:2065–2088`) exposes. The backend fields are present and populated; only the TypeScript contract is missing them.

**Related tickets**: GAP-0292 (`BroadcastPrice.tsx` viewer component absent), GAP-0293 (`BroadcastPriceEditor.tsx` broadcaster component absent). Both depend on this fix being applied first because they require a correctly-typed `ShelfItem`.

**Owning area**: Frontend / TypeScript API contract layer.

## 2. Current-State Investigation (Root Cause)

### Backend — what the API actually returns

The backend Pydantic model `BroadcastShelfItemOut` is defined at `app/routers/broadcast.py:2065–2088`:

```python
# app/routers/broadcast.py:2065
class BroadcastShelfItemOut(BaseModel):
    session_id: str
    item_id: str
    category_id: str
    name: str
    description: Optional[str] = None
    price_cents: int
    currency: str = "USD"
    image_url: Optional[str] = None
    display_order: int = 0
    added_by: str
    added_at: int
    # Broadcast pricing fields (LCOM-004)
    broadcast_price_cents: Optional[int] = None
    broadcast_price_expires_at: Optional[int] = None
    broadcast_price_set_at: Optional[int] = None
    effective_price_cents: Optional[int] = None
    is_broadcast_price: bool = False
    discount_pct: int = 0
    original_price_cents: Optional[int] = None
```

The `_shelf_item_out_with_pricing()` helper at `app/services/broadcast_product_shelf.py` (called from every shelf list/add/reorder response) populates all seven pricing fields from DynamoDB, including `broadcast_price_cents`, `broadcast_price_expires_at`, `effective_price_cents`, `is_broadcast_price`, `discount_pct`, and `original_price_cents`.

The SSE event `shelf:price_update` published by `set_broadcast_price` and `clear_broadcast_price` also carries these fields inside its payload.

### Frontend — what the TypeScript interface declares

`frontend/src/api/endpoints/broadcast-shelf.ts:5–17`:

```typescript
export interface ShelfItem {
  session_id: string;
  item_id: string;
  category_id: string;
  name: string;
  description: string | null;
  price_cents: number;
  currency: string;
  image_url: string | null;
  display_order: number;
  added_by: string;
  added_at: number;
}
```

Seven fields present in every API response are absent. No `setBroadcastPrice` or `clearBroadcastPrice` API wrapper functions exist in this file either; the file currently exposes only `addShelfProduct`, `removeShelfProduct`, `getShelfProducts`, and `reorderShelf` (lines 33–43).

### How the bug manifests at runtime

At runtime, `getShelfProducts` returns JSON that contains `broadcast_price_cents`, `effective_price_cents`, etc. TypeScript's type system strips these from the inferred type at compile time, making them inaccessible without an unsafe cast. Any component that tries to read `item.broadcast_price_cents` gets a compile-time type error, which is why the viewer (`BroadcastPrice.tsx`) and editor (`BroadcastPriceEditor.tsx`) components were never built — there was no safe typed surface to build on. Additionally, the `ProductShelfCard` in `ProductShelf.tsx:85–87` always renders `item.price_cents` (the catalog price) rather than the effective discounted price:

```tsx
// ProductShelf.tsx:85–87 — only catalog price rendered; broadcast discount never shown
<p className="text-sm font-semibold text-primary">
  {formatPrice(item.price_cents, item.currency)}
</p>
```

In dev mode the error is invisible because TypeScript is not enforced at runtime; but the broadcast discount is silently discarded for every viewer. In production the same runtime behaviour applies — users watching a live broadcast see the original price even when the broadcaster has set a time-limited discount.

## 3. Impact / Exploit / Blast Radius

This is primarily a correctness/availability gap rather than a security vulnerability, but the commercial impact is material:

1. **Revenue loss for broadcasters**: Any broadcaster who uses the `PATCH /broadcast/sessions/{id}/products/{item_id}/price` endpoint (via curl, Postman, or a third-party integration) to set a broadcast-exclusive discount will have that discount silently invisible to viewers. The viewer's cart will be pre-filled at the full catalog price.

2. **Broken add-to-cart price**: `ProductShelf.tsx:44–52` calls `addCartItem` with `unit_price_cents: item.price_cents`. If the effective broadcast price is lower, the cart records the wrong price. Downstream checkout and order fulfilment will charge the wrong amount — either the full price (overcharging the buyer) or, if the broadcaster manually adjusts the catalog price to match the broadcast price, items are sold below intended margin.

3. **SSE event data silently dropped**: The SSE `shelf:price_update` window event dispatched by the backend carries a `ShelfItem`-shaped payload. The `handleShelfAdd` handler in `ProductShelf.tsx:133–144` accepts `CustomEvent<ShelfItem>`. Because `ShelfItem` lacks the pricing fields, even a real-time SSE push of updated pricing is silently truncated by TypeScript and the discount is never displayed.

4. **Developer confusion and test fragility**: E2E tests or integration clients that attempt to read pricing fields from a `ShelfItem` variable receive `undefined` rather than `null | number`, which can cause unexpected `NaN` in formatted price strings.

Blast radius is scoped to: live broadcast sessions where a broadcaster has set a broadcast-exclusive price. All other shelf functionality (add/remove/reorder) is unaffected.

## 4. Fix Design (Code-Level)

### 4a. Extend `ShelfItem` interface

In `frontend/src/api/endpoints/broadcast-shelf.ts`, replace the existing `ShelfItem` interface definition with:

```typescript
export interface ShelfItem {
  session_id: string;
  item_id: string;
  category_id: string;
  name: string;
  description: string | null;
  price_cents: number;
  currency: string;
  image_url: string | null;
  display_order: number;
  added_by: string;
  added_at: number;
  // Broadcast-exclusive pricing fields (LCOM-004)
  broadcast_price_cents: number | null;
  broadcast_price_expires_at: number | null;
  broadcast_price_set_at: number | null;
  effective_price_cents: number | null;
  is_broadcast_price: boolean;
  discount_pct: number;
  original_price_cents: number | null;
}
```

All seven new fields are optional/nullable on the server side, so existing callers that destructure only the base fields continue to work without change.

### 4b. Add `setBroadcastPrice` and `clearBroadcastPrice` API wrappers

Still in `broadcast-shelf.ts`, append two new exports:

```typescript
export interface SetBroadcastPriceRequest {
  broadcast_price_cents: number;
  expires_in_seconds?: number;
}

export interface BroadcastPriceResponse {
  session_id: string;
  item_id: string;
  original_price_cents: number;
  broadcast_price_cents: number;
  broadcast_price_expires_at: number | null;
  discount_pct: number;
  set_by: string;
  set_at: number;
}

export const setBroadcastPrice = (
  sessionId: string,
  itemId: string,
  body: SetBroadcastPriceRequest,
) =>
  api.patch<BroadcastPriceResponse>(
    `/broadcast/sessions/${sessionId}/products/${itemId}/price`,
    body,
  );

export const clearBroadcastPrice = (sessionId: string, itemId: string) =>
  api.del<{ ok: boolean; item_id: string; session_id: string }>(
    `/broadcast/sessions/${sessionId}/products/${itemId}/price`,
  );
```

These wrap the already-implemented backend endpoints at `app/routers/broadcast.py:2223–2310`.

### 4c. Update `ProductShelfCard` to display effective price

In `frontend/src/pages/broadcast/ProductShelf.tsx`, the price display at line 85 should use `effective_price_cents` when a broadcast discount is active, falling back to `price_cents`:

```tsx
// Replace the static price display
const displayCents = item.effective_price_cents ?? item.price_cents;
const isDiscounted = item.is_broadcast_price && item.broadcast_price_cents !== null;

<div className="flex items-center gap-1">
  {isDiscounted && (
    <span className="text-xs line-through text-muted-foreground">
      {formatPrice(item.price_cents, item.currency)}
    </span>
  )}
  <p className="text-sm font-semibold text-primary">
    {formatPrice(displayCents, item.currency)}
  </p>
</div>
```

This change is purely in the read path and requires no backend modification.

### 4d. Dev/Prod parity (SECOPS-007)

No backend code is changed by this fix; all new fields are already present in the backend response in both dev and prod paths. The `_shelf_item_out_with_pricing` helper is called identically by the mock and production code paths — there are no feature flags or `dev_mode` branches on the pricing fields. The `setBroadcastPrice` and `clearBroadcastPrice` frontend wrappers call the same `/broadcast/sessions/...` endpoints used in dev and prod; the backend's `PATCH /price` and `DELETE /price` routes are gated only by session-creator ownership (`ctx["user_sub"] != session.created_by` at `app/routers/broadcast.py:2241–2244`), not by a feature flag.

### 4e. Alternatives considered

- **Type-casting without interface change**: Using `(item as any).broadcast_price_cents` in component code is unsafe and would not provide autocomplete or compile-time safety for the two missing component files (GAP-0292, GAP-0293). Rejected.
- **Separate `PricedShelfItem` interface extending `ShelfItem`**: Would require a backend-layer discriminator or conditional type. Adds complexity without benefit since every shelf item already carries the pricing fields (they default to `null`/`false`/`0`). Rejected in favour of a flat extension.

## 5. Testing, Verification & Rollout

### Regression test (fails before, passes after)

Add a Playwright test to `frontend/e2e/broadcast-pricing.spec.ts` (new file, to be wired to the suite):

```typescript
test("ShelfItem type includes broadcast pricing fields and effective price is displayed", async ({ page }) => {
  // Seed a session + shelf item via API
  const sessionId = await createTestSession(request);
  const itemId = await addTestShelfItem(request, sessionId);

  // Set a broadcast price (50% off)
  await request.patch(`/broadcast/sessions/${sessionId}/products/${itemId}/price`, {
    data: { broadcast_price_cents: 500 }, // catalog price 1000
  });

  await page.goto(`/broadcast/${sessionId}/watch`);

  // Before fix: formatPrice(item.price_cents) = "$10.00", no strikethrough
  // After fix:  strikethrough "$10.00" + bold "$5.00"
  await expect(page.getByText("$5.00")).toBeVisible();
  await expect(page.locator(".line-through").filter({ hasText: "$10.00" })).toBeVisible();
});
```

### Manual QA steps

1. Start the dev stack (`just up`).
2. Create a broadcast session, add a catalog item to the shelf.
3. Call `PATCH /broadcast/sessions/{id}/products/{item_id}/price` with `broadcast_price_cents` set to half the catalog price.
4. Open the broadcast viewer page. Confirm the shelf card shows struck-through original price and the discounted effective price.
5. Call `DELETE /broadcast/sessions/{id}/products/{item_id}/price`. Confirm the shelf card reverts to showing only the catalog price without strikethrough.
6. Confirm the `setBroadcastPrice` and `clearBroadcastPrice` TypeScript exports are importable with correct types in the component files built by GAP-0292 and GAP-0293.

### Metrics / observability

No new server-side metrics are needed (the backend endpoints already log to structured output). The frontend should add a `data-testid="broadcast-price-effective"` attribute to the displayed price element for Playwright selector stability.

### Rollback

The interface extension is additive and backward-compatible. Reverting the `ShelfItem` extension simply removes fields that existing code does not reference; no data migration is needed.

### Effort and sequencing

**Effort: S** (as noted in the ticket). The interface change is ~15 lines. The `ProductShelfCard` display patch is ~8 lines. The two new API wrapper functions are ~20 lines. Total: under one hour of implementation.

**Sequencing**: This fix (GAP-0291) must be merged before GAP-0292 and GAP-0293, as both downstream components import `ShelfItem` and depend on the extended type.
