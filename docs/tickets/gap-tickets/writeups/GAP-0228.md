# GAP-0228: Background Billing Timer Not Wired — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code at `app/services/compute_billing.py` and `app/main.py`.

## 1. Summary & Classification

**Plain-English statement**: The compute billing system (INFRA-005) records per-minute charges for running EC2 instances and K8s pods, deducts from wallet balances, and auto-terminates resources when a wallet reaches zero. However, the background timer that should fire these ticks automatically — once per minute (or per `COMPUTE_BILLING_POLL_INTERVAL`) — has never been implemented and never registered as a startup task. Billing only occurs when a user or test explicitly sends a manual HTTP `POST /ui/remote/billing/tick` request. Zero-balance auto-termination never fires.

- **Severity**: HIGH
- **Source ticket**: INFRA-005
- **Status**: Open
- **Owning area**: Remote Compute / Billing
- **Verdict**: Claim **confirmed**. `app/services/compute_billing.py` contains no `run_compute_billing_timer` function and no async background loop. `app/main.py` (lines 799-806) registers eight startup tasks — none of which is a compute billing timer. The setting `S.compute_billing_poll_interval` (line 2138 of `settings.py`) is defined but never read at runtime by any background loop.
- **One-line impact**: Compute charges are never assessed automatically; users consume EC2 and K8s resources at zero cost after wallet balance is manually zeroed, and the zero-balance termination safeguard is entirely inactive.
- **Related tickets**: INFRA-005 (core billing design), INFRA-004 (K8s launcher), EC2 launcher billing integration.

## 2. Current-State Investigation (root cause)

### What exists

`app/services/compute_billing.py` provides:
- `record_billing_tick(user_sub, ...)` — writes a ledger entry, deducts from wallet, updates monthly totals, fires spending alerts.
- `check_spending_alerts(user_sub)` — reads thresholds from the `BUDGET` item and sends alerts.
- `get_rate(resource_type, type_or_preset)` — rate card lookup (EC2_RATES, K8S_RATES).
- Manual HTTP endpoint at `POST /ui/remote/billing/tick` (router `app/routers/compute_billing.py:156-187`).

The setting `S.compute_billing_poll_interval` is declared at `app/core/settings.py:2138` with a default of `300` seconds (5 minutes). It is set but not consumed anywhere.

### What is missing

No function named `run_compute_billing_timer` (or equivalent) exists anywhere in `app/services/compute_billing.py` or any other module. A `grep` for `run_compute_billing`, `billing_timer`, or `start_compute_billing` across the entire `app/` tree returns zero results. The startup event handler list in `app/main.py` (lines 799-806) includes `start_k8s_ttl_checker_task` (line 708) and `start_ec2_idle_checker_task` (line 696) but no billing timer.

### Comparison with working background tasks

The existing patterns for K8s and EC2 background tasks follow a consistent three-part structure:
1. A blocking loop function: `async def run_pod_ttl_checker(*, poll_interval: int = 300)` at `k8s_launcher.py:328-337`.
2. A startup registration function: `def start_k8s_ttl_checker_task()` at `k8s_launcher.py:340-344`, gated by a feature flag (`S.k8s_ttl_checker_enabled`).
3. Registration in `app/main.py`: `app.add_event_handler("startup", start_k8s_ttl_checker_task)` at line 708.

None of these three parts exist for compute billing.

### Zero-balance auto-terminate

`record_billing_tick` calls `_deduct_from_wallet` which raises `InsufficientBalanceError` if the balance would go negative. The router catches this and returns HTTP 402. But without the background timer, `record_billing_tick` is never called automatically; thus `InsufficientBalanceError` is never raised for a running resource and no auto-termination logic (which would need to be added) is ever triggered.

---

## 3. Impact / Exploit / Blast Radius

**Financial risk (platform)**:
- Every running EC2 instance and K8s pod consumes compute resources without generating revenue. A user who deposits any amount to their wallet can run resources indefinitely — the wallet is only charged via the manual endpoint.
- At the lowest K8s rate (`"small": 0.1 cents/min`), a user running a pod for a month (44,640 minutes) should be billed 4,464 cents ($44.64). With the timer absent, they pay nothing.

**Correctness**:
- Monthly spend summaries (`GET /ui/remote/billing/spending`) and resource breakdowns (`GET /ui/remote/billing/resources`) reflect only ticks that were manually posted. They will show `0` for any resource that was never manually ticked.
- Budget thresholds (50%, 80%, 100%) are only checked on `record_billing_tick`. Without the timer, users never receive spending alerts.

**Zero-balance termination**: As noted, the auto-terminate safeguard is inactive. A malicious or mistaken user can run resources after their wallet is empty.

**Blast radius**: All users with running EC2 instances or K8s pods are affected. Every billable-minute since the compute features were deployed (INFRA-004/005) has gone uncharged if no manual tick was sent.

## 4. Fix Design (code-level)

### Part 1: Add `run_compute_billing_timer` to `app/services/compute_billing.py`

The timer must enumerate all running EC2 instances and K8s pods system-wide, compute elapsed time since the last billing tick, and call `record_billing_tick` for each. A per-resource "last billed at" timestamp must be tracked to compute `duration_minutes` accurately.

```python
# Add to app/services/compute_billing.py

import asyncio

async def run_compute_billing_timer(*, poll_interval: int | None = None) -> None:
    """Background task: bill all running compute resources every poll_interval seconds."""
    interval = poll_interval if poll_interval is not None else S.compute_billing_poll_interval
    while True:
        try:
            _tick_all_running_resources()
        except Exception:
            logger.exception("compute_billing_timer error")
        await asyncio.sleep(interval)


def _tick_all_running_resources() -> int:
    """Enumerate all running EC2 instances and K8s pods; emit billing ticks.

    Returns the total number of ticks emitted.
    """
    from app.services.ec2_launcher import _scan_all_running_instances
    from app.services.k8s_launcher import _scan_all_running_pods

    ticked = 0
    now = now_ts()

    for inst in _scan_all_running_instances():
        user_sub = inst.get("user_sub", "")
        resource_id = inst.get("instance_id", "")
        last_billed = int(inst.get("last_billed_at", 0))
        if not last_billed:
            last_billed = int(inst.get("started_at", now))
        elapsed_minutes = max(0.0, (now - last_billed) / 60.0)
        if elapsed_minutes < 0.5:
            continue  # avoid sub-half-minute ticks

        try:
            record_billing_tick(
                user_sub,
                resource_type="ec2",
                resource_id=resource_id,
                resource_label=inst.get("label", ""),
                instance_type_or_preset=inst.get("instance_type", "t3.micro"),
                event="periodic_tick",
                duration_minutes=elapsed_minutes,
            )
            _update_last_billed_at("ec2", user_sub, resource_id, now)
            ticked += 1
        except InsufficientBalanceError:
            logger.warning(
                "compute_billing_zero_balance user_sub=%s resource_id=%s — terminating",
                user_sub, resource_id,
            )
            _auto_terminate_resource("ec2", user_sub, resource_id)

    for pod in _scan_all_running_pods():
        user_sub = pod.get("user_sub", "")
        resource_id = pod.get("pod_id", "")
        last_billed = int(pod.get("last_billed_at", 0))
        if not last_billed:
            last_billed = int(pod.get("started_at", now))
        elapsed_minutes = max(0.0, (now - last_billed) / 60.0)
        if elapsed_minutes < 0.5:
            continue

        try:
            record_billing_tick(
                user_sub,
                resource_type="k8s",
                resource_id=resource_id,
                resource_label=pod.get("label", ""),
                instance_type_or_preset=pod.get("preset", "small"),
                event="periodic_tick",
                duration_minutes=elapsed_minutes,
            )
            _update_last_billed_at("k8s", user_sub, resource_id, now)
            ticked += 1
        except InsufficientBalanceError:
            logger.warning(
                "compute_billing_zero_balance user_sub=%s resource_id=%s — terminating",
                user_sub, resource_id,
            )
            _auto_terminate_resource("k8s", user_sub, resource_id)

    logger.info("compute_billing_timer_tick ticked=%d", ticked)
    return ticked


def _update_last_billed_at(resource_type: str, user_sub: str, resource_id: str, ts: int) -> None:
    table = T.ec2_instances if resource_type == "ec2" else T.k8s_pods
    sk = f"INST#{resource_id}" if resource_type == "ec2" else f"POD#{resource_id}"
    table.update_item(
        Key={"user_sub": user_sub, "sk": sk},
        UpdateExpression="SET last_billed_at = :t",
        ExpressionAttributeValues={":t": ts},
    )


def _auto_terminate_resource(resource_type: str, user_sub: str, resource_id: str) -> None:
    try:
        if resource_type == "ec2":
            from app.services.ec2_launcher import terminate_instance
            terminate_instance(user_sub, resource_id)
        else:
            from app.services.k8s_launcher import terminate_pod
            terminate_pod(user_sub, resource_id)
    except Exception:
        logger.exception(
            "compute_billing_auto_terminate_failed user_sub=%s resource_id=%s",
            user_sub, resource_id,
        )


def start_compute_billing_task() -> None:
    """Register the billing timer background task at app startup."""
    if S.compute_billing_enabled:
        asyncio.ensure_future(run_compute_billing_timer())
        logger.info("Compute billing background timer started (interval=%ds)", S.compute_billing_poll_interval)
```

`_scan_all_running_instances` and `_scan_all_running_pods` are thin wrappers around the existing table scans in `ec2_launcher.py` and `k8s_launcher.py`, made accessible without a `user_sub` filter (system-wide scan). The `last_billed_at` field must be added to the `ec2_instances` and `k8s_pods` DDB table schemas (no GSI required — it is only a write target).


This follows the same pattern as `S.ec2_auto_terminate_enabled` at line 2045 and `S.k8s_ttl_checker_enabled` at line 2119.

### Part 3: Register the startup task in `app/main.py`

After line 799 (with the other startup event handlers):

```python
from app.services.compute_billing import start_compute_billing_task
app.add_event_handler("startup", start_compute_billing_task)
```

### Dev/Prod parity (SECOPS-007)

- **Dev mode**: `S.k8s_mock_enabled = True` means pods exist in `_MockK8sStore` (in-memory) but their DDB records are real. `_scan_all_running_pods` queries DynamoDB Local — this works correctly in dev with no additional mocking.
- **Prod mode**: The same DDB scan runs against AWS DynamoDB. No code path diverges.
- **KMS / encryption**: Not relevant for billing tick logic.
- **Feature flag**: `COMPUTE_BILLING_ENABLED=0` disables the timer in dev for tests that want to fire ticks manually, preserving backward compatibility with existing manual-tick tests.

### Manual QA steps

1. `just restart`.
2. Deposit 100 cents to a test user's wallet.
3. Launch an EC2 instance or K8s pod (small preset, rate 0.1 c/min).
4. Wait for one poll interval (or lower `COMPUTE_BILLING_POLL_INTERVAL=10` in `.env.local`).
5. Check `GET /ui/remote/billing/spending` — `total_cents` should be non-zero.
6. Check `GET /ui/remote/billing/history` — at least one `periodic_tick` entry should appear.
7. Set wallet balance to 0 in DDB and wait for the next tick — pod/instance should transition to `terminated`.

### Rollout

- **Effort**: M (1-2 days: implement timer, scanner helpers, `last_billed_at` DDB field, tests)
- **Risk**: Medium. The timer touches all users' wallet balances. Must be tested thoroughly with rate-limiting to avoid runaway charges during a misconfigured rollout.
- **Sequencing**: Deploy with `COMPUTE_BILLING_ENABLED=0` first; verify DDB schema changes; then enable with a low-traffic period window.
- **Rollback**: Set `COMPUTE_BILLING_ENABLED=0` in the environment. No wallet adjustments are needed for a brief rollback since the timer only deducts in real time (no retroactive backfill on rollback).
