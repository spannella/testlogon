# GAP-0292: `BroadcastPrice.tsx` Component Does Not Exist — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; all file:line citations confirmed.

## 1. Summary & Classification

**Bug**: The viewer-facing `BroadcastPrice.tsx` React component, specified in LCOM-004 §3.8, does not exist anywhere in the repository. As a result, `ProductShelfCard` in `frontend/src/pages/broadcast/ProductShelf.tsx` has no way to render a struck-through original price, an effective broadcast-discounted price, a "LIVE DEAL" badge, or an expiry countdown for broadcast-exclusive pricing set by the broadcaster. Every viewer watching a live broadcast sees only the static catalog price, regardless of any active discount.

**Severity**: HIGH (source ticket LCOM-004). Effort: M.

**Status**: Open. No investigation doc exists; claim is confirmed by filesystem search.

**Claim verdict**: Confirmed. `find /home/ubuntu/testlogon/frontend/src -name "BroadcastPrice*"` returns no results. The backend endpoints `PATCH /broadcast/sessions/{session_id}/products/{item_id}/price` and `DELETE .../price` at `app/routers/broadcast.py:2223–2310` are fully implemented and return a correctly shaped `BroadcastPriceOut`. The `BroadcastShelfItemOut` model at `app/routers/broadcast.py:2065–2088` includes all required pricing fields. Only the viewer UI component is missing.

**Related tickets**: GAP-0291 (the `ShelfItem` TypeScript interface must be extended first, as `BroadcastPrice.tsx` will consume those fields); GAP-0293 (`BroadcastPriceEditor.tsx`, the broadcaster-side companion, is also absent).

**Owning area**: Frontend / Broadcast viewer UI.

## 2. Current-State Investigation (Root Cause)

### What the backend produces

After a broadcaster calls `PATCH /broadcast/sessions/{id}/products/{item_id}/price`, the `broadcast_product_shelf` DynamoDB table is updated and every subsequent `GET /broadcast/sessions/{id}/products` response includes (per `app/routers/broadcast.py:2080–2087`):

```python
broadcast_price_cents: Optional[int] = None   # the discounted price
broadcast_price_expires_at: Optional[int] = None  # Unix timestamp of expiry
broadcast_price_set_at: Optional[int] = None
effective_price_cents: Optional[int] = None   # resolved: broadcast_price if active, else price_cents
is_broadcast_price: bool = False              # True iff broadcast discount is currently active
discount_pct: int = 0                         # percentage saving
original_price_cents: Optional[int] = None   # catalog price, for strikethrough display
```

Additionally, when the session is live, `set_broadcast_price` in `app/services/broadcast_product_shelf.py:315–396` publishes an SSE event `shelf:price_update` carrying the full shelf item payload. The frontend `ProductShelf.tsx:131–161` already has handlers for `shelf:add`, `shelf:remove`, and `shelf:reorder` custom window events, but has no handler for `shelf:price_update`.

### What the frontend currently renders

`frontend/src/pages/broadcast/ProductShelf.tsx:63–104` defines `ProductShelfCard`:

```tsx
// ProductShelf.tsx:85–87 — always catalog price; no broadcast pricing logic
<p className="text-sm font-semibold text-primary"
   aria-label={`Price: ${formatPrice(item.price_cents, item.currency)}`}>
  {formatPrice(item.price_cents, item.currency)}
</p>
```

There is no reference to `effective_price_cents`, `is_broadcast_price`, `discount_pct`, `broadcast_price_expires_at`, or `original_price_cents` anywhere in `ProductShelf.tsx`. The `ShelfItem` type consumed by this component also lacks these fields (GAP-0291), completing the two-layer gap.

### Root cause

LCOM-004 specified a viewer-side `BroadcastPrice.tsx` component to be integrated into each `ProductShelfCard`. The backend was implemented; the frontend component was not created. The gap is a straightforward frontend omission — no server-side work is required.

## 3. Impact / Exploit / Blast Radius

1. **Broadcast discount invisible to all viewers**: Any broadcaster who activates a time-limited price drop (e.g., "first 100 viewers pay $5 instead of $20") has that discount silently ignored. The viewer sees and pays the full catalog price. The feature is, from the user's perspective, completely broken even though the backend is correct.

2. **Expiry countdown absent**: Even if a broadcaster sets a 10-minute flash deal via `expires_in_seconds`, there is no countdown shown. Viewers have no urgency signal; the commerce conversion driver is lost.

3. **LIVE DEAL badge absent**: The `shelf:price_update` SSE event is published but no component listens or renders a badge. Real-time deal notifications do not reach the viewer.

4. **Cart price mismatch**: `ProductShelf.tsx:44–52` passes `unit_price_cents: item.price_cents` to `addCartItem`. When a broadcast price is active, the cart will contain the wrong (full) price. Downstream checkout charges the viewer the full amount while the broadcaster intends to offer a discount — creating either customer dissatisfaction or manual refund overhead.

5. **No security or integrity risk**: This is a UI presentation gap, not an authorization or data-integrity issue. No user can bypass pricing by exploiting this gap; the backend enforces that `broadcast_price_cents < price_cents` at `app/services/broadcast_product_shelf.py:347–352`.

**Blast radius**: All viewers of any live broadcast session where the broadcaster has set a broadcast-exclusive price. The issue is production-impacting for any broadcaster using the pricing API programmatically.

## 4. Fix Design (Code-Level)

### 4a. Create `BroadcastPrice.tsx`

Create `frontend/src/pages/broadcast/BroadcastPrice.tsx` as a self-contained presentational component. It accepts a `ShelfItem` (post-GAP-0291 extended type) and renders the broadcast pricing UI:

```tsx
// frontend/src/pages/broadcast/BroadcastPrice.tsx

import { useEffect, useState } from "react";
import { Badge } from "@/components/ui/badge";
import type { ShelfItem } from "@/api/endpoints/broadcast-shelf";

interface BroadcastPriceProps {
  item: ShelfItem;
}

function useExpiryCountdown(expiresAt: number | null): string | null {
  const [label, setLabel] = useState<string | null>(null);

  useEffect(() => {
    if (!expiresAt) { setLabel(null); return; }
    const update = () => {
      const seconds = Math.max(0, expiresAt - Math.floor(Date.now() / 1000));
      if (seconds === 0) { setLabel("Expired"); return; }
      const m = Math.floor(seconds / 60);
      const s = seconds % 60;
      setLabel(m > 0 ? `${m}m ${s}s` : `${s}s`);
    };
    update();
    const id = setInterval(update, 1000);
    return () => clearInterval(id);
  }, [expiresAt]);

  return label;
}

function formatPrice(cents: number, currency = "USD"): string {
  return new Intl.NumberFormat("en-US", { style: "currency", currency }).format(cents / 100);
}

export function BroadcastPrice({ item }: BroadcastPriceProps) {
  const countdown = useExpiryCountdown(item.broadcast_price_expires_at);
  const effectiveCents = item.effective_price_cents ?? item.price_cents;
  const isDiscounted = item.is_broadcast_price && item.broadcast_price_cents !== null;

  if (!isDiscounted) {
    return (
      <p className="text-sm font-semibold text-primary"
         aria-label={`Price: ${formatPrice(effectiveCents, item.currency)}`}>
        {formatPrice(effectiveCents, item.currency)}
      </p>
    );
  }

  return (
    <div className="space-y-0.5">
      <div className="flex items-center gap-1.5 flex-wrap">
        <p className="text-sm font-bold text-green-400"
           data-testid="broadcast-price-effective"
           aria-label={`Broadcast price: ${formatPrice(effectiveCents, item.currency)}`}>
          {formatPrice(effectiveCents, item.currency)}
        </p>
        <span className="text-xs line-through text-muted-foreground"
              data-testid="broadcast-price-original">
          {formatPrice(item.price_cents, item.currency)}
        </span>
        <Badge variant="destructive" className="text-[10px] px-1 py-0 h-4"
               data-testid="broadcast-price-badge">
          LIVE DEAL {item.discount_pct}% OFF
        </Badge>
      </div>
      {countdown && countdown !== "Expired" && (
        <p className="text-[10px] text-amber-400"
           data-testid="broadcast-price-countdown"
           aria-label={`Deal expires in ${countdown}`}>
          Ends in {countdown}
        </p>
      )}
      {countdown === "Expired" && (
        <p className="text-[10px] text-muted-foreground">Deal ended</p>
      )}
    </div>
  );
}
```

### 4b. Integrate `BroadcastPrice` into `ProductShelfCard`

In `frontend/src/pages/broadcast/ProductShelf.tsx`, replace the static price `<p>` at lines 85–87 with the new component:

```tsx
// Add to imports
import { BroadcastPrice } from "./BroadcastPrice";

// Replace lines 85–87 in ProductShelfCard
<BroadcastPrice item={item} />
```

### 4c. Wire the `shelf:price_update` SSE event

In `ProductShelf.tsx`, inside the existing `useEffect` SSE handler block (lines 132–161), add a handler for price updates:

```tsx
const handlePriceUpdate = (e: Event) => {
  const item = (e as CustomEvent<ShelfItem>).detail;
  setShelfItems((prev) =>
    prev.map((i) => (i.item_id === item.item_id ? item : i))
  );
};

window.addEventListener("shelf:price_update", handlePriceUpdate);
// ...in cleanup:
window.removeEventListener("shelf:price_update", handlePriceUpdate);
```

This requires that wherever the `shelf:price_update` SSE event is dispatched (the existing broadcast SSE consumer), it passes the full `BroadcastShelfItemOut` payload as the event detail.

### 4d. Cart price fix

Also update `addCartItem` call at `ProductShelf.tsx:44–52` to use `effective_price_cents`:

```tsx
unit_price_cents: item.effective_price_cents ?? item.price_cents,
```

### 4e. Dev/Prod parity (SECOPS-007)

No backend code is modified. The component reads from the same API response in both dev and prod. The `effective_price_cents` computation in `app/services/broadcast_product_shelf.py:_shelf_item_out_with_pricing` (which resolves whether the broadcast price is still valid based on `broadcast_price_expires_at`) is identical for the local DynamoDB-backed dev stack and the production DynamoDB path. There are no feature flags gating the pricing fields.

The `useExpiryCountdown` hook uses `Date.now()` which behaves identically in both environments. No mock or stub is needed.

### 4f. Alternatives considered

- **Inline the pricing UI directly into `ProductShelfCard`**: Would avoid a new file but entangle the countdown timer logic with the card component, making it harder to test in isolation. Rejected in favour of a dedicated component.
- **Show broadcast price only if `is_broadcast_price === true`, omit otherwise**: This is what the fix does. An alternative of always rendering a placeholder "no deal" state was rejected as it adds visual noise.
