# GAP-0227: Host Inventory Not Cleaned Up on Pod Termination — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code at `app/services/k8s_launcher.py`.

## 1. Summary & Classification

**Plain-English statement**: When a Kubernetes pod is terminated — whether through a direct user action (`terminate_pod`), the TTL expiry checker (`check_expired_pods`), or an administrative action — the corresponding host inventory entry that was (or should be) automatically created at launch time is never deleted. Host inventory entries for dead containers therefore accumulate indefinitely.

- **Severity**: HIGH
- **Source ticket**: INFRA-004
- **Status**: Open
- **Owning area**: Remote Compute / Host Inventory
- **Verdict**: Claim **confirmed**. The code at `app/services/k8s_launcher.py:260-286` updates the `k8s_pods` DDB record to `status="terminated"` and logs the event but contains no call to `host_inventory.delete_host`. The `host_id` field is read nowhere in the termination path.
- **One-line impact**: Stale host entries for terminated pods fill the user's Host Inventory, cause confusion when users attempt to connect to them, and consume against any per-user host inventory quota.
- **Related tickets**: GAP-0226 (prerequisite: without the registration fix, `host_id` is always empty and this fix has no data to act on), INFRA-004, INFRA-001.
- **Dependency note**: This fix is only effective after GAP-0226 is applied. Both must be deployed together for end-to-end correctness.

## 2. Current-State Investigation (root cause)

### Code path: `terminate_pod`

`terminate_pod` at `app/services/k8s_launcher.py:260-286`:

```python
def terminate_pod(user_sub: str, pod_id: str) -> Dict[str, Any]:
    item = get_pod(user_sub, pod_id)
    if not item:
        raise PodNotFound("Pod not found")
    if item["status"] in ("terminated",):
        raise PodAlreadyTerminated("Pod already terminated")

    k8s_pod_name = item.get("k8s_pod_name", "")
    namespace = item.get("namespace", "")

    if S.k8s_mock_enabled:
        _mock_store.delete_pod(k8s_pod_name, namespace)

    now = now_ts()
    T.k8s_pods.update_item(
        Key={"user_sub": user_sub, "sk": f"POD#{pod_id}"},
        UpdateExpression="SET #st = :st, terminated_at = :ta",
        ExpressionAttributeNames={"#st": "status"},
        ExpressionAttributeValues={":st": "terminated", ":ta": now},
    )
    item["status"] = "terminated"
    item["terminated_at"] = now
    logger.info("k8s_pod_terminated user_sub=%s pod_id=%s", user_sub, pod_id)
    return item
```

The `item` dict that is fetched via `get_pod` contains a `host_id` field (set to `""` currently, but intended to be a valid `host_id` after GAP-0226 is fixed). There is no branch that reads `item.get("host_id")`, imports `host_inventory`, or calls `delete_host`.

### Code path: `check_expired_pods` (TTL expiry)

The TTL expiry background loop at lines 289-321 calls `terminate_pod(item["user_sub"], item["pod_id"])` in a loop. It does not perform any host inventory cleanup independently — it fully delegates to `terminate_pod`, so the same gap applies. Once `terminate_pod` is fixed, TTL expiry also benefits automatically.

### Why it is broken

The termination function was written without the host inventory integration in mind (or the integration was deferred). The field `host_id` was reserved for exactly this purpose (it is initialized to `""` in the item dict at line 197) but no code was ever written to use it.

### Dev vs prod

The `host_inventory` service (`app/services/host_inventory.py`) and its `delete_host` function are environment-agnostic — they perform a DynamoDB `delete_item` operation. In dev mode the DynamoDB Local instance is used; in production, AWS DynamoDB is used. The same code path applies in both environments. No mock switching is needed.

## 3. Impact / Exploit / Blast Radius

This gap is **availability and data-integrity** in nature, not a security vulnerability.

**User-facing consequences**:
- Every terminated container pod leaves behind a "ghost" entry in the Host Inventory. The user sees hosts that no longer exist.
- Attempting Quick Connect or opening a terminal to a ghost host will fail with a connection-refused or DNS-resolution error since the `service_hostname` resolves to nothing after pod termination.
- If the host inventory has a per-user cap (`S.host_inventory_max_per_user`), accumulation of ghost entries will eventually block new host registrations, making the feature entirely unusable for long-running users.

**Operational consequences**:
- The host inventory table grows unboundedly with stale records. Over time, query latency on `list_hosts` degrades (more items per `user_sub` partition key).
- Admin dashboards that aggregate host counts across users will overreport active infrastructure.

**Financial**: No direct financial impact. However, if the host count feeds into a billing or quota system in a future feature, stale records could incorrectly inflate usage.

**Blast radius**: All pods ever created through the K8s launcher (after the GAP-0226 fix makes `host_id` non-empty) will have orphaned host entries unless explicitly cleaned up. There is no automatic TTL or expiry on host inventory records. A one-time cleanup script will be required at rollout to handle historically stale entries.

## 4. Fix Design (code-level)

### Change: `app/services/k8s_launcher.py` — `terminate_pod`

Add a conditional `delete_host` call immediately before the logger line at the end of `terminate_pod`:

```python
def terminate_pod(user_sub: str, pod_id: str) -> Dict[str, Any]:
    item = get_pod(user_sub, pod_id)
    if not item:
        raise PodNotFound("Pod not found")
    if item["status"] in ("terminated",):
        raise PodAlreadyTerminated("Pod already terminated")

    k8s_pod_name = item.get("k8s_pod_name", "")
    namespace = item.get("namespace", "")

    if S.k8s_mock_enabled:
        _mock_store.delete_pod(k8s_pod_name, namespace)

    now = now_ts()
    T.k8s_pods.update_item(
        Key={"user_sub": user_sub, "sk": f"POD#{pod_id}"},
        UpdateExpression="SET #st = :st, terminated_at = :ta",
        ExpressionAttributeNames={"#st": "status"},
        ExpressionAttributeValues={":st": "terminated", ":ta": now},
    )
    item["status"] = "terminated"
    item["terminated_at"] = now

    # Clean up host inventory entry (GAP-0227)
    host_id = item.get("host_id", "")
    if host_id:
        try:
            from app.services.host_inventory import delete_host, HostNotFound
            delete_host(user_sub, host_id)
            logger.info(
                "k8s_pod_host_deregistered user_sub=%s pod_id=%s host_id=%s",
                user_sub, pod_id, host_id,
            )
        except HostNotFound:
            logger.warning(
                "k8s_pod_host_deregister_notfound user_sub=%s pod_id=%s host_id=%s",
                user_sub, pod_id, host_id,
            )
        except Exception:
            logger.exception(
                "k8s_pod_host_deregister_failed user_sub=%s pod_id=%s host_id=%s",
                user_sub, pod_id, host_id,
            )

    logger.info("k8s_pod_terminated user_sub=%s pod_id=%s", user_sub, pod_id)
    return item
```

### Design decisions

- **`if host_id:` guard**: Ensures the fix is a no-op for all existing pods that have `host_id: ""` (i.e., pods created before GAP-0226 was fixed). This makes the change backward-compatible without requiring a migration.
- **Failure isolation**: `delete_host` failures are caught and logged but do not raise — the pod status is already updated to `terminated` and the K8s workload is already deleted. A failed host cleanup is less harmful than an exception that rolls back the pod termination state.
- **TTL path**: `check_expired_pods` calls `terminate_pod`, so it automatically inherits the cleanup behavior.
- **Late import**: The `from app.services.host_inventory import ...` is inside the `if host_id:` block to avoid loading the module on every call in the pre-GAP-0226 world where `host_id` is always empty.

### Dev/Prod parity (SECOPS-007)

- The `delete_host` function in `host_inventory.py` is a pure DDB `delete_item` call — it operates identically against DynamoDB Local (dev) and AWS DynamoDB (prod).
- No environment-specific code path is added; no feature flag is needed for this fix beyond what GAP-0226 requires.
- The `S.k8s_mock_enabled` flag remains relevant only for the K8s API call (`_mock_store.delete_pod`), not for host inventory cleanup.

### One-time cleanup migration

For pods that were terminated before this fix was applied (and after GAP-0226 is deployed), a migration script should:
1. Scan the `k8s_pods` table for items where `status="terminated"` and `host_id` is non-empty.
2. Call `delete_host(user_sub, host_id)` for each, ignoring `HostNotFound`.

A script skeleton:
```python
# scripts/migrate_cleanup_terminated_pod_hosts.py
from app.services import k8s_launcher, host_inventory
from app.core.tables import T

resp = T.k8s_pods.scan(
    FilterExpression="attribute_exists(host_id) AND #st = :t AND host_id <> :empty",
    ExpressionAttributeNames={"#st": "status"},
    ExpressionAttributeValues={":t": "terminated", ":empty": ""},
)
for item in resp.get("Items", []):
    try:
        host_inventory.delete_host(item["user_sub"], item["host_id"])
        print(f"Cleaned {item['pod_id']} -> {item['host_id']}")
    except host_inventory.HostNotFound:
        pass  # already gone
```

## 5. Testing, Verification & Rollout

### Regression test (fails-before / passes-after)

Add to `tests/test_k8s_launcher.py`:

```python
def test_terminate_pod_removes_host_inventory(monkeypatch, ddb):
    """GAP-0227: terminate_pod must delete the host inventory entry when host_id is set."""
    deleted_hosts = []

    def fake_delete_host(user_sub, host_id):
        deleted_hosts.append((user_sub, host_id))

    monkeypatch.setattr(
        "app.services.k8s_launcher.delete_host", fake_delete_host, raising=False
    )

    # Manually plant a pod record with a host_id already set (as if GAP-0226 worked)
    from app.core.tables import T
    from app.core.time import now_ts
    T.k8s_pods.put_item(Item={
        "user_sub": "user_alice",
        "sk": "POD#p_deadbeef",
        "pod_id": "p_deadbeef",
        "k8s_pod_name": "ws-alice-deadbeef",
        "namespace": "user-alice",
        "label": "Test Pod",
        "status": "running",
        "host_id": "h_abc123",
        "created_at": now_ts(),
        "expires_at": now_ts() + 3600,
    })

    import app.services.k8s_launcher as launcher
    launcher.terminate_pod("user_alice", "p_deadbeef")

    # Before fix: deleted_hosts == []
    # After fix:  deleted_hosts == [("user_alice", "h_abc123")]
    assert len(deleted_hosts) == 1, "delete_host must be called once"
    assert deleted_hosts[0] == ("user_alice", "h_abc123")


def test_terminate_pod_no_host_id_does_not_call_delete(monkeypatch, ddb):
    """GAP-0227: terminate_pod with host_id='' must not attempt host cleanup."""
    delete_calls = []

    monkeypatch.setattr(
        "app.services.k8s_launcher.delete_host",
        lambda *a, **kw: delete_calls.append(a),
        raising=False,
    )

    from app.core.tables import T
    from app.core.time import now_ts
    T.k8s_pods.put_item(Item={
        "user_sub": "user_alice",
        "sk": "POD#p_nohostid",
        "pod_id": "p_nohostid",
        "k8s_pod_name": "ws-alice-nohostid",
        "namespace": "user-alice",
        "status": "running",
        "host_id": "",  # old pod, pre-GAP-0226

    })

    import app.services.k8s_launcher as launcher
    launcher.terminate_pod("user_alice", "p_nohostid")
    assert delete_calls == [], "delete_host must not be called when host_id is empty"
```

### Manual QA steps

1. `just restart` to reset state.
2. Apply both GAP-0226 and GAP-0227 fixes together.
3. Launch a pod and verify the host appears in Host Inventory.
4. Terminate the pod via the UI.
5. Refresh Host Inventory — the entry should be gone.
6. Optionally trigger TTL expiry by setting `expires_at` to `now_ts() - 1` in DDB and waiting for the TTL checker to run, or call `check_expired_pods()` directly in a test.

### Metrics / observability

- Add `k8s_pod_host_deregistered_total` counter metric on successful cleanup.
- Add `k8s_pod_host_deregister_failed_total` for exception-path failures (signals a host inventory / DDB connectivity issue).

### Rollout

- **Effort**: S (< 1 day, closely coupled to GAP-0226)
- **Risk**: Low. The guard `if host_id:` makes this change a no-op for all pre-existing pods. Failure of `delete_host` does not break pod termination.
- **Sequencing**: Must be deployed together with GAP-0226, or immediately after. Deploying GAP-0227 alone (without GAP-0226) is safe but produces no observable benefit.
- **Rollback**: Remove the `if host_id:` block. Orphaned host entries will need manual cleanup after rollback.
