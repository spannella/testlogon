# GAP-0124: `behavior="end"` Not Fully Wired in Accept Handler — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual codebase. No prior investigation doc exists.

## 1. Summary & Classification

**Claim verdict: Confirmed.** The `accept_private_request_route` handler in `app/routers/broadcast.py` (decorator at line 1058, function body lines 1062–1143) handles `body.behavior == "pause"` explicitly but has no branch for `body.behavior == "end"`. When the creator accepts a private request with `behavior="end"`, the broadcast session is transitioned to `"private"` status and the private request is accepted — but `stop_session_with_provider()` is never called. The underlying MediaLive channel (or equivalent live streaming provider) continues ingesting and transmitting video at platform expense.

- **Severity**: HIGH
- **Source ticket**: BCAST-011
- **Status**: Open
- **Owning area**: Broadcast Accept Handler, Private Session Lifecycle (`app/routers/broadcast.py`, `app/services/broadcast_orchestrator.py`)
- **Impact**: Provider-side streaming resources are not torn down when the creator chooses `behavior="end"`. This means the live channel continues running, accumulating costs, potentially consuming ingest bandwidth, and holding MediaLive resources that could conflict with future sessions on the same channel.
- **Related tickets**: BCAST-011, GAP-0123 (billing atomicity in the same private session flow), SECOPS-007 (dev/prod parity)
- **Dependencies**: `stop_session_with_provider` from `app/services/broadcast_orchestrator.py` is already imported in `broadcast.py` at line 36 (confirmed: line 36 is the import; line 37 in the import block).

## 2. Current-State Investigation (root cause)

The `PrivateRequestAcceptIn` model (line 951) validates that `behavior` must be one of `"pause"`, `"end"`, or `"continue"`:

```python
class PrivateRequestAcceptIn(BaseModel):
    ...
    behavior: str = Field(..., pattern="^(pause|end|continue)$")
```

The accept route handler at line 1062–1143 processes the request in the following sequence:

1. Authorization check: verifies caller is the broadcaster (line 1071–1072).
2. Fetch private request from DDB (line 1078–1080).
3. Create WebRTC call session (line 1084–1094).
4. Accept private request in DDB — sets status to `"accepted"`, stores `behavior` and `call_id` (line 1097).
5. Transition broadcast session to `"private"` status (line 1100–1108).
6. Record audit event (line 1112–1118).
7. Publish SSE events (line 1121–1133).

Step 7 contains the only behavior-specific branch:

```python
if body.behavior == "pause":
    broadcast_sse_publish(session_id, {
        "_type": "private:broadcast_paused",
        "session_id": session_id,
        "message": "Creator is in a private session",
    })
```

There is no corresponding `elif body.behavior == "end":` block. When `behavior="end"` is submitted, the handler completes successfully, the broadcast session record shows `status="private"` with `private_behavior="end"`, and the creator's client receives the `PrivateAcceptOut` response — but the live provider is never told to stop the public stream.

Searching for where `stop_session_with_provider` is called elsewhere confirms the pattern that should be applied:

- `stop_session_route` at `broadcast.py:403–433`: calls `stop_session_with_provider(session_id=..., actor=..., reason=body.reason)` (reason is dynamic, not hardcoded `"creator-stop"`).
- `app/services/delegate_broadcast.py:404`: calls it with `reason=f"Stopped by delegate {delegate_id}"` (not hardcoded `"delegate-end"`).

Both call sites pass `session_id`, `actor`, and a `reason` string. The same three-argument call is needed here.

**What `stop_session_with_provider` does** (`broadcast_orchestrator.py:125–175`): it calls `provider.stop(current, ...)` on the live streaming provider (MediaLive or the mock provider in dev), transitions the broadcast session to `"stopping"` → `"stopped"`, and — if `broadcast_recording_enabled` — triggers the recording pipeline. This is the correct and complete teardown sequence.

**Why the session is in `"private"` status, not `"live"` or `"ready"`**: `stop_session_with_provider` guards on `current.status in {"ready", "live"}` (line 136). When the handler calls `transition_session_status(..., to_status="private")` at line 1100 before calling `stop_session_with_provider`, the session is already in `"private"` status, so the provider stop guard would short-circuit without actually stopping the provider.

This means the fix must call `stop_session_with_provider` **before** transitioning to `"private"`, or alternatively change the guard in `stop_session_with_provider` to also accept `"private"` as a valid source status. The cleanest approach is to add `"private"` to the allowed set inside `stop_session_with_provider` when `reason="go_private_end"`, or to call it before the status transition.

## 3. Impact / Exploit / Blast Radius

### Cost overrun

AWS MediaLive charges by the channel-hour. A channel that is "paused" by the `behavior="pause"` flow has its public stream paused at the application layer, but the MediaLive input is still active. A channel with `behavior="end"` is supposed to have the provider stop called, which would stop the MediaLive channel input and stop per-minute billing. Because `stop_session_with_provider` is never called, the provider's live channel continues running indefinitely.

For a session that completes a 60-minute private session and then the creator ends the broadcast, the MediaLive channel continues running until:
- An operator manually stops it via the AWS console.
- A watchdog timeout (if one exists — none is visible in the codebase).
- The server process restarts (which would not help; MediaLive is an external service).

AWS MediaLive channel costs can reach $15–$50/hour for HD channels. A single missed stop call on a high-activity platform with dozens of concurrent sessions could accumulate thousands of dollars in uncollected costs.

### State inconsistency

The broadcast session in DynamoDB is in `"private"` status with `private_behavior="end"`. The intended final state is `"stopped"`. If the end-private flow (which fires when the private call concludes) checks `private_behavior` and tries to resume or stop accordingly, it may issue redundant state transitions or skip the stop call again because the session is not in an expected live-provider-active state.

### Blast radius

Every creator who accepts a private request with `behavior="end"` triggers this gap. The number of affected sessions equals the count of `go_private` audit events with `behavior="end"` in DynamoDB. No financial or security breach is involved — this is a cost and operational integrity issue.

## 4. Fix Design (code-level)

### 4.1 Call `stop_session_with_provider` before status transition for `behavior="end"`

The fix inserts a conditional call in `accept_private_request_route` between step 3 (WebRTC call creation) and step 5 (status transition to `"private"`). Because `stop_session_with_provider` guards on `status in {"ready", "live"}`, the call must happen while the session is still in its pre-private status.

```python
# app/routers/broadcast.py — inside accept_private_request_route, after call_id is set
# (~line 1097, before the accept_private_request DDB call)

# Accept the private request in DDB
result = accept_private_request(session_id, request_id, body.behavior, call_id)

# --- NEW BLOCK ---
if body.behavior == "end":
    # Tear down the public stream immediately; session must still be live/ready
    # at this point (transition to "private" has not happened yet).
    try:
        stop_session_with_provider(
            session_id=session_id,
            actor=ctx["user_sub"],
            reason="go_private_end",
            correlation_id=_correlation_id(request),
        )
    except Exception:
        # Log but do not abort: the private session itself must still proceed.
        # The provider stop failure is non-fatal here; an operator alert will fire.
        import logging
        logging.getLogger(__name__).exception(
            "go_private_end: stop_session_with_provider failed for session %s", session_id
        )
# --- END NEW BLOCK ---

# Transition broadcast to private status (for both pause and end, record the transition)
transition_session_status(
    session_id=session_id,
    to_status="private",
    reason="go_private",
    actor=ctx["user_sub"],
    extra_fields={
        "private_session_id": request_id,
        "private_behavior": body.behavior,
    },
)
```

Note: the `stop_session_with_provider` call already transitions the session from `"live"/"ready"` → `"stopping"` → `"stopped"`. The subsequent `transition_session_status(..., to_status="private")` would then see `status="stopped"` and add the `"private"` transition as an additional record. This may be fine for audit purposes (the session went `live → stopped → private`) or the `"private"` status could be skipped when `behavior="end"` (since the session is effectively over). The simplest correct approach is to not issue the `"private"` transition when `behavior="end"`:

```python
if body.behavior != "end":
    transition_session_status(
        session_id=session_id,
        to_status="private",
        reason="go_private",
        actor=ctx["user_sub"],
        extra_fields={
            "private_session_id": request_id,
            "private_behavior": body.behavior,
        },
    )
```

### 4.2 Publish `"private:broadcast_ended"` SSE event for `behavior="end"`

The existing code publishes `"private:broadcast_paused"` for `behavior="pause"`. Clients should receive an equivalent notification for `behavior="end"`:

```python
if body.behavior == "pause":
    broadcast_sse_publish(session_id, {
        "_type": "private:broadcast_paused",
        "session_id": session_id,
        "message": "Creator is in a private session",
    })
elif body.behavior == "end":
    broadcast_sse_publish(session_id, {
        "_type": "private:broadcast_ended",
        "session_id": session_id,
        "message": "Broadcast has ended for private session",
    })
```

### 4.3 SECOPS-007 dev/prod parity

`stop_session_with_provider` calls `get_broadcast_provider()`, which returns a mock provider in dev mode (`app/services/broadcast_provider.py`). The mock provider's `stop()` method is a no-op but does not raise. The status transitions still happen. The fix therefore runs the same code path in dev and production, with the provider's behavior being the only environmental difference.

### 4.4 Alternatives considered

- **Add `"private"` to the allowed statuses in `stop_session_with_provider`**: Possible but misleading — the intent of the guard is to only stop live/ready channels. Widening it pollutes a guard that is correct for all other callers.
- **Defer the stop to the end of the private call**: Already happens via `end_private_session` → the broader flow handles teardown after the call. But the public live stream should stop at accept time, not at call end, to avoid billing the creator for live minutes they are not using.
- **Separate endpoint for `behavior="end"` accept**: Over-engineering; the `behavior` field already carries this intent.

## 5. Testing, Verification & Rollout

### Regression test (fails before fix, passes after)

Add to `tests/test_broadcast_accept_private.py`:

```python
import pytest
from unittest.mock import patch, MagicMock, call
from fastapi.testclient import TestClient
from app.main import app

@pytest.fixture
def client():
    return TestClient(app)

def test_accept_private_behavior_end_calls_stop_provider(
    client, alice_broadcaster_session, bob_viewer_private_request
):
    """Accepting with behavior='end' must call stop_session_with_provider.

    FAILS BEFORE FIX: stop_session_with_provider is never called.
    PASSES AFTER FIX: stop_session_with_provider is called with reason='go_private_end'.
    """
    session_id = alice_broadcaster_session["session_id"]
    request_id = bob_viewer_private_request["private_session_id"]

    with patch(
        "app.routers.broadcast.stop_session_with_provider"
    ) as mock_stop:
        mock_stop.return_value = MagicMock(status="stopped")
        response = client.post(
            f"/ui/broadcast/sessions/{session_id}/private/{request_id}/accept",
            json={"behavior": "end"},
            headers={
                "Cookie": alice_broadcaster_session["cookies"],
                "x-csrf-token": alice_broadcaster_session["csrf_token"],
            },
        )
    assert response.status_code == 200
    mock_stop.assert_called_once()
    call_kwargs = mock_stop.call_args.kwargs
    assert call_kwargs["session_id"] == session_id
    assert call_kwargs["reason"] == "go_private_end"


def test_accept_private_behavior_pause_does_not_stop_provider(
    client, alice_broadcaster_session, bob_viewer_private_request
):
    """Accepting with behavior='pause' must NOT call stop_session_with_provider.

    Ensures the fix does not regress the pause path.
    """
    session_id = alice_broadcaster_session["session_id"]
    request_id = bob_viewer_private_request["private_session_id"]

    with patch("app.routers.broadcast.stop_session_with_provider") as mock_stop:
        response = client.post(
            f"/ui/broadcast/sessions/{session_id}/private/{request_id}/accept",
            json={"behavior": "pause"},
            headers={
                "Cookie": alice_broadcaster_session["cookies"],
                "x-csrf-token": alice_broadcaster_session["csrf_token"],
            },
        )
    assert response.status_code == 200
    mock_stop.assert_not_called()


def test_accept_private_behavior_continue_does_not_stop_provider(
    client, alice_broadcaster_session, bob_viewer_private_request
):
    """Accepting with behavior='continue' must NOT call stop_session_with_provider."""
    session_id = alice_broadcaster_session["session_id"]
    request_id = bob_viewer_private_request["private_session_id"]

    with patch("app.routers.broadcast.stop_session_with_provider") as mock_stop:
        response = client.post(
            f"/ui/broadcast/sessions/{session_id}/private/{request_id}/accept",
            json={"behavior": "continue"},

                "Cookie": alice_broadcaster_session["cookies"],
                "x-csrf-token": alice_broadcaster_session["csrf_token"],

    mock_stop.assert_not_called()
```

### Rollout

- **Effort**: S (the code change is 5–10 lines; the adjacent SSE event is 5 more lines).
- **Feature flag**: No flag needed; this is a correctness fix.
- **Backward compatibility**: Sessions already in `"private"` with `private_behavior="end"` will not be retroactively fixed. A one-off query for such sessions and a manual call to `stop_session_with_provider` (or equivalent) should be run post-deploy.
- **Risk**: Low. The `stop_session_with_provider` call is already battle-tested in the regular stop flow. The only new risk is the provider stop failing for a session that is already in `"private"` status (since `stop_session_with_provider` guards on `status in {"ready", "live"}`). This is handled by moving the stop call before the status transition (as described in section 4.1).
- **Sequencing**: Independent of GAP-0121/GAP-0122/GAP-0123; can be merged in any order.
