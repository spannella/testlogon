# GAP-0289: `ProductLinkCard.tsx` component does not exist — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code at
> `frontend/src/pages/broadcast/BroadcastChat.tsx` and
> `frontend/src/api/endpoints/broadcast-chat.ts`.

## 1. Summary & Classification

**Plain-English statement**: The backend endpoint `POST /broadcast/sessions/{id}/chat/product`
(line 1694 of `app/routers/broadcast.py`) emits SSE events of type `chat:product_link`
and stores `kind="product_link"` chat messages containing a rich `product_link` payload
(item ID, name, price, discount, image URL). However, the frontend component
`ProductLinkCard.tsx` that should render these messages does not exist anywhere in the
codebase. The `ChatMessage` TypeScript interface in `broadcast-chat.ts` also omits the
`product_link` field. When a broadcaster shares a product, viewers see either nothing or a
blank message bubble because `renderMessageContent` in `BroadcastChat.tsx` has no branch
for `kind === "product_link"`.

- **Severity**: HIGH — core viewer UX feature is completely non-functional
- **Source ticket**: LCOM-002
- **Owning area**: Broadcast Frontend / Live Commerce
- **Status**: Open
- **Claim accuracy**: Confirmed. `find frontend/src -name "ProductLinkCard*"` returns
  empty. Grep for `product_link` across all of `frontend/src/` returns zero results.
  `BroadcastChat.tsx` `renderMessageContent()` has branches for deleted, expired, and
  locked messages but no `product_link` branch.

**Impact in one line**: Broadcasters can share products from the backend API, but viewers
see nothing in the chat — the live-commerce purchase funnel is broken at the first step.

**Related tickets**: GAP-0290 (`ShelfProductPicker.tsx` also absent — the broadcaster UI
to trigger the product share), LCOM-002 write-up, `app/routers/broadcast.py` lines 1694–
1760, `BroadcastChatProductLinkOut` model (line 1506 of broadcast.py).

## 2. Current-State Investigation (root cause)

### Backend — fully implemented

`app/routers/broadcast.py` provides:

- **`BroadcastChatProductLinkOut`** model (line 1506) with fields: `item_id`,
  `category_id`, `name`, `description`, `price_cents`, `currency`, `image_url`,
  `broadcast_price_cents`, `broadcast_price_expires_at`, `effective_price_cents`,
  `is_broadcast_price`, `discount_pct`.
- **`POST /sessions/{id}/chat/product`** handler (line 1698) that validates the product
  is on the shelf, resolves the effective price, and calls
  `send_product_link_message()` which stores a `kind="product_link"` message.
- **SSE stream** (line 1808): the chat stream handler emits `event: chat:product_link`
  for these messages.

The backend is complete and correct.

### Frontend `ChatMessage` type — `product_link` field missing

`frontend/src/api/endpoints/broadcast-chat.ts`, lines 5–33, defines the `ChatMessage`
interface. It includes all other message fields (reactions, replies, expiry, lock,
tip, lottery) but has no `product_link` field:

```typescript
export interface ChatMessage {
  message_id: string;
  // … reactions, replies, expiry, lock …
  // ← no product_link field
}
```

### BroadcastChat.tsx — no product_link rendering branch

`frontend/src/pages/broadcast/BroadcastChat.tsx`, `renderMessageContent()` (lines 221–263):

```typescript
const renderMessageContent = (msg: ChatMessage) => {
  if (msg.deleted) { /* … */ }
  if (msg.expired) { /* … */ }
  if (msg.lock_price_cents && msg.is_unlocked === false) {
    return <ChatLockedCard … />;
  }
  return <span …>{msg.text}</span>;   // ← falls through here for kind="product_link"
};
```

A `kind="product_link"` message has `text: null` (the text field is not used for product
link messages). The fallthrough `<span>{msg.text}</span>` renders an empty span —
effectively invisible to the viewer.

The message list render loop (lines 287–370) has a single special-case for `kind="lottery"`
(checking `msg.kind === "lottery" && msg.lottery_id`), but no equivalent for
`kind="product_link"`.

### SSE event listener — `chat:product_link` not handled

The `useEffect` SSE listener (lines 64–143) handles `chat:message`, `chat:delete`,
`chat:reaction`, `chat:unlock`, and `chat:lottery` events. There is no
`es.addEventListener("chat:product_link", …)`. Product link messages received via SSE
are silently discarded.

### `sendChatProductLink` API function — does not exist

`broadcast-chat.ts` has no exported function to call `POST .../chat/product`. This is
the companion gap covered by GAP-0290 (the picker dialog that would call it).

### What the backend sends in the SSE stream

When `send_product_link_message()` is called, the backend stores the message with
`kind="product_link"` and a nested `product_link` dict containing all pricing snapshot
fields. The SSE stream at line 1808 checks `if out.get("kind") == "product_link": event_type = "chat:product_link"` — so the SSE event type is `chat:product_link`, not the
generic `chat:message`. The frontend SSE listener only handles `chat:message` events for
the default message path; a separate `addEventListener("chat:product_link", …)` listener
is required to receive these messages in real-time. Without it, product link messages
sent during a live session are invisible until the page is refreshed and
`getChatHistory()` fetches the stored messages — but even then, the `renderMessageContent`
fallthrough returns an empty span for `text: null` messages.

The full chain of missing pieces: (1) `ChatMessage.product_link` TypeScript field absent,
(2) no `chat:product_link` SSE listener, (3) no `kind === "product_link"` branch in
`renderMessageContent`, (4) no `ProductLinkCard` component to render. All four must be
addressed together for the feature to function end-to-end.

## 3. Impact / Exploit / Blast Radius

### User-facing

Broadcasters who attempt to share products (currently only via direct API call, since
the picker UI is also absent per GAP-0290) see no confirmation in the chat. Viewers
never see the product card. The live-commerce purchase funnel — share → view card →
click buy → checkout — is broken at step one.

### Missed revenue

Live commerce product sharing is a monetization feature. Every broadcast session during
which a product should have been shared but was invisible represents lost transaction
revenue.

### Not a security issue

There is no exploitable vulnerability here. The gap is a missing frontend component.
The backend correctly scopes `POST /chat/product` to the session creator (`ctx["user_sub"]
!= session.created_by` → 403).

### Blast radius scope

Only `BroadcastChat.tsx` and `broadcast-chat.ts` are affected. No other pages render
broadcast chat messages. The `kind="text"` message path is unaffected.

## 4. Fix Design (code-level)

### Step 1 — Create `ProductLinkCard.tsx`

Create `frontend/src/pages/broadcast/ProductLinkCard.tsx`:

```typescript
import { ShoppingCart, Tag, Zap } from "lucide-react";
import { Card, CardContent } from "@/components/ui/card";
import { Badge } from "@/components/ui/badge";
import { Button } from "@/components/ui/button";

export interface ProductLinkData {
  item_id: string;
  name: string;
  description?: string;
  price_cents: number;
  currency: string;
  image_url?: string;
  effective_price_cents: number;
  is_broadcast_price: boolean;
  discount_pct: number | null;
}

interface ProductLinkCardProps {
  sessionId: string;
  productLink: ProductLinkData;
}

export function ProductLinkCard({ sessionId, productLink }: ProductLinkCardProps) {
  const displayPrice = (productLink.effective_price_cents / 100).toFixed(2);
  const originalPrice = (productLink.price_cents / 100).toFixed(2);
  const hasDiscount = productLink.is_broadcast_price && productLink.discount_pct;

  const handleBuy = () => {
    // Navigate to the catalog product page; checkout handled there
    window.open(`/shop?item=${productLink.item_id}&session=${sessionId}`, "_blank");
  };

  return (
    <Card
      className="my-1 mx-1 max-w-xs border border-primary/20 bg-primary/5"
      data-testid="product-link-card"
    >
      <CardContent className="p-2">
        <div className="flex gap-2">
          {productLink.image_url && (
            <img
              src={productLink.image_url}
              alt={productLink.name}
              className="h-14 w-14 rounded object-cover shrink-0"
              data-testid="product-link-image"
            />
          )}
          <div className="flex-1 min-w-0">
            <p
              className="text-xs font-semibold truncate"
              data-testid="product-link-name"
            >
              {productLink.name}
            </p>
            {productLink.description && (
              <p className="text-[10px] text-muted-foreground line-clamp-2">
                {productLink.description}
              </p>
            )}
            <div className="mt-1 flex items-center gap-1.5">
              <span
                className="text-xs font-bold text-primary"
                data-testid="product-link-price"
              >
                {productLink.currency === "USD" ? "$" : productLink.currency}
                {displayPrice}
              </span>
              {hasDiscount && (
                <>
                  <span className="text-[10px] line-through text-muted-foreground">
                    ${originalPrice}
                  </span>
                  <Badge
                    variant="destructive"
                    className="text-[9px] px-1 py-0 h-4"
                    data-testid="product-link-discount"
                  >
                    <Zap className="h-2 w-2 mr-0.5" />
                    {productLink.discount_pct}% off
                  </Badge>
                </>
              )}
            </div>
          </div>
        </div>
        <Button
          size="sm"
          className="mt-2 w-full h-7 text-xs"
          onClick={handleBuy}
          data-testid="product-link-buy-btn"
        >
          <ShoppingCart className="mr-1 h-3 w-3" />
          Buy Now
        </Button>
        {productLink.is_broadcast_price && (
          <p className="mt-1 text-center text-[9px] text-amber-500 flex items-center justify-center gap-0.5">
            <Tag className="h-2.5 w-2.5" /> Live broadcast price
          </p>
        )}
      </CardContent>
    </Card>
  );
}
```

### Step 2 — Extend `ChatMessage` type in `broadcast-chat.ts`

Add `product_link` field to the `ChatMessage` interface:

```typescript
export interface ChatProductLink {
  item_id: string;
  name: string;
  description?: string;
  price_cents: number;
  currency: string;
  image_url?: string;
  effective_price_cents: number;
  is_broadcast_price: boolean;
  discount_pct: number | null;
}

export interface ChatMessage {
  // … existing fields …
  product_link?: ChatProductLink | null;   // ← NEW
}
```

Also add the `sendChatProductLink` API function:

```typescript
export const sendChatProductLink = (sessionId: string, itemId: string) =>
  api.post<ChatMessage>(`/broadcast/sessions/${sessionId}/chat/product`, {
    item_id: itemId,
  });
```

### Step 3 — Add SSE listener and render branch in `BroadcastChat.tsx`

Add import at the top:

```typescript
import { ProductLinkCard } from "./ProductLinkCard";
```

Add SSE listener inside the `useEffect` (after the `chat:lottery` listener):

```typescript
es.addEventListener("chat:product_link", (event) => {
  const msg: ChatMessage = JSON.parse(event.data);
  setMessages((prev) => {
    if (prev.some((m) => m.message_id === msg.message_id)) return prev;
    return [...prev, msg].slice(-500);
  });
});
```

Add branch in `renderMessageContent` (before the final `return <span>` fallback):

```typescript
// LCOM-002 — Product link card
if (msg.kind === "product_link" && msg.product_link) {
  return (
    <ProductLinkCard
      sessionId={sessionId}
      productLink={msg.product_link}
    />
  );
}
```

### Dev/Prod parity (SECOPS-007)

No backend changes are required. The frontend change uses the existing Vite proxy to
reach the backend, which is identical in dev and production routing. The new component
does not call any AWS services directly. The `image_url` from the product link is a
relative path or a pre-signed S3 URL (resolved by the backend) and renders without any
environment-specific configuration.

### Backward compatibility

Messages with `kind="product_link"` that were received before this fix had `text: null`
and rendered as empty spans. After the fix, any such messages that are still in the
SSE history window (initial `getChatHistory` call) will render as `ProductLinkCard`.
This is the correct behaviour. No data migration is needed.

## 5. Testing, Verification & Rollout

### Regression test — Playwright E2E (fails before fix, passes after)

```typescript
// frontend/e2e/broadcast-product-link.spec.ts
import { test, expect } from "@playwright/test";
import { injectAuth } from "./helpers/auth";

test.describe("BroadcastChat — product link card (GAP-0289)", () => {
  let sessionId: string;

  test.beforeAll(async ({ request }) => {
    // Create a broadcast session and add a shelf product via API
    const s = await request.post("/broadcast/sessions", { data: { title: "test" } });
    sessionId = (await s.json()).session_id;
    await request.post(`/broadcast/sessions/${sessionId}/products`, {
      data: { catalog_item_id: "TEST_ITEM_ID" },
    });
    // Set session live
    await request.post(`/broadcast/sessions/${sessionId}/go-live`);
  });

  test("product link message renders ProductLinkCard for viewer", async ({ browser }) => {
    const viewerPage = await browser.newPage();
    await injectAuth(viewerPage, "alice");
    await viewerPage.goto(`/broadcast/${sessionId}`);
    await viewerPage.waitForLoadState("domcontentloaded");

    // Broadcaster sends a product link
    const broadPage = await browser.newPage();
    await injectAuth(broadPage, "root");  // broadcaster is root in e2e
    await broadPage.request.post(
      `/broadcast/sessions/${sessionId}/chat/product`,
      { data: { item_id: "TEST_ITEM_ID" } }
    );

    // Trigger refetch on viewer
    await viewerPage.evaluate(() => window.dispatchEvent(new Event("online")));

    // Before fix: locator times out (no product-link-card rendered)
    // After fix:  card is visible
    await expect(
      viewerPage.getByTestId("product-link-card")
    ).toBeVisible({ timeout: 5000 });

    await expect(
      viewerPage.getByTestId("product-link-name")
    ).toBeVisible();

    await expect(
      viewerPage.getByTestId("product-link-buy-btn")
    ).toBeVisible();
  });

  test("discounted price badge appears when broadcast price is active", async ({ browser }) => {
    const page = await browser.newPage();
    await injectAuth(page, "alice");
    await page.goto(`/broadcast/${sessionId}`);

    // (Assumes the test product has a broadcast_price_cents set below regular price)
    const discountBadge = page.getByTestId("product-link-discount");
    if (await discountBadge.count() > 0) {
      await expect(discountBadge).toBeVisible();
    }
  });
});
```

**Before fix**: `getByTestId("product-link-card")` times out — element never appears.
**After fix**: Card is visible with product name and "Buy Now" button.

### Observability

- Log `broadcast.chat.product_link.rendered` (client-side analytics event) when the
  card is mounted, to track exposure rate.
- Track `product_link_buy_btn_clicks` via the existing analytics event emitter.
- The backend already records the product link message in DynamoDB with `kind="product_link"`.
  A backend analytics job can query for all `product_link` messages per session and
  correlate with subsequent purchases in the catalog service to measure conversion rate.
- Add a `broadcast.product_link.viewed` server-side event when the SSE `chat:product_link`
  event is delivered, enabling server-authoritative view-count tracking independent of
  client-side rendering.

### Handling the fallback for `text: null` before the fix is deployed

An intermediate guard can be added to `renderMessageContent` without requiring
`ProductLinkCard.tsx` to exist yet:

```typescript
if (msg.kind === "product_link") {
  // Fallback until ProductLinkCard.tsx is available
  return (
    <span className="text-xs text-muted-foreground italic">
      [Product: {msg.text ?? "view in catalog"}]
    </span>
  );
}
```

This prevents the completely invisible message and gives viewers a text hint. The full
`ProductLinkCard` component replaces this fallback in the same PR.
