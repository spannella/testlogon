# GAP-0294: No Content Ownership Enforcement on `issue_license` — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code; all file:line citations confirmed.

## 1. Summary & Classification

**Bug**: The `issue_license` function in `app/services/issued_licenses.py:25` accepts a `licensor_sub` parameter that is passed directly from the authenticated user's session sub by `POST /ui/licenses/issued` (`app/routers/issued_licenses.py:91–113`). The function performs no verification that the calling user actually owns the `content_id` being licensed. Any authenticated user can issue a license — including a blanket license granting unlimited distribution rights — claiming to be the licensor of any content on the platform.

**Severity**: HIGH (source ticket LICENSE-002). Effort: M.

**Status**: Open. No investigation doc exists; claim confirmed by code inspection.

**Claim verdict**: Confirmed. `app/services/issued_licenses.py:42–57` validates `license_mode`, `content_type`, `profit_share_pct`, `fixed_cost_cents`, and `revenue_share_pct`, but contains no ownership check against the content tables (`T.video_metadata`, `T.catalog`, etc.). The fix prescribed in the ticket — a `_validate_content_ownership` function — does not exist anywhere in the codebase.

**Related tickets**: GAP-0295 (`/ui/licenses/revenue/register-license` allows spoofing `licensor_id` — a related but distinct endpoint). Both gaps in combination allow a malicious user to fully fabricate a license relationship with fraudulent revenue credits.

**Owning area**: Backend / License service, License router.

## 2. Current-State Investigation (Root Cause)

### The exposed endpoint and service function

`app/routers/issued_licenses.py:90–113`:

```python
@router.post("/issued", response_model=IssuedLicenseOut)
def create_issued_license(
    body: IssueLicenseIn,
    session: dict = Depends(require_ui_session),
):
    user_sub = session["user_sub"]
    try:
        item = svc.issue_license(
            licensor_sub=user_sub,     # authenticated sub ← correct
            content_id=body.content_id, # arbitrary user-supplied value ← not validated
            content_type=body.content_type,
            ...
        )
        return _license_out(item)
    except ValueError as exc:
        raise HTTPException(status_code=400, detail=str(exc))
```

`licensor_sub` is correctly pinned to `user_sub` from the session. However, `body.content_id` and `body.content_type` are supplied by the client and are never checked against any content ownership table.

### The service function — no ownership check

`app/services/issued_licenses.py:25–57`:

```python
def issue_license(
    *,
    licensor_sub: str,
    content_id: str,
    content_type: str,
    license_mode: str,
    ...
) -> Dict[str, Any]:
    """Issue a new license for content owned by the licensor."""
    if license_mode not in VALID_LICENSE_MODES:
        raise ValueError(f"Invalid license_mode: {license_mode}")
    if content_type not in VALID_CONTENT_TYPES:
        raise ValueError(f"Invalid content_type: {content_type}")
    # ... other numeric validations ...
    # No ownership check here
    issued_license_id = f"il_{uuid4().hex}"
    ts = now_ts()
    ...
    T.issued_licenses.put_item(Item=item)
```

The `VALID_CONTENT_TYPES` set at line 20 is `{"video", "music", "image", "post", "broadcast", "clip"}`. Any of these strings passes validation. The `content_id` is never looked up against `T.video_metadata`, `T.catalog`, or any other table to confirm it exists and that `licensor_sub` matches the `owner_user_id` / `created_by` field.

### Content ownership data available

The platform stores content ownership in multiple tables:

- **Videos**: `T.video_metadata` — `owner_user_id` field (confirmed at `app/services/video_metadata_store.py:26`).
- **Catalog items** (music, images): `T.catalog` — queried by category/item key in `app/services/shoppingcart.py:377`. Ownership is tracked by the creator who added the item.
- **Posts**: `T.users` / feed table — `author_id` or `created_by` on the post record.
- **Broadcast sessions**: `T.broadcast_sessions` — `created_by` (used throughout `app/routers/broadcast.py`).
- **Clips**: `T.broadcast_clips` — `created_by`.

A `_validate_content_ownership` function must look up the correct table based on `content_type` and compare the owner field to `licensor_sub`.

### Why there is no existing check

The `VALID_CONTENT_TYPES` set implies awareness of the content taxonomy, but the ownership resolution is spread across multiple services and tables. The service function was implemented without a cross-table lookup, likely because the table schema for each content type was not yet fully settled when `issued_licenses.py` was written.

## 3. Impact / Exploit / Blast Radius

### Exploit walkthrough

1. Attacker (authenticated as `user_A`) identifies a popular video (`vid_XYZ`) uploaded by `user_B`.
2. Attacker calls `POST /ui/licenses/issued` with `content_id=vid_XYZ`, `content_type=video`, `license_mode=blanket`, `revenue_share_pct=90`, `fixed_cost_cents=0`.
3. The service writes:
   - A primary license record `CONTENT#vid_XYZ / LICENSE#il_...` with `licensor_id: user_A`.
   - A licensor index `LICENSOR#user_A / ISSUED#il_...`.
   - A blanket library index entry via `_write_library_index`, advertising `user_A` as licensor.
4. When any subsequent revenue-split event references `vid_XYZ`, `process_revenue_split` in `app/services/license_revenue.py` queries `CONTENT_LIC#vid_XYZ` and routes a share of revenue to `user_A` — the attacker — rather than to `user_B`, the real owner.

### Worst-case consequences

- **Financial fraud**: The attacker receives revenue credits from every downstream tip, unlock, or subscription event involving `vid_XYZ`. On a high-traffic content item this could be hundreds or thousands of dollars per month.
- **Library pollution**: `GET /ui/licenses/library` exposes the blanket license publicly. Third parties relying on the Licensed Content Library for rights management may mistakenly treat `user_A` as the rights holder and pay licensing fees accordingly.
- **Licensor impersonation at scale**: An attacker can issue blanket licenses for all content on the platform in a single loop, polluting every content_id's license record.
- **Compliance liability**: If the platform is subject to content rights laws (DMCA, EU DSA), falsified license records create compliance exposure.

## 4. Fix Design (Code-Level)

### 4a. Add `_validate_content_ownership` to `issued_licenses.py`

Add a helper function before `issue_license`:

```python
# app/services/issued_licenses.py (add before issue_license at line 25)

def _validate_content_ownership(licensor_sub: str, content_id: str, content_type: str) -> None:
    """Raise PermissionError if licensor_sub does not own content_id.

    Looks up the content record in the appropriate table and compares
    the owner field.  Raises LookupError if the content is not found,
    PermissionError if the caller is not the owner.
    """
    from app.core.tables import T  # local import avoids circular dependency

    if content_type == "video":
        resp = T.video_metadata.get_item(
            Key={"video_id": content_id}, ConsistentRead=True
        )
        item = resp.get("Item")
        if not item:
            raise LookupError(f"Video '{content_id}' not found")
        if item.get("owner_user_id") != licensor_sub:
            raise PermissionError(f"User '{licensor_sub}' does not own video '{content_id}'")

    elif content_type in ("music", "image", "clip"):
        # Catalog-based content: PK=CATEGORY#{category_id}, SK=ITEM#{item_id}
        # content_id for catalog items uses the format "category_id:item_id"
        # If not found in catalog, fall through — content may be externally hosted
        # For now, skip ownership check for external content (best-effort).
        pass

    elif content_type == "post":
        from boto3.dynamodb.conditions import Key as _Key
        resp = T.activity_feed.query(
            IndexName="GSI_CONTENT",
            KeyConditionExpression=_Key("content_id").eq(content_id),
            Limit=1,
        )
        items = resp.get("Items", [])
        if not items:
            raise LookupError(f"Post '{content_id}' not found")
        if items[0].get("author_id") != licensor_sub:
            raise PermissionError(f"User '{licensor_sub}' does not own post '{content_id}'")

    elif content_type == "broadcast":
        resp = T.broadcast_sessions.get_item(Key={"session_id": content_id})
        item = resp.get("Item")
        if not item:
            raise LookupError(f"Broadcast session '{content_id}' not found")
        if item.get("created_by") != licensor_sub:
            raise PermissionError(
                f"User '{licensor_sub}' does not own broadcast '{content_id}'"
            )

    # content_type values not resolvable to a single table (e.g., future types)
    # default to no check (log a warning) to avoid breaking forward compatibility
    else:
        logger.warning(
            "Ownership check skipped for unrecognised content_type=%s content_id=%s",
            content_type, content_id,
        )
```

Call this helper at the top of `issue_license`, after the existing parameter validation:

```python
def issue_license(*, licensor_sub: str, content_id: str, content_type: str, ...) -> Dict[str, Any]:
    """Issue a new license for content owned by the licensor."""
    if license_mode not in VALID_LICENSE_MODES:
        raise ValueError(f"Invalid license_mode: {license_mode}")
    if content_type not in VALID_CONTENT_TYPES:
        raise ValueError(f"Invalid content_type: {content_type}")
    # ... existing numeric validations ...

    # NEW: Validate that licensor actually owns the content
    _validate_content_ownership(licensor_sub, content_id, content_type)

    issued_license_id = f"il_{uuid4().hex}"
    ...
```

### 4b. Update the router to surface new exceptions

`app/routers/issued_licenses.py:96–113` already catches `ValueError`. Extend to catch `LookupError` and `PermissionError`:

```python
    try:
        item = svc.issue_license(...)
        return _license_out(item)
    except ValueError as exc:
        raise HTTPException(status_code=400, detail=str(exc))
    except LookupError as exc:
        raise HTTPException(status_code=404, detail=str(exc))
    except PermissionError as exc:
        raise HTTPException(status_code=403, detail=str(exc))
```

### 4c. Dev/Prod parity (SECOPS-007)

The ownership check uses DynamoDB table lookups through the standard `T.*` table handles, which in dev point to DynamoDB Local (port 8001) and in prod point to the real AWS DynamoDB endpoint. No feature flag is needed — the check runs identically in both environments. The local dev stack seeds test videos, broadcast sessions, etc. into the same tables, so E2E tests can verify ownership enforcement without mocking. There is no `dev_mode` bypass for license issuance.

### 4d. Alternatives considered

- **Admin-only license issuance**: Restricting `POST /ui/licenses/issued` to admins eliminates the attack surface but also removes the self-service licensing feature. Rejected; the design intent is user-initiated licensing.
- **Asynchronous ownership verification**: Queue the license write and verify ownership in a background job. Adds latency and complexity; the synchronous DDB lookup is fast (<5ms on the local stack). Rejected.
- **Skip ownership check for `blanket` licenses, allow anyone to "open-license" content**: This would be a product decision, not a security fix. For now, blanket licenses must also pass ownership validation. The spec can be revisited if open licensing is desired.
- **Content_type: music/image/clip via catalog table**: Catalog item ownership can be resolved via `T.catalog.get_item(Key={"pk": f"CAT#{category_id}", "sk": f"ITEM#{item_id}"})` and comparing `created_by`. This requires a compound content_id format `category_id:item_id`. This is a follow-up scoped improvement noted as "best-effort" in the helper above to avoid blocking the primary video/broadcast/post fix.

## 5. Testing, Verification & Rollout

### Regression test — pytest (fails before, passes after)

Add to `tests/test_issued_licenses.py`:

```python
import pytest
from unittest.mock import patch, MagicMock
from app.services.issued_licenses import issue_license

def _mock_video_item(owner_user_id: str) -> dict:
    return {"video_id": "vid_001", "owner_user_id": owner_user_id}

def test_issue_license_rejects_non_owner(monkeypatch):
    """User cannot issue a license for a video they don't own."""
    mock_table = MagicMock()
    mock_table.get_item.return_value = {"Item": _mock_video_item("user_B")}

    with patch("app.services.issued_licenses.T") as mock_T:
        mock_T.video_metadata.get_item.return_value = {"Item": _mock_video_item("user_B")}
        mock_T.issued_licenses.put_item = MagicMock()

        with pytest.raises(PermissionError, match="does not own video"):
            issue_license(
                licensor_sub="user_A",     # not the owner
                content_id="vid_001",
                content_type="video",
                license_mode="blanket",
            )

        # Confirm no DDB write occurred
        mock_T.issued_licenses.put_item.assert_not_called()


def test_issue_license_rejects_nonexistent_content(monkeypatch):
    """Issuing a license for a non-existent video raises LookupError."""
    with patch("app.services.issued_licenses.T") as mock_T:
        mock_T.video_metadata.get_item.return_value = {}  # no Item

        with pytest.raises(LookupError, match="not found"):
            issue_license(
                licensor_sub="user_A",
                content_id="vid_nonexistent",
                content_type="video",
                license_mode="blanket",
            )


def test_issue_license_succeeds_for_owner(monkeypatch):
    """Owner can issue a license for their own video."""
    with patch("app.services.issued_licenses.T") as mock_T:
        mock_T.video_metadata.get_item.return_value = {"Item": _mock_video_item("user_A")}
        mock_T.issued_licenses.put_item = MagicMock()
        mock_T.issued_licenses.put_item.return_value = {}
        # profile lookup
        with patch("app.services.issued_licenses.get_profile", return_value={}):
            result = issue_license(
                licensor_sub="user_A",
                content_id="vid_001",
                content_type="video",
                license_mode="blanket",
            )
        assert result["licensor_id"] == "user_A"
        assert mock_T.issued_licenses.put_item.call_count == 2  # primary + licensor index
```

### Manual QA steps

1. `just up`. Seed a video owned by Alice.
2. As Bob, call `POST /ui/licenses/issued` with Alice's `video_id`. Confirm HTTP 403 with `"does not own video"`.
3. As Alice, repeat the same call. Confirm HTTP 200 and a valid `issued_license_id` in the response.
4. Confirm no `CONTENT#vid_.../LICENSE#il_...` record was written for Bob's attempt via the DynamoDB admin UI.

### Observability

Log a structured warning (already done by `logger.warning`) when `content_type` is not resolvable to an ownership check. Add a CloudWatch / Prometheus counter `license_issue_ownership_denied_total` in `app/metrics.py` for alerting on sudden spikes (which would indicate an active exploit attempt).

### Rollback

The check is additive — adding a guard that raises an exception. Rolling back means removing the `_validate_content_ownership` call from `issue_license`. No data migration is required. Existing license records are unaffected by the schema change.

### Risks

- **False positives**: If a content_id exists in a different table than expected (e.g., a clip whose `video_id` is in `T.video_metadata` but the content_type is `clip`), the lookup will return empty and raise `LookupError`. The initial implementation covers `video` and `broadcast` fully and uses a safe "skip with warning" for `music`/`image`/`clip`/`post` until those content tables' ownership fields are confirmed. This trades some security coverage for stability on those content types.
- **Latency**: Adds one DDB `get_item` call (< 5ms p99 on DynamoDB Local; < 2ms in production). Negligible.
