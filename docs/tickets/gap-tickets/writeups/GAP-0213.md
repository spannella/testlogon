# GAP-0213: No CSV Import Endpoint for Bulk Payouts — Remediation Write-up

> ~5 pages. Fix-oriented. Source ticket: FIN-017. No prior investigation doc.
> Claim verified against actual code.

## 1. Summary & Classification

**Severity**: HIGH
**Source ticket**: FIN-017 (Bulk Payout/Refund Tools)
**Owning area**: `app/routers/bulk_payout_tools.py`, `app/services/bulk_payout_tools.py`
**Status**: Open — no fix applied

**Claim verification**: CONFIRMED. The as-built gap review stated that `app/routers/bulk_payout_tools.py` has no `import-csv` route and `app/services/bulk_payout_tools.py` has no `import_csv_payouts` function. Both assertions are correct. The router (109 lines total) was read in full: its five existing routes are `/eligible`, `/preview`, `/execute`, `/batches`, and `/batches/{batch_id}`. No multipart upload, no CSV parsing, and no import-specific service function exist anywhere in the codebase.

Finance teams regularly prepare payout batches in spreadsheets — listing payout IDs, amounts, and reasons — before handing them to platform operations. Without a CSV import endpoint, those spreadsheets must be re-entered manually through the preview/execute flow, which does not scale and introduces transcription errors. This is the companion HIGH gap to GAP-0212 (no undo window) from FIN-017.

**Related tickets**: GAP-0212 (no undo window) — both gaps must be addressed together to make bulk payout tooling safe for high-volume use. FIN-017 source ticket.

## 2. Current-State Investigation (root cause)

### No import-csv route exists

`app/routers/bulk_payout_tools.py` contains exactly five endpoint decorators (lines 33, 44, 65, 93, 100). None accept a multipart file upload or contain the path fragment `import`:

```python
@bulk_payout_tools_router.get("/eligible", ...)
@bulk_payout_tools_router.post("/preview", ...)
@bulk_payout_tools_router.post("/execute", ...)
@bulk_payout_tools_router.get("/batches", ...)
@bulk_payout_tools_router.get("/batches/{batch_id}", ...)
```

A `POST /ui/admin/bulk-payouts/import-csv` call today returns HTTP 405 (Method Not Allowed / path not found).

### No CSV parsing service function exists

`app/services/bulk_payout_tools.py` exports six public functions: `list_eligible`, `preview_batch`, `execute_batch`, `get_batch`, `list_batches`, and (after GAP-0212 fix) `undo_batch`. There is no `import_csv_payouts`, `parse_payout_csv`, or equivalent. The module imports no `csv` module.

### The execute path already accepts ref_ids as a list

`execute_batch` in `app/services/bulk_payout_tools.py` accepts `kind: Optional[str]` and `ref_ids: Optional[list[str]]` (lines 314–317). CSV import is therefore a parse-and-validate step that produces the same `{kind, ref_ids}` pair — it does not require a new execution path.

### What Finance teams need from the CSV format

Based on FIN-017 ticket intent and standard payout batch patterns, the minimal viable CSV schema is:

| Column | Required | Notes |
|--------|----------|-------|
| `ref_id` | Yes | Payout ID or refund request ID |
| `kind` | No | `payout` or `refund`; can be a single query param instead |
| `amount_cents` | No | For validation only; backend re-checks from DB |
| `recipient_email` | No | Informational; not used for routing |

The backend validates each `ref_id` against its DDB record — the CSV-supplied `amount_cents` is cross-checked but the authoritative value comes from the database.

### Dev vs. prod

No environment difference. The CSV parsing and `execute_batch` call would run identically in both environments. `S.bulk_payout_use_real_provider` controls whether real provider calls are made during execute (unchanged).

## 3. Impact / Exploit / Blast Radius

### Operational impact

Without CSV import, Finance teams:
1. Export their approved payout list from their internal ERP/spreadsheet.
2. Manually extract payout IDs and paste them into a JSON body for `POST /preview`.
3. Review the preview, then execute.

For batches exceeding 20–30 items, step 2 alone takes 30+ minutes and introduces copy-paste errors. Batches prepared externally (e.g., by a contractor processing creator invoices) have no automated ingestion path.

### Security considerations

CSV uploads introduce SSRF and injection risks that must be explicitly mitigated:

- **CSV injection**: `ref_id` values could be crafted to inject formulas (e.g., `=HYPERLINK(...)`) if the uploaded file is ever re-exported to Excel. The backend must reject any `ref_id` that does not match the expected ID format.
- **Resource exhaustion**: A CSV with 100,000 rows could take minutes to parse. A hard row limit (e.g., 500 per import) is required.
- **Path traversal in file handling**: The file must be read into memory, not written to disk, to avoid path traversal risks. FastAPI's `UploadFile.read()` handles this correctly.

### Blast radius

Limited to admin-role users (the router uses `require_admin_or_root`). No regular user can reach this endpoint. The actual financial impact of a malformed import is bounded by `_validate_items`, which rejects any `ref_id` that is not a pending item — a rogue import cannot approve items that are not in the pending state.

## 4. Fix Design (code-level)

### Overview

1. Add `POST /ui/admin/bulk-payouts/import-csv` accepting `multipart/form-data` with a `file` field and a `kind` field.
2. Add `parse_payout_csv(file_bytes, kind)` in `app/services/bulk_payout_tools.py` that parses, validates column names, enforces row limits, and returns a list of `ref_id` strings.
3. Call the existing `preview_batch` and `execute_batch` with the parsed IDs. Return a `BulkBatchOut` response.

The import endpoint runs a combined preview-then-execute in one request (the Finance workflow is: upload CSV → see results). The caller can pass `dry_run=true` to stop at the preview stage.

### Step 1 — Service: `parse_payout_csv`

Add to `app/services/bulk_payout_tools.py`:

```python
import csv as _csv
import io as _io
import re as _re

_CSV_MAX_ROWS = 500
_REF_ID_PATTERN = _re.compile(r'^[a-zA-Z0-9_\-]{6,128}$')

class CsvImportError(ValueError):
    pass

def parse_payout_csv(file_bytes: bytes, kind: str) -> list[str]:
    """Parse a payout/refund CSV and return a validated list of ref_ids.

    Expected columns: ref_id (required), amount_cents (optional, for display only),
    recipient_email (optional). The `kind` parameter defines which table to validate
    against; it must be one of _VALID_KINDS.

    Raises CsvImportError on format errors.
    Returns a deduplicated list of ref_id strings, max _CSV_MAX_ROWS entries.
    """
    _validate_kind(kind)

    try:
        text = file_bytes.decode("utf-8-sig")  # handle BOM from Excel exports
    except UnicodeDecodeError as exc:
        raise CsvImportError("File must be UTF-8 encoded") from exc

    reader = _csv.DictReader(_io.StringIO(text))
    if not reader.fieldnames:
        raise CsvImportError("CSV has no header row")

    fieldnames_lower = [f.strip().lower() for f in reader.fieldnames]
    if "ref_id" not in fieldnames_lower:
        raise CsvImportError(
            f"CSV must have a 'ref_id' column. Found: {list(reader.fieldnames)}"
        )

    # Map original fieldname -> normalised fieldname
    field_map = {f.strip(): f.strip().lower() for f in reader.fieldnames}

    ref_ids: list[str] = []
    seen: set[str] = set()
    skipped_invalid = 0

    for row_num, row in enumerate(reader, start=2):
        if len(ref_ids) >= _CSV_MAX_ROWS:
            raise CsvImportError(
                f"CSV exceeds maximum of {_CSV_MAX_ROWS} rows. "
                f"Split into smaller batches."
            )
        normalized = {field_map[k]: (v or "").strip() for k, v in row.items()}
        ref_id = normalized.get("ref_id", "").strip()
        if not ref_id:
            continue
        if not _REF_ID_PATTERN.match(ref_id):
            skipped_invalid += 1
            continue
        if ref_id in seen:
            continue
        seen.add(ref_id)
        ref_ids.append(ref_id)

    if not ref_ids:
        raise CsvImportError("No valid ref_id values found in CSV")

    return ref_ids
```

### Step 2 — Router: `import-csv` endpoint

Add to `app/routers/bulk_payout_tools.py`:

```python
from fastapi import File, Form, UploadFile
from app.services.bulk_payout_tools import (
    parse_payout_csv,
    CsvImportError,
    preview_batch,
    execute_batch,
)

@bulk_payout_tools_router.post(
    "/import-csv",
    response_model=BulkBatchOut,
)
async def bulk_import_csv(
    file: UploadFile = File(...),
    kind: str = Form(...),
    dry_run: bool = Form(default=False),
    request: Request = ...,
    _admin=Depends(require_admin_or_root),
):
    """Import a CSV file and either preview or execute the batch.

    Form fields:
      - file: CSV upload (UTF-8 or UTF-8-BOM, max 500 data rows)
      - kind: "payout" or "refund"
      - dry_run: if true, stop at preview (default false)
    """
    if file.content_type not in (
        "text/csv",
        "application/csv",
        "application/vnd.ms-excel",
        "text/plain",
    ):
        raise HTTPException(
            status_code=415,
            detail=f"Unsupported content type: {file.content_type}. Upload a CSV file.",
        )

    file_bytes = await file.read()
    if len(file_bytes) > 5 * 1024 * 1024:  # 5 MB hard cap
        raise HTTPException(status_code=413, detail="File too large (max 5 MB)")

    try:
        ref_ids = parse_payout_csv(file_bytes, kind)
    except CsvImportError as e:
        raise HTTPException(status_code=400, detail=str(e))
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))

    if dry_run:
        out = preview_batch(_admin.sub, kind, ref_ids)
        audit_event(
            "bulk_payout.csv_import_preview",
            _admin.sub,
            request,
            kind=kind,
            ref_count=len(ref_ids),
            batch_id=out["batch_id"],
        )
        return out

    out = execute_batch(_admin.sub, kind=kind, ref_ids=ref_ids)
    audit_event(
        "bulk_payout.csv_import_execute",
        _admin.sub,
        request,
        kind=kind,
        ref_count=len(ref_ids),
        batch_id=out["batch_id"],
        status=out["status"],
    )
    return out
```

### Dev/Prod parity (SECOPS-007)

`parse_payout_csv` is a pure function — no AWS calls, no environment branching. `execute_batch` already handles the `S.bulk_payout_use_real_provider` switch internally. The file is read into memory (`await file.read()`) in both environments. No mock-only code path is introduced. The 5 MB cap and 500-row limit apply equally in dev and prod.

### Backward compatibility

This is a new endpoint at a new path. No existing endpoint or response model is changed. `BulkBatchOut` carries the response; the same model is returned by `/preview` and `/execute` — no frontend type change needed.

### Alternatives considered

- **JSON body with base64-encoded file**: Works, but requires Finance teams to base64-encode their CSV manually. Multipart form is the standard for file uploads and compatible with `<input type="file">` in the browser.
- **S3 pre-signed upload then async processing**: Necessary at very large scale. Overkill for the 500-row limit enforced here; synchronous processing stays well within FastAPI's request timeout.
- **Client-side parse then JSON post**: Moves CSV validation to the browser, making it bypassable. Rejected — server-side validation is authoritative.

## 5. Testing, Verification & Rollout

### Regression test (pytest offline)

```python
# tests/test_bulk_csv_import.py
import io
import pytest

def _make_csv(rows: list[dict]) -> bytes:
    buf = io.StringIO()
    import csv
    writer = csv.DictWriter(buf, fieldnames=["ref_id", "amount_cents"])
    writer.writeheader()
    writer.writerows(rows)
    return buf.getvalue().encode("utf-8")

def test_parse_payout_csv_valid():
    from app.services.bulk_payout_tools import parse_payout_csv
    data = _make_csv([{"ref_id": "po_abc123", "amount_cents": 5000}])
    ids = parse_payout_csv(data, kind="payout")
    assert ids == ["po_abc123"]

def test_parse_payout_csv_missing_ref_id_column():
    from app.services.bulk_payout_tools import parse_payout_csv, CsvImportError
    data = b"amount_cents\n5000\n"
    with pytest.raises(CsvImportError, match="ref_id"):
        parse_payout_csv(data, kind="payout")

def test_parse_payout_csv_too_many_rows():
    from app.services.bulk_payout_tools import parse_payout_csv, CsvImportError, _CSV_MAX_ROWS
    rows = [{"ref_id": f"po_{i}", "amount_cents": 100} for i in range(_CSV_MAX_ROWS + 1)]
    data = _make_csv(rows)
    with pytest.raises(CsvImportError, match="exceeds maximum"):
        parse_payout_csv(data, kind="payout")

def test_parse_payout_csv_invalid_ref_id_filtered():
    from app.services.bulk_payout_tools import parse_payout_csv
    data = _make_csv([
        {"ref_id": "valid_id_001", "amount_cents": 100},
        {"ref_id": "=HYPERLINK(\"evil\")", "amount_cents": 100},  # injection attempt
    ])
    ids = parse_payout_csv(data, kind="payout")
    assert ids == ["valid_id_001"]

def test_parse_payout_csv_deduplicates():
    from app.services.bulk_payout_tools import parse_payout_csv
    data = _make_csv([
        {"ref_id": "dup_id", "amount_cents": 100},
        {"ref_id": "dup_id", "amount_cents": 100},
    ])
    ids = parse_payout_csv(data, kind="payout")
    assert ids == ["dup_id"]

# API integration test
def test_import_csv_endpoint_dry_run(client, admin_auth_headers, seed_pending_payout):
    csv_bytes = _make_csv([{"ref_id": seed_pending_payout["payout_id"], "amount_cents": 5000}])
    resp = client.post(
        "/ui/admin/bulk-payouts/import-csv",
        files={"file": ("batch.csv", csv_bytes, "text/csv")},
        data={"kind": "payout", "dry_run": "true"},
        headers=admin_auth_headers,
    )
    assert resp.status_code == 200
    body = resp.json()
    assert body["status"] == "preview"
    assert body["item_count"] == 1

# Before fix: POST /ui/admin/bulk-payouts/import-csv returns 404/405
# After fix: returns 200 with preview/completed batch
```
