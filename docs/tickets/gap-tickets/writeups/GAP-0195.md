# GAP-0195: Payout methods CRUD not implemented — Remediation Write-up

> ~5 pages. Fix-oriented. Verified against actual code in
> `app/services/creator_payouts.py` (450 lines), `app/routers/creator_payouts.py`
> (106 lines), `app/models.py` (PayoutRequestIn at line 2475), and the FIN-009
> writeup at `docs/tickets/writeups/FIN-009.md`.

## 1. Summary & Classification

**Bug / Gap**: Creators cannot configure real bank account or PayPal destinations for
payouts. The payout request endpoint (`POST /ui/payouts/request`) accepts a `method`
string that defaults to `"bank_transfer"` but there is no storage, validation, or
management layer for actual payout destinations. Admins approving and completing
payouts have no routing information to work with, making real disbursement impossible.

**Claim verdict**: Confirmed. `app/services/creator_payouts.py:44` has
`"method": item.get("method", "bank_transfer")` and `app/models.py:2477` has
`method: str = "bank_transfer"`. A full search of `app/services/creator_payouts.py`,
`app/routers/creator_payouts.py`, and `app/models.py` returns zero matches for
`payout_method`, `PayoutMethod`, `routing_number`, `account_number`,
`list_payout_methods`, `add_payout_method`, or `PMTH`.

**Severity**: HIGH — FIN-009 source ticket.
**Status**: Open.
**Owning area**: Creator Finance / Payouts.
**Impact**: The payout system is effectively non-functional end-to-end: a creator can
request a payout and an admin can approve it, but there is no mechanism to route the
funds anywhere. The `method` field on every payout record is the literal string
`"bank_transfer"` with no associated account details. Operations teams cannot execute
wire transfers, ACH payments, or PayPal transfers without a destination record.

**Related tickets**: SECOPS-007 (dev/prod parity), SEC-004 (PII — last-4-digit-only
storage), FIN-009 writeup (`docs/tickets/writeups/FIN-009.md`).

### Root cause

FIN-009 was partially implemented (balance, request, cancel, list, admin approve/reject).
The payout methods sub-feature, which would need to be built before meaningful payout
processing can occur, was left out of scope or deferred during the original sprint.
The hardcoded `"bank_transfer"` string is a placeholder that was never replaced.

## 3. Impact / Exploit / Blast Radius

**Operational impact**: Every approved payout is stuck in the `approved` state with no
routing target. Admins must manually obtain bank details out-of-band (support tickets,
emails) and enter them into an external payment system. This is error-prone and
does not scale beyond a handful of creators.

**Financial risk**: If a payout is processed against an incorrectly collected routing
number (because there is no validated in-system storage), funds can be mis-routed.
ACH returns for incorrect account numbers incur fees ($2–25 per returned item).

**PII / security risk**: Without a dedicated payout method storage layer, teams resort
to storing full bank account numbers in freeform notes fields (`notes: str` on the
payout record). The fix must enforce that only `account_last4` and `routing_last4`
are stored; full numbers must never be persisted (FIN-009 writeup, SEC-004 reference).

**No authentication bypass** is implied by the missing endpoints — adding them
increases attack surface slightly, but all endpoints will use `require_ui_session`
with CSRF enforcement.

## 4. Fix Design (code-level)

### 4.1 DDB storage pattern

Payout methods are stored in the existing `creator_payouts` table using a separate key
space:

```
PK = "METHODS#<user_id>"
SK = "PMTH#<method_id>"
```

This co-locates payout data in one table and avoids a new `TableDef`. The default
method pointer is stored as:

```
PK = "METHODS#<user_id>"
SK = "DEFAULT"
default_method_id: str
```

### 4.2 Service layer (`app/services/creator_payouts.py`)

Add the following functions after `get_payout_stats`:

```python
import uuid as _uuid

PAYOUT_METHOD_TYPES = {"bank_ach", "bank_wire", "paypal", "check"}


def _method_id() -> str:
    return f"pmth_{_uuid.uuid4().hex}"


def _method_to_dict(item: Dict[str, Any]) -> Dict[str, Any]:
    return {
        "method_id": item.get("method_id", ""),
        "method_type": item.get("method_type", ""),
        "account_last4": item.get("account_last4", ""),
        "routing_last4": item.get("routing_last4", ""),
        "paypal_email": item.get("paypal_email", ""),
        "nickname": item.get("nickname", ""),
        "is_default": bool(item.get("is_default", False)),
        "created_at": _to_int(item.get("created_at", 0)),
        "updated_at": _to_int(item.get("updated_at", 0)),
    }


def list_payout_methods(user_id: str) -> List[Dict[str, Any]]:
    """List all payout methods for a creator."""
    resp = T.creator_payouts.query(
        KeyConditionExpression=Key("PK").eq(f"METHODS#{user_id}")
        & Key("SK").begins_with("PMTH#"),
    )
    return [_method_to_dict(i) for i in resp.get("Items", [])]


def add_payout_method(
    user_id: str,
    *,
    method_type: str,
    account_last4: str = "",       # ACH/wire: last 4 of account number
    routing_last4: str = "",       # ACH/wire: last 4 of routing number
    paypal_email: str = "",        # PayPal methods
    nickname: str = "",
    set_as_default: bool = False,
) -> Dict[str, Any]:
    """Add a new payout method.  Only last-4 digits stored for bank accounts."""
    if method_type not in PAYOUT_METHOD_TYPES:
        raise ValueError(f"invalid_method_type:Must be one of {PAYOUT_METHOD_TYPES}")
    if method_type in ("bank_ach", "bank_wire") and (not account_last4 or not routing_last4):
        raise ValueError("bank_details_required:account_last4 and routing_last4 are required for bank methods")
    if method_type == "paypal" and not paypal_email:
        raise ValueError("paypal_email_required:paypal_email is required for PayPal methods")

    ts = now_ts()
    mid = _method_id()
    item = {
        "PK": f"METHODS#{user_id}",
        "SK": f"PMTH#{mid}",
        "method_id": mid,
        "method_type": method_type,
        "account_last4": account_last4,
        "routing_last4": routing_last4,
        "paypal_email": paypal_email,
        "nickname": nickname,
        "is_default": False,
        "created_at": ts,
        "updated_at": ts,
    }
    T.creator_payouts.put_item(Item=item)
    if set_as_default:
        set_default_payout_method(user_id, mid)
        item["is_default"] = True
    return _method_to_dict(item)


def update_payout_method(
    user_id: str,
    method_id: str,
    *,
    nickname: str,
) -> Dict[str, Any]:
    """Update mutable fields (currently only nickname)."""
    ts = now_ts()
    try:
        resp = T.creator_payouts.update_item(
            Key={"PK": f"METHODS#{user_id}", "SK": f"PMTH#{method_id}"},
            UpdateExpression="SET nickname = :n, updated_at = :ts",
            ExpressionAttributeValues={":n": nickname, ":ts": ts},
            ConditionExpression=Attr("method_id").exists(),
            ReturnValues="ALL_NEW",
        )
    except T.creator_payouts.meta.client.exceptions.ConditionalCheckFailedException:
        raise LookupError("payout_method_not_found:Payout method not found")
    return _method_to_dict(resp["Attributes"])


def delete_payout_method(user_id: str, method_id: str) -> None:
    """Delete a payout method.  Raises ValueError if it is the sole default."""
    existing = list_payout_methods(user_id)
    target = next((m for m in existing if m["method_id"] == method_id), None)
    if not target:
        raise LookupError("payout_method_not_found:Payout method not found")
    if target["is_default"] and len(existing) > 1:
        raise ValueError(
            "cannot_delete_default:Set another method as default before deleting this one"
        )
    T.creator_payouts.delete_item(
        Key={"PK": f"METHODS#{user_id}", "SK": f"PMTH#{method_id}"}
    )
    if target["is_default"]:
        # Delete the DEFAULT pointer too
        T.creator_payouts.delete_item(
            Key={"PK": f"METHODS#{user_id}", "SK": "DEFAULT"}
        )


def set_default_payout_method(user_id: str, method_id: str) -> None:
    """Mark a method as default.  Updates the DEFAULT pointer and all method rows."""
    # Verify method exists
    resp = T.creator_payouts.get_item(
        Key={"PK": f"METHODS#{user_id}", "SK": f"PMTH#{method_id}"}
    )
    if not resp.get("Item"):
        raise LookupError("payout_method_not_found:Payout method not found")
    ts = now_ts()
    T.creator_payouts.put_item(Item={
        "PK": f"METHODS#{user_id}",
        "SK": "DEFAULT",
        "default_method_id": method_id,
        "updated_at": ts,
    })


def get_default_payout_method(user_id: str) -> Optional[Dict[str, Any]]:
    """Return the default payout method dict, or None if none set."""
    ptr = T.creator_payouts.get_item(
        Key={"PK": f"METHODS#{user_id}", "SK": "DEFAULT"}
    ).get("Item")
    if not ptr:
        return None
    method_id = ptr.get("default_method_id", "")
    resp = T.creator_payouts.get_item(
        Key={"PK": f"METHODS#{user_id}", "SK": f"PMTH#{method_id}"}
    )
    item = resp.get("Item")
    if not item:
        return None
    out = _method_to_dict(item)
    out["is_default"] = True
    return out
```

### 4.3 Router additions (`app/routers/creator_payouts.py`)

Add new imports and five endpoints after the existing `list_payouts` endpoint:

```python
from app.models import PayoutMethodIn, PayoutMethodOut, PayoutMethodListOut
from app.services.creator_payouts import (
    list_payout_methods, add_payout_method,
    update_payout_method, delete_payout_method, set_default_payout_method,
)


@router.get("/methods", response_model=PayoutMethodListOut)
def list_methods(session=Depends(require_ui_session)):
    items = list_payout_methods(session["user_sub"])
    return PayoutMethodListOut(methods=[PayoutMethodOut(**m) for m in items])


@router.post("/methods", response_model=PayoutMethodOut, status_code=201)
def add_method(body: PayoutMethodIn, session=Depends(require_ui_session)):
    try:
        result = add_payout_method(session["user_sub"], **body.model_dump())
    except ValueError as exc:
        code, _, msg = str(exc).partition(":")
        raise HTTPException(400, detail={"code": code, "message": msg or code})
    return PayoutMethodOut(**result)


@router.put("/methods/{method_id}", response_model=PayoutMethodOut)
def update_method(method_id: str, body: PayoutMethodUpdateIn, session=Depends(require_ui_session)):
    try:
        result = update_payout_method(session["user_sub"], method_id, nickname=body.nickname)
    except LookupError as exc:
        raise HTTPException(404, detail=str(exc))
    return PayoutMethodOut(**result)


@router.delete("/methods/{method_id}", status_code=204)
def delete_method(method_id: str, session=Depends(require_ui_session)):
    try:
        delete_payout_method(session["user_sub"], method_id)
    except LookupError as exc:
        raise HTTPException(404, detail=str(exc))
    except ValueError as exc:
        raise HTTPException(400, detail=str(exc))


@router.post("/methods/{method_id}/default", response_model=PayoutMethodOut)
def set_default_method(method_id: str, session=Depends(require_ui_session)):
    try:
        set_default_payout_method(session["user_sub"], method_id)
    except LookupError as exc:
        raise HTTPException(404, detail=str(exc))
    result = get_default_payout_method(session["user_sub"])
    return PayoutMethodOut(**result)
```

### 4.5 `request_payout` integration

Once payout methods exist, `request_payout` should accept a `method_id` param and
validate that the method belongs to the user:

```python
def request_payout(user_id: str, amount_cents: int,
                   method_id: Optional[str] = None, notes: str = "") -> dict:
    ...
    if method_id:
        method_item = T.creator_payouts.get_item(
            Key={"PK": f"METHODS#{user_id}", "SK": f"PMTH#{method_id}"}
        ).get("Item")
        if not method_item or method_item.get("PK") != f"METHODS#{user_id}":
            raise ValueError("invalid_method_id:Payout method not found or not yours")
        method_str = method_item.get("method_type", "bank_transfer")
    else:
        default = get_default_payout_method(user_id)
        method_id = default["method_id"] if default else None
        method_str = default["method_type"] if default else "bank_transfer"
    ...
    item = { ..., "method": method_str, "method_id": method_id or "", ... }
```

### 4.6 Dev/prod parity (SECOPS-007)

Payout method records are stored in the `creator_payouts` DynamoDB table. In dev,
`T.creator_payouts` points to DynamoDB Local (port 8001); in prod it points to real
DynamoDB. No special mock path is required. The `PMTH#` key prefix is distinct from
`payout_id`-keyed records so no GSI changes are needed (methods are queried via a
`begins_with("PMTH#")` KeyCondition on the table's existing sort key).

The `dev_mode` flag is used only in `complete_payout` (line 370) to allow
`approved → completed` in one step. No `dev_mode` branching is needed for payout
methods.

**Feature flag**: Add `payout_methods_enabled: bool` to `app/core/settings.py`
(default `True`) to allow ops to disable the sub-feature without removing endpoints.
