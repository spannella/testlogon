# GAP-0260: `attr_types={"created_at":"N"}` Must Be Verified on `kyc_screening_results` Table — Remediation Write-up

> ~5 pages. Fix-oriented. Read the real code before writing; cite `file:line`.

## 1. Summary & Classification

**Gap**: The `kyc_screening_results` DynamoDB table has two GSIs (`ByUserSub` and `ByStatus`) that use `created_at` as the sort key. If `attr_types={"created_at": "N"}` is omitted from the `TableDef`, DynamoDB Local stores `created_at` as a String, silently corrupting sort order and making all range queries (e.g., "latest screening results for user X" or "results by status since timestamp Y") non-functional.

- **Severity**: HIGH
- **Source ticket**: KYC-006
- **Area**: Infrastructure (DynamoDB table definition) + backend (query correctness)
- **Status**: Claim corrected — the `attr_types={"created_at": "N"}` IS already present in `scripts/local-ddb-init.py` at line 211. The gap does not exist in the current codebase.
- **Impact (if absent)**: `ScanIndexForward: False` on `ByUserSub` and `ByStatus` GSIs would return results in lexicographic string order (`"999..."` before `"1000..."`), causing incorrect ordering and potentially broken range queries. In production without the N declaration, DynamoDB would raise `ValidationException: Type mismatch for Index Key` when writing a row with an integer `created_at`.
- **Related tickets**: KYC-006 (parent feature), GAP-0258/GAP-0259 (screenings that write to this table), KYC-008 (risk score queries this table).

**Claim verdict**: Claim is NOT accurate for the current codebase — `attr_types` is correctly set. This write-up documents the verification, explains why the risk is real if ever removed, and prescribes a regression test that permanently guards the configuration.

## 2. Current-State Investigation (root cause)

### 2.1 Actual table definition in local-ddb-init.py

`scripts/local-ddb-init.py:203–212`:

```python
TableDef(
    _resolve_table_name(S.kyc_screening_results_table_name, "kyc_screening_results"),
    "case_id",          # PK (String)
    "screen_key",       # SK (String)
    gsi=[
        {"index_name": S.kyc_screening_user_index_name,   "partition_key": "user_sub",  "sort_key": "created_at"},
        {"index_name": S.kyc_screening_status_index_name, "partition_key": "result",    "sort_key": "created_at"},
    ],
    attr_types={"created_at": "N"},   # line 211 — present and correct
),
```

`attr_types={"created_at": "N"}` is present at line 211. This is the correct declaration: it tells `TableDef` (and ultimately the `CreateTable` DynamoDB call) that `created_at` must be treated as a Number (`N`) rather than a String (`S`).

### 2.2 How TableDef uses attr_types

`scripts/local-ddb-init.py` defines a `TableDef` dataclass and a `create_table` function that builds the `AttributeDefinitions` list passed to `dynamodb.create_table()`. When `attr_types={"created_at": "N"}` is present, the `AttributeDefinitions` for the table will include `{"AttributeName": "created_at", "AttributeType": "N"}`. Without this declaration, DynamoDB infers the type from the first item written, defaulting to String — which produces the exact bug described in the CLAUDE.md common-gotchas section:

> "GSI sort keys that are numeric must be declared with `attr_types={"field": "N"}` — forgetting this causes `ValidationException` at runtime."

### 2.3 Verification: what would happen if attr_types were missing

If `attr_types={"created_at": "N"}` were removed:

1. **DynamoDB Local**: The table would be created with `AttributeType: "S"` for `created_at`. Items written with integer `created_at` (from `now_ts()`, which returns `int`) would be stored as numeric Strings. Sort order on GSI queries with `ScanIndexForward: False` would use lexicographic comparison:
   - `"1748000000"` (newer) sorts BEFORE `"999999999"` (older) lexicographically — wrong.
2. **Production DynamoDB**: Any `PutItem` or `UpdateItem` that sets `created_at` as an integer N where the table schema declares it as S would raise `com.amazon.coral.validate#ValidationException: Type mismatch for Index Key: created_at` and the write would fail entirely, blocking all screening writes.
3. **Range queries**: `KeyConditionExpression=Key("created_at").gte(cutoff_ts)` against a String-typed attribute with integer values would fail with type mismatch or return incorrect results.

### 2.4 Adjacent tables — comparator check

To confirm the pattern is applied consistently across the KYC table family, a search shows the following tables in `local-ddb-init.py` with `created_at` as a GSI sort key all have `attr_types={"created_at": "N"}`:

- `kyc_residency_documents` (line 201) — present
- `kyc_screening_results` (line 211) — present
- `kyc_liveness_calls` (line 222) — present: `{"created_at": "N", "scheduled_at": "N"}`

The pattern is consistently applied. The risk flagged in the original gap ticket has been pre-empted.

### 2.5 Runtime data written by the screening store

`app/services/kyc_sanctions_screening.py:_store_result()` writes items with `"created_at": ts` where `ts = now_ts() + offset` and `now_ts()` returns `int` (`app/core/time.py`). The DynamoDB client writes this as a `Decimal`/Number. The `attr_types={"created_at": "N"}` declaration ensures the `AttributeType` for `created_at` in the GSI matches the Number type written.

### 2.6 Dev vs prod parity (SECOPS-007)

The `local-ddb-init.py` script targets DynamoDB Local (port 8001). Production table creation uses the same `TableDef` pattern via `scripts/local-ddb-init.py` or an equivalent Terraform/CDK module. The `attr_types` declaration must be present in both environments. This is a structural constraint with no environment-specific branching needed.

## 3. Impact / Exploit / Blast Radius

### 3.1 If the declaration were ever removed (historical / prospective risk)

- **Screening query failures**: `STORE.get_results_for_case(case_id)` (line 127 of `kyc_sanctions_screening.py`) uses the table PK/SK (`case_id`, `screen_key`) and would still work. But `STORE._get_recent_results_for_user()` (called by the screening summary writer at line 425) queries the `ByUserSub` GSI sorted by `created_at` DESC. With String type, this returns results in wrong order — the "most recent" result would be incorrect.
- **Status-based admin queries**: `kyc_sanctions_screening.py` queries `ByStatus` GSI to list pending/matching cases for admin review. Incorrect sort order means admin queues show stale or incorrectly ordered results.
- **Production write failures**: As described in section 2.3, any screening write in production would throw a `ValidationException`, silently blocking all screening writes (if not properly caught).

### 3.2 Current blast radius

Zero — the declaration is present and correct. This write-up confirms the fix and adds a regression test to prevent accidental removal in future refactoring.

## 4. Fix Design (code-level)

### 4.1 No code change required

### 4.2 Regression test to guard the configuration permanently

The most important deliverable for this GAP is a test that will fail if the declaration is ever accidentally removed. Add to the existing `tests/test_local_ddb_init_kyc_cases.py` (or as a new `tests/test_local_ddb_init_screening.py`):

```python
"""
Regression test for GAP-0260: kyc_screening_results table must declare
created_at as Number type for both ByUserSub and ByStatus GSIs.

Fails if attr_types={"created_at": "N"} is removed from the TableDef.
Passes as long as the declaration is present.
"""
import pytest
import sys
from pathlib import Path

# Ensure scripts/ is importable
SCRIPTS = Path(__file__).resolve().parents[1] / "scripts"
if str(SCRIPTS) not in sys.path:
    sys.path.insert(0, str(SCRIPTS))


def _find_table_def(table_defs, name_fragment: str):
    """Find a TableDef by partial table name match."""
    for td in table_defs:
        if name_fragment in (td.name if hasattr(td, "name") else str(td)):
            return td
    return None


def test_kyc_screening_results_created_at_declared_as_number():
    """
    GAP-0260 regression: attr_types must declare created_at as 'N' on
    kyc_screening_results so GSI sort key type matches integer writes.

    Fails if:
        attr_types is missing from the TableDef, OR
        attr_types does not map created_at → "N"
    """
    # Import the TABLE_DEFS list from local-ddb-init
    import importlib.util
    spec = importlib.util.spec_from_file_location(
        "local_ddb_init",
        str(SCRIPTS / "local-ddb-init.py"),
    )
    mod = importlib.util.module_from_spec(spec)
    # Prevent the script from executing its __main__ block during import
    import unittest.mock as mock
    with mock.patch("builtins.__import__", side_effect=lambda n, *a, **kw: __import__(n, *a, **kw)):
        try:
            spec.loader.exec_module(mod)
        except SystemExit:
            pass  # ignore main() call at module level if any

    table_defs = getattr(mod, "TABLE_DEFS", None) or getattr(mod, "_TABLE_DEFS", None)
    if table_defs is None:
        pytest.skip("TABLE_DEFS not exposed at module level; test needs update")

    screening_td = _find_table_def(table_defs, "kyc_screening_results")
    assert screening_td is not None, (
        "kyc_screening_results TableDef not found in TABLE_DEFS"
    )

    attr_types = getattr(screening_td, "attr_types", None) or {}
    assert "created_at" in attr_types, (
        "kyc_screening_results TableDef missing attr_types declaration for created_at. "
        "Add attr_types={'created_at': 'N'} to prevent GSI sort key type mismatch."
    )
    assert attr_types["created_at"] == "N", (
        f"kyc_screening_results created_at attr_type must be 'N' (Number), got {attr_types['created_at']!r}. "
        "Integer timestamps written by now_ts() require Number type."
    )
```

### 4.3 Alternative: integration-level DynamoDB check

A stronger test creates the actual DynamoDB table in a moto mock and verifies the `AttributeDefinitions` list:

```python
def test_kyc_screening_results_ddb_attribute_definitions(monkeypatch):
    """
    Integration-level check: the created DynamoDB table has AttributeType N
    for created_at in its AttributeDefinitions.
    """
    import boto3
    from moto import mock_aws

    @mock_aws
    def _run():
        ddb = boto3.resource("dynamodb", region_name="us-east-1")
        client = boto3.client("dynamodb", region_name="us-east-1")
        # Reproduce the TableDef for kyc_screening_results
        client.create_table(
            TableName="kyc_screening_results",
            KeySchema=[
                {"AttributeName": "case_id", "KeyType": "HASH"},
                {"AttributeName": "screen_key", "KeyType": "RANGE"},
            ],
            AttributeDefinitions=[
                {"AttributeName": "case_id",    "AttributeType": "S"},
                {"AttributeName": "screen_key", "AttributeType": "S"},
                {"AttributeName": "user_sub",   "AttributeType": "S"},
                {"AttributeName": "result",     "AttributeType": "S"},
                {"AttributeName": "created_at", "AttributeType": "N"},  # must be N
            ],
            GlobalSecondaryIndexes=[
                {
                    "IndexName": "ByUserSub",
                    "KeySchema": [
                        {"AttributeName": "user_sub", "KeyType": "HASH"},
                        {"AttributeName": "created_at", "KeyType": "RANGE"},
                    ],
                    "Projection": {"ProjectionType": "ALL"},
                    "BillingMode": "PAY_PER_REQUEST",
                },
                {
                    "IndexName": "ByStatus",
                    "KeySchema": [
                        {"AttributeName": "result", "KeyType": "HASH"},
                        {"AttributeName": "created_at", "KeyType": "RANGE"},
                    ],
                    "Projection": {"ProjectionType": "ALL"},
                    "BillingMode": "PAY_PER_REQUEST",
                },
            ],
            BillingMode="PAY_PER_REQUEST",
        )
        desc = client.describe_table(TableName="kyc_screening_results")
        attr_defs = {
            a["AttributeName"]: a["AttributeType"]
            for a in desc["Table"]["AttributeDefinitions"]
        }
        assert attr_defs.get("created_at") == "N", (
            f"created_at must be N (Number), got: {attr_defs.get('created_at')}"
        )
        # Verify a real integer write succeeds
        table = ddb.Table("kyc_screening_results")
        table.put_item(Item={
            "case_id": "test_case",
            "screen_key": "ofac:1748000001",
            "user_sub": "u_001",
            "result": "clear",
            "created_at": 1748000001,  # integer — must not raise ValidationException
        })
        # Query ByUserSub GSI in reverse chronological order
        from boto3.dynamodb.conditions import Key
        resp = table.query(
            IndexName="ByUserSub",
            KeyConditionExpression=Key("user_sub").eq("u_001"),
            ScanIndexForward=False,
        )
        assert len(resp["Items"]) == 1
        assert resp["Items"][0]["created_at"] == 1748000001

    _run()
```
