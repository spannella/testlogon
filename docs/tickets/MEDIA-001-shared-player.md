# MEDIA-001: Create Shared HLS/DRM Player Component

**Status**: Implemented

## 1. Overview & Motivation

### Why a shared component

The platform has two distinct video playback surfaces arriving in parallel:

1. **Live broadcast viewer** (BCAST-002 — `/live/:sessionId`): Plays an HLS manifest minted by `broadcast_playback.py` at `POST /broadcast/sessions/{id}/playback-url`. The stream is live (DVR-disabled), and the URL includes an MD5 `secure_link` token (`?md5=...&expires=...`) generated by `mint_local_playback_url`.

2. **VOD player** (VOD-008 — `/videos/:videoId`): Plays a pre-packaged multi-bitrate HLS manifest produced by `ffmpeg_abr_pipeline.py`, stored in S3 at `tenants/{tenant_id}/assets/{asset_id}/hls/{rendition}/index.m3u8`. Access is gated by a playback entitlement JWT (`PLAYBACKJWT` / HS256) issued via `POST /v1/playback/entitlements/issue`.

Without a shared abstraction, both pages would independently implement HLS.js initialization, adaptive bitrate setup, quality-level selection UI, DRM key-system attachment, fullscreen/PiP controls, error recovery, and responsive sizing. This duplicates ~400-600 lines of non-trivial media code and diverges over time.

A single `<MediaPlayer>` component in `frontend/src/components/shared/MediaPlayer.tsx` ensures:

- Consistent playback UX (loading spinner, error messages, quality badge, controls) across both live and VOD surfaces.
- Centralized HLS.js configuration (buffer tuning, ABR bandwidth estimation, error recovery) that can be optimized once.
- Single integration point for DRM/EME (Encrypted Media Extensions) — the DRM key system config is passed as a prop rather than re-implemented.
- Reusability in future contexts: embedded player in newsfeed posts, file preview, messaging video attachments, broadcast recording archives (BCAST-006).

### Reuse scenarios

| Consumer | Mode | DRM | Notes |
|----------|------|-----|-------|
| `LivePlayer.tsx` (BCAST-002) | Live (no seek bar) | Optional (Widevine/FairPlay per policy) | manifest URL from `mint_local_playback_url` |
| `VideoPlayer.tsx` (VOD-008) | VOD (seekable) | Per-asset DRM policy | manifest URL signed with playback entitlement token |
| `BroadcastDashboard.tsx` | Preview (muted, inline) | None | Low-latency preview of own stream |
| `ConversationGallery.tsx` | VOD (seekable) | None | Video message attachments in messaging |
| `PostCard.tsx` (newsfeed) | VOD (seekable) | None | Future: video posts embedded in feed |
| `FilePreview.tsx` (file manager) | VOD (seekable) | None | Future: replace native `<video>` with HLS player for transcoded previews |

### User stories

- **US-1**: As a viewer, I want smooth adaptive playback of a live broadcast so that I get the best quality my connection supports without manual intervention.
- **US-2**: As a content creator, I want my uploaded videos to play with a quality selector so viewers on slow connections can manually drop to a lower rendition.
- **US-3**: As a subscriber, I want DRM-protected content to decrypt and play transparently after my entitlement is verified.
- **US-4**: As a mobile user, I want picture-in-picture so I can multitask while watching.
- **US-5**: As a viewer, I want clear error feedback (network error, expired access, stream ended) so I know why playback stopped and what to do next.

### HLS output format (backend)

The FFmpeg ABR pipeline (`app/services/ffmpeg_abr_pipeline.py`) produces:

```
output_dir/
  master.m3u8          ← Variant playlist (4 streams)
  1080p/index.m3u8     ← 1920x1080, 6000 kbps video, 192 kbps audio
  1080p/seg_00001.ts
  720p/index.m3u8      ← 1280x720, 3500 kbps video, 128 kbps audio
  720p/seg_00001.ts
  540p/index.m3u8      ← 960x540, 2200 kbps video, 128 kbps audio
  540p/seg_00001.ts
  360p/index.m3u8      ← 640x360, 1200 kbps video, 96 kbps audio
  360p/seg_00001.ts
```

The `master.m3u8` format (from `write_master_playlist`):

```m3u8
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-STREAM-INF:BANDWIDTH=6000000,RESOLUTION=1920x1080
1080p/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=3500000,RESOLUTION=1280x720
720p/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=2200000,RESOLUTION=960x540
540p/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=1200000,RESOLUTION=640x360
360p/index.m3u8
```

Segment duration: 2 seconds (`-hls_time 2`). For live broadcast the pipeline uses `-hls_list_size 6 -hls_flags delete_segments+append_list` producing a rolling window. For VOD packaging, a separate invocation (VOD-004) will produce complete playlists with `#EXT-X-ENDLIST`.

### Canonical ABR ladder (`app/contracts/video_rendition_profiles.py`)

| Name | Resolution | Video Bitrate | Audio Bitrate | FPS | GOP |
|------|-----------|---------------|---------------|-----|-----|
| 1080p | 1920x1080 | 6000 kbps | 192 kbps | 30 | 2s |
| 720p | 1280x720 | 3500 kbps | 128 kbps | 30 | 2s |
| 540p | 960x540 | 2200 kbps | 128 kbps | 30 | 2s |
| 360p | 640x360 | 1200 kbps | 96 kbps | 30 | 2s |

### Playback entitlement token format (`app/services/playback_entitlements.py`)

Tokens are compact JWTs with header `{"alg": "HS256", "typ": "PLAYBACKJWT"}` and payload:

```json
{
  "tenant_id": "...",
  "asset_id": "...",
  "session_id": "...",
  "device_id": "...",
  "profile": "...",
  "aud": "playback",
  "iat": 1716500000,
  "exp": 1716500120,
  "jti": "abc123..."
}
```

Issued via `POST /v1/playback/entitlements/issue` (requires authenticated user). Default TTL: 120 seconds, configurable max: 300 seconds. The token is passed as a URL query parameter or `Authorization` header depending on the CDN/nginx configuration.

### 3.2 HLS.js Integration

**Library**: `hls.js` (latest stable, currently v1.5.x). Tree-shakeable, supports MSE-based playback with EME, handles ABR natively.

**Initialization pattern**:

```tsx
import Hls from "hls.js";

function useHlsPlayer(
  videoRef: React.RefObject<HTMLVideoElement>,
  src: string,
  options: { live?: boolean; drm?: DrmConfig; onTokenExpiring?: () => Promise<string> }
) {
  const hlsRef = useRef<Hls | null>(null);

  useEffect(() => {
    const video = videoRef.current;
    if (!video || !src) return;

    // Native HLS support (Safari/iOS) — use native player directly
    if (video.canPlayType("application/vnd.apple.mpegurl") && !options.drm) {
      video.src = src;
      return () => { video.src = ""; };
    }

    if (!Hls.isSupported()) {
      // Fallback: attempt native playback or show unsupported error
      video.src = src;
      return () => { video.src = ""; };
    }

    const hls = new Hls({
      // Buffer tuning
      maxBufferLength: options.live ? 8 : 30,
      maxMaxBufferLength: options.live ? 15 : 60,
      maxBufferSize: options.live ? 30 * 1024 * 1024 : 60 * 1024 * 1024,
      // ABR settings
      abrEwmaDefaultEstimate: 1_000_000, // 1 Mbps initial estimate
      abrBandWidthUpFactor: 0.7,
      abrBandWidthFactor: 0.95,
      // Live-specific
      liveSyncDurationCount: options.live ? 3 : undefined,
      liveMaxLatencyDurationCount: options.live ? 6 : undefined,
      // Error recovery
      fragLoadingMaxRetry: 3,
      manifestLoadingMaxRetry: 3,
      levelLoadingMaxRetry: 3,
      // Low-latency
      lowLatencyMode: options.live ?? false,
      backBufferLength: options.live ? 10 : 30,
    });

    hls.loadSource(src);
    hls.attachMedia(video);
    hlsRef.current = hls;

    return () => {
      hls.destroy();
      hlsRef.current = null;
    };
  }, [src]);

  return hlsRef;
}
```

**Key HLS.js configuration rationale**:

- `maxBufferLength: 8` for live keeps latency low (4 segments of 2s each).
- `maxBufferLength: 30` for VOD provides smooth seeking without re-buffering.
- `liveSyncDurationCount: 3` means the player targets 3 segments behind live edge (6 seconds at 2s segments).
- `lowLatencyMode: true` for live enables LL-HLS features (part loading, preload hints) if the server supports them.
- `fragLoadingMaxRetry: 3` provides resilience against transient network errors without infinite retries.

### 3.3 Quality Switching

HLS.js exposes quality levels via the `MANIFEST_PARSED` event and the `hls.levels` array. The component maps these to a user-facing quality menu.

```tsx
interface QualityLevel {
  index: number;
  height: number;
  width: number;
  bitrate: number;
  label: string; // e.g., "1080p", "720p", "Auto"
}

// After MANIFEST_PARSED:
const levels: QualityLevel[] = hls.levels.map((level, i) => ({
  index: i,
  height: level.height,
  width: level.width,
  bitrate: level.bitrate,
  label: `${level.height}p`,
}));

// Add "Auto" option at the top
levels.unshift({ index: -1, height: 0, width: 0, bitrate: 0, label: "Auto" });

// Switch quality:
function setQuality(levelIndex: number) {
  if (!hlsRef.current) return;
  hlsRef.current.currentLevel = levelIndex; // -1 = auto
  hlsRef.current.nextLevel = levelIndex;    // immediate switch for next segment
}
```

The quality selector renders as a `DropdownMenu` (from `frontend/src/components/ui/dropdown-menu.tsx`) anchored to a settings/gear button in the controls bar. The currently active level is indicated with a check mark (`<Check>` icon from lucide-react). When "Auto" is selected, a secondary label shows the current effective resolution (e.g., "Auto (720p)").

### 3.4 Fullscreen & Picture-in-Picture

**Fullscreen** uses the Fullscreen API on the container `<div>` (not the `<video>` element) so that custom controls remain visible:

```tsx
const containerRef = useRef<HTMLDivElement>(null);

function toggleFullscreen() {
  if (!containerRef.current) return;
  if (document.fullscreenElement) {
    document.exitFullscreen();
  } else {
    containerRef.current.requestFullscreen();
  }
}
```

Listen for `fullscreenchange` to update button icon state.

**Picture-in-Picture** uses the PiP API directly on the `<video>` element:

```tsx
async function togglePiP() {
  const video = videoRef.current;
  if (!video) return;
  if (document.pictureInPictureElement) {
    await document.exitPictureInPicture();
  } else if (video.requestPictureInPicture) {
    await video.requestPictureInPicture();
  }
}
```

Feature-detect PiP support and hide the button when unavailable:

```tsx
const pipSupported = "pictureInPictureEnabled" in document && document.pictureInPictureEnabled;
```

### 3.5 Loading & Buffering States

The component tracks playback state via a combination of HLS.js events and native `<video>` events:

| State | Trigger | UI |
|-------|---------|-----|
| `idle` | No src provided or player not yet attached | Poster image or empty area |
| `loading` | `src` set, manifest loading | Centered `Loader2` spinner over poster |
| `buffering` | `FRAG_BUFFERED` incomplete, `video.readyState < 3` | Spinner overlay on playing video |
| `playing` | `video.playing` event | Controls visible, no overlay |
| `paused` | `video.pause` event | Large centered play icon overlay |
| `ended` | `video.ended` or `Hls.Events.ERROR` with `data.details === "bufferStalledError"` + live stream end | "Stream ended" message + replay button (VOD) |
| `error` | Fatal HLS error or DRM failure | Error message card with description + retry button |

**Buffering detection** avoids false positives by requiring 500ms of continuous stall before showing the spinner (prevents flash during normal segment boundary transitions):

```tsx
const [isBuffering, setIsBuffering] = useState(false);
const bufferTimerRef = useRef<number>();

useEffect(() => {
  const video = videoRef.current;
  if (!video) return;

  const onWaiting = () => {
    bufferTimerRef.current = window.setTimeout(() => setIsBuffering(true), 500);
  };
  const onPlaying = () => {
    clearTimeout(bufferTimerRef.current);
    setIsBuffering(false);
  };

  video.addEventListener("waiting", onWaiting);
  video.addEventListener("playing", onPlaying);
  return () => {
    video.removeEventListener("waiting", onWaiting);
    video.removeEventListener("playing", onPlaying);
    clearTimeout(bufferTimerRef.current);
  };
}, []);
```

### 3.8 Token Injection for Authenticated Streams

Two token delivery mechanisms are supported:

**1. Query parameter (broadcast local cache / nginx secure_link)**:

The `src` prop already contains the token as URL params (e.g., `?md5=...&expires=...`). No additional injection needed — HLS.js passes the full URL including params for every segment and manifest request.

**2. Authorization header (playback entitlement JWT for CDN/DRM)**:

For CDN-fronted content requiring bearer authentication on each segment request, use HLS.js's `xhrSetup` config:

```tsx
const hls = new Hls({
  // ... other config
  xhrSetup: (xhr, url) => {
    if (options.drm?.token) {
      xhr.setRequestHeader("Authorization", `Bearer ${options.drm.token}`);
    }
  },
});
```

**Token refresh** — Playback entitlement tokens expire after 120-300 seconds. For long VOD sessions (watching a 2-hour video), the component must refresh the token before expiry:

```tsx
// Monitor token expiry (assume token is JWT with exp claim)
useEffect(() => {
  if (!options.onTokenExpiring || !options.drm?.token) return;

  const payload = JSON.parse(atob(options.drm.token.split(".")[1]));
  const expiresAt = payload.exp * 1000;
  const refreshAt = expiresAt - 30_000; // Refresh 30s before expiry
  const delay = Math.max(0, refreshAt - Date.now());

  const timer = setTimeout(async () => {
    const newToken = await options.onTokenExpiring!();
    // Update the xhrSetup with new token
    if (hlsRef.current) {
      hlsRef.current.config.xhrSetup = (xhr) => {
        xhr.setRequestHeader("Authorization", `Bearer ${newToken}`);
      };
    }
  }, delay);

  return () => clearTimeout(timer);
}, [options.drm?.token]);
```

### 3.9 DRM / EME Integration

For DRM-protected content, HLS.js supports EME natively when configured with `emeEnabled: true` and key system configuration:

```tsx
const hls = new Hls({
  emeEnabled: true,
  drmSystems: {
    "com.widevine.alpha": {
      licenseUrl: drm.licenseUrl,
    },
    "com.apple.fps.1_0": {
      licenseUrl: drm.licenseUrl,
      serverCertificateUrl: drm.fairplayCertificateUrl,
    },
  },
  licenseXhrSetup: (xhr, url) => {
    xhr.setRequestHeader("Authorization", `Bearer ${drm.token}`);
  },
});
```

For Safari native HLS (which bypasses HLS.js), FairPlay is handled via the `webkitneedkey` event on the `<video>` element. This requires a separate code path:

```tsx
if (video.canPlayType("application/vnd.apple.mpegurl") && drm) {
  // Safari native + FairPlay
  video.src = src;
  setupFairPlayNative(video, drm);
} else {
  // MSE + HLS.js + Widevine/PlayReady
  const hls = new Hls({ emeEnabled: true, ... });
}
```

- `PlayerControls.tsx`: Compose play/pause button, progress bar (or LIVE badge), time display, volume, quality menu trigger, PiP button, fullscreen button. Auto-hide logic (3s idle timeout).

**Step 5: Main `MediaPlayer.tsx` component**


**Step 6: Error recovery**

HLS.js errors are categorized as `fatal` or non-fatal. For fatal errors:

- `Hls.ErrorTypes.NETWORK_ERROR`: Call `hls.startLoad()` to retry.
- `Hls.ErrorTypes.MEDIA_ERROR`: Call `hls.recoverMediaError()` (first attempt), then `hls.swapAudioCodec(); hls.recoverMediaError()` (second attempt).
- Other fatal: Destroy and show error UI.

For non-fatal errors: Log but do not interrupt playback (HLS.js handles recovery internally).

**Step 7: Token refresh integration**

Wire `onTokenExpiring` prop into a `useEffect` that schedules refresh 30 seconds before JWT `exp`. On refresh, update `hls.config.xhrSetup` and optionally reload the manifest.

### 5.5 Performance Considerations for Tests

- Unit tests mock HLS.js entirely (no real media decoding) — fast execution (~100ms per test).
- E2E tests use a 2-second fixture segment (~15KB) to minimize I/O.
- E2E tests set `test.setTimeout(15_000)` — HLS.js initialization + segment load typically completes in 2-3 seconds in headless Chromium.
- The test player page is lazy-loaded and only available in dev mode; it adds zero weight to production bundles.

### 5.6 Edge Cases to Cover

| Scenario | Test approach | Expected |
|----------|--------------|----------|
| `src` changes mid-playback | Rerender with new `src` | Old HLS instance destroyed, new one created |
| `src` is empty string | Render with `src=""` | Player shows idle state, no HLS init |
| Browser without MSE (old Safari) | Mock `Hls.isSupported() = false` | Falls back to native `<video src=...>` |
| Manifest 404 | Route returns 404 | Shows "Video unavailable" error |
| Segment timeout (slow network) | Route delays 30s | HLS.js retries, then shows buffering, then error |
| Token expiry mid-stream | Simulate exp in 2s, verify refresh callback | `onTokenExpiring` called, new token applied |
| DRM license failure | Return 403 from license URL | Shows "Access denied" error |
| User clicks retry after error | Click "Try again" | New HLS instance created, playback retried |
| Component unmount during loading | Unmount before MANIFEST_PARSED | No memory leak, destroy() called |
| Rapid src changes (race condition) | Change src 5 times in 100ms | Only final src is loaded |
