# KYC-002: Identity Document Verification — Investigation & Implementation Write-up

## 1. Summary & Classification

**KYC-002** delivers automated OCR extraction of identity fields from uploaded ID documents (front and back of government-issued IDs), cross-referenced against the user's profile for name and date-of-birth matching, with a confidence score surfaced to reviewers in the admin case detail page. The backend service (`app/services/kyc_document_verification.py`, 581 lines), router (`app/routers/kyc_documents.py`), DynamoDB table (`kyc_documents`), and user-facing frontend pages (`KycDocumentVerificationPage.tsx`, `KycDocumentReviewQueuePage.tsx`) are all fully implemented. The remaining work is integrating extraction results into the KYC-001 admin case detail page (`KycCaseDetailPage.tsx`) as a dedicated sub-panel.

- **Type**: Feature (automated identity verification with mock OCR provider)
- **Priority**: High — feeds confidence scores into KYC-008 risk scoring and KYC-006 sanctions screening
- **Status**: Backend + standalone user/reviewer pages implemented; admin case-detail integration pending (depends on KYC-001)
- **Persona**: KYC reviewer (ADMIN/ROOT), applicant (USER)
- **Dependencies**: KYC-001 (admin detail page must exist before extraction results panel can be added). Downstream: KYC-006 (uses extracted name/DOB for sanctions matching), KYC-008 (uses overall_confidence), KYC-010 (passport scanner extends this service).
- **Cross-references**: [[SECOPS-007]] — mock OCR provider in dev (deterministic from filename patterns), real provider gated by `S.kyc_documents_real_extraction_enabled` (default `false`). S3 via moto in dev, real S3 in prod.

## 2. Current-State Investigation

### 2.1 Backend Service: `app/services/kyc_document_verification.py`

The `KycDocumentVerificationStore` dataclass (line 152) wraps a `_table` defaulting to `T.kyc_documents`. It implements the full pipeline:

**Document upload** (`upload_document`, stores image in S3 via `_store_image`):
- `bucket = S.kyc_documents_bucket` (`"local-uploads"` in dev)
- `s3_key = f"{S.kyc_documents_s3_prefix}{document_id}/{safe_name}"`
- In dev, calls `s3_client().put_object(Bucket=bucket, Key=s3_key, Body=body, ContentType="image/jpeg")` — intercepted by moto.
- Writes a `pending` record to `kyc_documents` DDB table (PK=`document_id`).

**Mock OCR extraction** (deterministic provider, selected by `_mock_extraction_enabled()`):
- Filename pattern matching: `*_mismatch_*` → name prefixed "WRONG", DOB shifted +1 year; `*_partial_*` → name with minor variation; `*_expired_*` → expiry date in the past; `*_fail_*` → `status=failed`.
- Default → extracted fields match the profile exactly.

**Real provider gate** (`S.kyc_documents_real_extraction_enabled`, default `false`): when enabled, calls a production OCR provider. Not wired in dev — the function raises `NotImplementedError` as a failsafe, and the service falls back to the mock. This satisfies SECOPS-007 rule 3 (graceful degradation).

**Profile matching** (`_load_profile_identity`, line 159):
- Calls `app.services.profile.get_profile(user_sub)` to get `display_name` / `first_name`+`last_name` and `birthday`.
- Name similarity: `difflib.SequenceMatcher` ratio on normalized (uppercase, collapsed whitespace) strings (`_name_similarity`, line 125). Threshold: `>= 0.85` → `match`; `>= 0.6` → `partial`; otherwise `mismatch`.
- DOB matching: exact ISO-format string comparison.

**Confidence computation**: `high` = all fields match; `medium` = any partial; `low` = any mismatch; `failed` = extraction failed.

**Status lifecycle**: `pending` → `extracted` (both mock and real success paths) or `failed`. Admin can then set `approved` or `rejected` via the review endpoint.

### 2.5 Dev/Prod Behavior Today

In dev (`S.dev_mode = True`), `_mock_extraction_enabled()` returns `True` (checks `not S.kyc_documents_real_extraction_enabled`). The mock runs synchronously during upload — no background task, no latency. In prod, real extraction is async: the upload endpoint queues an extraction job; the `extract` endpoint re-runs synchronously on demand. The `ByStatus` GSI with `status=pending` is the background processor's work queue.

## 3. Gap / Threat Analysis

### 3.1 Integration Gap: Admin Case Detail Panel

The core remaining work is an `ExtractionResultsPanel` component in `KycCaseDetailPage.tsx` that calls `GET /ui/kyc/documents?` filtered by `case_id`, displays extracted fields per document type, and shows confidence badges. Currently, an admin viewing a case can see the file references but cannot see extracted data without switching to the separate reviewer queue.

The admin needs:
- Per-document extracted fields (`full_name`, `date_of_birth`, `document_number`, `expiry_date`, `issuing_country`).
- Match status per field (match/partial/mismatch) compared to the profile.
- Overall confidence badge.
- A "Re-extract" button triggering `POST /ui/kyc/documents/{id}/extract`.

### 3.2 Edge Cases and Failure Modes

**Missing profile data**: If the applicant has not set `display_name` or `birthday` in their profile, `_load_profile_identity` returns `None` for those fields. The matching function returns `NOT_AVAILABLE` — this must be displayed clearly to the reviewer, not as a false `mismatch`.

**Expired documents**: An ID with `expiry_date` in the past is still extracted and matched, but the expiry field should carry a warning badge. The reviewer sees the extracted expiry date but must manually assess validity; the service does not auto-reject on expiry.

**Name normalization edge cases**: `O'Brien-Smith` normalizes to `OBRIEN-SMITH` (hyphens preserved). The `_normalize_name` function collapses whitespace but does not strip punctuation. A document that reads `OBRIEN SMITH` (no hyphen) would score `partial` (ratio ≈ 0.85 for a 13-char string) — acceptable but worth documenting for reviewers.

**Concurrent re-extractions**: `POST /{id}/extract` uses `UpdateItem` with `ConditionExpression: attribute_exists(document_id)`. If two requests race, both succeed (the second overwrites the first). The `extraction_id` changes, `updated_at` advances — idempotent outcome, last writer wins.

**S3 key not found**: If the S3 object was deleted before extraction runs (e.g., moto reset), `get_object` raises `ClientError`. The service catches this and sets `status=failed`. The reviewer sees a failed extraction badge and can re-upload.

**PII in `raw_response`**: The full JSON provider response is stored in `raw_response` on the DDB record. In prod, this may contain document image metadata. The `raw_response` field is included in the admin view (`include_match=True`) but NOT in the owner view (`public_document_view` with `include_match=False`). This is correct — `raw_response` must not be exposed to the applicant.

**Compliance**: Storing extracted name and DOB in DynamoDB constitutes PII storage. The `kyc_documents` table should be covered by the same retention policy as `kyc_cases` (KYC-023 / GDPR erasure path). The purge endpoint (`POST /admin/purge/run`) in KYC-001 only covers `kyc_cases`; a companion purge for `kyc_documents` linked to the same case is needed for full compliance.

## 4. Proposed Design / Fix

### 4.1 Admin Case Detail Integration

Inside `KycCaseDetailPage.tsx`, add a new tab "Document Extraction" alongside the existing document viewer. The tab renders `ExtractionResultsPanel`:

```typescript
// fetch documents for this case (admin view includes match_results)
const { data: docsData } = useQuery(
  ["kyc", "admin", "case-docs", caseId],
  () => api.get<KycDocumentListResponse>(
    `/ui/kyc/documents/admin/by-status?user_sub=${caseDetail.user_sub}&limit=50`
  )
);
// filter client-side to documents belonging to this case_id
const caseDocs = (docsData?.documents ?? []).filter(d => d.case_id === caseId);
```

Note: The `/ui/kyc/documents/admin/by-status` endpoint accepts `status` as a required query param (GSI PK). To list all documents for a case across all statuses, the frontend must call it once per status or the backend must add an optional `case_id` filter (secondary scan). The simpler approach: add a `?case_id=` filter to the admin by-status endpoint backed by a `FilterExpression` on the GSI scan result (acceptable for low-volume KYC documents — fewer than 10 per case).

### 4.2 ExtractionResultsPanel Component

Two-column layout, one column per document type (id_front / id_back). Each column:

- `OverallConfidenceBadge` — green "High", yellow "Medium", red "Low", gray "Pending", red outline "Failed".
- `ExtractionFieldTable` — rows for `full_name`, `date_of_birth`, `document_number`, `expiry_date`, `issuing_country`. Each row: extracted value, profile value (or "N/A"), `MatchBadge` (green/yellow/red/gray for not_available).
- `ExpiryWarning` — if `expiry_date` is in the past, show an amber alert "Document expired".
- `ReExtractButton` — calls `POST /ui/kyc/documents/{documentId}/extract` (admin variant), invalidates the documents query.
- `PendingSpinner` — shown when `status=pending`.
- `FailedBanner` — shown when `status=failed` with re-extract option.

### 4.3 Backend Filter Addition (`app/routers/kyc_documents.py`)

Add optional `case_id: str | None = Query(default=None)` to the `GET /admin/by-status` endpoint. When provided, wrap the GSI query result in a client-side filter:

```python
items = [i for i in items if str(i.get("case_id") or "") == case_id]
```

This is safe because KYC cases have at most 2–4 documents.

### 4.4 Dev/Prod Parity (SECOPS-007)

The existing implementation already satisfies SECOPS-007:
- **Dev**: mock OCR provider runs inline, no outbound calls, deterministic from filename.
- **Prod**: real provider gated by `S.kyc_documents_real_extraction_enabled=true`; dev always uses mock (fail-closed on egress).
- **S3**: moto in dev (`app/core/dev_s3.py`), real S3 in prod — same `s3_client()` factory from `app/core/aws_clients.py`.
- **DynamoDB**: DynamoDB Local (:8001) in dev, real DynamoDB in prod — same `T.kyc_documents` handle from `app/core/tables.py`.

No new external dependencies introduced by the integration panel.

### 4.5 Alternatives Considered

- **Auto-trigger extraction on KYC case submission** — the ticket originally proposed this (hooking into `submit_kyc_case`). Not implemented in the current backend (the service is standalone). Rejected to keep services decoupled; reviewers can trigger re-extraction manually.
- **Store extracted fields on the KYC case instead of a separate table** — rejected because it conflates verification state (owned by `kyc_document_verification.py`) with case state (owned by `kyc_cases.py`). The separate table enables independent lifecycle and purge.

### 5.4 Observability

The service uses `logger = logging.getLogger(__name__)` (line 40). Extraction outcomes (confidence, mismatch) should be emitted via `audit_event` or the KYC metrics counter. Currently only `KycDocumentValidationError` is logged. Add:
- `logger.info("kyc.extraction.completed", extra={"case_id": ..., "confidence": ..., "document_type": ...})`
- `logger.warning("kyc.extraction.name_mismatch", extra={"case_id": ..., "similarity": ...})`
