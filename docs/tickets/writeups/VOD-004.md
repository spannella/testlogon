# VOD-004: FFmpeg Execution with ABR Output and Watermark — Investigation & Implementation Write-up

> Status: **Implemented**. The executor, pipeline, manager, and watermark lifecycle components all exist. This write-up documents the actual implementation in detail and identifies gaps.

## 1. Summary & Classification

VOD-004 implements the layer that actually runs FFmpeg as a subprocess within the transcode worker (VOD-003). It provides:
- `app/services/ffmpeg_executor.py` — asyncio subprocess wrapper with real-time progress parsing, resource limits, structured error classification, and timeout enforcement
- `app/services/ffmpeg_abr_pipeline.py` — per-rendition argument builder with watermark filter graph construction
- `app/services/ffmpeg_manager.py` — binary detection, version validation, and codec verification
- `app/services/ffmpeg_executor_types.py` — typed result and error dataclasses
- `app/services/ffmpeg_watermark_lifecycle.py` — watermark asset download and cleanup

The critical design goals are: no synchronous subprocess calls in the async event loop, bounded resource consumption, structured failure modes, and a deterministic output directory layout.

- **Type**: Feature (execution infrastructure)
- **Priority**: P0 — the transcode worker calls into this layer for every rendition
- **Status**: Fully implemented
- **Owning area**: Backend / media processing
- **User persona**: System (called by transcode_worker.py)
- **Dependencies**: VOD-003 (worker provides job context), `app/contracts/video_rendition_profiles.py` (canonical ABR ladder), `app/contracts/watermark_policy.py` (watermark modes)
- **SECOPS-007 parity**: Local `ffmpeg` binary in dev; same binary in prod (no AWS substitution). Scratch dir is local filesystem in both. moto S3 for watermark asset downloads in dev.

## 2. Current-State Investigation (what exists today)

### 2.1 FFmpeg Manager — `app/services/ffmpeg_manager.py`

The manager is 130 lines. Its primary export is `get_ffmpeg_path()` which uses `@lru_cache` to probe for the binary once and return its absolute path on all subsequent calls.

**Detection order** (lines ~80–110):
1. Check `S.ffmpeg_binary_path` setting
2. Fall back to `shutil.which("ffmpeg")`
3. Fall back to `shutil.which("ffmpeg6")`, `shutil.which("ffmpeg5")` (distro-specific names)

**Validation** (called on first use):
- Runs `ffmpeg -version` and parses the version string with `_parse_version_tuple`
- Requires `MIN_VERSION = (5, 0)` — FFmpeg 5.0 or later
- Runs `ffmpeg -codecs` and checks that `REQUIRED_CODECS = {"libx264", "aac"}` are present
- Warns (but does not fail) if `RECOMMENDED_CODECS = {"libx265", "libvpx", "libopus"}` are absent

`is_ffmpeg_available()` calls `get_ffmpeg_path()` and catches any exception, returning `False`. This is the safe check callers use before attempting transcoding.

### 2.2 FFmpeg ABR Pipeline — `app/services/ffmpeg_abr_pipeline.py`

**`build_rendition_ffmpeg_args`** (line 50): Constructs the full FFmpeg argument list for a single rendition. Called by the transcode worker's `_run_ffmpeg_for_rendition` for each entry in `job["renditions"]`.

Key argument groups added:
1. **Input**: `-rw_timeout 5000000 -i {input_url}` — 5-second network timeout
2. **Watermark (dynamic_text mode)**: `drawtext` filter using `interpolate_template_variables` to inject tenant_id, session_id, timestamp into the text template
3. **Watermark (static_image mode)**: `[0:v][1:v]overlay=...` filter graph referencing a second input for the overlay image
4. **Video codec**: `-c:v libx264 -preset medium -crf 23 -b:v {bitrate}k`
5. **Audio codec**: `-c:a aac -b:a {audio_bitrate}k`
6. **HLS output**: `-f hls -hls_time 6 -hls_list_size 0 -hls_flags independent_segments -hls_segment_filename {out_dir}/seg_%05d.ts {out_dir}/index.m3u8`

The output directory structure per rendition: `{scratch_dir}/output/{rendition_name}/`
- `index.m3u8` (variant playlist)
- `seg_00001.ts`, `seg_00002.ts`, ... (media segments)

**`write_master_playlist`** (line 145): Scans the output directory for subdirectories containing `index.m3u8`, generates a `master.m3u8` with `#EXT-X-STREAM-INF` entries for each variant, and writes it to `{output_dir}/master.m3u8`.

**Canonical ABR ladder** — `app/contracts/video_rendition_profiles.py` defines `CANONICAL_ABR_LADDER`, a list of dicts with `name`, `width`, `height`, `video_bitrate_kbps`, `audio_bitrate_kbps`, `fps`, `gop_seconds`. Typical entries: 1080p/5000kbps, 720p/2500kbps, 480p/1200kbps, 360p/800kbps. The transcode job router uses this as the default when no rendition_profiles are supplied.

### 2.3 FFmpeg Executor — `app/services/ffmpeg_executor.py`

The executor is 570 lines. Its primary export is `execute_rendition(args, rendition_name, expected_duration_us, timeout_seconds, on_progress, cancel_event)`.

**Argument augmentation — `_validate_and_augment_args`** (line 184): The executor modifies the argument list before running, in order:
1. Validates first arg is `"ffmpeg"` or the configured binary path
2. Injects `-nostdin` (prevents interactive prompts that would block stdin)
3. Injects `-progress pipe:1` (enables structured progress output on stdout)
4. Calls `_patch_args_for_vod` to replace `-hls_list_size N` with `0` and `-hls_flags live_*` with `independent_segments`, and inject `-hls_playlist_type vod` if absent
5. Calls `_inject_rate_control` to add `-maxrate {1.2x bitrate}k -bufsize {2x bitrate}k` after any `-b:v` flag
6. Calls `_inject_thread_limit` to add `-threads N` based on `S.ffmpeg_max_threads_per_job` (0 = auto = `cpu_count // max_concurrent`)

**Resource limits — `_apply_resource_limits`** (line 317): Called via `preexec_fn` in `asyncio.create_subprocess_exec`:
- `RLIMIT_CPU`: soft=7200s (2 hours), hard=7500s — absolute CPU time safety net
- `RLIMIT_AS`: `S.ffmpeg_max_memory_gb * 1GB` — virtual address space cap (default 8GB)
- `RLIMIT_FSIZE`: 50GB — prevents runaway disk writes
- `os.nice(10)` — lower scheduling priority than API worker

**Restricted environment — `_build_restricted_env`** (line 307): The subprocess inherits only:
```python
{"PATH": "/usr/local/bin:/usr/bin:/bin", "HOME": "/tmp", "LANG": "C.UTF-8", "LC_ALL": "C.UTF-8"}
```
No AWS credentials, no `DATABASE_URL`, no `SECRET_KEY`, no `HOME` pointing to `/root` — this prevents the FFmpeg process from inheriting production secrets even if it somehow calls out to the host.

**Progress parsing — `_read_progress`** (line 340): Reads FFmpeg's `-progress pipe:1` protocol from stdout. FFmpeg outputs key=value pairs, ending each frame with `progress=continue` or `progress=end`. The reader collects pairs into `current_frame`, emits a `ProgressSample` on each `progress=` line, and calls the `on_progress` callback with `pct = min(100, int((out_time_us / expected_duration_us) * 100))`.

**Stderr ring buffer — `_read_stderr_tail`** (line 415): Collects up to `max_bytes=4096` of stderr. Keeps only the tail — FFmpeg's first stderr lines contain version/build info; the errors appear at the end.

**Timeout and cancellation — `_wait_with_cancel`** (line 437): Races between `proc.wait()` and `cancel_event.wait()`. On cancellation, calls `_terminate_gracefully` (SIGTERM → grace period → SIGKILL). On timeout (`asyncio.wait_for` TimeoutError), same graceful termination, then raises `RenditionTimeoutError`.

**Error classification — `classify_error`** (line 510): Matches stderr against `_ERROR_PATTERNS` (line 37), returning `(error_code, is_retryable)`:
- `"source_not_found"` / `"invalid_input"` / `"unsupported_codec"` → non-retryable
- `"disk_full"` / `"oom"` / `"network_timeout"` / `"network_error"` / `"source_truncated"` / `"broken_pipe"` → retryable
- Unknown → `f"ffmpeg_exit_{returncode}"`, retryable (transient assumption)

**Output validation — `validate_output`** (line 531): Checks that `master.m3u8` exists, each rendition has `index.m3u8`, and each rendition directory has at least one `seg_*.ts`. Raises `OutputValidationError` (from `ffmpeg_executor_types.py`) on failure.

**Disk space check — `_check_disk_space`** (line 493): Pre-flight check via `os.statvfs`. Raises `RetryableError("disk_full", ...)` if free space < `S.ffmpeg_min_free_disk_gb` (default 5.0 GB).

### 2.4 Executor Types — `app/services/ffmpeg_executor_types.py`

Defines the typed result and exception hierarchy:
- `ProgressSample(timestamp, out_time_us, frame, fps, speed)` — frozen dataclass
- `FFmpegExecutionResult(success, returncode, duration_seconds, output_dir, segments_written, stderr_tail, progress_samples)` — frozen dataclass
- `RenditionTimeoutError(rendition_name, timeout_seconds)` — Exception subclass
- `RetryableError(error_code, message)` — Exception subclass
- `NonRetryableError(error_code, message)` — Exception subclass
- `OutputValidationError(message)` — Exception subclass

### 2.5 Watermark Lifecycle — `app/services/ffmpeg_watermark_lifecycle.py`

**`prepare_watermark_asset`** (line ~30): If `watermark_policy.mode == "static_image"`, downloads the asset from S3 to `{scratch_dir}/watermark/asset.*`. Returns the local path for FFmpeg's second input. Also validates file size (max 10MB) and format (JPEG/PNG).

**`patch_watermark_input`** (line ~80): Inserts `-i {local_wm_path}` into the args list at the right position (after the source `-i` but before video codec flags) so FFmpeg treats it as a second input stream for the overlay filter graph.

### 2.6 Integration with Transcode Worker — `transcode_worker.py:234`

`_run_ffmpeg_for_rendition` orchestrates the executor:
1. Constructs watermark policy from `job["watermark"]`
2. Calls `build_rendition_ffmpeg_args(input_url=source_uri, output_dir=scratch_dir/output, rendition=rendition, watermark_policy=watermark_policy)`
3. Calls `prepare_watermark_asset` and `patch_watermark_input` if watermark asset is needed
4. If DRM is enabled: calls `prepare_encryption_params` and `get_ffmpeg_encryption_args` (VOD-010) to inject `-hls_key_info_file` argument
5. Calls `execute_rendition(args=args, rendition_name=..., expected_duration_us=..., timeout_seconds=S.transcode_rendition_timeout_seconds, on_progress=_on_progress, cancel_event=cancel_event)`
6. The `_on_progress` callback throttles DynamoDB writes to `S.transcode_progress_update_interval_seconds`
7. On `RetryableError` or `NonRetryableError`, propagates to `execute_transcode_job`'s exception handler

### 2.7 Dev vs Prod Parity (SECOPS-007)

| Concern | Dev | Prod |
|---|---|---|
| FFmpeg binary | Local `ffmpeg` on PATH | Same: `get_ffmpeg_path()` uses `shutil.which` |
| Source input | S3 key → `s3://local-uploads/vod/...` resolved to moto | Real S3 presigned GET URL or `s3://` with IAM role |
| Scratch dir | `tmp/transcode-scratch/{job_id}/` relative CWD | `TRANSCODE_SCRATCH_DIR` absolute path on NVMe/EFS |
| S3 watermark asset download | boto3 → moto | boto3 → real S3 |
| Resource limits | Applied via `preexec_fn` | Same; check ulimits on host |
| Subprocess environment | Restricted (no secrets) | Same — identical restriction in both |
| Output validation | Runs against local scratch dir | Same |

The code path is identical. `S.dev_mode` does not gate any FFmpeg execution logic — the executor is unaware of whether it's in dev or prod.

## 3. Gap / Threat Analysis

### 3.1 Source URI Resolution in Worker

`_run_ffmpeg_for_rendition` passes `source_uri = job.get("source_uri", "")` directly as the `-i` argument to FFmpeg. In prod, this is `s3://{bucket}/{key}` — which requires FFmpeg to be compiled with `libavformat`'s S3 support or an S3 FUSE mount. Most stock FFmpeg builds do NOT support the `s3://` protocol directly. The worker needs to download the source file from S3 to local scratch first, then pass the local path as the `-i` argument.

In dev mode, the source_uri is also `s3://local-uploads/...` — the moto mock. FFmpeg cannot talk to moto. This means end-to-end transcode tests with a real FFmpeg invocation would fail unless a pre-downloaded source file is placed in scratch.

**Fix**: In `execute_transcode_job`, before calling `_run_ffmpeg_for_rendition`, download the source from S3 to `scratch_dir / "source.<ext>"` and pass the local path as the source_uri.

### 3.2 `expected_duration_us` Defaults to 600 Seconds

`_run_ffmpeg_for_rendition` at `transcode_worker.py:295`:
```python
expected_duration_us = int(rendition.get("expected_duration_us", 600_000_000))
```
If the rendition dict does not include `expected_duration_us`, progress percentage will be calculated against a 10-minute baseline. A 2-hour source will show 100% at the 10-minute mark and never show intermediate percentages correctly. The correct approach is to probe the source file with `ffprobe` to get actual duration before transcoding, and set `expected_duration_us = duration_seconds * 1_000_000`.

### 3.3 No Source File Validation (Probe Step)

The ticket design mentioned a `probing` status in the VideoStatus state machine (created → probing → pending_encoding). However, the current implementation does not perform an ffprobe step before creating the transcode job. The probe failure path (`probe_failed` status) is never reached in practice. The first indication of a corrupted source file is a `NonRetryableError("invalid_input", ...)` from the executor on the first rendition — after the job has already claimed disk space and processing time.

Adding an `ffprobe` call before submitting the transcode job would:
1. Set `duration_seconds`, `width`, `height`, `frame_rate`, `video_codec`, `audio_codec` on the VideoMetadata record (needed for ABR ladder selection)
2. Populate `expected_duration_us` correctly in the job's rendition profiles
3. Fail fast on corrupted uploads before wasting queue capacity

### 3.4 `_patch_args_for_vod` May Produce Duplicate Flags

`_patch_args_for_vod` injects `-hls_playlist_type vod` if not present. `build_rendition_ffmpeg_args` never sets this flag explicitly, so it will always be added. But if a future caller explicitly passes `-hls_playlist_type event`, the patch function replaces `-hls_list_size` and `-hls_flags` but does not remove the existing `-hls_playlist_type` — it only injects a second occurrence. Duplicate FFmpeg flags are generally last-wins, so the injected `vod` would override `event`. This is the correct behavior but should be documented.

### 3.5 Subprocess Environment Loses `TMPDIR`

`_build_restricted_env` sets `HOME=/tmp` but does not include `TMPDIR`. Some FFmpeg builds write temporary files to `$TMPDIR` or `$TEMP`. Without this variable, they fall back to `/tmp`. If `/tmp` is on the root filesystem with a separate scratch mount, this creates a resource accounting inconsistency. Adding `TMPDIR` pointing to the scratch directory would be cleaner.

## 4. Proposed Design / Fix

### 4.1 Fix Source URI — Download Before FFmpeg

In `transcode_worker.execute_transcode_job`, before the rendition loop:
```python
from app.services.vod_s3_downloader import download_source_to_scratch

source_path = await download_source_to_scratch(
    source_uri=source_uri,
    scratch_dir=scratch_dir,
)
# Replace source_uri with local path for all rendition calls
source_uri = str(source_path)
```

Create `app/services/vod_s3_downloader.py` that:
1. Parses `s3://{bucket}/{key}` from the URI
2. In dev: calls `s3.get_object(Bucket=bucket, Key=key)` on the moto client, streams to local file
3. In prod: same boto3 call, but S3 Transfer Manager handles multipart download for large files
4. Returns the local `Path`

This eliminates the S3 protocol gap and enables real end-to-end testing in dev.

### 4.2 Fix `expected_duration_us` — Add ffprobe Step

Add `app/services/ffprobe_inspector.py` that runs `ffprobe -v quiet -print_format json -show_format -show_streams {path}` and parses the output. Call it in `execute_transcode_job` after download, before the rendition loop. Use the result to:
- Update VideoMetadata with `duration_seconds`, `width`, `height`, etc.
- Set `expected_duration_us` in each rendition dict

### 4.3 Dev/Prod Parity (SECOPS-007)

Both fixes (S3 download, ffprobe) use the same `s3_client()` factory that already branches on `S.dev_mode` via `_s3_endpoint_url()`. No explicit `if S.dev_mode:` branching needed.

### 5.2 Integration Tests (real FFmpeg)

These tests only run when `is_ffmpeg_available()` returns True:

```python
@pytest.mark.skipif(not is_ffmpeg_available(), reason="ffmpeg not installed")
async def test_execute_minimal_rendition(tmp_path):
    """Transcode a 5-second silent video to HLS, verify output structure."""
    source = tmp_path / "source.mp4"
    # generate 5s silent video:
    subprocess.run(["ffmpeg", "-f", "lavfi", "-i", "testsrc=duration=5:size=640x360:rate=25",
                    "-f", "lavfi", "-i", "anullsrc", "-c:v", "libx264", "-c:a", "aac",
                    "-t", "5", str(source)], check=True, capture_output=True)
    output_dir = tmp_path / "output"
    rendition = {"name": "360p", "width": 640, "height": 360, "video_bitrate_kbps": 400, "audio_bitrate_kbps": 64}
    args = build_rendition_ffmpeg_args(
        input_url=str(source), output_dir=output_dir,
        rendition=rendition, watermark_policy=WatermarkPolicy()
    )
    result = await execute_rendition(args=args, rendition_name="360p",
                                      expected_duration_us=5_000_000, timeout_seconds=60)
    assert result.success
    assert (output_dir / "360p" / "index.m3u8").exists()
    assert result.segments_written > 0
```
