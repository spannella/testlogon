# VOD-005: Upload Transcode Outputs to S3 and Generate Manifest URLs — Investigation & Implementation Write-up

> Status: **Implemented**. The S3 uploader, playback URL generator, and thumbnail extractor all exist. This write-up documents the implementation, the dev/prod branching, and unresolved issues.

## 1. Summary & Classification

VOD-005 closes the loop of the transcode pipeline by taking the local HLS output directory produced by FFmpeg (VOD-004) and pushing it to S3 for CDN delivery. It introduces:
- `app/services/vod_s3_uploader.py` — concurrent upload of HLS manifests, TS segments, and thumbnails to S3 with correct content types, cache headers, multipart support, and progress reporting
- `app/services/vod_playback_url.py` — signed manifest URL generation in three modes: dev (`/mock/s3/`), CloudFront signed token, and S3 presigned GET
- `app/services/vod_thumbnail_extractor.py` — FFmpeg-based poster image extraction at configurable timestamps
- Extension of `transcode_job_store.complete_job_with_outputs` (VOD-003) to atomically store all output metadata in the TranscodeJobs record on completion

- **Type**: Feature (output persistence and CDN delivery)
- **Priority**: P0 — without this, transcode outputs are lost when the job's scratch dir is cleaned up
- **Status**: Fully implemented
- **Owning area**: Backend / media pipeline
- **User persona**: System (called by transcode_worker.py), Viewer (receives playback URL)
- **Dependencies**: VOD-003 (worker calls upload after FFmpeg), VOD-004 (FFmpeg produces the output dir), `app/core/aws_clients.py` (s3_client), `app/core/dev_s3.py` (moto)
- **SECOPS-007 parity**: In dev, boto3 S3 calls hit moto in-process; in prod, real S3 with Transfer Manager multipart. Same code path, `S.dev_mode` only gates URL generation.

## 2. Current-State Investigation (what exists today)

### 2.1 S3 Uploader — `app/services/vod_s3_uploader.py`

The file is ~300 lines. Module-level `_s3 = s3_client()` creates the client at import time.

**Content-type map** (line 28):
```python
_CONTENT_TYPE_MAP = {
    ".m3u8": "application/vnd.apple.mpegurl",
    ".ts": "video/mp2t",
    ".mp4": "video/mp4",
    ".mpd": "application/dash+xml",
    ".jpg": "image/jpeg",
    ...
    ".vtt": "text/vtt",
}
```

**Cache-control map** (line 40): Variant playlists and TS segments get `max-age=31536000, immutable` (1 year) — they are write-once and content-addressed. `master.m3u8` gets `max-age=5, stale-while-revalidate=10` — it changes when new renditions are added.

**Transfer config** (line 66): `_build_transfer_config()` reads settings to produce a `boto3.s3.transfer.TransferConfig`:
- `multipart_threshold = S.vod_upload_multipart_threshold_mb * 1MB` (default 8MB)
- `multipart_chunksize = S.vod_upload_multipart_chunksize_mb * 1MB` (default 8MB)
- `max_concurrency = S.vod_upload_concurrency` (default 4)

**`UploadResult` dataclass** (line 80 area):
```python
@dataclass
class UploadResult:
    manifest_s3_uri: str        # s3://{bucket}/{prefix}/{tenant}/{video}/hls/master.m3u8
    manifest_s3_key: str
    total_bytes: int
    files_uploaded: int
    upload_duration_seconds: float
    thumbnail_s3_keys: list[str]
```

**`upload_transcode_outputs`** (line ~100): The main entry point called by the worker. Takes `job_id`, `video_id`, `tenant_id`, `output_dir`, `thumbnail_dir`, and `on_progress` callback.

1. Discovers all files under `output_dir` and `thumbnail_dir` recursively
2. For each file, computes S3 key: `{S.vod_output_prefix}/{tenant_id}/assets/{video_id}/hls/{relative_path}` for HLS files, `{S.vod_output_prefix}/{tenant_id}/assets/{video_id}/thumbnails/{filename}` for thumbnails
3. Calls `_upload_file(local_path, bucket, s3_key, content_type, cache_control)` for each
4. `_upload_file` uses `_s3.upload_file(Filename=..., Bucket=..., Key=..., ExtraArgs={...}, Config=transfer_config)` — the Transfer Manager handles multipart automatically based on file size vs. threshold
5. Calls `on_progress(files_done, total_files)` after each successful upload
6. Returns `UploadResult` with aggregated stats

**`abort_incomplete_uploads`** (line ~250): Lists and aborts any in-progress multipart uploads in the target prefix. Called by `execute_transcode_job`'s exception handler to avoid billing for abandoned multipart uploads in prod.

```python
def abort_incomplete_uploads(bucket: str, prefix: str) -> None:
    resp = _s3.list_multipart_uploads(Bucket=bucket, Prefix=prefix)
    for upload in resp.get("Uploads", []):
        _s3.abort_multipart_upload(
            Bucket=bucket, Key=upload["Key"], UploadId=upload["UploadId"]
        )
```

### 2.2 Playback URL Generator — `app/services/vod_playback_url.py`

The file is ~200 lines. Module-level `_s3 = s3_client()`.

**`mint_vod_playback_url(video_id, tenant_id, ttl_seconds)`** (line 40): Dispatches to one of three modes:

**Dev mode** (`S.dev_mode = True`) — `_mint_dev_url`:
```python
bucket = S.vod_output_bucket or S.transcode_output_bucket or "vod-output"
key = f"{prefix}/{tenant_id}/assets/{video_id}/hls/master.m3u8"
url = f"http://localhost:8000/mock/s3/{bucket}/{key}"
thumb_key = f"{prefix}/{tenant_id}/assets/{video_id}/thumbnails/poster_0s.jpg"
thumb_url = f"http://localhost:8000/mock/s3/{bucket}/{thumb_key}"
return VodPlaybackUrl(url=url, expires_at=0, manifest_key=key, mode="dev", thumbnail_url=thumb_url)
```
The `expires_at=0` means no expiry in dev — the `/mock/s3/` route serves any key without token validation.

**CloudFront mode** (if `S.vod_cloudfront_domain` or `S.broadcast_cloudfront_domain` is set) — `_mint_cloudfront_url`:
Uses `_sign(normalized_path, expires_at)` from `broadcast_cloudfront.py` to generate HMAC-SHA256 tokens. The signing secret is `S.vod_cloudfront_signing_secret` (default `"dev-vod-cf-secret"`). URL format: `https://{domain}/{prefix}/{tenant}/{video}/hls/master.m3u8?cf_token={token}&cf_expires={expires_at}`.

**Presigned mode** (fallback) — `_mint_presigned_url`:
Calls `_s3.generate_presigned_url(ClientMethod="get_object", Params={...}, ExpiresIn=ttl)`. Returns the S3 presigned GET URL directly.

**`validate_vod_playback_token(path, token, expires)`** (line 65): Validates:
1. Token is non-empty
2. `expires` is in the future (not expired)
3. `expires` is not more than `max(60, vod_playback_url_ttl_seconds) + 30` seconds in the future (prevents replay of old tokens with manipulated expiry)
4. HMAC matches `_vod_sign(normalized_path, expires_at)`

Used by the VOD playback endpoint (`vod_drm.py` or similar) to authorize manifest fetches without a DynamoDB lookup.

**Settings for playback URL** (`settings.py`):
- `vod_playback_url_ttl_seconds`: `VOD_PLAYBACK_URL_TTL_SECONDS`, default 3600
- `vod_cloudfront_domain`: `VOD_CLOUDFRONT_DOMAIN`, default `""`
- `vod_cloudfront_signing_secret`: `VOD_CLOUDFRONT_SIGNING_SECRET`, default `"dev-vod-cf-secret"`

### 2.3 Thumbnail Extractor — `app/services/vod_thumbnail_extractor.py`

Called by the transcode worker after transcoding and before the S3 upload:
```python
await extract_thumbnails(
    source_path=source_path,
    output_dir=thumbnail_dir,

`extract_thumbnails` runs one FFmpeg invocation per timestamp:
```

Errors are caught and logged (thumbnails are non-fatal), consistent with the worker's `try/except` at `transcode_worker.py:158`.

**Settings for thumbnails** (`settings.py:1420`):
- `vod_thumbnail_enabled`: `VOD_THUMBNAIL_ENABLED`, default `True`
- `vod_thumbnail_timestamps`: `VOD_THUMBNAIL_TIMESTAMPS`, default `"0,10,30"`
- `vod_thumbnail_width`: `VOD_THUMBNAIL_WIDTH`, default `640`
- `vod_thumbnail_quality`: `VOD_THUMBNAIL_QUALITY`, default `5`

### 2.4 Integration in Transcode Worker — `transcode_worker.py:134`

The VOD-005 services are called in this order after FFmpeg completes:

```python
# 1. Extract thumbnails (non-fatal)
if S.vod_thumbnail_enabled:
    await extract_thumbnails(source_path=..., output_dir=thumbnail_dir, ...)

# 2. Upload all outputs
upload_result = upload_transcode_outputs(
    job_id=job_id, video_id=job["video_id"], tenant_id=job["tenant_id"],
    output_dir=output_dir, thumbnail_dir=thumbnail_dir,
    on_progress=_upload_progress,
)

# 3. Generate playback URL
playback_url = mint_vod_playback_url(video_id=job["video_id"], tenant_id=job["tenant_id"])

# 4. Complete job with all outputs atomically
complete_job_with_outputs(
    job_id=job_id, worker_id=wid,
    upload_result=upload_result, playback_url=playback_url,
    renditions_completed=completed_renditions,
)
```

The upload progress callback maps upload progress to the 90–100% range (FFmpeg ran 0–90%):
```python
def _upload_progress(files_done: int, total_files: int) -> None:
    pct = 90 + int((files_done / max(1, total_files)) * 10)
    update_job_progress(job_id, progress_pct=pct, current_rendition="uploading")
```

### 2.5 Dev vs Prod Parity (SECOPS-007)

| Concern | Dev | Prod |
|---|---|---|
| S3 target | moto in-process (`vod-output` bucket pre-created at startup) | Real S3 (`VOD_OUTPUT_BUCKET`) |
| Upload method | `_s3.upload_file(...)` → moto handles multipart transparently | Same boto3 call → real S3 Transfer Manager |
| Multipart abort | `list_multipart_uploads` → moto returns `[]` (no real MPU) | Real S3 lists + aborts actual incomplete parts |
| Playback URL | `http://localhost:8000/mock/s3/{bucket}/{key}` — no expiry | CloudFront signed or S3 presigned, with expiry |
| Thumbnail extraction | Local FFmpeg → local files → moto upload | Same; source file must be local (see VOD-004 gap) |

The `S.dev_mode` flag is the single branch point in `mint_vod_playback_url`. The S3 upload path has no `dev_mode` branch — it calls the same boto3 API in both environments, and moto intercepts transparently.

### 2.6 `complete_job_with_outputs` — `transcode_job_store.py:181`

The atomic DynamoDB update writes to TranscodeJobs:
- `output_hls_manifest_uri = upload_result.manifest_s3_uri`
- `output_s3_prefix = upload_result.manifest_s3_key.rsplit("/hls/", 1)[0]` (extracts the asset prefix)
- `output_total_bytes`, `output_object_count`, `output_upload_duration_seconds`
- `output_thumbnail_keys = upload_result.thumbnail_s3_keys`
- `output_playback_url = playback_url.url`
- `output_playback_expires_at = playback_url.expires_at`

- Condition: `#s = :running AND worker_id = :wid`

The VideoMetadata record is NOT updated here. The worker updates it separately via `transition_video_status(..., to_status="pending_review")` (see VOD-003 — currently tries `"published"` incorrectly). The playback URL stored in TranscodeJobs is used by the listing API when serving the video detail endpoint.

## 3. Gap / Threat Analysis

### 3.1 VideoMetadata `hls_manifest_url` Never Updated

`complete_job_with_outputs` updates the TranscodeJobs record with `output_playback_url`. However, `VideoMetadataModel.hls_manifest_url` — the field that the listing API returns in `VideoDetailOut.hls_manifest_url` — is never populated by this flow. The listing API issues the playback token from `video.hls_manifest_url` in `_try_issue_playback_token`:
```python
if not video.hls_manifest_url:
    return None, None
```
Since `hls_manifest_url` is always None after transcoding, no playback token is ever issued. The video shows as published but has no playable URL.

**Fix**: After `complete_job_with_outputs`, update the VideoMetadata record:
```python
from app.services.video_metadata_store import transition_video_status
video = get_video(job["video_id"])
updated = video.model_copy(update={
    "hls_manifest_url": playback_url.url,
    "hls_manifest_s3_key": upload_result.manifest_s3_key,
    "thumbnail_url": playback_url.thumbnail_url,
    "thumbnail_s3_key": upload_result.thumbnail_s3_keys[0] if upload_result.thumbnail_s3_keys else None,
    "renditions": [
        {"label": r["name"], "width": r["width"], "height": r["height"], "bitrate_kbps": r.get("video_bitrate_kbps", 0)}
        for r in job.get("renditions", [])
    ],
    "updated_at": now_ts(),
})
T.video_metadata.put_item(Item=video_to_item(updated))
```
This can be done in the worker after the atomic job completion.

### 3.2 Playback URL Key Path Assumption

`_manifest_key(video_id, tenant_id)` in `vod_playback_url.py:113` constructs:
```python
f"{prefix}/{tenant_id}/assets/{video_id}/hls/master.m3u8"
```
But `upload_transcode_outputs` uses:
```python
f"{S.vod_output_prefix}/{tenant_id}/assets/{video_id}/hls/{relative_path}"
```
Both use the same prefix (`S.vod_output_prefix`). If the tenant_id used in `mint_vod_playback_url` differs from the tenant_id used during upload, the manifest key won't match the actual S3 key. In `execute_transcode_job`, `tenant_id = job["tenant_id"]` is used for both calls — consistent. But the `video.owner_user_id` is used as `tenant_id` in the job creation path when no explicit tenant is set, which in dev mode is the user's email address. In prod, tenant_id should be a proper account ID. If this changes, the stored playback URLs become stale.

### 3.3 `upload_transcode_outputs` Is Synchronous in an Async Context

`upload_transcode_outputs` uses `_s3.upload_file(...)` (synchronous boto3), called from the async `execute_transcode_job`. This blocks the asyncio event loop for the duration of each file upload. For a typical 1080p video with 4 renditions × ~200 segments each = ~800 files, each sync upload call blocks the loop. While the progress callback makes it appear responsive, the API server cannot handle incoming requests during the upload phase.

**Fix**: Run `upload_transcode_outputs` in a thread pool executor:
```python
upload_result = await asyncio.get_event_loop().run_in_executor(
    None,
    lambda: upload_transcode_outputs(job_id=job_id, ...)
)
```

### 3.4 Thumbnail Source File Not Guaranteed to Exist

`transcode_worker.py:145` looks for the source file:
```python
source_candidates = list(scratch_dir.glob("source*"))
if source_candidates:
    source_path = source_candidates[0]
```
If the source was never downloaded to the scratch dir (the VOD-004 gap of using `s3://` URIs directly), `source_candidates` is empty and `source_path` defaults to `scratch_dir / "source"` (a non-existent path). FFmpeg's thumbnail extraction would fail (silently caught), producing zero thumbnails. This links back to the VOD-004 source download gap.

## 4. Proposed Design / Fix

### 4.1 Fix `hls_manifest_url` Not Being Set on VideoMetadata

In `app/services/transcode_worker.py`, after `complete_job_with_outputs` succeeds (~line 195), add:
```python
# Update VideoMetadata with playback URL and rendition info
try:
    from app.services.video_metadata_store import get_video, video_to_item
    from app.core.tables import T
    from app.core.time import now_ts as _now
    vid = get_video(job["video_id"])
    updated = vid.model_copy(update={
        "hls_manifest_url": playback_url.url,
        "hls_manifest_s3_key": upload_result.manifest_s3_key,
        "thumbnail_url": playback_url.thumbnail_url or "",
        "thumbnail_s3_key": (upload_result.thumbnail_s3_keys or [""])[0],
        "updated_at": _now(),
    })
    T.video_metadata.put_item(Item=video_to_item(updated))
except Exception:
    logger.warning("Could not update video %s hls_manifest_url", job["video_id"])
```

### 4.2 Make Upload Async

Wrap the synchronous upload call in `execute_transcode_job`:
```python
import asyncio
upload_result = await asyncio.get_event_loop().run_in_executor(None, _do_upload)
```
where `_do_upload` is a lambda or partial that calls `upload_transcode_outputs(...)`.

### 4.3 Dev/Prod Parity (SECOPS-007)

The `_mint_dev_url` branch uses `S.dev_mode` to switch from CloudFront/presigned URLs to mock S3 URLs. This is the only environment-sensitive branch. S3 upload itself is identical in both environments — moto intercepts transparently. The `VOD_CLOUDFRONT_SIGNING_SECRET` default value `"dev-vod-cf-secret"` is a hardcoded string in `settings.py:1417`; prod deployments must set a real secret or token validation is trivially forgeable.
