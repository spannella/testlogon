# ADS-020: Broadcast Ad Serving + Billing Integration — Investigation & Implementation Write-up

## 1. Summary & Classification

ADS-020 wires the existing broadcast ad-break viewer experience (ADS-006) into the real ad platform: real ad selection via the ADS-004 serving engine, advertiser billing and creator revenue-share via ADS-007, fraud detection via `ad_fraud_prevention`, analytics rollup writes, and fixes for two failing E2E overlay UI tests. Currently, broadcast ads are a self-contained stub that generates no revenue and has no targeting.

- **Type**: Feature / Integration
- **Priority**: High (6–9 days estimate)
- **Status**: Open — the viewer flow and ad-break lifecycle are fully implemented in `app/services/broadcast_ads.py`. The ad serving, billing, fraud, and analytics integration is explicitly stubbed with a `NOTE` comment in the source file. Two E2E UI tests (`369.1` and `369.2`) are failing.
- **Owning area**: Broadcast / Ad Platform
- **User persona**: Advertisers (campaign spend / reach), creators (revenue-share), platform (monetization)
- **Dependencies**: ADS-004 (`ad_serving.serve_ad`), ADS-007 (`ad_billing` charge + credit), ADS-002 (approved creatives), `ad_fraud_prevention`, `ad_analytics_rollups`
- **Cross-references**: [[ADS-006]] (broadcast ad-breaks, the upstream stub), [[ADS-004]] (serving engine), [[ADS-007]] (billing), [[SECOPS-007]] (same code path in dev/prod; `BROADCAST_ADS_BILLING_ENABLED` flag guards billing writes)

## 2. Current-State Investigation (what exists today)

### 2.1 `app/services/broadcast_ads.py` — What Is Implemented

**`is_ad_free(viewer_id, creator_id)`** (`broadcast_ads.py:36–49`): Correctly returns `True` for the broadcaster themselves and for viewers with an active subscription via `has_active_subscription` (from `app/services/subscription_access`). The subscription check is production-ready.

**`serve_broadcast_ad(...)`** (`broadcast_ads.py:55–83`): The stub. Lines 66–83 return a hardcoded `bcast_house_{slot_type}` creative with a mock video URL `/mock/s3/ad-creatives/{creative_id}.mp4`. The comment at lines 5–6 explicitly acknowledges this: "ADS-004 (ad serving engine) and ADS-002 (video creatives) are not yet implemented. [...] When ADS-004 lands this function should delegate to `app.services.ad_serving.serve_ad`." ADS-004 now exists (`app/services/ad_serving.py` is fully implemented).

**`build_pre_roll(session, viewer_id)`** (`broadcast_ads.py:86–121`): Calls `serve_broadcast_ad` and constructs the pre-roll payload with impression/click/skip tracking URLs. This function is correct and will work unchanged once `serve_broadcast_ad` is wired.

**`start_ad_break(session)`** (`broadcast_ads.py:127–152`): Updates `broadcast_sessions` table fields (`ad_break_active=True`, `ad_break_started_at`, `total_ad_breaks`+1) and publishes `ad_break:start` SSE event. Correct and complete.

**`end_ad_break(session_id)`** (`broadcast_ads.py:155–161`): Clears `ad_break_active`, publishes `ad_break:end`. Idempotent.

**`record_ad_event(...)`** (`broadcast_ads.py:185–216`): Writes to `T.broadcast_ad_events` only. No writes to `T.ad_impressions`, no call to `ad_billing` charge functions, no fraud check, no analytics rollup update. This is the primary integration gap.

### 2.2 `app/services/ad_serving.py` — The Real Engine

`serve_ad(surface, content_type, creator_id, content_id, slot_type, user_id, user_context)` (`ad_serving.py:45–`) performs full campaign eligibility evaluation, targeting, frequency capping, budget pacing, and returns the winning creative with tracking URLs. This is production-ready code that broadcast ads should delegate to.

The `HOUSE_AD` constant at `ad_serving.py:30` is a fallback when no eligible paid campaign fills the slot. This is what `serve_broadcast_ad` should fall back to when `serve_ad` returns `is_house_ad=True` or `filled=False`.

### 2.3 Frontend: `LivePlayer.tsx` — Ad Overlay Race Condition

**`adJoinMutation`** (`LivePlayer.tsx:115–129`): Calls `adJoin(sessionId)` on success, sets `preRoll` state if `data.pre_roll` is present. The trigger is `useEffect(() => { adJoinMutation.mutate(); }, [session])` at line 138–142.

**The race**: `sessionMutation` and `adJoinMutation` are triggered by different `useEffect` hooks — `sessionMutation` on `[sessionId, isAuthenticated]` (line 133–136), `adJoinMutation` on `[session]` (line 138–142). The `adJoinMutation` fires when `session` becomes non-null after `sessionMutation` succeeds. This dependency chain is correct.

**The overlay render** (`LivePlayer.tsx:232–253`):
```tsx
{preRoll && !preRollDone && (
  <AdOverlay
    ad={preRoll}
    skipAfterSeconds={preRoll.skip_after_seconds}
    onImpression={...}
    onSkip={...}
    onComplete={...}
    onClick={...}
  />
)}
```

The pre-roll overlay renders when `preRoll` is non-null and `preRollDone` is false. The E2E test `369.1` navigates `bobPage` to the broadcast URL and expects `[data-testid="broadcast-ad-overlay"]` to be visible.

**The failing test cause**: The test creates a session and navigates immediately to the broadcast URL. At the time of navigation, the session may not have `pre_roll_enabled=true` persisted if the broadcast session is fetched from DDB before the `PATCH /ad-config` is applied. Review of the test setup at `ads-broadcast.spec.ts:510–517`:
```
const sid = await createSession(rootPage, { pre_roll_enabled: true });
await bobPage.goto(`/broadcast/live/${sid}`);
await expect(bobPage.locator('[data-testid="broadcast-ad-overlay"]')).toBeVisible({ timeout: 15000 });
```
The `createSession` helper includes `pre_roll_enabled: true` in the session creation body. If `broadcast_sessions` DDB item is written with `pre_roll_enabled=true` at creation time, the ad-join should return a pre-roll. The overlay should then render.

The actual failure mode is likely the `adJoinMutation` not firing because `session` is never set — `sessionMutation` (the playback URL fetch) may fail with an auth error for `bobPage` (a non-subscriber viewer). If `sessionMutation` fails, `setPlayerError` is called and the component renders the error state, never triggering `adJoinMutation`. The pre-roll overlay is never mounted.

The fix: `adJoinMutation` should be triggered by `sessionId` directly (not gated on `session` being set), so ad-join fires independently of playback URL resolution. This decouples the ad experience from the playback auth check.

## 3. Gap / Threat Analysis

### 3.1 Revenue Leakage

Every broadcast impression since ADS-006 shipped has generated zero advertiser spend. With broadcast as a significant viewer surface, this represents ongoing revenue leakage. The integration to `ad_billing` is the highest-priority change.

### 3.2 Billing Safety on Integration

When `record_ad_event` is wired to call `ad_billing.charge_advertiser_impression(campaign_id, creative_id, ...)`, a failure in the billing call must not break playback tracking. The existing `try/except Exception: pass` pattern in `record_ad_event` (line 214) means billing failures are silently swallowed. This is the right behavior for UX (tracking must never block playback) but creates an audit gap: failed billing calls are invisible. The fix should log billing failures with `logger.warning(...)` and increment a `broadcast_ad_billing_failure_total` counter.

### 3.3 Frequency Capping for Broadcast Surface

`ad_serving.serve_ad()` enforces frequency caps via `_check_frequency_cap`. Broadcast pre-roll is a high-frequency context — a viewer who joins and leaves repeatedly could rapidly accumulate impression counts. The frequency cap windows (`1h: 3`, `24h: 10`) apply to the viewer's count across all surfaces. Broadcasting must use the same `user_id` as VOD ads so frequency counts are shared across surfaces.

### 3.4 House Creative Fallback

When `serve_ad()` returns `is_house_ad=True` (no eligible paid ad), `serve_broadcast_ad` should serve the house creative without billing. The `record_ad_event` call should check whether the creative is a house ad and skip the billing path. A `is_house_ad: bool` flag on the return from `serve_ad` already exists (via `_house_ad_response` returning `is_house_ad=True`).

### 3.5 Subscriber Ad-Free — No Billing Risk

`is_ad_free` returning `True` prevents `build_pre_roll` from calling `serve_broadcast_ad` at all (`broadcast_ads.py:92–93`). Subscribers never reach the billing path. This is correct.

## 4. Proposed Design / Fix

### 4.1 `serve_broadcast_ad` — Delegate to Real Engine

Replace lines 66–83 of `broadcast_ads.py`:
```python
def serve_broadcast_ad(*, surface, creator_id, content_id, slot_type, user_id) -> Dict[str, Any]:
    from app.services.ad_serving import serve_ad, HOUSE_AD
    try:
        result = serve_ad(
            surface=surface,
            content_type="broadcast",
            creator_id=creator_id,
            content_id=content_id,
            slot_type=slot_type,
            user_id=user_id,
        )
        if result.get("is_house_ad") or not result.get("filled"):
            return {**result, "is_paid": False}
        return {**result, "is_paid": True}
    except Exception:
        logger.warning("ad_serving unavailable, falling back to house creative")
        return {
            "filled": True,
            "is_paid": False,
            "is_house_ad": True,
            "creative_id": f"bcast_house_{slot_type}",
            "format": "video",
            "video_url": f"/mock/s3/ad-creatives/bcast_house_{slot_type}.mp4",
            "image_url": None,
            "cta_url": None,
            "impression_url": f"/broadcast/sessions/{content_id}/ads/bcast_house_{slot_type}/track?event=impression",
            "click_url": f"/broadcast/sessions/{content_id}/ads/bcast_house_{slot_type}/track?event=click",
            "skip_url": f"/broadcast/sessions/{content_id}/ads/bcast_house_{slot_type}/track?event=skip",
        }
```

### 4.2 `record_ad_event` — Wire Billing, Fraud, Analytics

After writing to `T.broadcast_ad_events` (keep for broadcast-specific audit), add:
```python
from app.core.settings import S

if event_type == "impression" and S.broadcast_ads_billing_enabled:
    from app.services.ad_billing import charge_ad_event
    from app.services.ad_fraud_prevention import check_impression_fraud
    from app.services.ad_analytics import record_impression_event
    try:
        if not is_house_ad:  # only bill real paid ads
            fraud_ok = check_impression_fraud(user_id=user_id, creative_id=creative_id, session_id=session_id)
            if fraud_ok:
                charge_ad_event(creative_id=creative_id, slot_type=slot_type,
                                surface=f"broadcast_{slot_type}", viewer_id=user_id)
        record_impression_event(creative_id=creative_id, surface=f"broadcast_{slot_type}",
                                viewer_id=user_id, is_paid=not is_house_ad)
    except Exception as exc:
        logger.warning("broadcast_ad billing/analytics error: %s", exc)
        # Never break tracking
```

### 4.3 Feature Flag

Add to `app/core/settings.py`:
```python
broadcast_ads_billing_enabled: bool = bool(os.environ.get("BROADCAST_ADS_BILLING_ENABLED", "1") == "1")
```

Add `BROADCAST_ADS_BILLING_ENABLED=1` to `.env.local.example`. In dev this enables the billing path against DDB Local (moto). In prod it uses real DynamoDB. Same code path, same `T.*` handles — SECOPS-007 compliant.

### 4.4 LivePlayer.tsx Fix

Change the `adJoinMutation` effect trigger from `[session]` to `[sessionId, isAuthenticated]` (same as `sessionMutation`):
```tsx
useEffect(() => {
  if (!sessionId || !isAuthenticated) return;
  adJoinMutation.mutate();
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [sessionId, isAuthenticated]);
```

This fires ad-join as soon as the session ID is known, independent of whether the playback URL resolved successfully. The pre-roll overlay will mount regardless of playback auth errors.

### 4.5 Dev/Prod Parity (SECOPS-007)

- `serve_ad()` is already env-agnostic (DDB via `T.*`)
- `ad_billing` charge functions use `T.ad_billing` handle
- `ad_fraud_prevention` uses DDB Local in dev
- `BROADCAST_ADS_BILLING_ENABLED` flag: default `1` (enabled) — safe because billing writes use moto in dev (`@mock_dynamodb` in tests), not real AWS
- No outbound calls anywhere in this path
