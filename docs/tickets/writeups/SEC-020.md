# SEC-020: Browser-SSH / SFTP Destination SSRF (Default Allow-All → Metadata/Pivot) — Investigation & Implementation Write-up

> ~5 pages. Real code read, citations at `file:line`.

## 1. Summary & Classification

The browser-based SSH terminal and SFTP file-manager mount allow authenticated users to dial an arbitrary `host:port` of their choosing. Both the SSH destination policy (`app/routers/browser_ssh_terminal.py:408–488`) and the SFTP destination policy (`app/services/sftp_destination_policy.py:16`) default to `allow_all` when no explicit configuration is present — and the shipped defaults include no allowlist, no denylist, and no hardcoded protection against cloud instance-metadata endpoints, loopback, or RFC-1918 addresses. Any authenticated user can point the terminal at `169.254.169.254:80` (AWS instance metadata), `127.0.0.1:<port>` (services listening on loopback), or any internal host reachable from the backend process, effectively making the backend a general-purpose SSRF proxy. In a cloud deployment, the metadata endpoint returns IAM role credentials, enabling privilege escalation to any AWS resource the instance role can access.

- **Type**: security-fix (Critical SSRF)
- **Priority**: Critical
- **Status**: Open
- **Area**: `app/routers/browser_ssh_terminal.py`, `app/services/sftp_destination_policy.py`, `app/services/sftp_mounts.py`, `app/services/sftp_client.py`
- **Affected users**: all authenticated users (attacker only needs a valid session)
- **Attacker class**: 🌐 any-user with a valid session
- **Cross-references**: SEC-001 (SSRF), SECOPS-007 (dev/prod parity — denylist must fire in both)

## 2. Current-State Investigation (What Exists Today)

### 2.1 SSH terminal destination policy

`app/routers/browser_ssh_terminal.py:452–488` (`_enforce_destination_policy`):

```python
def _enforce_destination_policy(connect_info: dict[str, Any]) -> dict[str, Any] | None:
    host = str(connect_info.get("host") or "").strip().lower()
    port = int(connect_info.get("port") or 0)

    denied_hosts = _policy_hosts_denied()      # reads BROWSER_SSH_DENIED_HOSTS env var
    if any(_host_matches(pattern, host) for pattern in denied_hosts):
        return _error_payload(...)             # blocked

    allowed_hosts = _policy_hosts_allowed()    # reads BROWSER_SSH_ALLOWED_HOSTS env var
    if allowed_hosts and not any(_host_matches(pattern, host) for pattern in allowed_hosts):
        return _error_payload(...)             # not in allowlist

    # ... similar port checks ...
    return None                                # ← ALLOW
```

`_policy_hosts_denied()` at line 415: reads `BROWSER_SSH_DENIED_HOSTS` env var. Defaults to empty string via `getattr(S, "browser_ssh_denied_hosts", "")` — resulting in `_csv_items("")` returning `[]`. **An empty denied list means nothing is denied.**

`_policy_hosts_allowed()` at line 408: reads `BROWSER_SSH_ALLOWED_HOSTS` env var. Defaults to `""` → `[]`. The check at line 464–470 is `if allowed_hosts and not any(...)` — **if `allowed_hosts` is empty, the condition short-circuits to False and no allowlist check is performed.** Everything is allowed.

Therefore, in a default deployment with no environment variables set, `_enforce_destination_policy` always returns `None` (allow). The WebSocket handler at line 868 calls `_enforce_destination_policy(normalized)` and only blocks if the return is non-None.

The default mode is `"allow_all"` and the function returns immediately. There is no hardcoded denylist that would fire regardless of mode.

### 2.3 Call sites

- `app/services/sftp_mounts.py:192`: `enforce_sftp_destination_policy(host=mount.host, ...)` on mount creation.
- `app/services/sftp_mounts.py:284`: same on mount update.
- `app/services/sftp_client.py:470`: `enforce_sftp_destination_policy(host=cfg.host, ...)` on actual SFTP connection.

### 2.4 No hostname resolution / DNS-rebinding safety

`_host_matches` at line 395 performs a **string** comparison only:
```python
def _host_matches(pattern: str, host: str) -> bool:
    ...
    return h == p  # or startswith check for wildcard
```

There is no DNS lookup of `host`. An attacker can register `attacker.com` → points to `169.254.169.254` and the string-based check would not catch it even if `169.254.169.254` were in a denylist.

Similarly, `app/services/sftp_destination_policy.py:27–54` (`_host_matches_rule`) does parse IP addresses and CIDR ranges correctly (using `ipaddress.ip_address` and `ip_network`), but this only helps for literal IP addresses in the SFTP host field. A hostname `metadata.internal` resolving to `169.254.169.254` would not be caught.

### 2.5 Dev vs prod behavior

In dev mode the backend runs on a developer workstation inside a VPN/firewall. The practical risk of hitting `169.254.169.254` is lower (no cloud metadata endpoint), but an attacker could still probe `127.0.0.1:8001` (DynamoDB Local), `127.0.0.1:4566` (moto), `127.0.0.1:7999` (KMS mock), or `127.0.0.1:12111` (Stripe mock) — all running on loopback with no authentication. This means the SSRF is exploitable in development too, allowing an authenticated test user to interact with the raw DynamoDB Local HTTP API.

## 3. Gap / Threat Analysis

### 3.1 Cloud metadata credential theft

**Preconditions**: backend is deployed on an EC2/ECS/GKE instance with an IAM role; any authenticated user account.

**SSH path**:
1. Attacker opens the browser SSH terminal UI at `/remote/ssh`.
2. WebSocket `connect` message: `{"type": "connect", "payload": {"host": "169.254.169.254", "port": 80, "username": "x", "authType": "password", "password": "x"}}`.
3. `_enforce_destination_policy` returns `None` (allow all).
4. `ParamikoSshBridge.connect()` at line 111–146 calls `client.connect(hostname="169.254.169.254", port=80, ...)`.
5. Paramiko fails to SSH-handshake (HTTP endpoint, not SSH), but the TCP connection reaches `169.254.169.254:80`. With a crafted HTTP payload in the "username" or by switching to a different attack surface:
   - An attacker using a raw WebSocket could potentially send HTTP GET requests formatted as SSH auth data; or
   - Target `169.254.169.254:80` with a mock HTTP server on attacker-controlled infra that responds with valid SSH and then relays requests.
6. More directly: SFTP path allows mounting a `host=169.254.169.254` destination.

**SFTP path (more direct)**:
1. Attacker calls `POST /ui/fs/mounts` with `{"host": "169.254.169.254", "port": 22, "path": "/", ...}`.
2. `enforce_sftp_destination_policy` returns immediately (allow_all).
3. When the mount is first accessed, `sftp_client.py:470` calls `enforce_sftp_destination_policy` again → still allow_all.
4. The SFTP client opens a TCP connection to `169.254.169.254:22`.

The metadata endpoint also responds to `http://169.254.169.254/latest/meta-data/iam/security-credentials/<role-name>` with JSON containing `AccessKeyId`, `SecretAccessKey`, and `Token` — granting full IAM role access to whoever can exfiltrate the response.

### 3.2 Internal service pivot

Even without cloud metadata, the attacker can probe `127.0.0.1:<port>` to interact with:
- DynamoDB Local (`:8001`) — raw HTTP API, unauthenticated
- moto S3 (`:4566`) — unauthenticated S3 API
- Mock KMS (`:7999`)
- Stripe mock (`:12111`)

In production, the equivalent would be internal databases, Redis, the Kubernetes API server, or other microservices that trust connections from the backend's IP.

### 3.3 DNS rebinding

Even if `169.254.169.254` were in a string denylist, an attacker controlling `evil.attacker.com` can:
1. Present a short-TTL DNS response pointing to an attacker-controlled IP during the policy check.
2. After the check passes, respond with `169.254.169.254` for the actual TCP dial.

This bypasses hostname-string denylists entirely. The only safe defence is to resolve the hostname and check the resolved IP.

### 3.4 Blast radius

Full IAM credential exfiltration → unrestricted AWS access. In a multi-tenant deployment, cross-tenant data access, DynamoDB table dumps, S3 bucket enumeration, Cognito user pool access.

## 4. Proposed Design / Fix

### 4.1 Hardcoded unconditional denylist

Add a new module `app/services/ssrf_guard.py`:

```python
import ipaddress
import socket
from typing import Tuple

_DENIED_NETWORKS = [
    ipaddress.ip_network("169.254.0.0/16"),   # link-local / AWS metadata
    ipaddress.ip_network("127.0.0.0/8"),       # loopback
    ipaddress.ip_network("10.0.0.0/8"),        # RFC-1918
    ipaddress.ip_network("172.16.0.0/12"),     # RFC-1918
    ipaddress.ip_network("192.168.0.0/16"),    # RFC-1918
    ipaddress.ip_network("::1/128"),           # IPv6 loopback
    ipaddress.ip_network("fc00::/7"),          # IPv6 unique-local
    ipaddress.ip_network("fe80::/10"),         # IPv6 link-local
    ipaddress.ip_network("0.0.0.0/8"),         # IANA "this network"
    ipaddress.ip_network("100.64.0.0/10"),     # CGNAT
    ipaddress.ip_network("192.0.2.0/24"),      # TEST-NET-1
    ipaddress.ip_network("198.51.100.0/24"),   # TEST-NET-2
    ipaddress.ip_network("203.0.113.0/24"),    # TEST-NET-3
]

_DENIED_HOSTNAMES = {"metadata.google.internal", "metadata.internal"}

_ALLOWED_PORTS = {22, 2222}   # SSH standard ports; expand per allowlist

def resolve_and_check(host: str, port: int) -> Tuple[str, None]:
    """
    Resolve `host` to an IP and verify it is not in the hardcoded denylist.
    Returns the resolved IP string if safe.
    Raises ValueError with a descriptive message if denied.
    """
    h = (host or "").strip().lower()
    if h in _DENIED_HOSTNAMES:
        raise ValueError(f"Destination host is blocked: {h}")
    try:
        # Resolve: getaddrinfo returns all IPs; check all of them
        results = socket.getaddrinfo(h, port, proto=socket.IPPROTO_TCP)
    except socket.gaierror as exc:
        raise ValueError(f"DNS resolution failed: {exc}") from exc
    for _family, _type, _proto, _canonname, sockaddr in results:
        ip_str = sockaddr[0]
        try:
            ip_obj = ipaddress.ip_address(ip_str)
        except ValueError:
            continue
        for net in _DENIED_NETWORKS:
            if ip_obj in net:
                raise ValueError(
                    f"Destination IP {ip_obj} is in blocked range {net} "
                    f"(resolved from {h})"
                )
    # Return the first resolved IP for logging
    return socket.getaddrinfo(h, port, proto=socket.IPPROTO_TCP)[0][4][0]
```

### 4.2 Integrate into SSH terminal policy

In `app/routers/browser_ssh_terminal.py:452–488`, replace the hostname-string matching with a call to `resolve_and_check` before the existing allowlist/denylist checks. The function should be called with the user-supplied host and the resolved IP placed in the audit log:

```python
from app.services.ssrf_guard import resolve_and_check

def _enforce_destination_policy(connect_info: dict[str, Any]) -> dict[str, Any] | None:
    host = str(connect_info.get("host") or "").strip().lower()
    port = int(connect_info.get("port") or 0)

    # Unconditional denylist — runs regardless of config
    try:
        resolved_ip = resolve_and_check(host, port)
    except ValueError as exc:
        return _error_payload(
            code="policy_denied_host",
            message=f"Connection denied by destination policy: {exc}",
            request_type="connect",
        )

    # Existing config-based checks follow ...
    denied_hosts = _policy_hosts_denied()
    ...
```

### 4.3 Integrate into SFTP destination policy

In `app/services/sftp_destination_policy.py:84–97`, add the unconditional check before the mode branch:

```python
from app.services.ssrf_guard import resolve_and_check

def enforce_sftp_destination_policy(*, host, owner, mount_id, stage) -> None:
    # Unconditional SSRF guard — fires regardless of policy mode
    try:
        resolve_and_check(host, port=22)
    except ValueError as exc:
        _deny(owner=owner, mount_id=mount_id, host=host, stage=stage, mode="ssrf_guard")

    mode = _mode()
    if mode == "allow_all":
        return
    ...
```

The `port` parameter to `resolve_and_check` for SFTP mounts should come from the mount configuration. Extend the `enforce_sftp_destination_policy` signature to accept `port: int = 22`.

### 4.4 Change default policy from `allow_all` to `deny_all`

In `app/services/sftp_destination_policy.py:16` and `app/core/settings.py:993`, change the default:

```python
# settings.py
filemgr_sftp_destination_policy_mode: str = os.environ.get("FILEMGR_SFTP_DESTINATION_POLICY_MODE", "deny_all")
```

Similarly for SSH: when `BROWSER_SSH_ALLOWED_HOSTS` is not set, default to allowing only well-known cloud provider SSH endpoints (operator configured) — or require explicit opt-in to `allow_all`:

```python
# app/routers/browser_ssh_terminal.py
def _policy_mode_default() -> str:
    return os.environ.get("BROWSER_SSH_POLICY_MODE", "allowlist")
```

If `policy_mode == "allowlist"` and `allowed_hosts == []`, deny all. This is a breaking change — document in the `.env.local.example` with `BROWSER_SSH_POLICY_MODE=allow_all` to maintain dev-stack behavior.

### 4.5 Dev/Prod parity (SECOPS-007)

`resolve_and_check` uses `socket.getaddrinfo` which resolves via the system DNS. In dev mode, `127.0.0.1` is in the loopback denylist and will be blocked — this is intentional. The dev `.env.local.example` should set `BROWSER_SSH_POLICY_MODE=allow_all` and `FILEMGR_SFTP_DESTINATION_POLICY_MODE=allow_all` so that developers using the feature to connect to local test VMs can still do so, but the unconditional SSRF guard in `resolve_and_check` still blocks cloud-metadata ranges. Alternatively, add a `SSRF_GUARD_DISABLE=1` flag gated on `S.dev_mode` that bypasses the guard entirely in local dev (with a loud warning log).

### 4.6 Rate-limit and alerting

Add `audit_event("ssrf_blocked", user_sub, ...)` when the SSRF guard fires, feeding the SECOPS-001 alerting pipeline. Track denied connection attempts per user per hour; alert on ≥ 3 blocked attempts.

### 4.7 Alternatives considered

- **Allowlist-only, no resolve**: faster but vulnerable to DNS rebinding.
- **Firewall/iptables rules at host level**: correct defense-in-depth but does not address audit/alerting and can be bypassed via IPv6 if iptables rules are v4-only.
- **Dedicated egress proxy**: correct for production but out of scope for this fix; compatible with this change.

### Rollout plan

1. Deploy `app/services/ssrf_guard.py` with the hardcoded denylist — no behavior change yet (nothing calls it).
2. Integrate into `sftp_destination_policy.py` (§4.3) — SFTP is lower-volume.
3. Integrate into `browser_ssh_terminal.py` (§4.2) — SSH terminal.
4. Change SFTP default to `deny_all` (§4.4) — breaking change; document in upgrade notes.
5. Change SSH default similarly.

### Risks & open questions

- `socket.getaddrinfo` is blocking I/O; in the async FastAPI event loop it should be wrapped in `asyncio.get_event_loop().run_in_executor(None, ...)` for the SSH WebSocket path to avoid blocking the event loop.
- IPv6 metadata address for Azure is `fd00::ec2` — add to `_DENIED_NETWORKS` once IPv6 deployment scope is confirmed.
- GCP metadata endpoint is `metadata.google.internal` / `169.254.169.254` — already covered.
- Operators running legitimate internal SSH gateways on RFC-1918 must explicitly set `BROWSER_SSH_ALLOWED_HOSTS` and will be blocked by the default-deny change; document in migration guide.

**Effort**: M (new SSRF guard module is ~50 lines; integration into two policy files is straightforward; default-policy change requires documentation and config template updates; async-wrapping the DNS call adds modest complexity).
