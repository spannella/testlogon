## What is NOT built (gaps from ticket spec)

### Gap 1: W-9/TIN collection form — MISSING (HIGH)
The ticket requires a W-9-equivalent form where creators submit `legal_name`, `tin` (SSN/EIN), `tax_classification`, address, and `certified_signature`. None of this exists:
- No `submit_tax_info()` service function.
- No `get_tax_info()` / masked TIN display.
- No `POST /ui/tax/w9` endpoint.
- No `GET /ui/tax/info` endpoint.
- No `TaxInfoPage.tsx` frontend component.
- No `W9SubmissionIn`, `TaxInfoOut`, `TaxInfoAdminOut` Pydantic models.

### Gap 2: KMS-encrypted TIN storage — MISSING (CRIT for compliance)
The ticket requires TINs to be encrypted via `app/core/crypto.kms_encrypt` before storage. The existing 1099 service uses a hardcoded placeholder `_PAYER_TIN_LAST4 = "0000"` (`app/services/tax_form_1099.py:55`) and never stores a recipient TIN. Without TIN collection, 1099 PDFs cannot include the payee's TIN, making them non-compliant with IRS 1099-NEC requirements.
- `app/core/crypto.py:16` provides `kms_encrypt`/`kms_decrypt` but they are not called from the tax service.

### Gap 3: Admin TIN reveal endpoint — MISSING (HIGH)
- No `GET /ui/admin/tax/info/{user_id}` endpoint that decrypts and returns full TIN.
- No `TaxInfoAdminOut` model with `tin_full` field.
- No IP-address-logged audit trail for TIN decryption events.

### Gap 4: Admin tax submissions list — MISSING (MED)
- No `GET /ui/admin/tax/submissions` endpoint.
- No `ByTaxStatus` GSI on the billing table.
- No `TaxSubmissionListOut` model.

### Gap 5: Tax audit log — PARTIAL (MED)
- The admin generate/correct endpoints call `audit_event` from `app/services/alerts` but this is a generic alert mechanism, not a dedicated `TAX_AUDIT` table with `tin_viewed`/`1099_generated`/`tax_info_updated` action codes and IP address tracking per the ticket's `TaxAuditEntryOut` spec.

## SEC-004 cross-reference
TIN decryption is a high-privilege money-path operation. Every `kms_decrypt` call on a TIN must be audit-logged with actor user ID, target user ID, IP address, and timestamp. The admin TIN reveal endpoint must use `require_admin_session` (role >= ADMIN). Unmasked TINs must never appear in API responses to non-admin callers; responses must always return `tin_masked` only.

## SECOPS-007 parity
- TIN stored as KMS ciphertext; last 4 digits stored plaintext for display only.
- All TIN decrypt events logged to `TAX_AUDIT` table with IP address.
- Admin batch 1099 generation decrypts TINs inline — each decryption event logged.
- TIN fields use `type="password"` inputs and are never cached.
