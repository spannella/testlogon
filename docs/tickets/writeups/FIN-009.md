## What is NOT built (gaps from ticket spec)

### Gap 1: Payout methods CRUD — MISSING (HIGH)
- No `list_payout_methods()`, `add_payout_method()`, `update_payout_method()`, `delete_payout_method()`, `set_default_payout_method()` in `app/services/creator_payouts.py`.
- No `GET /ui/payouts/methods`, `POST /ui/payouts/methods`, `PUT /ui/payouts/methods/{id}`, `DELETE /ui/payouts/methods/{id}`, `POST /ui/payouts/methods/{id}/default` endpoints.
- No `PayoutMethodIn`, `PayoutMethodOut`, `PayoutMethodListOut` models in `app/models.py`.
- No payout methods tab in `PayoutDashboard.tsx`.
- Without payout methods, the request payout dialog uses a hardcoded `"bank_transfer"` string; creators cannot configure real bank/PayPal destinations.

### Gap 2: Payout schedule endpoint and display — MISSING (MED)
- No `get_payout_schedule()` in `app/services/creator_payouts.py`.
- No `GET /ui/payouts/schedule` endpoint.
- No `PayoutScheduleOut` model.
- No schedule card in `PayoutDashboard.tsx`.

### Gap 3: Payout detail endpoint — MISSING (LOW)
- No `GET /ui/payouts/{id}` individual payout detail endpoint.
- No `PayoutDetailOut` model.
- Clicking a payout row shows nothing.

### Gap 4: Admin queue tab — MISSING (HIGH)
- Admin endpoints exist in `app/routers/admin_payouts.py` but `PayoutDashboard.tsx` has no "Admin Queue" tab visible to root/admin users.
- No approve/reject buttons in the UI.
- No reject reason dialog.

### Gap 5: Batch-complete endpoint and UI button — MISSING (MED)
- No `batch_complete_payouts()` in `app/services/creator_payouts.py`.
- No `POST /v1/admin/payouts/batch-complete` endpoint in `app/routers/admin_payouts.py`.
- No `BatchCompleteOut` model.
- No "Process All Approved" button in the frontend.

### Gap 6: payout_dashboard_enabled feature flag — MISSING (LOW)
- `app/core/settings.py:1176-1177` has `payout_hold_period_seconds` and `payout_minimum_cents` but no `payout_dashboard_enabled` flag mentioned in the rollout plan.

## SEC-004 cross-reference
- `batch_complete_payouts` changes multiple payout records to "completed" — must validate `status == "approved"` before completing; must not process "requested" payouts directly.
- Payout method bank account numbers: only last 4 digits stored; full routing/account numbers must never be persisted (PII).
- The `delete_payout_method` function must prevent deleting the sole remaining method if it is the current default; add a service-level guard.
