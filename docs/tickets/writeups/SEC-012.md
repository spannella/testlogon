# SEC-012: Media Pipeline SSRF / Local-File-Read (ffmpeg, watermark, subtitles) — Investigation & Implementation Write-up

> ~5 pages. Read the real code before writing; cite `file:line`. Be concrete, not generic.

## 1. Summary & Classification

The video transcoding pipeline exposes three distinct server-side request forgery (SSRF) / local-file-read (LFR) attack surfaces, plus a weak VTT sanitizer that may allow Cross-Site Scripting (XSS) in subtitle-capable players. All four issues stem from user-controlled data reaching subprocess or HTTP-fetch code without adequate restriction.

1. **ffmpeg ABR pipeline — no `-protocol_whitelist`** (`app/services/ffmpeg_abr_pipeline.py:75`): the primary ffmpeg invocation passes `input_url` directly as the `-i` argument with no protocol restriction. A mis-validated or attacker-controlled `input_url` can reference `file://etc/passwd`, `http://169.254.169.254/latest/meta-data/` (cloud metadata), or chained protocols like `concat:` / `subfile:`.
2. **Concat demuxer — `-safe 0`** (`app/services/video_concatenator.py:338`): the filelist-based concat demuxer runs with `-safe 0`, which tells ffmpeg to accept any file path in the concat list—including `file://` URIs or absolute paths outside the scratch directory.
3. **Watermark asset download — arbitrary HTTP(S) and `file://`** (`app/services/ffmpeg_watermark_lifecycle.py:51–58`): the watermark asset-preparation function explicitly branches on `file://` (copies the path) and `http(s)://` (fetches via `urllib.request.urlretrieve`) with no domain restriction and no SSRF guard, allowing a watermark policy URI of `http://169.254.169.254/latest/meta-data/iam/security-credentials/...` to exfiltrate cloud credentials.
4. **VTT subtitle sanitizer — regex denylist** (`app/services/vod_subtitle_manager.py:123–138`): the sanitizer strips a blocklist of dangerous HTML tags and event attributes but leaves through WebVTT-specific tags `<c>`, `<ruby>`, `<b>`, `<i>`, `<u>` with arbitrary attributes, which Chromium's VTT parser and some DASH/HLS players can render as styled HTML—enabling XSS.

- **Type**: security-fix (SSRF, LFR, XSS)
- **Severity**: High (SSRF to cloud metadata / credentials); Medium (LFR, XSS)
- **Status**: Open
- **Area**: `app/services/ffmpeg_abr_pipeline.py`, `app/services/video_concatenator.py`, `app/services/ffmpeg_watermark_lifecycle.py`, `app/services/vod_subtitle_manager.py`
- **Attacker class**: 🌐 authenticated content uploader / creator (must own a video asset to trigger transcoding); ⚙️ operator misconfiguration for watermark URI
- **Dependencies**: SEC-001 (SSRF guard, if it exists); SECOPS-007 (dev/prod parity — all fixes must work with moto/DDB Local, no real AWS)

## 2. Current-State Investigation (what exists today)

### 2.1 ffmpeg ABR pipeline — protocol unrestricted

`app/services/ffmpeg_abr_pipeline.py:71–75`:
```python
ffmpeg_bin = get_ffmpeg_path()
args = [ffmpeg_bin, "-hide_banner", "-loglevel", "warning", "-y",
        "-rw_timeout", "5000000", "-i", input_url]
```

`input_url` comes from whatever the caller passes (typically an S3 presigned URL or a local scratch-dir path). There is no `-protocol_whitelist` flag before `-i`, so ffmpeg accepts all protocols it was compiled with: `file`, `http`, `https`, `rtsp`, `rtmp`, `data`, `concat`, `subfile`, `crypto`, etc. A call with `input_url="file:///etc/passwd"` would read the file into the HLS segment output, which gets uploaded to S3 and is then accessible via the presigned URL.

The watermark input is appended at line 101:
```python
args += ["-i", asset, "-filter_complex", filter_complex, "-map", "[vout]", "-map", "0:a?"]
```
Here `asset` is the result of `_resolve_asset_uri(watermark_policy, tenant_settings)` which returns `policy.asset_uri` directly—an admin-configured string that is not validated against an allowlist before being handed to ffmpeg.

### 2.2 Concat demuxer — `-safe 0` + filelist injection

`app/services/video_concatenator.py:336–343`:
```python
cmd = [
    ffmpeg_bin, "-hide_banner", "-loglevel", "warning", "-y",
    "-f", "concat", "-safe", "0",
    "-i", str(filelist_path),
    ...
]
```

`-safe 0` disables ffmpeg's built-in filelist safety check that would otherwise reject absolute paths and `file://` URIs. The filelist is written from `input_paths` (a list of `Path` objects, line 325–328), but if an attacker can influence the list of source video S3 keys and those keys are not validated as being in the owned output bucket, the resolved `Path` could point outside the scratch directory.

The `create_concat_job` caller at `_run_concat_demuxer` takes `input_paths: List[Path]` — these are local scratch copies of S3-downloaded videos. The actual risk is indirect but real: if the S3 key validation is incomplete or the scratch directory can be escaped via symlinks, the concat job would read arbitrary local files with `-safe 0` enabled.

### 2.3 Watermark download — SSRF via HTTP + local file copy

`app/services/ffmpeg_watermark_lifecycle.py:49–58`:
```python
if asset_uri.startswith("s3://"):
    await _download_from_s3(asset_uri, local_wm_path)
elif asset_uri.startswith("file://"):
    src = Path(asset_uri[7:])  # strip file://
    _copy_local(src, local_wm_path)    # <-- local file read
elif asset_uri.startswith("/"):
    src = Path(asset_uri)
    _copy_local(src, local_wm_path)    # <-- local file read
elif asset_uri.startswith("http://") or asset_uri.startswith("https://"):
    await _download_from_url(asset_uri, local_wm_path)  # <-- SSRF
```

`_download_from_url` (line 126–135) uses `urllib.request.urlretrieve` with no timeout, no redirect limit, no domain allowlist, and no SSRF guard:
```python
urllib.request.urlretrieve(url, str(local_path))
```

Magic byte validation at line 138–175 happens *after* the download, so the attacker receives the HTTP response content regardless of format. A `file://` URI results in `_copy_local` which reads any path the uvicorn process can access (e.g. `/etc/passwd`, the `.env.local` secrets file, DynamoDB Local data files).

The S3 download path at line 100–123 validates bucket+key structure but does not check that the bucket matches the platform's owned bucket name (`S.transcode_output_bucket` etc.), potentially allowing a cross-bucket read if the operator stores assets in multiple buckets.

### 2.4 VTT sanitizer — regex denylist leaves `<c>` and data attributes

`app/services/vod_subtitle_manager.py:123–138`:
```python
_DISALLOWED_TAGS_RE = re.compile(
    r"<\s*/?\s*(script|style|link|meta|object|embed|iframe|applet|form|...)...",
    re.IGNORECASE,
)
_EVENT_ATTRS_RE = re.compile(r"\s+on\w+\s*=", re.IGNORECASE)
_DATA_URI_RE = re.compile(r"data\s*:", re.IGNORECASE)
_JAVASCRIPT_URI_RE = re.compile(r"javascript\s*:", re.IGNORECASE)
```

The allowlist of permitted VTT tags (`<b>`, `<i>`, `<u>`, `<c>`, `<ruby>`, `<rt>`, `<v>`, `<lang>`) is not enforced — only a blocklist of dangerous tags is stripped. `<c>` and `<v>` tags with arbitrary `class=` attributes are passed through. In WebVTT-aware players, `<c.classname>` injects CSS class names. While browsers' VTT parsers don't allow full HTML, attackers can use malformed VTT to escape the cue context in some players. Additionally, the `data:` regex strips `data:` only when preceded by `=`, allowing `<img src=data:...>` to slip through if the `=` is URL-encoded or split with whitespace.

### 2.5 Dev vs prod behavior today

Both dev (moto S3, DDB Local) and prod (real S3, real AWS) share the same ffmpeg invocation and watermark download code paths. In dev mode, `S.dev_mode=True` and `S.s3_endpoint_url` points to moto, but the ffmpeg subprocess and `urllib.request.urlretrieve` still make real filesystem and network calls respectively — the SSRF vulnerability is fully exploitable in both environments.

## 3. Gap / Threat Analysis

### 3.1 Cloud metadata SSRF (critical path)

On AWS EC2/ECS, `http://169.254.169.254/latest/meta-data/iam/security-credentials/` returns the instance's IAM role credentials. The watermark lifecycle `_download_from_url` issues a raw `urllib` request to any `http://` URL. An attacker with access to the "create watermark policy" admin endpoint can set `asset_uri: "http://169.254.169.254/latest/meta-data/iam/security-credentials/default"`, trigger a transcode job, and then retrieve the downloaded watermark bytes (which now contain the JSON credentials) via a subsequent API call to check job status or by arranging for the malformed "watermark" to be used in the ffmpeg pipeline (the magic byte check will throw, but the file is already on disk in the scratch directory and any race-window read could extract it).

### 3.2 Local file read (high severity)

`file://` URI handling in `ffmpeg_watermark_lifecycle.py:52–56` allows the watermark to be any file on the local filesystem readable by the uvicorn process, including `.env.local` (`UI_ACCESS_TOKEN_SECRET`, `API_KEY_PEPPER`, DDB credentials) and DynamoDB Local data files.

`-safe 0` in the concat demuxer, combined with a path-traversal in S3 key naming, could reference files outside the scratch directory.

### 3.3 VTT XSS (medium severity)

The VTT file is served directly to the browser via a presigned S3 URL or `/mock/s3/` path. Chromium's VTT parser does apply a limited sandbox, but `<c>` tag attributes can inject CSS in some player implementations (video.js, shaka-player) that render WebVTT without a strict CSP context.

**Code sites that must change**:
- `app/services/ffmpeg_abr_pipeline.py:75` — add `-protocol_whitelist`
- `app/services/video_concatenator.py:338` — change `-safe 0` to `-safe 1`, validate all paths
- `app/services/ffmpeg_watermark_lifecycle.py:49–58` — remove `file://` and bare-path branches; add domain allowlist + SSRF guard to HTTP fetch
- `app/services/vod_subtitle_manager.py:123–138` — replace denylist with allowlist sanitizer

## 4. Proposed Design / Fix

### 4.1 ffmpeg protocol whitelist

In `build_rendition_ffmpeg_args` (`ffmpeg_abr_pipeline.py:75`), insert the whitelist flag immediately before the input:

```python
FFMPEG_PROTOCOL_WHITELIST = "file,crypto,https,s3"

args = [ffmpeg_bin, "-hide_banner", "-loglevel", "warning", "-y",
        "-rw_timeout", "5000000",
        "-protocol_whitelist", FFMPEG_PROTOCOL_WHITELIST,
        "-i", input_url]
```

- `file` is required for local scratch-dir segment files and keyinfo files.
- `crypto` is required for HLS AES-128 (`hls_key_info_file`).
- `https` is required for S3 presigned HTTPS URLs.
- `http` is intentionally excluded unless a non-TLS S3-compatible endpoint is needed in dev; controlled via `S.ffmpeg_allow_http: bool` (default `False`, set `True` for dev with moto if the S3 endpoint is HTTP).
- `concat`, `subfile`, `data`, `rtsp`, `rtmp`, `ftp`, `gopher` are excluded.

Export the constant so both the ABR pipeline and any future transcode paths use the same value.

### 4.2 Concat demuxer: `-safe 1` + scratch dir validation

In `video_concatenator.py:_run_concat_demuxer`:
1. Change `-safe 0` to `-safe 1`.
2. Before writing the filelist, validate that every `Path` in `input_paths` is strictly under `scratch_dir.resolve()`:
```python
scratch_resolved = scratch_dir.resolve()
for p in input_paths:
    if not str(p.resolve()).startswith(str(scratch_resolved) + "/"):
        raise ConcatError(f"Input path escapes scratch directory: {p}")
```
3. The filelist line format with single-quoted paths is compatible with `-safe 1` when paths are relative or within the allowed directory.

### 4.3 Watermark asset fetch — SSRF guard + domain allowlist

Remove the `file://` and bare-`/` branches entirely from `prepare_watermark_asset`:
- Those branches are only needed if an operator stores a watermark asset as a local file, which is not a supported production pattern. Remove them and document that assets must be in S3.

For `http(s)://` URIs:
1. Parse the URL and check the hostname against `S.watermark_asset_allowed_domains` (a comma-separated setting, empty = only S3 is allowed).
2. Block all RFC-1918/loopback/link-local hostnames (`169.254.*`, `10.*`, `172.16-31.*`, `192.168.*`, `127.*`, `::1`, `fd00::/8`) using the same IP denylist already described in SEC-001.
3. Use `httpx` with `follow_redirects=False`, `timeout=10.0`, and `max_size=S.watermark_asset_max_bytes` (default 5 MB).
4. Validate magic bytes before writing.

For S3 URIs: validate that `bucket` matches one of the platform's configured buckets (`S.transcode_output_bucket`, `S.vod_output_bucket`, `S.media_assets_bucket`).

**Dev/prod parity**: In dev mode (`S.dev_mode=True`) the moto S3 endpoint is already wired via `S.s3_endpoint_url`. The HTTP-fetch path is disabled in dev if `S.watermark_asset_allowed_domains` is empty (the default for `.env.local.example`). No AWS dependency is introduced.

### 4.4 VTT allowlist sanitizer

Replace the denylist in `sanitize_vtt_content` with a strict allowlist parser that:
1. Identifies cue payload lines (lines between timestamp lines and blank lines).
2. Strips all HTML tags except the WebVTT voice span `<v NAME>`, `</v>`, `<b>`, `</b>`, `<i>`, `</i>`, `<u>`, `</u>`, `<ruby>`, `</ruby>`, `<rt>`, `</rt>`. Critically, `<c>` and `<lang>` are stripped (they carry class/attribute vectors and are rarely needed for accessibility).
3. Strips all attributes from permitted tags.
4. Escapes `<` and `>` characters in cue text that are not part of the whitelisted tags.

```python
_VTT_ALLOWED_TAGS_RE = re.compile(
    r"<(/?(b|i|u|ruby|rt|v\s[^>]*?))>",
    re.IGNORECASE,
)

def sanitize_vtt_content(content: str) -> str:
    lines = content.split("\n")
    in_cue = False
    result = []
    for line in lines:
        if _VTT_TIMESTAMP_RE.match(line.strip()):
            in_cue = True
            result.append(line)
        elif in_cue and line.strip() == "":
            in_cue = False
            result.append(line)
        elif in_cue:
            # Strip all tags not in the whitelist
            cleaned = re.sub(r"<[^>]*>", lambda m: m.group(0) if _VTT_ALLOWED_TAGS_RE.fullmatch(m.group(0)) else "", line)
            result.append(cleaned)
        else:
            result.append(line)
    return "\n".join(result)
```

### Manual QA / penetration steps

1. Set a watermark policy with `asset_uri: "http://169.254.169.254/latest/meta-data/"` (or `http://localhost:4566/` in dev); trigger a transcode; confirm job fails with `invalid_watermark_uri` or `blocked_ip`, not with a 500.
2. Build an ffmpeg args list with `input_url="file:///etc/passwd"` and confirm `-protocol_whitelist` causes ffmpeg to exit with an error rather than reading the file.
3. Inspect the generated concat filelist; confirm `-safe 1` is present and a path like `/tmp/../../etc/passwd` is rejected before ffmpeg is invoked.

### Observability

- Log `WARN watermark_uri_blocked reason=ssrf_ip` whenever an HTTP watermark URI is rejected at the IP-blocklist stage — alerts the security team to active probing.
- Add a Prometheus counter `ffmpeg_protocol_rejected_total` (label: `protocol`) where possible (wrap subprocess stderr parsing).

### Rollout & rollback

- No DDB schema changes.
- Rollout: deploy backend only. Existing transcode jobs in flight are not affected since ffmpeg args are built at job execution time.
- Risk: `-safe 1` in concat may break edge-case filelist entries with unusual path characters. Mitigation: the escape logic (`str(p).replace("'", "'\\''")`) already in `video_concatenator.py:327` handles single quotes; validate in staging with a multi-video concat job.
- Rollback: revert the backend service changes; no data migration needed.

### Effort estimate

**M** — four separate service files, each with a focused change. The VTT allowlist rewrite is the most careful part (test coverage needed for malformed cue payloads). Estimated 1–2 days including tests.
