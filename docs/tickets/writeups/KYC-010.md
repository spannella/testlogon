# KYC-010: Passport & National ID Scanner — Investigation & Implementation Write-up

> ~5 pages. Read the real code before writing; cite `file:line`. Be concrete, not generic.

## 1. Summary & Classification

KYC-010 introduces automated MRZ (Machine Readable Zone) parsing for ICAO 9303-format identity documents. It adds a dedicated `kyc_id_scans` DynamoDB table, a `KycIdScannerStore` service with full TD3 (passport) and TD1 (ID card) parsing, ICAO check-digit validation, document expiry checking, and cross-reference of extracted data against the user profile. The scanner is an independent feature — explicitly invoked via a separate router (`/ui/kyc/id-scanner`) and completely decoupled from the existing file attachment flow in `kyc_cases.py`.

- **Type**: Feature — identity document data extraction and validation
- **Priority**: High — eliminates manual admin review of document text; reduces reviewer workload
- **Status**: Implemented. `app/services/kyc_id_scanner.py` (801 lines) and `app/routers/kyc_id_scanner.py` exist. Registered at `app/main.py:574`.
- **Owning area**: KYC / Document verification
- **User persona**: Applicants triggering document scans; KYC reviewers seeing automated extraction results; admins adjudicating flagged scans
- **Cross-references**: KYC-002 (document verification OCR layer that KYC-010 extends), KYC-008 (scanner calls `KycRiskScoringService.compute_score()` after each scan), KYC-013 (user portal integrates scanner UI), KYC-014 (extracted facial photo used by facial comparison)
- **SECOPS-007 parity**: Dev mode uses deterministic mock MRZ strings or caller-supplied MRZ lines. `S.kyc_id_scanner_real_ocr_enabled` (default `false`) gates real OCR. Same code path, provider selected by flag.

## 2. Current-State Investigation (what exists today)

### 2.1 Existing file attachment (the gap this ticket fills)

`app/routers/kyc_cases.py:734` — `attach_kyc_file()` accepts `file_type` ∈ `_KYC_ALLOWED_FILE_TYPES` (line 51) and appends an opaque file record to `case["files"]`. Zero content analysis occurs. `validate_kyc_file_requirements()` at line 791 checks only presence (selfie, id_front, id_back) — not document contents, expiry, or data consistency.

### 2.2 MRZ parsing implementation

`app/services/kyc_id_scanner.py` contains a complete, pure-Python ICAO 9303 MRZ parser:

**`mrz_check_digit()`** (lines 124–137): Implements the ICAO weighted sum algorithm using weights `[7, 3, 1]` repeating. Characters `<` → 0, digits → face value, letters → `ord - ord('A') + 10`.

**`parse_td3_mrz()`** (lines 184–228): Parses two 44-character passport lines:
- Line 1: doc type (2), issuing state (3), names (surname `<<` given_names, rest filler)
- Line 2: document number (9) + check, nationality (3), DOB (YYMMDD) + check, sex, expiry (YYMMDD) + check, optional (14) + check, composite check
- Validates 5 check digits: `document_number`, `date_of_birth`, `expiry_date`, `optional_data`, `composite`

**`parse_td1_mrz()`** (lines 231–274): Parses three 30-character ID card lines:
- Line 1: doc type + issuing state + doc number + check + optional1
- Line 2: DOB + check, sex, expiry + check, nationality, optional2 + composite check
- Line 3: names (surname `<<` given_names)
- Validates 4 check digits

**Key subtlety — expiry date century pivot**: `_mrz_expiry_to_iso()` (lines 159–177) uses a forward-looking pivot: if the 1900s interpretation predates the current year, it rolls to 2000s. This is distinct from `_mrz_date_to_iso()` (lines 145–156) which uses the fixed `00-29 → 2000s, 30-99 → 1900s` pivot for dates of birth. Without this distinction, a passport expiring in 2036 would be parsed as expired in 1936.

### 2.3 Scan pipeline

`KycIdScannerStore.scan_document()` (lines 487–576):
1. Validates document type and file type
2. Loads the KYC case; verifies caller ownership and that case is not finalized
3. Validates MRZ line count (hard error: TD3 needs exactly 2, TD1 exactly 3)
4. Runs extraction via `_run_extraction()` — mock or real per flag
5. Computes expiry status via `check_document_expiry()`
6. Cross-references against user profile/case identity if extraction succeeded
7. Derives scan status: `matched` | `flagged` | `rejected` via `_derive_status()`
8. Writes item to `kyc_id_scans` table
9. Calls `KycRiskScoringService().compute_score()` (lazy import, best-effort)

**Status derivation** (`_derive_status()`, lines 580–599):
- Expired document → `rejected`
- MRZ parse error or failed check digit → `flagged`
- Expiring within 90 days → `flagged`
- Cross-reference match_score < 50 → `flagged`
- Otherwise → `matched`

### 2.4 Cross-reference engine

`cross_reference_profile()` (lines 334–380) compares three fields:
- **Name**: full name exact match scores 1.0; surname-only match (given name differs) scores 0.5
- **DOB**: exact string match scores 1.0
- **Nationality**: case-insensitive 3-letter code comparison

Returns `match_score = round(score / total_fields_checked * 100)`. Missing profile fields are skipped (no penalty for partial profile).

### 2.5 DDB storage

Scans stored in `kyc_id_scans` table (separate from `kyc_cases`). PK=`scan_id`. Two GSIs:
- `ByCase` (PK=`case_id`) — for `list_scans_for_case()`
- `ByStatus` (PK=`status`, SK=`created_at`) — for admin review queue, using `S.kyc_id_scanner_status_index_name`

Settings at `app/core/settings.py` lines 1231–1241: `kyc_id_scanner_status_index_name`, `kyc_id_scanner_bucket`, `kyc_id_scanner_s3_prefix`, `kyc_id_scanner_enabled`, `kyc_id_scanner_real_ocr_enabled`.

### 2.6 Router endpoints

`app/routers/kyc_id_scanner.py` under prefix `/ui/kyc/id-scanner`:
- `POST /cases/{case_id}/scan-document` — user scans a document (owner)
- `GET /cases/{case_id}/scans` — list own scans
- `GET /cases/{case_id}/scans/{scan_id}` — get one (owner, no cross-reference)
- `POST /cases/{case_id}/validate-document` — check side requirements
- `GET /admin/by-status` — admin list by status (ByStatus GSI)
- `GET /admin/scans/{scan_id}` — admin view with cross-reference
- `POST /admin/scans/{scan_id}/adjudicate` — approve/decline a scan

### 2.7 Mock MRZ data

`_MOCK_MRZ` (lines 386–407) provides deterministic valid-checksum MRZ strings for passport and national_id_card/residence_permit. The mock expiry date in the passport mock is `1204159` (line 2, chars 21–27) = `120415` → April 15, 2012. This date is expired relative to today (2026), so the default passport mock scan will produce `status="rejected"`. E2E tests that need a `matched` scan must supply custom MRZ lines with a future expiry.

## 3. Gap / Threat Analysis

### 3.1 Mock expiry problem for default scans

The default passport mock MRZ produces an expired document. Any E2E test that calls `POST scan-document` without supplying `mrz_lines` will get a `"rejected"` scan, not a `"matched"` one. Tests must either:
1. Pass `mrz_lines` with a future-dated expiry (e.g., change line 2 to use expiry `260101` for 2026-01-01 → see `_mrz_expiry_to_iso()` for correct format)
2. Or use a custom utility that generates valid MRZ with check digits for a given future date

This is a significant E2E test authoring complexity. The spec's `Section 187 test 1` ("Scan passport with valid TD3 MRZ returns parsed fields") must supply explicit MRZ lines.

### 3.2 Risk scoring trigger after every scan

`_feed_risk_scoring()` (lines 601–609) calls `KycRiskScoringService().compute_score()` synchronously after every scan. This adds ~500ms to every `POST scan-document` response (per KYC-008 latency targets). In a sequential flow where the user scans front then back of their national ID, the risk engine fires twice. Consider making this async or fire-and-forget with proper error handling.

### 3.3 Case finalization check

`scan_document()` checks `case.get("status") in ("approved", "rejected")` and raises `KycIdScannerStateError("kyc_case_finalized")`. However, the ticket spec says 400 `kyc_case_finalized`. The router must translate this `KycIdScannerStateError` to HTTP 400. Verify this is handled correctly in `kyc_id_scanner_router`.

### 3.4 Cross-reference profile field names

`_load_crosscheck_profile()` (lines 433–454) reads:
- `profile.get("first_name")` / `profile.get("last_name")`
- `profile.get("birthday") or profile.get("date_of_birth")`
- `profile.get("nationality") or profile.get("country")`

The profile service (`app/services/profile.py`) may use different field names (e.g., `display_name` rather than `first_name`/`last_name`). If the profile has only `display_name = "Anna Eriksson"` and no `first_name`/`last_name`, the name comparison produces `extracted_name = "ANNA ERIKSSON"` vs `profile_name = ""` → no name match at all, score 0. This is a data consistency issue that needs alignment between profile storage conventions and the scanner's assumptions.

### 3.5 `ByCase` GSI fallback to scan

`list_scans_for_case()` (lines 615–627) has a fallback `except` that scans the entire table if the `ByCase` GSI query fails. In production, a missing GSI would return all scans for all users — this is a data exposure bug. The fallback should either raise the exception or return an empty list, not scan the entire table.

### 3.6 Image URL in dev mode only

`image_url` is only set when `S.dev_mode` is True (lines 545–548), producing `/mock/s3/{bucket}/{key}` URLs. In production, the image URL would need to be a pre-signed S3 URL with an expiry. This is currently unimplemented for production.

### 3.7 TD1 composite check digit coverage

The TD1 composite check covers `line1[5:30] + line2[0:7] + line2[8:15] + line2[18:29]` (line 258). The ICAO 9303 TD1 spec defines the composite as covering `line1[5:30] + line2[0:7] + line2[8:15] + line2[18:29]`. This matches, but needs a unit test with the canonical ICAO example to confirm correctness.

## 4. Proposed Design / Fix

### 4.1 Fix `ByCase` GSI fallback

Replace the dangerous table-scan fallback:

```python
def list_scans_for_case(self, case_id: str) -> list[dict[str, Any]]:
    try:
        resp = self._table.query(
            IndexName="ByCase",
            KeyConditionExpression=Key("case_id").eq(case_id),
            ScanIndexForward=False,
        )
        return list(resp.get("Items", []))
    except Exception:
        logger.exception("list_scans_for_case GSI query failed case_id=%s", case_id)
        return []  # Safe: return empty list, not all records
```

### 4.2 Fix profile field name alignment

In `_load_crosscheck_profile()`, also try `display_name` as a fallback for the name:

```python
first_name = profile.get("first_name") or ""
last_name = profile.get("last_name") or ""
if not first_name and not last_name:
    # Fall back to splitting display_name
    display = profile.get("display_name", "")
    parts = display.rsplit(" ", 1)
    first_name = parts[0] if len(parts) > 1 else display
    last_name = parts[1] if len(parts) > 1 else ""
out["first_name"] = first_name
out["last_name"] = last_name
```

Alternatively, add a test helper endpoint (dev mode only) that returns a fresh valid MRZ string with a 10-year expiry.

### 4.4 Async risk scoring

Make `_feed_risk_scoring()` non-blocking to avoid adding 500ms to the scan response:

```python
def _feed_risk_scoring(self, *, case_id: str, user_sub: str) -> None:
    import threading
    def _bg():
        try:
            from app.services.kyc_risk_scoring import KycRiskScoringService
            KycRiskScoringService().compute_score(case_id=case_id, user_sub=user_sub, trigger="id_scan")
        except Exception:
            logger.warning("kyc.id_scanner.risk_rescore_failed case_id=%s", case_id)
    threading.Thread(target=_bg, daemon=True).start()
```

This is safe with `--workers 1` (dev). In production with async workers, use `asyncio.create_task()` instead.

### 4.5 Dev/prod parity (SECOPS-007)

| Aspect | Dev | Prod |
|--------|-----|------|
| MRZ extraction | In-process mock or caller-supplied lines | Real OCR provider (AWS Textract or third-party) |
| OCR flag | `KYC_ID_SCANNER_REAL_OCR_ENABLED=false` | `=true` |
| S3 image access | moto in-process, `/mock/s3/` URLs | AWS S3 pre-signed URLs |
| DDB table | Local port 8001 | AWS DynamoDB |
| Risk scoring trigger | Best-effort sync or async | Same (async preferred in prod) |
| `ByStatus` GSI | `kyc_id_scanner_status_index_name` setting | Same setting |

E2E tests supply `mrz_lines` explicitly in the request body, bypassing the real OCR path even when `KYC_ID_SCANNER_REAL_OCR_ENABLED=false`. This ensures both mock and (future) real OCR paths produce the same structural output.

Alert if > 30% of scans return `match_score < 50` in a 24-hour window — this may indicate a profile field name mismatch or systematic data quality issue.

### 5.5 Rollout phases

1. Deploy service and router with `KYC_ID_SCANNER_ENABLED=false` — no user impact
2. Enable on staging; validate TD3 and TD1 parsing with test documents
3. Enable in production informational mode (scans stored, not blocking submission)
4. After 2 weeks: enable `KYC_SCANNER_EXPIRY_BLOCK_ENABLED=true` to reject expired documents at scan time
5. Long-term: integrate real OCR provider for image-based MRZ extraction

### 5.6 Rollback

Set `KYC_ID_SCANNER_ENABLED=false` — all scanner endpoints return 404. Existing scan records in `kyc_id_scans` are unaffected. The existing KYC case file attachment flow (`attach_kyc_file()` at `kyc_cases.py:734`) continues to work independently.
