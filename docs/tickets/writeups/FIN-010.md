## Click time-series implementation note
`get_link_click_timeseries` must query `AffiliateClicks` table by `link_id` PK, filter by `created_at` in date range, then group by `floor(created_at / 86400)` (day bucket) in-process. For v1 use DDB query with up to 4-page pagination (4MB max). Unique-click deduplication: group visitor hashes by day; `unique_clicks = len({hash for clicks on that day})`.

## Earnings breakdown implementation note
Conversion records store a `status` field (`"pending"`, `"approved"`, `"paid"`). `get_earnings_breakdown` lists all conversion records for the creator's links (query `AffiliateClicks` by `link_id` for each active link), sums `commission_earned_cents` by status. Alternative: if conversions are stored on the `AffiliateLinks` table directly as sub-items, query those.

## SEC-004 cross-reference
Click recording (`record_click`) writes to the billing-adjacent `AffiliateClicks` table. Commission amounts (`commission_earned_cents`) on conversion records affect creator earnings downstream. The `get_earnings_breakdown` endpoint must scope queries to the authenticated creator's links only (validated via `ByAffiliate GSI` — `GSI1PK = AFL#{creator_id}`). Admin stats endpoint (`get_platform_affiliate_stats`) must require `require_admin_session`.
