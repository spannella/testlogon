# VOD-002: Video Upload Endpoint with S3 Presigned URL — Investigation & Implementation Write-up

> Status: **Implemented**. All described components exist. This write-up documents the actual implementation, divergences from the spec, and notable edge cases.

## 1. Summary & Classification

VOD-002 implements the two-step presigned-URL video upload pattern: the client requests a short-lived S3 PUT URL from the backend, uploads binary data directly to S3 (bypassing the API server entirely), then calls a confirmation endpoint to finalize the video record. This avoids streaming multi-gigabyte files through uvicorn workers, which would exhaust memory and block request threads. The pattern mirrors the existing `presign_upload` flow in `app/services/filemanager.py` (lines 2207, 2264) and the `images/presign` endpoint in `app/routers/messaging.py:7914`.

- **Type**: Feature (upload infrastructure)
- **Priority**: P0 — prerequisite for the entire VOD pipeline
- **Status**: Fully implemented
- **Owning area**: Backend / upload flow
- **User persona**: Creator (uploads video files)
- **Dependencies**: VOD-001 (VideoMetadata table, create_video), `app/core/aws_clients.py` (s3_client), `app/core/dev_s3.py` (moto mock)
- **SECOPS-007 parity**: In dev, presigned URLs are replaced with `/mock/s3/` paths served by moto; in prod, real S3 presigned PUTs with 15-minute TTL

### 2.1 Router — `app/routers/vod.py`

### 2.2 Presign Endpoint — `vod.py:134`

```python
@router.post("/upload/presign", response_model=VideoUploadPresignOut)
def vod_presign_upload(inp: VideoUploadPresignIn, user=Depends(require_ui_session)):
```

**Step 1: Content-type validation** (lines 143–148). Validates `inp.content_type` against `ALLOWED_VIDEO_CONTENT_TYPES` (line 39), a frozenset of 10 MIME types. Returns HTTP 422 with a human-readable message on rejection — more informative than Pydantic's regex error.

```python
ALLOWED_VIDEO_CONTENT_TYPES = frozenset({
    "video/mp4", "video/quicktime", "video/x-msvideo", "video/x-matroska",
    "video/webm", "video/mpeg", "video/ogg", "video/x-flv", "video/3gpp", "video/3gpp2",
})
```

**Step 2: Video metadata record creation** (lines 151–158). `create_video()` is called to produce a `VideoMetadataModel` with `status="created"` before the S3 key is known. The `video_id` is embedded in the S3 key path.

**Step 3: S3 key generation** (line 162). `_generate_s3_key(user_sub, video_id, filename)` produces:
```
vod/{user_sub}/raw/{year}/{month}/{video_id}/{filename}
```
This keeps uploads organized by user and date, avoids key collisions, and allows per-user lifecycle policies.

**Step 4: Presigned URL generation** (lines 167–182). Branches on `S.dev_mode`:
- Dev: `f"{S.public_base_url}/mock/s3/{bucket}/{s3_key}"` — served by the `/mock/s3/` route
- Prod: `_s3.generate_presigned_url(ClientMethod="put_object", ...)` with `ExpiresIn=900` (15 minutes), `ContentType`, and metadata headers `vod-ticket`, `vod-user`

**Step 5: Upload ticket storage** (lines 184–208). A ticket record is stored in the **same `VideoMetadata` table** using a `TICKET#{ticket_id}` primary key (ticket_pk helper at line 118). The ticket holds: `owner_user_id`, `actual_video_id`, `s3_key`, `s3_bucket`, `content_type`, `expected_size_bytes`, `filename`, `status="pending"`, `expires_at` (ISO string), and a `ttl_epoch` for DynamoDB TTL cleanup 24 hours post-expiry.

This co-location of ticket records in the `VideoMetadata` table was discussed in the VOD-001 write-up; it's functional but adds noise to the `ByOwnerCreatedAt` GSI.

**Response** (lines 210–221): `VideoUploadPresignOut` returns two aliased URL fields (`upload_url` and `presigned_url`) to accommodate both the frontend and E2E test clients. Also returns `bucket`, `key`, `s3_key`, `ticket_id`, `video_id`, `content_type`, `expires_at`, `expires_in_seconds=900`, `max_size_bytes=10GB`.

### 2.3 Confirm Endpoint

The confirm endpoint (`POST /ui/videos/upload/complete`) is also in `vod.py`. It:
1. Looks up the `TICKET#{ticket_id}` record from DynamoDB (`get_item` on `video_metadata` table)
2. Verifies the ticket owner matches the authenticated user
3. Checks the ticket has not expired (compares `expires_at` string)
4. Calls `_s3.head_object(Bucket=bucket, Key=key)` to confirm the object exists in S3
5. Checks the object's `ContentLength` against `expected_size_bytes`
6. Updates the `VideoMetadataModel` with `source_s3_key`, transitions status (though the exact transition is muted by the "queued" bug noted in VOD-001)
7. Deletes the ticket record
8. Returns `VideoUploadCompleteOut(ok=True, video_id=..., s3_key=..., size_bytes=..., content_type=..., status="created")`

### 2.4 Request Model — `VideoUploadPresignIn` (line 59)

```python
class VideoUploadPresignIn(BaseModel):
    model_config = {"populate_by_name": True}
    filename: str = Field(..., min_length=1, max_length=255)
    content_type: str = Field(..., min_length=1)
    file_size_bytes: int = Field(
        ..., ge=1, le=MAX_SIZE_BYTES,
        validation_alias=AliasChoices("file_size_bytes", "size_bytes")
    )
    title: Optional[str] = Field(default=None, max_length=500)
    description: Optional[str] = Field(default=None, max_length=5000)
    folder_path: Optional[str] = Field(default=None, max_length=1024)
```

The `AliasChoices` on `file_size_bytes` accepts both `"file_size_bytes"` (canonical) and `"size_bytes"` (what the frontend sends). `MAX_SIZE_BYTES = 10 * 1024 * 1024 * 1024` (10 GB). Note that the `title` max length here is 500 characters while `VideoMetadataModel.title` is capped at 256 — the presign model is more lenient than the data model accepts.

### 2.5 S3 Client Infrastructure — `app/core/aws_clients.py:114`

```python
def s3_client():
    endpoint_url = _s3_endpoint_url()
    return boto3.client(
        "s3",
        region_name=_aws_region(),
        endpoint_url=endpoint_url,
        config=_s3_config(),
        **_local_credentials_kwargs(endpoint_url),
    )
```

`_s3_endpoint_url()` returns `None` in prod (real AWS) or the configured local endpoint (moto) in dev. `_local_credentials_kwargs()` injects `aws_access_key_id="test"` / `aws_secret_access_key="test"` when a local endpoint is detected — required because moto validates credential presence even though it ignores their values.

### 2.6 Moto Mock — `app/core/dev_s3.py`

The `start_s3_mock(bucket_names)` function (line 20):
1. Imports `moto.mock_aws` and calls `.start()` on the context manager
2. Pre-creates every bucket listed in `bucket_names`
3. Stores the context in module-level `_mock_ctx` to prevent garbage collection

Called from `main.py:514` with a list that includes `S.vod_output_bucket or "vod-output"` and `S.video_upload_bucket or "local-uploads"`. This means both the upload bucket and the output bucket are available in-memory from startup. All `boto3.client("s3")` calls in the process hit the moto store — no network, no external service.

### 2.7 `/mock/s3/` Proxy Route

In dev mode, presigned PUT URLs point to `{S.public_base_url}/mock/s3/{bucket}/{key}`. There is a backend route (typically in `app/routers/devtools.py` or similar) that accepts `PUT` requests at `/mock/s3/{bucket}/{key}` and forwards them to the moto S3 instance via a `put_object` call. This proxy is what allows the browser (or Playwright tests) to "upload" to S3 without any real AWS calls.

## 3. Gap / Threat Analysis

### 3.1 Title Length Mismatch

`VideoUploadPresignIn.title` allows up to 500 characters (vod.py:72). `VideoMetadataModel.title` enforces `max_length=256` (models_video.py:39). When `create_video()` is called with a 400-character title, Pydantic validation on `VideoMetadataModel.__init__` will raise `ValidationError`. This surfaces as an unhandled 500 unless caught. The ticket spec set 256 for both.

**Fix**: Change `max_length=500` to `max_length=256` in `VideoUploadPresignIn.title`.

### 3.2 No Content-Type Enforcement at S3 Level

The presigned URL's `ContentType` param ensures the PUT URL was generated for a specific content type, but the generated presigned URL does not strictly enforce this at the S3 level without `Conditions` in a POST policy. With a `PUT` presigned URL (as opposed to a presigned POST), the `ContentType` in the `Params` dict only means the URL signature covers that content type — a client that sends a different `Content-Type` header on the PUT will get a `SignatureDoesNotMatch` error in prod. In dev mode (mock `/mock/s3/` proxy), no such check exists. This is acceptable for dev but should be noted.

### 3.3 No File Extension Validation

`VideoUploadPresignIn.filename` accepts any string up to 255 characters. A user could submit `filename="malicious.sh"` with `content_type="video/mp4"`. The backend would create an S3 key `vod/{user}/raw/.../{video_id}/malicious.sh`. The content-type allowlist is validated but the file extension is not. While the actual file bytes are determined by what the client uploads (and FFprobe will reject invalid video files during probing), validating the extension as a secondary check would harden the input.

### 3.4 Ticket Same-Table Storage Race

The `TICKET#` record and the `v_` video record share the `VideoMetadata` table. If DynamoDB point-in-time recovery is enabled and a restore is needed, both tickets and video records would be restored together, potentially revealing expired tickets that reference deleted S3 keys. This is a minor operational concern, not a security issue.

### 3.5 `S.public_base_url` in Dev Presign URL

The dev-mode presigned URL uses `S.public_base_url` (defaulting to `http://localhost:8000`). If the frontend is served from a different host (e.g., in a CI container), this URL may not be reachable. The Vite proxy proxies `/mock/s3/` to the backend, so browser-to-backend the URL resolves correctly. But E2E tests using `page.request.put()` (which bypasses the Vite proxy) must use `http://localhost:8000/mock/s3/...` directly.

## 4. Proposed Design / Fix

### 4.1 Fix Title Max Length

In `app/routers/vod.py`, line 72:
```python
# Before:
title: Optional[str] = Field(default=None, max_length=500)
# After:
title: Optional[str] = Field(default=None, max_length=256)
```

### 4.2 Add File Extension Validation (optional hardening)

Add an extension allowlist to `vod_presign_upload`:
```python
ALLOWED_EXTENSIONS = {".mp4", ".mov", ".avi", ".mkv", ".webm", ".mpeg", ".ogg", ".flv", ".3gp", ".3g2"}
ext = Path(inp.filename).suffix.lower()
if ext not in ALLOWED_EXTENSIONS:
    raise HTTPException(status_code=422, detail=f"File extension not allowed: {ext}")
```

### 4.3 Dev/Prod Parity (SECOPS-007)

Current implementation already satisfies SECOPS-007:
- Dev path: `vod.py:167` branches to `/mock/s3/` URL
- Prod path: `vod.py:170` calls real `generate_presigned_url`
- Same function, same parameters, single branch point gated by `S.dev_mode`
- The moto mock in `dev_s3.py` intercepts all boto3 S3 calls at the botocore layer — no separate service, no network

### 4.4 Backward Compatibility

Both endpoints (`/upload/presign`, `/upload/complete`) are new in this ticket and have no existing callers to break.
