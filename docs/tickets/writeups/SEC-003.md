# SEC-003: Eliminate Hardcoded dev-* Secret Fallbacks (Fail-Closed) — Investigation & Implementation Write-up

> ~5 pages. Code citations verified against the live codebase.

## 1. Summary & Classification

Multiple security-critical secrets across the codebase use `os.environ.get(KEY, "<dev-default>")` or accept empty strings. If any of these environment variables is absent or blank in a production deployment, the application silently operates with a well-known default — allowing an attacker who has read the source code to forge pagination cursors (IDOR), bypass DRM token validation, forge playback URL tokens, or issue API keys without entropy protection. There is no startup-time guard that fails app boot in non-dev mode when these secrets are missing. This is a systemic configuration-hardening issue that compounds the risks described in SEC-002.

- **Type**: security-fix / hardening
- **Severity**: High (multiple critical paths)
- **Status**: Open
- **Area**: `app/core/cursor.py`, `app/services/broadcast_local_drm.py`, `app/services/broadcast_playback.py`, `app/services/drm_production_provider.py`, `app/core/settings.py`, `app/services/api_keys.py`
- **Attacker class**: 🌐 any-user (cursor/API-key forgery), ⚙️ config (misconfigured prod env)
- **Cross-references**: [[SEC-002]] (same root cause — hardcoded webhook secrets); [[SECOPS-007]] (dev/prod parity — secrets must differ between environments); [[SEC-008]] (WS token secret also empty-allowed)


## 2. Current-State Investigation

### 2a. Pagination cursor — HMAC signed with a forgeable default (`app/core/cursor.py:22,36`)

```python
_DEFAULT_CURSOR_SECRET = "dev-cursor-secret"

def _cursor_secrets() -> list[str]:
    current = os.environ.get(
        "CURSOR_SIGNING_SECRET", _DEFAULT_CURSOR_SECRET
    ).strip() or _DEFAULT_CURSOR_SECRET
    ...
```

Lines 22 and 35–41. `_DEFAULT_CURSOR_SECRET = "dev-cursor-secret"` is the module-level fallback. If `CURSOR_SIGNING_SECRET` is not set (or is set to an empty string), the fallback is used in both dev **and prod**. The cursor HMAC (line 100) then uses this known default.

The cursor format is `v2.{base64-payload}.{hmac-signature}`. An attacker who knows the default secret can:
1. Decode any legitimate cursor to learn the DynamoDB `LastEvaluatedKey` format for any table.
2. Craft an arbitrary `LastEvaluatedKey` targeting any PK/SK, sign it with `"dev-cursor-secret"`, and submit it to any paginated endpoint.
3. The backend calls `decode_cursor(forged_cursor)` → `_signature_key_source(payload_b64, sig)` → verifies with the default secret → returns the attacker-supplied `LastEvaluatedKey`.

This allows **arbitrary DynamoDB pagination start-position injection**, effectively scanning any table from an attacker-controlled starting position — an IDOR over all paginated resources. The backward-compat legacy decoder at line 126 also accepts **unsigned** (plain base64) cursors — any caller can inject an arbitrary `LastEvaluatedKey` with no secret at all on that path.

### 2b. DRM key-rotation salt (`app/services/drm_production_provider.py:155`)

```python
DrmRotationConfig(
    ...
    id_salt=(S.drm_key_rotation_salt or "dev-drm-rotation-salt"),
)
```

The `id_salt` is used to derive deterministic DRM key IDs from stream keys. If the salt is the known default, an attacker can predict the DRM key IDs for any stream, potentially correlating key IDs across sessions or influencing key selection. Impact is limited to DRM metadata prediction, not direct decryption, but the salt leaks the rotation schedule.

### 2c. Static DRM token bypass (`app/services/broadcast_local_drm.py:41–44`)

```python
def validate_local_drm_token(token: str, stream_key: str) -> bool:
    static_token = (S.broadcast_local_drm_static_token or "").strip()
    if static_token and token == static_token:
        return True   # ← any request with this token bypasses HMAC validation
```

Line 41–44. If `S.broadcast_local_drm_static_token` is set (it defaults to empty, but can be set in `.env.local` for convenience), any token equal to that static string bypasses the per-stream-key HMAC validation. There is no dev-mode gate on this check. If `broadcast_local_drm_static_token` is accidentally set in a production environment, every holder of that static string can access any stream.

The HMAC token signing/verification itself (lines 35 and 50) falls back to `"local-drm-secret"`:

```python
secret = (S.broadcast_local_drm_token_secret or "local-drm-secret").encode("utf-8")
```

### 2d. Playback URL signed with MD5 (`app/services/broadcast_playback.py:38–41`)

```python
token_payload = f"{expires_at}{path} {S.broadcast_local_cache_token_secret or 'local-cache-secret'}"
md5_token = _b64url_md5(token_payload)
url = f"{base}{path}?md5={md5_token}&expires={expires_at}"
```

Two issues: (a) `"local-cache-secret"` is the fallback for the signing secret; (b) **MD5** is used as the signature primitive. MD5 is cryptographically broken — collisions can be computed in seconds on modern hardware — meaning an attacker who can craft a URL with a matching MD5 token can access any HLS stream path with a valid-looking token. Even with a strong secret, MD5 is not suitable for MACs in a security context (use HMAC-SHA256).

### 2e. Empty-string secrets allowed in Settings (`app/core/settings.py`)

The following settings default to empty string and have no startup validation:

| Setting | Line | Used for |
|---------|------|----------|
| `api_key_pepper` | 45 | API key HMAC hashing |
| `ui_access_token_secret` | 98 | UI session JWT signing (HS256) |
| `ws_token_secret` | 246 | WebSocket auth token signing |

With `api_key_pepper = ""`, API key hashes become `HMAC("", raw_key)` — still a valid HMAC, but the "pepper" provides no additional entropy beyond the key itself. With `ui_access_token_secret = ""`, anyone who knows the empty secret can forge session JWTs for any user. With `ws_token_secret = ""`, WebSocket tickets can be forged.

### 2f. Dev vs prod behavior today

In dev (`DEV_MODE=1`, `.env.local`): `UI_ACCESS_TOKEN_SECRET`, `API_KEY_PEPPER`, and `CURSOR_SIGNING_SECRET` are generated by `scripts/setup_ubuntu.sh` with `openssl rand -hex 32`. So in a correctly-set-up dev environment, these are **not** empty. However:
- Any fresh `git clone` without running `setup_ubuntu.sh` gets empty values.
- Any operator who manually sets `UI_ACCESS_TOKEN_SECRET=` (blank) in a prod environment gets empty.
- The cursor secret's `_DEFAULT_CURSOR_SECRET = "dev-cursor-secret"` module-level fallback activates even when the env var is explicitly set to empty.

There is no startup check that validates any of these secrets.


## 3. Gap / Threat Analysis

### Attack A — Cursor IDOR (forge pagination to scan arbitrary DDB records)

**Precondition**: attacker has any authenticated session; target app has `CURSOR_SIGNING_SECRET` unset or set to empty.

1. Call any paginated endpoint (e.g., `GET /ui/achievements/display-badges/{any_user_sub}`) to obtain a legitimate cursor.
2. Decode the cursor: `base64url_decode(cursor.split(".")[1])` → reveals the DDB `LastEvaluatedKey` structure.
3. Construct a new `LastEvaluatedKey` pointing to a different partition (e.g., a different user's `user_sub`).
4. Sign with `"dev-cursor-secret"`: `HMAC-SHA256(b64(json({"v":"v2","k":{...}})), "dev-cursor-secret")`.
5. Submit forged cursor — backend accepts it, scans from the attacker-controlled position.

Additionally, the legacy unsigned path (`decode_cursor` lines 126–130) accepts any base64-encoded JSON dict as a valid cursor — no secret needed at all. This path exists for backward compatibility with pre-v2 cursors.

**Blast radius**: any paginated DDB endpoint. Combined with other IDORs (SEC-005), attacker can enumerate any table.

### Attack B — Forge UI session JWT (empty `ui_access_token_secret`)

With `UI_ACCESS_TOKEN_SECRET=""`, craft an HS256 JWT with `{"sub": "root_user_sub", "role": "ROOT"}`, sign with empty key. Present as `ui_access_token` cookie → `require_ui_session` accepts it → full ROOT access.

### Attack C — Static DRM bypass (if `broadcast_local_drm_static_token` set in prod)

If `BROADCAST_LOCAL_DRM_STATIC_TOKEN=dev-token` is present in a production `.env`, any request carrying `token=dev-token` in a DRM license request bypasses per-stream-key validation → attacker accesses all HLS streams.

### Sites requiring change

| File | Line(s) | Secret | Risk |
|------|---------|--------|------|
| `app/core/cursor.py` | 22, 35–41 | `CURSOR_SIGNING_SECRET` | IDOR |
| `app/services/broadcast_local_drm.py` | 35, 50 | `broadcast_local_drm_token_secret` | DRM bypass |
| `app/services/broadcast_local_drm.py` | 41–44 | `broadcast_local_drm_static_token` | DRM bypass |
| `app/services/broadcast_playback.py` | 38 | `broadcast_local_cache_token_secret` + MD5 | URL forgery |
| `app/services/drm_production_provider.py` | 155 | `drm_key_rotation_salt` | Key-ID prediction |
| `app/core/settings.py` | 45, 98, 246 | `api_key_pepper`, `ui_access_token_secret`, `ws_token_secret` | Token forgery |


## 4. Proposed Design / Fix

### 4a. Startup secret validation

Add a new `app/core/secret_validation.py` module:

```python
def validate_secrets_on_startup() -> None:
    """Fail app boot in non-dev mode if any required secret is empty or default."""
    from app.core.settings import S
    if S.dev_mode:
        return   # dev environment: rely on .env.local generation by setup_ubuntu.sh

    REQUIRED = {
        "UI_ACCESS_TOKEN_SECRET": S.ui_access_token_secret,
        "API_KEY_PEPPER": S.api_key_pepper,
        "WS_TOKEN_SECRET": S.ws_token_secret,
        "CURSOR_SIGNING_SECRET": os.environ.get("CURSOR_SIGNING_SECRET", ""),
    }
    FORBIDDEN_VALUES = {
        "dev-cursor-secret", "local-drm-secret", "local-cache-secret",
        "dev-drm-rotation-salt", "dev-mock-eid-signing-key",
        "local-ccbill-webhook-secret",
    }
    errors = []
    for name, val in REQUIRED.items():
        v = (val or "").strip()
        if not v:
            errors.append(f"{name} is empty")
        elif v in FORBIDDEN_VALUES:
            errors.append(f"{name} is a known-insecure default value")
    if errors:
        raise RuntimeError(f"Startup secret validation failed: {'; '.join(errors)}")
```

Register in `app/main.py`:

```python
app.add_event_handler("startup", validate_secrets_on_startup)
```

### 4b. Cursor secret — hard-fail instead of fallback

In `app/core/cursor.py`, change `_cursor_secrets()`:

```python
def _cursor_secrets() -> list[str]:
    current = os.environ.get("CURSOR_SIGNING_SECRET", "").strip()
    if not current:
        from app.core.settings import S
        if not S.dev_mode:
            raise RuntimeError("CURSOR_SIGNING_SECRET must be set in non-dev mode")
        current = _DEFAULT_CURSOR_SECRET   # dev only
    ...
```

Also remove the legacy unsigned-cursor decoder once all clients have migrated (or gate it: `if S.dev_mode: return _decode_legacy_cursor(s)` to prevent unsigned cursors in prod).

### 4c. Broadcast DRM — scope static token bypass to dev; upgrade MD5

**`app/services/broadcast_local_drm.py`** — gate static-token bypass:

```python
static_token = (S.broadcast_local_drm_static_token or "").strip()
if static_token and S.dev_mode and token == static_token:
    return True
```

Remove the bypass entirely from non-dev code paths.

**`app/services/broadcast_playback.py`** — replace MD5 with HMAC-SHA256:

```python
import hashlib, hmac as _hmac, base64
secret = (S.broadcast_local_cache_token_secret or "").encode("utf-8")
if not secret:
    from app.core.settings import S as _S
    if not _S.dev_mode:
        raise RuntimeError("BROADCAST_LOCAL_CACHE_TOKEN_SECRET required in prod")
    secret = b"local-cache-secret"
sig = _hmac.new(secret, f"{expires_at}{path}".encode(), hashlib.sha256).digest()
token = base64.urlsafe_b64encode(sig).rstrip(b"=").decode()
url = f"{base}{path}?token={token}&expires={expires_at}"
```

Note: this changes the URL query parameter name from `md5` to `token` — a breaking change for any existing playback URLs. Mitigate with a brief dual-accept period.

### 4d. Settings — no empty defaults for critical secrets

Settings fields for `ui_access_token_secret`, `api_key_pepper`, `ws_token_secret` should not be validated at dataclass construction time (frozen dataclass, no `__post_init__`), but the startup validator (4a) covers them. Optionally add a `@property` on a wrapper or use `pydantic.BaseSettings` for fail-fast validation.

### 4e. Password hashing (Argon2id)

Current `registration.py` uses PBKDF2-SHA256 at 260,000 iterations — adequate for 2024 but non-adaptive. Argon2id is recommended by OWASP. This is a deferred migration: store a `hash_alg` field alongside each password hash; on successful login with an old hash, re-hash with Argon2id transparently. Require `argon2-cffi` dependency.

### 4f. Dev/prod parity (SECOPS-007)

The startup validator is the enforcement point:
- **Dev** (`S.dev_mode=True`): validator returns immediately. `setup_ubuntu.sh` generates strong random secrets in `.env.local` for all required vars. DDB Local, moto, mock KMS — no AWS calls.
- **Prod** (`S.dev_mode=False`): validator raises on missing/default secrets before the app accepts traffic. AWS Secrets Manager or parameter store should be the source; secrets injected as environment variables at container start.

The dev defaults (`"dev-cursor-secret"`, `"local-drm-secret"`, etc.) remain in code but are never reachable in prod because the validator fails boot first.

### 4g. Alternatives considered

- **Remove all hardcoded defaults entirely**: Clean, but breaks `git clone + just up` for new developers who haven't run `setup_ubuntu.sh`. Decision: keep defaults for dev, add validator for prod.
- **Kubernetes Secrets / Vault integration**: Best practice for secret injection; infrastructure-level concern, out of scope for this ticket. The startup validator is agnostic to the injection mechanism.


## 5. Testing, Verification & Rollout

### pytest unit tests

1. `test_startup_validator_passes_dev_mode`: `S.dev_mode=True` → `validate_secrets_on_startup()` does not raise.
2. `test_startup_validator_fails_empty_secret`: `S.dev_mode=False`, `UI_ACCESS_TOKEN_SECRET=""` → raises `RuntimeError` containing `"UI_ACCESS_TOKEN_SECRET is empty"`.
3. `test_startup_validator_fails_default_value`: `S.dev_mode=False`, `CURSOR_SIGNING_SECRET="dev-cursor-secret"` → raises `RuntimeError` containing `"known-insecure default"`.
4. `test_cursor_forged_with_default_rejected_in_prod`: `dev_mode=False`, `CURSOR_SIGNING_SECRET` unset → `decode_cursor` raises `RuntimeError` (or returns None if we handle gracefully at decode time).
5. `test_cursor_legacy_path_blocked_in_prod`: pass a plain-base64 cursor without `v2.` prefix → returns `None` in prod (no unsigned fallback).
6. `test_drm_static_bypass_blocked_in_prod`: `dev_mode=False`, `broadcast_local_drm_static_token="dev-token"` → `validate_local_drm_token("dev-token", stream_key)` does not short-circuit to True.
7. `test_playback_url_uses_hmac_sha256`: call `mint_local_playback_url` → URL contains `?token=...` not `?md5=...`; verify token using HMAC-SHA256.
8. `test_playback_url_md5_no_longer_accepted`: old `?md5=...` token rejected by new validator.

### Playwright E2E

No dedicated E2E spec needed (these are startup-time and crypto primitive changes). Existing messaging and DRM E2E suites (e.g., `messaging-features.spec.ts`, broadcast tests) should continue passing after the change — they exercise the happy path.

### Manual / QA steps

1. Remove `CURSOR_SIGNING_SECRET` from `.env.local`; restart backend with `DEV_MODE=0` → should refuse to start.
2. Restore valid secret; confirm pagination cursors still work across all paginated endpoints.
3. In dev, confirm `BROADCAST_LOCAL_DRM_STATIC_TOKEN=dev-token` still allows HLS access (dev-only path active).
4. Set `DEV_MODE=0` with `BROADCAST_LOCAL_DRM_STATIC_TOKEN=dev-token` → confirm static bypass no longer works.

### Observability

- Add a startup log line `secrets_validated: ok` at INFO level when all checks pass, so ops can confirm validation ran.
- Add `secret_validation_fail_total{secret_name=...}` metric (but this metric would only be visible if the app starts, which it won't — instead emit the failure to stderr and structured logs before exit).

### Rollout

1. Add `validate_secrets_on_startup` but initially make it a **WARNING** (not a boot failure) for one deployment cycle to discover any production secrets that are already unset.
2. After confirming all required secrets are set in prod, flip to hard failure.
3. Deploy cursor-secret hard-fail. Monitor for cursor-decode failures in metrics.
4. Deploy MD5→HMAC-SHA256 playback URL change with dual-accept window.
5. Deploy static DRM token dev-gate.

**Effort**: S–M. Startup validator is S (1–2 hours). MD5 migration has a compatibility window that adds complexity (M). Argon2id password migration is M–L and should be a separate ticket.

**Open questions**: How long should the legacy unsigned-cursor path be supported for backward compat? Recommendation: deprecate immediately by logging a WARNING on legacy cursor decode, remove after 30 days.
