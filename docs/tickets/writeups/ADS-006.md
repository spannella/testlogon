# ADS-006: Broadcast Ad Breaks — Investigation & Implementation Write-up

## 1. Summary & Classification

ADS-006 adds advertising to live broadcasts via two surfaces: pre-roll ads that play when a viewer joins a session, and broadcaster-triggered mid-roll ad breaks that fan-out via SSE to all connected viewers. Subscribers to the broadcaster receive an ad-free experience (server-authoritative check). The broadcast session model is extended with ad configuration fields (`pre_roll_enabled`, `mid_roll_ad_break_duration_seconds`, `mid_roll_skip_after_seconds`, `ad_break_active`, `total_ad_breaks`). A dedicated router `app/routers/broadcast_ads.py` (registered in `app/main.py:552`) keeps the large existing broadcast router untouched.

The ad selection is currently **stubbed** in `app/services/broadcast_ads.py:55–83` — it returns a deterministic house creative. The stub explicitly documents that it must be replaced with `app.services.ad_serving.serve_ad` once ADS-004 is wired in. ADS-004 (`ad_serving.py`) is now implemented, making this the most important remaining integration gap for ADS-006.

- **Type**: feature (broadcast integration)
- **Priority**: Medium — depends on ADS-004 (serving engine) and ADS-002 (video creatives)
- **Status**: Partially implemented — session model, ad-break endpoints, pre-roll join endpoint, SSE fan-out, subscriber ad-free check, and frontend components (`AdOverlay.tsx`, `AdBreakButton.tsx`, `LivePlayer.tsx` integration) are all implemented. The ad selection inside `serve_broadcast_ad()` is stubbed with a house creative.
- **Owning area**: Advertising platform — broadcast integration; intersects with broadcast system
- **Affected personas**: viewers (see pre-roll/mid-roll ads or skip if subscribed), broadcasters (trigger ad breaks, configure ad settings), advertisers (video creatives served to broadcast audience)
- **Cross-references**: ADS-002 (video creative format), ADS-004 (serve_ad engine — integration gap), ADS-007 (broadcast impression billing), ADS-008 (broadcast ad analytics), ADS-020 (broadcast ad serving billing integration), BCAST-001 (broadcaster dashboard — where AdBreakButton lives), BCAST-002 (viewer player — where AdOverlay lives)
- **Dev/prod parity**: [[SECOPS-007]] — `broadcast_ad_events` table on DDB Local in dev; SSE events use `broadcast_sse_publish` which is in-process in dev; `has_active_subscription` reads from DDB Local; no external network calls

## 2. Current-State Investigation (what exists today)

### 2.1 Session model extension — `app/routers/broadcast.py`

`BroadcastSessionModel` (defined at `broadcast.py:165–171`) now includes:
- `pre_roll_enabled: bool = True`
- `pre_roll_creative_id: Optional[str] = None` — reserved for future pinned-creative support
- `mid_roll_ad_break_duration_seconds: int = 30`
- `mid_roll_skip_after_seconds: int = 15`
- `ad_break_active: bool = False`
- `ad_break_started_at: Optional[int] = None`
- `total_ad_breaks: int = 0`

`BroadcastSessionCreateIn` at `broadcast.py:113–121` has validators for `pre_roll_enabled`, `mid_roll_ad_break_duration_seconds` (must be 15, 30, or 60 via `_validate_midroll_duration`), and `mid_roll_skip_after_seconds`. Session creation at line 294–295 persists these fields to DDB.

`app/services/broadcast_store.py:169,233` reads/writes `ad_break_started_at` and all ad config fields from the `broadcast_sessions` DDB table. The `update_session_fields` helper (used by `broadcast_ads.py`) handles partial updates.

### 2.2 Broadcast ads service — `app/services/broadcast_ads.py`

Key functions:

- **`is_ad_free(viewer_id, creator_id)`** at line 36: returns `True` if `viewer_id == creator_id` (broadcaster is always ad-free) or if `has_active_subscription(viewer_id, creator_id)` returns `True` (active subscriber). `has_active_subscription` is imported from `app/services/subscription_access.py:55`.

- **`serve_broadcast_ad(surface, creator_id, content_id, slot_type, user_id)`** at line 55: **STUB** — returns hardcoded house creative with `format="video"`, `video_url="/mock/s3/ad-creatives/{creative_id}.mp4"`. The docstring explicitly states ADS-004 must replace this: "When ADS-004 lands this function should delegate to `app.services.ad_serving.serve_ad`."

- **`build_pre_roll(session, viewer_id)`** at line 86: checks `is_ad_free`, then `session.pre_roll_enabled`, then calls `serve_broadcast_ad`. Returns `{"pre_roll": <payload|None>, "ad_free": bool}`.

- **`start_ad_break(session, user_sub)`** at line 120+: validates broadcaster ownership and session `status="live"`, checks `not session.ad_break_active`. Updates DDB fields via `update_session_fields`. Calls `broadcast_sse_publish(session.id, {"_type": "ad_break:start", ...})` at line 151. Also calls `schedule_ad_break_end(session.id, duration)`.

- **`end_ad_break(session_id, ended_by)`** at line 155+: sets `ad_break_active=False`, `ad_break_started_at=None` via `update_session_fields`. Calls `broadcast_sse_publish(session_id, {"_type": "ad_break:end", "ended_by": ended_by})` at line 161.

- **`schedule_ad_break_end(session_id, duration)`** at line 164+: `asyncio.sleep(duration)` then calls `end_ad_break(session_id, "auto")`. Runs in the uvicorn event loop.

- **`record_ad_event(session_id, creative_id, viewer_id, event_type)`**: writes to `T.broadcast_ad_events` table for analytics.

### 2.3 Broadcast ads router — `app/routers/broadcast_ads.py`

Registered in `app/main.py:89,552` as `broadcast_ads_router` with prefix `/broadcast`. Routes:

- `GET /broadcast/sessions/{session_id}/ad-config` — get ad configuration
- `PATCH /broadcast/sessions/{session_id}/ad-config` — update ad config (broadcaster only)
- `POST /broadcast/sessions/{session_id}/ad-join` — viewer join with pre-roll; returns `BroadcastJoinOut` with `pre_roll: PreRollOut | null`, `ad_free: bool`
- `POST /broadcast/sessions/{session_id}/ad-break` — broadcaster triggers mid-roll break
- `POST /broadcast/sessions/{session_id}/ad-break/end` — broadcaster ends break early
- `GET /broadcast/sessions/{session_id}/ad-break/status` — current ad break state
- `POST /broadcast/sessions/{session_id}/ads/{creative_id}/track` — ad event tracking for broadcast surface

The authorization check at `broadcast_ads.py:127` compares `session.created_by != ctx["user_sub"]` and `ctx.get("role") not in {"admin", "root"}`. Note: `ctx["role"]` in the session auth context is a `Role` enum (not a string), so `ctx.get("role") not in {"admin", "root"}` string comparison may fail silently. The check should use `ctx.get("role") not in {Role.ADMIN, Role.ROOT}` or compare to the string representation of the enum value.

### 2.4 Frontend components — `frontend/src/pages/broadcast/`

- **`AdOverlay.tsx`**: full-screen overlay over the broadcast player. Props: `ad: AdOverlayAd`, `skipAfterSeconds: number`, `onSkip`, `onComplete`, `onCtaClick`. Renders video ad (`<video>`) or image ad. Countdown timer. Skip button appears after `skipAfterSeconds` seconds. `data-testid="broadcast-ad-overlay"`.
- **`AdBreakButton.tsx`**: broadcaster controls button. Props: `sessionId`, `isLive`, `adBreakActive`, `durationSeconds`, `onTrigger`. Disabled during active break (shows countdown). Shows confirm dialog before triggering. `data-testid="ad-break-button"`.
- **`LivePlayer.tsx`** at lines 118–120, 233–257, 359: integrates `AdOverlay` for pre-roll (on join response with `data.pre_roll && !data.ad_free`) and mid-roll (on SSE `ad_break:start` event). `AdBreakButton` visible for session owner.

SSE event handling: `case "ad_break:start"` in `LivePlayer.tsx` sets `adBreakActive=true` and calls `serveAd({surface: "broadcast", slot_type: "broadcast_midroll"})` client-side to fetch the mid-roll ad. Non-subscriber viewers show `AdOverlay`; subscriber viewers ignore the event (client-side check against `adFree` state set on join).

### 2.5 DynamoDB table — `BroadcastAdEvents`

`scripts/local-ddb-init.py:990` creates `BroadcastAdEvents` table. Table handle at `app/core/tables.py:229` as `T.broadcast_ad_events`. Setting at `app/core/settings.py:537` as `broadcast_ad_events_table_name = os.environ.get("DDB_BROADCAST_AD_EVENTS", "BroadcastAdEvents")`.

The `broadcast_sessions` table itself is pre-existing; the new ad fields are stored as additional attributes on existing session records.

### 2.6 Dev vs prod behavior (SECOPS-007)

- All DDB calls route through `T.*` table handles — DDB Local in dev, real DDB in prod
- SSE events via `broadcast_sse_publish` use an in-process asyncio Queue per session — no external message broker in dev or prod (current prod architecture uses same in-process pattern per uvicorn worker; multi-worker SSE requires Redis fan-out, not in scope here)
- `has_active_subscription` reads from `T.billing` — DDB Local in dev
- `schedule_ad_break_end` uses `asyncio.sleep` — same in dev and prod
- `BROADCAST_PREROLL_ENABLED` and `BROADCAST_MIDROLL_ENABLED` feature flags at `app/core/settings.py` (verify these exist; ticket spec defines them)

## 3. Gap / Threat Analysis

### 3.1 Critical gap — `serve_broadcast_ad` stub not wired to ADS-004

The `serve_broadcast_ad` function in `app/services/broadcast_ads.py:55–83` returns a hardcoded house creative. `app/services/ad_serving.serve_ad` is now fully implemented. The integration requires replacing the stub body:

```python
def serve_broadcast_ad(*, surface, creator_id, content_id, slot_type, user_id) -> Dict[str, Any]:
    try:
        from app.services.ad_serving import serve_ad
        return serve_ad(
            surface=surface,
            content_type="broadcast_session",
            creator_id=creator_id,
            content_id=content_id,
            slot_type=slot_type,
            user_id=user_id,
        )
    except Exception:
        # Graceful degradation: serve house ad if engine fails
        return {"filled": False, "is_house_ad": False, "fill_reason": "engine_error"}
```

Until this is done, all broadcast viewers see the same hardcoded stub creative regardless of targeting, frequency caps, or budget.

### 3.2 Authorization role-type bug in `broadcast_ads.py:127`

```python
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {"admin", "root"}:
```

`ctx["role"]` from `require_ui_session` is a `Role` enum value (e.g., `Role.ADMIN`). String comparison `not in {"admin", "root"}` will always be True for enum values, meaning an admin would fail the check. Fix:

```python
from app.auth.roles import Role
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {Role.ADMIN, Role.ROOT}:
```

### 3.3 `ad_break:end` not sent if `asyncio.sleep` task is cancelled

If the uvicorn process restarts or the session goes offline while an ad break is active, `schedule_ad_break_end` never fires. `ad_break_active` remains `True` in DDB. A background recovery scan (similar to the one described in the ticket spec at section 17.3) should detect sessions with `ad_break_active=True` and `ad_break_started_at + duration < now_ts()` and call `end_ad_break`.

### 3.4 Pre-roll ad-free check is client-side for mid-roll

For pre-roll, `build_pre_roll` checks `is_ad_free` server-side. For mid-roll, the `ad_break:start` SSE event is broadcast to all viewers; the client checks its local `adFree` state to decide whether to show the overlay. If the `adFree` state was set incorrectly on join (or the client stores it incorrectly), a subscriber might see mid-roll ads. The server-side ad-free flag from the `/ad-join` response should be the authoritative source; the client must persist it in session state, not re-derive it.

### 3.5 `BROADCAST_PREROLL_ENABLED` and `BROADCAST_MIDROLL_ENABLED` flags

The ticket spec defines these flags but they are not verified as present in `app/core/settings.py`. The settings file has `ad_serving_enabled` and `sponsored_posts_enabled` but the broadcast-specific flags should also be present. Without them, the feature cannot be gated independently.

### 3.6 `schedule_ad_break_end` blocks with a 15-60 second `asyncio.sleep`

In a single-worker uvicorn (dev mode), this is acceptable. In multi-worker production, the task runs only in the worker that handled the `POST /ad-break` request. Other workers do not have the task; if the initiating worker dies, the break hangs. The ticket spec addresses this with a secondary scan loop. This scan is not yet implemented.

## 4. Proposed Design / Fix

### 4.1 Wire `serve_broadcast_ad` to ADS-004 engine (critical)

Replace the stub in `app/services/broadcast_ads.py:55–83` as described in Gap 3.1. The serving engine now handles targeting, frequency caps, and budget. Gracefully degrade (return empty/house ad) if `serve_ad` throws.

### 4.2 Fix role-type comparison (critical)

Update `broadcast_ads.py:127` to compare against `Role` enum values from `app/auth/roles.py`:

```python
from app.auth.roles import Role
if session.created_by != ctx["user_sub"] and ctx.get("role") not in {Role.ADMIN, Role.ROOT}:
```

This also applies to `update_ad_config_route` at line 127.

### 4.3 Add stuck ad-break recovery scan

Add to `app/main.py` lifespan (alongside existing background tasks):

```python
async def _recover_stuck_ad_breaks():
    import asyncio
    while True:
        await asyncio.sleep(60)  # check every minute
        from app.services.broadcast_store import scan_active_sessions
        from app.services.broadcast_ads import end_ad_break
        sessions = scan_active_sessions(status="live", ad_break_active=True)
        for s in sessions:
            duration = s.mid_roll_ad_break_duration_seconds
            if s.ad_break_started_at and (now_ts() - s.ad_break_started_at) > (duration * 3):
                end_ad_break(s.id, "recovery")
```

### 4.4 Add `BROADCAST_PREROLL_ENABLED` and `BROADCAST_MIDROLL_ENABLED` feature flags

In `app/core/settings.py`, add:

```python
broadcast_preroll_enabled: bool = os.environ.get("BROADCAST_PREROLL_ENABLED", "1") not in ("0", "false")
broadcast_midroll_enabled: bool = os.environ.get("BROADCAST_MIDROLL_ENABLED", "1") not in ("0", "false")
```

Gate in `build_pre_roll`:
```python
if not S.broadcast_preroll_enabled:
    return {"pre_roll": None, "ad_free": False}
```

Gate in `trigger_ad_break_route`:
```python
if not S.broadcast_midroll_enabled:
    raise HTTPException(403, "Mid-roll ads not enabled")
```

### 4.5 Dev/prod parity (SECOPS-007)

After wiring `serve_broadcast_ad` to `serve_ad`, the broadcast ad serving inherits ADS-004's dev/prod parity:
- DDB Local for campaigns/creatives/targeting/frequency caps in dev
- No external calls; graceful degradation on engine failure
- E2E tests can run offline: `just restart` seeds sessions; ADS-001/002/003/004 E2E setup provides active campaigns and approved video creatives

For the ad event tracking (`POST /broadcast/sessions/{id}/ads/{creative_id}/track`), events write to `T.broadcast_ad_events` — DDB Local in dev, same schema in prod.
