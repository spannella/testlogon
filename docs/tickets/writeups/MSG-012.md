# MSG-012: Message Formatting & Rich Text — Investigation & Implementation Write-up

## 1. Summary & Classification

MSG-012 adds three complementary capabilities to the messaging system: (1) a `format` field on messages so senders can flag text as `"markdown"` and have it rendered with bold/italic/strikethrough/code/quotes in the message bubble; (2) an `@mention` system with autocomplete in the compose bar, validation against conversation participants, storage of `mentioned_user_ids`, and a notification for each mentioned user; and (3) URL auto-linking and link-preview cards rendered in the message bubble from the existing `preview` field already auto-fetched by the backend on send.

- **Type**: Feature
- **Priority**: Medium
- **Status**: Unbuilt — zero production code exists for format, mentions, markdown rendering, or the mention notification flow.
- **Area**: Messaging (backend router, service layer, frontend compose + bubble).
- **User personas affected**: All messaging participants — senders want formatting expressiveness; recipients need consistent rendering; group-chat users need @mention directed communication.
- **Dependencies**: None — uses existing message infrastructure. `FEED-008` downstream depends on the `MarkdownRenderer` component.

### 2.2 Dev vs Prod Behavior

`_fetch_link_preview()` makes a real outbound HTTP GET. In dev mode (no internet isolation) this may succeed or fail silently — acceptable. A mock OG fallback for deterministic dev testing is desirable but not strictly required. The `send_text_message` path already wraps the fetch in a `try/except` (line 7979).

## 3. Gap Analysis

### 3.1 Missing Backend Changes

1. **`SendTextMessageIn`** (line 1844): needs `format: str = Field(default="plain", pattern=r"^(plain|markdown)$")` and `mentioned_user_ids: list[str] = Field(default_factory=list, max_length=50)`.
2. **`MessageOut`** (line 2404): needs `format: str = "plain"` and `mentioned_user_ids: list[str] = Field(default_factory=list)`.
3. **`_message_out_from_item()`** (line 3766): must populate `format` (default `"plain"` for legacy messages without the field) and `mentioned_user_ids`.
4. **`send_text_message()`** (line 7854): must (a) validate all `mentioned_user_ids` are active conversation participants (query participants, compare sets, raise HTTP 400 if any are invalid), (b) store `format` and `mentioned_user_ids` in the DDB item, and (c) for each mentioned user (excluding sender), call `audit_event("message_mention", ...)` to create a notification.
5. **Standalone link-preview endpoint**: `POST /ui/messaging/link-preview` body `{url: str}` → reuse `_fetch_link_preview(url)` → 200 with OG data or 404 if nothing found. Needed so the compose bar can display a preview before the message is sent. New request model `LinkPreviewUrlIn(BaseModel): url: str = Field(..., max_length=2048, pattern=r"^https?://")`.
6. **`ALERT_EVENT_TYPES`** (`app/services/alerts.py:133`): add `"message_mention"` so preferences and dispatch work correctly.

### 3.2 Missing Frontend Changes

1. **`frontend/src/api/types.ts`**: add `format?: "plain" | "markdown"` and `mentioned_user_ids?: string[]` to `MessageOut`.
2. **`frontend/src/api/endpoints/messaging.ts`**: add `getLinkPreview(url: string)` calling `POST /ui/messaging/link-preview`.
3. **`frontend/src/components/shared/MarkdownRenderer.tsx`** (NEW): regex-based parser, no raw HTML, props `{text, format, mentionedUserIds?, className?}`. Must escape HTML before processing. Supports: `**bold**`, `*italic*`, `~~strike~~`, `` `code` ``, ` ```block``` `, `> quote`, `[text](url)`, bare URL auto-link, `@mention` highlight span.
4. **`frontend/src/pages/messages/MentionAutocomplete.tsx`** (NEW): dropdown anchored below cursor, filters conversation participants by prefix after `@`, keyboard navigation, inserts `@DisplayName` and records `user_sub` in parent state. `data-testid="mention-autocomplete"`.
5. **`frontend/src/pages/messages/LinkPreviewCard.tsx`** (NEW): renders `MessageOut.preview` (title, description, image, domain). Uses React Query with `staleTime: 3600000`. `data-testid="link-preview-card"`. Limits to 3 cards per message.
6. **`frontend/src/utils/urls.ts`** (NEW): `extractUrls(text): string[]` using `/https?:\/\/[^\s<>"\])+/g`.
7. **`ComposeBar.tsx`**: add `formatMode` state (`"plain" | "markdown"`), `RichTextToggle` button, `mentionedUserIds` accumulator, `mentionQuery` state, `MentionAutocomplete` overlay, live preview `<div>` (debounced 200ms, shown only in markdown mode). Send handler passes `format` and `mentioned_user_ids` to API.
8. **`MessageBubble.tsx`**: replace plain `<p>{message.text}</p>` with `<MarkdownRenderer text={message.text} format={message.format || "plain"} mentionedUserIds={message.mentioned_user_ids} />`. Add `<LinkPreviewCard>` components for URLs extracted from text (plain mode) or already stored in `message.preview`.

### 3.3 Edge Cases and Abuse Potential

- **XSS via markdown**: `MarkdownRenderer` must escape HTML entities before applying markdown transforms. No `dangerouslySetInnerHTML`. React renders all output as JSX nodes.
- **SSRF via link preview**: `_fetch_link_preview` already makes outbound HTTP. The new endpoint adds an authenticated user-triggered path. In production: validate `https://` scheme, deny private IP ranges (RFC 1918, loopback), enforce 5s timeout and 512KB max response size. In dev: acceptable to call real URLs or add an in-memory mock dict keyed by domain.
- **Mention spam in groups**: max 50 `mentioned_user_ids` enforced by Pydantic `max_length=50`. Participant validation prevents mentions of non-members.
- **Self-mention**: allowed (stored), but no notification sent for sender's own `user_sub`.
- **Markdown in encrypted messages**: `encryption` and `text` are mutually exclusive (existing validator at line 1872); `format=markdown` on an encrypted message is not meaningful. Should be silently ignored (format stored as `"plain"`) or rejected with 400.

## 4. Proposed Design

### 4.1 Backend

**`app/routers/messaging.py`**

```python
# Add to SendTextMessageIn (after line 1859):
format: str = Field(default="plain", pattern=r"^(plain|markdown)$")
mentioned_user_ids: list[str] = Field(default_factory=list, max_length=50)

# Add to MessageOut (after line 2495):
format: str = "plain"
mentioned_user_ids: list[str] = Field(default_factory=list)

# In _message_out_from_item() (line 3766+):
format=item.get("format", "plain"),
mentioned_user_ids=item.get("mentioned_user_ids") or [],

# In send_text_message() (line 7854+), after participant check:
if inp.mentioned_user_ids:
    participant_subs = _get_participant_subs(conv_id)
    invalid = set(inp.mentioned_user_ids) - participant_subs
    if invalid:
        raise HTTPException(400, f"Mentioned users are not participants: {', '.join(invalid)}")

# Store fields in DDB item:
item["format"] = inp.format
item["mentioned_user_ids"] = inp.mentioned_user_ids

# After message stored:
for mentioned_sub in inp.mentioned_user_ids:
    if mentioned_sub != user_sub:
        audit_event("message_mention", mentioned_sub, ...,
                    title=f"{sender_name} mentioned you",
                    body=inp.text[:100],
                    link=f"/messages/{conv_id}")
```

**New endpoint (after existing reaction endpoints):**
```python
class LinkPreviewUrlIn(BaseModel):
    url: str = Field(..., max_length=2048, pattern=r"^https?://")

@router.post("/messaging/link-preview")
def get_link_preview(body: LinkPreviewUrlIn, user_id: str = Depends(get_messaging_user_id)):
    og = _fetch_link_preview(body.url)
    if not og:
        raise HTTPException(status_code=404, detail="Could not fetch preview")
    return og
```

**`app/services/alerts.py:133`** — add `"message_mention"` to `ALERT_EVENT_TYPES`.

### 4.3 Feature Flags

| Flag | Default | Purpose |
|------|---------|---------|
| `MSG012_MARKDOWN_ENABLED` | `false` | Format toggle + rendering |
| `MSG012_LINK_PREVIEW_ENABLED` | `false` | LinkPreviewCard rendering |
| `MSG012_MENTIONS_ENABLED` | `false` | Autocomplete + notifications |

Backend stores `format` and `mentioned_user_ids` regardless of flags (safe, additive). Frontend gating via env var or settings check in `ComposeBar` and `MessageBubble`.

### 4.4 Dev/Prod Parity (SECOPS-007)

- `_fetch_link_preview` already runs in both dev and prod (HTTP GET in both modes). No dev-mock needed unless CI environment blocks outbound.
- `audit_event("message_mention", ...)` dispatches through the existing alert pipeline (SSE + email + push per user prefs) in both dev and prod. Dev: logs to file, no real email/SMS sent.
- `format` and `mentioned_user_ids` stored in DDB Local in dev, same DDB table schema in prod.
