# FIN-005: Multi-Currency Display — Investigation & Implementation Write-up

## 1. Summary & Classification

FIN-005 adds display-only multi-currency support: all financial processing stays in USD, but users can choose a preferred display currency (from 15 major currencies) in their profile. Prices across billing, shop, subscriptions, tips, and unlock surfaces render the converted amount with a `~` prefix plus the original USD in smaller text. Exchange rates are fetched from an external provider (or a static fallback) and cached in DynamoDB, with an in-memory layer for sub-millisecond reads. The feature is purely presentational — no changes to payment processing, ledger storage, or settlement currency.

- **Type**: Feature
- **Priority**: Low (ticket-assigned)
- **Status**: Unbuilt — zero backend or frontend infrastructure exists for this ticket
- **Persona**: Any platform user, especially international buyers who want price transparency
- **Cross-references**: [[SECOPS-007]] (dev/prod parity — no outbound calls in dev mode); [[SEC-004]] (billing authz — currency preference is display-only, no money-path changes)

### 3.2 Abuse / Failure Modes

- **Stale rates used for checkout disclaimer**: Since rates are display-only and the actual charge is always USD, stale rates only mislead the user about the approximate converted price — not a financial error, but a UX concern. The `is_stale` flag and `~` prefix mitigate this.
- **External API unavailability**: If the rate provider is down, the last DDB-cached rates must be served; if DDB cache is also missing, the static fallback must activate transparently. Zero-fallback would leave international users with blank prices.
- **JPY / zero-decimal currencies**: Rounding errors possible if `toFixed(0)` is applied to a small fractional yen amount. Must use `Math.round` not `toFixed` for zero-decimal currencies.
- **SECOPS-007**: In dev mode, `_fetch_from_external_api()` must never make outbound HTTP calls. The function must check `S.dev_mode` and return static fallback rates instead. The same code path runs in both envs; the provider selection is isolated to the fetch helper, not scattered through business logic.

## 4. Proposed Design / Fix

### 4.1 DynamoDB Table (`exchange_rates`)

```python
# scripts/local-ddb-init.py
TableDef(
    _resolve_table_name(S.exchange_rates_table_name, "exchange_rates"),
    "pk", "sk",
)
# No GSIs needed — all access is by single key (RATES/CURRENT, STATIC/FALLBACK)
```

Seed `STATIC/FALLBACK` at init time with conservative rates for all 15 currencies.

### 4.2 Settings (`app/core/settings.py`)

```python
multi_currency_enabled: bool = os.environ.get("MULTI_CURRENCY_ENABLED", "true").lower() not in ("0", "false")
exchange_rates_table_name: str = os.environ.get("EXCHANGE_RATES_TABLE_NAME", "exchange_rates")
exchange_rate_ttl_seconds: int = int(os.environ.get("EXCHANGE_RATE_TTL_SECONDS", "3600"))
exchange_rate_api_url: str = os.environ.get("EXCHANGE_RATE_API_URL", "")
```

### 4.3 Exchange Rate Service (`app/services/exchange_rates.py`)

Three-layer cache hierarchy (mirrors the existing `app/core/dev_s3.py` pattern):

```
get_current_rates():
  1. _rate_cache in-memory (module-level dict + _cache_expires_at int)
     → if valid: return immediately (< 1 μs)
  2. DDB GetItem(RATES/CURRENT) → check expires_at
     → if valid: update in-memory, return
  3. _fetch_from_external_api()   ← guarded by S.dev_mode
     → if S.dev_mode: return _load_static_fallback() (no outbound)
     → else: HTTP GET to S.exchange_rate_api_url (5s timeout)
     → on success: write DDB CURRENT + HISTORY snapshot, update in-memory
  4. _load_static_fallback() from DDB (STATIC/FALLBACK)
     → mark response is_stale=True
```

Key public functions:
- `get_current_rates() -> Dict[str, Any]` — full rate response with `rates`, `fetched_at`, `is_stale`
- `convert_usd_cents(amount_cents: int, target_currency: str) -> Dict[str, Any]` — returns `original_cents`, `converted_amount` (string), `rate`, `approximate`, `rate_updated_at`
- `refresh_rates() -> Dict[str, Any]` — force-fetch from external API (admin only)
- `get_supported_currencies() -> List[Dict[str, str]]` — list of 15 currencies with code, name, symbol, decimal_places

**SECOPS-007 parity**: `_fetch_from_external_api` is the only function that touches the network. It is a leaf function with no side effects beyond DDB writes. `if S.dev_mode: return _load_static_fallback()` at the top of that function ensures no outbound calls in dev, satisfying the SECOPS-007 provider-isolation requirement.

### 4.4 Exchange Rate Router (`app/routers/exchange_rates.py`)

### 4.6 Pydantic Models (`app/models.py`)

```python
class ExchangeRateOut(BaseModel):
    currency: str
    rate: str  # string preserves Decimal precision for JSON round-trip
    symbol: str = ""
    name: str = ""
    decimal_places: int = 2

class ExchangeRatesOut(BaseModel):
    rates: List[ExchangeRateOut] = Field(default_factory=list)
    source: str = ""
    fetched_at: int = 0
    expires_at: int = 0
    is_stale: bool = False

class CurrencyConversionOut(BaseModel):
    original_cents: int
    original_currency: str = "USD"
    converted_amount: str
    converted_currency: str
    rate: str
    rate_updated_at: int = 0
    approximate: bool = True
```

### 4.7 Frontend Context (`frontend/src/contexts/CurrencyContext.tsx`)

```typescript
// Wrap at app root in main.tsx (inside QueryClientProvider, outside Router)
export const CurrencyProvider = ({ children }: { children: ReactNode }) => { ... }

export const useCurrency = () => useContext(CurrencyContext)
```

The provider:
1. Reads `preferredCurrency` from `useAuthStore().user.preferred_currency` (default `"USD"`)
2. Fetches rates via `useQuery(["exchange-rates"], fetchExchangeRates, { staleTime: 30 * 60 * 1000 })`
3. Exposes `convert(usdCents): ConvertedAmount` and `formatPrice(usdCents): string`
4. When `preferredCurrency === "USD"`: pass-through, no conversion indicator
5. When rates unavailable or `is_stale`: `formatPrice` appends `*` and renders a tooltip

### 4.11 Checkout Disclaimer

On all checkout / payment confirmation pages: render a small notice `"Displayed amount in {currency} is approximate. You will be charged in USD."` when `preferredCurrency !== "USD"`.

### 4.12 Alternatives Considered

- **Client-side-only rate fetch (no backend caching)**: Rejected — would bypass the SECOPS-007 no-outbound-in-dev requirement and would expose the exchange rate API key to the browser.
- **Build-time static rates**: Rejected — rates would be stale at deploy time; no admin refresh mechanism.
- **Store rates in `app/core/settings.py`**: Rejected — requires restart to update; admin refresh would be impossible.

### 5.5 Rollout

Feature flag: `MULTI_CURRENCY_ENABLED` (default `true`). When disabled, the `CurrencyAmount` component falls back to USD formatting; the exchange rate endpoints return 404; the settings currency selector is hidden. No data loss on rollback — profile `preferred_currency` field is simply ignored.

**Phased delivery**:
1. Backend + static fallback, flag OFF (2 days, unit tests)
2. Enable for internal accounts; verify CurrencyAmount rendering (3 days)
3. 10% canary — check rate freshness, no display breakage (3 days)
4. GA

### 5.6 Effort Estimate

**L** (8–10 days as per ticket). Estimated breakdown: backend service + router + DDB table (3 days), profile extension (0.5 days), frontend context + CurrencyAmount + CurrencySelector (2 days), price surface integration across ~9 files (1.5 days), E2E tests (1.5 days), QA/polish (0.5 days).

### 5.7 Risks and Open Questions

- **Exchange rate provider selection**: `exchangerate-api.com` is mentioned in the spec. An API key will be required for prod. Dev mode must never call it (SECOPS-007).
- **`requests` vs `httpx`**: `requirements.txt` contains `requests==2.31.0` (synchronous). Using `requests` in a FastAPI async handler requires `asyncio.to_thread(...)` wrapper to avoid blocking the event loop. Alternatively add `httpx` for native async. Recommend `asyncio.to_thread(requests.get, ...)` to avoid a new dependency.
- **Currency of zero-decimal amounts (JPY < 1 USD)**: Rounding 1 cent at JPY 149.5 gives JPY 1.495 → rounds to 1 yen. Acceptable for display purposes given the `~` prefix.
