# KYC-001: Admin KYC Review Dashboard — Investigation & Implementation Write-up

## 1. Summary & Classification

**KYC-001** delivers the admin-facing frontend for the KYC review workflow. The backend API is completely implemented — seven admin endpoints live in `app/routers/kyc_cases.py` (lines 974–1282) and their service layer in `app/services/kyc_cases.py` (828 lines). What is missing is every pixel of the frontend: the queue page, the case-detail page with document viewer, the metrics dashboard, the API client module, and the sidebar navigation entry. Admins currently have no way to review submissions, view uploaded identity documents, or issue approve/reject/request-info decisions through the UI.

- **Type**: Feature (pure frontend)
- **Priority**: High — blocks every other KYC review ticket (KYC-002 through KYC-009 all surface results through this dashboard)
- **Status**: Backend implemented; frontend not yet built
- **Persona**: KYC reviewer (ADMIN/ROOT role) and compliance lead
- **Dependencies**: None — existing backend endpoints require no changes. All downstream KYC tickets (KYC-002, KYC-003, KYC-004, KYC-005, KYC-006, KYC-008, KYC-011) will add panels and tabs inside this dashboard.
- **Cross-references**: [[KYC-002]] adds extraction results panel, [[KYC-003]] adds liveness call panel, [[SECOPS-007]] governs dev/prod parity (S3 presigned URLs via moto in dev, real S3 in prod).

## 2. Current-State Investigation

### 2.1 Backend: Fully Implemented

All seven admin endpoints are live and registered (`app/main.py:565` — `app.include_router(kyc_cases_router)`). The router prefix is `/v1/kyc/cases` (`app/routers/kyc_cases.py:69`).

| Endpoint | Function | Line |
|---|---|---|
| `GET /admin/queue` | `list_admin_kyc_queue` | `kyc_cases.py:974` |
| `GET /admin/metrics` | `get_admin_kyc_metrics` | `kyc_cases.py:1012` |
| `POST /admin/purge/run` | `run_admin_kyc_purge` | `kyc_cases.py:1038` |
| `GET /admin/cases/{case_id}` | `get_admin_kyc_case_detail` | `kyc_cases.py:1062` |
| `POST /admin/cases/{case_id}/request-info` | `admin_request_more_info` | `kyc_cases.py:1086` |
| `POST /admin/cases/{case_id}/approve` | `admin_approve_case` | `kyc_cases.py:1263` |
| `POST /admin/cases/{case_id}/reject` | `admin_reject_case` | `kyc_cases.py:1274` |

**Auth guard** (`kyc_cases.py:986`): `normalize_role(user.role) not in {Role.ADMIN, Role.ROOT}` → raises `kyc_admin_role_required` (403). Scoped admins must be the assigned reviewer (`_is_scoped_admin_for_case`, `kyc_cases.py:84`); ROOT bypasses scope checks.

**Queue endpoint** (`kyc_cases.py:974–1009`) accepts `status`, `assignee_admin_sub`, `min_waiting_seconds`, `risk_tier`, `cursor`, `limit` query params. Calls `STORE.list_admin_queue()` (`kyc_cases.py` service at line ~646). Returns `KycAdminQueueEnvelope` with `items[]` and `next_cursor`.

**Case detail endpoint** (`kyc_cases.py:1062`) calls `_build_admin_case_detail(case)` which assembles `files_ref`, `questionnaire_ref`, `signature_ref`, `ticket_ref`, `decision_state`, and `timeline` (pulled from the audit log). Returns `KycAdminCaseDetailEnvelope`.

**Decision endpoint** (`kyc_cases.py:1165`) — the shared `_admin_decide_case` helper validates `expected_version`, `reason_codes` (must be non-empty), and `note` (min 5 chars before trimming). It then calls `STORE.apply_admin_decision()` with OCC via DynamoDB `ConditionExpression`. After approval, it also calls `create_review_schedule` (KYC-016, `kyc_cases.py:1249`) to schedule the first periodic review.

**Metrics endpoint** (`kyc_cases.py:1012`) calls `STORE.get_metrics_snapshot(stale_after_seconds)` and augments with `_SUBMIT_GUARD_FAILURES` (in-process counter dict) and the ticket-sync snapshot from `get_kyc_sync_snapshot()`. Returns funnel counts per status, review latency (p50/p90/p99 in seconds), stale queue count.

**DynamoDB tables** (`scripts/local-ddb-init.py:91–96`): `kyc_cases` table with two GSIs — `owner-updated-index` (PK=`OWNER#{sub}`) and `status-updated-index` (PK=`STATUS#{status}`, SK=`UPDATED#{ts}#{case_id}`). The `created_at`/`updated_at` sort key attributes must be declared `attr_types={"updated_at": "N"}` (already present).

**KYC settings** (`app/core/settings.py:1065–1072`): `kyc_cases_table_name`, `kyc_status_updated_index_name`, `kyc_owner_updated_index_name`, `kyc_retention_days`.

### 2.3 File Access for Document Viewer

KYC files are referenced by `path` (a file-manager path) stored in `case.files_ref[].path`. In prod, URLs are real AWS S3 presigned. The 15-minute presigned URL expiry requires a `refetchOnMount` strategy or re-fetch on 403.

## 3. Gap / Threat Analysis

### 3.1 Missing Frontend Pieces

Every user story is blocked on the absent pages. Specifically:

1. **Queue page** — no way to see pending submissions, apply filters, or paginate.
2. **Case detail page** — no document viewer, no side-by-side comparison of uploaded files, no approve/reject/request-info dialogs, no timeline.
3. **Metrics dashboard** — compliance lead cannot monitor queue depth, approval rate, or latency SLAs.
4. **Document viewer component** — identity document review requires zoom, rotate, and fullscreen because photos are often angled or small.

### 3.2 Compliance and Legal Edge Cases

- **Optimistic concurrency conflicts**: Two admins loading the same case and both clicking Approve must produce a 409 for the second. The `expected_version` field in all POST bodies enforces this at the backend. The frontend dialog must surface the 409 as "This case was modified by another reviewer — please reload" rather than swallowing the error.
- **Reviewer note minimum length**: The backend enforces `len(note.strip()) >= 5` (`kyc_cases.py:1181`). The frontend form must validate this client-side to avoid a failed server round-trip.
- **Reason codes required**: Backend rejects `reason_codes = []` (`kyc_cases.py:1179–1180`). At least one checkbox must be selected.
- **Scoped admin scope check**: A Charlie (ADMIN) who is not assigned to a case receives 403 from `/admin/cases/{id}`. The queue page must only show cases assigned to the current admin (or all cases for ROOT).
- **Audit trail**: Every admin action is written to the audit log via `_audit_state_transition` and also synced to the linked helpdesk ticket via `_ensure_decision_ticket_updates`. The timeline on the case detail page must display these events in chronological order.
- **Purged cases**: `_is_purged_case` checks `case.review.purged_at`. Purged cases must not appear in the queue and attempting to view one should show a "case not available" state.
- **PII exposure**: `case.user_sub` is an email address (e.g., `e2e_alice@test.local`). File paths and questionnaire content visible in the detail view may contain PII. The admin detail page is already behind ADMIN/ROOT role check, but reviewer notes and reason codes written via this UI become part of the audit record — they must not contain free-form PII about the reviewer.

## 4. Proposed Design / Fix

### 4.1 KycQueuePage (`frontend/src/pages/admin/KycQueuePage.tsx`)

Use `useQuery` with key `["kyc", "admin", "queue", filters]` calling `fetchKycQueue`. Polling interval: none (manual refresh button). Cursor-based pagination: store `cursorStack: string[]` in local state; push on "Next", pop on "Previous".

Filter bar components (shadcn/ui `Select`, `Input`, `Slider`):
- `status` — select among `submitted | under_review | needs_more_info | all`
- `risk_tier` — select among `standard | enhanced | high_risk | all`
- `assignee_admin_sub` — text input (empty = all)
- `min_waiting_seconds` — slider 0–172800 (48 h)

DataTable columns: `kyc_case_id` (link), `user_sub`, `status` (Badge), `risk_tier` (Badge), waiting time (human-readable from `waiting_seconds`), `assigned_admin_sub` ("Unassigned" if null), View button.

Empty state: "No cases match the current filters." Clicking a row navigates to `/admin/kyc/cases/{kyc_case_id}`.

### 4.2 KycCaseDetailPage (`frontend/src/pages/admin/KycCaseDetailPage.tsx`)

Two-column layout (shadcn/ui `Grid`). Left 60%: `DocumentViewer`. Right 40%: stacked `CaseInfoPanel`, `CaseActionPanel`, `CaseTimeline`.

**CaseInfoPanel** fields: `user_sub`, status Badge, intake_profile, created_at (formatted), questionnaire status, signature status. Read from `useQuery(["kyc", "admin", "case", caseId], () => fetchKycCaseDetail(caseId))`.

**CaseActionPanel** — buttons shown only when case is in actionable status (`submitted | under_review | needs_more_info`):
- Approve → `ApproveDialog` (multi-select reason codes + notes textarea, submit calls `approveKycCase`)
- Reject → `RejectDialog` (same structure)
- Request Info → `RequestInfoDialog` (checklist of items, notes)

All three dialogs read the current `version` from the case detail response and include it as `expected_version`. On 409 conflict: show toast "Case updated by another reviewer — refreshing" and invalidate the query. On success: invalidate `["kyc", "admin", "queue"]` and `["kyc", "admin", "case", caseId]` — the queue page will update in the background.

**CaseTimeline** — map `case.timeline[]` to `TimelineItem` components. Each item shows icon keyed by `event_type` (e.g., `case_created`, `file_attached`, `case_submitted`, `kyc_admin_decision`), formatted timestamp, and actor. Expandable details JSON using shadcn/ui `Collapsible`.

### 4.3 DocumentViewer Component (`frontend/src/components/shared/DocumentViewer.tsx`)

Props: `files: KycFileRef[]` (type, path, verification_state).

State: `activeTab: string`, `zoom: number` (1.0–4.0), `rotation: number` (0/90/180/270).

Image URL: fetched via `useQuery(["file-url", path], () => api.get("/ui/files/download?path="+path))`. URL cached 5 minutes (`staleTime: 300_000`). On 403 (presigned URL expired): `refetchOnWindowFocus: true`.

Controls: zoom in/out buttons, rotate CW/CCW (90°), fullscreen toggle (CSS `position: fixed; inset: 0; z-index: 50`). Scroll wheel zoom via `onWheel` event handler.

`VerificationStateBadge` overlay (top-right corner of image): `pending` = gray, `verified` = green, `rejected` = red.

Tab bar labels: `selfie` → "Selfie", `id_front` → "ID Front", `id_back` → "ID Back", `proof_of_address` → "Proof of Address". Tabs only shown for file types present in `files[]`.

### 4.4 KycMetricsDashboard (`frontend/src/pages/admin/KycMetricsDashboard.tsx`)

`useQuery(["kyc", "admin", "metrics"], () => fetchKycMetrics(48*3600), { staleTime: 60_000 })`.

Components:
- **FunnelChart** — horizontal bar chart (native `<div>` with CSS width percentage, no chart library dependency) showing counts per status in order: draft → submitted → under_review → needs_more_info → approved → rejected → expired.
- **ApprovalRateCard** — `approved / (approved + rejected) * 100`, shown as percentage with color: green ≥ 80%, yellow 50–79%, red < 50%.
- **LatencyCards** (3) — p50/p90/p99 in seconds, human-readable (e.g., "14 h 24 m"). Color: green < 24 h, yellow 24–48 h, red > 48 h.
- **StaleQueueAlert** — shown when `stale_queue_count > 0`: "⚠️ {N} cases have been waiting over 48 hours."

### 4.5 Dev/Prod Parity (SECOPS-007)

No new AWS dependencies. Document presigned URLs already use moto in dev (`app/core/dev_s3.py`). The frontend fetches presigned URLs from `/ui/files/download` — the same endpoint works in both environments. No additional mock needed.

The backend `GET /admin/metrics` endpoint reads from DynamoDB Local in dev and from real DynamoDB in prod — transparent to the frontend.

### 4.6 Alternatives Considered

- **Merge into existing admin pages** — rejected; KYC review is a distinct workflow requiring a dedicated navigation section.
- **Use a charting library** — Recharts or Chart.js for the funnel chart. Rejected for the metrics dashboard due to bundle size; simple CSS bars are sufficient. The liveness/extraction sub-tickets may add a real chart library later.
- **Real-time SSE updates** — rejected for v1; polling on focus-regain (`refetchOnWindowFocus`) is sufficient. SSE could be added in KYC-011 (webhooks) as a background notification.

All run with moto + in-memory DDB, no dev stack required.

- `test_list_admin_queue_returns_submitted_cases` — seed two cases (one draft, one submitted), assert queue returns only submitted.

### 5.2 Playwright E2E Tests (`frontend/e2e/kyc-admin-dashboard.spec.ts`)

Sections 150–155 (as designed in the ticket spec). Key patterns:
- Auth: `injectAuth(page, "root")` for admin pages; `page.request.get` with cookie for API calls.
- CSRF: `x-csrf-token` header from `sessions["root"].csrf_token` for all POST requests.
- Seed a KYC case: create case as Alice via API, attach files, submit — then view as Root.
- Test 155.2: Approve dialog — fill reason code checkboxes + notes textarea, click Confirm. `waitForResponse` on the approve endpoint. Assert status Badge updates to "approved" without page reload (React Query invalidation).

Test 155.6 (concurrent conflict): Open two browser contexts as Root; both load the same case detail. First approves successfully. Second submits with the stale `expected_version` — assert toast "Case updated by another reviewer" appears.

All E2E tests run fully offline: moto provides S3 presigned URLs (`/mock/s3/...` path), DynamoDB Local stores cases.

### 5.3 Manual QA Steps

1. `just restart` — clean database, re-seed sessions.
2. As Alice, create a KYC case via `POST /v1/kyc/cases`, attach `selfie`/`id_front`/`id_back` files, link questionnaire + signature, submit.
3. Log in as Root in the browser, navigate to `/admin/kyc`.
4. Verify the submitted case appears in the queue. Apply `status=submitted` filter.
5. Click the case row → verify document tabs render images (moto presigned URL).
6. Click Approve → select reason codes → type a note → Confirm. Verify toast + status badge change.
7. Navigate to `/admin/kyc/metrics` — verify funnel counts include the newly approved case.

### 5.4 Observability

Backend already emits `audit_event` calls for every admin action (`kyc_admin_case_detail_read`, `kyc_admin_decision`, `kyc_admin_request_info`, `kyc_admin_queue_listed`). Frontend should track client-side errors in React Query's `onError` callbacks and log to the platform's telemetry endpoint.

### 5.5 Rollout

Feature flag `KYC_ADMIN_DASHBOARD_ENABLED` in `app/core/settings.py` (default `false` prod, `true` dev). Frontend routes gated by flag checked from `GET /ui/config`. Deploy sequence:

1. Merge frontend code with flag `false` — routes exist but are hidden.
2. Enable in staging, run E2E suite.
3. Enable for ROOT users in prod (soft launch, 1 week).
4. Enable for ADMIN users after ROOT testing passes.

**Rollback**: Set `KYC_ADMIN_DASHBOARD_ENABLED=false`. No data migration needed — all data is read-only over existing DDB records.

**Effort**: M (7–10 days) — backend is done; work is entirely frontend scaffolding, component build, and E2E.
