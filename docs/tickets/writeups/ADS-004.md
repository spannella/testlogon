# ADS-004: Ad Serving Engine — Investigation & Implementation Write-up

## 1. Summary & Classification

ADS-004 is the central real-time ad selection engine that integrates all upstream ADS tickets into a unified serve path. When any ad surface (newsfeed, broadcast, VOD) needs an ad, it calls `serve_ad()` with viewer and content context. The engine loads active campaigns, runs targeting evaluation, checks frequency caps and budgets, ranks candidates by bid CPM, selects a creative by rotation weight, and returns the creative with tracking URLs. Impression, click, skip, and complete events are tracked via `track_ad_event()`.

- **Type**: feature (integration layer)
- **Priority**: High — ADS-005, ADS-006, ADS-007, ADS-008 all depend on this engine
- **Status**: Implemented — `app/services/ad_serving.py` is fully implemented and wired into `app/routers/ads.py`
- **Owning area**: Advertising platform — serving engine subsystem
- **Affected personas**: all viewers (served ads), advertisers (budget consumed), creators (revenue credited), platform (fill rate)
- **Cross-references**: ADS-001 (campaigns), ADS-002 (approved creatives), ADS-003 (targeting + creator prefs), ADS-005 (newsfeed), ADS-006 (broadcast), ADS-007 (billing integration), ADS-008 (analytics), ADS-009 (user prefs), ADS-014 (fraud detection), ADS-015 (affiliate/promo on serve response)
- **Dev/prod parity**: [[SECOPS-007]] — frequency caps and impressions go to DDB Local in dev; GeoIP mock returns "US" in dev; same `serve_ad()` code path in both environments; `AD_SERVING_ENABLED` flag gates the engine

## 2. Current-State Investigation (what exists today)

### 2.1 Serving engine — `app/services/ad_serving.py`

Fully implemented. The file is the authoritative serving engine:

**`serve_ad(surface, content_type, creator_id, content_id, slot_type, user_id, user_context)`**:
1. Calls `get_creator_ad_settings(creator_id)` — returns `{"fill_reason": "creator_ads_disabled"}` if `allow_ads=False`
2. Calls `list_campaigns_by_status("active")` — returns house ad if list is empty
3. For each active campaign: (a) calls `is_advertiser_blocked(creator_id, account_id)`, (b) calls `_has_budget(campaign)`, (c) calls `list_targeting_sets(campaign_id)` then `evaluate_targeting()` for each set, (d) calls `_is_frequency_capped(user_id, campaign_id)`
4. Scores candidates: `bid_cpm = campaign.get("bid_cpm_cents", 500)` × relevance (mock: 1.0)
5. Sorts by score descending, selects winner
6. Calls `_weighted_random_creative(creatives)` using `rotation_weight` field
7. Returns full creative payload with tracking URLs

**`track_ad_event(event, creative_id, campaign_id, account_id, surface, slot_type, content_id, creator_id, user_id, ip_address, user_agent, view_time_ms, geo_country)`**:
- Calls `record_ad_impression()` from `app/services/ad_placement.py:222`
- On `event="impression"`: calls `_increment_frequency_cap(user_id, campaign_id)` — atomic ADD on all three windows (1h, 24h, 7d)
- Returns `{"ok": True, "event_id": ...}`

The router at `ads.py:331–365` exposes `POST /ui/ads/serve` and `POST /ui/ads/track` (body-based parameters, not query-string). The `track_ad_event_endpoint` at line 345 also extracts `ip_address` from `X-Forwarded-For` header and `user_agent` for fraud detection integration.

**`get_serving_stats(campaign_id)`** at `GET /ui/ads/stats/{campaign_id}` — returns aggregate impression/click/spend data; used by ADS-008 analytics.

### 2.2 Frequency cap table — `AdFrequencyCaps`

`scripts/local-ddb-init.py:1110–1119` (noted: the line numbers shown in the grep output were for `AdTargeting`; `AdFrequencyCaps` follows immediately). The table uses TTL on `expires_at` field. Table handle at `app/core/tables.py:178` as `T.ad_frequency_caps`. Setting at `app/core/settings.py:1578`.

`_is_frequency_capped` makes 3 `GetItem` calls (one per window: 1h, 24h, 7d). `_increment_frequency_cap` makes 3 `UpdateItem` calls with atomic ADD and TTL set. Default limits: `DEFAULT_FREQ_CAPS = {"1h": 3, "24h": 10, "7d": 30}`.

### 2.3 Budget checking — `_has_budget(campaign)`

Checks campaign dict fields:
- `budget_type="lifetime"`: `lifetime_spent_cents >= budget_cents` → excluded
- `budget_type="daily"`: `spent_today_cents >= budget_cents` → excluded (uses the same `budget_cents` field for daily cap)

Note: there is no daily reset mechanism for `spent_today_cents`. This field must be reset at midnight by a background job. Currently no cron or scheduled task resets this field — it will accumulate indefinitely unless a daily reset is implemented (see Gap 3.1.1 below).

### 2.4 House ad fallback

`HOUSE_AD` dict at `ad_serving.py:30–39` with `"is_house_ad": True` — a static platform self-promotion. Returned via `_house_ad_response(reason)` when no paid campaigns match or when the campaign list is empty. Fill reason strings are logged in the response for diagnostics.

### 2.5 Creative selection

`_weighted_random_creative(creatives)` uses `random.choices(creatives, weights=weights, k=1)` for weighted selection. Falls back to `random.choice()` if all weights are 0.

### 2.6 Router endpoints

- `POST /ui/ads/serve` (`ads.py:331–342`) — requires `require_ui_session`, accepts `AdServeRequestIn` body
- `POST /ui/ads/track` (`ads.py:344–365`) — requires `require_ui_session`, accepts `AdTrackEventIn` body; extracts real IP from `X-Forwarded-For` for fraud detection
- `GET /ui/ads/stats/{campaign_id}` (`ads.py:367–371`) — ownership-gated campaign stats

Both serve and track endpoints are registered under `/ui/ads/` — they are cookie-auth + CSRF-protected. There is no unauthenticated beacon endpoint.

### 2.7 `AdServeRequestIn` and `AdTrackEventIn` models

`AdServeRequestIn` in `app/models.py`: `surface` pattern `^(newsfeed|broadcast|vod)$`, `creator_id`, `content_id`, `slot_type` pattern `^(pre_roll|mid_roll|overlay|sponsored_post|broadcast_preroll|broadcast_midroll)$`.

`AdTrackEventIn`: `event` pattern `^(impression|click|skip|complete)$`, plus `user_agent`, `view_time_ms`, `geo_country` — additional fields passed through to fraud detection in ADS-014.

### 2.8 Dev vs prod behavior (SECOPS-007)

The `AD_SERVING_ENABLED` flag at `app/core/settings.py:1575` defaults to `true` in dev (env var `AD_SERVING_ENABLED=1`). When false, the serve endpoint returns `{"filled": False, "fill_reason": "serving_disabled"}` immediately. Frequency cap and impression writes go to DDB Local in dev via the standard `T.*` table handle pattern. No external services are called during ad serving — the campaign/creative/targeting data is all in DDB, the relevance scoring is hardcoded to 1.0, and GeoIP is mocked.

## 3. Gap / Threat Analysis

### 3.1 Critical gaps

1. **No daily `spent_today_cents` reset** — `_has_budget` checks `spent_today_cents >= budget_cents` for daily-budget campaigns, but there is no scheduled job that resets `spent_today_cents` to 0 at midnight UTC. A `daily` budget campaign will exhaust its daily cap and never resume serving. This is a correctness bug that blocks daily-budget advertisers from using the platform. Fix: a background task (cron or FastAPI `lifespan` startup scheduler) that scans active campaigns with `budget_type="daily"` and resets `spent_today_cents=0, daily_reset_date=today` once per day.

2. **`list_campaigns_by_status("active")` is a full table scan** — `ad_campaigns` PK is `ACCT#{account_id}`, SK is `CAMPAIGN#{campaign_id}`. There is no `ByStatusCreatedAt` GSI usage for the active campaigns list in the serving engine. The `ByCampaignId` GSI exists but partitions by `campaign_id`. At scale with thousands of campaigns across many accounts, a scan will be slow and expensive. The `ByStatusCreatedAt` GSI (defined on `AdCampaigns` with partition key `status`) is the correct access pattern — `Query(IndexName="ByStatusCreatedAt", KeyConditionExpression=Key("status").eq("active"))`.

3. **`bid_cpm_cents` not yet a campaign field** — `_has_budget` and scoring reference `campaign.get("bid_cpm_cents", 500)` but `bid_cpm_cents` is not in `CampaignCreateIn` or `CampaignOut` in `app/models.py` (ADS-001 spec). All campaigns default to 500 CPM. True campaign-level bid support requires adding `bid_cpm_cents` to the campaign model (ADS-007 scope).

4. **`record_ad_impression` from `ad_placement.py` called inside `track_ad_event`** — `ad_placement.record_ad_impression` was designed for VOD; it expects `video_id`, not a generic `content_id`. The call at `ad_serving.py` passes `content_id=content_id` as the `video_id` argument — this works functionally (it's stored as a string) but the `ad_impressions` table SK is `VIDEO#{video_id}#{user_id}#{ts}`, which will contain non-video content IDs for newsfeed/broadcast impressions. This is a naming inconsistency; for ADS-008 analytics, queries for newsfeed impressions will need to filter by `surface` field, not by the SK prefix.

### 3.2 Minor gaps

5. **No rate limiting on serve endpoint** — the ticket spec mentions 60 req/min per user but no rate limiter is applied to `POST /ui/ads/serve`. The existing `app/services/rate_limiter.py` token-bucket infrastructure should be applied.

6. **`_is_frequency_capped` makes 3 sequential GetItem calls** — for every campaign candidate. With 50 active campaigns this is up to 150 DDB reads per serve request. Batch GetItem or a per-user frequency cap cache (Redis or in-memory with TTL) would reduce this significantly.

7. **No actual advertiser debit on impression** — `track_ad_event` calls `record_ad_impression` which credits creator revenue via `_credit_ad_revenue` (the VOD implementation), but does not debit the advertiser's `balance_cents` or `lifetime_spent_cents`. This is ADS-007's responsibility; the current implementation tracks impressions without financial settlement.

## 4. Proposed Design / Fix

### 4.1 Daily budget reset task (critical)

Add to `app/main.py` startup scheduler (or as a cron via the existing pattern in `scripts/dev.sh`):

```python
async def daily_budget_reset():
    """Reset spent_today_cents for all daily-budget campaigns at midnight UTC."""
    import asyncio
    from datetime import datetime, timezone
    while True:
        now = datetime.now(timezone.utc)
        # Sleep until next midnight UTC
        next_midnight = now.replace(hour=0, minute=0, second=0, microsecond=0)
        if next_midnight <= now:
            next_midnight = next_midnight.replace(day=now.day + 1)
        await asyncio.sleep((next_midnight - now).total_seconds())
        # Scan active daily-budget campaigns and reset
        camps = list_campaigns_by_status("active")
        for c in camps:
            if c.get("budget_type") == "daily":
                T.ad_campaigns.update_item(
                    Key={"pk": c["pk"], "sk": c["sk"]},
                    UpdateExpression="SET spent_today_cents = :z, daily_reset_date = :d",
                    ExpressionAttributeValues={":z": 0, ":d": now.strftime("%Y-%m-%d")},
                )
```

In dev, this loop runs in the uvicorn event loop. In prod, an EventBridge scheduled rule or the same in-process loop works. SECOPS-007: same code path; DDB endpoint differs.

### 4.2 Use `ByStatusCreatedAt` GSI for active campaigns

Replace the implicit scan in `list_campaigns_by_status` with a GSI query:

```python
def list_campaigns_by_status(status: str) -> list[dict]:
    resp = T.ad_campaigns.query(
        IndexName="ByStatusCreatedAt",
        KeyConditionExpression=Key("status").eq(status),
        ScanIndexForward=False,
    )
    return resp.get("Items", [])
```

The `ByStatusCreatedAt` GSI with `attr_types={"created_at": "N"}` already exists in the table definition.

### 4.3 Rate limiting on serve endpoint

Add to `POST /ui/ads/serve` in `ads.py`:

```python
from app.services.rate_limiter import check_rate_limit
rate_key = f"ad_serve:{ctx['user_sub']}"
if not check_rate_limit(rate_key, limit=60, window_seconds=60):
    raise HTTPException(429, "Too many ad requests")
```

### 4.4 Batch frequency cap checks

Replace the 3-GetItem per campaign with a BatchGetItem for all windows simultaneously:

```python
def _is_frequency_capped(user_id: str, campaign_ids: list[str]) -> set[str]:
    """Returns set of campaign_ids that are frequency capped for this user."""
    keys = [
        {"pk": {"S": f"USER#{user_id}"}, "sk": {"S": f"CAMPAIGN#{cid}#{w}"}}
        for cid in campaign_ids for w in DEFAULT_FREQ_CAPS
    ]
    # BatchGetItem(Keys=keys) ...
```

This collapses N×3 GetItems to a single BatchGetItem call.

### 4.5 Dev/prod parity (SECOPS-007)

The daily reset task must not make AWS-specific calls; it uses `T.ad_campaigns` which routes to DDB Local in dev. The same background task runs in both environments. No mock needed for the task itself.

The `AD_SERVING_ENABLED` flag (`True` in `.env.local.example`) ensures the engine is exercisable end-to-end in dev without any AWS. `just restart` recreates tables and seeds E2E sessions, providing the pre-conditions (active campaigns, approved creatives) for E2E tests to exercise the full serve path.

### 5.5 Rollout

- Feature flag: `AD_SERVING_ENABLED` (default `true` in dev/`.env.local.example`)
- Phase 1: shadow mode — serve_ad called, result logged but house ad always returned to client
- Phase 2: gradual rollout — 10% → 50% → 100% of users see real ads
- Phase 3: remove shadow-mode flag; `DEV_AD_CREATIVES` fallback remains in `ad_placement.py` for VOD
- Rollback: `AD_SERVING_ENABLED=false` — immediate fallback, no data loss
