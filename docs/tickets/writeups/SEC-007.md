# SEC-007: Production Exposure & Config Hardening (Dev/Mock Surfaces, Headers) — Investigation & Implementation Write-up

> ~5 pages. Read the real code before writing; cite `file:line`. Be concrete, not generic.

## 1. Summary & Classification

Several development-only or sensitive backend surfaces are either fully exposed in production or rely solely on per-request runtime gates rather than not being registered at all. Additionally, default security posture settings (cookie `secure` flag, CORS, mass-assignment guards) are weaker than production-safe defaults. Together these create a collection of medium-to-high severity exposure paths.

- **Type**: hardening / security-fix
- **Priority/Severity**: Medium-High
- **Status**: Open
- **Owning area**: `app/main.py`, `app/routers/s3_mock.py`, `app/core/settings.py`, `app/models.py`, `app/routers/csv_export.py`, `app/routers/webhooks.py`
- **Attacker class**: 🌐 any network-reachable client (unauthenticated for mock-S3 and `/internal/ffmpeg-status`); ⚙️ config/deployment errors
- **Cross-references**: [[SEC-016]] (security headers, CSP), [[SEC-008]] (IP resolution), [[SEC-005]] (IDOR)

## 2. Current-State Investigation (what exists today)

### 2.1 Mock routers registered unconditionally (`app/main.py:443-452`)

```python
443    app.include_router(ccbill_mock_router)
444    app.include_router(google_calendar_mock_router)
445    app.include_router(google_drive_mock_router)
447    app.include_router(apple_caldav_mock_router)
448    app.include_router(jira_mock_router)
449    app.include_router(paypal_mock_router)
450    app.include_router(s3_mock_router, prefix="/mock/s3")
452    app.add_api_route("/mock/s3", _s3_list_buckets, …)
```

Every mock router is imported unconditionally at module load time and registered with `app.include_router` on every startup — dev and prod. The per-request protection varies:

- **`s3_mock_router` (`app/routers/s3_mock.py`)**: The docstring says "Only active in DEV_MODE=1" but the router has **no authentication and no dev-mode check**. `GET /mock/s3/{bucket}/{key}` calls `_s3.get_object(Bucket=bucket, Key=key)` directly. In dev this reads from the moto in-process store; in prod with real AWS credentials this would read from real S3 buckets. Even in dev, any unauthenticated caller who guesses a key path (e.g., `{user_sub}/objects/{uuid}`) can download files without owning them.
- **CCBill/Google/PayPal/Caldav/Jira mocks**: These have per-handler `_ensure_mock_enabled()` or similar checks, but the routes are still advertised in `GET /openapi.json` in prod, leaking implementation details.

### 2.2 `/docs`, `/openapi.json`, `/redoc` exposed in prod (`app/main.py:384`)

```python
384    app = FastAPI(title="Security Backend (refactored)", version="0.1.0", redirect_slashes=False)
```

`FastAPI` defaults: `docs_url="/docs"`, `openapi_url="/openapi.json"`, `redoc_url="/redoc"`. None are disabled. The full API schema (all endpoints, input/output models, auth requirements) is publicly accessible in production with no authentication. This gives attackers a complete attack surface map.

### 2.3 `/internal/ffmpeg-status` unauthenticated (`app/main.py:395-398`)

```python
395    @app.get("/internal/ffmpeg-status")
396    def ffmpeg_status():
397        from app.services.ffmpeg_manager import validate_ffmpeg
398        return validate_ffmpeg()
```

No `Depends(require_ui_session)`, no dev-mode gate. The response reveals the ffmpeg binary path and version, useful for exploit targeting. The `/internal/` prefix suggests it was intended as an internal route but there is no network or auth guard enforcing that.

### 2.4 Cookie `secure` defaults to `False` (`app/core/settings.py:92`)

```python
92    ui_cookie_secure: bool = os.environ.get("UI_COOKIE_SECURE", "0") not in ("0", "false", "False")
```

Default is `"0"` → `False`. Unless the operator explicitly sets `UI_COOKIE_SECURE=1`, all session cookies (`ui_session`, `ui_csrf`, `ui_access_token`, `ui_device`) are sent over HTTP. In a prod deployment behind TLS, the first plain-HTTP request (e.g., a redirect) can expose the cookies.

### 2.5 CORS wildcard with credentials (`app/main.py:364-381`)

```python
365    raw_origins = os.environ.get("CORS_ALLOW_ORIGINS", "*")
371    if "*" in allow_origins:
372        allow_origins = [o for o in allow_origins if o != "*"]
373        allow_origin_regex = allow_origin_regex or ".*"
375    return {
376        "allow_origins": allow_origins,
377        "allow_origin_regex": allow_origin_regex,
378        "allow_credentials": _to_bool(os.environ.get("CORS_ALLOW_CREDENTIALS"), default=True),
```

When `CORS_ALLOW_ORIGINS` is not set (the default in dev, and potentially forgotten in prod), it defaults to `"*"`. The code then converts that to an `allow_origin_regex=".*"` so Starlette echoes the `Origin` header. Combined with `allow_credentials=True`, this means **any origin can make credentialed cross-origin requests**. A malicious page at `evil.example.com` can `fetch("https://app.example.com/ui/profile", {credentials:"include"})` and read the response.

### 2.6 Mass assignment — `DocConfigIn` `extra="allow"` (`app/models.py:7371`)

```python
7370    ignored_paths: List[str]
7371    model_config = ConfigDict(extra="allow")
```

`DocConfigIn` (the agent documentation config model) accepts and persists any extra fields provided in the request body. An attacker or misconfigured client can inject arbitrary keys into the DynamoDB item, potentially poisoning downstream logic that iterates over the record.

### 2.7 CSV export — no rate limit (`app/routers/csv_export.py:22-46`)

`GET /ui/export/csv` streams the entire `billing_ledger`, `contacts`, or `questionnaire_responses` dataset for the authenticated user with no rate-limit or per-window cap. This enables a bulk exfiltration run: an attacker who hijacks a session can automate repeated CSV pulls with wide date windows to exfiltrate every billing record and contact.

### 2.8 Webhook `rotate-secret` returns plaintext secret (`app/routers/webhooks.py:164-173`)

```python
170    new_secret = rotate_secret(ctx["user_sub"], endpoint_id)
171    if not new_secret:
172        …
173    return {"secret": new_secret}
```

The new webhook signing secret is returned in every rotate response, in plaintext, with no show-once mechanism. Any session that can replay or replay-log the response (e.g., a browser history, a shared network recording) obtains the secret.

### 2.9 `_security_headers_middleware` not wired into the middleware stack (`app/main.py:348-356`)

The function is defined:

```python
348  def _security_headers_middleware(default_csp: str):
349      async def _middleware(request: Request, call_next):
350          response = await call_next(request)
351          response.headers.setdefault("Content-Security-Policy", default_csp)
352          response.headers.setdefault("X-Content-Type-Options", "nosniff")
353          response.headers.setdefault("X-Frame-Options", "DENY")
354          response.headers.setdefault("Referrer-Policy", "strict-origin-when-cross-origin")
355          return response
356      return _middleware
```

But `_security_headers_middleware` is never added via `app.add_middleware` or `app.middleware("http")`. The headers `Content-Security-Policy`, `X-Frame-Options`, and `Referrer-Policy` are therefore **never sent** on any response. `X-Content-Type-Options` is also absent except where set manually in individual routes. Additionally `Strict-Transport-Security` (HSTS) is missing from the middleware entirely.

**Dev vs. prod:** All items above are present identically in dev and prod. The dev stack simply doesn't face external adversaries; prod does. The key risk is a prod deployment where `DEV_MODE` was left as `1` or `CORS_ALLOW_ORIGINS` was not set.

## 3. Gap / Threat Analysis

### 3.1 Unauthenticated mock-S3 read — any-file exfiltration

An attacker who knows (or can enumerate) S3 key patterns (`{user_sub}/objects/{uuid}`) can issue `GET /mock/s3/files-bucket/{user_sub}/objects/{uuid}` with no credentials. In dev this reads from moto. In prod (if the mock is not gated), it reads from real S3 with the app's IAM credentials. Even in dev, the route leaks files across users.

### 3.2 `/openapi.json` — full attack surface enumeration

A prod deployment exposes every endpoint path, HTTP method, parameter name, and response model. Attackers use this to build automated scanners targeting specific endpoints.

### 3.3 CORS wildcard + credentials — account takeover via CSRF-equivalent

Any attacker-controlled origin can make credentialed API calls. While CSRF is separately protected by `x-csrf-token` headers (for cookie-auth POST), GET endpoints that return sensitive data (e.g., `GET /ui/profile`, `GET /ui/api-keys`) are fully readable cross-origin.

### 3.4 Insecure cookies — cookie exfiltration over HTTP

Without `Secure`, a misconfigured HTTP endpoint (or redirect before HTTPS upgrade) leaks session cookies in the clear. Especially dangerous on shared networks.

### 3.5 Mass assignment — DDB record poisoning

Injecting unknown keys into a DDB item can corrupt agent configuration, disable doc-gen runs, or plant unexpected values if downstream code later grows new attribute checks.

### 3.6 CSV exfiltration — bulk data theft

A stolen or long-lived session can run unlimited bulk CSV exports. Combined with a wide date window this extracts every billing transaction and contact in one request cycle.

**Code sites that must change**:
- `app/main.py:383-452` — conditional router registration, disable docs in prod
- `app/main.py:395-398` — gate `/internal/ffmpeg-status`
- `app/main.py:364-381` — CORS default
- `app/core/settings.py:92` — cookie secure default
- `app/models.py:7371` — `extra="allow"` → `"ignore"`
- `app/routers/csv_export.py` — add rate limit
- `app/routers/webhooks.py:173` — show-once secret handling

## 4. Proposed Design / Fix

### 4.1 Register mock routers conditionally

**`app/main.py`** — wrap all mock router registrations in an `if _S.dev_mode:` block:

```python
if _S.dev_mode:
    app.include_router(ccbill_mock_router)
    app.include_router(google_calendar_mock_router)
    app.include_router(google_drive_mock_router)
    app.include_router(apple_caldav_mock_router)
    app.include_router(jira_mock_router)
    app.include_router(paypal_mock_router)
    app.include_router(s3_mock_router, prefix="/mock/s3")
    app.add_api_route("/mock/s3", _s3_list_buckets, methods=["GET"], include_in_schema=False)
```

Additionally, add a minimal auth+ownership check to `s3_mock_router` even in dev mode: require `X-Mock-Owner` header or a session cookie, and verify the `Key` starts with the authenticated user's `user_sub`.

### 4.2 Disable OpenAPI docs in production

```python
docs_url = "/docs" if _S.dev_mode else None
openapi_url = "/openapi.json" if _S.dev_mode else None
redoc_url = "/redoc" if _S.dev_mode else None
app = FastAPI(…, docs_url=docs_url, openapi_url=openapi_url, redoc_url=redoc_url)
```

### 4.3 Gate `/internal/ffmpeg-status`

```python
@app.get("/internal/ffmpeg-status")
def ffmpeg_status(ctx=Depends(require_root_session)):   # or require_admin_session
    from app.services.ffmpeg_manager import validate_ffmpeg
    return validate_ffmpeg()
```

Alternative: move to a `/_internal/` path not exposed through the Vite proxy, relying on network-level restriction.

### 4.4 Default cookie `secure=True` in prod

**`app/core/settings.py:92`** — flip the default to `True` and derive from `dev_mode`:

```python
ui_cookie_secure: bool = os.environ.get("UI_COOKIE_SECURE", "1") not in ("0", "false", "False")
```

Or better, derive from `dev_mode`: `secure = not S.dev_mode` when `UI_COOKIE_SECURE` is unset.

### 4.5 Tighten CORS

**`app/main.py:364-381`** — require explicit origin list in production:

```python
def _build_cors_options() -> dict[str, object]:
    raw_origins = os.environ.get("CORS_ALLOW_ORIGINS", "")
    if not raw_origins and not _S.dev_mode:
        raise RuntimeError("CORS_ALLOW_ORIGINS must be set in production")
    # In dev only, allow wildcard
    if not raw_origins and _S.dev_mode:
        raw_origins = "*"
    …
```

Remove the regex wildcard fallback (`".*"`) entirely; only exact origins should be allowed with credentials.

### 4.6 Fix mass assignment — `DocConfigIn`

**`app/models.py:7371`**:

```python
model_config = ConfigDict(extra="ignore")   # was: extra="allow"
```

Audit all other Pydantic models for `extra="allow"` and change to `"ignore"` or `"forbid"` as appropriate.

### 4.7 Rate-limit CSV export

**`app/routers/csv_export.py`** — add a per-user DynamoDB-backed rate limit before streaming:

```python
from app.services.rate_limit import check_rate_limit
allowed, _, _ = check_rate_limit(
    pk=f"CSV#{ctx['user_sub']}",
    window_seconds=3600,
    max_requests=10,
)
if not allowed:
    raise HTTPException(429, "CSV export rate limit exceeded")
```

### 4.8 Show-once webhook secret

**`app/routers/webhooks.py:164-173`** — store only the hash at rotation time; return the plaintext only once, flag `shown=True` in DDB, and return `null` on subsequent reads:

```python
return {"secret": new_secret, "shown_once": True}
# After this response the stored item has secret_hash only; plaintext is gone
```

Clients who lose the secret must rotate again. This is standard practice (GitHub webhooks, Stripe webhooks).

### 4.9 Wire the security headers middleware

**`app/main.py`** — add the middleware to the stack after the CORS middleware:

```python
DEFAULT_CSP = (
    "default-src 'self'; "
    "script-src 'self'; "
    "style-src 'self' 'unsafe-inline'; "
    "img-src 'self' data: blob:; "
    "connect-src 'self'; "
    "frame-ancestors 'none'; "
    "object-src 'none';"
)
app.middleware("http")(_security_headers_middleware(DEFAULT_CSP))
```

Also add `Strict-Transport-Security: max-age=63072000; includeSubDomains` to the middleware (only when `not _S.dev_mode` to avoid HTTPS enforcement in local dev).

**Dev/Prod parity (SECOPS-007):** `_S.dev_mode` governs all conditional registrations. Dev uses moto/mock services; prod uses AWS. The code paths (rate limit checks, CORS logic, cookie flags) are identical — only the configuration values differ. The HSTS header is explicitly gated on `not dev_mode` to avoid browser HSTS preload issues in local development.

### Alternatives considered

- **Network firewall to block `/mock/*`**: rejected — defence-in-depth; the router should not exist at all in prod.
- **`extra="forbid"` on `DocConfigIn`**: would reject requests with unknown fields with a 422, which is safer but may break existing clients; `"ignore"` is the pragmatic migration step.

## 5. Testing, Verification & Rollout

### pytest unit tests

- `tests/test_main_prod_mode.py`:
  - With `dev_mode=False`: `GET /mock/s3/any-bucket/any-key` returns `404`; `GET /docs` returns `404`; `GET /openapi.json` returns `404`; `GET /internal/ffmpeg-status` returns `403`.
  - CORS with `CORS_ALLOW_ORIGINS="https://app.example.com"`: `OPTIONS` from `evil.example.com` does not receive `Access-Control-Allow-Origin`.
- `tests/test_models_extra_fields.py`:
  - `DocConfigIn(**valid_data, unexpected_field="x")` does not include `unexpected_field` in `.model_dump()`.
- `tests/test_csv_export_rate_limit.py`:
  - Eleventh call within 1 hour returns `429`.
- `tests/test_webhook_rotate_secret.py`:
  - Rotate response contains `secret` string.
  - Calling rotate again returns a new `secret`, not the previous one.

### Playwright E2E

- `frontend/e2e/sec-007-config.spec.ts` (runs in dev-mode=false environment):
  - `page.goto("/docs")` → 404.
  - `page.goto("/mock/s3/test-bucket/test-key")` → 404.
  - Authenticated request to `/internal/ffmpeg-status` with non-admin user → 403.

### Manual QA

1. Set `DEV_MODE=0` locally (update `.env.local`) and restart backend; verify `/docs` returns 404.
2. Verify mock S3 route is unreachable: `curl http://localhost:8000/mock/s3/files-bucket/test` → 404.
3. Confirm cookies have `Secure` flag in browser DevTools when `UI_COOKIE_SECURE=1`.
4. Test CORS: use a different origin in browser fetch → no `Access-Control-Allow-Origin` header.

### Observability

- Log a `config_warning` audit event at startup if `CORS_ALLOW_ORIGINS` is `*` in non-dev mode.
- Alert on `GET /mock/s3` or `GET /docs` requests in prod (should never occur after fix).

### Rollout

1. Deploy cookie-secure and CORS fixes first (backward-compatible with explicit env vars already set).
2. Deploy mock-router conditional registration and docs disable in the same backend release.
3. Deploy CSV rate limit and webhook show-once as follow-on changes (require brief feature testing).

**Rollback**: revert to unconditional router registration; no data migration needed.

**Risks**: operators who rely on `/docs` in non-dev environments must be notified; internal tooling using mock S3 in integration environments must be checked.

**Effort estimate**: M (3–4 days). Most changes are single-line; CORS and cookie defaults require operator communication.
