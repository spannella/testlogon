# QST-001: Questionnaire Gaps — Branching, File Upload, One-Response, Targeting — Investigation & Implementation Write-up

## 1. Summary & Classification

The questionnaire system is a solid MVP supporting 9 question types (text, select, multiselect, radio, slider, date, time, timezone, address), immutable versioned publishing, 3-tier validation, partial autosave, PDF export per response, analytics, and anonymous/authenticated respondents. However five meaningful feature gaps block real-world survey use cases: (1) no branching/conditional logic to show/hide questions based on prior answers; (2) no `file` question type for collecting attachments; (3) no one-response-per-respondent enforcement (a user can submit multiple times); (4) no questionnaire assignment/targeting (owners cannot require specific users/roles to complete a form); (5) the CSV response export service exists (`app/services/csv_export.py`) but is not wired to any questionnaire endpoint. Config UI for date/time/timezone (gap 6 from the ticket) is already built in `QuestionTypeConfigEditor.tsx:114-160`. E2E coverage for several question types is missing from `frontend/e2e/questionnaires.spec.ts`.

- **Type**: Feature (multiple gaps)
- **Priority**: Medium (P1 = branching, P2 = file upload + one-response, P3 = assignment + CSV)
- **Status**: UNBUILT — none of the five gaps are implemented
- **Area**: Backend (`app/models_questionnaire.py`, `app/routers/questionnaires.py`, `app/services/questionnaire_validation.py`, `app/services/questionnaires_repository.py`) + Frontend (`frontend/src/pages/questionnaires/`)
- **Cross-refs**: SECOPS-007 (dev/prod parity for file uploads via S3 mock / moto)

## 2. Current-State Investigation

### 2.1 Question type system (`app/models_questionnaire.py:8-18`)

```python
QuestionType = Literal[
    "text", "select", "multiselect", "radio", "slider",
    "date", "time", "timezone", "address",
]
```

No `file` type. The `Question` model (`models_questionnaire.py:54-62`) has a `config_json` dict that holds type-specific config; there is no schema enforcement per type — all config is freeform JSON validated at the service layer.

### 2.2 Validation engine (`app/services/questionnaire_validation.py`)

The validator has `GroupRuleType` and `FormRuleType` constructs for cross-question relationships (e.g., `requires_if_answered`, `mutually_exclusive`). There is no `VisibilityRule` or `BranchingRule` type; the existing group/form rules gate **validation** only, not question **visibility**. They do not skip validation for hidden questions.

### 2.3 Response session (`app/routers/questionnaires.py:645-667` — `start_response_session`)

The handler creates a new session unconditionally for any authenticated or anonymous respondent. There is no check for an existing submitted response when `one_response_per_respondent` would be set. The `Questionnaire` model has no such flag.

### 2.4 CSV export service (`app/services/csv_export.py`)

`generate_csv_rows(source="questionnaire_responses", questionnaire_id=...)` is fully implemented (lines 222-227). It iterates `repo.list_response_sessions(questionnaire_id=...)` and formats 7 columns per row. However no endpoint in `app/routers/questionnaires.py` calls this function. The only export is PDF per-response at `app/routers/questionnaires.py:825-895`.

### 2.5 Frontend builder (`frontend/src/pages/questionnaires/QuestionTypeConfigEditor.tsx`)

Date (`type === "date"`, line 114), time (`type === "time"`, line 129), and timezone (`type === "timezone"`, line 144) all have config panels — this gap from the ticket description is already built. There is no branch/visibility rule editor and no file-type config panel.

### 2.6 E2E coverage (`frontend/e2e/questionnaires.spec.ts`)

Playwright exercises text, select, and slider question types. Date, time, timezone, address, and multiselect are exercised only in pytest unit tests. The PDF download endpoint (line 868) has no E2E test.

## 3. Gap Analysis

### Gap 1 — Branching / Conditional Visibility (P1)

No code exists for this anywhere. Required changes:
- **`app/models_questionnaire.py`**: Add `VisibilityRule` model: `{ rule_id, source_question_id, operator: "eq"|"neq"|"in"|"lt"|"gt"|"answered"|"not_answered", value: Any }`. Add `visibility_rules: list[VisibilityRule]` to `Question` and `Section`.
- **`app/services/questionnaire_validation.py`**: Add `evaluate_visibility(question, answers) -> bool`. Skip required validation + group/form rules for hidden questions. Return a `hidden_question_ids` set from the submit validator.
- **`app/services/questionnaires_repository.py`**: Persist `visibility_rules` as part of `config_json` (already a freeform dict) or as a separate `rules_json` attribute on the question DDB item.
- **Frontend builder**: Add a rule editor panel in `QuestionTypeConfigEditor.tsx` (or a separate `BranchingRuleEditor` component) for each question: "Show this question when `<select question>` `<op>` `<value>`".
- **Frontend respondent**: In the response form, evaluate rules against current answers and conditionally render or skip questions.

### Gap 2 — File Upload Question Type (P2)

No `file` type anywhere in backend or frontend. Required changes:
- **`app/models_questionnaire.py`**: Add `"file"` to `QuestionType` Literal. Add `FileQuestionConfig` model: `{ allowed_extensions: list[str], max_size_mb: int, max_count: int }`.
- **`app/services/questionnaire_validation.py`**: Add `validate_file_answer(answer, config) -> list[ValidationError]` checking count, extension, size.
- **`app/routers/questionnaires.py`**: Add `POST /ui/questionnaires/{id}/sessions/{session_id}/file-upload` accepting `multipart/form-data`. Store via existing S3 pipeline (`app/core/dev_s3.py` / moto in dev, real S3 in prod — SECOPS-007 parity). Write a file reference (S3 key + metadata) into the session `answers` dict, not bytes.
- **Frontend builder**: Add file config panel to `QuestionTypeConfigEditor.tsx`.
- **Frontend respondent**: Add file upload widget with progress/preview/remove to the question renderer.
- **Settings**: Add `QUESTIONNAIRE_FILE_MAX_MB` and `QUESTIONNAIRE_FILE_ALLOWED_EXT` to `app/core/settings.py`.

### Gap 3 — One-Response-Per-Respondent (P2)

Not implemented. Required changes:
- **`app/models_questionnaire.py`**: Add `one_response_per_respondent: bool = False` and `one_response_mode: Literal["block", "edit_existing"] = "block"` to the `Questionnaire` model (stored in the questionnaire DDB item, snapshotted in the published version schema).
- **`app/routers/questionnaires.py` `start_response_session`** (line 645): When `one_response_per_respondent=True` and the respondent is authenticated, query for an existing submitted session for this questionnaire + user. If `one_response_mode="block"`, raise HTTP 409 with the existing session ID. If `"edit_existing"`, return the existing session for editing.
- **`app/services/questionnaires_repository.py`**: Add `find_submitted_session(questionnaire_id, user_sub)` — requires a GSI on `(questionnaire_id, user_sub)` or a scan with FilterExpression.
- **Frontend**: Show "already submitted" message with link to the existing response; hide "Start questionnaire" button.

### Gap 4 — Assignment / Targeting (P3)

Not implemented. Required changes:
- **New DDB table** `questionnaire_assignments` (PK `questionnaire_id`, SK `assignment_id`): fields: `target_type` (user/role/segment), `target_ids`, `assigned_at`, `due_at`, `notify_on_assign`.
- **GSI**: `(target_user_sub, assigned_at)` for the "assigned to me" query.
- **`app/routers/questionnaires.py`**: Add CRUD endpoints `POST/GET/DELETE /ui/questionnaires/{id}/assignments`; add `GET /ui/questionnaires/assigned-to-me` for respondents; add `GET /ui/questionnaires/{id}/completion` for owners (who responded / who hasn't).
- **Notifications**: Reuse the existing `app/services/alerts.py` notification pipeline to send assignment notifications.
- **Frontend**: New "Assignments" tab in the questionnaire builder. New "Required for you" section in the respondent dashboard.

### Gap 5 — CSV Export Endpoint (P3)

The service is built; only the endpoint is missing:
- **`app/routers/questionnaires.py`**: Add `GET /ui/questionnaires/{id}/responses/export.csv` (owner-only, requires `require_ui_session` + ownership check). Call `generate_csv_rows(source="questionnaire_responses", user_sub=ctx["user_sub"], questionnaire_id=id)` and return a `StreamingResponse(content=generator, media_type="text/csv", headers={"Content-Disposition": f'attachment; filename="responses-{id}.csv"'})`.
- **Frontend**: Add "Export CSV" button in the builder analytics tab. Use `window.location.href` or an anchor with `download` attribute.

### Gap 6 — E2E Coverage (P3)

`frontend/e2e/questionnaires.spec.ts` exercises text/select/slider only. Extend to cover: multiselect (add + remove), address (all subfields), date/time/timezone inputs and validation feedback, and PDF download (download attribute / response header assertion).

## 4. Proposed Design

### Branching — Data Model

Store `visibility_rules` as a JSON array on each question DDB item under key `rules_json`. The array is part of the published version snapshot (`schema_json`), so in-flight responses use the version's original rules. A visibility rule:

```json
{
  "rule_id": "vr_abc",
  "source_question_id": "q_1",
  "operator": "eq",
  "value": "yes"
}
```

`operator` values: `"eq"`, `"neq"`, `"in"` (value is list), `"lt"`, `"gt"`, `"answered"`, `"not_answered"`.

`evaluate_visibility(question, answers)` returns `True` (visible) when no rules are defined or when **all** rules are satisfied.

### File Upload — Dev/Prod Parity (SECOPS-007)

In dev mode (`S.dev_mode=True`), `app/core/dev_s3.py` intercepts boto3 calls via moto in-process. File uploads go to the mock bucket. In prod, the same code path uses real S3. The file reference stored in the answer is `{"s3_key": "...", "filename": "...", "size_bytes": N, "content_type": "..."}`. No binary data in DDB.

### One-Response — GSI

Add to the response sessions DDB table (assumed existing `questionnaire_sessions`): a GSI `respondent-questionnaire-index` with PK `user_sub`, SK `questionnaire_id#submitted_at`. This allows an efficient `query` for existing submitted sessions without a full table scan. Add `attr_types={"submitted_at": "N"}` to the `TableDef` in `scripts/local-ddb-init.py` (required for numeric GSI sort keys — see CLAUDE.md gotchas).

### CSV Endpoint

```python
@router.get("/{questionnaire_id}/responses/export.csv")
async def export_responses_csv(
    questionnaire_id: str,
    ctx: dict = Depends(require_ui_session),
):
    q = repo.get_questionnaire(questionnaire_id)
    if not q or q["owner_id"] != ctx["user_sub"]:
        raise HTTPException(status_code=403, detail="Not owner")
    generator = generate_csv_rows(
        source="questionnaire_responses",
        user_sub=ctx["user_sub"],
        questionnaire_id=questionnaire_id,
    )
    return StreamingResponse(
        generator,
        media_type="text/csv",
        headers={"Content-Disposition": f'attachment; filename="responses-{questionnaire_id}.csv"'},
    )
```

## 5. Testing, Verification & Rollout

### pytest

- Branching: `test_hidden_question_not_required`, `test_hidden_question_excluded_from_analytics`, `test_visibility_rule_eq_operator`, `test_visibility_rule_in_operator`, `test_all_rules_must_pass`.
- File upload: `test_file_type_validator_rejects_disallowed_ext`, `test_file_size_limit_enforced`, `test_file_count_limit_enforced`, `test_file_reference_stored_not_bytes`.
- One-response: `test_second_session_blocked_when_one_response_enabled`, `test_second_session_returns_existing_when_edit_mode`.
- Assignment: `test_assignment_create`, `test_assigned_to_me_list`, `test_completion_tracking`.
- CSV: `test_export_csv_owner_only`, `test_export_csv_shape_7_columns`, `test_export_csv_injection_sanitization`.

### E2E (extend `frontend/e2e/questionnaires.spec.ts`)

- Branching: fill question 1 with value that triggers visibility rule → question 2 appears; fill different value → question 2 hidden.
- File upload: attach file in respondent view → submit → response includes file reference.
- One-response: submit response → attempt to start again → blocked with message.
- CSV: owner clicks "Export CSV" → download header `text/csv`, 7 columns, correct data.
- Gap closure: multiselect, address, date, time, timezone, PDF download.

### Rollout

Each gap is independently shippable as a sub-ticket. Feature-flag the larger pieces (`QUESTIONNAIRE_FILE_MAX_MB=0` disables file upload; `QUESTIONNAIRE_ASSIGNMENTS_ENABLED=0` disables assignment). Branching and one-response have no flag (opt-in per questionnaire). CSV export has no flag.

**Effort**: Branching M-L (frontend rule editor is the bulk); File upload M; One-response S; Assignment L; CSV S; E2E coverage M.
