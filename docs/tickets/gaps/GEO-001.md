# GEO-001: Geo-Blocking & Content Restrictions — As-Built Gaps

Cross-ref: SECOPS-002 reuses `app/services/geoip.py` for its network blocklist country checks and will add `lookup_asn()` to the same file. GEO-001 is content-geofencing (creator-controlled per-asset); SECOPS-002 is attacker-blocking (platform-level middleware). The two share the `geoip.py` lookup layer but are otherwise independent enforcement paths.

- [HIGH] Catalog item detail (`GET /ui/catalog/categories/{cat_id}/items` and item search) does not enforce `geo_mode`/`geo_countries` — `app/routers/catalog.py` GET endpoints at lines 374 (`/categories/{id}/items`) and 441 (`/items/search`) never call `check_geo_access`; only the `geo_rules.py` PATCH endpoint writes the geo fields — Creators who set geo-restrictions on catalog items are not protected; blocked-country buyers can still browse and purchase. Fix: in each catalog GET that returns item detail (or item list), load `geo_mode`/`geo_countries` from the DDB record and call `check_geo_access(request, geo_mode, geo_countries)` as done for video (`video_listing.py:682`) and broadcast (`broadcast.py:485`). Effort: S

- [HIGH] Platform-level country block list is env-var only — `app/services/geo_check.py:53` reads `S.geo_platform_block_countries` (a comma-separated env var); `frontend/src/pages/settings/GeoRulesPage.tsx:137` explicitly states "Platform-wide blocks are configured via environment variable `GEO_PLATFORM_BLOCK_COUNTRIES`" — Admins cannot change the platform block list at runtime without an engineer editing env vars and restarting the server; no audit trail of changes. Fix: store platform block rules in a DDB `geo_rules` table (e.g., PK=`PLATFORM`, SK=`BLOCK_LIST`) and add an admin-only `GET/PATCH /ui/admin/geo/platform-block` endpoint; update `geo_check.py` to read from DDB (with a short cache TTL) instead of `S.geo_platform_block_countries`. Effort: M

- [MED] `geoip.py` `_lookup_country_uncached` has a dev fallback that always returns `None` — `app/services/geoip.py:60` falls back to `None` when MaxMind DB is absent and no IP-API call is made — `geo_check.py:74` treats `None` country as allowed (fail-open); SECOPS-002 will rely on the same function for attacker-blocking and expects fail-closed in prod. Fix: document the fail-open/closed duality; add `geo_blocking_fail_open` setting (True in dev, False in prod) and enforce it consistently. Effort: S

- [MED] No admin "list all geo-restricted content" endpoint — the ticket design (section 3.2) calls for an admin scan listing all content with `geo_mode` set; `app/routers/geo_rules.py` has no such endpoint — Admins have no visibility into which items are geo-restricted across the entire platform. Fix: add `GET /ui/geo/admin/restricted-content` that scans `video_metadata`, `broadcast_sessions`, and `shopping_catalog` with `FilterExpression=Attr("geo_mode").exists()`. Effort: S

- [LOW] No E2E test spec for geo-blocking — the ticket spec (section 8 / acceptance criteria) calls for a Playwright spec (e.g., `frontend/e2e/geo-blocking.spec.ts`); none exists — Regression risk for catalog, video, and broadcast geo enforcement paths. Effort: M
