# PLATFORM-007: SMS Delivery Production Config — Gap Report

- [HIGH] No toll-fraud global spending cap (SEC-014) — `app/services/sms_delivery.py`, `app/core/settings.py` — Only a per-number daily limit (`sms_daily_limit_per_number=10`) exists; there is no global daily SMS spend ceiling, no per-country rate cap, and no absolute cost limiter to prevent toll-fraud pump attacks. SEC-014 requires a configurable daily cost cap (e.g., `SMS_DAILY_COST_CAP_USD`) that halts all outbound SMS once the estimated spend exceeds the threshold — Fix: add `sms_daily_cost_cap_usd` setting; in `send_sms()` at `sms_delivery.py:174`, check cumulative daily segment count * cost-per-segment before publishing and return `rate_limited` if exceeded — Effort: M

- [MED] DynamoDB table name mismatch between init script and settings default — `scripts/local-ddb-init.py:1342` vs `app/core/settings.py:197` — `local-ddb-init.py` creates the table as `SmsDelivery` (PascalCase default) but `settings.py` defaults `sms_delivery_table_name` to `"sms_delivery"` (lowercase). In a fresh local dev stack without `SMS_DELIVERY_TABLE_NAME` set, `T.sms_delivery` points to a non-existent table, causing `ResourceNotFoundException` on every SMS tracking write — Fix: align the `TableDef` fallback name in `local-ddb-init.py:1342` to `"sms_delivery"` (lowercase) to match the settings default — Effort: S

- [MED] Silent exception swallowing still present in SMS audit fanout — `app/services/alerts.py:686-687` — The outer `except Exception: pass` wrapping the SMS fanout block in `audit_event()` silently discards all errors from `send_alert_sms()` including the new structured result. Even with improved `send_sms_bulk()`, the caller never sees failures — Fix: replace bare `except Exception: pass` with `except Exception: logger.warning("SMS fanout failed: %s", exc)` to surface errors in logs — Effort: S

- [LOW] SNS client still created per-call in legacy path — `app/core/aws.py:30-37` — `sns_client()` creates a new boto3 client on every invocation (no connection pool reuse). The new `send_sms()` in `sms_delivery.py` calls `sns_client()` each time; module-level caching as specified in ticket section 4.1 was not implemented — Fix: add a module-level `_sns_client: Optional[boto3.client] = None` cache in `sms_delivery.py` — Effort: S

- [LOW] No E2E test file for PLATFORM-007 — `frontend/e2e/` — Admin SMS dashboard E2E tests (stats, failures, suppression CRUD) described in ticket section 6 do not exist; admin SMS monitoring endpoints are untested by automated E2E — Fix: create `frontend/e2e/admin-sms.spec.ts` covering stats, failures, suppression add/remove — Effort: M
