# MSG-009 gaps — Find-a-DateTime Message

- [MED] no deadline-based auto-close background task — `app/main.py` — the ticket specifies `MSG009_AUTO_CLOSE_ENABLED` and a background loop that closes polls whose `deadline_at` has passed; no such task is registered in the FastAPI startup sequence; polls remain `status=open` indefinitely after deadline, and participants can still submit availability (the submission endpoint checks `deadline_at` correctly, but there is no server-side state transition to "closed") — Fix: add an `asyncio.create_task` or APScheduler job in `app/main.py` that runs every 5 min, queries FADT items with `deadline_at < now_ts()` and `status=open`, calls `close_and_compute()` for each, and adds `find_datetime_auto_close_enabled` setting to `app/core/settings.py` — Effort: M

- [MED] FADT uses uppercase SK convention (`META`, `AVAIL#`, `RESULT`) inconsistent with existing meeting polls — `app/routers/messaging.py:10051` — the `FADT#` items use `sk="META"` whereas meeting polls (same calendar table) use `sk="meta"` (lowercase); single-table queries that scan all SKs for a PK will work, but any shared utility code or future cross-type queries must handle mixed conventions; also noted in the ticket's codebase reference section — Fix: align FADT to use lowercase `sk="meta"`, `sk="avail#{user_sub}"`, `sk="result"` to match the existing meeting-poll convention — Effort: S

- [LOW] `from_date` is not validated to be today-or-later server-side — `app/routers/messaging.py:10013-10050` — `CreateFindDateTimeIn.from_date` is only pattern-validated (`^\d{4}-\d{2}-\d{2}$`); the error matrix specifies a 400 `date_in_past` response when `from_date < today`; a user can create a FADT poll for dates in the past, which causes an empty (already-expired) grid for all participants — Fix: add `if parse_date(inp.from_date) < date.today(): raise HTTPException(400, "from_date must be today or later")` in `create_find_datetime_message` — Effort: S

- [LOW] `MSG009_AUTO_CLOSE_ENABLED` feature flag is absent from `app/core/settings.py` — `app/core/settings.py:1122-1124` — `find_datetime_enabled` and `find_datetime_max_date_range_days` are present but the auto-close toggle is missing; if/when the background task is added, it will lack the flag needed to disable it independently of the main feature — Fix: add `find_datetime_auto_close_enabled: bool = os.environ.get("FIND_DATETIME_AUTO_CLOSE_ENABLED", "false").lower() == "true"` to Settings — Effort: S
