# PWA-004 Gaps

- [HIGH] No message idempotency — backend `app/routers/messaging.py` send-message endpoint, frontend `frontend/src/api/types.ts:1249-1264` — `SendTextMessageReq` has no `idempotency_key`/`client_request_id` field; if both the main-thread `useOfflineQueue` flush and the service-worker Background Sync `flushSyncQueue` fire within the same reconnect window (race condition possible on Chrome when background-sync fires while the page is foregrounded), the same message is sent twice and two identical messages appear in the conversation — Fix: add optional `client_request_id` to `SendTextMessageReq` and backend create-message handler; use the offline action `id` as the key — Effort: M

- [MED] `useOfflineQueue` does not skip flush when `SyncManager` is available — `frontend/src/hooks/useOfflineQueue.ts:55-122` — the design in the ticket calls for the main-thread hook to skip when Background Sync is handling the flush; the comment at line 49 documents the decision to ALWAYS flush from the main thread (and delete from IDB after success), but this means the SW sync event can race the main-thread flush on reconnect — Fix: if both paths are intentional, document clearly and ensure `removeFromSyncQueue` is always called on main-thread success (already done at line 79); otherwise add the `SyncManager` guard and rely solely on the SW — Effort: S

- [MED] CSRF token staleness after long offline period not surfaced — `frontend/public/sw.js:393-406` (`getCsrfTokenSW`) — the SW stores the CSRF token with each queue item at enqueue time; if the session cookie has expired by the time Background Sync fires (user closed tab, device went to sleep for hours), the sync request will receive a 403 and the item will exhaust retries and move to dead-letter with an opaque error, giving the user no clear indication to re-authenticate — Fix: detect 401/403 in `dispatchSyncAction`, and emit a `sync-item-auth-expired` message to notify the UI to prompt re-login — Effort: S

- [LOW] `DeadLetterPanel` persists in `localStorage` across logout — `frontend/src/stores/offlineStore.ts:210` — `partialize` persists `deadLetter` to localStorage; `clearAllCacheForUser` (PWA-003) clears IndexedDB but does not clear the Zustand offline store; dead-letter items from a logged-out session remain visible on the next user's login — Fix: call `useOfflineStore.getState().clearDeadLetter()` (and `clearQueue()`) inside `authStore.logout()` — Effort: S
