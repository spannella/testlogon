# FIN-003 Gaps

- [HIGH] Multi-stage reminder schedule not implemented — `app/services/shoppingcart.py:781-846` — `send_cart_reminder` sends a single reminder with hardcoded subject/body; there is no stage config, no stage progression, and the background loop (`app/routers/shoppingcart.py:266-290`) simply sends one reminder per eligible cart per cooldown window; FIN-003 requires configurable stages with per-stage delay, subject, and body template — Fix: create `app/services/cart_reminders.py` with `process_abandoned_carts()` that reads from a `cart_reminder_config` DDB table and advances each cart through numbered stages — Effort: L

- [HIGH] Cart recovery links not generated or included in reminder emails — `app/services/shoppingcart.py:824-835` — the email body is a plain string with no unique recovery URL; clicking the link requires the user to already be logged in and to navigate to `/cart`; there is no `RECOVERY` token record, no `recover_cart` endpoint, and no one-time-use token flow — Fix: add `generate_recovery_link()` and `recover_cart()` in `cart_reminders.py`; add `GET /ui/shoppingcart/recover/{token}` public endpoint; embed the recovery URL in the reminder email body — Effort: M

- [HIGH] No user opt-out preference for cart reminders — `app/routers/shoppingcart.py` and `app/services/shoppingcart.py` — there is no `GET/PUT /ui/shoppingcart/reminders/preferences` endpoint, no `OPTOUT` row in any DDB table, and no opt-out check in `send_cart_reminder`; users who have opted out of emails still receive reminders — Fix: add opt-out storage in `cart_reminder_config` table (`OPTOUT/USER#{sub}` row), `is_user_opted_out()`, and preference endpoints — Effort: M

- [MED] No admin configuration UI or API for reminder settings — all abandonment parameters (`cart_abandonment_threshold_hours`, `cart_abandonment_max_reminders`, `cart_abandonment_reminder_cooldown_hours`) are environment variables in `app/core/settings.py:742-746`; changing them requires a backend restart — Fix: add `GET/PUT /ui/shoppingcart/admin/reminders/config` endpoints backed by `cart_reminder_config` DDB table (`CONFIG/GLOBAL` row) — Effort: M

- [MED] No recovery tracking or extended analytics — `app/services/shoppingcart.py:849-883` `get_abandonment_stats()` returns only open/abandoned/purchased counts and lacks recovery rate, average cart value, or reminders-sent breakdown; `recovered_at` field is never written — Fix: write `recovered_at` on cart recovery; add `GET /ui/shoppingcart/admin/reminders/analytics` with conversion metrics — Effort: M

- [LOW] No `cart_reminder_config` DDB table or `CART_REMINDERS_ENABLED` feature flag — `scripts/local-ddb-init.py` has no `cart_reminder_config` `TableDef` and `app/core/settings.py` has no `cart_reminders_enabled` setting — Fix: add table definition and setting as part of `cart_reminders.py` rollout — Effort: S

- [LOW] No frontend cart recovery page or reminder preference UI — `frontend/src/pages/shop/CartRecoveryPage.tsx` and `frontend/src/pages/settings/CartReminderPrefs.tsx` do not exist; the `cartAbandonment.ts` API wrapper covers only admin sweep and status endpoints — Fix: create `CartRecoveryPage`, `CartReminderPrefs`, and `CartReminderAdmin` frontend components with corresponding API wrappers — Effort: M
