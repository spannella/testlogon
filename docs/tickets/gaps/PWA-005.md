# PWA-005 Gaps

- [MED] Offline optimistic messages not restored after page reload — `frontend/src/pages/messages/ConversationView.tsx:227` and `frontend/src/components/layout/AppShell.tsx` — the ticket design calls for an `OfflineOptimisticRestorer` headless component in AppShell that re-injects queued messages from the persisted offline store into the React Query cache on mount; this component is not present in AppShell nor is `useOfflineOptimisticRestore` defined anywhere — Fix: implement the restorer hook that reads `offlineStore.queue`, finds `send_message` entries, and injects optimistic messages into `["messages", conversationId]` cache on mount — Effort: M

- [MED] Offline-queued feed posts have no offline indicator in PostCard after page reload — `frontend/src/pages/feed/FeedTimeline.tsx:50,66` — `FeedTimeline` builds optimistic posts from the Zustand queue on render, so they reappear correctly; however `PostCard.tsx:410` only checks `post.__offline` which is set on the in-memory object constructed at `FeedTimeline.tsx:50`; if the user reloads while offline, `FeedTimeline` must re-derive optimistic posts from `offlineStore.queue` on every render (it currently does via the `offlinePosts` useMemo), but there is no `StalenessIndicator` or "last cached" signal for the feed page when offline — Fix: add `StalenessIndicator` to `FeedTimeline` header using the `useFeedTimelineQuery` hook's `__fromOfflineCache` metadata (already available in `newsfeed.ts`) — Effort: S

- [MED] Sidebar preview not updated for offline-queued messages — `frontend/src/pages/messages/ConversationView.tsx:1202-1230` — the offline enqueue path injects the optimistic message into `["messages", convoId]` but does NOT update the `["conversations"]` query cache to reflect the new `last_message`; the sidebar preview therefore continues to show the previous last message until reconnect — Fix: add a `queryClient.setQueryData(["conversations"], ...)` call alongside the message injection (design code is documented in the ticket at section 2.11) — Effort: S

- [LOW] `retryAction` in `offlineStore` increments `__retryCount` but `useOfflineQueue` caps retries at `MAX_RETRIES=3` using `action.__retryCount`; if a user retries a dead-lettered action from `MessageBubble`, the `__retryCount` is already 3+ so the next flush immediately re-fails it — `frontend/src/hooks/useOfflineQueue.ts:82-93`, `frontend/src/stores/offlineStore.ts:148-153` — Fix: reset `__retryCount` to 0 in `retryAction` — Effort: S
