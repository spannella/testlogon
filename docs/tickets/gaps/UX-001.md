# UX-001 gaps — Dark Mode Backend Persistence

- [MED] No rate limiting on PATCH /ui/settings/preferences — `app/routers/profile.py:609` has no rate_limit decorator; ticket §6.1 specifies 30 req/min; a malicious client could hammer the DynamoDB UpdateItem chain (2 calls per PATCH) — Fix: add `rate_limit_check(user_sub, "preferences_patch", limit=30, window=60)` at top of `ui_update_preferences` — Effort: S
- [LOW] Two-step DynamoDB update is not atomic — `app/services/user_preferences.py:224-238` uses two sequential UpdateItem calls (ensure-map-exists + set-nested-key); a crash between the two leaves the map initialized but the key unset — Fix: combine into a single UpdateItem using `SET ui_preferences = if_not_exists(ui_preferences, :empty)` followed by map merge, or use a single-step `SET ui_preferences.#k = :val` with a ConditionExpression that auto-creates the map (DynamoDB allows this in one call with `if_not_exists` on nested paths) — Effort: S
- [LOW] prefsLoaded flag not reset on logout — `frontend/src/stores/uiStore.ts` does not reset `prefsLoaded` to `false` when the user logs out; on subsequent login with a different account the old preferences are served from localStorage before the new account's server preferences load — Fix: call `useUiStore.setState({ prefsLoaded: false })` in the auth store logout handler — Effort: S
- [LOW] Theme flicker mitigation not documented — ticket §4.8 describes the FOWT mitigation strategy but no code comment in `frontend/src/components/layout/AppShell.tsx` or `frontend/src/stores/uiStore.ts` explains why `prefsLoaded` guards the load; future maintainers may remove it thinking it is redundant — Fix: add a comment block explaining the flash-of-wrong-theme mitigation — Effort: S
