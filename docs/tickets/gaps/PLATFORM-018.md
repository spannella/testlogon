# PLATFORM-018 gaps — Privacy / Account Deletion

- [CRIT] Old `POST /ui/delete-account` endpoint skips production password verification — `app/routers/privacy.py:148-151`: production path is `if not S.dev_mode: pass` (explicit no-op); any authenticated user can trigger account deletion with any non-empty password string; the newer `POST /ui/privacy/account-deletion/request` in `app/routers/account_deletion.py:67` correctly calls `verify_user_password()`; the old endpoint remains registered and reachable — Fix: remove or redirect the old endpoint, or add `verify_user_password` call matching `account_deletion.py:67` — Effort: S — cross-ref: SEC-018 session revocation
- [HIGH] `finalize_deletion` does not anonymize messages or posts — `app/services/account_deletion.py:390-391` sets `messages_anonymized: 0` and `posts_anonymized: 0` as hardcoded zeros; when `account_deletion_destructive=True`, `delete_user_data` runs but that function does not touch conversation messages or newsfeed posts — deleted-user messages remain visible with real sender identity — Fix: add `_anonymize_messages(user_sub)` and `_anonymize_posts(user_sub)` steps in `finalize_deletion` that overwrite `sender_display_name`/`text` and `author_id`/`content` fields with "Deleted User" / "[This message was deleted]" — Effort: M
- [HIGH] `finalize_deletion` does not cancel active subscriptions before deletion — `app/services/account_deletion.py:397-404` only calls `delete_user_data`; the subscriptions step in `gdpr_service.process_deletion` (line 767) hard-deletes subscription records but does not call the subscription cancellation logic (which would stop future billing charges) — Fix: add a `_cancel_active_subscriptions(user_sub)` step in `finalize_deletion` before DDB delete that calls the subscription cancellation service — Effort: S
- [MED] `DeleteAccountRequestIn` (used by old endpoint) missing `confirm_text` field — `app/models.py:2886-2888`: old model has only `password` and `reason`; `AccountDeletionRequestIn` at line 9334 has `confirm_text` with `@field_validator` enforcing "DELETE MY ACCOUNT"; users who reach the old endpoint bypass this intent confirmation — Fix: deprecate old endpoint (see CRIT gap above) — Effort: S
- [MED] No session revocation on deletion request creation — when a deletion request is created, existing UI sessions for the deleted user are not invalidated; an attacker who obtained session cookies before the user submitted deletion can continue to operate until cookies expire — SEC-018 cross-ref — Fix: in `create_deletion_request` or its router handler, call `revoke_all_user_sessions(user_sub)` so all `T.sessions` rows are purged at grace-period start — Effort: S
- [LOW] Data export is stub-only — `app/services/account_deletion.py:483-490`: `_collect_export_data` returns `{"included": True}` for every non-profile category (messages, posts, files, push_devices, etc.) rather than actual user data; the exported ZIP contains no real records — Fix: implement per-category DDB queries that return actual serialized records, consistent with `gdpr_service.process_export` — Effort: L
