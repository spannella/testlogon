# MSG-008 gaps — GIF & Sticker Messages

- [HIGH] GIF `gif_url` is accepted without domain allowlist validation — `app/routers/messaging.py:9626-9690` — `send_gif_message()` stores any `gif_url` value (max 2048 chars) with no check against allowed domains; an attacker can send a GIF pointing to an arbitrary external URL (tracking pixel, SSRF target, malicious animated SVG); the error-handling matrix in the ticket specifies a `gif_url_not_allowed` 400 response for URLs from disallowed domains, and MSG-008 cross-references FEED-004 for a GIF URL allowlist — Fix: add `gif_allowed_domains: list[str]` setting (default `[""]` to allow `/mock/*` in dev); validate `urllib.parse.urlparse(inp.gif_url).netloc` against the list in `send_gif_message()`; raise `HTTPException(400, "gif_url_not_allowed")` on mismatch — Effort: S

- [MED] GIF search endpoint has no per-user rate limiting — `app/routers/sticker_collections.py` — `GET /ui/stickers/gifs/search` calls the mock (or future real) provider without any rate limiting; the ticket specifies 30 requests/minute per user; without this, a single user can flood the endpoint (or an upstream provider) with unbounded requests — Fix: apply the existing `_rate_limit_check()` pattern from messaging.py or add a Redis/DDB sliding-window counter keyed on `user_sub`; return 429 after 30 calls/min — Effort: M

- [MED] sticker upload in `sticker_collections.py` trusts declared `content_type` header without magic-byte verification — `app/services/sticker_collections.py:159-160` — `_ALLOWED_MIME.get((content_type or "").lower())` accepts any value the caller sends; an attacker can upload SVG-with-script or HTML disguised as PNG; custom emoji service uses magic-byte sniffing (`custom_emojis.py:72`) but sticker service does not — Fix: add Pillow-based or header-sniff content detection to `sticker_collections.py` before writing to S3 — Effort: S

- [LOW] `MSG008_GIF_ENABLED` / `MSG008_STICKER_ENABLED` / `MSG008_ADMIN_STICKER_UPLOAD` flag naming differs from what is in settings — `app/core/settings.py:1107-1108` — deployed names are `gif_messages_enabled` and `sticker_messages_enabled`; no dedicated admin-upload flag; `.env.local.example` and deployment docs should reference the actual env var names to avoid confusion — Fix: update `.env.local.example` and deployment docs to reflect actual env var names `GIF_MESSAGES_ENABLED` and `STICKER_MESSAGES_ENABLED` — Effort: S

- [LOW] sticker collection does not enforce duplicate collection name per admin — `app/services/sticker_collections.py` — the ticket's error matrix specifies a 409 `collection_name_conflict` for duplicate names from the same admin, but no uniqueness check is implemented (no GSI on `name`); admins can create duplicate-named collections that confuse the UI — Fix: add a GSI or scan query on `name` before creating; raise HTTPException(409) on match — Effort: M
