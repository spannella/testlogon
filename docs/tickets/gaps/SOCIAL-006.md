# SOCIAL-006: Hashtags / Topics — Gap Report

- [MED] Hashtag patterns in post body text are not linkified in rendered post bodies — `frontend/src/pages/feed/PostCard.tsx:559-570` only renders `post.tags` as badge chips below the post; `frontend/src/pages/feed/RichContentRenderer.tsx` and `MarkdownComposer.tsx` render body HTML verbatim with no `#word` → `<Link>` substitution — acceptance criterion 5 ("PostCard renders hashtags as clickable links") requires `#photography` in body text to navigate to `/discover/tags/photography`; body-embedded hashtags are inert — Fix: apply a `linkifyHashtags(html)` pass on `body_markdown_html` before rendering in `RichContentRenderer.tsx`, or add a `HashtagText` component for plain-text bodies — Effort: S

- [LOW] Video tags are not unified in the tag discovery page (`/discover/tags/:tag`) — `app/routers/discovery.py:110-167` queries only `TAG#{tag}` items (post tag-index entries); `app/models_video.py:126` stores video `tags` but no video tag-index entries are written; videos do not appear on the `TagPage` — acceptance criterion 10 ("Existing video tags field is not broken; future integration can unify") leaves this as future but ticket section 2.1 user story says "browse posts and videos together by topic" — Fix: on video publish, write `TAG#{tag}` items to the app_single_table (same pattern as posts); extend discovery endpoint to resolve video hits — Effort: L

- [LOW] No `HASHTAGS_ENABLED` feature flag — `app/core/settings.py` has no `hashtags_enabled` field; `app/routers/newsfeed.py` and `app/routers/discovery.py` have no flag guard — ticket section 13.1 requires the flag for rollback; currently the feature cannot be disabled without a code deploy — Fix: add `hashtags_enabled: bool` to `Settings`; skip `_write_tag_index` and `_update_tag_stats` when disabled; return 404 from tag endpoints — Effort: S
