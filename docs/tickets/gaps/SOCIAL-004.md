# SOCIAL-004: User Blocking — Gap Report

- [HIGH] Block/Unblock UI is absent from `PublicUserProfilePage` — `frontend/src/pages/profile/PublicUserProfilePage.tsx` (362 lines, no import of `blockUser`/`getBlockStatus`/`BlockButton`); `frontend/src/components/shared/BlockButton.tsx` does not exist — users have no surface to initiate a block from a profile; the only blocking surface is `BlockedUsersPage` (unblock only); acceptance criteria 10 fails — Fix: create `BlockButton.tsx` shared component; import `getBlockStatus`/`blockUser`/`unblockUser` in `PublicUserProfilePage`; add a "Block" option in a `DropdownMenu` alongside the Follow button — Effort: M

- [MED] Discovery search (`/ui/discover/search`) does not filter blocked users — `app/routers/discovery.py` (no `block` import), `app/services/discovery.py` (no `get_blocked_set` call in `search_users`) — blocked users appear in search/discovery results for the user who blocked them; acceptance criterion 8 ("Blocked users filtered from discovery/search results") fails — Fix: load `get_blocked_set(viewer_id) | get_blocked_by_set(viewer_id)` in the discovery `search_users` function and filter results — Effort: M

- [MED] Notification system (`social_alerts.py`) does not suppress alerts from blocked users — `app/services/social_alerts.py` has no `is_any_block` or `get_blocked_set` call (grep returns 0 matches); new-post and other follow-triggered alerts from blocked users are still delivered — acceptance criterion 12 ("Blocked user is NOT notified" is met, but the inverse — blocker not receiving notifications from blocked user — is not enforced) — Fix: add `is_any_block(recipient_id, sender_id)` guard in notification dispatch path — Effort: M

- [LOW] `GET /ui/social/status/{target_user_id}` response includes `is_blocked_by_me` / `is_blocking_me` fields — `app/routers/social.py:236-237` — but these fields are NOT surfaced on `PublicUserProfilePage` (no `useQuery` for `/block-status/`); UI cannot show "You've blocked this user" state on profile — Fix: query `getBlockStatus(userId)` in `PublicUserProfilePage` and display a banner or disabled-follow state when `is_blocked_by_me` is true — Effort: S

- [LOW] Contacts search endpoint (`GET /messaging/contacts/search`) does not filter blocked users — `app/routers/messaging.py` contacts search path has no blocking import; blocked users appear in the contact search autocomplete — Fix: add `is_any_block` filter to the contacts search path — Effort: S
