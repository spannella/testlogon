- [HIGH] `validate_promo_code` returns generic `message` strings with no machine-readable `error_code` — `app/services/promo_codes.py:251-331` — each failure path sets only a human-readable `message`; no `error_code` key is returned; frontend `Checkout.tsx` and future surfaces cannot distinguish `expired` from `usage_limit` programmatically — Fix: add `error_code` to each `fail` dict return: `not_found`, `deactivated`, `expired`, `usage_limit`, `already_used`, `min_order`, `product_mismatch`, `checkout_type_mismatch` — Effort: S

- [LOW] No re-validation of promo code at purchase time — `app/routers/shoppingcart.py` `purchase_cart` endpoint reads `promo_code` from `CartPurchaseIn` (line 884) but passes it directly to purchase flow without calling `validate_promo_code` again; a code that expires between preview and purchase is still honoured — Fix: re-validate inside the purchase handler before applying the discount — Effort: S
