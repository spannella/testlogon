# PLATFORM-013: Theme Customization — Gap Report

- [MED] `ThemeConfigPatchReq.custom_accent_hex` field length cap is 7 chars but allows values missing the `#` prefix — `app/models.py:11006,11012-11019` — `max_length=7` enforces a 7-char limit, and `_validate_hex` strips a leading `#` and validates 6 hex chars. However, a value submitted without `#` (e.g. `"aabbcc"`) passes validation (6 chars, all hex) but is stored without the `#` prefix. `ThemeProvider.tsx` then calls `document.documentElement.style.setProperty("--color-primary", customAccentHex)` which requires a full `#rrggbb` value — Fix: normalize in `_validate_hex`: if the value is 6 hex chars without `#`, prepend it; if it is 7 chars starting with `#`, accept; otherwise reject — Effort: S

- [MED] `font_scale` field in backend model (`app/models.py:10987`) does not match `fontSize`/`font_size` in frontend store and preferences API — `frontend/src/stores/uiStore.ts:38` vs `frontend/src/api/endpoints/preferences.ts:12` vs `app/models.py:10987` — The backend `ThemeConfigOut` uses `font_scale` (`small`/`default`/`large`/`xlarge`), the old preferences API uses `font_size` (same literals), and `uiStore` uses `fontSize`. The `uiStore.ts:149` hydration maps `prefs.font_size` to `updates.fontSize`, but `GET /ui/theme` returns `font_scale`. The theme endpoint and preferences endpoint return different field names for the same setting, causing one to be ignored on load — Fix: standardize on `font_scale` in all layers; update `preferences.ts` types and `uiStore` hydration to read `font_scale` from the theme endpoint response — Effort: S

- [LOW] `ThemePreviewPane` is a static mock, not a live preview of pending changes — `frontend/src/components/shared/ThemePreviewPane.tsx` — Ticket section 1 specifies a live preview pane that shows how the UI would look *before* committing a theme change. `ThemePreviewPane` renders a static sample card using current (already-applied) store values, not a preview of an uncommitted selection. Since `setAccentColor()` immediately applies the CSS variable, there is no "preview before apply" — Fix: add a `previewTheme` state to `AppearanceSection` that is applied to a sandboxed `<div>` element via inline CSS variables (not `document.documentElement`) for preview, then committed on "Apply" click — Effort: M

- [LOW] No `preset` field in `uiStore` or `AppearanceSection` — `frontend/src/stores/uiStore.ts`, `frontend/src/pages/settings/AppearanceSection.tsx` — The backend `ThemeConfigOut` includes a `preset` field (`midnight`, `sunrise`, `forest`, `ocean`, `default`) but `uiStore` has no `preset` state variable and `AppearanceSection` has no preset picker UI. Preset selection described in the ticket is completely absent from the frontend — Fix: add `preset: Preset` to `uiStore` alongside `accentColor`; add preset picker rows to `AppearanceSection` that call `setPreset()` and sync via `debouncedSyncToServer` — Effort: M
