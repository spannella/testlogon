# ENTERPRISE-005 Gap Analysis — Webhooks v2 with Enhanced Reliability

- [HIGH] Circuit breaker not integrated into dispatcher loop — `app/services/webhook_dispatcher.py:44-71` — The `webhook_circuit_breaker.py` module (`should_attempt_delivery`, `record_delivery_result`) is fully implemented but the dispatcher loop in `webhook_dispatcher.py` never imports or calls it. Every delivery is attempted regardless of circuit state; the circuit breaker has no effect in production. — Fix: Import `should_attempt_delivery` and `record_delivery_result` in `webhook_dispatcher.py` and call them around each delivery attempt (mirroring the dispatcher snippet in the ticket's section 3.4). — Effort: S

- [HIGH] Per-delivery stats (`webhook_stats`) not recorded — `app/services/webhook_dispatcher.py` / `app/services/webhook_stats.py` — `record_delivery_stat()` is implemented in `webhook_stats.py` and the `T.webhook_stats` table handle is wired, but the dispatcher never calls it after each delivery. The delivery dashboard (`GET /ui/webhooks/{id}/stats`) will return empty data. — Fix: Call `record_delivery_stat(endpoint_id, result)` after `mark_delivery_success` and `handle_delivery_failure` in the dispatcher loop. — Effort: S

- [MED] `replay_dead_letter` rate limiting setting defined but not enforced — `app/core/settings.py:1736` (`webhooks_replay_rate_limit_per_hour=100`) — The setting exists but the replay endpoints in `app/routers/webhooks.py:288-340` never consult it. An authenticated user can replay 10,000 dead-lettered events per second, effectively creating a self-inflicted DDoS against their own endpoint. — Fix: Track replay count per `(user_sub, endpoint_id, hour_bucket)` in DDB (or in-memory counter) and return HTTP 429 when limit exceeded. — Effort: M

- [MED] `v1` signature header sends `sha256=` prefix but spec says `v1=` — `app/services/webhook_service.py:616-621` — The v1 backward-compat signature is written as `X-Webhook-Signature-v1: sha256={sig}` in the implementation (line 621), but consumers that read `X-Webhook-Signature` for the v1 prefix format will not find it there. The original PLATFORM-002 code used `X-Webhook-Signature: sha256={sig}`. Depending on which convention existing consumers use, one code path will break on upgrade. — Fix: Verify and document the exact header name and value format; add an integration test for v1 backward-compat. — Effort: S

- [MED] `run_webhook_dispatcher_once` ignores circuit breaker and stats — `app/services/webhook_dispatcher.py:103-138` — The "run now" helper duplicates the loop body without the circuit-breaker or stats calls, meaning manual triggering from the admin UI bypasses both safeguards. — Fix: Extract a shared `_process_single_delivery(delivery)` function used by both the loop and the run-once path. — Effort: S

- [LOW] Delivery dashboard `GET /ui/webhooks/{id}/stats` endpoint exists in router but `get_endpoint_stats` may return empty results for endpoints older than `webhooks_stats_retention_days` — `app/services/webhook_stats.py:75` — The stats query is bounded by the retention window; there is no explicit error or pagination indicator when querying outside the window. Operators may believe there is no data when it simply fell off. — Fix: Return a `retention_days` field in the stats response so clients can show a "data retention window" warning. — Effort: S

- [LOW] `webhooks_max_payload_size_bytes` setting referenced in ticket but absent from `settings.py` — Ticket section 2.8 lists `webhooks_max_payload_size_bytes` as a v2 setting; `app/core/settings.py:1729-1737` does not define it. `deliver_webhook` sends payloads of any size. — Fix: Add the setting (default 256 KB) and enforce it in `enqueue_webhook_event` before writing to DDB. — Effort: S
