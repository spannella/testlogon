# SYND-003 Gaps — Revenue Splitting Engine

- [HIGH] execute_split uses Python `assert` for financial integrity invariant — `app/services/syndicate_revenue_split.py:222-225` — Python assertions are silently disabled when the interpreter runs with the `-O` flag (optimized mode); if the split calculation ever produces a distribution mismatch the assertion passes silently, crediting members with wrong amounts and leaving platform fee inconsistent — Fix: replace both `assert` statements with `if ... raise HTTPException(500, ...)` or `raise RuntimeError(...)` that will always execute regardless of optimization flags — Effort: S

- [HIGH] execute_split writes ledger credit entries for each member but never calls `apply_wallet_delta` — `app/services/syndicate_revenue_split.py:231-261` — members receive a ledger credit record but their spendable wallet balance (`wallet_balance_cents` on their billing row) is never incremented; payout and wallet-balance endpoints will show $0 despite the member having earned revenue share — Fix: add `apply_wallet_delta(T.billing, f"USER#{dist['user_id']}", dist["amount_cents"])` for each distribution entry — Effort: S

- [MED] get_split and get_member_earnings scan up to 1000 split records via `get_split_history(limit=1000)` using a linear Python search — `app/services/syndicate_revenue_split.py:302-306, 310-331` — syndicates with hundreds of payments will be slow; `get_split` is O(N) for every single-split detail lookup — Fix: store `split_id` in the SK or maintain a `SPLIT_ID#{split_id}` lookup item; for earnings, accumulate per-member totals incrementally — Effort: M

- [LOW] Performance-based split falls back to equal when no seeded scores exist instead of surfacing the unconfigured state — `app/services/syndicate_revenue_split.py:416-432` — admin configures `mode=performance` but forgets to call `set_performance_scores`; the split silently behaves as `mode=equal` with no warning in the split execution record — Fix: write `effective_mode="equal_fallback"` (or log a warning) when performance scores are all default-1 and the configured mode is "performance" — Effort: S
