# PWA-002 gaps

- [LOW] Vite build-time `CACHE_VERSION` injection plugin not implemented — `frontend/vite-plugin-sw-version.ts` (file absent); `frontend/vite.config.ts` has no `swVersionPlugin()` — Deployments require manual `CACHE_VERSION` bump in `sw.js`; CI builds will silently serve stale cached assets — Fix: create `vite-plugin-sw-version.ts` per ticket §3.7 and register it in `vite.config.ts` — Effort: S

- [LOW] `IMAGE_CACHE` (`images-v1`) defined in `sw.js` but not described in the ticket design — `frontend/public/sw.js:18` — A fourth cache bucket (`IMAGE_CACHE`) exists in the implementation but is absent from the ticket's three-cache architecture (§3.1); it is added to `VALID_CACHES` but no fetch handler route writes to it — Fix: either add a cache-first handler for `/uploads/*` or dynamic image paths, or remove the unused constant to avoid confusion — Effort: S

- [LOW] `clear-all-caches` debug handler in production SW — `frontend/public/sw.js` (message handler for `"clear-all-caches"`) — Any same-origin script can call `navigator.serviceWorker.controller.postMessage({type:"clear-all-caches"})` and erase all caches, causing an offline-capable app to become non-functional; ticket §7.5 notes negligible risk but recommends a `DEV_MODE` gate — Fix: wrap both `list-caches` and `clear-all-caches` handlers in a check for a build-time `__DEV__` constant or remove the clear handler from production builds — Effort: S
