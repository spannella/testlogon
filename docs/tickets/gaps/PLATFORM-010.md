# PLATFORM-010: Web Push Service Worker — Gap Report

- [HIGH] Auto-revoke fires on any delivery failure, not only definitive 410/404 — `app/services/push.py:300-310` — `web_push_send()` returns `False` for both transient errors (network timeout, 429 rate-limit from push vendor) and permanent subscription expiry (410 Gone). The caller at line 300 revokes the device on any `not success` return, so a single transient outage wipes all a user's push subscriptions and they receive no future notifications until they re-enable — Fix: have `web_push_send()` return a 3-value enum or raise a distinct `StaleSubscriptionError` on 410/404 so the caller can distinguish permanent from transient failures; only revoke on permanent — Effort: S

- [MED] VAPID keys not auto-generated by `setup_ubuntu.sh` — `scripts/setup_ubuntu.sh` — Ticket section 6.2 specifies that `setup_ubuntu.sh` auto-generates VAPID keys when not already set in `.env.local`. The script was not updated; `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` remain empty in fresh dev stacks, so `web_push_send()` always short-circuits at `push.py:160` and the "Test" button silently fails — Fix: add `python3 scripts/generate_vapid_keys.py` invocation to `setup_ubuntu.sh` post-install section, writing the resulting lines into `.env.local` if absent — Effort: S

- [MED] `sw.js` includes a full offline cache layer not planned in the ticket — `frontend/public/sw.js:4-5,81-98` — The service worker implements pre-caching of the app shell on `install` and cache-purging on `activate` (ticket section 5.1 explicitly said "does NOT handle fetch caching or offline support — Phase 2"). An unexpected caching layer can serve stale HTML/JS after deployments, breaking the app for users with an active SW registration until they hard-refresh or the TTL expires — Fix: remove the `CACHE_NAME`/`APP_SHELL_FILES` cache logic from `sw.js`; keep only `push` and `notificationclick` handlers as specified — Effort: S

- [LOW] `push_devices` DDB table missing `ttl_epoch` TTL attribute declaration — `scripts/local-ddb-init.py:2227` — `upsert_push_device()` at `push.py:117` writes a `ttl_epoch` field, but the `TableDef` for `push_devices` in `local-ddb-init.py` has no `ttl=True` / TTL attribute annotation. DynamoDB Local does not enforce TTL but DynamoDB in prod silently ignores TTL until it is enabled on the table — Fix: add `ttl="ttl_epoch"` parameter to the `push_devices` `TableDef` and enable TTL via `update_time_to_live` in the init script — Effort: S

- [LOW] No E2E test for VAPID key format validity (65-byte decoded length) — `frontend/e2e/web-push.spec.ts` — The spec file exists but the test "VAPID key decodes to 65 bytes" (ticket section 11.2 test #3) was not implemented; only key non-emptiness and base64url character set are checked — Fix: add atob/decode assertion in `web-push.spec.ts` that the decoded VAPID public key is exactly 65 bytes — Effort: S
