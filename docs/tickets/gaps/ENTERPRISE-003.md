# ENTERPRISE-003 Gap Analysis — Organization / Team Workspaces

- [HIGH] `_find_invite` does a full table scan — `app/services/org_service.py:1221-1232` — `accept_invite` calls `_find_invite(invite_id)` which issues an unbounded DynamoDB `scan()` with a `FilterExpression` on `sk`. On a busy table this will miss items beyond the first 1 MB page and will also be extremely slow and expensive under any meaningful load. The ticket's own comment acknowledges the need for a dedicated GSI. — Fix: Add an `invite-id-index` GSI to the `organizations` table (PK: `invite_id`) in `scripts/local-ddb-init.py` and use `query()` in `_find_invite`. — Effort: M

- [HIGH] `list_user_orgs` GSI query returns raw membership items, not org metadata — `app/services/org_service.py:972-989` — The `user-orgs-index` GSI is queried but only membership items (with `sk=MEMBER#{user_sub}`) project to that index, not the org `#META` items. The result is a list of membership records without org name/status, and the follow-up `get_org()` per-membership call is an N+1 pattern. — Fix: Project `org_id`, `org_role` and `status` from the GSI; do a `batch_get_item` for the `#META` records. — Effort: S

- [MED] `org_upload_file` ignores `file.size` for storage-limit check — `app/services/org_files.py:380` — `_check_storage_limit` is called with `file.size or 0`; `UploadFile.size` is `None` until the file is fully read (FastAPI/Starlette only sets it from `Content-Length`). If the header is absent the check always passes with 0 bytes, allowing unlimited uploads. — Fix: Read `file.read()` into memory (or stream to a temp buffer) first to obtain the actual byte count, then call `_check_storage_limit`. — Effort: S

- [MED] `OrgBillingPmAddReq` model not used — `app/routers/orgs.py:220-232` — The `add_org_payment_method` endpoint accepts a raw `body: dict` instead of the typed `OrgBillingPmAddReq` model, bypassing Pydantic validation (field constraints, pattern checks, required fields). A caller can inject arbitrary keys. — Fix: Change the parameter type from `dict` to `OrgBillingPmAddReq` and access fields via the model. — Effort: S

- [MED] Org billing invoice endpoint missing — `app/routers/orgs.py` — The ticket's section 4.5 specifies `GET /ui/orgs/{org_id}/billing/invoice/{period}` for PDF monthly invoices; this endpoint is absent from the router. — Fix: Implement invoice generation (at minimum a JSON summary; PDF is deferred) under the org billing sub-path. — Effort: M

- [LOW] `member_count` denormalisation can go negative — `app/services/org_service.py:1147-1152` — `remove_member` updates `member_count = member_count - :one` without a condition expression preventing underflow. If two concurrent removals race, the count could reach -1 (or worse if DDB allows it). — Fix: Add `ConditionExpression=Attr("member_count").gt(0)` and handle the `ConditionalCheckFailedException`. — Effort: S

- [LOW] Org file listing does not expose subfolder path navigation — `app/routers/orgs.py:131-134` — `GET /ui/orgs/{org_id}/files` always calls `org_list_children(org_id, user_sub)` with no `path` parameter, so the caller cannot browse subfolders. The ticket's section 4.3 specifies a `{path}` variant. — Fix: Add an optional `path: str = "/"` query parameter and pass it through to `org_list_children`. — Effort: S
