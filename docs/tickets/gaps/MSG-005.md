# MSG-005 gaps — Read Receipts Real-time

- [HIGH] `message:viewed` SSE handler uses `invalidateQueries` (triggers a full refetch) instead of `setQueriesData` for the messages cache — `frontend/src/hooks/useMessagingStream.ts:125` — every time any participant views any message the entire message list is re-fetched from the server, causing significant unnecessary traffic and a perceptible flicker in the UI; the ticket design explicitly called for synchronous `setQueriesData` cache mutation — Fix: replace `queryClient.invalidateQueries({ queryKey: ["messages", conversationId] })` with `queryClient.setQueriesData(...)` that surgically increments `read_by_count` / `read_by_user_ids` on the matching message item — Effort: M

- [MED] `DeliveryStatus` component does not accept `participantCount` prop — `frontend/src/pages/messages/DeliveryStatus.tsx:6` — the component cannot distinguish "DM fully read" (1 reader of 1 expected) from "group partially read" (1 reader of N expected), so it never shows the group count badge ("Read by 2") designed in the ticket — Fix: add `participantCount?: number` prop (default 2) and add the partial-read branch using `readCount > 0 && readCount < participantCount - 1` — Effort: S

- [MED] `ReadReceipts` stale time is still 30 seconds — `frontend/src/pages/messages/ReadReceipts.tsx:33` — the ticket required reducing it to 5 seconds since the SSE handler now invalidates the query on each view event; the 30s value means viewer avatars still lag by up to 30s as a fallback — Fix: change `staleTime: 30_000` to `staleTime: 5_000` — Effort: S

- [LOW] no E2E test file for read receipts real-time — the ticket specifies `frontend/e2e/read-receipts-realtime.spec.ts` (14 tests) but it is not present in the test suite — Fix: create the spec covering delivery count in API response, SSE-driven checkmark update, group partial/full read badge, and clock icon for optimistic messages (14 tests as designed) — Effort: L
