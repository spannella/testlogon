# MON-004 gaps

- [HIGH] Payout balance calculation (`get_available_balance`) does not exclude `state=reversed` credit entries — `app/services/creator_payouts.py:84-90` — chargebacked subscription payments and refunded tip credits inflate the available balance, allowing creators to withdraw funds that were actually reversed; this is a direct financial loss to the platform — Fix: add `Attr("state").ne("reversed")` to the FilterExpression on the billing query; also exclude `amount_cents=0` subscription-access entitlement records — Effort: S

- [HIGH] `request_payout` performs balance check then write as two separate non-atomic operations without any conditional write — `app/services/creator_payouts.py:188-209` — a creator submitting two concurrent requests can both pass the `_has_active_payout` and `amount > available` checks before either `put_item` lands, creating duplicate payout requests that together exceed the available balance — Fix: use a DDB conditional write with `ConditionExpression="attribute_not_exists(payout_id)"` on the payout record and a version counter on the user's payout state row — Effort: M

- [MED] Payout destination management (add/remove bank accounts with KMS-encrypted account/routing numbers) described in the ticket is not implemented — no `PAYOUT_DEST#` pattern exists in `app/routers/creator_payouts.py` or `app/services/creator_payouts.py`; `PayoutRequestIn.method` is a free-text string defaulting to `"bank_transfer"` with no validated destination — `app/routers/creator_payouts.py:50-75`, `app/models.py:2475-2478` — creators cannot register and select verified payout accounts; the payout system accepts an unvalidated method field with no backend enforcement — Fix: implement `POST/GET/DELETE /ui/payouts/destinations` endpoints with KMS encryption for sensitive fields per section 3.2 of MON-004 design — Effort: L

- [MED] Subscription revenue is excluded from payout-eligible balance because subscription server writes under `CREATOR#` PK in `T.subscriptions`, not `USER#` in `T.billing` — `app/services/creator_payouts.py:68` queries only `T.billing` — creators' subscription income can never be paid out through the payout system — Fix: blocked on MON-003 gap fix; once subscription payments write `USER#` LEDGER credits to `T.billing`, they will automatically appear in the payout balance — Effort: M (same fix as MON-003 HIGH gap)

- [LOW] `complete_payout` writes a debit ledger entry but the payout record's `ledger_entry_id` field is not documented in `PayoutOut` response model — `app/services/creator_payouts.py:357-395` — operators cannot audit which ledger debit corresponds to which payout from the API — Fix: include `ledger_entry_id` in `PayoutOut` model — Effort: S
