# FIN-017: Bulk Payout/Refund Tools — As-Built Gaps

- [HIGH] No undo window — `app/services/bulk_payout_tools.py` `_persist_batch` at `:202` stores no `undo_expires_at` field; `BulkBatchOut` model (`app/models.py:1599`) has no `undo_expires_at` field; no undo endpoint exists in `app/routers/bulk_payout_tools.py` — Once a batch executes, there is no 5-minute reversal window. Fix: add `undo_expires_at` to batch record and `BulkBatchOut`; add `POST /ui/admin/bulk-payouts/batches/{batch_id}/undo` endpoint; implement per-item reversal by calling `reject_payout`/`reverse_refund` for already-approved items. Effort: M

- [HIGH] No CSV import endpoint — `app/routers/bulk_payout_tools.py` has no `import-csv` route; `app/services/bulk_payout_tools.py` has no `import_csv_payouts` function — Finance teams cannot upload externally-prepared payout batches. Fix: add `POST /ui/admin/bulk-payouts/import-csv` (multipart) endpoint; implement CSV parse, validate, and `request_payout()` for each valid row. Effort: M

- [MED] Batch items stored only in-memory result list, not persisted as individual DDB rows — `_persist_batch` at `app/services/bulk_payout_tools.py:202` stores `items` as a DDB List attribute on the batch record, not as separate SK rows — Large batches (>200 items) may exceed the 400KB DDB item limit; per-item status cannot be updated atomically mid-execution. Fix: store each item as `sk=ITEM#{ref_id}` row (as the ticket design specifies) and update individually. Effort: M

- [MED] No batch progress polling endpoint �� `app/routers/bulk_payout_tools.py` has only `GET /batches` (list) and `GET /batches/{batch_id}` (full detail); no lightweight `GET /batches/{batch_id}/progress` — Frontend cannot show live progress bar during long-running batches. Fix: add `GET /ui/admin/bulk-payouts/batches/{batch_id}/progress` returning only counters (processed/succeeded/failed/status). Effort: S

- [MED] Router prefix diverges from ticket spec — `app/routers/bulk_payout_tools.py:29` uses prefix `/ui/admin/bulk-payouts`; ticket and models specify `/v1/admin/bulk-ops` — Frontend `bulkPayoutTools.ts` must match whichever prefix is canonical; a future rename will break existing clients. Fix: decide on one canonical prefix and update router + frontend API file consistently. Effort: S

- [LOW] No E2E test spec for bulk operations — ticket spec calls for `frontend/e2e/admin-bulk-ops.spec.ts` (sections 539–543); none exists — Regression risk for batch execute, undo, and CSV import paths. Effort: M
