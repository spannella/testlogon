# GROUP-003 gaps

- [HIGH] `_AUTO_CONFIRM_DONATIONS = True` is a hardcoded module-level constant, not gated on `S.dev_mode` — `app/services/group_fundraising.py:35` — in production this would auto-confirm every donation without waiting for a real Stripe webhook, crediting the treasury for payments that have not actually cleared; any donation attempt (even a failed card) would be auto-confirmed and the treasury credited — Fix: change to `_AUTO_CONFIRM_DONATIONS = S.dev_mode` so prod requires Stripe webhook confirmation; implement a `POST /internal/fundraisers/{id}/donations/{id}/confirm` webhook handler for production — Effort: M — (Cross-ref: **SECOPS-007** dev/prod parity)

- [MED] Advertising campaigns and fundraisers share a single `group_fundraising_enabled` flag — `app/routers/group_fundraising.py:38-40` — the ticket specifies separate `group_advertising_enabled` and `group_fundraising_enabled` flags (`GROUP-003 §13.1`); a platform operator cannot disable advertising without also disabling fundraising — Fix: add `group_advertising_enabled` setting to `app/core/settings.py` and gate campaign endpoints separately — Effort: S

- [MED] Router URL prefix is `/ui/groups/fundraising/{group_id}/campaigns` but the ticket spec and frontend pages at `frontend/src/pages/groups/GroupAdsPage.tsx` expect `/ui/groups/{group_id}/campaigns` — `app/routers/group_fundraising.py:34` sets `prefix="/ui/groups/fundraising"` creating a URL mismatch between the ticket design and the frontend API calls — Fix: verify frontend `GroupAdsPage.tsx` and `GroupFundraisingPage.tsx` use the `/ui/groups/fundraising/` prefix; if the frontend was updated to match the router, document the deviation; otherwise align router prefix to `/ui/groups` — Effort: S

- [MED] No "link advertiser account" endpoint exists — the ticket requires `POST /ui/groups/{group_id}/advertiser` to link an ADS-001 advertiser account before campaigns can be created; `app/services/group_fundraising.py` and `app/routers/group_fundraising.py` have no such endpoint or `ADVERTISER` record check — `create_campaign` skips the advertiser account prerequisite entirely — Fix: decide if advertiser account linking is deferred (ADS-001 dependency not built) or implement a simplified campaign creation without the link requirement — Effort: S

- [LOW] Public donation receipt endpoint URL deviates from ticket spec — ticket specifies `GET /public/donations/{id}/receipt` but implementation is `GET /public/fundraisers/{fundraiser_id}/donations/{donation_id}/receipt` requiring `fundraiser_id` as a path parameter (`app/routers/group_fundraising.py:210`) — callers receiving only a `donation_id` from the create-donation response cannot construct the receipt URL without knowing `fundraiser_id` �� Fix: either expose `fundraiser_id` in the `create_donation` response or add a lookup-by-donation-id-only path — Effort: S

- [LOW] `donor_email` stored in plaintext in DynamoDB — `app/services/group_fundraising.py:286` — email is PII; for GDPR compliance it should be encrypted at rest or omitted from storage if only used for a one-time receipt email — Fix: encrypt with mock KMS in dev / real KMS in prod, consistent with SECOPS-007 parity pattern — Effort: M
