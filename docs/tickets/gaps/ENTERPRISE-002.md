# ENTERPRISE-002 Gap Analysis — SSO / SAML Integration

- [CRIT] Unvalidated `RelayState` redirect — `app/routers/sso_saml.py:212` — The ACS endpoint redirects to `str(relay_state or "/")` without validating that the URL is local/same-origin, creating a classic open-redirect (CWE-601) that an attacker can exploit by crafting a malicious IdP response with `RelayState=https://evil.com/steal`. SEC-011 requires RelayState validation. — Fix: Parse the RelayState URL; reject any value whose host differs from the platform's own origin; default to `/` on rejection. — Effort: S

- [HIGH] SSO-only enforcement not wired into login endpoint — `app/routers/ui_session.py` — The `is_sso_only_tenant()` helper is implemented in `app/services/sso_saml_provider.py` and referenced in the ticket's section 3.5, but `POST /ui/session/start` in `ui_session.py` never calls it. Users belonging to tenants with `sso_only=true` can still log in with a password. — Fix: Call `is_sso_only_tenant(tenant_id)` at the top of `ui_session_start` and raise HTTP 403 when it returns True. — Effort: S

- [HIGH] `MockSamlAuth` used in production path — `app/routers/sso_saml.py:38,60,106` — The router imports and uses `MockSamlAuth` (not `OneLogin_Saml2_Auth`) for both the login redirect and ACS response processing; SAML assertions are never cryptographically verified. Any POST to `/saml/acs` can be accepted with forged attributes. — Fix: Conditionally use the real `OneLogin_Saml2_Auth` when `not S.dev_mode`; restrict `MockSamlAuth` to `S.dev_mode` only. — Effort: M

- [HIGH] `relay_state` carries attacker-controlled form field not sanitised — `app/routers/sso_saml.py:78-79` — `relay_state` is taken directly from `form.get("RelayState")` with no length or character-set validation; a sufficiently long or binary value could cause issues downstream. In combination with the open-redirect gap above, this is the primary attack surface for SAML-based phishing. — Fix: Limit RelayState to ≤2 KB, restrict to printable ASCII, and validate the URL before use. — Effort: S

- [MED] SSO provider management (CRUD) endpoints absent — `app/routers/sso_saml.py` — The ticket's section 4.1 specifies nine admin endpoints (`POST /v1/admin/sso/providers`, metadata upload, role-mapping, test, stats, etc.); only `GET /ui/sso/info` and the public SAML flow endpoints are implemented. Admins cannot configure providers via API. — Fix: Implement the provider CRUD router and mount it in `main.py`. — Effort: M

- [MED] `auto_update_role` path skips `enforce_root_role_invariant` call — `app/routers/sso_saml.py` — The `_update_user_role` helper is defined in the ticket design but is not present in the implemented router; the `auto_update_role` branch (line 189) only calls `update_user_profile`, never updates the role. SSO group-to-role mapping has no effect on returning users. — Fix: Implement the role-update path and guard it with `enforce_root_role_invariant`. — Effort: S

- [LOW] `session_index` not stored in SSO session link — `app/routers/sso_saml.py:202-209` — `session_index` is extracted from the SAML assertion (line 137) but `_record_sso_session_link` is called with `session_index=session_index`; inspect the helper to confirm it is persisted — if `session_index` is dropped the SP cannot initiate IdP-side SLO for the correct session. — Fix: Verify `sso_sessions` DDB item stores `saml_session_index` and SLO endpoint uses it. — Effort: S
