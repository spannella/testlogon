## 1. Overview & Motivation

### The Gap

User search exists in the platform but is scoped exclusively to the messaging context. The `GET /messaging/contacts/search` endpoint (line 5544 of `app/routers/messaging.py`) queries the `UserSearch` DynamoDB table for prefix-matched tokens and returns results as `Contact` objects. This search:

1. **Is only accessible from the messaging router** — requires messaging-level auth (`get_messaging_user_id`). There is no public or general-purpose user search endpoint.
2. **Has no discovery features** — no suggested users, no trending creators, no "people you may know" algorithm.
3. **Uses basic prefix matching only** — the `UserSearch` table stores prefix tokens generated by `build_prefix_tokens()` (defined at line 2573, called at line 1534), which creates 1-12 character prefixes of display_name and email. There is no fuzzy matching, relevance ranking, or search scoring.
4. **Has no frontend discovery page** — there is no dedicated page for finding and exploring other users on the platform.
5. **Does not surface follower counts or follow status** — search results show only `user_id` and `display_name`, with no social context (follower count, mutual followers, follow button).

### Why This Is Needed

User discovery is essential for social platform growth. Without it:
- New users cannot find interesting creators to follow.
- The feed remains empty for users who do not manually know who to follow.
- Creator growth is stunted because there is no algorithmic surface to promote their content.
- The "New DM" dialog's search is the only way to find users, which is an unnatural discovery path.

## 3. Technical Design

### 3.1 New DynamoDB Table: `DiscoveryIndex`

A dedicated search index table optimized for user discovery:

| Attribute | Type | Description |
|-----------|------|-------------|
| pk | S | `TOKEN#{normalized_token}` |
| sk | S | `USER#{user_id}` |
| user_id | S | User's sub |
| display_name | S | Current display name |
| profile_photo_url | S | Avatar URL |
| follower_count | N | Cached follower count (updated on follow/unfollow) |
| description | S | Short bio / title (first 200 chars) |
| discoverability | S | `active` / `hidden` / `deactivated` / `deleted` |
| indexed_at | N | Unix timestamp of last index update |
| GSI1PK | S | `TRENDING` (for trending query) |
| GSI1SK | N | `follower_count` (numeric, for ranking) |

**Token generation**: For each user, generate tokens from:
- Display name (prefix tokens, 1-12 chars).
- Username/handle (prefix tokens, 1-12 chars).
- Exact match tokens for full display name and username.

**GSI1** (TrendingIndex):
- Partition key: `TRENDING` (constant — all visible users in one partition).
- Sort key: `follower_count` (numeric).
- Enables: "top creators by follower count" query with `ScanIndexForward=False`.

**DynamoDB Access Pattern Summary**:
```
+--------------------------------------------------------------------+
| Access Pattern                | Table/Index      | Key Condition    |
+--------------------------------------------------------------------+
| Search by prefix token        | Main table       | pk=TOKEN#{tok}   |
|                               |                  | sk begins_with   |
|                               |                  |   USER#          |
+--------------------------------------------------------------------+
| Trending creators (by count)  | GSI1             | GSI1PK=TRENDING  |
|                               |                  | ScanForward=F    |
+--------------------------------------------------------------------+
| All tokens for a user         | Main table       | FilterExpr:      |
|   (for re-indexing)           |                  | sk=USER#{uid}    |
+--------------------------------------------------------------------+
| Suggested users cache         | app_single_table | pk=DISCOVERY_    |
|                               |                  |   CACHE#{uid}    |
|                               |                  | sk=SUGGESTED     |
+--------------------------------------------------------------------+
```

### 3.2 API Endpoints

#### 3.2.1 `GET /ui/discover/search`

**Auth**: `Depends(require_ui_session)`

**Query parameters**:
```python
q: str = Query(..., min_length=1, max_length=64)
limit: int = Query(default=20, ge=1, le=50)
cursor: Optional[str] = Query(default=None)
```

**Response**:
```python
class DiscoveryUser(BaseModel):
    user_id: str
    display_name: str
    profile_photo_url: Optional[str] = None
    description: Optional[str] = None
    follower_count: int = 0
    is_following: bool = False
    is_followed_by: bool = False
    is_mutual: bool = False

class DiscoverySearchResponse(BaseModel):
    items: List[DiscoveryUser]
    next_cursor: Optional[str] = None
    total_estimate: int = 0
```

**Logic**:
1. Normalize query: lowercase, strip whitespace, split into tokens.
2. For each token, query `DiscoveryIndex` with `pk=TOKEN#{token}`.
3. Intersect results across tokens (AND semantics for multi-word queries).
4. Filter out `discoverability != "active"`.
5. Filter out the requester's own profile.
6. Sort by relevance: exact match > prefix match > partial match, then by `follower_count` descending.
7. For each result, check follow status against the requester (batch operation).
8. Return paginated results.

**Relevance scoring**:
```python
import math

def _score_search_result(user_item: dict, query_tokens: list[str]) -> float:
    score = 0.0
    name = (user_item.get("display_name") or "").lower()
    # Exact name match
    if name == " ".join(query_tokens):
        score += 100.0
    # Prefix match on name
    for token in query_tokens:
        if name.startswith(token):
            score += 50.0
        elif token in name:
            score += 20.0
    # Follower count boost (logarithmic)
    followers = int(user_item.get("follower_count", 0))
    if followers > 0:
        score += min(math.log10(followers) * 5, 25.0)
    return score
```

**Data flow diagram**:

#### 3.2.2 `GET /ui/discover/suggested`

**Auth**: `Depends(require_ui_session)`

**Query parameters**:
```python
limit: int = Query(default=12, ge=1, le=50)
```

**Response**: Same `DiscoverySearchResponse`.

**Algorithm**:
1. Get the requester's following list (up to 100 followed users).
2. For each followed user, get THEIR following list (up to 50 each) — "friends of friends".
3. Aggregate: count how many of requester's followed users also follow each candidate.
4. Filter out users already followed by the requester.
5. Filter out `discoverability != "active"`.
6. Sort by mutual follow count (descending), then by follower_count.
7. Return top N results.

**Caching**: The suggested users computation is expensive (multiple GSI queries). Cache the result per user for 1 hour in DynamoDB:

```python
CACHE_KEY = {"pk": f"DISCOVERY_CACHE#{user_id}", "sk": "SUGGESTED"}
CACHE_TTL = 3600  # 1 hour
```

### 3.3 Discovery Index Service — Full Implementation (`app/services/discovery.py`)

```python
# app/services/discovery.py (new file)

from __future__ import annotations

import logging
import math
import os
import time
from typing import Any, Dict, List, Optional, Set, Tuple

from boto3.dynamodb.conditions import Key, Attr
from botocore.exceptions import ClientError

from app.core.aws import ddb
from app.core.cursor import decode_cursor, encode_cursor
from app.core.settings import S
from app.core.tables import T
from app.services.profile import get_profile, PROFILE_FIELDS
from app.services.profile_discoverability import (
    resolve_discoverability_state,
    DiscoverabilityState,
)

DDB_DISCOVERY_INDEX = os.getenv("DDB_DISCOVERY_INDEX", "DiscoveryIndex")
tbl_discovery = ddb.Table(DDB_DISCOVERY_INDEX)

APP_TABLE = os.environ.get("APP_TABLE", "app_single_table")
tbl_app = ddb.Table(APP_TABLE)

logger = logging.getLogger(__name__)

# Token generation
MAX_PREFIX_LEN = 12
MAX_WORDS_FOR_PREFIX = 4


def build_discovery_tokens(display_name: str, username: Optional[str] = None) -> Set[str]:
    """Generate search tokens for a user profile.

    Returns a set of lowercase prefix tokens (1 to MAX_PREFIX_LEN chars)
    for each word in display_name and username, plus exact match tokens.
    """
    tokens: Set[str] = set()
    for field_value in [display_name, username]:
        if not field_value:
            continue
        normalized = field_value.strip().lower()
        words = normalized.split()[:MAX_WORDS_FOR_PREFIX]
        for word in words:
            word = word.strip()
            if not word:
                continue
            # Single-character tokens only for words >= 2 chars
            start = 1 if len(word) >= 2 else 2
            for i in range(start, min(len(word), MAX_PREFIX_LEN) + 1):
                tokens.add(word[:i])
        # Full value as exact match token
        if normalized:
            tokens.add(normalized)
    return tokens


def index_user_for_discovery(user_id: str) -> int:
    """Index or re-index a user in the discovery table.

    Reads profile data, generates tokens, writes/updates entries.
    Returns the number of tokens written.
    """
    profile = get_profile(user_id)
    if not profile:
        return 0
    display_name = (profile.get("display_name") or "").strip()
    if not display_name:
        return 0

    # Resolve discoverability
    acct_item = T.account_state.get_item(Key={"user_sub": user_id}).get("Item")
    discoverability = resolve_discoverability_state(acct_item)

    username = None  # TODO: read from profile when username field is added
    tokens = build_discovery_tokens(display_name, username)
    follower_count = int(profile.get("follower_count", 0))
    description = (profile.get("description") or profile.get("title") or "")[:200]
    photo_url = profile.get("profile_photo_url")
    now = int(time.time())

    with tbl_discovery.batch_writer() as bw:
        for token in tokens:
            item: Dict[str, Any] = {
                "pk": f"TOKEN#{token}",
                "sk": f"USER#{user_id}",
                "user_id": user_id,
                "display_name": display_name,
                "follower_count": follower_count,
                "discoverability": discoverability.value,
                "indexed_at": now,
                "GSI1PK": "TRENDING",
                "GSI1SK": follower_count,
            }
            if photo_url:
                item["profile_photo_url"] = photo_url
            if description:
                item["description"] = description
            bw.put_item(Item=item)
    return len(tokens)


def remove_user_from_discovery(user_id: str) -> int:
    """Delete all discovery index entries for a user.

    Scans for all pk=TOKEN#* with sk=USER#{user_id}.
    This is expensive but only called on account deletion or explicit hide.
    """
    deleted = 0
    last_key = None
    while True:
        kwargs: Dict[str, Any] = {
            "FilterExpression": Attr("sk").eq(f"USER#{user_id}"),
            "ProjectionExpression": "pk, sk",
            "Limit": 200,
        }
        if last_key:
            kwargs["ExclusiveStartKey"] = last_key
        resp = tbl_discovery.scan(**kwargs)
        items = resp.get("Items", [])
        if items:
            with tbl_discovery.batch_writer() as bw:
                for item in items:
                    bw.delete_item(Key={"pk": item["pk"], "sk": item["sk"]})
                    deleted += 1
        last_key = resp.get("LastEvaluatedKey")
        if not last_key:
            break
    return deleted


def search_users(
    query: str,
    *,
    viewer_id: Optional[str] = None,
    limit: int = 20,
    cursor: Optional[str] = None,
) -> Tuple[List[Dict[str, Any]], Optional[str]]:
    """Search users by prefix-matching their display name / username.

    Multi-word queries use AND semantics (all tokens must match).
    Results are scored by relevance and sorted descending.
    """
    normalized = query.strip().lower()
    if not normalized:
        return [], None

    query_tokens = [t.strip() for t in normalized.split() if t.strip()]
    if not query_tokens:
        return [], None

    # Query for each token and intersect
    candidate_sets: List[Dict[str, Dict]] = []
    for token in query_tokens:
        resp = tbl_discovery.query(
            KeyConditionExpression=Key("pk").eq(f"TOKEN#{token}"),
            Limit=200,
        )
        items = resp.get("Items", [])
        by_user: Dict[str, Dict] = {}
        for it in items:
            uid = it.get("user_id")
            if uid:
                by_user[uid] = it
        candidate_sets.append(by_user)

    if not candidate_sets:
        return [], None

    # Intersect across all token results
    common_ids = set(candidate_sets[0].keys())
    for cs in candidate_sets[1:]:
        common_ids &= set(cs.keys())

    # Get full item data from first token's results
    results = []
    for uid in common_ids:
        item = candidate_sets[0][uid]
        disc = item.get("discoverability", "active")
        if disc != "active":
            continue
        if viewer_id and uid == viewer_id:
            continue
        score = _score_search_result(item, query_tokens)
        results.append((score, item))

    # Sort by score descending
    results.sort(key=lambda x: x[0], reverse=True)

    # Paginate
    offset = 0
    if cursor:
        try:
            offset = int(cursor)
        except (ValueError, TypeError):
            offset = 0
    page = results[offset : offset + limit]
    next_cursor = str(offset + limit) if offset + limit < len(results) else None

    # Enrich with follow status
    items_out = []
    for _score, item in page:
        out = {
            "user_id": item.get("user_id"),
            "display_name": item.get("display_name"),
            "profile_photo_url": item.get("profile_photo_url"),
            "description": item.get("description"),
            "follower_count": int(item.get("follower_count", 0)),
            "is_following": False,
            "is_followed_by": False,
            "is_mutual": False,
        }
        items_out.append(out)

    if viewer_id:
        _enrich_with_follow_status(items_out, viewer_id)

    return items_out, next_cursor


def get_suggested_users(
    viewer_id: str,
    *,
    limit: int = 12,
) -> List[Dict[str, Any]]:
    """Return suggested users based on mutual follows and popularity.

    Algorithm: friends-of-friends. For each user the viewer follows,
    look at who THEY follow. Candidates that appear most often are
    suggested (they share the most mutual connections).
    """
    # Check cache first
    cache_item = tbl_app.get_item(
        Key={"pk": f"DISCOVERY_CACHE#{viewer_id}", "sk": "SUGGESTED"}
    ).get("Item")
    if cache_item and int(cache_item.get("expires_at", 0)) > int(time.time()):
        import json
        return json.loads(cache_item.get("data", "[]"))[:limit]

    # Get viewer's following list (up to 100)
    following_ids: Set[str] = set()
    last_key = None
    while len(following_ids) < 100:
        kw: Dict[str, Any] = {
            "KeyConditionExpression": (
                Key("pk").eq(f"USER#{viewer_id}")
                & Key("sk").begins_with("FOLLOWING#")
            ),
            "FilterExpression": Attr("state").eq("following"),
            "Limit": 100,
        }
        if last_key:
            kw["ExclusiveStartKey"] = last_key
        r = tbl_app.query(**kw)
        for it in r.get("Items", []):
            tid = it.get("target_user_id")
            if tid:
                following_ids.add(tid)
        last_key = r.get("LastEvaluatedKey")
        if not last_key:
            break

    if not following_ids:
        # Cold start: return trending instead
        return get_trending_creators(viewer_id=viewer_id, limit=limit)

    # Friends-of-friends aggregation
    candidate_scores: Dict[str, int] = {}
    for fid in following_ids:
        fof_key = None
        count = 0
        while count < 50:
            fof_kw: Dict[str, Any] = {
                "KeyConditionExpression": (
                    Key("pk").eq(f"USER#{fid}")
                    & Key("sk").begins_with("FOLLOWING#")
                ),
                "FilterExpression": Attr("state").eq("following"),
                "Limit": 50,
            }
            if fof_key:
                fof_kw["ExclusiveStartKey"] = fof_key
            fof_r = tbl_app.query(**fof_kw)
            for it in fof_r.get("Items", []):
                cid = it.get("target_user_id")
                if cid and cid != viewer_id and cid not in following_ids:
                    candidate_scores[cid] = candidate_scores.get(cid, 0) + 1
                count += 1
            fof_key = fof_r.get("LastEvaluatedKey")
            if not fof_key:
                break

    # Sort by score descending
    sorted_candidates = sorted(candidate_scores.items(), key=lambda x: x[1], reverse=True)
    top_ids = [uid for uid, _ in sorted_candidates[:limit * 2]]

    # Enrich with profile data
    results = []
    for uid in top_ids[:limit]:
        profile = get_profile(uid)
        if not profile:
            continue
        results.append({
            "user_id": uid,
            "display_name": profile.get("display_name", uid),
            "profile_photo_url": profile.get("profile_photo_url"),
            "description": (profile.get("description") or profile.get("title") or "")[:200],
            "follower_count": int(profile.get("follower_count", 0)),
            "is_following": False,
            "is_followed_by": False,
            "is_mutual": False,
        })

    _enrich_with_follow_status(results, viewer_id)

    # Write cache
    import json
    tbl_app.put_item(Item={
        "pk": f"DISCOVERY_CACHE#{viewer_id}",
        "sk": "SUGGESTED",
        "data": json.dumps(results),
        "expires_at": int(time.time()) + 3600,
        "ttl": int(time.time()) + 7200,
    })

    return results


def get_trending_creators(
    *,
    viewer_id: Optional[str] = None,
    limit: int = 20,
) -> List[Dict[str, Any]]:
    """Return top creators by follower count via GSI1 query."""
    resp = tbl_discovery.query(
        IndexName="GSI1",
        KeyConditionExpression=Key("GSI1PK").eq("TRENDING"),
        ScanIndexForward=False,
        Limit=limit * 2,  # Over-fetch to account for filtering
    )
    items = resp.get("Items", [])

    # Deduplicate by user_id (multiple token entries per user)
    seen: Set[str] = set()
    results = []
    for item in items:
        uid = item.get("user_id")
        if not uid or uid in seen:
            continue
        if item.get("discoverability", "active") != "active":
            continue
        seen.add(uid)
        results.append({
            "user_id": uid,
            "display_name": item.get("display_name"),
            "profile_photo_url": item.get("profile_photo_url"),
            "description": item.get("description"),
            "follower_count": int(item.get("follower_count", 0)),
            "is_following": False,
            "is_followed_by": False,
            "is_mutual": False,
        })
        if len(results) >= limit:
            break

    if viewer_id:
        _enrich_with_follow_status(results, viewer_id)

    return results


def _score_search_result(user_item: dict, query_tokens: list) -> float:
    """Score a search result for relevance ranking."""
    score = 0.0
    name = (user_item.get("display_name") or "").lower()
    joined_query = " ".join(query_tokens)
    if name == joined_query:
        score += 100.0
    for token in query_tokens:
        if name.startswith(token):
            score += 50.0
        elif token in name:
            score += 20.0
    followers = int(user_item.get("follower_count", 0))
    if followers > 0:
        score += min(math.log10(followers) * 5, 25.0)
    return score


def _enrich_with_follow_status(items: List[Dict], viewer_id: str) -> None:
    """Batch-check follow status for each user in the list."""
    from app.services.social import get_follow_status
    for item in items:
        uid = item.get("user_id")
        if not uid:
            continue
        try:
            status = get_follow_status(viewer_id, uid)
            item["is_following"] = status["is_following"]
            item["is_followed_by"] = status["is_followed_by"]
            item["is_mutual"] = status["is_mutual"]
        except Exception:
            pass


def reindex_all_users() -> Dict[str, int]:
    """Full re-index of all users. Run periodically (daily)."""
    indexed = 0
    errors = 0
    last_key = None
    while True:
        kwargs: Dict[str, Any] = {
            "ProjectionExpression": "user_sub",
            "Limit": 100,
        }
        if last_key:
            kwargs["ExclusiveStartKey"] = last_key
        resp = T.profile.scan(**kwargs)
        for item in resp.get("Items", []):
            user_sub = item.get("user_sub")
            if user_sub:
                try:
                    index_user_for_discovery(user_sub)
                    indexed += 1
                except Exception:
                    logger.exception("Failed to index user %s", user_sub)
                    errors += 1
        last_key = resp.get("LastEvaluatedKey")
        if not last_key:
            break
        time.sleep(0.02)  # Throttle: 50 users/second
    return {"indexed": indexed, "errors": errors}
```

### 3.4 Index Maintenance Strategy

The `DiscoveryIndex` must stay in sync with profile changes and follower count changes:

1. **On profile update** (`app/services/profile.py::apply_profile_update`): Re-index the user by calling `index_user_for_discovery(user_id)`.
2. **On follow/unfollow** (`app/services/social.py`): Update `follower_count` on all the user's discovery index entries. This is a scan + batch update, which can be deferred to a background task.
3. **On discoverability change** (`app/services/profile_discoverability.py::set_profile_discoverability_state`): Re-index to update the `discoverability` field on all token entries.
4. **Periodic full re-index**: A background job (daily) scans all users and re-indexes them. This catches any drift from missed updates.

### 3.5 Privacy Controls

- Users with `discoverability_status = "hidden"` are excluded from all search and discovery results.
- Users with `discoverability_status = "deactivated"` or `"deleted"` are excluded.
- Email is NOT indexed in the discovery table (unlike the messaging UserSearch table). Only display name and username.
- Profile fields returned are limited to public-audience fields per `PROFILE_FIELD_VISIBILITY` in `app/services/profile.py`.

### 3.6 Rate Limiting

- Search: 30 queries per minute per user.
- Suggested users: 10 queries per minute per user (cached, so rate limit is rarely hit).
- Trending: 60 queries per minute per user (lightweight query).

### 5.3 Edge Cases

1. **Empty profile** — User with no display_name should not be indexed (`index_user_for_discovery` returns 0).
2. **Very long display name** — Names over 128 chars are truncated for token generation. Only the first 3 words generate prefix tokens.
3. **Hot trending partition** — All visible users share `GSI1PK=TRENDING`. For >100K users, this partition exceeds DDB's 10GB limit. Mitigation: use a sharded key like `TRENDING#{shard}` where `shard = user_id_hash % 10`, and query all 10 shards + merge results. For MVP, the single partition is sufficient.
4. **Stale index entries** — A user changes their display name. Old token entries remain in the index. The periodic re-index job cleans these up. For immediate consistency, `index_user_for_discovery()` first deletes all existing entries for the user (scan `sk=USER#{user_id}` across all pk prefixes) — this is expensive, so only do it on explicit profile updates.
5. **Suggested users cold start** — New user with no follows gets no suggestions. Fallback: return trending creators instead.
6. **Concurrent index updates** — Two profile updates for the same user racing. DDB `put_item` is last-writer-wins, which is acceptable for search index data.

### 5.4 Performance Considerations

| Operation | DDB Reads | DDB Writes | Expected Latency |
|-----------|-----------|------------|-------------------|
| Search (single token) | 1 query (DiscoveryIndex) + N follow checks | 0 | ~30ms |
| Search (multi-word) | 2+ queries + intersection + N follow checks | 0 | ~60ms |
| Suggested users (cached) | 1 get_item (cache) | 0 | ~5ms |
| Suggested users (cold) | ~100 GSI queries + intersection | 1 (cache write) | ~500ms |
| Trending | 1 GSI1 query | 0 | ~10ms |
| Index user | 0 (profile from caller) | ~30 put_items (avg token count) | ~100ms |

## 6. Security Considerations

### 6.1 Authentication & Authorization

- Search and suggested endpoints require `require_ui_session` — no anonymous search.
- Trending endpoint is optionally authenticated (public for SEO).
- Discovery profile endpoint is optionally authenticated — public profile data only, follow status only when authenticated.

### 6.2 Input Validation

- Search query `q` is validated via Pydantic: `min_length=1, max_length=64`.
- Query tokens are normalized (lowercase, stripped) before DDB queries.
- User IDs in path parameters are validated against injection patterns.

### 6.3 Data Privacy

- Email addresses are NOT indexed in the DiscoveryIndex (unlike the messaging UserSearch table).
- Only public-audience profile fields are included in search results: `display_name`, `profile_photo_url`, `description`.
- Hidden/deactivated/deleted users are excluded from all results.

### 6.4 Abuse Vectors

- **Search scraping**: A user could scrape the search API to build a database of all users. Mitigation: rate limiting (30/min) + pagination limits (max 50 results per page).
- **Follower count manipulation**: Fake accounts following a creator to inflate trending ranking. Mitigation: SOC-001 rate limiting on follow + future bot detection.
- **Search token injection**: Malicious display names (e.g., "Buy Cheap Pills") polluting search results. Mitigation: content moderation on profile display_name + the `discoverability_status` suppression mechanism.

### 6.5 Bot Detection

- Suggested users computation involves expensive cross-graph queries. A bot making rapid `/discover/suggested` calls could cause DDB throughput spikes. Mitigation: aggressive rate limiting (10/min) + caching (1 hour TTL).

## 7. Migration & Rollback Plan

### 7.1 DDB Table Creation

The `DiscoveryIndex` table must be created before the feature is enabled. In local dev, this happens automatically via `scripts/local-ddb-init.py`. In production, create via CloudFormation.

### 7.2 Data Backfill

A one-time migration script to index all existing users:

```python
# scripts/migrate_discovery_index.py

def backfill_discovery_index():
    """Index all existing users in the DiscoveryIndex table."""
    from app.services.discovery import reindex_all_users
    result = reindex_all_users()
    print(f"Indexed {result['indexed']} users, {result['errors']} errors")
```

Estimated time for 10K users: ~200 seconds (50 users/second throttle).

### 7.3 Feature Flag

```
DISCOVERY_ENABLED=true       # Kill switch for all discovery endpoints
DISCOVERY_SUGGESTIONS=true   # Kill switch for suggested users (expensive)
```

### 7.4 Rollback Steps

1. Set `DISCOVERY_ENABLED=false` — returns 503 for all discovery endpoints.
2. Frontend falls back to the existing messaging search for user lookups.
3. DiscoveryIndex table data remains but is not queried.
4. To fully revert: drop the DiscoveryIndex table.

### 9.1 DiscoveryIndex Table Size

| Users | Avg tokens/user | Total items | Avg item size | Total size |
|-------|----------------|-------------|---------------|------------|
| 1K | 30 | 30K | 200 bytes | 6MB |
| 10K | 30 | 300K | 200 bytes | 60MB |

The `TRENDING` GSI1 partition at 1M users holds 30M items — this exceeds the 10GB per-partition limit. Shard the key at 100K+ users.

### 9.2 Caching Impact

Suggested users caching reduces repeated expensive queries:
- Without cache: ~100 GSI queries per call
- With cache (1h TTL): 1 get_item per call for 99%+ of requests
