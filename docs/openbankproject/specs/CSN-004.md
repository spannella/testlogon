# CSN-004 — Dynamic Endpoints — register a custom OpenAPI path mapped to a handler/connector

**Type:** Feature | **Priority:** P3 | **Estimate:** 3d
**Flag:** `DYNAMIC_ENDPOINTS_ENABLED` (new, default **off**)
**Source ticket:** `docs/openbankproject/OBP_CONSENTS_DYNAMIC_TICKETS.md` §CSN-004
**Gap row:** `docs/openbankproject/OBP_GAP_ANALYSIS.md:87` — "Dynamic Entities / Dynamic Endpoints — MISSING"

---

## 1. Summary & Goal

CSN-004 delivers the **Dynamic Endpoint** capability from the Open Bank Project (OBP) specification:
a ROOT-privileged administrator registers a custom `{method, path}` at runtime, maps it to an
allowlisted **connector kind**, and that path is immediately reachable through a static gateway
route — no code deploy, no restart required.

The two connector kinds shipped in this ticket are:

1. **`static_response`** — the registered endpoint returns a stored JSON body + HTTP status code.
   This is the OBP "mock dynamic endpoint" mode: useful for partner sandbox stubs, feature-flag
   redirects, and capability-advertisement surfaces.
2. **`dynamic_entity_proxy`** — the registered endpoint proxies to a CSN-003 dynamic entity's CRUD
   operations, mapping a custom path like `GET /custom/widgets` to `list_rows("widget")` without
   any new data path. This makes a partner-branded URL work transparently on top of the
   generic entity store.

Arbitrary code execution or handler binding is explicitly out of scope. The security boundary is
enforced by the allowlisted connector kinds and the `/custom/` path prefix.

The entire surface is **additive, flag-gated default-off**. When `DYNAMIC_ENDPOINTS_ENABLED` is
`false` (the default), no router is registered, no `T.dynamic_endpoints` table is read, no startup
task runs, and the platform is byte-for-byte unchanged.

## 2. Context & Current State

### 2.1 No dynamic endpoint surface exists today

`OBP_GAP_ANALYSIS.md:87` marks Dynamic Endpoints as **MISSING**. There is no runtime API
generator anywhere in the codebase. Every route is a statically compiled FastAPI handler in
`app/main.py` or one of its imported routers. CSN-004 closes this gap with a single static
catch-all gateway route that dispatches at runtime to a registered connector.

### 2.2 CSN-003 as the prerequisite for the proxy connector

The `dynamic_entity_proxy` connector kind calls functions defined in CSN-003's service module
(`app/services/dynamic_entities.py`): `list_rows`, `create_row`, `get_row`, `update_row`,
`delete_row`. The `static_response` connector is wholly independent of CSN-003 and can ship first.
The dependency is therefore **soft for the static connector, hard for the proxy connector**.
`register_endpoint` must validate that the referenced `entity_name` exists in
`T.dynamic_entity_defs` when `connector_kind = "dynamic_entity_proxy"`.

### 2.3 Root-session gating for admin writes

`require_root_session` (`app/auth/deps.py:308`) raises HTTP 403 for any caller whose `role != ROOT`.
It is already in use for admin-write gating at `app/routers/achievements.py:68` and for the CSN-003
entity definition endpoints. CSN-004 admin endpoints (register, list, delete definitions) use the
same dependency, with no new role system.

### 2.4 Conditional router registration pattern

`app/main.py:699-701` shows the established pattern for flag-gated routers:

```python
if _S.ticket_boards_enabled:
    from app.routers.ticket_boards import router as ticket_boards_router
    app.include_router(ticket_boards_router)
```

CSN-004 uses this same pattern. Neither the admin definition router nor the gateway catch-all is
imported or registered when `S.dynamic_endpoints_enabled` is `False`.

### 2.5 Audit machinery

`audit_event(event, user_sub, request, **fields)` (`app/services/alerts.py:644`) is the single
audit sink, called from every mutation in `app/routers/api_keys.py:21, 28, 35`. CSN-004 emits
`dynamic_endpoint.registered` and `dynamic_endpoint.deleted` via the same call.

### 2.6 Public-router and no-auth patterns (not used here; noted for contrast)

The public-router pattern (`calendar.py:89` — `public_event_router = APIRouter(prefix="/calendar/public", tags=["calendar_public"])`, imported at `app/main.py:61` and registered via `app.include_router` at `app/main.py:596`) is used by CSN-005 (open-data). CSN-004 gateway routes are **not** public — they require `require_ui_session` — because a dynamic endpoint could expose any registered connector operation, and allowing unauthenticated gateway access would be unsafe. An operator wishing to expose a public endpoint can register a `static_response` connector and then add its specific path to `API_KEY_ROUTE_EXEMPTIONS` (`app/services/api_key_route_scope_registry.py:70`) manually.

### 2.7 Rate-limit primitive

`_bucket_limit(user_sub, sid, max_n, win)` (`app/services/rate_limit.py:60`) is the DDB-backed
counter used by the KYC partner API throttle (`rate_limit.py:385`) and MFA send-rate limits.
CSN-004 introduces a per-endpoint invocation rate limit (keyed on `dye:{endpoint_id}:{caller_sub}`)
to prevent gateway amplification attacks, reusing `_bucket_limit` directly.

### 2.8 Pagination with cursor

`app/core/cursor.py` provides HMAC-signed opaque cursor encode/decode (handles `Decimal` from
numeric GSI `LastEvaluatedKey` via the `_json_default` helper at line 12). The `list_endpoints()`
service function uses this for the admin list endpoint.

### 2.9 DynamoDB table definition and numeric-GSI gotcha

All tables are declared as `TableDef` frozen dataclasses in `scripts/local-ddb-init.py:29-35`.
The `attr_types` field must list any numeric GSI sort key (`scripts/local-ddb-init.py:52-53`).
`T.*` handles are wired in `app/core/tables.py` using the `_FloatSafeTable` proxy (line 29).

## 3. Data Model

### 3.1 One new DynamoDB table: `dynamic_endpoints`

Single-table design; every registered endpoint definition is one row.

```
PK: endpoint_id   (S)    # "dye_" + uuid4().hex
SK: sk="DEF"      (S)    # constant sentinel; row is the sole item per endpoint
```

#### Attributes

| Attribute | DDB Type | Description |
|---|---|---|
| `endpoint_id` | S | `dye_{uuid4().hex}` |
| `sk` | S | `"DEF"` (constant) |
| `method` | S | One of `GET`, `POST`, `PUT`, `DELETE` |
| `path` | S | Normalized path, must start `/custom/`, e.g. `/custom/widgets` |
| `method_path` | S | `f"{method} {path}"` — uniqueness key used in `ByMethodPath` GSI |
| `connector_kind` | S | `"static_response"` or `"dynamic_entity_proxy"` |
| `connector_config` | M | Config map, shape depends on `connector_kind` (see §4.2) |
| `openapi_spec` | M | Stored path-item dict surfaced by `GET /ui/dynamic-endpoints/openapi` |
| `created_by` | S | ROOT `user_sub` who registered this endpoint |
| `created_at` | N | `now_ts()` integer Unix seconds |
| `updated_at` | N | `now_ts()` on each mutation |

#### `connector_config` shapes

**`static_response`**:
```json
{
  "status": 200,
  "body": { "...": "any JSON-serializable object" },
  "headers": {}
}
```
`status` must be a valid 2xx/3xx/4xx/5xx integer (validated at registration time).
`body` is stored as a DDB map and returned as JSON.
`headers` is optional; values must be strings.

**`dynamic_entity_proxy`**:
```json
{
  "entity_name": "widget",
  "op": "list | get | create | update | delete"
}
```
`entity_name` must match an existing `T.dynamic_entity_defs` row.
`op` is validated against the allowed set. Method/op compatibility is enforced:
`GET` accepts `list`/`get`; `POST` accepts `create`; `PUT` accepts `update`; `DELETE` accepts `delete`. (`PATCH` is **not** in the allowed method set — see §5.3.)

#### GSIs

**`ByMethodPath`** — enforces uniqueness and supports `get_endpoint(method, path)` lookup:

```
Partition key: method_path  (S)
Sort key:      sk           (S)     # always "DEF", so the GSI sort is deterministic
```

No numeric attributes on this GSI; no `attr_types` needed.

**`ByCreatedAt`** — supports ordered admin listing:

```
Partition key: created_by  (S)
Sort key:      created_at  (N)      # numeric → REQUIRES attr_types={"created_at": "N"}
```

#### `TableDef` declaration (`scripts/local-ddb-init.py`)

```python
TableDef(
    _resolve_table_name(S.dynamic_endpoints_table_name, "dynamic_endpoints"),
    partition_key="endpoint_id",
    sort_key="sk",
    gsi=[
        {
            "index_name": S.dynamic_endpoints_method_path_index,
            "partition_key": "method_path",
            "sort_key": "sk",
        },
        {
            "index_name": S.dynamic_endpoints_created_by_index,
            "partition_key": "created_by",
            "sort_key": "created_at",
        },
    ],
    attr_types={"created_at": "N"},   # numeric GSI sort key — mandatory
)
```

#### Settings added to `app/core/settings.py`


## 4. API / Service Design

### 4.1 Pydantic models (`app/models.py`)

```python
class DynamicEndpointCreateIn(BaseModel):
    method: Literal["GET", "POST", "PUT", "DELETE"]
    path: str                      # must start "/custom/"
    connector_kind: Literal["static_response", "dynamic_entity_proxy"]
    connector_config: dict         # validated per kind in service layer
    openapi_spec: dict | None = None  # caller-supplied path-item; defaulted if omitted

class DynamicEndpointOut(BaseModel):
    endpoint_id: str
    method: str
    path: str
    connector_kind: str
    connector_config: dict
    openapi_spec: dict
    created_by: str
    created_at: int
    updated_at: int

class DynamicEndpointListOut(BaseModel):
    endpoints: list[DynamicEndpointOut]
    cursor: str | None = None

class DynamicEndpointsOpenApiOut(BaseModel):
    paths: dict                    # merged OpenAPI path-items keyed by path string
```

### 4.2 Service layer: `app/services/dynamic_endpoints.py`

```python
def register_endpoint(
    admin_sub: str,
    body: DynamicEndpointCreateIn,
    req,
) -> DynamicEndpointOut:
    ...

def get_endpoint_by_id(endpoint_id: str) -> DynamicEndpointOut | None:
    ...

def get_endpoint(method: str, path: str) -> DynamicEndpointOut | None:
    """Query ByMethodPath GSI — used by the gateway on every invocation."""
    ...

def list_endpoints(
    *,
    created_by: str | None = None,
    cursor_token: str | None = None,
    limit: int = 50,
) -> DynamicEndpointListOut:
    ...

def delete_endpoint(admin_sub: str, endpoint_id: str, req) -> None:
    ...

def invoke_endpoint(
    endpoint: DynamicEndpointOut,
    method: str,
    path: str,
    caller_sub: str,
    request_body: dict | None,
    query_params: dict,
    req,
) -> JSONResponse:
    """Dispatch on connector_kind. Returns a FastAPI JSONResponse."""
    ...
```

#### `register_endpoint` logic

1. Validate `path` starts with `/custom/` and matches `^/custom/[a-zA-Z0-9/_\-\.{}]+$` (max 128 chars). Reject any path that would shadow the admin prefix `/ui/dynamic-endpoints` or any non-`/custom/` path.
2. Validate `method` is one of `GET POST PUT DELETE`.
3. Validate `connector_kind`:
   - `static_response`: require `status` (integer 100–599) and `body` (any JSON-serializable dict) in `connector_config`. Optional `headers` (dict of str→str, max 10 keys, no headers starting with `x-internal-` or overriding `content-type`).
   - `dynamic_entity_proxy`: require `entity_name` (validates it exists in `T.dynamic_entity_defs`) and `op` in `{list, get, create, update, delete}`. Validate `method`/`op` compatibility (see §3.1).
4. Check uniqueness via `ByMethodPath` GSI query on `method_path = f"{method} {path}"`. If a row exists: raise `409 endpoint_already_exists`.
5. Default `openapi_spec` if omitted: `{"summary": f"{method} {path}", "responses": {"200": {"description": "OK"}}}`.
6. Write item to `T.dynamic_endpoints` with `put_item`.
7. `audit_event("dynamic_endpoint.registered", admin_sub, req, endpoint_id=..., method=method, path=path, connector_kind=...)`.
8. Return `DynamicEndpointOut`.

#### `invoke_endpoint` logic

1. Rate-limit the caller: `_bucket_limit(f"dye:{endpoint.endpoint_id}:{caller_sub}", "rl#dye_invoke", S.dynamic_endpoints_invoke_rate_per_hour, 3600)`. If `False`: raise `429` with `detail.code="dynamic_endpoint_rate_limited"` and `Retry-After` header.
2. Dispatch on `connector_kind`:
   - **`static_response`**: return `JSONResponse(content=cfg["body"], status_code=cfg["status"], headers=cfg.get("headers", {}))`.
   - **`dynamic_entity_proxy`**: import `dynamic_entities` (local import to avoid circular dep if needed); dispatch `op`:
     - `list` → `list_rows(entity_name, owner_sub=caller_sub, ...)` (uses `query_params` for cursor/limit)
     - `get` → `get_row(entity_name, row_id, caller_sub)` (row_id from path param extracted from `path`; `caller_sub` enforces ownership — CSN-003 `get_row` signature requires `owner_sub` and returns `None` if owner mismatches)
     - `create` → `create_row(entity_name, caller_sub, request_body)`
     - `update` → `update_row(entity_name, row_id, caller_sub, request_body)`
     - `delete` → `delete_row(entity_name, row_id, caller_sub)` → `JSONResponse({"ok": True})`
3. Unknown `connector_kind` raises `500 internal_connector_error` (should be unreachable after validation at registration, but defensive).

### 4.3 Router: `app/routers/dynamic_endpoints.py`

Two logical sub-routers, **both registered in `app/main.py` only when `S.dynamic_endpoints_enabled`**:

#### Admin definition router (prefix `/ui/dynamic-endpoints`, `Depends(require_root_session)`)

| Method | Path | Handler | Notes |
|---|---|---|---|
| `POST` | `/ui/dynamic-endpoints` | `register_endpoint_handler` | 201 on success |
| `GET` | `/ui/dynamic-endpoints` | `list_endpoints_handler` | cursor-paginated |
| `GET` | `/ui/dynamic-endpoints/openapi` | `get_openapi_handler` | MUST be declared **before** `/{endpoint_id}` |
| `GET` | `/ui/dynamic-endpoints/{endpoint_id}` | `get_endpoint_handler` | |
| `DELETE` | `/ui/dynamic-endpoints/{endpoint_id}` | `delete_endpoint_handler` | |

The `/openapi` route must be declared before `/{endpoint_id}` in the router to prevent FastAPI from
capturing the literal string `openapi` as a path parameter — the same declaration-order constraint
documented in the CSN-003 spec and applied in `app/routers/kyc_cases.py` (templates routes before
`/{case_id}`).

#### Gateway catch-all router (prefix `/custom`, `Depends(require_ui_session)`)

```python
gateway_router = APIRouter(prefix="/custom", tags=["dynamic-endpoints-gateway"])

@gateway_router.get("/{path:path}")
async def gateway_get(path: str, request: Request, ctx=Depends(require_ui_session)):
    ...

@gateway_router.post("/{path:path}")
async def gateway_post(path: str, request: Request, ctx=Depends(require_ui_session)):
    ...

@gateway_router.put("/{path:path}")
async def gateway_put(path: str, request: Request, ctx=Depends(require_ui_session)):
    ...

@gateway_router.delete("/{path:path}")
async def gateway_delete(path: str, request: Request, ctx=Depends(require_ui_session)):
    ...
```

Each handler reconstructs `full_path = "/custom/" + path`, looks up `get_endpoint(method, full_path)`, and calls `invoke_endpoint(...)`. An unregistered path → `404` with `detail.code="endpoint_not_found"`.

**CSRF handling**: the gateway uses `require_ui_session`, which for non-GET cookie-auth requests requires the `x-csrf-token` header matching the session's stored `csrf_token` — the standard behavior of `require_ui_session` with no special case needed.

## 5. Detailed Behavior & Edge Cases

### 5.1 Path validation

A path is accepted only if it:
- Starts with `/custom/` (enforced first; any other prefix → `400 invalid_path_prefix`).
- Matches `^/custom/[a-zA-Z0-9/_\-\.{}]{1,120}$` (no `..`, no query-string characters, no null bytes).
- Does not shadow admin or internal paths (`/ui/`, `/internal/`, `/mock/`, `/telemetry/`).
- Is at most 128 characters total.

OpenAPI path templates with `{param}` placeholders (e.g. `/custom/widgets/{widget_id}`) are stored as-is. When the gateway receives a request for `/custom/widgets/abc123`, the lookup key is the registered template path; the gateway uses a simple prefix/template match (the `ByMethodPath` GSI stores the template; the gateway normalizes the incoming path by matching registered templates in order of specificity — more-specific templates first to prevent `/custom/widgets/{id}` from shadowing `/custom/widgets/featured`).

### 5.2 Uniqueness enforcement

`register_endpoint` queries `ByMethodPath` with `KeyConditionExpression=Key("method_path").eq(f"{method} {path}")`. If any result is returned: `409 endpoint_already_exists`. The GSI is eventually consistent (DynamoDB GSIs do **not** support `ConsistentRead=True` — this is a hard DynamoDB constraint); in the rare case of a concurrent double-registration, the second `put_item` is tolerated (both items exist) and the GSI may transiently return either item during dispatch. This is a very-low-probability race — the `409` prevents the common case. A conditional `put_item` with `attribute_not_exists(endpoint_id)` on the base table provides a stronger uniqueness guarantee for production use.

### 5.3 `dynamic_entity_proxy` — op/method compatibility table

| HTTP Method | Allowed `op` values |
|---|---|
| `GET` | `list`, `get` |
| `POST` | `create` |
| `PUT` | `update` |
| `DELETE` | `delete` |

A registration that pairs `GET` with `create` → `400 incompatible_method_op`. `PATCH` is not in the allowed method set (kept simple; `PUT` is used for full-replace update).

### 5.4 `dynamic_entity_proxy` path parameter extraction

For a `get`, `update`, or `delete` op the gateway must extract the row identifier from the URL. The convention is: if the registered path ends with a `{row_id}` template segment (e.g. `/custom/widgets/{row_id}`), the matching segment from the live request path is used as `row_id`. If no `{row_id}` segment is in the template but the op is `get`/`update`/`delete`, the gateway returns `400 missing_row_id` at invocation time (not at registration time, to allow the operator to fix the path template and re-register).

### 5.5 `static_response` body size cap

The stored `body` field is a DDB map. DDB item size limit is 400 KB, but `body` is bounded at 64 KB (measured as the UTF-8 encoding of its JSON serialization) at registration time to prevent abuse of the definition store. Bodies larger than 64 KB → `400 body_too_large`.

### 5.6 Delete behavior

`delete_endpoint(endpoint_id)` performs a `delete_item` on `T.dynamic_endpoints`. The `ByMethodPath` GSI entry is removed automatically (DDB GSI is updated on item deletion). After deletion, any in-flight requests to the gateway for that path get `404` (the GSI read misses). There is no soft-delete; the audit trail (`dynamic_endpoint.deleted`) serves as the historical record.

### 5.7 `GET /ui/dynamic-endpoints/openapi` — merged path-items

This endpoint scans `T.dynamic_endpoints` (all `sk="DEF"` items) and merges their `openapi_spec` fields into a single `{"paths": {...}}` response keyed by path string, with method-level path-item objects. Two endpoints on the same path but different methods are merged under the same path key. This provides a runtime OpenAPI fragment that clients can use to understand the dynamic surface. The response is informational only — it is not automatically injected into the main `GET /openapi.json`.

### 5.8 Rate limit on invocation

The per-endpoint-per-caller rate limit uses `_bucket_limit` (`rate_limit.py:60`) keyed on
`f"dye:{endpoint_id}:{caller_sub}"` with `sid="rl#dye_invoke"`, `max_n=S.dynamic_endpoints_invoke_rate_per_hour` (default 1000), `win=3600`. On `False` (limit exceeded): raise `HTTPException(429, detail={"code": "dynamic_endpoint_rate_limited", "endpoint_id": endpoint_id, "limit": ..., "window_seconds": 3600})` with `Retry-After` header. This reuses `_bucket_limit` exactly as `rate_limit_kyc_partner_api` does at `rate_limit.py:385-425`.

### 5.9 Error catalog

| Condition | HTTP | `detail.code` |
|---|---|---|
| Path not under `/custom/` | 400 | `invalid_path_prefix` |
| Path fails charset/length regex | 400 | `invalid_path_format` |
| Unknown `connector_kind` | 400 | `unknown_connector_kind` |
| Malformed `connector_config` | 400 | `invalid_connector_config` |
| `dynamic_entity_proxy` references unknown entity | 400 | `entity_not_found` |
| Incompatible `method`/`op` | 400 | `incompatible_method_op` |
| Body exceeds 64 KB | 400 | `body_too_large` |
| Duplicate `method + path` | 409 | `endpoint_already_exists` |
| Non-root caller on admin routes | 403 | (FastAPI default from `require_root_session`) |
| Unregistered path at gateway | 404 | `endpoint_not_found` |
| Invocation rate limit exceeded | 429 | `dynamic_endpoint_rate_limited` |

## 6. Feature Flag & Config

### 6.1 Master flag

`DYNAMIC_ENDPOINTS_ENABLED` (env var) → `S.dynamic_endpoints_enabled: bool` (default `false`).

When `false`:
- No router is imported or registered in `app/main.py` (neither admin nor gateway).
- No DynamoDB table is read or written.
- No startup task or middleware runs.
- Every request to `/custom/*` and `/ui/dynamic-endpoints/*` returns `404` (FastAPI default for unregistered paths).
- The platform is byte-for-byte unchanged.

When `true`:
- Both routers registered; `T.dynamic_endpoints` table must exist.
- The CSN-003 flag (`DYNAMIC_ENTITIES_ENABLED`) must also be `true` for `dynamic_entity_proxy` connectors to function. The system is operational with only `static_response` connectors even if CSN-003 is off.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security & Money-safety

### 7.1 Dev/prod parity (SECOPS-007)

There is no `if S.dev_mode:` branch anywhere in `app/services/dynamic_endpoints.py` or
`app/routers/dynamic_endpoints.py`. All DDB I/O goes through frozen `T.dynamic_endpoints`
(`_FloatSafeTable` proxy, `app/core/tables.py:29`), which resolves to DynamoDB Local in dev and real
DynamoDB in prod. The `static_response` connector returns the stored JSON without any env-conditional
logic. The `dynamic_entity_proxy` connector calls `dynamic_entities` service functions that are
themselves parity-clean.

### 7.2 Registration idempotency

`register_endpoint` is **not idempotent by default** — a second call with the same `method + path`
returns `409 endpoint_already_exists`. This is deliberate: silent idempotency would make it easy to
accidentally overwrite a live endpoint's config without a delete-then-create audit trail.

`delete_endpoint` followed by `register_endpoint` with the same `method + path` is the correct
update path. This ensures every config change has two audit events: `dynamic_endpoint.deleted` +
`dynamic_endpoint.registered`.

### 7.3 Security constraints

**Attack surface containment:**
- `/custom/` prefix restriction prevents shadowing existing platform routes.
- Allowlisted connector kinds prevent arbitrary code execution.
- `body` size cap (64 KB) prevents the definition store from becoming a large-payload cache.
- Gateway requires `require_ui_session` (not public) so unauthenticated clients cannot reach any connector unless the operator explicitly removes specific paths from auth via `API_KEY_ROUTE_EXEMPTIONS`.
- Header injection: the `static_response` connector validates that no `connector_config.headers` key begins with `x-internal-` and does not override `content-type`, `set-cookie`, or auth headers.
- The `dynamic_entity_proxy` connector is caller-scoped: it passes `caller_sub` as `owner_sub`, so a regular user cannot list or modify another user's rows.

**No money movement:** CSN-004 touches no billing, ledger, or wallet primitives. The `dynamic_entity_proxy` connector calls only `dynamic_entities` service functions, which are DDB-only. No `new_ledger_entry`, `apply_wallet_delta`, `settle_or_reverse_ledger`, or payment-method reads appear in this ticket. There is no TXR, PIS, or SCA interaction.

### 7.4 Audit trail

Every `register_endpoint` and `delete_endpoint` emits `audit_event(...)` (`app/services/alerts.py:644`)
with at minimum `{endpoint_id, method, path, connector_kind}`. Gateway invocations are not audited
per-call (high volume) but are tracked via the rate-limit bucket, which serves as an invocation
counter.

## 8. Backward Compatibility & Migration

### 8.1 Zero impact when flag is off

No existing behavior changes when `DYNAMIC_ENDPOINTS_ENABLED=false`. The `dynamic_endpoints` table
does not need to exist until the flag is first enabled. No migration is required for existing data.

### 8.2 First-time enable in production

1. Add the five settings keys to `.env.local` (dev) / Secrets Manager / Parameter Store (prod).
2. Run `scripts/local-ddb-init.py` (dev) or apply `CreateTable` (prod) for `dynamic_endpoints` with
   both GSIs and `attr_types={"created_at": "N"}`.
3. Set `DYNAMIC_ENDPOINTS_ENABLED=true` and restart the backend.
4. Optionally enable `DYNAMIC_ENTITIES_ENABLED=true` (CSN-003) if `dynamic_entity_proxy` connectors
   are needed.

No backfill is needed; the table starts empty.

### 8.3 Schema evolution

The `connector_config` and `openapi_spec` attributes are stored as DDB maps and treated as opaque
blobs by the framework. Adding new fields to `connector_config` for a future connector kind is
backward-compatible: existing registered endpoints are unaffected. Adding a new `connector_kind`
requires a code deploy (a new dispatch branch in `invoke_endpoint`) and must be accompanied by a
version bump in the `openapi_spec` defaults for new registrations.

### 8.4 Removing an endpoint

`DELETE /ui/dynamic-endpoints/{endpoint_id}` hard-deletes the DDB row and GSI entries. Any
in-flight requests after deletion receive `404 endpoint_not_found`. There is no grace-period
drain; operators should coordinate client-side before deleting.

## 10. Open Questions / Assumptions

1. **Path template matching order**: The spec assumes a first-registered-wins match when two templates could both match an incoming path (e.g. `/custom/widgets/{id}` and `/custom/widgets/featured`). More-specific static segments should take priority over `{param}` segments. The implementation should sort registered templates by specificity (number of static segments) before matching. This ordering behavior should be documented in the operator guide.

2. **PATCH method**: The current design omits `PATCH` from the allowed method set to keep the gateway simple. If needed in future, `PATCH` maps to `update` (partial update) in the `dynamic_entity_proxy`. Adding it is backward-compatible (no existing endpoints break; validation allows it).

3. **Connector kind: internal service proxy**: The ticket description calls out a third connector kind (`connector` that calls a registered internal service) as an explicit follow-up. The design here does not allocate any data model or service-call mechanism for it. When added, it should reuse the existing service-layer import pattern and add a new `connector_config` shape.

4. **`dynamic_entity_proxy` `get` by non-`row_id` key**: The proxy `get` op assumes the row identifier is in the URL as `{row_id}`. If an entity needs a custom lookup key (e.g. `{slug}`), the `connector_config` should carry a `row_id_param` field. This is not shipped here; the default is always `row_id`.

5. **Assumption**: `T.dynamic_entity_defs` and `T.dynamic_entity_rows` (CSN-003) must exist when `dynamic_entity_proxy` connectors are used. If `DYNAMIC_ENTITIES_ENABLED=false` but `DYNAMIC_ENDPOINTS_ENABLED=true`, any `dynamic_entity_proxy` connector will fail at invocation time (DDB table missing or entity not found). A startup check should warn (log only, not fail) if any registered `dynamic_entity_proxy` endpoints exist while `DYNAMIC_ENTITIES_ENABLED` is off.

6. **Assumption**: The `openapi_spec` stored at registration time is not live-revalidated when the `dynamic_entity_proxy` entity schema changes in CSN-003. It is informational only. Operators must re-register or update the endpoint's `openapi_spec` if the underlying entity schema evolves.
