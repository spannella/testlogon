# PRT-003 — Jobs RSS / Atom feed

**Prefix:** `PRT` · **Area:** ATS / Public Career Portal  
**Type:** Feature · **Priority:** P2 · **Estimate:** 0.5d  
**Source:** `docs/opencats/ATS_CAREER_PORTAL_TICKETS.md` §PRT-003; gap: `docs/opencats/OPENCATS_GAP_ANALYSIS.md:80-84`

---

## 1. Summary & Goal

PRT-003 delivers a public RSS 2.0 feed of all `is_public=True` + open job orders so that external job boards, aggregators, and automated indexers can subscribe to and syndicate the platform's open positions.

The feed is a single public endpoint — `GET /public/careers/jobs.rss` — that returns a valid RSS 2.0 XML document (`Content-Type: application/rss+xml`). It is a thin read-through over the `list_public_jobs` service function introduced by PRT-002: no new DynamoDB tables, no new GSIs, no new auth surface. The only new artefacts are:

1. `build_jobs_rss() -> str` in `app/services/career_portal.py` — a dependency-free XML string builder that assembles a well-formed RSS 2.0 channel from the public job listing and portal config.
2. `GET /public/careers/jobs.rss` handler on the `public_router` declared in PRT-001.
3. One new `API_KEY_ROUTE_EXEMPTIONS` entry.
4. One new settings key: `S.career_portal_rss_max_items` (default 50, env `CAREER_PORTAL_RSS_MAX_ITEMS`).

With `S.career_portal_enabled = False` the endpoint returns HTTP 404 and no I/O occurs — byte-for-byte identical behavior to all other PRT endpoints. With the flag on and JOB-* absent at runtime the feed renders as an empty but structurally valid RSS channel (zero `<item>` elements), not a 500.

## 2. Context & Current State

**No RSS or Atom feed exists anywhere in the codebase.** `docs/opencats/OPENCATS_GAP_ANALYSIS.md:80` classifies the entire public job board (including RSS) as `MISSING`. Grep of the app tree confirms no `rss`, `atom`, or `application/rss+xml` reference in any existing router or service.

**Existing primitives this ticket directly reuses, grounded in code:**

- **Dependency-free text-payload `Response` pattern** (`app/routers/calendar.py:2097-2109`): the `download_public_ical` handler builds an iCal string with `_build_ics` (`:2048`) and returns it via `Response(content=ics, media_type="text/calendar", headers={...})`. PRT-003 follows the exact same pattern: build an XML string, return `Response(content=xml, media_type="application/rss+xml")`. No external library (`feedgen`, `lxml`, `ElementTree`) is imported — identical to the dependency-free approach of `app/services/receipts.py` and `app/services/audit_export_pipeline.py` (CLAUDE.md "Audit export PDF format").

- **`_extract_excerpt` HTML-strip helper** (`docs/suitecrm/specs/KB-011.md:336-340`): `_extract_excerpt(body_html, max_chars)` strips HTML tags via `re.sub(r"<[^>]+>", " ", ...)` and normalizes whitespace. PRT-003 uses this algorithm on `public_description` to produce a tag-free `<description>` text for each RSS `<item>`. KB-011 §4.2 defines the function for `app/services/kb_articles.py` (a spec-only file, not yet in the repo). PRT-003 **inlines** the logic as `_strip_html_excerpt` (see §4.1) rather than importing across services, to avoid a cross-service coupling between `career_portal.py` and a not-yet-deployed `kb_articles.py`. This decision is documented in §10 assumption #3.

- **`html.escape` for XML attribute/content escaping** (`app/services/seo_metadata.py:650-651`): `html.escape(value, quote=True)` from Python's standard library is the existing codebase pattern for escaping user-controlled strings before interpolation into markup. PRT-003's `_xml_escape` wrapper calls `html.escape(str(v), quote=True)` — same stdlib import, no third-party dep. `html.escape(..., quote=True)` covers the mandatory XML character escapes: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`, and also escapes `'` → `&#x27;` (Python stdlib behavior — not `&apos;`; see §10 assumption #1 for why this is acceptable).

- **`list_public_jobs` service function** (`app/services/career_portal.py`, PRT-002): the single source of truth for the public job listing. `build_jobs_rss` calls it with `limit=S.career_portal_rss_max_items` and `cursor=None` (single page; RSS feeds are not paginated). The lazy-import + `try/except` degradation that wraps JOB-* inside `list_public_jobs` is already in place; PRT-003 inherits it for free.

- **`get_portal_config` service function** (`app/services/career_portal.py`, PRT-001): provides `portal_name` (RSS channel `<title>`) and `support_email` (channel `<managingEditor>`). Never raises when no config row exists — returns S-defaults.

- **`S.public_base_url`** (`app/core/settings.py:349`): `os.environ.get("PUBLIC_BASE_URL", "http://localhost:8000").rstrip("/")`. The RSS item `<link>` is `{S.public_base_url}/public/careers/jobs/{slug}`. In dev this is `http://localhost:8000/public/careers/jobs/{slug}`; in prod the real domain. No `dev_mode` branch in PRT code (SECOPS-007).

- **`_require_enabled()` guard** (`app/services/career_portal.py`, PRT-001): raises `HTTPException(404)` when `S.career_portal_enabled` is `False`. `build_jobs_rss` calls this at entry — identical to `list_public_jobs` and `get_job_detail`.

- **`public_router` APIRouter skeleton** (`app/routers/career_portal.py`, PRT-001): `public_router = APIRouter(prefix="/public/careers", tags=["career_portal_public"])`. The route `GET /public/careers/jobs.rss` is appended to this same router object; no new `include_router` call needed in `app/main.py`.

- **`API_KEY_ROUTE_EXEMPTIONS`** (`app/services/api_key_route_scope_registry.py:70`): dictionary of `"METHOD:/path": {"reason": "..."}` entries. PRT-002 added entries for `/config`, `/jobs`, and `/jobs/{slug}`; PRT-003 adds one entry for `/jobs.rss`. Without this entry, API-key-bearing callers without a matching scope receive 403.

- **`now_ts()`** (`app/core/time.py:2`): integer Unix timestamp. Used to build the channel `<lastBuildDate>` (the current server time at feed generation, formatted as RFC-822).

- **Route declaration order constraint**: the `jobs.rss` path uses a dot (`.`) in the segment name, which FastAPI treats as a literal string. It must be declared **before** `GET /jobs/{slug}` on `public_router` to prevent FastAPI from attempting to capture `"jobs.rss"` as a slug value and routing to the detail handler. Per CLAUDE.md ("KYC template-signature endpoints" and KB-011 §4.1), static/literal paths always precede dynamic `{param}` paths. The current PRT-002 declaration order is: `GET /config`, `GET /jobs`, `GET /jobs/{slug}`. PRT-003 inserts `GET /jobs.rss` **after** `GET /jobs` and **before** `GET /jobs/{slug}`.

## 4. API / Service Design

### 4.1 Service function: `build_jobs_rss() -> str` in `app/services/career_portal.py`

Appended to the service module created by PRT-001 and extended by PRT-002. Synchronous (no `async`). Returns a complete RSS 2.0 XML document as a Python `str`.

```python
import html as _html
import re as _re
from datetime import datetime, timezone

def _xml_escape(v: object) -> str:
    """Escape a value for safe interpolation into XML text content or attribute values.
    Uses stdlib html.escape (same pattern as app/services/seo_metadata.py:650-651).
    Covers &, <, >, " per XML 1.0 §2.4.
    """
    return _html.escape("" if v is None else str(v), quote=True)

def _rfc822_date(unix_ts: int) -> str:
    """Format a Unix timestamp as an RFC-822 date string for RSS <pubDate>/<lastBuildDate>.
    Example: 'Tue, 14 Nov 2023 22:13:20 +0000'
    Dependency-free: uses strftime on a UTC datetime (no email.utils, no feedgen).
    """
    dt = datetime.fromtimestamp(unix_ts, tz=timezone.utc)
    return dt.strftime("%a, %d %b %Y %H:%M:%S +0000")

def _strip_html_excerpt(text: str | None, max_chars: int = 500) -> str:
    """Strip HTML tags and return a plain-text excerpt for RSS <description>.
    Reuses the _extract_excerpt regex approach from app/services/kb_articles.py
    (KB-011 §4.2): re.sub(r'<[^>]+>', ' ', ...) + whitespace normalization.
    Inline here to avoid a cross-service import cycle; same dependency-free constraint.
    """
    if not text:
        return ""
    text = _re.sub(r"<[^>]+>", " ", text)
    text = _re.sub(r"\s+", " ", text).strip()
    return text[:max_chars]

def build_jobs_rss() -> str:
    """Build an RSS 2.0 XML document for public job listings.

    Returns a well-formed RSS 2.0 string. Calls _require_enabled() → 404 when
    career_portal_enabled is False. Calls list_public_jobs() (PRT-002) which
    already lazy-imports JOB-* and degrades gracefully to an empty list if absent.
    Channel metadata comes from get_portal_config() (PRT-001), which returns
    S-defaults if no admin config row exists.

    XML escaping: every interpolated value is passed through _xml_escape().
    Date formatting: _rfc822_date() for <pubDate> and <lastBuildDate>.
    Dependency-free: no feedgen, lxml, or ElementTree — same approach as
    _build_ics() at app/routers/calendar.py:2048 and receipts.py.
    """
    _require_enabled()

    config = get_portal_config()           # never raises; returns S-defaults on no row
    portal_name = _xml_escape(config.get("portal_name") or "Careers")
    support_email = _xml_escape(config.get("support_email") or "")

    listing = list_public_jobs(limit=S.career_portal_rss_max_items, cursor=None)
    items: list[dict] = listing.get("items", []) or []

    portal_link = f"{S.public_base_url}/careers"
    now_str = _rfc822_date(now_ts())

    lines: list[str] = [
        '<?xml version="1.0" encoding="UTF-8"?>',
        '<rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom">',
        "  <channel>",
        f"    <title>{portal_name} — Open Positions</title>",
        f"    <link>{_xml_escape(portal_link)}</link>",
        f"    <description>Current job openings at {portal_name}</description>",
        f"    <language>en-us</language>",
        f"    <lastBuildDate>{now_str}</lastBuildDate>",
        f'    <atom:link href="{_xml_escape(S.public_base_url)}/public/careers/jobs.rss"'
        f' rel="self" type="application/rss+xml" />',
    ]
    if support_email:
        lines.append(f"    <managingEditor>{support_email}</managingEditor>")

    for item in items:
        slug = item.get("slug", "")
        item_link = f"{S.public_base_url}/public/careers/jobs/{_xml_escape(slug)}"
        posted_at = int(item.get("posted_at") or 0)
        pub_date = _rfc822_date(posted_at) if posted_at else now_str
        description_text = _strip_html_excerpt(item.get("public_description") or "", 500)

        lines += [
            "    <item>",
            f"      <title>{_xml_escape(item.get('title', ''))}</title>",
            f"      <link>{_xml_escape(item_link)}</link>",
            f"      <guid isPermaLink=\"true\">{_xml_escape(item_link)}</guid>",
            f"      <pubDate>{pub_date}</pubDate>",
            f"      <description>{_xml_escape(description_text)}</description>",
        ]
        if item.get("location"):
            lines.append(
                f"      <category>{_xml_escape(item['location'])}</category>"
            )
        if item.get("employment_type"):
            lines.append(
                f"      <category>{_xml_escape(item['employment_type'])}</category>"
            )
        lines.append("    </item>")

    lines += ["  </channel>", "</rss>"]
    return "\n".join(lines)
```

**Design notes:**

- `_xml_escape` wraps `html.escape(..., quote=True)` from stdlib, matching the pattern in `app/services/seo_metadata.py:650-651`. The `quote=True` flag escapes `"` to `&quot;`, which is required inside XML attribute values (used in the `<atom:link href="...">` element and `<guid isPermaLink="...">` attribute).
- `_strip_html_excerpt` mirrors `_extract_excerpt` from `app/services/kb_articles.py` (KB-011 §4.2) inline, with a larger `max_chars=500` cap suitable for RSS description fields. The same two-regex approach (`<[^>]+>` strip + `\s+` normalize) is used. It is inlined rather than imported to avoid a cross-service import between `career_portal.py` and `kb_articles.py`; the KB-011 spec notes this approach is "dependency-free" and "private helper but importable" — both are valid; the inline approach removes coupling.
- `_rfc822_date` uses `datetime.strftime("%a, %d %b %Y %H:%M:%S +0000")` on a UTC datetime. No `email.utils.formatdate` is called — the standard library's strftime produces a conforming RFC-822 date string for UTC timestamps. Python's `strftime` day/month abbreviations are locale-independent for the `%a`/`%b` directives when the locale is `C` (the default on most Linux servers).
- The `<atom:link rel="self">` element is the recommended self-referential Atom namespace extension for RSS 2.0 feeds; it allows feed readers to detect feed updates correctly. The namespace declaration `xmlns:atom="http://www.w3.org/2005/Atom"` is on the `<rss>` root element. No Atom-specific elements beyond `<atom:link>` are used.
- `<guid isPermaLink="true">` is set to the full item URL. If the slug changes (JOB-* republishes with a different slug), the GUID changes and feed readers treat it as a new entry. This is acceptable behavior — slug immutability is a JOB-* responsibility.
- `<category>` is used for `location` and `employment_type` because RSS 2.0 has no dedicated job-metadata elements. This is the standard practice for job board RSS feeds. Multiple `<category>` elements per item are valid in RSS 2.0.
- The function does not set `<ttl>` or `Cache-Control` headers. Caching policy is left to the operator's CDN/proxy configuration. PRT-003 deliberately sets no cache headers to avoid stale listings.

### 4.2 Router handler in `app/routers/career_portal.py`

Appended to the router module after PRT-002's `GET /jobs` declaration and **before** `GET /jobs/{slug}`. The `from fastapi.responses import Response` import is already used by the calendar iCal handler at `app/routers/calendar.py:2099`; PRT-003 follows the identical import pattern.

```python
from fastapi.responses import Response as _FastAPIResponse
from app.services.career_portal import build_jobs_rss

@public_router.get("/jobs.rss")
def public_jobs_rss() -> _FastAPIResponse:
    """Public RSS 2.0 feed of all open job postings.
    No auth. Mirrors the calendar iCal handler pattern at
    app/routers/calendar.py:2097-2109.
    Flag off → build_jobs_rss() raises HTTPException(404) via _require_enabled().
    """
    xml = build_jobs_rss()
    return _FastAPIResponse(
        content=xml,
        media_type="application/rss+xml; charset=utf-8",
        headers={
            "Content-Disposition": 'inline; filename="jobs.rss"',
            "X-Content-Type-Options": "nosniff",
        },
    )
```

No `Depends(...)` auth parameter. No CSRF (GET request; CSRF gate at `app/services/sessions.py:429` fires only when `ui_session` cookie is present). No `response_model` — the return type is a raw `Response`, not a Pydantic model.

The `media_type="application/rss+xml; charset=utf-8"` is the registered IANA media type for RSS feeds. The `X-Content-Type-Options: nosniff` header prevents browsers from MIME-sniffing the XML response as HTML (a defense against RSS content injection attacks).

**Declaration order on `public_router`** (critical):

```
GET /config          ← PRT-002 (static)
GET /jobs            ← PRT-002 (static)
GET /jobs.rss        ← PRT-003 (static, dot in segment — must precede {slug})
GET /jobs/{slug}     ← PRT-002 (dynamic)
```

FastAPI matches routes in declaration order. `"jobs.rss"` contains a literal dot that is not special in URL path syntax, so `GET /public/careers/jobs.rss` would match `GET /public/careers/jobs/{slug}` with `slug="jobs.rss"` if the dynamic route were declared first. Declaring `GET /jobs.rss` before `GET /jobs/{slug}` prevents this capture — the same constraint applied to `GET /config` and `GET /jobs` in PRT-002 §5.8.

## 5. Detailed Behavior & Edge Cases

### 5.1 Flag-off behavior

When `S.career_portal_enabled = False`:
- `build_jobs_rss()` calls `_require_enabled()` as its first statement → `HTTPException(404, "Not found")`.
- The handler propagates the 404; no XML is generated; no DDB reads occur.
- This is identical to `list_public_jobs()` and `get_job_detail()` (PRT-002 §5.1).

### 5.2 JOB-* absent at runtime

`list_public_jobs` (PRT-002) wraps the JOB-* lazy import in `try/except Exception` and returns `{"items": [], "cursor": None, "total_estimate": None}` on any error. `build_jobs_rss` therefore receives `items=[]` and generates a valid RSS 2.0 document with zero `<item>` elements:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom">
  <channel>
    <title>Careers — Open Positions</title>
    <link>http://localhost:8000/careers</link>
    <description>Current job openings at Careers</description>
    <language>en-us</language>
    <lastBuildDate>Tue, 14 Nov 2023 22:13:20 +0000</lastBuildDate>
    <atom:link href="http://localhost:8000/public/careers/jobs.rss" rel="self" type="application/rss+xml" />
  </channel>
</rss>
```

This is a valid, parseable RSS document. Feed readers that subscribe to it will show zero items rather than an error. No 500 is raised.

### 5.3 Portal config absent

`get_portal_config()` (PRT-001) returns S-defaults when no config row exists (`portal_name="Careers"`, `support_email=None`). `build_jobs_rss` handles this gracefully: `portal_name` defaults to `"Careers"`, and `<managingEditor>` is omitted when `support_email` is falsy. The channel renders correctly without admin-set branding.

### 5.4 XML escaping correctness

Every string interpolated into the XML output passes through `_xml_escape`. Critical cases:
- Job title containing `&`: `"Software & Hardware Engineer"` → `Software &amp; Hardware Engineer` in `<title>`.
- Public description containing `<script>` tags → stripped to plain text by `_strip_html_excerpt` before `_xml_escape`; the resulting plain text is then XML-escaped.
- Slug containing URL-unsafe characters (should not occur if JOB-* enforces slug format, but PRT-003 escapes defensively).
- Support email containing `"@"`: `_xml_escape` leaves `@` unchanged (not a special XML character); the email is safely embedded in `<managingEditor>`.
- `portal_link` and `item_link` are full URLs; `_xml_escape` escapes any `&` in query strings (e.g. `?utm_source=rss&utm_medium=feed` → `&amp;`).

The `_strip_html_excerpt` → `_xml_escape` pipeline is applied to `public_description` before use in `<description>`. This two-step approach (strip HTML first, then XML-escape the resulting plain text) prevents double-escaping of legitimate `&` characters that appear in plain text (e.g. `"Rust & Go experience"`).

### 5.5 `posted_at` of zero or absent

Some job orders created before `posted_at` was introduced by JOB-* may have `posted_at=0` or a missing field. `build_jobs_rss` handles this:

```python
posted_at = int(item.get("posted_at") or 0)
pub_date = _rfc822_date(posted_at) if posted_at else now_str
```

If `posted_at` is falsy (0 or absent), `<pubDate>` falls back to `now_str` (the feed generation timestamp). Feed readers render this as "published now," which is a safe fallback — far preferable to a `datetime.fromtimestamp(0)` epoch date (1970-01-01) that would confuse aggregators.

### 5.6 RSS feed size and single-page behavior

The feed returns at most `S.career_portal_rss_max_items` (default 50) items. There is no pagination in the RSS feed; `list_public_jobs` is called with `cursor=None`. Items are ordered newest-first as provided by JOB-*'s query. This is consistent with the OpenCATS career portal design — job board RSS feeds conventionally surface the most recent N postings, not the complete history.

If the platform has more than 50 open positions, the 51st-oldest posting does not appear in the feed. Operators can increase `CAREER_PORTAL_RSS_MAX_ITEMS` up to an operator-defined bound. There is no enforced upper limit in the setting itself; a reasonable production value is 100–200. The feed endpoint does not stream — the entire XML string is built in memory before being returned. At 500 bytes per item, 200 items produce ~100 KB of XML, well within a single HTTP response.

### 5.7 Character encoding

The XML declaration `<?xml version="1.0" encoding="UTF-8"?>` declares UTF-8 encoding. The FastAPI `Response` is returned with `media_type="application/rss+xml; charset=utf-8"`. Python's `str` → `bytes` encoding via FastAPI's `Response` uses UTF-8 by default. Emoji, CJK characters, and other multi-byte sequences in job titles or descriptions are handled correctly.

### 5.8 Idempotency and caching

`GET /public/careers/jobs.rss` is a pure read — no writes. Calling it N times with the same underlying data produces the same XML document (modulo `<lastBuildDate>`, which reflects the current server time at each call). No `Cache-Control` header is set; clients and CDNs cache or revalidate at their discretion. If operators want to reduce JOB-* query load, they can layer a CDN TTL in front of the endpoint without any PRT-003 code change.

### 5.9 `<atom:link rel="self">` correctness

The `href` attribute of `<atom:link>` must be the canonical URL of the feed document itself, per the Atom namespace recommendation. PRT-003 sets this to `{S.public_base_url}/public/careers/jobs.rss`. In dev (`S.public_base_url = "http://localhost:8000"`) the URL is `http://localhost:8000/public/careers/jobs.rss`; in prod it uses the real domain. No `dev_mode` branch.

### 5.10 No rate limiting on the feed endpoint

Unlike the self-apply endpoint (PRT-004), the RSS feed is a public GET with no write-side effects. Rate limiting is not applied in PRT-003. If feed aggregators cause excessive load, a CDN cache or an optional per-IP `_bucket_limit` guard (mirroring `app/services/rate_limit.py:60`) can be added in a follow-up. The `_bucket_limit` infrastructure is available at `app/services/rate_limit.py:60,81` for future use.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 No `dev_mode` branches

PRT-003 contains zero `if S.dev_mode:` conditionals. All logic is identical in development and production:
- `S.public_base_url` resolves to `http://localhost:8000` in dev and the real domain in prod. This is set once at settings load time (`settings.py:349`) and is used directly by `build_jobs_rss` — no branch.
- DDB reads go through `get_portal_config()` and `list_public_jobs()`, both of which use the same boto3 client path in both environments (moto in tests, DDB Local at port 8001 in dev, real DDB in prod).
- There are no S3 calls, no KMS calls, and no email calls in PRT-003.

This satisfies SECOPS-007 (dev/prod parity). The CLAUDE.md gotcha for this codebase is that S3 URL format (`/mock/s3/...` in dev vs presigned URL in prod) is decided inside `presign_upload` at `app/services/filemanager.py:2223-2238` — PRT-003 does not call `presign_upload`, so this distinction is irrelevant.

### 7.2 Idempotency

`GET /public/careers/jobs.rss` is idempotent. The endpoint performs no writes. Calling it N times produces the same XML document modulo `<lastBuildDate>` (server generation time). Feed readers that poll the endpoint multiple times are not at risk of duplicating data or triggering side effects.

### 7.3 Security

**No authentication, no CSRF.** The endpoint carries no `Depends(...)`. CSRF validation at `app/services/sessions.py:429` fires only when a `ui_session` cookie is present; unauthenticated RSS consumers carry no session cookie.

**XML injection prevention.** Every string value interpolated into the XML is passed through `_xml_escape` (wraps `html.escape(..., quote=True)` from stdlib). Combined with the prior `_strip_html_excerpt` pass on `public_description`, this provides defense-in-depth: HTML tags are removed from descriptions before XML escaping, preventing RSS feed injection attacks via job descriptions containing `<script>` or `</description><item><title>injected` payloads.

**Information leakage.** The RSS feed surfaces the same public-safe fields as `CareerJobDetailOut` (PRT-002): title, location, employment type, posted date, slug link, and a plain-text excerpt of `public_description`. Internal fields (`pay_rate`, `bill_rate`, `recruiter_notes`, `owner_sub`) are never passed from JOB-* to `list_public_jobs` items, and `build_jobs_rss` only reads named fields from the item dict — a whitelist approach.

**Only public+open jobs appear.** `list_public_jobs` (PRT-002) delegates to JOB-*'s `list_public_job_orders` which filters for `is_public=True` AND `status in _OPEN_STATUSES`. Drafts, closed, or non-public postings never reach `build_jobs_rss`.

**No SSRF or path traversal.** `build_jobs_rss` does not accept user-supplied URLs. All URLs in the feed are constructed from server-controlled values (`S.public_base_url` + slug from JOB-*). The `S.public_base_url` setting is operator-configured, not user-supplied.

**`X-Content-Type-Options: nosniff`** prevents browsers from MIME-sniffing the RSS XML as HTML. This is a belt-and-suspenders defense against content injection in environments where the `Content-Type` header might be misread.

## 8. Backward Compatibility & Migration

**Additive only.** The default flag value is `"0"` (off). With `CAREER_PORTAL_ENABLED=0`:
- `GET /public/careers/jobs.rss` returns 404; no XML is generated; no DDB reads occur.
- No existing routes are modified.
- No existing tables are modified.
- No existing models are modified.
- The one new setting `career_portal_rss_max_items` has a default of 50 and has no effect when the master flag is off.

**No data migration.** The feed is a pure read-through. There are no new DDB rows to write, no new indices to build. Enabling the RSS endpoint on a live system (setting `CAREER_PORTAL_ENABLED=1`) requires zero data work beyond having PRT-001 and PRT-002 already deployed and the `CareerPortal` table populated with config and slug rows.

**Forward compatibility with JOB-*:** if JOB-* adds new fields to job order rows (e.g., `remote_ok`, `salary_range_text`), `build_jobs_rss` is unaffected because it only reads named fields from the item dict. Adding new `<category>` or custom RSS namespace elements for those fields is a follow-up change to `build_jobs_rss`, not a breaking change to existing feed consumers.

**`posted_at` evolution:** if JOB-* renames its timestamp field, the fallback `int(item.get("posted_at") or 0)` → `now_str` behavior (§5.5) ensures the feed remains valid at the cost of approximate `<pubDate>` values. A follow-up can add `item.get("posted_at") or item.get("created_at", 0)` chaining once the JOB-* field name is confirmed.

## 10. Open Questions / Assumptions

1. **`html.escape` vs manual `replace` for `_xml_escape`.** Python's `html.escape` escapes `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, and (with `quote=True`) `"` → `&quot;`. It does NOT escape `'` → `&apos;` by default, which is acceptable for RSS 2.0 content (single quotes are not special in XML content, only in attribute values delimited by `'`). All attribute values in PRT-003's XML use `"` delimiters, so `&quot;` escaping suffices. This assumption is safe.

2. **Locale-independence of `strftime` day/month abbreviations.** Python's `strftime` is documented to be locale-dependent for `%a`/`%b`. On production Linux servers the locale is typically `C` or `POSIX`, producing the required ASCII English abbreviations (`Mon`, `Jan`, etc.). If the server locale differs, `_rfc822_date` should use a hardcoded lookup table (`DAYS = ["Mon","Tue",...]`, `MONTHS = ["Jan","Feb",...]`). This is a low-risk assumption for the current infrastructure; a follow-up can add the lookup table if locale issues arise.

3. **`_strip_html_excerpt` inline vs import from `app/services/kb_articles.py`.** Inlining avoids a cross-service import; the KB-011 spec defines `_extract_excerpt` as a private module-level helper in `kb_articles.py` (prefixed with `_`). The inline version is identical in logic but uses `max_chars=500`. If the codebase later establishes a shared text-utility module, both uses should migrate there. For now, the inline approach is safer.

4. **Atom feed vs RSS 2.0.** The ticket title mentions "RSS / Atom feed." PRT-003 implements RSS 2.0 with the `atom:link` self-reference extension (the most widely supported format for job board syndication). A pure Atom 1.0 feed (`application/atom+xml`) would require different element names and is not implemented here. If Atom is required (e.g. for a specific aggregator), it can be added as a second endpoint (`GET /jobs.atom`) in a follow-up.

5. **`<item><guid>` stability — deviation from source ticket.** `ATS_CAREER_PORTAL_TICKETS.md §PRT-003` specifies `<guid>` = `job_order_id` (a bare ID string with `isPermaLink="false"` implied). PRT-003 instead uses the full item URL as `<guid isPermaLink="true">`, which is the convention recommended by the RSS 2.0 specification for permalink-style job boards and is more useful to feed readers. The trade-off: if JOB-* ever changes a slug, the GUID changes and feed readers treat the posting as a new entry (the old one appears "deleted" and a new one appears). JOB-* should treat slugs as immutable once a job order is published. PRT-003 cannot enforce this — it is a JOB-* behavioral contract. If strict GUID stability with the source ticket's intent is required, revert to `<guid isPermaLink="false">urn:job:{job_order_id}</guid>`.

6. **`<image>` and portal branding in the feed.** RSS 2.0 supports a `<image>` channel element (URL, title, link). PRT-003 omits it because `logo_url` in `get_portal_config()` is a file-manager download URL that may not be publicly accessible without session auth. A follow-up can add `<image>` once the portal logo is guaranteed to be served without auth (e.g., via a public S3 bucket or CDN).
