# PRT-001 — Career-portal config table, flag, and admin branding settings

**Prefix:** `PRT` · **Area:** ATS / Public Career Portal  
**Type:** Feature · **Priority:** P1 · **Estimate:** 1.5d  
**Source:** `docs/opencats/ATS_CAREER_PORTAL_TICKETS.md` §PRT-001; gap: `docs/opencats/OPENCATS_GAP_ANALYSIS.md:80-92`

---

## 1. Summary & Goal

PRT-001 is the foundation layer for the public career portal vertical. It delivers exactly three things:

1. **The master feature flag** (`S.career_portal_enabled` / env `CAREER_PORTAL_ENABLED`, default `"0"`) that gates every subsequent PRT ticket. With the flag off the platform is byte-for-byte unchanged — no DDB I/O, no router registration side effects, every PRT endpoint returns HTTP 404.
2. **The `CareerPortal` DynamoDB single-table** with its `TableDef` in `scripts/local-ddb-init.py` and a `T.career_portal` handle in `app/core/tables.py`. The table stores three row types: the admin branding config row, posting-slug index rows (written by future JOB-* tickets, read by PRT-002), and any PRT-specific ancillary rows needed by later tickets.
3. **Admin-facing CRUD endpoints** (`GET /ui/admin/career-portal/config`, `PUT /ui/admin/career-portal/config`) for the operator to configure portal branding: portal name, intro copy, logo, primary color, support email. These are session-authenticated + ADMIN/ROOT-gated and are the only authenticated surface in PRT-001; all public endpoints are declared here as a `public_router` skeleton populated by PRT-002 onward.

The goal is to unblock PRT-002 through PRT-006 with zero runtime impact when the flag is off, while keeping every design decision reversible and fully additive.

## 3. Data Model

### 3.1 DynamoDB table: `CareerPortal`

**`TableDef` addition in `scripts/local-ddb-init.py` inside `_table_defs()` at line ~42:**

```python
TableDef(
    _resolve_table_name(S.career_portal_table_name, "CareerPortal"),
    "pk",      # partition key (String)
    "sk",      # sort key (String)
    gsi=[],    # no GSIs in PRT-001; posting-status GSI added by JOB-* when it writes slug rows
    attr_types={},
),
```

No GSI is needed in PRT-001. The config row is a single-item point lookup (`pk="CONFIG"`, `sk="META"`); slug rows are also point lookups by `pk="SLUG#{slug}"`. If JOB-* needs a GSI on the slug table for list-by-job-order, it amends the `TableDef` at that time. Any numeric GSI sort key added later must be declared with `attr_types={"field": "N"}` per the CLAUDE.md gotcha.

### 3.2 Row shapes

**Config row** (one per tenant):
```
pk           = "CONFIG"
sk           = "META"
portal_name  : str      — e.g. "Acme Careers"  (max 120 chars)
intro_copy   : str      — welcome / hero text   (max 4000 chars)
logo_file_path : str | None — file-manager path, e.g. "/career-portal/logo.png"
primary_color  : str | None — "#RRGGBB" hex color
support_email  : str | None — shown on portal
updated_at   : N (int)  — Unix timestamp; MUST be stored as Number for any future GSI
updated_by   : str      — user_sub of last ADMIN/ROOT who wrote it
```

`logo_url` is **derived at read time** by calling `build_download_url(logo_file_path)` from `app/services/filemanager.py:2374`; it is never persisted. This avoids stale URLs and follows the same pattern used by profile photo URL resolution.

**Posting-slug index row** (written by JOB-* publish; PRT-001 defines the read shape only):
```
pk           = "SLUG#{slug}"   — e.g. "SLUG#senior-python-engineer-2026"
sk           = "META"
job_order_id : str
slug         : str             — redundant but convenient on read
created_at   : N (int)         — Unix timestamp
```

This is the same point-lookup pattern as the questionnaire `published_slug-index` row (CMP-005 published-by-slug model, `app/routers/questionnaires.py:615-620`), adapted for job-order slugs.

## 4. API / Service Design

### 4.1 Pydantic models (`app/models.py`)

Add in a new `# ATS Career Portal (PRT)` block:

```python
class CareerPortalConfigIn(BaseModel):
    portal_name: str = Field(..., min_length=1, max_length=120)
    intro_copy: str = Field(default="", max_length=4000)
    logo_file_path: Optional[str] = Field(default=None)
    primary_color: Optional[str] = Field(
        default=None,
        pattern=r"^#[0-9a-fA-F]{6}$",
    )
    support_email: Optional[str] = Field(default=None, max_length=254)

class CareerPortalConfigOut(BaseModel):
    portal_name: str
    intro_copy: str
    logo_file_path: Optional[str]
    logo_url: Optional[str]          # resolved at read time; None when no logo
    primary_color: Optional[str]
    support_email: Optional[str]
    updated_at: Optional[int]        # None when no row persisted yet (default config)
    updated_by: Optional[str]
```

`CareerPortalConfigIn.primary_color` uses Pydantic v2 `pattern=` (not `regex=`) to validate the `#RRGGBB` hex format. `logo_file_path` has no path-format constraint at the model layer; the service validates that the path belongs to a file node accessible to the system user before resolving.

### 4.2 Service (`app/services/career_portal.py`, new file)

Synchronous, no `async`. Follows the `cart_reminders.py` module shape (synchronous service, no background tasks in PRT-001).

```python
from app.core.settings import S
from app.core.tables import T
from app.core.time import now_ts
from app.services.filemanager import build_download_url
from fastapi import HTTPException

_CONFIG_PK = "CONFIG"
_CONFIG_SK = "META"

def _require_enabled() -> None:
    """Raise 404 when career_portal_enabled is False.
    Mirrors CMP-006 _require_web_lead_enabled and KB-011 flag-gated guard."""
    if not S.career_portal_enabled:
        raise HTTPException(status_code=404, detail="Not found")

def _resolve_logo_url(logo_file_path: str | None) -> str | None:
    """Derive a download URL from a file-manager path at read time.
    Uses build_download_url (filemanager.py:2374) so dev returns
    http://localhost:8000/v1/fs/download?path=... and prod a real URL —
    no dev_mode branch here (SECOPS-007)."""
    if not logo_file_path:
        return None
    try:
        return build_download_url(logo_file_path)
    except Exception:
        return None

def get_portal_config() -> dict:
    """Return the config row. Returns S-default branding when no row exists (never 500)."""
    _require_enabled()
    item = T.career_portal.get_item(
        Key={"pk": _CONFIG_PK, "sk": _CONFIG_SK}
    ).get("Item") or {}
    return {
        "portal_name": item.get("portal_name", "Careers"),
        "intro_copy": item.get("intro_copy", ""),
        "logo_file_path": item.get("logo_file_path"),
        "logo_url": _resolve_logo_url(item.get("logo_file_path")),
        "primary_color": item.get("primary_color"),
        "support_email": item.get("support_email"),
        "updated_at": int(item["updated_at"]) if item.get("updated_at") else None,
        "updated_by": item.get("updated_by"),
    }

def set_portal_config(data: dict, *, actor_sub: str) -> dict:
    """Persist branding config. Overwrites entire row (last-write-wins)."""
    _require_enabled()
    now = now_ts()
    item = {
        "pk": _CONFIG_PK,
        "sk": _CONFIG_SK,
        "portal_name": data["portal_name"],
        "intro_copy": data.get("intro_copy", ""),
        "updated_at": now,
        "updated_by": actor_sub,
    }
    if data.get("logo_file_path") is not None:
        item["logo_file_path"] = data["logo_file_path"]
    if data.get("primary_color") is not None:
        item["primary_color"] = data["primary_color"]
    if data.get("support_email") is not None:
        item["support_email"] = data["support_email"]
    T.career_portal.put_item(Item=item)
    try:
        from app.services.alerts import audit_event  # local import — SECOPS-007 parity
        audit_event("career_portal.config_updated", actor_sub,
                    portal_name=data["portal_name"])
    except Exception:
        pass
    return get_portal_config()
```

Key design notes:
- `get_portal_config` never raises on a missing row; it returns safe defaults. This allows PRT-002's public `/config` endpoint to work before an admin has ever visited the settings page.
- `set_portal_config` uses a full `put_item` (not `update_item`) because the config row is a small, single-item document. The last-write-wins semantics are correct: there is one tenant config and concurrent writes are admin-only.
- `audit_event` is locally imported inside `try/except` to avoid a circular import and to ensure audit failure never blocks the write, matching the pattern in `app/services/ec2_launcher.py` (`_record_timeline` lazy import).

### 4.3 Router (`app/routers/career_portal.py`, new file)

```python
from fastapi import APIRouter, Depends, HTTPException
from app.auth.roles import Role, role_allows_admin_features
from app.services.sessions import require_ui_session
from app.models import CareerPortalConfigIn, CareerPortalConfigOut
from app.services.career_portal import get_portal_config, set_portal_config

# Admin-facing router (session auth required)
router = APIRouter(prefix="/ui/admin/career-portal", tags=["career_portal_admin"])

# Public-facing router skeleton (no auth; populated by PRT-002+)
public_router = APIRouter(prefix="/public/careers", tags=["career_portal_public"])

@router.get("/config", response_model=CareerPortalConfigOut)
def admin_get_config(ctx: dict = Depends(require_ui_session)) -> CareerPortalConfigOut:
    if not role_allows_admin_features(ctx.get("role")):
        raise HTTPException(status_code=403, detail="Admin or Root role required")
    return get_portal_config()

@router.put("/config", response_model=CareerPortalConfigOut)
def admin_put_config(
    body: CareerPortalConfigIn,
    ctx: dict = Depends(require_ui_session),
) -> CareerPortalConfigOut:
    if not role_allows_admin_features(ctx.get("role")):
        raise HTTPException(status_code=403, detail="Admin or Root role required")
    return set_portal_config(body.model_dump(), actor_sub=ctx["user_sub"])
```

The `public_router` is a skeleton here. PRT-002 imports it and adds `GET /config`, `GET /jobs`, `GET /jobs/{slug}` to it. PRT-003 adds `GET /jobs.rss`. The router module owns the declaration; later PRT tickets import and extend the same object. This avoids multiple `APIRouter` re-registrations in `main.py`.

## 5. Detailed Behavior & Edge Cases

**Flag off — every path returns 404:**
- `GET /ui/admin/career-portal/config` → `_require_enabled()` raises 404 before any DDB read.
- `PUT /ui/admin/career-portal/config` → same.
- Public router routes (added in PRT-002+) are also gated by `_require_enabled()` at the service layer, ensuring no public surface is reachable when the flag is off.
- No DDB I/O occurs at any point when the flag is off.

**Flag on, no config row persisted:**
- `get_portal_config()` performs a `get_item` that returns `{}`, then returns the default branding dict (`portal_name="Careers"`, empty intro, `logo_url=None`). The response is `200 OK` with default values, never a 500. This is the "cold start" state after `CAREER_PORTAL_ENABLED=1` is set but before an admin saves config.

**`logo_file_path` handling:**
- An admin may supply a `logo_file_path` pointing to a file already uploaded to the file manager (e.g. `/career-portal/logo.png`). PRT-001 stores the path as-is; `get_portal_config` calls `build_download_url(path)` which builds `{S.public_base_url}/v1/fs/download?path=...`. In dev this URL is reachable via the same uvicorn process; in prod it is served by the file-manager endpoint with presigned S3 redirection. No dev/prod branch in PRT code.
- If `logo_file_path` is `None` or missing, `logo_url` is `None` in the response. The portal frontend should render a default placeholder.
- PRT-001 does not validate that the file-manager path actually exists; that validation is left to the frontend (which can verify via `GET /v1/fs?path=...`) or a future PRT enhancement.

**Partial updates:**
- `PUT /ui/admin/career-portal/config` replaces the entire config row (full `put_item`). All fields in `CareerPortalConfigIn` must be supplied on each write. If the caller omits `logo_file_path` (sends `null`), the stored row will have no `logo_file_path` key. This is a deliberate "explicit clear" semantic — admins who want to keep the current logo must re-send the current path.
- `updated_at` is always refreshed on any `PUT`, even if no values changed. This is intentional (audit trail).

**Concurrency:**
- There is one config row. Concurrent admin writes use last-write-wins `put_item`. Given that config changes are infrequent admin actions, optimistic concurrency (conditional writes on `updated_at`) is not required in PRT-001 and can be added in a follow-up if contention is observed.

**`updated_at` as Number:**
- The `updated_at` attribute is stored as a DDB Number (`N`), consistent with all other timestamp fields (`now_ts()` returns an integer). Although no GSI uses `updated_at` in PRT-001, storing it as `N` from the start ensures that any future GSI addition does not require a data backfill.

**Role check placement:**
- The inline `role_allows_admin_features(ctx.get("role"))` check runs after `require_ui_session` succeeds. A caller with a valid session but `role=USER` gets a 403, not a 404. This reveals that the admin config path exists, which is acceptable (it is behind session auth — only authenticated users reach the check).

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

**SECOPS-007 — no `dev_mode` branches in PRT code:**
- Logo URL resolution uses `build_download_url` (`filemanager.py:2374`), which builds the URL from `S.public_base_url`. In dev, `S.public_base_url = "http://localhost:8000"` (`settings.py:349`); in prod it is the real domain. The same code path runs in both environments.
- `audit_event` writes to `T.alerts` (DDB local in dev, real DynamoDB in prod). Same code path.
- DDB `put_item` / `get_item` calls go through the same boto3 client regardless of environment. moto intercepts them in tests; DynamoDB Local at port 8001 in the dev stack; real DynamoDB in prod.
- There is no S3 call in PRT-001. S3 interactions (résumé upload) are in PRT-005 and go through `presign_upload` / `filemanager.py:2207`, which already handles dev vs prod internally.

**Idempotency:**
- `PUT /ui/admin/career-portal/config` is idempotent: calling it N times with the same body produces the same stored state. The `updated_at` field will differ across calls (each call records the current timestamp), but the functionally observable state (branding) is identical.
- `GET /ui/admin/career-portal/config` is trivially idempotent (read-only).

**Security:**
- Admin endpoints require a valid `ui_session` cookie (enforced by `require_ui_session` at `app/services/sessions.py:330`) plus CSRF token for the `PUT` (CSRF validation fires for non-GET requests when the session cookie is present, `sessions.py:429`). A bearer-token caller bypasses CSRF (consistent with the global CSRF gate).
- `role_allows_admin_features` (`app/auth/roles.py:60`) gates on `Role.ADMIN` and `Role.ROOT` only. `Role.USER` callers receive 403.
- `primary_color` is validated by a Pydantic regex (`^#[0-9a-fA-F]{6}$`). `portal_name` and `intro_copy` are plain text with length caps; no HTML sanitization is required at the API layer because rendering is the frontend's responsibility.
- `support_email` is stored as-is (no normalization); the portal frontend renders it as a `mailto:` link. A future hardening pass could add `normalize_email` validation, but the field is admin-supplied so the risk is low.
- `logo_file_path` is stored and resolved without executing the path as code; `build_download_url` at `filemanager.py:2374` only URL-encodes it with `quote(path, safe='')`.

## 8. Backward Compatibility & Migration

**Additive only.** With `CAREER_PORTAL_ENABLED=0` (the default), the platform is byte-for-byte unchanged:
- No new routers are active (the admin and public routers exist but all handlers call `_require_enabled()` → 404 immediately).
- The `CareerPortal` DDB table is created at `just restart` / `just up` (via `local-ddb-init.py`) but is empty and never queried.
- No existing table schemas are modified.
- No existing models are modified.
- No existing routes are modified.

**First-time activation (dev):**
1. Set `CAREER_PORTAL_ENABLED=1` in `.env.local`.
2. Run `just restart` (recreates tables including `CareerPortal`, re-seeds sessions).
3. Admin can immediately `GET /ui/admin/career-portal/config` → returns default branding.
4. Admin `PUT`s config → row persists.

**First-time activation (prod):**
1. Deploy the new code.
2. Run `scripts/local-ddb-init.py` equivalent (`UpdateTable` or the prod table-creation script) to create the `CareerPortal` table.
3. Set `CAREER_PORTAL_ENABLED=1` in the environment and restart the service.
4. No data migration is needed (the table starts empty; `get_portal_config` returns defaults gracefully).

**Forward compatibility:**
- The `SLUG#{slug}` row shape is defined here but never written by PRT-001. JOB-* will write these rows at job-order publish time. PRT-002 will read them. Neither the row schema nor the table definition needs to change when JOB-* ships.
- If a future ticket needs a GSI on the `CareerPortal` table (e.g. listing all slugs for a job order), it amends the `TableDef` in `local-ddb-init.py` and adds `attr_types` for any numeric sort key. Existing rows continue to be readable.

## 10. Open Questions / Assumptions

1. **Single-tenant only.** PRT-001 stores one `CONFIG` row per DDB table. If the platform requires multi-tenant career portals (one per client company), the config row would need `pk = "CONFIG#{tenant_id}"`. This is deferred; `S.career_portal_slug_prefix` is reserved for future multi-tenant slug namespacing but is not used in PRT-001.

2. **Logo file ownership.** `logo_file_path` is stored as a file-manager path under a "system_career_portal" namespace or an admin-owned path. PRT-001 does not enforce file ownership; it assumes the admin uploading the logo has file-manager access. A future hardening step could validate the path via `T.filemgr_table` node lookup before persisting.

3. **`support_email` validation.** Currently stored as raw string; `normalize_email` from `app/core/normalize.py:60` raises `HTTPException(400)` on bad input. PRT-001 deliberately omits this call to match the "admin-supplied, low-risk" profile. If email validation is required, add `Field(pattern=r"^[^@]+@[^@]+\.[^@]+$")` or call `normalize_email` in the service.

4. **Config versioning / audit history.** PRT-001 records only the most recent write via a single `put_item`. A full audit history (all past config states) would require writing to an additional `HISTORY#{ts}` row or to `T.alerts`. This can be added if regulators require it; the audit log currently captures only the event name and actor, not the diff.

5. **ADMIN scope restriction.** The current role check (`role_allows_admin_features`) allows any ADMIN (general or scoped). If career-portal config should be restricted to only general ADMINs (not scoped content-moderation admins), the check should additionally verify `ctx.get("admin_profile", {}).get("type") == "general"`. This is deferred until a firm requirement exists.
