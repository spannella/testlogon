# RSK-002 — Résumé text-extraction service (PDF/DOCX → plain text)

**Type:** Feature · **Priority:** P1 · **Estimate:** 2 days  
**Cluster:** ATS Résumé / Skills (RSK) · **Gap analysis:** `docs/opencats/OPENCATS_GAP_ANALYSIS.md` §A (line 47)  
**Depends on:** CND-001 (table, flag, settings), CND-003 (attachment row + S3 upload path)  
**Required by:** RSK-003 (full-text index), RSK-006 (quick-add-from-résumé)

---

## 1. Summary & Goal

`docs/opencats/OPENCATS_GAP_ANALYSIS.md:47` states:

> Résumé parsing / text extraction → full-text résumé search — **MISSING** — no parsing
> anywhere; file search is filename-only (`filemanager.py:1734`).

RSK-002 closes the first half of this gap: it extracts plain text from an uploaded candidate
résumé (PDF or DOCX) and stores that text as additional attributes on the résumé attachment
row already owned by CND-003. The stored `extracted_text` field is the sole input consumed
by RSK-003 (inverted-token index) and can also be surfaced in the recruiter UI as a
structured preview without re-fetching from S3.

The extraction service is **dependency-free / stdlib-only**, following the principle
established by `app/services/receipts.py:53` (`_render_pdf`, no `reportlab`) and
`app/services/audit_export_pipeline.py:81` (`_build_pdf`, no `reportlab`). It produces
text from the two document types most commonly encountered in résumé workflows:

- **DOCX** — a ZIP of XML; extracted via Python's `zipfile` module (stdlib), already
  imported by `app/services/legal_export.py:22`, `app/services/gdpr_service.py:11`, and
  `app/services/filemanager.py:17`.
- **PDF** — extracted via a minimal content-stream parser that handles both uncompressed
  and `/FlateDecode`-compressed streams using `zlib` (stdlib). The parser is designed to
  round-trip text from PDFs produced by `receipts.py._render_pdf` (the platform's own PDF
  writer) and covers common third-party PDFs. Scanned/image-only PDFs yield no text and
  are flagged `extraction_status="unsupported"` — OCR is explicitly out of scope.

The service is wired into CND-003's résumé-upload path as a best-effort post-upload
enrichment step (same "register-then-enrich" shape used by EC2 host inventory in
`app/services/ec2_launcher.py`, documented in CLAUDE.md §GAP-0223). A re-extract endpoint
allows UI-triggered retry of failed extractions.

## 2. Context & Current State

### 2.1 Gap analysis placement

## 3. Data Model

### 3.1 Table

RSK-002 uses **only the existing `candidates` table** delivered by CND-001 (`T.candidates`,
`pk`/`sk` single table). No new table is created, no new GSI is added, and no entry in
`scripts/local-ddb-init.py` is required for this ticket.

### 3.2 Additive attributes on the attachment row

Four attributes are written by `update_item` onto the `ATTACHMENT#` sub-item already
created by CND-003. These are purely additive — the row exists before RSK-002 runs, and
CND-003 functions correctly whether or not RSK-002 has enriched it.

| Attribute | DDB Type | Notes |
|---|---|---|
| `extracted_text` | S | Extracted plain text, capped at `S.ats_resume_extract_max_chars` (default 50,000). Absent until first successful extraction. |
| `extraction_status` | S | `"ok"` — text extracted successfully; `"unsupported"` — format not extractable (image-only PDF, unknown format); `"error"` — unexpected exception during extraction. Absent until extraction is attempted. |
| `extracted_at` | N | `now_ts()` — Unix timestamp of the most recent extraction attempt. Absent until first attempt. |
| `extracted_bytes` | N | Source byte length of the S3 object at extraction time (observability). Absent until first attempt. |

`extracted_at` and `extracted_bytes` are non-key attributes on an existing sub-item. They
are **not** GSI sort keys, so no `attr_types` declaration is required (CLAUDE.md "DynamoDB
numeric GSI sort keys" — the `attr_types` requirement only applies to attributes declared as
GSI key attributes in `scripts/local-ddb-init.py`).

The `update_item` expression is:

```
UpdateExpression="SET extracted_text = :txt, extraction_status = :st,
                      extracted_at = :ts, extracted_bytes = :b"
ExpressionAttributeValues={":txt": text, ":st": status, ":ts": now_ts(), ":b": byte_len}
Key={"pk": f"CANDIDATE#{candidate_id}", "sk": f"ATTACHMENT#{attachment_id}"}
```

### 3.3 No `extracted_text` in `CandidateOut`

`CandidateOut` (defined by CND-001 in `app/models.py`) does not expose `extracted_text`.
Instead, the re-extract endpoint response (`ResumeExtractionOut`) and RSK-003's search
results expose extraction metadata. The raw text can be included in a dedicated
`CandidateResumeOut` (extended in CND-003) by adding an optional `extracted_text: Optional[str]`
field — that extension is a follow-up owned by CND-003/CND-005, not by RSK-002 itself.

## 4. API / Service Design

### 4.1 Service: `app/services/resume_extraction.py` (new file)

All functions are synchronous (CPU-bound parsing); the async route calls them via
`asyncio.to_thread`. The module-level S3 singleton follows `filemanager.py:58`:

```python
from app.core.aws_clients import s3_client as _s3_factory
_s3 = _s3_factory()
```

#### `_detect_format(data: bytes) -> str`

Pure function. Returns `"pdf"`, `"docx"`, or `"text"`.

- `"pdf"` — `data[:4] == b"%PDF"`
- `"docx"` — `data[:4] == b"PK\x03\x04"` **and** the ZIP archive contains a member
  whose name starts with `"word/"` (checked by opening with `zipfile.ZipFile`; catches
  ordinary ZIP files that are not DOCX).
- `"text"` — everything else (UTF-8 passthrough).

Magic-byte detection is mandatory; filenames are untrusted.

#### `_extract_docx_text(data: bytes) -> str`

1. Open `zipfile.ZipFile(io.BytesIO(data))`.
2. Read `word/document.xml` as bytes; decode UTF-8 with `errors="replace"`.
3. Paragraph breaks: replace `</w:p>` with `"\n"` before tag-stripping.
4. Extract run text: `re.findall(r"<w:t[^>]*>(.*?)</w:t>", xml, re.DOTALL)` — captures
   the text content of each `<w:t>` element, including those with `xml:space="preserve"`.
5. Join runs with a space; normalize whitespace: `re.sub(r"[ \t]+", " ", text)` then
   `re.sub(r"\n{3,}", "\n\n", text)`.
6. Return stripped result.

#### `_extract_pdf_text(data: bytes) -> str`

Minimal content-stream parser. The platform's own PDFs (`receipts.py:53-95`) write
uncompressed streams with `( … ) Tj` operands; third-party PDFs commonly use
`/FlateDecode` compression and `[ … ] TJ` arrays.

Algorithm:

1. Split `data` on `b"stream\n"` to find stream boundaries; collect bytes between each
   `stream\n` and `\nendstream`.
2. For each candidate stream:
   a. If the preceding stream dictionary contains `/Filter /FlateDecode` (or
      `/Filter[/FlateDecode]`), decompress with `zlib.decompress(stream_bytes)`.
      On `zlib.error`, skip this stream silently.
   b. Decode the (possibly decompressed) bytes as Latin-1 (PDF strings are Latin-1,
      not UTF-8; the platform's own PDFs are ASCII-safe).
   c. Extract text operands:
      - `Tj` strings: `re.findall(r"\(([^)\\]*(?:\\.[^)\\]*)*)\) Tj", stream_text, re.DOTALL)`
      - `TJ` arrays: `re.findall(r"\(([^)\\]*(?:\\.[^)\\]*)*)\)", array_content)` where
        `array_content` is matched via `re.findall(r"\[([^\]]*)\] TJ", stream_text)`.
   d. Un-escape PDF string escapes: `\\(` → `(`, `\\)` → `)`, `\\\\` → `\`.
   e. Collect all strings.
3. Join with spaces; normalize whitespace.
4. If all collected strings are empty, return `""` (caller sets `"unsupported"`).

#### `_normalize_extracted_text(text: str, max_chars: int) -> str`

Pure function. Collapses internal whitespace sequences to single spaces or single
newlines; strips leading/trailing whitespace; truncates to `max_chars`.

#### `extract_resume_text(candidate_id: str, attachment_id: str, *, s3_key: str | None = None, s3_bucket: str | None = None, raw_bytes: bytes | None = None, actor_sub: str) -> dict`

The primary public entry point. Callable from the upload hook (where `raw_bytes` is
available) or the re-extract endpoint (where `s3_key`/`s3_bucket` are used).

```
def extract_resume_text(
    candidate_id: str,
    attachment_id: str,
    *,
    s3_key: str | None = None,
    s3_bucket: str | None = None,
    raw_bytes: bytes | None = None,
    actor_sub: str,
) -> dict:  # {"extraction_status": str, "char_count": int}
```

Steps:

1. Flag guard: `if not S.ats_recruiting_enabled: return {"extraction_status": "disabled", "char_count": 0}`.
2. Obtain bytes:
   - If `raw_bytes` is provided (upload path), use it directly.
   - If `s3_key`/`s3_bucket` are provided (re-extract path), call
     `_s3.get_object(Bucket=s3_bucket, Key=s3_key)["Body"].read()`.
   - If neither: return `{"extraction_status": "error", "char_count": 0}` without
     touching DDB (no attachment row mutation for misconfigured call sites).
3. Size guard: if `len(bytes_) > S.ats_resume_extract_max_bytes`, write
   `extraction_status="unsupported"` with empty text and return early (oversized binary).
4. Detect format via `_detect_format`.
5. Dispatch:
   - `"pdf"` → `_extract_pdf_text`
   - `"docx"` → `_extract_docx_text`
   - `"text"` → `bytes_.decode("utf-8", errors="replace")`
6. Normalize via `_normalize_extracted_text(text, S.ats_resume_extract_max_chars)`.
7. Determine status: `"ok"` if `text` is non-empty, else `"unsupported"`.
8. Call `T.candidates.update_item(...)` with the four additive attributes.
9. If the extraction was `"ok"`, call (best-effort, inner `try/except`):
   `from app.services.resume_search import _write_resume_index; _write_resume_index(candidate_id, candidate_name, text)`
   — the local import avoids circular dependency (RSK-003 imports nothing from RSK-002);
   `candidate_name` is obtained via a `get_item` of the META row.
10. Emit `audit_event("ats.resume.extracted", actor_sub, candidate_id=candidate_id, attachment_id=attachment_id, status=status, chars=char_count)`.
11. Return `{"extraction_status": status, "char_count": char_count}`.

All exceptions in steps 2–9 are caught by an outer `try/except Exception`. On any
uncaught exception: write `extraction_status="error"`, empty text, emit the audit event
with `status="error"`, and return — never re-raise. This ensures the upload path is never
interrupted by a parse failure.

## 5. Detailed Behavior & Edge Cases

### 5.1 Upload-path wiring (CND-003 hook)

CND-003's `add_resume` function (in `app/services/candidates.py`) already holds the raw
bytes in memory immediately after the S3 `put_object` call. The hook is:

```python
try:
    from app.services.resume_extraction import extract_resume_text
    extract_resume_text(
        candidate_id, attachment_id,
        raw_bytes=file_bytes,        # avoids a redundant S3 GET
        actor_sub=actor_sub,
    )
except Exception:
    pass  # extraction failure never blocks upload success
```

This is the same "register-then-best-effort-enrich" pattern used by EC2 host inventory
(`app/services/ec2_launcher.py`; CLAUDE.md §GAP-0223) and KB-009's `_write_kb_search_index`
best-effort posture. The résumé S3 object is already durably stored at this point.

### 5.2 Re-extraction on re-upload

When CND-003 replaces a résumé (a new `ATTACHMENT#` item with a new `attachment_id`), the
hook fires again naturally for the new item. Old token rows (if RSK-003 has been indexed) are
deleted by `_delete_resume_index` before new ones are written — RSK-003 owns this cleanup, not
RSK-002.

### 5.3 Format detection — edge cases

| Input | `_detect_format` result | extraction outcome |
|---|---|---|
| `%PDF-1.4 … BT (text) Tj ET` (platform PDF) | `"pdf"` | `"ok"` |
| `%PDF-1.4 … /Filter /FlateDecode … stream <compressed>` | `"pdf"` | `"ok"` (zlib decompress) |
| `%PDF-1.4 … (image-only, no text streams)` | `"pdf"` | `"unsupported"` (empty text) |
| `PK\x03\x04 … word/document.xml` | `"docx"` | `"ok"` |
| `PK\x03\x04 … (not a DOCX — no word/ member)` | `"text"` | UTF-8 passthrough |
| Truncated / corrupt ZIP | `"docx"` detect attempt, `BadZipFile` caught | `"error"` |
| Plain `.txt` UTF-8 | `"text"` | `"ok"` |
| Empty bytes (`b""`) | `"text"` | `"unsupported"` (empty after decode) |
| Oversized (> `S.ats_resume_extract_max_bytes`) | any | `"unsupported"`, early return, no parse |

### 5.4 Truncation

`extracted_text` is always ≤ `S.ats_resume_extract_max_chars` (default 50,000 characters).
The S3 object is the source of truth and is never modified. `char_count` in the response and
in `ResumeExtractionOut` reflects the stored (possibly truncated) length. The truncation
boundary is at a character, not a word — a partial token at the boundary is acceptable because
RSK-003's tokenizer operates on the stored text.

DynamoDB's 400 KB item size limit: 50,000 ASCII/Latin-1 characters ≈ 50 KB. The attachment
sub-item already carries filename, S3 key, timestamps, and status fields; total item size
remains well under the 400 KB limit.

### 5.5 Concurrent re-extract

The `update_item` call is unconditional — it overwrites whatever was there. If two
re-extract requests race, the last writer wins. This is acceptable: both requests read from
the same immutable S3 object and will produce identical extracted text. No conditional
expression is needed.

### 5.6 File-manager-linked attachments (`source="file_manager"`)

CND-003 allows attaching a résumé that lives in the file manager with no byte copy — only
a `node_path` is stored, not an `s3_key`. `extract_resume_text` handles this path:

1. If `raw_bytes` is `None` and `s3_key` is `None`, resolve the bytes from the file manager:
   `node = filemanager.get_node(owner_sub, node_path)`, then fetch from
   `node["s3_bucket"]` / `node["s3_key"]` via `_s3.get_object`.
2. All downstream logic is identical.

The `node_path`/`owner_sub` values are fetched from the attachment sub-item before
dispatching to `asyncio.to_thread`.

### 5.7 `zlib` decompression safety

`zlib.decompress` raises `zlib.error` on malformed input. This is caught per-stream and the
stream is skipped (no partial text from a corrupt stream is emitted). `zlib.decompress`
with untrusted input is safe from infinite-loop risk; however, a decompression bomb (tiny
compressed bytes → huge output) is bounded by `S.ats_resume_extract_max_bytes` applied
**after** decompression via `len(decompressed) > S.ats_resume_extract_max_bytes` → skip
that stream.

### 5.8 DOCX nested tables and textboxes

`<w:t>` elements appear inside `<w:tbl>` (tables) and `<w:txbxContent>` (textboxes) as
well as in normal paragraphs. The `re.findall(r"<w:t[^>]*>(.*?)</w:t>", xml, re.DOTALL)`
pattern captures them all regardless of nesting depth. The ordering will follow XML
document order, which matches human reading order for standard DOCX files.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 SECOPS-007 — no `dev_mode` branch in extraction code

All DDB writes go through `T.candidates` (the frozen handle from `app/core/tables.py`). The
`update_item` expression is identical in dev (DynamoDB Local at port 8001) and prod (AWS
DynamoDB). S3 reads go through `s3_client()` at `app/core/aws_clients.py:114` — in dev
this transparently hits in-process moto; in prod it hits real S3. There is no `if S.dev_mode`
branch anywhere in `resume_extraction.py`. The sole dev/prod branch in the attachment path is
`_make_download_url` in CND-003 — RSK-002 does not add another.

### 7.2 Idempotency

`extract_resume_text` is unconditionally idempotent: re-calling it with the same
`candidate_id` + `attachment_id` produces the same four attribute values (since the S3
object is immutable) and overwrites the previous values. `extracted_at` will differ
(new `now_ts()`), but this is expected and harmless.

### 7.3 Input safety

- **ZIP bomb (DOCX):** `zipfile.ZipFile` does not auto-decompress member content;
  `member.read()` is called only for `word/document.xml`. The XML byte length is bounded
  by `S.ats_resume_extract_max_bytes` (checked on raw bytes before format dispatch).
- **zlib bomb (PDF):** post-decompression byte length is checked against
  `S.ats_resume_extract_max_bytes` per stream; oversized decompressed streams are skipped.
- **ReDoS:** the `<w:t>` regex uses `.*?` (lazy, `re.DOTALL`); the PDF string regex has
  character-class exclusions (`[^)\\]*`) rather than `.*?` to bound backtracking. Both
  are acceptable for the bounded input sizes guaranteed by the byte cap.
- **XML injection / external entities:** the extracted text is stored as a DynamoDB
  string attribute and never parsed as XML again after extraction. No `xml.etree` or
  `lxml` is used — only `re.findall` on the raw XML bytes decoded to a string.
- **Path traversal:** S3 keys are constructed by CND-003 using a deterministic scheme
  (`{prefix}{candidate_id}/{attachment_id}/{safe_filename}`) and are read back from the
  stored `s3_key` attribute — RSK-002 never constructs S3 keys itself.
- **Privilege:** the re-extract endpoint enforces ownership (`uploaded_by ==
  ctx["user_sub"]` or `role >= ADMIN`) before dispatching extraction.

### 7.4 Audit trail

`audit_event("ats.resume.extracted", actor_sub, candidate_id=..., attachment_id=..., status=..., chars=...)` is emitted for every extraction attempt, including errors. This provides an immutable log of who triggered extraction, when, and with what outcome — sufficient for recruiter access reviews.

## 8. Backward Compatibility & Migration

### 8.1 Additive-only schema change

The four new attributes (`extracted_text`, `extraction_status`, `extracted_at`,
`extracted_bytes`) are written to existing `ATTACHMENT#` sub-items only when extraction
runs. Existing rows have none of these attributes; `CandidateResumeOut` (CND-003) projects
them as `Optional` with `None` defaults. No migration is needed for already-uploaded
résumés — they simply have no extracted text until the re-extract endpoint is called or
until the indexing ticket (RSK-003) runs a cold-start rebuild.

### 8.2 Cold-start bulk extraction

RSK-003 defines a `rebuild_resume_index()` helper that scans `ATTACHMENT#` rows. This helper
can trivially be extended to also call `extract_resume_text` for any row where
`extraction_status` is absent — giving operators a one-shot bulk extraction path for
pre-existing résumés. RSK-002 does not implement the bulk scan itself (that is a RSK-003
concern), but `extract_resume_text` is designed to be safely callable from a scan loop: it
is idempotent, best-effort, and returns a dict (never raises) so a bulk loop can
accumulate results.

### 8.3 Flag-off safety

With `ATS_RECRUITING_ENABLED=0` (the default), the router is registered but every endpoint
returns 404. `extract_resume_text` returns `{"extraction_status": "disabled", ...}` with no
DDB or S3 side-effects. The upload-path hook (`try/except` wrapped) is a no-op. No existing
behavior changes.

## 10. Open Questions / Assumptions

1. **OCR for scanned PDFs:** explicitly out of scope. Image-only PDFs yield
   `extraction_status="unsupported"`. Adding OCR (e.g., Tesseract) would require a system
   dependency and a dev/prod parity strategy — deferred to a future ticket (RSK-002-OCR).

2. **Password-protected PDFs:** a PDF with a `Encrypt` dictionary will produce mostly
   empty or garbled text. The `"unsupported"` status covers this case gracefully. An
   explicit check for the `/Encrypt` keyword in the PDF header can be added as a micro-
   optimization (return `"unsupported"` early rather than attempting to parse), but is not
   required for correctness.

3. **DOCX macros / embedded objects:** `<w:t>` extraction ignores embedded OLE objects,
   charts, and VBA code. This is the correct behavior — only the human-readable text of the
   résumé is needed for search indexing.

4. **Encoding of PDF text operators:** the `Tj`/`TJ` parser assumes Latin-1 encoding (PDF
   default). PDFs that embed Unicode via `/ToUnicode` CMaps (common in non-Western résumés)
   will produce garbled characters for non-ASCII runs. Correct CMap handling requires
   significant additional logic and is deferred; affected résumés will produce partial text
   and `extraction_status="ok"` with degraded recall. The open question is whether this
   degraded-quality output is better than `"unsupported"` — the assumption here is yes,
   since even partial text produces useful search tokens.

5. **`candidate_name` fetch for RSK-003 wiring (step 9):** `extract_resume_text` fetches
   the candidate META row (`sk="META"`) to obtain `name` before calling
   `_write_resume_index`. If CND-001/CND-002 have not yet been deployed, this `get_item`
   returns nothing and `_write_resume_index` is skipped (best-effort inner `try/except`).
   RSK-002 is therefore safely deployable before CND-002, though RSK-003 indexing will not
   fire until both CND-002 and RSK-003 are live.

6. **Attachment ownership for the re-extract endpoint:** the spec uses `uploaded_by ==
   ctx["user_sub"]` as the ownership predicate. If CND-003 introduces a separate
   `owner_sub` attribute on attachment rows (distinct from the uploader), the guard should
   be updated to use that field. The assumption here is that `uploaded_by` is the correct
   ownership field until CND-003's spec is finalized.
