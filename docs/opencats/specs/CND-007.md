## 1. Summary & Goal

CND-007 delivers the complete test surface for the Candidate entity cluster: a fully
offline, hermetic `pytest` suite covering all service, attachment, history, and router
behaviour introduced by CND-001 through CND-005, and a Playwright E2E spec exercising the
full UI and API flows introduced by CND-006 end-to-end.

The `pytest` suite (`tests/test_cnd_candidates.py`) runs with no real AWS, no network, and
no dev stack — it is self-contained in CI. The Playwright spec
(`frontend/e2e/candidates.spec.ts`) runs against the live dev stack with
`CANDIDATES_ENABLED=1` seeded and validates every visible recruiter workflow from the
browser.

Neither file introduces any new production code. Their combined acceptance criteria are:

- `pytest tests/test_cnd_candidates.py` passes with `moto` in-process, offline, from a bare
  Python venv.
- `npx playwright test e2e/candidates.spec.ts` passes against the running dev stack with the
  flag on; the flag-off section passes without the flag.
- Test isolation is total: no moto `@mock_aws` global decorator leaks into the production
  code path; every table handle and settings flag is patched and restored per test class via
  `object.__setattr__`.

## 2. Context & Current State

### 2.1 Hermetic test isolation pattern

Two reference files establish the canonical offline pattern CND-007 follows verbatim:

- **`tests/test_gap_0220_0221_ssh_stored_key.py`** (lines 1–33): isolation rules — no
  global `@mock_aws` leaking into business code; frozen `T.*` and `S` handles patched via
  `object.__setattr__`; async handlers driven on `asyncio.new_event_loop()`, never
  `get_event_loop()`. `_patch_frozen` / `addCleanup` restore idiom at
  `tests/test_gap_0286_0287_kyc_partner_api.py:154`.
- **`tests/test_gap_0286_0287_kyc_partner_api.py`** (lines 88–116): `_FakeS3` in-memory
  S3 stub (no moto S3); `_UploadFile` async-readable multipart stand-in; `_run(coro)` helper
  at lines 50–56 — fresh `asyncio.new_event_loop()` per call, closed on exit.

`T` and `S` are both `@dataclass(frozen=True)` singletons. `object.__setattr__` bypasses
`FrozenInstanceError` without copying, so all modules referencing `T`/`S` see the patched
value immediately and the original on `addCleanup` restore.

### 2.2 No candidate tests exist

`grep -r "candidates\|CandidateCreate\|cand_" tests/` returns no results. No candidate
service test, no router test, and no E2E spec exist prior to this ticket.

### 2.3 E2E test infrastructure

The Playwright configuration (`frontend/playwright.config.ts`) runs 1 worker, 1 retry,
Chromium only. E2E sessions are seeded by `e2e_admin_session_setup.py` and loaded
synchronously via `execSync` — the pattern used by `frontend/e2e/tickets.spec.ts` (lines
56–66). The `newIdentityPage`, `injectAuth`, `apiPost`, `apiGet`, and `apiDelete` helpers
(tickets spec lines 70–121) are the canonical auth+CSRF helpers CND-007 reuses verbatim.
Note: `apiPatch` is NOT present in `tickets.spec.ts`; `candidates.spec.ts` must define it
locally (same pattern: `page.request.patch(url, { headers: { "x-csrf-token": ... }, data })`).

The `CANDIDATES_ENABLED=1` environment variable must be set in the dev stack for the E2E
spec to pass; the flag-off section explicitly unsets or tests against a separate context
where the flag is `"0"`. Because `e2e_admin_session_setup.py` uses `object.__setattr__` on
`S` for flag overrides in the backend seed script, the simplest approach is to run
`CANDIDATES_ENABLED=1 just restart` before the E2E run, consistent with how other
feature-gated specs are exercised.

### 2.4 Feature-flag gate (CND-001)

`S.candidates_enabled` is a `bool` on `app/core/settings.py` (beside `cart_reminders_enabled`
at `settings.py:821`) defaulting `False`. With the flag off, every CND-005 route returns
HTTP 404 before executing any auth check or service call, and every CND-002 service function
raises `HTTPException(503)`. The `pytest` suite tests both the flag-on happy path and the
flag-off 503/404 behaviour by toggling `S.candidates_enabled` between test classes via
`object.__setattr__`.

## 3. Data Model

CND-007 introduces no new DynamoDB tables. All tables are owned by earlier cluster tickets.

### 3.1 Tables exercised by the pytest suite

| Table handle | Owner ticket | Role in CND-007 tests |
|---|---|---|
| `T.candidates` | CND-001 | Primary table; META rows + `ATTACHMENT#` sub-items + `ACTIVITY#` sub-items |
| `T.alerts` (optional) | existing | `audit_event` writes; not asserted — fire-and-forget |

The `candidates` table `TableDef` (created by CND-001 in `scripts/local-ddb-init.py`) has:

```python
TableDef(
    S.candidates_table_name,  # default "candidates"
    partition_key="pk",
    sort_key="sk",
    gsi=[
        {"index_name": "ByOwner",  "partition_key": "GSI1PK", "sort_key": "GSI1SK"},
        {"index_name": "ByStatus", "partition_key": "GSI2PK", "sort_key": "GSI2SK"},
        {"index_name": "BySource", "partition_key": "GSI3PK", "sort_key": "GSI3SK"},
    ],
    attr_types={"GSI1SK": "N", "GSI2SK": "N", "GSI3SK": "N"},
)
```

The numeric `attr_types` declaration is required by the DynamoDB local gotcha documented in
`CLAUDE.md`: omitting it stores timestamps as String, causing `ValidationException` on
integer comparisons.

### 3.2 In-memory table creation in the pytest suite

Each test class creates the table inline via `boto3.resource` on the moto backend, mirroring
`_make_kyc_cases_table` (`tests/test_gap_0286_0287_kyc_partner_api.py:59`). The function
`_make_candidates_table(ddb)` calls `ddb.create_table` with `TableName="candidates_test"`,
`PK=pk (S)` / `SK=sk (S)`, three GSIs (`ByOwner` on `GSI1PK/GSI1SK`, `ByStatus` on
`GSI2PK/GSI2SK`, `BySource` on `GSI3PK/GSI3SK`), `ProjectionType=ALL`, `BillingMode=PAY_PER_REQUEST`,
and `AttributeType=N` for the three numeric GSI sort-key attributes (`GSI1SK`, `GSI2SK`,
`GSI3SK`) — the numeric `attr_types` requirement from `CLAUDE.md`. (`created_at` is a plain
item attribute, not a key-schema attribute, and must NOT appear in `attr_types`; including
it would cause DynamoDB `ValidationException: Number of attributes in KeySchema does not
exactly match number of attributes defined in AttributeDefinitions` — per CND-001 §3.4.)

## 5. Detailed Behavior & Edge Cases

### 5.1 `TestCandidateCrudService` — CND-002 service layer

Setup: `mock_aws()` context, `_make_candidates_table`, `_patch_frozen(T, "candidates", table)`,
`_patch_frozen(S, "candidates_enabled", True)`. Key cases: `create_candidate` lowercases
email (stores `email_raw`), normalizes phone to E.164, defaults `owner_sub=creator_sub` and
`status="active"`; flag off → 503; `get_candidate` returns `None` for unknown ID;
`update_candidate` → 404 (missing) / 410 (soft-deleted); rewrites `GSI2PK`/`GSI2SK` on
status change and `GSI3PK`/`GSI3SK` on source change; fires `record_candidate_change` spy;
`delete_candidate` idempotent + sets `status="archived"`; `find_candidate_by_email` returns
existing item by normalized email.

### 5.2 `TestCandidateListGsi` — GSI routing + soft-delete exclusion + pagination

Seeds five candidates across two owners, two statuses, two sources (one soft-deleted);
`now_ts()` patched to deterministic ints. Asserts: `owner_sub` filter returns only that
owner's rows; `status` and `source` filters each return only matching rows; soft-deleted
candidate excluded from all three GSI paths; `limit=2` on 3 items returns cursor; round-trip
cursor yields the third item; `limit=9999` clamped to 200.

### 5.3 `TestResumeAttachments` — CND-003 service layer

Setup: moto DDB + `_FakeS3` at `app.core.aws_clients.s3_client`
(`tests/test_gap_0286_0287_kyc_partner_api.py:89`); `max_per_candidate=3`. Cases:
`add_resume` writes `ATTACHMENT#att_…` sub-item + calls `s3.put_object` at
`candidate-resumes/{cand_id}/{att_id}/{name}`; first upload auto-primary + back-writes
`primary_resume_id`; `set_primary_resume` enforces exactly-one; `list_resumes` primary-first +
excludes soft-deleted; `delete_resume` on primary promotes next-newest (or clears pointer);
count cap → 400 `candidate_resume_limit_reached`; soft-delete frees a slot; `delete_resume`
never calls `s3.delete_object`; `source="file_manager"` records `node_path`, calls no S3
put; `get_resume` → 404 for soft-deleted.

### 5.4 `TestMakeDownloadUrl` — dev vs prod presign

`_make_download_url` is the **only** production function with a `S.dev_mode` branch (CND-003,
SECOPS-007 parity note). Two cases: `dev_mode=True` → URL starts with `/mock/s3/`; `dev_mode=False`
with `_FakeS3.generate_presigned_url` returning `https://s3.example/…` → URL starts `https://`.

### 5.5 `TestCandidateHistory` — CND-004 adapter

ACT-009 absent in this class (fallback path). Cases: `record_candidate_change` never raises
with bad ID; writes `ACTIVITY#{inverted_ts}#{event_id}` sub-item; `list_candidate_history`
newest-first (seed ts=10,ts=20; first result ts=20); paginates (3 events, limit=2 + cursor);
ACT-009 delegation: patch `crm_activity_timeline` into `sys.modules`; assert called with
`entity_type="candidate"`.

### 5.6 `TestCandidateRouter` + `TestResumeRouter` — CND-005 handlers

`_FakeSession(user_sub, role, admin_profile=None)` bypasses `Depends(require_ui_session)`.
Handlers invoked with `_run(handler(..., user=fake_session))`. Key cases: flag off → 404 (no
service call); create/list/detail/update/delete round-trip; non-owner delete → 403; admin
delete → 200. Résumé router: bytes exceeding `candidate_resume_max_bytes` → 413 (`vod.py:316`
pattern); disallowed content-type → 400; allowed PDF → 201 + `fake_s3.put_calls` one entry;
dev URL in `GET /resumes`; `PUT /primary` → `is_primary=True`; `DELETE` → 204 + subsequent
GET → 404.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 SECOPS-007 parity in tests

The pytest suite deliberately exercises the same code path that runs in production. No
`S.dev_mode` branch is introduced by CND-001 through CND-005 **except** `_make_download_url`
(CND-003), which the `TestMakeDownloadUrl` class tests in both modes. The `_FakeS3` replaces
the actual boto3 S3 client at the module boundary (`app.core.aws_clients.s3_client`) so the
production `put_object` call stack runs normally; only the I/O is intercepted.

DynamoDB: moto in-process intercepts the exact `T.candidates` handle that production uses.
The `object.__setattr__` patch swaps the underlying resource object; the service code sees
an identical boto3 Table API. There is no `if S.dev_mode` DDB branch anywhere in the
service.

### 7.2 Idempotency & security tests

- `delete_candidate` idempotent (second call is a no-op; `deleted_at` / `status="archived"` consistent).
- `set_primary_resume` called twice on same target: no-op, exactly one `is_primary=True` remains.
- Flag-off: handler raises `HTTPException(404)` before any auth check or DDB write; confirmed
  by `TestCandidateRouter.test_flag_off_returns_404_or_503`.
- Non-owner DELETE → 403 at router layer (service is authz-agnostic per LED-003 §7.4; guard
  is at the router). E2E section TBD-G confirms the UI renders `ModuleDisabledState` on API 404.

## 8. Backward Compatibility & Migration

CND-007 is test-only; it adds no production code and modifies no existing file. Running
`pytest tests/test_cnd_candidates.py` without CND-001–CND-005 merged fails with
`ImportError` — correct and expected; CND-007 merges last. `frontend/e2e/candidates.spec.ts`

`CANDIDATES_ENABLED=1` causes sections TBD-A through TBD-F to fail; section TBD-G
(flag-off) passes. Any
backward-incompatible change to `CandidateOut` will surface as an assertion failure in
sections 71–76, providing a regression safety net.
