# PRT-002 — Public job board listing + per-posting public slug page

**Prefix:** `PRT` · **Area:** ATS / Public Career Portal  
**Type:** Feature · **Priority:** P1 · **Estimate:** 2d  
**Source:** `docs/opencats/ATS_CAREER_PORTAL_TICKETS.md` §PRT-002; gap: `docs/opencats/OPENCATS_GAP_ANALYSIS.md:80-84`

---

## 1. Summary & Goal

PRT-002 delivers the public-facing read surface of the career portal: a paginated job listing endpoint and a per-posting detail page resolved by a stable public slug. Both endpoints are fully unauthenticated, flag-gated, and abuse-hardened. Together with PRT-001's config endpoint they constitute the complete public read layer; PRT-003 (RSS) and PRT-004 (self-apply) build directly on top.

The three public endpoints this ticket adds to the `public_router` declared in PRT-001:

- `GET /public/careers/config` — portal branding (portal name, logo, intro copy) for the frontend header. Delegates to `get_portal_config()` defined in PRT-001.
- `GET /public/careers/jobs` — cursor-paginated list of all `is_public=True` + open job orders, newest first.
- `GET /public/careers/jobs/{slug}` — per-posting detail page resolved via the `SLUG#{slug}` index row in `T.career_portal`, returning only public-safe fields.

All three routes carry no `Depends(...)` auth parameter, are registered in `API_KEY_ROUTE_EXEMPTIONS`, and return HTTP 404 when `S.career_portal_enabled` is `False`. When the forward-dependency JOB-* modules are absent at runtime, `GET /jobs` returns an empty list and `GET /jobs/{slug}` returns 404 — never a 500.

## 3. Data Model

### 3.1 No new DynamoDB tables

PRT-002 introduces no new tables or GSIs. It reads three existing row types from `T.career_portal` (created by PRT-001):

| Row type | PK | SK | Written by | Read by |
|---|---|---|---|---|
| Config row | `CONFIG` | `META` | PRT-001 `set_portal_config` | PRT-002 `/config` |
| Slug index row | `SLUG#{slug}` | `META` | JOB-* publish | PRT-002 `/jobs/{slug}` |

Slug index row fields (read shape; write shape is JOB-*'s responsibility):

```
pk           = "SLUG#{slug}"
sk           = "META"
job_order_id : str            — FK to the job order entity in JOB-* table
slug         : str            — redundant convenience copy
created_at   : N (int)        — Unix timestamp (numeric, not string)
```

The `created_at` field is stored as DynamoDB `N` (Number). If a GSI is ever added on this row type (e.g. `ByJobOrder` for reverse-lookup), its sort key must be declared with `attr_types={"created_at": "N"}` in `scripts/local-ddb-init.py` per the CLAUDE.md gotcha. No GSI is needed in PRT-002.

## 4. API / Service Design

### 4.1 Service additions (`app/services/career_portal.py`)

Three new functions appended to the service file created by PRT-001. All are synchronous (no `async`), following the `cart_reminders.py` module shape.

#### `list_public_jobs(limit, cursor) -> dict`

```python
def list_public_jobs(
    *,
    limit: int = 25,
    cursor: Optional[str] = None,
) -> dict:
    """
    Returns {"items": [...CareerJobSummaryOut dicts...], "cursor": str|None}.
    Delegates to JOB-* list_public_job_orders.
    Graceful degradation: any import or runtime error → empty list.
    """
    _require_enabled()
    from app.core.cursor import decode_cursor, encode_cursor
    esk = decode_cursor(cursor)
    try:
        from app.services.job_orders import list_public_job_orders  # lazy import
        result = list_public_job_orders(limit=limit, exclusive_start_key=esk)
        items = [_to_job_summary(jo) for jo in result.get("items", [])]
        next_cursor = encode_cursor(result.get("last_evaluated_key"))
    except Exception:
        items = []
        next_cursor = None
    return {"items": items, "cursor": next_cursor, "total_estimate": None}


def _to_job_summary(jo: dict) -> dict:
    return {
        "job_order_id": jo["job_order_id"],
        "slug": jo["slug"],
        "title": jo["title"],
        "location": jo.get("location"),
        "employment_type": jo.get("employment_type"),
        "posted_at": int(jo.get("posted_at", 0)),
        "openings": int(jo.get("openings", 1)),
    }
```

#### `get_job_detail(slug) -> dict`

```python
def get_job_detail(slug: str) -> dict:
    """
    Resolves SLUG#{slug} → job_order_id → full job order.
    Returns a CareerJobDetailOut dict.
    Raises HTTPException(404) for unknown/non-public/closed slugs.
    Never returns internal fields (pay_rate, bill_rate, recruiter_notes, etc.).
    """
    _require_enabled()
    # 1. Resolve slug index row
    slug_row = T.career_portal.get_item(
        Key={"pk": f"SLUG#{slug}", "sk": "META"}
    ).get("Item")
    if not slug_row:
        raise HTTPException(status_code=404, detail="Job not found")
    job_order_id = slug_row.get("job_order_id")
    if not job_order_id:
        raise HTTPException(status_code=404, detail="Job not found")

    # 2. Load job order from JOB-* service
    jo = None
    try:
        from app.services.job_orders import get_job_order  # lazy import
        jo = get_job_order(job_order_id)
    except Exception:
        pass
    if not jo:
        raise HTTPException(status_code=404, detail="Job not found")

    # 3. Visibility gate: must be public + open
    if not jo.get("is_public"):
        raise HTTPException(status_code=404, detail="Job not found")
    if jo.get("status") not in _OPEN_STATUSES:
        raise HTTPException(status_code=404, detail="Job not found")

    # 4. Resolve optional screening questionnaire slug
    q_slug = _resolve_screening_questionnaire_slug(jo.get("screening_questionnaire_id"))

    return {
        **_to_job_summary(jo),
        "public_description": jo.get("public_description"),
        "screening_questionnaire_slug": q_slug,
        "apply_path": f"/public/careers/jobs/{slug}/apply",
    }


_OPEN_STATUSES = {"open", "active"}   # JOB-* must use one of these for open requisitions

def _resolve_screening_questionnaire_slug(questionnaire_id: Optional[str]) -> Optional[str]:
    """
    Returns the published slug of a linked questionnaire, or None.
    Best-effort: any error → None (never blocks the detail page).
    Reuses questionnaires_repository.REPO.get_questionnaire() and .get_published_by_slug()
    patterns from app/routers/questionnaires.py:620,633.
    """
    if not questionnaire_id:
        return None
    try:
        from app.services.questionnaires_repository import DynamoQuestionnaireRepository
        repo = DynamoQuestionnaireRepository()
        draft = repo.get_questionnaire(questionnaire_id)
        if not draft or draft.get("status") != "published":
            return None
        published_version_id = draft.get("published_version_id")
        if not published_version_id:
            return None
        version = repo.get_version_by_id(questionnaire_id, published_version_id)
        if not version:
            return None
        return version.get("published_slug")
    except Exception:
        return None
```

## 5. Detailed Behavior & Edge Cases

### 5.1 Flag-off behavior

When `S.career_portal_enabled = False`:
- All three handlers call `_require_enabled()` via `get_portal_config_public()` / `list_public_jobs()` / `get_job_detail()` before any DDB or JOB-* I/O occurs, and raise `HTTPException(404, "Not found")`.
- No DDB read or write occurs.
- The routes still exist in the router (they are registered unconditionally), but every call to them 404s — identical to KB-011's flag-off behavior at `kb_articles.py:144-146`.

### 5.2 `GET /public/careers/jobs` — listing semantics

- Only `is_public=True` AND `status in _OPEN_STATUSES` postings appear. Drafts, closed, filled, or cancelled job orders never appear.
- Items are ordered newest-first (`posted_at` descending). The ordering is enforced by JOB-* at the query level; PRT-002 does not re-sort the returned slice.
- Cursor is an opaque HMAC-signed token from `encode_cursor` (`app/core/cursor.py:94`). A `null` cursor means no further pages. Passing an expired or tampered cursor causes `decode_cursor` to return `None` (signature mismatch → silent fallback at `cursor.py:111-124`), which is then treated as no cursor — the handler returns the first page rather than raising 400. Callers must not rely on a 400 for invalid cursors; the silent restart is intentional.
- `limit` defaults to 25, maximum 100. Values outside `[1, 100]` return 422 from Pydantic.
- `total_estimate` is always `None`. DynamoDB does not provide a count from a filtered GSI query without a full scan; the frontend must not rely on this field.
- An authenticated user calling this endpoint gets the same response as an unauthenticated user — no personalization.

### 5.3 `GET /public/careers/jobs/{slug}` — visibility gates

The function applies four consecutive 404 gates before returning data:

1. **Slug row missing**: `T.career_portal.get_item(Key={"pk": "SLUG#{slug}", "sk": "META"})` returns no `Item` → 404.
2. **`job_order_id` absent or blank** in the slug row → 404 (data integrity guard).
3. **JOB-* absent / `get_job_order` raises** → 404 (graceful degradation; never 500).
4. **`is_public=False` or `status` not in `_OPEN_STATUSES`** → 404.

The same 404 detail string (`"Job not found"`) is returned in all four cases to avoid leaking slug-existence to unauthenticated callers.

### 5.4 Screening questionnaire link

`screening_questionnaire_slug` is derived via `_resolve_screening_questionnaire_slug`. The function:
- Returns `None` when `screening_questionnaire_id` is absent.
- Returns `None` when the questionnaire exists but `status != "published"` — a draft or archived questionnaire is never surfaced publicly (CMP-005 §4.2 `_validate_questionnaire_link` pattern).
- Returns `None` on any exception (lazy import failure, DDB error, etc.) — best-effort, never blocks the detail response.
- Returns the `published_slug` string when the questionnaire is published. The frontend can then direct applicants to `/questionnaires/published/{screening_questionnaire_slug}` (the existing public submit pipeline at `app/routers/questionnaires.py:644`).

### 5.5 Public-safe field contract

`get_job_detail` returns **only** the fields in `CareerJobDetailOut`. Specifically absent:
- `pay_rate` / `bill_rate` (internal recruiter fields)
- `recruiter_notes` / `internal_notes`
- `owner_sub` / `recruiter_sub` (internal user references)
- `source` / `origin` (lead-source tracking)
- Any full pipeline / candidate count

The `_to_job_summary` helper copies only the whitelisted fields by name, not by spreading the entire JOB-* dict. A future JOB-* change adding new internal fields does not risk leaking them.

### 5.6 `GET /public/careers/config` — cold-start behavior

`get_portal_config()` (PRT-001) returns the `S`-defaults (`portal_name="Careers"`, empty intro, `logo_url=None`) when no config row exists. This means the portal renders even before an admin has visited the settings page. `logo_url` is `None` → the frontend should render a default placeholder; no missing-key error.

### 5.7 JOB-* absent at runtime

All JOB-* calls in the service functions are wrapped in `try/except Exception` blocks:
- `list_public_jobs`: exception → `items=[]`, `cursor=None`, `total_estimate=None`. Returns 200 with an empty list — not a 500.
- `get_job_detail`: exception from `get_job_order` → raises `HTTPException(404)` — not a 500.

This is the "graceful degradation to 404/empty" pattern from CMP-006 §5.8 and LED-005's lazy-import guard, adapted here with the 404 semantics appropriate for a slug-resolution failure.

### 5.8 Route declaration ordering

On `public_router` the declaration order is:
1. `GET /config`
2. `GET /jobs`
3. `GET /jobs/{slug}`

FastAPI matches in declaration order. If `/jobs/{slug}` were declared first, a request to `/jobs` would be captured as `slug="jobs"` and return 404. The static segments must always precede the dynamic segment. This matches the constraint documented for `GET /public/kb/categories` vs `GET /public/kb/categories/{category_id}` in KB-011 §4.1 and the `kyc_cases.py` `/templates`-before-`/{case_id}` pattern (CLAUDE.md "KYC template-signature endpoints"; `kyc_cases.py:911` before `:932`).

### 5.9 Caching and freshness

No response caching is implemented in PRT-002. The DynamoDB reads for the config row and slug row are always live. If read latency becomes a concern in production, a short TTL in-process cache (or a CDN cache header) can be added in a follow-up. The PRT-002 implementation must set no `Cache-Control` headers so CDNs do not inadvertently cache stale listings.

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 No `dev_mode` branches

PRT-002 contains zero `if S.dev_mode` branches. The only environment-determined behavior is:
- `build_download_url` (`filemanager.py:2374`) uses `S.public_base_url` which is `http://localhost:8000` in dev and the real domain in prod — decided inside that helper, not in PRT code.
- `presign_upload` (`filemanager.py:2207`) used by PRT-005, not this ticket.

All DDB reads go through the same boto3 client in both environments (moto in tests, DDB Local at port 8001 in dev, real DDB in prod). No mock data paths, no in-memory substitutions.

### 7.2 Idempotency

- All three handlers are pure `GET` requests — inherently idempotent.
- `get_job_detail` performs a point read followed by a JOB-* read; both are read-only operations with no side effects.
- `list_public_jobs` performs a paginated read from JOB-*; same result for the same cursor input given the same underlying data.

### 7.3 Security

**No authentication, no CSRF** on public endpoints. CSRF validation at `app/services/sessions.py:429` fires only when the `ui_session` cookie is present; unauthenticated callers carry no such cookie.

**Information leakage prevention:**
- `get_job_detail` uses a whitelist approach (`_to_job_summary` copies named fields only). Internal JOB-* fields are never passed through to the response.
- All four visibility gates return the same `"Job not found"` 404 — slug existence is not leaked to the public.
- Screened questionnaire resolution returns `None` on any error, not an error message referencing internal IDs.

**No write paths on public endpoints.** `GET /config`, `GET /jobs`, and `GET /jobs/{slug}` are all read-only; they perform no DDB writes, no file operations, and no billing operations.

**Slug enumeration risk:** The slug format is JOB-*'s responsibility. PRT-002 only reads slugs; it does not validate or normalize them. If JOB-* uses sequential or predictable slugs, a bot could enumerate them. This is a JOB-* hardening concern, not a PRT-002 concern.

**DDB `FilterExpression` and pagination completeness:** If JOB-* queries use a `FilterExpression` on a sparse attribute (e.g., `is_public=True` on a table that also stores drafts), DynamoDB fetches up to 1MB before filtering. JOB-*'s `list_public_job_orders` must loop via `LastEvaluatedKey` to ensure all pages are fully filtered (CLAUDE.md "DDB FilterExpression doesn't reduce page size" gotcha). PRT-002 passes `exclusive_start_key` through transparently; correctness depends on JOB-*'s implementation.

## 10. Open Questions / Assumptions

1. **`_OPEN_STATUSES` definition.** PRT-002 defines `_OPEN_STATUSES = {"open", "active"}`. The exact set of open-state strings must be agreed with JOB-* before the first integrated test run. JOB-* may use a state machine with values like `"accepting_applications"` or `"filled"`. PRT-002 should export `_OPEN_STATUSES` or import it from a JOB-* constant to avoid duplication; for now it is local to the service.

2. **Employment type enum.** `CareerJobSummaryOut.employment_type` is declared as `Optional[str]` with a comment noting the expected values. If JOB-* defines an enum (e.g., `EmploymentType`), PRT-002 should adopt the same values. No validation is applied at this layer — an unexpected string is returned as-is.

3. **`posted_at` vs `created_at`.** JOB-* may use `created_at` for the creation timestamp and a separate `posted_at` for the date the role was published to the portal. PRT-002 assumes `posted_at` is the publication timestamp. If JOB-* only has `created_at`, the mapping in `_to_job_summary` can fall back: `int(jo.get("posted_at") or jo.get("created_at", 0))`.

4. **Search branch (`_search_careers`) scope.** Marked optional for PRT-002. If deferred, it should land as part of a future KB-009-style follow-up ticket so the careers domain appears in global search results when users search from the main app. The `ALLOWED_TYPES` extension is non-breaking additive.

5. **Multi-tenant slugs.** `S.career_portal_slug_prefix` (declared in PRT-001) is unused in PRT-002. If the platform ever needs multi-tenant career portals, slug rows would need to be namespaced `SLUG#{prefix}/{slug}`. This is a JOB-* change (it writes the row); PRT-002 would only need to update the key format in `get_job_detail`. Deferred.

6. **Logo URL in listing.** `CareerJobListOut` does not include a `logo_url` field per item. If individual job orders need per-posting branding images, a `job_image_path` field on the job order would need to be resolved via `build_download_url` in `_to_job_summary`. Not in scope for PRT-002.
