## 1. Summary & Goal

CND-005 creates `app/routers/candidates.py` — the FastAPI router that exposes the Candidate
entity, résumé management, owner assignment, and change-history feed as authenticated HTTP
endpoints. It is the thin HTTP layer over the three service tickets that precede it: the CRUD
functions from CND-002 (`app/services/candidates.py`), the attachment operations from CND-003
(also in `app/services/candidates.py`, sub-section), and the history feed from CND-004
(also in `app/services/candidates.py`, via `record_candidate_change` /
`list_candidate_history`).

The router:

- Enforces the global feature flag (`S.candidates_enabled`) with a hard 404 gate at the top
  of every handler — no service call, no auth check, no side effect runs with the flag off.
- Uses standard cookie-based session auth via `Depends(require_ui_session)` for all routes.
- Runs every sync service function through `asyncio.to_thread` so the event loop is never
  blocked (same pattern as `app/routers/google_drive_integration.py:160`).
- Exposes twelve endpoints across three conceptual groups: candidate CRUD (5 routes), résumé
  management (5 routes), and change history (1 route), plus owner assignment (1 route).
- Is registered in `app/main.py` with `app.include_router(candidates_router)` — no prefix
  argument because the router itself carries `prefix="/ui/candidates"`, matching the contacts
  and tickets conventions.

The primary outcome is a complete, tested REST surface that the CND-006 frontend pages and
the CND-007 Playwright E2E tests can exercise end-to-end.

```python
    raise HTTPException(status_code=404, detail="Not found")
```

This is the simplest correct gate — it returns 404 (indistinguishable from "route does not

### 2.5 Auth dependency shape

`require_ui_session` (`app/services/sessions.py:330`) returns a `dict` with at minimum:

```python

```

The router extracts `ctx["user_sub"]` for all service calls. `_is_admin(user)` is imported
from `app/routers/tickets.py` or rewritten inline — the tickets implementation at line 207

stay decoupled.

Because `require_ui_session` returns a plain dict (not `AuthenticatedUser`), the `_is_admin`
helper for this router accepts `ctx: dict` and reads `ctx.get("role")`.

## 3. Data Model

CND-005 is a **pure router ticket** — it introduces no new DynamoDB tables, no new GSIs, and
no new settings. All storage is owned by CND-001 through CND-004. This section is a
reference summary of the DDB structures the router reads and writes through the service layer.

### 3.1 `candidates` table (owned by CND-001)

```
PK  = "CANDIDATE#{candidate_id}"    SK = "META"
GSI1: ByOwner   — GSI1PK="OWNER#{owner_sub}"    / GSI1SK=created_at (N)
GSI2: ByStatus  — GSI2PK="STATUS#{status}"      / GSI2SK=created_at (N)
GSI3: BySource  — GSI3PK="SOURCE#{source}"      / GSI3SK=created_at (N)
attr_types: {"GSI1SK": "N", "GSI2SK": "N", "GSI3SK": "N", "created_at": "N"}
```

`scripts/local-ddb-init.py` declares this `TableDef` with all three GSIs and the numeric
`attr_types` map (CLAUDE.md numeric-GSI-sort-key gotcha; pattern: `local-ddb-init.py:35`).

### 3.2 Résumé sub-items (owned by CND-003)

```
PK  = "CANDIDATE#{candidate_id}"    SK = "ATTACHMENT#{attachment_id}"
Fields: attachment_id, filename, content_type, size_bytes, s3_key (or node_path),
        source ("upload"|"file_manager"), is_primary (BOOL), uploaded_by,
        created_at (N), deleted_at (N|absent)
```

No separate table — single-table design on `candidates`.

### 3.3 Activity sub-items (owned by CND-004, fallback path)

```
PK  = "CANDIDATE#{candidate_id}"    SK = "ACTIVITY#{inverted_ts}#{activity_id}"
Fields: activity_id, change_type, summary, actor_sub, metadata, created_at (N)
```

Written only when ACT-009 (`crm_activity_timeline.py`) has not shipped. If ACT-009 is
present, history rows live in the `crm_activity_timeline` table (ACT-001/ACT-009 scope).

### 3.4 S3 résumé objects

Bucket: `S.candidate_resume_bucket` (env `CANDIDATE_RESUME_BUCKET`, default `"local-uploads"`)  
Key pattern: `{S.candidate_resume_s3_prefix}{candidate_id}/{attachment_id}/{safe_filename}`  
Client: `app.core.aws_clients.s3_client()` (`app/core/aws_clients.py:114`) — moto intercepts
in dev, real S3 in prod; no `dev_mode` branch in the router or service.

## 4. API / Service Design

### 4.1 Router declaration

```python
# app/routers/candidates.py
from fastapi import APIRouter, Depends, File, Form, HTTPException, Query, UploadFile
from app.services.sessions import require_ui_session
from app.core.settings import S
...

router = APIRouter(prefix="/ui/candidates", tags=["candidates"])
```

Registered in `app/main.py` (append after `contacts_router` at line 683):

```python
from app.routers.candidates import router as candidates_router
...
app.include_router(candidates_router)
```

No `prefix` argument on `include_router` — the prefix is embedded in the router declaration,
following the contacts pattern (`app/routers/contacts.py:14`).

### 4.2 Flag gate helper

```python
def _require_candidates() -> None:
    if not S.candidates_enabled:
        raise HTTPException(status_code=404, detail="Not found")
```

Called at the top of every handler body — before auth resolution, before service calls. The
helper raises 404 (not 503) because to an unauthenticated observer the routes should not
exist when the module is disabled.

### 4.3 Admin helper

```python
def _is_admin(ctx: dict) -> bool:
    from app.auth.roles import normalize_role, Role
    return normalize_role(ctx.get("role", "user")) in {Role.ADMIN, Role.ROOT}
```

Mirrors `app/routers/tickets.py:207-208`. Defined once in the router module, used in the
delete and set-owner handlers.

### 4.4 Endpoint table

All routes require `Depends(require_ui_session)` (abbreviated as `[auth]` below). Literal
path segments (`resumes`, `history`, `owner`) are declared **before** the `/{candidate_id}`
catch-all group — FastAPI matches in declaration order, so a wildcard declared first would
shadow them (GAP-0210 ordering gotcha; CLAUDE.md "SCHEDULES routes declared BEFORE
`/{export_id}`").

```
POST   /ui/candidates                                         create_candidate_endpoint
GET    /ui/candidates                                         list_candidates_endpoint
GET    /ui/candidates/{candidate_id}                          get_candidate_endpoint
PATCH  /ui/candidates/{candidate_id}                          update_candidate_endpoint
DELETE /ui/candidates/{candidate_id}                          delete_candidate_endpoint
PUT    /ui/candidates/{candidate_id}/owner                    set_owner_endpoint
POST   /ui/candidates/{candidate_id}/resumes                  upload_resume_endpoint   (multipart)
GET    /ui/candidates/{candidate_id}/resumes                  list_resumes_endpoint
GET    /ui/candidates/{candidate_id}/resumes/{att_id}         get_resume_endpoint
PUT    /ui/candidates/{candidate_id}/resumes/{att_id}/primary set_primary_resume_endpoint
DELETE /ui/candidates/{candidate_id}/resumes/{att_id}         delete_resume_endpoint
GET    /ui/candidates/{candidate_id}/history                  get_history_endpoint
```

## 5. Detailed Behavior & Edge Cases

### 5.1 Flag gate is the first statement in every handler body

```python
@router.post("")
async def create_candidate_endpoint(body, ctx=...):
    _require_candidates()          # ← first — raises 404 with flag off
    user_sub = ctx["user_sub"]
    ...
```

When the flag is off, FastAPI still matches the route (the router is registered unconditionally
— this is intentional so that a flag-on restart does not require server restart), but the
handler returns 404 before touching auth or services. This differs from the `if _S.flag:
include_router(...)` conditional-registration pattern seen in `app/main.py:699` (ticket boards)
— for CND-005 unconditional registration is preferred because it makes the flag hot-reloadable
in tests without rebuilding the app object.

### 5.2 CRUD authorization model

| Action | Who may perform it |
|---|---|
| `POST /ui/candidates` | Any authenticated user |
| `GET /ui/candidates` | Any authenticated user; `owner_sub` filter defaults to caller's own sub |
| `GET /ui/candidates/{id}` | Any authenticated user (records are not per-user private) |
| `PATCH /ui/candidates/{id}` | Record's `owner_sub` OR admin/root |
| `DELETE /ui/candidates/{id}` | Record's `owner_sub` OR admin/root; others → 403 |
| `PUT /{id}/owner` | Admin/root only; non-admin → 403 |
| All résumé endpoints | Candidate owner or admin/root (consistent with PATCH/DELETE) |
| `GET /{id}/history` | Any authenticated user (read-only audit trail) |

Owner check in delete/update handlers:

```python
candidate = await asyncio.to_thread(candidates.get_candidate, candidate_id)
if not candidate:
    raise HTTPException(404)
if candidate.get("deleted_at"):
    raise HTTPException(410, detail={"code": "candidate_deleted"})
if candidate["owner_sub"] != ctx["user_sub"] and not _is_admin(ctx):
    raise HTTPException(403, detail={"code": "forbidden"})
```

### 5.3 List endpoint — `owner_sub` filter default

When `owner_sub` is omitted, `list_candidates` is called with `owner_sub=ctx["user_sub"]`
so recruiters see only their own candidates by default. Admins who want all candidates pass
`owner_sub=*` (a sentinel string); the service detects `"*"` and skips the ByOwner GSI,
falling back to a full ByStatus or BySource scan (capped at 200 rows). This mirrors the
tickets list pattern where the default scope is the caller's own tickets.

### 5.4 Résumé upload flow

```
1. _require_candidates()
2. Resolve candidate (404/410 if missing/deleted); owner/admin gate
3. data = await file.read()
4. if len(data) > S.candidate_resume_max_bytes: raise HTTPException(413)
5. if file.content_type not in _RESUME_ALLOWED_CONTENT_TYPES: raise HTTPException(400)
6. safe_name = re.sub(r"[^A-Za-z0-9._-]", "_", file.filename or "resume")[:255]
7. attachment_id = "att_" + uuid4().hex
8. s3_key = f"{S.candidate_resume_s3_prefix}{candidate_id}/{attachment_id}/{safe_name}"
9. await asyncio.to_thread(
       s3_client().put_object,
       Bucket=S.candidate_resume_bucket,
       Key=s3_key,
       Body=data,
       ContentType=file.content_type,
   )
10. row = await asyncio.to_thread(
        candidates.add_resume,
        candidate_id,
        uploaded_by=ctx["user_sub"],
        filename=safe_name,
        content_type=file.content_type,
        size_bytes=len(data),
        s3_key=s3_key,
        s3_bucket=S.candidate_resume_bucket,
        make_primary=make_primary,
    )
11. row["url"] = candidates._make_download_url(s3_key, S.candidate_resume_bucket)
12. return CandidateResumeOut.model_validate(row)
```

Steps 9 and 10 are intentionally ordered: S3 write first, then DDB metadata. On S3 failure
the DDB row is never written; on DDB failure after S3 success, the S3 object is orphaned
(lifecycle policy cleans it up — same KB-003 §5.3 rationale: avoiding a compensating
transaction). The S3 write runs inside `asyncio.to_thread` because `put_object` is a blocking
boto3 call.

### 5.5 Detail endpoint populates `resumes[]`

```python
raw = await asyncio.to_thread(candidates.get_candidate, candidate_id)
if not raw or raw.get("deleted_at"):
    raise HTTPException(404)
attachments = await asyncio.to_thread(candidates.list_resumes, candidate_id)
for att in attachments:
    # file_manager-sourced items have no s3_key; _make_download_url is only called
    # for s3-backed items. For source="file_manager" rows CND-003's list_resumes
    # already populates url via filemanager.get_node — the router does not re-derive it.
    if att.get("s3_key"):
        att["url"] = candidates._make_download_url(
            att["s3_key"],
            att.get("s3_bucket") or S.candidate_resume_bucket,
        )
raw["resumes"] = attachments
return CandidateOut.model_validate(raw)
```

`list_resumes` already excludes soft-deleted attachments and sorts primary first.

### 5.6 `set_primary_resume` endpoint

The `PUT /{id}/resumes/{att_id}/primary` path segment `/primary` is a sub-resource action,
not a separate top-level route. FastAPI matches it because the path template is more specific
than `/{candidate_id}/resumes/{att_id}`. The handler calls `candidates.set_primary_resume`
(CND-003), which enforces the exactly-one-primary invariant atomically in DDB (conditional
expression on the old primary row).

### 5.7 History endpoint delegates entirely to CND-004

```python
page = await asyncio.to_thread(
    candidates.list_candidate_history,
    candidate_id,
    cursor=cursor,
    limit=limit,
)
# CND-004 returns {"events": [...], "next_cursor": str|None}.
# CandidateHistoryPage uses "cursor" (not "next_cursor"), so map explicitly
# rather than calling model_validate(page) which would silently drop next_cursor.
return CandidateHistoryPage(
    events=page.get("events", []),
    cursor=page.get("next_cursor"),
)
```

The router has no history logic. Cursor encoding/decoding, newest-first ordering, and ACT-009
delegation are all handled by `list_candidate_history`.

### 5.8 Route ordering — literal segments before wildcard

Declaration order in the router module:

```python
# 1. Literal-segment routes (cannot be shadowed)
@router.get("")                    # /ui/candidates
@router.post("")                   # /ui/candidates

# 2. Wildcard with sub-resource literal paths declared first inside the group:
@router.put("/{candidate_id}/owner")      # declared BEFORE /{candidate_id}
@router.post("/{candidate_id}/resumes")
@router.get("/{candidate_id}/resumes")
@router.get("/{candidate_id}/history")
# ... then the catch-all:
@router.get("/{candidate_id}")
@router.patch("/{candidate_id}")
@router.delete("/{candidate_id}")
```

FastAPI route matching is first-match-wins. If `/{candidate_id}` were declared first, a GET
to `/ui/candidates/abc123/history` would match with `candidate_id="abc123/history"` (or fail).
Declaring all sub-resource routes before the catch-all prevents this.

### 5.9 Error response shape

All 4xx errors use the standard platform envelope:

```json
{"detail": {"code": "candidate_not_found", "message": "Candidate not found"}}
```

Error codes used by this router:

| HTTP | Code | Trigger |
|---|---|---|
| 404 | `not_found` | Flag off, candidate missing |
| 410 | `candidate_deleted` | Soft-deleted candidate |
| 403 | `forbidden` | Non-owner/non-admin trying to write |
| 413 | `resume_too_large` | File exceeds `S.candidate_resume_max_bytes` |
| 400 | `invalid_content_type` | MIME type not in allowlist |
| 400 | `candidate_resume_limit_reached` | Cap of `S.candidate_resume_max_per_candidate` active résumés |
| 503 | (from service) | Flag off at service layer (belt-and-suspenders) |

## 7. Dev/Prod Parity (SECOPS-007), Idempotency, Security

### 7.1 SECOPS-007 — no `S.dev_mode` branch in this router

The router contains **zero** `if S.dev_mode:` branches. The single dev/prod split is
`candidates._make_download_url` (owned by CND-003 in the service file):

```python
def _make_download_url(s3_key: str, s3_bucket: str) -> str:
    if S.dev_mode:
        return f"/mock/s3/{s3_bucket}/{s3_key}"
    return s3_client().generate_presigned_url(
        "get_object",
        Params={"Bucket": s3_bucket, "Key": s3_key},
        ExpiresIn=300,
    )
```

This is the exact pattern from `app/services/kyc_partner_api.py:630-641`. The router calls
`_make_download_url(s3_key, s3_bucket)` (two args, matching CND-003 §4.1 definition); the
split is invisible to the HTTP layer. All DDB access goes through `T.candidates` (moto in dev, real DDB in prod — same
code path). All S3 access goes through `s3_client()` (`app/core/aws_clients.py:114`), which
moto intercepts in-process in dev.

### 7.2 Idempotency

- **`POST /ui/candidates`**: Not idempotent by design. The service's cheap same-email
  short-circuit (CND-002) returns the existing candidate if an active record with the same
  normalized email already exists, preventing duplicate creation from a double-submit. This
  is not a full merge (LED-009 scope) but avoids accidental duplicates from UI retries.
- **`DELETE /ui/candidates/{id}`**: Idempotent — soft-deleting an already-soft-deleted
  candidate is a no-op (`delete_candidate` checks `deleted_at` and returns silently).
- **`PUT /{id}/resumes/{att_id}/primary`**: Idempotent — calling it twice with the same
  `att_id` results in the same state (one primary, others non-primary).
- **`DELETE /ui/candidates/{id}/resumes/{att_id}`**: Idempotent — soft-deleting an already
  soft-deleted résumé is a no-op.

### 7.3 CSRF

All non-GET requests go through `require_ui_session` which enforces CSRF for cookie-auth
callers (CLAUDE.md auth section). The frontend `api/client.ts` axios instance attaches the
`x-csrf-token` header automatically (reads from `ui_csrf` cookie). No extra CSRF handling is
needed in the router.

### 7.4 Input validation and normalization

- Email/phone normalization happens **in the service layer** (CND-002 `create_candidate` /
  `update_candidate`), not in Pydantic validators — this is the project-wide convention
  (`normalize_email` / `normalize_phone` at `app/core/normalize.py:60,66` both raise
  `HTTPException(400)`, which works correctly from synchronous code called in `to_thread`).
- `key_skills` is capped at 4000 characters via `Field(..., max_length=4000)` on
  `CandidateCreateIn` (CND-001 model).
- URL fields (`linkedin_url`, `web_url`) are capped at 500 characters by the Pydantic model.
- `status` validates against `CANDIDATE_STATUSES` set via Pydantic `Literal` or a custom
  validator in `CandidateUpdateIn` (CND-001).

### 7.5 File upload security

- Size cap enforced **before** `put_object` (step 4 in §5.4): the entire file is read into
  memory first. This is acceptable for the 20 MB default cap; for production deployments with
  very large PDFs, a streaming approach could be used, but for the current cap this is
  identical to the KYC document upload pattern.
- Content-type check uses `file.content_type` (HTTP header, client-supplied). This is not
  a guarantee of actual file content (clients can lie). Tier-3 résumé text extraction (out
  of scope for this ticket cluster) would add a magic-byte check. For now, the MIME allowlist
  reduces the attack surface without adding a dependency.
- Filename is sanitized with `re.sub(r"[^A-Za-z0-9._-]", "_", ...)[:255]` before use in
  the S3 key and DDB record. The original filename is not stored raw.
- S3 keys are constructed from trusted server-side components (`candidate_id`,
  `attachment_id`, sanitized filename); no user input reaches the key construction
  unescaped.

### 7.6 Ownership enforcement

The service layer (`candidates.py`) is authorization-agnostic — it executes whatever the
router passes. Authorization lives exclusively in the router:

- Delete and update operations verify `owner_sub == ctx["user_sub"]` or `_is_admin(ctx)`
  before calling the service (LED-003 §7.4 pattern: "service stays authz-agnostic").
- Set-owner is admin-only: `if not _is_admin(ctx): raise HTTPException(403)`.
- Résumé operations use the same gate as their parent candidate PATCH/DELETE.

## 10. Open Questions / Assumptions

1. **`owner_sub=*` wildcard for admin list**: The `list_candidates` service function
   (CND-002) is specified with `owner_sub` as a required keyword argument; passing `"*"` as
   a sentinel to mean "all owners" requires a small service-layer accommodation. If CND-002
   does not implement this, the router can instead omit `owner_sub` entirely for admin callers
   (passing `None`) and rely on the service to fall back to ByStatus or BySource. This must
   be clarified during CND-002 implementation; the router design supports either approach.

2. **410 vs 404 for soft-deleted candidates**: The spec above returns 404 for soft-deleted
   candidates in the detail endpoint (to avoid leaking deletion status to unauthorized
   callers). Admins could plausibly want a 410 to distinguish "never existed" from "deleted".
   The current design uses 404 for both; a future admin-only 410 can be added without
   breaking existing clients (new HTTP status code is additive).

3. **Résumé upload streaming**: The current design reads the entire file into memory before
   the size check. For a 20 MB cap this is acceptable, but if `CANDIDATE_RESUME_MAX_BYTES`
   is increased significantly in production, a streaming upload with an early-abort approach
   (chunk-by-chunk byte accumulation) would be safer. This is a known limitation documented
   as a future improvement.

4. **File-manager-source résumé path**: CND-003 defines a `source="file_manager"` path where
   the recruiter attaches an existing file manager node (pointer, no byte copy). CND-005 does
   not add a dedicated endpoint for this path — it would require a separate `POST /{id}/resumes/link`
   endpoint accepting a `node_id` body. This is treated as a CND-006/CND-007 follow-up;
   the service supports it but the router does not expose it in this ticket.

5. **Pagination `total_hint`**: `CandidateListOut.total_hint` is marked `| None` because
   DDB does not support cheap COUNT queries. A "Count: N candidates" UI hint would require
   a separate `Query(..., Select="COUNT")` call. Including it is a CND-006 UX decision; the
   router today returns `null` for `total_hint`.
