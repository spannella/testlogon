# Advertising — Rough-Edges Audit & Smoothing Plan

**Scope:** audit of the shipped ADVERTISING subsystem (ADV-B0..B5 real funding+serving+charge+CPA+hardening, ADV2-E1..E6 live-stream ad breaks / in-player CTAs / self-advertising / sponsored-as-creator / ad-messaging / syndicate ads, AD-ECOM sponsored products + seller boost, LIVE-COMMERCE). The core ledger/charge/attribution/auction engine is genuinely real. This document catalogs the ROUGH EDGES an advertiser actually hits, weighted toward the advertiser lifecycle (create -> fund -> target -> creative -> review -> launch -> serve -> charge -> attribute -> measure), and lays out a dependency-ordered ticketed plan to smooth them.

- **Method:** 5 dimension auditors (flow/UX, serving/delivery, money-correctness, measurement, policy) + foundation map. Every finding grounded in file:line. Two headline questions were settled by a read-only prod SSM probe. This is an AUDIT — the only write is this plan; nothing below changes advertising behavior.
- **Status:** AUDIT COMPLETE.

## 1. HEADLINE — how rough is it, really?

**Verdict: the engine is real, the business is not yet live, and the advertiser flow is half-wired.** The hard part is genuinely built and correct: funds-guarded atomic debits that can't go negative, idempotency markers, a real second-price auction, TTL'd last-click CPA attribution with an atomic claim, self-promo/tip no-charge carve-outs, budget auto-pause at 100%, a real paid-creative review gate at serve, a real kill switch, and a real 6-rule fraud engine on the track path — all with real admin surfaces. This is no longer "a sophisticated simulation" at the ledger layer.

**But three things keep it from being a live ad business, and they are the load-bearing rough edges:**

1. **Nobody's card is ever charged (P0, money).** Prod probe confirms `stripe_secret_key` is empty, so `_charge_deposit` short-circuits to `return None` for every deposit while `deposit_funds` still credits the balance and books `PLATFORM#revenue`. The entire ad economy runs on funny money: unlimited free advertiser budget, "revenue" that is never collected. The code path *looks* like a charge rail and is documented as one — this is the one place simulation is masquerading as a live flow.

2. **On prod, real paid ads barely render, and one whole placement bills nobody (P1, serving).** VOD pre-roll ships a static placeholder because `vod_ad_supported_deterministic` defaults/ships **True** — the decoupled live `serve_ad(preroll)` path never runs, no advertiser is selected, no CPM charges, the poster earns nothing. And the decisive open question RE-7 stands: serving anything real requires >=1 active campaign with an approved creative; the fold README records newsfeed injection as "ON-but-empty." If prod has no live inventory, every wired placement still serves house/nothing regardless of the code.

3. **The advertiser can't actually run the flow (P1, UX).** The guided create wizard forward-chains a brand-new advertiser straight into a campaign-create step that is **guaranteed to 403** ("Account is not active"). After launch there is **no campaign management at all** — the list is read-only, rows are dead, the backend PATCH is called nowhere, so you can't pause/resume/edit budget from the app. Funding is **orphaned from the create flow** and the billing hub is hardwired to the *first* account. There is no accounts-list screen, so every account-scoped surface silently pins to account #1.

Around those three, measurement is real when read via the ledger `/roas` endpoint but the KPI dashboard is fed by an async rollup layer that drops the current day, can lose whole days, doesn't reconcile with the ledger ROAS card sitting next to it, mislabels CPC as "CPA," and renders three fabricated/empty metrics; and policy review is 100% manual eyeballing with **no automated content policy at all** plus three surfaces (seller-boost, sponsored-as-creator, ad-messaging) that bypass the review gate.

**Honest split: ~70% real engine, ~30% live business.** The money movement, auction, attribution and serving *logic* are real; the *cash-in rail* (deposit charge), the *primary render surface* (VOD pre-roll), the *management surface* (campaign edit/pause + accounts + funding wiring), and the *automated policy layer* are the simulation/holes. Close the deposit charge, flip the VOD flag, wire accounts/funding/management, and reconcile the dashboard, and it becomes a real advertiser product.

### EPIC 1 — MONEY-CORRECTNESS (do first; nothing else matters if the cash rail is fake)

- Scope: provision a real/stripe-mock `stripe_secret_key` on prod OR gate `deposit_funds` so a missing key/PM produces a LOUD simulation state, never a silent free credit. Split the internal-seed caller (`internal=True` may skip charge) from the public `/deposit` endpoint (must 400 when `payment_method_id` empty). App deposit sheet forces PM selection; add an "Add card" affordance in `PaymentMethodPicker`.
- AC: on prod, a `/deposit` with a valid PM creates a PaymentIntent and only credits balance on success; a `/deposit` with no PM 400s (public) — never credits; a ledger-only degrade writes `state="uncharged_simulation"` + emits an alert when `payment_intent_id==""`; app cannot submit a deposit without a PM; a metric/log confirms no `budget_deposit` row is ever written with empty `payment_intent_id` on the public path.

**ADV3-2 — Charge-path correctness hardening (A3, A4, A5, A6, E4-charge-half).** [M]
- Scope: (a) `record_cta_click` reuses the `{id}#click` idempotency key so click+CTA can't double-bill; (b) add a campaign-budget conditional to the campaign-spend update so concurrent charges can't exceed `budget_cents` (clamp the crossing charge); (c) attribution marks `converted` only after a successful `charge_conversion` (or records `pending_charge` for retry on refund); (d) reversal meta writes `member_clawback`; (e) gate the CTA CPC charge behind a fraud check (shared with ADV3-12/E4).
- AC: a creative with both a click-through and an in-player CTA bills CPC exactly once per `ad_click_id`; a load test firing N concurrent charges past budget leaves `lifetime_spent <= budget_cents + one_bid` (documented bound) or exactly `<= budget_cents`; an insufficient-funds conversion is retriable and settles after a refund; a syndicate reversal audit row shows `member_clawback` matching the DDB debit; unit tests cover each.

### EPIC 2 — ADVERTISER FLOW / UX (unblock the lifecycle)

- AC: a brand-new advertiser never reaches a guaranteed-403 campaign submit; account status is shown on the campaign screen; a successful deposit cannot be double-submitted from the open sheet.

**ADV3-4 — Campaign management + funding wiring + accounts list (B2, B3, B4, B10).** [L]

- AC: an advertiser with 2+ accounts can select any account for billing/campaigns/analytics; a campaign can be paused/resumed and have its budget/bid edited from the app (verified against the PATCH endpoint); an advertiser is prompted to fund the specific campaign's account; the campaign detail shows a humanized live status.

**ADV3-5 — "Advertise" hub + studio campaign picker + flight dates (B5, B6, B7).** [M]

- AC: advertiser entries are grouped under one discoverable hub, not scattered across 61 flat rows; studio editors never silently edit "first campaign" after a cold start — they show/require an explicit campaign; flight dates can be set at campaign creation.

### EPIC 5 — POLICY (review / fraud / limits)

**ADV3-10 — Close the three review-bypass surfaces (E2, E3, E7).** [M]
- Scope: route seller-boost creatives through the `pending_review`->`approved` (or auto-policy-scan) gate before serving (keep account auto-provision); require the sponsored-as-creator linked `creative_id` be admin-approved (or policy-scanned) and enforce a non-empty platform-standard disclosure/label server-side; policy-scan ad-messaging offer bodies pre-send + enforce a disclosure label + a global per-recipient frequency cap.
- AC: a boosted product, a sponsored-as-creator post, and a sponsored DM cannot serve/publish with unreviewed/undisclosed creative; disclosure labels are server-enforced, not advertiser-optional.

**ADV3-11 — Automated ad-content policy pass (E1).** [L]
- Scope: add an ad-policy pass that runs on submit-for-review — deny-list + landing-URL/domain reputation check + reuse `moderation_policy_engine` for creative text/image — auto-rejecting hard violations and risk-scoring the rest into the admin queue; policy-check `cta_url` domains.
- AC: a creative with a deny-listed term or a bad landing domain is auto-rejected (or hard-flagged) before a human sees it; the admin queue is risk-ranked; no ad text/URL reaches serve without a policy pass.

**ADV3-12 — Advertiser limits + fraud coverage + state-machine validation (E4, E5, E6, E8, E9).** [L]
- Scope: run `check_fraud` inside `record_cta_click` (shared with ADV3-2) and feed `record_account_activity`; add an account-level daily spend cap + a lower cap/velocity throttle for new/boost accounts until first settlement + minimal KYC above a threshold; require `serve_ad` to check account `status=="active"` (not merely not-suspended) and make `reject` cascade-pause; validate `review_creative`/`review_ad_account` decisions against an enum (422 on unknown); thread targeting countries into `check_fraud` and record activity even when scoring errors.
- AC: CTA CPC clicks are IVT-filtered and count toward fraud stats; a new/boost account cannot burst-spend past a velocity cap before first settlement; a `rejected` account stops serving immediately; an unknown review decision 422s; the geo fraud rule fires on the live path.

## 4. RECOMMENDED BUILD SEQUENCE

1. **ADV3-1** (real/loud deposit charge + require PM) — the P0; until this lands the whole economy is funny money.
2. **ADV3-2** (charge-path correctness: double-charge, budget overshoot, attribution consume, reversal meta, CTA fraud-gate) — money mis-moves.
3. **ADV3-3 -> ADV3-4 -> ADV3-5** (unblock wizard, then campaign management + funding wiring + accounts list, then hub/picker/dates) — the advertiser can finally run the flow.
4. **ADV3-6** (ops flip + prove live inventory) — quick, unblocks real serving; **ADV3-7** (diversity/pacing/ranked-feed) after.
5. **ADV3-8 -> ADV3-9** (reconcile dashboard to ledger + fix range/CPA/ROAS, then kill fake metrics) — advertiser can trust the numbers.
6. **ADV3-10 -> ADV3-11 -> ADV3-12** (close review bypasses, then automated policy pass, then limits/fraud/validation) — hardening for self-serve scale.

Money-correctness (Epic 1) and the flow unblock (Epic 2) are the bulk of "the flow feels rough"; ADV3-6 is a near-free ops win that turns the biggest dark placement on.
