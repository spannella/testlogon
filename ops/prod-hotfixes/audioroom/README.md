## What it adds
Broadcast AUDIO ROOM on LiveKit (audio-only, up to 20 speakers, unlimited
listeners), reusing the existing broadcast session + live chat. NO new table:
the per-room stage reuses the `group_call_sessions` DDB table (pk/sk).

### Session model (video broadcasts unchanged; `mode` defaults `"video"`)
- `mode: str = "video"` — new value `"audio_room"`
- `stage_max_slots: int = 20` — clamped 2..20 at create
- derived read-only `speaker_count` + `listener_count` on `BroadcastSessionOut`
  (`listener_count = viewers - speakers`, reusing `broadcast_viewers`).

### New service — `app/services/broadcast_stage_store.py`
Per-room stage. Keyspace `pk=ROOM#{session_id}`, `sk=SPK#{user_id}` (mirrors
`group_call_service`). One item per host / speaker / raised-hand listener; plain
listeners have no item. Fields: role(host|speaker|listener), mic_muted,
hand_raised, joined_at.

### New endpoints (all `Depends(_ctx)` = `require_ui_session`) under `/broadcast/sessions/{id}`
- `POST stage/request` — listener raises a hand (fans `stage.hand` to host)
- `GET  stage` — roster `{speakers[], hands[], speaker_count, listener_count, stage_max_slots}`
- `POST stage/promote {user_id}` — host/root only; slot-clamp (409 STAGE_FULL); LiveKit `update_participant` can_publish=true; fans `stage.promote` to target
- `POST stage/demote {user_id}` — host/root only; LiveKit can_publish=false; fans `stage.demote`
- `POST stage/mute {user_id}` / `POST stage/unmute {user_id}` — host/root only; LiveKit `mute_published_track`; fans `stage.mute`/`stage.unmute`
- `POST stage/leave` — self step-down
- `GET  livekit-token` — mints a LiveKit JWT per caller role (speaker if host/on-stage, else listener)

Stage `stage.*` events are written to the per-user `tbl_events` queue so they
surface on the proven `GET /messaging/events/poll` realtime path (a promoted
listener re-fetches its token and starts publishing).

Discovery: `GET /broadcast/live` (already existed on prod) now surfaces `mode`
and accepts an optional `?mode=audio_room` filter.

### LiveKit config (server-authoritative controls; audio-only)
Token: `api.AccessToken(key,secret).with_identity(uid).with_grants(VideoGrants(
room_join, room=session_id, can_subscribe, can_publish=is_speaker,
can_publish_sources=["microphone"] if speaker else []))`.
Controls via `api.LiveKitAPI(control_url,key,secret)` — best-effort (the stage
store is the roster source of truth; LiveKit enforces). `livekit-api` pip pkg
installed into the prod runtime venv `/home/ubuntu/testlogon/.venv`.

### Settings (`app/core/settings.py`) + prod `.env.local`
`LIVEKIT_URL` (ws for clients), `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`
(copied from `/etc/livekit/livekit.yaml`, 0600 — NOT hardcoded in source),
`LIVEKIT_CONTROL_URL` (http RoomService, default `http://127.0.0.1:7880`).
